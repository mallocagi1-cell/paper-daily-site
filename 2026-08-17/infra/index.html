TriInfer: Hybrid EPD Disaggregation for Efficient Multimodal Large Language Model Inference

TriInfer 将多模态推理拆成 Encode、Prefill、Decode 三阶段，分别部署到异构实例，并用阶段级批处理提升资源匹配。论文在真实多模态负载上报告相对 vLLM、SGLang 最高 3.7 倍吞吐，同时满足 90 分位请求 SLO。

INSIGHT如果社区搜索同时接入图片、视频或 OCR，统一实例会让视觉编码和文本解码互相争抢资源。可借鉴 EPD 解耦，按阶段独立扩缩容，并把图片编码耗时、文本 TTFT 和召回链路整体延迟作为联合 SLO，而不是只监控生成吞吐。

Optimal Scheduling Algorithms for LLM Inference: Theory and Practice

论文针对 LLM 推理的 Prefill-Decode 两阶段结构建立路由与调度模型，提出吞吐最优的 RAD 调度器，以及面向 SLO 的 SLAI 调度器。SLAI 会优先处理接近 TBT 截止时间的 Decode 请求，并按已知 prompt 长度重排 Prefill，以降低 TTFT。

INSIGHTUGC 搜索的 query 很短但 RAG 上下文可能很长，FCFS 容易让长上下文请求阻塞短请求。工程上可将 TTFT 与 TBT 分开建模，使用队列实时信号调节 Decode 优先级，再把 prompt 长度和候选文档数作为 Prefill 的调度特征。

Multi-Segment Attention: Enabling Efficient KV-Cache Management for Faster Large Language Model Serving

论文提出 AsymCache，面向非连续 KV Cache 访问设计 Multi-Segment Attention，并联合考虑缓存命中率、位置相关的重算代价和自适应分块调度。它把 KV Cache 驻留、淘汰与 GPU attention kernel 的真实计算延迟放进同一个系统优化目标，摘要未给出统一的跨基线倍数。

INSIGHT当社区搜索的长上下文请求共享前缀、但候选证据分散在不同缓存段时，仅优化命中率可能反而增加重算成本。可把缓存位置、attention kernel 代价和请求优先级联合评估，并用长尾 query 分桶检查缓存策略是否伤害 P99 延迟。

负载感知路由实践

Alibaba Cloud

阿里云实践把 GPU 显存、KV Cache 利用率和请求排队状态纳入生成式推理服务的路由决策，并以 vLLM 与 Prometheus 指标说明采集方式。它没有给出统一离线或线上提升数字，但提供了从实例指标到负载均衡策略的可落地链路。

INSIGHT社区搜索的请求成本会随上下文和生成长度剧烈变化，按连接数或平均 QPS 做负载均衡不够。可以先接入 GPU 利用率、KV Cache 使用率、队列长度和 TTFT 四类指标，再按租户或 query 长度做加权路由，避免热门长 query 挤压短 query。

GhostServe: A Lightweight Checkpointing System in the Shadow for Fault-Tolerant LLM Serving

GhostServe 将流式 KV Cache 做纠删码，在主设备之外把 parity shard 保存在主机内存，设备故障时可恢复缓存并继续生成。实验显示单批次 checkpoint 延迟最高降低 2.7 倍、恢复延迟降低 2.1 倍，相比现有方法中位响应延迟降低 1.2 倍。

INSIGHT对长上下文问答或搜索 Agent，整请求重算会同时放大 GPU 成本和用户等待。可先在非关键流量上引入异步 shadow checkpoint，并按 KV Cache 大小、恢复时间和可接受重算窗口做分层；不要一开始就对所有短请求启用纠删码。

Shakya Jayakody, Youpeng Zhao, Chinmay Dhanraj Nehate, Jun Wang

PipeSD: An Efficient Cloud-Edge Collaborative Pipeline Inference Framework with Speculative Decoding

University of Surrey

PipeSD 面向云边协同推理，把 speculative decoding 的 token 生成与通信重叠为流水线，并用动态规划优化 token-batch 调度。双阈值触发器和轻量 Bayesian autotuner 用于适配不同验证成本，适合隐私敏感或边缘算力受限的部署，但公开摘要未给出统一吞吐数字。

INSIGHT若社区端需要本地 embedding、轻量 reranker 或隐私过滤，云边协同比把全部请求送入云端更稳妥。可将短 query 的前处理留在边缘，把高成本生成/重排放到云侧，再用 speculative decoding 和链路带宽共同调参，避免只优化 GPU 而忽视网络尾延迟。

SHIP: SRAM-Based Huge Inference Pipelines for Fast LLM Serving

Groq

SHIP 总结 SRAM 型大规模推理流水线的系统设计，重点包括低直径同步互联、受限内存下的 LLM serving 优化，以及适配不同 Prefill/Decode 比例和上下文长度的流水线结构。它更像硬件—系统协同的工程报告，适合用于评估专用推理硬件路线。

INSIGHT社区搜索通常更看重成本、弹性和生态兼容，专用 SRAM 路线未必适合直接替换通用 GPU。借鉴点是按上下文长度和 Prefill/Decode 比例做硬件画像；在采购前应同时测 embedding、reranker、生成模型三类负载，避免单一 token/s 指标误导。
