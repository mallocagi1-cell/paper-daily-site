OxygenREC: An Instruction-Following Generative Framework for E-commerce Recommendation

OxygenREC 将近线 LLM 的“慢思考”意图推理与实时编码器—解码器的“快生成”拆开，并用 Q2I 对齐、指令引导历史检索及 SA-GCPO 统一六个电商场景。京东 10% 流量 A/B 中，订单量提升 1.49%–8.03%、GMV 提升 1.46%–11.80%，线上延迟为 50–80ms。

Bridging the Structural Gap: Adapting Autoregressive Generation for Recommendation

Tencent

BARGE 针对语义 ID 展平后物品边界消失、层级解码早期错误造成语义漂移，加入 Item Context-Aware Attention、Hierarchical Path Reranking 与双路径解码。腾讯商业媒体平台以 6% 流量验证，相比现网多阶段系统 CTR 提升 0.60%、点击用户数提升 1.34%、总阅读时长提升 1.70%。

INSIGHT生成式推荐的关键瓶颈不只在编码质量，还在“物品边界”和层级路径的一致性。对 UGC 搜推，可在用户历史编码时显式保留每条帖子或问答的 token 分组，并在每层语义码上做路径级对比排序；双路径解码则把单一路径的级联错误变成可互补的候选来源，适合先替换召回与预排而保留现有精排。

Structuring and Tokenizing Distributed User Interest Context for Generative Recommendation

MetaUIUC

G2Rec 以 O(M log M) 稀疏共参与图和软聚类提取分布式兴趣原型，再把兴趣 token 与物品 token 交替输入生成模型。四个公开数据集上均领先，例如 Yelp NDCG@10 达 0.4927；Meta 多产品面 7 天与长期 A/B 中，会话指标提升超过 0.03%，时长、点赞、分享等提升 0.06%–0.19%。

INSIGHT把图结构直接塞进在线模型代价很高，而 G2Rec 将图计算移到离线，只在线拼接兴趣原型 token，单批推理开销仅从 0.0534 增至 0.0561。社区平台可由用户共同点击、收藏或停留构建帖子图，再软聚类出可重叠兴趣；这比单一 hard cluster 更能表达跨圈层用户，也便于给生成式召回提供稳定、可刷新且有业务含义的上下文。

Can Generative Recommendation Reach Cold Items? A Temporal Perspective on Semantic-ID Generation

AlibabaRenmin University of China

该研究用绝对时间切分重新评估 TIGER，并以 token 覆盖、前缀支持与 oracle-prefix probing 诊断冷物品可达性。Sports 中 40.5% 冷物品的所有 token 均见过，但 Recall@20 仍仅 0.00006；含未见原子 token 的样本为 0，只有三层前缀受支持时 Recall@20 升至 0.01007。

INSIGHT语义 ID 的“可组合”不等于能生成新物品：当前模型更像沿已学层级树做受限搜索，深前缀支持比单个 token 覆盖更重要。社区内容持续新增时，应按时间而非随机留一评测冷启动，并单独统计未见 token、未见路径和深前缀三类；上线可考虑独立码本、生成后打分接口或动态文本上下文，避免新品永久落在不可达路径。

Diffusion Language Model for Recommendation

TencentHHong Kong Polytechnic University

DLMRec 以离散扩散替代自回归 next-token 生成，用多跳协同随机 tokenizer、逐级掩码课程学习和稳定性投票并行修正整段推荐。LastFM、MovieLens-1M、Amazon-Beauty 上相对最强基线各指标提升 3.25%–8.22%，对强 LLM 基线平均 Recall 与 NDCG 分别提升 6.75% 和 5.19%。

INSIGHT推荐序列的先后顺序往往带噪，双向去噪比不可回退的左到右解码更适合恢复整体偏好。其代价是迭代步数：8B 模型三步生成 Top-20 约 154.27ms，但只需 2–3 步即可达最优。实践中可先在离线候选生成或低频刷新链路试验，并用稳定投票提前锁定高置信 token，避免过度迭代破坏已正确结果。

On the Memorization Behavior of LLMs in Generative Recommendation: Observations, Implications, and Training Strategies

SnapKAISTSungkyunkwan University

研究发现 LLM 生成式推荐的大部分领先来自记住训练集中一跳物品转移，而非真正利用预训练知识泛化。IIRG 增加多跳协同邻居和语义邻居生成任务；在 Beauty 上 Recall@10 从朴素训练的 0.0828 提至 0.1011，Toys 从 0.0892 提至 0.1097，二者联合优于任一单独任务。

INSIGHT离线总指标会掩盖模型只是在复述热门转移路径。社区搜推应将测试用户按目标是否被一跳历史覆盖分桶，并把冷门 query、跨主题跳转和新内容作为独立泛化切片；训练时加入多跳共现与文本语义邻居，可迫使模型学习更丰富的物品关系。该方法仍保留标准 next-item 主任务，适合以辅助样本生成方式接入现有训练管线。

Beyond Fixed Depths and Widths: Optimizing Textual Decoding Tries in LLM-based Generative Recommendation

SnapMichigan State University

BONSAI 不再把文本 ID 的前缀树视为副产品，而以贪心最小集合覆盖共同设计可变长度 ID 和低浅层分支的解码 trie，再用 SFT 与强化学习适配真实束搜索。三个 Amazon 类目上相对强基线最高提升 21.6%；控制实验还显示分支因子从 6 增至 12 时 Hit@5 持续下降。

INSIGHT生成式召回的准确率同时由语义表示和搜索树几何决定：根部一次分太多支，正确路径会在束宽有限时过早被剪掉。UGC 物品描述长短差异大，固定码长会压缩丰富帖子又浪费简单帖子；可先抽取标题、话题与实体词，再用最小覆盖构建可变深度 trie。该改造主要发生在索引与训练阶段，不必更换 LLM 主干。

Intuition-Guided Latent Reasoning for LLM-Based Recommendation

MetaBeihang UniversityUSTCCUHKNUS

IntuRec 先由推荐器生成 Top-K 候选，再经自注意力与交叉注意力压成“直觉”向量，作为 LLM 连续空间多步推理的起点，减少隐状态与目标物品空间错位。CDs 上 D³ 的 Recall@5 从 0.1122 提至 0.1174，Games 从 0.0608 提至 0.0751；Toys NDCG@5 从 0.0610 提至 0.0708。

INSIGHT潜在推理若从任意 hidden state 开始，计算步数增加也可能沿错误方向细化。更稳妥的结构是让现有召回器先给出低成本候选分布，再把它作为推理先验；这很适合社区搜索的“传统召回+LLM 精炼”渐进改造。直觉向量仍在连续空间内迭代，无需生成可见 CoT，可降低额外 token 延迟，同时保留对多兴趣的深层推断。

RAGR: Review-Augmented Generative Recommendation

HuaweiCity University of Hong KongDDalian University of Technology

RAGR 将物品语义 ID 与评论语义 ID 按时间交错，让自回归模型同时学习用户选了什么与为什么选择，再以 DPO 保证预测位置偏向物品 token。三套 Amazon 数据上对 TIGER 与 LETTER 均显著提升；Toys 的 TIGER NDCG@5 从 0.0206 升至 0.0259（+26%），Beauty 的 LETTER Hit@5 提升 20%。

INSIGHT点击序列只记录行为结果，评论、问答或搜索改写更接近选择原因；把这些信号作为序列内原生 token，比末端拼接辅助向量更容易参与逐步生成。社区产品可将帖子评论、收藏备注或追问离散成语义码与内容码交错训练，但要用 item-centric 对齐约束输出类型，避免模型在推荐位置生成解释 token 而不是可服务的候选。

Factorized Latent Reasoning for LLM-based Recommendation

MeituanUNSWMacquarie University

FLR 用多因子注意力把单一潜在思维向量拆成可解耦偏好，并以正交、注意力多样性和稀疏正则避免因子塌缩，再用 GRPO 在连续思维空间对齐。四个数据集上较 LatentR3 平均提升 3.2%；Games NDCG@5 从 0.0419 提至 0.0462（+10.26%），完整正则使 Hit@5 比无约束版本高 7.2%。

INSIGHT用户兴趣天然多面，单个 latent token 容易把主题、风格与时效偏好混成平均表示。社区搜推可用若干可学习 query 分别读取历史行为，再由门控按当前 query 动态聚合；正交、多样性与稀疏约束缺一不可，否则多头只是重复注意同一热门兴趣。该方案不输出文本 CoT，推理长度固定，更适合受延迟约束的精排或重排链路。
