Shepherd: A Runtime Substrate Empowering Meta-Agents with a Formalized Execution Trace

针对 Meta-Agent 缺乏可形式化、可回放的执行底座的问题，Shepherd 提出一种函数式编程模型，将 Meta-Agent 对目标 Agent 的操作抽象为函数，并用 Lean 形式化核心操作。系统以 Git 风格的类型化执行轨迹记录每次 Agent-环境交互，可以从任意历史状态 fork 并回放，进程与文件系统 fork 速度比 Docker 快 5 倍，回放时 prompt-cache 复用率 >95%。论文在三个场景中验证：运行时干预把 CooperBench 上的配对编码通过率从 28.8% 提到 54.7%；反事实元优化在四个 benchmark 上比 baseline 高 11 分，且 wall-clock 时间最多减少 58%；Tree-RL 训练把 TerminalBench-2 上的表现从 34.2% 提到 39.4%。

Nautilus Compass: Black-box Persona Drift Detection for Production LLM Agents

生产环境的 LLM 编码 Agent 在长会话中会出现 persona drift：忘记用户约束、重复犯错、捏造此前的「共识」。已有的白盒方法（如 persona vectors）需要模型权重，对 Claude/GPT-4 等闭源 API 不可用。Nautilus Compass 提出一种黑盒检测方法：完全在 prompt 文本层操作，用 BGE-m3 把用户 prompt 与行为锚文本做余弦相似度，再用加权 top-k 平均聚合。论文称这是公开 Agent memory 方案（对比 Mem0、Letta、Cognee、Zep、MemOS 等）中唯一不在索引时调用 LLM 抽事实/建图的，原文直接嵌入，落地为 Claude Code 插件 + MCP A2A 服务。

INSIGHT对社区搜索 Agent 的核心启示：当 Agent 多轮处理用户查询、改写、点击反馈时，必须持续监测它是否「漂移」出最初的用户意图。黑盒 + 文本层 + 直接嵌入的设计有三个工程优势：1) 不依赖模型内部，可在 Claude/GPT-4 调用链上做监控；2) 索引时零 LLM 调用，省钱、低延迟，适合规模化；3) 用 BGE-m3 等开源 embedding 即可部署，复用既有向量检索基建。对短文本社区搜索来说，可以把它包装成「会话健康度指标」，作为长会话 Agent 的运行时护栏。

Human-Inspired Memory Architecture for LLM Agents

现有 LLM Agent 缺乏原则化的长期记忆机制。论文提出一套生物启发的记忆架构，包含 6 个认知机制：1) 睡眠期巩固；2) 干扰式遗忘；3) engram 成熟；4) 检索时再巩固；5) 实体知识图谱；6) 多线索混合检索。每个机制对应一种朴素记忆累积的失败模式。论文还提出一种合成校准方法，可以在不接触 benchmark 数据的前提下确定所有阈值，避免评估泄漏。在 VSCode issue 数据集（13K issues / 120K events）上，去重式巩固达成 97.2% 保留精度同时减少 58% 存储（比 baseline 提升 21.8 pp）；并在 LongMemEval 流式 personal-chat 上首次完成 streaming 评估。

INSIGHT把「睡眠巩固 + 干扰遗忘 + 重检索强化」这套大脑启发的机制工程化，可作为社区搜索/问答 Agent 长期会话记忆的设计参考。三个可借鉴点：1) 用「去重 + 巩固」取代单纯堆叠日志，可以在保留信息精度的同时把存储减半；2) 多线索检索 + 实体 KG 适合 UGC 场景下「用户 + 话题 + 标签」的多维度上下文召回；3) 合成阈值校准是个被低估的工程实践，能避免在线 benchmark 数据被滥用于调阈值，提升离线评估可信度。

Doga et al.

G-Zero: Self-Play for Open-Ended Generation from Zero Data

自演化 LLM 在可验证任务上效果好，但在开放式任务上严重依赖 LLM-as-Judge，从而带来能力上限和 reward hacking。G-Zero 提出一种 verifier-free 协同演化框架：核心创新是 Hint-δ，即 Generator 在「无提示」和「自生成提示」两种条件下回答的预测偏移量，作为内在奖励。Proposer 用 GRPO 训练，持续合成能触发 Generator 盲区的查询和 hint；Generator 同时用 DPO 内化 hint 引导的改进。论文还为理想化版本证明了 best-iterate suboptimality 上界，并对探索覆盖率和伪标签噪声给出条件。

INSIGHT对搜索/推荐 Agent 训练的启示：当任务难以构造确定性 reward（如「好的回答」、「自然的对话」）时，可借鉴 Hint-δ 这种「自指型」内在奖励 —— 模型给自己一个 hint，比较「看 hint 前后」的输出差异作为学习信号。对 UGC 搜索的应用想象：把「召回结果摘要」作为 hint，比较 LLM 在有/无摘要时对用户 query 的回答差异，可以筛选高价值召回；同时避免单一 judge 模型的偏见。

DeepRefine: Agent-Compiled Knowledge Refinement via Reinforcement Learning

Agent 编译的知识库为 LLM Agent 在开放式知识密集任务上提供持久外部知识，但质量受限于不完整性、错误、冗余三类问题：缺失证据/跨文档连接、置信度低、共指消解歧义。多次迭代后这些缺陷会复合，降低检索可靠性。DeepRefine 是一个基于 LLM 的通用推理模型，针对预构建知识库做 query-aware 的精炼：它与知识库多轮交互、对交互历史做溯因诊断、定位可能缺陷，并执行有针对性的增量更新动作；通过 RL 优化精炼策略，使知识库更适合下游任务。

INSIGHT对社区搜索的启示：当我们用 Agent 自动构建「帖子摘要 / 问答库 / 知识卡片」等中间知识资产时，质量退化是长期不可避免的工程难题。DeepRefine 把「知识库精炼」建模为可 RL 优化的多轮交互决策问题，给出了三个有用范式：1) 把「诊断 - 定位 - 修补」显式拆开，便于工程介入；2) 用下游任务表现作为 reward，比单纯的「内部一致性指标」更有用；3) query-aware 精炼意味着同一个知识库可以根据当前 query 流做轻量级局部修复，而不是定期全量重建。

Haoyu et al.

OpenIIR: An Open Simulation Platform for Information Retrieval Research

OpenIIR 是一个用 LLM 驱动 persona 跑可重复 IR 实验的开放仿真平台。研究者可以配置 4 类多 Agent 研究：审议小组、社交平台、推荐 feed、内容生产者与可信度检测器的共进化。Persona 预算、检索策略、排序选择、干预时点、变异率等均前置声明，同一实验可在不同设置下并行重跑做对比。每次运行产出结构化输出（论证图、曝光日志、fitness 轨迹、对话），下游评估器可直接消费；新研究通常只需在共享内核（Agent runtime、世界模型存储、检索原语、claim 抽取、persona 本体）上写 200–400 行 plug-in。

INSIGHT把「模拟用户 + 模拟内容生产者」作为 IR 离线评估的一等公民，对社区搜索是重要工具：1) 可以在没有真实用户的情况下，先用 persona simulation 验证排序变化对长尾用户、不同立场用户的影响；2) 「内容生产者 vs 可信度检测器」的共进化范式正好对应 UGC 平台的 spam/低质回答博弈，可以用来压力测试排序策略；3) 共享内核 + 短 plug-in 的工程化范式值得借鉴，能让算法同学快速做 A/B 假设验证。

Dynamic Skill Lifecycle Management for Agentic Reinforcement Learning

LLM Agent 越来越依赖外部技能（skill）作为模块化能力扩展。已有方法假设外部技能要么持续累积、要么内化进策略后转入零技能推理。论文指出该假设过于严格：受参数容量限制 + 技能边际贡献不均，最优活跃技能集是非单调、随任务和阶段变化的。论文提出 SLIM 框架：把活跃外部技能集作为与策略联合优化的动态变量，通过 leave-one-skill-out 估计每个技能的边际外部贡献，并执行三种生命周期操作 —— 保留高价值技能、淘汰低价值技能、引入新技能。

INSIGHT对工业搜索/推荐 Agent 工具链管理的启示：1) 工具/技能不应一加上就永久存在，应当像缓存一样有 TTL 和淘汰策略；2) leave-one-skill-out 的边际贡献评估给出了一种可量化的「工具下线」决策依据 —— 这正是大多数 Agent 平台在做的「工具治理」任务的算法版本；3) 把工具集本身视为可优化变量，使 Agent 推理成本可控、避免「工具集爆炸」导致的 prompt 膨胀与 latency 退化。

Junha et al.

TMAS: Scaling Test-Time Compute via Multi-Agent Synergy

Test-time scaling 是提升 LLM 推理能力的有效范式，已有结构化方法通过多轨迹推理、多轮精炼和验证反馈进一步推进。但已有结构化方法要么轨迹间协同弱，要么依赖噪声历史信息且不显式决定保留/复用什么，限制了探索-利用平衡。TMAS 提出一个「多 Agent 协同」框架：把推理组织为多个专用 Agent 的协作过程，支持跨 Agent、跨轨迹、跨精炼轮次的结构化信息流动。核心是引入分层记忆 —— 经验库（experience bank）记录跨轨迹有用结论，使 Agent 间共享高质量上下文，避免重复探索。

INSIGHT把「多 Agent 协作 + 分层记忆」作为复杂查询处理框架，对搜索 Agent 有几条直接启示：1) 用专家 Agent 分工（query 重写专家、召回专家、排序专家、答案合成专家）比单 prompt 包打天下更可控；2) experience bank 这种「跨轨迹共享结论」的结构，可以避免每次都从头探索，对长尾 query 处理特别有用；3) 显式控制「保留什么、复用什么」比依赖隐式上下文窗口更可靠，工程上也更易调试。

Georg et al.

Rebellious Student: Reversing Teacher Signals for Reasoning Exploration with Self-Distilled RLVR

自蒸馏中「带额外信息的 teacher 指导无信息的 student」的范式，在 student 失败时有益，但在 student 成功时反而压制其自驱推理。论文提出「反向读取」自蒸馏信号：当 student 走出一条 teacher 不会预测的成功路径，这些 token 即代表其自驱推理。基于此提出 RLRT（RLVR with Reversed Teacher），在 GRPO 上扩展，对正确 rollouts 中的这些 token 做强化。论文把这种策略解读为 RLVR 中的一种新型探索方式 —— 不是均匀多样性，而是基于 student 自身成功的有价值探索。在 Qwen3 的 base、instruction、thinking 三个版本上，RLRT 显著超过自蒸馏和探索类 baseline。

INSIGHT对 RL 训练搜索/排序 Agent 的启示：RLVR 范式下「探索」的定义可以更精细 —— 不一定要鼓励多样性，而是要鼓励「模型自己想出、教师不会想到、但事实上对的」路径。在搜索 query 改写或答案合成场景中，这意味着可以保留模型「出人意料的好回答」，并以此为种子训练；对工业系统而言，这也降低了对「理想 teacher」的依赖，让 self-improvement 训练更稳定。

Jeong et al.

What Parameter Golf taught us about AI-assisted research

OpenAI

OpenAI 复盘 Parameter Golf 大赛：聚集 1000+ 参赛者、2000+ 提交方案，主题围绕「AI 辅助机器学习研究」在严格约束下展开 —— 包括 coding agent、量化技术、新型模型设计。OpenAI 把这个竞赛作为评估 AI 辅助研究能力的真实场景，并总结了「coding agent + 严约束」下的若干模式。

INSIGHT对工业团队的启示：1) 「在严约束下让 Agent 跑研究/工程任务」是当前最值得跟踪的能力增长方向之一 —— 它逼迫 Agent 在搜索/验证/迭代上做真实权衡，远比开放任务有诊断价值；2) 类似的「内部 mini 竞赛」可作为团队内部评估 coding agent 实力的工程实践，比单纯跑 benchmark 更接近真实生产场景；3) OpenAI 把社区竞赛产物（2000+ 提交）转化为内部研究信号，这是个值得借鉴的「用户 - 平台」知识流转模式。
