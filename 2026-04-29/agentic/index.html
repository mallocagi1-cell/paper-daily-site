Rewarding the Scientific Process: Process-Level Reward Modeling for Agentic Data Analysis

针对动态数据分析 Agent 任务，作者发现通用 PRM 难以发现执行无异常但结果错误的「静默错误」，且会错误惩罚必要的探索性步骤。论文提出 DataPRM——一个具备环境交互能力的生成式过程奖励模型：作为主动验证器自主执行代码探查中间状态以揭露静默错误，并采用「反思感知三元奖励」区分可纠正的执行失败与真正的逻辑错误。在多个数据分析基准上 DataPRM 显著提升 Agent 执行成功率，且作为 RL 监督信号能稳定训练 8B 数据分析 Agent。

KEY INSIGHT · 对业务意味着什么对于多步骤 Agent 任务，单纯沿用「数学推理 PRM」会把试错惩罚混入训练信号，是当前 search/rec Agent 落地的核心痛点。论文给出两条可借鉴的工程做法：一是让 PRM 像 Agent 一样主动调用工具回放执行环境去判分，而不是只看文本轨迹；二是用「正确/中性/负」的三元奖励对探索性 trial-and-error 留出空间。这套思路可直接迁移到搜索 Agent 的 query 改写、检索回退等多轮决策的过程级奖励训练。

Stabilizing Efficient Reasoning with Step-Level Advantage Selection

AMD

高效推理 LLM 在短上下文下做 GRPO 后训练能自动压缩推理长度，但训练动态会越来越不稳，准确率下滑。作者把不稳定原因归结为：截断与验证器误判会让正确答案被错误反传梯度，常规 GRPO 把句段级 advantage 一刀切到所有 token。论文提出 SAS（Step-level Advantage Selection），在每个推理步上根据置信度细粒度地选择是否回传 advantage——对正确轨迹中的低置信步置零 advantage，对验证失败轨迹中的高置信步置零 advantage，从而过滤截断/验证噪声。在数学与代码推理基准上 SAS 在大幅压缩推理长度的同时保持或提升准确率，训练曲线显著更平滑。

INSIGHTRL 后训练里「token 全部用同一 advantage」是一个隐藏的稳定性陷阱，这在 search Agent 的工具调用 RL 训练中同样存在。论文揭示：失败 rollout 中真正错误的不是所有 token，而是少量关键决策步；用置信度做轨迹内 step-level 过滤是一个比奖励 reshape 更直接的稳定化手段。对实际部署的启示：训练搜索 Agent 时不要一刀切惩罚整个轨迹，可以借助置信度或 verifier 信号识别真正出错的子步骤，否则 RL 训练会逐步退化。

Han Wang, Xiaodong Yu, Jialian Wu, Jiang Liu, Ximeng Sun

Improving Vision-language Models with Perception-centric Process Reward Models

RUC

RLVR 在 VLM 上以「结果级」奖励监督，对推理链中的中间感知错误无能为力。论文提出 Perceval：一个面向感知的过程奖励模型，可从 VLM 输出中抽取与图像相关的声明并逐条与图像证据比对，定位幻觉 span。Perceval 用感知密集型 SFT 数据训练，并嵌入到 RL 训练流程：相比传统 GRPO 的序列级 advantage，Perceval 在被识别的幻觉 span 上施加 token 级负向 advantage，提供细粒度监督。多个 VLM 推理 benchmark 上感知幻觉显著下降，多步推理准确率提升。

INSIGHT把 PRM 设计为「token 级幻觉检测器」而非整段评分器，是当前多模态 Agent 的关键技术分水岭。对搜索/推荐场景的启示：当 LLM 用做检索结果改写或归纳时，可在「与文档证据冲突的 span」上施加局部惩罚，而不是仅做最终答案打分；这种细粒度 token-level RL 有望显著降低事实幻觉，是落地 search Agent 必须考虑的训练信号设计方向。

Yingqian Min, Kun Zhou, Yifan Li, Yuhuan Wu, Han Peng

Quantifying Divergence in Inter-LLM Communication Through API Retrieval and Ranking

UUniversity of Washington Tacoma

随着 LLM Agent 越来越多地通过 API 完成任务，不同 LLM 在「API 发现 / 排序」一致性上的可靠性尚不清晰。作者构建了一个统一基准，跨 15 个标准 API 领域、5 个主流模型家族评估 inter-LLM 一致性，使用 Average Overlap、Jaccard、Rank-Biased Overlap、Kendall's tau / W、Cronbach's alpha 等集合 / 排序 / 共识维度的指标。结果显示总体一致性中等（AO≈0.50, tau≈0.45），但领域差异强：结构化任务（Weather、Speech-to-Text）稳定，开放任务（Sentiment Analysis）发散明显。波动性与共识分析揭示一致性聚簇受任务结构而非模型规模主导。

INSIGHT对 Agentic 搜索系统的关键提示：把 LLM 当作 retriever 时，不同模型对同一 query 选 tool / API 的排序差异可能很大，且这种差异在开放语义任务上最严重——这正是社区搜索的典型场景。落地启示：1) 不要假设换一个更强模型就能稳定 tool ranking，反而需要在系统层面引入投票或 reranker 平滑模型间方差；2) 评估 search Agent 必须包含「跨模型 / 跨 prompt 一致性」指标，而不仅是单一模型的 nDCG。

Eyhab Al-Masri

CyberCane: Neuro-Symbolic RAG for Privacy-Preserving Phishing Detection with Formal Ontology Reasoning

UMBC

隐私敏感场景的钓鱼检测需要同时满足极低误报、可解释、不向外部 API 暴露明文、抗 AI 攻击四个相互冲突的约束。作者提出 CyberCane：双阶段神经-符号 RAG 框架。首阶段对邮件元数据应用确定性符号规则；边界 case 升级到第二阶段，使用本地 RAG 检索（仅检索钓鱼专用语料），并通过自动敏感字段脱敏防止信息泄漏；同时引入 PhishOnt（OWL 本体）对攻击类做形式化推理与可验证解释。该 pipeline 在多个钓鱼基准上保持高召回的同时维持接近零误报，并提供可被合规审计的推理链。

INSIGHTNeuro-Symbolic RAG 是一种被 LLM-only RAG 长期忽视的 Agent 落地范式。其核心思想——「先用规则筛掉 95%，再让 LLM 处理 5% 的边界 case」——直接适用于社区搜索的安全 / 反垃圾场景：不要让 LLM 处理全量 query，而是用符号规则做硬过滤，把模糊 case 升级到 RAG/LLM。可借鉴的工程设计：检索源限定（只检索域内白名单语料）、自动 PII 脱敏、用本体做检索结果一致性校验，三者结合可显著降低 RAG 上线后的合规风险。

Safayat Bin Hakim, Aniqa Afzal, Qi Zhao, Vigna Majmundar, Pawel Sloboda, Houbing Herbert Song

Behavioral Intelligence Platforms: From Event Streams to Autonomous Insight via Probabilistic Journey Graphs, Behavioral Knowledge Extraction, and Grounded Language Generation

现行产品分析平台依赖用户主动写 SQL / 配置看板，门槛高且假设用户事先知道要问什么。作者提出 BIP（Behavioral Intelligence Platform）四层架构，把原始事件流转化为自动洞察：1) NSD 层标准化事件并映射到语义状态层级；2) BGE 层用吸收马尔可夫链建模用户旅程，计算转移概率与 removal effect；3) BKE 层抽取行为知识；4) GLG 层用 LLM 生成有据可查的自然语言解释。系统从被动答查询转向主动检测并解释行为现象。

INSIGHT对搜索/推荐运营的启示：把「分析」从 pull 模式转成 push 模式是一种典型的 agentic 改造。BIP 的 removal effect 公式可以无缝迁移到搜索归因——评估某个排序信号或某个召回通道「拿掉之后用户旅程会发生多少概率分布变化」，比传统 A/B 更细粒度。其工程做法是把事件流先转成马尔可夫图，再让 LLM 在已结构化的图上生成解释，这套「先结构化、后 grounding」的范式比直接喂事件流给 LLM 更可靠。

Arun Patra, Bhushan Vadgave

RADIANT-LLM: an Agentic Retrieval Augmented Generation Framework for Reliable Decision Support in Safety-Critical Nuclear Engineering

TTexas A&M

面向核工程安全决策这一高合规场景，作者提出 RADIANT-LLM 多模态 Agentic RAG 框架。核心特性：本地优先、模型无关；多模态文档摄取管线 + 结构化 metadata-rich 知识库，支持页/图级检索；Agent 层协调领域工具，对响应强制要求带溯源标注的引用，并保留人工 in-the-loop 验证；同时通过自动 redaction 防止敏感数据外泄。框架在内部核安全 QA 工作流上证明了相比纯 LLM 基线显著降低幻觉、提升溯源可审计性。

INSIGHTRADIANT-LLM 是把 RAG 工程化到强合规场景的一个完整模板，对企业内部知识搜索（社区运营手册、客服知识库）有直接复用价值。可借鉴的设计点：1) 多模态摄取必须保留页/图级粒度，否则下游引用无法溯源；2) Agent 层强制 citation-backed 响应是降低幻觉最有效的工程手段，胜过模型层调优；3) 「local-first、model-agnostic」架构让模型升级不影响 RAG pipeline，是搜索系统长期演进必须考虑的解耦原则。

Zavier Ndum Ndum, Jian Tao, John Ford, Mansung Yim, Yang Liu

Zero-to-CAD: Agentic Synthesis of Interpretable CAD Programs at Million-Scale Without Real Data

Autodesk

现有大规模 3D 数据集主要是 B-Rep / mesh，缺少表达设计意图的「构造历史」。Zero-to-CAD 把合成问题建模为 agentic search：将 LLM 嵌入到一个有反馈的 CAD 环境中，迭代「生成 → 执行 → 校验」代码，并在过程中调用工具与文档查找，以促进几何有效性与操作多样性。整个 pipeline 无需真实 CAD 数据，最终合成约 100 万条可执行、可读、可编辑的 CAD 序列，并发布 10 万条精选高质量子集。

INSIGHT「无真实数据，靠 Agent + 验证环境合成训练数据」是一种被低估的数据飞轮范式。对搜索/推荐的启示：当人工标注成本极高（例如 query 改写、复杂多轮搜索意图）时，可以构造一个带验证器的环境，让 LLM Agent 自我「生成 query → 执行检索 → 校验」从而合成高质量训练样本。关键是验证环节必须是「可执行 + 可机验」，否则合成数据噪声会反向毒化模型——这点也是与「self-instruct」最大的区别。

Mohammadmehdi Ataei, Farzaneh Askari, Kamal Rahimi Malekshan, Pradeep Kumar Jayaraman

RCSB PDB AI Help Desk: retrieval-augmented generation for protein structure deposition support

RRutgers

RCSB PDB 每年要处理约 19000 条来自 8000 条目深存的结构存档求助消息，人工 biocurator 负担巨大。作者构建了基于 LangChain + pgvector (PostgreSQL) + GPT-4.1-mini 的 RAG help desk：使用 pymupdf4llm 做保留 Markdown 结构的 PDF 抽取、两阶段文档切块、MMR 检索、话题 guardrail 拦截 off-topic 查询，并通过专用 system prompt 防止内部术语外泄。系统在内部评估中显著降低了人工响应时间。

INSIGHT这是一个朴素但工程参考价值很高的 RAG 落地案例，几乎所有「企业内部 RAG 客服 / 文档问答」都可直接抄此栈。可借鉴的细节：1) PDF 抽取保留 Markdown 结构是 RAG 质量的隐性瓶颈，pymupdf4llm 是当前社区共识；2) 两阶段切块（粗粒度索引、细粒度回填）+ MMR 检索是对长文档最稳的检索方案；3) Topical guardrail 必须放在 retrieval 之前而非之后，可防止无关 query 被强行拼接进上下文。

Vivek Reddy Chithari et al. (RCSB PDB)

ComplianceNLP: Knowledge-Graph-Augmented RAG for Multi-Framework Regulatory Gap Detection

HKU

金融机构每年要追踪超 6 万条监管事件，作者提出 ComplianceNLP 端到端系统自动检测合规缺口，包含三个组件：1) 基于知识图谱的 RAG，将生成 grounding 在含 12847 条 SEC / MiFID II / Basel III 条款的图上；2) 共享 LEGAL-BERT 编码器的多任务义务抽取，融合 NER、deontic 分类、跨引用消解；3) 基于严重程度的合规缺口打分。在自有 benchmark 上 ComplianceNLP 在 gap detection 上取得 87.7 F1，相比 GPT-4o+RAG 提升 +3.5 F1。

INSIGHT这是「Knowledge-Graph-Augmented RAG」打过纯向量 RAG 的具体证据：当查询本身需要满足多条件交叉（条款引用、责任主体、生效时间）时，向量相似度往往找不到「全部条件成立」的文档子集，必须借助 KG 上的子图匹配。落地启示：在搜索关注「关系约束 query」（例如「同时满足 X 和 Y 的帖子」）时，纯 dense retrieval 会输给 KG-augmented 检索；可以投入产出比较高地从「构建小型领域知识图」入手，作为现有 RAG 的补强而非替换。

Dongxin Guo, Jikun Wu, Siu Ming Yiu
