Efficient Rationale-based Retrieval: On-policy Distillation from Generative Rerankers based on JEPA

针对 rationale-based 检索需要对 query-document 联合编码导致计算成本过高的问题，提出 Rabtriever：先训练一个把 document 放在 query 之前、用 log p 生成相关性分数的 LLM 生成式重排器作为教师，再通过基于 JEPA（Joint-Embedding Predictive Architecture）的 on-policy 蒸馏，把教师能力压缩到独立编码 query 与 document 的双塔模型，从而保留对查询-文档的深度理解但显著降低线上推理成本。在多个检索基准上 Rabtriever 接近 cross-encoder 重排器的效果，同时具备双塔模型的延迟优势。

KEY INSIGHT · 对业务意味着什么把昂贵的 LLM 生成式重排器作为教师、用 JEPA 表征对齐做策略内蒸馏到双编码器，是社区 UGC 搜索的高 ROI 路径——线上仍跑廉价的双塔召回，但语义理解水平接近重排器。值得借鉴的设计点：(1) 让教师按 'doc 在前 + query 在后 + 生成相关性' 的范式打分，可以充分利用 LLM 长上下文与因果注意力的判别能力；(2) on-policy 而非 offline 蒸馏避免学生分布漂移。社区短文本搜索的 query-doc 语义鸿沟很大，这套方案可以直接落到现有 Faiss/HNSW 召回栈上。

R$^3$AG: Retriever Routing for Retrieval-Augmented Generation

针对 RAG 中 'one-size-fits-all' 检索范式的瓶颈，提出 R$^3$AG 路由框架：把检索器能力解耦为 '检索质量' 和 '生成有用性' 两个可学习维度，根据 query 动态选择最适合的检索器。与之前只看语义相关性的路由不同，R$^3$AG 显式建模检索结果对下游生成器最终回答正确性的贡献。在多个 RAG benchmark 上相比 BM25/Dense/Hybrid 的最佳单一检索器和现有路由方法都有显著提升。

INSIGHT传统检索质量指标（nDCG、Recall）和下游任务收益并不完全等价——一篇高相关度文档可能因为表述方式问题反而干扰生成器。社区搜索若引入 RAG/生成式回答，需要把 '召回是否有助于最终回答' 作为新的优化目标。可借鉴的设计：(1) 用 'retrieval quality + generation utility' 双维度评分把召回器能力剖面化；(2) Query 级路由可以在 BM25/Dense/LLM 召回之间动态切换，对长尾 query 用更重的语义召回，对头部 query 用 BM25 + 缓存。

Beyond Static: Related Questions Retrieval Through Conversations in Community Question Answering

针对 Stack Overflow 这类社区问答平台 (cQA) 的相关问题检索任务，作者提出 TeCQR：通过 tag 增强的澄清问题构建用户-系统多轮对话，把静态匹配转化为对话式细粒度匹配。框架还包含一个噪声容忍模块，用问题与 tag 之间的语义相似度对噪声 tag 进行加权过滤。在公开 cQA 基准上 TeCQR 相比传统的双塔与 cross-encoder 静态匹配模型有稳定的 MRR/nDCG 提升，特别是在长尾查询和模糊查询上提升更明显。

INSIGHT完全对应社区 UGC 搜索场景：用户输入往往不完整、含糊，传统静态相关度匹配缺乏上下文。该工作的可借鉴点：(1) 用 tag 系统反向构造澄清问题，是冷启动构造对话式数据的低成本路径，社区平台的话题/标签体系都可以这样玩；(2) 显式的 noise-tolerance 模块对真实社区里 tag 噪声很高的现实非常关键——直接把 tag 当 query 的扩展会被噪声反噬。建议社区搜索引擎尝试把搜索框升级为 '理解-澄清-检索' 的轻量交互式流程。

A Parametric Memory Head for Continual Generative Retrieval

生成式检索 (GenIR) 把整个检索过程压缩到一个直接从 query 解码 docid 的神经模型中，但这种 'model-as-index' 范式难以适应文档集动态变化——传统的全量微调或 PEFT 都会触发灾难性遗忘。作者提出参数化记忆头 (Parametric Memory Head, PMH)：在主模型基础上增加一个独立的、可增量更新的记忆头，新文档只需训练记忆头即可被索引，主体参数保持冻结。实验显示 PMH 在多轮文档更新后比标准 fine-tune 与 LoRA 在历史文档保留率与新文档召回率上都有大幅提升。

INSIGHT生成式检索是 TIGER/HSTU 之后搜索/推荐范式革新的关键方向，但 'model 即索引' 必然遇到增量更新难题，这是工业落地的核心阻塞点。PMH 的思路具有极高借鉴价值：(1) 把 docid 编码能力从主干表征中分离到一个轻量级的可插拔头，工程上类似把倒排表从主模型剥离；(2) 这种 '冻主干 + 增量头' 模式天然适合 UGC 社区每天百万级新增帖子的场景。但要落地还需解决 docid 编码方式（Semantic ID vs hash ID）与延迟约束。

Learning to Route Queries to Heads for Attention-based Re-ranking with Large Language Models

把 LLM 当作零样本细粒度重排器时，现有方法要么聚合所有 attention head 的信号，要么用启发式规则静态选一组。但作者发现 informative 的 head 在不同 query/domain 下会变化，简单聚合多 head 还会因冗余/冲突反而掉点。本文提出 RouteHead：训练一个轻量路由器把每个 query 映射到最优 head 子集，相关性分数只从被选中的 head 聚合。由于缺乏 query-head 监督标签，作者通过离线搜索构造伪标签训练 router。在 BEIR 等多个 benchmark 上 RouteHead 相对所有 head 平均与人工选 head 的基线分别有 3-7 nDCG 点提升。

INSIGHTLLM 作零样本重排的本质是 attention 信号的 'informational geometry'——head 的判别力随 query 漂移。这篇启发了几个工程实践：(1) 真实社区搜索的 query 多样性极强 (代码、生活、情感)，不应共用一组 head；(2) 用离线 grid search + 蒸馏 router 的范式，可以在不增加 LLM 推理成本的前提下显著提升 attention-based 重排质量；(3) 这种 'meta 层稀疏路由' 思路可以推广到 prompt 选择、专家模型选择，是把 LLM 系统化的重要基本功。

Yuxing Tian, Fengran Mo, Zhiqi Huang, Weixu Zhang, Jian-Yun Nie

MMEB-V3: Measuring the Performance Gaps of Omni-Modality Embedding Models

GoogleWWaterloo

多模态 embedding 的现有 benchmark 大多只覆盖部分模态，难以系统评估全模态表征能力。作者提出 MMEB-V3：覆盖 text/image/video/audio + agent 场景的全模态 embedding benchmark，并构造了 OmniSET（语义等价的跨模态实例对），用以解耦 '语义相似度' 与 '模态偏置'。在 30+ 主流 embedding 模型的系统评测中发现三个关键现象：(1) 模型在跨模态检索时常常误召回同模态结果；(2) 模型对模态偏置的敏感度差异巨大；(3) 当前没有任何模型在所有模态对上达到一致水平。

INSIGHT对社区搜索这种以文本为主、但越来越含图片/视频/音频的场景，全模态 embedding 的选型是关键工程决策。该 benchmark 可以直接拿来体系化测试候选模型，避免 '某模态强但其他模态崩塌' 的隐患。值得借鉴的方法学：(1) OmniSET 的语义等价构造法可以套用到自家业务，做内部模型的模态鲁棒性测试；(2) 模型对模态的偏置必须先解耦再评估，否则离线 nDCG 与线上多模态混排表现不一致是常见 trap。

Prism-Reranker: Beyond Relevance Scoring -- Jointly Producing Contributions and Evidence for Agentic Retrieval

面向 RAG 与自主 agent 的下游消费者，传统重排器只输出标量相关性分数，迫使 agent 把整篇文档塞进 LLM 上下文，浪费大量 token 在边角内容上。作者提出 Prism-Reranker：基于 Qwen3.5 训练 0.8B/2B/4B/9B 四种规格的重排器，除了 yes/no 相关性判断外，命中 yes 时还会输出 (i) contribution statement（这篇文档对 query 有什么贡献）和 (ii) evidence passage（剥离冗余、只保留 query 相关信号的自包含重写）。训练混合点态蒸馏（来自商业 reranker API）与有监督微调。

INSIGHT把重排器从 '打分器' 升级为 'contribution + evidence 提取器'，正是社区搜索向 'AI 总结答案' 演化的关键基建。具体启发：(1) 让重排同时产出证据片段，可以减少下游 LLM 的 prompt token 60%+，显著降低 RAG/智能搜索成本；(2) 蒸馏自商业 reranker API 的范式可以快速冷启动 evidence rewrite 能力；(3) 0.8B 起步的多档规格便于在社区搜索的不同 traffic 等级（首页、长尾、深度页）灵活部署。

MEG-RAG: Quantifying Multi-modal Evidence Grounding for Evidence Selection in RAG

多模态 RAG (MRAG) 现有评估指标多依赖启发式 position-based confidence，难以判断检索结果是否真正支撑答案语义核心。作者提出 MEG（Multi-modal Evidence Grounding）指标：聚焦答案中的高 IDF 信息词 anchor，量化检索证据对 anchor 的支撑度。基于 MEG 训练一个多模态重排器 MEG-RAG，让重排目标显式对齐到证据-语义锚点。在 OK-VQA、InfoSeek 等多模态 QA benchmark 上 MEG-RAG 比 vanilla MRAG 在最终 QA 准确率上提升 3-5 个百分点。

INSIGHT评估指标驱动训练目标——这篇用 MEG 指标作为重排器的监督信号，是把 'evidence supports answer' 作为新优化目标的一种实现。借鉴价值：(1) 高 IDF anchor 词的语义支撑度是一个比 cosine similarity 更稳健的相关性代理；(2) 对社区里图文混合的 UGC 搜索，多模态重排目标若不考虑模态间证据支撑，往往是 '看起来匹配但实际无信息' 的假相关——MEG 思路可以给图文混搜带来更稳定的指标。

Xihang Wang, Zihan Wang, Chengkai Huang, Quan Z. Sheng, Lina Yao

S2G-RAG: Structured Sufficiency and Gap Judging for Iterative Retrieval-Augmented QA

迭代式 RAG 的核心难题是控制 'next retrieval query' 与 '何时停止'，否则证据链不全或冗余文本干扰后续推理。作者提出 S2G-RAG：用一个显式 controller S2G-Judge，每轮判断当前证据 memory 是否够支持回答；不够则输出结构化的 'gap items'（缺失信息描述），并据此构造下一轮的检索 query。框架还维护一个 sentence-level Evidence Context，从历史检索中抽取 compact 子集减少噪声累积。在 HotpotQA、2WikiMQA、MuSiQue 等多跳 QA benchmark 上稳定优于 IRCoT、Self-Ask 等迭代基线。

INSIGHT把 '检索充分性' 显式当作一个判别任务，而非隐式靠生成器自主停止，是迭代检索系统稳定性的关键。社区里的多步骤问答（'我家路由器闪红灯怎么办' → 需要先确认型号）很合适这种范式。可借鉴：(1) gap items 的结构化输出比自由文本更可控，便于映射到下一跳 query 模板；(2) 句级 Evidence Context 缓存避免 'context bloat'，对社区移动端 RAG 的延迟与成本都关键。

Lost in Decoding? Reproducing and Stress-Testing the Look-Ahead Prior in Generative Retrieval

生成式检索常用 trie-constrained beam search 解码 docid，但在有限 beam 下相关 prefix 容易被早期剪枝。PAG (Planning Ahead in Generative Retrieval) 通过 simultaneous decoding 计算文档级 look-ahead prior 缓解此问题。本文系统重现 PAG 并对其解码行为做压力测试：在原作者放出的 checkpoint 上验证主要结论，但发现 (1) 看似稳健的提升对 beam size 异常敏感；(2) look-ahead 的收益在长 docid 与高度倾斜分布上明显衰减；(3) 部分提升其实来自 doc-level normalization 而非 'planning' 本身。

INSIGHT极少数论文愿意做这种严肃的可复现性研究，但它对工业团队意义重大——盲目复用 GenIR 论文 trick 容易踩坑。该工作给生成式检索的工程师三个警示：(1) Beam size 是 GenIR 系统的隐性超参，必须像 batch size 一样在 ablation 中显式扫；(2) 'look-ahead' 类方法的收益和 docid 长度强相关，TIGER 风格 Semantic ID 与 hash ID 的表现不可类比；(3) 当看到 'X% nDCG 提升' 时，先去查论文是否做了 doc-level normalization 控制。

Kidist Amde Mekonnen, Yongkang Li, Yubao Tang, Simon Lupart, Maarten de Rijke
