RedParrot: Accelerating NL-to-DSL for Business Analytics via Query Semantic Caching

小红书提出 RedParrot：面向企业级 NL-to-DSL 业务分析场景的语义缓存框架。它观察到用户查询在结构上高度重复，提出离线构建归一化的 "query 骨架"（query skeleton），将新请求与缓存骨架做语义匹配后直接复用并改写对应的 DSL，绕开多阶段 LLM 流水线。论文呈现了离线骨架挖掘、在线骨架匹配与 DSL 适配三个核心组件，并展示其在小红书电商/广告分析任务上的延迟与成本下降效果。

Domain Fine-Tuning vs. Retrieval-Augmented Generation for Medical Multiple-Choice Question Answering: A Controlled Comparison at the 4B-Parameter Scale

在 4B 量级开源模型上做 "领域微调 vs RAG" 的对照实验：固定模型大小、prompt 模板、解码温度、检索流水线和评测协议，仅变化 (i) 是否进行领域适配（Gemma 3 4B vs MedGemma 4B，均为 4-bit 量化、Ollama 部署）和 (ii) 是否注入医学知识库检索段落。在 MedQA-USMLE 1,273 题、3 次重复（共 15,276 次调用）下，领域微调相对通用 4B 提升多数投票准确率 +6.8pp（53.3% → 60.1%）；论文进一步分析了 RAG 与微调的可叠加性。

INSIGHT对实践者最有价值的不是结论本身，而是这种 2×2 受控实验设计：在线上要决定 "小模型微调还是接 RAG" 时，常被混入 prompt、检索器、解码参数等多变量噪声。社区搜索语义匹配/相关性模型选型时，可复用本文方法——固定除变量外的全部条件、跑足够多次取多数投票，得到的结论才能作为线上路由决策依据，而不是凭一次 demo 拍板。

Avi-ad Avraam Buskila

Citation-Driven Multi-View Training for Patent Embeddings: QaECTER and Sophia-Bench

InriaQatent

面向专利检索提出两件事：(1) Sophia-bench——10,000 query × 75,000 文档的大规模专利检索 benchmark，覆盖 10 年、8 个 IPC 技术分区与 12 个司法管辖区，包含 12 种 query 类型（结构化字段、AI 生成摘要等），并用引用关系 + 新提出的 InScope 域相关性指标作为 ground truth；(2) QaECTER——一个 344M 参数的领域 embedding 模型，基于专利引用 "多视图" 对比训练（同族、引用、被引等关系），在 Sophia-bench 多种 query 类型上系统超越通用 embedding。

INSIGHT对社区搜索 embedding 训练的启发是：单一 query-doc 对的训练数据无法表达短文本搜索的多面性。可以借鉴 "多视图" 思路，从社区图结构提取出 "同主题贴-收藏关系-同作者-同评论用户" 等多种正样本视图，构造一个多源对比损失。再加上类似 InScope 的领域相关性指标做评测过滤，能让 344M 量级的 base 模型在垂直语料上击败大规模通用 embedding，是工业可承受的 ROI 区间。

Younes Djemmal, You Zuo, Kim Gerdes, Kirian Guiller

Geometric Analysis of Self-Supervised Vision Representations for Semantic Image Retrieval

UUniversity of Costa Rica

在向量库 + 近邻检索（ANN）这套现代 CBIR 栈下，系统评估自监督视觉表征（DINO、MAE、I-JEPA 等）的几何性质对检索性能的影响。核心结论：现代 SSL 方法产生的表征常常高度各向异性、偏度大（high anisotropy + skewness），即使在自身线性探针 benchmark 上很强，但分区式（IVF）和哈希式（LSH）ANN 检索都会被显著拖垮；只有暴力 / 图索引能保住其相对优势。论文给出了 isotropy / kurtosis 等几何指标到 ANN recall 的相关性分析。

INSIGHT这条 "在线 ANN 性能受 embedding 几何分布影响" 的结论对所有上线 dense retrieval 的团队都是直接生产警告。社区搜索的 query/doc embedding 上线前，必须把 isotropy（如 mean cosine to centroid、explained-variance ratio）作为评测指标的一部分；并在训练中加入白化（whitening）、各向同性正则项或对比学习中显式去除 hubness，才能保证向量库选型（IVF-PQ、HNSW、ScaNN）不被几何分布坑掉一大段 recall。

Esteban Rodríguez-Betancourt, Edgar Casasola-Murillo

Improving Robustness of Tabular Retrieval via Representational Stability

RRPIIIBM Research

Transformer 表格检索系统会把结构化表格 "压平" 成 token 序列，使检索结果对序列化方式（csv / tsv / html / markdown / ddl）极度敏感，即使表格语义不变。作者指出语义等价的不同序列化产出的 embedding 在多个 benchmark 与 retriever（MPNet、E5 等）上差异巨大，于是把这些序列化视为同一语义信号的 "噪声视角"，用其几何中心（centroid）作为典则表征。实验显示 centroid 表征在多个 benchmark 上聚合 pairwise 比较稳定优于任意单一格式。

INSIGHTcentroid 平均这一招几乎是免训练的鲁棒性提升工具，思想完全可以迁移到社区搜索短文本：同一帖子在标题、正文、话题标签、评论摘要等不同 view 下编码出的 embedding 也会差异显著。线上做 doc 侧编码时，可以为同一帖子并行算 N 个 view 的 embedding 后取 centroid 入库，等价于在召回阶段做 view-level ensemble，对 query rewriting 漂移、正负样本不一致等噪声都更鲁棒，且不增加召回延迟。

Kushal Raj Bhandari, Adarsh Singh, Jianxi Gao, Soham Dan, Vivek Gupta

GLIER: Generative Legal Inference and Evidence Ranking for Legal Case Retrieval

针对法律检索 (LCR) 中口语化 query 与专业法律文书之间的语义鸿沟，提出 GLIER：把检索重新表述为对潜在法律变量的推理过程。两阶段设计：(1) Joint Generative Inference 用统一 seq2seq 一次性生成 "罪名 + 法律要素" 等潜在指标，并通过联合生成强制逻辑一致性；(2) Multi-View Evidence Fusion 把生成置信度、结构信号与词汇信号融合用于精排。可解释性优于传统 dense 黑盒匹配。

INSIGHTGLIER 的精排结构思路很值得社区搜索借鉴：与其把 query → doc 当成一段黑盒匹配，不如显式生成出一组 "中间语义变量"（社区场景如 query 意图标签、目标人物、内容垂类、情绪极性），用生成置信度作为一路打分，再融合 BM25/dense 词法/向量信号做多视图精排。这条 "先生成再融合" 的 reranking pattern 比单纯增大 cross-encoder 更可解释，也更容易在线 A/B 拆解收益归因。

Minghan Li, Tianrui Lv, Chao Zhang, Guodong Zhou

StratRAG: A Multi-Hop Retrieval Evaluation Dataset for Retrieval-Augmented Generation Systems

推出 StratRAG：基于 HotpotQA distractor 设置构造的开源多跳 RAG 检索 benchmark，含 2,200 条样本（bridge / comparison / yes-no 三类问题），每条配 15 文档候选池（恰好 2 篇 gold + 13 篇主题相关干扰）。对 BM25、dense（all-MiniLM-L6-v2）、混合融合三种策略评测 Recall@k、MRR、NDCG@5：混合检索整体最佳（Recall@2 = 0.70、MRR = 0.93），但 bridge 类问题仍显著难（Recall@2 = 0.67），作者把这指向后续基于 RL 的检索策略方向。

INSIGHT对社区搜索的两个直接启示：(1) 在自有 query log 上构造类似 "gold + 主题相关干扰" 的评测集是当前最有性价比的离线评测设计——纯 random 干扰会让所有模型分数虚高，无法区分；(2) 即便混合 BM25+dense 已能拿到 0.70/0.93 量级，bridge / 多跳 / 多约束 query 仍是结构性短板，下一阶段投入应该集中在 query 改写或 RL-based 多步检索，而不是继续挪 dense 模型参数量。

Structure Guided Retrieval-Augmented Generation for Factual Queries

提出 "Exact Retrieval Problem (ERP)"：传统 RAG 仅靠向量相似度难以保证返回结果同时满足事实 query 中的多个复合条件（语义噪声大）。SG-RAG 把检索建模为基于 embedding 的子图匹配（subgraph matching）任务，先在知识子图上找出同时满足所有 query 条件的拓扑结构，再用拓扑结果引导 LLM 生成答案，从而显式处理 "多条件 AND" 的事实问题。

INSIGHT社区搜索里大量复杂 query 形如 "上海 周末 亲子 室内 平价"——本质上是多约束合取条件，纯向量召回容易丢约束。SG-RAG 提供的范式是：把约束抽成结构化字段（地点 / 时间 / 适用人群 / 室内外 / 价格档），先在结构化倒排（或属性图）上做硬约束过滤，再用 dense embedding 做内容精排。这种 "硬约束子图召回 + 向量重排" 的两阶段比纯 dense+post-filter 更可控，也更能保证 query 条件全满足。

Miao Xie, Xiao Zhang, Yi Li, Chunli Lv

FinGround: Detecting and Grounding Financial Hallucinations via Atomic Claim Verification

HKU

面向金融文档 QA 的三阶段 verify-then-ground pipeline。Stage 1 做文本+表格的 finance-aware 混合检索；Stage 2 把答案分解为原子陈述（atomic claims），按六类金融命题（事实、定义、量化指标、计算结果、引用、推断）分类后用 type-routed 验证策略（含公式重构）逐条校验；Stage 3 把不被支持的陈述用段落级 / 表格单元格级 citation 重写。论文指出现有 hallucination 检测器漏掉了 43% 的计算类错误（需要对结构化表格做算术再核验）。

INSIGHT对社区 UGC 搜索 + LLM 答案聚合（如帖子摘要/智能问答）场景的最大启示：把 LLM 输出拆为 atomic claim 再按类型路由验证，是比 "整段答案 self-consistency" 远更精细且成本更可控的可信度方案。可以借鉴 type-routed 思想，把社区答案拆为 "事实陈述 / 个人体验 / 价格信息 / 时效信息"，对不同类型用不同的检索源和验证策略（如价格走外部抓取、时效走帖子时间过滤），减少 LLM 编造对线上展示的风险。

Dongxin Guo, Jikun Wu, Siu Ming Yiu

IntrAgent: An LLM Agent for Content-Grounded Information Retrieval through Literature Review

提出新任务 IntraView——基于 "已提供文献内容" 进行细粒度信息检索（要求严格 grounded），并提出 IntrAgent：模仿人类阅读文献的两阶段 LLM agent。Stage 1 "Section Ranking"：用结构知识增强的 reasoning 对各 section 排序，先选最可能含有答案的部分；Stage 2 "Iterative Reading"：在选中的 section 中迭代抽取关键细节并合成简洁、内容 grounded 的回答。论文同步发布配套数据集与基线对比。

INSIGHTIntrAgent 的 "先排版块再迭代精读" 范式对长文档社区搜索（如长帖、攻略类内容）非常对口：与其一上来用 dense embedding 做整篇召回，不如先做 "section / 段落级" 排序选出 top-3 最相关段落，再让 LLM 在这些段落上做迭代抽取式问答。这样能极大降低 LLM context 成本、提升答案 grounding 质量，也能直接复用现有段落召回基础设施作为第一阶段。

Fengbo Ma, Zixin Rao, Xiaoting Li, Zhetao Chen, Hongyue Sun, Yiping Zhao, Xianyan Chen, Zhen Xiang
