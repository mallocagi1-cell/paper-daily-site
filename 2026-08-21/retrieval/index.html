FinRCA-Bench: Benchmarking Evidence Retrieval and Reasoning for Financial AI Systems

FinRCA-Bench把“能否拿到正确证据”从最终问答准确率中拆出来，构造了覆盖14张业务表的2,250个应付账款到银行对账案例，其中含1,500个注入故障、15类根因和750个正常或困难负例。作者比较规则/SQL、机器学习、稠密检索、关系扩展与TPGR，发现加入更强检索后，必需记录宏平均召回率从0.83%升至77.70%，16分类准确率从2.05%升至72.44%。

Predicting the Benefit of Retrieval Augmentation in Open-Domain Question Answering

论文研究“什么时候检索反而会伤害回答”，比较检索信号、答案特征、回答与证据的一致性，以及探测语言模型内部状态等预测器。作者据此构建按问题动态选择“检索”或“不检索”的选择性RAG框架；在开放域问答实验中，选择性应用检索的答案质量超过对所有问题都检索的策略，论文包含3张表和4幅图。

INSIGHT对社区搜索而言，检索不是越多越好：短、明确且已有高置信候选的query可以直接走轻量排序，低置信或证据不足的query再触发扩展、混合召回或LLM重排。建议把“是否值得扩大候选集”建成一个独立门控模型，用离线答案质量、点击后满意度和延迟共同校准，而不是只优化固定召回率。

Or Dado, David Carmel, Oren Kurland

LACONIC: Dense-Level Effectiveness for Scalable Sparse Retrieval via a Two-Phase Training Curriculum

📖 深度解读 · 10 分钟 →

LACONIC针对稠密检索的GPU与内存成本，提出基于Llama3的1B、3B、8B学习稀疏检索器。训练分两阶段：先用弱监督预训练让因果模型具备双向上下文，再用精选困难负例进行高信号微调；8B版本在MTEB Retrieval上达到60.2 nDCG@10，缩小了学习稀疏与稠密模型的效果差距。

INSIGHTUGC短文本的实体词、口语词和新词仍需要倒排索引的精确命中，LACONIC提供了把语义扩展写回稀疏词项空间的方向。落地时可先以小尺寸模型生成稀疏权重，保留BM25兜底，再用困难负例和query-帖子点击对训练，重点观察索引膨胀、召回延迟与nDCG的折中。

How GPU acceleration builds billion-scale vector indexes on Amazon OpenSearch Service

AWSNVIDIA

AWS介绍在Amazon OpenSearch Service上构建十亿级向量索引的工程方案：用NVIDIA cuVS和GPU工作节点承担计算密集的索引构建，同时保留现有CPU基础设施在线服务查询。核心设计是把离线建索引与线上检索解耦，在不重写服务层的情况下提升大规模向量检索的吞吐与延迟表现。

INSIGHT对于社区搜索，索引重建常常比模型推理更容易成为发布瓶颈；GPU建索引、CPU在线服务的分层架构能降低迁移风险。可先在影子索引上验证新embedding和量化方案，再按分片并行构建、灰度切换，监控索引构建时间、P95延迟、召回损失与硬件成本，而不是只看单机QPS。

AMU at RAG4Reports 2026 Task B: A Practical Multilingual RAG Pipeline for Citation-Grounded Reports

AMU的RAG4Reports系统把全查询检索、可选query改写、Qdrant稠密召回、cross-encoder 重排、多样性上下文选择和结构化生成串成可复用流水线。最佳提交使用bge-m3、bge-reranker-v2-m3与GPT-5.1，在官方榜单上取得F1=0.4351、sentence_support=0.8280、nugget_coverage=0.3403，说明证据支撑较强但覆盖仍不完整。

INSIGHT它的价值不在某个单一模型，而在把召回、重排、证据选择和生成的接口边界固定下来。社区UGC搜索可借鉴“多样性上下文选择”避免同质帖子挤占结果，并把sentence support式的证据覆盖指标加入nDCG、CTR之外，用于评估结果是否真正支撑用户意图。

GenAIus at SemEval-2026 Task 8: Beyond Retrieval with Relevance-Aware RAG for Faithful Multi-Turn Generation

GenAIus在SemEval-2026 Task 8中采用高召回词法检索、双embedding稠密重排、RRF、LLM相关性判断和严格证据约束生成的多阶段流水线。论文的核心观察是，先做相关性感知过滤，再限制生成只能使用证据，能够提升多轮RAG的faithfulness与整体表现；该系统发表于2026年7月的SemEval论文集。

INSIGHT对于短query和多轮上下文，不要把所有LLM改写都直接送入同一个召回器；应按词法精确性、语义覆盖和证据置信度路由到不同候选通道。可把LLM相关性判断放在小候选集上，并用严格证据约束拦截“召回正确但生成越界”的结果，降低UGC场景中的幻觉和错配。

Reducing Technician Search Burden: A Multimodal RAG for Cessna 172 Maintenance Manual

论文针对维修手册中步骤、图表、警告和规格信息难以定位的问题，构建能检索多模态页面的MMR，并把检索页面交给视觉语言模型生成回答。作者用覆盖四类需求的合成query评测，MMR达到93.37%的Recall@5，展示了页面级视觉结构对专业检索的补充价值。

INSIGHT社区帖子同样常把文字、图片、截图和评论上下文混在一起，纯文本embedding可能漏掉关键证据。可先在query理解阶段识别“图示/外观/步骤/规格”等意图，再并行召回文本和视觉页面，以页面级候选融合后重排；上线时要单独监控图文query的Recall@5和首屏点击。

GreekBarRetrieval: A Benchmark for Greek Statutory Retrieval

GreekBarRetrieval构建了283个法律考试问题与6,308条候选法规组成的检索基准，比较3种BM25变体和9种稠密检索器。结果显示原生稠密检索在Recall@100上明显优于原生稀疏检索；但十轮ReAct式LLM查询改写进一步提升BM25，使其取得所有测试检索器中最好的nDCG和MAP，并优于伪相关反馈、稀疏稠密融合和英文翻译。

INSIGHT对UGC短文本，query改写的收益取决于它是否补足领域术语，而不是是否生成更多词。可采用“原query+受约束改写”的双路召回，并通过实体、意图和候选集合反馈限制改写漂移；离线同时看Recall@100、nDCG、MAP，防止改写提高召回却污染首屏相关性。

Ernest Beta, Odysseas S. Chlapanis, Dimitrios Galanis, Ion Androutsopoulos

StocksTalk: A Voice-Enabled Conversational Agent for Structured Query Generation over Web Data

StocksTalk把语音识别、检索增强约束抽取、schema-grounded SQL生成、规则校验和人工确认串成可解释的结构化查询系统。作者构造了覆盖多种投资策略和噪声条件的150条语音金融query，实验表明检索grounding、受约束生成和交互验证共同改善约束抽取、SQL可执行性、逻辑一致性和多轮稳定性。

INSIGHT搜索query理解可以借鉴它的“中间产物可审计”设计：把实体、属性、过滤条件、排序偏好和改写结果结构化保存，而不是只输出一个黑盒向量。对社区搜索尤其要把硬约束送入过滤或高权重特征，把软偏好留给排序，并为低置信解析提供人工或规则兜底。

PLASMA: A Layout-Aware Benchmark Reveals Memory Layout Matters for Graph-based ANNS on GPU

PLASMA把GPU图近邻索引的拓扑和内存布局拆开评测，允许在统一搜索内核下重新排列节点，分析图结构与硬件访存的独立影响。实验显示，仅做顶点重排就能在保持检索准确率的同时带来最高80%的QPS提升，常见收益约为10%至30%，为百万级向量库优化提供了可操作基准。

INSIGHT向量召回的瓶颈不一定来自embedding模型，节点布局和访存局部性也会直接改变线上吞吐。社区平台可以在固定召回质量的前提下，对HNSW或其他图索引做布局A/B，分别记录QPS、P95、内存带宽和Recall@K；先优化索引物理布局，再决定是否换更大的模型。

Yutaro Oguri, Mai Nishimura, Yusuke Matsui
