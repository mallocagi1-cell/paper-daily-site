  1. 1. ToolRec: Calibrated Preference Alignment for Query Recommendation in On-Device Assistants

    LLM 显著提升了生成式 query 推荐，但已有对齐多面向标准 chatbot，不适配端侧助手——用户主要期望快速调起系统级工具。直接用真实点击日志对齐会因用户活跃度差异、未强调执行导向 query 引入严重噪声。ToolRec 提出校准的偏好对齐，面向 on-device 助手的工具调用 query 推荐。

    出现于日报：06-09

  2. 2. TrustMargin: Training-Free Arbitration between Parametric Memory and Retrieved Evidence in Large Language Models

    LLM 回答知识密集问题同时用参数化记忆与检索证据，但两者都非一致可靠：检索能补空缺，干扰段落也可能盖过正确的闭卷答案。本文把这种生成后的来源冲突建模为答案级来源仲裁：给定同一冻结模型的 Direct 与 RAG 答案，判定信哪个。提出 TrustMargin，免训练、即插即用。

    出现于日报：06-09

  5. 5. GraphER: An Efficient Graph-Based Enrichment and Reranking Method for Retrieval-Augmented Generation

    针对 RAG 在多源、复杂查询下语义检索难以召回完整证据的问题，提出 GraphER：在查询时依据数据的组织结构与邻近关系临时构建图，再用图排序挑选 top 文档。方法不需要额外的图数据库基建，可直接接入现有向量库，引入的查询延迟开销很小。在表格检索、多跳检索、长文档三类基准上检索完整性持续提升。

    出现于日报：06-13

  6. 6. Agent-Orchestrated Adaptive RAG: A Comparative Study on Structured and Multi-Hop Retrieval

    系统对比了把 agentic 能力（动态查询拆解、迭代检索、带上限的自反思评估环）加到 RAG 上的实际收益。在 DevOps 知识库与 MuSiQue 多跳基准上发现：查询拆解在结构化领域提升明显（DevOps 总分 +0.04、MRR +0.17），却会拉低多跳任务的排序精度；自反思提升了引用准确率但带来显著延迟。作者结论是 agentic 增强并非普遍有益，应按查询特征做成本敏感的选择性启用。

    出现于日报：06-13
