2026-08-17 ~ 08-23 · AI 搜索

  1. 1. Dense Expands, Sparse Anchors: Channel-Asymmetric Query Expansion for Hybrid Retrieval

    论文研究混合检索中查询扩展与融合截断深度相互耦合的问题，提出 DESA：让 LLM 生成互补参考段落，用正交残差扩展稠密查询，同时用得分乘积把词法线索锚定到稀疏通道。作者在 7 个 BEIR 数据集上使 nDCG@10 提升 3.82%、Recall@20 提升 2.38%，稠密和稀疏访问深度分别下降 36.90% 和 36.56%。

    出现于日报：08-19

  2. 2. Query Drift Compensation: Enabling Compatibility in Continual Learning of Retrieval Embedding Models

    论文关注检索 Embedding 持续学习中的索引失配问题：文档已用旧模型编码，新模型上线后查询向量进入不同空间，通常必须重建全量索引。作者对查询端和文档端做 Embedding 蒸馏，并提出 Query Drift Compensation，将新查询投影回旧文档空间。实验报告在无需重建索引的条件下显著改善持续检索效果，并开源代码。

    出现于日报：08-17

  3. 3. Static Pruning Across Sparse Retrieval Regimes: What Transfers, What Breaks, and What Still Helps

    论文跨 3 个检索引擎、2 个基准、SPLADE 与 V3-GTE 两类查询密度，完成 1,140 组静态剪枝实验，并用 TREC DL 2019/2020 深度判断复核。索引侧剪枝稳定带来 1.2–6.6 倍延迟下降和 18–82% 索引缩减；在 BMP 上结合文档与查询剪枝可获得 2.5 倍加速，同时 nDCG@10 与精确基线相差不超过 0.003。

    出现于日报：08-19

  4. 4. Polaris: Learning to Generate Table Descriptions from Retrieval Feedback

    Polaris面向NL2SQL中的表检索，解决LLM生成表描述偏重流畅性、却未必提升可检索性的问题。它从查询—表相关性标注生成多个描述，用BM25效果排序构造偏好对，再以DPO训练描述生成器，并先扩展缩写的表名和列名以缓解词汇不匹配。多个表检索基准上，Polaris通常以显著幅度超过AutoDDG。

    出现于日报：08-20

  5. 5. IterCOMP: Reasoning-aware Adaptive Prompt Compression for Multi-hop Question Answering

    IterCOMP 针对文档过长、噪声干扰推理问题，提出无需训练的迭代压缩框架：把文档切成证据片段，用 bge-m3 稠密语义相似度与加权词法匹配筛选，让 LLM 判断证据是否足够，不足时生成下一跳追问。在 MuSiQue、2WikiMultiHopQA、HotpotQA 上取得 16.67/27.36、27.39/39.69、37.65/51.78 的 EM/F1，上下文比例为 0.14–0.37。

    出现于日报：08-18

  6. 6. FinRCA-Bench: Benchmarking Evidence Retrieval and Reasoning for Financial AI Systems

    FinRCA-Bench把“能否拿到正确证据”从最终问答准确率中拆出来，构造了覆盖14张业务表的2,250个应付账款到银行对账案例，其中含1,500个注入故障、15类根因和750个正常或困难负例。作者比较规则/SQL、机器学习、稠密检索、关系扩展与TPGR，发现加入更强检索后，必需记录宏平均召回率从0.83%升至77.70%，16分类准确率从2.05%升至72.44%。

    出现于日报：08-21

  7. 7. Sparse Coverage: Semantic Center Representations for Patent Prior-Art Retrieval

    Sparse Coverage针对长文本和结构化文档中单向量压缩多个技术要点的问题，把局部span向量映射到由覆盖型k-center目标选出的稀疏语义中心。文档通过激活邻近中心形成稀疏表示，既保留局部语义证据，又能复用倒排索引。CLEF-IP 2013实验显示，该方法在多种配置下达到或超过强稠密专利编码器的文档级召回，并保持有竞争力的段落级检索效果。

    出现于日报：08-20

  8. 8. RCEM: Embedder Equipped with Query Rewriting Skill for Robust Conversational Search in Distributional Shift

    RCEM 将 LLM 的查询改写能力蒸馏进对话式稠密检索器，通过让会话查询向改写后的独立查询对齐，减少对高质量 query-document 标注的依赖。作者在 QReCC、TopiOCQA 和 TREC CAsT 上验证了分布偏移鲁棒性，Recall@10 最高提升 20%，且无需重建原有文档索引即可兼容独立查询。

    出现于日报：08-19

  9. 9. SAG: SQL-Retrieval Augmented Generation with Query-Time Dynamic Hyperedges

    SAG 面向结构约束和多跳检索，避免维护全局知识图谱，而是把每个文本块表示为“事件+实体”的语义完整单元，形成保留多元关系的隐式超边。查询时以共享实体作为 Join Key，动态拼出局部事件邻域，同时保留原始证据。在 HotpotQA、2WikiMultiHopQA 和 MuSiQue 上均取得最佳检索及端到端结果，MuSiQue 的 Recall@5 达到 80.36%，比最强基线高 11.52 个百分点。

    出现于日报：08-17

  10. 10. Predicting the Benefit of Retrieval Augmentation in Open-Domain Question Answering

    论文研究“什么时候检索反而会伤害回答”，比较检索信号、答案特征、回答与证据的一致性，以及探测语言模型内部状态等预测器。作者据此构建按问题动态选择“检索”或“不检索”的选择性RAG框架；在开放域问答实验中，选择性应用检索的答案质量超过对所有问题都检索的策略，论文包含3张表和4幅图。

    出现于日报：08-21
