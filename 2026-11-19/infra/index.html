Efficient Wide-Beam Generative Retrieval with Model-Native Trie Decoding and Shared-Context Attention

生成式检索用短语义编号指向目录条目，用树约束的束搜索保证编号合法，但束宽一大，就会在整张词表上堆出大多用不上的分数张量，还要对同一段提示反复做注意力。一种模型原生的输出接口把标识树存成校验过的 GPU 张量，不再走 Python 自定义 logit 回调和整词表候选缓冲，只对紧凑码本候选打分，并流式计算全词表归一化项，在实数运算里保住原模型的合法 token 分数，而且不必重训。

SIMQ: A Single Graph-based Index for Multi-Vector Query

TTongji UniversityAAnt GroupXXi’an Jiaotong University

多向量检索把文档表示成一组 token 级向量，再用最大相似度打分，效果好，但算力贵，很难扩到大语料。现有近似方法要么每次查询都要算完整的中心交互矩阵并依赖 GPU 聚类，要么用与数据无关的压缩，召回不稳定，还得反复补偿。一种单图索引把所有 token 向量做数据感知采样聚类，只在簇中心上建一张图，再按 token 做图导航来近似最大相似度，既不用物化交互矩阵，也不依赖 GPU 加速。五个基准上，在接近的召回水平上，数据感知聚类的查询吞吐相当或更高，例如在 SciDocs 上每秒处理 121.6 次查询，高于 k-means 的 105.0 次。该方法已接入蚂蚁集团开源的向量检索库 VSAG，让多向量检索可以主要在 CPU 上扩出去。

Yifan Lu, Jiabao Jin, Xiaoyao Zhong, Peng Cheng, Xiangyu Wang, Haotian Li, Hua Chen, Junqing Chen 等 10 人

03 4.40

KVUse: Reusable-KV User Memory for Efficient LLM Recommenders

Meta

基于大模型的记忆增强推荐会维护一段自然语言用户档案，排序时再把它拼进提示，并在预填充阶段反复计算 KV cache。这些排序调用预填充很重、解码很短，还被频繁调用，而前缀缓存又帮不上忙，因为档案前面的文本每次都不同，于是重复预填充成了服务瓶颈。一种做法把用户档案存成可复用的 KV cache，而不是文本：用自蒸馏训练轻量 LoRA 写入器，让档案更新在解码时直接写出可复用缓存，模型在新位置和新上下文后也能读取，不必重算。定制调度器还会在当前批次计算时预取下一批档案缓存。在四个 InstructRec 数据集和 Llama-3.1-8B-Instruct 上，排序质量与完整预填充没有统计显著差异；饱和负载下，下游打分路径吞吐提高 4.0 倍至 4.5 倍。

Xin Guo, Qiang Zhang, Xiang Zhou, Arushi Rai, Siyu Lin, Yifan Wu, Xiang Shen, Lei Huang 等 11 人

CheckCo: Checkpoint-Coordinated Load Balancing for Skewed Event Streams at Scale

KKing

事件流很少均匀：少数热门键可以比其余键多出几个数量级的事件，接到它们的工作进程会被打满，整条流水线的吞吐也被卡住。一种检查点协同的负载均衡不需要事先统计，而是从实时流里估计每个键的频率：工作进程本地计数，在每个检查点屏障合并，再按估计频率把键切成若干分片并打包到各进程，用新的分区函数路由下一个检查点窗口。在一条每天处理超千亿条事件的生产流水线上，负载最重的进程全天只比平均值多处理 9.8% 的事件，不均衡比为 1.10，而按键路由在模拟中这一比值是 8.03。键分布变化会从下一个检查点起反映到路由里，任务重启后负载仍能保持均衡。

Muhammad Anis Uddin Nasir, Reza Sadraei

SGLang-Neuron v0.1.0: SGLang's Serving Stack on AWS Trainium

AWS

要在 AWS Trainium 上把大模型和扩散模型跑进统一的服务栈，过去缺少一套公开可用的 SGLang 后端。现在发布的首个公开预览版以 PyTorch 原生插件接入，由 SGLang 团队与 Annapurna Labs 共同开发，并在预览期内通过 AWS 深度学习容器提供支持。所有受支持的大模型共用一套全异步运行时，芯片上的解码步进可以背靠背进行；一步中的各解码层还能收进单次核心调用。Kimi-K3 可在多台 Trainium3 节点上做预填充与解码分离，GLM-5.2 能为智能体编程负载提供百万级 token 上下文。在 GPT-OSS-120B 上，把被驱逐前缀放进主机内存的二级缓存，可让输出吞吐提高 72% 至 75%。这让 Trainium 上的服务不再只是模型能跑通，而是开始按服务栈来优化。

SGLang Team, AWS Annapurna Labs

SpecSearch: Towards Hardware-Aware Efficient Speculative Decoding

UIUC

推测解码能加快大模型推理，但最优配置同时取决于负载、GPU 硬件和可用显存。例如在 RTX 5090 上，先进的草稿模型 DFlash 在低并发时吞吐可达到自回归的 3.50 倍，高并发且输出较短时却只有 0.76 倍，同一套方法在不同负载下完全换了方向。一套硬件感知的搜索引擎会在负载与 GPU 组合上联合选择解码策略、草稿长度和精度，先用解析代价模型收窄可行空间，再在多块 GPU 上做校准测量。在 RTX 5090、H100、L40 和 AMD MI300X 上，完整校准后的平均吞吐达到自回归的 2.01 倍、达到普通推测解码的 1.36 倍，两者都由 vLLM 提供服务。一个参数高效的预测器在未见过的 GPU 上也能接近这一结果，不必再做部署卡校准。

Selin Yildirim, Ali Zeyrek, Deming Chen

VisHead-Spec: Head-Routed Visual Attention for Multimodal Speculative Decoding

Meta

推测解码可以在保持目标模型输出的前提下加速视觉语言模型，但高并发时系统更受计算约束，加速会变弱；提示里长长的图像 token 还会让草稿预测更贵，块扩散草稿器在这种负载下的加速往往仍然有限。观察目标模型到草稿模型的跨模态信息流会发现，视觉注意力很稀疏：草稿只需少量键值头直接看图像，也只需看目标模型顶层的视觉特征。一种头路由方法因此让固定的一小部分键值头去读顶层图像特征，其余头只看文本。在 Qwen3-VL-8B 上，接受长度与块扩散基线相差不超过 0.3%；较大批次时，相对自回归的吞吐提升达到 16.0%，而对照草稿器为 9.5%。

Xin Guo, Arushi Rai, Xiang Zhou, Qiang Zhang, Siyu Lin, Xiangjun Fan, Lizhu Zhang

TAILROLL: Tail-Aware Rollout Acceleration for RL-Based LLM Post-Training

ÉÉTSHuaweiRRBC BorealisUniversity of Melbourne

大模型强化学习后训练的瓶颈常在滚动生成：响应长度拖着长尾，每一步都要等最长的那条，引擎因此空转。异步训练可以掩盖、却消除不了这段等待；真正卡住步时间的，往往是尾部长度而不是平均负载。一种在线调度把无状态的飞行中迁移和按样本是否足够来提前结束合在一起：在块边界把解码请求迁到更空闲的引擎，只做一次重新预填充；当同一分组里已经有足够完成样本来估计优势时，就提前结束这条响应，并把不完整输出从训练损失里掩掉。端到端训练中，滚动时间缩短 24% 至 34%，生成吞吐最高提升 33%，最终奖励相当或更高。

Niloofar Gholipour, Marcos Assuncao, Timothy Yu, Gursimran Singh, Rajkumar Buyya 等 8 人

TokenRouter: Efficient Serving System for Token-Level LLM Routing

已录用 NeurIPS 2026Tsinghua UniversityCMU

大模型路由能把推理工作分到不同模型上，从而推动成本与质量的边界；会话或查询级的粗路由已在生产中常用，而 token 级细路由在算法上能带来更大的效率与质量收益，现有服务系统却很难把它跑顺。这些系统多按单模型假定来建，token 级路由下会出现严重的步进失步和批准入延迟，开发复杂度也高。一套面向 token 级路由的服务系统让开发者按单条请求描述路由逻辑，运行时再为每个模型拉起子服务并异步分发。每个子服务用延迟组批调度，超参数由系统吞吐的数学模型给出。在多种路由算法、负载和模型对上，它比现有系统的解码吞吐高 2.01 倍至 64.15 倍，让 token 级路由真正进得了服务层。

Tianyu Fu, Tengxuan Liu, Ruoxi Wang, Yixin Dong, Yi Ge, Yichen You, Yu Wang

Keep or Preempt? Termination-Aware Scheduling for LLM Serving with Speculative Decoding

已录用 NeurIPS 2026

交互式大模型服务既看重首 token 时间，也看重端到端延迟。推测解码用轻量草稿和并行校验来降延迟，却也让传统按输出长度估计的 SRPT 调度变得不那么可靠：一条请求还要跑多久，还取决于草稿接受率和校验轮数。一套终止感知的调度先用运行时草稿与校验状态训练的轻量预测器，识别在接下来几步解码里就快结束的请求，再通过考虑切换代价的在线策略，判断抢占是否值得，以免运行集被改得太勤。在开源 vLLM 服务系统上，它相对默认调度器，把平均和中位首 token 时间最多分别降到原来的约三分之一以下，其中平均首 token 时间最多降低 3.83 倍；相对按长度抢占的对照，平均首 token 时间仍最多降低 2.0 倍。

Ziyu Cheng, Mingyan Li, Songtao Guo, Chang Han, Hongyu Xu, Xu Luo
