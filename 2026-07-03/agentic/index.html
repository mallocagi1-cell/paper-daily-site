Unlocking dependable responses with Gemini Enterprise Agent Platform’s Agentic RAG

Google Research 与 Google Cloud 发布 Gemini Enterprise Agent Platform 中的 Agentic RAG 框架，目标是解决企业多源、多跳问题在传统 RAG 中只能得到局部答案的问题。系统把复杂查询拆成规划、改写、路由、充分上下文检查等多个 agent 步骤，并持续跨语料检索直到证据足够；官方称在事实性数据集上相对标准 RAG 最高提升 34% 准确率，并在内部领域任务上提升 grounding 与推理准确性。

Bringing Agentic Search to Earth Observation Data Discovery

NASA

论文面向 NASA 地球观测数据发现，提出一个已部署的 agentic search 系统，让用户用自然语言研究问题检索匹配的数据集和工具。作者基于 NASA Earth Observation Knowledge Graph 构建 NASA-EO-Bench，包含 4.7 万 query-dataset 对，其中 2.1 万是任务型查询；微调神经 scorer 已优于 cosine 与 BM25，进一步与 BM25 做分数融合后 Recall@10 和 MRR 均提升超过 5 倍，并叠加零样本 agentic reranking。

INSIGHT这篇最接近“搜索 agent 落地”：知识图谱提供可控结构，神经 scorer 负责语义排序，BM25 融合保留词面召回，agentic reranking 再处理复杂任务意图。对 UGC 搜索可借鉴其分层设计：先用结构化实体/主题图约束召回范围，再用学习排序和 agent 复核处理多意图 query，而不是直接让 LLM 在原始帖子池上自由搜索。

Minghan Yu, Youran Sun, Chugang Yi, Yixin Wen, Haizhao Yang

BaRA: Budget-constrained and Reliable Web Data Collection Agent

BaRA 将 LLM Web agent 的目标从“完成单个网页任务”扩展为预算受限的网站级多模态数据采集：agent 需要在固定交互次数内发现站内页面，并可靠提取文本、图像、视频等资产。方法采用 BFS 链接发现、存活性验证过滤幻觉和死链、基于 provenance 与可访问性的规则校验，以及历史自反思模块恢复执行失败；论文在合成和真实网站上显示 BaRA 能更稳定地发现有效页面并减少无效采集。

INSIGHT对搜索/推荐团队而言，BaRA 的价值在于把 Web agent 做成“可预算、可验证、可恢复”的采集管线。UGC 搜索经常需要抓取外部内容、商家页或长尾资料，不能只看最终回答是否看似合理；链接存活检查、资产 provenance、失败历史回放这些工程约束，应该进入 agent 检索系统的默认执行协议。

Soojeong Lee, Joseph Lee, Yongseong Cho, Sunjae Kim, Youngwoo Moon, Kyungwoo Song

SkillCoach: Self-Evolving Rubrics for Evaluating and Enhancing Agentic Skill-Use

SkillCoach 关注 LLM agent 使用“技能库”时的过程质量问题：现实技能仓库中 SOP、领域规则、工具流程会互相重叠，只看最终 verifier 成败无法区分 agent 是正确选择技能，还是靠试错偶然通过。论文提出自演化 rubric 框架，从真实 rollout 中生成 skill-grounded 过程评分，并在技能选择、技能遵循、技能组合、基于技能的反思四个维度评估轨迹，同时保留外部 verifier 作为独立结果信号。

INSIGHT这对搜索 agent 的运维很实用：召回、重排、改写、事实核验、工具调用都可以被封装成技能，但必须评估“过程是否走对”。SkillCoach 提示我们把 agent 日志变成训练与评测资产，用过程 rubric 捕捉错选工具、跳步骤、错误组合等问题，避免只用最终答案准确率掩盖不可控的执行路径。

Jiayin Zhu, Kelong Mao, Yudong Guo, Dengbo He, Sulong Xu

LongCat 开源 VitaBench 2.0：长期动态智能体基准新标杆

Meituan

美团 LongCat 开源 VitaBench 2.0，定位为长期、真实、动态用户互动场景下的智能体评测基准，重点衡量大语言模型在长期记忆、用户建模、个性化响应和主动性上的能力。它把评测从静态单轮问答推进到连续用户互动，更贴近社区产品中“用户偏好随时间变化、agent 需要记住并调整策略”的真实问题。

INSIGHTAgentic 搜索不仅是多跳检索，还需要长期记忆和用户状态建模。VitaBench 2.0 对 UGC 社区有直接参考价值：搜索助手如果要做个性化追问、主动推荐或长期任务，需要评估记忆是否正确影响决策，以及是否会在动态偏好变化后及时更新，而不是只评估一次检索的 nDCG。

用 EdgeOne Makers 构建与托管 Agent：从 RAG 检索到智能助手

Tencent

这篇腾讯云开发者社区文章展示了把已有文档 RAG/MCP 服务升级为 EdgeOne Makers 托管 Agent 的工程路径。实践中作者将工具规划阶段改为非流式 Chat Completions，模型返回 tool call 后由 Agent 执行工具并把 tool_call/tool_result 传给前端，最终回答再用 streaming；同时用 tracing 记录知识库查询、工具调用、LLM 阶段和 token 用量。

INSIGHT这是一篇小而实用的工程样例：Agent 不一定要一次性重构完整后端，可以把现有文档站、知识库和工具函数包成清晰的托管边界。对 UGC 搜索助手而言，类似的链路追踪非常关键，能把“没检索到、工具选错、模型整理错误、token 超限”拆成可诊断事件，而不是只看到最终答案失败。

Safeguarding LLM Agents from Misalignment through Provenance Analysis

CMU

ProvenanceGuard 针对 LLM agent 工具调用偏离用户意图的风险，提出用 provenance analysis 判断一个动作是否被上下文中的可追溯证据支持。论文把 misalignment detection 形式化为“拟执行工具调用是否能从 agent 上下文中找到支撑链”，并构建多阶段流水线分析 action 与用户意图、上下文证据之间的关系，以替代难审计且不稳定的 LLM-as-judge 守卫。

INSIGHTAgentic 搜索会调用检索、过滤、写入、推荐等工具，错误 action 的代价高于普通文本幻觉。ProvenanceGuard 的核心启示是：每个工具调用都要能回溯到用户 query、检索证据和中间推理，而不是只让另一个 LLM 判断“看起来是否合理”；这有助于构建可审计的搜索 agent 安全边界。

Yining She, Yiliang Liang, Eunsuk Kang

PACE: A Proxy for Agentic Capability Evaluation

PACE 解决 agentic benchmark 昂贵、耗时、基础设施复杂的问题。作者观察 SWE-Bench、GAIA 等完整 agent 评测一次可能花费数千美元并持续数天，因此提出从非 agentic 原子能力评测中选择一小组实例，训练回归映射来预测模型在昂贵 agent benchmark 上的表现；这个 proxy benchmark 能用更低成本快速估计 agent 能力。

INSIGHT对工程团队来说，PACE 的价值在于把“全量 agent 评测”拆成可日常运行的代理指标。搜索/推荐 agent 上线前仍需要端到端回放，但日常模型选型、prompt 变更、工具策略调整可以用小规模 proxy 先筛选，只有候选方案通过后再跑昂贵的多步检索与真实业务回归。

Yueqi Song, Lintang Sutawika, Jiarui Liu, Lindia Tjuatja, Jiayi Geng

Mastering Agentic Techniques: AI Agent Reinforcement Learning

NVIDIA

NVIDIA Developer Blog 的这篇工程文章聚焦 AI agent reinforcement learning，梳理从 RLHF 到更面向 agent 的强化学习技术如何用于对齐语言模型和优化工具使用策略。作为产业实践材料，它强调 RL 不只是提升聊天偏好，也可以训练 agent 在多步任务中学习何时调用工具、如何利用反馈、如何在环境交互中改进行为。

INSIGHT它对 agentic 搜索的实践意义在于把“检索策略”视为可学习策略，而不是固定规则。对于复杂 UGC 搜索，可以从日志中定义奖励：是否找到足够证据、是否减少无效检索、是否提升用户点击/满意度，再用离线或在线 RL 逐步优化查询改写、工具选择和停止条件。

AgenticSTS: A Bounded-Memory Testbed for Long-Horizon LLM Agents

AgenticSTS 将长程 LLM agent 记忆建模为“未来每次决策允许看到什么”的契约，而不是简单把历史观察、工具调用和反思全部追加进 prompt。论文提出 bounded memory contract：每次决策都从新用户消息出发，通过 typed retrieval 组装上下文，不附加原始跨决策 transcript；作者在 Slay the Spire 2 长程决策环境中实现该契约，使 prompt 长度有界，并能独立消融每层记忆。

INSIGHT搜索 agent 往往会在多轮探索中积累大量中间证据，直接堆上下文会造成不可控的信息污染。AgenticSTS 的启示是为记忆层定义清晰契约：哪些事实、偏好、工具结果可被检索进入下一轮，哪些只能归档；这样既控制成本，也便于定位某类记忆是否真的改善搜索决策。

Xiangchen Cheng, Yunwei Jiang, Jianwen Sun, Zizhen Li, Chuanhao Li
