GR2 Technical Report

这份 Meta 技术报告把 LLM 用到工业推荐漏斗最后的重排阶段，提出 GR2：先用 99% 唯一性的语义 ID 做中训练，再用教师模型生成重排推理轨迹，最后用面向 AUC/NDCG 的可验证奖励做 RL 后训练。实验基于约 7 万个内部用户会话，并在 02-01 到 02-09 的 9 天留出流量上评估；相对强 legacy point-wise baseline，GR2 提升 +18.7% Recall@1、+7.1% Recall@3、+9.6% NDCG@3。

MixFormer: Co-Scaling Up Dense and Sequence in Industrial Recommenders

ByteDanceDDouyin📖 深度解读 · 12 分钟 →

MixFormer 针对工业推荐中“序列建模”和“稠密特征交互”分离导致的容量分配问题，提出统一 Transformer-style backbone，把用户行为序列、非序列特征和高阶交互放到同一参数化结构里共同扩展。离线数据来自抖音推荐系统连续两周、万亿级 user-item 交互，单样本超过 300 个特征；MixFormer-medium 相比 TADLRM 在 Finish AUC/UAUC 上提升 +1.28%/+1.60%，Skip AUC/UAUC 提升 +1.60%/+2.46%。线上 A/B 覆盖抖音与抖音极速版，整体时长分别提升 +0.2799% 和 +0.4105%，评论最高提升到 +1.9097%。

INSIGHT这篇论文的实践启示很直接：推荐大模型扩容时，不应只在序列塔或特征交互塔单点堆参数，而应让两类信号在同一 backbone 中共享容量并深度交互。它的 UI-MixFormer 通过 user-item decoupled HeadMixing 做请求级复用，把 medium 版 FLOPs 从 3503 降到 2242，同时保持同等 AUC/UAUC；这对 UGC 信息流和社区搜索排序很有价值，因为长行为序列与上下文/内容特征往往同时决定 CTR、停留和互动。

IntentTune: Using user demand and personalization to resolve "unknown" query intents for e-commerce search

📖 深度解读 · 13 分钟 →

IntentTune 面向电商搜索里“watch”“shirt”这类欠规格查询，尝试用个体历史和全站需求分布推断缺失的年龄、性别、品类、尺码等隐式意图。论文比较两类信号：用户级搜索历史、浏览行为、profile 属性，以及全体用户聚合的 population-level demand pattern；真实电商数据实验显示，仅靠总体需求分布无法稳定解析 under-specified query，而 prior search queries 等用户特异行为明显优于静态 profile 和总体统计。

INSIGHT它把搜索 query understanding 与个性化排序连接起来：当 query 本身信息不足时，用户最近搜索和浏览序列可以成为 intent resolver 的特征，而不只是排序模型的后置特征。对社区 UGC 搜索，这意味着“关键词召回前”就应引入轻量用户意图推断，例如把模糊 query 映射到用户偏好的内容类目、创作者类型或消费场景，再影响召回/重排；同时需保留 population prior 作为冷启动兜底，但不能把它当成主信号。

AI Innovations in Meta Ads Ranking Driving Advertiser Performance

Meta

Meta 的广告排序实践文章从产品侧介绍其近期 ads ranking 架构演进，重点提到 GEM、Lattice、Andromeda 等模块：GEM 承担更强的生成式/表征能力，Lattice 管理大规模广告知识与特征组织，Andromeda 面向候选检索与排序效率。虽然不是论文式实验报告，但它清楚展示了工业广告推荐从单点 CTR 模型转向多组件、分层、强表征的个性化排序系统。

INSIGHT这类行业实践的价值在于确认一个趋势：头部平台正在把广告/推荐排序拆成“强语义表征 + 大规模候选管理 + 多阶段排序”的系统工程，而不是只优化一个 CTR tower。对社区搜索推荐团队，可借鉴的是分层升级路线：先让候选集生成与用户/内容语义更强，再逐步把多目标排序、预算约束和延迟控制放进统一服务框架；文章也提醒，工程可维护性和 serving 成本会成为模型创新能否上线的关键门槛。

Planning over Matrix-Factorization MDPs for Candidate Generation

这篇 KDD 2026 workshop 论文把候选生成重新表述为 Matrix-Factorization MDP：每推荐一个 item，用户向量会因 fold-in 更新，下一步最优候选也随之变化。作者在固定 embedding 下比较静态 top-K、一步 lookahead 和 horizon-K MCTS，覆盖 5 个数据集与 2 种协议（per-user leave-last-n 和更严格的 global time split）；动态规划在 leave-last-n 下所有数据集都优于静态检索，在 MovieLens-1M 与 VK-LSVD 的 global time split 中也保持收益。

INSIGHT它的关键启发是把候选生成从“独立打分列表”改成“用户状态演化决策”，尤其适合连续消费场景，如社区帖子流、短视频、问答链路。论文指出单步 lookahead 已捕获大部分收益，且不需要重训表示，只在现有协同过滤 embedding 上加轻量 planning layer；这给工业系统一个低风险试验点：先在召回后处理或 candidate re-order 中引入一步状态更新，而不是立刻替换主召回模型。

Mikhail Trapeznikov, Maksim Utushkin

CoPersona: Collaborative Persona Graphs for Robust LLM Personalization

CoPersona 解决 LLM 个性化中常见的稀疏用户历史问题：多数用户只有少量交互，即使重度用户的日志也只覆盖偏置的偏好切面。论文提出 collaborative persona graph，把用户历史拆成多个 facet-level representation，并在 multiplex persona graph 上建模 peer-to-peer 的切面对齐；推理时结合非参数 peer retrieval 与参数化 graph reasoning。实验跨多个领域与模型规模，对强 baseline 均有稳定提升。

INSIGHT它对推荐/搜索的启示是，用户画像不应只做一个全局向量；当用户行为稀疏时，按兴趣切面寻找相似 peer 能缓解 profile 冷启动和 facet 缺失。社区内容推荐可以把“相似用户补全”限制在话题、作者、消费深度等明确 facet 内，避免全局近邻带来的偏置迁移；同时使用 dual-branch 结构，让检索式 peer evidence 和模型内图推理互补。

Yangtian Zhang, Leyao Wang, Hiren Madhu, Ngoc Bui, Walter Roznyatovskiy, Rex Ying

Bi-NAS: Towards Effective and Personalized Explanation for Recommender Systems via Bi-Level Neural Architecture Search

Bi-NAS 关注推荐解释质量，提出 bi-level neural architecture search 同时优化 cross-attention 机制和 feature interaction function，并探索 intra-layer 与 inter-layer 两级设计空间。论文还把 LLM 零样本提示接入解释生成，使推荐理由同时对齐用户特征偏好和 item quality score；在 4 个真实世界数据集上，Bi-NAS 不仅提升推荐准确性，也改善解释有效性。

INSIGHT它适合用于“为什么推荐给我”这类解释增强场景，而不是主排序模型的第一优先级。对社区推荐而言，可借鉴的是把解释模块和排序特征交互一起搜索，而非事后让 LLM 编一段理由；如果解释要影响信任、点击和长期留存，就需要在模型结构里显式对齐用户偏好、内容属性和质量分，而不是只做自然语言包装。

快手向左，阿里向右｜2025大模型融入推荐系统的两条路线深度解读

KuaishouAlibaba

这篇中文行业解读比较快手与阿里在大模型融入推荐系统中的两条路线：一类强调用大模型的推理/CoT 能力重写或增强排序逻辑，另一类更偏向把大模型作为推荐系统中的表征、生成和工程组件。文章属于二手解读，不提供可复现实验表，但覆盖 LLM4Rec、生成式推荐、推荐系统 scaling law 等近两年工业界关注点。

INSIGHT它的实用价值在于帮助团队判断路线取舍：如果目标是短期 CTR/CVR 提升，更现实的是把 LLM 用于特征增强、样本生成、用户意图理解和候选语义化；如果目标是长期范式升级，才考虑让推理链参与排序决策。对社区 UGC 推荐，建议先把 LLM 放在可灰度、可监控的旁路模块中，例如 query/user intent tagging 与内容语义 ID，而不是直接替换主 ranker。

Monosemanticity in Recommender Systems

Monosemanticity in Recommender Systems 研究协同过滤 embedding 的可解释性：传统矩阵分解维度缺乏语义，标准 sparse autoencoder 又会随字典规模出现 feature splitting、absorption、composition 等问题。作者在 Amazon Fashion 上训练大规模矩阵分解推荐模型，再用 Matryoshka Sparse Autoencoder 分解 latent features，并结合 metadata alignment 与 LLM labeling 检查语义一致性，最后对一组与性别相关的 latent neurons 做干预。

INSIGHT这篇论文的贡献不在短期指标，而在推荐系统治理和可控性：如果能从协同过滤 embedding 中恢复层级语义特征，就能解释、审计甚至干预推荐偏差。对社区平台，类似方法可用于定位“低质内容”“特定风格”“敏感倾向”等 latent 因子，辅助排序调参和安全策略；但它距离线上 CTR 提升还有距离，更适合作为诊断工具进入模型分析链路。

Yagel Alfasi, Eden Rzezak, Eadan Schechter
