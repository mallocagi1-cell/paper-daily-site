Deploying Semantic ID-based Generative Retrieval for Large-Scale Podcast Discovery at Spotify

Spotify 提出 GLIDE，一个生产级 Semantic ID 生成式推荐系统，用于播客发现场景。系统将 LLM 的语义推理能力与用户级个性化结合，通过 Semantic ID 表示物品并实现目录锚定生成，解决了 LLM 推荐系统中的幻觉、延迟和个性化三大落地难题。GLIDE 已在 Spotify 全量上线，服务于大规模播客推荐场景。

A Unified Language Model for Large Scale Search, Recommendation, and Reasoning

Spotify📖 深度解读 · 7 分钟 →

Spotify 提出 NEO 框架，将预训练 decoder-only LLM 适配为无工具依赖的、目录锚定的统一搜索/推荐/推理生成器。NEO 使用 Semantic ID (SID) 表示物品，通过单一模型同时支持检索、推荐和推理三种行为，避免了工具编排的复杂性。系统能处理多类型实体和异构目录，在严格延迟约束下运行。

INSIGHTNEO 提出了一个关键洞察：搜索、推荐和推理可以在同一 LLM 内统一建模，而无需外部工具链。通过 SID 表示将 LLM 生成锚定在真实目录中，实现了端到端优化。这为社区搜索系统提供了重要启示——未来可以用单一模型同时覆盖 query 理解、内容推荐和推理解释，减少多模块级联的延迟和维护成本。

HierarchicalKV: A GPU Hash Table with Cache Semantics for Continuous Online Embedding Storage

NVIDIA

NVIDIA 提出 HierarchicalKV (HKV)，首个支持缓存语义的通用 GPU 哈希表库，专为超大规模 embedding table 设计。HKV 采用缓存行对齐桶、行内评分驱动 upsert、双桶动态选择和三组并发四大机制，在 H100 GPU 上实现 3.9B key-value/秒的查找吞吐，并支持 HBM 之外的分层存储扩展。

INSIGHTHKV 解决了推荐系统中 embedding table 超出单 GPU 显存容量的核心痛点。其缓存语义设计——满桶时通过评分驱动淘汰而非扩容——完美匹配了在线推荐的热数据访问模式。对于社区搜索场景，该库可直接用于加速大规模用户/物品 embedding 的在线存储与查找，显著降低 serving 延迟。其开源库的形式也大幅降低了落地门槛。

Learning Evolving Preferences: A Federated Continual Framework for User-Centric Recommendation

提出 FCUCR，一种联邦持续推荐框架，解决联邦学习场景下用户偏好随时间演变导致的「时序遗忘」和「协作个性化弱化」问题。引入时间感知自蒸馏策略，在本地模型更新时隐式保留历史偏好；设计跨用户原型迁移机制，利用相似用户的知识丰富每个客户端的表征。框架在隐私保护的前提下实现了长期个性化。

INSIGHTFCUCR 揭示了联邦推荐中两个被忽视的关键问题：时序遗忘（模型更新时丢失历史偏好）和异构数据下的协作个性化失效。其「自蒸馏 + 原型迁移」的双策略设计提供了一种轻量的解决方案——不需要存储完整历史数据，仅通过蒸馏和原型即可保留关键偏好信号。这对社区搜索中的用户建模有直接参考价值：如何在用户兴趣迁移时仍保持个性化效果。

VLM2Rec: Resolving Modality Collapse in Vision-Language Model Embedders for Multimodal Sequential Recommendation

提出 VLM2Rec 框架，将视觉-语言大模型 (VLM) 作为协同过滤感知的多模态编码器用于序列推荐。研究发现标准对比监督微调会加剧 VLM 的模态坍塌问题——优化被单一模态主导，另一模态退化。VLM2Rec 引入弱模态增强机制，确保视觉和语言模态的均衡利用，从而提升多模态序列推荐的准确性。

INSIGHTVLM2Rec 发现了一个重要现象：将 VLM 适配为推荐 embedder 时，标准 contrastive SFT 反而会加剧模态坍塌，而非改善多模态融合。这个反直觉的发现对实践有重要警示——直接微调大模型做推荐表征并非万能，需要专门的模态平衡设计。对社区搜索中的 UGC 多模态内容理解（图文帖子）有直接参考价值。

Junyoung Kim, Woojoo Kim, Jaehyung Lim, Dongha Kim, Hwanjo Yu

Is Your LLM-as-a-Recommender Agent Trustable? LLMs' Recommendation is Easily Hacked by Biases (Preferences)

提出 BiasRecBench，首个系统评估 LLM-as-a-Recommender 范式偏差漏洞的基准。覆盖论文评审、电商推荐和招聘三个高价值领域，构建了带有校准质量差距的偏差合成流水线，可定量衡量 LLM 推荐在偏好注入攻击下的脆弱性。实验揭示了当前主流 LLM 在推荐场景中的系统性偏差问题。

INSIGHTBiasRecBench 揭示了 LLM 推荐的一个关键安全风险：通过精心设计的偏好注入，可以轻易操纵 LLM 的推荐结果。这对搜索系统具有直接实践意义——随着 LLM 越来越多地被用于排序和推荐决策，其对偏差和攻击的脆弱性必须被纳入系统设计考量。论文提出的校准质量差距方法也为评估自有系统的鲁棒性提供了工具。

Embedding World Knowledge into Tabular Models: Towards Best Practices for Embedding Pipeline Design

系统评估了 256 种 LLM embedding 管道配置（8 种预处理策略 × 16 种 embedding 模型 × 2 种下游模型）用于表格预测任务。核心发现：拼接 embeddings 优于替换原始特征列；更大的 embedding 模型通常效果更好但公开排行榜不是好的选型指标；GBDT 作为下游模型表现稳健。

INSIGHT该研究为推荐系统中使用 LLM embedding 增强特征提供了实用指南：拼接而非替换原始特征、优先选用大模型 embedding、不要盲目依赖公开排行榜选型。对社区搜索场景的 query 和内容 embedding 特征工程有直接参考价值——特别是如何将 LLM 世界知识有效融入现有排序模型的特征体系中。

Oksana Kolomenko, Ricardo Knauer, Erik Rodner

ListK: Semantic ORDER BY and LIMIT K with Listwise Prompting

提出 ListK 框架，利用微调 listwise 排序器优化语义 ORDER BY + LIMIT K 操作的延迟。设计了多种排序算法：确定性 listwise 锦标赛、Las Vegas 并行 listwise 多枢轴快速选择/排序、蒙特卡洛锦标赛过滤器。其中 listwise 多枢轴快速选择/排序为首次提出，在保持准确性的同时显著降低延迟。

INSIGHTListK 将 LLM listwise 排序能力与经典排序算法结合，在 top-K 选取场景中实现了效率突破。其 listwise 多枢轴快速选择算法的设计思路可借鉴到推荐系统的重排环节——利用 LLM 对候选列表的全局比较能力替代逐一评分，有望在社区搜索的结果精排中降低 LLM 调用次数同时保持排序质量。

MALLES: A Multi-agent LLMs-based Economic Sandbox with Consumer Preference Alignment

提出 MALLES，基于多 Agent LLM 的经济沙盒框架，通过在异构交易记录上对 LLM 进行后训练实现消费者偏好对齐。框架使用均场机制建模群体动态交互，将跨品类的隐式消费偏好迁移到 LLM 中，解决了单品类数据稀疏的问题。可用于跨域跨品类的消费行为模拟。

INSIGHTMALLES 的核心创新在于用 LLM 内化消费者偏好模式：通过在大规模异构交易数据上的后训练，LLM 可以跨品类迁移偏好知识。这种思路对推荐系统的冷启动和跨域推荐有启发——用 LLM 作为偏好知识的迁移载体，而非传统的特征工程方式。但目前仍处于仿真阶段，距离在线部署有较大距离。
