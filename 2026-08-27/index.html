CodeHID: Learning an Addressable Hierarchical Code Index for Generative Code Retrieval

论文把代码检索从平面相似度排序改写为分层语义地址生成：先用 RQ-VAE 与 kNN 伪邻居学习四层 DocID，再用硬负例、排序蒸馏和前缀约束解码导航。CoSQA 上 Hit@1=0.744、MRR@20=0.766；ProCQA-Python 上分别为 0.597 和 0.706，均明显高于 BM25、UniXcoder、NCI 等基线。

KEY INSIGHT · 对业务意味着什么生成式检索的关键不只是训练一个“会生成 ID”的模型，而是先把目标空间组织成可寻址的语义层级。对社区 UGC 搜索，可把主题、实体和细粒度意图编码为多层 Semantic ID，再用候选 Trie 约束解码；但要像 CodeHID 一样保留硬负例区分，否则相近帖子容易共享过深前缀而互相混淆。业务关联 对社区搜索场景，CodeHID 的分层地址思路可用于把短文本帖子按主题、实体和细粒度意图组织起来，再用生成式模型完成粗到细的候选定位；建议先在离线语料上验证 Semantic ID 稳定性，再接入线上候选链路。证据 在 CoSQA 上 CodeHID 的 Hit@1/MRR@20 为 0.744/0.766；在 ProCQA-Python 上为 0.597/0.706，并在 ProCQA-Java 上取得 0.520/0.654。完整实验覆盖 2 个代码检索基准、多个稀疏/稠密/生成式基线及组件消融。
Zhen Li, Yuhong Chen, Wenhao Xu, Xiaodong Li, Hui Li · 2026-08-26 · arXiv

EviGraph: Towards Verifiable Evidence Construction for Information-Seeking Agents

Tencent

EviGraph 将信息搜索改写为可验证证据图构建：执行器负责查询，冻结验证器抽取带极性和约束标签的原文证据，共享策略模型提交图更新并由确定性校验器检查。BrowseComp-Plus 上 Qwen3-8B+RL 达到 35.9%，同架构无 RL 为 26.9%，单体 Agent 仅 2.7%；LiveVQA 达到 78.0%。

INSIGHT把“搜到相关页面”与“证据支持了哪条结论”拆开，是生成式搜索可靠性的关键。EviGraph 用可达性不变量阻止伪造来源、用覆盖率和冲突率提供过程奖励；社区搜索可借鉴这一设计，让复杂 query 的生成答案绑定到帖子原文片段，并把缺失约束显式暴露给重试或人工兜底。

业务关联对于社区平台的复杂意图搜索，可将帖子片段、候选答案和约束条件组成证据图；生成模型只负责提出查询和图更新，结构校验器负责阻断无来源结论，从而降低 UGC 噪声、引用错配和答案幻觉对 nDCG/CTR 的影响。

证据在 830 道 BrowseComp-Plus 上，EviGraph(Qwen3-8B RL) 为 35.9%，双角色无 RL 为 26.9%，同一模型的 ReAct 基线为 8.2%；在 LiveVQA 上为 78.0%，相对无搜索图方案提升 27.0 个百分点。

Jiashun Chen, Yirong Mao, Wenhui Que

RAGSentinel: Certifiable Geometric Consensus for Robust Retrieval-Augmented Generation

University of North TexasUniversity of Louisville

针对知识库投毒导致 RAG 生成错误答案，RAGSentinel 用代理编码器计算 query-document 隐状态偏移，去除共享主题方向，再以几何中位数和局部一致性识别异常文档；方案无需训练、标签或白盒访问。作者在 NQ、HotpotQA、MS-MARCO 三个数据集、三类 LLM 和多种攻击上验证，保持接近 Vanilla RAG 的准确率并降低攻击成功率。

INSIGHTUGC 搜索接入生成式回答后，内容库写入权限本身就成为攻击面。RAGSentinel 的价值在于把防御放在生成前，用独立编码器的几何信号筛掉异常证据；工程上可先对高风险主题启用 query 自适应过滤，再监控过滤率、答案正确率和误删率，避免把一致但错误的帖子直接送入 LLM。

业务关联社区搜索的帖子、评论和商家内容会持续更新，RAGSentinel 可作为生成式问答前的轻量安全层；建议把它接在召回/重排之后、LLM 调用之前，并将 honest-majority 假设作为内容审核和多源证据配比的上线前置条件。

证据论文覆盖 3 个问答数据集、3 类 LLM、多个投毒攻击及 3 种自适应攻击；理论上在投毒文档少于召回集合一半且表示空间满足分离条件时，可恢复无毒多数上下文，防御只需 k+1 次代理前向和 1 次黑盒 LLM 调用。

Yueyang Quan, Anjun Gao, Yufei Xia, Minghong Fang, Zhuqing Liu

Automating Multi-Hop RAG Evaluation via TRIAD: From Context Extraction to Validated Dataset Generation

University of Innsbruck

TRIAD 从现有向量库自动构造多跳 RAG 评测集：先生成 QA，再用反馈循环校验，最后补充带相关性标签的上下文文档。HotpotQA 生成 703 题后保留 481 题（68%），MuSiQue 生成 723 题后保留 478 题（66%）；人工检查显示两套数据的正确率分别为 92% 和 98%，并在 7 种 RAG 配置上复现了基准趋势。

INSIGHT生成式检索系统最容易被“看起来合理”的离线集误导，TRIAD 把不可回答、多跳和上下文相关性纳入同一评测流水线。社区搜索可从真实帖子向量库生成带约束的测试 query，并分开看 context recall、precision、答案正确率和拒答率；但要警惕因同一向量库生成问题而造成的语义相似偏置。

业务关联建议为社区搜索建立按主题、时间和实体约束分层的自动评测集，用真实 UGC 片段生成多跳或不可回答 query，再把 nDCG/CTR 之外的证据召回与拒答质量纳入发布门禁。

证据HotpotQA 与 MuSiQue 的人工验证中，answerability 为 0.90/0.93、correctness 为 0.92/0.98、multi-hop 为 0.91/0.85；在生成集上 HotpotQA 的 context precision 从 0.364 提升到 0.582，7 种 RAG 配置保持可比较趋势。

Lorenz Brehme, Adam Jatowt

Evidence-State Reliability Under Controlled Degradation: Parser-Validity Divergence in a Multi-Stage LLM Pipeline

论文提出 Evidence-State Reliability（ESR），把多阶段 LLM 流程中的“格式可解析”与“证据是否足够、可靠、可用”分开评估。研究用 60 个案例、4 种证据状态和决策/审计/升级 3 个阶段设计 720 次调用，保留 713 条执行记录；所有 9 个降质条件的业务成功率变化均为负，而审计检测率仍为 1.0。

INSIGHT结构化输出通过不等于搜索推荐链路可靠；证据被压缩、缺失或冲突时，解析器可能更容易通过，业务判断却更差。对社区生成式搜索，应把 evidence sufficiency、冲突、升级恢复和安全拒答作为独立指标，并在监控中区分“发现问题”和“恢复成功”，避免用 JSON 合法率替代相关性或可信度。

业务关联可将 ESR 思路接入社区搜索的 query 改写、召回解释和答案生成链路：每阶段记录证据完整性与冲突状态，降质回放覆盖短文本截断、重复评论和相互矛盾的帖子，并将升级失败率作为上线风险信号。

证据在 60×4×3 的配对实验中，9 个 operational stage-success 变化全部为负且 bootstrap 区间均低于 0；三种降质状态下审计检测率均为 1.0，但升级恢复率均为 0，说明检测与恢复不能合并成一个指标。

Naimur Rahman

Music Recommendation with Large Language Models: Challenges, Opportunities, and Evaluation

这篇工作系统讨论 LLM 驱动音乐推荐中的用户建模、物品建模、自然语言请求和评测，不提出单一新模型，而是给出从 zero-shot、few-shot、RAG 到 CoT 的任务框架。作者把评测拆为 G1–G5 五类目标和 R1–R8 八类风险；一个三轮对话示例中，实体可落地率为 1，但 query adherence、alignment 和 constraint hit rate 的平均值都只有 1/3。

INSIGHT生成式推荐不能只看“返回的是不是一个真实物品”，还要检查是否满足用户约束、是否真正带来发现价值以及解释是否忠实。对社区 UGC 推荐，可把 query adherence、实体 grounding、个性化增量和长尾覆盖并列监控，优先用 RAG 约束生成空间，再用离线与用户研究共同校准 LLM 评审。

业务关联社区搜索/推荐可借鉴 G1–G5 与 R1–R8 建立生成结果质量面板：除了 nDCG、CTR，还要量化 query 约束命中、实体消歧、推荐新颖度、用户画像忠实度及隐私泄漏，避免单一 LLM judge 掩盖体验失败。

证据论文的运行示例覆盖 3 个评分轮次：实体 groundedness 平均为 1、hallucination rate 为 0，但 query adherence、query alignment 和 constraint hit rate 均为 1/3；工作还系统列出 5 类目标与 8 类风险供评测设计使用。

Elena V. Epure, Yashar Deldjoo, Bruno Sguerra, Markus Schedl, Manuel Moussallam

CAFE: Self-Improving Search Agents Need Co-Evolving Feedback

CAFE 针对搜索 Agent 只在终点获得奖励、无法定位中间检索错误的问题，采用共享参数的 Agent–Critic 双角色框架。在线强化学习中用“请求反馈与跳过反馈的成功差”塑造反馈请求回报，并在反馈前后重加权 token advantage；离线阶段再利用自身失败轨迹训练恢复能力，形成在线与离线协同。

INSIGHT对于多步生成式检索，反馈不应只是最终分数，而应成为轨迹中的可调用工具。CAFE 的 call–skip 对比信号能抑制无意义的反复反馈，反馈前后分段 advantage 则把信用分配落到具体动作；社区搜索可先在离线失败轨迹上验证请求反馈的收益，再逐步开放在线策略更新。

业务关联复杂 UGC query 往往需要多轮召回、改写和证据核验，可将 CAFE 的反馈角色改造成相关性/安全性 critic；上线前用固定预算比较“主动请求反馈”和“直接继续搜索”的成本收益，防止 RL 让 Agent 仅通过增加调用次数刷高终点指标。

证据实验设计明确包含共享参数的两类角色、prompt-level call–skip success gap、反馈感知 advantage shaping，以及在线 RL 与离线失败恢复两个训练环节；候选记录未提供统一的跨基准最终分数，因此证据质量按中等评估。

Boyang Liu, Senjie Jin, Peixin Wang, Zhangyue Yin, Yibo Wang

On-policy Distillation with Verifiable Reward

OPDVR 将 on-policy distillation 的密集 token 监督与 RLVR 的轨迹级正确性结合，先把采样 token 的隐式蒸馏奖励按整条轨迹的正确性重写，再用 ReLU gating 让正确轨迹获得非负奖励、错误轨迹保留纠偏信号。方法不新增超参数，针对现有“加权混合或启发式切换”带来的调参成本给出统一训练路径。

INSIGHT生成式推荐若直接用教师模型概率蒸馏，容易复制教师的错误或上限；若只用终点奖励，又会失去 token 级信用分配。OPDVR 提供了一个可迁移的折中：先用轨迹正确性筛选蒸馏信号，再让 dense guidance 帮助模型稳定学习，适合在推荐解释、自然语言 query 改写等生成子任务上做小规模验证。

业务关联在社区搜索中可将 OPDVR 用于生成式 query 改写或答案草稿训练：用点击/人工相关性校验提供可验证奖励，用教师分布提供密集监督，并单独审计错误实体、越权内容和位置偏差，避免把不可验证的语言流畅度当成业务目标。

证据论文明确比较 RLVR 的稀疏任务反馈与 OPD 的密集 token 指导，提出无需额外超参数的 ReLU gating 融合；候选摘要未给出统一的推荐数据集或线上指标，因此将其证据质量评为 4 而非 5。

Wenze Lin, Jiale Zhao, Xitai Jiang, Songde Rao, Yining Li

On the Role of Citations in Preference Data

论文研究引用如何影响偏好数据中的人类与 LLM 评审，使用混合效应模型分析人类评审和 4 个开源 LLM 在科学问答中的成对选择。结果显示，人类更偏好引用来源更多样但总数更少的答案；LLM 即使看不到来源，也会表现出与引用相关的偏好，但偏好会随数据集和模型变化。

INSIGHT生成式搜索的引用数量不是可信度的单调代理，引用过多可能降低可读性，来源单一又会放大偏差。社区场景应把引用多样性、证据覆盖和用户约束命中分开标注，并用人工偏好校准 LLM judge；训练偏好模型时还要保留来源可见与不可见两种条件，识别“看引用格式”而非“看证据质量”的捷径。

业务关联对 UGC 答案和推荐理由，可建立引用级标注：记录每条 claim 的支持帖子、来源多样性、时间新鲜度和冲突情况，再用这些标签训练偏好模型；线上同时观察点击、停留和举报，避免引用格式优化带来虚假的相关性提升。

证据研究包含人类评审与 4 个开源 LLM，使用混合效应模型分析科学问答中的成对偏好，并报告“更多样但更少总数”的人类引用偏好及模型间差异；未提供社区推荐线上 A/B 结果。

Yu Hou, Hal Daum\'e III, Rachel Rudinger, William Walden

10 3.45

When LLM judges agree, should we believe them?

Amazon

Amazon Science 讨论多个 LLM judge 给出一致结论时是否真的值得相信，核心做法是识别并折减高度相关的评审意见，让评审面板保留更真实的观点多样性。文章把“意见一致”与“独立证据充分”区分开来，适合作为生成式搜索和推荐评测的工程提醒。

INSIGHTLLM judge 的一致性可能来自共享模型、提示词或训练数据，而不是独立验证。实践中应先测评审间相关性，再对高度相关的意见降权，并用人工样本、业务指标和来源证据做三角校验；这比简单增加 judge 数量更有助于发现生成式推荐的幻觉和偏置。

业务关联在社区搜索的摘要、推荐理由和答案评测中，可按模型/提示词族群聚类 judge，避免同源评审重复计票；将 nDCG、CTR、举报率和人工相关性作为外部校验，防止评审面板对同一种错误形成一致认可。

证据候选文章明确提出对高度相关的 LLM judge 意见进行折减，以提高面板观点多样性；由于可用摘要未提供公开的样本规模、指标数值或线上 A/B 结果，证据质量按中等评估。
