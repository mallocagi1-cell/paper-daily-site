PSG: Pair-Space Generation for Efficient Generative Reranking

现代生成式重排以单物品为自回归单元，序列越长，推理开销与教师强制误差越重。PSG 将生成原子提升为有序物品对，使长度为 L 的列表只需生成 L/2 个 token，并用大规模曝光日志预训练物品对表示。理论速度提升 2–4 倍，工业环境实测 1.83 倍；在快手 4 亿日活场景上线后，人均停留时长提升 0.178%。

KEY INSIGHT · 对业务意味着什么物品对生成不是简单压缩：它保持与逐物品生成等价的序列分布表达力，同时把误差传播路径缩短约一半。对生成式排序系统，可优先在候选集内动态构造 pair vocabulary，以较小改造换取更多候选列表探索；但应重点验证二次规模词表构造和 pair 表示模块的在线成本。

Understanding Semantic IDs: From Item Representation to Item Selection in Generative Recommendation

UIUC

论文从编码、SID 构造、自回归生成到最终选品系统审视 Semantic ID。三个 Amazon 领域、八种 SID 方案中，SID 邻域平均只保留编码器前十近邻的 32.2%；替换商品描述会改变 38.4% 的精确 SID，TIGER 最终仅保留 29.9% 原本可行的目标。作者提出无需训练的 ISD，在所有设置提升 NDCG@10，最高相对增益 31.2%。

INSIGHTSID 更适合承担粗粒度语义分桶，而不应独占最终候选生杀权。ISD 用用户级物品排序分数在 beam search 淘汰前支撑对应前缀，并在生成后重排，无需增加参数或重训；这为 UGC 搜索中的 Semantic ID 召回提供了低风险补丁，也提示必须单独监控前缀剪枝召回损失。

Junting Wang, Xinrui He, Yunzhe Li, Hari Sundaram

SSRLive: Live Streaming Recommendation with Dynamic Semantic ID

Alibaba📖 深度解读 · 15 分钟 →

淘宝直播的粗排模型 SSRLive 给每个直播间两套 Semantic ID：静态 SID 来自主播近几天的历史内容，动态 SID 由直播间此刻的实时特征量化而来，随热度和内容变化。生成式编码器–解码器放在用户侧，交替生成两套 SID 并用任务 query 抽表示，打分仍交给带用户–主播交叉特征的判别网络。线上观看时长涨 3.38%，算力涨约 16 倍，延迟只多 1.33%。离线提升小且不均匀，Watch200 的 GAUC 还略低于基线。

Teng Shi, Zhaoheng Li, Yuanhang Qu, Yi Liu, Lixiang Lai, Yuning Jiang

Gryphon: A Unified Architecture for Semantic-ID Generation and Item-Level Scoring in Industrial Recommendations

Yandex

Gryphon 针对 beam search 的 token 序列似然与真实物品相关性错位，在 SID 生成旁增加共享用户表征的物品级打分头。工业音乐场景中，Recall@1000 比原始生成检索高 3.7%、比碰撞消解基线高 2.5%，同一候选集物品打分比 beam 似然高 4.2%。七天 A/B 的总收听时长为 +0.25%，并替换了 15 个以上候选生成器和独立预排。

INSIGHTSID 碰撞和逐 token 概率累积会让生成概率难以直接充当排序分数，复用编码器用户向量增加轻量物品头是更稳妥的工业折中。该实验也提醒：离线召回提升不必然转化为核心在线时长，但架构简化本身可显著降低多路召回维护成本，应纳入综合收益评估。

Daria Tikhonovich, Oleg Sorokin, Vladislav Dodonov, Mariia Ulianova, Ilya Murzin

Taiji: Pareto Optimal Policy Optimization with Semantics-IDs Trade-off for Industrial LLM-Enhanced Recommendation

Kuaishou📖 深度解读 · 14 分钟 →

快手的 Taiji 让一个 7B 模型读用户画像和最近 50 条行为，推理“下一单会买什么”，输出编码后给广告排序模型当特征，或用来找最相似的用户借行为序列。思维链先“知道答案再反推”、按困惑度筛掉一半，强化学习的两个奖励权重按区分度自动调。线上 ADVV 涨 2.83%、收入涨 3.30%，长尾用户涨 5% 以上。离线奖励和评估用同一个排序模型，动态权重在偏好指标上只多 0.74%。

UniVA: Unified Value Alignment for Generative Recommendation in Online Advertising at Tencent

TencentWuhan UniversityPeking University📖 深度解读 · 9 分钟 →

UniVA 面向广告推荐中生成概率与商业价值不一致的问题，在 SID 构造、解码和在线服务三层统一注入价值信号：商业属性参与 tokenization，解码器融合生成分数与 token 价值，个性化 trie 约束合法路径。在腾讯视频号广告上，离线 Hit Rate@100 相对提升 37.04%，线上 A/B 的 GMV 提升 1.5%。

INSIGHT商业目标若只在生成后重排，相关物品可能早已被 beam pruning 淘汰；价值信号应前移到 SID 和逐 token 解码阶段。对社区搜索可类比注入内容质量、时效或安全价值，并用请求级合法前缀树约束生成，使相关性与业务价值从候选形成阶段就共同优化。

Xinxun Zhang, Yuling Xiong, Yangru Huang, Jiale Zhou, Zhengkai Guo, Zhennan Pang, Junbang Huo 等 17 人

WhisperRec: Latent Reasoning for Efficient Foundation Recommendation Models

Kuaishou

WhisperRec 把教师生成的显式 CoT 压缩成可学习的潜在推理 token，以“潜在推理后回答”避免逐字生成长推理链。多视角自适应 CoT 按样本难度分配推理复杂度，再经三阶段潜在对齐和课程式后训练内化推理。在快手工业数据和公开基准上，SID@64 较显式 Think 与 No-Think 分别提升 17.44% 和 9.33%，在线吞吐超过 10 倍。

INSIGHT潜在推理把推荐中的多因素兴趣分析保留在隐藏空间，适合延迟敏感的召回与排序。可借鉴其“难样本多推理、易样本少推理”和分阶段蒸馏策略，但应分别监控教师 CoT 质量、潜变量漂移及吞吐收益，避免将不可解释的隐藏推理直接用于高风险决策。

MLPs are Efficient Distilled Generative Recommenders

UCSDSnap📖 深度解读 · 13 分钟 →

生成式推荐逐位解码、每位都要跑一遍 Transformer 解码器，beam 一宽就慢。作者先数了 SID 每一位的合法分支数：第一位有 256 个选择，后面几位很快只剩一两个，说明难点只在开头。于是 Sid-Mlp 只对用户历史做一次注意力读出，之后每一位用一个独立的小 MLP、输入“上下文 + 已生成前缀”来预测，并从冻结的 TIGER 教师蒸馏。在三个 Amazon 数据集上，效果和教师持平或略高，吞吐快 8.74 倍，显存峰值降 95.7%。局限是教师和物品规模都小；换成 7B 大模型当教师时已不再无损，大目录下要先测自己的分支数。

Zitian Guo, Yupeng Hou, Clark Mingxuan Ju, Neil Shah, Julian McAuley

RcLLM: Accelerating Generative Recommendation via Beyond-Prefix KV Caching

HKBUHuawei

推荐提示中的用户历史和物品上下文常以非连续方式重复，传统前缀缓存命中有限。RcLLM 将提示拆成可复用块：小型用户历史缓存复制到各节点，大型物品缓存按相似性分片，并用亲和调度提升局部性、选择性注意力修正近似误差。真实数据实验将首 token 延迟降低 1.31–9.51 倍，对推荐准确率影响可忽略。

INSIGHT生成式推荐缓存的基本单位应从连续前缀改为可组合的用户与物品块。对长 UGC 历史，可复制高复用的用户短上下文、分片海量内容 KV，并把缓存驻留纳入调度目标；选择性补算则应由相关性敏感度触发，避免为了命中率牺牲排序质量。

Zhan Zhao, Yuxin Wang, Amelie Chi Zhou

CapsID: Soft-Routed Variable-Length Semantic IDs for Generative Recommendation

📖 深度解读 · 9 分钟 →

CapsID 把残差量化的硬最近邻替换为胶囊软路由，让物品在每层按概率路由到多个语义胶囊，并在置信度足够时提前终止 SID；SemanticBPE 再按共现与 embedding 兼容性合并相邻 token。在四个 Amazon 数据集和 3500 万物品工业目录上，Recall@10 平均比 ReSID 高 9.6%，推理延迟仅为稀疏—稠密方案的 51%。

INSIGHT生成式推荐的性能上限可能首先受 tokenizer 而非 Transformer 限制，尤其是多义和长尾内容。软路由缓解簇边界的信息坍缩，变长编码按物品难度分配容量，语义 BPE 再压缩解码步数；上线前应重点评估码本稳定性、增量物品重编码成本和约束 beam search 的兼容性。

Wenzhuo Cheng, Menghang Gong, Qixin Guo, Hang Zheng, Zhaobin Yang, Jianguo Lou, Zhengwei Zheng
