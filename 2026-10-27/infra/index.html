Where Rounding Happens Matters: Rounding-Location Alignment Stabilizes LLM Reinforcement Learning

大模型强化学习通常用一套推理引擎生成回答、另一套框架训练，就算权重相同、都用 BF16，两边算出来的数也会有细微差别，本该是同策略的更新悄悄变成了异策略，训练可能突然崩掉。字节跳动 Seed 和北大的这篇论文发现，不必把两套系统整体对齐，只要在 RoPE、SwiGLU 和残差 RMSNorm 三处让训练端和推理端在同一个位置做舍入就够了：这几处的中间结果先保留 FP32，到输出时再转成 BF16。三处都对齐后，四个 Qwen 系列模型都不再崩溃，只对齐 RoPE 一处也够用。推理引擎、矩阵乘法和注意力内核以及训练目标都不用改。

C 2 KV: Compressed and Composable KV Cache Reuse for Efficient LLM Inference

已录用 KDD 2026📖 深度解读 · 11 分钟 →

检索增强生成要把多篇检索到的文档拼进上下文，每次都从头算这些文档的 KV 缓存很贵，于是有方法把每篇文档的 KV 缓存存起来、用时直接拼接。但长文档的 KV 缓存很大，存储和读取本身成了瓶颈，直接压缩后再拼接，准确率又会明显下降。上海交大和阿里巴巴的这篇论文提出 C2KV，在冻结的原模型旁加一个轻量提取器：把几个可学习的压缩 token 接在文档后面一起读，只留下这几个 token 的 KV 当作这篇文档的缓存。缓存存的时候不带位置，拼接时再按新位置补上位置编码，所以能像积木一样任意组合。在长上下文下，推理最多快 17 倍，生成质量基本不变。

Chuheng Du, Junyi Chen, Hanlin Tang, Kan Liu, Tao Lan

Qdrant 1.20 - Full-Text Search Improvements

Qdrant📖 深度解读 · 12 分钟 →

以前在 Qdrant 里用 BM25 给关键词搜索结果排序，得先把每篇文档和每个查询都转成稀疏向量，平均文档长度还要自己维护，数据一变就不准。Qdrant 1.20 版直接在全文索引上算 BM25，所有统计量都从数据里自动算，不用再生成向量，参数可以按查询调整，也能和向量检索混合使用。新版还加了专门搜代码的分词器，getUserName 和 get_user_name 能互相匹配；另外新增 16 位的 TurboQuant 向量格式，和默认的 32 位浮点格式相比存储减半，在 12 个数据集上召回几乎不变。

NgramRL: Accelerating RL Post-Training for Structured Generation via Rollout-Aware N-gram Speculative Decoding

📖 深度解读 · 12 分钟 →

大模型强化学习后训练里，生成回答常常占到训练时间的七成以上。这篇论文注意到，同一道题在前几轮训练中生成过的回答很像这一轮要生成的内容，可以直接拿来当草稿。他们提出 NgramRL，每道题只用自己最近几次的回答建一个 n-gram 草稿表。生成时拿当前回答的最后几个词去表里查，把表中接在后面的内容当草稿，大模型一次验证多个 token，不需要额外的草稿模型，也不占 GPU 显存，生成结果的分布也不变。在推理和结构化生成任务上，缓存预热后大模型每次前向能确认 3.6 到 7.8 个 token，最多是 SuffixDecoding 的 2 倍，后者是用全局历史回答建后缀树查草稿的同类方法。

Nilesh Prasad Pandey, Jangseon Park, Jason Kong, Onat Gungor, Tajana Rosing

05 3.90

KnitTrans: Coordinated Trajectory Transfer for Effective and Efficient LLM Reinforcement Learning

大模型强化学习把生成和训练拆到不同机器上时，生成好的轨迹往往要等凑齐一整批才能送去训练，训练用的模型版本和生成时差得更远。轨迹数据很大，搬运方式和训练取用方式对不上，又会重复搬运、白白等待。这篇论文提出 KnitTrans，先把已完成的轨迹放进早期小批次。一整批要按设定比例混合不同数据来源的轨迹，所以每放入一条前都检查剩下的名额还够不够把比例凑齐。同一道题生成的多条轨迹共用同一份图片等输入，一个小批次里这份输入只编码一次。版本差距最多降低 93%，多模态任务上搬运加训练最多快 5.8 倍。

Bangjun Xiao, Chiheng Lou, Xiaodong Ji, Xiangwei Deng, Yikai Zhao, Gang Huang, Hailin Zhang

How NVIDIA Mission Control 2.5 Brings Autonomous Recovery to Kubernetes

NVIDIA

在几百个节点上连续跑几天甚至几周的大模型训练，硬件故障、软件报错和网络超时迟早会碰上，靠人工排查恢复会白白浪费大量算力。英伟达的集群管理软件 Mission Control 在 2.5 版把自动恢复引擎从 Slurm 扩展到 Kubernetes 上的训练任务。它先根据任务上下文判断故障类型，再决定是重试任务还是隔离机器：硬件出问题时，任务被重启或换到别的节点，同时坏节点被隔离并并行做诊断；临时性的软件错误只重试任务，不会误触发硬件维修。它还能提前发现性能退化的节点，在任务受影响前把它移出调度池。

Aquavit: Ascending Quantization for Communication-Efficient Vast-Scale Distributed Training

已录用 KDD 2026

在大规模 GPU 集群上训练大模型，通信越来越成为瓶颈。ZeRO++ 这类框架用固定位数的量化压缩通信量，位数低时吞吐高，但量化噪声一直存在，训练后期难以收敛；位数高时精度好，速度却上不去。这篇论文提出一个假设：权重量化带来的噪声和随机梯度的噪声作用类似。他们从理论上证明，就像学习率要逐步衰减才能收敛，量化精度也要随训练逐步提高，才能在吞吐尽量高的同时保持训练稳定。据此做出的 Aquavit 在训练前期用低位数量化通信，后期再换成高位数。

Hong Huang, Jiaxun Ye, Jinhai Yang, Wenjiao Feng, Zonghang Li

Accordion: Elastic-Depth Inference via Fixed-Prefix Layer Looping

同一个大模型要服务不同的推理预算，为每种预算单独训练和维护一个模型成本很高。这篇论文提出 Accordion，一个混合专家模型，用同一套权重支持五档推理预算：模型中段一组连续的层是可循环的窗口，每档从窗口开头起把前若干层各连续执行两遍，预算越高，重复的层越多，最低一档就是不循环的原模型。预训练时每个小批次随机抽一档预算训练，不加额外的一致性约束。最高一档的大部分收益，中间一档只用一半的额外计算就能拿到。加深推理让 37 项任务的平均分提高 3.01 个百分点，中间一档拿到其中 89%。

Yudong Zhang, Wei Ding, Kaili Zheng, Yuchen Ding, Zhenyu Zhang

Beyond Hotness: High-Resolution Memory Characterization of Cloud and LLM Workloads for Tiered Memory with ARM SPE

数据分析和大模型应用的内存需求涨得很快，数据中心开始用多层内存，把冷数据放到便宜但较慢的内存上。但哪些数据该放哪一层，只看访问冷热往往不够准。这篇论文用 ARM 处理器的统计采样扩展（SPE）做高分辨率的内存访问分析，测了云计算基准和大模型应用里八个内存密集型负载。它把内存切成连续的区域，统计每个区域的访问延迟分布，延迟长的区域更值得放在快的一层；再看每个区域最长有多久没被访问，空闲越长，越适合挪到慢的一层，还评估了面向云负载的缓存层次是否有效。

Jie Ren, Ivy Peng

Tile-Based Decompression in Compiled GPU Engines

GPU 做数据分析查询，只有数据装得进显存时才快，而显存被多个任务分着用，单位价格的容量这几代也没涨多少。压缩能省显存和带宽，但现有做法要么只适配一种执行方式，要么先把解压后的整列写回显存再查询。这篇论文在 GPU 查询编译引擎 Proteus 里把解压做成一个独立的算子，解压在片上共享内存里按块进行，和查询融合在同一个 GPU 内核里，解压后的数据不再写回显存。和 HeavyDB、Sirius 相比，查询时间相当，常驻显存最多降到四分之一，带宽占用最多降到六分之一。

Antonio Boffa, Ananya Gupta, Hamish Nicholson, Anastasia Ailamaki
