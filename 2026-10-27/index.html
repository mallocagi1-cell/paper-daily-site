PinRec: Unified Generative Retrieval Model for Pinterest Recommender Systems

已录用 KDD 2026

推荐系统里首页、搜索和相关推荐通常各有各的召回模型，因为三处要的东西不一样：首页看用户会不会保存，搜索看会不会点出去购买，相关推荐看会不会继续往下逛。Pinterest 这篇 KDD 2026 论文把三处换成同一个生成式召回模型 PinRec，先在全站行为上预训练，再用各场景日志微调，生成时还告诉模型这次要找哪种行为的物品。真正起作用的是按目标行为生成，统一模型本身收益小得多。去掉这个条件，三个场景的离线召回掉 7.5% 到 12.6%；线上接进搜索作为一路召回，保存数涨了 3.88%。

Unifying Behavior Modeling and Semantic Generation for Generative Recommendation

已录用 KDD 2026📖 深度解读 · 14 分钟 →

用 Semantic ID 逐位生成下一个物品编号的生成式推荐，有一个系统性的偏向：华南理工大学这篇 KDD 2026 论文发现，用户历史里和目标物品同类的东西越少，它就越不如只看行为的老式序列推荐模型，最差的一组里 TIGER 的 NDCG@10 比 SASRec 低 30%。原因是编码器学的是下一个物品是谁，解码器要生成的却是编号。OMG 在两者之间加一个两层小网络，每一步把上一步的状态和编码器的最终状态相加再过一遍网络。每一步同时预测下一个物品和编号首位，后者的权重逐步加大，所有中间状态再一起交给解码器。只加这一个部件，各项指标平均涨 14.5%，计算量只多 0.16%。

Binquan Wu, Xinbo Chen, Yicheng Luo, Yuhao Ke, Jingye Li

CoFiRec: Coarse-to-Fine Tokenization for Generative Recommendation

已录用 RecSys 2026📖 深度解读 · 11 分钟 →

用户在网上挑东西，通常是先看大类再挑具体商品，但大多数生成式推荐在编 Semantic ID 时，把物品的类目、标题、描述和协同信号揉成一个向量再量化，这种由粗到细的结构就丢了。UIUC 和 Meta 的这篇论文提出 CoFiRec，按类目、文本内容、协同信号分层，各层单独编码，再由粗到细地生成。在多个公开数据集和不同骨干模型上，按 Recall 和 NDCG 计算，它比最强的传统和生成式基线平均高 7.27%。冷门物品上的提升达到 10.0%，高于热门物品上的 4.7%。

Tianxin Wei, Xuying Ning, Xuxing Chen, Ruizhong Qiu, Yupeng Hou

Knowledge Distillation across Item and Code Spaces for Parallel Generative Recommendation

📖 深度解读 · 11 分钟 →

用 Semantic ID 做生成式推荐时，训练只告诉模型下一个物品是哪一个，同一段历史下其他物品有多大可能，模型学不到。传统序列推荐模型能给出这种概率分布，但它给物品打分，生成模型却逐位预测编号，知识很难直接蒸馏过去。港科大等单位的这篇论文给并行生成模型设计了两种蒸馏：一种把学生的编号预测还原成全库物品分布再对齐老师，另一种把老师的物品概率摊到每个编号位上再对齐。平均来看，前者让 Recall@10 提升 15.39%，后者让 NDCG@10 提升 8.28%。

Yixuan Xu, Hailin Liu, Linxiang Peng, Can Yang

05 3.90

Separating Thinking from Spelling for Efficient Generative Recommendation

生成式推荐靠逐位写出物品的 Semantic ID 来召回，束搜索每走一步都要过一遍大模型，候选越多、编号越长，花得越多，这部分常常是主要开销。这篇论文提出 Deco，把读历史和写编号分开：大模型只读一遍历史，压成一个代表下一个物品的向量，整个束搜索交给一个带缓存的小解码器，编号和前缀树都不变。在电商、电影和音乐的七个数据集上，它的准确率与原模型相当或更好。在 50 毫秒的延迟预算下，吞吐量是原来的 3.2 到 8.6 倍。

Danil Gusak, Anna Volodkevich, Ivan Oseledets, Evgeny Frolov

SAGE: Sequence-level Adaptive Gradient Evolution for Generative Recommendation

已录用 RecSys 2026

生成式推荐常先做监督训练，再用强化学习按用户反馈对齐整份推荐列表。为了训练稳定，每次更新时模型生成这份列表的概率只允许变化一定比例，现有方法逐个样本定一个固定比例，冷门物品难得的正反馈因此被压住，单调的负样本列表也罚得不够。小红书这篇论文提出 SAGE，只换优化器：列表得到正反馈时调高概率上调的上限；列表的单一程度按其中物品类目分布的熵衡量，负反馈列表的熵比近期平均水平低得越多，允许把它的概率压得越多。在 Amazon 数据上，前几名的准确率不变，冷启动物品的离线召回提升约 90% 到 101%，多样性提高约 11%。

Yu Xie, Xing Kai Ren, Ying Qi, Ping Yang, Yao Hu

TGR-EvoDAG: A DAG-based Multi-Agent Code Evolution Framework for Generative Recommendation on Tencent

Tencent

让大模型智能体自动改代码、搜索更好的推荐算法，放到生成式推荐上有两个难处。编码、预训练、对齐三段流水线的重训代价差别很大，智能体却一视同仁地花预算；上游的好改动在下游适配之前常常让指标先变差，结果被过早丢掉。腾讯这篇论文提出 TGR-EvoDAG，用一张有向无环图同时保留多条改进分支：每个节点是一版改过的代码，记下这次改动碰了哪几段流水线、重训要多少 GPU 时长。上游改动让指标先降时不丢掉，等下游改动适配后再把两条分支合起来，预算则按预期收益和重训成本分配。在腾讯的商业媒体平台上，自动改出的模型让线上点击率显著提高 0.40%。

Junlin He, Junzhang Zhu, Yudong Li, Yihong Tang, Xuefeng Jiang, Wei Ma, Chengxiang Zhuo, Zang Li

GUIDER: Generative User Interest Discovery via Explicit Reasoning with Large Language Models

已录用 KDD 2026

生成式推荐常用的 Semantic ID 只是一串编号，模型生成了什么、为什么这么生成都很难看懂，也用不上大模型本身的推理能力。这篇论文提出 GUIDER，把推荐拆成两步：先让大模型用文字推理出用户接下来可能感兴趣的兴趣圈子。兴趣圈子是用文字描述的兴趣主题，只能从平台给定的一个固定集合里选，选好后再到这些主题下匹配具体物品。强化学习训练时，不在集合里的编造圈子会被扣分，过长的思考也会被扣分。在快手平台上的大规模线上 A/B 中，用户平均使用时长持续提升，也更容易跳出原有的兴趣范围。

Jinke Wu, Yinghao Wu, Shuchang Liu, Yandong Bai, Qi Zhu
