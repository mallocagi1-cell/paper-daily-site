Probing the Prompt KV Cache: Where It Becomes Dispensable

这篇论文追问 prompt KV cache 到底“哪里、何时、以何种形式”是冗余的。作者设计受控 splice 干预：扫描层数 cutoff 与解码步数，把上层 prompt span 的 KV cache 替换为“中性占位用户内容 + 相同 chat 模板”产生的 KV cache，发现准确率几乎不掉；而把同样的 slot 置零则准确率崩溃。结论是冗余来自“形式”（chat 模板脚手架）而非“内容”。该现象在 Qwen3、Gemma 3、Llama 3 三个模型族、多个数据集上都复现。

KEY INSIGHT · 对业务意味着什么现有 KV cache 压缩方法多是经验性地丢弃或摘要 entry，这篇给出机理性解释：上层 prompt KV 编码的是模板形式而非语义内容，所以可被同模板的“空壳” KV 安全替换。对在搜索/推荐里部署 LLM（query 改写、生成式排序解释）的工程启示——固定 system/chat 模板的 KV 可预计算并跨请求复用，prefill 只需对真正变化的用户 query 重新编码，是比无差别压缩更安全的省显存路径。

Speculative Decoding Across Languages

投机解码靠小 draft 模型起草多 token、大模型并行验证来加速 LLM 推理，但小 draft 模型的多语言能力差，导致非英语生成时加速比大幅下降。作者在 11 种语言上比较三种改进 draft 的策略：用翻译任务数据微调 draft、用无标注单语语料微调 draft、以及在单语语料上训练简单 n-gram draft 模型。关键发现是 n-gram draft 虽然接受率较低，但因起草本身极快，反而能稳定带来较大的端到端加速。

INSIGHT对需要服务多语言（含中文）UGC 搜索的团队，这给出一个低成本加速方案：无需训练神经 draft 模型，直接用领域单语语料统计 n-gram 即可获得投机解码收益，部署与维护成本远低于 EAGLE/Medusa 类方法。也提示在评估投机解码时“接受率”不是唯一指标——draft 生成耗时同样关键，低接受率但极快的 draft 在长尾语言上可能是更优的工程选择。

Nirajan Paudel, Michael Ginn, Luc De Nardi, Alexis Palmer

NVIDIA Vera CPU Sets a New Standard for Agentic Workloads in AI Factories

NVIDIA

NVIDIA 发布面向 AI factory “agentic 工作负载”的 Vera CPU：88 个自研 Olympus 核、10-wide 解码 + 深乱序执行，IPC 比上代 Grace 高最多 50%；内存子系统用 LPDDR5X，带宽 1.2 TB/s 且满载下维持 90% 峰值，峰值内存延迟比 x86 低 40%、内存功耗 <30W（DDR5 为 100W+）。官方称在 agentic sandbox 负载上吞吐比竞品高 1.8 倍、图遍历比 x86 架构高 3 倍，核间数据搬运经统一 mesh fabric 快 50%，TDP 250–450W 可配。

INSIGHT信号意义在于硬件厂商开始把“agent 工作负载”（大量分支、图遍历、sandbox 隔离执行）当作和训练/推理并列的一类负载来设计 CPU。对搜索/推荐基建的参考：当检索 + 多跳 agent 编排成为线上主路径，瓶颈正从 GEMM 转向访存与控制流，选型时图遍历吞吐、内存延迟/功耗比纯算力更值得关注。需留意这些是厂商自测数字，缺乏第三方复现。

NVIDIA DSX OS Delivers Open, Modular Software for Operating AI Factories at Scale

NVIDIA

DSX OS 是 NVIDIA 开源的模块化 AI factory 运维软件栈，源自 DGX Cloud 的生产实践，统一编排算力、网络、供电、散热与机房设施。组件包括 DSX Exchange（基于 MQTT 的 IT/OT 通信枢纽）、DSX MaxLPS / DSX Flex（跨 GPU/机柜动态分配功率、对接电网需求响应）、Infra Controller（API 化裸金属生命周期管理）、NVSentinel（GPU 故障自动检测与自愈）、KAI Scheduler/Run:ai（拓扑感知 GPU 调度）以及 Dynamo + Grove（分布式推理服务）。官方称功率优化可在固定功率预算下多跑 40% GPU 且对推理性能影响极小。

INSIGHT可直接关注其中已开源的 KAI Scheduler（拓扑感知调度）和 Dynamo/Grove（分布式推理服务）——这两块对自建推理集群的搜索/推荐团队有复用价值，无需绑定整套 DSX。更值得借鉴的是“把功率/散热当一等调度维度”的思路：推理集群规模上来后，固定功率预算下的 GPU 利用率（这里宣称 +40%）直接决定单位 QPS 成本，调度器需要从纯拓扑感知扩展到能耗感知。

An Organization-Scoped LLM Agent Runtime Architecture for Regulated Cybersecurity Operations

面向受监管的网络安全运营场景，本文提出一套组织域内的 LLM agent 运行时架构。核心是在每个入口创建并贯穿所有组件的“类型化 Security Context”，配合受治理的 Tool Adapter Layer、带证据引用的结构化 findings、分级的 human-in-the-loop 审批门、以及 append-only 审计日志；运行时核心由若干专精子 agent 组成，以 SIEM/XDR 告警为主要触发源。整体保持模型无关、可本地部署，并支持合规工作流（可选扩展 MCP、数字孪生、联邦知识共享）。

INSIGHT抛开网络安全场景，这套架构提供了一个“生产级 LLM agent 系统”的通用骨架，对做搜索/推荐 agent 的团队同样适用：类型化上下文做权限与数据范围的强制隔离、Tool Adapter Layer 统一治理工具调用、分级人审门控制高风险动作、append-only 审计保证可追溯。短板是论文偏架构描述、缺乏量化实验（证据质量较弱），落地时仍需自行验证各组件在高 QPS 下的开销。

George Fatouros, Georgios Makridis, George Kousiouris, John Soldatos, Dimosthenis Kyriazis
