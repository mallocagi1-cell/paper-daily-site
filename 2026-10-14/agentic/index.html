SOAR: Source-Aware Reinforcement Learning with Precise Credit Assignment for Search Agents

将模型内部知识与外部检索证据分为可观察的两条信息流，并用来源一致性奖励约束搜索 Agent，避免答对却编造依据。3B 模型七项问答平均准确率为 0.414，Search-R1 为 0.372；证据编造率从 16.08% 降至 4.05%，相对下降 74.81%。这些是离线问答结果，尚不能等同社区搜索的线上收益。

Do Prompt Optimizers Break Requirements They Are Not Scored On? A Preregistered Study

预注册研究比较 GEPA、MIPROv2 与 TextGrad，发现优化答案准确率时会破坏未计分的输出契约。HotpotQA 精确匹配提升 21–34 个百分点，同时引用违规回归达 10.7–41.6 个百分点；后续分析发现 200-token 输出限制引起 13.9%–47.0% 的截断，放宽至 1,024 token 后内容回归低于 1 个百分点。核心问题是优化目标与完整契约不一致。

INSIGHT社区搜索回答的优化不能只看答案匹配，还应把 JSON 格式、引用、拒答条件和长度限制纳入独立校验。应分别统计解析失败与可解析回答的内容错误，尤其检查输出预算是否被推理耗尽；这能避免把截断误判成知识退化，也能及时发现离线得分上涨但页面无法呈现或引用失效的实际回归。

Sangdo Han, Moonsoo Kim

03 4.00

Test-Time Memory Construction

T²Mem 将复杂记忆构建推迟到查询时，离线仅保留轻量事件元数据和原始交互链接，由 Agent 随推理逐步检索并组织相关记忆。Qwen3.5-27B 在 LoCoMo 上平均得分 71.69，优于 LazyMem 的 69.84；LongMemEval 达到 84.80，超过 LightMem 的 77.40。开源实现为复现提供入口，但调用成本仍需按业务负载评估。

INSIGHT对于社区连续搜索与追问，可先保存会话事件索引，再根据当前问题补齐原始帖子和历史交互，减少预先构建全量记忆的工作。重点验证知识更新、跨会话引用及用户偏好恢复；论文的长期记忆指标不能直接替代搜索相关性，试点应同时测量额外工具调用、响应延迟和查询级 nDCG。

MADS: Multi-Agent Dialog Simulation for Robust Conversational Agents

UUC Santa CruzUniphore

MADS 用多 Agent 合成并校验非合作用户对话，结合 SFT 与可验证奖励训练工具调用策略。正文表 1 给出 189 段对话、1,095 个轮次，摘要对此表述存在不一致；本文按正文统计。Qwen2.5-7B 的 Pre-Act 工具 F1 从基础模型 0.38 提高到 SFT 的 0.70，再到 SFT+RLVR 的 0.77，展示了失败路径训练的作用。

INSIGHT社区搜索助手也会遇到问题改口、信息缺失和不合理工具请求，可为这些轨迹构造明确的工具与参数检查，而不是只用顺畅问答训练。需分别统计轮次级工具准确率和整段任务成功率；MADS 的跨领域数据规模较小，适合作为失败路径设计参考，不能据此认定社区搜索 CTR 会提升。

How to Rewrite Apache Spark UDFs for GPU Acceleration with AI Agents

NVIDIA

NVIDIA 展示通过四个 Agent 技能环节完成 Spark UDF 的测试、转换、基准测量与优化，按 SQL、cuDF 或 CUDA 路线消除 CPU 回退。某大型消费科技公司已转换 30 多个生产 UDF；一个 6,000 亿行负载的算子累计时间由 274.55 小时降至 12.78 小时。这里是特定算子加速案例，不能推断整个搜索链路均获得同等收益。

INSIGHT对社区搜索的数据清洗、特征生产和离线评测，可借鉴以可执行语义测试与性能反馈驱动 Agent 的方法。先筛选确实造成 GPU 回退的 UDF，再校验空值、类型边界和输出一致性，最后比较端到端作业成本；本文主要贡献是工具调用与验证闭环，适合数据工程试点，和在线排序模型优化应分别衡量。

Temporal Evidence Forests for Long-Horizon Multi-Party Conversational Memory

T-Mem 针对多人长期对话中的状态更新与交错讨论，利用时间邻域发现遗漏证据，再构建记录状态转移和支持关系的证据森林。GPT-5.5 配置下，GroupMemBench 总体准确率为 63.09%，HippoRAG2 为 54.50%；EverMemBench 为 79.46%，超过最强已完成基线的 71.04%。结果说明时序组织能够补充单纯的语义相似度。

INSIGHT社区帖子和评论里的纠正、补充与最终结论常发生在相邻时间段，检索相似片段容易混淆旧状态与新状态。可借鉴时间邻域扩展和状态转移结构，把当前事实及其修改来源一起交给回答 Agent；上线前需检查编辑时间、跨用户同名实体及被删除内容，避免时序结构把过时观点重新当成现状。

Evo$^2$: Evolving the Evolver through Weight-Harness Co-Evolution

Evo² 将 Agent 模型权重与运行框架共同优化，同一策略分别提出框架修改和反思执行结果，EvoTIDE 再结合 SFT 与交错 GRPO 学习可用轨迹。Qwen3.8-27B 在 Polyglot 达到 82.1%，最强基线为 62.6%；SWE-bench Verified 为 48.3%，对比 HGM 的 41.0%。论文也报告记忆任务迁移，但编程基准与社区搜索存在场景差异。

INSIGHT搜索 Agent 的质量同时取决于模型及检索、上下文、停止条件等运行设计，可把框架改动与执行反馈成对记录。社区业务更适合先在冻结模型的情况下迭代提示词和工具策略，再考虑权重训练；每次修改都用未参与优化的查询集检查 nDCG、引用正确性和成本，防止框架进化仅适配训练任务。

Scaling Agentic Data for Long-Horizon Terminal Intelligence

USTCAlibabaSUSTech

TerminalHorizon 从真实专业任务出发，先用独立执行发现被环境构建预先解决的关键工作，再扩展任务以保留探索、纠错和验证。论文构建约 1.5K 环境与 3K 轨迹，训练 Qwen3.5-27B 后 Terminal-Bench 2.0 从 41.6 提升至 55.8，AutomationBench 完成率从 5.5 升至 17.2。结果覆盖 12 个基准，社区搜索迁移仍待验证。

INSIGHT构造搜索 Agent 训练环境时，不应提前提供已经整理完的答案或消除检索困难，否则轨迹只教会执行命令。可将社区复杂查询拆为寻找证据、核对冲突、修订判断和输出可追溯答案，逐步增加约束；同时保留独立验证环节，评价完整任务成功率与相关性，避免把长轨迹或更多调用本身视为能力提升。

Agent Evaluation Metric for multi-turn conversations

Amazon

AWS 的 AEM 将多轮 Agent 正确性拆成真实性和完整性，并逐轮记录工具、参数及回答的错误原因。文中的五轮示例把第 2 轮的一次错误与后续三次级联失败区分开，说明整段失败计数会掩盖根因。文章提供评价机制和实施路径，没有披露生产提升比例；示例中的数值用于解释指标，而非实证收益。

INSIGHT社区多轮搜索可把错误拆为查询理解、工具选择、参数值、证据覆盖与最终回答，再标注从哪个轮次开始传播。这样同一个错误改写导致的多次失败不会被误算成多个独立问题；采用相似度或模型裁判时，需要用人工标注查询校准阈值，并将这些诊断指标与 nDCG、CTR 和最终成功率并行记录。

Automated agent evaluation with Amazon Bedrock AgentCore and GitHub Actions

Amazon

AWS 给出将 AgentCore 与 GitHub Actions 连接的工程示例，在拉取请求上部署 Agent、调用 MCP 工具、收集轨迹并执行四项内置评价。示例以 0.8/1.0 为门槛检查任务成功、正确性、工具选择及参数准确率，再清理测试资源。文章提供可运行流程与失败示范，没有对照实验，门槛数值也不是通用业务标准。

INSIGHT社区搜索 Agent 的提示词或工具变更应触发固定查询集回归，检查工具参数和引用，并将模型评分与确定性校验结合。可借鉴每次改动都保留轨迹、输出评价 JSON 和清理资源的闭环；实际阈值需要业务标注校准，且机器间调用示例绕过用户角色检查，权限测试须另设用户身份场景。
