Efficient Listwise Reranking with Compressed Document Representations

针对 LLM listwise 排序计算开销过大的问题，本文提出 RRK，将每篇文档先通过 RAG 中常用的文档压缩技术编码成多 token 的固定长度 embedding，再用蒸馏方式训练 listwise reranker。8B 参数的 RRK 相比 0.6B-4B 的小型 reranker 仍可提速 3-18 倍且质量持平甚至更优；在长文档基准上优势进一步放大。

KEY INSIGHT · 对业务意味着什么把“压缩 + 蒸馏 + listwise”三件套组合是 LLM 重排在 UGC 短/长文本搜索中落地的关键路径：用紧凑表示替代 token 拼接可大幅压缩输入长度，蒸馏让大模型质量迁移到推理友好的形态。社区搜索的 reranker 完全可以参考这种“先压再排”的两阶段方案，把现有 cross-encoder 替换为基于压缩 embedding 的 LLM listwise 排序，兼顾 nDCG 与延迟。

Breaking the Autoregressive Chain: Hyper-Parallel Decoding for Efficient LLM-Based Attribute Value Extraction

Amazon

针对电商场景中“同一文档抽取多条属性值 (Attribute Value Extraction, AVE)”的离线大批量任务，提出 Hyper-Parallel Decoding (HPD)：通过 position ID 操控让多条互相独立的输出序列在同一批次内乱序生成，并把多文档拼接进同一 prompt，单次最多并行解码 96 个 token。在不损失质量的前提下，推理成本和耗时降幅最高达 13.8 倍，对所有 LLM 通用。

INSIGHTUGC 内容理解里“标题抽实体 / 帖子打标签 / 给评论打多维属性”完全是 AVE 同型任务——多条短输出共享同一上下文。HPD 提供了一个无须改模型的纯解码侧加速思路：识别出条件独立的输出，复用 KV cache 与计算，乱序解码后再回拼。社区搜索的离线索引侧（query 改写、帖子打 tag、行为属性挖掘）可以直接借鉴这种 batched parallel 解码，把 LLM 离线打标的吞吐拉到接近线性的水平。

Theodore Glavas, Nikhita Vedula, Dushyanta Dhyani, Yilun Zhu, Shervin Malmasi

When to Retrieve During Reasoning: Adaptive Retrieval for Large Reasoning Models

HKU

DeepSeek-R1、OpenAI o1 这类长链路推理模型在标准 RAG 框架中“开头一次取证、后续盲推”的范式存在错位。本文提出 ReaLM-Retrieve，包含三件事：(1) 步级不确定性检测器，在 reasoning step 粒度（而非 token/句子）识别知识缺口；(2) 干预策略学习何时调用外部证据收益最大；(3) 工程优化把单次检索开销降低 3.2 倍。在 MuSiQue / HotpotQA / 2WikiMultiHopQA 上验证有效。

INSIGHT推理模型时代的 RAG 不再是“先检索后生成”，而是“边推理边按需取证”。社区搜索如果引入 reasoning LLM 来做长尾问答或多跳问题理解，必须配套这种步级不确定性触发机制——避免一次性灌大量低相关的帖子进 context 反而干扰推理；同时步级触发能把检索次数压到必要的最小值，控制延迟。这是把 reasoning model 工程化部署到搜索链路的关键启示。

Dongxin Guo, Jikun Wu, Siu Ming Yiu

Accelerating RL Post-Training Rollouts via System-Integrated Speculative Decoding

NVIDIA

前沿模型 RL post-training 的瓶颈集中在自回归 rollout 生成。本文把投机解码 (speculative decoding) 当作无损加速原语接入 NeMo-RL + vLLM，同步/异步流水都支持，并兼容 MTP heads、外部小 draft 模型乃至 Eagle3 等多种投机机制。在 8B 推理 RL 训练实测显著加速，且不改变目标模型输出分布。

INSIGHT搜索/推荐场景如果跟进生成式 RL 训练 (RLHF/RLEF/GRPO)，rollout 是真实成本大头。本文给出的“投机解码 = 无损加速原语”工程范式很值得借鉴：在不重写训练流程的情况下，单纯换上带 spec decoding 的推理后端就能拉高 RL rollout 吞吐。配合 vLLM/NeMo-RL 这种成熟栈，落地门槛比从头搭分布式训练低得多，是性价比最高的训练侧优化方向。

Hayate Iso, Tiyasa Mitra, Sudipta Mondal, Rasoul Shafipour, Venmugil Elango

CroSearch-R1: Better Leveraging Cross-lingual Knowledge for Retrieval-Augmented Generation

BBJTUUniversité de Montréal

多语种语料中其它语言的知识可以补充和纠正主语言的事实，但简单拼接不同语言上下文反而会因表达差异而失效。本文提出 CroSearch-R1，把 GRPO 强化学习和多轮检索结合：策略学习在每一轮主动调用跨语种检索，将不同语言的证据动态对齐到统一表示空间，并通过多语言 rollout 提升跨语推理迁移性。

INSIGHT社区搜索面对多语种 UGC（中/英/泰/日混杂）时常遇到同一问题在某种语言下答案丰富、在主语言下空洞。CroSearch-R1 给出的“GRPO 学习何时跨语取证、再用对齐 head 把跨语证据塞进上下文”是一个可行模板：把检索 step 视为可学习动作而非固定 pipeline。落地时可以先在小流量跨语 query 子集上做 RL 微调，作为多语 RAG 主搜的补全层。

Rui Qi, Fengran Mo, Sijin Lu, Yufeng Chen, Jian-Yun Nie, Kaiyu Huang

AgentSim: A Platform for Verifiable Agent-Trace Simulation

训练可信赖的 agentic LLM 需要带 grounded 推理过程的数据，但现有 QA 数据集只有结果，CoT 数据没有挂到具体文档，web-agent 数据集只记录界面动作而非 RAG 真正的检索-合成步骤。AgentSim 是一个开源平台，可生成带可验证轨迹的 RAG agent 训练样本，把 retrieval 和 synthesis 两步显式打标。

INSIGHT社区搜索如果要训自己的搜索 agent（query 拆解 → 多轮检索 → 答案聚合），数据是核心瓶颈。AgentSim 给出的“轨迹可验证”思路对工业搜索很有意义：每步检索调用 + 引用文档 ID + 中间结论都可重放回放。可以把站内 query 日志 + 帖子库 + 标注答案塞进这种平台，自动产出大规模带 grounded trace 的 agent 训练数据，比人工标注 RAG 链路便宜数量级。

Turning the TIDE: Cross-Architecture Distillation for Diffusion Large Language Models

PKU

扩散式语言模型 (dLLM) 支持并行解码与双向上下文，但 SOTA 模型仍要数十亿参数。本文提出 TIDE，首个跨架构 dLLM 蒸馏框架：TIDAL 按训练进度和扩散时间步动态调蒸馏强度；CompDemo 用互补掩码增强 teacher 的上下文；Reverse CALM 用反向 chunk 似然匹配做跨 tokenizer 训练。把 8B dense teacher 成功蒸馏到不同架构 student。

INSIGHT扩散 LLM 在搜索/推荐场景里因为并行解码和双向上下文，理论上比自回归更适合“批量 query 重写、批量召回扩展、双向打分”这类任务。但 8B+ 的 dLLM 在线服务成本高。TIDE 提供的跨架构蒸馏路径意味着可以把大 dLLM 的能力压到自家自回归小模型里，享受 dLLM 的训练范式优势同时保留传统推理栈，这是把 dLLM 引入工业搜索的现实切入点。

Gongbo Zhang, Wen Wang, Ye Tian, Li Yuan

SpecTr-GBV: Multi-Draft Block Verification Accelerating Speculative Decoding

现有投机解码要么靠多 draft 提高接受率，要么用 block verification 一次验多 token，两者割裂。本文 SpecTr-GBV 把多 draft 与 greedy block verification 统一进同一框架，把验证步建模为 draft/target token block 上的最优传输问题，理论上证明在 i.i.d 框架下可达可实现的最优期望接受长度，实证也优于现有 SD 方案。

INSIGHT搜索/推荐里的 LLM 在线打分、query 改写都是延迟敏感场景，投机解码已成为标准化加速手段。SpecTr-GBV 的“最优传输 + 多 draft + block 联合验证”统一视角让我们能用一个理论框架挑选 SD 算法配置，而不必在 Eagle / Medusa / ReDrafter 里反复经验调参。可以作为线上 LLM serving stack 中 SD 模块升级的下一步选项，特别是在 batched decoding 场景下。

Yijun Lin, Jinhao Sheng, Qingyue Cai, Feng Zhou

Don't Retrieve, Navigate: Distilling Enterprise Knowledge into Navigable Agent Skills for QA and RAG

NUS

传统 RAG 让 LLM 被动接受检索结果，看不到语料整体结构也无法主动回溯。Corpus2Skill 离线把整个文档库蒸馏成一棵层级 skill 目录树（迭代聚类 + 各层 LLM 写摘要 + 物化为 navigable skill 文件），serving 时 agent 从俯视图开始钻取分支、按需调阅原文，可显式 backtrack 与跨分支组合证据。在企业 WixQA 上验证有效。

INSIGHT社区搜索的“主题/版块/帖子”天然就是层级结构，与本文的 skill 树高度契合。把站内热门话题 / 标签体系 / 高质量帖子离线蒸馏成 skill 树，让 LLM agent 先看主题概览再钻进具体板块再调原文，可以替代纯向量召回。这种“导航式 RAG”在长尾、多跳、需要跨主题聚合的查询上尤其有优势，对社区问答类长尾流量是个值得试的方向。

Yiqun Sun, Pengfei Wei, Lawrence B. Hsieh

GLM-5V-Turbo: Toward a Native Foundation Model for Multimodal Agents

ZZhipu AI

GLM-5V-Turbo 把多模态感知作为推理、规划、工具使用与执行的核心组件，而不是语言模型的辅助接口，面向真实环境中能“看图、读网页、操作 GUI”的 agent。报告涵盖模型设计、多模态训练、强化学习、工具链扩展与 agent 框架集成五条主线，在多模态编程、视觉工具使用与框架式 agent 任务上获得强表现，纯文本编程能力也保持竞争力。

INSIGHT社区搜索正在从纯文本走向多模态（图文帖、视频、富媒体）。GLM-5V-Turbo 体现的“原生多模态 agent”思路（把图像/视频/网页/GUI 作为一阶上下文）启发我们：站内多模态搜索不应是“VLM 抽 caption + 文本检索”两段式，而可以把多模态内容直接交给 agent 边看边检索。开源国产 VLM agent foundation 也意味着自部署多模态搜索 agent 的门槛在快速下降。

V Team, Wenyi Hong, Xiaotao Gu, Ziyang Pan, Zhen Yang
