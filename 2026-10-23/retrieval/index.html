pplx-embed-v2-late Technical Report

Perplexity 发布 0.6B 和 9B 两个多向量检索模型，能编码文本、图片和文档截图：文档每个 token 存一个 128 维向量，查询的每个向量取它和文档向量内积的最大值再求和打分。两个模型都去逐 token 拟合同一个 18B 教师的输出向量，因此向量空间相同，可以用 9B 离线建文档索引、线上用 0.6B 编码查询。在 72 个领域检索任务上，9B 平均 nDCG@10 为 81.3%，比 nemotron-3-embed-8b 高 1.6 个百分点；0.6B 查询配 9B 索引得到 79.6%，高于两端都用 0.6B 的 78.0%。BrowseComp+ 上 9B 让智能体答对 64.0%，搜索次数也最少。

Directional Posterior Feedback Fusion for Query Reformulation in Dense Retrieval

TsinghuaRenmin University📖 深度解读 · 12 分钟 →

用第一轮检索文档或大模型写的假想答案（HyDE）来改写查询向量时，常见做法是把反馈向量取平均再和原查询插值。DIFF 认为一条反馈只支持查询往某个方向修正，其他方向不该被它拉回：它先减掉每条反馈与原查询平行的部分，得到这条反馈要求的转动方向和幅度，只约束修正量在这个方向上的投影，再按反馈与查询的相似度和整组方向是否一致加权，解一个 K×K 的线性方程得到修正，不训练任何模型。BEIR 14 个子集上，bge-base 配 HyDE 反馈的平均 NDCG@10 从原查询的 0.5492 升到 0.5717；用检索文档做反馈时，向量平均会掉到 0.5045，DIFF 是 0.5522。

Yiteng Tu, Qingyi Pan, Weihang Su, Jiaxin Mao, Yiqun Liu, Qingyao Ai

Scan or Index? large Evidence Coverage, Answer Quality, and Cost in Long-Document RAG

长文档问答该先建向量索引再检索，还是每次让模型把全文逐段看一遍？作者在 396 道 QASPER 论文题和 8 本完整教科书的 80 道题上比较了 11 种配置，固定段落切分、最多取 5 段和同一个回答模型。教科书上，混合检索加 Jev 重排的证据覆盖率最高（94.1%），Jev 全文扫描 88.7%，OpenAI 向量检索 81.3%：全文扫描虽然看过每一段，后面的筛减步骤会丢掉相关段落。证据覆盖更高不等于答得更好，答案准确率最高的是混合检索加 OpenAI Decisions 重排（0.892）。查询一多，可复用的向量索引成本最低。

An Explicit Feedback Contract for Iterative ML-Agent Harnesses

让 ML 智能体改代码、跑实验、看验证集分数、再决定下一步时，它会不断留下“碰巧在这份验证集上更高”的改动。沃尔玛团队给这个循环定了一个反馈规则：只有新提交相对当前最好结果的提升超过按配对标准误算出的噪声阈值，才把验证分数告诉智能体，并规定何时停止、何时才能碰测试集。在一个构造上不可能有提升的对照任务上，看精确分数的智能体最后报告提升 0.0157，按规则只报告 0.0033。Criteo 点击率和 MSLR 排序两个真实任务上，验证与测试的差距缩小，测试分略高；看精确分数时 3 个任务里有 2 个用满 30 次提交，按规则 4 到 12 次就停了。

How to Read Data into GPU Memory in Python with NVIDIA GPUDirect Storage

NVIDIA

NVIDIA 的这篇教程讲怎么在 Python 里用 KvikIO 把文件直接读进 GPU 显存，不经过 CPU 内存中转（GPUDirect Storage）。读取要经过两次选路：KvikIO 先决定走 cuFile 还是自己的 POSIX 兼容路径，小于阈值（教程环境为 16 KiB）的读直接走 POSIX；cuFile 再决定走 nvidia-fs 加速路径还是 CPU 中转的兼容路径。两处分别由 KVIKIO_COMPAT_MODE、KVIKIO_GDS_THRESHOLD 环境变量和 cufile.json 里的并行切分参数控制。判断是否真的走了加速路径，要设 CUFILE_STATS_LEVEL=3，再用 gds_stats 看计数落在 nvfs 还是 posix 一栏。

The science behind TorchNeuron, Amazon’s new PyTorch backend for AWS Trainium chips

Amazon

TorchNeuron 是亚马逊开源的 PyTorch 后端，让 PyTorch 模型直接在 Trainium 芯片上运行。可选的“自适应 eager”模式把逐个执行的算子攒成小计算图，交给后台编译、缓存后排队执行，并按图的大小挑选切分方式，让编译和已编译部分的执行重叠，接近整图编译的速度。编译产物在内存和磁盘两级缓存，同一台服务器上的多个加速器共用一个编译服务；在一个跨加速器的大模型上，到第一步训练的时间缩短约三分之一。测试方面，AI 智能体从 Hugging Face 几十万个模型里按结构特征挑出 841 个代表模型做调优和回归测试。

Running Frontier-Class AI Models Across 8 NVIDIA DGX Spark Nodes

NVIDIA

NVIDIA 宣布 DGX Spark 正式支持 8 台组成集群，每台 128 GB 统一内存，合计 1 TB，可以本地跑完整的 GLM 5.3（753B，NVFP4 约 470 GB）：单并发预填充约每秒 1,600 token，解码每秒 31 token。交换机组网下，专门的集合通信后端 RoCEnante 降低了张量并行解码中 all-reduce 的延迟，8 台的解码加速比从 3.05 倍提到 4.43 倍。在 8 台上从头预训练 nanochat，加速 7.79 倍，扩展效率 97.4%。

PACE: Periodic and Channel-Aligned Encoding of Four-Bit Recurrent States

线性注意力模型为每条正在解码的序列存一份固定大小的循环状态，状态存得越省，一张卡能同时服务的序列越多。已有方法每生成一个 token 就把状态量化一次，4 比特下效果明显下降。PACE 改为每隔几个 token 量化一次，中间的 token 先放进小缓冲区；另外发现门控 delta 状态里的大数值按列聚集，于是每一列共用一个量化缩放系数；最容易累积误差的几个注意力头保留 8 比特。在 4B 到 35B 的四个混合架构模型上，4/8 比特混合版在三个较大模型上与 8 比特的 DAMP 效果相当，内存约为其三分之二；纯 4 比特版在同等内存下优于 Q-Mamba。

FrontierCS 2: A Benchmark for Computer Science R&D

FrontierCS 2 检验 AI 智能体能否做计算机科学研发：取一篇论文和作者公开的代码，删掉论文的核心贡献，智能体要在这个代码库里重新实现，并超过被删掉的原始实现。48 个任务覆盖机器学习系统、高性能计算、数据库、安全、机器人等 13 个领域；智能体可以随时提交补丁并拿到开发集分数，最终用不公开的测试集和原实现对比。12 个智能体里最好的是 Claude Opus 5.5，58% 的运行通过；有 16 个任务没有任何一次运行通过。综合分超过原实现的运行，多数仍在某个指标或负载上达不到要求。

MemoryTax: The Bitter Lesson of Agent Memory

Mem0、Zep 这类智能体记忆系统在问题到来之前就决定存什么；编码智能体则保留原始对话，让模型自己用工具去搜。作者在 LoCoMo 的一段对话（419 轮、152 个问题）上，分别用 GPT-4o-mini、GPT-6 Luna 和 Claude Opus 5.5 跑四种记忆方法（全文上下文、BM25、Mem0、Zep）和三个编码智能体（Pi、Codex、Claude Code），并记录每次成本。Mem0 只在 GPT-4o-mini 上胜过全文上下文，光建记忆的花费就超过一次全文上下文问答；用 Claude Opus 5.5 时，Pi 答对 99%，成本不到全文上下文的一半。每个组合只跑一次，作者自己说明研究规模很小。

Zedong Peng
