MARS: Multi-rate Aggregation of Recency Signals for Sequential Recommendation across Sparse and Dense Regimes

序列推荐里，Transformer 用位置自注意力、State-Space Model（如 Mamba）用单一隐式衰减来加权历史行为，二者都没把真实用户行为的多尺度时间结构显式建模。MARS 提出一个与编码器无关的聚合算子：直接消费真实时间戳，产出 K 个强调不同 recency 尺度的摘要，再用上下文自适应门控融合。它最多只增加 6% 参数、时间复杂度 O(LdK)，并按训练集平均序列长度自动在稀疏数据用 MARS-T（Transformer）、稠密数据用 MARS-M（Mamba）间切换。在 5 个公开 benchmark、对比 10 个 Transformer/Mamba 基线（统一 RecBole 协议）下，MARS 在每个 benchmark 上都拿到最佳 HR@10，平均相对提升 +19.7%。

Taiji: Pareto Optimal Policy Optimization with Semantics-IDs Trade-off for Industrial LLM-Enhanced Recommendation

Kuaishou📖 深度解读 · 14 分钟 →

快手的 Taiji 让一个 7B 模型读用户画像和最近 50 条行为，推理“下一单会买什么”，输出编码后给广告排序模型当特征，或用来找最相似的用户借行为序列。思维链先“知道答案再反推”、按困惑度筛掉一半，强化学习的两个奖励权重按区分度自动调。线上 ADVV 涨 2.83%、收入涨 3.30%，长尾用户涨 5% 以上。离线奖励和评估用同一个排序模型，动态权重在偏好指标上只多 0.74%。

BAHSD: Bridging the Long-tail Gap via Adaptive Distillation in Black-box Sequential Recommendation

CAS

序列推荐常以黑盒 API 部署，催生了「模型抽取」把能力本地复刻的需求。但长尾分布带来严重信号异质性：稠密 head 序列会固化 teacher 偏好、把抽取偏向局部模式；稀疏 tail 序列预测平坦且噪声大。现有一刀切抽取忽视这种差异，导致噪声过拟合。BAHSD 提出黑盒自适应蒸馏：用多尺度一致性探测机制隐式量化信号可靠性，再设计分层目标——高置信信号用动态温度 KL 散度缓解偏好固化，tail 用排序一致性与 InfoNCE 对比约束抑制噪声。

INSIGHT把蒸馏温度/损失从全局常数改成按信号可靠性自适应分层，是处理长尾的通用技巧。社区内容天然长尾（大量低频 query/低曝光帖），head 与 tail 用同一蒸馏目标会顾此失彼；BAHSD 的「多尺度一致性探测 → 动态温度 KL + tail 用 InfoNCE」可迁移到本地化精排/召回蒸馏。黑盒抽取视角也提醒：只靠 teacher 打分蒸馏会固化头部偏好，需对 tail 单独设计监督信号。

Xi Zhou, Famin Wu, Mingming Li, Hongyue Zhang, Jiao Dai, Jizhong Han, Tao Guo

The Efficiency vs. Accuracy Trade-off: Optimizing RAG-Enhanced LLM Recommender Systems Using Multi-Head Early Exit

Meta

Meta 团队针对 LLM 做 CTR 预估时的效率/精度两难，提出 RAG + 多头早退（multi-head early exit）联合优化框架。检索端用 Graph Convolutional Network (GCN) 作为高效检索机制，显著降低数据检索耗时同时保持性能；推理端用早退策略，基于多个 head 的实时置信度评估动态终止推理，在不牺牲（甚至提升）精度的前提下加快 LLM 响应。实验展示该架构在实时场景下能同时兼顾效率与准确率。

INSIGHTLLM 做 CTR 的最大落地障碍是在线延迟，这篇给出两个互补杠杆：用 GCN 把 RAG 检索成本压下来、用多头早退按置信度提前出分。对要把 LLM 引入精排/重排但卡延迟的团队，多头早退是低改造成本的推理加速思路——不同 head 对应不同退出深度，简单样本浅层即可出分。注意这是 2025-01 的工作（此次为 replace 版本），新鲜度有限，可作为 LLM-CTR 工程加速的参考基线。

Huixue Zhou, Hengrui Gu, Xi Liu, Kaixiong Zhou, Mingfu Liang, Yongkang Xiao, Srinivas Govindan 等 18 人

VirtualMLE: A Virtual ML Engineer that Optimizes Sequential Recommenders

序列推荐模型在新数据集上调参仍高度依赖资深 ML 工程师的手工试错。VirtualMLE 是一个 LLM-agent 框架，把推荐器优化组织成「执行—反思—记忆更新」的闭环：每次试验后 agent 显式分析观测结果，把简洁的启发式反馈存入分层记忆系统，指导下一轮调参。在三个 Amazon 序列推荐 benchmark、用 SASRec 和 HSTU 两种代表性骨干上评估，VirtualMLE 用明显更少的试验次数就达到了有竞争力的推荐质量。

INSIGHT把「调参」当成可被 LLM-agent 自动化的工程工作流，是这篇的角度。对长期维护大量推荐模型、调参成本高的团队，分层记忆 + 反思闭环提供了 AutoML 之外的新路径——agent 积累的是可读的启发式经验而非黑盒超参搜索。在 SASRec/HSTU 上都奏效说明其骨干无关性，可作为内部炼丹自动化的原型参考；但仅在 Amazon 公开集验证，工业大规模可扩展性待考。

Shiteng Cao, Jingwen Liu, Junda She, Zhiheng Li

TalkPlay: Multimodal Music Recommendation with Large Language Models

KAIST

TalkPlay 把音乐推荐重构成 LLM 的 token 生成问题：利用 LLM 的指令跟随与自然语言生成能力，从多样的用户 query 推荐音乐并生成上下文相关回复。两个关键创新：一个多模态音乐 tokenizer，编码音频特征、歌词、元数据、语义标签和歌单共现信号；一个词表扩展机制，让语言 token 与音乐相关 token 统一处理与生成。通过把推荐系统直接嵌进 LLM 架构，TalkPlay 把传统两阶段对话式推荐统一成单一生成模型。

INSIGHT把「物料」编码成可被 LLM 词表统一生成的 token（音频/歌词/元数据/共现信号），是生成式推荐落地多模态内容的代表做法，思路同 Semantic ID 一脉但更强调多信号融合。对社区内容（帖子=文本+图+互动信号）的对话式检索有借鉴：用扩展词表把异构内容信号统一进 LLM 生成空间，可省去传统召回-排序两阶段拼接。代价是 tokenizer 设计复杂、生成式推理成本高，更适合对话式/会话式场景而非高 QPS 精排。

Seungheon Doh, Keunwoo Choi, Juhan Nam

LLM-Assisted Reranking to Operationalize Nuanced Objectives in Recommender Systems

UPenn

推荐系统已从内容组织工具演变为塑造日常行为的系统，引发对信息茧房、极化的担忧；LLM 让个性化更强，也可能放大这些动态。本文用真实新闻消费历史，通过零样本指令式 prompting 对 YouTube 侧边栏候选做 LLM-assisted reranking，实证检验：在提升个性化的同时，是否会无意放大对意识形态极端或阴谋论政治内容的曝光。论文把「细腻目标」（如降低极端内容曝光）operationalize 成可执行的 reranking 目标，量化了个性化与社会风险的权衡。

INSIGHT这篇提供的是「用 LLM 把难以量化的细腻目标直接写进 reranking prompt」的范式——传统多目标排序要为每个目标训练打分器，而 LLM 重排可用零样本指令操作化模糊目标（如内容健康度、多样性）。对社区内容治理有直接价值：可在重排层用 LLM 注入「降低低质/极端内容曝光」的约束而无需额外训练。但论文同时警示个性化增强会放大极端曝光，提醒上线 LLM 重排须配合曝光审计，否则优化 engagement 会反噬内容生态。

Amir Ghasemian, Homa Hosseinmardi, Upasana Dutta, Duncan J. Watts
