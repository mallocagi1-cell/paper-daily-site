How We Built TLX: A Hardware-Native GPU Compiler for Production ML at Scale

Meta

新一代 GPU 的性能越来越取决于几组线程怎么分工，比如一组搬数据、一组算矩阵。CUDA 能写这种分工，但要写大量和架构绑定的调度代码，Triton 又把它藏进了编译器。Meta 在 Triton 上加了一层 TLX，工程师继续写 Python，只在关键处显式写线程组的分工和同步。对做推荐的人，最实在的例子是打分时的用户特征：同一份特征通常要按候选数复制几十次。Meta 把这次复制挪进 kernel 内部，配合模型一起改，计算密集部分的净时延最多降了三分之二。GEM 广告模型的训练在数千张 Blackwell 上做到 20% 到 25% 的端到端 MFU。kernel 优化正在变成算法工程师的日常手段。

Multi-GPU MoE Inference with Adaptive Expert Offloading

MoE 模型每个 token 只激活少数专家，所以大部分专家权重可以放在内存里，用到时再算。已有的专家卸载系统大多针对单 GPU 或离线大批量，有的系统加卡后吞吐反而下降。AdaOffload 把专家均匀切到所有 GPU 上，CPU 这边按 NUMA 结构单独切，再结合离线测出的硬件开销和线上观察到的专家负载，实时决定多大比例的未命中专家拉到 GPU 上算。在三个开源模型和五种机器上，推理题负载的平均 decode 吞吐是最强基线的 1.9 到 15.5 倍。最优的 CPU 和 GPU 分工随硬件和负载变化，固定策略跟不上。

PACE: Keeping the Right Tokens in the KV Cache Is Not Enough for Long-Horizon LLM Agents

长会话 agent 的 KV cache 一张卡放不下，只能留一小部分 token，大家默认该留的都留住就行。这篇发现这还不够：需要的 token 几乎全留住了，定义离使用点越来越远时，准确率仍从 93% 掉到 64%。token 还在，只是到 query 的旋转位置距离太远，模型用不好了。PACE 让 agent 的规划器告诉 cache 后面的步骤要读什么，再给留下的 token 重新编号，把距离压在小范围内。在新任务上做的预注册实验里，它通过 97% 的隐藏单元测试，两部分单独用都差一大截。这个结果用的是真实依赖图，任务也是合成的编码会话。KV cache 除了留住 token，还要让它们离 query 够近。

Suman Chatterjee

Hibana: Fast Agentic Inference on Unified-Memory Devices

DGX Spark 这类统一内存设备放得下大模型，但内存带宽有限，decode 常卡在读权重上，agent 的会话状态又和权重抢同一块内存。Hibana 为此改了三处：同一批请求共享一组专家，减少权重读取；不活跃会话的状态存到 SSD；投机解码每步多生成几个 token，按最近的接受率自动调整。在一台 DGX Spark 上回放录制好的 agent 会话，每小时完成的任务数最多是其他框架的 3.4 倍，各自最佳并发下的峰值 decode 吞吐最多是 3.9 倍。快速档是有损的，三比特权重和放宽校验会让部分任务的准确率掉几个点。本地推理要省的是每个被接受的 token 背后的内存流量。

Yahya Emara, Chi-Chih Chang, Anthony Fei, Ahmed F. AbouElhamayed, Chong-Yan Chen, Hung-Yueh Chiang 等 8 人

MACaQ: Fast, Model Agnostic Calibrated Quantization for Low-Precision Weights and Activations

W4A4 量化常靠基变换把输入和权重变得好量化，过去的做法是把输入侧的变换吸收进前面的层，推理时省掉开销，代价是层与层耦合，换个架构就要重新适配。MACaQ 反过来，把每层的缩放和小块旋转留在推理时在线执行，每层独立量化，一次只需把一层放在内存里。这笔在线开销很小，在 Qwen3-32B 上端到端只多 2.3%。再用一个贪心的微调步骤把单个 FP4 编码挪到相邻取值，困惑度比 DuQuant++ 和 MR-GPTQ 更低，达到它们最好的质量时量化速度是它们的 11 倍。在线变换的开销随层变大而摊薄，用它换层间解耦很划算。

Lorenz K. Muller, Philippe Bich, Chiara Boretti, Hyun-Min Chang, Jiawei Zhuang, Lukas Cavigelli

美团 LongCat-2.5 正式开源：从看见，到抵达

Meituan

万亿参数的 MoE 模型要在国产卡上训练，最现实的约束是单卡显存不足 80GB。美团开源的 LongCat-2.5 总参数 1.6 万亿，这篇博客讲了他们怎么应对。训练时用 FSDP 双重分片和扁平化缓冲区压低显存，把参数、专家 token 和 KV 的交换尽量留在超节点内部的高带宽互联里，并让通信和计算重叠执行。推理用 W4A4，专家权重和激活一起量化，专家间通信和计算全程用同一份 INT4 表示。长序列 SFT 任务上，这套 FSDP 配置的单卡吞吐比 DDP 基线高 86%。显存和带宽的边界改不了，能改的只有架构、算子和并行策略。

Start and Restore GPU Workloads in Seconds with NVIDIA Snapshot

NVIDIA

推理流量突增或副本故障时，空闲的 GPU 也接不上活，因为初始化一个大模型要好几分钟。NVIDIA 开源的 Snapshot 把初始化好的工作负载连同 CPU 和 GPU 内存一起存下来，在同型号 GPU、同驱动的节点上直接恢复，跳过权重加载、编译和图捕获。在 vLLM、SGLang 和 TensorRT LLM 上，恢复比冷启动快 8 到 36 倍，所有配置都在 43 秒内回来。在每个测试配置里，做一次 checkpoint 加一次恢复的总时间都短于一次冷启动。这些时间都不含拉镜像和设置容器运行时。第一个恢复的副本就能把 checkpoint 的成本赚回来。
