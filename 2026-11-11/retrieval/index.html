PatternBloom: Empowering Agentic RAG with Externalized RL-Distilled Graph Patterns

已录用 NeurIPS 2026

用强化学习训练的 RAG agent 能学会找更好的内容，可同一类问题该按什么步骤推理，每次都要从头推一遍。PatternBloom 把高分的推理过程抽象成只保留实体类型的模板（论文叫 Graph Pattern Memory，比如从电影查导演、再查导演国籍）。这样的模板一共 27 条，放在模型外面，回答时先查模板再沿着模板找证据。在 MuSiQue 里需要五跳以上的问题上，它的 EM 是 17.4，对比方法中最高的 R1-Searcher 只有 3.9。多跳问答里反复出现的推理路径，本身也可以当检索对象。这些模板人能读也能改，不过实验都在维基百科语料上。

Yi Ge, Heng Huang

Search-by-Answer Bias in Retrieval Models

向量检索本该按 query 问的关系找段落，这篇发现它会偏向模型本来就知道的答案。作者造了成对的句子，一种只换答案实体，另一种让关系对的句子配替代答案、关系错的句子配熟悉答案。八个检索模型上，模型给某个答案的概率越高，含这个答案的段落得分就越高。在模型本就偏向标准答案的样本里，Qwen3-Embedding-8B 只换答案时有 94.6% 选熟悉的那句，无偏时应是 50%，关系错的句子也有 65.0% 排在前面。答案不止一个或者会过时的查询，召回容易被模型记住的答案带偏。实验句子都是模板生成的。

Adiel Avigad, Shauli Ravfogel, Yoav Goldberg

CoRA-Bench: Evaluating Evidence Preservation by Context Selectors Under Token Budgets

已录用 NeurIPS 2026 Workshop

长上下文推理前先筛一遍内容能省 token，也可能把答案证据筛掉。CoRA-Bench 在相同 token 预算下比了截断、BM25、向量检索、重排和两种压缩方法，结果没有哪种方法通吃。在证据和问题字面重合很少的 NoLiMa 上，向量检索的证据召回是 0.908，BM25 只有 0.467，到了字面线索明显的 BABILong，BM25 反过来领先。保住证据也不等于答对，Provence 在 LongMemEval 上按逐字标准几乎没留下完整证据，答题准确率却有 66.60%。选上下文筛选方法时，证据召回和答题准确率要分开看。

Huzaifa Pardawala, Siddhant Sukhani, Sudheer Chava, Agam Shah

TRIAD: Multimodal Retrieval across Abstraction, Constraints, and State

agent 场景下的多模态检索，排在前面的结果可能很相似，却不满足用户的要求。TRIAD 用上下位概念、正反约束、多轮对话三类任务测了二十种模型配置，没有哪一种在六个子集上全部领先。多轮任务的结果最明显：把同一个最终需求拆成几轮说，40 组比较里有 39 组 mAP 下降，掉分集中在用户中途改条件的会话，比如先要橙色后改蓝色。只留最后一轮也救不回来，整体上比保留完整历史更差。多轮检索既要留住还有效的条件，又要清掉被改掉的旧值，这一步现有的 embedding 模型普遍吃亏。

Xiangyang Wu, Chen Ju, Xu Chen, Likang Peng, Jinsong Lan, Haihong Tang, Yang Hu

NIFT-SQL: Customer-Supervised Table Scoring for Enterprise Text-to-SQL Retrieval

企业文本转 SQL 的第一步是找表，可 schema 里常常只有晦涩的表名和列名。NIFT-SQL 用每家客户自己的示例问题单独训练，让一个小 cross-encoder 逐表判断这张表是否必需，再和同样微调过的混合检索融合。在近千张表的 LiveSQLBench-Large 上，把需要的表全部排进前十五位的问题比例，混合检索是 21.8%，NIFT-SQL 是 85.6%，只微调检索器也有 70.4%。这个领先并不稳，换到更新的 BEAVER 版本、只用合成问题训练时，它在真实问题上输给了只微调的检索器。手里有标注问题时，微调检索器本身就是便宜又强的基线。

Arjun Rao, Nishant Gopinath

Two-Sided Conformal Evidence Sets for Retrieval-Augmented Generation

RAG 检索回来的段落可能支持一个说法，也可能反驳它，现有的校准方法大多只管支持这一边。这篇用共形预测给支持和反驳各出一个证据集，保证每边按设定的概率至少含一条真证据。换打分模型时差别最清楚，换成弱模型后证据覆盖率仍贴着目标，判断准确率却从 0.898 掉到 0.516。数据分布一变，覆盖率也守不住，FEVER 上最多少了 12.7 个百分点，要用部署环境的带标注数据重新校准。证据找得全和结论下得对是两件事，评测时分开报告才看得清。

Ben Jenkins, Mihaela Cardei

Calibrating Document-Local Boundaries for Contextual Chunk Retrieval

Late Chunking 先编码整篇文档再切块，上下文保住了，同一文档里相似的文本块却更难区分。在用同文档负例微调的基线 InSeNT 上，排错的问题里有 82.21% 是同文档的另一块得分压过了正确块。阿里 Qwen 团队的 DcLBC 改了两处。一是看正确块和同文档得分最高的错误块差多少，差得越小，这条 query 的分数放大得越多，二是把文本块边界告诉编码阶段的注意力层。按同文档竞争强度分四档看，NDCG@10 的提升集中在最难的一档，加了 5.46 个点，容易的两档几乎不动。长文档检索的错误，很多出在同一文档内部的区分上。

Yuanxiang Wang, Hui Jiang, Da Zhu, Zhihua Chang
