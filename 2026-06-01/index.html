Towards Generalizable and Efficient Large-Scale Generative Recommenders

论文复盘了把一个生成式推荐主干网络（不含 embedding 与 decoding 层）从 2M 参数扩到 1B 参数的生产经验，场景是工业级的标题推荐。作者发现预训练阶段的收益并不会自动传导到下游应用：任务自身的提升空间（task headroom）、重复训练成本、serving 延迟、item 时效性都会削弱迁移效果。在多个下游任务上观察到“任务相关的 scaling 行为”——部分任务在观测的参数区间内就逼近经验上限，另一些则持续受益于更大容量。

Learning Variable-Length Tokenization for Generative Recommendation

生成式推荐把推荐重写为对离散语义 ID (semantic ID) 的 next-token 预测，但已有方法都用“定长 tokenization”给所有 item 编码，隐含假设了统一的编码容量。作者在 4 个数据集上系统实验，发现“流行度-长度悖论 (Popularity-Length Paradox)”：热门 item 用短 ID 就能达到最优，长尾 item 则需要明显更长的 code 才能刻画区分性语义。原因是热门 item 有充足协同信号、不需要太多语义细节，长尾 item 因交互稀疏必须依赖细粒度内容特征。据此提出 VarLenRec，为不同 item 学习可变长度的 semantic ID。

INSIGHT把“定长 ID 给所有 item”这一被忽视的默认设计点拆开，是对 semantic ID 范式的一个真问题修正：对长尾内容（社区 UGC 场景里占绝大多数）给更长 code、对头部内容给短 code，本质是把编码预算按信息量分配。对做生成式检索/推荐的团队，这意味着 tokenizer 设计要和 item 流行度分布耦合，而不是统一码本长度——这对短文本、长尾密集的 UGC 召回尤其有参考价值。

Minhao Wang, Bowen Wu, Wei Zhang

Don't Let Bandit Feedback Pull Continual LLM-Recommender Updates Off Target

生成式 LLM 推荐器 (LLM-Rec) 上线后需要持续更新，但部署日志只能提供“被前一版策略塑形过”的上下文 bandit 反馈：只有被曝光的 item 才有结果，导致曝光偏差 (exposure bias)，且信号是不对称的——正反馈相对可靠、无响应则含义模糊。作者提出 Anchored Bandit Policy Optimization (ABPO)，把 GRPO 与对曝光偏差、反馈歧义的显式处理结合：在每个 GRPO rollout group 里插入“被实际曝光的推荐”作为日志锚点 (logged anchor)，让 group-relative 归一化是相对“前一版策略实际曝光的动作”校准，而不是相对新采样的 rollout。

INSIGHT这篇直击 LLM 推荐器“持续在线更新”里最现实的坑：你只能从自己曝光过的东西学习，naive 地用 GRPO 会被曝光偏差带偏。把 logged anchor 塞进 rollout group 做相对归一化，是一个轻量、可直接嫁接到现有 GRPO/RLHF 管线的技巧。对任何想把 LLM 排序/推荐做成在线持续学习闭环的团队，这是处理反事实/部分反馈的可落地方案。

Taesan Kim, Hyeongjun Yun, Jaegul Choo, Chung Park

GEO-Bench: Benchmarking Ranking Manipulation in Generative Engine Optimization

LLM 越来越多地直接为用户 query 排序产品、文档和推荐结果，操纵这种排序（generative engine optimization, GEO）正成为公平性和信息完整性的隐患。已有 GEO 操纵方法各用各的数据集和指标，相对强弱与可检测性无从比较。GEO-Bench 在统一协议下评测排序操纵攻击：涵盖黑盒 prompt 攻击 (TAP、Zero-Shot)、白盒梯度攻击 (STS、RAF、StealthRank) 与 10 种 white-hat C-SEO 策略，在 5 个数据集上针对固定的开放权重 ranker (Llama-3.1-8B-Instruct) 打分，同时用有效性指标 (NRG、Success@α、Promote@α) 和隐蔽性指标 (关键词违规率、困惑度比) 衡量。

INSIGHT对运营生成式搜索/推荐入口的平台，这是一份现成的“攻防对照表”：它把分散的排序操纵手法统一到同一 ranker 和同一组指标下，让你能评估自己的生成式排序对 prompt 注入式 SEO 的脆弱性。把有效性与隐蔽性分开度量的设计，提示防御侧不能只看“是否被提权”，还要看攻击是否低困惑度、难检测——这对 UGC 社区里对抗刷量、内容操纵的相关性体系有直接借鉴。

Ojas Nimase, Zhe Chen, Gengpei Qi, Yue Zhao, Xiyang Hu

SAPO: Step-Aligned Policy Optimization for Reasoning-Based Generative Recommendation

LinkedIn

生成式推荐把 next-item 预测当作语义 ID (SID) 的自回归生成，SID 是由粗到细的短 token 序列（早期 token 抓大类语义、后续 token 细化）。近期工作给这一范式加上推理链 (reasoning trace) 并用可验证奖励的 RL 优化，常用 outcome-reward + SID 精确匹配反馈。作者指出问题：大目录推荐里，精确匹配只告诉你最终 item 对不对，一旦 SID 不匹配，outcome-reward 无法定位是哪个 SID-token 出错，会把匹配对的 token 位置和出错位置一起惩罚。SAPO 提出 step-aligned 的策略优化，把奖励对齐到逐个 SID-token 步上做信用分配。

INSIGHT这是对“给生成式推荐做 RL”的一个精细化修正：把 outcome-level 的粗糙奖励改成 step-level 的 token 信用分配，解决“一错全错、好 token 被连坐”的梯度噪声问题。对采用 coarse-to-fine SID + RL 后训练的生成式推荐/检索系统，按 token 步对齐奖励是提升训练稳定性和样本效率的可借鉴设计，思路与 NLP 里 process-reward / step-level RL 一脉相承。

Zaiyi Zheng, Guanghui Min, Yaochen Zhu, Liang Wu, Liangjie Hong, Chen Chen, Jundong Li

Generative Conversational Recommender System

对话式推荐 (CRS) 要通过自然语言交互给个性化推荐，但已有方法要么把推荐和对话生成解耦、要么依赖检索式管线，导致推荐与回复生成割裂、对用户意图建模欠佳。论文提出一个完全生成式的对话推荐系统，用单一自回归框架统一推荐与对话生成：把 item 表示为离散 semantic ID 并直接嵌入生成过程，通过 next-token 建模联合预测 item 与回复。并引入结构化生成范式，把对话推荐分解为一串相互依赖的生成步骤。

INSIGHT把“推荐”和“回话”塞进同一个自回归生成里，是 LLM-as-recommender 在对话场景的自然延伸：semantic ID 作为可生成的 item 表征，让模型在生成回复的同时直接“说出”要推的 item，省掉了检索式管线的拼接。对要做 AI 搜索助手 / 对话式内容发现的团队，这种 item-token 与语言-token 共享生成空间的设计，是统一意图理解与结果生成的一个可参考架构。

Sixiao Zhang, Mingrui Liu, Cheng Long

TurboGR: An Accelerated Training System for Large-Scale Generative Recommendation

Huawei

生成式推荐 (GR) 用统一的 Transformer 模型替代碎片化的场景专用架构，表现出 scaling-law 行为。但在 Ascend NPU 上大规模部署 GR 面临系统级难题：缺少 jagged（不规则变长）算子的高性能实现，且不规则稀疏原语与 NPU 偏向稠密计算的架构存在错配。TurboGR 是面向 Ascend 的训练系统，通过三项核心创新解决瓶颈，其一是 Ascend-affinity 的 jagged 加速，针对变长序列推荐特有的不规则计算做亲和优化。

INSIGHT这篇的价值在于把生成式推荐落到非 GPU（Ascend NPU）硬件上的工程真账：GR 的核心痛点是变长用户行为序列带来的 jagged tensor 计算，与加速器的稠密计算假设冲突。对国内受限于国产算力、又想上 GR 的团队，jagged 算子亲和优化、稀疏-稠密错配的解法是直接可参考的系统经验；也提醒 GR 的 scaling 红利能不能吃到，很大程度取决于底层不规则算子的实现质量。

Huichao Chai, Zhixin Wu, Xuemiao Li, Shiqing Fan, et al.

Mixture-of-Experts Knowledge Graph Retrieval-Augmented Generation for Multi-Agent LLM-based Recommendation

LLM 推荐器常依赖参数化知识、易过时，因此用知识图谱检索增强生成 (KG-RAG) 把推荐 grounding 到结构化、可更新的 KG 上。但 KG-RAG 在推荐里有两个难点：用户 query 复杂度不一、需要不同粒度的 KG 知识，而现有方法用一刀切的检索策略，对简单 query 过度检索、对复杂 query 检索不足；此外把图结构数据线性化成文本喂给 LLM 会引入噪声。论文用 Mixture-of-Experts 做自适应粒度的 KG 检索，并在多智能体 LLM 推荐框架下组织检索与生成。

INSIGHT把“检索多少 KG 知识”交给 MoE 按 query 复杂度自适应决定，是对 RAG 推荐里“一刀切检索”这一常见缺陷的针对性修补。对用 KG/RAG 给 LLM 推荐补充时效知识的团队（如社区里需要 grounding 到最新话题、商品、问答的场景），按 query 难度动态调检索粒度、控制图转文本的噪声，是值得借鉴的工程取舍。

Shijie Wang, Chengyi Liu, Yujuan Ding, Shanru Lin, See-Kiong Ng, Xu Xin, Wenqi Fan

Persona Conditioning of Brand Recommendations in Retrieval-Augmented Commercial Chat: A Prominence-Stratified Cross-Provider Audit

同一句 prompt（如“最好的 CRM 软件”）会来自语境迥异的买家：个人创业者、企业 VP、英国中小企业主。论文审计了这种语境差异对模型推荐哪些品牌的影响。审计跑了 2000 次，覆盖 10 personas × 8 prompts × 3 模型配置 × N=10 重复（两个 OpenAI cell 全 8-prompt 覆盖，Anthropic sonnet-4.6/low cell 为 4-prompt）。在 user message 前加 persona 前缀，会让推荐集合的相似度 (Jaccard) 相对同 persona 基线下降 Δ = -0.12 到 -0.20（聚类 95% 置信区间均不含 0）。效应呈显著的“显著度分层 (prominence-stratified)”：头部品类领导者受 persona 影响更稳。

INSIGHT这是一份关于“生成式推荐里 persona/上下文如何重塑结果”的量化审计：persona 前缀能把推荐集 Jaccard 拉低 0.12–0.20，且头部品牌更抗扰、长尾更敏感。对做 RAG/对话式商业推荐的团队，提醒上下文注入既是个性化抓手、也是公平性与一致性风险源；评估生成式推荐系统时应把“同 query 跨 persona 的结果漂移”作为一个独立的稳定性/公平性指标来监控。

Will Jack, Noah Lehman, Keller Maloney, Sarah Xu
