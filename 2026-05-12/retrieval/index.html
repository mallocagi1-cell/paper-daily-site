When Does Embedding Magnitude Matter? A Cross-Task Functional-Symmetry Framework

本文挑战了 dense retrieval 长期默认 cosine 或 dot product 的选择，提出 2x2 的查询/文档独立归一化框架，揭示了之前未被研究的 QNorm 与 DNorm 两种中间变体。在 MS MARCO、BEIR、BRIGHT 以及多跳 QA 四类基准上，单边归一化变体均优于 cosine 和 dot product，相对增益在域外达到 +72%，在下游 RAG 上达到 +24%。论文进一步用 Fisher 信息矩阵的条件数预测应归一化哪一侧，并将该机制扩展到检索之外的 5 项任务，建立了基于功能对称性的任务分类。

KEY INSIGHT · 对业务意味着什么对工业向量检索系统而言，这是少数无需重训、只改打分阶段就能拿到两位数 OOD 收益的工作，特别适合 UGC 短文本搜索这种 query-doc 长度严重不对称的场景。核心洞察是：文档侧 magnitude 控制推理打分，query 侧 magnitude 控制训练梯度，是两条独立的杠杆。实践启示是在线 ANN 索引可以保留 raw embedding magnitude，只在 query 端做归一化（或反之），并用 Fisher 条件数离线挑选侧别，无需 A/B 多轮试错即可定位最优配置。

IntentGrasp: A Comprehensive Benchmark for Intent Understanding

UUBC

针对 LLM 助手中长期缺乏统一意图理解评测的问题，论文从 49 个开源高质量语料合并出 IntentGrasp，覆盖 12 个领域，统一了意图标签上下文化与任务格式。基准包含 262,759 条训练集、12,909 条 All Set 测试集以及精选的 470 条 Gem Set。对 7 个家族 20 个 LLM（含 GPT-5.4、Gemini-3.1-Pro、Claude-Opus-4.7 等前沿模型）的评测显示，All Set 得分均低于 60%，Gem Set 低于 25%，且 20 个模型中有 17 个表现不及随机基线，表明意图理解仍是 LLM 的显著短板。

INSIGHT对社区 UGC 搜索 query 理解管线来说，这是首个跨 12 个开放领域、规模足够大的意图基准，可直接用于评测线上 query intent classifier 的横向能力差异。关键启示是即使最强 LLM 在结构化意图分类上的失败率也很高，说明搜索侧不应盲目把 query 意图改写交给基础大模型，而要保留专用 intent 模型；同时 262K 训练集可用于蒸馏一个轻量 BERT/小模型作为线上意图分类基座，对应短文本召回阶段的多通道触发策略。

Yuwei Yin, Chuyuan Li, Giuseppe Carenini

WiCER: Wiki-memory Compile, Evaluate, Refine Iterative Knowledge Compilation for LLM Wiki Systems

针对 LLM Wiki 这一新兴范式（把领域知识编译成持久 artifact 通过 KV cache 推理），论文系统刻画了与 RAG 的此消彼长。在 RepLiQA 的 17 个领域、6,800 个问题上发现：在小规模 curated 知识上 full-context KV cache 优于 RAG（4.38 vs 4.08/5，TTFT 快 7.3 倍），但规模放大后因 attention dilution 反而劣于 RAG；而盲目压缩 wiki 会带来灾难性失败（2.14–2.32 vs 3.46，53–60% 失败率）。WiCER 借鉴 CEGAR 的反例引导思想，迭代地评估编译产物并精修，闭合 compile-evaluate-refine 循环。

INSIGHT对长尾内容社区搜索/问答系统，这篇给出了一个比传统 RAG 更可控的替代路径：把高频长尾知识离线编译为压缩 wiki，再通过 KV cache 命中复用，可以同时拿到低延迟和零检索失败。关键启示是编译过程必须显式做反例驱动的精修，否则会丢掉关键事实造成线上塌方；这与日志驱动的 query rewriting 词表迭代思路一脉相承，可借鉴 CEGAR 风格做 query rewrite 词典／FAQ 库的自迭代质量门，避免一次性大模型 distill 的不可控漂移。

Juan M. Huerta

04 3.20

MLAIRE: Multilingual Language-Aware Information Retrieval Evaluation Protocal

Korea University

现有多语言 IR 评测把语言无关的语义相关性当作唯一目标，但实际用户偏好读得懂的语言、且跨语言结果会拖累下游 RAG 的事实核验。MLAIRE 提出一个语言感知的评测协议，通过构造跨语言平行的 passage pool，把语义相关性与查询语言偏好两个维度解耦，能分别量化跨语言语义召回率与 query-language 偏好程度。协议同时为 RAG 系统提供可控变量以诊断混合语种语料下的检索效用。

INSIGHT对面向多语种 UGC（中英混合贴、海外社区）搜索系统而言，这套协议给出了一个被长期忽视的评测维度：相同语义相关性下，结果语言是否与 query 语言对齐会显著影响用户验证成本。实践启示是线上 nDCG 不应当作语言无关指标看，而要拆出 same-language nDCG 与 cross-language nDCG，并把语言偏好放进 reranker 特征；这同时也是合规与体验改进的抓手——避免把中文 query 全部返回英文 passage。

Youngjoon Jang, Seongtae Hong, Hyeonseok Moon, Heuiseok Lim

Overview of the TREC 2025 RAGTIME Track

JJHU HLTCOEAAI2

TREC 2025 RAGTIME track 围绕从多语种源文档生成报告这一新任务展开，提供阿拉伯语、中文、英语、俄语新闻语料以及三类任务：多语种报告生成、英语报告生成、多语种信息检索（MLIR）。共有 13 支队伍提交 125 个 run（含组织者基线），论文系统刻画了三类任务设定、评测维度与各 run 的相对表现，可作为今年多语种 RAG/IR 评测的权威参照。

INSIGHT对自建搜索/问答系统的团队来说，RAGTIME 提供了与公司常用 BEIR 互补的多语种基准，尤其覆盖了报告生成这一聚合式输出场景。关键参考是 MLIR 子任务的 baseline 与最强 run 之间的差距能直接定位团队自有多语种 dense retriever 的工业差距；而报告生成任务的评分协议（基于多语种证据聚合）可移植到 UGC 社区 Top-K 摘要、 multi-turn QA 等聚合产品的离线评测。

Dawn Lawrie, Sean MacAvaney, James Mayfield, Luca Soldaini, Eugene Yang, Andrew Yates

Hunt Globally: Wide Search AI Agents for Drug Asset Scouting in Investing, Business Development, and Competitive Intelligence

针对药物资产侦察这种典型 wide search 场景（异构、多语种、含付费墙的来源，结果完整性与召回率比 precision 更关键），论文提出一个 benchmark 方法学并 fine-tune 出一个 deep research agent，以 high-recall 为目标在低幻觉前提下覆盖跨语种公开/私域来源。当前 deep research 类 AI 系统在该任务上的 recall 仍显著落后人类专家，论文给出了量化差距与可复现实验。

INSIGHT把 wide search 与一般 Q&A-style deep research 分开看是关键贡献：UGC 社区里类似的 wide search 场景（找'同款讨论'、'相似维权帖'、'某事件全部相关帖'）也强调召回完整性而非精排得分。可借鉴的思路是把搜索 agent 的奖励从 answer correctness 转向 entity-level recall + 去重，并显式建模多语种、长尾来源；这条 reward 设计可直接用于社区站内 search agent 的训练目标重写。

Vlad Vinogradov, Alisa Vinogradova, Luba Greenwood, Ilya Yasny, Dmitry Kobyzev, Shoman Kasbekar 等 10 人

DisastRAG: A Multi-Source Disaster Information Integration and Access System Based on Retrieval-Augmented Large Language Models

TTexas A&M

灾害管理需要同时访问结构化运行记录、非结构化文档与动态外部源，现有单通路 RAG 框架难以同时支持时效性与异构来源。DisastRAG 采用多路径架构：基于精选灾害语料的文档检索、基于关系型数据库的结构化检索，以及外部 web fallback；并加入 query understanding 与策略路由模块，根据 query 类型自动选择最合适的检索通道。

INSIGHT其多路径 + 策略路由的工程范式对社区搜索同样适用：UGC 平台往往既有非结构化帖子，又有结构化数据（用户、商品、话题标签），还需要兜底外部 web 搜索（如热点新闻）。可借鉴的设计是把 query understanding 提前到入口层，按 query 实体/意图路由到不同 retriever，再在 reranker 阶段做跨通道融合；同时显式给 web fallback 设置可控触发条件，避免误调外部 API 拉高 P99 延迟。这种'多路 + 显式 router'比硬塞进单一 dense retriever 更可控、更易于线上调试。

Bo Li, Zhitong Chen, Kai Yin, Junwei Ma, Yiming Xiao, Ali Mostafavi
