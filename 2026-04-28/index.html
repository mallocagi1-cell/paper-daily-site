Aligning Dense Retrievers with LLM Utility via Distillation

论文提出 Utility-Aligned Embeddings (UAE)，把稠密检索的目标从语义相似度转换为分布匹配——让 bi-encoder 通过 Utility-Modulated InfoNCE 直接拟合 LLM 视角下的 “效用分布”（基于困惑度下降衡量哪些 passage 真正帮助生成）。在 QASPER benchmark 上 Recall@1 较 BGE-Base 提升 30.59%，MAP +30.16%，Token-F1 +17.3%，同时推理速度比 LLM 重排序快 180×。整体把 LLM rerank 的能力蒸馏回了一阶召回。

ResRank: Unifying Retrieval and Listwise Reranking via End-to-End Joint Training with Residual Passage Compression

ResRank 将 LLM 监听式重排序从“逐 token 自回归生成”改造成“一次余弦匹配”：用 Encoder-LLM 把每个候选文档压成单向量，再通过残差连接把 encoder embedding 与 reranker hidden state 融合，最终用一步余弦相似度替代解码。两阶段、多任务端到端训练。在 TREC DL 和 8 个 BEIR benchmark 上获得与原始 listwise LLM 重排序相当或更好的效果，但每个 passage 仅消耗 1 token、零生成 token，效率/效果折衷大幅改善。

INSIGHT对线上生产来说，listwise LLM rerank 的最大瓶颈是自回归延迟与“lost in the middle”，ResRank 用残差结构把 encoder 的语义压缩与 LLM 的判别能力同时端到端训练，把重排序变成单次相似度计算。在社区短文本场景中，可以借鉴“压缩成 1 token + 残差连接”的思路：召回与精排共用同一 backbone，避免传统两塔/cross-encoder 链路的训练目标错位，同时获得近似 listwise LLM 的精度。

Context-Fidelity Boosting: Enhancing Faithful Generation through Watermark-Inspired Decoding

ACL 2026 论文 CFB 借鉴文本水印思路，提出三层渐进式 logits 偏置策略增强 RAG/QA 的上下文忠实度：1) Static boosting 对 context 中出现的 token 加固定偏置；2) Context-aware boosting 基于 “有/无 context 的分布散度” 调整偏置幅度；3) Token-aware boosting 利用 attention 与语义相似度对 token 级偏置自适应再分配。无需任何模型重训或结构改动，即插即用，在摘要与问答任务上一致提升 faithfulness 指标。

INSIGHT对 UGC 社区生成式答案/摘要场景，hallucination 是上线最大风险。CFB 给出了不需要重训 LLM 的“纯解码侧解法”：通过对召回上下文中真实 token 的 logit 加权重，让模型生成时偏向 RAG 命中的事实片段。三层 boosting 形成层次化引导信号，且全部基于现有 attention/分布信号，工程接入只需要 logits 钩子，可作为现有 RAG 答案生成模块的零成本补丁。

04 3.85

Bridging the Long-Tail Gap: Robust Retrieval-Augmented Relation Completion via Multi-Stage Paraphrase Infusion

RC-RAG 针对 RAG 在“长尾关系/低频实体”上召回与生成同时崩塌的问题，提出在三个阶段系统化注入关系释义（paraphrase）：检索时用 paraphrase 扩展词汇覆盖，摘要时生成 relation-aware 总结，生成时用 paraphrase 引导推理。在 5 个 LLM × 2 个 benchmark 上一致优于 RAG baseline；长尾设置下相对独立 LLM 的 Exact Match 最高提升 40.6 个点，相对最强基线也高出 13.8–16.0 EM。

INSIGHT社区/UGC 搜索的核心痛点之一是“长尾实体的召回与改写”：用户口语化、缩写、网络黑话频繁。RC-RAG 验证了一个非常实用的范式：不动模型权重，只在 retrieval/summarize/generate 三处插入 paraphrase 信号，就能补齐长尾覆盖。计算开销低、可与现有 query rewriting 模块叠加，对 head/tail query 同时友好，是工程性价比极高的“长尾兜底”方案。

Fahmida Alam, Mihai Surdeanu, Ellen Riloff

Large Language Models Decide Early and Explain Later

论文提出 “forced answer completion” 实验范式，强制让模型在 chain-of-thought 各步暂停并直接回答，探测最终答案到底何时被锁定。结果：仅有 32% 的 query 中模型答案在生成过程中真正发生变化，平均会在答案稳定后再产生约 760 个无效推理 token。基于探针的早停启发式可以在精度仅下降约 2% 的前提下平均节省 ~500 推理 token/查询。

INSIGHT对在线 LLM 服务（包括生成式搜索答案、生成式排序解释）来说，这个发现的工程意义远比理论意义大：CoT 输出中的大半 token 是“事后解释”，对最终结果几乎无贡献。可以用一个轻量探针在解码过程中实时检测“答案稳定性”，触发 early stop，把首响延迟和单 query 成本降一半左右。在召回-生成混合管线中相当于给推理侧的 KV cache/算力松绑，是生成式推荐/搜索落地非常直接的成本优化点。

Ayan Datta, Zhixue Zhao, Bhuvanesh Verma, Radhika Mamidi, Mounika Marreddy, Alexander Mehler

How Large Language Models Balance Internal Knowledge with User and Document Assertions

ACL 2026 Findings。首次系统研究三源知识冲突：参数化知识 vs 用户输入断言 vs 检索文档断言，构建评测套件覆盖 27 个模型 × 3 个家族 × 2 个数据集。核心发现：模型对“文档断言”的依赖显著强于“用户断言”，且这一偏好被指令微调进一步强化；多数模型难以辨别外部信息的有用与有害；在含三源交互样本上做微调可显著提升模型对来源的甄别能力。

INSIGHTRAG 落地中常见的 trust 问题：当用户在 query 中夹带矛盾信息（“我已经买了 X，再推 Y”）、检索结果又提供第三方说法时，LLM 该信谁？本文给出实证：当前主流模型几乎默认以“文档为先”，post-training 还会进一步加深这种偏置。对生成式搜索、对话推荐、客服 RAG 等场景的启示——必须显式用三源数据做对齐微调，否则会出现“被低质检索结果带偏”或“忽视用户最新偏好”这两类系统性错误。

Shuowei Li, Haoxin Li, Wenda Chu, Yi Fang

07 3.55

STEM: Structure-Tracing Evidence Mining for Knowledge Graphs-Driven Retrieval-Augmented Generation

ACL 2026 Main。STEM 把多跳推理重构成 schema-guided graph search：1) Semantic-to-Structural Projection 把 query 拆成关系断言并构造自适应查询子图；2) Triple-Dependent GNN 为每个三元组生成全局指导子图增强结构感知；3) Globally-Aware Retrieval 做节点锚定与子图抽取得到证据推理图。在多个多跳问答 benchmark 上达到 SoTA，显著提升答案准确率与“证据完整度”。

INSIGHT对带有结构化知识的搜索/推荐（商品图、问答图、社交图）很有借鉴价值：传统 dense 检索召回的是“语义最近”的片段，但多跳问题真正需要的是“路径完整”的证据。STEM 把检索目标从“相关 chunk”转向“覆盖完整推理路径的子图”，这意味着在工程上需要把 KG 索引、GNN 探索、向量检索三层并联，而不是堆叠 RAG。对社区 QA、商品问答这类需要因果/关系推理的场景是清晰的方向。

Peng Yu, En Xu, Bin Chen, Haibiao Chen, Yinfei Xu

Contexts are Never Long Enough: Structured Reasoning for Scalable Question Answering over Long Document Sets

Stanford

SLIDERS 解决的是 “文档集大到任何 LLM context 都装不下” 的 QA 场景：把信息从原文中抽到关系型数据库，再通过 SQL + 数据调和（基于 provenance / 抽取理由 / 元数据修复重复或不一致记录）来回答问题。在三个长文本基准上全面超越基线，平均比 GPT-4.1 高 6.6 个点；在两个新构造的 3.9M 与 36M token 基准上分别超过次优 ~19/~32 个点。

INSIGHT把 RAG 从“向量检索 + 拼接 context”推向“先结构化再 SQL”，避开了 long context 的硬上限。对社区/UGC 搜索的间接启示：当用户问 “过去一周关于 X 的所有评测”、“某品牌共有多少差评” 这类“跨文档聚合” 问题时，向量检索几乎无法解决，但 SLIDERS 的“抽取→数据库→SQL”范式更契合。可以与现有 RAG 互补，作为“聚合型” query 的专用通道。

Harshit Joshi, Priyank Shethia, Jadelynn Dao, Monica S. Lam

Adapting MLLMs for Nuanced Video Retrieval

Oxford

把生成式 MLLM 改造成视频检索 embedding 模型：以预训练多模态生成模型为底座，用对比学习（hard negative 精心采样）只在文本侧 fine-tune，无需视频-文本配对数据。结果在 nuanced video retrieval 三大维度（时间区分如 “开门 vs 关门”、否定词处理、文本+视频组合检索）上一致刷新 SoTA，并发现“纯文本对比训练”会拉近文本/视频 embedding 空间。

INSIGHT短视频/UGC 社区是当下搜索增长最大的场景，视频检索却长期被“粗粒度全局相似”所限。本文揭示一个反直觉但极具落地价值的事实：你不必有大量视频-文本对，只用文本对比就能把生成式 MLLM 转成精细化视频 embedding。对工程团队意味着可用现成 MLLM（Qwen-VL / LLaVA 等）+ 文本对比 finetune 快速搭建 nuanced 视频召回，且天然支持 query 中带否定/时序约束的复杂检索。

Piyush Bagad, Andrew Zisserman

10 3.25

Outcome Rewards Do Not Guarantee Verifiable or Causally Important Reasoning

Stanford

本文系统检验了 RLVR（reinforcement learning from verifiable rewards）训练的推理模型：提出 Causal Importance of Reasoning (CIR) 与 Sufficiency of Reasoning (SR) 两个指标，衡量模型回答时是否真的依赖了所生成的 reasoning。结论：RLVR 提升了任务准确率，却未一致提升 CIR/SR——很多情况下 CoT 仅是装饰；适量的 SFT 预热 + 显式 CIR/SR 辅助奖励能让模型在准确率不掉的同时真正“依赖推理”。

INSIGHT对生成式搜索/推荐里的 reasoning 模块（如 query 解析、推荐解释、复杂工具调用）有警示意义：单看 outcome 准确率有可能训出“嘴上推理、心里抄答案”的模型，落地后 reasoning trace 既无法用于解释也无法做安全审计。要么在训练时混合 process reward / 因果约束，要么在评测时强制做 forced-answer 实验，避免被任务指标欺骗。

Qinan Yu, Alexa Tartaglini, Peter Hase, Carlos Guestrin, Christopher Potts
