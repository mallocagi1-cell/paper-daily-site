HybridGen: Efficient LLM Generative Inference via CPU-GPU Hybrid Computing

面向长上下文场景下 KV cache 膨胀至数百 GB 的瓶颈，HybridGen 在 FlexGen 之上修改 PyTorch 的 CPU 分配器，实现语义感知的分层内存映射，把注意力计算协同分摊到 CPU 与 GPU。核心方法包括 attention logit 并行、用于平衡 CPU-GPU 负载的自适应调度器，以及面向 CXL 等分层内存的智能缓存映射，解决多维注意力依赖、序列变长导致的工作负载倾斜与分层内存访问惩罚。在多个模型与 GPU 平台上对比 6 类 KV cache 管理基线，平均吞吐提升 1.41x–3.2x，且不损失生成质量。

Scepsy: Serving Agentic Workflows Using Aggregate LLM Pipelines

Imperial College London

Scepsy 关注多模型 agentic 工作流的 GPU 集群调度，核心观察是单条请求的端到端时延虽不可预测，但每个 LLM 在端到端中所占的执行时间比例是稳定的。基于该不变量，论文提出 Aggregate LLM Pipeline——一个轻量级 profiler，在不同并行度下刻画各个 LLM 的延迟特征，并据此联合做 GPU 资源分配与层次化放置。相比独立优化各 LLM 或采用人工指定分配的系统，Scepsy 端到端吞吐提升最高 2.4x，时延降低最高 27x，提供面向 agentic search/RAG 的服务系统蓝图。

INSIGHT对要把 LLM agent 工作流上线到搜索/推荐场景的团队，本文最关键的启发是把工作流作为一阶调度单元而非单个 LLM 调用：通过 share-of-time 的稳定性，可以把多 LLM 路由问题降维成可预测的 pipeline 调度。可直接迁移的设计是离线 profile + 在线层次化放置：先在不同并行度下刻画每个 LLM 的延时-吞吐曲线，再用启发式将整个工作流映射到 GPU 集群，省去针对每个 agent 重新调参的运维成本，对长尾 agent 调用场景尤为关键。

Beyond N-gram: Data-Aware X-GRAM Extraction for Efficient Embedding Parameter Scaling

X-GRAM 针对 token 索引型 embedding 表的三大问题：低频 token 训练不充分、不同层对 embedding 的需求不一致、以及参数冗余，提出基于数据感知的 X-gram 抽取与压缩方案，把模型容量与计算量解耦。其核心思路是按数据分布选择要扩展的 token 组合，并对各层重新分配 embedding 容量，再通过精细化向量抽取减少冗余。实验在 0.73B 与 1.15B 参数规模上相对 baseline 准确率最多提升 4.4 个百分点，同时显著降低 embedding 内存占用。

INSIGHT对中文社区短文本搜索这类深度依赖词表与 embedding 的任务，论文提供了把 lookup table 当成可调资源的视角：低频/长尾 token 不应平均分配容量，而是根据数据分布与层敏感度做差异化扩展。可借鉴的工程做法是把 embedding 表拆成层级（共享层 + 任务/层定制层），结合 X-gram 选择策略可在不增加模型计算量的前提下提升对长尾 query 的覆盖；这一思路对 query 重写、稀疏检索的 token 表设计直接可参考。

Unlocking the Edge Deployment and On-Device Acceleration of Multi-LoRA enabled Foundational LLM

SSamsung

论文给出在 Samsung Galaxy S24/S25 上部署一个 LLaMA 多语言基础模型的完整工程方案。亮点是把多个 LoRA 作为运行时输入实现动态任务切换，提出多流解码（multi-stream decoding）在一次前向同时生成多种风格变体，并引入 Dynamic Self-Speculative Decoding 加速 token 生成；与 INT4 量化和架构级优化叠加后，在内存与时延上实现 4–6x 综合提升，覆盖 9 种语言、8 类任务，论文已被 ACL 2026 接收。

INSIGHT这是少有的真正落到手机端的端侧 LLM 工程实证，对探索端云协同搜索或端上 query 改写的团队价值很高。可直接迁移的三件套是：（1）Multi-LoRA 作为 runtime adapter，按任务/语种动态加载，避免给每个场景训完整模型；（2）Multi-stream 解码在单 forward 内并发产出多变体，便于做候选生成或 query 多视角扩展；（3）自投机解码与 INT4 量化的组合，对中端手机推理是经过实测的可行方案。

Sravanth Kodavanti, Sowmya Vajrala, Srinivas Miriyala, Utsav Tiwari, Uttam Kumar et al.

The Recurrent Transformer: Greater Effective Depth and Efficient Decoding

Harvard

Recurrent Transformer 修改标准 Transformer，让每层的注意力对自己输出的 KV 进行回看，从而在保持自回归解码成本的同时引入层内的循环记忆。设计上它能模拟标准 Transformer 与 token-by-token 循环模型两种极端。论文提出一种 tiling 算法将每层注意力的内存流量从 Theta(N^2) 降至 Theta(N log N)，显著提高训练与推理的算术强度。在 C4 预训练上，150M 与 300M 规模的 Recurrent Transformer 用更少层数即可达到 baseline 同等或更好的交叉熵。

INSIGHT对训练自家小模型或定制 LLM 的搜索团队，论文提供一条用更少层但更深等效深度的路径，潜在意义在于以更低延时拿到更强的表征。可借鉴点是把 KV 重定义为同层产生而非前一层产生——这与现有 vLLM/SGLang 的 paged KV 机制完全兼容，工程改造主要落在 attention kernel；其 N log N tiling 算法对长上下文 attention kernel 设计也有直接参考价值。当前实验仅到 300M 规模，扩展到 7B+ 仍待验证。

Costin-Andrei Oncescu, Depen Morwani, Samy Jelassi, Alexandru Meterez, Mujin Kwun, Sham Kakade

RouterWise: Joint Resource Allocation and Routing for Latency-Aware Multi-Model LLM Serving

University of Melbourne

RouterWise 关注多模型 LLM 服务中常见的假设固定时延误区——共享 GPU 资源的不同模型时延会因资源分配与负载变化。论文把资源分配与路由放在同一个优化问题里，用 dual-price 路由形式化结合 system profiling 得到的时延模型，搜索可行配置并算出每种配置下满足 SLA 的最优路由策略。一个关键实证发现是：在同一 GPU 集群上，不同资源配置带来的输出质量分数差异最高可达 87%，证明仅靠路由策略而不联合调资源会损失大量收益。

INSIGHT对维护多模型/多版本同栈部署（小/中/大模型 + 多 LoRA）的搜索团队，本文最值得记住的事实是：固定显存配额下的路由策略上限远低于联合调度。可立刻借鉴的实践包括：（1）线下 profile 各模型在不同并行度与共享强度下的 P95；（2）把分多少 GPU 给哪个模型视作主决策变量，路由仅作辅助；（3）用 dual-price 之类的对偶方法在线滚动求解，以应对流量与混部。这一点对成本敏感的中型搜索栈尤其关键。

Hossein Hosseini Kasnavieh, Christopher Leckie, Adel N. Toosi

DiP-SD: Distributed Pipelined Speculative Decoding for Efficient LLM Inference at the Edge

Tsinghua

DiP-SD 把 draft-then-verify 的 speculative decoding 拆到边缘多用户场景：每个设备本地草稿、中心服务器批量验证。核心创新是设备级草稿与草稿-验证流水线的双重并行，并把批量配置、用户分配与草稿长度联合建模为一个吞吐最大化（每秒被接受 token 数）的优化问题。在 Qwen3 模型上相比纯 autoregressive decoding 取得最高 17.89x 吞吐增益，并显著优于直接迁移投机解码到多用户的基线，论文已接收于 IEEE VTC 2026 春。

INSIGHTspeculative decoding 已是大模型服务的标配，但 DiP-SD 提醒：在多设备/多用户共享一个验证节点的情景下，必须把草稿在哪里、批量怎么编、每用户多少 draft token 放在同一个调度器里联合决策，否则收益会被 draft 长度过短或验证空转吞掉。其优化问题形式化与流水线加 draft 长度自适应的双层并行，对端云协同搜索 agent（设备出 query 改写草稿、云端 LLM 验证）有直接借鉴意义。

Yaodan Xu, Sheng Zhou, Zhisheng Niu

SparKV: Overhead-Aware KV Cache Loading for Efficient On-Device LLM Inference

SparKV 是一个面向端侧 LLM 推理的开销感知 KV 加载框架，把云端 KV 流式下发与端侧重新计算的成本建模在一起，对每个 KV chunk 单独决策流式加载还是本地重算。运行时调度还会根据网络与资源波动动态调整。在多种设备与模型上，SparKV 把首 token 时延降低 1.3x–5.1x，能耗降低 1.5x–3.3x，给低带宽/异构端侧场景的长上下文推理提供了具体实现。

INSIGHT对要让搜索 query 上下文/历史记忆下沉到端侧的团队，KV cache 不能再被视为单一存储介质，而应当作按 chunk 计费的资源。SparKV 的核心思想——以 chunk 为粒度做 stream 还是 recompute 的代价权衡——同样适用于云端分层缓存（GPU vs CPU vs 远端 KV 存储）：把 KV 切片，按命中概率与传输代价做小颗粒决策，可显著降低 P95 TTFT。其调度逻辑也可抽象为一类通用的边缘-中心 KV 协同框架。

Hongyao Liu, Liuqun Zhai, Junyi Wang, Zhengru Fang

Initialisation Determines the Basin: Efficient Codebook Optimisation for Extreme LLM Quantization

UUniversity of Sheffield

论文研究 LLM 极端量化（2 比特 additive quantization）下质量陡降的根因：codebook 初始化是主要瓶颈，常用的贪心顺序初始化会把模型推入劣势的优化盆地。作者提出 OA-EM——用 Hessian 加权的 EM 初始化方法，在 Llama 与 Qwen 系列上经过 PV-tuning 后稳定取得更优 codebook。论文还形式化了表征比 ρ = N/(KM)，量化展示初始化失败在更低比特位下会带来数量级级别的质量损失。

INSIGHT对计划上线 INT2 量化以最大化 KV 容量与吞吐的团队，论文提供一个非常实用的诊断工具——表征比 ρ 与 Hessian 初始化。可直接迁移的做法是：在做 W2A 系列量化前先按 ρ 检查模型/层的可压缩性，对 ρ 低的层保留更高比特或转用更好的 codebook 初始化。对 RAG 场景的小模型量化尤其重要，因为这些模型常被压到 2 比特以塞下更多上下文，但容易出现质量崖。

Ian W. Kennedy, Nafise Sadat Moosavi

Temporally Extended Mixture-of-Experts Models

PPrinceton

论文借鉴强化学习中的 options 框架，引入时序扩展的 MoE 层：用一个 controller 学习何时切换专家集合以及加载哪些专家，从而显式优化专家切换频率。在 gpt-oss-20b 上叠加 LoRA 微调，专家切换率从 50%+ 降到 5% 以下，同时在 MATH、MMLU、MMMLU 上保留最高 90% 的精度。该方法把现有预训练 MoE 通过轻量训练改造成时序扩展版，让从业者可在切换效率与精度间做显式 trade-off。

INSIGHT对计划用 MoE 模型（如 DeepSeek-V3、Qwen3-MoE）跑搜索/推荐线上服务的团队，专家加载的切换成本是最被低估的部署瓶颈。本文给出一个不重新预训练就能压低切换率的方案：用 RL options 控制器学习什么时候保持专家集合不变，将切换从 token 级提升到 segment 级。这一思路和现有 expert paging（如 FluxMoE）正交，理论上可叠加获得更稳定的 KV/expert 共占内存模型，对 MoE serving 集群的延迟/吞吐都有积极意义。

Zeyu Shen, Peter Henderson
