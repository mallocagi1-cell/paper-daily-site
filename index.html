Personalization · 个性化推荐 — 10 篇入选

头条：UniPinRec: Unifying Generative Retrieval and Ranking at Pinterest Scale — Pinterest 的召回模型和排序模型分开训练、分开部署，同一段用户历史在线上要编码两遍。UniPinRec 把两者合进一个 Transformer：先编码用户历史，得到的用户向量拿去做 ANN 召回；召回的候选 Pin 再接在历史后面，由同一个模型输出保存、点击、隐藏等动作的概率，候选之间不互相做注意力。历史只编码一次，算好的 KV cache 直接留给排序阶段复用。离线 Hit@3 比线上排序模型高 14.7%；在通知场景替换原召回后，沉睡用户的 push 打开提升 1.72%。

Generative · 生成式推荐 — 6 篇入选

头条：CSG4Rec: Collaborative-Similarity Guided Semantic IDs Tokenization for Generative Sequential Recommendation — 生成式序列推荐用的语义 ID，一般由商品文本向量逐层量化得到，文本相近的商品拿到相近的编码；但“常被同一批用户购买”这类协同信息进不了编码。CSG4Rec 训练分词器时加了一项对比损失：协同行为相似的两件商品，量化后的向量被拉近，不相似的被推远，目的是让编码相近的商品在文本和用户行为上都相近。它还把每个用户历史交互商品的向量聚合起来，同样量化成一串用户语义 ID，和商品语义 ID 一起输入生成模型。作者报告在三个基准数据集上都超过现有基线。

Retrieval · 检索与RAG — 10 篇入选

头条：The Fusion Tax: A Diagnostic Analysis of When Hybrid Retrieval Hurts — 混合检索把 BM25 和向量检索两路结果融合成一个排序，主流检索引擎和 RAG 框架的文档大多默认用倒数排名融合（RRF）。作者在 7 个 BEIR 数据集上逐条查询记账：表现最好的融合方式是向量分数占 0.7 权重的分数插值，它在每个数据集的平均 nDCG@10 上都赢过只用向量检索，却仍让 8–21% 的查询排得比只用向量检索更差。这些损失集中在只有一路命中相关文档的查询上，另一路此时只贡献噪声，融合会把已经排上来的相关文档往下压。把向量编码器从 22M 换到 596M 参数，这部分损失也没有消失。RRF 只在两路水平相当的数据集上才赢过纯向量检索，所以融合方式应该按目标语料上两路的实测差距来选。

Agentic · 智能体搜索 — 6 篇入选

头条：ForkPilot: Self-Evolving Policy for Retrospective Search in Long-Horizon Agents — 长程智能体任务里，前面一次工具调用出错，后面的步骤会跟着错下去。回溯搜索的补救办法是回到失败轨迹里一个可以恢复的早期状态，保留之前正确的动作，从那里分叉重跑。难点在于什么时候分叉、分叉几次：奖励要到任务结束才知道，每次分叉又要多花 token。ForkPilot 用已经跑完的轨迹造标签：在同一个状态上，分叉和不分叉各跑到结束，用两者的最终得分差减去 token 成本差，作为这次分叉值不值的标签，再训练一个预测器给候选分叉方案打分。部署时只有预测收益的下界大于零才分叉，每完成一个任务就把新轨迹加进训练集重新拟合。它学的是这一步值不值得多花算力，智能体本身的动作策略不动。在 6 个基准、4 个开源模型上，和完整回溯树搜索 RTS 相比，原始 token 平均少 36.2%，任务分平均高 0.23 分。

  2. 大模型服务平台 TokenHub 联网搜索
  3. TeleTune: Evolving Agent Skills From Offline Telemetry
  4. Subagents vs Agent Skills: Executing Reusable Knowledge for Long-Horizon Agentic Tasks
  5. Agentic RAG 是什么：智能体如何增强检索生成
  6. Code Understanding is a Bottleneck for Coding Agents

Infra · 系统与索引 — 8 篇入选

头条：llm-d 1.0, an open source stack for distributed inference — 智能体流量多步、共享长前缀、突发到达。放在普通轮询负载均衡后面，各副本会重复计算相同的提示，显存里堆满重复的 KV cache。Google 联合 Red Hat、IBM 等在 PyTorch Conference 发布的 llm-d 1.0，是一个跑在 Kubernetes 上的开源分布式推理栈，把一组 vLLM、SGLang 模型服务器组织成一个统一的服务池：路由器记录每个缓存前缀存在哪些副本上，结合负载和预测延迟选副本；显存满时把 KV cache 依次挪到主机内存和 SSD；预填充和解码拆成两个池。1.0 新增按优先级和公平性排队的流控，以及不中断会话的滚动升级。在 Ironwood TPU 上的编码智能体负载里，前缀感知路由加主机内存卸载让首 token 延迟中位数下降 85% 以上，总吞吐是普通 Kubernetes Service 的 2.4 倍。收益主要来自把同一会话的请求送回已经存着它上下文的副本，省掉重复的预填充。
