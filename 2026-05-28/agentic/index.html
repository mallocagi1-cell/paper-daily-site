The MiniMax-M2 Series: Mini Activations Unleashing Max Real-World Intelligence

MiniMax 发布面向 agentic 部署的 MoE 模型 M2 系列：总参 229.9B、单 token 激活仅 9.8B。三大组件支撑：(i) agent-driven 数据流水线在可执行 workspace 中生成 agentic coding/cowork 的可验证轨迹，奖励对齐产出物；(ii) Forge——为长视野 agent 轨迹设计的 agent-native RL 系统，含 windowed-FIFO 调度、prefix-tree merging 与推理优化；(iii) 端到端面向真实 agent 任务的训练目标。模型卡定位为「小激活换最大现实智能」，并对外开源。

RICE-PO: Turning Retrieval Interactions into Credit Signals for Reasoning Agents

UMass Amherst

针对 retrieval agent 训练里 outcome reward 无法区分有效推理步与无效推理步的 credit-assignment 难题，作者提出 RICE-PO（Retrieval-Interaction Credit Estimation Policy Optimization）。核心思路：把可执行动作（query 重写、summary）的 retriever 反馈作为局部、可观测的密集 credit 信号，回传到中间 latent reasoning step，再以 critic-free 的方式做策略优化。这样避免了 outcome-level reward 把同样的最终结果错误归因到不实际影响检索的 reasoning step 上。

INSIGHTRICE-PO 把「retriever 返回什么」当作天然奖励源，特别适合搜索 agent 训练——召回器/排序器本身就是可微/可计分的环境，无需额外训练 critic。对实践的直接借鉴：搜索 agent 在做 query 改写、HyDE、reflection 时，可以用召回质量（nDCG、覆盖率、相关性 score）作为中间步骤的稠密 reward，避免只看最终 answer 准确率带来的稀疏信号问题。这对社区搜索里「先理解 query 再多轮召回」的复杂查询流是低成本的训练范式。

Mingchen Li, Hansi Zeng, Zhuo Qian, Jiatan Huang, Hamed Zamani, Hong Yu

Efficient Agentic Reinforcement Learning with On-Policy Intrinsic Knowledge Boundary Enhancement

作者发现 agentic RL 训练会导致工具调用越练越冗余，模型的内在知识边界被模糊化，分不清何时该用工具、何时直接用参数化知识。现有 reward shaping 方案做的是粗粒度抑制（少调用工具就给正奖励），容易奖励黑客化、变成无差别地不调用工具。论文提出 AKBE（Agentic Knowledge Boundary Enhancement）：on-policy 地动态探测模型自身的知识边界，把「该不该调用工具」判定细化到样本级，作为更精细的优化目标。

INSIGHT做 agentic 搜索的工程团队最容易踩的坑就是论文指出的过度调用工具——一次召回就够的 query，模型反复发起 hybrid search、知识库查询、web search，既增加延迟又抬高成本。AKBE 的思路（先探测模型自身的能力边界，再决定是否触发工具）可以迁移成线上的轻量门控：在 query 进入 agent 链之前，先用一个小模型判定是否需要外部检索。对社区搜索场景，能显著减少高频简单 query 的不必要召回开销。

Dingwei Chen, Zefang Zong, Zhipeng Ma, Leo Luo, Yang Li

Rethinking Agentic RAG: Toward LLM-Driven Logical Retrieval Beyond Embeddings

Fudan University

当前 agentic RAG 一边把检索后端越做越重（dense/hybrid/graph 混合架构），一边又依赖 LLM 多轮迭代改写 query。作者主张反过来：让 LLM 直接生成结构化、逻辑表达式形式的检索请求，后端只需轻量、可解释的「逻辑检索」接口；retrieval 的复杂度从向量空间转移到 LLM 自己的 query 构造能力。论文给出了这种 LLM-driven logical retrieval 的形式化定义和实证比较，论证在多个 RAG benchmark 上结构化逻辑检索可与重型 embedding 后端持平甚至更优。

INSIGHT这是对「砸更多模型/索引复杂度」路线的一次反思。对社区搜索的实际意义：与其堆叠多路 dense/sparse/rerank/graph 后端，不如把 LLM 的 logical query 生成能力当作一等公民——LLM 输出可执行的过滤条件（如「过去 30 天 + 评论数>5 + 主题 X」），检索后端只需服务这些结构化请求。这种模式对短文本召回特别契合：UGC 短文本天然向量噪声大，结构化 + 关键词匹配反而更稳。

Yuqi Zeng, Qixiang Deng, Yulei Wan, Ruiquan Jiang, Xiaoqing Zheng, Xuanjing Huang

Learning to Act under Noise: Enhancing Agent Robustness via Noisy Environments

论文指出 agent benchmark 表现好的 LLM 一上线就性能掉点，根因是训练环境过于理想化——任务指令工整、环境稳定，与现实交互动态完全脱节。作者提出 NoisyAgent，agentic 训练框架在训练阶段就主动注入指令噪声（typo、不完整指令）、环境噪声（工具返回延迟/失败、观测乱序）和奖励噪声。在多个 agent benchmark 上，NoisyAgent 训出的策略在原始 clean setting 几乎不掉点的情况下，对真实噪声环境的鲁棒性显著提升。

INSIGHT搜索 agent 上线最大的痛点就是这个：离线评测 nDCG 高，线上点击率/相关性反而拉胯。NoisyAgent 给出的处方很直接——训练数据里要刻意混入噪声 query（错别字、半句、多意图）、噪声环境（召回返回为空、ANN 超时、rerank 接口偶发失败）、噪声反馈（点击有 bias）。社区搜索的训练管线如果只在 clean 标注数据上做 RLHF/RLAIF，遇到 UGC 真实流量必然脆。把噪声注入作为 agent 训练的标配，比单纯堆模型规模更有 ROI。

Yuxin Chen, Xiaodong Cai, Junfeng Fang, Zhuowen Han, Yu Wang

Beyond Final Answers: Auditing Trajectory-Level Hallucinations in Multi-Agent Industrial Workflows

现有幻觉评测只看 agent 的最终输出，错过了大量发生在 Thought-Action-Observation 中间步的失败。作者发布 Trajel 数据集和评测框架，针对工业多 agent 工作流（基于 AssetOpsBench 的专家标注轨迹）定义五类轨迹级幻觉：事实型、指代型、逻辑型、过程型、范围型。论文在 subtask、trajectory、long-context 三个粒度上 benchmark 监督检测模型，发现单纯依赖最终答案正确率会严重低估系统的可靠性风险。

INSIGHT对搜索 agent 上线监控有直接借鉴：只看最终是否命中目标文档是不够的，必须看中间 trajectory——agent 在第几步幻造了一个不存在的 facet、把 user query 误解为另一个意图、调用了错误的工具组合。Trajel 的五类幻觉 taxonomy 可以直接拿来做线上 trace 标注体系，配合采样回放就能持续发现系统薄弱环节。社区搜索往往涉及多轮澄清、多种召回工具的协同，这种 trajectory-level 监控比端到端 CTR 更早发现问题。

Harshada Badave, Santosh Borse, Andrea Gomez, Harshitha Narahari, Sara Carter

SPEAR: Code-Augmented Agentic Prompt Optimization

现有 Automatic Prompt Engineering（APE）把优化器本身视作固定流程，作者把 CodeAct（code-as-action）的范式移植到 APE，提出 SPEAR：一个自由形式的 agentic 优化器，配四个工具——evaluate、python、set_prompt、finish，让优化器自主决策何时、如何调用。最关键的工具是 Python 沙箱：优化器可以写并执行任意 Python 代码，在当前评测 DataFrame 上做结构化错误分析（混淆矩阵、错误聚类、子集统计），然后据此调整 prompt。带 rollback 机制避免劣化迭代。

INSIGHT对搜索 agent 团队来说，「prompt 调优 + 数据分析」通常分两条腿走：算法同学手动看 bad case，工程同学跑统计。SPEAR 的 code-as-action 模式把这两件事合二为一——让一个 agent 既能跑 SQL/Python 切片分析失败 query 的共性（query 长度、领域、意图分布），又能据此自动改写 system prompt 或 few-shot。这种「会写代码的 prompt 优化器」很适合搜索相关性 prompt 的迭代，因为相关性问题往往按 query type 切片才能定位。

Mengyin Lu, Cong Feng, Huimin Han, Guangming Lu, Yu Sun, Xiaonan Ding, Shihui Long, Fengyi Li 等 9 人

Building self-improving tax agents with Codex

OpenAITThriveCCrete

OpenAI 与 Thrive、Crete 联合公布了基于 Codex 构建自我改进型 tax agent 的工程实践，覆盖税务报表自动化、准确率提升与工作流加速。博客侧重披露生产部署经验：把 Codex 作为代码生成 + 自我修正引擎，在结构化税务工作流里逐步替换人工步骤；agent 通过对比预期产物与实际执行结果，自动迭代修复自身代码与规则；上线后报表准确率与处理吞吐均有量级提升（具体数字以原博为准）。

INSIGHT这是一份典型的垂直领域 self-improving agent 工业案例。对搜索/推荐工程的可借鉴点：(1) agent 真正落地的关键不是模型规模，而是任务可分解到可执行/可验证的子步（税务流程被显式拆成数据获取、规则校验、表单生成、复核）；(2) 自我改进必须有一个 ground truth oracle——税务里就是政策文件 + 历史申报，搜索里对应的就是相关性标注 + 点击日志；(3) Codex 这种代码 agent 的边界正在从写代码扩展到用代码做业务自动化，搜索运营、报表分析、bad case 修复这些工程岗位的工作流值得用类似 agent 框架重构。

Memory Architectures for Multi-Turn Text-to-SQL: A Benchmark and Empirical Study

多轮 Text-to-SQL 是企业分析核心场景，但现有评测几乎都是单轮。作者发布 EnterpriseMem-Bench：300 sessions、1400 turns，覆盖 BIRD financial、SEC EDGAR、Northwind 三个企业域，所有 ground truth 由确定性程序生成，并对每一 turn 标注 memory-critical 属性。在 GPT-5 mini / GPT-5.2 / Claude Sonnet 4.5 / 4.6 / Opus 4.6 五个前沿模型 × 五种 memory 条件下做三向消融，独立隔离 working-memory 窗口大小、episodic retrieval、semantic augmentation 的贡献。

INSIGHT对搜索 agent 设计 memory 子系统有直接参考价值——论文的三向消融告诉我们：working memory（短期上下文）、episodic memory（轮次级历史）、semantic memory（跨 session 的 user 偏好/历史 query）三者作用不可替代。社区搜索做多轮会话搜索、个性化 agent 时，常常一股脑塞进上下文窗口；这篇工作提示要把三种 memory 分层做，分别用不同存储/检索机制（KV cache、向量库、画像服务）。benchmark 本身也可以拿来对照测试自家 agent 在 memory-critical turn 上的失败模式。

Ravi Kumar Tummalapenta, Suman Addanki
