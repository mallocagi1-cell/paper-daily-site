SilverTorch: Index as Model — A New Retrieval Paradigm for Recommendation Systems

Meta 在 UGC 推荐召回中把原本散落在 CPU/向量索引/模型服务里的多套召回组件合并成一个统一架构 SilverTorch，把 "索引" 当作模型的一部分用 GPU 端到端服务。相对此前 CPU 召回方案吞吐提升 23.7×、单位算力成本提升 20.9×，同时精度还有所提高，已在 Meta 内部 UGC 场景上线。

MobileMoE: Scaling On-Device Mixture of Experts

Meta

MobileMoE 把 MoE 架构下沉到端侧 sub-billion 规模（active 0.3-0.9B / total 1.3-5.3B），并先推出一条端侧 MoE Scaling Law，联合优化内存与算力两个约束。结论是 "中等稀疏度 + fine-grained + shared expert" 是端侧 sweet spot，配合 pre-training/mid-training/SFT/QAT 四阶段训练，在 14 个 benchmark 上以 2-4× 更少 active 参数追平或超过当前 SOTA 端侧 dense LLM。

INSIGHT这篇给端侧 MoE 画了一条可落地的等高线：服务器端的 fine-grained MoE 比例放到 1B active 以下时会被内存带宽打回原形，必须重新求解 expert 粒度/sharing 比例。对搜推端侧场景（手机/IoT 上的轻量推荐/重排/Query 改写）很有参考价值——可以直接套用其 QAT 训练流程，把多目标推荐头放进 MoE 的 shared expert 复用计算预算。

Yanbei Chen, Hanxian Huang, Ernie Chang, Jacob Szwejbka, Digant Desai

Develop High-Performance GPU Kernels in C++ with NVIDIA CUDA Tile

NVIDIA

NVIDIA 正式把 CUDA Tile 编程模型带进 C++，让开发者可以在既有大型 C++ GPU 代码库里写 tile-based Kernel，不再被迫迁移到 Python/Triton 才能享受新的张量内存与异步拷贝抽象。Tile 提供 collective memory/compute 原语，让单个 thread block 像 "瓦片" 一样直接调度 TMA 与 WGMMA，把 Hopper/Blackwell 上 SOTA Kernel 的写法标准化。

INSIGHT对搜推线上系统的意义是：检索打分、HSTU/MoE 大算子如果还停留在手写 cuBLAS+CUTLASS 模板，可以考虑把热路径迁到 CUDA Tile，把 TMA 与异步拷贝调度交给编译器；可在 H100/B200 上以更少代码贴近 Flash/Cutlass 性能上限。对正在做自研推理引擎（vLLM/SGLang 之外）的团队值得马上 PoC。

04 4.10

RT-Lynx: Putting the GEMM Sparsity In a Right Way for Diffusion Models

RT-Lynx 重新审视 DiT 推理的 N:M 半结构化稀疏：作者发现 DiT 的 activation 本身远比 weight 稀疏、对 2:4/N:M 剪枝鲁棒得多，于是把稀疏目标从权重换到激活，并配合误差补偿与定制 CUDA Kernel，在线性层上平均拿到 1.55× 加速且基本不掉点，可与 W8A8 量化叠加。

INSIGHT"稀疏权重 vs 稀疏激活" 的换帧很关键——过去 NVIDIA 的 2:4 weight pruning 在 DiT/扩散视频生成上几乎都会掉质量；改成 activation N:M 后既能吃到 Sparse Tensor Core 的算力，又不破坏模型容量。搜推场景如果在跑 DiT/Video 生成或大规模生成式重排，可以直接借用其 CUDA Kernel 思路评估激活稀疏化的 ROI。

Xing Cong, Hanlin Tang, Kan Liu, Lan Tao, Lin Qu

Share More, Search Less: Collaborative Parallel Thinking for Efficient Test-Time Scaling

CPT (Collaborative Parallel Thinking) 是一种 training-free 的并行推理框架：在 best-of-N / 树搜索这类并行 TTS 中，让每条 branch 把已发现的中间结论压缩成短信息块写入共享的 query-level 信息池，并通过 prompt context 广播给其他分支，从而避免每条 branch 重复发现同样的事实，减少冗余搜索步数。

INSIGHT并行 reasoning/搜索 Agent 的瓶颈正在从 "算多少条 branch" 转移到 "branch 之间能不能通信"。CPT 给出了一个最朴素的工程实现：用 dedup query-level pool + context broadcast，不改模型权重，可以塞到现有 vLLM / SGLang 的批推理里。这对 Search Agent / Deep Research 这类 "多 branch 并行召回+综合" 应用是即插即用的性价比优化。

Xinglin Wang, Hao Lin, Shaoxiong Feng, Peiwen Yuan, Yiwei Li

Extract More Kernel Performance with NVIDIA CompileIQ Auto-Tuning

NVIDIA

CompileIQ 是 NVIDIA 把性能工程里 "找最优编译选项" 这件事工程化的工具：在给定 Kernel/工作负载下，自动在 nvcc 编译选项空间内做 auto-tuning，搜索 register/shared memory/调度等参数组合，给出针对当前 SM 架构的最佳编译配置。

INSIGHT对搜推自研 Kernel 团队最实用的一点：以往 Hopper/Blackwell 上不同算子（FMHA、HSTU attention、ANN scoring kernel）都要手动 sweep nvcc flag，工作量大且容易过拟合单算子。CompileIQ 把搜索流程标准化，意味着维护一份 Kernel 仓库就能持续吃到新 GPU 架构红利，建议把推理引擎里的关键 Kernel 接入其 auto-tuning pipeline 作为发布前流程。

NVIDIA CUDA 13.3 Enhances GPU Development with Tile Programming in C++, Compiler Autotuning, and Python Updates

NVIDIA

CUDA 13.3 的发布把 Tile 编程模型 (C++)、CompileIQ 编译器 autotuning 与 CUDA Python (cuda.core / numba-cuda) 三条线一起拉到 GA。Blackwell/Hopper 上的 TMA + WGMMA 等新硬件原语通过 Tile 统一暴露，Python 一侧也对齐了 CUDA Graphs / Driver API / NVRTC 的新接口。

INSIGHT13.3 是一次 "上层编程模型对齐底层硬件" 的里程碑版本，对搜推自研引擎团队的实际影响是：写 Kernel 的入口从 cuBLAS/CUTLASS 模板向 Tile 收敛，自动调参从 autotune 脚本向 CompileIQ 收敛，Python 侧 cuda.core 也能直接做 graph capture。值得安排一次 CUDA 13.3 升级评估，特别是 Blackwell 集群上线前。

In-Context Optimization for Retrieval-Augmented Generation: A Gradient-Descent Perspective

作者证明在线性 self-attention 假设下，一层 attention 恰好实现 RAG 的一步梯度下降——把 "projection-based" 和 "dot-product" 两类检索接口统一到一个线性化目标上。基于这一对应，他们设计了一种把 query 和 retrieved docs 当作 in-context 梯度信号的交互方式，使 LLM 在 forward pass 里完成一次自适应。

INSIGHT这是把 RAG 从 "静态拼上下文" 推向 "上下文作为隐式 fine-tune" 的理论桥梁。工程意义在于：未来 reranker / context compressor 设计可以显式按 "哪个 doc 对 forward pass 的隐式梯度贡献最大" 来打分，而不是简单按 cosine 相似。对搜索/RAG 系统的 reranker 替代方案研究有理论参考价值，但短期内还不是可直接上线的工程方案。

Mingchen Li, Jiatan Huang, Chuxu Zhang, Liang Zhao, Hong Yu
