Credit-assigned Policy Gradient for Early Stage Retrieval in Two-stage Ranking

针对搜索/推荐/RAG 系统普遍使用的两阶段架构，作者提出 credit-assigned policy gradient (CA-PG)，用于端到端训练早期召回阶段（ESR）。常规的 vanilla policy gradient 把梯度回传到整个候选集的联合概率上，当候选集规模达到工业级（数千到上万）时方差爆炸，几乎无法训练。CA-PG 把梯度改为对'目标 item 在任意候选集中被选中'这一边际概率求导，利用边际化消去与具体候选集组合的依赖。在 RecSys-style 仿真和真实数据集上的实验显示 CA-PG 显著降低梯度方差并稳定收敛，比 V-PG 更易扩展到大候选集场景。

KEY INSIGHT · 对业务意味着什么ESR 的 RL 训练长期受限于'候选集联合采样'带来的组合爆炸，CA-PG 把目标转成'目标 item 被覆盖'的边际概率，是搜索/推荐场景中能直接落地的工程化简化。该思路与 negative sampling、importance weighting 有内在联系，可与召回侧已有的对比学习/序列推荐范式叠加。对社区搜索而言，意味着可以用统一的 RL 目标共同训练召回与精排，让召回更直接对齐下游业务指标（点击/转化），而不只是 retrieval-only 的 nDCG。

Uniboost: Global Coordination with Value Alignment for Fair and Efficient Traffic Allocation

Alibaba📖 深度解读 · 10 分钟 →

面向工业级推荐系统的混排/重排阶段，论文提出 Uniboost 统一流量分配框架，重点解决多业务目标（自然+商业+生态）耦合时的三大痛点：分配方案彼此耦合无法独立调优、模型分数被'通胀'、缺乏业务可解释性。核心机制是 posterior value alignment（后验价值对齐），把抽象模型分数校准到带显式业务语义的锚点指标（如 GMV、播放时长）；并采用独立线性 boosting 范式解耦各计划权重，使每个加权项的边际贡献可归因。在淘宝/天猫线上 A/B 验证：降低低边际计划权重不必然损失流量，并对收入与用户体验都有正向收益。

INSIGHT传统混排把多个 plan 的 score 全部加权拼接进 listwise loss，导致权重之间相互掩盖、调一个动全身。Uniboost 的关键不是新模型，而是工程范式转变：把 score 校准成可比的 anchor metric（货币化/时长化），再用线性独立 boosting 让每个 plan 都能像电商促销活动一样'打开/关闭'并精确计量收益。对社区搜索的启示：如果同时承接广告、生态扶持、首页推荐多个目标，应优先把所有 score 标定到同一业务指标空间，再做线性可加权组合，避免黑盒精排被业务方质疑。

Ge Fan, Nan Zhao, Kai Meng, Cong Luo, Yang Fu, Huiping Chu, Jialin Liu, Yuning Jiang, Bo Zheng

Hi-SAM: A Hierarchical Structure-Aware Multi-modal Framework for Large-Scale Recommendation

ByteDance

针对大规模多模态推荐中 semantic ID 路径的两大顽疾——RQ-VAE 类 tokenizer 没有解耦跨模态共享语义与模态特异细节（导致 token 冗余或塌缩），以及 vanilla Transformer 把展开后的 token 流当作 flat 序列处理时被局部 token 主导注意力——论文提出 Hi-SAM 框架。两个核心组件：(1) Disentangled Semantic Tokenizer (DST) 通过几何对齐统一文本/图像模态，并用粗到细策略量化，共享码本承载跨模态语义、模态私有码本承载模态细节；(2) 层次化的 Transformer 显式建模 user→item→token 三层结构。实验显示在大规模数据集上 NDCG 和 HitRate 显著优于 TIGER、HSTU 等 baseline。

INSIGHTTIGER 之后的生成式推荐路线一直在 token 化与序列建模两个维度上分别打补丁，Hi-SAM 第一次同时处理'tokenizer 解耦 + 注意力层级化'两个问题，指出二者在系统里是耦合的：粗粒度 token 承载用户级语义，细粒度 token 承载 item 级细节，注意力应当按这个层级分配。对社区搜索/UGC 推荐的启示：当帖子同时有标题、正文、封面图、视频帧时，不要把所有模态量化到同一个 codebook 里，而应共享码本 + 模态私有码本组合，并在排序模型里显式表达层级，避免长 token 序列的注意力被局部细节淹没。

Pingjun Pan, Tingting Zhou, Peiyao Lu, Tingting Fei, Hongxiang Chen, Chuanjiang Luo

L2Rec: Towards Dual-View Understanding of LLMs for Personalized Recommendation

ByteDance

LLM 用于个性化推荐时，行为信号（交互序列）与语义信号（item 文本）的融合通常发生在两个极端：输入端把 behavioral embedding 注入 token space（存在分布 gap），或输出端用对比学习对齐两个独立编码器（缺乏端到端监督）。L2Rec 提出在参数层面统一两类信号：同一组 Transformer 参数作为共享介质，通过 Dual-view Personalized Mixture-of-Experts (DPMoE) 给每个 view 注入个性化的 low-rank 扰动 (LoRA-like)，让单个 LLM backbone 同时输出行为和语义两种互补表示。实验显示在多个 benchmark 上优于现有 LLM4Rec baseline。

INSIGHTDPMoE 的设计本质上是'每个用户/每个 view 学习一组私有的 LoRA delta'，这与 PEFT 路线的个性化结合是当前 LLM4Rec 的活跃方向。把参数级融合作为第三种范式（区别于 input-level 和 output-level），避免了 token space 失配和后期对齐的额外训练损失。对工业落地的启示：直接 fine-tune 全量 LLM 服务每个用户不现实，但 LoRA-based per-view perturbation 是个介于 prompt-tuning 与 full FT 之间的可行折中，适合中等流量场景；社区搜索可以参考'兴趣 view + 内容 view'的双 LoRA 设计做个性化排序。

Pingjun Pan, Tingting Zhou, Peiyao Lu, Tingting Fei, Hongxiang Chen, Chuanjiang Luo

VitaBench 2.0: Evaluating Personalized and Proactive Agents in Long-Term User Interactions

现有 agent benchmark 主要评测推理和工具使用，几乎不评测 agent 是否能从碎片化日常交互中推断并利用用户偏好。VitaBench 2.0 把任务组织成按时间排序的用户长序列，偏好被嵌入在异质碎片化交互中。成功完成任务要求 agent 持续地从历史交互中提取、利用并更新用户偏好。Benchmark 包括明确指令任务和需要主动提问澄清的任务，覆盖多个真实场景（出行、购物、餐饮、健康），并提供量化的 personalization 与 proactivity 评分维度。

INSIGHTAgent + personalization 是 2025-2026 的下一个评测重心：用户不再每次重新交代偏好，agent 应像老朋友一样记住并主动询问。VitaBench 把'长期记忆 + 主动澄清'纳入评测，对推荐和搜索都是重要信号——下一代搜索框不只是召回排序，而是会主动澄清意图。对工业落地的启示：在做对话搜索/对话推荐时，建议同时引入'偏好抽取召回率'和'澄清问题相关性'两个评测维度，VitaBench 提供了直接可借鉴的指标设计。

Yuxin Chen, Yi Zhang, Zhengzhou Cai, Yaorui Shi, Zhiyuan Yao

BESPOKE: Benchmark for Search-Augmented Large Language Model Personalization via Diagnostic Feedback

YYonsei

面向 ChatGPT/Gemini 等通过用户历史做'伪个性化'的搜索增强 LLM，BESPOKE 提出更现实的评测：直接收集真实人类的 chat 与 search 历史，并为每条回应配上细粒度的偏好分数和文字反馈。Benchmark 通过长期纵向收集构建，可同时评测 retrieval 阶段的偏好对齐（是否返回了该用户偏好的文档）和 generation 阶段的形式偏好（长度、列表 vs 段落、语气）。

INSIGHT目前搜索增强 LLM 的'个性化'大多停留在简单注入用户档案，BESPOKE 的关键贡献是把评测拆成 retrieval-level 偏好 + generation-level 偏好两个维度。这种解构对工业产品很有价值——可以分别诊断召回侧偏好建模不够还是生成侧风格控制不够。对社区搜索的启示：在用 LLM 做搜索结果摘要时，应同时记录用户对'返回了哪些帖子'与'摘要怎么写'的反馈，而不是单一相关性反馈，否则无法定位 personalization 的瓶颈。

Hyunseo Kim, Sangam Lee, Kwangwook Seo, Dongha Lee

Exploration on Demand: From Algorithmic Control to User Empowerment

推荐系统过度专精导致 filter bubble。本文用 sentence-transformer embedding 对 item 做 online 动态阈值聚类，得到语义连贯的内容簇结构，并提出一个用户主导的探索机制：用户可主动从 less-engaged 簇中采样，控制推荐多样性，并显式暴露 relevance-diversity trade-off。在 MovieLens 上验证有效。

INSIGHT把'多样性 vs 相关性'决策权交给用户，是与平台单方面调控相反的设计思路。虽然实验只在 MovieLens 这种学术数据上，但思路对社区搜索的'兴趣探索'入口有借鉴价值：与其平台暗自插入多样化结果引起负反馈，不如显式提供'看看其他方向'按钮让用户主导跳出茧房。簇级别的 less-engaged 采样比单 item 级别更可控，工程上也好实现。

RAGEAR: Retrieval-Augmented Graph-Enhanced Academic Recommender

RAGEAR 是面向学术课程推荐的 neurosymbolic 推荐系统：在完整讲义转录文本上做 dense retrieval，配合一个建模课程、单课、转录 chunk、学分、培养方案等结构化信息的 Knowledge Graph。KG 支持基于结构约束（学分、专业、培养方案、先修课）的符号过滤；核心贡献是一个 graph-aware 聚合函数，把 chunk 级证据传播到 course 级推荐，得分由三个因素组成：检索相似度占比、chunk 排名强度、结构约束匹配度。

INSIGHT学术推荐看似垂直，方法论可推广到任何'item 有内部结构 + 强业务规则'的推荐场景：把 RAG 检索的细粒度命中通过图聚合到业务实体（课程、商品、服务），并允许符号约束硬过滤。对社区搜索的启示：当帖子是'回答+评论'的层级结构时，应在 chunk 检索后用聚合函数滚动到帖子级排序，而不是直接以 chunk 作为返回单位；硬业务规则（不可推未审核帖、强制城市过滤）应在 KG/符号层处理，避免污染向量空间。

Francesco Granata, Lorenzo Lamazzi, Misael Mongiovì, Francesco Poggi, Valeria Secchini
