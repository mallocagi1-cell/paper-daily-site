MuChator: Enabling Active Music Discovery via Conversational Music LLMs in Douyin Music

抖音音乐百万级 DAU 的 feed 流推荐缺少'主动指定意图'通路，用户对'下雨天通勤想听的歌'这类模糊、场景化的 query 无法直接表达；直接套用 LLM 又面临音乐领域知识不足、音乐-query 协同推理弱、用户偏好理解浅三个问题。作者提出 MuChator，一套交互式 MusicLLM 框架：在通用 LLM 上注入音乐元数据 SFT、构建 query-音乐协同推理的偏好数据集、并引入用户行为序列做个性化适配，从而把对话理解、音乐召回、个性化偏好三个能力放在一个 LLM 里。已在抖音音乐上线服务百万级用户，论文给出了完整工程拆解。

Large Language Model-Powered Query-Driven Event Timeline Summarization in Industrial Search

Baidu

百度搜索上线的 QDET 系统针对热点新闻类 query 生成围绕 query 的事件时间线摘要。两个关键设计：(1) 多任务监督微调，引入'时间排序'、'因果判断'、'时间线补全'三个辅助任务，让小模型在该领域达到大模型水平；(2) 基于强化学习的事件简洁摘要，在严格长度约束下保持语义质量，事件摘要长度合规率达到 88.2%。论文报告了基于百万级日文档的生产系统效果数据，并讨论了 noise candidate 与 query-event 相关性筛选的工程实现。

INSIGHTQDET 给社区搜索的启示是：把'查询场景'本身拆成可训练的辅助任务（如'问答顺序'、'回答与问题的因果'）就能让一个 7B 量级模型在垂直能力上拼掉通用大模型——这对线上延迟敏感的搜索场景至关重要。RL 强约束生成摘要的思路也可以借鉴用于社区搜索的 query-focused 帖子摘要，关键是把'长度合规率'和'语义保真度'同时作为 reward 信号，而不只是最大化 ROUGE。

Mingyue Wang, Xingyu Xie, Hang Yang, Li Gao, Lixin Su, Ge Chen, Dawei Yin, Daiting Shi

ICICLE: Expanding Retrieval with In-Context Documents

NTU

生成式检索（Generative Retrieval, GR）把 query 直接映射到 docid，新文档加入需要重新训练模型，存在灾难性遗忘问题。ICICLE 把'增量 GR'重新定义为 in-context 检索：把新增的 document-docid 配对作为 inference 阶段的上下文证据给模型。框架由三部分组成：基于 `[COPY]` token 的路由机制（区分参数记忆 vs 上下文记忆）、preference-based calibration（校准两路概率）、long-context 适配。MS MARCO 和 NQ320K 上对新增文档的检索准确率提升明显，且不损害对已有文档的检索性能。

INSIGHTICICLE 把'语料更新'从'重新训模型'转成了'上下文喂证据'，是 generative retrieval 真正可工程化的关键一步——社区搜索新帖子持续涌入，传统 GR 几乎不可用。`[COPY]` routing 的设计也可以单独移植：在 RAG 场景下，给模型一个明确开关'此回答应来自参数记忆 vs 检索证据'，能显著改善对新内容的可控性。该范式与 long-context LLM 的发展耦合，未来 1M+ context 模型出现后可能成为主流的索引-即-上下文方案。

Yu-Chen Den, Yung-Yu Shih, Zhi Rui Tam, Kuan-Yu Chen, Pu-Jen Cheng, Yun-Nung Chen, Eugene Yang

The Coverage Illusion: From Pre-retrieval Routing Failure to Post-retrieval Cascades in a Production RAG System

Aarhus University

丹麦国家百科全书生产 RAG 系统的 case study：对 20,000 条 query-workflow 配对（真实 + 合成）评估 HyDE/query expansion 等增强方法的真实必要性。合成 query 显示 90%+ query 需要 LLM 增强才能达到高检索覆盖；但在生产 deferral 策略下，只有 27.8% 的真实用户 query 需要 LLM 增强——作者称这种 90% 与 27.8% 的差距为 'Coverage Illusion'，并把根因归结为合成 query 与真实 query 分布的结构性失配。同时分析了 pre-retrieval 路由失败如何在 post-retrieval 引发级联放大问题。

INSIGHTCoverage Illusion 戳穿了一个广泛流传的误判：'必须给所有 query 套 LLM 改写'。生产侧绝大多数 query 都是简单的语义匹配，盲目套 HyDE 反而增加延迟和成本——这与社区搜索短文本场景几乎完全契合（多数 query 是关键词级，长 query 占少数）。该论文给出了 deferral 策略（按 query 难度路由是否调用 LLM 增强）的直接证据，应该成为做 LLM4Search 工程时的默认设计：先在线分流再决定是否进入 LLM 通路，而不是默认走全量 LLM 重写。

Zafar Hussain, Kristoffer Nielbo

LLM-guided Hierarchical Search for End-to-end Reasoning Intensive Retrieval

GoogleUCLA

针对 reasoning-intensive 检索（query-doc 相关性需要推理而非表面匹配），标准的'embedding 召回 + LLM 重排'流程在 SOTA embedding 也无法把正确文档塞进 top-k 时失效。query 改写、agentic loop 等做法仍在 embedding 上游，受限于 embedder 表现和 LLM 凭参数知识改写 query 的能力。本文提出 LLM-guided hierarchical search：LLM 直接通过可层次导航的搜索索引与语料交互，不依赖 embedder，构建层次索引以支持端到端推理密集检索。

INSIGHT该工作把 LLM 推到了'与索引直接交互'的位置，把传统检索的检索-重排两段式打散成 LLM 主动遍历索引树的搜索过程，对社区搜索里'用户问'有没有 N 年前关于 XX 引申问题的帖子'这种推理型 query 是更对的范式。代价是索引侧需要可被 LLM 导航的层次结构（不是 ANN 向量索引）——这可能意味着用主题/标签 KG 或聚类树作为可走的'索引图'，工程上比维护 HNSW 复杂，但对小规模、高 NDCG 要求的垂类场景值得评估。

Nilesh Gupta, Wei-Cheng Chang, Ngot Bui, Cho-Jui Hsieh, Inderjit S. Dhillon
