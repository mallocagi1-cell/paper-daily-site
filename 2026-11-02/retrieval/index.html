Contextual Embeddings Beyond the Gold Chunk

上下文 embedding 的训练和评测都默认一个问题在文档里只有一个相关段，这篇论文指出这个假设在 RAG 里不成立。回答一个问题往往还需要交代说的是哪个产品、哪一年的段落，可现有训练把同一文档里答案段以外的段一律当负例，这些佐证段反而被压低。作者拿一个现成的上下文压缩模型当老师，它原本负责从检索到的文档里挑出和 query 相关的片段，会给每个 token 打相关度分。每段取段内最高几个 token 分的平均当段分数，embedding 模型去拟合这个分数，不再需要标注答案段。在新建的诊断基准上，9B 模型前 10 段里找到答案的比例是 45.5%，最强基线 voyage-context-4 是 31.1%。

Retrieving from Your Own Mistakes: On-Policy Training of Embedding Models for Multi-Hop Retrieval-Augmented Generation

📖 深度解读 · 14 分钟 →

多跳检索里的链式 embedding 检索器，训练和上线时看到的历史不一致，这篇论文给出一个不加大模型调用的修法。这类检索器每一步把问题和已找到的段落拼在一起再找下一段，训练时历史全是正确段落，上线后却常混进它自己找错的段落。在四跳的 MuSiQue 问题上，到第三步已有 70% 的检索状态带了错段。作者每轮训练都让当前模型自己跑一遍，拿它真实走到的状态来训练，目标设为还没找到的最早那段正确段落。同样配方下，前五段里把证据找全的问题比例从 44.6% 提到 50.5%。

Chenjie Qiu, Zixuan Zeng, Shaobin Shi, Bingfeng Chen, Dongsheng Luo, Boyan Xu

03 4.30

DeFT-RAG: Incrementally Decomposing Multi-Hop Questions into Self-Contained Sub-Questions with Reusable Answers

📖 深度解读 · 13 分钟 →

多跳问答里原本压在 LLM 一个身上的活，可以拆开交给不同部件：这篇论文的 DeFT-RAG 让 LLM 每次只写一个把实体名写全的子问题，每个子问题和答案由程序按规则记进一张问答表，LLM 最后读这张表回答原问题。在 MuSiQue 上，准确率从最强基线的 0.577 提到 0.629。因为子问题把实体名写全了，答案还能跨题复用：23.1% 的子问题直接从缓存作答，LLM 调用少了 12.9%，准确率不降。多跳问题难在要靠问题里从不提的中间实体一环扣一环地找证据，而迭代式方法让 LLM 同时规划、排先后、改写、记账，每件事都会出错。

Dingyi Kang, Bingzhe Li

04 4.30

Decompose, Estimate, Select: Coverage-Aware Context Construction for Long-Form RAG

📖 深度解读 · 14 分钟 →

长答案 RAG 里，检索覆盖得更全，答案不一定更全。这篇论文做了一条显式计算覆盖的检索链路，并用它量出了这一点。作者先让 LLM 把问题拆成一组子问题，再用一个 cross-encoder 预测每篇候选文档能回答哪些子问题，然后每次挑一篇能补上最多新子问题的文档。在 TREC RAG 2024 上，α-nDCG 从 0.625 提到 0.702，接近把子问题换成人写答案要点时的上限。可在生成模型、候选池和文档预算都固定的对照里，直接按参考标注挑出的文档覆盖得更全，写进答案的要点却并不比它多。答案完不完整，不只取决于找到了什么，还取决于生成模型有没有用上。

He Tu, Aleena Bosco Kurumthottam, Torsten Suel

05 4.30

xPRT: Cross-Passage Retrieval Pretraining

📖 深度解读 · 14 分钟 →

同一篇网页里哪几段在讲相关的事，本身就能拿来训练检索模型。xPRT 先挑出向量和全文平均向量足够接近的段落当代表段，再按向量相似度和词面重合，给每个代表段找出同文档里最相关的四段，然后训练 embedding：代表段要在混着其他文档段落的候选里认出和它最相关的那一段；相关段被遮掉大部分词后，单层小解码器要借助代表段的向量把这些词补回来。在已经很强的 E5 上只换训练目标继续预训练，五种已有方法在 MTEB 上最多涨 0.38 分，xPRT 稳定涨约 1.8 分。起作用的主要是正样本怎么选，新加的补词项只贡献一小部分。

Danush Khanna, Himanshu Singhal, Pranjal A. Chitale, Bishal Santra

Glance: The Generator Is Its Own Reranker

📖 深度解读 · 18 分钟 →

RAG 系统通常要同时部署一个 reranker 和一个生成模型，候选段落被两个模型各读一遍。Glance 的思路是：生成模型反正要读这些段落，不如让它自己来排序。它把所有候选段落一次 prefill 进 KV cache，再从这份共享缓存上给每段接一小段打分提示，由一组 LoRA 参数和一个打分头给出相关度，然后关掉 LoRA，由同一个模型读选中的几段写答案，每多一种判断能力只多占约 0.1 GiB 显存。在 MS MARCO 上短暂微调后，它在 SciFact 上的 nDCG@10 是 0.741，专用 reranker bge-reranker-v2-m3 是 0.721。评测只覆盖两个检索集和一个模型家族，但少部署一个常驻模型，对服务成本的影响很直接。

Adilet Metinov, Chingiz Arziev

How Specific Do I Need to Be? Effects of User Query Underspecification on Deep Research Agents

用户向深度研究 agent 提问时，常常没说清时间范围、用错专业术语，或者没提自己的偏好。作者把完整问题里的这类信息逐项删掉或说得含糊，在三个深度研究 agent 上对比答案。少了范围或术语时，答案对用户真实需求的覆盖明显下降，但引用依旧准确，并没有更多幻觉。搜索过程给出了原因：问题一含糊，agent 搜得更广，搜索词里来自用户原话的部分变少，更多来自模型训练时学到的东西。专门为深度研究训练、完整问题上得分更高的 agent，掉得反而更多。深度研究 agent 需要学会在问题不清楚时先问一句，而不是自己猜。

Yi Wen, Xiangjue Dong, Bingxuan Li, Hangxiao Zhu, Leo Zhicheng Liu, Yu Zhang, James Caverlee

Relevance-Guided Residual Calibration for Spectral Compression of Dense Retrieval Embeddings

把检索 embedding 投影到少数几个主方向上，是压缩存储和打分开销的常用办法，但每个方向保留多大权重，只看语料统计出的整体趋势，不看它对区分相关和不相关文档有多大用。RRC 用相关性标注重新估计每个方向的权重：某个方向对相关和不相关文档的得分差贡献平均越大、波动越小，权重就越高。它再用一条幂律曲线拟合这些权重的整体走势，只把每个方向偏离曲线的那部分加到原有权重上，原来大方向权重高、小方向权重低的走势不变。它只改 query 和文档共用的那个线性变换，不用训练模型，也不加推理步骤。在推理密集的 BRIGHT 基准的五个数据集上，压到 768 维时，nDCG@10 比原来的压缩方法 SpecTemp 平均高 2.34 个点，再做量化收益依旧在。

Yongkang Li, Panagiotis Eustratiadis, Evangelos Kanoulas

Quantum-Inspired Pairwise Ranking Aggregation via Active LLM Feedback

融合多路检索结果时，RRF 这类无监督方法便宜但不会学习，用 LLM 做列表式重排效果好，每个 query 却要调用上百次。LLM-IRA 走中间路线：只挑几路检索器排序相反的文档对（比如 BM25 认为 A 比 B 好，向量检索认为 B 比 A 好），让 LLM 判断哪篇更相关，用这些判断去学各路检索器的融合权重，最后的排序仍是简单的线性加权打分。作者用一个 8B 开源指令模型当裁判，在多数基准上持平或超过最好的静态融合方法；在两届 TREC DL 上，每个 query 只要约 5 次 LLM 调用就已超过最好的无监督融合。它不需要训练数据，也不用微调模型，适合只想在融合层花少量 LLM 预算的场景。

Quan Mai, Susan Gauch, Gibson Nkhata

Feedback-Assisted Trust Propagation over Document Relation Graphs for Retrieval-Augmented Generation

RAG 的语料里常混着过期、互相矛盾或不可靠的文档，人工标注哪篇可信又很贵，只能覆盖一小部分。这篇把每篇文档当作图上的一个点：两篇来自同一来源或互相支持，就连一条支持边；互相矛盾，就连一条矛盾边，这些关系可以用 NLI 模型判断。人工只给少数文档标出可不可信。它再解一个优化问题：支持边两端的可信度分要尽量接近，矛盾边两端的分加起来要接近 1，也就是最多只信一篇，同时贴合人工反馈。可信度就这样从少数标过的文档传到全库。检索和生成答案时都参考这个分数。作者报告检索质量和 EM 都优于基线，反馈稀少或带噪时依旧稳定。

Zhuoheng Li, Ying Chen
