PFA: Attention Can Be Progressively Focused in Long-Sequence Generative Recommendation

AlibabaZhejiang University📖 深度解读 · 14 分钟 →

阿里的作者发现，生成式推荐做 beam 解码时，越往后注意力越集中在少数几条历史行为上，而且哪些行为重要，前后几步基本不变。据此提出的 PFA 把挑选重要历史这件事，从每步、每条 beam 各挑一次，改成整个解码只挑一次。

RoFiGR: Coarse Routing, Fine Refinement via Level-Adaptive Distillation in Multimodal Generative Recommendation

📖 深度解读 · 14 分钟 →

生成式推荐逐个码地生成物品的 SID，前两层码一旦选错大分支，后面再准也找不回相关物品；而多模态推荐里的 SID 多按图文语义构建，前几个码未必反映哪些物品常被同一批用户购买。这篇论文的 RoFiGR 因此把协同信息集中用在前两层码上。

R2QRec: Learning Recommendation Queries from Retrieval Feedback

用大模型做推荐有一种思路：先根据用户历史写几条搜索 query，再交给现成的检索系统去找物品。难点在于日志里只有用户点了什么，没有当初该写什么 query。常见做法是拿被点物品的文字当目标去模仿，但这样写出的 query 未必能把这个物品检索出来。R2QRec 直接用一个固定的检索器来检验：先生成很多候选 query，只留下真能检索回被点物品的那些做 SFT；再让模型一次写一组 query，每条各检索出一个列表，用 RRF 合成一个推荐列表，GRPO 按被点物品在这个列表里的排名给奖励。只训练 query 生成器，检索器和物品索引都不动。在 MovieTV 上，去掉检索检验这一步，NDCG@10 从 5.07% 掉到 4.03%。

Weixin Chen, Shuchang Liu, Hailan Yang, Yuhan Zhao, Li Kang, Xuefeng Zhang, Chenghao Zhang 等 16 人

Statistical Detection of Positional Bias in LLM-Based Recommender Systems: Methodologies and Empirical Evidence

把候选商品写进提示词、让大模型挑一个推荐，候选的排列顺序本身就会改变它的选择。作者在一个真实商品目录上搭了 RAG 推荐测试，同一条 query 把候选顺序反复打乱，测了 8 个模型，统计检验在每个模型上都确认推荐结果和位置有关。各家偏向不同：GPT-OSS 偏爱排在前面的，LLaMA 4 Scout 反而避开第一个。候选越多越严重。给 20 个候选时，只是打乱顺序，DeepSeek R1 7B 就有 58.1% 的推荐和它对同一条 query 最常给出的那件商品不一样。顺序带来的偏差取决于模型本身，换温度也去不掉，用大模型做推荐时值得把候选顺序随机化，并定期做这类检查。

Carlos Peláez-González, Francisco Herrera, Andrés Herrera-Poyatos

Merge and Branch: Efficient Tree-Structured Supervised Fine-Tuning of LLMs for Recommendation

用大模型做生成式推荐时，输入是一长串带文字的历史，输出却只是几个 token 的 SID。训练时费力读完一整段历史，往往只学一个目标物品。M&B 第一步把每条历史物品压成少数几个 token：先把它各层 SID 码的 embedding 合成一个锚点向量，再分别加上几个可学习的偏移向量作为查询，对物品的 SID 和文字 token 做注意力；每个查询取回的内容再加回锚点向量上，就成了一个 token。第二步让压缩后的历史同时预测多个目标：下一个物品、更往后的物品和老师模型推荐的物品，这些目标像树枝一样共用同一段历史，彼此看不见。解码时各条 beam 也共用历史 KV cache。历史只算一次，每个分支都能回传梯度。历史长度为 512 时，beam 解码的显存少了 61.8%，延迟少了约一成。

Yunqin Zhu, Yao Xie

08 3.75

Federated Recommender Agents

用大模型 agent 做推荐，集中所有用户的记忆有隐私问题，各自为战又学不到别人的经验。FedRecAgent 让每个用户端的 agent 只上传用自然语言写的经验，不上传交互记录，也不更新模型参数。每条经验写成三段：当时处在什么情境，用户下一步怎么选（接着看当前感兴趣的那类、回到以前喜欢的、还是换个新方向），以及为什么这样选。具体物品和个人偏好都去掉。服务器按文本相似度，把情境相近的经验归成一组，组里选择也相近的合并，选择不同的分开保存。推荐时，用户端先找与当前情境最接近的一组，再按本地的偏好和选择习惯记忆挑出组里最贴近的几条，由模型选一条辅助排序。在六个数据集上，最好的版本比最强基线的 NDCG@10 高 1.54% 到 9.19%。

Jaehyung Lim, Woojoo Kim, Junyoung Kim, Dongha Kim, Wonbin Kweon, Hwanjo Yu

PALATE: Pretrained Autoregressive LATent Embeddings

已录用 CIKM 2026 WorkshopDoorDash

外卖和本地生活平台的广告排序要做到千人千面，但用户的行为历史很稀疏，店铺又有几十万家。DoorDash 原来的排序模型只靠手工统计特征和不分先后的历史汇总，没有一个学出来的用户序列表示。PALATE 训练一个 GPT 式模型，根据用户的行为序列预测接下来会和哪些店铺互动，取最后一个位置的隐藏状态当用户 embedding，每天刷新一次，作为普通特征喂给各个广告位的排序模型。因为复购多，训练时给用户没去过的新店更高权重，先用点击预训练，再用下单微调。离线它是单个特征里 AUC 涨得最多的；上线时随排序模型的整体重训一起发布，搜索广告收入提升 0.94%，转化率提升 1.50%。

Sizhang Zhao, Praveen Gondhi, Bin Li, Utsaw Kumar

Category-Anchored Large Language Models for Next POI Recommendation

已录用 ICDE 2027

预测用户下一个要去的地点（POI）时，直接让大模型生成地点 ID 并不可靠：地点多、分散、长尾严重，名字本身也没多少语义。ANCHOR 换了个顺序，先让大模型预测用户接下来想去哪一类地方，类别数量少、含义稳定，更好预测；再从三路凑出候选，分别是这一类的地点、用户去过的地点，以及用户长期、近期和对应时段偏爱的类别下的地点；最后用一个参照历史轨迹的重排模型选出具体地点。先猜类别再落到地点，比直接猜地点稳。在纽约、东京和加州三个签到数据集上，它的 Acc@1 比最强的大模型基线 Think2Go 分别高 7.56%、11.21% 和 1.94%。

Lexi Bai, Xiaopeng Zeng, Xun Zhou, Yuanshao Zhu, James Jianqiao Yu
