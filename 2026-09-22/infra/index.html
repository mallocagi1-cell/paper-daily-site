Hybrid GPU-CPU Retrieval for Personalized Search at Ultra-Large Scale

Meta 针对超大规模 UGC 搜索，把深交互召回与预排序放在 GPU 的十亿级精选库，把广覆盖交给约大20倍的 CPU 库，合并去重后进入共享排序。九天线上实验相对旧 CPU 系统，模型评分 DCG@20 提升4.51%，有效互动指标 GSRR 提升2.01%；这些结果对应整体方案，不能单独归因于硬件。

Open-Sourcing Rebalancer: A Generic, High-Performance Library for Solving Assignment Problems

Meta

Meta 开源 Rebalancer，把对象分配到资源容器的问题抽象成约束、目标与表达式图，可选择局部搜索或整数规划求解。系统每天求解约4000万次、覆盖30多种问题；26.5万个对象与3200个容器的场景中，P99求解时间为12秒，并提供可视化工具解释约束与分配结果。

INSIGHT社区搜索可用这类建模方式统一索引分片、模型副本和训练任务的放置，把故障域、容量与迁移代价写成可调约束。先在离线容量规划中建立小规模最优解，再切换局部搜索测试大规模调度质量与时限；文中的生产规模证明工程成熟度，但不能直接推导本业务成本或 CTR 收益。

Richard Barnes, Neeraj Kumar, Pol Mauri Ruiz

Scaling Forced Alignment to End-User Devices

BBYU

论文为长音频与文本强制对齐引入 Hirschberg 线性内存算法，并用受约束随机游走剪枝搜索空间。三小时输入的对齐内存由140GB降至5MB，CPU耗时约为 torchaudio 的三分之一；超过20分钟的输入再获约2倍加速，超过98%的测试保持对齐准确性，代码已开放。

INSIGHT社区音频帖与视频转写的数据管线可以借此在普通 CPU 机器上生产片段级训练样本和可定位搜索结果，减少长内容离线处理的资源门槛。应先核对转写错误较多、语言混杂等 UGC 样本的剪枝失误，再比较吞吐与时间戳质量；这里的加速作用于对齐阶段，不代表语音识别模型本身提速。

Lawry Sorenson, Michael Crandall, Eric K. Ringger, Stephen D. Richardson

Simplifying Model Serving Across Multiple GPUs with NVIDIA TensorRT Multi-Device Integration in NVIDIA Dynamo-Triton

NVIDIA

Dynamo-Triton 26.07 将 TensorRT 多设备引擎封装为一个服务实例，由后端管理多 GPU 执行上下文和 NCCL 通信。Cosmos 3 Nano 的44,160个视频词元用 Ulysses 上下文并行切分；单卡到八卡的端到端生成耗时从156.595秒降至34.183秒，约4.58倍，实验未衡量并发吞吐与总成本。

INSIGHT多 GPU 服务应把模型版本、通信组和执行生命周期收进服务端，减少社区搜索上层在调用大模型时处理设备细节的负担。迁移到 query 理解或多模态帖子处理前，应重新测试短输入、小批量和多请求竞争；视频生成的4.58倍加速不能直接用于短文本检索容量预算。

Daisy Chu, Peter Kisfaludi, Zhaoyuan He, Joseph Loftin, Byungsoo Jeon

Reading Less While Writing: A Closed-Form Bandwidth Dial for Streaming Multimodal Decoders

UUET Lahore

ZENDAYA 用单个连续参数控制流式解码可读取的输入前缀，随生成进度和预测输入长度调整，统一离线与实时处理。29M参数解码器在三套音视频数据上评估；ActivityNet 三随机种子复验得到离线 BLEU-4 1.97、METEOR 12.25，参数量不含冻结编码器，不能把不同评测协议直接当作性能胜负。

INSIGHT若社区搜索扩展到直播、音频帖或视频字幕索引，可把内容可见范围作为显式延迟预算，降低首段文本进入索引前的等待。落地时应同时测字幕质量、时间戳和内容入库时延，并验证上游特征是否严格因果；该方法对纯短文本召回没有直接收益，较适合作为多模态数据管线实验。

Yasir Mehmood, Kashif Javed

Do small language models know what they don't know?

研究在7组模型、5个自然语言理解基准上比较小于30亿参数模型的置信度与路由。91%的数据集—模型组合中，词元熵几乎为零，无法区分答案对错；多次采样后的语义熵可将难例转交较强模型，跨系列路由报告平均22.0%的准确率改善，但增加了计算开销。

INSIGHT为社区搜索的 query 理解设计大小模型级联时，不宜直接把输出概率当作可靠的升级阈值。可以先在模糊意图与长尾问句上比较语义采样路由和固定路由，并计入多次生成的成本；原文强调收益是更合理地分配计算，不能据此承诺节省算力或改善搜索 CTR。

Prashant Mudgal

mnemosyne systems: orangu 1.3.0

Mmnemosyne systems

orangu 1.3.0 扩展 Rust 本地模型栈，提供直接输出 GGUF 的 CPU 训练工具、量化转换与 RKNPU 矩阵计算卸载。在 Orange Pi 5 上，1976词元提示的预填充达到21.2词元/秒，CPU路径为16.4；约0.4毫秒的设备调用开销使窄矩阵解码仍保留在 CPU，证据来自单一设备示例。

INSIGHT对社区搜索的小模型原型与本地数据实验，统一训练产物和推理格式有助于减少转换及部署差异，按算子宽度选择硬件也值得借鉴。它尚未提供大规模搜索服务的吞吐与稳定性证据，适合先验证可复现性、量化质量和延迟，再判断是否适用于 query 理解或离线标注。
