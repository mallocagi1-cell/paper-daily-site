GRP v0.1 Technical Report

Snap 将召回、排序与奖励建模整合进同一编码器—解码器：生成多模态语义 ID，再用共同训练的多头模块打分，并冻结该模块用于强化学习奖励。线上先作为一路召回源，逐步旁路预排和替换弱源；最终组合实验相对生产基线使观看时长提升 0.82%、分享提升 2.56%，服务链路延迟降低 69%。

02 3.65

Learning Better Reasoning for Generative Recommendation with Semantic IDs

Evo-Rec 研究语义 ID 生成式推荐中的推理轨迹质量问题：先对齐物品 ID 与文本、行为上下文，再从多条候选推理中挑选能提高真实物品预测的轨迹，最后用目录约束和排序反馈进行强化学习。作者在三个 Amazon Review 基准上比较判别式、生成式和带推理的推荐器；公开摘要未给出具体提升幅度。

INSIGHT方法提醒社区内容推荐团队，显式推理可能误导物品生成，应以目标物品预测质量筛选轨迹，并在解码时强制约束到现有内容目录。三阶段训练可作为语义 ID 推荐实验方案，但迁移到 UGC 场景前需核查论文的详细指标、消融和推理成本；不能仅凭更长推理链假定 nDCG 或 CTR 会提高。

Mengdan Zhu, Yufan Zhao, Sophie Di, Yao Zhao, Tao Di, Yulan Yan, Sridhar Iyer, Liang Zhao

03 3.45

Do Evidence-Reading Diagnostics Improve Interface Selection in Small LLM Recommenders?

论文测试六个小型指令模型、四个推荐领域和 3426 名用户，比较历史提示、协同证据提示与分数融合三种接口。加入证据阅读诊断后，NDCG@5 从基线选择器的 0.5447 降至 0.5428，差值为 −0.0019；按开发集固定选择接口则达到 0.5524。相似用户证据比随机用户证据高 0.0999 NDCG@5。

INSIGHT对社区帖子推荐，先验证协同证据本身是否有增益，再检验额外诊断特征能否改变正确的接口选择。论文的负结果说明模型能回答证据题，不代表这些诊断值得部署；可用固定接口、简单选择器及额外诊断三档作离线对照，并监控候选顺序偏差与置信区间。

Han Chen, Yingrui Li
