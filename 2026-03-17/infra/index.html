98× Faster LLM Routing Without a Dedicated GPU: Flash Attention, Prompt Compression, and Near-Streaming for the vLLM Semantic Router

针对 LLM 请求路由器（用于安全分类、领域路由、PII 检测）的推理性能优化。标准注意力机制在 8K–32K token 长上下文分类时内存消耗过高（O(n²)），三个并发分类器在 8K token 下需约 4.5GB 仅用于注意力掩码。论文提出三阶段优化：(1) 基于 CK 的 Flash Attention 算子将内存从 O(n²) 降至 O(n)，延迟从 4918ms 降至 127ms（38.7×）；(2) 提示压缩进一步降低冗余；(3) 近流式处理。最终在 AMD MI300X 上实现 98× 端到端加速，且无需专用 GPU。

Serving Hybrid LLM Loads with SLO Guarantees Using CPU-GPU Attention Piggybacking

提出 OmniServe 系统，解决 LLM 服务共置部署中延迟敏感（LS）服务与尽力而为（BE）服务的干扰问题。现有方案通过粗粒度的资源预留来隔离 BE 负载，但这既损害 LS 的 SLO 达标率，又限制了 BE 的吞吐。OmniServe 的核心机制是 Attention Piggybacking：将 CPU 和 GPU 资源协同利用，在 GPU 为 LS 服务计算 attention 的间隙，将 BE 负载的 KV cache 操作迁移到 CPU，从而在保证 LS SLO 的前提下大幅提升 BE 吞吐。

INSIGHTCPU-GPU 协同推理是 LLM 混合负载服务的关键创新。对搜索系统而言，在线搜索（延迟敏感）与离线批量推理（尽力而为）通常共享 GPU 集群，OmniServe 的 Attention Piggybacking 机制提供了一种细粒度的资源隔离方案，可在保证搜索请求 SLO 的同时最大化集群利用率。比传统的资源预留策略更灵活、更高效。

Zizhao Mo, Junlin Chen, Huanle Xu, Chengzhong Xu

Architecture-Aware LLM Inference Optimization on AMD Instinct GPUs: A Comprehensive Benchmark and Deployment Study

AMD

首个在 AMD Instinct MI325X GPU 上进行的大规模 LLM 推理基准评测。覆盖 235B 到 1T 参数的四个模型，涉及三种架构族（MoE+MLA、Dense+GQA、MoE+GQA），在 8 卡集群（2TB 聚合 HBM3e）上使用 vLLM v0.14.1 进行测试。提供了 AMD GPU 上 LLM 部署的全面性能数据，包括吞吐、延迟、内存利用率等关键指标，为非 NVIDIA GPU 的部署决策提供数据支撑。

INSIGHT随着 AMD MI300/MI325 系列在性价比上的竞争力提升，非 NVIDIA GPU 部署成为降低推理成本的现实选项。该 benchmark 的实用价值在于提供了可参照的部署指南：不同模型架构（MoE vs Dense、MLA vs GQA）在 AMD 硬件上的性能表现差异很大，选型时需要架构感知的评估。对搜索系统的 GPU 采购和部署规划有直接参考价值。

TaxBreak: Unmasking the Hidden Costs of LLM Inference Through Overhead Decomposition

CMU

提出 TaxBreak 方法论，将 LLM 推理的主机端开销分解为三个可操作的组件：框架翻译时间、CUDA 库翻译时间和内核启动路径时间。在 NVIDIA H100 和 H200 系统上验证，提出 Host-Device Balance Index (HDBI) 指标来量化设备活跃执行与主机端编排之间的平衡关系。实验覆盖 dense 和 MoE 模型在 prefill 和 decode 阶段的代表性负载，揭示了 GPU 闲置率与主机端开销的非直觉关联。

INSIGHTLLM 推理中，主机端开销常被忽视但在延迟敏感场景下可能占主导。TaxBreak 提供的三层分解方法论对推理系统调优非常实用：它能精确定位瓶颈在框架层、CUDA 层还是内核启动层，避免盲目优化。HDBI 指标可作为搜索/推荐系统 LLM 推理服务的标准诊断工具，帮助判断当前是计算瓶颈还是编排瓶颈。

CMoE: Converting Mixture-of-Experts from Dense to Accelerate LLM Inference

提出 CMoE 框架，可在不需要训练的情况下将 dense LLM 快速转换为 MoE 架构以加速推理。传统的 dense-to-MoE 转换需要高成本的持续预训练，CMoE 通过无训练转换绕过这一瓶颈。核心思路是识别 dense 模型中 FFN 层的专家化模式，利用路由机制实现条件计算，从而在保持模型质量的前提下，通过只激活部分参数显著降低推理计算量。

INSIGHTCMoE 的核心价值在于提供了一条低成本的推理加速路径：无需重新训练即可将已部署的 dense 模型转换为 MoE 结构，享受条件计算的加速优势。对搜索系统中已有的 dense 排序/语义模型，这意味着可以在不改变训练流程的前提下获得推理加速。但需关注转换后的精度损失，尤其在排序任务中对精度要求较高的场景。

Cost-Efficient Multimodal LLM Inference via Cross-Tier GPU Heterogeneity

分析多模态 LLM 推理中的硬件需求不匹配问题：视觉编码阶段是计算密集型，语言生成阶段是内存带宽密集型。论文证明在标准 KV caching 下，模态边界（视觉编码器与语言模型之间）是最小化跨设备传输的最优切分点，将传输复杂度从 O(L×s_ctx) 降至 O(N_v×d)（GB 级 → MB 级）。这使得异构 GPU 部署（如高端 GPU 做语言生成 + 低端 GPU 做视觉编码）在普通网络下即可实现。

INSIGHT该论文的核心洞察是：多模态 LLM 的最佳切分点在模态边界而非 transformer 层边界，这一结论对异构 GPU 集群的部署规划有直接指导意义。对搜索系统中的多模态内容理解（如图文搜索），可以利用这一原理将视觉编码卸载到低成本 GPU，语言生成保留在高端 GPU 上，大幅降低总体推理成本。

EWSJF: An Adaptive Scheduler with Hybrid Partitioning for Mixed-Workload LLM Inference

提出 EWSJF（Effective Workload-based Shortest Job First），一种面向 LLM 混合负载推理的自适应请求级调度器。混合负载包含短时延迟敏感的交互式查询和长时吞吐导向的批处理请求，两者在 SLO 要求和资源消耗模式上差异巨大。EWSJF 通过实时学习负载结构，结合混合分区策略，在公平性和吞吐之间取得平衡，同时保证交互式请求的延迟 SLO。

INSIGHT搜索系统中经常存在在线推理（用户查询、低延迟）与离线批量任务（模型评估、日志处理）共享 GPU 集群的场景。EWSJF 的自适应调度方案可以有效管理这种混合负载，在保证搜索请求响应时间的同时最大化离线任务的吞吐。工作负载感知的实时学习机制比静态优先级策略更适合负载波动较大的搜索场景。

LLM Query Scheduling with Prefix Reuse and Latency Constraints

提出 LLM 推理中带前缀重用和延迟约束的查询调度理论框架。基于 RadixAttention 的前缀复用技术可显著降低计算开销——多个共享相同系统提示或上下文前缀的查询只需计算一次 KV cache。论文将此形式化为带约束的调度优化问题，在满足延迟 SLO 的前提下最大化前缀重用率，提供了理论最优解和近似算法。

INSIGHT前缀重用对搜索系统尤其有价值：批量处理的搜索查询通常共享相同的系统提示和少量 few-shot 示例。通过合理的查询调度将共享前缀的请求分组，可以大幅减少 KV cache 的重复计算。RadixAttention 结合延迟约束调度的理论框架为搜索系统的 LLM 推理服务优化提供了严格的理论基础。

KernelFoundry: Hardware-Aware Evolutionary GPU Kernel Optimization

NVIDIA

提出 KernelFoundry，利用 LLM 进行硬件感知的 GPU 内核进化优化。核心包含三个机制：(1) 基于 MAP-Elites 的质量多样性搜索，使用内核特定行为维度维持探索多样性；(2) 元提示进化，与内核共同进化以发现任务特定的优化策略；(3) 基于模板的参数优化，将内核调优到特定输入和硬件。克服了现有 LLM 内核生成方法仅依赖简单提示和反馈循环的局限。

INSIGHTKernelFoundry 代表了「LLM 优化 GPU 内核」这一新范式的前沿。进化搜索 + 元提示进化的组合使得内核优化可以超越人工调优的水平。对搜索系统的基础设施团队而言，该方法可用于自动优化自定义 attention kernel、embedding lookup 等核心算子，但需要较强的 CUDA 和 GPU 架构理解才能有效应用。

Nina Wiedemann, Quentin Leboutet, Michael Paulitsch, Diana Wofk, Benjamin Ummenhofer

Google Cloud AI infrastructure at NVIDIA GTC 2026

GoogleNVIDIA

INSIGHTNVIDIA Vera Rubin NVL72 的发布标志着从 Blackwell 到下一代架构的演进，机架级设计进一步模糊了单 GPU 和集群的边界。对搜索/推荐系统的基础设施规划而言，需要关注：(1) 新硬件的上线时间表对采购计划的影响；(2) NVL72 的高密度互联可能改变分布式推理的最优并行策略；(3) Google Cloud 的首发供应意味着云上用户可较早获取评测机会。
