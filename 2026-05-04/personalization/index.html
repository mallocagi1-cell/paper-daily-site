One Pass, Any Order: Position-Invariant Listwise Reranking for LLM-Based Recommendation

InvariRank 解决 LLM 列表式重排对候选项顺序敏感的问题：相同候选集换序后排名差异显著。方法用结构化注意力掩码屏蔽候选间的 cross-attention，并通过共享旋转位置编码 (RoPE) 把每个候选都视作出现在同一位置，从而抵消位置带来的打分偏差。一次前向即可对全部候选打分，速度等同传统方案，但排序结果在任意顺序下保持稳定。论文已被 SIGIR 2026 接收，代码开源。

KEY INSIGHT · 对业务意味着什么LLM 重排不稳定的根因在于自注意力让候选项互相比较时受位置先后影响，社区搜索场景下排序稳定性直接关联 nDCG 复现性。InvariRank 用注意力掩码 + RoPE 共享位置框架的工程化方案极轻量，几行 attention mask 改动就能给现有 LLM 重排器加上「位置不变」性质。后续在线召回-精排链路可借鉴该思路，把候选独立打分以避免顺序扰动带来的指标波动。

LLM-Enhanced Topical Trend Detection at Snapchat

Snap📖 深度解读 · 9 分钟 →

Snapchat 在端到端短视频平台上线全球范围 LLM 增强的话题趋势检测系统。流水线由三阶段组成：多模态主题抽取（视频/文本/标签融合）、时间序列爆点检测（基于历史基线的 burst score）、LLM 二次整合与丰富（去重、命名、扩充元数据）。线上六个月人评显示有效，下游接入内容排序与搜索后，内容时效性和用户互动指标均有可量化提升。

INSIGHT趋势检测是 UGC 平台搜推共用的「中间件信号」，LLM 用于「消歧+命名+富化」环节是最佳切入点：替代规则化的 topic 命名，不会卷入纯算法的 attention 大模型化。社区搜索可借鉴其三阶段架构——保留高效的统计 burst 检测，仅在最后阶段用 LLM 做语义聚合，避免对全量数据做 LLM 推理的成本。该论文也证实新鲜度信号能直接提升内容排序与搜索 CTR。

Position-Aware Drafting for Inference Acceleration in LLM-Based Generative List-Wise Recommendation

KuaishouUSTC

PAD-Rec 把投机解码（speculative decoding）引入 LLM 生成式列表推荐：核心难点是推荐 token 通常对应多个 item token，传统 draft model 对位置敏感导致接受率低。方法引入 item position embedding 与 step position embedding 让 draft 模型感知 list 内 item 边界与生成步骤，再加可学习门控自适应不同生成步骤的不确定性。多个数据集报告 wall-clock 加速最高 3.1× 而不损推荐质量。

INSIGHTLLM 推荐线上化的最大瓶颈是 P99 延迟，PAD-Rec 给出「在不动 base LLM 的前提下加 draft 模块」的可行路径。社区搜索若考虑 LLM 重排或 list-wise 生成，3× 加速直接决定能否落地。值得借鉴的是把「位置语义」显式输入到 draft 模型这一思路——所有 list-wise LLM 任务都存在 item-token 的「块状结构」，把块边界 / 块内步骤显式建模能显著提升接受率。

Jiaju Chen, Chongming Gao, Chenxiao Fan, Haoyan Liu, Qingpeng Cai, Peng Jiang, Xiangnan He

Hierarchical Multi-Persona Induction from User Behavioral Logs: Learning Evidence-Grounded and Truthful Personas

EEmory

提出从用户行为日志层次化归纳多 persona 的框架。先把用户动作聚合为意图记忆（intent memories），再对记忆聚类、命名生成多个 evidence-grounded persona。把 persona 生成形式化为联合优化目标——cluster cohesion、persona-evidence alignment、persona truthfulness——并用 DPO 变体训练打分模型。三个数据集上得到的 persona 更连贯、更贴合证据，对未来交互预测准确率也更高。

INSIGHT短文本社区里单一用户标签很难覆盖多兴趣，多 persona 表达更适合 UGC 搜索场景。论文最值得借鉴的是把「persona 真实性」作为可优化目标——用 DPO 让 LLM 学会拒绝把没有日志支撑的兴趣写进 persona，避免生成式用户画像里常见的幻觉。落地路径：把现有规则化兴趣标签换成多 persona 表征，作为召回侧的多路 query 改写或精排侧的 user feature。

Nayoung Choi, Haeyu Jeong, Changbong Kim, Hongjun Lim, Jinho D. Choi

AgenticRecTune: Multi-Agent with Self-Evolving Skillhub for Recommendation System Optimization

Alibaba

AgenticRecTune 用多智能体框架自动化推荐系统的系统级配置调优。Actor agent 生成候选配置、Critic agent 过滤次优方案、Online agent 自动跑 A/B 实验，Insight 与 Skill agent 协作维护一个自进化的 Skillhub——总结历史结果、抽取每个推荐子任务的潜在机理并更新可复用技能。让 LLM 参与配置空间探索，把架构师的调参经验沉淀为结构化技能。

LUCid: Redefining Relevance For Lifelong Personalization

MichiganEEmory📖 深度解读 · 15 分钟 →

LUCid 是首个挑战「语义相似 = 相关」假设的终生个性化基准，包含约 2000 条 query 配多 session 历史。结果显示当相关上下文来自话题不同的历史 session 时，主流检索模型 recall 在最难子集近乎为 0；即使 Gemini、GPT 这类强模型也只能维持约 50% 响应一致性。揭示语义匹配范式无法解决「跨 session 跨话题」的真实个性化需求。

INSIGHT社区搜索常面对的「用户历史与当前 query 表面无关但实际相关」场景被这个 benchmark 精确捕获——例如用户历史问烹饪、本次搜健康饮食。论文提示需要超越纯 embedding 相似度的相关性建模，可能要引入用户长期画像 + 当前意图的联合推理。落地启示：在长期个性化场景增加跨话题历史的训练样本，并用 LUCid 类难例评估线上模型对跨话题相关性的覆盖能力。

Chimaobi Okite, Anika Misra, Joyce Chai, Rada Mihalcea

Separable Expert Architecture: Toward Privacy-Preserving LLM Personalization via Composable Adapters and Deletable User Proxies

IIndependent

提出三层架构隔离用户数据与共享权重：基模型 + 领域 LoRA adapter + 可删除的用户代理（user proxy）。在 Phi-3.5-mini 与 Llama-3.1-8B 上验证：移除 proxy 后模型 KL 散度回到基线 0.21 nat、行为通过率 82–89%，且用户间数据泄漏极小。把机器遗忘从难解的权重编辑问题变成「删除用户文件」的确定性操作，并兼容 DP-SGD。

INSIGHT在 GDPR / 数据合规收紧的趋势下，「用户级删除权」对所有持久化用户表征的搜推系统都有实际意义。Separable Expert 思路（用户信息只进 proxy 不进共享权重）可以借鉴到 user embedding 平台：把「高频可变的个性化信号」放在可独立淘汰的 user proxy 里，「稳定的共性信号」留在共享 backbone。代价是路由 + proxy 加载的延迟，需要评估线上服务可承受性。

Chris Schneider, Philipp Schoenegger, Ben Bariach

A Gated Hybrid Contrastive Collaborative Filtering Recommendation

UUFBA

提出门控混合对比协同过滤：用自适应门控机制动态平衡协同 embedding 与基于评论的主题特征，再加对比学习对齐语义信号与协同信号，最后以 pairwise ranking 联合优化。Amazon Movies & TV、IMDb、Rotten Tomatoes 三个评论丰富的数据集上排序指标均超过同类 review-aware 推荐模型。

INSIGHT社区 UGC 上既有「用户-内容」行为信号也有「用户-内容」文本信号，二者强弱因物品冷启动情况差异巨大，固定权重融合不是最优。门控自适应思路简单且对推理成本友好：对一个交互少但评论丰富的内容，门控自动偏向语义；对热门内容偏向协同。可在召回粗排阶段试点，把门控输入接 user/item 上下文统计量。

Eduardo Ferreira da Silva et al.
