MTGR：美团外卖生成式推荐 Scaling Law 落地实践

美团外卖团队基于 HSTU 架构提出 MTGR (Meituan Generative Recommendation)，针对外卖排序场景的混合式生成推荐架构。保留交叉特征等全部传统信息进行建模，采用统一的 HSTU 同时编码用户行为序列与上下文。通过 Fused Cutlass-based HSTU kernel 优化，单算子性能相较 Triton 版本提升 2-3 倍。线上离线 CTCVR GAUC +2.88pp，外卖首页列表订单量 +1.22%，PV_CTR +1.31%，已于 2025 年 4 月底在外卖首页、频道页、小程序等核心场景完成全量上线。

GRAM: Generative Recommendation via Semantic-aware Multi-granular Late Fusion

GRAM 提出多粒度晚融合 (Multi-granular Late Fusion) 的生成式推荐方法，解决 RQ-VAE 类语义 ID 在表示能力与生成效率之间的折衷问题。将语义 ID 拆解为粗粒度（类目/品牌等抽象语义）和细粒度（具体属性）两个层级，在 decoder 末段进行晚融合，避免早期融合带来的信息纠缠。在 Amazon、MovieLens 等标准序列推荐基准上超越 TIGER 等 RQ-VAE 基线，Recall@10 / NDCG@10 提升 5-12%。

INSIGHT语义 ID 设计的"晚融合"思想是该方法的核心创新——粗细粒度信息在 decoder 后期才合并，使生成过程能在不同粒度上独立优化。对短文本/UGC 搜索的启示：一方面短文本本身缺乏长上下文，可借鉴多粒度表示来分别建模 query 的字面词汇 vs 语义意图；另一方面晚融合架构相对于把所有特征早期拼接更适合做迭代式优化。建议社区搜索的语义 ID/embedding tokenizer 设计参考 GRAM 的层级划分，分别学习"主题级"和"细节级"两套 token。

CRAB: Codebook Rebalancing for Bias Mitigation in Generative Recommendation

Walmart

CRAB 识别出生成式推荐中"不均衡 tokenization 会继承并进一步放大历史交互的流行偏置"这一关键问题：codebook 中常见 token 训练样本多、参数更新充分，导致冷门 item 难以生成。CRAB 通过两步处理：1) 拆分过度流行的 token 同时保留语义结构；2) 引入树状结构正则化器增强语义一致性。后处理 (post-hoc) 应用于已训练模型，无需重训。在真实数据集上显著提升整体推荐质量，特别是长尾物品。

INSIGHTCRAB 的核心洞察是把"流行偏置"问题从模型/损失层面下沉到 codebook 设计层面，这对生成式推荐架构很有借鉴意义：流行 item 占据高频 token 后，自回归生成会形成强偏置正反馈。关键工程价值在于"后处理"——可以直接应用到线上已训练的 GR 模型而无需重训，部署成本极低。社区搜索同样存在帖子/作者长尾分布问题，可借鉴 codebook 重平衡思路改进语义索引：把热门作者/话题的 token 拆分为子簇，让冷门内容获得更多生成概率。

GPR: Towards a Generative Pre-trained One-Model Paradigm for Large-Scale Advertising Recommendation

GPR 提出"一模型"生成式预训练范式，用单个 decoder-only Transformer 统一广告推荐的召回、排序、创意选择三个阶段，取代传统多级级联架构。核心思路是借鉴 LLM 预训练 + SFT 模式，先在大规模日志上做生成式预训练学习用户/商品分布，再针对每个下游任务做小规模微调。在大型广告平台的生产 A/B 测试中相比传统多级方案带来显著收入提升，并大幅简化工程复杂度。

INSIGHTGPR 验证了"一模型范式"在工业广告/搜索系统的可行性，对搜推架构演进有方向性意义：1) 传统多级 (recall→pre-rank→rank) 累积误差可由统一生成模型消除；2) 共享预训练大幅降低维护多个独立模型的成本；3) 一模型对长尾物品/新广告主的冷启动天然更友好。但要警惕：生成式 one-model 的时延仍是瓶颈，社区搜索可分阶段实施——先用一模型替代 pre-rank 验证收益，再考虑端到端化。

BehaveGPT: A Foundation Model for Large-scale User Behavior Modeling

BehaveGPT 是面向用户行为预测的基础模型，使用 Transformer 架构在海量用户行为日志上做生成式预训练。预训练任务包括 next-behavior 预测和长期行为序列生成；下游通过微调或 prompt 实现"下一个行为预测""长期行为生成""跨域行为迁移"等多任务能力。模型设计借鉴了 LLM 的自回归范式，但 token 词表是行为类型而非自然语言词。

INSIGHTBehaveGPT 把"用户行为序列"做成像语言模型那样可预训练、可迁移的基础模型，意义在于打破了传统推荐"每个场景训一个模型"的孤岛模式。对社区搜索的启示：搜索行为（query → click → dwell → 转化）天然是一种行为序列，可以构建社区行为基础模型，下游同时支持搜索排序、推荐、用户画像、新用户冷启动。但跨域迁移收益还需验证，且基础模型对算力/数据量要求较高，建议先在大业务上做单域预训练再考虑通用化。

Reasoning Over Space: Enabling Geographic Reasoning for LLM-Based Generative Next POI Recommendation

本文针对 LLM 生成式 POI 推荐缺乏空间推理能力的问题，提出在 tokenize POI 序列时显式注入空间上下文，并在推理阶段加入"地理可信度"过滤模块，对生成的 POI 候选按地理合理性重排。基于 Foursquare、Gowalla 等基准，相比纯 LLM 生成的 baseline 在 Top-K 命中率上有显著提升。

INSIGHT论文把"领域专属推理（地理）"作为 LLM 生成式推荐的可插拔模块，方法论可推广到任何带显式领域知识的推荐场景。对社区搜索的启示：UGC 帖子有"话题层级""作者社群""时间衰减"等隐含约束，可参考本文设计专属可信度模块过滤 LLM 生成的候选。但要注意，过度的后处理会削弱生成模型本身的多样性优势，建议作为弱过滤而非强约束。
