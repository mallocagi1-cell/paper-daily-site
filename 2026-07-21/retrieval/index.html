LLM-Based Re-Ranking for Real Estate Search

面向房产平台多轮对话中难以用固定筛选项表达的复杂意图，论文用 LLM 对首阶段召回结果重排，并构建含 96 万个 query-item 对、经人工校验的离线数据集。生产 A/B 测试显示点击率提升 5.3%，预约看房量提升 4.8%，证明对话上下文可直接改善商业搜索排序。

KEY INSIGHT · 对业务意味着什么对社区短文本搜索，最值得借鉴的是把完整会话意图留在重排层处理，而非强行压缩成若干结构化过滤条件。可先保留现有召回系统，再用蒸馏或小型 LLM 重排 Top-K，并以点击、后续转化和人工相关性共同验证；该方案已有线上实验，落地风险显著低于重建全链路。

Efficient and Effective In-place Graph-based Vector Index Updates

论文针对动态语料下图向量索引频繁增删会降低吞吐与召回的问题，提出原地更新系统 Yi，以 tasklet 执行引擎、异步缓冲管理器和向量文件系统协同更新。在 8 亿向量数据集上，Yi 的更新吞吐提高 1.75 倍、并发检索吞吐提高 1.8 倍，峰值内存仅为对比系统的 73%。

INSIGHT社区内容持续新增和删除，离线重建向量索引会形成明显的新鲜度缺口；Yi 表明将更新拆成细粒度任务并异步合并，可以同时守住吞吐、内存和检索质量。工程团队可优先审视索引更新路径的批次合并、缓存阻塞与文件布局，再决定是否引入同类原地更新架构。

Haotian Liu, Yujun He, Bo Tang

Scientific Claim-Source Retrieval Revisited: A Comparative Study of Style Transfer and Re-Ranking

论文在 CheckThat! 2026 上比较稀疏、稠密检索、四种风格迁移及三类重排方法，解决社媒表述与原始论文语言风格不一致造成的召回困难。英文翻译与出版元数据均带来增益，基于验证推理的重排进一步超过纯语义相似度，最终取得 MRR@5 0.758。

INSIGHTUGC 搜索中的口语、转述与源内容风格错位，不能只靠更大的 embedding 模型解决；查询规范化、元数据匹配和可验证重排应作为互补信号。尤其对事实性强的帖子，可先生成标准化查询，再让重排器判断候选是否真正支持主张，而不是只判断文字是否相似。

Tobias Schreieder, Harsh Khandelwal, Yu-Ling Zhong, Michael Färber

UTRAG at SemEval-2026 Task 8: History-Aware Query Rewriting and LoRA-Finetuned Generation for Multi-Turn RAG

UTRAG 将历史感知查询改写与 LoRA 微调生成器串成多轮 RAG 流程，分别优化检索与回答忠实度。系统在三个子任务上取得 nDCG@5 0.4855、生成调和均值 0.6554 和端到端得分 0.5159；分析还指出，对话越长，历史筛选和查询表述的累积误差越明显。

INSIGHT多轮社区搜索不能简单拼接全部历史，否则无关上下文会造成 query drift。更稳妥的做法是显式选择与当前轮相关的历史片段，再生成独立可检索查询，并分别监控改写质量与召回质量；UTRAG 的结果也提醒团队按对话轮数分桶评估，避免平均指标掩盖长会话退化。

Ke Zhou, Yi-Shan Lin

Multi-Faceted Self-Consistent Preference Alignment for Query Rewriting in Conversational Search

论文认为会话查询改写若只优化文本本身，会与后续召回和回答目标脱节，因此从改写、段落检索、响应生成三个维度构造自一致偏好数据，并用前缀引导的多维 DPO 训练 MSPA-CQR。作者报告该方法在域内与域外场景均有效，但摘要未披露具体增幅。

INSIGHT查询改写的训练标签不应只看语义相似度，还要纳入检索命中和最终回答效用。社区搜索可从日志中构造三类偏好对：是否保留原意、是否提高相关内容召回、是否帮助下游回答或点击，并通过多目标偏好优化减少“改写更流畅但检索更差”的失败模式。

Zhiyu Cao, Peifeng Li, Qiaoming Zhu

JCT at SemEval-2026 Task 8: Resource-Efficient Multi-Turn RAG via Nano-LLM Rewriting and Hybrid Reranking

JCT 用 1.5B 参数 Qwen 负责多轮查询改写，再并行执行 Qdrant 混合检索和 Cross-Encoder 重排，强调低资源条件下的模块化实现。开发集可回答查询的 nDCG@5 为 0.1991，盲测为 0.1744；虽然落后于 20B 模型方案，但给出了域偏移和检索漏斗的误差分析。

INSIGHT该结果说明查询理解不必默认依赖超大模型：1.5B 改写器加混合召回和交叉编码重排，就能形成成本清晰的基线。实践中应先把每层候选数量、召回损失和重排增益单独观测；若盲测下降明显，应优先处理域偏移与未充分说明的短 query，而不是盲目放大模型。

Tal Farhan, Chaya Liebeskind

LLMs Encode Relevance as a Layer-Wise Cross-Lingual Signal

论文在 TREC DL20 与 MIRACL 上，用 UMBRELA 式提示驱动 4–9B 指令模型，并从每层最后一个 token 的残差流训练线性探针预测 query-document 相关性。中后层信号最强，部分模型的探针达到或超过生成式判断，并更好保持人工标注下的系统排序；跨语言迁移可行但弱于同语种。

INSIGHTLLM 的内部相关性表征可能优于它最终生成的分数或标签，说明重排器不必局限于解码输出。可尝试从中后层激活训练轻量探针，降低生成延迟并改善稳定性；多语言社区场景则应分别校准语种，因为跨语言信号虽能迁移，却仍存在明显性能损失。

Pietro Bernardelle, Samaneh Mohtadi, Stefano Civelli, Joel Mackenzie, Gianluca Demartini

What Do Chinese-Language Generative Search Engines Cite and Surface? A Large-Scale Empirical Study

研究覆盖 4 个中文生成式搜索平台的 8 个 Web/App 界面、614 个查询和每组合 3 次重复，从 214119 条原始记录清洗出 160860 条引用。仅 8.3% 的引用池品牌最终进入回答，时效查询的引用半衰期约 39 天，且同平台 App 与 Web 的来源集合存在系统差异。

INSIGHT生成式搜索中的“被召回”不等于“被展示”，内容适配度、跨来源出现次数和语义角色比单一质量分更重要。社区平台评估 AI 搜索时，应把召回、引用、答案曝光拆成三级漏斗，并按端形态分别监测；热点查询还需要更积极的新鲜度策略，因为有效引用半衰期只有约 39 天。

Tao Zhen, Yue Liu, Gege Zhang, Yixuan Niu

Adaptive Retrieval Strategies for Biomedical Question Answering

论文反对用单一检索流程处理所有问题类型，按 yes/no、事实、列表和摘要问题动态选择查询理解、文档检索、重排、知识图谱、聚类及证据聚合策略。在 BioASQ 上，问题类型感知流程改善了证据相关性与答案质量；摘要未给出具体提升数字，因此证据强度仍需结合正文判断。

INSIGHT社区搜索同样存在导航型、事实型、探索型和总结型意图，固定 Top-K 与固定融合权重往往浪费算力或漏掉证据。可先训练轻量意图路由器，再针对精确问答使用窄召回和强重排，针对探索问题扩大证据覆盖并聚类去重，从而把成本投入到真正需要的环节。

大模型应用：从粗排到大模型生成：交叉熵、余弦重排序的全流程实践.97

Alibaba

文章以“粗排→交叉熵或余弦精排→重排序→大模型生成”梳理检索系统，将百万级候选先低成本收缩至千级，再筛到 Top-K 后交给大模型润色和个性化。流程对工程入门较实用，但文中“排序决定 80% 检索质量”等说法没有可核验实验，不能当作效果结论。

INSIGHT这篇行业实践的价值在于明确分层职责：召回负责覆盖、精排负责相关性、重排负责局部顺序与多样性，大模型不应替代前面的检索质量控制。社区搜索团队可据此检查各层离线指标和延迟预算，但模型选型与阈值必须用自有日志验证，避免照搬缺少实验支撑的经验比例。
