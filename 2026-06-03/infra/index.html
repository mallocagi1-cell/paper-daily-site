An Industrial-Scale Sequential Recommender for LinkedIn Feed Ranking

LinkedIn 用 transformer 序列排序模型 Feed SR 替换原有的 DCNv2 排序器，重点不在模型结构本身，而在如何在 12 亿用户规模下满足严格的生产时延约束。论文披露了建模选择、训练技巧和 serving 优化三方面工程细节，并对比了其他序列模型和 LLM-based 排序架构落地的取舍。Feed SR 已承载 LinkedIn Feed 大部分线上流量超过三个月，在线 A/B 相比原生产模型带来 +2.10% 停留时长、+3.52% 点赞/评论/转发。

Self-Conditioned Positional HNSW for Overlap-Aware Retrieval in Chunked-Document RAG Systems

RAG 把文档切成有重叠的 chunk 后用 HNSW 做近邻检索，重叠虽能改善边界覆盖，却带来一个常见故障：top-k 经常返回相邻 chunk，重复证据、挤占 prompt 预算。SCP-HNSW 给 chunk embedding 追加一个低维位置编码，用两遍 query 流程估计并施加 query 相关的文档位置先验，再用一个可审计的 minimum-index-gap 选择器构造最终上下文。该方法不改动 HNSW 的图构建与遍历，属于轻量级旁路改造。论文还附带了 770 条评论的文本证据审计和 70 例 OCR 审计。

INSIGHT这是针对 chunk 重叠导致检索冗余的轻量补丁，值得社区搜索的 RAG/长文召回链路借鉴。它不动 HNSW 索引本身，只在 embedding 上拼位置码、在选择阶段加最小间隔约束，工程改造成本极低。但论文的实验偏弱——没有给召回率、冗余下降比例或时延数字，只有评论质量审计（574/770 评分 3/5、OCR 清晰截图通过率 95% 降到手写模糊 45%），证据强度不足，落地前需自己补检索指标的 A/B。

Nataraj Agaram Sundar, Tejas Morabia

Cost and Accuracy of Long-Term Memory in Distributed Multi-Agent Systems Based on Large Language Models

现有长期记忆 (LTM) 框架的评测多由框架方自己发布，只看 token 用量和时延，很少算系统级成本。本文搭了一个可复现的云-边仿真测试床，在 LoCoMo 基准上对 mem0、Graphiti、cognee 三个 VC 投资的框架，以及 RAG 和 full-context 基线，测量准确率、时延、CPU 时间、峰值内存、磁盘 I/O 和网络用量。结论：mem0/RAG/full-context 准确率 77–81%，Graphiti/cognee 因检索不完整只有 55–56%；RAG 以 8.4 倍更低的总拥有成本 (TCO) 达到第一梯队准确率，与 mem0 同为 Pareto 前沿上的非支配方案。

INSIGHT一份难得的第三方、独立可复现的记忆/检索框架横评，结论对选型很直接：在 LoCoMo 上 RAG 用 8.4 倍更低的成本打平了 mem0 的准确率，决定准确率的是压缩精度而非上下文体量。对要给搜索/Agent 加长期记忆的团队，这说明先别急着上重型记忆框架——朴素 RAG 在成本-准确率 Pareto 前沿上往往就够。边-云约束下向量检索只增加 4–5% 时延，带宽抖动几乎不影响检索质量。

Benedict Wolff, Jacopo Bennati

04 3.55

Differentially Private Datastore Generation for Retrieval-Augmented Inference

端侧检索增强推理需要在不泄露个体隐私的前提下发布和共享 datastore。本文提出一个基于哈希的概率生成框架：用局部敏感哈希 (LSH) 把高维数据分桶，对每个桶累计的投票加校准过的差分隐私 (DP) 噪声，生成跨类别的概率分布，从而可发布满足 DP 保证的 datastore。在 7 个数据集（类别数 2–14）上，ε=5 时发布的 DP datastore 平均只损失 2.6% 准确率，并把成员推断攻击的成功率压到 53.60%（接近随机的 50%）。

INSIGHT把 LSH 分桶 + 校准 DP 噪声组合成可发布的 key-value datastore，适用于任何需要安全发布检索库的管线。对社区搜索这类强 UGC 隐私敏感场景有参考价值：当要把用户产生的检索语料对外共享或跨团队复用时，ε=5、2.6% 准确率损失换来成员推断攻击降到 53.6% 是可接受的代价。方法与具体检索模型解耦，可叠加在现有向量库之上，而不必重训 embedding 模型。

Abdelrahman Abouelenein, Marwan Torki

DOT-MoE: Differentiable Optimal Transport for MoEfication

从零训 MoE 不稳定且算力昂贵，把预训练的稠密模型转成稀疏 MoE（MoEfication）是替代路线，但现有方法多用启发式神经元聚类或随机切分来划分 FFN 专家。DOT-MoE 把稠密层分解建模成可微的最优传输 (Optimal Transport) 问题，用可微的 Sinkhorn-Knopp 迭代来强制满足专家容量约束下的神经元分配，替代静态启发式。论文报告转换后可在仅激活 50% 参数的情况下保留约 90% 的稠密模型性能，已被 ICML 2026 接收。

INSIGHTMoEfication 的核心痛点是 FFN 神经元怎么分到各专家，过去靠聚类或随机切分，DOT-MoE 把它形式化成带容量约束的最优传输并用 Sinkhorn 求可微解，分配更均衡。对想降低 LLM 推理成本的团队，这条路比从头训 MoE 省钱：拿现成稠密模型转稀疏，50% 激活参数保 90% 性能。适合社区搜索中用 LLM 做 query 改写/重排时压缩推理开销，但论文给出的下游任务数字偏少，落地前要在自己的检索任务上验证精度回退。

Udbhav Bamba, Arnav Chavan, Aryamaan Thakur, Steve Teig, Deepak Gupta

SplitZip: Ultra Fast Lossless KV Compression for Disaggregated LLM Serving

prefill-decode 分离 (disaggregation) 部署下，prefill worker 产生的 KV cache 必须跨物理机传给 decode worker，这个传输在大规模、长输入和 agentic 负载下是显著瓶颈。已有无损编码器要么针对离线权重压缩、要么跑在 CPU、要么用变长编码压缩太慢跟不上 KV 产生速度。SplitZip 是 GPU 友好的无损 KV 传输压缩器，利用 KV 激活浮点指数的冗余，对高频指数用定长码、稀有指数走稀疏 escape 流，离线标定 top-16 指数码本避免在线直方图。实测 BF16 压缩吞吐 613.3 GB/s、解压 2181.8 GB/s，端到端 KV 传输加速最高 1.32×、TTFT 加速 1.30×、请求吞吐提升 1.23×。

INSIGHT针对 PD 分离架构中被忽视的 KV 跨机传输瓶颈做无损压缩，且关键在于 GPU 上编解码都要快——变长编码解压快但压缩跟不上 KV 产生，SplitZip 用定长指数码 + 稀疏 escape 修正解决。位运算无损、不改模型执行、可插入现有 serving 框架，工程接入成本低。对自建 LLM 推理集群（如用 LLM 做搜索重排）有参考：当 prefill/decode 分离部署时，KV 传输用 SplitZip 可换来 1.3× 量级的 TTFT 改善，对长 query/长文档重排尤其有用。

Yipin Guo, Siddharth Joshi
