Discrimination Is Generation: Unifying Ranking and Retrieval from a Tokenizer Perspective

该文针对生成式推荐的核心瓶颈——语义 ID（SID）由独立的检索目标训练、与个性化信号解耦，导致生成式检索长期落后于判别式排序。作者提出 DIG（Discrimination Is Generation），核心观点是“排序在 item 空间求 argmax、检索在 token 空间求 argmax，二者是同一问题的不同粒度”，据此把 tokenizer 嵌入判别式排序模型做端到端训练，使排序器自然成为检索模型，一次训练同时产出排序与检索两个模型，并围绕 feature assignment taxonomy 组织 SID 构建，让个性化信号直接参与 tokenizer 学习。

KEY INSIGHT · 对业务意味着什么把语义 ID 的学习与排序目标统一，是缩小生成式检索与判别式排序差距的关键设计。对搜推系统的启示：召回（token 空间生成）与精排（item 空间判别）可共享一套 tokenizer 与训练流程，省去单独训练 RQ-VAE 的解耦损耗；“一次训练两个模型”降低维护成本，适合需要召回+排序共用语义空间的统一架构。

HARNESS-LM: A Three-Phase Training Recipe for Harnessing SLMs in Sponsored Search Retrieval

Microsoft

面向赞助搜索召回，大型 SLM 检索器（如 Qwen3-Embedding-4B/8B）在公开榜单上很强但难以在高吞吐、低延迟线上部署。作者提出 HARNESS-LM 三阶段训练：(1) 微调十亿参数级 SLM 作为高性能 teacher 检索器；(2) 用 L2 目标对齐 query 表示，把知识蒸馏进 <600M 参数的 student 编码器；(3) 用对比学习做最终精炼。论文系统比较了关键设计选择，给出在延迟敏感环境下兼顾检索质量与成本的方案。

INSIGHT把大 SLM 检索能力压缩到 sub-600M 学生模型，是 LLM 检索器落地搜索的现实路径。对社区搜索召回的启示：蒸馏中“L2 对齐 query 表示 + 对比精炼”两段式优于单纯对比蒸馏；先用大模型刷质量上界、再蒸馏到可上线规模，可在不大幅牺牲 nDCG 的前提下满足 QPS/延迟约束。

Vipul Gupta, Shikhar Mohan, Lakshya Kumar, Pranjal Chitale, Nikit Begwani, Amit Singh, Manik Varma

TubiFM: Unified Item, Carousel, and Search Ranking for Streaming Discovery

Tubi📖 深度解读 · 7 分钟 →

个性化分发常为 item 排序、carousel 排序、搜索分别训练模型，但这些任务来自同一用户旅程、信号互补。作者提出 “user story”：把用户跨场景历史（属性、会话、带场景与 carousel 上下文的观看事件、搜索事件）序列化为单一 token 序列，将预训练语言 token 与领域事件 token 交织，使异构推荐与搜索任务都表达为共享语法上的 prompted next-token 预测。TubiFM 基于 Llama 3.2 1B 在 user story 上训练，通过 prompt 完成 item/carousel/搜索排序。

INSIGHT用“用户故事”把多场景行为统一成语言序列，是 LLM-as-recommender 做多任务统一建模的可落地范式。对搜推平台的启示：搜索 query（即便无点击命中）也能作为意图 token 注入用户序列，帮助区分重看、续看与新发现；1B 级 Llama 即可承载统一排序，避免为每个场景维护独立模型。

A Hierarchical Quantized Tokenization Framework for Task-Adaptive Graph Representation Learning

语言与视觉基础模型受益于统一的离散 token 接口，但图数据的 tokenizer 难以同时跨尺度捕捉节点语义与关系结构——以往基于量化的图 tokenizer 多用固定规则组合 RVQ 层级、只关注单一结构视图，限制跨任务迁移。作者提出带 task-conditioned routing 与双视图 token 流的分层量化 tokenization：产出多尺度编码与两条同步序列（保留节点级信息的 local 流、概括连通性的 diffusion-style 多跳流），轻量 router 学习任务相关的 RVQ 深度混合。

INSIGHT任务自适应地选择量化粒度、并行保留局部与多跳结构，是图上“语义 ID”接口的关键改进。对生成式搜推的启示：推荐里的 user-item 图同样需要可复用离散 token，双视图（局部协同+多跳传播）思路可迁移到图增强的语义 ID 构建；task-conditioned routing 提示不同下游任务应使用不同 SID 粒度，而非固定码本深度。

Yang Xiang, Li Fan, Chenke Yin, Lutz Oettershagen, Chengtao Ji
