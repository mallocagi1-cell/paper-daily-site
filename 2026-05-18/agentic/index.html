Towards Self-Evolving Agentic Literature Retrieval

针对纯关键词检索可靠但召回受限、而前沿 LLM 直接生成检索结果昂贵且幻觉率高（实测幻觉率 37.79%）的矛盾，提出 PaSaMaster：把文献检索拆成「意图分析 → 检索 → 排序」的可迭代闭环，并坚持用排序而非生成来产出结果以杜绝来源幻觉，同时把规划与检索分离以控成本。在覆盖 38 个学科的 PaSaMaster Benchmark 上，F1 较传统关键词检索提升 15.6 倍，较 GPT-5.2 提升 30% 而仅用其 1% 算力，且来源幻觉为零。

Self-Distilled Agentic Reinforcement Learning

MeituanZhejiang University

针对 RL 训练多轮 agent 时轨迹级奖励监督过于稀疏、而直接叠加 On-Policy Self-Distillation (OPSD) 会因多轮不稳定而崩溃的问题，提出 SDAR：把 OPSD 当作一个「门控辅助目标」，RL (GRPO) 仍是主干优化；将脱离梯度的 token 级信号映射为 sigmoid 门，对 teacher 认可的正差距 token 加强蒸馏、对 teacher 否定项软性衰减。在 Qwen2.5/Qwen3 上、ALFWorld/WebShop/Search-QA 三个任务，相比 GRPO 分别提升 +9.4%、+10.2%（WebShop-Acc）、+7.0%（Search-QA），且避免了朴素 GRPO+OPSD 的训练不稳定。

INSIGHT对搜索 agent 训练的启示：轨迹级 reward（只看最终答对没答对）对多轮检索-推理的中间步骤几乎没有指导，SDAR 用一个带门控的 token 级蒸馏信号补足密集监督，且通过 sigmoid 门区分对待「teacher 认可」与「teacher 否定」——后者可能源于检索/技能利用不完美，不能一味惩罚。Search-QA +7.0% 说明该框架能直接迁移到检索问答型 agent；门控设计是把辅助蒸馏稳定接入 RL 主干的关键工程技巧。

Is Grep All You Need? How Agent Harnesses Reshape Agentic Search

实证研究 agentic 搜索中「检索策略」与「agent harness」如何交互。在 LongMemEval 的 116 题样本上，对比 grep（词法）与 vector（向量）检索，跨自研 harness（Chronos）与厂商原生 CLI（Claude Code、Codex、Gemini CLI），并分别测 inline 工具结果与 file-based 工具结果；第二组实验逐步混入无关历史对话以测鲁棒性。核心结论：grep 在各 harness 上普遍比向量检索准确率更高，但整体得分强依赖于具体用哪个 harness 与工具调用风格。

INSIGHT对社区搜索做 agent 化的直接警示：在 agent 内部，简单的词法检索（grep/BM25 类）往往比向量检索更准、更鲁棒，向量召回的语义优势在 agent 多轮上下文里并不一定兑现。更重要的发现是 harness 与工具调用风格（inline vs file-based 结果）对端到端效果的影响可能大于检索算法本身——这意味着搭建搜索 agent 时，工具结果如何回灌进上下文、用哪套 harness，应当作为一等超参来调，而非默认上向量库。

Sahil Sen, Akhil Kasturi, Elias Lumer, Anmol Gulati, Vamse Kumar Subbiah

EvolveMem: Self-Evolving Memory Architecture via AutoResearch for LLM Agents

UUNC

现有 agent 记忆系统只让存储内容演化，而打分函数、融合策略、答案生成策略在部署后被冻结。EvolveMem 主张存储知识与检索机制必须协同演化：把完整检索配置暴露成一个结构化动作空间，由 LLM 诊断模块读取每题失败日志、定位根因、提出针对性配置调整；一个带「回退-止损」与「停滞-探索」保护的 meta-analyzer 应用这些调整，形成对自身架构做迭代研究的 AutoResearch 闭环。从极简 baseline 起步可自主收敛，并发现原动作空间外的全新配置维度。LoCoMo 相对最强 baseline +25.7%，MemBench +18.9%。

INSIGHT把「检索配置（召回打分、融合权重、答案策略）」本身当成可被 LLM 自动调优的动作空间，是对推荐/搜索系统调参范式的一个新视角：传统做法是人工网格搜索打分公式与融合权重，这里改成由 LLM 读失败案例做根因诊断并自动改配置，且带自动回退防退化。对长期会话型社区搜索（跨多轮记忆用户偏好），检索机制需随数据漂移而自适应；+25.7% 的相对提升说明「配置随用随调」比固定打分函数有显著收益。

Jiaqi Liu, Xinyu Ye, Peng Xia, Zeyu Zheng, Cihang Xie, Mingyu Ding, Huaxiu Yao

HAGE: Harnessing Agentic Memory via RL-Driven Weighted Graph Evolution

针对 agent 记忆检索常被当成静态查找（扁平向量检索或固定二元关系图），无法刻画关系的强度、置信度与 query 相关性的问题，提出 HAGE：把记忆组织为共享节点上的「关系特定加权多关系图」，每条边带可训练的关系特征向量；给定 query，LLM 分类器识别关系意图，路由网络动态调制对应边嵌入维度，遍历得分由语义相似度与 query 条件化边表征学习组合而成。再用 RL 框架以下游任务联合优化路由行为与边表征。实验显示长程推理准确率提升且取得更优的准确率-效率折衷。

INSIGHT把检索从「向量 top-k 查找」重构为「query 条件化的图遍历」，且用 RL 以下游任务端到端优化路由与边权——这对需要多跳关联的社区搜索（如「找与某帖观点相反的高赞回答」）有借鉴价值：关系强度/置信度不再靠人工规则而是可训练的边特征，路由网络按 query 意图动态加权不同关系视图，能软性抑制噪声关联。代价是需要 RL 训练与图基础设施，落地门槛高于纯向量召回，适合关系结构明确、对多跳质量敏感的场景。

Orchard: An Open-Source Agentic Modeling Framework

Microsoft

针对开源 agent 研究受限于「高性能系统多依赖闭源代码/模型/服务，而多数开源框架只做编排与评测、不做可扩展 agent 训练」的基建缺口，微软提出开源框架 Orchard。核心是 Orchard Env——一个轻量环境服务，提供可复用的沙箱生命周期原语，覆盖多任务域、多 agent harness 与多流水线阶段；其上构建三种 agentic 训练配方。Orchard-SWE 在 SWE-bench Verified 上 SFT 64.3%、SFT+RL 67.5%；Orchard-GUI 在 WebVoyager/Online-Mind2Web/DeepShop 分别 74.1/67.0/64.0%；Orchard-Claw 在 Claw-Eval pass@3 59.6%。

INSIGHT对要自建搜索/推荐 agent 训练管线的团队，价值在于把「沙箱环境生命周期管理」抽象成可复用原语并跨 harness、跨训练阶段统一——这正是工业界做 RL agent 训练时最容易重复造轮子、最难复现的部分。开源 + SFT 到 SFT+RL 的完整配方（SWE-bench 64.3%→67.5% 印证 RL 增量）提供了可直接借鉴的工程骨架；GUI/WebVoyager 类配方与 web 搜索 agent 的环境交互范式高度相通，可作为搭建检索 agent 训练环境的起点。

Learning to Build the Environment: Self-Evolving Reasoning RL via Verifiable Environment Synthesis

Tencent

提出一种自改进 RL 新范式：模型不再生成题目或轨迹去模仿，而是构造训练自己的「环境」——在零数据推理 RL 下，把自改进从数据生成循环改成环境构造循环，每个产物是可复用的可执行对象（采样实例、计算参考答案、给响应打分）。关键前提是环境必须具备稳定的「解-验非对称性」：模型能写一次 oracle、却无法在新实例上靠自然语言可靠执行。落地为 EvoEnv（单策略生成器-求解器），从十个种子合成 Python 环境，经分阶段校验/语义自审/相对难度校准/新颖性检查后才纳入。在已经很强的 Qwen3-4B-Thinking 上，固定公开数据与固定手工环境的 RLVR 反而拉低均值，EvoEnv 把均值从 72.4 提到 74.8（相对 +3.3%）。

INSIGHT核心洞察是「持续自改进的关键不是造更多合成数据，而是让模型学会构造难度结构性地超出自身能力的世界」——解-验非对称（写代码 oracle 易、自然语言执行难）保证奖励在学习者变强后仍有信息量、且无法靠刷验证器作弊。对搜索/推荐而言短期落地性弱（偏推理 RL 研究），但其「奖励信号要相对学习者保持难度」的思想，对设计搜索 agent 的训练课程与防 reward hacking 有方法论参考价值。

Yucheng Shi, Zhenwen Liang, Kishan Panaganti, Dian Yu, Wenhao Yu, Haitao Mi

WildClawBench: A Benchmark for Real-World, Long-Horizon Agent Evaluation

Shanghai AI Lab

指出现有 agent benchmark 多依赖合成沙箱、短程任务、mock 服务 API 与只看最终答案，无法回答 agent 能否在真实部署运行时完成长程工作。WildClawBench 提供 60 个人工撰写、双语、多模态任务，覆盖六大主题，每任务平均约 8 分钟、20+ 次工具调用，运行在装有真实 CLI agent harness（OpenClaw/Claude Code/Codex/Hermes）的可复现 Docker 容器中，用真实工具而非 mock；评分混合规则校验、环境副作用审计与 LLM/VLM 语义判定。19 个前沿模型中，最佳 Claude Opus 4.7 在 OpenClaw 下仅 62.2%，其余均低于 60%，仅切换 harness 就能使单一模型波动达 18 分。

INSIGHT对评估搜索/推荐 agent 的方法论启示：在 mock 服务+最终答案校验下测出来的指标会系统性高估真实部署表现；应转向「真实运行时 + 副作用审计 + 语义判定」的混合评分。最反直觉的发现是「仅换 harness 就让同一模型波动 18 分」——这与第 3 篇 Grep 论文的结论相互印证：harness/工具调用方式是 agent 系统的一等变量。落地前应在与生产同构的运行时上做长程评测，而非仅看短程 benchmark。

PREPING: Building Agent Memory without Tasks

KAIST

无论 agent 记忆来自离线示范还是线上交互，初到新环境时都面临无任务经验的冷启动缺口。本文研究「任务前记忆构造」：能否在观察到任何目标任务前，仅靠自生成的合成练习构建程序性记忆。直接合成不够——不控制练什么/存什么会让合成任务冗余、不可行、无信息量。提出 Preping：核心是 proposer memory（塑造未来练习的结构化控制状态），Proposer 据此生成合成任务、Solver 执行、Validator 判定哪些轨迹可入库并反馈以指导后续提议。在 AppWorld/BFCL v3/MCP-Universe 上大幅超越无记忆基线、与离线/线上经验构建的强 playbook 方法相当，且部署成本在 AppWorld 低 2.99 倍、BFCL v3 低 2.23 倍。

INSIGHT对搜索/推荐 agent 上线的实际价值：新场景/新品类冷启动时没有线上交互日志可学，Preping 证明可以「先用受控自生成练习预热程序性记忆」，达到接近线上经验积累的效果，且部署成本低 2~3 倍。关键设计是 proposer memory 这个控制状态——它决定下一步该练什么、存什么，避免合成任务发散；这套「Proposer-Solver-Validator」闭环可迁移到搜索 agent 的冷启动预训练，降低对真实流量回放的依赖。

Yumin Choi, Sangwoo Park, Minki Kang, Jinheon Baek, Sung Ju Hwang

Further Notes on Our Recent Research on AI Delegation and Long-Horizon Reliability

Microsoft

微软研究院探讨：当把多步修改重要文档/表格/代码/结构化文件的工作委托给 AI 且步骤间几乎无人监督时，语义内容能否被准确保留。方法是用「变换-逆变换链式任务」评估扩展委托工作流中语义是否被准确保留，并用领域特定语义解析判定实质改动而非表面格式差异。关键发现：前沿模型在扩展工作流中会引入稀疏但后果严重的错误，20 次委托迭代后产物保真度下降约 19–34%；而 Python 工作流鲁棒性显著更好，平均退化不到 1%。作者强调这是诊断委托模式的工具，而非衡量模型整体能力。

INSIGHT对长程搜索/推荐 agent 落地的工程警示：多步委托链中误差会复利累积，20 步后语义保真可掉 19–34%——这正是 agentic 搜索做多轮检索-改写-合成时最隐蔽的风险来源。最具操作性的结论是「用结构化/可执行表示（Python）做中间状态，退化可压到 <1%」，与第 2 篇 PyRAG「用可执行代码表示多跳推理」的思路一致：把 agent 的中间状态显式化、可执行、可校验，并辅以验证回路与编排，是抑制长程误差累积的关键工程手段。

Philippe Laban, Tobias Schnabel, Jennifer Neville
