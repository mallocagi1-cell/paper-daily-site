Clarify-Then-Search: A Clarification Benchmark for Deep Search with End-to-End Nugget Restoration

论文针对短 query 缺少时间、地点、范围等约束导致的检索漂移，提出 Clarify-Then-Search 基准。数据来自百度真实搜索日志，共 518 个“意图 query—欠明确 query”实例；系统让澄清器提出 1、2 或 3 个问题，再由重写器生成检索式，并用带来源标识的证据 nugget 评估端到端恢复效果。

EnSI-RAG: Entity-Structure-Indexed Retrieval-Augmented Generation for Long-Document Question Answering

UIUC

EnSI-RAG 认为长文 RAG 的瓶颈不只是 chunk 长度，而是实体、关系和证据被切散后难以联合召回。它建立与 query 无关的实体中心索引，每条记录写成（实体、类型、语义类别、值）四元组，同时保留原文段落链接；查询时先取结构化检索句柄，再让 LLM 综合证据生成答案。

INSIGHT社区帖子、评论和问答天然包含作者、地点、事件、商品等实体，适合把“实体—属性—关系”作为补充召回通道。落地时应保留结构记录到原文的可追溯指针，并让关键词、向量和实体索引并行召回，再由排序模型融合，避免结构抽取错误直接替代原始文本证据。

Xuanyu Meng, Jiashuo Sun, Jash Rajesh Parekh, Jiawei Han

RAG Deserves an Index: Why Ingest-Time Compilation Beats Query-Time Interpretation

论文把生产 RAG 中每次查询都让模型重新解释原始语料、随后丢弃中间结果的问题类比为数据库全表扫描，并提出 ingest-time semantic compilation。该方案在写入阶段增量维护 embedding 与带来源校验的 atomic claims，把语料语义编译成可查询底座，读取阶段直接利用已维护结构，减少重复推理。

INSIGHT对高频 UGC 搜索，昂贵的语义抽取应尽量前移到帖子入库、编辑和审核流程，而不是每次请求重复调用 LLM。可先为高曝光内容维护 claim、实体和多粒度 embedding，再用版本化增量更新；上线前必须监控索引新鲜度、覆盖率和错误传播，保留原文回退路径。

Kyle Wild, Yusuke Takahashi, Asako Uraki

Trustworthy RAG: An Evaluation Agent for Detecting Misinformation and Knowledge Poisoning in Generative AI Systems

论文指出“语义相关”不等于“事实可信”，恶意文档可通过 knowledge poisoning 诱导 RAG 输出定向错误信息。作者把 NLI 事实核验、五信号污染检测和 Trust Index（T=0.4F+0.35C+0.25(1-P)）组合成评估中间件；在 TruthfulQA 与 Llama 3.3 70B 上达到 91% 准确率、100% 精确率和 100% 指令注入召回率。

INSIGHTUGC 搜索不应只把点击或向量相似度当作相关性终点，尤其在问答、医疗和经验分享内容中要增加可信度信号。可将轻量 NLI、来源质量、冲突检测和污染分数放在重排后段，对高风险 query 触发人工审核或多源交叉验证；实体替换等隐蔽篡改仍需单独建设检测集。

Balkrishna Giri, Md Toufique Hasan, Jussi Rasku, Muhammad Waseem, Pekka Abrahamsson

Edge-Based Agentic Retrieval-Augmented Generation for Autonomous FHWA Bridge Inspection Compliance

BridgeGuard 将向量检索、NBI 结构化 SQL 查询和有状态 ReAct 规划环组合成可离线运行的合规检索系统，并用 section-aware chunking 保留法规层级。其分块完整率达到 94.2%，高于固定长度切分的 28.4%；系统在 Delaware 2023 年 874 座桥梁清单上评测，展示了受限网络环境下的多源检索路径。

INSIGHT这项工作对社区搜索的可迁移点是“检索工具分工”：语义召回处理自然语言，SQL 或倒排索引处理精确字段，规划器只负责选择下一步查询。对短文本 UGC，应让 Agent 仅在低置信度、多跳关系或需要结构过滤时介入，并用固定预算、超时和可回退的多阶段 pipeline 控制延迟。

Viraj Nishesh Darji, Hemaliben Rakeshkumar Darji

PhotoBench: Beyond Visual Matching Towards Personalized Intent-Driven Photo Retrieval

PhotoBench 认为真实个人相册检索不能只做图像相似度匹配，因为用户意图往往依赖时间连续性、社交关系和地点等上下文。论文构建来自真实相册的基准，把视觉语义、时空元数据、社会身份和事件轨迹统一到多源画像中，并合成面向生活经历的复杂检索 query，测试跨来源证据聚合能力。

INSIGHT社区内容搜索同样需要从“文本像不像”升级到“是否符合用户正在找的事件和关系”。可把作者、发布时间、地点、话题演化和评论上下文做成可解释的检索特征，再与文本 embedding 融合；评测集要加入跨帖、多时间段和隐式意图 query，避免离线 benchmark 过度简化真实需求。

Making Large Language Models Efficient Dense Retrievers

EffiR 系统分析 LLM 适配为 dense retriever 后的层冗余，发现 MLP 层比生成任务更容易剪枝，而 attention 对语义聚合仍关键。方法先做粗粒度深度裁剪，再做细粒度宽度裁剪，并配合 retrieval-specific fine-tuning；在多套 BEIR 数据集和不同 LLM backbone 上降低模型规模与推理成本，同时保持接近完整模型的检索效果。

INSIGHT对社区搜索，压缩重点不应平均施加到所有层，而应先测量 attention 与 MLP 对 nDCG、召回和长尾 query 的敏感度。可把 EffiR 式粗到细压缩放在蒸馏或量化之前，再用线上 query 分桶验证短 query、错别字和新话题是否退化，从而把大模型语义能力转化为可承受的服务成本。

Yibin Lei, Shwai He, Ang Li, Andrew Yates

KoViDoRe: Korean Visual Document Retrieval

KoViDoRe 针对韩文 PDF、报告等视觉文档缺少复杂版式和跨页证据评测的问题，发布覆盖表格、图形、多栏布局的检索基准。数据构建采用结构化解析、摘要式与上下文式合成 query、人工相关性映射三阶段流程，重点考察多页证据聚合，而不是只命中单页文本。

INSIGHTUGC 搜索的难点也常来自图片、表格、长评论和跨帖上下文，不能只用纯文本 benchmark 估计系统能力。实践上可按内容类型分别切分评测集，保留版式和跨文档链接，并把“召回到正确证据片段”的指标与最终点击、停留和答案可引用率一起看。

MetaRoCE: A New RDMA Transport Built for AI-Scale Ethernet

Meta

Meta 发布面向 AI 规模以太网的 MetaRoCE RDMA 传输协议，并同步开放规范、参考软件实现和合规测试。文章聚焦训练与 serving 集群中 GPU 间数据搬运的可靠性和效率；对搜索系统而言，它代表向量索引、批量重排和多模型服务共享网络时需要关注的底层传输能力，而非单一模型指标。

INSIGHT检索延迟优化不能只看 encoder 或 ANN 算法，跨节点的向量、候选和特征搬运同样会决定 P99。若 UGC 搜索采用多路召回和分布式重排，应把网络拥塞、尾延迟、重试和 GPU 利用率纳入 nDCG/CTR 实验的性能面板，并优先验证带宽提升是否真的转化为更多可排序候选。

How NVIDIA Groq 3 LPX Unlocks Ultrafast Interactivity at Long Context on NVIDIA Vera Rubin

NVIDIA

NVIDIA 介绍 Groq 3 LPX 作为 Vera Rubin 平台的交互式 AI 推理加速器，重点面向长上下文、多轮调用和低延迟服务。对检索链路的直接启示是：当 query 改写、重排或证据融合引入更长上下文时，系统需要把 token 处理能力、批处理方式和端到端尾延迟一起设计，而不是只比较离线相关性。

INSIGHT社区搜索可以把长上下文模型限制在低召回规模的重排、澄清或证据压缩阶段，并通过候选截断和动态 batch 控制成本。部署评估应同时记录首 token、每 token 延迟、GPU 显存和 P99；只有当模型带来的 nDCG/CTR 增益覆盖额外推理开销时，才值得扩大调用范围。
