From Noisy Traces to Root Causes: Structural Trajectory Analysis and Causal Extraction for Agent Optimization

STRACE 面向长程 LLM Agent 的失败诊断与策略优化，解决真实执行轨迹冗余、异质、包含大量无关步骤的问题。方法在批次层面挖掘失败模式、筛掉重复轨迹；在单条轨迹内构建文本依赖图做因果定位，保留真正导致失败的模块和证据。论文在 VeruSAGE-Bench 形式化验证任务上把人工专家设计 Agent 的成功率从 42.5% 提升到 58.5%，约 1.4 倍。

From Atomic Actions to Standard Operating Procedures: Iterative Tool Optimization for Self-Evolving LLM Agents

EvoSOP 针对工具型 LLM Agent 反复调用原子工具、重复发明多步流程的问题，提出把执行轨迹中的原子动作自动合成为可复用 SOP，并作为更高阶 callable tool 回写到工具集。框架包含构造、合并、评估、剪枝四个生命周期阶段，用迭代工具优化提升任务成功率并减少交互轮数。论文没有在摘要中披露具体百分点，但明确报告相对 baseline 的成功率提升和交互轮次下降。

INSIGHT这篇的核心启发是把高频搜索/审核/问答流程沉淀成动态工具，而不是永远让 Agent 逐步规划。对 UGC 社区搜索，可以把“query 改写→召回诊断→证据聚合→答案校验”等稳定链路封装成 SOP，既降低推理成本，也减少工具调用漂移和长链路失败。

03 3.95

How Search Quality Shapes RL Outcomes

EExa

Exa 从工程侧研究“搜索后端质量”如何影响 RL 搜索智能体训练，比较 Exa 与 Google/SERP baseline，关注 pass@k、轨迹多样性和 live-web 检索质量。文章报告多个任务上约 +3.50pp 到 +3.51pp 的改善信号，并指出不同搜索工具会改变 RL 后的概率质量集中方式。它不是传统论文，但直接回答了搜索 Agent 训练中常被忽略的变量：检索环境本身。

INSIGHT如果要训练社区搜索 Agent，不能只调 reward 和 policy，还要把搜索后端作为训练环境的一部分做 A/B。召回质量、实时性、摘要片段结构会影响 RL 学到的查询策略；建议在离线训练前固定可观测检索指标，并用多个后端或索引版本评估策略是否过拟合某个搜索工具。

A Roadmap for Agentic Recommender Systems

这篇综述把 Agentic Recommender Systems 从静态排序推进到“自主信息寻求”系统，提出按自治水平和三类范式组织：agent-assisted recommendation、agent-as-recommender、agent-as-user-simulator。论文系统梳理 profile、memory、tool use、workflow、optimization、evaluation，并在表格中比较 classical RS、LLM-based RS、Agentic RS 的 7 个维度，包括目标、主动性、上下文、交互、适应性、记忆、工具知识。

INSIGHT对搜索/推荐从业者的价值在于给“Agent 化推荐”划边界：不是把 LLM 接在排序后面，而是让系统能解释目标、拆任务、调用检索/排序/API、维护约束状态并迭代修正。社区搜索中的探索式查询、商品/内容发现和复杂约束推荐，都可按 LoA 分级逐步落地，避免一开始就做不可控全自治。

Behavior Leverage Imbalance in Multi-Teacher On-Policy Distillation

论文研究多教师 on-policy distillation 训练工具型语言模型时的行为偏移：一个教师偏工具调用、另一个教师偏直接回答，vanilla GKD 虽提升 tool-call recall，却会让模型过度调用工具。作者提出 behavior leverage imbalance，指出 <tool_call>、函数名等模式入口 token 对全局生成模式有过强控制，并用 Soft Clamp 动态压缩极端 token-level JS divergence。APIGen-MT 上 over-calling 从 13.7% 降到 9.0%，同时保持决策准确率；BFCL 多轮诊断中也减少工具循环和重复调用。

INSIGHT搜索 Agent 的线上成本和稳定性往往毁在“该搜不搜、该停不停”。这篇提示我们监控聚合 loss 不够，要盯住工具调用入口 token 和函数名等结构位置；训练 query 改写、检索调用、外部 API 调用模型时，可用类似 Soft Clamp 抑制过度检索，同时保留必要召回能力。

Jiabin Shen, Guang Chen, Chengjun Mao

阿里云百炼推出Agentic RAG服务，让AI的知识检索和回答更精准

Alibaba

阿里云百炼的 Agentic RAG 服务是近期产业实践，核心链路是意图理解、任务拆解、知识检索、结果验证闭环。系统内置 6 类检索工具：语义搜索、章节浏览、章节精读、页面浏览、SQL 执行、文件获取，并支持 15 个知识库联合检索；回答阶段通过 Agentic Generation 反复验证检索结果，并给出文档、段落、页码级来源。报道还提到保险、汽车、物流、零售等行业数万家企业使用百炼 RAG。

INSIGHT这类产品化方案说明 Agentic RAG 的工业重点已经从“多轮检索”扩展到可追溯、可配置、多知识库路由。UGC 搜索可以借鉴其工具分层：把帖子语义检索、评论页浏览、结构化 SQL、用户画像查询拆成不同工具，并要求最终答案带片段来源，降低复杂查询的幻觉风险。

ChatGPT is now a partner for your most ambitious work

OpenAI

OpenAI 发布 ChatGPT Work，把 ChatGPT 定义为可跨 apps、files、browser、desktop 执行动作的工作型 Agent，可把目标拆成较小步骤并持续数小时完成。文中披露 Codex 每周超过 500 万用户，其中超过 100 万用于非软件开发工作；内测案例包括 RingCentral 从支持 1 个产品经理扩展到约 50 个、NVIDIA 把会前 Excel 工作流中约 40% 的时间转给 Agent。

Infinite Worlds with Versatile Interactions

LingBot-World 2.0 面向交互式世界模型，提出无界交互时长、实时蒸馏、多样化动作事件和 agentic harness 四项升级。系统声称蒸馏后的实时版本可驱动 720p、60fps 视频流；agentic harness 中 pilot agent 规划并执行角色行为，director agent 随场景进展合成新的环境元素。虽然主题偏 embodied/world model，但“长时程交互 + 双 Agent 协作”的结构与复杂搜索 Agent 相通。

INSIGHT这篇提示 Agentic 系统可以把“规划者”和“环境生成/维护者”拆开，避免单模型同时承担行为决策和世界状态更新。对搜索场景，可以映射为 query planner 负责下一步信息需求，context director 负责维护候选证据、用户约束和会话状态，从而支持更长时程的探索式搜索。

Final Checkpoints Are Not Enough: Analyzing Latent Reasoning Faithfulness Along Training Trajectories

论文分析 latent reasoning 方法在训练过程中的 faithfulness，而不是只看最终 checkpoint。作者用可验证 counterfactual edit 和 latent reasoning step 的 noise-ablation activation patch，跟踪不同范式在多个保存 checkpoint 上的因果贡献变化。结果显示：输出层面最终可能同样不忠实，但训练轨迹不同；activation 层面 latent reasoning step 对最终答案的因果贡献会随训练衰减；且二选一答案和开放式解码的变化趋势不同。

INSIGHT对 Agent 搜索的启发是：中间推理轨迹“看起来合理”不等于因果有效，尤其在工具调用、检索链和答案生成分离训练时。评估时应加入轨迹级反事实编辑和关键步骤 ablation，而不是只在最终响应上做准确率或 LLM-as-judge；这有助于发现伪推理和不可解释的成功。

Hengyu Jin, Shu Yang, Di Wang
