Generalized Tensor Parallelism: Powering Trillion-Parameter LLM Training at 10+ EFLOP/s

训练到万亿参数的大模型时，常见并行方案总要在单卡显存和吞吐之间让步。数据并行会复制参数，张量并行和 FSDP 每个微批次都要通信，流水线并行又会让 GPU 在填满和排空时闲着。对线性层来说，这五种常见并行其实都是同一种广义张量并行 GTP 的特例，参数和激活都可以先切分，用时再一次收集回来。它把参数收集当成每次矩阵乘之前的可选预处理，而不是整块 Transformer 前的一步，因而能更早发出通信，又不过早占显存。在 12,288 张 GB300 上，内部两万亿参数的 MoE 模型达到 13.0 EFLOP/s。从 4,096 卡扩到这一规模时，弱扩展效率为 98%。实现已放进 Megatron-Core，还能在五百多张卡上跑长达一百万 token 的序列。

ModelLess: A Serverless System for Multi-Tier LLM Inference on Shared GPUs

AAnt Group

大模型推理平台常按产品固定占用 GPU，高峰过去后卡会闲着，别的任务却在等。ModelLess 把推理做成无服务器服务：空闲实例会缩到零，把权重量在主机内存里休眠，释放和唤醒只需数秒，而冷启动往往要四分钟以上。腾出来的 GPU 可以借给更低优先级的档次，并且按在线、任务和弹性各档约定，被抢占时可以丢掉什么。抢占会先停止接新请求，再持久地重新入队，然后才释放内存。回放 1,100 张 H20 上一周长尾在线模型的轨迹，在粗略延迟目标和单一空闲阈值下，约 38% 的 GPU 时间可以出借，这是恢复只需数秒时的理想上限。若冷启动要 240 秒，即便按服务调节阈值，也只剩 8%。

Ding Shi, Wei Wu, Jiayuan Chen, Chenghu Yang

LoomKV: Lossless KV Cache Compression from GPU Memory to SSD for LLM Serving

ECNUZZTE

服务引擎把 KV cache 从 GPU 卸到主机内存和 SSD，好让多轮和智能体请求复用前缀，但容量不够就会限制并发，有损压缩又可能改写输出。LoomKV 在不改引擎的前提下做无损压缩，按注意力头校准的两级三比特编码，能把 BF16 的 KV 压到原来体积的 0.71，并在九个模型上得到这一比例。写入分层存储时不必改原有的淘汰和预取，读回时直接解压进分散的 GPU 页。在 AgentX 上，碰到 LMCache 的 LRU 悬崖时，分层模式的有效吞吐是未压缩时的 2.7 到 3.6 倍。若原始容量已经装得下工作集，压缩带来的吞吐损失最多 2.2%，分层模式的输出还与未压缩完全一致。GPU 侧的池化模式则用融合解码内核原地读取更小的页，在工作集已经放下时保持与未压缩接近的排队和有效吞吐。

Wentao Zhu, Ziao Sheng, Peng Deng, Huiqi Hu, Xuan Zhou, Xing Wei, Zhuang Wang

FlashQLA: Efficient Context Parallelism for Gated DeltaNet

Zhejiang UniversityAlibaba

Gated DeltaNet 靠递推状态把计算做成线性，可块与块之间仍有顺序依赖。长上下文、小批量或单卡头并行不足时，上下文并行往往施展不开，边界状态的预处理尤其昂贵，甚至可占去前向时间的一半以上。FlashQLA 用感知衰减的准备降低这笔开销，并用 Dual CP 在不同并行级别之间共享摘要计算，再按负载自动选择并行配置。单卡上，前向比 Flash Linear Attention 加快 1.7 到 3.1 倍。反向最多加快 4.4 倍。在八张 GPU、上下文长达百万 token 时，Dual CP 的前向最高达到 FLA KCP 的 4.8 倍。自动选择在绝大多数推理和训练负载上都能落到接近最优的配置。真实模型里，多数注意力头的衰减窗口往往短于八千 token，这也让感知衰减的准备更有针对性。

Wavefront: Low-Rank Drafting with Parallel Causal Refinement for Speculative Decoding

University of OregonAmazon

推测解码让廉价起草器先提出 token，再由目标模型并行验证。并行块起草可以一次提出整块，却会丢掉块内 token 之间的依赖。再用串行修正头补回来时，这个头往往会改写大多数位置，昂贵的完整输出层多半只是在给种子。Wavefront 把完整输出层换成学出来的低秩底座，让修正头看到同一块里已起草的整个前缀，再用几次并行的 Jacobi 迭代解出结果。起草步数固定，因而可以在 vLLM 里收成一张 CUDA 图，并配上融合内核。在 Qwen3-8B 上，它在数学、代码、对话和智能体基准上的平均吞吐比 DFlash 高 23.6%，比 DSpark 高 10.7%。在长上下文提示上，相对 DFlash 的优势达到 28.9%，并发升高后这一优势仍然在。

Huy Huu Nguyen, Xin Huang

RankServe: Rank-Aware CPU-GPU Scheduling for Memory-Constrained MoE Serving

Stevens Institute of TechnologyNortheastern University

低秩压缩能缩小 MoE 的专家池，但不同专家留下的秩不一样，存储、传输和计算代价也不一样。只看热度和搬运成本，并不能决定在显存不够时该把谁留在 GPU 上。RankServe 按每个专家的秩和 token 负载，比较留在 GPU 上，与在 CPU 上算或先搬运再上 GPU，哪条路更便宜，再按每字节节省来排优先级。它根据近期路由更新驻留，未命中时也可按当前负载临时在 GPU 上算，而不写入缓存。可变秩运行时用分组矩阵乘执行不同秩的因子，不必先补齐到同一秩。在单机 CPU-GPU 上对照六套服务系统，各模型几何平均的 TTFT 是每项配置最快基线的 1.69 到 2.29 倍。同一比较里，TPOT 是 1.71 到 2.48 倍。

Hengyi Zhu, Zhendong Mi, Pu Zhao, Yanzhi Wang, Hao Wang, Shaoyi Huang

Shifter Quantization: Compact Representations for Native Integer Computation

Columbia University

按组量化能在低比特下保住精度，但分组后，标准整数矩阵乘往往无法一次覆盖整个点积，GPU 推理就不容易跑满。Shifter Quantization 通过补上并移位共享比特，重建出原生宽度的整数操作数，其变体 SHI 还能走 INT4 内核。在约四千 token 的预填充上，二比特的 SQ2 和 SHI2 吞吐达到 llama.cpp 中 Q2_K 检查点的 2.71 到 3.77 倍。它们还把 WikiText-2 的 KL 散度降低 6.6% 到 7.8%。质量按投影误差和 KL 衡量，速度则在解码和预填充里一起比较。四比特和八比特设定里，预填充吞吐和误差也优于相应的分组整数和在线 FP8 基线。这样既能保住低比特下的精度，又能让整数矩阵乘覆盖完整的点积，不再被分组把计算割裂开。

Yufeng Huang

VenusOCR2.0: Towards Efficient and Effective Document Parsing

Tencent

文档解析既要看清文字、表格和公式，又要跑得快，很大的通用视觉语言模型并不总占上风。新的识别器 VenusOCR2.0 把规模做到约十亿参数，用动态分辨率编码和空间 token 合并，再用紧凑的表格 token 缩短序列，减轻结构错误。为了减轻自回归解码瓶颈，它配上约六千七百万参数的并行起草模块 PTPv2，并保证与标准解码逐 token 一致。训练数据由一套有界的递归数据引擎提供，模型只负责找出弱点，监督则来自外部多专家共识和视觉校验。在 OmniDocBenchv1.6 上，总分达到 96.45，公式 CDM 为 98.57，高于体量更大的 Gemini-3-Pro 的 92.91。部署在单张 H20 和 vLLM 里，PTPv2 把单请求速度提高到 2.96 倍。批量请求的吞吐也有提升，且不会改写标准解码的结果。

Lei Li, Zheng Wei, Yi Yuan, Qingbin Liu, Jiang Bian, Zang Li

How to Run NVIDIA Cosmos 3 on Local AI Devices Using Hugging Face Diffusers

NVIDIA

在本地跑视频生成模型时，权重和中间结果常常超出 GPU 显存。NVIDIA Cosmos 3 Nano 可从文本、图像等输入生成视频，用来支持物理 AI 开发。这篇教程用 Hugging Face Diffusers，把大部分权重量在系统内存，需要时再搬到 GPU，从而在只有 12 GB 显存的消费级卡上也能生成，还可以试声音和其他输入类型。代价是系统内存和 PCIe 传输都会增加，也不能做到交互式延迟，更不会在推理时直接从磁盘读权重。在 RTX 5070 上，720p 文生视频用 BF16 单次跑完要 2,624.9 秒，峰值显存 9.94 GiB。还可以选用 FP8 检查点，进一步降低显存需求。更高显存的卡会更快，但这些测量是单次运行，并不能当成卡与卡之间的正式排名。

Accelerating Direct Sparse Solvers for Computational Engineering with NVIDIA cuDSS 1.0

NVIDIA

结构力学、流体和电路仿真都要解稀疏线性方程组。问题变大、精度变严之后，既要在 GPU 上加速，又不能丢掉生产仿真依赖的稳健性。NVIDIA cuDSS 1.0 成为可商用的 GPU 直接稀疏求解库。在真实的半导体和力学建模矩阵上，相比 Intel MKL，分析阶段的几何平均加速为 2.5 倍，数值分解为 5.9 倍，三角求解为 151 倍。混合内存模式把数据放在 GPU 显存和 CPU 内存之间调度，在大型 VLSI 例子上把最低设备内存需求平均降低约 30%，让过去需要多卡的问题有可能在单卡上解完。它还为对称不定系统提供更稳的选主元，并把符号分解放到 GPU 上加速。厂商可以把这套库直接用到商业仿真软件里。
