OmniEVIE: Evidence-Vector-Informed Embedding for Multi-modal Retrieval

多模态检索既要对付密集页面、细粒度实体，也要对付有顺序的视频和智能体工具。单向量会丢掉局部证据，cross-encoder 又要在线重读每个召回结果，未压缩的迟交互则大到难以服务。OmniEVIE 用约四十五亿参数的多向量模型，覆盖文本、图像、视觉文档、视频和工具，却共用一套压缩索引和三阶段检索。每条记录最多存放一百二十八个六十四维的 int8 向量，一百万条大约只占 8.82 GiB，并能为命中定位到页面区域或视频片段。在 MMEB-V3 的一百九十项任务上，完整序列得分 60.68，压缩索引仍有 60.06，几乎没有掉点。百万条语料上，单线程查询只要 54.2 毫秒。视频直接由帧编码，不必再经过解析模型。

LARF: Learning-aligned Reasoning Framework for Search Relevance

已录用 WSDM 2027TencentSouthwest University

AI 搜索要判断文档是否满足复杂、多维度的信息需求，直接用大模型做这件事并不容易。普通微调给不出领域里特有的判断理由，轨迹级强化学习又不一定能拉开相邻相关性等级之间的间隔，推理时再走思维链也往往太慢。LARF 先在多智能体引导的思维链样本上做冷启动微调，再用带间隔损失的判别式强化学习对准最终相关性标记，最后把教师蒸馏成只保留分类头的学生，推理时不必自回归生成。在约三十万条训练、一万六千条测试的人工标注网页相关性基准上，LARF-8B 的六类分类准确率提高 5.78 个百分点，NDCG 提高 5.05 个点。只走分类头的服务路径把推理延迟降低了 82.9%。

Tian Tang, Guo Chen, Reed Li, Hao Wang, Yu Lu, Haijin Liang, Haibo Shi

Teaching Time Without Losing General Retrieval: Adapting Multimodal Embeddings for Time-Sensitive Video Retrieval

University of TokyoNNational Institute of InformaticsUUniversity of Augsburg

文本搜视频时，多模态 embedding 模型擅长匹配场景描述，却不擅长匹配动作及其方向。已有做法用时间困难负例微调，能提高对时间敏感的检索，却会把通用检索打下去。新方法坚持用一个模型和每个片段一个向量，同时保住两方面。它发现片段和其倒放在视频 embedding 里往往靠得太近，于是沿两条文本 embedding 的差值方向把这条间隔拉开，并把 LoRA 只加在时间信息最集中的中间层。通用检索的 R@1 仍保持 58.4，把倒放拷贝放进候选库后，R@1 从 55.5 升到 63.2。这些 LoRA 参数只占全部权重的 0.15%，在多数时间敏感基准上已接近训练全部权重，也能用到未见过的基准和其他模型上。

Rainer Lienhart, Shin' Toya Oyama, ichi Satoh

SOARS: System One Assisted Reranking for Agentic Search

University of WaterlooThomson ReutersUniversity of Guelph

深度搜索智能体要反复检索和推理，证据是否相关会直接影响后面的答案，可全程调用重排器又会带来明显的延迟和费用。SOARS 不必额外训练，用一个反应更快的 System One 模型做校准过的相关性估计。每一步只调用一次，就能从长文档里抽出与问题有关的段落，并同时参考原始问题和智能体生成的子查询来重排候选。在 BrowseComp-Plus 和 WebShaper 上，它对六种大模型骨干都能提高答题准确率和证据召回，同时减少搜索次数、端到端延迟和推理费用。在 BrowseComp-Plus 上，GPT-5.4 Mini 的准确率从 73.9% 提高到 84.7%。搜索次数从 23 次降到 14 次。也就是说，深度搜索不必每一步都请昂贵的重排器，用校准过的快速估计就能把检索次数和费用压下去。

Amin Bigdeli, Liye Fu, Fattane Zarrinkalam, Joel Stremmel, Elizabeth Lingg

Efficient Video Retrieval Augmented Generation via Token Allocation

University of Illinois Urbana-Champaign

要理解长视频，就得找出相关证据，又不能让视觉语言模型处理过多 token。现有的视频检索增强生成多半只做选帧和压缩，却很少问多给一个 token 到底还值不值。Lembas 把这件事看成在共享预算下，给帧和字幕分配 token 的问题。它的关键观察是，同一条证据里，后来的 token 越来越不值钱，相似证据再拿到更多 token，价值还会继续下降。它把这两种衰减写进同一个目标，并用有收敛保证的迭代注水算法来求解。多轮对话里，还可以复用前面已经处理过的 token，并用模型注意力重新估计相关性，不必再额外计算。精度最多比现有最强基线高 7.2 个百分点。在多轮视频理解上，精度最多再高 1.5 个百分点，所用浮点运算可减少 1.7 到 17.3 倍。

Ayush Barik, Fan Lai, Francis Y. Yan

TableRouter: Query-Aware Evidence Construction for Long-Table Question Answering

大模型能对表格做推理，可表一长过上下文预算，只把相关行检索回来往往还不够。检索子集可能漏掉精确汇总所需的信息，即便证据齐全，模型也不一定用得好。TableRouter 不必额外训练，先分析问题再选路：一条路从全表算出与问题相关的统计量，另一条路检索相关行和列摘要，选好的上下文只调用一次冻结的大模型。在三个模型和三个长表基准的全部九组设定里，它都超过六种单次调用基线里最强的那一个。把算好的统计量明确提供给模型，准确率最多可再提高 40.0 个百分点，即便所有决定答案的行都已经在上下文里。在先前实验没用过的数据库长表上，配合 Qwen2.5-7B 的准确率达到 35.8%，最强外部基线只有 16.4%。

Anahita Bolourani, Xiaofeng Lin, Tung Sum Thomas Kwok, Guang Cheng

RELAY: Learning Compatible Representations One Encoder at a Time

Alibaba

图库要换新的文档编码器时，新旧嵌入会在回填过程中并存，查询向量往往不能同时对两种文档版本公平打分。RELAY 先让新的查询编码器带着一个学出来的投影，对着原来的图库训练，再把两者冻结，去训练新的文档编码器。同一次回填里，同一个查询向量就能给两个版本的文档打分。回填结束后，还可以做可选的查询精炼，丢掉投影并复用已经存好的文档向量。在 COCO 和 Flickr30K 的三次文搜图升级中，它对尚未更新的图库，把 Recall@1 提高了 8.66 到 10.23 个百分点。精炼之后，最终 Recall@1 与常规联合训练的差距不超过 0.97 个百分点。这说明升级编码器不必等整库重算完才能用。

Yu Wang, Chuan Qin, Qiang Zhang

Ask Again: Answer-List Instability in Generative Engines

生成式搜索引擎的可见度，取决于回答里出现了哪些实体、又以什么顺序出现。同一句问再问一遍，名单却可能换序，甚至换成另一批条目。在 60,000 次回答里，同一提示有 32% 的时候会点出不同的第一条，即便两次列出的条目相同，何者居首也可能不一致。第一条本身就是一个独立的测量目标。七八次重复之后，往往能看出一个明显领先者，可这正是品牌和来源监测常用的预算；真正接近的领先者，大约只有一半时候能确定。即便问到 25 次，接近的领先者也只有 60% 的时候能被认定。引擎与引擎之间的差异，比同一引擎内部更大。可见度报告应当分别写出哪些条目出现过、各自多久排第一，并带上不确定性。

Björn Busch-Geertsema, David Antony Selby, Sebastian Vollmer

Data Auctions for Retrieval Augmented Generation

已录用 NeurIPS 2026

检索增强生成要向买家出售数据时，一份数据对买方的价值会随着能覆盖更多预期查询的相关样本而上升。若每条样本只能独家卖给一个买家，福利最大化即使只有两个竞拍者也已经是 NP-hard。作者给出一种多项式时间算法，能在任意多个竞拍者时达到 (1-1/e) 的近似比，可这个高效分配本身并不能保证激励相容。关键补丁是事后烧掉一部分数据：在保住同一近似比的同时，让机制变成激励相容。它还可以借助虚拟估值，把同一近似保证转到收益最大化。在合成数据以及真实的图像和文本数据集上，这套做法也比常见的组合拍卖基线更管用。

Minbiao Han, Seyed A. Esmaeili, Michael Albert, Haifeng Xu

No pipeline, no second copy: Querying Amazon S3 from Elasticsearch with ES|QL

Elastic

要把已经躺在对象存储里的历史日志或表格拿来检索，传统做法往往先做数据管道，再在集群里存一份副本，既贵也慢。Elasticsearch 的 ES|QL Data Federation 可以把 Amazon S3 桶登记成数据源，用和查索引相同的 FROM 句法直接查询其中的 Parquet、CSV、TSV 和 NDJSON 文件，而不必把数据拷进集群。模式来自文件本身，因而也不必先建摄取管道或映射。过滤和列选择会下推到 Parquet 读取器，查询只从 S3 读取需要的列。联合身份认证让 AWS 凭证不必写进 Elasticsearch。热索引和已经放在对象存储里的冷数据可以在同一次查询里一起扫。该功能目前仍是技术预览，适合先做探索，而不是把所有生产检索都搬过去。
