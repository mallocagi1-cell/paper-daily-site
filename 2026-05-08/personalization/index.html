RecGPT-Mobile: On-Device Large Language Models for User Intent Understanding in Taobao Feed Recommendation

针对淘宝信息流推荐中云端 LLM 推理成本高、用户意图变化快的痛点，提出 RecGPT-Mobile：把 Qwen3-0.6B-Quant 通过 LoRA 微调加 8-bit 量化部署到手机端，用本地行为数据动态生成下一步检索 query。训练数据按 60% 行为驱动 + 20% 共购 + 15% LLM 增广 + 5% 人工标注混合。在淘宝四个 feed 场景千万级 A/B 实验中，CTR 平均 +1.8%、支付转化 +2.7%、GMV +2.5%，购物车页 GMV 提升达 +2.9%。

Beyond Static Best-of-N: Bayesian List-wise Alignment for LLM-based Recommendation

USTCZJU📖 深度解读 · 9 分钟 →

现有 LLM4Rec 多用 token 级目标，难以直接优化 NDCG、Fairness 等列表级不可微指标；推理时 Best-of-N 虽能优化但成本极高。BLADE 用贝叶斯框架动态融合历史先验与当前 rollout 证据：F̂(r)=(N_ref^<r + τ·N_batch^<r)/(M+τ·G)，最优 τ≈0.3。在 Amazon-CDs/Steam/Goodreads 上 NDCG@5 较 BoN 对齐基线提升 5.1–23.1%，单次推理 44.56s vs N=4 BoN 的 178.24s，且在 Fairness/Diversity 上达到 Pareto 占优。

INSIGHT把 BoN 静态参考分布换成贝叶斯自演化目标，解决了「静态参考无法区分超出经验范围的候选」与「策略变好后梯度消失」两大对齐顽疾。社区搜索/推荐的 list-wise 公平性、多样性、相关性混合目标无法用 token-level loss 直接优化的场景，可借鉴该 CDF 估计器：不需要在线 BoN，offline 训练一次即可。τ 控制先验稳定性 vs 在线适应，是后续多目标推荐对齐工作的关键超参。

Ruijun Chen, Chongming Gao, Jiawei Chen, Weiqin Yang, Xiangnan He

Rethinking Convolutional Networks for Attribute-Aware Sequential Recommendation

UUniversity of Hildesheim

针对自注意力序列推荐计算/显存复杂度 O(n²)，难以建模长用户历史的问题，提出 ConvRec：用 strided 卷积层级下采样替代 self-attention，首层 kernel=2，后续层 kernel=5/7，配合两个可学习残差权重 α₁, α₂（初始 0.5）。在 Amazon Fashion/Men/Games/Beauty 四个数据集上对比 SASRec、BERT4Rec：Beauty HR@10 从 0.485 → 0.629（+29.7%），Fashion NDCG@10 从 0.245 → 0.469（+91%），Men HR@10 +55.7%，且具备线性复杂度。

INSIGHT在 attention 主导的序列推荐研究风潮下，重新论证「卷积 + 层级下采样」对捕捉局部+长程序列模式的有效性，并显著优于 SASRec/BERT4Rec。对 UGC 社区/短视频长行为序列建模具有直接借鉴意义：当用户历史动辄上千条互动时，线性复杂度+多尺度卷积比稀疏 attention 更易工程化。可作为社区搜索 query session、阅读历史等长序列建模的稳健基线。

Shereen Elsayed, Ngoc Son Le, Ahmed Rashed, Lars Schmidt-Thieme

CapsID: Soft-Routed Variable-Length Semantic IDs for Generative Recommendation

📖 深度解读 · 9 分钟 →

生成式推荐的瓶颈在于 Semantic ID tokenizer：传统 RVQ 在每层用硬最近邻分配会在簇边界处丢失多语义并把早期错误传染到后续 token。CAPSID 用胶囊路由替代硬 RVQ：每层物品概率路由到多个语义胶囊，残差由路由重建更新而非单一 winning code，置信度足够时变长 SID 自然终止；并辅以 SemanticBPE 把高频 SID 子序列合并为可复用 subword。在 Amazon Beauty/Sports/Toys 与 35M 工业目录上 Recall@10 平均 +9.6%，推理延迟仅为 COBRA 风格稀疏-密集系统的 51%。

INSIGHT把生成式推荐的「tokenizer 才是瓶颈」论点用胶囊路由具体化解决：软路由+变长 SID 同时缓解了「硬量化语义塌陷」与「定长 SID 浪费 token」两个问题，且不需要额外 dense vector 拼接，保留生成接口的简洁。对正在尝试 HSTU/TIGER 路线的搜推团队，CAPSID 提供了一个低成本的 tokenizer 升级路径——尤其对长尾物品和多面语义（如社区帖子）的 SID 表征更友好。

Wenzhuo Cheng, Menghang Gong, Qixin Guo, Hang Zheng, Zhaobin Yang, Jianguo Lou, Zhengwei Zheng

Interests Burn-down Diffusion Process for Personalized Collaborative Filtering

PKU

传统扩散 CF 方法用高斯噪声破坏用户交互向量，与协同过滤的稀疏离散本质不匹配。StageCF 提出 interests burn-down 扩散过程：用个性化二项采样 X_u(t) ~ Binomial(X_u(0), e^{-F_u(t)})，其中 [F_u(t)]_i = t/(1 + γ·[G̃_I r_u]_i) 通过物品 Gram 矩阵注入协同信号，反向 burn-up 过程生成推荐。在 Gowalla/Yelp2018/Amazon-Book 上 Recall@20 较最佳基线（含 LightGCN、MultVAE、DiffRec、FlowCF）分别提升 4.70%/5.51%/14.18%；NDCG@20 提升 4.33%/4.40%/11.26%。

INSIGHT把扩散过程从「高斯加噪→去噪」重新设计为「兴趣随时间二项衰减→反向恢复」，对推荐场景的离散稀疏交互更自然，并把协同信号嵌入到衰减率 F_u(t) 中，是扩散式生成推荐少数从根上重新建模噪声分布的工作。对工业 CF 场景，关键启示是：当现成的 DDPM 框架表现不佳时，应当根据数据分布性质重新设计扩散核（如二项、泊松），而不是只调神经网络。Amazon-Book 长尾场景 +14% 提升意味着对低频物品的恢复尤其有效。

Yifang Qin, Zhaobin Li, Arisa Watanabe, Wei Ju, Zhiping Xiao, Ming Zhang

One Pool, Two Caches: Adaptive HBM Partitioning for Accelerating Generative Recommender Serving

HKBU

生成式推荐 (GR) 推理时 embedding 热缓存 (EMB) 与 KV cache 在 GPU HBM 中直接竞争，最优 EMB:KV 比例随负载漂移可达 0.35，被孤立优化的现有系统损失 20–30% 时延。HELM 用三层 PPO 控制器（冻结基策略 + 在线残差适配器 + 突发感知恢复）联合管理 HBM 分配与请求路由，决策延迟仅 32μs，与离线最优比例偏差 0.024–0.029。32 节点 A100 集群三类负载（稳态/趋势漂移/突发）下，P99 时延较静态策略降 24–38%，SLO 满足率 93.5–99.6%。

INSIGHT把 GR serving 的内存调度从「双缓存独立优化」升维到「联合分配 + 路由」并以 RL 实时控制，是生成式推荐进入工业部署阶段后必然要解决的资源调度问题。对正在落地 HSTU/MTGR/OneRec 的团队，HELM 的工程价值很高：在线 H2D 重填会冲击 P99，需要 burst-aware 控制器在突发时回退到保守策略；32μs 决策延迟说明 PPO 控制器完全可放在 critical path。可借鉴的设计原则：冻结基策略保稳定，在线 residual adapter 学增量，突发恢复模块兜底。

Wenjun Yu, Shuguang Han, Amelie Chi Zhou
