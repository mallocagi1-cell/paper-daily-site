CapsID: Soft-Routed Variable-Length Semantic IDs for Generative Recommendation

针对生成式推荐中 RQ 残差量化 tokenizer 的两个核心瓶颈——“硬最近邻路由”造成的语义崩塌和早期错误向后续 SID 位的传播，CapsID 将 RQ 的硬路由替换为基于胶囊网络的软路由：每一层物品按概率路由到多个语义胶囊，残差按加权重建更新，并在胶囊置信度收敛时提前终止生成变长 SID，从而避免“附加 dense 向量”这类双表示带来的推理膨胀。在多个公开数据集与变长 SID 基线上，CapsID 在保持生成接口简洁的前提下取得更优 Recall@K 与 NDCG。

One Pool, Two Caches: Adaptive HBM Partitioning for Accelerating Generative Recommender Serving (HELM)

生成式推荐 (GR) 在线推理面临 EMB 热缓存与 KV 缓存争抢 GPU HBM 的问题，二者最优分配比可在不同负载下偏移高达 0.35，孤立优化各损失 20–30% 时延。HELM 提出运行时联合管理 HBM 和请求路由：由三层 PPO 控制器（冷启动基策略 + 在线残差 adapter + 突发恢复控制器）做 32μs 决策延迟的内存重分配，并通过分批预取与请求路由避免 H2D 流量打到关键路径触发 P99 SLO 违例。生产规模实验显示 P99 时延降低 ~25%，HBM 利用率显著提升。

INSIGHTGR 上线最大的隐藏成本不是模型本身，而是“EMB 与 KV 双缓存”在 HBM 上的资源博弈。HELM 把这个分配问题建模成 RL 控制问题并解耦了“快策略 + 慢恢复”的双时间尺度，是搜推 serving 工程少见的“OS 级”创新。对自研生成式推荐栈的团队，可借鉴：(1) 不要把 EMB 缓存与 KV 缓存视为静态切分；(2) 决策器要做到 μs 级才能跟上请求 burst；(3) 把 H2D refill 流量挪出关键路径是保 SLO 的关键。

Rank-GRPO: Training LLM-based Conversational Recommender Systems with Reinforcement Learning

ConvRec-R1 提出端到端训练 LLM-based 会话推荐器的两阶段框架，并引入 Rank-GRPO——ranking 感知的 group relative policy optimization 变体。它把多目标对齐 (catalog 内、用户偏好、列表序) 联合纳入 RL 目标，缓解 LLM 直接生成推荐时常见的“目录外物品 (out-of-catalog)”问题，并改善生成列表末端 ranking 质量退化。在公开 ConvRec 基准上比 SFT、DPO、标准 GRPO 在 Catalog Hit Rate、NDCG 上均有显著提升，且降低了出 catalog 比例。

INSIGHT把会话推荐看作“在受限物品空间下的列表生成 RL 任务”是一个清晰的范式：奖励函数同时编码 (1) catalog membership、(2) 偏好对齐、(3) 列表序敏感的 ranking 质量。对工业搜推的启示：当 LLM 直接生成 item id 时，必须在 RL 阶段显式惩罚 out-of-catalog；GRPO 的 group 相对优势天然适合排序任务，比 token-level reward shaping 更稳。社区搜索的 conversational query rewrite 也可借鉴此类 ranking-aware GRPO，把改写质量与下游召回 NDCG 联合训练。

UniVer: A Unified Perspective for Multi-step and Multi-draft Speculative Decoding

Speculative Decoding 通过 draft-then-verify 加速 LLM 解码，已有方法把 multi-draft 与 multi-step 验证拆开处理 (扁平 OT / 单 token rejection)，难以利用 candidate tree 中“水平分支 + 垂直依赖”的耦合。UniVer 提出把树形 verification 视作 conditional Optimal Transport 问题：用 prefix 接受概率作为动态缩放因子主动指导 horizontal draft 选择，统一 multi-step 和 multi-draft 范式。在多种 draft 模型与 token tree 设置下，UniVer 较 EAGLE-2、SpecInfer 等基线在 throughput 与接受率上均有显著提升。

INSIGHT对正在或将来上线“生成式排序 / 生成式检索”的团队，UniVer 给出一个可复用的解码加速思路：(1) 自回归 next-item / next-SID 解码本质就是带树形 candidate 的生成，可直接套用 multi-step + multi-draft 的统一 OT 框架；(2) prefix 接受概率作为缩放因子，能让搜推中“高概率前缀对应高概率后续 token”的归纳偏置变成显式收益；(3) 短文本社区搜索的 query rewrite / 生成式相关性这类“候选树短但分支宽”的场景，与 UniVer 的 multi-draft 主战场高度契合。

OpenAI: Testing ads in ChatGPT

OpenAI

OpenAI 公开宣布在 ChatGPT 内开始测试广告，并明确产品原则：广告与“答案独立”分离、保留清晰标识、强化隐私保护与用户控制 (例如可关闭广告)，目的是支撑 ChatGPT 免费版的可持续运营。这是首次主流生成式搜索/对话产品系统披露其广告体系的产品化原则，对生成式搜索/推荐的产品形态、相关性-收益平衡、广告可解释性都是关键信号。

INSIGHT生成式搜索的“答案 vs. 广告”是和传统搜索 SERP 完全不同的产品命题：传统搜索是“多结果上下并列”，生成式回答是“单一权威答复”。OpenAI 给出的“答案独立 + 清晰标识 + 用户控制”三原则可以直接迁移到社区搜索/推荐的生成式答复场景：当我们用 LLM 生成答案/卡片摘要时，广告/商业内容必须与有机内容在 ranking、可解释性、用户控制三个维度上完全解耦，否则会迅速摧毁用户信任。
