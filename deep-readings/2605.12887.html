EcoGEO: Trajectory-Aware Evidence Ecosystems for Web-Enabled LLM Search Agents

对生成式搜索而言，影响因素已经从「单页 SEO」迁移到「轨迹级证据生态」——Agent 经过哪些页面、链接结构如何、证据如何在路径上分布共同决定了生成答案。对于社区搜索/推荐场景，意味着帖子/评论需要构建可被 Agent 沿链路串联的证据网（互引、互链、互证），而不是单条孤立优化；这也提示 UGC 搜索系统需要重新设计 query-trajectory-evidence 三方耦合的排序与去偏机制。

1. 问题与动机

随着 GPT-5.1 这类具备网页浏览能力的 LLM Agent 接管真实搜索场景，传统 SEO/GEO 的优化对象已经从「单个落地页」迁移为「Agent 在多步访问中的整条浏览轨迹」。已有 Generative Engine Optimization (GEO) 研究（如 C-SEO、E-GEO、AutoGEO）的核心假设依然是单页面：把目标内容塞进单文档里，希望它在 1 次召回里被采纳。但 Agent 实际上会做最多 5 次 search + 5 次 crawl 这样的多步交互——issuance、follow-link、reformulate、聚合证据——单页优化的 lever 与之并不匹配。论文用一个简单的对照实验定量描述这种 gap：在 E-GEO 数据集上，单页基线 final recommendation rate 仅 59.0%，且 internal-link crawl 几乎为 0，意味着 Agent 在浏览中根本「走不进来」单页系统设计的影响范围。

由此作者把 GEO 重写为 ecosystem-level influence 问题，研究 page content、page-to-page 结构、轨迹经过点位三者如何协同放大 Agent 端的被推荐概率，并构造受控环境严格验证这一新设定的可优化性。

2. 方法详解

作者提出 TRACE（Trajectory-Aware Coordinated Evidence Ecosystem），核心做法是为每个目标产品构造一张「证据图」：

  • 一个 navigation entry page v₀：表面伪装为「评估指南」/「选购对比」等中立 hub，而非赤裸宣传的产品页。它的关键作用是创造下一步动作的 affordance——给 Agent 一个明确的「下一跳」选择列表。
  • 一个由 6 个 role-specialized support pages 组成的 V_s 集合：official、review、expert、news、forum、social。每个角色对应一种 Agent 在多步检索中倾向消化的证据风格。

TRACE 的两层协调机制：(i) Attribute consistency——目标产品在所有 page 上保留一致的「身份属性」（型号、参数、关键卖点），让 Agent 在多源比对时认得是同一个对象、不会因细节漂移触发自我否定；(ii) Internal cross-referencing——review 引官方规格、expert 引行业数据、forum 引 review 评论，编织出 Agent 可沿链路展开的「证据网」。

测试环境是 "9+1" controlled exposure：合成的目标结果被插入到真实 Google Search API 9 条结果的第 5 位；对目标后的 follow-up 查询，TRACE 的 ecosystem 页面按语义相似度替换第 9 位。Agent 采用 GPT-5.1，预算最多 5 次 query + 5 次 crawl。基线包括纯单页、C-SEO、E-GEO、AutoGEO，所有方法共享同一搜索预算与暴露协议，保证「优化对象」是唯一变量。

3. 核心技术贡献

  1. 重新定义优化对象：从 page-level 的内容补写跨到 ecosystem-level 的轨迹环境构造。这一抽象使得「结构」和「连接」第一次成为一阶 lever；过往 GEO 几乎只动 page content。
  1. Navigation entry + role-specialized support 的双层设计：通过 ablation 证明 navigation page 贡献最大——在 SafeSearch 上 internal-link crawl 从 0% 提升到 29.7%。这说明 Agent 跳转行为是个稀缺资源，谁能提供更便利的 affordance 谁就能截走更多浏览。
  1. OPR-Bench 数据集：3,124 个 query-product pair (SafeSearch 64 + E-Commerce 121 + E-GEO 2,939)，用 fictional product 避免真实产品 leak 与伦理风险，是这类研究的方法论贡献——保证实验可复现、可对照。
  1. 可分离的指标体系：除了 final recommendation rate，还监控 Initial Target-Result Crawl、Target-Specific Second Search、Internal-Link Crawl 三项轨迹指标，允许把「为什么 TRACE 涨」拆解到具体行为层面。

4. 实验结果分析

最终推荐率（vs. 最强 page-level 基线）：

数据集TRACE最强基线绝对涨幅
SafeSearch67.2%35.9%+31.3
E-Commerce71.9%56.2%+15.7
E-GEO73.9%59.0%+14.9

轨迹指标（E-GEO）：

  • Initial Target-Result Crawl: 48.9% (TRACE) vs 27.0% (single-page)
  • Target-Specific Second Search: 21.9% vs 11.0%
  • Internal-Link Crawl: 20.4% (TRACE 独有，基线为 0)

Ablation（强制初次抓取，剥离暴露因素）：

  • Uncoordinated multi-page → coordinated：SafeSearch 75.0% → 82.8%；E-Commerce 81.8% → 87.6%。证明多页协调本身就能加分。
  • Coordinated → TRACE（加 navigation page）：SafeSearch 82.8% → 89.1%；E-Commerce 87.6% → 93.4%；同时 internal-link crawl 跃升至 29.7% / 25.6%。说明 navigation page 的影响主要来自「给 Agent 主动跳转的入口」，而不是单纯内容更多。

值得关注的反直觉点是：E-Commerce 在最强 page-level 基线下已能拿到 56.2%，TRACE 涨 15.7 个点；SafeSearch 单页基线只有 35.9%、TRACE 涨 31.3 点——越是难影响的高门槛 query，ecosystem-level lever 越突出。这暗示 page-level GEO 已临近天花板，未来增益空间几乎都在结构层。

5. 局限与未来方向

作者明确指出三类局限：

  1. 全部使用虚构产品 + 受控环境，没有覆盖真实排名波动、Organic discovery、时效衰减等动态因素；
  2. 仅研究了一类 evidence ecosystem 结构（navigation + 6 角色 support），support page 数量、多样性、链接密度的影响尚未系统消融；
  3. 出于伦理考虑没有在公开 web 部署，所有评测都在合成环境完成，方法的真实环境鲁棒性未知。

需要补充观察的是：实验 Agent 只用了 GPT-5.1，未横跨 reasoning/non-reasoning 模型，也没考察国内 Agent（如基于 Qwen、DeepSeek 的浏览 Agent）的行为差异；Agent 改预算（如 10+10）下 TRACE 的边际收益是否衰减也未做。

6. 工业实践意义

对搜索/推荐侧团队，本文最直接的两条 takeaway：

  1. 「Agent-friendly site structure」开始成为流量获取的新 surface：传统 SEO 关注关键词与单页可读性，未来 Agent 优化的核心是为 LLM Agent 的多步行为铺出可走的路——hub 页 + 角色化 support + 互相引用。对内容平台/电商/UGC 社区，这意味着内容运营从「单帖优化」迁移到「话题生态构建」。
  1. 召回/排序系统要重新定义"target"：当 Agent 是真正的消费者时，"被点击/被采纳"的最小单位不再是一条结果，而是一组互联的结果簇。对社区搜索来说，应当考虑把"同主题、互相引用"的多个帖子打包成一个 cluster 候选，rerank 阶段直接评估 cluster-level 的轨迹友好度，而不是 doc-level 的独立得分。

部署层面，TRACE 的方法不需要训练任何新模型（all training-free），只是改 site map + page template，但前提是站点本身允许批量改造页面与互链结构——对老旧 CMS 是工程量大于算法的事。另一个隐含成本是：navigation entry page 必须看起来"中立"，过度自我推销会触发 Agent 端的反垃圾/反 prompt-injection 启发式（GPT-5.1 已经具备），所以内容写作上是一门"避免被识破"的工艺，工业部署需配合 Agent-side 行为监控来动态调整。

最后注意：本文方法在伦理上接近 prompt injection / SEO grey-hat 边界，企业实际采用前需要法务与 trust&safety 评估，避免触发平台反作弊系统或合规问题。
