Stratified Sparse Attention: Reducing the Sparse-to-Dense Gap at Extreme Sparsity

长上下文解码时，每生成一个 token 都要把整个 KV cache 从 HBM 读一遍，注意力成本随上下文线性增长。稀疏注意力只读其中一小部分，但在 50 倍稀疏这种激进设置下，现有方法离稠密注意力还差得远：Llama-3.1-8B 在 RULER-HARD 32K 上，稠密注意力得 88.76，PQCache 风格的 top-k 只有 72.51。这篇论文提出分层稀疏注意力 SSA（Stratified Sparse Attention）：高分 token 确定性地保留，剩下的长尾按代理分数做重要性采样，再用纳入概率修正权重。同样 50 倍稀疏，Llama-3.1-8B 的分数提到 83.67；在 Qwen3.5-9B 的 AIME 2025 上，SSA 得 59.8，PQ 只有 36.7。配合优化过的 CUDA kernel，SSA 在 1M 上下文时的解码注意力比 FlashInfer 快 2.96 倍。

1. 问题：top-k 丢掉了尾部，均匀采样浪费了预算

稀疏注意力的预算 k 怎么分配，现有方法有三条路。确定性检索（Quest、PQCache，以及做 top-p 的 Tactic）用代理分数挑出分数最高的 token；注意力集中时很有效，但注意力分布弥散或长尾时，集合之外的质量全部丢掉，代理分数稍有偏差、真正重要的 token 落在边界之外时更是如此。纯采样（MagicPig）用 LSH 近似采样加重要性校正，覆盖更广，但在小预算下方差大。混合方法（vAttention）保留 top-k，再对剩下的 token 做均匀采样，比前两者都好，但激进稀疏时和稠密注意力的差距仍然明显。

作者的预实验指出了均匀采样的问题：残余注意力质量的分布非常不均匀，均匀采样把同样多的预算花在几乎没有贡献的 token 上。图 1 显示，按分数做重要性采样，相对 L2​ 误差始终低于均匀采样。

2. 方法：先分层，再采样，最后修正

先回顾一下重要性采样版本的稀疏注意力。设 si​=q⊤ki​/d​，wi​=exp(si​)。如果每个 token 以概率 πi​ 被选入集合 S，就用 1/πi​ 给它加权：
o=∑i∈S​wi​/πi​∑i∈S​(wi​/πi​)vi​​
这就是逆概率加权：被选中概率低的 token 一旦被选中，就要放大它的权重，以代表那些没被选中的同类。SSA 分三步：

第一步：按代理分数自动分配预算。 把代理分数 s~i​（实验里来自 PQCache 的乘积量化）做 softmax 得到 qi​，找一个 λ 使 ∑i​min{1,λqi​}=k。满足 λqi​≥1 的 token 构成重集合 H，确定性保留；剩下的预算 m=k−∣H∣ 留给残余集合 R 采样。重集合多大不用手工设定，由代理分布本身决定：分布越尖，重集合越大。

第二步：在残余集合里按分数采样。 在 R 上把 qi​ 重新归一化成提议分布 pi​，有放回地抽 m 次，去重后得到 S。残余 token 至少被抽中一次的概率是 πi​=1−(1−pi​)m；重集合的 token πi​=1。

第三步：精确打分并修正。 只对 H∪S 里的 token 算精确分数 ℓi​，权重取 exp(ℓi​)/πi​，再做归一化加权求和。由于重复抽中的 token 只算一次，实际读取的 token 数不超过 k。

一个示意走查（数字为示意）：上下文 100 万 token、50 倍稀疏，预算 k=20,000。假设代理分布里有 8,000 个 token 满足 λqi​≥1，它们直接进入重集合；剩下的 12,000 次抽样在约 99 万个残余 token 里按 pi​ 进行。一个 pi​ 很小的 token 被抽中后，它的 1/πi​ 很大，代表的是一大片同样低分、但加起来仍有可观注意力质量的尾部。纯 top-k 会把这片尾部整体丢掉，均匀采样则会把大部分抽样浪费在几乎为零的 token 上。

这个框架把已有方法都包含为特例：只有重集合就是 top-k 或 top-p；重集合为空就是纯采样；提议分布取均匀分布就是 vAttention 式的混合方法。

误差界。 设 AR​ 是残余集合里的真实注意力质量，ρ=maxi∈R​aˉi​/pi​ 衡量提议分布对真实残余质量的覆盖程度（ρ≥1，提议分布与真实分布一致时取等号）。定理 2 给出，以至少 1−δ 的概率，输出误差 ∥o−o∥2​ 按 AR​ρ/m​ 缩放（去重只带来一个常数因子）。这个式子说明了预算分配的权衡：多保留重 token 会降低 AR​，多留采样预算会增大 m；代理分数低估了某个重要的残余 token 时，ρ 变大，误差上升。

3. 核心贡献

论文的主要贡献是把“检索”和“采样”统一到一个框架里，让同一个代理分数同时决定保留谁、采样谁、怎么修正。它和具体的近似检索方法正交：任何能给出代理分数的 top-k 方法（PQCache、Quest 等）都可以直接作为 SSA 的提议分布，检索方法的改进会直接传到 SSA 上。另一个贡献是工程上的：采样常被认为太慢，作者用一套 kernel 证明它在长上下文下可以比稠密注意力更快。

4. 实现：让采样不拖慢解码

为了效率，实际 kernel 用固定的重集合比例 h 代替自适应分配，作者报告这个固定预算版本的结果和理论版本很接近。解码一步分四个阶段，前三个阶段扫描全部上下文，但每个 token 只读几个字节：

  • 代理打分：每个 key 用 16 字节的 PQ 码表示（16 个子空间、256 个中心），而 head 维度 256 的 fp16 KV 对要 1 KiB；查表算出所有 token 的代理分数，同一个 kernel 里顺带处理 sink 和局部 token 的掩码。
  • 重集合选择：用 radix top-k，返回无序的下标集合，因为估计量和顺序无关。
  • 残余采样：分层采样，每次抽样先选一个 1024 token 的 chunk，再选一个 32 token 的子块，最后在不超过 32 个 token 里选一个；用每行一个哈希表去重；πi​ 下限截断为 10−4，避免权重过大，代价是引入一点偏差；随机数用基于计数器的生成器，兼容 CUDA graph 捕获。
  • 稀疏解码：从分页 KV cache 里取出选中的 K、V，用 online softmax 计算，每个 query head 拆到多个 thread block 上，再用 log-sum-exp 合并。1M 上下文、batch 1 时，拆成 64 份比 32 份快 1.58–1.71 倍，拆到 128 或 256 份反而变慢。

5. 实验

实验对比 Oracle-top-k（用精确分数选 top-k，无法加速，作为确定性检索的上界参考）、PQCache、vAttention（PQ），所有方法都用 128 个 sink token 和 128 个局部 token。模型包括 Llama-3.1-8B、Qwen3.5-4B/9B、Ministral-3-3B/8B，以及 LongBench 上的 Qwen3.5-27B。

RULER-HARD（50 倍稀疏）。 SSA 在所有模型和长度上都超过 PQ 和 vAttention（PQ）。三者用同样的 PQ 分数和预算，差别只在预算怎么分。

Ministral-3-8B 上，SSA 在 32K 和 128K 分别恢复了稠密注意力 94% 和 85% 的分数。注意 Oracle-top-k 在 Llama 和 Ministral-3-3B 的 128K、以及 Ministral-3-8B 的所有长度上仍然更强，说明代理分数本身的质量还是瓶颈。Qwen3.5 系列上所有稀疏方法都和稠密差不到 2 分。

AIME 2025（32K token 的长生成）。 稀疏度越高，SSA 的优势越明显。Qwen3.5-9B（稠密 66.3）在 50 倍稀疏时，SSA 得 59.8，Oracle-top-k 48.3，PQ 36.7，vAttention（PQ）35.8；100 倍稀疏时，SSA 仍有 51.5，vAttention（PQ）掉到 3.5。低稀疏时情况不同：5 倍稀疏下 vAttention（PQ）反而更好（65.4 对 61.0）。对重集合比例 h 的消融显示，h∈[0.2,0.8] 的混合分配得 61.0–64.0，纯采样（$h=0$）只有 40.2–42.5，纯 top-k（$h=1$）为 49.4–53.8。

LOFT 与 LongBench。 LOFT 上 SSA 在所有长度和稀疏度下的注意力误差都是非 oracle 方法里最低的，但任务指标 subspan-EM 在各方法间最多差 0.04；LongBench 上（Qwen3.5-27B）所有稀疏方法都在稠密注意力 1 分以内。这两组结果说明，误差降低并不总能转化为任务分数的差异。

解码效率。 测试在单张 H200 上做（16 个 query head、4 个 KV head、head 维度 256、fp16 KV）。batch 1 时，128K 上下文下 SSA 只有 FlashInfer 速度的 0.60–0.74 倍；上下文变长后开销被摊薄，到 1M 时 50 倍、20 倍、10 倍稀疏分别加速 1.79、1.39、1.07 倍。batch 越大收益越高，1M、batch 16、50 倍稀疏时达到 2.96 倍。kernel 优化在 batch 1 时最关键：没优化的参考实现只有 FlashInfer 的 0.37–0.47 倍，优化后提升 2.95–3.80 倍。两级采样器比只按 chunk 采样快 1.21–3.16 倍，1M 上下文、$h=0.4$ 时采样耗时 0.30–1.18 ms。

6. 局限与工业实践意义

局限有几点。实际 kernel 用的是固定重集合比例，自适应分配的高效实现还没做；πi​ 截断会引入少量偏差；采样带来随机性，同一个请求两次解码的注意力输出不完全一样，需要可复现性的场景要固定随机种子；128K 以下、batch 1 时 SSA 比 FlashInfer 慢；在 Qwen3.5、LongBench 这类稀疏本来就不怎么掉点的设置下，SSA 没有明显优势。作者提出的后续方向是让 SSA 可验证，即由用户设定近似质量的保证。

对工业界，SSA 适合的场景比较明确：百万级上下文、batch 较大的解码服务，并且要压到 20–50 倍以上的稀疏度，例如长时程智能体的会话历史、超长文档问答、长推理链生成。如果系统里已经有 PQCache、Quest 这类 top-k 检索，接入 SSA 只需要把一部分预算从 top-k 挪给按代理分数的采样，再加上 1/πi​ 修正，检索索引可以原样复用。上线前建议先在自己的任务上扫一遍 h：论文的 AIME 结果显示 h 在 0.2–0.8 之间都表现不错，但纯 top-k 和纯采样都明显更差。如果你的稀疏度只有 5–10 倍，现有的 top-k 或 vAttention 可能已经够用，SSA 的收益主要出现在激进稀疏的区间。
