Seed1.8 Model Card: Towards Generalized Real-World Agency

4.55
Relevance 4 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: ByteDance 发布 Seed1.8 基础模型，目标是通用的真实世界代理能力：从单轮预测扩展到多轮交互、工具使用和多步执行。该模型保持了强大的 LLM 和视觉语言性能，同时支持统一的 agentic 接口——搜索、代码生成与执行、GUI 交互。部署层面提供延迟和成本感知推理，包括可配置的思考模式和优化的视觉编码。在标准 benchmark 和应用对齐工作流上进行了涵盖基础能力、多模态理解和 agentic 行为的全面评估。

Key insight: Seed1.8 的核心价值在于将搜索能力作为 agentic 接口的一等公民集成到基础模型中，而非作为外挂工具。其可配置思考模式（延迟/成本权衡）对搜索系统的实践意义重大：在线搜索场景可用轻量模式保证时延，离线深度研究可用深度推理模式。对于社区搜索场景，该模型的多轮交互和工具使用能力可直接支撑 query 理解 → 检索 → 排序的 agentic 搜索流程。

深度解读：Seed1.8 Model Card: Towards Generalized Real-World Agency

1. 问题与动机

当前的大语言模型和视觉语言模型在单轮预测任务上表现出色，但真实世界应用往往需要超越单轮预测——涉及工具使用、环境反馈和多步任务执行的交互式场景。现有的解决方案通常依赖任务特定的 agent pipeline，将感知、推理和行动能力分散在不同模块中，导致系统复杂度高、维护成本大。

Seed1.8 的核心动机是在单一基础模型中统一感知、推理和行动能力，构建通用的真实世界代理。具体而言，该工作要解决三个关键挑战：(1) 如何在保持强大基座能力的同时支持 agentic 交互；(2) 如何在延迟和成本之间实现可配置的权衡；(3) 如何在搜索、代码执行、GUI 交互等多种 agentic 场景中保持一致的高质量表现。这些问题对于将 LLM 从「聊天助手」升级为「行动代理」至关重要。

2. 方法详解

Seed1.8 的设计围绕四个核心原则展开：

统一 Agentic 接口：模型原生支持三类 agentic 能力——搜索（从外部来源检索信息和综合证据）、代码生成与执行（结构化计算、程序修改和工具编排）、GUI 交互（基于视觉理解直接操作软件界面）。这些能力不是通过外挂工具实现的，而是内置于模型的推理流程中。

可配置思考模式：Seed1.8 支持四种推理深度模式——no_think、think-low、think-medium、think-high，允许在推理深度与延迟之间进行精确控制。在 MMMU-Pro 上，No-Think 模式达到 65.4%，超过 Seed-1.6（61.0）和 GPT-5.1（43.5）。这意味着即使在最低延迟模式下，模型仍能保持竞争力。

视觉 Token 效率优化：针对多模态和长上下文输入，Seed1.8 优化了视觉编码以减少 token 消耗。在长视频 benchmark 上，使用 32K token 预算即超过了 Seed-1.5-VL（80K token 预算）在所有三个评测上的表现，实现了 2.5 倍的 token 效率提升。

VideoCut 工具：创新性地引入视频裁剪工具，允许代理指定时间戳范围和帧率（1-5 FPS）进行高帧率回放，实现「慢动作」分析能力。这使得模型在需要精细动作感知的场景中表现显著提升。

流式视频主动响应：模型能在连续视频流中自主识别最佳干预时机，无需显式触发，这对实时应用至关重要。

训练细节方面，该论文以模型卡（Model Card）形式发布，未公开具体模型参数量、训练数据规模和训练硬件信息，而是侧重展示评测结果和实际能力。

3. 核心技术贡献

贡献一：搜索与代码执行的统一 Agentic 框架。不同于将搜索、代码、GUI 作为独立工具链的传统方案，Seed1.8 在统一模型内支持这些能力的无缝切换和组合。在 GAIA benchmark 上达到 93.2 分，大幅超过 GPT-5-high 的 76.7 分（+16.5），证明了统一框架在复杂多步推理任务上的优势。

贡献二：延迟感知的可配置推理。四级思考模式设计解决了实际部署中延迟与质量的矛盾。在 BrowseComp 上，low/medium 推理模式仅用不到 50 步即达到 45.0/55.0 的得分，unlimited 模式达到 67.6，展示了清晰的 scaling 行为。这一设计使模型能适配从在线搜索（低延迟）到深度研究（高质量）的不同场景。

贡献三：高效视频理解与工具使用。VideoCut 工具使 CGBench 从 62.4% 提升至 65.9%，LVBench 从 73.0% 提升至 78.9%，ZeroVideo 从 6.9% 大幅提升至 18.8%（超过 Gemini-3-Pro 的 14.3%）。视频工具的引入证明了「让模型自己决定看什么」比「一次性输入所有帧」更有效。

贡献四：中文搜索能力突出。在 BrowseComp-zh 上达到 81.3%，高于英文的 67.6%，表明模型在中文信息检索和综合方面有特别优势。

搜索代理能力是最突出的亮点：GAIA 得分 93.2 大幅领先第二名 16.5 分。在 BrowseComp 实验中，模型展示了清晰的步数-性能 scaling 曲线，说明其搜索策略能有效利用更多计算预算。

在视频工具使用消融实验中，VideoCut 在 ZeroVideo 上带来了 11.9 个百分点的绝对提升（6.9% → 18.8%），这是最大的性能增量，说明在需要精细时序感知的任务中，工具使用的价值最为显著。

不过值得注意的是，在部分 benchmark 上模型仍有差距：视频知识类任务（VideoMMMU、MMVU）落后于 Gemini-2.5/3-Pro，运动感知任务（TOMATO）达到 60.6 而人类表现为 95.2，部分工具使用任务（BFCL-v4: 57.2）也落后于同行模型。

5. 局限与未来方向

作者明确承认的局限包括：

  1. 视频知识推理不足：在学科知识类视频 benchmark（VideoMMMU、MMVU、VideoSimpleQA）上落后于 Gemini-2.5/3-Pro，说明模型在结合视觉与领域知识方面仍有提升空间。
  2. 运动感知与人类差距大：TOMATO benchmark 上 60.6 vs 人类 95.2，差距达 34.6 个百分点，作者表示计划「弥合这一差距以达到人类水平的运动感知」。
  3. 部分工具使用场景偏弱：BFCL-v4（57.2）和 τ²-Bench（72.0）落后于部分同行模型。

作者未讨论的潜在限制：(1) 模型参数量和推理成本未公开，无法评估实际部署的经济性；(2) 作为闭源模型卡，缺乏架构细节使得社区难以复现和改进。

6. 工业实践意义

搜索代理直接可用：GAIA 93.2 的得分表明 Seed1.8 在复杂搜索任务上已达到实用水平。对于需要多步搜索和信息综合的场景（如社区搜索中的深度问答），可以直接使用 Seed1.8 的搜索接口。中文搜索 81.3% 的高性能对中文社区搜索场景特别有价值。

可配置推理模式的实践价值：四级思考模式设计是最具工程实践意义的创新。在线搜索场景可使用 no_think/think-low 模式保证延迟（<50 步），复杂问答场景可使用 think-high 模式追求质量。这种延迟-质量权衡机制是搜索系统工程化落地的关键需求。

视频搜索的新机会：VideoCut 工具 + 流式视频主动响应能力开辟了视频内容搜索的新可能。对于 UGC 社区中的视频内容理解和检索，模型可以自主决定「看哪一段」和「看多仔细」，比传统的固定帧采样更灵活高效。

部署考量：由于未公开模型规模和推理成本，实际部署前需要评估 API 调用成本。建议：(1) 对延迟敏感的在线搜索使用低思考模式；(2) 对质量敏感的深度研究使用高思考模式；(3) 评估 BrowseComp 的步数-性能曲线确定最优计算预算。
