RACE: RoPE-Aligned Attention Compression Based on Query-Key Activation Energies

Irene Tenison, Abdulrahman Alabdulkareem, Daniel Karl I. Weidele, Nima Dehmamy, Dan Gutfreund · arXiv 2610.28385 · 发表 2026-10-20

KV cache 的大小等于“token 数 × 层数 × head 维度 × 精度”。砍 token（H2O、SnapKV）和降精度（KIVI）都有人做；砍 head 维度的方法也有，但大多只省了存储：EigenAttention、PALU 把 key 压成低维向量存起来，到了推理时为了套 RoPE 位置编码，又要把 key 重建回完整维度。论文表 1 的统计是：保留 50% KV 时，EigenAttention 的解码 FLOPs 是原始注意力的 11.42 倍，PALU 是 21.92 倍。这篇论文的 RACE（RoPE-Aligned Attention Compression based on activation Energy）换了思路：只保留完整的 RoPE 旋转对，按 query 和 key 的联合激活能量挑选，再把选择直接折叠进权重，这样 RoPE、缓存和注意力计算都在低维里完成，不需要重建，也不需要自定义 kernel。Llama-3.2-3B 在 50% KV 保留、256K 上下文时，总推理 FLOPs 降 47.8%，整体吞吐提升 1.79 倍，首 token 延迟（TTFT）降 43.2%，GPU 显存降 28.1%。

1. 问题：省了存储，没省计算

先说清楚 head 维度压缩为什么难。注意力的打分取决于加了 RoPE 之后的 Q~​K~⊤。RoPE 把 head 的每两个相邻坐标看成一个二维平面上的“旋转对”，按 token 位置转一个角度。如果在 RoPE 之前用一个稠密的低秩矩阵把 key 投影到低维，这个投影一般和旋转不可交换：先投影再旋转，结果不等于先旋转再投影。所以 EigenAttention、PALU 这类方法只能在 RoPE 之前把低维 key 重建回原维度，PALU 为了不显式生成重建后的张量还写了自定义 kernel，但解码 FLOPs 仍然被重建矩阵主导。

另两种已有做法各缺一块：Thin Keys 不重建 key，但 value 维度保持不动，所以 KV 只省到 75%；并发工作 RAP 也保留完整旋转对，但它用 WK​ 的梯度算经验 Fisher 分数，要做反向传播，并且只看 key 一侧。

作者把问题表述成一个带约束的近似矩阵乘法：找一个低维映射 P，让 (Q~​P)(K~P)⊤≈Q~​K~⊤，约束是这个映射必须能在 RoPE 之前执行。由此推出两条设计原则：query 和 key 要共用同一个低维子空间，因为乘积沿同一个特征维度计算；挑选这个子空间时，要同时看 query 和 key 两边的统计量，因为被近似的是两者的乘积。

2. 方法：保留完整旋转对，按联合能量排序

哪些降维能和 RoPE 交换？ 论文的定理 1 给出了精确答案：对“坐标选择”这类降维（即直接挑出某些坐标、丢掉其余坐标），它和 RoPE 可交换，当且仅当选中的坐标恰好由若干完整的旋转对组成，并且顺序和原 RoPE 一致。直觉很直接：一个旋转对的两个坐标在旋转时会互相混合，只留一个坐标就会丢掉另一个坐标混进来的那部分信息。满足这个条件后，在低维上用原来的频率转同样的角度，结果和“先全维旋转、再挑坐标”完全一样。

留哪些旋转对？ 对每个注意力头的第 m 个旋转对，在校准数据上算联合能量：
Em​=∥Qm​∥F2​+∥Km​∥F2​
Qm​、Km​ 是这一对坐标上所有校准 token 的 query 和 key 激活，∥⋅∥F​ 是 Frobenius 范数。目标维度为 rk​ 时，保留能量最大的 rk​/2 对。命题 1 说明，丢掉一组旋转对带来的乘积误差，上界是被丢掉的那些对的 21​∑Em​，所以按能量取 top 正好让这个可分离上界最小。作者也说明，这不等于让真实误差最小，只是一个只需前向、计算便宜的可行准则。

value 怎么压？ value 不经过 RoPE，沿用 EigenAttention 的做法：对校准激活做 SVD，取前 rv​ 个右奇异向量作为 PV​。

折叠进权重。 选好之后，WQ​、WK​ 右乘 PQK​，WV​ 右乘 PV​，WO​ 左乘 PV⊤​。得到的是一个普通的、head 维度更小的注意力层：存的是低维 K、V，RoPE 只作用在保留的旋转对上（频率下标保持原样，不重新编号），之后的 QK 点积、value 聚合、输出投影全在低维完成，用标准的 PyTorch 注意力就能跑。

一个示意走查（数字为示意）：head 维度 128，共 64 个旋转对。在 32,768 个校准 token 上算出每对的能量，保留最大的 32 对，key 维度降到 64；value 用 SVD 也降到 64。这一层的 KV cache 变成原来的一半，QK 点积和 value 加权的计算量也各减一半，权重矩阵 WQ​,WK​,WV​,WO​ 同步变小。

恢复训练（可选）。 激进压缩时，作者建议用 100 万 FineWeb-Edu token 做一次 KL 蒸馏：只更新折叠后的注意力权重，其余参数冻结。保留 75% 时效果不明显，保留 50% 时能找回大部分性能。实验里 RACE 和 RAP 都做了这一步，以保证可比。

3. 核心贡献

论文的贡献主要在“哪些压缩是合法的”这一步：先把 head 维度压缩写成带 RoPE 约束的矩阵乘法近似，再证明坐标选择类降维里只有“保留完整旋转对”这一族能原生执行。有了这个结论，问题就从“怎么重建”变成“在合法的旋转对里挑哪些”，挑选准则只需要前向统计。工程上的结果是：压缩后的模型就是一个 head 维度变小的标准 Transformer，现有推理后端不需要任何修改。

和并发工作 RAP 相比，两者最后得到的结构很像，都是保留完整旋转对的低维注意力，但出发点不同。RAP 把它当成结构化参数剪枝，用 WK​ 的梯度算经验 Fisher 分数，需要反向传播和任务损失，而且 Fisher 估计对 batch 的选取比较敏感。RACE 从矩阵乘法近似出发，只做前向统计，并且同时看 query 和 key。附录图 12 按层画出了近似误差，联合 Q/K 的选择在大多数层都低于只看一侧。

实现上有几个细节值得照抄：校准统计和 SVD 用 FP32 计算，推理用 BF16；保留下来的旋转对沿用原来的频率下标和 RoPE 缩放规则，不重新编号成连续频率；注意力的缩放系数仍然是原来的 1/dk​​。论文分别在 SDPA、eager 和 flash attention 三种后端上测了系统收益，各后端的墙钟时间不同，但 FLOPs 一样。

4. 实验

质量（KV 预算相同）。 要证明的是：不做重建，精度能否跟上重建式方法。实验在 Qwen2.5-7B、Llama-3.2-3B-Instruct、Granite-4.1-3B 上对比 PALU、EigenAttention、Thin Keys、RAP，指标是 WikiText 困惑度、15 个零样本任务的平均准确率和 16 个英文 LongBench 任务的平均分。保留 75% KV 时，RACE 保住了未压缩模型零样本准确率的 98.5%（Qwen）、96.5%（Granite）和 97.5%（Llama）。各压缩档位上，RACE 的零样本和 LongBench 分数与 PALU 接近，但不需要运行时重建；它在所有档位都优于 RAP，在 50% 和 75% 保留时困惑度最低。

系统收益。 要证明的是：存储省下来之后，计算和延迟是否也真的下降。测试在 Llama-3.2-3B-Instruct 上做，提示长度 64K/128K/256K，输出固定 128 token，每组跑 10 次取平均。收益随提示长度增大，因为注意力在总成本里的占比越来越高。256K、50% 保留时，预填充、解码和整体吞吐分别提升 1.76 倍、1.90 倍和 1.79 倍。显存只降 28.06%，没有降到一半，原因是总显存里还有模型参数和激活，这部分不受影响。

与 token 压缩、量化叠加。 先用 RACE 保留 75%，再叠加各占 50% 的 H2O、SnapKV 或 KIVI，总保留率为 37.5%。在已经压缩过的模型上再用 RACE，掉点比在原模型上多，说明两种压缩的影响并不独立；和 KIVI 量化叠加时掉点最小，困惑度尤其稳定。

校准数据与挑选准则。 用下游同分布数据做校准，最多比 FineWeb-Edu 好 5.4%，大多数任务差距在 6% 以内，所以通用语料做校准已经够用。消融里，只看 query、只看 key、联合两者的归一化乘积误差分别是 0.1159、0.1120 和 0.1051，联合能量的困惑度最好。它也比 magnitude、attention-product、梯度 Fisher 这几种打分便宜：校准耗时 2.717 秒，attention-product 要 11.616 秒，Fisher 要 8.290 秒；峰值显存 6.142 GB，对比 10.592 GB 和 9.218 GB。

宽头更耐压缩。 作者从头预训练了三个约 2.45 亿参数的 GPT-NeoX 风格模型（4×256、8×128、16×64 头，2.5B token），三者未压缩时困惑度相近。激进压缩下宽头模型保持得最好，原因是宽头里可选的旋转对更多。

5. 局限

作者自己说明，能量准则最小化的是误差的可分离上界，不是真实误差；50% 保留时需要一次蒸馏恢复，不能完全免训练；和 token 压缩叠加时，两级压缩的损失会相互放大。定理 1 只刻画了“坐标选择”这一类降维；为了做到免重建，论文主动放弃了更一般的稠密低秩投影，在更大的可交换族里有没有更好的解，论文没有讨论。另外，系统收益只在一个 3B 模型上测过，256K 以下的收益更小，大模型、GQA 头数很少的架构上收益会是多少，论文没有给出。

6. 工业实践意义

对长上下文推理服务，RACE 的好处是部署简单：输出就是一个 head 维度更小的标准 checkpoint，vLLM、SGLang 这类后端不需要改 kernel，和 KIVI 一类 KV 量化也可以叠加。可以先在自己的模型上保留 75% 做试点：用 3 万多个通用语料 token 校准，不做蒸馏，看长文任务掉点；如果要压到 50%，预留一次 100 万 token 级别的 KL 蒸馏。如果你在规划新的预训练架构，并且预期部署时要做这类压缩，头数少、单头更宽的设计会给后续的结构化降维留出更多空间。
