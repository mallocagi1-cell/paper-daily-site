OneRec-Think: In-Text Reasoning for Generative Recommendation

显式推理不必与在线低延迟冲突：重推理路径和前两级 item token 可离线生成，线上仅完成轻量续写。对社区 UGC 搜推，可把帖子语义 token、用户意图解释和候选生成联合训练，并用 Item Alignment 打通文本内容与行为 ID，优先验证停留时长、CTR 与端到端延迟。

1. 问题与动机

论文针对生成式推荐的一个具体断层：TIGER、HSTU、OneRec 等模型已经能把候选物品表示成分层语义 ID 并自回归生成，但多数仍是“黑盒下一物品预测器”，没有现代 LLM 的显式、可检查推理链。已有 ReaRec 主要依赖隐式推理，DeepRec 又把推理拆到外部工具和多轮调用中，难以把解释、个性化与最终 item token 做端到端优化。工业短视频序列还包含误点、探索行为和大量弱相关历史，直接要求模型从长序列产生思维链，容易得到噪声解释。作者因此提出三个连续阶段：先把离散 item token 放进语言语义空间，再用剪枝后的高相关行为启动推理，最后用适应“一个用户可能喜欢多个物品”的强化奖励优化。另一个现实动机是时延：完整推理链不能逐请求在线生成，所以论文同时设计 Think-Ahead，将重推理移出实时路径。

2. 方法详解

每个物品 v 被映射成三层 itemic token 序列 sv=(s1,s2,s3)，用户历史则是这些序列按时间拼接。传统目标只学习 P(s_next|history)，OneRec-Think 改成先生成文本推理 τ，再条件于 history 与 τ 生成下一个 item token，即同一条自回归流中完成“解释后推荐”。第一阶段 Itemic Alignment 扩展 Qwen-8B 词表：三层各 8192 个 token，共 24576 个新 token，另加 item_begin/item_end。它用四项 next-token 任务联合对齐：交错的用户画像与 item token、最长 256 个行为的序列偏好预测、从 item token 反向生成详细描述、通用语言建模。训练先冻结骨干，仅以 5×10^-4 学习新 token embedding；工业语料使用 60 亿 token。随后解冻并用 LoRA 以 3×10^-4 做多任务整合，数据比例依次为 24.30%、65.73%、4.94%、5.03%，避免 item token 在单一 next-item 目标下退化成无语义编号。

Reasoning Activation 采用两段课程。第一段对每个目标物品，用预训练 item embedding 的余弦相似度从历史中选 top-10 相关行为，让已对齐模型生成“为什么用户会点击目标”的高质量推理轨迹；第二段把这些轨迹作为监督，但输入换回原始含噪长序列，迫使模型学习从噪声中提炼同样的偏好逻辑。Reasoning Enhancement 再进行推荐专用强化学习：不是把唯一标注物品当成唯一正确答案，而是用能覆盖多个合理偏好的奖励衡量生成结果，并通过多次 rollout 改善推理与 item token 的一致性。

在线部署使用 Think-Ahead 两阶段架构。离线阶段由完整模型生成昂贵的文本推理和前两级 item token；在线阶段只根据缓存结果续写最后一级 token。这样把多步 reasoning 的成本与严格实时 SLA 解耦，同时保留前两级语义决策对最终候选的约束。

3. 核心技术贡献

第一，论文不是把解释作为推荐后的附加文本，而是让推理 τ 成为最终 item token 的显式条件；解释质量和推荐准确率因此可以共同训练。第二，Itemic Alignment 同时训练 token→文本、文本/画像→token 与序列预测，形成双向语义桥梁；消融中 Beauty 的 Recall@5 从 Base 0.0460，经 Item Alignment 升至 0.0532，再加 reasoning 达 0.0563，说明语义对齐提供主要底座，推理继续增益。第三，剪枝上下文到原始噪声序列的课程把“教师可解释样本”转化为真实工业输入能力，避免直接在数百行为上生成不稳定理由。第四，Think-Ahead 不是常规 KV cache：它预计算推理及分层 ID 的高层决策，只把最后一级候选辨别留在线上，最终在快手获得 APP Stay Time +0.159%，证明显式推理可进入大规模推荐链路。

4. 实验结果分析

论文在 Amazon Beauty、Sports、Toys 三个公开数据集比较传统序列模型与 TIGER、HSTU、ReaRec 等生成模型。核心结果如下：

数据集/指标HSTUReaRecOneRec-Think
Beauty Recall@50.04240.04500.0563
Beauty NDCG@100.03530.03440.0471
Sports Recall@100.03430.03320.0412
Toys Recall@100.05660.07640.0797
Toys NDCG@100.03090.03760.0482

Beauty 上相对 ReaRec，Recall@5 提升约 25.1%，NDCG@10 提升约 36.9%；Toys 上 Recall@10 的提升较小，约 4.3%，但 NDCG@10 提升约 28.2%，说明推理对前排质量的帮助大于简单扩大召回集合。消融进一步显示 Beauty 的 Base→Base+IA 使 Recall@10 从 0.0654 到 0.0735，再加入推理到 0.0791；NDCG@5 则从 0.0314、0.0342 到 0.0398。Toys 也呈同样单调趋势，证明对齐和推理互补，而非单纯由更大骨干带来。

工业实验以 Qwen-8B 为骨干，新增 24576 个 item token，并把推理适配到短视频行为序列。线上主指标 APP Stay Time 提升 0.159%；论文还展示用户明确表达“心情不好、想看轻松内容”时，模型能从原有动作/运动偏好切换到宠物、温馨动画和自然内容，体现自然语言约束可以改变生成路径。值得注意的是，公开表格只给最终离在线指标，没有披露 Think-Ahead 的 P50/P99 时延、缓存命中率和算力成本，因此无法量化 0.159% 收益对应的资源 ROI。

5. 局限与未来方向

作者明确指出，公开推荐数据集的行为序列短、物品空间受限，使 Reasoning Activation 和强化阶段无法学到接近工业数据质量的推理；因此公开实验采用了更简化、偏稳定的 reasoning 方案。论文计划构建更长行为轨迹、更丰富物品目录的大规模基准，并继续研究长序列建模与 dense RL reward。作者未充分展开的风险包括：显式理由可能只是与结果相关但不忠实于实际决策的事后解释；离线预生成的推理会在实时兴趣突变时变旧；用户画像、文本内容与长历史联合进入 LLM 也提高隐私治理和敏感属性泄漏风险。

6. 工业实践意义

对社区搜索/推荐团队，最值得先复用的是三步渐进路线，而非一次替换全链路。第一步，把帖子、作者、主题及多模态内容量化成分层 token，并同时做 token→标题/摘要、画像→token、next-item 三类任务，检查 token 是否真的保留语义。第二步，从点击历史中按目标相似度选 top-k 行为生成高质量训练理由，再让模型在完整噪声序列复现；这比直接用所有曝光训练 CoT 更容易控制质量。第三步，把线上奖励拆成 nDCG/CTR、理由与 query 的一致性、最终物品与用户长期偏好的一致性，同时允许多个合理正例，避免单标注奖励压制推荐多样性。

部署时可按语义 ID 层级切分计算：定时或行为更新后预生成推理与高层 token，请求时结合最新 query、实时行为和库存约束完成末级 token，再进入安全过滤或轻量重排。上线实验除停留时长外，应同时观察 CTR、nDCG、内容多样性、解释忠实度、缓存陈旧率以及 P99 延迟；若高层 token 因实时意图变化失效，需要设置 query/行为漂移阈值触发重算。OneRec-Think 证明了这条路线在大规模短视频平台有正向收益，但论文缺少绝对延迟和成本，实际采用前必须用小流量 A/B 验证单位算力收益。
