Unleashing the Native Recommendation Potential: LLM-Based Generative Recommendation via Structured Term Identifiers

4.20
Relevance 5 | Novelty 4 | Practical 4 | Evidence 4 | Timely 3

Summary: 论文用5个标准化自然语言关键词组成 Term IDs，以替代易幻觉的自由文本标识和需扩词表的 Semantic IDs；GRLM 联合上下文词项生成、指令微调与弹性标识落地。Beauty、Sports、Toys 上 Recall@5 相对最强基线分别提升7.8%、30.2%、14.9%，跨域 Recall@K 平均提升超过50%。

Key insight: 对生成式搜推而言，物品标识可以直接复用大模型原生词表，并通过相似邻居约束做到全局一致、局部可区分。其 VR@10 与直接命中率均超过99%，说明业务可先在离线候选库验证五词标识，再用精确映射加结构映射兜底，避免大规模扩词表和对齐训练。

1. 问题与动机

生成式推荐把传统“召回—排序”改写为根据用户历史自回归生成物品标识，但标识设计一直存在两难。直接生成标题或描述能够复用大模型的原生词表和世界知识，却面对无限文本输出空间：标题区分度不足，完整描述又过长，同义词还会造成标识碎片化，最终产生不存在或无法落到物品库的结果。另一条路线把物品嵌入量化成 Semantic ID，再给模型扩充专用 token；这种数值编码缺乏天然语义，跨域迁移弱，还需要额外的词表扩展与语义对齐训练。论文因此把核心问题定义为：能否找到一种既属于 LLM 原生词表、又足够短且可稳定映射回真实物品的标识。

作者的动机不只是减少幻觉，还包括让大模型在推荐中真正使用预训练语义知识。传统 SID 把“手机”“电子配件”等跨域关联压缩成彼此无关的数字码，难以迁移；自然语言词项则能充当语义桥。论文在 Amazon 真实交互数据上同时设置 Beauty、Sports、Toys 三个域内任务，以及 Sports–Clothing、Phones–Electronics 两组跨域任务，专门检验这种桥接能力。

2. 方法详解

GRLM 是一个围绕 Term IDs（TIDs）的三阶段框架。每件物品最终由5个标准化关键词表示，而非单一数字 ID 或自由文本描述。第一阶段 Context-aware Term Generation（CTG）先汇总物品元数据，用 Qwen3-Embedding-8B 编码成向量，再按余弦相似度检索近邻物品。目标物品与近邻元数据共同进入结构化提示：共享属性必须采用一致词项，差异属性则要刻意突出。这个邻域条件解决两个相反问题——“Cell-Phone”和“Mobile-Phone”之类的同义词碎片化，以及不同 iPhone 型号都被粗略标成“iPhone”的碰撞。CTG 的结果是全局较一致、局部可区分的五词标识。

第二阶段 Integrative Instruction Fine-tuning（IIFT）联合优化两个任务。Generative Term Internalization（GTI）要求模型只看单个物品元数据，不再借助近邻上下文，直接复现标准 TIDs；其作用相当于把宽广的自然语言输出空间蒸馏进受约束的词项子空间。User Behavior Sequence Prediction 则把每个历史物品表示为“TIDs + 原始标题”，以用户序列第一个物品为输入锚点，把后续序列拼为输出，按 next-token negative log-likelihood 做自回归训练。推理时无需生成完整标题，只生成下一物品的 TIDs，因此训练阶段保留语义监督，服务阶段控制解码长度。

第三阶段 Elastic Identifier Grounding（EIG）把生成词项落回候选库。系统先做字符串级 Direct Mapping，完全匹配时直接返回；若失败，再执行 Structural Mapping，把生成序列中的各词项按位置衰减加权，与库中 TIDs 计算结构得分，选择得分最高的物品。这种双通道设计既保留精确映射的低成本，也利用 TIDs 可分解的结构处理轻微词项偏差。论文报告绝大多数请求在第一通道即可完成。

主实验采用 Qwen3-4B-2507，CTG 阶段冻结参数，IIFT 阶段全参数微调；生成最大长度设为30并使用 beam search。附录说明各尺寸 Qwen3 均使用 next-token 目标、cosine annealing 学习率、全局 batch size 128、训练3个 epoch。规模实验覆盖0.6B、1.7B、4B、8B、14B五档参数。数据经过5-core 过滤并以 leave-one-out 切分，评价 Recall@5/10 与 NDCG@5/10。三套域内数据分别包含22,363/35,598/19,412名用户和12,101/18,357/11,924件物品；跨域最大的 Electronics 集有192,403名用户、63,001件物品。

3. 核心技术贡献

第一，TIDs 把“可解释自然语言”与“可执行物品索引”统一起来。它不扩展词表，而是借助邻居约束把原生关键词标准化，使相似物品共享高层语义、不同物品保留区分特征；这正面修复 Text ID 的同义词与幻觉问题，也绕开 SID 的无语义数字码。

第二，IIFT 把标识学习与行为序列学习合为同一训练目标。GTI 不是附加的展示任务，而是让模型内化从元数据到受限词项空间的生成规则；消融中去掉 GTI 后，Beauty Recall@5 从0.0607降至0.0564，说明标识内化直接影响序列预测。去掉 CTG 后该指标降至0.0576，证明近邻上下文确实提高标识质量。

第三，EIG 把开放生成风险变成可测量、可兜底的检索过程。五个测试域的 VR@10 为0.989–0.998，DHR@10 为0.997–1.000，即合法标识率和直接映射率都超过99%。相比依赖 constrained decoding 或固定候选文本的方案，它保留了生成灵活性，同时给线上系统明确的失败处理路径。

第四，论文验证了语义词项的跨域与压缩能力。Phones 上 Recall@5 从最强基线0.0436提高到0.0928，增幅112.84%；把54,255个原始词项压缩到3,000个核心词后，十域联合训练的 Recall@10 仅由0.0664降到0.0655，说明收益主要来自高层语义组合，而非记忆大量字符串。

4. 实验结果分析

域内结果对 SASRec、BERT4Rec、TIGER、HSTU、IDGenRec、OneRec-Think 均占优；跨域还加入 TriCDR、LLM4CDSR、GenCDR。关键结果如下：

最显著的模式是跨域增益远高于域内增益：域内 Recall@5 提升7.8%–30.2%，跨域 Recall@K 平均超过50%。这支持作者的解释——词项“Portable”“Ergonomic”等能跨品类复用，数字 SID 则容易形成域内孤岛。不过绝对数值仍不高，例如 Sports Recall@5 为0.0480，说明它改善了难题但并未消除推荐稀疏性。

消融表明 CTG 与 GTI 都有效。Sports 上完整模型 Recall@5 为0.0375，去 CTG 为0.0346，去 GTI 为0.0361；Toys 上分别为0.0684、0.0637、0.0653。CTG 在这些数据上通常比 GTI 影响更大，意味着先把标识构造好，比单纯增加一个辅助学习任务更关键。长度实验也给出反直觉结果：5词与7词接近，但10词在 Beauty 的 Recall@10 从0.0846降到0.0752，在 Toys 从0.0942降到0.0875。更长标识带来冗余噪声与更高解码延迟，并非信息越多越好。

规模实验从0.6B扩到14B时三套域内数据的 Recall 持续上升，表明 TIDs 能承接基础模型扩容收益；但论文只给趋势图，没有拟合幂律指数，也没有把算力成本纳入最优规模分析，因此更准确的表述是“正向规模趋势”，而不是已经建立完整 scaling law。十个 Amazon 子域联合训练得到平均 Recall@10 0.0664、NDCG@10 0.0387；词表压缩到8,000时分别为0.0657、0.0379，损失很小，给目录扩张提供了较强证据。

5. 局限与未来方向

作者明确列出两项限制。其一，CTG 依赖固定外部 embedding 模型检索近邻；如果向量模型在业务域内语义偏移，邻居上下文会把错误的一致性传播到 TIDs，后续 IIFT 无法完全修复。作者计划研究更强的领域专用检索。其二，受计算资源限制，实验主要围绕 Qwen3，尚未证明不同 tokenizer、不同语言模型家族都能复制结果。

论文还没有提供线上 A/B、端到端延迟、GPU 成本、增量物品更新频率或超大真实目录上的碰撞率。全部推荐数据来自 Amazon 公开集，五词英文标识在中文 UGC、拼音缩写、网络新词和多语言混合内容上是否稳定仍是开放问题。另一个被弱化的风险是 CTG 的全库近邻检索和离线 LLM 生成成本；物品高频新增时，需要增量索引与版本化策略，防止同一物品在不同批次获得漂移标识。

6. 工业实践意义

对搜索/推荐团队，最可落地的部分不是立刻替换现有召回排序，而是把 TIDs 作为第二套语义索引做旁路实验。可以先从一个类目抽样：用业务 embedding 检索近邻，生成固定5词标识，监控重复标识率、同义词碎片率、VR@10、DHR@10、长尾 Recall 和跨类目迁移，再与现有 SID 或文本 embedding 对照。若直接命中率接近论文的99%，结构映射只承担少量尾部请求，服务复杂度可控。

社区 UGC 的关键适配是把“物品元数据”改成标题、正文摘要、话题、作者领域和多模态标签，并在 CTG 提示中明确社区同义词、品牌别名与时效性实体。五词结构可以设计为主题、对象、意图、属性、场景，而不是让模型自由挑五个词。对于 query 侧，可让模型生成同一词项空间中的意图 TIDs，再用结构得分做召回或 rerank 特征；这样能够把 query 理解与内容索引连接起来，同时保留现有 ANN 召回作为安全网。

部署上应避免每次请求调用大模型生成全部候选。论文方案适合离线生成并缓存物品 TIDs，在线只让推荐模型预测下一组词项，再走精确哈希映射；结构映射可放在低命中分支。模型从0.6B到14B都有正向趋势，但没有成本曲线，实际应先以0.6B–4B验证增益/延迟比。词表压缩实验尤其有价值：把54,255词压到3,000后 Recall@10 只降0.0009，意味着可用受控核心词表降低解码空间、缓存体积和内容治理成本。

不宜直接照搬的部分包括把离线 benchmark 提升当作线上 CTR 保证，以及在没有多语言验证时将英文词项规则推广到中文社区。建议上线前增加三类保护：新物品标识版本化与回滚、非法/低置信 TIDs 回退现有召回、按类目和语言监控直接命中率。论文没有线上结果，因此最合理的下一步是小流量 shadow test，先验证覆盖率、nDCG、P95 延迟和增量索引稳定性，再考虑替换主链路。
