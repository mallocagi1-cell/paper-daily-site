计算深度可以成为行为级的可学习变量。较新或低频行为往往需要更多处理；动态路由减少的计算量和实际延迟要分别测量，因为 GPU 上的分支调度也有成本。

LoopRec 在序列编码器内部按历史物品分配计算深度：所有位置先经过一次共享编码块，然后由逐位置门控决定退出或继续。模型仍只用下一物品预测提供任务监督。作者在三个 Amazon 数据集、四类主干上测试，Software 上 SASRec 的 NDCG@20 相对提高 5.68%。这些步骤在线执行，训练时另加路由正则与预热。

1. 问题与动机：历史行为需要多少计算

这项工作调整序列推荐的编码环节。序列推荐根据用户按时间排列的行为预测下一件物品。常规模型把每条历史行为送过相同层数，默认所有位置都需要同样多的计算。

作者先检查一个训练好的三层 SASRec。SASRec 是使用自注意力学习用户行为顺序的推荐模型。诊断时只让一个历史位置提前停止，其他位置照常计算，比较最终推荐集合是否改变。如果不变，就把那个深度称为该位置的饱和深度。

第二个诊断只改变最近五条行为的深度。研究者让一个知道真实目标物品的离线搜索器选择最好的分配。这是分析固定深度局限的工具，实际路由器不会看到未来目标。它回答的是固定计算是否留下改进空间。

2. 方法：共享参数，逐次决定是否继续

共享递归首先解决不同深度表示难以对齐的问题。模型重复使用同一个编码块，而不是给每一层分配独立参数。论文用 LxRy 表示结构：x 是共享块的层数，y 是最多递归次数。比如 L2R3 对应两层编码块、最多使用三次。

初始阶段把整个历史序列编码一次。后面的每个递归边界，路由器读取每个活跃位置的当前状态与递归索引，输出一个标量。通过 sigmoid 函数把它变成退出概率：
pi(r)​=σ(g(hi(r)​,er​)).
i 是历史位置，r 是当前递归深度，h 是该位置状态，e 是深度编码，g 是轻量门控网络。退出概率达到阈值就停止，否则继续。直觉是先吸收一轮上下文，再判断是否值得追加处理。

只有继续的位置才组成下一轮输入。它们保留原有相对顺序并使用因果掩码，即当前位置只依赖此前可见行为。已经停止的位置保留当前状态，不再参与后续状态更新。到达最大递归预算时，所有剩余位置强制停止。

这意味着下一轮处理的序列本身会改变。工程实现必须忠实保留活跃位置的索引和顺序，才能让不同请求与不同批次得到一致结果。动态位置压缩也是实际速度收益是否出现的关键。

读出阶段把位置的输入向量与所选深度状态结合。前向计算选择硬深度，深度相关权重仍保留对路由概率的梯度，使门控能通过推荐目标学习。共享块负责控制参数规模，深度相关读出负责连接停止决策与最终预测。

训练阶段主要解决路由容易退化的问题。若所有位置都在同一深度退出，模型就接近固定深度。论文加入深度使用正则，结合实际硬路由比例和可微的软质量，避免路由过度集中。

另一项正则抑制门控过早给出极端分数。极端概率会让停止选择很快固定，早期尚未稳定的状态就可能决定整个训练轨迹。作者借用路由 z-loss，惩罚二元门控的对数配分函数过大。

总体目标可概括为：
L=Lrec​+λb​Lbal​+λz​Lz​.
Lrec 是下一物品交叉熵，Lbal 是深度使用正则，Lz 是门控稳定项；两个 lambda 分别控制正则强度。额外项只约束路由，目标物品标签仍是唯一的物品预测监督。

训练还包含预热阶段。预热时所有有效位置都执行最大深度，暂时关闭路由正则，先让共享主干形成可用状态。随后开启门控。最值得关注的结构参数是共享块层数、最大递归次数，以及预热长度；它们共同影响可学习性和实际计算预算。

一次请求可用以下示意走查。用户最近五次看过 A、B、C、D、E，候选是 F。初始编码让五个位置交换过去的上下文。门控让 A、B 退出，C、D、E 继续；下一轮又让 C 退出，最后 D、E 达到预算。模型读出所选状态后为 F 评分。这里的退出轨迹和物品字母仅作说明，线上不会用真实下一物品来替路由器作决定。

3. 核心贡献：把计算分配变成推荐建模的一部分

这篇论文把推荐质量与行为级计算预算联系起来。模型学习哪个位置需要更深处理，而不是仅把整段序列统一加长或加深。逐轮判断可以利用更新后的上下文，比一次性给所有位置分配深度更灵活。

作者观察到较新和较低频物品更常得到深层处理。低频行为缺少充分统计，较新行为又可能更接近当前意图，因此这个分配方向具有解释性。实验也比较了按位置或频率制定的启发式规则，学习式路由取得更高的平均表现。

共享主干使这套方法不局限于注意力网络。论文还测试卷积和线性循环模型。它们怎样聚合序列不同，但都能把编码块重复使用，并由门控控制继续处理的位置。

4. 实验结果：准确率与延迟分别比较

实验使用 Software、Office Products 和 Patio 三个 Amazon Reviews 2023 类别。每个用户按时间留下最后一次交互测试，模型选择使用验证集 NDCG@20。NDCG 是按名次折损的排序质量，MRR 是真实目标排名倒数的平均值。主表报告五次运行均值。

比较NDCG@20：固定主干 → LoopRec解读
SASRec / Software0.0944 → 0.0998相对收益报告为 5.68%
SASRec / Office0.0582 → 0.0595注意力主干也有稳定小幅收益
NextItNet / Patio0.0192 → 0.0263卷积主干相对收益较大
LRURec / Software0.0958 → 0.1001对线性循环主干同样有效

NextItNet 是因果卷积序列模型，LRURec 是线性循环序列模型。主表的四种主干还包括带频域建模的注意力变体 BSARec。相对收益使用作者报告值，因为展示的绝对指标经过四位小数舍入。

速度实验在单张 A6000 GPU 上测编码器，不含全量候选打分。L2R4 相对同最大深度的固定模型，编码时间从 91.230 毫秒降到 79.273 毫秒。L2R2 则几乎没有延迟变化，即使选择执行的计算量已经减少。

这个结果说明计算节省与延迟收益的差别。较深结构给提前退出留下更多空间，但动态分支、索引整理和小矩阵计算会吞掉部分收益。线上评估需要把编码与候选打分放到完整请求里再看。

5. 局限：动态执行收益依赖运行环境

论文的速度测量限定为单 GPU 编码器时间。作者明确指出，跳过计算只能部分转成墙钟时间收益。不同递归结构的改善幅度也明显不同。

评估集中在三个同源公开数据集，条件历史按热启动物品处理。工业超长行为序列、特征交叉和候选打分的成本构成不同；它们属于本文未直接覆盖的环境。另一个具体实现风险是动态活跃序列改变了后续上下文，批处理需要正确维护用户与位置映射。

6. 工业实践意义：观察路由是否用在有价值的行为上

可以在现有用户序列主干旁记录位置、物品频次与所选深度，检查模型是否把额外计算集中到新近或稀疏行为。这样的分析比只报告平均递归次数更容易解释质量变化。

上线前把同最大有效深度的固定主干作为速度对照，并分别测编码器和完整请求延迟。消融中保留共享参数、去掉自适应门控，能帮助区分参数复用和计算分配各自的收益。对于以用户历史支持个性化排序的系统，这些实验直接对应效果与服务成本之间的选择。
