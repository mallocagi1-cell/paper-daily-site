ICEGR: An Intent-Coherent End-to-End Generative Retrieval Framework for E-commerce Search

4.75
Relevance 5 | Novelty 4 | Practical 5 | Evidence 5 | Timely 5

Summary: 针对电商生成式检索在语义 ID 构建、低曝光商品监督和偏好优化三个阶段出现的意图漂移，ICEGR 将查询意图贯穿 SID、统一 SFT 与相关性校准偏好学习。离线 Recall@20 提升 21.7%、NDCG@20 提升 26.6%；百度线上 A/B 中 CTR、订单量和 GMV 分别相对提升 3.52%、15.96% 和 7.53%。

Key insight: 最值得借鉴的是把业务偏好与相关性约束放进同一个 margin-adaptive 目标，而不是让高价值或热门商品覆盖真实意图。对 UGC 搜索，可用真实 query 与合成 query 联合补齐长尾内容监督，并让语义 ID 同时吸收内容语义和查询意图，直接优化召回覆盖与 nDCG。

ICEGR 深度解读

1. 问题与动机

工业电商搜索通常采用 query 理解、召回、预排序、精排的级联架构；一旦相关商品在召回阶段漏掉，后续模型无法补救。生成式检索把商品映射为分层 Semantic ID（SID），再由自回归模型直接从 query 生成候选，理论上能减少阶段间目标错位。但作者发现，架构端到端并不等于意图端到端：SID 多由标题、描述等静态内容构建，无法表达“情人节送女友礼物”同时对应口红和项链这类跨内容意图；SFT 中 product-to-SID、SID-to-product 任务偏向记忆商品编码，真实 query-to-SID 日志又对低曝光商品覆盖不足；最后，直接按点击、支付或 GMV 构造偏好对，会把热门、高价值但不相关的商品推到前面。ICEGR 因此把 query-product relevance 作为 SID 构建、监督微调与偏好优化三阶段共享的约束，而不是分别做局部优化。

2. 方法详解

第一阶段 IA-SID 先用历史点击三元组训练电商适配编码器。对正样本 query-product 与查询内负样本采用 InfoNCE，使 query 向量靠近被点击商品、远离负例。随后从共 query 点击构造商品图：商品 i、j 的边权为所有共同 query 上点击数几何均值的求和，再对邻接矩阵对称归一化。商品表示做 3 步带残差的图传播，每步按 0.8 邻域信息与 0.2 原始向量混合，避免高阶关系覆盖商品本义。每个商品还聚合历史点击 query，权重按点击频次归一化；置信门随有效 query 数增长并在 Qmax=50 饱和，控制意图画像注入强度。融合后的 256 维向量由三层 RQ-KMeans 离散化，每层 1,024 个 code，得到三级 SID。

第二阶段 SQE-SFT 先把目录文本解析成标准商品名、品牌、品类、系列、型号和属性，再生成两类多粒度 query：实体指定类覆盖商品名、品类范围与系列变体，属性约束类组合商品名和非低频属性。清洗、去重后，第一阶段用合成 query→SID 覆盖全目录，第二阶段继续用真实点击/转化 query→SID 对齐线上分布；两阶段使用同一指令“给定用户请求，推荐最相关 SID”，避免传统商品记忆任务与推理输入不一致。

第三阶段 RCPO 从 beam search 候选构造偏好对。语义相关分 SRS 由 0.6B 微调模型评估 query 与 SID 对应商品描述；业务偏好分 SBP 综合点击、支付和 GMV，权重分别为 0.2、0.3、0.5，GMV 先按非零值第 95 百分位做对数缩放与截断，再用类目均值和 κ=10 平滑稀疏 pair。SRA 以语义相关性决定偏好方向，BPR 只在语义接近的候选间用业务分细排。RCPO 以 SRS、SBP 等权复合分的 pair margin 动态调整每对样本的 β：证据差距大时减少重复优化，差距小时加强学习，并加入长度归一化的 preferred-SID SFT 锚点。线上最终部署 0.5B backbone，beam size 为 50。论文未公开优化器、batch size、训练步数和离线训练硬件，这些是复现缺口。

3. 核心技术贡献

  1. 意图感知的 SID：不是只把 query 当生成器输入，而是在量化前通过 query-product 对齐、共点击商品图和置信门控的历史 query 画像改写商品表示。消融中去掉 query-product 对齐，Recall@20 从 0.5169 降到 0.4179，跌幅 19.15%，说明目标空间本身是否贴近搜索意图是决定性因素。
  1. 统一的合成—真实两阶段监督：用目录结构自动生成多粒度 query，先补全长尾覆盖，再用真实日志校准分布。按组件累加，SQE-SFT 贡献累计 Recall@20 增益的 76.7%；Low 组提升 36.2%，Tail 组提升 21.2%，表明“合成覆盖+少量真实监督”优于只有合成 query。
  1. 相关性校准的业务偏好学习：只在语义相关候选间引入业务价值，并按证据 margin 调节更新强度。固定 β 会让 NDCG@20 下降 7.36%，人工盲评 top-5 相关率从 0.87 降至 0.58；移除 SBP 时 MRR@20 下降 6.26%，说明动态校准和业务信号分别保护整体排序与首个相关结果。
  1. 真实生产闭环：系统不是只做离线验证，而是把固定数量的 ICEGR top-k 直接插入曝光列表，其余候选仍进入原级联链路，形成可控的渐进式端到端路径。

4. 实验结果分析

离线数据来自百度电商搜索近三个月日志，按时间切分，最终一天抽取 20,000 个不同 query，以点击商品为相关标签。核心结果如下：

相对 ProdGR，ICEGR 的 Recall@20、MRR@20、NDCG@20 分别提升 21.7%、26.6%、26.6%；K=50 时分别提升 16.1%、26.0%、23.4%。MRR/NDCG 增幅高于 Recall，说明收益不仅是多召回商品，还把相关商品推到了更靠前位置。IA-SID 消融显示，去掉关系建模只让 Recall@20 降 4.35%，去掉表示融合降 4.78%，但同时去掉两者降 13.60%，两条意图注入路径存在互补。偏好标签反转后 MRR@20 仅 0.1719，甚至低于 ProdGR 的 0.1982，排除了“多训练一遍就有效”的解释。

模型规模从 0.5B、1.5B、3B 扩到 7B，固定数据、codebook 和解码配置，Recall@20 从 0.5043 单调升至 0.5334，MRR@20 与 NDCG@20 分别提升 5.1%、5.8%，尚未观察到平台期；但团队为性价比选择 0.5B 上线。两周 A/B 覆盖 20% 流量，对照为生产 MCA：Show PV +8.84%、CTR +3.52%、长点击率 +5.27%、商品落地页 PV +8.75%、订单量 +15.96%、GMV +7.53%。这组结果说明曝光扩大没有以点击效率为代价，且转化增幅更大。

5. 局限与未来方向

论文没有独立 Limitations 章节。作者明确指出因保密只报告线上相对增幅，未给绝对指标、置信区间和显著性检验；训练日志、完整目录规模、优化器、batch size、训练步数与成本也未公开。实验只来自百度电商单一业务，二元点击相关标签可能混入位置与曝光偏差，人工评测也只有 50 个 query。线上方案依赖 67 张 NVIDIA L20、beam=50，平均 156 ms；对规模更小或延迟更严的团队并不轻量。未来应验证跨域 SID 迁移、合成 query 的分布偏差、去偏点击监督，以及更小 beam、非自回归或蒸馏解码能否保持收益。

6. 工业实践意义

对社区 UGC 搜索，最直接的映射是把“商品”替换为帖子、问答和评论，把共点击图扩展为同 query 下的共阅读、收藏、长停留关系。SID 构建前可融合标题正文、话题/作者/社区结构与历史 query 画像；对低曝光 UGC，可从实体、主题、时间、地域和属性组合生成多粒度 query，再用真实搜索日志做第二阶段校准。业务偏好层应把 SRS 设为硬护栏，只在语义相近内容间用 CTR、长停留、收藏或负反馈调整顺序，避免热门内容挤压 query relevance。

部署上不必立即替换全部召回：ICEGR 的做法是固定插入少量生成候选，再与现有级联结果合并，适合灰度验证增量 Recall、nDCG、CTR 与生态指标。论文的生产配置为 67×L20、2,200 QPS、156 ms 平均延迟，说明 beam=50 的自回归召回成本仍高；社区业务应先从 0.5B backbone、小 beam 和有限流量开始，并把 GPU 成本、尾延迟、生成非法 SID 率纳入守护指标。最应避免的是直接按点击或商业价值做 DPO：固定 β 的人工相关率从 0.87 跌到 0.58，已经展示了业务优化覆盖语义意图的具体风险。
