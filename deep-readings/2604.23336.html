Efficient Rationale-based Retrieval: On-policy Distillation from Generative Rerankers based on JEPA

4.30
Relevance 5 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 针对 rationale-based 检索需要对 query-document 联合编码导致计算成本过高的问题，提出 Rabtriever：先训练一个把 document 放在 query 之前、用 log p 生成相关性分数的 LLM 生成式重排器作为教师，再通过基于 JEPA（联合嵌入预测架构）的 on-policy 蒸馏，把教师能力压缩到独立编码 query 与 document 的双塔模型，从而保留对查询-文档的深度理解但显著降低线上推理成本。在多个检索基准上 Rabtriever 接近 cross-encoder 重排器的效果，同时具备双塔模型的延迟优势。

Key insight: 把昂贵的 LLM 生成式重排器作为教师、用 JEPA 表征对齐做策略内蒸馏到双编码器，是社区 UGC 搜索的高 ROI 路径——线上仍跑廉价的双塔召回，但语义理解水平接近重排器。值得借鉴的设计点：(1) 让教师按 'doc 在前 + query 在后 + 生成相关性' 的范式打分，可以充分利用 LLM 长上下文与因果注意力的判别能力；(2) on-policy 而非 offline 蒸馏避免学生分布漂移。社区短文本搜索的 query-doc 语义鸿沟很大，这套方案可以直接落到现有 Faiss/HNSW 召回栈上。

1. 问题与动机

本文针对的是 'rationale-based retrieval'（理由型检索）这一新兴任务：与传统基于事实匹配的检索（如 MS MARCO 风格 QA）不同，理由型检索需要找到一段在语义上能够支撑/共情/对齐查询的文档（典型场景包括情感咨询 ESConv、心理问答 PsyQA、机器人指令对齐 SayCan）。这类任务对 query-document 之间细粒度的因果与共情判别要求很高，传统双塔（独立编码）模型在这类基准上的表现远落后于 LLM-based cross-encoder 重排器：例如在 ESConv 上最强的 LLM 重排器 LaHoRe 的 R@1 = 34.4 / MRR = 54.8，而最强的双塔基线 LlaMA2Vec 仅有 R@1 = 23.9 / MRR = 45.5——绝对差距 ≈10 个 R@1 点。

但 LLM 重排器的代价是工业不可承受的：单 query 响应时间 ~980ms（vs 双塔 ~93ms）、且时间复杂度对文档长度二次增长。这使得 LaHoRe 类方案只能停留在小规模 reranking 后处理阶段，不能进入真正的检索/召回主干。本文动机就是要 '保留 LLM 重排器对 query-document 的深度理解，但获得双塔检索器的延迟特性'。

2. 方法详解

2.1 教师：LLM 生成式重排器

首先训练一个 LLM 生成式重排器作为蒸馏教师。关键 prompt 模版如下（注意 doc 在前、query 在后）：

Document: {D}
Query: {Q}
Can Query be appropriately replied with Document?
If the answer is true, choose <T>; otherwise, choose <F>.

相关性得分由 'true/false' 两个 token 的对数概率归一化而来：score = log P(<T>) / (log P(<T>) + log P(<F>))。这种 'doc-first / query-last' 安排有一个非平凡的好处：因为 LLM 是 causal attention，document embedding 在 doc-only 编码与 doc+query 联合编码下数学上完全相同（论文 Eq.8），意味着所有 doc embedding 可以离线一次性预计算并缓存。教师在 SFT 阶段用所有 (q,d) 正负对 + cross-entropy 训练。

2.2 学生：Rabtriever（JEPA-style 双编码器）

核心设计是把传统双塔的 'cosine + dot product' 评分头替换为一个轻量级的 JEPA 预测器，并用 on-policy 蒸馏对齐到教师。

架构：

  • backbone 用与教师同款的 Qwen2-7B-Instruct，所有 transformer 参数全部冻结
  • query 与 document 独立编码，分别取最后一层 token embedding eQ、eD
  • 在 LLM 输出和 scoring head 之间插入 JEPA 预测器：

```
eQ_student = MLP_θ(eQ) ⊙ eD[-1]
```
其中 MLP 是 2 层带 ReLU 的小网络（仅 θ 可训练），eD[-1] 是文档的最后一个 token 嵌入，作为 JEPA 中的 latent control variable z；⊙ 是逐元素相乘

  • 把 eQ_student 送回原 (frozen) scoring head 得到 score

损失函数（Eq.13）由两部分组成：

F = F_MSE(eQ_student, eQ_teacher) + w · KL_rev(P_student || P_teacher)
  • F_MSE：JEPA 风格的能量函数，要求学生 'predicted query embedding' 在 latent 空间逼近教师的真实 query embedding
  • KL_rev：反向 KL 散度，把学生输出 logits 拉向教师输出 logits；w = 0.25
  • 反向 KL（而非常用的正向 KL）是关键设计：reverse KL 鼓励学生的概率质量集中在 'true/false' 这两个真正决定相关性的 token 上，避免正向 KL 'mean-seeking' 引入大量噪声 token 的拉力

这是典型的 'on-policy' 蒸馏：student 在 mini-batch 上前向 → 同 batch 用教师 inference 得到目标 → 学生反传更新 MLP（其余参数冻结）。整套流程对算力非常友好。

3. 核心技术贡献

  1. 'doc-first' 因果对称 prompt： 把 document 放在 query 之前，配合 LLM 的 causal attention 使 doc embedding 在联合编码与独立编码下严格相等。这是把 '联合编码教师' 蒸馏到 '独立编码学生' 的理论保证，避免了传统蒸馏中 student-teacher 输入分布不一致带来的偏差。
  1. JEPA 风格的预测器插件： 把 'query embedding 的语义对齐' 形式化为 JEPA 中的 latent prediction 任务。MLP_θ(eQ) ⊙ eD[-1] 这一逐元素乘是低秩、低算力的对齐器，在仅训练 2 层 MLP 的前提下就能让冻结的 7B backbone 输出贴近教师；这比 LoRA 之类参数化方法成本更低。
  1. Reverse KL + MSE 复合损失： 论文消融显示去掉 reverse KL 让 R@1 从 32.8 跌到 24.1，去掉 F_MSE 让 R@1 跌到 ~0；用正向 KL 替换反向 KL 也明显劣化（28.4 vs 32.8）。这套损失组合是 Rabtriever 性能的真正引擎。
  1. 线性时间复杂度推理： 通过文档 embedding 离线缓存 + 在线只编 query + 单 MLP 评分，整体推理复杂度降为 O(L_Q²) + n·O(1)（n 为候选文档数），打破了重排器 n·O(L_D + L_Q)² 的二次瓶颈，端到端延迟从 980ms 降到 95ms（10× 加速）。

4.1 Rationale-based 检索（核心指标）

4.3 跨域泛化

  • MS MARCO（in-domain QA 检索）：MRR@10 = 49.30（教师 52.4，最佳双塔基线 ~46）——保留教师 94% 性能
  • BEIR 13 个子任务零样本平均：Rabtriever nDCG@10 = 58.2（教师 65.8，GritLM 59.2）——略逊于教师，但与 GritLM 这种 SOTA 双塔接近
  • 在 BEIR 13 个子任务里 Rabtriever 拿到 2 个 SOTA、4 个第二，证明知识蒸馏后的能力具备一定的零样本迁移性，但确实在 OOD 上有 7.6 点 nDCG 差距

5. 局限与未来方向

论文 Appendix C 自陈了几个限制：

  1. 零样本 OOD 性能下降： BEIR 上 Rabtriever 比教师低 7.6 nDCG 点，且只在 2/13 任务拿到 SOTA。蒸馏明显损失了一部分跨域泛化能力。
  2. 数据集覆盖窄： 主要实验只在 3 个 rationale-based 数据集上做（共情、心理、机器人指令），尚未在大规模 web 检索（如 ClueWeb22）上验证。
  3. JEPA 缺乏理论保证： 该 energy function 在检索蒸馏场景下没有形式化收敛证明，目前是经验性 work。
  4. Predictor 简单： MLP + element-wise mul 表达能力有限；更复杂的 cross-attention 预测器是否能进一步缩小与教师差距未知。

论文未明确提及但显然存在的限制：(a) 教师 prompt 设计强依赖于 'true/false' 单 token 分类，对于细粒度多档相关度评分（如 0-4 graded）需要重新设计；(b) on-policy 蒸馏需要在线跑教师 inference，训练阶段比 offline KD 慢约 30-40%。

6. 工业实践意义

对社区 UGC 搜索的核心启示：

  1. 'Generative reranker → Bi-encoder' 的蒸馏范式可以直接落地。 社区搜索的 query-doc 语义鸿沟（口语 query vs 长帖正文）和论文中的 ESConv/PsyQA 同质化程度很高。先用一个 7B-13B 的 LLM 当教师对小批量 (q, d) 标记相关性，再蒸馏到双塔，几乎是把 cross-encoder 的判别力 '免费' 注入 ANN 召回栈。
  1. 'Doc-first prompt + reverse KL' 是值得复用的 trick： 这两个看似细节的设计带来巨大差距。任何想做 LLM 蒸馏的团队都应：(a) 把可缓存的 entity 放在 prompt 前面，确保 causal attention 对其表征独立；(b) 用 reverse KL 而非正向 KL 训练 binary 决策。
  1. 延迟数据可以直接对账上线： 95ms ≈ 双塔 baseline，且文档可全离线编。社区搜索动辄千万-亿级文档库，正好用上 doc embedding 离线全量预计算的优势。建议先在 'session 内相关问题推荐' 这种千级别召回场景试点。
  1. OOD 退化要警惕： BEIR 上 7.6 nDCG 点的差距提醒我们，蒸馏出来的双塔不能完全替代 cross-encoder 重排——线上仍需把它放在 retriever 位置（召回 1000 -> 100），重排阶段保留一个更轻量的 cross-encoder 才稳妥。
  1. 基础设施要求温和： 8×A100 < 10 小时即可完成蒸馏，对中型团队完全可行；推理 vLLM + prefix cache 已是工业标配。这是少数 'paper-to-prod' 距离极短的工作。

部署清单：(a) 准备一个可信的 LLM 重排器作为教师（Qwen2-7B 或类似规模即可，无需巨型）；(b) 离线给百万级 (q, d) 对打教师分；(c) 训 MLP predictor + 双塔；(d) 文档 embedding 全量预计算；(e) 线上以双塔形式服务，召回阶段直接用蒸馏后的分数，而不需要再过 cross-encoder。
