From Overlooked to Explored: Recovering Item Relations via Mixture of Perspectives for Sequential Recommendation

对 UGC 短文本或多兴趣推荐，不能只把用户历史压成单一相似度分数；应显式保留“相似兴趣”和“跨兴趣桥接”两类关系。PRISM 以共享参数的轻量注意力校准层插入 Transformer，单 RTX 3090、两层模型即可验证，适合先在重排层做插件式消融。

1. 问题与动机

这篇论文针对序列推荐里一个常被忽略的失效模式：Transformer 的自注意力并不一定把权重给真正有助于预测下一物品的历史行为。作者把原因归结为相似性偏置（similarity bias）：点积注意力天然偏好与 query 表示相似的 key，因此会反复强化同一类兴趣，却压低跨品类、跨语义但具有预测价值的“桥接行为”。论文在 Amazon Toys 与 Beauty 上取 1,000 条测试序列，用最后一层平均注意力 A 与遮蔽单个物品导致的目标概率下降 I 做 Spearman 相关和 Align@1 分析。SASRec 的注意力—因果重要性相关在两个数据集上为负；AC-SASRec、ICLRec、ICSRec 和 FAME 也没有稳定消除错配。反事实干预进一步显示，把低注意力位置整体提升会改善目标置信度，而只提升低注意力且高因果重要性的位置（C4）比盲目提升底部位置（C3）更好，说明被忽略的信号确实有用，而且分布在多个关系面上。

这个问题对个性化尤其重要。用户的兴趣不是单一主题，社区内容、商品、视频和广告中常常存在由“主兴趣→桥接主题→目标物品”构成的路径。如果模型只抓住同质相似项，会在短历史用户、长历史多兴趣用户和新颖兴趣目标上表现差。论文因此不把问题描述成简单的“需要更多 attention heads”，而是强调要重新定义哪些关系应该被看见。

2. 方法详解

PRISM（Perspective-based Relational Insight Synthesis Module）插入 L 层 Transformer 的前 L-1 个层之间。它的第一步是 Semantic Anchor Router：对每个 item 表示 h_i 计算 K 个语义组的 routing logits，并加上带 Softplus 噪声的 noisy gate 促进训练期探索；softmax 后得到语义组成比例 g_i，最大分量对应 Primary Semantic Anchor（PSA）。这不是把 item 硬分配给固定专家，而是保留一个连续的多语义组成比例。

第二步是 K 个 Perspective Lens。第 k 个 lens 根据 key 位置的 PSA 构造 Semantic Focus Mask，只看属于语义组 k 的列；然后计算该组的平均 attention logit 作为 relational boost signal S。新的 attention logit 为 A + exp(βS)，其中 β 是可学习标量，指数项保证添加的是非负增益。所有 lens 共享 β 和线性层参数，所以不同视角的差异主要来自语义 mask，而不是复制 K 份大网络。每个 lens 形成一个 z_i^k，之后按 g_i^k 做加权和并经过 Feed-Forward，送入下一层 Transformer。

该结构自然形成双视角：若 query 的 PSA 就是 lens k 的组，lens 工作在 Affinity View，增强同组相似关系，例如 laptop 与 monitor 的工作站语义；若 query 不属于该组，lens 工作在 Contrast View，显式观察被相似性偏置压低的跨组关系，例如 laptop 与 backpack 之间的数字游民语义。每个 item 恰好有一个 Affinity View 和 K-1 个 Contrast View，兼顾同质精化和异质发现。

训练目标包括推荐交叉熵 L_rec、序列偏好对比损失 L_SPCL 和协同一致性损失 L_CCL，最终 L=L_rec+λ(L_SPCL+L_CCL)。SPCL 为拥有同一 target 的两条序列构造正样本，但担心对比学习把用户不同的关系模式过度对齐，因此引入 Stochastic Perspective Masking：保留主语义 lens，按 ρ=0.25 随机屏蔽非主 lens，再对序列表示做 InfoNCE。CCL 对每个 lens 输出在采样 item embedding 上的 softmax 分布计算对称 KL，并用两个 lens 的语义组成比例加权；弱激活的 lens 对损失贡献小，避免为了“一致”而抹掉视角差异。

实验采用 PyTorch+Adam，学习率 0.001，β1=0.9、β2=0.999，batch size 256，dropout 0.5，N@20 连续 10 个 epoch 无提升早停；两层 Transformer、两头注意力、隐藏维度 64、最大序列长度 50。K 在 2/4/6/8，λ 在 0.01/0.05/0.1/0.3/0.5，温度在 0.05/0.7/1.0/2.0 中搜索，单张 RTX 3090 完成实验。

3. 核心技术贡献

第一，论文把“注意力与因果重要性错配”从经验现象提升为可诊断问题。相比只看 attention heatmap，它用 mask intervention 测量每个历史位置对 target 概率的真实贡献，为用户建模提供了更接近因果的审计信号。

第二，PRISM 用语义锚点路由和双视角透镜处理同质与异质关系。传统 attention calibration 通常用一个矩阵修正分数，intent 模型则偏向序列级 prototype；PRISM 在 item 关系级别动态重看每个位置，因而能在 Novel Set 上避免固定 intent prototype 的过度压制。ML-1M 案例里，主流模型会忽视跨类型的 Bridge Item，PRISM 能把它排到第 3 位，并在遮蔽该物品时出现更大的置信度下降。

第三，SPCL 与 CCL 的组合解决了多视角模型的两个冲突：只做序列对比会让不同关系模式塌缩，只做 lens 输出分离又可能破坏 item-space 一致性。SPM 只对共享目标所需的主语义做对齐，CCL 用语义组成权重做软一致性约束。

第四，效率设计比较克制。Toys 上 SASRec 有 866,496 个参数、推理 3.43 秒，FamouSRec 有 964,739 个参数、推理 4.47 秒；PRISM K=4 为 909,057 参数、推理 4.13 秒，N@20=0.0751，超过 FamouSRec 的 0.0721。K 从 2 增至 8 只新增 768 个参数，但推理时间从 4.00 秒升到 4.73 秒，表明主要成本是 K 次关系重算而非大模型参数复制。

4. 实验结果分析

论文在 Toys、Beauty、Games、Sports、ML-1M、Yelp 和 Electronics 七个数据集上使用 leave-one-out：最后一次交互测试、倒数第二次验证，其余训练；H@5/10/20 和 N@5/10/20 取 5 个随机种子的平均且不做负采样。代表性结果如下：

数据集/指标最强基线PRISM相对提升
Toys H@100.1027（STAR-Rec）0.10633.51%
Toys N@100.0637（FamouSRec）0.06664.55%
Beauty H@100.0946（FamouSRec）0.09965.29%
Beauty N@100.0558（FamouSRec）0.06038.06%
Games H@50.0912（STAR-Rec）0.09928.77%
Electronics N@100.0313（STAR-Rec）0.03233.19%

总体上，PRISM 在七个数据集和全部指标上超过基线，Beauty 和 Games 的收益更明显，说明用户兴趣更分散或跨类关系更多时，多视角关系恢复更有价值。消融结果显示，去掉 SPCL 或 CCL 都会下降，说明 item-level 关系和 sequence-level 偏好不能互相替代；去掉 Dual-View 后，跨组目标表现尤其差。冷启动分析中，当历史长度 T<5 时，PRISM 比 ICSRec 提升 12.44%；长序列从 T<50 增至 T≥300 时，ICSRec 性能下降 50.02%，PRISM 下降 42.99%，表明动态组合视角比固定 prototype 更能应对多兴趣累积。

注意力干预是论文很有说服力的中间证据：对基线模型，提升任何低注意力位置都可能改善预测，提升“低注意力且高因果重要性”的位置又优于盲目提升；对 PRISM，C1-C4 干预带来的置信度变化接近 0 或为负，说明模型已经把因果重要关系纳入注意力。工业规模 Electronics 有 192,403 个用户、63,001 个 item、1,689,188 次交互，PRISM 仍保持最高精度且训练成本低于需要大量 prototype 的 intent 模型。

失败和边界也很清楚。K 过大并不单调变好：Toys 上 K=4 的 N@20=0.0751，K=6 降到 0.0728，K=8 为 0.0744；因此视角数量需要在表达能力和延迟间调优。论文报告的实验均为公开离线数据，没有线上 CTR、延迟 P99 或真实业务 A/B。

5. 局限与未来方向

作者明确报告的内容主要是实验结论与未来工作：PRISM 依赖语义锚点数量 K、λ、温度和 perspective dropout 等超参数，虽然论文做了敏感性分析，但没有给出跨业务自动选择 K 的机制；结论部分指出后续还需要继续研究不同关系视角在更复杂数据上的扩展。论文的 GenAI disclosure 说明 ChatGPT 和 Claude 只用于语法润色与代码重构，方法与实验设计由作者完成。

从部署角度看，还存在作者没有充分展开的限制：公开数据的 item 语义通常比社区 UGC 更干净，真实短文本中的歧义、噪声和快速漂移可能让 PSA 路由不稳定；PRISM 的 O(T²Kd) 复杂度意味着长行为序列和大 K 会直接增加线上成本；同时，attention-importance 的 mask 测试本身是离线诊断，不等于线上因果效果。将其用于 CTR 排序前，需要在流量分层、延迟预算和曝光偏差下复验。

6. 工业实践意义

对社区搜索或推荐，第一步不是立刻把 PRISM 放进全链路，而是用它建立“被忽略关系”诊断集：收集用户短期主兴趣与最终点击/停留内容跨主题的样本，检查普通 attention 是否遗漏了决定性历史行为。若问题存在，可以先在精排或重排阶段加一层共享参数的多视角关系校准，K 从 2 或 4 起步，与原模型做线上 shadow、P99 延迟和内存对照。

方法很适合多兴趣 UGC：一个用户可能同时关注求职、健身和数码；相似性 attention 会把历史压成一个大主题，而 Contrast View 允许不同主题通过桥接行为共同解释目标。训练上保留原 CTR/交互目标，把 SPCL 作为辅助目标，避免直接用它替代业务 label；如果样本存在严重曝光偏差，应在同一训练框架中加校准或反事实加权。

推荐的落地顺序是：离线 attention-importance 审计 → K=2/4 的小流量重排 → 分短历史/长历史、热门/长尾和跨主题 query 分群评估 → 再决定是否升级到全量精排。论文的 K=4 配置在 909K 参数下比 FamouSRec 少参数、训练快约 5 倍，且推理延迟接近 SASRec，是较现实的起点。需要避免的是把离线 H@K 提升直接解释为线上 CTR 提升，也不要在没有桥接关系证据时盲目增加 lens 数量。
