LACONIC: Dense-Level Effectiveness for Scalable Sparse Retrieval via a Two-Phase Training Curriculum

UGC短文本的实体词、口语词和新词仍需要倒排索引的精确命中，LACONIC提供了把语义扩展写回稀疏词项空间的方向。落地时可先以小尺寸模型生成稀疏权重，保留BM25兜底，再用困难负例和query-帖子点击对训练，重点观察索引膨胀、召回延迟与nDCG的折中。

1. 问题与动机

核心问题：学习型稀疏检索（Learned Sparse Retrieval）与稠密检索（Dense Retrieval）之间持续存在的性能差距。

信息检索领域正经历从传统词项匹配（BM25）到神经网络检索的范式转变。当前稠密检索模型（如基于 LLM backbone 的双塔模型）在语义理解上表现优异，但面临严峻的部署挑战：

  • 内存开销巨大：8B 参数的稠密模型在 MSMARCO 上的索引大小达 134.9 GB
  • 依赖 GPU 加速：向量相似度搜索需要 GPU 计算，部署成本高
  • 延迟不可控：大规模语料上的近似最近邻搜索延迟波动大

学习型稀疏检索（如 SPLADE）提供了一条替代路径：生成词汇级别的稀疏表示，可以直接使用传统的倒排索引在 CPU 上高效检索。然而，历史上稀疏检索在效果上一直落后于同等规模的稠密模型。

为什么重要？ 对于工业搜索系统而言，稀疏检索意味着：(1) 可复用现有倒排索引基础设施；(2) 无需 GPU 即可在线服务；(3) 索引存储成本大幅降低。如果稀疏检索能达到稠密检索的效果，将极大降低高质量语义检索的落地门槛。LACONIC 正是要证明这一点。

2. 方法概述

LACONIC（名字来源于斯巴达人的简洁表达传统）是一系列基于 Llama3 架构的学习型稀疏检索模型，提供 1B、3B 和 8B 三个规模。核心方法论是一个精简的两阶段课程训练：

阶段一：预微调（Pre-finetuning）

  • 目的：将因果语言模型适配为双向编码器，建立基础的稀疏模式
  • 数据：Nomic-embed-pretrain-lite（约 900 万弱监督文本对）
  • 训练方式：仅使用 batch 内负样本，全局 batch size 2048
  • 关键操作：直接移除因果注意力掩码，使模型自适应为双向编码

阶段二：微调（Finetuning）

  • 目的：用高质量硬负样本精炼相关性判断能力
  • 数据：RLHN 数据集（69 万三元组）
  • 训练方式：每个 query 配 1 个正样本 + 15 个硬负样本 + batch 内负样本

稀疏表示生成

基于 SPLADE 框架：对每个输入 token 的隐层表示，通过语言模型头投影到词汇表大小的向量，再经 MaxPooling + ReLU + log 缩放生成最终的稀疏文档/查询表示。

3. 核心技术贡献

贡献 1：首次将学习型稀疏检索缩放到 LLM 规模

此前最大的学习型稀疏检索模型是 CSPLADE（8B 参数），但其训练策略复杂且效果有限（BEIR14* 平均 nDCG@10 仅 54.6）。LACONIC 证明，通过简洁的两阶段训练，8B 稀疏检索模型可以达到 61.5 nDCG@10，远超前代。

更重要的是，仅 1B 的 LACONIC 就以 57.6 nDCG@10 大幅超越 SPLADE-v3（51.3）和 CSPLADE（54.6），同时超过了同等参数量的稠密模型 Nomic-v1（53.9）和更大的 Arctic-v2（56.0）。

贡献 2：直接移除因果掩码的简洁适配策略

相比其他将因果 LLM 适配为编码器的方法（如 echo 输入策略、额外的轻量适配层），LACONIC 采用了最简洁的方式：直接去掉因果注意力掩码，让模型在对比训练中自适应学会双向注意力。

这一设计看似简单，但实验证明其有效性：1B 稠密模型仅通过预微调阶段就达到了 48.8 nDCG@10，超过了 E5-base 的完整训练结果（42.9）。

贡献 3：稀疏检索的效果-效率帕累托最优

LACONIC-8B 的索引大小仅 38.8 GB，而同等 8B 参数的稠密模型 RepLlama3 需要 134.9 GB——内存减少 71%（3.5 倍压缩）。同时在检索效果上 LACONIC-8B（60.2 nDCG@10）与 RepLlama3（59.8）持平甚至略优。

这意味着在完全不牺牲效果的前提下，部署成本大幅降低。Seismic 倒排索引还实现了无需 GPU 的高效检索。

贡献 4：极高的数据效率

LACONIC 的预微调仅使用了 900 万文本对，而竞争对手使用了 4.7 亿（Nomic）到 3 亿（Arctic-v2）。在数据量不到竞品 1/30 的情况下，LACONIC 实现了更优的性能，说明两阶段课程训练策略的有效性。

4. 实验结果分析

主实验：MTEB-R 15 数据集

LACONIC-8B 在 MTEB Retrieval 基准上达到 60.2 nDCG@10，截至 2026 年 1 月 1 日排名第 15，是该排行榜上唯一的学习型稀疏检索模型。

消融实验

消融实验在 1B 规模上比较了稠密 vs 稀疏、预微调 vs 微调的组合效果：

关键发现 1：仅预微调后，稀疏模型（42.6）落后稠密模型（48.8），原因是稠密模型天然使用全部隐层维度作为特征，而稀疏模型依赖学习到的少量激活 token 权重。

关键发现 2：经过微调阶段后，稀疏模型（56.0）基本追平稠密模型（56.8），证明了两阶段课程训练对稀疏检索的关键作用——预微调建立稀疏模式基础，微调精炼相关性判断。

关键发现 3：仅微调（无预微调）的稀疏模型表现显著较差，说明预微调阶段对于将因果 LLM 适配为有效的稀疏编码器不可或缺。

5. 局限与未来方向

现有局限

  1. 预微调数据量受限：LACONIC 仅使用了 900 万对训练数据，而竞品使用了 3-5 亿。论文明确指出"我们假设扩大预微调数据可以进一步提升性能"，暗示当前结果可能远非上限。
  1. 数据集选择的启发式方法：从 Nomic 的 4.7 亿数据中选择了 11 个子集构成 900 万对，选择标准是"启发式的 vibe-checking 和计算预算"，缺乏系统性的数据选择方法。
  1. Batch size 受限：全局 batch size 仅 2048，而竞品使用 16K-32K。对比学习通常受益于更大的 batch size，计算资源限制了 LACONIC 的潜力发挥。
  1. 仅支持英文：当前模型仅在英文数据上训练和评测，多语言能力未知。
  1. 序列长度限制：查询截断至 64 tokens，文档截断至 192 tokens。对于长文档检索场景（如法律文书、学术论文全文），可能表现受限。

未来方向

  • 扩大预微调数据规模：系统性地扩展训练数据到数亿级别
  • 多语言和多模态扩展：将 LACONIC 方法推广到多语言和多模态检索
  • 无推理稀疏检索：探索不需要模型推理的稀疏表示生成方法
  • 训练数据混合优化：开发系统化的数据选择策略替代启发式方法

6. 工业实践意义

对搜索系统的直接价值

1. 倒排索引复兴

LACONIC 最大的工业意义在于证明了倒排索引 + 学习型稀疏表示可以达到向量检索的效果。这对于拥有成熟倒排索引基础设施的搜索团队是一个重大利好——无需推倒重来构建向量检索系统，只需替换索引中的词项权重即可获得语义检索能力。

2. 去 GPU 化部署

LACONIC 的在线检索完全可以在 CPU 上运行（使用 Seismic 倒排索引）。对于无法大规模部署 GPU 的团队（成本限制或基础设施限制），LACONIC 提供了一条可行的高质量语义检索路径。

3. 索引存储成本的大幅降低

71% 的索引内存减少意味着：对于十亿级文档语料，存储成本从 TB 级降至百 GB 级。在多副本、多机房部署的场景下，这种节约效果会被放大数倍。

4. 与现有管线的无缝集成

稀疏检索的倒排索引格式与 Elasticsearch、Lucene 等成熟搜索引擎天然兼容。LACONIC 生成的稀疏表示可以直接存入现有索引系统，无需引入向量数据库等新组件。

对推荐系统的启示

5. 召回层的轻量化替代

推荐系统的召回层常用双塔向量模型。LACONIC 表明稀疏双塔可以达到相同效果，且部署更轻量。特别是在用户/物品规模极大时，稀疏索引的存储和检索效率优势更加明显。

关键工程建议

  • 增量部署策略：可以先用 LACONIC-1B（已超越多数稠密模型）验证效果，再逐步升级到 3B/8B
  • 混合检索：LACONIC 稀疏检索与 BM25 可以天然融合（同为倒排索引），形成"传统词项 + 语义词项"的混合检索方案
  • 离线编码并行化：文档编码是离线批处理任务，可以充分利用 GPU 集群并行化，模型大小不构成在线服务瓶颈

总结：LACONIC 的核心贡献是打破了"稀疏检索效果不如稠密检索"的固有认知。通过将 LLM backbone 引入稀疏检索并设计精简的两阶段训练课程，LACONIC-8B 在 MTEB Retrieval 排行榜上达到了与最佳稠密模型平齐的水平，同时索引体积缩小 71%、可在 CPU 上部署。这为工业搜索系统提供了一条"高效果 + 低成本"的新路径——用成熟的倒排索引技术栈获得前沿的语义检索能力。
