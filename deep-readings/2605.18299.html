SD-Search: On-Policy Hindsight Self-Distillation for Search-Augmented Reasoning

4.05
Relevance 4 | Novelty 4 | Practical 3 | Evidence 4 | Timely 5

Summary: 搜索增强推理 agent 在内部推理与外部检索调用之间交替，整条 rollout 只有一个轨迹级 outcome reward，单次 search query 拿不到 step 级信用。已有 process-supervision 方法要么依赖更大的 teacher 模型，要么依赖外部系统标注的子问题。SD-Search 让同一个模型扮演两个只在 conditioning 上不同的角色：student 只看推理时可见的上下文，teacher 额外条件于一段紧凑的 hindsight block（汇总本次 rollout 发出的 search query 与最终成败）。训练时在每个 search 决策点最小化 student 与 teacher 输出分布的 Jensen-Shannon 散度，把 step 级信号叠加到轨迹 reward 上，整个过程在标准 RL 训练 loop 内完成，不需外部 teacher 推理、额外标注或辅助训练阶段。

Key insight: 核心是用 on-policy hindsight self-distillation 做 query 级信用分配：teacher 知道哪些 rollout 成功，其 query 分布隐式标出哪些 search 决策值得做，再用 JS 散度蒸馏回 student。对社区搜索的启示是，用 LLM 做多轮 query 改写或迭代检索时，可用同一模型加后见上下文构造 step 级监督，省掉维护更大 teacher 或人工标注子问题，降低 query 改写策略训练的标注与算力门槛；hindsight block 只传 query 摘要与成败这一极简接口，本身就是一种轻量信用分配设计。

SD-Search 深度解读

1. 问题与动机

搜索增强推理（search-augmented reasoning）agent 在内部 think 与外部 retriever 调用之间交替，性能高度依赖每一次 search query 的质量。问题在于：当前主流用 outcome-reward RL（如 GRPO）训练时，一条 rollout 里所有 search 决策共享同一个轨迹级 reward——"every search decision in a rollout shares the same trajectory-level reward, leaving individual queries without step-specific credit"。后果是一条成功轨迹里的差 query 和好 query 拿到完全相同的梯度信号，反之亦然，step 级信用分配缺失。

已有的 process-supervision 方案（Thinker、StepSearch）确实补了 step 级信号，但代价是引入外部资源：Thinker 需要一个 72B teacher 模型对全训练集做一遍推理再加 SFT 阶段，StepSearch 依赖 GPT-4o 标注子问题。作者的关键观察是：policy 自己只要拿到关于 rollout 结果的"后见信息"，就能在内部产生这些 step 级信号，不需要更大的 teacher，也不需要训练之外的额外标注。这一动机直接对应工业界痛点——多轮检索/query 改写策略训练里，维护一个更大的 teacher 或人工标注子问题的成本极高。

2. 方法详解

双角色（同参数）。 student 只看推理时可见的上下文：对位置 p 的动作 token，student 分布为 πθ(·|τ<p)。teacher 用同一套参数，但额外条件于一个 hindsight block h(𝒢)，其中汇总了同一问题采样的一组（group size G=5）sibling rollouts 的 search query 与 outcome label。

Hindsight block 内容。 对每条 sibling rollout τⱼ，block 含两部分：(a) 掩码视图 ℳ(τⱼ)，只保留 search span，用"future masking"剥掉 think、检索文档、answer；(b) 二元 outcome label y(τⱼ)∈{Correct, Incorrect}，由 F1 阈值（ρ=0）导出。future masking 的必要性被消融证明：若 teacher 看到检索文档和后续 think，gold answer 会从 hindsight 前缀里被直接抽出，导致分布崩塌——去掉 future masking 掉 3.0 EM（在 2Wiki 多跳上掉 4.7）。

JS 散度目标。 只在 search-query token 集合 𝒬τ 上施加 token 级损失：ℒ_SD(τ)=(1/|𝒬τ|)Σ JSD(P^tch_p ∥ P^stu_p)。选 JSD 而非 KL/MSE 的理由是对称（避免 mode-seeking/covering 偏置）且有界（≤log2，提升稳定性），分布只取 top-k=50 token 提效。消融显示：forward KL −1.0、reverse KL −1.4、MSE −2.1 EM；把作用域从 𝒬τ 扩到全部动作 token 𝒜τ −0.7 EM。

与轨迹级 reward 结合。 总损失 ℒ_total=ℒ_GRPO+α_SD·ℒ_SD，两项互补：GRPO 用 advantage 提供粗粒度轨迹级强化，ℒ_SD 用直接分布匹配提供稠密 token 级监督。

训练配置。 base 模型 Qwen2.5-3B/7B（base 与 instruct）；GRPO，group size 5；训练集 NQ+HotpotQA 合并，评测 7 个 QA 基准（3 单跳 4 多跳）；actor lr 1e-6，200 步，KL 系数 β=0.001，clip ε=0.2；SD 专属超参 α_SD=1e-3、warmup 50 步、top-k=50、outcome 阈值 ρ=0；检索器 E5-base-v2 + 2018-12 Wikipedia，每 query 取 3 文档；硬件 8×H800。

3. 核心技术贡献

(1) on-policy hindsight self-distillation 框架：用 policy 自身在标准 RL loop 内产生 search 决策的 step 级监督，不需外部 teacher、不需 outcome-reward 训练以外的标注。机制是"teacher 知道哪些 rollout 成功，其 query 分布隐式标出哪些 search 决策值得做"，再蒸馏回 student。

(2) token 级 JS 目标：在每个 search step 把 policy 的 query 分布对齐到"后见条件下"的分布。相比 KL，JSD 的对称+有界特性带来 1.0–2.1 EM 的稳定收益（消融实证）。

(3) 规模化验证：在 3B/7B 两个尺度、7 个基准上一致优于 outcome-reward，并匹配或超过依赖外部 teacher 的 process-supervision 基线。相比 AutoRefine-Base，3B 提升 +2.3、7B +2.1，多跳收益更大。

4. 实验结果分析

3B 尺度（Table 1，Avg EM）：AutoRefine-Base 0.405、MR-Search-Base 0.414、Thinker-Instruct（72B teacher+SFT）0.430、SD-Search-Base（纯 RL）0.428——即不用外部 teacher 就追平了最强 process-supervision 基线，比 AutoRefine-Base 高 2.3、比 MR-Search-Base 高 1.4。多跳收益更明显：Bamboogle +5.8、MuSiQue +3.1、2Wiki +2.7，作者归因于更稠密的 per-step 监督与轨迹内方差。

7B 尺度（Table 2）：SD-Search-Instruct 0.476，超 Thinker-Instruct 2.4 点；值得注意的是 7B 上 Thinker 相对 AutoRefine 的增益转负（−0.3），而 SD-Search 仍 +2.1。Scaling 分析（1.5B/3B/7B/14B）：SD-Search 增益 +2.5/+2.3/+2.1/+0.9，全程为正；Thinker 增益随规模单调缩小并从 7B 起转负——说明外部 teacher 蒸馏在大模型上反而拖累，而 on-policy 自蒸馏更稳。

消融（hindsight block）：去掉 outcome label −1.4；打乱 label −2.3（比直接删更差，说明 label 必须正确而非仅占位）；去 future masking −3.0；leave-one-out（teacher 只看 siblings 不看本条）−0.5。超参敏感性（Figure 4）各默认值都在曲线峰附近，波动 <2.5 点，调参鲁棒。局限是 14B 上增益收窄。

5. 局限与未来方向

作者明确两点局限（Section 4）：(1) 可评分性要求：hindsight 对比依赖由 gold answer 导出的 outcome label，方法被限制在有可靠参考答案、可打分的任务；开放式生成需要换成学习的偏好分数或多数投票代理。(2) label 同质化退化：当一组 rollout 的 label 全同时对比信号消失——全失败时与 GRPO 一样崩，全成功时对比被抹平；这正是 14B 上增益收窄的原因（base 成功率高使 group 内全 Correct 更频繁）。一个作者未展开但明显的方向是：把二元 label 换成连续/分档 reward，或对 group 采样做难度平衡以缓解同质化。

6. 工业实践意义

对社区搜索/UGC 检索的 LLM query 改写与多轮检索策略训练，SD-Search 提供了一条低成本路径：用同一个 policy + 后见上下文构造 step 级监督，省掉维护更大 teacher 或人工标注子问题。该采用的：JSD 而非 KL 作对齐目标（对称有界、收益 1–2 EM 且更稳）；future masking（不掩码会让 teacher 泄漏答案、掉 3 EM）；只在 search-query token 上施加蒸馏（扩到全 token 反而 −0.7）。该试的：把 hindsight block 的"query 摘要+二元成败"接口迁移到自家 RL 改写管线，作为轻量信用分配层。部署考量：训练端到端 wall-clock 仅 +15.5%（8×H800，11.9h vs 10.3h），其中 teacher forward+JSD +22% step 时间、SD backward +17.5%，rollout/PPO/optimizer 基本不变；推理成本完全不变（teacher forward 仅训练时用且 stop-gradient）。相较 Thinker 需 72B 全集推理+SFT、StepSearch 需 GPT-4o API，SD-Search 的开销全部包在标准 RL loop 内，对算力有限的搜索团队尤其友好。需注意其前提是任务可打分——社区搜索相关性可用线上点击/人工标注代理 outcome label，但要警惕 label 同质化（高基线成功率场景对比信号会变弱）。
