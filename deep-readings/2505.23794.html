R3-RAG: Learning Step-by-Step Reasoning and Retrieval for LLMs via Reinforcement Learning

R3-RAG 的核心创新在于将 RL 引入 RAG 的推理-检索循环训练。对搜索系统的启示：传统 RAG 的检索策略是固定的（retrieve-then-read），而 R3-RAG 让模型自主学习何时检索、检索什么，形成动态检索策略。过程奖励的设计思路可迁移到搜索排序模型的训练中。

1. 问题与动机

现有 RAG 系统的核心瓶颈在于检索策略的固化：稠密检索器参数有限且不具备推理能力，而迭代 RAG 方法（如 ReAct、FLARE、IRCoT）依赖人工设计的固定工作流模板，无法充分发挥 LLM 的能力。具体而言，面对需要多跳推理的复杂查询（如"哪部电影的导演出生更早"），现有方法要么一次检索所有信息（容易遗漏），要么按固定模式迭代（不够灵活）。R3-RAG 的核心洞察是：让 LLM 通过强化学习自主学习何时检索、检索什么、以及何时停止检索，而非遵循预设的工作流。

2. 方法详解

R3-RAG 采用两阶段训练架构：

第一阶段：冷启动（Cold Start）。 使用 DeepSeek-V3 生成监督数据，产出 51,254 条推理-检索交错的轨迹（trajectory）。每条轨迹由多个步骤组成：每步包含推理过程（xi）、检索查询（psi）和检索到的文档（d），最终步骤生成答案。通过拒绝采样仅保留正确答案的轨迹，对基础模型（Llama-3.1-8B 或 Qwen2.5-7B）进行 SFT，得到 R3-RAG-CS 检查点。

第二阶段：强化学习优化。 使用 8,192 条 HotpotQA 样本进行 PPO 训练。核心创新在于双奖励机制的设计：

  • 结果奖励（Outcome Reward）：结合字符串匹配和 LLM 语义判断，评估最终答案的正确性（0/1 二值）。
  • 过程奖励（Process Reward）：使用 LLM 对每步检索到的文档与问题的相关性打分（0-1 连续值，0.1 精度），为中间检索步骤提供细粒度反馈。
  • 格式奖励：二值奖励，确保输出格式合规。

最终奖励公式：r(s_ij) = Val(s_ij) * (Acc(a_i) + Rel(d_ij)) + Val(s_ij) - 1。关键设计是引入轨迹依赖因子 lambda_T：正确轨迹的奖励被放大（lambda > 1），错误轨迹被抑制（0 < lambda < 1）。

PPO 训练参数：Actor 学习率 5e-7，Critic 学习率 9e-6，使用 GAE 进行优势估计，KL 散度约束防止策略偏移过大。

3. 核心技术贡献

贡献一：首创过程奖励+结果奖励的双奖励 RL-RAG 框架。 与仅使用结果奖励的 ReSearch 相比，过程奖励提供了中间步骤的梯度信号，引导模型学习更好的检索决策。消融实验显示移除过程奖励导致 1.4 个百分点下降，移除结果奖励再下降 3.6 个百分点。

贡献二：冷启动+RL 两阶段训练策略。 纯 RL 训练面临探索空间过大的问题，冷启动阶段通过 SFT 给出好的初始策略，使 RL 阶段可以在此基础上进行有效探索和优化。

贡献三：跨检索器强迁移性。 仅用 E5 检索器训练的模型，在 BGE 和 BM25 上的性能波动不到 3%（IRCoT 波动超过 20%），说明模型学到了检索器无关的推理策略。

4. 实验结果分析

主要结果（Llama-3.1-8B, Accuracy）：

方法HotpotQA2WikiMuSiQue平均
IRCoT52.8%40.6%16.7%36.7%
ReSearch54.2%47.8%24.8%42.3%
R3-RAG-CS59.6%56.2%29.0%48.3%
R3-RAG64.4%61.0%32.2%52.5%

R3-RAG 平均超过最强基线（IRCoT）约 15 个百分点。Qwen2.5-7B 上趋势类似。

效率分析： R3-RAG 使用的 token 数比 ReSearch 少 22.8%（2Wiki 上少 24.6%），说明过程奖励引导模型进行了更精准的检索，避免了无效查询。

泛化性分析： 推理步数实验显示，即使评估时使用超过训练时的最大步数（5步），性能仍持续提升（最高到10步），表明模型学到了通用的迭代推理能力。

检索器迁移： E5 训练 → BGE 评估：65.3%（反而优于 E5 的 64.4%），BM25 评估：62.5%。对比 IRCoT 在不同检索器间 20+ 个百分点的波动，R3-RAG 仅 3% 波动，具有显著的工程实用价值。

5. 局限与未来方向

论文提及的局限： (1) 实验仅使用学术数据集（HotpotQA、2WikiMultiHopQA、MuSiQue），缺乏真实产品级查询的多样性验证。(2) 冷启动阶段依赖 DeepSeek-V3 生成轨迹，部分困难样本无法生成可靠轨迹，使用更强的模型（如 DeepSeek-R1）可改善这一问题。

未提及的局限： (1) PPO 训练的计算成本和稳定性问题未详细讨论。(2) 过程奖励需要 LLM 对每步检索结果评分，训练时的成本较高。(3) 未测试在开放域（非维基百科）检索语料上的表现。

6. 工业实践意义

直接应用场景： 对于需要多跳推理的搜索任务（如复杂问答、对比查询、因果链推理），R3-RAG 的训练框架可直接应用。其 8K 样本 RL 训练即可获得显著提升，数据效率较高。

过程奖励的迁移价值： 过程奖励的核心思想——对检索中间结果的相关性提供反馈——可迁移到搜索排序模型的 RLHF 训练中。例如，在多轮搜索场景中，不仅奖励最终点击行为（结果奖励），还奖励中间检索步骤返回了相关结果（过程奖励）。

检索器迁移性的工程意义： R3-RAG 的跨检索器迁移性意味着训练好的推理策略可在更换检索后端时复用，降低系统升级的重训练成本。

部署建议： (1) 冷启动阶段可用现有商用 LLM 生成训练数据，降低人工标注成本。(2) 推理时的迭代步数可通过延迟预算动态控制——简单查询 1-2 步，复杂查询允许更多步。(3) 过程奖励模型可简化为基于检索分数的规则（而非 LLM 评分），降低训练成本。
