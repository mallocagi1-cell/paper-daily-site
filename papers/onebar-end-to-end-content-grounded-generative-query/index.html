1. 问题与动机

短视频播放器下方的"可点击搜索入口"（bottom-bar query）要把用户从被动观看引导到主动搜索，但它的在线预算极其苛刻：整条链路只有 20–30ms。传统多阶段级联（MCA：召回→过滤→排序）为了塞进这个预算，只能依赖离线预计算的候选 query 池，于是被迫在 query 新鲜度、语义相关性与服务效率之间做取舍——无法利用当前视频的实时上下文，对新发布视频和长尾 query 表现差，且各阶段目标割裂、难以联合优化。近期的生成式方案虽然能端到端出 query，却又受 content 侧噪声元数据（标题党、boilerplate）和偏好漂移困扰。OneBar 的目标就是用单次生成替换 MCA：既要抓住视频内容诱发的即时意图，又要守住在线延迟，还要能在没有安全/相关 query 时主动弃权（abstain）。这是快手电商单列信息流的真实生产问题。

2. 方法详解

OneBar 把每个触发视频抽象成结构化证据 ℰ(x,u) = ⟨Tx, Mx, Ax, Hu⟩：Tx 是清洗后的文本元数据（去掉 @、话题标签、模板词）；Mx 是多模态基础模型每日刷新的视频摘要（视觉物体、OCR、语音、场景、商品使用）；Ax 是协同 anchor，由一个行为对齐的 embedding 模型（Qwen3-Embedding 0.6B，在 query→video 搜点日志、video→query 看后搜、query→query 改写三种关系上训练）做 ANN 召回 query anchor，再加同触发的 RAG 历史 query，阈值 0.88 过滤把命中率从 0.282 抬到 0.335；Hu 是按触发相关性（而非长期兴趣）筛出的用户历史 query。

证据用 [SEP] 拼成紧凑序列 sx = [Tx;[SEP];Mx;[SEP];Ax;[SEP];Hu]，喂给 BART encoder-decoder；解码 pθ(y|sx)=∏ pθ(yt|y<t,Enc(sx))，输出要么是一条 query，要么是特殊 token [REJECT] 主动弃权。这个紧凑 schema 比冗长指令式 prompt 显著更好（HR@8 0.3564 对 0.1864），与 BART 的文本重建预训练目标对齐。

训练分三阶段递进内化偏好：Stage I 内容 grounded SFT，在点击 query 对上做标准 SFT，并把违规内容样本映射到 [REJECT] 学会何时弃权；Stage II 行为反馈偏好对齐，把同触发候选按 6 个行为档（点击+互动 > 仅点击 > 人群点击+互动 > 人群点击 > 曝光未点 > 召回未曝）组织，用 list-wise Softmax DPO（β=0.1, T=1.0, λ_SFT=1.0）拉开偏好；Stage III 偏好内化的 on-policy 蒸馏（PIOPD），不另训 reward model，而是把点击 query y_ref 随机插进 teacher 输入、student 只看普通触发并 on-policy 采样轨迹，teacher 在 student 访问到的状态上给软分布，用双向 KL（前向 KL 覆盖 teacher 支持的备选、反向 KL 抑制无依据 token，τ=2）+ 熵正则 + R-Drop + FGM 对抗扰动联合优化。关键是训练后 teacher 和 y_ref 全部丢弃，只留不依赖 y_ref 的 student，在线接口不变。训练规模：Stage I 6 epoch、batch 128、lr 1e-5；Stage III 500 步、batch 64、lr 1e-6。

3. 核心技术贡献

(1) 协同-多模态意图锚定：把"视频内容理解"与"行为派生的协同 anchor"显式拼进生成证据，直接解决生成式 query 推荐的 content 侧噪声问题——消融里多模态特征单独就带来 +70% HR@8，是最大增益来源。(2) 紧凑 [SEP] 证据 schema 而非自然语言 prompt：与 BART 重建预训练对齐，相对冗长 prompt 提升 +91% HR@8，且更省 token、利于压进延迟预算。(3) 带 [REJECT] 的弃权机制：把安全/风控直接学进生成模型，线上风控类 bad-case 降 4.33pp。(4) PIOPD 三阶段渐进训练：用 on-policy 蒸馏把后验点击信号内化进 policy，既不需在线 reward model，又保持服务接口不变；Stage II 重整分布给 Stage III 提供更好起点，完整 I→II→III 在 MRR@8 上优于跳过 Stage II（0.2402 对 0.2397，且远好于单独 Stage II 的 0.1789）。

4. 实验结果分析

离线用约 4000 万条带底栏 query 的 PV（2026-04-09 至 04-16，7 天）训练。主表（Table 3）OneBar 完整版 Stage III：Exact HR@8 0.3690、MRR@8 0.2402、ED-HR@8 0.4934、BLEU@8 0.5039，全面碾压 ANN 检索（HR@8 0.1322）、zero-shot GLM5.1（0.0153）、GPT-5.5（0.0224）——说明这个任务靠通用大模型 zero-shot 远远不够，必须用行为数据做内容 grounded 训练。消融拆得很清楚：基础触发 HR@8 0.1787，+多模态→0.3046（+70%），+协同→0.3357（+10%），+个性化→0.3564（+6%），多模态是绝对主力；prompt 格式上 [SEP] schema 0.3564 对冗长 prompt 0.1864（+91%）；PIOPD 里 FKL+RKL 双向（0.3690）优于单独 FKL（0.3662）或 RKL（0.3626），且全词表蒸馏优于 top-k。证据缺失分析显示 caption 在场比缺失 HR@8 高约 24.5%。线上在快手单列电商视频流做 7 天 A/A + 8 天 A/B（9.12% 对 9.12% 流量）：query 曝光 +16.91%、query 点击 +18.68%、query CTR +0.19%、引导订单 +20.36%、引导 GMV +21.67%；400 条人工评测整体 bad-case 率降 9.00pp（视频-query 不相关 -3.66pp、风控类 -4.33pp）。分层分析显示 30 天内新视频 CTR 提升尤为明显，各活跃度档（U0–U4）均为正向。

5. 局限与未来方向

作者未单列局限章节，但从方法可读出几条隐含约束：多模态摘要是每日刷新而非实时，对刚发布、行为稀疏的冷启动视频，协同 anchor 证据不足；[REJECT] 弃权在降低风控 bad-case 的同时也牺牲了一部分曝光机会，弃权阈值是相关性与安全的权衡；PIOPD 训练阶段需要后验的点击 query 作为 teacher 注入信号，对标注/日志回流有依赖。可延伸方向包括把多模态摘要做到近实时以救冷启动、对 [REJECT] 阈值做收益敏感的动态调节，以及把行为档位与蒸馏温度做自适应。

6. 工业实践意义

对搜索/推荐从业者，OneBar 给了一套"在 20–30ms 预算内用单次生成替换多阶段级联"的完整可复制范式。最值得借鉴的三点：其一，证据工程比模型规模更关键——多模态摘要单项贡献 +70%，说明把视频/内容理解结果结构化喂进生成器，收益远大于堆参数；其二，紧凑 [SEP] 证据 schema 对齐 BART 重建预训练，相对自然语言 prompt 提升 +91% 且更省 token，对延迟敏感的在线生成是直接可抄的工程选择；其三，离线缓存（视频 embedding、RAG 历史、多模态特征进 Redis）+ 在线只跑 BART beam search（width=8）+ 去重 + 规则校验的混合架构，是把生成式模型塞进搜索链路的务实路线。社区搜索的"搜索发现/猜你想搜"位可直接迁移：用内容理解生成候选 query，用行为档位做偏好对齐，用 [REJECT] 把风控前置进模型，并用 PIOPD 这种不改服务接口的 on-policy 蒸馏持续日更。需要注意的是该方案重度依赖行为日志与多模态特征管线，中小团队落地的前置成本不低。
