1. 问题与动机

论文研究的不是静态 ANN 召回率，而是生产向量索引在持续增删时何时维护。HNSW、DiskANN/Vamana 依靠可导航近邻图做贪心搜索；删除节点通常先留下 tombstone，节点虽然不再返回，但原本经过它的搜索路径被截断，长期抖动会降低 recall@10。FreshDiskANN 一类系统通常按删除列表或操作数固定周期 consolidation：物理移除墓碑，将被删节点的入邻居重新连向出邻居，再按相对邻域规则剪边。固定时钟不观察实际退化，因此一个自然假设是：用小型探针查询实时估计导航质量，只在信号下降时修复，也许能用同样预算取得更高的尾部召回。

这篇 v2 的价值恰恰在于推翻作者自己的 v1。v1 声称信号触发策略在匹配预算下胜过固定周期，并把探针召回称为领先指标；但它没有在结论所在的“一次 consolidation”预算点真正运行固定周期基线，而是在 0 次和 4 次之间线性插值。真实响应曲线高度凹，一次维护已拿走 53.7% 的总收益，线性插值却只分配 25%，因此人为压低了基线。与此同时，v1 用两个同步下降序列的水平相关性证明领先性，而预注册要求的是信号与后续召回跌幅的相关性。论文由此把问题从“新控制器是否更好”扩展成更普遍的系统实验问题：在饱和型资源曲线上，怎样保证 matched-budget 比较真的匹配。

2. 方法详解

作者在同一 DiskANN Vamana 动态索引和同一操作流上比较三种策略。P0 只做惰性删除、不修复，作为下界；P1 每隔 c 次更新固定 consolidation；P2 在探针 recall@10 相对最近一次修复后的基线下降阈值 δ 时 consolidation。探针集合与正式评测 query 完全隔离，每个窗口重新计算，属于不依赖引擎内部统计的黑盒信号。正式指标不是对初始静态真值计算，而是在每个窗口对当前 live set 重新暴力求精确近邻，避免把合法删除导致的真值变化误当成索引漂移。

修正后的预算匹配协议是关键算法步骤。先对 P2 的每个阈值运行操作流，记录其实际触发次数 m；P1 只依赖更新计数，因此无需访问索引即可模拟 cadence，再用二分搜索找到在同一流上恰好触发 m 次的 c；最后必须真正运行这个 P1，而不是从其他预算点拟合。作者同时报告 pass count、清理 tombstone 数量和 wall time，因为相同 pass 数不等于相同工作量：P2 在相同次数下清理的 tombstone 是 P1 的 0.77–2.59 倍，30 个比较中有 28 个超出预注册的 ±5% 预算带，尽管 wall time 比值较接近，为 0.70–1.09。

实验固定 diskannpy 0.7.0，单线程构建以降低随机性。数据为 ann-benchmarks 的 SIFT-128 与 Fashion-MNIST-784，距离均为 L2；基础 live set 分别为 2 万与 1 万点，操作流约产生 10 倍周转，并交替出现删除密集 burst 与插入平静期。默认图 degree R=16，同时扫描 R=16、24、32；每种配置用 4 个 stream seed 计算 95% t 置信区间。扩展实验把 SIFT 放大到 10 万 live points、60 万 churn operations。

四个预注册负控也被真正实现：静态无 churn 时，4 个 seed、9 个策略的最大漂移为 0，信号触发 0 次；只插入时信号仍触发 28 次，相当于含删除流 37 次的 76%，暴露其会把增长误判为退化；预算奇偶负控失败并直接否定主结论；oracle 校验中动态索引与新建索引 recall@10 差为 0.0000，删除真实最近邻后召回从 0.9510 降至 0.8970，维护恢复到 0.9705，证明 harness 确实能测到修复作用。

3. 核心技术贡献

第一项贡献是一个可信的负结果：按实际 consolidation 次数匹配后，信号触发 P2 在两个数据集、三个图 degree 和 5 倍规模上都没有稳定超过固定周期 P1。该结论不是“修复无用”；P0 在 SIFT R=16 上最低 recall@10 漂到 0.9335、Fashion-MNIST 漂到 0.92，consolidation 确实恢复召回。被否定的是更窄的主张——廉价 probe recall 能比时钟更好地安排相同预算。

第二项贡献是可执行的预算奇偶协议。论文说明匹配次数只是必要条件，边修改数、墓碑清理量和耗时仍需并列记录。对于缓存容量、采样预算、重建次数等同样呈边际收益递减的系统实验，这个协议比换一条拟合曲线更根本：目标预算点必须实际运行基线。

第三项贡献是识别“插值基线陷阱”。SIFT 的固定周期最低 recall@10 从 0 次的 0.9348 提升到 1 次的 0.9583、2 次 0.9668、3 次 0.9712；第一步已捕获总增益的 53.7%。在这段凹曲线上从 0 到 4 次拉直线，会低估一次维护约 1.6 个 recall 点，比 v1 宣称的 1.34 点优势还大。

第四项贡献是开放、可审计的实验资产：实时 live-set 精确 oracle、bursty churn runbook、四个负控、预注册、claims.yaml 到 artifact key 的绑定，以及一条命令复现。这里的技术创新不只是控制器，也包括让研究结论能够被自身推翻的测量基础设施。

插值列几乎系统性偏正，而直接比较没有一个置信区间排除 0；全实验最大的直接正效应只有 +0.0016，远低于预注册的 0.02 成功门槛。图 degree 消融也没有挽救方法：R=16 的最佳差值为 +0.0016±0.0019，R=24 为 +0.0010±0.0040，但该 degree 的最差点达到 -0.0128±0.0006，显著偏向固定周期；R=32 的最佳点已是 -0.0001±0.0008。数据支持“稀疏图更易漂移”，却不支持“越易漂移越适合探针触发”。

5 倍规模实验进一步排除了小索引偶然性：10 万 live set、60 万更新、R=16 下，四个阈值的直接点估计全部为负，最好也只有 -0.0008±0.0083。13/16 个比较仍超出 ±5% spend parity 带，说明仅按 pass 匹配甚至对 P2 偏宽松。

机制检验同样失败。v1 报告 probe signal 与真实 recall 水平的 Spearman 相关约 0.95，当前与领先一窗口分别为 0.952 和 0.947，二者几乎一样，符合共同下降趋势而非领先关系。按预注册改测信号与未来召回跌幅后，|ρ| 只有 0.011–0.362；16 个 seed/lag 单元中 0 个达到 |ρ|≥0.6 成功线，14 个落在 |ρ|<0.3 的明确否定区。

5. 局限与未来方向

作者明确强调，负结果不是不存在有效触发器的证明。实验只有两个视觉向量数据集、一个 bursty churn 生成器、一个黑盒 probe-recall 信号、三个 graph degree、4 个 seed 和 per-window minimum 这一种尾部统计；图内部连通性、入口可达性或局部 orphan 计数等需要引擎埋点的信号仍可能更好。SIFT 与 Fashion-MNIST 也不同于真实 UGC 语义 embedding 的聚类、热度和删除模式。

预算定义仍不完美。pass count、墓碑数、边修改与 wall time 不能互相替代，论文虽并列报告，但没有统一成生产总成本；而 P2 在保留微小名义优势的一次维护点会清理 1.34–2.59 倍墓碑，本身就不预算中性。更大规模实验只到 10 万 live points，离亿级索引较远。v1 的原始大规模配置缺少 seed、burst block 等记录，无法完全复原，也说明实验元数据治理仍有改进空间。未来应在真实查询分布、分片索引和多种动态工作负载上，用实际 CPU、IO、延迟与边更新数共同约束优化。

6. 工业实践意义

对社区搜索，第一条结论是继续把固定周期 consolidation 作为强基线。除非触发器在真实预算相等、多个 churn regime 和多个 seed 上稳定胜出，不要仅凭 probe recall 与总体召回同步下降就上线自适应维护。可先离线回放帖子发布、删除、审核下架和 embedding 重算日志，建立 P0/P1/P2 三路 shadow index，并用当前 live corpus 每个窗口重算小规模精确真值。

第二，维护实验必须登记至少四种预算：实际 pass 次数、清理 tombstone 数、边修改数和 wall time/CPU；若线上还涉及 SSD 写放大、cache miss 与查询 P99，也应加入约束。对于 ANN 参数、候选数、重排深度和缓存大小，任何“相同成本”结果都应在目标点直接运行对照，特别警惕 0 到少量资源的凹曲线。

第三，论文的负控可以直接变成上线前测试。静态流应零漂移零触发；只插入流不应频繁触发删除修复；人工 orphan fixture 必须能被 oracle 捕捉并被 consolidation 恢复；预算偏差超出预注册带时，主结果自动判无效。把这些检查固化到 CI，比事后从漂亮曲线解释机制更可靠。

最后，复杂触发策略仍有探索空间，但应优先寻找真正领先的结构信号，如入口节点可达性、被删节点桥接中心性、局部连通分量变化或路径长度分布，而不是同步质量水平。线上策略还可采用保守混合设计：保留固定最大间隔作为安全网，只有结构信号通过阈值时提前维护；通过 shadow traffic 验证 recall@10、P99 延迟、写放大和资源成本后再逐步放量。
