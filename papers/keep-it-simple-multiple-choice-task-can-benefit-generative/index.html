Keep it Simple!：不改码本，用多选辅助任务补齐生成式推荐的比较信号

论文：Keep it Simple! A Multiple-Choice Task can Benefit Generative Recommendation（arXiv:2611.19320，NTU & Coupang）

基于 Semantic ID（SID）的生成式序列推荐自 TIGER 提出后，后续工作主要沿两条工程开销较高的路线演进：一条是改造 RQ-VAE tokenizer 以融入协同信息（如 LETTER、ETEGRec），另一条是接入预训练 LLM 并叠加多阶段语义对齐任务（如论文在相关工作中讨论的 LC-Rec 等路线，本文实验不涉及 LLM 架构）。这篇来自台大与 Coupang 的工作提出了一个更克制的问题：如果保持 RQ-VAE 码本和 Encoder-Decoder 架构不变、不依赖预训练语言模型权重，仅在自回归训练中加入一个多项选择辅助任务，能否直接补齐正负例之间的比较信号，并让原生 TIGER 逼近甚至追平重训练 tokenizer 的方法？

单目标自回归训练的信号盲区

在标准的序列推荐设定下，记用户集合为 U、物品全库为 I。对每位用户 u∈U，用 Su​ 表示其训练交互按时间切分出的全部历史前缀序列集合，其中一条历史序列 su,t​=[iu,1​,…,iu,t−1​]∈Su​ 对应时刻 t 的目标下一物品 iu,t​∈I。TIGER 一类的生成式模型先用预训练语义编码器提取物品文本向量，再通过 m 层 RQ-VAE 将每个物品量化为离散码序列 (qu,t1​,qu,t2​,…,qu,tm​) 作为 SID；训练时把历史序列展开为 SID token 串送入 Encoder-Decoder，以逐层码字的负对数似然优化主任务：
Lmain​=−u∈U∑​su,t​∈Su​∑​l=1∑m​logP(qu,tl​∣qu,t<l​,su,t​)
虽然 m 层码本的条件概率乘积隐式定义了全库物品分布（解码每步只在当前层的有限码本词表上做 softmax），但这一目标与推荐排序里 BPR 强调的「正负例相对比较」存在明显错位。训练过程中，Encoder 始终只看到「历史序列 → 单个正样本」的固定映射，从未在同一上下文里被要求显式区分正例与负例。在交互极度稀疏的语料上，模型容易记住高频共现路径，却难以泛化到训练集中极少共同出现的物品组合。论文举了一个典型场景：对吉他感兴趣的用户往往买吉他配件而极少买管弦乐器，但由于两者同属乐器且文本元数据相近，预训练语义赋予它们的 SID 表示天然接近；如果训练分布里缺乏这类易混淆组合的对比暴露，模型在面对跨意图或语义相近但行为分化明显的物品时就容易误排。相比在输出端额外设计负采样排序损失或重写 tokenizer，一个不改模型结构、不增对齐超参的做法，是直接把负例和正例一起放进输入端，让同一个 Encoder-Decoder 在训练期兼做「多选题」。

多选辅助任务的极简接入方式

作者在原生 TIGER 上只引入了三个可学习的独立特殊 token：p1​ 标识主任务，p2​ 标识多选辅助任务，p3​ 用于分隔历史序列与候选集合。对每条训练样本 (su,t​,iu,t​)，系统在每个 epoch 动态构造规模为 nc​ 的候选集 cu,t​=negu,t​∪{iu,t​}，其中 nc​−1 个负例从排除当前历史前缀与当前目标的集合 I∖(su,t​∪{iu,t​}) 中均匀采样（需注意原文公式仅排除时刻 t 及之前的交互与当前目标，并未排除该用户时刻 t 之后的未来交互）。采出负例并混入正例后，先将这 nc​ 个候选物品随机打乱，再按打乱后的候选顺序把每个物品展开为自身的 m 位 SID token，逐一串接为 cu,t​=(c1​c2​…cnc​​)。两路输入共享同一套 Encoder-Decoder 参数与解码目标（均为真实下一物品 iu,t​ 的 SID）：
Inputs={[p1​, su,t​],[p2​, su,t​, p3​, cu,t​],​主任务（训练 + 验证/推理）多选辅助任务（仅训练）​,L=Lmain​+Laux​
其中 Laux​=−∑u∈U​∑su,t​∈Su​​∑l=1m​logP(qu,tl​∣qu,t<l​,su,t​,cu,t​)。在每个训练 epoch 内，每条历史序列会以主任务和辅助任务各出现一次，再将两类样本混合后随机组成 batch 更新参数。这套设计的工程好处很直接：一方面，两路任务共享完全相同的解码目标，能够降低多任务优化目标冲突；另一方面，验证与推理阶段彻底剥离辅助任务，只输入 [p1​,su,t​]，在合法 SID 前缀树（trie）约束下执行受限束搜索（constrained beam search，确保解码出的每条 token 序列都对应物品库中的真实 SID），无需构造候选集，相比原版 TIGER 仅在编码端多出 1 个前缀 token p1​ 与词表中的 3 个特殊 token embedding。

由于辅助任务在推理阶段完全不出现，一个自然的问题随之而来：训练期额外做多选题，凭什么能改善推理期在无候选提示下的全库生成表现？论文从信息论和组合泛化两条线索给出了机理推演。

辅助任务反哺全库表示的机理

先从信息论视角看，论文将历史序列随机变量记作 S、目标正例记作 I+、候选集记作 C={I+,I−}（其中 I−={I1−​,…,Inc​−1−​}），并将多选任务的隐表示记作 G=g(S,C)。在信息瓶颈视角下，多选任务要求模型在给定 C 时选出 I+ 并抑制所有负例 I−，作者将其写作带隐式拉格朗日乘子 β 的优化目标：
gmax​[I(G;I+∣C)−βI(G;I−∣C)]
论文进一步假设，由于主任务同时在最大化 I(G;I+)，收敛时会满足 βI(G;I−∣C)≪I(G;I+∣C)，此时负例 I− 可视作输入端的结构化噪声扰动，促使共享表示函数 g(⋅) 对无关项保持鲁棒，从而也更抗用户历史序列中的噪声交互。不过从严格数学口径看，这一段推演更偏向定性直觉而非严密证明：一方面，给定集合 C={I+,I−} 后 I−=C∖{I+} 与 I+ 构成确定性双射，恒有 I(G;I−∣C)=I(G;I+∣C)，因此不等式 βI(G;I−∣C)≪I(G;I+∣C) 无法靠优化 g 实现，只能平庸地依赖 β≪1；另一方面，主任务输入实际为无候选集的 g(S) 而非 g(S,C)，对候选池噪声的鲁棒性如何通过共享权重迁移为对历史序列噪声的过滤，这一步仍缺少把迁移机制写清楚的形式化桥梁。

相比信息论推演，论文从组合泛化角度给出的解释更贴近实际训练过程：论文以「把稀疏数据中几乎不共现的物品放进同一个 Encoder 自注意力窗口」来解释模型如何接触跨意图组合。但辅助任务的损失仍是正例 SID 的生成损失，现有候选集遵循率还不能把正负例比较与「从候选段复制某个 SID」区分开。这一组合泛化思路还引出一个可直接验证的特例——当 nc​=1（即 negu,t​=∅，候选段只包含正确答案本身）时，辅助任务退化为「答案记忆任务」。作者认为，训练标签在未来会成为历史输入的一部分，而标准单目标训练常忽略 (su,t​,iu,t​) 在编码端的正例共现关系，因此即便没有负例，nc​=1 也能带来收益。这里需要补充一个细微前提：在标准多前缀训练中，除用户最后一条训练样本外，前序目标原本就会在下一步进入编码端；单目标训练真正未覆盖的是「最后一条训练标签（会在验证/测试时滚动进入历史输入）」以及「同一步内历史与目标共处编码上下文的直接共现」，原文对该机制的表述仍偏直观，未拆解验证这两种效应的各自占比。

1. 完整目标与符号约定

  • 物品 iu,t​ 的 m 层 RQ-VAE 编码：RQ-VAE(iu,t​)=(qu,t1​,…,qu,tm​)，解码端以起始符 <s> 引导，自回归预测 qu,t1​,…,qu,tm​ 直至终止符 EOS。
  • 候选集动态构造（每 epoch 刷新）：cu,t​=negu,t​∪{iu,t​}, negu,t​∼I∖(su,t​∪{iu,t​})，将 nc​ 个候选物品随机打乱后，按该乱序逐一展开为自身 m 位 SID 并依次串接为 (c1​c2​…cnc​​)。
  • 联合损失：L=−∑u∈U​∑su,t​∈Su​​∑l=1m​[logP(qu,tl​∣qu,t<l​,[p1​,su,t​])+logP(qu,tl​∣qu,t<l​,[p2​,su,t​,p3​,cu,t​])]（目标公式写到语义 token，下方参考实现在末尾 EOS 步加入交叉熵，属参考代码的实现选择）。
import random
import torch
import torch.nn.functional as F

def build_epoch_samples(user_seqs, sid_table, all_items, nc, p1, p2, p3, bos_id, eos_id):
    """每 epoch 为每条序列同时构造 1 条主任务样本与 1 条多选辅助样本。"""
    samples = []
    for history, target in user_seqs:
        hist_tokens = [tok for item in history[-20:] for tok in sid_table[item]]
        # 解码序列前后补齐 <s> 与 EOS，确保 q^1 ... q^m 与 EOS 全部参与监督
        target_tokens = [bos_id] + list(sid_table[target]) + [eos_id]

        # 1) 主任务: [p1, s_{u,t}] -> <s> q^1 ... q^m EOS
        samples.append(([p1] + hist_tokens, target_tokens))

        # 2) 多选辅助任务: [p2, s_{u,t}, p3, shuffled(c_{u,t})] -> <s> q^1 ... q^m EOS
        forbidden = set(history) | {target}  # 对齐原文 Eq. (5): I \ (s_{u,t} ∪ {i_{u,t}})
        negs = []
        while len(negs) < nc - 1:
            cand = random.choice(all_items)
            if cand not in forbidden and cand not in negs:
                negs.append(cand)
        cands = negs + [target]
        random.shuffle(cands)
        cand_tokens = [tok for item in cands for tok in sid_table[item]]
        samples.append(([p2] + hist_tokens + [p3] + cand_tokens, target_tokens))

    random.shuffle(samples)  # 跨任务随机混编 batch
    return samples

def train_step(model, batch_src, batch_tgt, optimizer, pad_id=0):
    # batch_tgt 形状为 [B, m+2]: [<s>, q^1, ..., q^m, EOS]
    logits = model(src=batch_src, tgt_in=batch_tgt[:, :-1])
    loss = F.cross_entropy(
        logits.reshape(-1, logits.size(-1)),
        batch_tgt[:, 1:].reshape(-1),  # 监督目标覆盖 q^1 ... q^m 与 EOS
        ignore_index=pad_id,
    )
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    return loss.item()

@torch.no_grad()
def infer_next_item(model, history, sid_table, p1, trie, beam_size=20):
    """验证与推理仅走 [p1, s_{u,t}] 路径，基于合法 SID 前缀树做受限束搜索。"""
    src = torch.tensor([[p1] + [tok for i in history[-20:] for tok in sid_table[i]]])
    return model.constrained_beam_search(src, valid_sid_trie=trie, beam_size=beam_size)

上述推演和 nc​=1 的预测最终要靠跨数据集实验来检验，下面先对齐实验所使用的四个基准、实现细节与基线口径，再看主表结果。

评测口径与跨数据集核心对照

实验选用四个公开数据集，统一采用 5-core 过滤与 leave-one-out 划分：三个高稀疏数据集分别是 Amazon'23 的 Industrial and Scientific（简称 Scientific，50,985 用户 / 25,848 物品，平均历史长度 8.10、中位数 6，稀疏度 99.97%）、Musical Instruments（简称 Instruments，57,439 / 24,587，均值 8.91、中位数 7，稀疏度 99.96%）和 Yelp（沿用 LETTER 预处理，30,431 / 20,033，均值 10.40、中位数 7，稀疏度 99.95%）；第四个则是高稠密的 MovieLens 1M（6,040 用户 / 3,416 物品，平均历史长度 165.50、中位数 96，稀疏度 95.16%）。

模型实现上，TIGER 与本文方法均用预训练 Sentence-T5（sentence-t5-xl）提取语义向量并训练 4 层 RQ-VAE（每层码本大小 256），最大历史长度统一截断为 20，学习率 5×10−4，最多训练 200 epoch，早停 patience 为 20 且仅监控主任务验证集损失。测试阶段在全库合法 SID 前缀树上执行 beam size 为 20 的受限束搜索，论文报告了 Top-5 与 Top-10 的 Hit@K（H@K）和 NDCG@K（N@K）。对照基线中，SASRec、GRU4Rec 等传统序列模型采用 RecBole 的交叉熵损失实现（论文指出这一实现可提供更强的基线）；生成式基线里，TIGER-SAS 改用 SASRec 学到的物品嵌入构建 SID，LETTER-TIGER 使用 LLaMA-2-7B 嵌入并加入协同与多样性正则，ETEGRec 则基于 RecBole 的 SASRec 嵌入做端到端 tokenizer 与生成器联合对齐。为便于横向阅读，下表汇总各模型核心 Top-10 指标（原文 Table 3 的 Top-5 关键涨幅在表后正文一并说明）：

第一，在 Scientific 和 Instruments 两个稀疏电商集上，不改 tokenizer 的 TIGER+nc​=10 与端到端联合训练的 ETEGRec 已处于同一水平线甚至局部占优：Scientific 上 H@10 与 N@10 双双领先（0.0442 / 0.0235 vs 0.0425 / 0.0222），Instruments 上 N@10 略胜（0.0323 vs 0.0318），H@10 小幅落后（0.0594 vs 0.0598）。此外，附录 Table 9 对 TIGER+nc​=2 相对原版 TIGER 做了 5 次随机种子复现（例如 Scientific N@10 为 0.0238 ± 0.0007 vs 0.0213 ± 0.0004，Yelp N@10 为 0.0282 ± 0.0024 vs 0.0182 ± 0.0016），全部四个数据集均通过 Welch's t 检验（p<0.05）且方差较小；但需明确，该多随机种子检验仅针对 nc​=2 对比 TIGER，并未覆盖 nc​=10，也不构成相对 ETEGRec 的显著性检验。

第二，Yelp 上高达 +79.0% 的 N@10 涨幅（0.0205 -> 0.0367）需要放在基线坐标系里看：原版 TIGER 在 Yelp 上大幅落后于 RecBole 交叉熵版 SASRec（0.0383），连 LETTER-TIGER（0.0243）和 ETEGRec（0.0279）也未能追上；多选辅助任务实质上是把原本在 Yelp 上明显失准的 SID 生成式模型拉回到了 SASRec 同一梯队（H@10 0.0621 略高于 0.0613，N@10 0.0367 仍小幅低于 0.0383）。

第三，在稠密的 MovieLens 1M 上，固定单一配置看，nc​=2 的 Top-10 涨幅为 +4.4% H@10 / +4.9% N@10（Top-5 涨幅更高，达 +7.7% H@5 0.1950 vs 0.1811、+6.4% N@5 0.1338 vs 0.1258），nc​=10 的 Top-10 涨幅为 +5.4% H@10 / +4.3% N@10（Top-5 为 +6.1% / +4.5%）。不仅 nc​=10 的 N@10（0.1586）反低于 nc​=2（0.1594），两者在 N@10 上也均未超过直接换用协同嵌入的 TIGER-SAS（0.1598）与 LETTER-TIGER（0.1597）。

同样一套辅助损失，为何在 Yelp 上拉出近八成涨幅、在两个稀疏电商集上约一成、到了 MovieLens 上却迅速见顶？接下来的候选规模扫描与物品频次切片给出了更直接的线索。

增益来源拆解与切片对比

先看候选数量 nc​ 的变化趋势（原文 Figure 2 与 Figure 3）。除了排序指标，论文还在测试集主任务输入 [p1​,su,t​] 上，通过 teacher-forcing 计算模型生成真实下一物品（从首个语义码 q1 累加至 EOS）的对数似然中位数：
ℓTF​=median(u,t)∈Dtest​​[l=1∑m​logP(qu,tl​∣qu,t<l​,[p1​,su,t​])+logP(EOS∣qu,t≤m​,[p1​,su,t​])]
结合 Table 3 的精确数值与 Figure 2、Figure 3 的扫描曲线（原文仅在图中绘制 nc​=1 与 nc​=20，未列出精确数字），各档位呈现三段走势：

  • nc​=1（纯正例记忆）：多个数据集上已出现高于原版 TIGER（nc​=0）的小幅提升，支持前文关于编码端正例共现记忆的判断；
  • nc​=2→10（主要爬坡段）：ℓTF​ 与 H@10 / N@10 同步上升，其中 Yelp 爬坡最陡（N@10 从 0.0205 -> 0.0279 -> 0.0367），Scientific（0.0213 -> 0.0228 -> 0.0235）与 Instruments（0.0293 -> 0.0318 -> 0.0323）稳步抬升，而 MovieLens 在 nc​=2（0.1594）即已接近顶部，nc​=10 时 N@10 小幅回落至 0.1586；
  • nc​=20（饱和与轻微回落）：四个数据集的对数似然与排序指标整体趋于饱和甚至略降。作者将此归因于负信号冗余以及候选池扩大后混入假负例（用户未交互但实际符合意图的物品）的风险升高，但这一假负例解释目前仍是未经验证的推测。

更能区分四个数据集行为差异的，是按训练集物品出现频次三等分（popular / medium / long-tail）的切片评测（原文 Table 4 与附录 Table 10）：

  • Scientific 与 Instruments（稀疏度 99.97% / 99.96%）：增益几乎全部落在头部热门切片（Popular N@10 分别从 0.0359 -> 0.0396、0.0421 -> 0.0466，增幅 +10.3% 与 +10.7%）；中频与长尾切片的绝对指标接近于零且变化微弱（Scientific 长尾 N@10 甚至从 0.0002 微降至 0.0001，Instruments 中频 H@10 从 0.0028 降至 0.0024、长尾 N@10 为 0.0003 -> 0.0004）。
  • MovieLens（稀疏度 95.16%）：三个频次切片同步改善，且相对涨幅随频次降低反而更高——Popular N@10 为 0.1794 -> 0.1866（+4.0%），Medium 为 0.0855 -> 0.0908（+6.2%），Long-tail 为 0.0155 -> 0.0194（+25.2%，对应长尾 H@10 保持 0.0340 不变，说明长尾增益主要来自 Top-10 内部排序前移）。
  • Yelp（稀疏度 99.95%）：结构分化最为剧烈。Popular N@10 提升 31.7%（0.0319 -> 0.0420），Medium 从 0.0041 跃升至 0.0245（6.0 倍），Long-tail 更从 0.0023 升至 0.0317（13.8 倍，H@10 从 0.0038 升至 0.0432，覆盖 6,808 名测试用户），绝对值甚至反超中频切片。

这里有一个原文尚未彻底解释的反常现象：Scientific、Instruments 与 Yelp 三者的交互稀疏度几乎一致（99.95%–99.97%），但唯独 Yelp 的中长尾大幅恢复且长尾 N@10 超过中频，论文仅将 Scientific 与 Instruments 的长尾平淡归因为任务难度更高，并未进一步排查 Yelp 商户元数据结构或 SID 冲突率带来的差异。

按用户历史长度三等分（short / medium / long，原文 Figure 4）的评测则显示：TIGER 与 TIGER+nc​=10 的绝对 NDCG@10 均随序列变长而下降——作者将其解释为长序列往往包含更复杂、更多元的用户意图，预测难度本身更高；而在全部三个长度桶上，TIGER+nc​=10 都保持了相对 TIGER 的稳定优势，未表现出明显长度偏置。

定性案例（原文 Table 5 与 Table 6，均为多选模型正确命中真实下一物品、而原版 TIGER 未命中的样本）进一步印证了推荐行为的变化：在 MovieLens 中，一位以剧情片为主但近期看过一部儿童片（Babe）的用户，原版 TIGER 的 Top-3 全是纯剧情片，而 TIGER+nc​=10 在 Top-1 直接命中了兼具儿童与剧情标签的真实目标 E.T.；在 Instruments 中，一位依次买过电钢琴、琴凳、琴架与监听耳机的用户，原版 TIGER 仅围绕文本元数据相近物品做同类推荐（琴凳、延音踏板、琴架），而 TIGER+nc​=10 的 Top-2 转向 USB 电容麦与防喷罩，命中了用户的桌面录音搭建意图。就 Instruments 案例而言，Table 6 以加粗标出真实目标并将其归为正确命中，此处仅确认其位于 Top-2 内，而不限定具体为 Top-1 或 Top-2。

在看清增益的频次与序列分布后，实际复现与调优还绕不开三个具体问题：负例采样分布要不要调整、主辅任务配比如何选择，以及模型内部是否真正学会了按多选方式利用候选信息。

消融实验与内部注意力行为

首先是负采样策略消融。作者在 nc​=10 下对比了四种负例构造方式：全库均匀采样（Uniform）、纯长尾采样（Long-tail，仅采频次后三分之一物品）、纯非长尾采样（Warm-set，仅采非长尾物品），以及动态退火策略（Dynamic）。其中 Dynamic 随训练轮次 ep 按 ptail​(ep)=e−ep/T 概率从长尾采样、以 1−ptail​(ep) 从非长尾采样（论文取衰减超参 T=100，原文简记该概率为 p，此处为避免与下文任务配比混淆而加下标区分）。结果汇总如下（原文 Table 7）：

候选采样策略（nc​=10）Scientific H@10 / N@10Instruments H@10 / N@10Yelp H@10 / N@10MovieLens H@10 / N@10
Uniform（默认）0.0442 / 0.02350.0594 / 0.03230.0621 / 0.03670.2770 / 0.1586
Long-tail0.0445 / 0.02390.0594 / 0.03210.0629 / 0.03680.2664 / 0.1517
Warm-set0.0452 / 0.02430.0588 / 0.03180.0604 / 0.03530.2737 / 0.1588
Dynamic（T=100）0.0458 / 0.02470.0590 / 0.03200.0623 / 0.03640.2740 / 0.1602

细看这张表，不同数据集对负采样分布的敏感度并不一致。最显著的反差出现在 MovieLens 上：纯 Long-tail 采样会直接跌回 TIGER 基线水平以下（N@10 从 0.1586 降至 0.1517，低于原版 TIGER 的 0.1520），而 Uniform（H@10 最高 0.2770，N@10 0.1586）、Warm-set（0.1588）与 Dynamic（N@10 最高 0.1602）均表现稳健；论文解释称，稠密交互序列本身已经暴露了充足的长尾物品，模型更易混淆的是正例与 warm-set 候选，因此不能缺少非长尾负例的对比。在三个稀疏数据集上，情况则有所分化：Instruments 与 Yelp 上纯 Long-tail 几乎与 Uniform 打平，而最稀疏的 Scientific 上反而是 Warm-set（0.0243）和 Dynamic（0.0247，相对 Uniform 提升 +5.1%）明显占优。因此，Dynamic 并非完全无效，而是在 Scientific 与 MovieLens N@10 上占优、在 Instruments 与 Yelp 上略逊于 Uniform，跨数据集缺乏一致优势；在不引入额外退火超参的前提下，静态 Uniform 是最省心的默认选项。

其次是主辅任务配比消融（原文 Figure 5）。论文把默认的确定性 1:1 改为伯努利随机分配：记主任务采样概率为 pmain​（原文记为 p），在 nc​=10 下扫描 pmain​∈{0.2,0.3,…,0.8}，每条训练样本按如下方式二选一：
zu,t​∼Bernoulli(pmain​),xu,t​={[p1​, su,t​],[p2​, su,t​, p3​, cu,t​],​zu,t​=1zu,t​=0​,Nepoch​=∣D∣（默认 1:1 为 2∣D∣）
需要注意两点实验口径细节：一是伯努利二选一使单 epoch 样本总量从 2∣D∣ 减半为 ∣D∣，将「任务比例变化」与「单轮样本量减半」耦合在了一起（原文 Figure 5 用星号标出了默认确定性 1:1 作为参考基线，但未列出各档位精确数值）；二是原文仅展示了 Scientific、Instruments、Yelp 三个数据集的曲线，未汇报 MovieLens 结果。从三组曲线的定性趋势看，pmain​ 过高（如 0.7–0.8）会因多选比较信号不足导致三集指标普遍下滑；pmain​ 过低（如 0.2）在 Scientific 和 Yelp 上同样掉点，原因是推理期实际使用的 [p1​,su,t​] 路径训练不充分。默认等权 1:1 在各域上最为稳健。

最后，作者检验了模型在多选辅助任务上的实际执行情况（原文 Table 8 与 Figure 6）。即便训练早停完全不看辅助任务损失，在测试集上为每条样本构造 nc​=2 与 nc​=10 的候选集并走 [p2​,su,t​,p3​,cu,t​] 路径时，Top-1 预测落入给定候选集的比例（候选集遵循率，原文称为 selection accuracy）在全部四个数据集上都达到 99.98%–100.00%（最小值为 MovieLens nc​=2 的 0.99983）。这一微小非 100% 缺口间接说明测试解码并未把搜索空间硬截断在候选集内，模型确实自发学会了按候选池约束生成；不过需留意，论文并未汇报多选题真正选对正例的 Top-1 准确率。

为进一步拆解内部信息流，作者将 Encoder 输入切分为历史段（p2​→p3​）与候选段（p3​ 之后），统计 4 层 Decoder 起始 token <s> 对两段的跨层平均 cross-attention，并定义候选段注意力占比（原文 Eq. 10）：
cand_attention_prop=cand_attention+history_attentioncand_attention​

整体上，4 层 Decoder 的注意力分布呈现「浅层更偏向历史段、深层候选段占比更高」的趋势；唯一例外是 Yelp（nc​=10），其候选段注意力占比在后两层明显回落。作者推测这可能是因为候选特征已在 Encoder 自注意力阶段提前融入了历史表征（原文未进一步验证这一早期融合现象是否与 Yelp 中长尾的大幅提升直接相关）。综合来看，这些消融与注意力诊断表明，多选辅助任务能够在不参与推理的前提下为主任务带来收益，且辅助路径确实在利用候选信息——在真实系统里评估这套方案时，核心权衡也因此落在训练开销的增量与线上推理的轻量改造之间。

工程代价与尚未验证的边界

在部署侧，验证与推理阶段只执行 [p1​,su,t​] 单路解码，不构造候选集，额外参数只有 3 个特殊 token 的 embedding，编码器输入长度仅比原版 TIGER 多 1 个前缀 token，因此线上服务链路的结构改动极小（不过需如实说明，论文全文并未汇报实际的推理耗时或吞吐实测数据）。

相比之下，训练期的算力开销增长相当直观：每 epoch 样本量翻倍，且辅助任务那一半样本还要在历史序列之后拼接 4nc​ 个候选 token 以及 p2​,p3​ 两个分隔符。以 4 层 RQ-VAE、历史 token 长度 Lhist​=4×len(su,t​) 估算，主任务编码长度为 Lhist​+1，辅助任务为 Lhist​+4nc​+2，单 epoch 内 Encoder 自注意力二次项与原生 TIGER 的计算量倍率为：
Renc​≈Lhist2​(Lhist​+1)2+(Lhist​+4nc​+2)2​
在 nc​=10 下代入两档典型长度做估算：当序列触及 20 个物品的截断上限（Lhist​=80，如中位长度 96 的 MovieLens）时，辅助任务输入长度增至 122 token，单 epoch 编码端总 token 数估算增至原版的 2.54×，自注意力二次项估算达到 3.35×；而在稀疏数据集平均 9 个物品（Lhist​=36，接近 Instruments 的 8.91）时，辅助任务长度为 78 token，总 token 数估算增至 3.19×，自注意力二次项估算达到 5.75×。

除了训练开销，论文还有几处未披露的实验细节与尚未验证的适用边界值得留意：

  1. 实现与统计信息不完整：关于训练开销，现有依据仅限于上文的目标公式与 Encoder 计算量估算；主干结构上，从 Figure 6 可看出 Decoder 为 4 层；统计复现方面，附录 Table 9 的多种子实验只覆盖了 nc​=2，未覆盖主打的 nc​=10。
  2. 架构外推尚未验证：全部实验都只把多选辅助任务挂在最基础的 Sentence-T5 版 TIGER 上，它与 LETTER、ETEGRec 等协同 tokenizer 方案之间是否存在可叠加增益，或迁移到 Decoder-only 大模型推荐架构后效果如何，目前仍是空白。
  3. 稠密长序列场景边际收益有限：在 MovieLens 这类用户历史极长（中位 96 却截断至 20）的稠密数据集上，单靠随机负例多选带来的 Top-10 提升有限，且 N@10 未超过直接使用协同嵌入的 TIGER-SAS。

对于已经在运行 SID 生成式召回、且正受高稀疏类目下语义-行为错位困扰的团队，这套方案仅需几十行数据构造代码、推理链路几乎无需改动，适合作为离线基准上的低成本先验试验，再依据实测收益决定是否投入大规模重构 tokenizer。
