这篇论文只换了去噪的一半：可疑交互怎么处理沿用旧办法，哪条交互可疑不再只问 loss。

一位常看科幻片的用户误点了一条烹饪视频。Loss 要等模型拟合这条样本出了问题，才会给出信号；样本一旦被拟合好，loss 变低，信号也就没了。NDL（这篇论文提出的去噪框架，全称 Noise-aware Dimension Learning）多问一句：这条交互在 embedding 空间里，和这位用户平均的交互同向吗？答案和 loss 混合后，决定这条交互能用 32 个 embedding 维度里的几个。

离线结果上，NDL 在三个公开数据集都赢了 DAR（按 loss 给每条交互分配 embedding 维度数的去噪方法），Recall@5 高 5.63% 到 17.95%。下面先看这个新信号怎么算、到底补了 loss 多少，再看涨幅里有多少能算在它头上。

Loss 的信号为什么来得晚

图协同过滤的显式去噪方法，手段各不相同。T-CE 把高 loss 的交互丢掉，R-CE 给高 loss 的交互降权，DAR 把每条交互的 loss 映射成它可用的 embedding 维度数。三者读噪声的地方却是同一个：交叉熵 loss。

作者对此的批评有两层。一层是被动，噪声要先误导模型、表现为预测误差，才看得见。另一层是混淆，loss 的高低还受训练阶段、负采样和用户活跃度影响，高 loss 也可能只是一条难拟合的正样本。

那么，有没有一个信号不依赖预测结果，只看 embedding 本身？

拿这条交互和用户的平均交互比方向

NDL 的做法叫 RCD（Representation Coherence Detection，用表示的一致性检测噪声）。一条交互的表示是 e_u ⊙ e_i，也就是用户和 item 的 embedding 按位相乘，每一位表示该维对亲和度的贡献。把用户所有交互的这个向量取平均，得到用户的历史中心，每个 epoch 开始时用当前 embedding 重算。

coherence 就是这条交互的表示和历史中心的余弦。回到开头的例子，烹饪视频那条交互如果偏离这位用户的中心，余弦就低，经过一个 sigmoid 后得到更高的噪声分。这个分数只来自现有的 embedding 几何，所以模型还没在这条样本上出错时就能算，作者称之为 active。 Hoot 说▾

它的前提是用户短期偏好稳定。作者也承认，真实的探索行为同样可能 coherence 偏低，比如新用户。所以 loss 没有被扔掉，两个信号要配合用。可配合的前提是它们确实会给出不同的判断，这要看数据。

在 DAR 判错的样本上，两个信号有多少分歧

图 1 用 MovieLens 上最好的 DAR checkpoint，挑出 loss 判错的两组样本，再以全体样本的 coherence 中位数（约 0.87）划线。DAR 留下的噪声里有 22.4% 落在线下，说明这部分漏网的噪声 coherence 认得出来。DAR 压掉的干净样本里有 19.6% 落在线上，意味着这部分误伤有机会保住。

作者把这称作 orthogonally complementary。按 0.87 这条阈值，两组样本分别有 22.4% 和 19.6% 得到了与 DAR 方向不同的判断。

在 DAR 判错的两组样本里，按这条阈值，约五分之一得到了与 DAR 方向不同的判断。

融合要用的正是这约五分之一的分歧。问题变成：两个信号谁说了算，结果又怎么作用到模型上？

混合权重跟着用户活跃度走，结果变成维度上限

历史丰富的用户，中心比较可靠；交互很少的用户，中心不稳定。所以权重取 w_u = min(用户交互数 / δ_act, 1)，融合噪声分 α = w_u·α_RCD + (1−w_u)·α_loss。其中 α_loss = σ(EMA 平滑后的交叉熵 loss / τ_loss)，取值在 0 到 1 之间。δ_act 设在各数据集用户交互数的中位数附近，MovieLens 是 50，Yelp 是 30，Amazon-book 是 25。

α 接下来决定维度数：d_ui = ⌊(1−α)·d⌋，预测分只累加前 d_ui 维的点积。以 32 维算，α=0.25 的交互能用 24 维，α=0.75 的只剩 8 维，所以可疑交互仍然参与训练，只是表达能力被收窄。这一步的机制来自 DAR，NDL 换掉的是驱动它的分数。

图 2 下方还有一个对比正则：对 batch 内的 embedding 做两路 dropout，算 InfoNCE，权重 λ=0.001。它不产生噪声分，也不进融合，作者的用意是让 RCD 工作的 embedding 空间更均匀。这个小模块后面会影响对结果的归因。

赢了 DAR，但功劳要分开算

实验按噪声训练、干净测试的协议：评分低于 3 的交互算噪声，只进训练集，验证和测试只留评分不低于 3 的交互。所有方法都用 d=32、两层的 LightGCN。这里的噪声是低评分，和开头的误点并不完全是一回事。

去掉 RCD 跌得最多，0.1003 甚至低于普通 LightGCN，至少在 MovieLens 的 Recall@5 上，coherence 是影响最大的一块。但另外两行让归因不能这么干净。去掉对比正则后，NDL 只比 DAR 高 0.0005，所以 MovieLens 上对 DAR 的领先，大部分要 coherence 和对比正则同时在场才拿得到。去掉 RCD 的版本同样只靠 loss，却比 DAR 低不少，我的理解是实现差异本身也不小。

对比正则的权重也敏感：λ 从 0.001 调到 0.01，Recall@5 掉到 0.1045，已经低于 DAR。

涨的召回是否真涨在干净样本上？作者用 sep@K 检查，它等于干净正样本的 Recall@K 减去低评分正样本的 Recall@K。NDL 的 sep@K 从 K=5 到 K=50 全程高于 DAR，K=20 时差距最大，为 0.0137，说明提升更多落在高评分的内容上。

干净和噪声交互的 embedding 余弦分布重叠度，也从 DAR 的 0.8661 降到 0.8316，说明两类交互在 embedding 空间里更容易分开。这两项检查都在 MovieLens 上，方向和 Recall 一致，作者把后者称为根本原因，我只把它当作相互印证。

最稀疏的用户偏向 loss，提升却最大

按融合公式，交互少的用户更依赖 loss，直觉上 coherence 对他们帮助最小。图 5 给出相反的结果：MovieLens 用户按训练交互数等分五档，最稀疏一档 NDL 比 DAR 的 Recall@5 高 15.90%，最活跃一档高 7.60%，中间三档在 11% 到 13% 之间。我的理解是两处口径对不上：等分五档时整体涨幅应落在各档之间，而各档都不低于 7.60%，表 2 整体却只有 5.63%；图 5 各档 DAR 柱值平均约 0.101，也低于表 2 的 0.1066，所以分档幅度只宜看趋势。

这个矛盾其实没有看上去那么大。图 5 里最稀疏一档是 13 到 36 条交互，按公式 δ_act=50 时 w_u 约为 0.26 到 0.72，所以 coherence 仍占相当份额。作者的解释是稀疏用户每条交互分量更重，一条噪声边更容易带偏偏好，这是一个合理的解释，图 5 本身并不能证明它。

上线成本低，线上效果还没有答案

NDL 的改动都在训练环节。线上仍然只输出用户和 item 的 embedding，形状和 LightGCN 一样，不增加线上延迟和参数。训练耗时比 LightGCN 多约 4.2%。

作者的目标场景是网易新闻 feed，约 2000 万用户、800 万 item，模型还没有上线。论文里的提升全部来自公开数据集的离线评估，噪声也由低评分定义，真实误点上能留下多少，要等实验组和对照组的结果。短期偏好稳定的假设也还在，作者把多兴趣用户留给了后续工作。

回到开头那一半：维度上限是 DAR 现成的，NDL 换的是判断可疑的依据，让它在预测出错之前多了一个来源。这个来源在 DAR 判错的两组样本里，约五分之一得到了与 DAR 方向不同的判断，放进模型后却撑起了对 DAR 的离线领先。在 MovieLens 上，去掉对比正则后 NDL 仍略高于 DAR，但大部分领先幅度随之消失。
