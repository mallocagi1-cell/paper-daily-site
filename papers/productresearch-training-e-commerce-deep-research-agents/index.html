1. 问题与动机

本文聚焦一个核心问题：现有电商购物 Agent 缺乏处理复杂商品调研任务的深度能力。

当前的 LLM 购物 Agent（如 WebShop、ShoppingBench 等任务中的 Agent）大多处理简单的"搜索→选购"流程，但现实中用户的购物决策远比这复杂。例如：

  • "我需要一台适合视频剪辑的笔记本，预算 8000 以内，续航要好，屏幕色准要高" — 这需要跨多个维度的深度对比调研
  • 用户需要综合 Web 知识（评测文章、用户口碑）和电商目录数据（商品属性、价格、库存）进行交叉验证

与此同时，"Deep Research" 范式（如 Gemini Deep Research、Qwen Deep Research）在通用 Web 搜索场景已展现出强大能力，但它们在电商领域面临三个特有挑战：

  1. 异构工具编排：需要同时调用 Web 搜索和电商商品数据库，两类工具的调用逻辑截然不同
  2. 属性验证与事实落地：调研结论必须基于可验证的商品属性，不能靠大模型"幻觉"编造参数
  3. 多源证据综合：需要从评测文章、用户评论、商品详情页等多种来源提取并融合信息

此外，训练此类 Agent 的另一大瓶颈是缺乏高质量的长链推理轨迹数据。人工标注成本极高，而直接让模型自我生成又难以保证质量。

2. 方法概述

ProductResearch 提出了一套"多 Agent 协同合成 → 轨迹蒸馏 → 单 Agent 微调"的完整训练框架，分三个阶段：

Phase 1: 用户画像与查询生成

User Agent 从用户行为历史中推断画像（persona），据此生成复杂的调研查询。关键创新在于同时生成 query-adaptive 评估 rubric，覆盖四个维度：全面性（comprehensiveness）、深度（depth）、指令遵从（instruction-following）、可读性（readability）。这使得后续评估不是"一刀切"，而是根据每个查询的特性定制评判标准。

Phase 2: 状态感知的迭代调研

Research Agent 执行 "Plan → Toolcall → Report" 的迭代循环，配备双环境工具：

  • Web 环境：web_search（搜索）和 visit_webpage（访问网页）
  • 电商环境：product_search（从 1140 万商品库中搜索）和 product_detail（查询商品详情）

Supervisor Agent 通过三阶段状态机验证（Plan 验证、Toolcall 验证、Report 验证）进行质量把关。当 Research Agent 的输出偏离规范时，Supervisor 提供纠正反馈，将其引回正轨。这种"监督-纠正"的交互形成了高质量的长链调研轨迹。

Phase 3: 轨迹精炼与蒸馏

这是方法论上最关键的一步 — 反思内化（Reflective Internalization）：

多 Agent 交互过程中，Supervisor 的多轮纠正反馈被"内化"到 Research Agent 的单轮输出中。具体做法是将"Research Agent 犯错 → Supervisor 纠正 → Research Agent 修正"的多轮对话，整合为一条连贯的、直接输出正确结果的单角色训练样本。这样既保留了纠正信号蕴含的知识，又使数据格式兼容标准 SFT 微调。

还进行了长度过滤，移除过短（信息量不足）和过长（噪声过多）的轨迹。

3. 核心技术贡献

贡献一：首个电商 Deep Research 数据集

结合复杂查询、自适应评估 rubric、多 Agent 交互轨迹三要素，构建了首个面向电商调研场景的训练数据集。查询覆盖 1140 万商品库，轨迹包含 Web + 电商双环境工具调用。

贡献二：状态机驱动的 Supervisor 验证机制

与简单的"生成后打分"不同，Supervisor 以有限状态机形式嵌入到 Research Agent 的每个执行阶段：

  • Plan 阶段：验证调研计划是否合理、覆盖面是否充分
  • Toolcall 阶段：检查工具调用是否正确、返回数据是否被合理利用
  • Report 阶段：验证最终报告是否基于实际检索的数据、是否存在幻觉

这种"在线实时纠偏"比"离线后评估"能产生质量高得多的轨迹数据。

贡献三：反思内化（Reflective Internalization）

这是连接多 Agent 协同与单 Agent 微调的桥梁。核心洞察：多 Agent 交互中的纠正信号是最有价值的学习素材，但直接用多轮对话做训练效率低且格式不兼容。通过将纠正信号"内化"为隐含知识，生成的训练样本看起来像是 Agent"一次就做对了"，但实际上蕴含了从错误中学习的经验。

贡献四：ReAct 式 Agent 可匹敌前沿 Deep Research 系统

实验证明，经过高质量合成数据训练的紧凑型 MoE 模型（Qwen3-30B-A3B，仅 3B 激活参数），性能可以接近甚至匹配 Gemini Deep Research 这类前沿系统。这说明数据质量 > 模型规模。

4. 实验结果分析

主要结果

使用 RACE 评估指标（基于 Deep Research Bench 改编的 query-adaptive rubric-driven 成对比较），核心数据：

模型RACE 总分全面性可读性
Qwen3-30B-A3B（base）31.7828.4135.42
+ ProductResearch 微调45.4043.8747.22
Gemini Deep Research45.56——

关键观察：

  1. 总分提升 +13.62：微调后的紧凑模型（3B 激活参数）几乎追平 Gemini Deep Research（45.40 vs 45.56），这是一个非常强的结果
  2. 全面性大幅提升（28.41 → 43.87）：说明多 Agent 轨迹蒸馏有效教会了模型进行系统性、全面的商品调研
  3. 商品覆盖率提升 3.5 倍（3.58 → 12.45 effective products）：模型学会了利用电商工具检索更多相关商品并进行有效对比
  4. 可读性提升（35.42 → 47.22）：Supervisor 对报告格式和结构的纠正信号被成功内化

上下文窗口实验

从 32K 扩展到 128K token 的上下文窗口带来一致性提升，验证了复杂调研轨迹需要长上下文支持。这也暗示未来还有继续扩展上下文获得收益的空间。

5. 局限与未来方向

当前局限

  1. 仅支持单轮查询：当前框架处理的是"一次性提出完整需求"的场景，尚未支持多轮追问和需求澄清式的对话交互。这与真实购物场景（用户逐步细化需求）有差距。
  1. 工具实现有优化空间：论文中的 Web 搜索和商品检索工具是相对基础的实现，检索质量直接制约了 Agent 的调研上限。
  1. 对 LLM 基座质量的依赖：整个 pipeline 严重依赖 Supervisor Agent 的判断能力。如果基座模型本身在电商领域知识不足，Supervisor 的纠正可能不准确，导致"错误内化"。
  1. 计算成本：多 Agent 协同生成轨迹的成本远高于单 Agent 自生成。虽然这是一次性的训练数据生成成本，但规模化到更多品类时仍需考虑。
  1. 商品领域泛化性：实验集中在特定电商场景，跨品类（如从 3C 数码到服装美妆）的泛化能力未被充分验证。

未来方向

  1. 多轮对话扩展：支持用户在调研过程中追问、修改需求、请求更深入的对比
  2. 工具能力增强：引入更丰富的工具（如价格趋势、促销信息、用户画像匹配）
  3. 在线强化学习：在部署后用真实用户反馈进一步优化，形成"合成预训练 + 在线 RL"的闭环
  4. 多模态扩展：整合商品图片、视频评测等多模态信息源
  5. 个性化调研：结合用户历史偏好，生成个性化的调研报告

6. 工业实践意义

对电商搜索系统的直接借鉴

  1. 从"搜索引擎"到"调研助手"的范式升级：传统电商搜索返回商品列表让用户自行筛选对比，ProductResearch 展示了一种新范式 — Agent 主动完成信息收集、对比分析、报告生成。这对高客单价、高决策复杂度的品类（3C 数码、家电、汽车等）价值尤为显著。
  1. 双环境工具编排模式可复用：Web 知识（评测、口碑）+ 电商结构化数据（商品属性、价格）的双通道检索模式，可以直接应用到任何有自有商品库的电商平台。

对推荐系统的启发

  1. 从被动推荐到主动调研：当前推荐系统是"猜你想要什么"，ProductResearch 展示了"帮你搞清楚你需要什么"的新方向。对于用户需求模糊的场景（如"想换个手机但不知道选什么"），Agent 式调研可能比 feed 推荐更有效。
  1. 用户画像驱动的查询生成：User Agent 从行为历史推断画像再生成查询的做法，可用于推荐系统中的"需求发现"模块。

对 Agent 训练的通用借鉴

  1. 多 Agent 合成 → 单 Agent 蒸馏的训练范式：这是本文最具通用价值的贡献。在任何需要训练工具使用 Agent 的场景中（如客服 Agent、广告投放 Agent），都可以复用"多 Agent 协同生成高质量轨迹 → 蒸馏为单 Agent 训练数据"的模式。其核心优势是用强模型的协同能力"教"弱模型独立完成任务。
  1. 状态机验证机制的工业适配性：Supervisor 的三阶段状态机验证非常适合工业场景 — 可以针对业务规则（如不允许推荐下架商品、不允许编造商品参数）定制验证规则，确保生成的训练数据满足业务合规要求。
  1. 小模型 + 高质量数据的路线：在工业部署中，Qwen3-30B-A3B（3B 激活参数）级别的 MoE 模型推理成本远低于调用 Gemini Deep Research API。本文证明了通过高质量合成数据，小模型可以达到接近前沿大模型的效果，这对线上 serving 成本控制意义重大。

落地建议

  • 适用场景优先级：高客单价品类 > 标品 > 快消品；需求复杂度高的场景 > 简单复购场景
  • 部署方式：可先作为"购物顾问"功能上线，处理用户主动发起的调研需求，而非替代现有搜索/推荐
  • 冷启动：可利用本文的多 Agent 框架为自有商品库生成初始训练数据，再用用户反馈迭代优化
