1. 问题与动机

搜索排序系统的相关性标注是训练数据准备、NDCG 评估、badcase 归因（root cause analysis）、护栏校准和特征评估的共同底座，但人工标注既慢又贵。论文给出生产环境的具体数字：3 名训练有素的标注员每天约产出 3,000 条标注，单价 $0.50/条，批量超过 10,000 条时周转需 3–5 个工作日。直接换用通用大模型也不行——在该团队的 5 分类相关性任务上，GPT-4 仅 68.2%、Claude-3 仅 70.1% 准确率，而人工标注员之间的一致性（inter-annotator agreement）达 89%。这 20 个百分点的差距说明：通用 LLM 在垂直领域（赞助搜索 query-product 相关性）上远未达到可替代人工的精度。作者要回答的核心问题是：如何在不牺牲标注质量的前提下，把离线相关性标注的成本和延迟同时压下来。

2. 方法详解

核心是一个 calibrated model cascade（校准模型级联），把三个按算力从小到大排序的微调分类器串成流水线：(1) Cross-Encoder，基于 DeBERTa-v3-base（184M 参数），约 5ms/条；(2) Gemma-2B，LoRA 微调（r=16，α=16），约 50ms/条；(3) LLaMA-3-8B，同样 LoRA 微调，约 200ms/条。延迟均在 NVIDIA A100（40GB）、batch size 64、FP16 下测得。

路由逻辑（Algorithm 1）是顺序级联：query 先进最便宜的 Cross-Encoder，若其"校准后置信度"超过该模型的阈值 τ_m 即直接返回预测，否则下放给更大的模型；若三个模型都不自信（defer），则用多数投票 + max-prediction 兜底的 ensemble fallback。

关键设计是 per-class isotonic calibration（按类别的保序回归校准）：对每个模型 m 和每个预测类别 c，收集所有 ŷ_i = c 的样本，计算是否正确 z_i = 1[ŷ_i = y_i]，再拟合单调非降函数 f_c = IsotonicRegression(p̂, z)，得到校准概率 p*_c = f_c(p̂)。之所以按类别分别校准，是因为不同相关性档位的置信度偏差不同，全局校准会被多数类淹没。

训练数据：1.2M 条电商赞助搜索 query-product 对（18 个月采集）；评测集 100K 条，由训练标注员按 5 分制（0=Embarrassing 到 4=Excellent）打标，各档约 18–22% 近似均衡；校准集按 50% 拟合 / 50% 评估切分。训练算力（Table 1）：Cross-Encoder 约 8 H100-hrs、Gemma-2B 约 16、LLaMA-8B 约 68，三档 LoRA 微调成本可控。

3. 核心技术贡献

贡献 A——把"精度"与"成本"识别为正交优化轴：领域微调贡献 20+ 个准确率百分点（LLaMA-8B 88.9% vs GPT-4 68.2%，差 20.7 点），而级联本身近似不损精度却能把算力减半。这一拆解很重要，因为它告诉工程团队"该投资微调拿精度，用级联拿成本"，二者互不干扰。

贡献 B——把 per-class isotonic calibration 作为级联的一个组件，相比最强的校准基线（global isotonic）再提升 +0.6 点且统计显著（p<0.05）。机制在于校准后的置信度更可靠，使级联的早停决策更准、误放行更少。

贡献 C——系统级验证：在 6 个离线用例上累计处理超过 1.5 亿条标注，把周转从 5 天压到 1–3 小时。

4. 实验结果分析

单模型对比（Table 2）：GPT-4 68.2%±0.9（500ms）、Claude-3 70.1%±0.9（450ms）；微调后 Cross-Encoder 87.5%±0.6（5ms）、Gemma-2B 88.2%±0.6（50ms）、LLaMA-8B 88.9%±0.6（200ms）。微调把准确率从 ~68% 拉到 ~88%，且延迟比调用云端 API 低 1–2 个数量级。

校准方法对比（Table 3）：per-class isotonic 把级联准确率提到 89.1%±0.6、平衡准确率 89.0%，高于 global isotonic 的 88.5%/88.3%；不过其 ECE（.017）并非最低，histogram binning（.010）和 global isotonic（.012）的 ECE 更好——说明 per-class 校准是用略高的 ECE 换来了更高的级联端到端准确率。

级联阈值（Table 4）：生产配置（XE/Gem/Lla = 0.85/0.80/0.75）达到 89.1% 准确率、50.1% 成本节省。流量归因（Table 5）很有看点：74.5% 的流量被最便宜的 Cross-Encoder 自信处理且准确率高达 91.2%；Gemma 处理 12.5%（86.8%）、LLaMA 处理 5.9%（84.5%）、ensemble fallback 占 7.1%（仅 79.2%）。即"简单 query 多、且简单 query 上小模型反而更准"，这正是级联省钱的根本原因。

消融拆解（Table 6）最关键：LLaMA-8B 单模型 88.9%（1.00× 成本）；微调把 GPT-4 的 68.2% 拉高 20.7 点（这是精度的主要来源）；而单纯级联未微调的 GPT-4+Claude-3 只从 68.2% 升到 71.4%（+3.2 点，杯水车薪）；未校准级联 88.2%（0.50× 成本，仅掉 0.7 点）、global isotonic 88.5%、per-class isotonic 89.1%（均 0.50× 成本）。结论清晰：精度几乎全来自微调，成本砍半来自级联，校准再补 0.9 点。

5. 局限与未来方向

作者明确承认：(1) 评测只覆盖单一领域（赞助搜索），20 点增益主要反映该场景下的微调效果，而非级联架构本身的普适收益；(2) 系统依赖大量标注数据——1.2M 条微调样本 + 50K 条校准样本，数据门槛高；(3) 延迟对比是本地 A100 推理 vs 云端 API，不完全对等，但其核心效率主张（相比"每条都跑 LLaMA-8B"节省 50%）是部署无关的；(4) 专有数据导致外部无法复现，仅提供方法学细节。此外作者在实践洞察里提到两点隐性约束：输入格式即使微小变动也会让准确率下降 10–15%；阈值过高（如 0.98）会让中间模型形同虚设，失去级联意义。

6. 工业实践意义

对搜索/推荐从业者，这套方法是离线相关性标注降本的可直接借鉴范式。可采纳的：用"微调小模型 + 级联 + 按类别保序校准"替代纯人工或纯大模型标注，先用最便宜的 Cross-Encoder 兜住大头流量（本案 74.5% 流量、91.2% 准确率），只把不自信的 query 升级。可借鉴的工程细节：LoRA 微调三档模型成本仅几十 H100-hrs；按类别而非全局做置信度校准；按季度用滚动 50K 窗口重训校准器以应对分布漂移。要警惕的：精度几乎全靠领域微调，没有高质量标注种子数据（本案 1.2M）这套方法立不住；级联省的是成本不是精度，别指望级联提分；输入 prompt/格式要严格固定，10–15% 的波动足以抹掉级联收益。部署层面，该系统自 2024 Q3 上线已处理 1.5 亿+ 标注、周转从 5 天降到 1–3 小时，证明离线大规模标注流水线用级联完全可行；社区搜索（UGC 短文本）可把它用于相关性训练样本生产、NDCG 离线评估与 badcase 批量归因。
