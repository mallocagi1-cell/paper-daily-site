Language Models Don't Know What You Want: Evaluating Personalization in Deep Research Needs Real Users

当前 Deep Research 工具（如 OpenAI DR）能自动综合论文回答查询，但缺乏对用户个人研究兴趣的理解，导致生成的报告内容与用户实际需求脱节。本文提出 MyScholarQA（MySQA），一个个性化 Deep Research 工具，通过三步流程解决此问题：(1) 从用户历史行为中推断个人研究兴趣画像；(2) 基于画像为每个查询提出个性化检索动作；(3) 生成聚焦于用户关注维度的多节报告。用户研究表明，MySQA 相比通用 Deep Research 工具在个性化满意度上显著更高，且用户认为推断的兴趣画像准确捕捉了其研究偏好。

KEY INSIGHT · 对业务意味着什么个性化 Deep Research 的核心挑战在于：LLM 无法从单一查询推断用户的深层研究意图。MySQA 的设计启示：(1) 用户兴趣画像应从历史行为动态推断而非依赖用户自填；(2) 检索动作（选择哪些子主题、关注哪些论文方面）是个性化的关键杠杆，而非仅仅改变报告风格；(3) 对搜索系统的实践意义：query 个性化应发生在检索计划阶段（retrieval planning），而不只是重排阶段，这与社区搜索中基于用户画像改写 query 的思路高度契合。

DeepRead: Document Structure-Aware Reasoning to Enhance Agentic Search

现有 Agentic Search 系统将文档视为平铺文本，忽略了文档内在的结构信息（章节、表格、图示、参考文献），导致在处理长结构化文档时定位目标证据效率低下。DeepRead 提出文档结构感知的推理 Agent，将文档原生的结构先验转化为可操作的推理能力，构建了段落级导航系统，包含扫描式定位工具和保序阅读工具。在文档级 QA 和长上下文检索任务上，DeepRead 相比结构无关基线取得显著提升，有效降低了无关段落的检索干扰。

INSIGHT文档结构是被长期忽视的检索信号。DeepRead 的核心洞察是：将文档结构（段落层级、节标题、图表位置）显式建模为工具接口，让 Agent 能够像人类一样扫描文档目录后直接跳转到相关章节，而非逐段暴力检索。对搜索工程的启示：(1) 长文档索引应保留结构元数据（section hierarchy）并暴露给检索 Agent；(2) 扫描式定位（找到相关章节后再精读）比全文密集检索更高效，适合 UGC 长帖的段落级召回；(3) 段落级导航系统可作为独立检索工具集成到现有 RAG Pipeline。

SentGraph: Hierarchical Sentence Graph for Multi-hop Retrieval-Augmented Question Answering

传统 RAG 在多跳问答场景下面临严重瓶颈：以 chunk 为单位的检索常返回碎片化、逻辑不连贯的上下文，导致推理链不完整、答案错误。SentGraph 提出层次化句子图方法，在索引期预构建文档间的桥接实体图，将多跳推理从在线推断转移到离线索引阶段。系统通过识别跨文档共享的桥接实体，生成证据路径供检索时直接利用。在 HotpotQA 和 MuSiQue 多跳 QA 基准上，SentGraph 相比传统 RAG 基线取得显著 F1 提升，且避免了迭代检索带来的高延迟问题。

INSIGHTSentGraph 的关键创新是将多跳推理的计算成本从在线 inference 转移到离线 indexing，这是搜索工程中经典的以空间换时间思路的延伸。对搜索系统的实践启示：(1) 在构建 UGC 搜索索引时，可预计算帖子/回答间的引用关系或实体共现图，为多跳问答预置推理路径；(2) 句子级图结构比段落级 chunk 更细粒度，对短文本 UGC 内容尤其适用；(3) 与 GraphRAG 相比，SentGraph 的层次化结构在保持效率的同时提供了更精确的推理路径，可应用于社区问答中的知识链回答场景。

Generalizable End-to-End Tool-Use RL with Synthetic CodeGym

当前 LLM Agent 的工具调用训练依赖静态轨迹监督微调或窄任务 RL，在遇到新工具和未见过的工作流时泛化能力差。CodeGym 框架通过合成代码执行环境训练通用 Tool-Use RL，使 Agent 学会端到端规划工具调用序列。核心贡献是：(1) 用代码执行反馈替代人工 reward 标注，大幅降低训练成本；(2) 设计多样化合成任务覆盖不同工具组合和调用深度；(3) 通过端到端 RL 让 Agent 学会在工具调用失败时自适应修复。在多个工具使用基准上，模型在未见过的工具组合上展现出显著更好的泛化性能。

INSIGHT搜索 Agent 的核心挑战之一是如何让模型可靠地学会在检索、重排、答案生成等多个工具间协调决策。CodeGym 的启示：(1) 合成代码执行环境可以作为训练搜索 Agent 的低成本 Reward 来源，无需人工标注检索质量；(2) 端到端 RL（而非分步监督学习）能让 Agent 学到更鲁棒的工具调用策略，包括处理检索失败、工具超时等情况；(3) 对于社区搜索场景，可设计包含 query 扩展到检索到重排到答案生成的工具链，用代码执行反馈（是否找到目标帖子）驱动 RL 训练。

MiroThinker-1.7 & H1: Towards Heavy-Duty Research Agents via Verification

MiroMind

复杂长链推理任务对 Research Agent 提出了更高可靠性要求，但现有 Agent 在多步交互中容易积累错误导致最终结果不可靠。MiroThinker-1.7 通过 Agentic Mid-Training 阶段强调结构化规划和上下文推理来提升每步交互的可靠性；MiroThinker-H1 在此基础上引入重量级推理能力，专门处理需要深度验证的多步问题求解任务。关键设计是：对每个推理步骤进行即时验证，而非依赖最终答案的 Outcome Reward，有效避免错误在长链推理中累积传播。在复杂问答和研究任务基准上取得业界领先性能。

INSIGHTMiroThinker 的核心贡献是将验证（Verification）提升到与规划（Planning）同等重要的位置。对搜索 Agent 的实践启示：(1) 步骤级验证（step-level verification）比结果级验证（answer-level verification）更适合长链检索任务，可及早发现并修正检索方向偏差；(2) Agentic Mid-Training 的思路可迁移到搜索 Agent：在正式 RL 之前，用结构化规划任务对模型进行预热训练，培养其正确分解搜索任务的能力；(3) 对于需要多轮检索的复杂查询（如找出社区中讨论某话题的最权威帖子），验证机制能显著提升最终答案的准确率。

Compiled Memory: Not More Information, but More Precise Instructions for Language Agents

现有 Agent 记忆系统聚焦于记忆管理（如何在上下文预算内检索更多信息），但忽视了记忆效用问题（哪些经验值得保留、如何转化为行为改变）。Atlas 提出编译记忆内核，将 Agent 积累的任务经验编译为精确的行为指令而非原始记忆片段。核心机制：从成功/失败的交互轨迹中抽取可泛化的策略，并将其转化为结构化指令注入 Agent Prompt。这样，记忆不再是更多上下文，而是更精准的行为引导，有效避免了记忆堆积带来的上下文污染问题。

INSIGHTAtlas 的核心洞察将记忆的作用从参考资料重新定义为行为编译器。对搜索 Agent 工程的启示：(1) 历史检索轨迹中的成功模式应被抽象为检索策略指令（如对时效性查询优先过滤最近7天的帖子），而非原样存储供参考；(2) 编译思想可应用于个性化搜索：用户历史行为→抽取偏好策略→注入为搜索 Agent 的行为指令，比传统 Embedding 用户向量更具可解释性；(3) 避免记忆膨胀对搜索 Agent 延迟的影响，是实际部署中的重要工程考量。

Efficient LLM Serving for Agentic Workflows: A Data Systems Perspective

Agentic 工作流由一系列相互依赖的 LLM 调用组成，已成为现代 AI 系统的主流负载。这类工作流因投机执行和并行探索而存在大量重叠的 Prompt 和中间结果冗余，但现有 LLM Serving 系统（如 vLLM）专注于单次请求优化，无法感知工作流级别的冗余。本文从数据系统视角分析 Agentic 工作流的特征，提出工作流感知的 KV Cache 共享、跨 Agent 调用的中间结果复用等优化策略，在保持功能正确性的前提下显著降低 Agentic 工作流的端到端延迟和计算成本。

INSIGHT搜索 Agent 的 Serving 效率是生产部署的核心瓶颈。本文的关键洞察：Agentic 工作流中大量 LLM 调用共享相同的系统 Prompt 和部分查询上下文，这是天然的 KV Cache 复用机会。对搜索系统的工程启示：(1) 多轮检索 Agent（query 扩展到检索到重排到答案生成）的各阶段 LLM 调用应共享 Prefix KV Cache；(2) 同一用户的多次检索 Session 间的共享系统 Prompt 也应被识别并缓存；(3) 数据系统层面的优化（并发调度、结果复用）比模型层面的压缩更直接影响搜索 Agent 的 P99 延迟，对高并发社区搜索场景尤为关键。

ARISE: Agent Reasoning with Intrinsic Skill Evolution in Hierarchical Reinforcement Learning

现有基于 RL 的推理增强方法将每个问题实例孤立处理，无法利用训练过程中涌现的可复用策略。ARISE 提出层次化强化学习框架，其中共享策略同时在两个层次运作：上层控制器根据问题类型选择技能（skill），下层执行器应用技能解决具体问题。内在技能进化机制（Intrinsic Skill Evolution）在训练过程中动态识别新涌现的有效策略并将其固化为可复用技能。在数学推理基准上，ARISE 相比单层 RL 基线取得显著提升，且技能库随训练持续扩充。

INSIGHTARISE 的层次化 RL + 技能进化机制对搜索 Agent 训练有重要借鉴意义。(1) 搜索 Agent 中同样存在可复用的技能：如时间范围过滤、权威来源优先、多角度查询扩展等策略，应被显式建模而非让模型在每次推理中重新发现；(2) 内在技能进化可应用于搜索 Agent 的持续学习：从用户反馈中识别高价值检索策略并固化；(3) 层次化 RL 框架（上层选择检索策略，下层执行具体检索操作）比端到端单层 RL 更适合处理搜索任务的组合复杂性，在训练稳定性和最终性能上都更优。

Internalizing Agency from Reflective Experience

当前基于结果驱动的后训练方法（如 RLVR）主要优化最终成功信号，未能充分利用 Agent 与环境交互过程中产生的丰富反馈，导致策略分布收窄（distribution sharpening）：模型越来越擅长复现已有成功行为，但遇到新情况时自我修复能力差。本文提出 Reflective Experience 方法，让 Agent 通过反思失败交互中的环境反馈来内化更通用的 Agency 能力，包括错误识别、策略调整和从失败中学习。在多个 Agentic 任务基准上，模型展现出更强的容错性和对新环境的适应能力。

INSIGHT从失败中学习是提升搜索 Agent 鲁棒性的关键途径。本文的核心贡献在于将环境反馈（而非只有最终 reward）作为训练信号。对搜索系统的启示：(1) 搜索 Agent 的训练不应只关注是否找到正确答案，中间步骤的环境反馈（如检索结果为空、候选集质量差）同样包含有价值的监督信号；(2) 反思机制可用于构建搜索 Agent 的自我诊断能力：当检索结果质量低时，Agent 能识别原因（query 歧义/召回策略失当）并自动调整；(3) 避免策略分布收窄对搜索多样性的伤害，是实际部署中需要持续监控的问题。

Rui Ge, Yichao Fu, Yuyang Qian, Junda Su, Yiming Zhao, Peng Zhao, Hao Zhang

Omanic: Towards Step-wise Evaluation of Multi-hop Reasoning in Large Language Models

现有多跳问答基准只评估最终答案，无法诊断 LLM 在哪个推理步骤出现错误，使得模型改进方向不明确。Omanic 提出开放域多跳推理的步骤级评估框架，为每个推理步骤提供细粒度标注，包括子问题生成、中间检索结果和推理链追踪。基准包含多种多跳推理结构（桥接型、比较型、交叉型），并引入步骤准确率（Step Accuracy）和推理连贯性（Reasoning Coherence）等新评测指标。评测结果揭示了当前 SOTA 模型在多跳推理中的具体瓶颈：在桥接实体定位和跨文档推理转换上错误率最高。

INSIGHT步骤级评估是诊断和提升 Agentic Search 质量的重要工具。Omanic 的设计启示：(1) 对搜索 Agent 的评估不应只看最终答案，每次检索操作和推理步骤都应被追踪，这能帮助识别错误来自哪个检索轮次；(2) 分类型分析（桥接型 vs. 比较型多跳）对于优化社区搜索中不同类型的复杂查询有参考价值，应在 Agent 训练数据中分别覆盖；(3) 步骤级标注数据的构建虽成本高，但对于监督微调阶段的搜索 Agent 训练至关重要，是当前高质量 Agentic 训练数据的稀缺资源。
