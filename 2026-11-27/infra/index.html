RankCast: Phase-Aware Rank Balancing in MoE Serving

MoE 推理里，专家并行会让每一层都等最忙的那张卡。预填充阶段受计算限制，瓶颈是最忙卡上的 token 数；在中等批量下，解码受访存限制，瓶颈则变成各卡上同时激活的专家数。训练时即使用了负载均衡，上线后冻结的路由器仍会碰到批次波动和领域漂移，真正卡住时延的是某一瞬间各张卡上的负载。RankCast 给每个 token 保住预测出的主要专家，其余名额再从更大的候选里分到较空的卡上：预填充时把灵活分配赶到负载更低的卡，解码时关掉最忙卡上的部分专家。计算和通信还能跟模型执行重叠。在 Qwen3-235B 和 Qwen3.5-397B 上，它消除了最忙卡上超过 75% 的多余预填充负载，预填充吞吐最多提高 19%，每输出 token 的解码时间最多降低 10%，质量损失不到一个百分点。

PipeAxes: Decoupling Compute and Communication Granularities for Pipeline-Parallel LLM Serving

用流水线并行在 PCIe 服务器或异构 GPU 上跑长上下文时，现有引擎常把预填充切成 token 块，块大小同时决定了 GPU 批宽和级间激活传输量。块太小会反复装权重，块太大又会把交互请求堵住。PipeAxes 让较宽的预填充批一次只跑几层，好在切片之间插入解码，并用压缩后的激活在独立大小的行组里传输，调度再按时延余量选批宽、切片深度和行组大小。衡量标准是有多少请求同时满足首 token 时延、每输出 token 时延和尾部间隔。在四段 MoE 流水线上，它在时延目标内的服务速率达到校准后 Revisit-PP 的 23.3 倍。在混合的长上下文负载里，短请求的高分位首 token 时延从原生 vLLM 的 129.8 秒降到 512 毫秒。

Xiaoqiang Guo, Yifan Lin, Yang Liu, Jianan Zhang, Yingqi Peng, Jiamei Lv, Yi Gao, Wei Dong

Any-Rate: Half-Bit Multi-Precision LLM Quantization with Coded Bit-Planes

端侧部署往往要在不同的内存和能耗预算之间切换精度，但一套权重里如果只能按整比特截取，相邻精度之间空隙大，到二比特时准度还会掉得很厉害。多个精度共用高位平面时，各自还要对齐不同目标，容易再损失一截准度。Any-Rate 从同一份检查点提供从二比特到八比特的多种精度，并在二到四比特之间按半比特分档。它把部分比特平面限制成短码字，各精度共用一行查找表，再为每个精度分别设目标，减轻共用高位平面带来的损失。在四个语言模型上，二比特仍能保住 FP16 准确度的 69%，在多精度方法里处于领先，解码速度也和现有内核差不多。按同等准确度估算，LPDDR 能耗最多可降 27%。

Hoonki Lee, Haechan Shin, Hyuntaek Jung, Yeonu Choi, Sangyeob Kim

DFly2: Turbocharging Long-Context Speculative Decoding by Sharing the Target&#39;s Sparsity

原生稀疏的长上下文模型已经在为目标查询挑选位置，投机解码的草稿模型却还常自己存一份上下文缓存，或者把整段、最近窗口都读一遍。自己建缓存会占显存、拖慢预填充，也会挤掉并发；按查询再算一遍选择，代价又会随上下文变长。DFly2 直接复用目标模型已经付过费的缓存和选择：每一层草稿只读配对目标层缓存里、被索引器挑中的那些位置，自己不再做打分、也不另建缓存。选择集合大小固定，却可以落在上下文的任意位置，因此长提示不必多读。在高并发、且每用户解码速度对齐时，服务 DS-V4.1-Flash 在长上下文和 agent 集合上的吞吐分别高出 62% 和 81%。

How to Optimize NVFP4 Attention on NVIDIA RTX Blackwell Through Register Recycling

NVIDIA

服务世界模型时，长序列会让注意力成为明显瓶颈。在 NVIDIA RTX Blackwell 上，NVFP4 能用四比特矩阵乘提高吞吐，但 softmax、数据搬运和中间结果之间的依赖，容易让 Tensor Core 空转。这类消费级芯片上的注意力又常常卡在矩阵乘，而不是 softmax。一种寄存器回收的排程把每个分数块拆成两个更窄的槽，在 softmax 量化之后立刻把寄存器让给下一块的计算，而不必再开一整块分数缓存。寄存器几乎占满，很难再同时放下下一块分数。在 RTX PRO 6000 Blackwell 上，NVFP4 注意力内核最多可加快 1.64 倍。Reactor 把优化后的内核接到世界模型的生产服务栈里，在 LongLive、Helios、OmniDreams 和 Cosmos 3 Nano 等负载上，端到端推理时延最多降低 15.34%。这套排程已合入 FlashInfer 主干。

Asymmetric Speculative Decoding: Unlocking In-Context Learning in Draft Models

投机解码的实际加速常常远达不到理论上限，尤其在推理任务上。原因是草稿模型和目标模型拿到同一份提示，弱很多的草稿模型被迫自己解题，拒绝率一高，并行校验的好处就没了。即便草稿模型能做出对的答案，解题路径也可能和目标模型不一致，照样会被拒。接受率会随着生成过程单调上升，说明草稿模型其实在已通过校验的 token 上做上下文学习，逐渐对齐目标分布。AsymSpec 不再给两边同一份提示，而是给草稿模型提供任务相关的例题解法，把它的目标从解题改成模拟，并且不用重新训练。在推理、代码和摘要任务上，它相对自回归解码可加速 2.29 倍到 4.95 倍，也超过常规的投机解码。

Guang Huang, Zeyi Wen

Looped Models are Fast Multi-Token Predictors

循环语言模型靠调整循环次数来改变算力，而不必按比例增加独立参数。浅循环常被拿来当快速草稿，深循环再做校验，因为起草时仍能用上全部参数。其实浅循环也能一次预测后面好几个 token。Floodgates 在序列末尾接上一组掩码 token，用低秩适配学会并行起草这些位置，并且保持无损。加速还依赖循环模型在各深度上都受过训练，让浅草稿能借校验时已经算好的深层前缀缓存。在七个模型、五项基准以及多种批量和解码方式下，它在多数情况下是最快的无损解码方法，加速最多达到 7.5 倍。四次循环的浅模型上，单次循环起草平均最多可加快 5.1 倍；更高的加速出现在更深的模型和弹性起草上。

Ayhan Suleymanzade, Sean McLeish, Sehoon Kim, Jinwoo Kim, Antoine Bosselut

Libtt: A Compiler and Runtime for Tenstorrent Processors

要在 Tenstorrent 芯片上跑现成的 PyTorch 和 JAX 程序，关键是接到这些框架已经用来驱动 TPU 的那套接口。Libtt 实现了这套接口，JAX 可以直接跑，PyTorch 则经 TorchTPU 接入，为 TPU 写的软件除了替换自定义内核外不必改。它把编译器和多卡运行时打成一个共享库，修了大量上游问题，还补了新的编译优化，让已有代码尽量开箱能跑。多数 JAX 和 TorchTPU 测试能够通过，SGLang、TorchTitan 和 Miles 也能跑起来，覆盖服务、微调和强化学习。四卡上可以沿用 TorchTitan 的 TPU 训练路径，而不必改训练框架源码。小规模对照里，芯片上的起始损失和 CPU 能对到小数点后三位。融合注意力和损失之后，Qwen3-8B 在单卡上的训练吞吐从每秒 287 个 token 提到 435 个。

Letting Models Manage Their Own Context: Where We Stand

今天的 agent 运行框架多半替模型管上下文：窗口满了就触发压缩，把历史摘要掉。另一种做法是让模型通过上下文接口自己决定何时压缩、压缩什么。对比是在 NVIDIA 开源框架 NOOA 里做的，任务包括文档研究和机器学习工程，上下文预算从很紧到很宽。能用好这套接口的模型往往更准，输入 token 也常常更少，预算紧时尤其明显：GPT 6.1 在 OfficeQA Pro v2 上的得分从 21% 提到 56%，几乎提高到原来的三倍。各模型调用频率、压缩力度和起步时机差得很远，改提示也会改变时机。推理引擎若复用编辑后未改后缀的 KV cache，单次请求的预填充计算最多可减 15%，准确度没有可测变化。

nnTrace: Detecting and Localizing Silent Bugs in Distributed Training

大规模分布式训练要把计算摊到成千上万块 GPU 上，实现一复杂，就容易出现不报错、却把训练结果算错的静默缺陷。只看训练损失或梯度范数曲线，往往发现得慢，有时根本看不出来，更难以定位到出问题的地方。nnTrace 用差分测试来做检测和定位：把分布式训练过程中的中间张量，与一份可信的参考实现对齐，再比较对应位置的浮点值。关键是容忍差不能随便设，它给出一套数学分析，用来区分缺陷造成的误差和正常的数值误差。这样，检查才不会把舍入差异误判成缺陷，也不会把真正的静默错误放过去。对正在做大规模训练的人来说，先能指出错在哪一层、哪一个张量，比只看见曲线后来不对要有用得多。

Haitian Jiang, Shaowei Zhu, Zhen Zhang, Zhenyu Song, Xinwei Fu, Zhen Jia, Yida Wang, Jinyang Li
