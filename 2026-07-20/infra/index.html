Launching UI for generative AI inference recommendations in Amazon SageMaker AI

针对生成式模型上线前需要反复试配实例、Serving 容器和优化参数的问题，Amazon SageMaker AI 将推理配置推荐能力做成可视化工作流。系统以真实基准测试比较成本、吞吐和延迟组合，常见工作负载可在数分钟内得到生产配置，自定义负载也能在数小时内完成评估；文章是工程发布，未给出统一模型上的精度或吞吐对照表。

对象存储向量检索概述

Tencent

腾讯云把向量检索直接接入对象存储 COS，由数据万象智能检索服务从图片、文本和视频对象中抽取特征并维护语义索引，通过 API 支持以文搜图、以图搜图、视频相似检索和文档检索。方案减少非结构化内容搬迁与独立向量栈维护，适合媒体资产和社区内容库；产品文档说明了能力边界，但没有公开延迟、召回率或规模基准。

INSIGHT对象存储与向量索引一体化适合冷数据和多模态 UGC：原始对象、元数据与向量生命周期可以统一管理，降低离线同步和删除一致性风险。落地时仍应把高频内容的在线 ANN 索引与 COS 后端分层，并针对帖子短文本、图片 OCR 和视频片段分别评测召回率、索引更新延迟与成本，避免将通用多模态能力直接等同于搜索相关性。

03 3.45

Monitor and debug generative AI inference with SageMaker detailed metrics and Insights dashboard on CloudWatch

Amazon

AWS 针对生成式推理端点 P99 延迟突增难定位的问题，在 SageMaker 与 CloudWatch 中汇总 GPU 利用率和显存压力、KV Cache 饱和度、跨可用区流量、请求排队及自动扩缩容状态。统一仪表盘帮助运维人员区分容量、缓存、路由和扩容策略故障，适用于数十模型、数百 GPU 实例；文章侧重操作路径，没有报告受控实验的故障定位提速比例。

INSIGHT大模型 Serving 的可观测性必须同时覆盖请求、调度器、KV Cache、GPU 和模型输出质量，仅看 GPU 利用率无法解释搜索链路的尾延迟。社区搜索可把 query 类型、输入/输出 token 长度和召回阶段标签写入 trace，再与 P99、缓存命中和扩容事件关联；这样能判断慢请求来自长上下文、热点模型、跨区路由还是容量不足，并建立分模块 SLO。
