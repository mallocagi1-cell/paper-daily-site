Decoupling Search from Reasoning: A Vendor-Agnostic Grounding Architecture for LLM Agents

生产环境 LLM Agent 越来越依赖实时搜索，但模型自带的 native search grounding 把检索策略、provider 选择、证据注入、成本、延迟、生成行为捆绑在单一模型-厂商边界内，难以检视、调参、复用与迁移，还会触发 Search-Induced Verbosity 破坏严格输出格式。论文提出 Decoupled Search Grounding (DSG)，用一个 MCP 兼容网关把 grounding 移出推理模型，将 provider 路由、来源感知上下文渲染、可配置 fallback、检索深度控制、精确+语义缓存都做成一等可控项。在 SimpleQA/FreshQA/HotpotQA 上对 5 个前沿模型评测：native search 仅在时效敏感的 FreshQA 占优，DSG 在整体上给出更强 frontier。

1. 问题与动机

生产环境的 LLM agent 越来越依赖实时检索来 grounding，但主流的 native search grounding（模型厂商把检索做成 provider-managed 的一体化特性）把检索策略、provider 选择、结果归一化、缓存、工具输出格式、迁移路径全部锁在模型-厂商边界内。作者把耦合带来的部署难题概括为四点：模型-厂商锁定、不透明延迟、固定成本结构，以及指令遵循退化——后者被命名为 Search-Induced Verbosity（检索诱发啰嗦）。量化证据：HotpotQA 上即便 prompt 明确要求"只给最终答案实体"，Claude Sonnet 4 的 native-search 运行有 78.1% 的预测以"Based on the search results..."开头；在 exact-match 失败样本里 62.3% 其实包含正确答案子串——答案是对的，却被解释性散文包裹而违反下游 parser 的 exact-match/JSON/boolean 契约。Figure 2 显示 native 响应中位长度比无检索长 27.1%（353 字符）、78.4% 是解释性输出，而 DSG 格式漂移为 0%（示例中 native 245 字符 vs DSG 答"Yes"仅 3 字符）。当 LLM 在自动化管线里只是中间节点、输出要被解析/分类/缓存/路由时，这种啰嗦是真实部署风险。

2. 方法详解

DSG（Decoupled Search Grounding）把 grounding 实现为一个 MCP 兼容网关，夹在 agentic 应用、可互换推理模型、provider-agnostic 检索后端之间，核心是"可控边界本身"：把 provider 策略、缓存复用、fallback、source-aware 上下文渲染外化为配置，推理模型保持可替换。三大组件：

(1) Source-Aware Tool Formatting：用显式可配置的 tool schema 暴露检索；LLM 发出 search tool call 后，网关执行并把异构 provider 响应归一化成结构化内部 result object，把 snippet 与 source URL 配对，给模型显式 provenance 线索（哪条证据支持哪个判断），这些 URL 同时成为日志、调试、来源过滤、fallback 的可检视产物，保住了检索-生成的边界（而 provider-managed 的上下文流会把它压平）。

(2) Provider Abstraction and Fallback：网关充当 grounding control plane，Provider Registry 把 Serper、BrightData、Firecrawl、Exa 等 agnostic provider 归一化；标准 HTTP provider 经 YAML adapter 接入（指定 endpoint、method、headers、请求模板、响应字段映射、能力、成本元数据），复杂 provider 用专用 adapter。provider 超时或报错时请求沿配置 fallback 链推进，瞬时故障不打断模型收到的 grounding 上下文。

(3) Search Intelligence Layer：跨请求优化检索策略的分层决策（Algorithm 1: Cache-Gated Provider Execution）。设 q 为 query、q̄ 归一化形式、C={(q_i,R_i)} 为 provider 隔离的语义缓存、e(·) 为 embedding、p_1..p_k 为配置 fallback 链。决策 D(q)：q̄ 命中 exact cache 则返回 R_e；否则取语义最近邻 j=argmax cos(e(q),e(q_j))，若 s_{j}≥τ（可配阈值）返回 R_{j*}；否则走 fallback 链 S(p,q) 逐 provider 执行，命中后写回 exact+semantic 双缓存。关键设计：缓存条目用 provider-scoped key，避免一个 provider 的结果悄悄替换另一个；缓存带 provider+domain 级 TTL，时效敏感 query 快速过期、静态事实长期保留，从而在不牺牲新鲜度下维持高命中。缓存位于共享网关之后，一个应用检索的证据可被另一应用复用，warm-cache 命中率随流量汇聚而升。所有控制以配置而非代码表达，使单一 grounding 层可在多 agent/多推理模型上统一治理，无需重训或重写 prompt。

3. 核心技术贡献

论文自述三点：(1) grounding 的系统边界——把 search grounding 形式化为解耦、provider-agnostic 的层，让推理模型可互换，同时把检索策略、缓存、provider 选择暴露为显式系统控制；其价值不在新算法，而在"把这个选择变成可控决策"，provider 退化时能逐 query/逐应用归因 grounding 成本与延迟、检测回归。(2) search-intelligence 与标准化框架——用 MCP 兼容网关给 agent 稳定检索接口，把异构 provider 输出归一化成 source-aware context，并支持带配置 fallback 的 cache-gated 检索（Algorithm 1 的分层 cache 决策）。(3) 对行为/质量/运营的证据——识别并量化 native 特有的 Search-Induced Verbosity，展示结构化工具边界如何缓解它，并在公开 QA 与生产负载上量化 accuracy/cost/retrieval-depth/cache-reuse 权衡。相比 Self-RAG/FLARE/RARR/Adaptive-RAG/IRCoT 等"检索-推理交互"工作，DSG 的定位正交：它不改检索时机或推理过程，而是固定 grounding 接口、让推理模型可换，研究"检索被嵌成不透明 provider 行为，还是被暴露成显式可控子系统"。

4. 实验结果分析

评测覆盖 5 个前沿模型（GPT-4o、GPT-4o-mini、Gemini 2.5 Flash、Gemini 2.5 Pro、Claude Sonnet 4）、4 类基准：SimpleQA（短事实）、FreshQA（时效）、HotpotQA（多跳）、QIU（电商意图：Retail N=7988 / Tail Synthetic N=2335）。成本为 provider 侧每 1K query 检索成本（不含模型推理）；SimpleQA/FreshQA 用 GPT-4.1 做 LLM-as-judge（3-judge 验证 97.78% 一致），HotpotQA 用确定性 EM/F1。

主表（accuracy / 每 1K query 成本）：

  • SimpleQA（5 模型均值）：No Search 30.8/$0；Native 87.7/$20.00；DSG+BrightData 86.1/$1.80；DSG+Serper 83.3/$0.67。DSG+BrightData 仅低 1.6 点、成本降 91%。
  • FreshQA：Native 72.6/$20.00；DSG+BrightData 68.0/$1.86；DSG+Serper 67.3/$0.66。这是 native 领先场景（时效敏感，native 紧耦合新鲜度/索引占优），作者据此主张"freshness 主导时把 native 当 fallback 链里的一个 provider"。
  • QIU Retail（Gemini Flash）：Native 93.40/$7.90；DSG+Serper 93.90/$0.110；DSG+BrightData 93.81/$0.238。DSG+Serper 反超 native 0.5 点、成本降约 98.6%。
  • QIU Tail（Gemini Flash）：Native 87.62/$10.37；DSG+Serper 87.79/$0.146。同样反超且成本降超 98%。注意 native baseline 是原生支持 Google Search grounding 的 Gemini Flash，用通用 provider 仍能持平/超越，说明外化控制可抵消紧耦合 native 的优势。

运营控制（Figure 4）：检索深度可调——SimpleQA 准确率从 2 个结果到 4–6 个结果急升、6–10 饱和（"practical sweet spot"），把 grounding 变成可调预算旋钮。重复 query 缓存实验（GPT-4o + DSG+BrightData）：warm pass 命中率 99.4%，平均延迟从 cold 4,570ms 降到 warm 1,465ms（降 68%），边际检索成本从 cold $0.739（6.2% 命中）降到 warm $0.0045（99.4% 命中），近乎归零。

5. 局限与未来方向

作者明确列出三条局限：(1) 依赖第三方 API——解耦架构根本上依赖 Serper/BrightData/Firecrawl 等 vendor 的稳定性、延迟、数据质量；其定价、限流、索引行为变化会移动论文的 cost-accuracy Pareto 前沿，论文强调贡献是"可控 grounding 接口与它暴露的运营前沿"而非某个价格点。(2) 多跳推理受限——HotpotQA 上无论 native 还是 DSG，检索增强相对单跳事实（SimpleQA）只带来温和增益；DSG 的工具边界对"可控检索"最有效，复杂多跳可能需更紧的迭代循环（planning、reflection、重复证据获取），单纯解耦不够。(3) 评测方法——LLM-as-judge（GPT-4.1）对格式敏感可能有偏，用 3-judge 多数投票缓解，但人评仍是金标准。未来方向：用 provider 侧 telemetry 进一步隔离 Search-Induced Verbosity 的内部触发器、在边界加 contract-aware validator、在同一接口上学习自适应路由/检索深度/多跳策略。

6. 工业实践意义

DSG 已作为 DoorDash 的共享生产 grounding 层服务电商 QIU（多应用复用），早期版本获 2026 DoorDash AI Hackathon 工程卓越奖。对社区搜索（UGC 短文本）实践者的直接借鉴：

  • 把实时 grounding 当成可优化的接口边界而非模型自带功能：用一个 MCP/网关层统一管 provider 路由、检索深度、证据渲染、缓存，可独立 A/B 调优且不绑定单一模型厂商，更强推理模型出现时可热插拔。
  • 双层缓存（exact + provider-scoped semantic，带 domain/TTL）是高 QPS 短文本搜索降本提速的高杠杆点：99.4% warm-cache 命中把延迟降 68%、边际检索成本近乎归零；provider-scoped key + 差异化 TTL 避免缓存污染与时效失真，可直接落地。
  • source-aware 渲染 + 结构化 tool 边界能根治 Search-Induced Verbosity：当搜索结果要被下游 parser/排序/分类消费时，保持 answer-only 契约（DSG 0% 格式漂移 vs native 78.4% 解释性输出）能避免"答案对但格式错"的隐性故障。
  • 检索深度 4–6 的 sweet spot 提示：召回更多文档收益快速饱和，可据此设预算旋钮控成本。
  • 部署注意：强依赖第三方检索 API，需做好 fallback 链与 provider 退化监控；时效敏感场景（类似 FreshQA）native/紧耦合索引仍占优，应把它作为 fallback 链中的一个 provider 按需启用，而非全盘替换。

RODS: Reward-Driven Online Data Synthesis for Multi-Turn Tool-Use Agents

多轮工具调用的强化学习受限于静态数据集中有效样本快速枯竭。论文从 GRPO 的梯度分析出发，指出梯度信号集中在 rollout 奖励方差最大的任务上（Popoviciu 上界的结果），即处于 Agent 能力边界、成败各半的样本贡献了最大策略梯度；随训练推进该边界持续移动，逐步耗尽静态池中的有效样本。RODS（Reward-driven Online Data Synthesis）把进度奖励方差当作零成本的边界探测器（无需 rollout 之外的额外推理），在线持续合成处于能力边界的新任务，把 RL 训练与数据生成连成回路。

STARE: Surprisal-Guided Token-Level Advantage Reweighting for Policy Entropy Stability

GRPO 等可验证奖励强化学习（RLVR）已成为 LLM 复杂推理的主流后训练范式，但常在训练中出现策略熵塌缩。论文对 GRPO 下 token 级熵动力学做一阶梯度分析，发现 token 级信用分配错配：每个 token 的熵变化可分解为轨迹级 advantage 与下一 token 分布上熵敏感度函数的乘积，呈现 advantage-surprisal 四象限结构与近临界性。据此提出 STARE：用 batch 内 surprisal 分位数识别熵关键 token 子集，选择性重加权其有效 advantage，并引入目标熵项稳定策略熵。

INSIGHT把熵塌缩归因到 token 级信用分配、再用 surprisal 分位定位"熵关键 token"做精细重加权，是稳定 RLVR 训练的实用手段。对要用 RL 训练推理/搜索 Agent 的团队，启示是熵塌缩并非全局现象而集中在少数高 surprisal token；与其全局调 KL 或熵系数，不如按 token 的 advantage-surprisal 象限做差异化干预，兼顾探索与收敛。

Tsinghua University

Externalizing Research Synthesis and Validation in AI Scientists through a Research Harness

AI 系统日益能自动化科研流程，但连接已有证据、生成想法、实验与最终结论的推理常隐含在模型推理内部、不可检视。论文提出 Xcientist 研究 harness，把研究综合与实验验证外化为可检视、受契约约束的过程：将文献证据、想法状态、实现计划、消融记录、修复轨迹组织成持久的研究产物，使生成的机制可被 grounding、执行、测试与修订而不丢失证据依据。论文识别出 claim drift（可运行产物不再支撑最初所声称的机制）这一自动科研失败模式，并在免训练记忆系统、图结构交通预测、多尺度物理信息神经网络三个案例上验证。

INSIGHT把 Agent 的推理与证据外化为受契约约束、可检视的持久产物，并显式监控 claim drift，是提升自动化 Agent 可靠性的有价值范式。对构建研究/分析型 Agent 的启示是：长链路 Agent 容易出现"结论与实际产物脱节"，应让每步的证据、计划、实验结果留痕可审计，用契约校验绑定"声称"与"可运行产物"，降低 silent failure。
