1. GrepSeek: Training Search Agents for Direct Corpus Interaction
3.45
Relevance 3 | Novelty 4 | Practical 3 | Evidence 4 | Timely 4

Summary: GrepSeek 提出“直接语料交互 (DCI)”搜索 agent：不依赖预建索引的稠密/稀疏检索器，而是把语料本身当作环境，通过执行 shell 命令（grep 等）查找、过滤、组合证据。训练分两阶段：先用 answer-aware Tutor + answer-blind Planner 构造经验证的因果搜索轨迹做冷启动，再用 GRPO 强化。配套语义保持的分片并行执行引擎把 shell 检索加速最高 7.6× 且与顺序执行字节级等价。在 7 个开放域问答基准上 token 级 F1 与 Exact Match 综合最优。

Key insight: DCI 把“检索”重构为 agent 对原始语料的可执行操作，绕开了索引构建与表示对齐，适合证据需精确定位、语料频繁更新的场景。论文也坦言纯词面交互在 query 与文档表层差异大时会失效——对社区搜索这类同义/口语表达多的场景，DCI 需与语义检索互补而非替代。其“冷启动轨迹 + GRPO”两阶段训练对稳定 agent RL（避免大语料上直接 RL 的不稳定）有参考价值。

2. RAISE: RAG Design as an Architecture Search Problem
3.45
Relevance 3 | Novelty 3 | Practical 4 | Evidence 4 | Timely 4

Summary: RAG 流水线包含 query 改写、分块、检索深度、重排、上下文压缩等大量设计选择，实践中多靠经验配置，难以系统评估与复现。RAISE 把这一问题形式化为“RAG 架构搜索”，提供统一搜索空间与预算下的 RAG 超参优化框架与基准，实现 13 种搜索算法，在 7 个公开文本/多模态数据集上用 3 个随机种子评测。核心结论：优化效果高度依赖任务，某数据集上强的方法未必跨数据集泛化，警示不要把聚合排名当作普适最优证据。

Key insight: 把 RAG 调参当 AutoML/架构搜索问题，对工程团队是务实视角：与其手调 chunk size、检索深度、重排开关，不如在标准搜索空间内自动搜索。RAISE 提供可复现的实验底座。最关键的实践警示是“无普适最优配置”——社区搜索落地 RAG 时必须在自己的数据与指标 (nDCG/CTR) 上做超参搜索，照搬论文配置风险高。

3. CRITIC-R1: Learning Structured Critics for Retrieval-Augmented Generation
3.35
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 4

Summary: CRITIC-R1 把 RAG 的“批评/纠错”建模为显式错误诊断的强化学习问题，诊断维度包括判定 (verdict)、错误定位、推理分析与修复生成。引入两个奖励：Conservative Judgement Alignment 抑制过度干预，Diagnostic Quality Alignment 提升反馈质量。用 GRPO 结合外部监督训练，在 5 个问答基准上相比强 RAG 基线持续提升答案质量。

Key insight: 多数 RAG 纠错只给“对/错”二元信号，CRITIC-R1 让 critic 输出结构化诊断（定位+分析+修复），更接近可执行反馈，对搜索答案质量把控有借鉴意义。其“保守判定奖励”针对 critic 过度否定这一常见失效模式，提示在搜索结果审核/重写链路中要平衡纠错力度与误伤率，避免 critic 干预到本已正确的答案。摘要未给具体提升数字，落地需自行复测。

4. SAAS: Self-Aware Reinforcement Learning for Over-Search Mitigation in Agentic Search
3.35
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 4

Summary: agentic 搜索存在两类浪费：内部知识已足够却盲目触发检索，以及证据已充分却不停止搜索。SAAS 提出“自我感知”强化学习缓解过度搜索，包含搜索边界建模、边界感知奖励模块，以及用顺序课程学习 (sequential curriculum) 的分阶段优化策略。实验表明 SAAS 在保持准确率的同时显著减少过度搜索。

Key insight: 让 agent 学会“何时该搜、何时该停”直接关系到 LLM 搜索的成本与延迟。SAAS 的搜索边界建模思路，对社区搜索中“简单 query 走轻量召回、复杂 query 才触发多轮 LLM 检索”的分流策略有参考价值。边界感知奖励 + 课程学习是缓解 RL 训练中 agent 行为不稳定的可借鉴手段；但摘要未给量化收益，实际 cost 节省幅度需自行验证。

5. Does The Way You Plan Matter? An Empirical Study of Planning Representations for LLM Web Agents
3.20
Relevance 3 | Novelty 3 | Practical 3 | Evidence 4 | Timely 4

Summary: 针对 LLM web agent 探索不足、漏关键步骤、对任务约束敏感的问题，论文用 PlanAhead 静态“规划器-执行器”框架研究自然语言计划表示的影响。先把 WebArena 任务自动分为 3 个难度等级，再在难任务上系统比较 4 种计划表示（顺序子目标、叙述式、伪代码、清单），覆盖 OpenAI、阿里、Google 三家多模态 LLM agent。引入 Achievement Rate (AR) 与 Solved-Task Consistency (STC) 两个新指标应对随机性。结论：计划的表述形式与生成计划的 LLM 都显著影响 web agent 的鲁棒性与成功率。

Key insight: 同一 agent 仅改变“计划怎么写”（清单 vs 伪代码 vs 叙述）就能显著改变成功率，说明 prompt 中的计划表示是被低估的可调旋钮。对搜索 agent 的 query 分解 / 多步规划设计有直接启示：应把计划表示作为实验变量而非随手选择。AR/STC 两个考虑随机性的指标，比单次成功率更适合评估非确定性 agent，可借鉴到搜索 agent 的离线评测。

6. Meta-Cognitive Memory Policy Optimization for Long-Horizon LLM Agents
3.05
Relevance 2 | Novelty 4 | Practical 3 | Evidence 3 | Timely 4

Summary: 论文主张 LLM agent 的记忆优化应以“中间摘要所诱导信念的清晰度”为目标，而非只看任务是否成功。MMPO（元认知记忆策略优化）提出 Belief Entropy 作为自监督度量，对会引发高认知不确定性的摘要施加惩罚，从而提供细粒度、面向记忆的监督。在扩展到 175 万 token 上下文时仍保持 97.1% 的性能，并在多种长程任务上持续优于现有方法。

Key insight: 长程 agent 的瓶颈常在记忆压缩——摘要丢信息会让后续步骤“信念模糊”。MMPO 用信念熵直接监督摘要质量，思路新颖，对需要跨多轮维持上下文的搜索/研究类 agent 有参考价值。175 万 token 下仍保 97.1% 性能，显示其在超长上下文记忆管理上的潜力；但与社区短文本搜索场景距离较远，更适合 deep research 类长程任务。
