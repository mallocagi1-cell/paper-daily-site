1. Frontier: Towards Comprehensive and Accurate LLM Inference Simulation
3.35
Relevance 3 | Novelty 3 | Practical 4 | Evidence 4 | Timely 3

Summary: Frontier 是面向现代 LLM 推理的离散事件模拟器，统一建模 co-location、Prefill-Decode 分离 (PDD) 与 Attention-FFN 分离 (AFD) 三种部署形态，并纳入运行时优化与新型 workload。在 16 卡 H800 测试台上平均吞吐误差低于 4%；端到端延迟误差在 co-location 下从 44.9% 降到 6.4%、在分离部署下从 51.7% 降到 2.6%，并可在普通 CPU 上模拟 1000+ GPU 规模。

Key insight: 随着 PDD/AFD 分离式部署成为 LLM serving 主流，离线评估不同并行/分离方案的收益变得关键。Frontier 提供吞吐误差 <4%、可扩展到千卡的高保真仿真，让搜索/推荐团队在不占用 GPU 的情况下做 serving 架构选型与容量规划。可直接借鉴其对 co-location 与分离部署的统一离散事件建模方法。

arXivCUHK2026-05-20Yicheng Feng, Xin Tan, Yangtao Deng, Yimin Jiang, Yibo Zhu, Hong Xu
2. Tutti: Making SSD-Backed KV Cache Practical for Long-Context LLM Serving
3.35
Relevance 3 | Novelty 4 | Practical 3 | Evidence 4 | Timely 3

Summary: 针对长上下文 LLM serving 把 KV cache offload 到 NVMe SSD 时，GPU 显存碎片化产生海量微小随机 I/O、且 CPU 介入关键路径导致 I/O 性能差、GPU 停顿的问题，Tutti 提出以 GPU 为中心的 SSD-backed KV cache：通过 GPU 原生对象抽象、GPU 端 io_uring、slack 感知 I/O 调度，把 CPU 移出关键数据与控制路径。在严格 SLO 下相比 GDS 版 LMCache 把 TTFT 降低 78.3%，请求速率容量提升 2x，服务成本降 27%，性能逼近 DRAM 方案但获得近乎无限容量。

Key insight: 长上下文/长 session 的搜索问答场景中，KV cache 显存压力是主要成本来源。Tutti 证明用 SSD 承接 KV cache 在严格延迟约束下也可行（TTFT 退化有限、成本降 27%）。核心可借鉴点是把 I/O 控制下沉到 GPU（GPU io_uring + slack 感知调度）以消除 CPU 瓶颈，为低成本扩展超长上下文 LLM 检索提供了工程范式。

3. Serving Compound Inference Systems on Datacenter GPUs
3.15
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 2

Summary: 针对由多个 ML 模型按任务图 (task graph) 组合的复合推理系统，JigsawServe 在数据中心 GPU 上联合优化延迟、精度与 GPU 成本：自适应选择模型变体，并通过 GPU 空间分区做细粒度资源分配。相比最接近的前序工作，最大可服务负载提升 11.3x，仅用 43.3% 的可用 GPU 资源即满足精度 SLO，且延迟 SLO 违约低于 0.6%。

4. ReCoVer: Resilient LLM Pre-Training System via Fault-Tolerant Collective and Versatile Workload
3.05
Relevance 2 | Novelty 4 | Practical 3 | Evidence 4 | Timely 3

Summary: 大规模 GPU 集群预训练中硬件故障已成常态。ReCoVer 坚持一个不变式：每次迭代保持 microbatch 数恒定，使每步梯度与无故障运行在统计上等价。系统分三层解耦协议：容错集合通信隔离故障跨副本传播、step 内细粒度恢复保留迭代内进度防止梯度污染、versatile-workload 策略在幸存节点间动态再分配 microbatch 配额，且与 3D 并行和 HSDP 即插即用。在最多 512 GPU、累计丢失 256 GPU 的情况下保持训练轨迹，相比 checkpoint-restart 有效吞吐高 2.23x，在 234 GPU-hours 多处理 74.9% 的 token。

Key insight: 对自训大模型的团队，ReCoVer 的「microbatch 数恒定 = 梯度统计等价」不变式是优雅的容错思路，避免故障后训练轨迹漂移。相比传统 checkpoint-restart 的 2.23x 有效吞吐提升，体现了大规模故障频发场景下容错系统设计的价值；其 parallelism-agnostic 设计便于嫁接到现有 3D/HSDP 训练栈。

5. KVDrive: A Holistic Multi-Tier KV Cache Management System for Long-Context LLM Inference
3.00
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 3

Summary: 长上下文 LLM 的 KV cache 内存需求巨大，现有 offload 方案将完整 cache 放在 host 内存并在 decode 时按需取关键条目，但稀疏度无法继续提高否则掉精度；当上下文与 batch 增大，KV 传输成为 decode 延迟主因。KVDrive 从系统角度联合编排 GPU/DRAM/SSD 三层的 cache 放置、流水线调度与跨层协调：让 cache 管理适配注意力行为、重构 decode 流水线以重叠各阶段、协调跨层数据搬移，在保持精度的同时吞吐最高提升 1.74x。

Key insight: KVDrive 与 Tutti 同属长上下文 KV cache 分层方向，区别在于它强调「适配注意力行为的 cache 管理 + decode 流水线重叠」。1.74x 吞吐提升来自系统级跨层协调而非牺牲精度，提示部署长上下文 LLM 检索的团队：KV cache 优化应跳出单纯稀疏化，转向多层内存编排 + 流水线重叠的系统视角。

6. DynoSim: Simulating the Pareto Frontier
3.45
Relevance 3 | Novelty 3 | Practical 4 | Evidence 3 | Timely 5

Summary: DynoSim 是 NVIDIA Dynamo 推理栈的全栈离散事件模拟器 (Rust 实现)，把 workload 回放、单引擎调度、路由、planner 自动扩缩容与 KV cache 管理统一到一条虚拟时间线上，解决 LLM 服务部署中张量并行度、prefill/decode 拆分、worker 数、调度/路由/扩缩容阈值等多层耦合参数难以在真机上低成本调优的问题。在 M4 MacBook Air 上 2.41 秒模拟 60.1 分钟、23608 个请求 (约 1500x 实时)。示例发现：KV 感知路由把前缀缓存复用率从 0.38 提到 0.44–0.45；host 内存层 (G2) 在峰值并发下把平均 TTFT 降 19.3%；5–10 秒扩缩容间隔把扩缩容事件从 1529 降到 233。

Key insight: 对需要部署 LLM 做检索/排序的搜索团队，DynoSim 提供「先模拟后上机」的容量规划路径，避免昂贵的真机扫参。可借鉴的设计是把路由策略、KV 缓存分层、planner 阈值都建模成可扫描参数；其 KV 感知路由提升前缀复用、host 内存分层降 TTFT 的结论，可直接迁移到自建 LLM serving 的调优中。
