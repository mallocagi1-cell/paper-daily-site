AlignQuant: Tile-Aligned Mixed-Precision Quantization for Efficient LLM Generation

AlignQuant 将二维权重块统一用作精度分配、压缩存储与 GPU 执行单元，解决细粒度混合精度难以转化为实际加速的问题。联合预填充与解码校准后，专用内核复用同一份压缩权重；在 4 个 3B–14B 模型、3 种 GPU 和最长 64K 上下文中，相对 BF16 生成速度最高达到 2.50 倍。

BARQ: Balanced Codebook Refinement for Low-Bit LLM Quantization

NUS中中南大学

BARQ 用带熵正则的最优传输为权重块与码字建立均衡软分配，再按曲率加权重构代价更新码字，最后恢复普通硬编码。六个模型的 60 组配置中，54 组困惑度降低、53 组五任务平均准确率提高；Llama3.1-8B 在 2.125 位预算下，WikiText-2 困惑度从 11.00 降至 8.30。

INSIGHT创新主要发生在离线码本拟合阶段，推理仍使用原有硬编码路径，适合已有低位权重量化平台做增量改造。社区搜索可以优先试验 query 理解模型的压缩，并将短文本语义匹配质量纳入校准；部分配置没有同步改善所有指标，应结合业务 nDCG 与延迟筛选方案。

Cui, Chenhang, Xie, Xu, Xu, Linrui, Liu, Xiaohao, Zhu, Xingyu, Shen, Fei, Chua, Tat-Seng

03 3.75

FailBench: Evaluating Fault Tolerance Across Distributed Training Architectures

FailBench 在统一框架中评估 7 种分布式训练架构、8 种容错机制及无容错基线，共测试 142 种组合，使用 8 张 V100。A2 架构的磁盘检查点稳态开销为 0.5%，内存复制恢复约需 17 毫秒；但复制开销跨架构从 3.7% 到 176%，故不存在通用最优机制。

INSIGHT社区搜索模型持续训练可按并行架构、故障频率和检查点体积选择容错策略，优先测完整恢复时间而非只看状态加载速度。论文指出丢失一个工作节点后吞吐增加 17.9% 并未带来可检测的损失进展改善，因此应以达到业务模型质量所需时间评估系统收益，而非只追求样本吞吐。

Aljbab, Khaled, Barrak, Amine

04 3.70

ML Drift: Next-Gen GPU AI/ML Inference at the Edge

Google

Google 开源跨平台 GPU 计算引擎 ML Drift，通过张量虚拟化与统一着色器支持 OpenGL ES、OpenCL、Metal 和 WebGPU，既作为 LiteRT 加速核心也可独立使用。官方报告 Adobe 移动端图像编辑性能最高提高 30%，Snap 的人脸与风格生成模型延迟改善 30%；这些是视觉应用结果，并非搜索排序指标。

INSIGHT社区 UGC 搜索可探索把轻量文本理解或内容处理迁移到端侧，减少服务调用并控制隐私数据传输。其统一后端设计与旧 TFLite GPU delegate 迁移路径降低工程接入成本，但需先验证目标文本模型算子、设备覆盖、耗电与冷启动；视觉任务的收益不能直接等同于 query 理解加速。

05 3.65

XOR-Trellis: Ultra-Low-Complexity Dequantization and Curvature-Aware Hadamard-Free LLM Quantization

XOR-Trellis 针对极低位量化中反量化开销与旋转变换成本，设计低复杂度状态到数值映射，并在原坐标空间用曲率感知目标优化路径。Llama-3.1-8B 的 WikiText-2 困惑度达到 8.00，优于未旋转网格量化的 8.69 和启用 Hadamard 旋转的 QTIP 的 8.48，但仍高于 BF16 的 5.84。

INSIGHT该设计把运行时重构复杂度与离线量化误差分开优化，说明压缩率之外还需关注反量化是否拖慢 GPU。社区 UGC 搜索的 LLM 理解服务可评估免旋转压缩方案，但要检查短文本改写与排序特征质量；困惑度改善不足以证明端到端速度或 nDCG 提升，需补做服务压测。

SpecForge v0.3.0: a Unified Disaggregated and Colocated Speculative Decoding Stack, and New Open SpecBundle Draft Models

RRadixArk

SpecForge v0.3.0 将冻结目标模型的特征采集与草稿模型训练拆分为独立进程，由 SGLang 捕获特征、Mooncake 传输张量，再由训练工作节点消费引用。在 8 张 H20 上，3 个采集服务器加 5 个训练节点的布局比此前同置实现训练吞吐约提高 10%，同时统一多种投机解码方法和开源草稿模型。

INSIGHT该框架把特征采集、交付和生命周期定义为显式契约，便于独立扩容训练与推理资源，并在训练前检查导出与服务的一致性。社区搜索若要给 query 改写模型训练草稿网络，可借鉴这种分离架构与一致性门禁；应额外比较短输出场景的接受率、首 token 延迟与整体算力成本。

SGLang and Miles on NVIDIA Vera Rubin

RRadixArkNVIDIA

SGLang 与 Miles 在两台共 8 张 GPU 的 Vera Rubin 节点上适配推理和 RL 训练。团队通过加深 MLA 流水、融合 MoE 尾部通信及消除 KDA 隐式复制降低开销；128K 上下文的 MLA 在 batch 16 下加速 16%，融合尾部移除每步 276 次内核启动，带来 5.9% 端到端收益。

INSIGHT实践重点是按模型形状与硬件资源重新做性能分析，分别消除带宽等待、内核启动和隐式拷贝，而非只替换 GPU。社区 UGC 搜索的 LLM 服务可以借鉴融合与拷贝排查流程；这里针对 Kimi K3 和 Rubin 的局部加速不应外推到短 query 工作负载，需测真实请求分布及 nDCG 保真。

Distributed Learning with Selective State Space Models: Architecture-Aware Convergence Analysis

论文为选择性状态空间模型建立架构感知梯度、平滑性及 FedAvg/FedProx 收敛界，分析递归稳定性与客户端异质性的影响。在六个文本域上比较九种 Mamba2 联邦学习算法，理论预期与 16 种结果中的 13 种一致；SCAFFOLD 在一种异质性设置下改善 23/24 组配置，却在另一设置下恶化 22/24 组。

INSIGHT结果提示分布式训练配置不能照搬 Transformer 的经验，状态递归与本地更新步数会共同改变稳定性。社区搜索若探索分散数据上的轻量 SSM 训练，可先验证文本域差异和状态参数约束，再选优化器；这是训练稳定性的研究证据，尚不能直接推出线上相关性或 CTR 改善。

Cross-Facility LLM Pre-training on HPC: Elastic Aggregation, Data Leasing, and Queue-Aware Placement

该系统通过弹性 DiLoCo 聚合、带心跳的数据租约与队列感知调度，将跨两洲、相距最远 7400 公里的三台超算用于同一次预训练。Qwen3-0.6B 在 C4 上训练 2 万步后，困惑度为 34.7，集中式基线为 28.2；本地步数从 100 增至 2000 时，交换与检查点开销占比从 32% 降至 3.1%。

INSIGHT主要价值是把异构且零散的算力额度组织成可运行任务，代价是模型质量与跨站同步效率的折中。社区 UGC 搜索若已有集中式训练资源，采用收益有限；若跨机房资源只能分段获取，可借鉴数据租约避免重复消费，并同时比较训练损失、总墙钟时间和通信成本。

QuantaSpike: Short-Window Spike-Driven Quantization for Large Language Models

QuantaSpike 用对数三值脉冲神经元、分组增益和选择性异常值处理，在四步放电窗口内完成 LLM 量化推理。它在 OPT、Llama-2 上验证，并迁移到 Llama-3-8B 与 Qwen3-8B；相对 SpikeQuant，分析模型估计单次线性变换能耗分别下降约 80.0% 与 67.1%，这些数字并非真实 GPU 服务的能耗测量。

INSIGHT其可借鉴之处是用高信息密度事件编码减少异常激活导致的长时间窗口，同时保留移位与累加计算路径。对社区搜索团队更适合作为低功耗推理的研究储备：先确认硬件和算子支持，再测 query 理解质量、真实功耗与延迟，不能把线性层分析估计等同于线上整体节能。
