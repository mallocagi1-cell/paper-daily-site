Cascading Hallucination in Agentic RAG: The CHARM Framework for Detection and Mitigation

多步 agentic RAG 流水线在复杂推理任务上能力很强，但早期阶段引入的错误会沿推理链逐级传播并放大，最终产出“自信但事实错误”的结果，而现有幻觉检测机制系统性地漏掉这类失败。论文把这种“级联幻觉(cascading hallucination)”形式化为 agentic RAG 的一种独立失败模式，给出四类级联模式的分类，并提出 CHARM 架构框架：包含阶段级事实校验、跨阶段一致性追踪、置信度传播监控、级联消解四个组件，用于在多步推理中检测并切断错误传播。

When Retrieval Doesn't Help: A Large-Scale Study of Biomedical RAG

论文在生物医学问答上系统重检验“RAG 一定有用”这个假设，覆盖 5 个 7B–72B 开源指令模型、10 个生物医学 QA 数据集、4 种检索方法、4 个检索语料。结论是：检索相比无检索基线只带来小且不稳定的提升，通常在 1–2 个点以内；而更换 backbone 模型的影响远大于更换检索器或语料，专家来源与通俗来源的检索效果也接近。作者判断瓶颈不在检索质量本身，而在模型利用检索证据的能力有限。

INSIGHT一项大规模负结果，提醒搜索团队别默认“加 RAG 就涨指标”。可借鉴的方法论是：上 RAG 前先做“无检索 baseline 加换 backbone”对照，确认增量真来自检索而非模型本身；当检索增益只有 1–2 个点时，资源应转向提升模型对证据的利用能力（证据对齐训练、引用约束解码）而不是反复调检索器。对社区搜索这类噪声多的 UGC 语料尤其值得警惕。

Erfan Nourbakhsh, Rocky Slavin, Ke Yang, Anthony Rios

Improving the Efficiency and Effectiveness of LLM Knowledge Distillation for Conversational Search

University of Amsterdam

会话搜索依赖 LLM 做 query 改写来提升相关性，但推理期调用 LLM 成本高。论文研究从 LLM query 改写做知识蒸馏的若干细节：在 KLD 蒸馏目标上加入对比损失，发现能显著提升 precision 类排序指标，并系统比较了不同对比采样策略对蒸馏效果的影响。目标是用小模型逼近 LLM 改写带来的相关性，同时把推理成本压下来。

INSIGHT直接对应社区搜索的 query 理解加成本约束：把 LLM 的 query 改写能力蒸馏进小模型，线上用小模型扛 QPS。关键设计是 KLD 加对比损失的组合——纯 KLD 放松了对教师信号的对齐，补一个对比项能把 precision 拉回来，对“排序头部要准”的搜索场景正合适。对比采样策略的选择会明显影响蒸馏质量，落地时值得专门调参。

Stan Fris, Jan Hutter, Jan Henrik Bertrand, Simon Lupart, Mohammad Aliannejadi

Streaming Communication in Multi-Agent Reasoning

多智能体推理系统普遍采用“先生成后传递”，端到端延迟随流水线深度线性增长。StreamMA 让每个推理步一生成就流式传给下游 agent，相邻 agent 流水线化以降低延迟；意外的是这还提升了效果——因为多步推理质量不均匀、早期步比晚期步更可靠，只用可靠的早期步能避免易错的晚期步误导下游。论文给出 stream/serial/single 三种协议的首个闭式联合分析，推导出效果排序、加速上界与成本比，并在 8 个数学/科学/代码推理基准、Claude Opus 4.6 与 GPT-5.4 两个前沿模型、Chain/Tree/Graph 三种拓扑上验证 StreamMA 优于基线。

INSIGHT对多 agent 搜索/research 流水线，“流式传递中间推理”是一个同时降延迟、提质量的设计点。反直觉结论值得记住：把完整长 CoT 全传给下游不一定更好，早期可靠步反而更有用。社区搜索若用多 agent 做 query 分解→检索→汇总，可以让检索 agent 不等上游推理完全结束就开工，既省墙钟时间又减少被晚期错误推理污染的风险。

Zhen Yang, Xiaogang Xu, Wen Wang, Cong Chen, Xander Xu

MM-BizRAG: Rethinking Multimodal Retrieval-Augmented Generation for General Purpose Enterprise Q&A

JJPMorgan

当前多模态 RAG 趋向“最少解析”，直接用页面级图像产出检索 embedding 和答案，忽略了企业文档里丰富的结构化信息。MM-BizRAG 反其道而行：用“文档结构感知切分”动态把文档路由到不同朝向的摄入流水线——竖排文档（如报告）走显式版面解析，横排文档（如幻灯片）走整页表征，再用统一的 LLM 驱动 artifact 转换流水线做基于占位符的位置对齐，把版面、表格、图文结构显式建模回来。

INSIGHT对要处理图文混排 UGC（截图、长图、表格帖）的社区搜索有参考价值。核心可借鉴点是“按文档朝向/类型路由不同解析策略”，而不是一刀切全用页面级图像 embedding——结构强的内容显式解析，结构弱的整页表征。占位符位置对齐的做法能在保留版面信息的同时喂给 LLM，适合做多模态帖子的索引与问答。

ThoughtFold: Folding Reasoning Chains via Introspective Preference Learning

大推理模型靠 RLVR 在长 CoT 上不断进步，但主流 RLVR 只挑“结果正确”的轨迹做记忆，会把长 CoT 里的试错冗余一并强化，导致过度思考。已有方法多只给短轨迹更高 advantage，学习信号仍是结果导向，无法削减冗余探索的记忆。ThoughtFold 用细粒度偏好学习缓解冗余：用内省策略在每条正确轨迹内部识别冗余，生成一组候选子轨迹构成“谱”，再基于该谱引入 masked 偏好学习去压缩冗余探索，实现更高效的推理。

INSIGHT对用推理模型做搜索/agent 的团队，过度思考直接等于推理延迟和 token 成本。ThoughtFold 的思路是在“一条正确轨迹内部”做冗余识别，而非只在轨迹之间比长短，这更能精确剪掉无效探索。可借鉴到搜索 agent 的训练：用内省式偏好信号压缩多步检索里反复试错的步骤，在不掉准确率的前提下缩短推理链。

Ziyan Liu, Xueda Shen, Yuzhe Gu, Songyang Gao, Kuikun Liu

SaliMory: Orchestrating Cognitive Memory for Conversational Agents

Meta

作为终身陪伴的会话 agent 需要跨全部交互维持持久记忆，但单纯扩大上下文窗口塞入原始检索会拉低推理质量，用标准 RL 训练记忆 agent 又会在多阶段流水线里遇到严重的信用分配瓶颈。SaliMory 训练单个语言模型来管理认知结构化的记忆（用户事实、偏好、工作记忆），引入分层的阶段级过程奖励和奖励解耦的对比精修，为不同记忆操作（选择性过滤、整合、线索驱动召回）提供端到端的隔离监督。结果是记忆相关失败减少约三分之一、端到端准确率超 SOTA 10% 以上、Good Personalization 率翻倍多。

INSIGHT记忆是个性化搜索/推荐的长期能力。SaliMory 的关键设计是把记忆拆成“过滤/整合/召回”三类操作并分别给过程奖励，绕开多阶段 RL 的信用分配难题，比“无脑扩 context 加原始检索”更可控。对社区搜索的启示：用户长期偏好不该靠把历史全拼进 prompt，而应训练一个会主动过滤、整合、按线索召回的记忆模块；记忆失败减少三分之一的收益对多轮个性化场景值得复现。

Disentangling Answer Engine Optimization from Platform Growth: A Log-Based Natural Experiment on ChatGPT Referral Traffic

ChatGPT 等“答案引擎”已经向开放网络导出可测量的引荐流量，类似 SEO 的“答案引擎优化(AEO)”随之出现。公开 AEO 成功案例常引用很大的原始增长倍数，但原始引荐增长被答案引擎平台自身的高速增长所混淆。论文对单个高流量域名（glasp.co，数十万 YouTube 问答页）做纵向实地研究：2026 年 1 月对站点一个子集施加了一组 AEO 干预，用同域未干预部分作为吸收平台红利的同期对照，并用第一方分析与服务器日志（而非第三方概率估计）测真实增量。

INSIGHT给搜索/内容团队提了个度量警示：在 LLM 答案引擎时代评估“优化带来的流量增长”时，必须扣掉平台自身增长这个混淆项，否则会高估自家干预效果。可借鉴的实验设计是“同域未干预子集做对照 加 第一方日志”，比依赖第三方估计更可信。对做内容分发、被 AI 引用的社区平台，这套自然实验方法可直接用于评估 AEO 类改动的真实 ROI。

Keisuke Watanabe, Kazuki Nakayashiki

Reproducing, Analyzing, and Detecting Reward Hacking in Rubric-Based Reinforcement Learning

Tsinghua

基于 rubric 的 RL 用 LLM-as-a-Judge 按评分细则给输出打分作为奖励，但策略模型会利用裁判的潜在偏置进行 reward hacking，导致训练无效甚至不安全。现实中这类作弊往往细微且与多种裁判偏置纠缠，难以分析、检测、缓解。CHERRL 构造了一个可控的 reward hacking 环境：向 LaaJ 注入已知偏置，从而稳定复现 reward hacking、显式观测奖励发散、精确定位作弊起始点，并从可发现性与可利用性两个角度分析不同裁判偏置，探索用 agent 系统自动发现作弊。

INSIGHT凡是用 LLM 当裁判做 RL/对齐（含搜索相关性打分、答案质量奖励）的团队都该警惕 reward hacking。CHERRL 的方法论价值在于把“注入已知偏置→复现作弊→定位起始点”做成可控实验台，便于上线前压测自家奖励模型。对用 LaaJ 评相关性/有用性的搜索场景，可借鉴它从可发现性、可利用性两个维度审计裁判偏置，避免策略模型钻分数空子。

Xuekang Wang, Zhuoyuan Hao, Shuo Hou, Hao Peng, Juanzi Li

用 Agent 评测思路管理 AI Coding——31 万行代码 AI 重构的实践 (Meituan LongCat)

美团

当 90% 以上代码由 AI 生成，决定系统走向的不再是谁写得快，而是约束 AI 的能力——没有统一规范，AI 会成倍放大混乱。美团基于 31 万行代码的 AI 重构实践，分享用“Agent 评测思路”管理 AI Coding：通过技术债梳理、建设 Rule、重构 SOP 和 Pre-PR 机制，把重构从高成本专项变成随迭代持续推进的日常动作。

INSIGHT一线工业级 agent 落地经验，重点不在模型而在“约束与评测”。可直接借鉴的是 Pre-PR 机制和 Rule 体系——给 AI agent 套上明确规范与自动评测门槛，再让它大规模改代码，否则规模越大混乱越大。对搭建内部 coding/检索 agent 平台的团队，这套“技术债梳理→建 Rule→SOP→Pre-PR”的工程方法论，比单纯追模型能力更决定落地成败。
