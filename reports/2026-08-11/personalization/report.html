Progressive Alignment of Recommender Foundation Model through Multi-Phase Post-Training

推荐基础模型通常把点击或点赞等稠密标签当作最终目标，难以对齐真正决定推荐质量的业务指标。论文提出三阶段渐进式后训练：先线性探测（LP）稳定任务头，再全量微调（FFT），最后用带奖励模型的强化微调（RFT）对齐业务目标；离线实验优于单阶段方案，并在大规模线上 A/B 中超过传统非基础模型。

1. 问题与动机

这篇论文研究的不是一个孤立的点击率模型，而是推荐基础模型在真实业务目标上继续对齐的问题。作者来自 NAVER WEBTOON，场景是韩国 Webtoon 推荐。平台上的内容消费具有明显的漏斗结构：用户先看到曝光，再点击内容，随后可能读到免费章节、付费章节，最后才形成更深层的付费或持续消费行为。只优化最上层点击，容易把短期吸引力误当成长期价值；只用最终付费标签，又会遇到样本稀疏、反馈延迟和曝光偏差。论文因此把推荐目标写成多个层级的用户反馈，而不是单一的二元 CTR 标签。

论文还关注推荐基础模型的灾难性遗忘与策略不稳定。基础模型已经从大规模行为中学到通用的用户兴趣和物品关系，但在继续训练一个新的业务头时，随机初始化的 head 可能让模型快速过拟合当前标签，破坏原有的序列表示。反过来，直接用强化学习优化深层反馈，也可能因为奖励稀疏而出现训练不稳定。作者的问题是如何利用已有的推荐基础模型，在保持通用能力的同时，按由浅入深的阶段学习多层级业务目标，并让最终排序策略真正改善用户的深度参与。

作者将问题拆成三个相互衔接的阶段。第一阶段是 Language Pre-training，先利用语言模型式目标让推荐 backbone 对业务序列保持稳定的基础能力；第二阶段是 Funnel Fine-tuning，把六级漏斗信号转化成监督目标，建立从曝光到深层消费的有序反馈表示；第三阶段是 Recommendation Fine-tuning，通过 reward model、GRPO 或 DPO 对候选排序策略做后训练。这个顺序很关键：先恢复并稳定表示，再学习业务漏斗，最后让策略接受结果导向的优化。

2. 方法详解

基础模型采用约 7M 参数的 HSTU 结构。输入是用户按时间排列的内容交互，模型将历史行为编码成序列隐状态，再通过 cross-attention pooling 得到用户在当前请求下的表示。作者为 serving policy、reward model 和 propensity model 准备不同的 prediction head，分别估计推荐策略、用户反馈价值和曝光概率。这样业务目标、反事实评价和最终排序策略不会完全挤在一个分类头里。

反馈标签被组织成六个层级。论文正文把它们描述为从 impression、click、free consumption、paid consumption 到更深层消费行为的一组漏斗信号，中间共使用五个 cutpoints。每个 cutpoint 将用户行为划分成有序的累计事件，因此模型既能学习是否发生点击，也能学习点击之后是否继续读、是否触达付费和是否完成更深层目标。与把六个标签当成互不相关的分类任务相比，序数结构保留了漏斗的单调关系：已经完成付费消费的用户不应被模型解释成完全没有点击。

日志存在 exposure bias。用户只能对被展示的候选产生反馈，而展示本身由旧策略决定。作者用 propensity model 估计曝光概率，再用 clipped inverse propensity weighting 构造 SNIPS 风格的修正目标。低曝光概率但实际得到反馈的样本会获得更高权重，但权重被截断以避免单个样本主导训练。这个修正让 funnel head 不只是复读历史排序策略，而是更接近对候选策略的反事实评价。

第一阶段 LP 使用推荐序列上的语言模型式训练目标，让基础模型在继续学习时不立即偏向某一个稀疏业务标签。第二阶段 FFT 同时训练漏斗任务，论文比较了单阶段直接 FFT、先 LP 再 FFT，以及在 FFT 中使用 learning-rate control 的两阶段方案。最终进入第三阶段 RFT：先训练 reward model，把多个漏斗指标与业务偏好压缩成一个可比较的奖励；再将候选列表视为组，在组内计算相对优势，使用 GRPO 更新 policy。GRPO 的 advantage 采用组内归一化形式，并通过 clip ratio 约束更新幅度，再加入 KL 惩罚保持策略不要偏离参考模型过远。

作者还比较 DPO。DPO 不要求在线式策略采样，而是从偏好对中直接学习 chosen 与 rejected 排序，更接近 pairwise preference optimization。训练使用三周日志、10% 用户作为测试划分；LP 单阶段 100 个 epoch，LP 与 FFT 两阶段各 50 个 epoch；LP 学习率为 1e-3，FFT 的 head 学习率为 1e-4、backbone 学习率为 1e-5，RFT policy 学习率为 1e-5、backbone 学习率为 1e-6。线上候选列表限制为 top-32，GRPO 的 clip 为 0.1，KL 系数为 0.001。

3. 核心技术贡献

第一，LP→FFT→RFT 是一条面向推荐基础模型的渐进式对齐路径。它把表示保持、业务监督和策略优化分开，降低了从通用行为模型直接跳到稀疏深层奖励的风险。两阶段设置中加入 learning-rate control 后，RankNDCG 与 FunnelNDCG 都继续上升，说明小学习率的 backbone 与较快适应的任务头之间存在实际收益。

第二，论文将多层漏斗和曝光校正放在策略优化之前。这样 reward model 学到的不是单一 CTR 代理，而是经过 propensity 修正的多目标价值。对于点击诱导、短停留和长周期转化不一致的问题，这个建模方式比简单加权 CTR 更可解释。

第三，作者用 reward model 将复杂业务目标与策略训练解耦。GRPO 可以在候选组内比较不同排序策略的相对收益，而不是依赖每一个候选都拥有稳定的绝对奖励；DPO 则提供另一条不需要显式策略采样的路径。两者的对照说明，推荐后训练不应被理解为只有一种 RL 算法。

第四，在线实验验证了深层目标的改善可以传递到真实行为。论文在韩国 Webtoon 平台做了一个月 A/B test，比较 CTRL、SFT、GRPO with RM 与 DPO without RM。各方案在 click、engaged、last-free 和 last-paid 等指标上均呈正向结果且具有统计显著性；GRPO 更擅长推动更深层参与，DPO 对即时 click 的收益更突出。

4. 实验结果分析

离线实验最能说明渐进式训练的效果。单阶段 FFT 的 RankNDCG 为 0.429、FunnelNDCG 为 0.620；只做 LP 时为 0.426 和 0.620。两阶段但不做 learning-rate control 后升至 0.434 和 0.622；加入 learning-rate control 后为 0.437 和 0.625。也就是说，先保持基础能力、再做漏斗微调本身有收益，而让 backbone 用更小步长继续适应又能避免基础知识被快速覆盖。

进入策略后，reward model 配合 GRPO 的 RankNDCG 为 0.463，FunnelNDCG 为 0.637，是表中最强的组合。GRPO 不使用 reward model 时为 0.441 和 0.627，说明有质量的 reward model 对深层漏斗价值十分重要。DPO 配合 reward model 为 0.423 和 0.630，而不配合 reward model 为 0.453 和 0.637，表明 DPO 对偏好对的构造方式敏感。不能简单根据一种离线指标宣布 GRPO 或 DPO 永远更优；GRPO 的优势更集中在策略与深层目标，DPO 的优势可能出现在更直接的点击偏好。

实验划分使用最近三周数据，测试为 10% 用户。这个设置能够验证短期时间外推，但结果主要反映一个内容平台、一个短窗口和一个业务漏斗。线上测试持续一个月，CTRL 是既有控制策略，SFT 是监督微调基线，GRPO 与 DPO 是后训练候选。论文报告各层行为指标总体正向且 p<0.001，并指出 GRPO 对 engaged、last-free、last-paid 等更深反馈的改善更明显，DPO 对第一步 click 更有优势。对于实际业务，这个差异比单个总体 CTR 更值得关注。

5. 局限与未来方向

论文没有单列很长的 limitations 章节，因此下面区分正文明确给出的范围与基于实验设计的工程边界。作者明确展示的是 NAVER WEBTOON 的韩国 Webtoon 业务、约 7M 参数 HSTU、三周离线日志和一个月线上 A/B；论文没有证明同一套 funnel cutpoints、reward model 或 top-32 约束可以直接迁移到电商、社区搜索或广告。六级漏斗的具体层级依赖内容消费流程，换成 UGC 搜索时必须重新定义点击之后的有效阅读、收藏、关注或问题解决。

从数据角度，SNIPS 只能依赖 propensity model 的质量。若曝光概率估计错误、旧策略覆盖不足或极低概率样本被大量截断，反事实排序评价仍然可能有偏。三周日志对节假日、长周期留存和内容生命周期的覆盖也有限；一个月线上 A/B 能说明短期行为变化，却不能替代更长时间的用户留存、创作者生态和内容消费质量分析。

从模型角度，RFT 的 reward model 把多个深层反馈压缩成可优化的标量或偏好关系，仍有 reward hacking 风险。系统可能提高某一层停留或付费，却降低满意度、内容多样性或长期留存。论文报告了四层漏斗指标，但没有给出足够细的负反馈、重复曝光、长周期 retention 或不同用户群体公平性切片。未来扩大部署时，应加入反短期诱导的约束、用户分群稳定性分析和策略漂移监控。

论文没有公开完整线上数据、候选生成器、reward model 标注细节或复现所需的工业基础设施。因此外部团队可以复用训练顺序、propensity 校正和 GRPO/DPO 对照，却不能只凭公开表格复现线上 lift。更长窗口的 sequential A/B、跨域迁移、不同候选规模、稀疏注意力和面向用户长期价值的多目标 Pareto 训练，都需要单独验证，不能从当前结果直接推出。

6. 工业实践意义

对社区短文本搜索，最值得借鉴的是训练顺序，而不是照搬 Webtoon 的标签。可以先用 query、曝光、点击和阅读序列做 LP 风格的基础行为训练；再把点击、有效阅读、收藏、关注、问题解决或负反馈组织成符合业务流程的漏斗；最后再对排序候选做 reward model 与偏好优化。backbone 使用比 task head 小一个数量级的学习率，能够减少新业务目标对通用用户兴趣表示的破坏。

上线前应保留强控制策略，并把 CTRL、SFT、GRPO、DPO 放在同一实验框架里。离线要同时记录基础相关性和深层漏斗：搜索可用 RankNDCG、Recall、CTR、长点击、收藏/关注率与 query 解决率；推荐可用点击、有效消费、付费、负反馈、多样性和留存。不要把所有目标提前折成一个总分后只看总分，否则会失去判断策略到底改善了哪一层的能力。

propensity 校正应成为日志和评测的一等组件。记录候选曝光概率、位置、过滤原因与策略版本，训练 propensity model 时做校准检查，并把 clipping 阈值、有效样本量和权重分布放入每日监控。若新候选在历史策略下几乎没有曝光，就不能仅用离线 SNIPS 宣称它已经被充分验证；应通过安全探索、流量护栏或受控随机化增加支持集。

对候选策略的更新要有预算。论文在 RFT 中使用 top-32 候选与较小 KL 惩罚，这提示线上可先限制策略动作空间，确保每次请求的延迟和风险可控。实际部署还应监控 P50/P95/P99 延迟、GPU 利用率、候选重复率、负反馈、用户分群差异和 reward model 与真实业务指标的偏离。若 GRPO 主要改善深层参与而牺牲即时点击，应根据产品目标选择流量，而不是简单把即时 CTR 作为唯一门槛。

最后，建议把管线分成可回滚阶段：先上线漏斗感知的监督模型，确认指标和日志稳定；再在小流量引入 DPO 或 GRPO；每轮只改变一种策略、一个 reward 版本或一个候选预算。对用户生成内容和搜索场景，增加内容安全、重复推荐、诱导点击、低质长文和 query 误解等守护指标。这样，Progressive Alignment 才能从工业案例转化为可审计、可回滚、可持续迭代的推荐后训练流程。

Teacher Retains Full Tokens, Student Merges Efficiently: TM20K for E-Commerce Sequence Modeling in Ad Recommendation

ByteDance📖 有深读 · 13 分钟

TM20K 面向电商广告中的超长用户行为序列，用全注意力教师和学生模型配合两阶段知识蒸馏，再通过 token merge 压缩学生序列。该方法把线上序列长度扩展到 20K，已部署于字节跳动电商广告推荐系统，ADSS 提升 1.036%，服务延迟仅增加 5.6%，训练和服务成本接近原有 SOTA。

INSIGHT不要在教师阶段过早丢弃细粒度行为：先让教师完整读取 20K 序列，再把长序列知识蒸馏给可合并 token 的学生模型。对 UGC 推荐或个性化搜索，可以把长期兴趣压缩放在蒸馏阶段，并以线上延迟和行为覆盖共同约束，而不是只优化离线召回。

1. 问题与动机

TM20K 解决的是工业推荐里长期行为序列变长之后的计算与收益矛盾。传统线上模型常用约 5K 个行为 token；当序列扩展到 20K 时，用户更早的兴趣、周期性偏好和跨场景行为可能被保留下来，但计算量、显存和 serving latency 同时快速上升。论文在 ByteDance 的广告推荐场景测量到：从 5K 扩展到 20K，训练时间约为 3.5 倍，GPU 显存增加 49G，线上服务延迟约为 6.3 倍。这不是单纯把 batch 调小就能解决的工程问题，因为长序列的注意力和数据搬运会同时压迫训练、推理与集群成本。

作者首先分析 20K 序列中不同位置的注意力。最近的 10% token 贡献了接近一半的 attention，上层网络的注意力分布更尖锐，下层的分布相对均匀。这个观察意味着不同层、不同位置对 token 分辨率的需要并不相同：最新行为需要更细的粒度，较旧行为可以在语义相近或时间相近时压缩；浅层可能适合处理较粗的行为模式，高层则需要保留更有区分度的信号。若用同一种固定 pooling 或简单截断，就不能同时利用长历史与控制成本。

2. 方法详解

论文的主体是一个 full-attention teacher 和一个 token-merging student。teacher 直接读取 20K 行为 token，尽量保留完整序列信息；student 在不同位置做压缩，再通过知识蒸馏学习 teacher 的预测。这样在线服务只需要运行较短的 student，而不是把完整 20K 的代价放到每个请求上。作者强调这是模型结构、CPU 预处理、GPU 通信和 serving 栈一起设计，而不只是提出一个新的 pooling 层。

第一种压缩策略是 LITM，也就是 Locality-Informed Token Merging。它在时间间隔小于阈值 T 的相邻行为中寻找同一 item ID 的重复 token。论文示例采用 T=3；若同一个 item 在短时间内连续出现，说明这些 token 的增量信息有限，可以合并其特征。LITM 利用的是局部时间与 ID 一致性，计算简单，适合放在 CPU 预处理阶段。

第二种策略是 PATM，也就是 Position-Aware Token Merging。作者把 20K 片段划成 [1,1K]、[1K,5K]、[5K,10K]、[10K,20K] 四个区域，示例压缩因子分别为 1、2、3、4。较新的位置保持原粒度，较旧的区域逐渐合并。按这个例子，20K 序列可压缩到约 7K token。PATM 的重点不是精确固定数字，而是让 token budget 随时间距离和信息新鲜度变化；实际系统仍需按业务序列分布调节边界。

第三种策略是 LPTM，也就是 Layer-wise Progressive Token Merging。论文的六层 Transformer 示例中，每两层将序列长度减半一次，使不同层看到不同粒度的行为历史。低层保留较多 token 来建立局部表示，高层使用更短序列来集中计算全局关系。它与 PATM 的区别在于，PATM 按位置预先决定压缩率，LPTM 让压缩在网络深度中逐步发生；两者可以组合，也可以根据硬件和模型结构分别使用。

压缩前后还要处理工业系统的 CPU-GPU 边界。论文把可以提前合并的原始特征放在 CPU 侧处理，再把压缩后的结果送入 GPU，减少长序列 embedding 后的通信成本。候选 item 的特征不能随意合并，因为目标候选需要单独保留与用户历史的交互关系。模型使用 QK normalization 稳定长序列 attention，并在 student 中设置主预测头与蒸馏头。teacher 的 logits 被缓存，student 同时优化主任务交叉熵和 teacher-student 的知识蒸馏损失；推理时只保留主头。

训练数据来自工业 CVR 任务，覆盖两个月、数十亿样本，数据经过匿名化处理。模型隐层维度为 512，FFN 维度为 1024，使用 SwiGLU；global batch size 为 320，teacher batch size 为 96，训练使用数百张 GPU。这个设置说明论文讨论的不是一个小型离线实验：完整 teacher 的训练和缓存本身就是重大基础设施成本，student 的价值在于把这笔训练成本换成可上线的推理收益。

3. 核心技术贡献

第一，teacher-student 结构把使用完整长序列与低成本在线推理拆开。teacher 允许研究者先验证 20K 历史是否真的包含额外信号，student 再学习如何用更短序列逼近 teacher，而不是一开始就用启发式截断决定哪些历史没有价值。

第二，LITM、PATM 和 LPTM 分别从局部重复、位置新鲜度和网络层深度三个维度定义压缩。三者对应不同的信息假设：短时间重复行为的边际信息较小；越旧的行为越适合粗粒度表达；不同层对序列分辨率的需求不同。这个组合比一刀切保留最近 N 个 token 更接近工业行为数据的结构。

第三，作者把 token merging 与 CPU 预处理、embedding 通信、QK normalization、主任务/蒸馏双头放在同一系统里评估。对工业推荐而言，省下的不是只有 attention FLOPs，还包括显存、数据搬运、缓存和线上服务栈的压力。

第四，知识蒸馏让压缩 student 回收大部分长序列收益。teacher 在离线表中比 5K baseline 获得 +0.26% AUC；普通 student 获得 +0.15%，加入 KD 后为 +0.22%。也就是说，student 恢复了长序列 teacher 相对 baseline 收益的大约 85%，同时避免了 teacher 的完整线上成本。

4. 实验结果分析

离线主表以 5K 模型作为 baseline。baseline 的 AUC 为 0.8212，LogLoss 为 0.4917，吞吐为 88K，显存为 52G。20K teacher 的 AUC 为 0.8233，提升 +0.26%；LogLoss 为 0.4890，下降 0.55%；吞吐为 11K，显存为 86G。普通 student 的 AUC 为 0.8224，提升 +0.15%；LogLoss 为 0.4903，下降 0.29%；吞吐为 83K，显存为 74G。加入 KD 后，student 的 AUC 为 0.8230，提升 +0.22%；LogLoss 为 0.4896，下降 0.43%；吞吐仍为 83K，显存仍为 74G。

这张表体现了论文的真实取舍。teacher 的精度最高，但吞吐从 88K 降至 11K，显存从 52G 增至 86G，难以直接作为线上模型。student 的吞吐接近 baseline，显存虽然仍比 5K 高，但明显低于 teacher；KD 只改变训练目标，不改变推理图，却把 AUC 拉近 teacher。因而适合线上部署的结论不是 20K teacher 替代 5K，而是 20K teacher 作为知识上限、压缩 student 作为服务模型。

线上 A/B 结果同样支持这个判断。TM20K-S student 在 ADSS 上提升 +0.881%，ADVV 提升 +0.515%，延迟变化 +5.6%；加入 KD 后，ADSS 提升 +1.036%，ADVV 提升 +0.780%，延迟仍为 +5.6%。KD 使线上收益进一步提高，而延迟没有继续恶化。对广告推荐，ADSS 与 ADVV 是核心业务指标；对社区搜索，不能直接照搬这两个指标，但可以把它们对应为相关性、有效点击或用户价值的线上收益。

论文还通过消融区分三种 token merge 的作用。LITM 更依赖短间隔重复 ID，适合压缩高重复行为；PATM 让最近行为保持细粒度并对旧历史施加更高压缩；LPTM 则通过层间逐步减半控制高层计算。不同数据域的行为重复率、时间间隔和序列长度分布不同，因此不能把示例中的 T=3 或四段压缩因子当作通用常数。正确的复用方式是先做 attention 质量、AUC/LogLoss 和延迟的联合扫描，再选择预算。

5. 局限与未来方向

论文明确写出的局限有两点。第一，LITM、PATM、LPTM 主要依赖规则和位置启发式，跨领域使用时需要重新调参；作者没有声称在一个域上找到的阈值可以直接迁移到另一个推荐场景。第二，论文没有把 sparse attention 纳入当前系统，因为这需要定制 GPU operator；作者把它列为未来可继续探索的方向。也就是说，TM20K 解决的是 token 数量与表示压缩，但没有完整解决长序列稀疏连接的硬件实现问题。

实验范围也有明确边界。数据是经过匿名化的 ByteDance 工业 CVR 数据，覆盖两个月和数十亿样本，训练使用数百张 GPU；这提供了真实规模证据，却不具备公开数据集那样的可复现性。论文主要报告 AUC、LogLoss、吞吐、显存、ADSS、ADVV 和延迟，没有展开长期留存、兴趣多样性、冷启动用户、不同年龄段或不同流量入口的切片。因此 20K 对所有用户都更好不是当前结果能够支持的结论。

从方法风险看，token merging 可能把低频但关键的早期兴趣与重复行为混在一起；teacher 的 attention 分布也不等于真实因果重要性，最近 token 获得更多 attention 不能自动证明旧行为无用。KD 会把 teacher 的偏差传给 student，且缓存 logits 的数据版本、时间窗口和策略版本必须严格对应。线上 +5.6% 延迟对于广告链路可能可以接受，对于极低延迟搜索链路则需要结合 P99、尾延迟和并发压力重新评估。

未来方向可以沿着作者已经指出的 sparse attention GPU operator 展开，并加入数据驱动的可学习 merge gate、用户分群的动态 token budget、跨域校准和候选感知压缩。但这些是基于论文边界的工程方向，不是论文已经验证的收益。部署时仍要用严格 A/B 与回滚阈值证明长历史带来的增量价值足以覆盖计算成本。

6. 工业实践意义

对社区 UGC 短文本搜索，TM20K 的启发不是盲目把 query 行为扩到 20K，而是把长期行为拆成可解释的时间和信息层级。最近的 query、点击帖子、停留和改写应尽量保留原 token；更早的重复 query、同一主题的连续浏览和低信息量曝光可以做局部合并；长期兴趣可以以较粗的主题或作者表示进入排序模型。先统计不同年龄 token 对 nDCG、CTR、长点击和 query 解决率的边际贡献，再决定预算。

建议先训练一个完整序列 teacher，确认长历史是否在离线和线上都提供稳定增益，再训练 student。teacher 与 student 的数据切分、标签窗口、候选集和特征版本必须一致；否则 KD 可能只是在蒸馏数据漂移。student 线上仅保留主预测头，蒸馏头与 teacher logits 保留在训练流水线，便于节省服务内存与延迟。

LITM 可以先用于重复 query 和同一帖子短时间连续曝光，T=3 之类的阈值必须按平台时间单位重新估计。PATM 可以把最近一段行为设为压缩因子 1，把更早历史按主题、作者或 query 意图逐步压缩。LPTM 适合已经具备多层 Transformer 的排序模型，但要逐层测量序列长度、GPU kernel、通信和 P99，而不能只看理论 FLOPs。目标候选及其关键上下文必须始终单独保留，避免压缩把召回候选的判别信号吞掉。

工程上应把 CPU 合并、embedding 传输和 GPU 栈一起纳入压测。报告里的 student 吞吐 83K 接近 5K baseline 的 88K，而 teacher 只有 11K，说明数据搬运与部署图同样重要。线上监控至少包括 P50/P95/P99 延迟、吞吐、显存、CPU 预处理耗时、序列压缩率、空序列率、重复 token 比例和不同用户群的收益。若 nDCG 上升但尾延迟、负反馈或结果多样性恶化，应降低长历史预算。

最后，长序列模型应有分层回滚方案。可以先只在高活跃用户、重复搜索或有明显长期兴趣的 query 上启用较长历史；普通用户继续使用 5K 或更短模型。每次只改变一类 merge 规则或一个 token budget，保留 teacher、5K baseline 和 student 三套对照。这样才能判断收益来自更长历史、KD，还是仅仅来自新的特征与流量分布，并把 TM20K 的系统方法安全地迁移到个性化搜索场景。
