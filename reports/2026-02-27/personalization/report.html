深度解读：From Scaling to Structured Expressivity: Rethinking Transformers for CTR Prediction

1. 问题与动机

本文瞄准了 CTR 预测领域一个根本性的架构错配问题：标准 Transformer 假设的是序列化的组合性（sequential compositionality），而 CTR 数据需要的是高基数语义字段间的组合推理（combinatorial reasoning）。

具体而言，当前工业界将 Transformer 引入 CTR 预测的主流做法是"简单堆参数"——增大模型宽度和深度。然而，这种朴素的 scaling 策略在 CTR 场景下遇到了严重瓶颈：

  • 数据极度稀疏：CTR 特征的词表规模 n 极大（通常 10⁶–10⁹ 量级），但有效的语义交互主要发生在有限的字段（field）之间，字段数 F 通常仅在 10–100 量级
  • 标准注意力的浪费：vanilla Transformer 在所有 token 对之间无差别地分配注意力，无法区分"用户年龄 × 商品品类"（有意义）和"用户年龄 × 请求时间戳"（弱相关）这类字段对的语义差异
  • 扩展回报递减：实验表明，传统 CTR 模型在参数量增长到一定规模后，AUC 提升几乎停滞，无法复现 LLM 领域的幂律增长曲线

这个问题之所以重要，是因为它直接挑战了"规模即性能"的信条。如果 CTR 模型不能像 LLM 一样通过 scaling 持续获益，那么工业系统的模型迭代策略就需要根本性转变——从"加资源"转向"改结构"。

2. 方法概述

论文提出了 Field-Aware Transformer (FAT)，核心思路是：将字段级交互的先验知识直接嵌入注意力机制的计算图中，让模型的表达能力沿着语义有效的路径增长，而非无差别膨胀。

FAT 的架构由两个关键组件构成：

(1) Field-Decomposed Attention（字段分解注意力）

将标准注意力拆解为两个正交的子机制：

  • Field-Aware Content Alignment（字段感知内容对齐）：Q 和 K 使用字段专属的投影矩阵 WQ(f)​,WK(f)​，使不同语义字段的 token 按照各自角色进行编码。这意味着"用户侧特征"和"物品侧特征"拥有不同的查询/键空间
  • Field-Pair Interaction Modulation（字段对交互调制）：引入标量权重 wfi​,fj​​ 控制字段对之间的信息流强度，允许非对称关系（如"用户历史 → 商品品类"可以比"商品品类 → 用户历史"更强）

(2) Basis-Composed Hypernetwork（基组合超网络）

为避免字段专属参数带来的参数膨胀，FAT 使用共享基矩阵（shared basis matrices）动态生成字段特定参数。这将参数增长与字段基数解耦，且在推理时零额外开销（参数在初始化后可以预计算）。

总体参数复杂度从 O(F2d2) 降低到 O(Fd2+F2)，其中 F 是字段数，d 是嵌入维度。

3. 核心技术贡献

贡献一：首个 CTR 模型的形式化 Scaling Law

这是本文最重要的理论贡献。Theorem 4.1 证明了：FAT 的泛化误差界依赖于 O(Fd2+F2)，而不依赖于词表大小 n（注意 n≫F）。

这一结论的深刻含义在于：

  • 传统模型的泛化界与 n 相关，而 n 在工业场景中可达数十亿，导致统计效率极低
  • FAT 将复杂度锚定在字段数 F 上，F 是一个远小于 n 的、与语义结构对齐的量
  • 由此推导出幂律关系：ΔAUC∝Nparamsβ​,β>0

贡献二：结构化表达力的概念框架

论文提出了 "structured expressivity"（结构化表达力） 的概念——模型的表达能力不应无差别膨胀，而应沿着数据固有的语义结构（字段间交互）有针对性地增长。这为 CTR 模型设计提供了新的原则性指导。

4. 实验结果分析

离线实验

论文设置了三个模型规模进行验证：

模型AUC 提升关键发现
FAT-Small+0.13%在同等参数量下已超越传统模型
FAT-Large+0.41%超越以 scaling 为导向的架构
FAT-XL+0.51%继续提升，无饱和迹象

"无饱和"这一点至关重要——它表明 FAT 的结构设计确实解锁了类似 LLM 的 scaling 行为。

Scaling Law 验证

Figure 3 展示了核心结果：幂律关系 ΔAUC=5.81×10−5×Nparams0.433​ 在三个数量级的参数范围内成立，没有出现饱和拐点。幂律指数 β=0.433 表明收益虽非线性递增，但持续稳定。

消融实验

Table 2 的消融结果揭示了各组件的贡献度排序：

  1. Field-Aware Content Alignment：贡献最大（0.17 个百分点），说明字段感知的 Q/K 投影是核心
  2. Field-Pair Interaction Modulation：提供次要但显著的增益
  3. Basis-Composed Hypernetwork：主要贡献是参数效率，对精度影响较小

可解释性分析

学到的字段对权重 wfi​,fj​​ 展现出强语义一致性：

  • 高权重集中在语义相关的字段对上（如"商品品类 × 用户近期点击"）
  • 无关字段对的权重趋近于零
  • 这为模型决策提供了直观的可解释性

线上 A/B 测试

在淘宝直通车（Taobao Sponsored Search） 上的在线实验取得了：

  • CTR +2.33%
  • RPM（千次展示收入）+0.66%

这是非常显著的线上提升，证实了方法的实际生产价值。

5. 局限与未来方向

当前局限

  1. 字段定义依赖人工先验：FAT 的核心假设是字段结构已知且固定，但实际业务中字段的划分（尤其是交叉特征、序列特征的归属）并不总是清晰的。如何自动发现最优字段划分是一个开放问题
  1. 对序列特征的建模不足：CTR 场景中用户行为序列（点击序列、购买序列）既有序列内的时序关系，又有与其他字段的交叉关系。FAT 目前主要关注字段间交互，对序列内建模可能仍需依赖额外的序列编码器
  1. Scaling Law 的泛化性待验证：论文的幂律关系在淘宝搜索广告场景下得到验证，但在其他场域（如信息流推荐、视频推荐）的适用性尚未确认。不同场景的字段结构差异可能导致不同的 scaling 行为
  1. 与预训练范式的结合：论文聚焦于监督学习下的 scaling，但未探讨 FAT 与预训练-微调范式的兼容性

未来方向

  • 自动化字段结构发现：结合 NAS 或可微分分组方法，自动学习最优字段划分
  • 动态字段交互：根据不同样本（query/user）动态调整字段对权重，而非全局共享
  • 多模态字段扩展：将 FAT 的字段分解思想扩展到图像、文本等多模态特征的交互建模
  • 跨域 Scaling Law：在更多业务场景下验证和校准幂律关系，建立通用的 CTR scaling 理论

6. 工业实践意义

对模型架构设计的启示

FAT 传递了一个清晰的信号：在 CTR 场景下，"怎么扩"比"扩多大"更重要。 工业团队在模型迭代时，应优先考虑架构是否与特征语义对齐，而非一味增大模型规模。具体来说：

  • 字段感知应成为标配：当前工业 CTR 模型（尤其是 Transformer-based 架构）大多忽略了字段结构。FAT 表明，仅通过在注意力层注入字段先验，就能以极低的额外成本获得显著收益
  • 参数预算的重新分配：与其将参数平均分配到所有交互路径，不如集中分配到高价值字段对上。FAT 的 wfi​,fj​​ 可以作为特征交互重要性的诊断工具

对 Scaling 策略的指导

  • 幂律指数 β=0.433 提供了量化的扩展预期：工业团队可以据此评估增加参数量的预期收益，做出更理性的资源分配决策
  • Scaling Law 可用于模型选型：在不同候选架构之间，比较其 scaling curve 的斜率（β），而非单点性能，可以更好地预测大规模部署后的收益

对系统工程的影响

  • 推理零开销：Basis-Composed Hypernetwork 的参数可以离线预计算，线上推理复杂度与标准 Transformer 相当，不增加 serving 延迟——这对工业部署极为友好
  • 可解释性辅助业务决策：字段对权重矩阵可以直接用于分析"哪些特征交互在驱动 CTR"，辅助特征工程和业务策略优化
  • 淘宝线上验证的可信度：CTR +2.33% 的线上增益在搜索广告场景下属于非常显著的提升，证明该方法已跨越了"论文效果"到"生产效果"的鸿沟

一句话总结

FAT 论文的核心洞见——CTR 模型的扩展瓶颈在结构而非规模——值得每个做搜推广的工业团队认真审视。它不仅提供了一个具体的模型架构，更重要的是确立了一个新范式：让模型复杂度沿着数据的语义结构增长，而非无差别膨胀。

OneRec-Think: In-Text Reasoning for Generative Recommendation 深度解读

论文信息: Zhanyu Liu et al. (快手), arXiv: 2510.11639
代码: github.com/wangshy31/OneRec-Think

问题与动机

核心问题: 现有生成式推荐模型（如快手自研的 OneRec）虽然具备强大的端到端生成能力，但本质上是隐式预测器（implicit predictor）——它们直接从用户行为序列映射到推荐结果，缺乏显式、可控、可解释的推理能力。

为什么重要:

  1. 可解释性缺失: LLM 在 NLP 领域已展现出强大的 Chain-of-Thought (CoT) 推理能力，但生成式推荐模型无法生成"为什么推荐这个 item"的文本推理路径，用户信任度低。
  2. 可控性不足: 隐式预测无法响应用户的动态约束（如"我今天心情不好，推荐一些轻松的内容"），缺乏对话式交互能力。
  3. 模态割裂: 推荐系统中的 item 通常以离散 ID/token 表示，与 LLM 的文本语义空间存在巨大鸿沟，如何在一个统一模型中同时支持推理（文本）和推荐（item token）是关键挑战。
  4. 工业落地困境: 即使引入推理机制，复杂的推理解码过程带来的延迟在工业级在线系统（如快手短视频推荐）中难以接受。

简言之，论文要回答的核心问题是：如何在不牺牲推荐效果的前提下，为生成式推荐模型注入显式的、可解释的文本推理能力，并使其在工业规模上可部署？

方法概述

OneRec-Think 提出了一个三阶段训练框架，将对话、推理与个性化推荐统一在一个 LLM 中：

阶段一：Itemic Alignment（跨模态项目对齐）

通过多任务预训练将离散 item token 投射到 LLM 的文本语义空间，建立语义基础。包含四个互补任务：

任务占比作用
Interleaved User Persona Grounding24.3%将 item token 与用户文本属性、搜索行为交织，建立跨模态理解
Sequential Preference Modeling65.7%从时序行为历史预测下一个 item（核心推荐能力）
Itemic Dense Captioning4.9%从 item token 生成文本描述（item→text 对齐）
General Language Modeling5.0%保持 LLM 基础语言能力不退化

训练采用两子阶段策略：先冻结 LLM 参数仅训练 token embedding（Token Warm-up），再全参数联合优化（Multi-Task Integration）。

阶段二：Reasoning Activation（推理激活）

通过监督微调（SFT）激活模型在推荐上下文中的 CoT 推理能力：

  • Bootstrapping with Pruned Contexts: 用相似度函数筛选 top-k 相关历史 item，从清洁序列生成高质量推理 rationale（bootstrap 标注）
  • Learning from Noisy Sequences: 在原始带噪行为序列上训练，让模型学会从真实行为数据中蒸馏出连贯推理

损失函数同时优化 rationale token 预测和 target item token 预测，等权加和。

阶段三：Reasoning Enhancement（推理增强）

使用强化学习（GRPO）精炼推理质量，核心创新是Rollout-Beam Reward：

  • 问题: 推荐场景中用户偏好具有多有效性（multi-validity）——用户可能对多个 item 感兴趣，标准 verification-based reward 过于稀疏（大部分 rollout 无法命中 target item）
  • 方案: 不直接判断最终推荐是否命中，而是评估模型在约束 beam search（beam width K=32）下的最佳可达性能，作为 reasoning path 的奖励信号

核心技术贡献

1. 首个统一对话-推理-推荐的生成框架

OneRec-Think 是第一个在单一模型中同时实现：(a) 自然语言对话理解；(b) 显式文本推理路径生成；(c) 个性化 item 推荐生成 的工作。这不是简单地用 LLM 做推荐，而是让推荐过程本身变得可推理。

2. Itemic Alignment 的多任务设计

与现有方法（如 TIGER 用量化 ID、P5 用文本描述替代 item）不同，OneRec-Think 引入了层次化 item token（3层，共 24,576 个新 token），并通过精心设计的四任务预训练（特别是 Interleaved User Persona Grounding）实现了 item token 与 LLM 文本空间的深度语义对齐。这比简单的 adapter 或 projection layer 更彻底。

3. Rollout-Beam Reward

这是最具创新性的技术贡献。传统 RL 在推荐场景的困境是：

  • 标准 reward: "推荐的 item 是否等于 target?" → 99%+ 的 rollout reward 为 0，信号极度稀疏
  • Rollout-Beam 解法: 给定一条推理路径，用 beam search（K=32）探索其最佳推荐结果，以此评价推理质量

这巧妙地将推理质量评估与推荐准确性解耦，使 RL 训练在推荐场景中真正可行。

4. Think-Ahead 工业部署架构

将推理解码拆分为离线-在线两阶段：

  • 离线: 生成 T 条多样化推理路径，解码前两级层次化 item token（L=3 中的前 2 级），产生 T×m 个候选前缀，缓存至分布式存储
  • 在线: 仅用实时更新的 OneRec 模型做最后一级 token 解码，约束搜索空间为缓存前缀

这种架构将推理的计算开销转移到离线，在线延迟仅需解码 1 个 token，满足工业级延迟要求。

局限与未来方向

当前局限

  1. 公开数据集规模受限: 作者承认 Amazon Review 等数据集的行为序列长度有限、item 空间受限，制约了推理能力的充分发展和评估。在这些小数据集上的结果可能无法完全反映工业场景的表现。
  1. 推理质量的 bootstrap 依赖: Reasoning Activation 阶段的 rationale 是通过 LLM bootstrap 生成的（从清洁序列生成），其质量上限受限于 bootstrap 模型本身的能力。
  1. 离线推理的时效性问题: Think-Ahead 架构将推理路径离线计算，意味着推理内容无法实时反映用户的最新行为变化。对于兴趣快速漂移的用户，可能存在推理滞后。
  1. 多有效性的评估困难: 用户偏好的 multi-validity 性质使得评估推理质量本身就很困难——"好的推理"并不唯一，如何系统性地评估推理质量仍是开放问题。
  1. 基座模型规模: 工业版使用 Qwen-8B，开源版使用 Qwen3-1.7B，相较于主流 LLM 模型规模仍较小。更大规模模型是否能释放更强推理能力值得探索。

未来方向

  • 大规模推荐推理 benchmark 建设: 作者提到正在构建更长轨迹、更大 item 空间的评估基准
  • 实时推理: 探索更高效的推理方法，使在线实时生成推理路径成为可能
  • 多轮对话推荐: 论文已展示对话能力的雏形（case study 中根据用户情绪调整推荐），但尚未系统性地评估多轮交互场景
  • 跨场景迁移: 当前验证集中在短视频和电商，在其他推荐场景（如音乐、新闻）的泛化性待验证

工业实践意义

1. 为推荐系统的"可解释性"提供了新范式

传统的推荐解释（post-hoc explanation）是在推荐完成后"编造"理由。OneRec-Think 的 in-text reasoning 是推理驱动推荐——推理过程本身影响推荐结果。这对于需要透明度的场景（如金融产品推荐、医疗内容推荐）有直接价值。

2. Think-Ahead 架构是工业落地的关键参考

论文最大的工业贡献是 Think-Ahead 的离线推理 + 在线决策两阶段架构。这为所有想在在线系统中引入推理/CoT 的团队提供了可行的落地路径：

  • 将计算密集的推理过程离线化，仅缓存中间结果
  • 在线仅做轻量级的 constrained decoding
  • 可以用 OneRec 等轻量实时模型做最终决策

3. 对话式推荐的工程化探索

OneRec-Think 在单一模型中统一了对话和推荐能力，这意味着未来的推荐系统可以支持：

  • 用户主动表达偏好约束（"推荐轻松的内容"）
  • 系统解释推荐理由并接受反馈
  • 基于对话上下文动态调整推荐策略

这对电商客服推荐、智能助手等场景有直接启发。

4. Rollout-Beam Reward 的方法论价值

推荐场景的 RL 训练长期受困于 reward 稀疏问题。Rollout-Beam Reward 的设计思路——将推理质量评估与最终结果解耦，用 beam search 探索最佳可达结果作为 proxy reward——可以推广到其他 RL-based 推荐场景（如对话推荐、交互式搜索）。

5. 对 Search/Ads 的启示

  • 搜索场景: in-text reasoning 可以用于 query 理解和结果排序的推理链生成，提升搜索结果的可解释性
  • 广告场景: 推理路径可以作为广告创意生成的依据（"基于用户对 X 的兴趣，推荐 Y 产品"），提升广告的相关性和用户接受度
  • 统一模型趋势: OneRec-Think 延续了 OneRec "统一 retrieve 和 rank" 的思路，进一步统一了推理和推荐，代表了工业推荐系统从 cascade 架构向 unified generative model 演进的趋势

总结: OneRec-Think 的核心价值不在于推荐准确率的提升本身，而在于它证明了显式推理与生成式推荐可以在统一框架中共存且互相增强，并且通过 Think-Ahead 架构解决了工业部署的延迟问题。这为下一代可解释、可交互的推荐系统开辟了新方向。

深度解读：Accelerating Generative Recommendation via Simple Categorical User Sequence Compression (CAUSE)

会议：WSDM 2026 | 作者：Qijiong Liu, Lu Fan, Zhongzhou Liu 等

1. 问题与动机

核心问题：生成式推荐（Generative Recommendation）在处理长用户交互序列时面临严重的计算效率瓶颈。

生成式推荐系统（如 Meta 提出的 HSTU）直接通过 Transformer 对用户行为序列建模并生成推荐 item，避免了传统"召回→粗排→精排"多阶段流水线的信息损失。然而，这类方法的注意力机制带来 O(HL²D) 的计算复杂度（H 为注意力头数，L 为序列长度，D 为维度），序列越长计算成本呈二次增长。

为什么重要：

  • 工业场景中用户的历史行为序列通常长达数百甚至数千，长序列对推荐精度至关重要，但计算成本难以承受
  • 现有序列压缩方法（如 GenRank）虽然能缩短序列，但往往导致推荐精度显著下降
  • 生成式推荐要在工业级系统中落地，必须解决"长序列高精度"与"低延迟低成本"之间的矛盾

论文的关键洞察是：用户长期历史中存在大量冗余信号，同一类别下的多次交互所携带的兴趣信息高度重叠。与其用复杂方法压缩序列，不如利用 item 天然自带的类别属性进行分组聚合，既简单又有效。

2. 方法概述

论文提出 CAUSE（CAtegory-based User Sequence comprEssion） 框架，核心思路是将用户的长交互序列分为两部分，分别处理：

  1. 近期序列（Recent Sequence, r_u）：保留最近的交互记录，完整输入 Transformer，捕捉用户当前兴趣
  2. 长期历史（Long-term History, h_u）：通过类别分组压缩为少量 compact token，作为历史兴趣的紧凑表示

压缩三步骤：

步骤操作说明
Grouping按 item 类别特征分桶利用 item 已有的 categorical feature（如视频标签、电影类型）将历史交互分组
Selection保留最近 V 个桶，每桶最多 G 个 item基于时间戳的双重截断，控制压缩后的 token 数量
Aggregation桶内 embedding 平均池化通过对齐变换 + 平均 + 桶位置编码，将每个桶压缩为单个 token

聚合公式：
ej(h)​=∣Bj​∣1​i∈Bj​∑​(Walign​⋅E(i)+balign​)+E(b)[j]
其中 Walign​,balign​ 是可学习的对齐参数，$E(b)[j]$ 是桶的位置编码。

最终模型输入为：[用户 ID] + [V 个压缩历史 token] + [近期序列 token]，大幅缩短了 Transformer 的有效输入长度。

3. 核心技术贡献

1. "简单即有效"的序列压缩范式

与追求复杂注意力压缩机制的研究路线不同，CAUSE 证明了一个反直觉的结论：利用 item 已有的类别属性做最朴素的分组平均，就能取得甚至超越复杂方法的效果。这是该论文最核心的贡献——它不是在方法上做创新，而是在认知上提出了重要洞察。

2. 对齐变换机制（Alignment Transformation）

在聚合前对 item embedding 施加线性变换 (Walign​,balign​)，将原始 embedding 映射到更适合聚合的空间。消融实验证明去掉该变换后性能显著下降，说明直接平均原始 embedding 是不够的。

3. 与动作预测的联合训练

除了 item 预测（使用 InfoNCE 对比学习损失），还联合训练 action 预测（点击/购买/dislike 等行为分类），总损失为 L=Litem​+Laction​。action 预测为 embedding 提供了额外的监督信号。

4. 模型无关性（Model-agnostic）

CAUSE 不绑定特定模型架构，在 HSTU 和 GenRank 两种不同的生成式推荐模型上都取得了改进，说明该压缩策略具有通用性。

与现有方法的关键区别：

  • 对比 HSTU：HSTU 直接处理全长序列，计算成本高；CAUSE 将历史部分压缩为少量 token
  • 对比 GenRank：GenRank 也做序列缩减，但采用更粗暴的截断/采样策略，导致精度下降；CAUSE 通过类别分组保留了兴趣多样性

5. 局限与未来方向

当前局限

  1. 对类别特征质量的依赖：方法效果很大程度上取决于 item 类别体系的合理性。如果类别划分过粗或过细，分组效果会打折扣。K-Means 替代方案虽可行但效果不如显式类别。
  1. 固定压缩粒度：V=8、G=32 是全局超参数，对所有用户一视同仁。但不同用户的兴趣广度不同——兴趣广泛的用户可能需要更多桶，而兴趣集中的用户可能只需要少数桶。
  1. 评估范围有限：仅在两个数据集上验证，且均为中等规模。在真正的工业级大规模数据（亿级用户、千万级 item）上的表现有待验证。
  1. 简单平均聚合的信息损失：桶内使用均值池化，不可避免地丢失了交互时间顺序、频率分布等细粒度信息。对于序列模式高度依赖时序的场景，可能不够。
  1. 类别层级单一：只使用一级类别特征。实际中 item 往往有多级类目体系（如"电子产品→手机→华为"），如何利用层级结构是开放问题。

未来方向

  • 自适应压缩：根据用户兴趣分布动态确定桶数和每桶容量
  • 加权聚合：用注意力机制或时间衰减替代简单平均，保留更多时序信息
  • 多粒度类别融合：同时利用多级类目或多个类别特征维度进行分组
  • 与其他序列压缩方法结合：CAUSE 可作为第一级粗压缩，再叠加更精细的压缩手段
  • 在线增量更新：如何在用户产生新交互时高效更新压缩 token，避免重新计算

6. 工业实践意义

直接可落地的价值

1. 生成式推荐的上线成本降低

这是论文最大的工业价值。生成式推荐（如 HSTU）在学术上已证明有效，但在工业部署中最大的痛点就是长序列带来的计算成本。CAUSE 提供了一条低成本改造路径：不需要改模型架构，只需要在数据预处理阶段加入类别分组压缩，就能大幅降低推理成本。

2. 充分利用已有类目体系

工业系统中 item 普遍已有完善的类目标签体系（电商的三级类目、视频的内容标签、新闻的频道分类等），CAUSE 的思路可以直接复用这些现成资源，无需额外构建。

3. 用户长期兴趣画像的新思路

传统推荐系统中的用户画像（user profile）通常是离线计算的统计特征。CAUSE 的"类别桶"本质上是一种端到端学习的用户兴趣画像——每个压缩 token 代表用户在某个类别上的兴趣向量。这为统一用户画像和序列建模提供了桥梁。

架构层面的启发

4. 近期行为 + 长期压缩的双通道架构

CAUSE 的"近期序列完整保留 + 历史分组压缩"模式，与工业中常见的"短期兴趣模型 + 长期兴趣模型"双塔设计理念一致，但在统一框架内端到端实现，减少了系统复杂度。

5. 序列冗余的启示

论文最深刻的启示是：用户行为序列中大量交互是冗余的。一个用户连续看了 50 个科幻电影，第 2-50 个所提供的边际信息量在递减。这提醒工业实践者：与其一味追求更长序列，不如思考如何高效去冗余。这个思路不限于生成式推荐，对任何基于序列建模的推荐/搜索系统都有参考价值。

6. 工程简洁性优势

方法极其简单（分组→截断→平均），无需复杂的注意力压缩、记忆网络或蒸馏机制，工程实现门槛低，适合快速实验验证和线上 A/B 测试。在"复杂方法提升有限"的搜推场景中，简单有效的方案往往是最佳选择。

总结：CAUSE 论文的核心价值不在于方法的复杂度，而在于它揭示了一个被忽视的事实——用户行为序列中的类别级冗余是生成式推荐效率的主要瓶颈。通过最朴素的类别分组压缩，就能实现 6 倍加速和精度同步提升。这种"少即是多"的设计哲学对工业系统的模型优化和成本控制具有很强的指导意义。
