1. R1-Searcher: Incentivizing the Search Capability in LLMs via Reinforcement Learning
3.80
Relevance 4 | Novelty 4 | Practical 4 | Evidence 3 | Timely 3

Summary: R1-Searcher 提出了一种两阶段强化学习方法，训练 LLM 在推理过程中自主调用外部搜索引擎。第一阶段通过 SFT 初始化模型的搜索调用格式，第二阶段通过 RL（基于结果奖励）训练模型学习何时搜索、搜索什么。该方法无需过程奖励或知识蒸馏，在多跳 QA 任务上显著超越传统 RAG 方法，甚至优于闭源的 GPT-4o-mini。模型自然涌现出反思和自纠错能力。

Key insight: R1-Searcher 的核心创新在于用纯 RL（无过程监督）让 LLM 学会在推理链中自主插入搜索操作。这种方法对搜索系统的启示是：可以通过 RL 训练让模型学会何时需要检索外部知识、如何构造有效查询，实现 reasoning-and-retrieval 的无缝融合。对 UGC 搜索场景，这种能力可用于复杂 query 的多步分解和迭代检索，提升长尾复杂查询的召回质量。

独立页面阅读 ↗

1. 问题与动机

R1-Searcher 针对大型推理模型（LRM，如 OpenAI-o1 和 DeepSeek-R1）的核心局限性：这些模型虽然推理能力强大，但完全依赖内部知识回答问题，在时效性信息、知识密集型任务和多跳推理场景中会产生幻觉和错误。传统 RAG 方法通过固定流程（检索-然后-生成）解决外部知识获取问题，但缺乏自适应推理能力——模型无法根据推理进展动态决定何时检索、检索什么。而基于测试时扩展的方法（如 ReARTeR 使用 MCTS）虽然能实现动态检索，但推理时计算成本极高（需要大量树搜索展开）。R1-Searcher 的核心动机是：能否通过强化学习训练模型在推理链中自主学会何时调用搜索、如何构造有效查询，同时避免 SFT 带来的「内部知识依赖」问题和 MCTS 的高推理成本？

2. 方法详解

R1-Searcher 采用两阶段的基于结果奖励的 RL 框架：

阶段一：学习检索调用格式。 使用 350 个中等难度样本（200 HotpotQA + 150 2WikiMultiHopQA），训练模型学会在推理过程中插入 <|begin_of_query|>...<|end_of_query|> 标签来触发搜索。奖励函数包含两部分：检索奖励（是否至少调用一次搜索，0.5 分）和格式奖励（输出是否符合规范，0.5 分），总奖励上限 1.0。此阶段不要求答案正确，只需模型学会调用检索。

阶段二：学习有效整合。 使用约 8,000 个混合难度样本，训练模型学会何时检索以及如何利用检索结果。奖励函数切换为：答案奖励（F1 分数，计算公式 2×IN/(PN+RN)，IN 为交集词数）+ 格式奖励（正确 0 分，错误 -2 分惩罚）。F1 奖励的选择至关重要——实验证明 EM 奖励导致平均 CEM 仅 39.7%，而 F1 奖励达到 60.6%。

训练算法基于修改版 Reinforce++（而非 GRPO），包含两个关键适配：(1) RAG-based Rollout：模型生成 <|end_of_query|> 时暂停生成，提取查询进行检索，将结果包裹在 <|begin_of_documents|>...<|end_of_documents|> 标签中注入上下文后恢复推理；(2) Retrieval Mask-based Loss：将文档标签指定为特殊 token 并在训练时遮蔽，防止外部环境内容影响损失计算。训练使用 16 rollouts/样本、batch size 256、学习率 2×10⁻⁶、温度 1.0、最大检索次数 8、DeepSpeed Zero-2 框架。

数据选择策略采用基于难度的课程学习：按正确答案所需 rollout 次数分为简单（<10）、中等（10-20）、困难（>20），混合中等和困难样本效果最佳。

3. 核心技术贡献

(1) 纯 RL 驱动的搜索学习范式。 不同于 SFT 依赖标注的搜索轨迹数据，R1-Searcher 通过结果奖励让模型自主探索最优搜索策略。实验证明 RL 比 SFT 平均 CEM 高 10+ 个百分点（60.6% vs 50.1%），因为 SFT 容易被内部知识误导，而 RL 学会了在不确定时主动检索。

(2) 检索遮蔽损失机制。 通过遮蔽检索文档在训练损失中的贡献，确保模型学习聚焦于推理策略而非记忆文档结构，这是将外部工具整合到 RL 训练循环中的关键技术。

(3) 两阶段课程学习。 分离「学会调用」和「学会有效使用」两个目标，降低了 RL 训练的探索难度。阶段一的低门槛奖励确保模型首先掌握工具使用格式。

(4) F1 奖励设计。 相比 EM 和 CEM 等严格匹配指标，F1 奖励提供了更平滑的梯度信号，使 RL 训练更稳定，带来 52.6% 的性能提升（F1 60.6% vs EM 39.7%）。

主实验在 HotpotQA、2WikiMultiHopQA（域内）和 Musique、Bamboogle（域外）上评测：

关键发现：(1) 7B 模型通过 RL 训练后超越闭源 GPT-4o-mini，在 HotpotQA 上高出 18.6 个百分点；(2) 大幅超越基于 MCTS 的 ReARTeR，同时推理成本更低；(3) RL vs SFT 消融显示 RL 在所有数据集上均优于 SFT；(4) 数据多样性至关重要——混合两个数据集训练比单数据集提升 10.9%；(5) 包含困难样本带来 3.4% 额外提升。

在线搜索泛化实验中，R1-Searcher (Qwen-7B) 使用 Google API 在 Bamboogle 上比 Search-o1 (32B) 高 11.4%，证明了从维基百科检索到真实网页搜索的迁移能力。

5. 局限与未来方向

作者提到的局限包括：(1) 实验仅覆盖 7B-8B 规模模型，更大模型的效果待验证；(2) 训练需要 16 rollouts/样本，计算成本不低；(3) 检索质量依赖于语料库（29M 维基百科段落）。未提及但值得注意的局限：(1) 仅在多跳 QA 任务上验证，未涉及开放域生成、摘要等任务；(2) 最大检索次数固定为 8，对极复杂任务可能不够；(3) 奖励设计需要针对不同任务类型调整，泛化性未充分验证。

6. 工业实践意义

对搜索/推荐系统从业者的核心启示：

(1) RL 训练搜索策略优于 SFT。 工业场景中，与其用标注数据教模型何时检索，不如用 RL 让模型自主探索——这避免了标注偏差和内部知识干扰的问题。对 UGC 搜索场景，可训练模型在处理复杂查询时自主决定是否需要多步检索。

(2) 检索遮蔽机制可推广。 在任何将外部工具（搜索引擎、知识图谱、API）整合到 LLM 训练循环的场景中，遮蔽外部输入的损失贡献都是值得采用的技术，防止模型学到捷径。

(3) 从离线检索到在线搜索的迁移。 实验证明在维基百科上训练的模型可直接迁移到 Google 搜索，这意味着可以用内部知识库训练，然后部署到真实搜索引擎环境。

(4) 部署考量。 模型规模 7B 可在单 GPU 上推理，但需要与检索系统实时交互（最多 8 次往返），延迟可能是瓶颈。建议在异步检索架构下部署，或对检索次数做更严格的预算控制。推理成本远低于 MCTS 方法但高于单次 RAG。

2. WebThinker: Empowering Large Reasoning Models with Deep Research Capability

Summary: WebThinker 为大型推理模型（LRM）赋予了自主网页研究能力。系统包含 Deep Web Explorer 模块（支持搜索、页面导航、信息抽取）和 Autonomous Think-Search-and-Draft 策略，使模型在推理过程中无缝交错信息检索与报告撰写。通过基于 iterative online DPO 的 RL 训练策略优化工具使用。在 GPQA、GAIA、WebWalkerQA 等基准上显著超越现有方法和商业系统。被 NeurIPS 2025 接收。

3. MA-RAG: Multi-Agent Retrieval-Augmented Generation via Collaborative Chain-of-Thought Reasoning
3.10
Relevance 3 | Novelty 3 | Practical 3 | Evidence 4 | Timely 3

Summary: MA-RAG 提出多 agent 协作的 RAG 框架，将 RAG 流程分解为多个专业化 agent：Planner 负责任务分解、Step Definer 定义子任务、Extractor 提取证据、QA Agent 生成答案。各 agent 通过 chain-of-thought 推理交换中间结果。在 NQ、HotpotQA、TriviaQA 等基准上，小模型通过多 agent 协作可超越大模型单体表现，且可零样本迁移到医疗问答等专业领域。

Key insight: MA-RAG 的核心设计思路是将 RAG 的「检索-推理-生成」流程拆分为多个专业 agent，每个 agent 负责一个阶段并输出可解释的中间推理步骤。这种分治策略的实践意义在于：(1) 可根据各阶段特点选择不同规模模型，降低成本；(2) 中间推理步骤提供了可调试性；(3) 零样本跨域迁移能力意味着不需要领域特定训练数据。对搜索系统可借鉴其「分阶段-多 agent」架构来处理复杂查询意图。

4. Knowledge-Aware Iterative Retrieval for Multi-Agent Systems
2.90
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 2

Summary: 该论文提出了一种知识感知的迭代检索框架，核心创新是将外部信息源与内部知识缓存分离。内部知识缓存持续更新，用于引导查询生成和证据选择，避免检索偏差的强化。在多步问答任务上，该方法随任务复杂度增加优势更显著。框架支持竞争性和协作性多 agent 配置，收敛步数与任务难度成本效益地扩展。

Key insight: 知识缓存与外部检索分离的设计理念值得搜索系统借鉴：在迭代检索中维护一个动态更新的「已知信息」缓存，避免重复检索相同内容，同时利用已积累的知识来改进后续查询。这对多轮搜索交互场景（如对话式搜索）有直接参考价值，可减少冗余检索并提高信息获取效率。

5. Characterizing Deep Research: A Benchmark and Formal Definition
2.80
Relevance 2 | Novelty 3 | Practical 3 | Evidence 4 | Timely 3

Summary: 该论文提出了 deep research 的形式化定义和 LiveDRBench 基准。作者指出 deep research 的核心特征是搜索过程中对概念的「高扇出」（high fan-out），而非仅产生长文本输出。基准包含 100 个跨科学和公共事件的挑战性任务，各系统 F1 分数从 0.02 到 0.72 不等，OpenAI 以 0.55 的 F1 得分领先，Perplexity 为 0.41，Gemini 为 0.35。

Key insight: 该工作的最大贡献是将 deep research 从模糊概念提升为可量化评估的任务：核心度量是「概念扇出」——需要搜索和综合多少不同概念才能回答问题。这为评估搜索 agent 质量提供了新视角：好的搜索 agent 不仅要生成长文本，更要展示对多样概念的广泛检索和综合能力。LiveDRBench 可作为评估搜索系统 deep research 能力的标准基准。
