1. HBM Is Not All You Need: Efficient Disaggregated LLM Serving across Memory-heterogeneous Accelerators
4.45
Relevance 4 | Novelty 5 | Practical 4 | Evidence 5 | Timely 5

Summary: 论文面向大模型推理中 prefill 计算密集、decode 访存密集的阶段差异，提出 HMA-Serve，把 GDDR 加速器用于 prefill、HBM GPU 用于 decode。系统通过阶段化低精度、逐层 KV 传输流水线和延迟反量化，跨 Qwen3 4B 到 32B 与 3 条生产 traces 验证，最高达到 3.2 倍 goodput 和 4.8 倍 goodput-per-dollar，且生成质量无可测损失。

Key insight: 对搜推和社区问答中的 LLM/RAG 服务来说，关键启发是不要把昂贵 HBM GPU 当成所有阶段的默认答案，而要按 prefill/decode 的瓶颈拆分硬件。KV cache 的格式转换、网络带宽和反量化时机是跨厂商异构推理能否落地的核心工程点，适合用于长上下文重排、答案生成和批量离线评测服务降本。

2. Kara: Efficient Reasoning LLM Serving via Sliding-Window KV Cache Compression
4.15
Relevance 4 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: Kara 针对推理模型长 CoT 解码时 KV cache 持续膨胀的问题，提出只在最近生成窗口内做滑动式压缩。方法用双向注意力为窗口内 KV 打分，再用 Token2Chunk 把关键 token 扩展为可变长语义块，并适配 PagedAttention 实现 KvLLM。摘要未披露具体吞吐百分比，但强调在多组实验中能降低 KV 内存并提升输出吞吐。

Key insight: 这篇论文的实践价值在于把 KV 压缩从“全局阈值触发”改成“解码时局部窗口维护”，更贴近真实推理服务的持续生成状态。对社区搜索中的复杂问答、解释型排序和长链路 agent 场景，可以优先评估类似窗口化压缩，因为它既保留近期推理上下文，又避免早期片段把显存长期占满。

Summary: Meta 这篇工程文章讨论 AI 训练数据和模型能力快速增长后，存储访问如何成为训练速度与计算成本的关键基础设施。文章指出前沿模型发布节奏已从“数月”压缩到“数周”，可靠、快速的数据访问直接影响 AI 创新的迭代速度。它不是论文式算法贡献，但提供了超大规模 AI 存储架构的产业实践信号。

4. ASAP: A Disaggregated and Asynchronous Inference System for MoE Prefill
4.05
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 3

Summary: ASAP 面向 MoE 大模型在线服务的 prefill 阶段，指出现有注意力 DP 与专家 EP 混合并行会在阶段切换处产生全局同步屏障。论文把 attention 与 MoE stage 解耦为异步流水线，并结合异步通信原语、请求调度和模型执行优化。在 CloudMatrix384 super-node 上，相比同步 serving 方案，SLO-compliant prefill throughput 提升 90%。

5. Geometry-Aware Online Scheduling for LLM Serving: From Theoretical Bound to System Practice
4.05
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 3

Summary: 论文指出 LLM serving 的 KV cache 占用具有二维时空增长特征，传统 Shortest Job First 等时间中心启发式无法刻画显存压力。作者提出 Smallest Volume First 与 1-bit SVF，并用 volume-certificate 证明把高并发场景下的最坏竞争比从既有 48 推近到 3。系统作为 vLLM 插件层实现，在 Llama-3.1 上降低平均和尾延迟。

Key insight: 这篇工作把“请求要跑多久”升级为“请求在时间和显存上占多少体积”，对多租户推理调度很有借鉴意义。搜索/推荐线上服务常同时有短 query、长上下文 RAG 和解释生成请求，SVF 类算法可以作为 admission control 与 batch scheduler 的统一排序信号。

6. SwiftCache: Efficient LLM Serving for Multi-turn Conversations with Heterogeneous KV Cache Sharing
4.05
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 3

Summary: SwiftCache 针对多轮对话中历史 token 持续累积、KV cache 被迫 offload 到 CPU/SSD 后 TTFT 上升的问题，提出跨模型异构 KV cache 共享。低 KV 需求模型把空闲 GPU 显存和 NVLink 带宽捐给高需求模型，同时只保留当前活跃层 KV 在本地显存。真实 workload 上，相比 vLLM 和 SGLang，P99 TTFT 最高降低 69%，最大上下文长度提升 3.98 倍。

Key insight: 对社区搜索的多轮问答、客服式搜索和 agentic RAG 来说，历史上下文缓存是成本大头。SwiftCache 的可借鉴点是把同机模型从彼此竞争显存改为协作共享 KV 前缀，并把层级 KV 常驻策略做细，这比简单扩容 GPU 更适合长会话负载。

7. Harnessing Routing Foresight for Micro-step-level MoE load balancing in RL Post-training
3.85
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 3

Summary: ForeMoE 关注 MoE 在 RL post-training 中的 expert 负载不均衡问题：不同于预训练，RL 微步 batch 很小，负载会发生高频波动。系统利用 rollout 阶段可预见的 routing 信息，提前指导 recompute 和 policy update 阶段的负载均衡，并用层级 planner 拆解 NP-hard 规划问题。在 64 GPU 评测中，相比 SOTA RL 后训练系统最高加速 1.45 倍。

8. Alignment Collapse Under KV Cache Quantization: Diagnosis and Mitigation
3.80
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 3

Summary: 论文研究 KV cache 量化对安全对齐的影响，发现只看 perplexity 或任务准确率会漏掉严重风险。跨 11 个 3.8B 到 72B 指令模型和 5 个 benchmark、1894 条 prompt，低比特量化可让 Mistral-7B 在 perplexity 仅 1.03 倍时损失 15.2% 拒答能力。作者提出 PCR 诊断三类失效模式，20 条 calibration prompt 即可预测修复方向，KIVI 上最高恢复 97.2%。

Key insight: 这篇论文提醒推理降本不能只验吞吐和困惑度，尤其是社区搜索里的安全问答、内容审核和合规场景。KV cache 量化上线前应增加拒答、越狱、敏感内容等对齐回归集，并按通道或层定位安全子空间，而不是用统一 bit-width 粗暴压缩。

9. DriftSched: Adaptive QoS-Aware Scheduling under Runtime Token Drift for Multi-Tenant GPU Inference
3.75
Relevance 4 | Novelty 3 | Practical 4 | Evidence 4 | Timely 3

Summary: DriftSched 面向 NVIDIA L4 上的多租户 LLM 推理，解决 admission-time 估算和真实 token 执行成本漂移导致的队列失衡与 QoS 下降。框架结合 workload 分类、token-budget 估算、租户感知队列和在线反馈，比较 FIFO、Priority、Weighted、SJF 与 Aging Priority。实验显示在线校准使 MAE 降低 38.8%、RMSE 降低 40.5%；SJF 相比 FIFO 让 median latency 降约 42%、P99 降约 16%。

Key insight: 对中小规模 GPU 池，这篇工作的价值在于可复现且工程门槛低：先把请求成本估准，再选择调度策略。社区搜索场景常混合 embedding、rerank、生成摘要和后台批处理请求，类似 token drift 监控可以直接接入队列系统，减少长请求拖垮交互式搜索体验。

10. ProWAFT: A ROMA-LPD Instance for Workload-Aware and Dynamic Fault Tolerance in FPGA-Based CNN Accelerators
3.05
Relevance 2 | Novelty 3 | Practical 3 | Evidence 4 | Timely 5

Summary: ProWAFT 面向边缘 CNN 推理中的 FPGA 瞬态故障，提出工作负载感知的主动容错框架，通过部分重配置选择性启用 TMR。系统量化任务关键性、故障传播和重配置开销，在 latency、energy 与 reliability risk 的组合目标下选配置。作者在 Xilinx Zynq UltraScale+ ZCU104、6 个可重配置区域和来自 ResNet-18、MobileNetV2、EfficientNet-Lite 的 500-task trace 上验证，保持接近基线吞吐并降低综合成本。

Key insight: 它与 LLM 搜推主线距离较远，但对边缘检索、端侧视觉理解和低延迟内容安全推理有工程启发。可借鉴的点是把可靠性策略做成 workload-aware，而不是全量冗余；当搜索链路包含 FPGA/NPU 加速的多模态召回或审核模块时，类似组合目标能帮助在可靠性和延迟之间做动态取舍。
