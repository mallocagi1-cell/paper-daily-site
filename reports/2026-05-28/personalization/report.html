Credit-assigned Policy Gradient for Early Stage Retrieval in Two-stage Ranking

针对搜索/推荐/RAG 系统普遍使用的两阶段架构，作者提出 credit-assigned policy gradient (CA-PG)，用于端到端训练早期召回阶段（ESR）。常规的 vanilla policy gradient 把梯度回传到整个候选集的联合概率上，当候选集规模达到工业级（数千到上万）时方差爆炸，几乎无法训练。CA-PG 把梯度改为对'目标 item 在任意候选集中被选中'这一边际概率求导，利用边际化消去与具体候选集组合的依赖。在 RecSys-style 仿真和真实数据集上的实验显示 CA-PG 显著降低梯度方差并稳定收敛，比 V-PG 更易扩展到大候选集场景。

1. 问题与动机

工业级搜索/推荐/RAG 系统普遍采用两阶段架构：early-stage ranker (ESR) 从十亿级 item 池中筛出几千到上万的候选集，late-stage ranker (LSR) 再在候选集内精排。LSR 训练已有大量 RL 方法，但 ESR 的端到端 RL 训练一直是空白——根本原因是把 vanilla policy gradient (V-PG) 直接套到 ESR 时方差呈 𝒪(|𝒜|^K) 指数级爆炸（|𝒜| 是动作空间，K 是候选集大小）。论文指出 V-PG 的两个症结：(1) 方差爆炸——V-PG 对整个候选集 𝒜^K 的联合概率求梯度，每次只采样一个候选集组合却要估计在 𝒜^K 组合空间上的期望；(2) credit-assignment 失败——V-PG 把候选集中所有 item 同等对待，无法把单个 item 对最终 reward 的贡献区分出来。例子：候选集 {A,B,C} 进入 LSR，A 被选中且 reward 正，B 被选中且 reward 负，V-PG 会把整体概率上调，无法识别 C 是否相关。前序工作 (Ma et al. 2020) 也讨论 V-PG 的两阶段训练，但只用启发式（对非目标 item 加 discount）压方差，缺乏严格分析。本工作要回答：能否找到一个 PG 形式，让 ESR 在大候选集场景下也能稳定收敛？

2. 方法详解

CA-PG 的核心是策略分解：把 ESR 的策略写成 π(a_l | x) = π_ESR(𝒮^K(a_l) | x) · π(l)(a_l | x, 𝒮^K(a_l))，其中 𝒮^K(a_l) := {𝒜^K | a_l ∈ 𝒜^K} 是所有包含 a_l 的候选集的集合，π_ESR(𝒮^K(a_l) | x) := Σ_{𝒜^K} 𝟙{a_l ∈ 𝒜^K} π_ESR(𝒜^K | x) 是 ESR 选中 a_l 的边际概率。关键 trick：CA-PG 只对第一项（边际概率）求梯度、忽略第二项（条件概率）：

∇v_l(π) = 𝔼_𝒟 [∇log π_ESR(𝒮^K(a_l) | x) · r_l]

这一步把动作空间从 |𝒜|^K 降到 |𝒜|，方差和样本复杂度都大幅下降。Theorem 3.1 证明 CA-PG 就是 V-PG 的一个组成部分，剩余项 ∇C(π) 包含一个 LSR 与 ESR 条件分布之比的因子，作者证明该因子在 LSR 与 ESR 合理对齐时贡献小。Theorem 3.3 给出 CA-PG 能学到正确排序的充分条件：reward 为正、LSR 相对 ESR 合理对齐（不必最优）。

具体落地用 Plackett-Luce (PL) 双塔 MoE 模型：每个专家 m(k) 输出 10 维用户/item embedding，logit = ⟨μ̂_{m(k)}(x), ν̂_{m(k)}(a)⟩，整体 PL 策略 π_ESR(𝒜^K | x) = ∏ exp(logit) / Σ。当 K 大、|𝒜| 大时直接求 PL marginal 不可行，作者引入 Sampling with Replacement (SwR) 近似——把不放回采样近似为放回，得到 CA-PG-SwR (论文也称 TOP1-PG，因为 M=1 时退化为 top-1 sampling 形式)。训练用标准 Adam，learning rate 网格搜索；代码开源于 facebookresearch/early_stage_retrieval。

3. 核心技术贡献

(1) 边际化变量替换：把策略分解中 ESR 的随机变量从"具体候选集 𝒜^K"换成"包含 a_l 的所有候选集 𝒮^K(a_l)"——这是 variance reduction 的根本机制。前序工作只在 single-stage 上做 PL 近似，没人意识到 two-stage 下边际概率才是统计上更稳的优化目标。(2) 与 V-PG 的精确关系定理（Theorem 3.1）：CA-PG = V-PG − 残差项，且残差项可解释为"每个具体候选集组合的归一化重要度"。这给出从 V-PG 移除噪声项的清晰理论解读。(3) 学习等价性证明（Theorem 3.3）：在 LSR-ESR 合理对齐 + reward 正性条件下，CA-PG 与 V-PG 学到相同最优 ESR。(4) SwR 实用近似：把 sampling-without-replacement 替换为 with-replacement，让 CA-PG 在 K=200 这种工业级候选集上仍可计算。

4. 实验结果分析

合成实验 (1000 users × 1000 items，K=5/10/20)：

  • V-PG: K=5/10/20 时 policy value 收敛到 7.22/7.17/6.86（500K 步）；
  • V-PG-SwR: 8.33/8.54/8.74；
  • CA-PG: 8.19/8.44/8.70；
  • CA-PG-SwR: 性能最优。

V-PG 在 K=20 时已出现 gradient overflow 提前中止；CA-PG 系列在 K=20 仍稳定收敛。

LSR 对齐扫描 (K=10)：四种 LSR (optimal/noisy/uniform/anti-opt)：

  • V-PG 在 noisy 下 7.25，uniform 下骤降到 3.27，anti-opt 仅 1.07；
  • CA-PG 在 uniform LSR 下仍能学到 5.64（更稳）。这验证 Theorem 3.3 关于"对齐宽容度"的预测。

真实数据 KuaiRec (1411 users × 3326 items，K=50/100/200，只能跑 SwR 版本)：

  • V-PG-SwR @50K 步: 5.05/5.39/5.92；@500K 步: 7.91/8.22/8.26；
  • CA-PG-SwR @50K 步: 5.61/6.37/7.10；@500K 步: 7.19/7.82/8.32。

CA-PG 在 @50K 早期收敛优势随 K 增大而扩大（K=200 时 7.10 vs 5.92），最终收敛值在 K=200 时也反超 V-PG-SwR。关键观察：CA-PG 的早期收敛优势在大候选集下最显著，这正是工业场景需要的（候选集越大 V-PG 越无法用）。

5. 局限与未来方向

作者明确列出两个方向：(1) off-policy learning (OPL)——本文是 on-policy，工业级 ESR 训练通常依赖 logged data，需要给 CA-PG 配套 importance sampling 策略；(2) reward 交互——本文假设 position-wise reward 只与对应 action 有关，但实际排序中存在 diversity 等 item-item 交互，CA-PG 在多样性场景下的扩展尚未解决。论文未明显讨论的局限：CA-PG-SwR 的 sampling 近似在极小 K 时与精确 CA-PG 有差距；MoE 多专家的 expert imbalance 问题未做专门处理；reward function 的正性要求（Theorem 3.3）在带 KL 罚的工业 reward 下可能违反。

6. 工业实践意义

对搜索/推荐工程团队的最具体启示：召回侧 RL 训练长期被认为"不可能用 vanilla PG"，CA-PG 把行动空间从 |𝒜|^K 降到 |𝒜|，让 ESR 可以与 LSR 联合优化业务 reward（CTR、CVR、播放时长）而非只优化 retrieval-only nDCG。落地路径：(1) 已有双塔召回 + 排序 pipeline 的团队，可以把召回侧 loss 从 in-batch negative softmax 切到 CA-PG-SwR，reward 用线上 LSR 输出 + 后验业务指标；(2) MoE 召回（业界常见的多通道融合）天然适配 CA-PG 的两阶段 PL 公式；(3) 候选集 K=200~1000 是工业典型量级，论文证明这正是 CA-PG 收益最大的区间。对社区搜索而言，UGC 帖子的召回长期靠 BM25 + 双塔召回融合，CA-PG 提供了"用线上点击/转化直接训召回模型"的可行通路，不再需要先用代理标签（如曝光-点击对）训召回再用 RL 训排序。需要注意的工程约束：CA-PG 需要 LSR 是固定/可查询的（或异步更新），不能 LSR/ESR 同时变化；梯度计算需要对 𝒮^K 边际概率做归一化，框架需支持 PL 的 logsumexp 稳定实现；reward 必须正（建议加 baseline）。Meta 的 facebookresearch/early_stage_retrieval 仓库提供了参考实现，可直接 fork 适配业务 PL 头。

Uniboost: Global Coordination with Value Alignment for Fair and Efficient Traffic Allocation

Alibaba📖 有深读 · 10 分钟

面向工业级推荐系统的混排/重排阶段，论文提出 Uniboost 统一流量分配框架，重点解决多业务目标（自然+商业+生态）耦合时的三大痛点：分配方案彼此耦合无法独立调优、模型分数被'通胀'、缺乏业务可解释性。核心机制是 posterior value alignment（后验价值对齐），把抽象模型分数校准到带显式业务语义的锚点指标（如 GMV、播放时长）；并采用独立线性 boosting 范式解耦各计划权重，使每个加权项的边际贡献可归因。在淘宝/天猫线上 A/B 验证：降低低边际计划权重不必然损失流量，并对收入与用户体验都有正向收益。

INSIGHT传统混排把多个 plan 的 score 全部加权拼接进 listwise loss，导致权重之间相互掩盖、调一个动全身。Uniboost 的关键不是新模型，而是工程范式转变：把 score 校准成可比的 anchor metric（货币化/时长化），再用线性独立 boosting 让每个 plan 都能像电商促销活动一样'打开/关闭'并精确计量收益。对社区搜索的启示：如果同时承接广告、生态扶持、首页推荐多个目标，应优先把所有 score 标定到同一业务指标空间，再做线性可加权组合，避免黑盒精排被业务方质疑。

1. 问题与动机

工业级推荐系统的 pipeline 通常分 Matching → Ranking → Blending (Re-ranking) 三阶段，其中 Blending 负责把多源候选（自然内容、广告、冷启、生态扶持等）混合并做最终流量分配。淘宝/天猫等大型电商的核心痛点：每出现一个新的运营活动（促销、联盟、冷启扶持）都要在原 blending score 上加一项 boost weight，长期积累后造成三个具体问题——(1) score 通胀：分数物理意义丧失（举例：原始 blending 分本来可解释为"用户偏好"，叠加 N 个 boost 后变成纯黑盒数值）；(2) 分配方案耦合：多个 plan 互相干扰，调一个动全身，无法独立 ROI 评估；(3) 可解释性缺失：业务方无法回答"为什么这条广告被推出来"。前序工作（Chen et al. 2022a 等广告系统的 value alignment）只解决广告的 revenue 对齐，无法直接迁移到内容推荐，因为内容侧"价值目标"不稳定（点击/时长/完播/互动哪个是 anchor 不明确）。论文要解决的是淘宝 Content Feeds 这种万级日活、N 个并行运营活动的场景下，如何让 Blending 阶段既保持业务多目标又能精确归因每个策略的边际贡献。

2. 方法详解

Uniboost 的整体 pipeline 分 Online Serving + Near-line Monitoring 两部分。

Online Serving 四步：

  • 2.1.1 Model Scoring：聚合上游 retrieval + ranking 输出形成候选集 𝒱，blending 模型对每个 v 输出原始预测分 y'_v；
  • 2.1.2 Value Alignment（核心创新一）：把 y'_v 校准到 anchor 指标空间，公式 y_v = F(y'_v | π) = y'_v · μ_anchor / μ_score，其中 μ_anchor 和 μ_score 分别是 anchor 指标和原始 blending 分的全局均值。Uniboost 选择"有效完播率"（Effective Completion Rate）作为 anchor，这一步把抽象分数变成"该 item 预期能贡献的完播次数"，业务语义可解释；
  • 2.1.3 Independent Boosting（核心创新二）：对每个运营 plan p，单独计算 boost score s_{p,v} = 𝟙_p(v) · (w_p · y_v + b_p)，其中 𝟙_p(v) 是 item 属于该 plan 的指示函数，w_p、b_p 是可学习权重和偏置。因为 y_v 已经在 anchor 空间，所以 s_{p,v} 也是"完播次数贡献"的单位，可加可比；
  • 2.1.4 Linear Aggregation：最终排序分 r_v = y_v + Σ_p s_{p,v}，强制用线性求和而非非线性融合，目的是保证可加性（Additivity）和可归因性（Attribution）——任何 plan 都可以被孤立地"打开/关闭"并精确度量其贡献。

Near-line Monitoring 两层：

  • Distribution Tracking：实时缓存 y'_v、y_v、s_{p,v} 的分布，用于监控线上漂移；
  • Aggregation & ROI Analysis：聚合每个 plan 的 Cost 与 Δ 业务指标，计算 ROI（如 ROI^VV = Δ^VV_p / Cost_p），驱动运营策略迭代。

整套机制可以理解为：把 N 个独立的"业务促销活动"建模成 N 条线性可加的 boost 通道，每条通道的 cost 和 lift 都能在 dashboard 上单独看，业务方可基于 ROI 做"关停/扩大"决策。

3. 核心技术贡献

(1) Posterior Value Alignment 把抽象 score 校准到带业务语义的 anchor 指标：这是论文的中心思想——所有 boost 必须先在统一物理量（完播次数）上做加法，否则线性叠加无意义。(2) Independent Linear Boosting：放弃复杂非线性融合，强制线性可加，换取归因可解释性和运营可控性。这是工程范式选择而非模型创新。(3) Effective Completion Score 作为 anchor 的实证选择：论文比较了 Effective Completion、Play Duration、Click、Buy、Interaction、Slide 六种后验指标，发现 Buy/Interaction/Slide 太稀疏不稳，Play Duration 在长尾区域校准误差大，Effective Completion 在所有 score 区间分布稳定、校准误差均匀，因此是内容推荐 feed 的最佳 anchor。(4) 实时数据闭环 + ROI 报表：把线上 boost 的边际效用变成可观测可决策的运营指标。

5. 局限与未来方向

作者明确提到的局限较少（更像工业落地报告而非纯研究论文）。论文未充分讨论但实际存在的限制：(1) anchor 指标的领域依赖性——Effective Completion 适合视频 feed，电商搜索/广告/新闻类 anchor 可能完全不同，需要每个场景重做相关性分析；(2) 线性求和的表达能力上限——某些业务规则（如"广告/自然 1:N 的硬比例约束"）无法用线性 boost 表达，仍需上层调度器配合；(3) w_p、b_p 的学习信号——论文未详细说明这两个权重是离线训练还是在线 PID 调控，业务方接入新 plan 时的冷启动策略也未展开；(4) anchor μ_anchor / μ_score 的全局均值估计：在用户分群、新用户、流量切片下可能漂移，需要更细的分群对齐；(5) 论文没有报告与现有 listwise re-rank 模型（如 PRM、SetRank）的对比，因此无法直接判断 Uniboost 在精排能力上的位置。

6. 工业实践意义

Uniboost 对搜索/推荐/广告工程团队的最具体启示是工程范式而非模型创新：当系统已经叠加了 5+ 个运营活动 boost 时，与其继续训更复杂的 listwise 精排模型，不如先做 score 物理量统一 + 线性可加分解。具体落地步骤：

  • 第一步：选 anchor 指标——用论文方法画 6~10 种后验指标 vs blending 分的分布图，选分布最均匀、校准误差最小的那个；社区搜索类场景可能选"有效阅读时长"或"7 日复访率"，电商可能选"GMV 或加购"。
  • 第二步：把所有 plan 重写成线性 boost 形式 (w_p · y_v + b_p)，并强制在 anchor 空间求和，禁止非线性融合。
  • 第三步：上 dashboard——按 plan 拆分 cost / Δ 指标 / ROI，让运营方能看到每个 plan 的边际贡献，并基于 ROI 排序决定关停顺序。
  • 第四步：A/B 验证——预期看到大量 boost 权重数值下降（论文是 92~96% 下降），但曝光分布不变，说明原系统的权重内耗被消除。

对社区搜索的特别启示：UGC 平台同时承担 feed 推荐、首页搜索、热门话题、商业广告多个流量入口，长期会演变成 Uniboost 论文描述的"耦合 boost 黑盒"。提前规划 anchor-aligned boost 架构是更经济的设计选择。部署考虑：线性求和 + anchor 校准的额外计算几乎为零，可与现有 blending 模型并存；distribution tracking 可复用现有特征监控系统。需要注意：Uniboost 论文报告的"权重下降 90%+ 但曝光不变"是该系统已经存在严重 score 通胀的标志，新建系统直接采用 Uniboost 架构应避免重蹈这条弯路。Uniboost 已在淘宝 Content Feeds 全量稳定运行，是 SIGIR 2026 录用的工业级方案。

Hi-SAM: A Hierarchical Structure-Aware Multi-modal Framework for Large-Scale Recommendation

ByteDance

针对大规模多模态推荐中 semantic ID 路径的两大顽疾——RQ-VAE 类 tokenizer 没有解耦跨模态共享语义与模态特异细节（导致 token 冗余或塌缩），以及 vanilla Transformer 把展开后的 token 流当作 flat 序列处理时被局部 token 主导注意力——论文提出 Hi-SAM 框架。两个核心组件：(1) Disentangled Semantic Tokenizer (DST) 通过几何对齐统一文本/图像模态，并用粗到细策略量化，共享码本承载跨模态语义、模态私有码本承载模态细节；(2) 层次化的 Transformer 显式建模 user→item→token 三层结构。实验显示在大规模数据集上 NDCG 和 HitRate 显著优于 TIGER、HSTU 等 baseline。

INSIGHTTIGER 之后的生成式推荐路线一直在 token 化与序列建模两个维度上分别打补丁，Hi-SAM 第一次同时处理'tokenizer 解耦 + 注意力层级化'两个问题，指出二者在系统里是耦合的：粗粒度 token 承载用户级语义，细粒度 token 承载 item 级细节，注意力应当按这个层级分配。对社区搜索/UGC 推荐的启示：当帖子同时有标题、正文、封面图、视频帧时，不要把所有模态量化到同一个 codebook 里，而应共享码本 + 模态私有码本组合，并在排序模型里显式表达层级，避免长 token 序列的注意力被局部细节淹没。

L2Rec: Towards Dual-View Understanding of LLMs for Personalized Recommendation

ByteDance

LLM 用于个性化推荐时，行为信号（交互序列）与语义信号（item 文本）的融合通常发生在两个极端：输入端把 behavioral embedding 注入 token space（存在分布 gap），或输出端用对比学习对齐两个独立编码器（缺乏端到端监督）。L2Rec 提出在参数层面统一两类信号：同一组 Transformer 参数作为共享介质，通过 Dual-view Personalized Mixture-of-Experts (DPMoE) 给每个 view 注入个性化的 low-rank 扰动 (LoRA-like)，让单个 LLM backbone 同时输出行为和语义两种互补表示。实验显示在多个 benchmark 上优于现有 LLM4Rec baseline。

INSIGHTDPMoE 的设计本质上是'每个用户/每个 view 学习一组私有的 LoRA delta'，这与 PEFT 路线的个性化结合是当前 LLM4Rec 的活跃方向。把参数级融合作为第三种范式（区别于 input-level 和 output-level），避免了 token space 失配和后期对齐的额外训练损失。对工业落地的启示：直接 fine-tune 全量 LLM 服务每个用户不现实，但 LoRA-based per-view perturbation 是个介于 prompt-tuning 与 full FT 之间的可行折中，适合中等流量场景；社区搜索可以参考'兴趣 view + 内容 view'的双 LoRA 设计做个性化排序。
