PULSAR: Pooled Unified Late-Interaction Search and Retrieval for Enterprise Visual Document RAG

针对高频更新的投研演示文稿、董事会材料等视觉文档，PULSAR 以冻结的 ColPali 风格骨干直接索引页面图像，并用紧凑页级摘要做首轮召回、细粒度池化表示做 MaxSim 精排。ViDoRe V3 上中位检索延迟降低 15.1 倍，nDCG@10 与 Recall@10 损失均低于 0.01；生产延迟为 156 毫秒，并发吞吐提升约 88 倍。

KEY INSIGHT · 对业务意味着什么这项工作把 late interaction 的主要成本拆成“低成本候选生成 + 精确局部重排”，证明视觉检索无需先做昂贵 OCR 和图表描述也能进入生产。对 UGC 搜索可复用同样设计：用紧凑表示覆盖大候选池，只对少量候选保留 token/区域级 MaxSim，从而在相关性基本不损失的情况下显著压低延迟和向量存储开销。

Mine and Refine: Optimizing Graded Relevance in E-commerce Semantic Search Retrieval

论文聚焦电商语义召回中的分级相关性、难负例误标和不同相关等级分数不可分三类问题。方法先用经行为数据审计微调的轻量 LLM 生成符合业务规范的多级标签，以标签感知监督对比学习建立全局空间；再挖掘难样本、重新标注，并用多级 circle loss 细化相似度分布，使召回分数更适合后续融合与排序。

INSIGHT其价值不只是“用 LLM 标注”，而是让同一套分级标签贯穿全局训练、难例挖掘与二阶段校准，避免把潜在相关但未曝光的商品当作负例。社区短文本搜索可把“完全相关、部分满足、主题相关、无关”显式编码进对比损失，并在 hard-negative 回流前复审，预计比单纯扩大负例池更稳健，也更利于稀疏与稠密分数融合。

03 4.10

GPU-Native Approximate Nearest Neighbor Search with IVF-RaBitQ: Fast Index Build and Search

IVF-RaBitQ 面向大规模向量召回，把 IVF 聚类索引与 RaBitQ 低比特量化整合为 GPU 原生建库和查询流水线。它用可扩展的 GPU 量化降低编码与存储成本，并设计 GPU 距离计算以减少高召回率下多探针造成的内存带宽压力，目标是在快速建库、高吞吐、高召回和低存储之间取得统一平衡。

INSIGHT对需要频繁更新 UGC 向量索引的系统，建库时间与显存占用往往和在线 QPS 同样关键；该方案比只追求查询性能的图索引更贴近完整生命周期。实践上应把低比特误差、探针数和批量大小联合调参，并以业务 Recall@K 和尾延迟验证，而不是仅比较单一 ANN 基准的峰值吞吐。

Jifan Shi, Jianyang Gao, James Xia, Tamás Béla Fehér, Cheng Long

04 4.10

A Versioned Unified Graph Index for Dynamic Timestamp-Aware Nearest Neighbor Search

TiGER 为动态向量集合构建带版本连接关系的统一图索引，使任意时间区间查询可直接在同一图中导航，无需事后过滤、分段建图或合并多个子索引。实验显示，在不牺牲准确率的情况下，相比过滤式和按时间分段的基线最高获得 5 倍 QPS，适用于实时推荐、日志分析及持续演化语料的时间感知检索。

INSIGHT时间约束不应只是 ANN 召回后的过滤条件，否则失效节点会浪费遍历预算并伤害召回率。对社区搜索，可把内容发布时间、版本和审核状态编码进图连接的有效区间，让“近 24 小时”“历史某阶段”等查询共享一套索引；上线前需重点评估高频更新下的连接维护成本与时间窗口分布。

Jun Woo Chung, Weijie Zhao

05 4.10

Select, Don't Train: The Benefits of Modular Entity Disambiguation with LLM-Based Selection

论文把实体消歧明确拆成高召回候选生成与上下文选择两个目标，系统比较 BM25、Web 知识库搜索和训练型稠密检索器，并统一交给开源或闭源 LLM 选择器。该设计避免双塔模型在同一嵌入空间里同时折中召回与细粒度判别，也减少知识图谱变化后反复训练检索器的维护负担。

INSIGHT模块化的关键收益是把“候选覆盖不足”和“候选判错”分开观测、独立迭代；在实体、话题或作者检索中尤其适用。UGC 搜索可先用词法、图谱和稠密多路召回保证覆盖，再让较小的上下文选择器处理歧义；这样更新实体库时只需刷新索引，不必同步重训全部语义表示。

Fina Polat, Daniel Daza, Pengyu Zhang, Klim Zaporojets, Paul Groth

06 3.90

NormasTCU --- A Brazilian Portuguese IR Dataset and an Evaluation of LLM-as-a-Judge for Relevance Assessment

NormasTCU 提供巴西葡萄牙语专业检索数据：14,469 份法律文档、46 个查询，以及对 812 个查询—文档对的 3,048 条人工判断。作者用三种 LLM、两类提示生成相关性标签并比较 15 个 IR 系统，发现模型在 0–2 分标尺上的平均绝对误差为 0.46–0.66，且与人工判断仅达到一般到中等一致性。

INSIGHTLLM judge 即使能大幅降低标注成本，也可能系统性高估相关性，进而改变离线系统排序；直接把自动 qrels 当真值风险很高。社区搜索应保留分层人工校准集，按 query 类型和内容语言监测偏差，并比较系统级排序相关性而非只看逐对准确率；自动标签更适合候选筛选和主动学习，不宜完全替代金标。

LINE Conversation History Retrieval for Personal Memory RAG: Evaluating Search Representations and Hybrid Retrieval

研究将 358,896 条 LINE 消息切分为 22,329 个时间连贯片段，对 raw text、摘要和“摘要+原文摘录”的 embedding_text 表示进行 BM25、向量及线性混合检索。单路最佳 Recall@5 为 0.584；在 6 种检索器组合、21 个权重共 126 个配置中，BM25 与向量以 β=0.45 混合后 Recall@5 达 0.697、MRR@5 为 0.595、nDCG@5 为 0.575。

INSIGHT短对话和 UGC 文本中，生成摘要并不意味着应丢弃原文；把摘要承担语义归纳、原文摘录保留关键词，再混合词法与向量召回更稳健。该实验规模虽大但仅来自一位用户和 100 个问题，适合作为表示设计的方向性证据；落地时应按查询意图动态调权，并用多用户、时间泄漏受控的数据复验。

Akito Hattori

Do LLM-Built Product Graphs Improve Ecommerce Search?

Astralab

这项 ESCI/WANDS 对照研究检验 LLM 构建的商品关系图能否改善冷启动搜索。在 58,138 个 ESCI 商品中，目录文本图覆盖 53,082 个商品，并连接 17,876 个无训练标注商品中的 90.04%；但 8,000 个锚点的配对试验中 Recall@100 仅提升 0.000981，低于预设的 0.005 实用阈值，简单 RRF 还降低头部排序质量。

INSIGHT高图覆盖率不等于有效检索增益，LLM 生成的关系边如果缺少相关性校准，融合后可能把噪声推到前列。对冷启动 UGC，可先将图信号限定为候选补充或固定比例替换，并预注册最小业务收益阈值；只有在分 query 桶的 Recall 与 nDCG 同时改善后，才扩大图召回权重。

Vin Lim

ITER: Interaction-Aware Retrieval for Agentic Search

ITER 针对深度研究 Agent 的多轮检索，将当前子查询、主问题和先前子查询共同编码，并从 Agent 交互轨迹中构造相对学习信号训练稠密检索器。它不再把每一步当成孤立查询；在三个模型家族的六种 Agent 骨干上均超过已有轨迹训练检索器 LRAT，说明历史交互能为后续证据检索提供稳定增益。

INSIGHT多轮搜索中的同一句子查询，其含义往往由主任务和已检索路径决定；只编码当前 query 会重复召回或偏离目标。社区搜索若引入对话式入口，可将原始意图、已点击/已排除主题和改写链压缩为检索状态，并使用轨迹相对偏好训练；同时要控制状态长度，避免早期错误在后续轮次持续放大。

Haodong Chen, Shuai Wang, Yu Yin, Shengyao Zhuang, Guido Zuccon, Teerapong Leelanupab

QUEST: A Query and Extraction System for Topics in Asylum Law Application Decisions

QUEST 把长篇、异构的庇护申请材料转化为检索任务，通过合成查询生成、主题抽取与相关性判断，定位影响原判决可信度评估的证据。除标准检索指标外，作者还引入领域评审，区分检出的文本是否真正支持法律人员判断，从而避免仅凭表面关键词命中高估系统价值。

INSIGHT复杂长文检索可先把业务判断维度转成一组可审计的合成查询，再联合主题抽取和相关性评估，而不是依赖单个宽泛 query。对社区治理、申诉或内容审核搜索，这种“业务因素—查询—证据”链路便于解释和复核；但领域迁移需由专家定义因素体系并持续抽查自动生成查询。
