1. Not All Prefills Are Equal: PPD Disaggregation for Multi-turn LLM Serving
3.80
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 2

Summary: 当前 Prefill-Decode (PD) 分离架构在多轮对话推理中存在低效：每轮都把整段历史重新 prefill。论文观察到多轮场景下并非所有 prefill 同等代价——只有本轮新增 token 需在 prefill 节点计算，历史轮次的 KV 可在 decode 节点本地复用，据此提出 PPD（Partial-Prefill Disaggregation），用 append-prefill 在 decode 节点上对增量 token 续算并动态路由请求。第 2 轮及以后请求 TTFT 降低约 68%，append-prefill 引入的 decode 减速比完整 prefill 小一个数量级，TPOT 基本无损。ICML 2026 接收。

Key insight: 多轮 serving 的关键不是“prefill 还是 decode”二选一，而是区分“新增 prefill”与“历史 prefill”的代价差异。对承接多轮搜索/会话的 LLM 服务，可在 decode 节点直接 append-prefill 增量 token、避免把整段上下文回传到 prefill 池，在不改动现有 PD 部署的前提下压低首 token 延迟。该思路与 vLLM/SGLang 的 prefix cache 互补，适合 query 改写、会话式检索等上下文逐轮增长的链路。

arXivUChicagoTogether AI2026-05-05Zongze Li, Jingyu Liu, Zhen Xu, Yineng Zhang, Tahseen Rabbani, Ce Zhang
2. When More Cores Hurts: The Vector Database Scaling Paradox in HPC
3.65
Relevance 4 | Novelty 3 | Practical 4 | Evidence 4 | Timely 3

Summary: 在 64 节点超算环境上系统压测 Qdrant、Milvus、Weaviate 三款向量数据库，发现违反直觉的扩展悖论：给实例增加 CPU 核数反而最多让查询吞吐下降 30.67%；把 worker 从 16 扩到 256（16x）只换来 5.46x 吞吐。作者将根因归为这些系统的云原生设计假设（多租户、网络拓扑、线程模型）与 HPC 紧耦合硬件错配，并给出大规模并行环境下的部署配置建议。

Key insight: 向量库是 UGC 短文本召回的核心基建，但“加资源=加吞吐”在高并发下并不成立——盲目堆核心可能因锁争用、NUMA、线程模型而负优化。实践上应针对目标硬件实测 worker 数与核数的配比，而非照搬云端默认配置；对自建大规模检索集群，容量规划要以实测的边际吞吐曲线为准，警惕过度并行带来的吞吐回退。

3. Latency Prediction for LLM Inference on NPU Systems
3.45
Relevance 3 | Novelty 3 | Practical 4 | Evidence 4 | Timely 4

Summary: 在 NPU 上部署 LLM 时缺少像 GPU 那样成熟的延迟预测方法，而部署需在并行策略、batching、调度策略构成的大配置空间中搜索。论文提出 LENS，无需 NPU 微架构或编译器内部细节，通过对 bucketing 造成的非线性延迟用最少测量做分桶 profiling，再组合出任意输入/输出长度组合的延迟估计。跨多家 NPU 厂商、多个 LLM 与多种 workload，平均预测误差仅 2.15%。

Key insight: 推理硬件正从 GPU 向 NPU/专用加速器扩散，但选型与容量规划缺少可移植的延迟模型。LENS 把延迟预测从“依赖厂商内部细节”变成“黑盒少量测量+组合”，对需要跨硬件评估 serving 成本/SLO 的团队很实用——可在采购前估算不同 batch、序列长度下的 TTFT/TPOT，免去逐一上机实测。分桶+组合的建模思路也可迁移到 GPU 集群的延迟画像。

4. Prefill/Decode-Aware Evaluation of LLM Inference on Emerging AI Accelerators
3.10
Relevance 3 | Novelty 3 | Practical 3 | Evidence 4 | Timely 3

Summary: 以 Llama2-7B 为统一模型，对 GPU 与新兴 AI 加速器（含 GroqRack）做分阶段（Prefill / Decode）的推理性能评测，用 TTFT、TPOT 等指标刻画两阶段不同的计算特征。结论：GPU 在计算密集的 Prefill 阶段持续领先；GroqRack 在 Decode 阶段单请求 TPOT 显著更低（当前不支持 batching）；随 batch size 增大，GPU 在 Decode 吞吐上重新反超。HPAI4S'26 @ IEEE IPDPS 2026。

Key insight: 加速器的优劣高度依赖推理阶段与指标，不能用单一吞吐数字下结论。serving 选型应分别评估 Prefill（看 TTFT/算力）与 Decode（看 TPOT/带宽与 batching 支持）：低并发、延迟敏感链路可能受益于 Groq 类低 TPOT 硬件，高并发批处理仍是 GPU 主场。这也提示 PD 分离架构天然适合异构硬件——把 prefill 和 decode 放到各自更擅长的加速器上。

5. LongCat-Flash-Prover: 美团开源数学形式化与定理证明模型
2.50
Relevance 2 | Novelty 3 | Practical 3 | Evidence 2 | Timely 2

Summary: 美团 LongCat 团队开源 LongCat-Flash-Prover，一个专用于数学形式化与定理证明的模型。区别于常规解题只需“答对最终数值”，定理证明要求严格逻辑链条，任何自然语言的模糊都可能使整条证明崩塌。团队以强化学习训练模型在形式化系统中产出可机器校验的严谨证明。属于近期国内大厂密集开源模型发布的一例。（作为工业实践/开源模型发布纳入覆盖。）

Key insight: 这是一条“可验证奖励 (RLVR) + 形式化校验”的工业样本：用形式化证明器作为客观、可自动判定的奖励信号训练推理模型，规避自然语言评测的噪声。对搜索/推荐中需要严格约束 LLM 输出（如可校验的 query 改写、规则一致性）的场景，这种“用可判定环境做 RL 奖励”的范式值得借鉴；同时也是观察国内开源模型生态的一个信号。
