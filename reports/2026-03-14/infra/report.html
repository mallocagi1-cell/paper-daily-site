LongFlow: Efficient KV Cache Compression for Reasoning Models

针对 DeepSeek-R1、OpenAI-o1 等推理模型输出序列显著加长导致部署成本飙升的问题，提出 LongFlow KV 缓存压缩方法。核心创新是利用注意力计算中间结果推导出一个高效重要性估计指标，无需额外存储或计算开销即可在生成阶段实时压缩 KV 缓存。实验表明在 80% KV 缓存压缩率下可实现高达 11.8 倍吞吐量提升，同时保持模型精度不下降。

KEY INSIGHT · 对业务意味着什么推理模型的长输出序列是当前 LLM serving 的核心瓶颈之一，LongFlow 提供了一条零训练成本的解决路径。其关键设计是将重要性评估嵌入注意力计算流程本身，避免了额外的 profiling 开销。对于部署 DeepSeek-R1 等推理模型的团队，该方法可直接集成到现有 serving 框架中，以极低成本换取数倍吞吐提升，尤其适合搜索场景中需要 LLM 做复杂推理的环节。
Yi Su, Zhenxu Tian, Dan Qiao, Yuechi Zhou, Juntao Li, Min Zhang · 2026-03-12 · arXiv

问题与动机

推理模型（如 OpenAI-o1、DeepSeek-R1）生成极长输出序列（16000+ token），造成巨大内存瓶颈。长输出需要大量 KV 缓存，导致高内存消耗和严重的带宽压力。现有压缩方法针对长输入短输出场景设计，在长输出场景下无效——它们要么需要大量计算开销，要么需要大量辅助存储。

方法概述

LongFlow 仅从当前查询和注意力计算中间值估计 token 重要性，消除对历史数据的依赖。通过定制 Triton 核函数将 FlashAttention、重要性估计和 token 逐出融合为单一算子。

核心技术贡献

  1. 轻量级压缩算法：重要性估计仅需当前查询信息，无辅助存储，成为注意力计算的「几乎免费的副产品」
  2. 融合高性能核函数：集成注意力、评分和逐出的定制核函数将注意力延迟从 47ms 降至 8ms
  3. 理论保证：严格误差界证明当 token 注意力权重趋近零且查询相似度增大时，近似误差消失
  4. 静态内存管理：预分配 KV 缓存消除碎片化，为分布式系统提供一致的逐步工作负载

实验结果分析

  • 模型：DeepSeek-R1-Distill-Llama-8B、Qwen3（0.6B/1.7B/4B/8B）
  • 吞吐量：80% KV 缓存压缩下实现 11.8× 吞吐量提升（Qwen3-1.7B，单 A100-40GB）
  • 精度：DeepSeek-R1 在 3200 token 预算下平均仅 ~0.08% 精度下降；Qwen3-8B 约 1.3%
  • 对比：H2O 吞吐量约为 LongFlow 的 1/4；VATP、R-KV 计算开销显著更高
  • 数据集：MATH-500、AMC-23、AIME-24/25、GPQA、Minerva、OlympiadBench、GSM8K

局限与未来方向

依赖连续查询相似性假设——在主题切换或工具调用交错时性能可能下降；仅针对长输出优化，不适用于长输入预填充或非自回归生成。

工业实践意义

对于部署推理型 LLM（如用于搜索排序解释的 Rank1）具有直接价值——KV 缓存压缩可显著降低长推理链的内存成本。11.8× 吞吐量提升使得在有限 GPU 上部署推理型模型变得经济可行。来自苏州大学和字节跳动的合作研究。

Cornserve: A Distributed Serving System for Any-to-Any Multimodal Models

University of Michigan📖 有深读 · 3 分钟

针对多模态模型（文本、图像、视频、音频任意组合）serving 场景，提出 Cornserve 分布式服务框架。核心思路是通过灵活的任务抽象实现组件解耦和独立弹性伸缩，用高效执行模型管理数据依赖关系。系统基于 Kubernetes 构建（约 23K 行 Python），实验表明相比现有方案可达 3.81 倍吞吐提升和 5.79 倍尾延迟降低。

INSIGHT随着搜索系统逐步引入多模态理解能力（如图文混合搜索），模型 serving 的复杂度急剧上升。Cornserve 的组件解耦设计使不同模态的编码器和解码器可以独立扩缩容，避免了 GPU 资源浪费。其基于 Kubernetes 的架构意味着可以直接融入现有云原生基础设施。对于正在规划多模态搜索能力的团队，这套架构设计思路具有很强的参考价值。

Jae-Won Chung, Jeff J. Ma, Jisang Ahn, Yizhuo Liang, Akshay Jajoo, Myungjin Lee, Mosharaf Chowdhury

问题与动机

现有 serving 系统仅提供针对特定模型类型的「点方案」：vLLM 针对纯文本 LLM，xDiT 针对扩散模型。没有统一系统能高效处理 Any-to-Any 多模态模型（接受和生成文本/图像/视频/音频）。这类模型的关键挑战：不同请求调用不同计算路径，组件具有截然不同的扩展特性（如文本生成吞吐量是音频的 4 倍）。

方法概述

Cornserve 引入三层任务抽象（unit task/composite task/app），允许开发者用纯 Python 表达任意模型计算。通过「模型裂变」将模型在组件边界解聚，独立部署各组件。分布式运行时采用 record-and-replay 执行来动态确定请求调用的组件，同时通过共享内存（节点内）和 RDMA（跨节点）转发中间张量。

核心技术贡献

  1. 任务抽象与模型裂变：composite task 在纯 Python 中组合 unit task，通过裂变参数控制部署配置
  2. Record-and-Replay 执行：record 阶段返回占位符并记录调用；replay 阶段用真实结果执行，支持循环/分支等复杂控制流
  3. 高效数据转发：Sidecar 直接在生产者和消费者间转发张量，绕过控制平面。节点内使用共享内存避免占用 NVLink 带宽；跨节点使用 UCX RDMA
  4. 组件共享：多个 app 部署等效 unit task 时自动共享执行器副本，减少 GPU 消耗

实验结果分析

  • 硬件：两台 8×A100-80GB 节点，NVSwitch + 400 Gbps 跨节点 RDMA
  • Qwen 2.5 Omni：8 GPU 上 3.09× 吞吐量提升；16 GPU 上 3.81× 提升
  • Qwen 3 Omni：单体部署 OOM 失败；Cornserve 从 8→16 GPU 实现 2.68× 提升（超线性）
  • 延迟降低（Qwen 2.5 Omni，16 GPU）：P50 降 3.24×，P95 降 5.3×，P99 降 5.79×
  • Sidecar 开销：跨节点 RDMA 转发 8MB 张量仅增加 5-10ms

局限与未来方向

Record-and-replay 要求确定性控制流；数据依赖分支需在 app 层处理；评测主要集中在 Qwen Omni 系列；跨节点开销在带宽敏感场景下可能成为瓶颈。

工业实践意义

随着搜索系统集成多模态能力（图文搜索、视频理解、语音交互），Cornserve 的解聚式 serving 方案具有前瞻价值。模型裂变使得不同组件可独立扩缩容——文本理解和图像处理可按各自流量比例配置资源。来自密歇根大学和 Cisco Research 的研究。

Slow-Fast Inference: Training-Free Inference Acceleration via Within-Sentence Support Stability

SSkywork AI

观察到句子内部的注意力支持模式高度稳定，据此提出 Slow-Fast 推理框架：在语义连贯片段内复用紧凑稀疏记忆（Fast 步骤），在语义边界处刷新完整注意力（Slow 步骤）。该方法完全无需训练，可直接应用于现有模型 checkpoint，实现 1.6 倍至 14.4 倍解码吞吐提升，同时保持输出质量。

INSIGHT该方法的最大价值在于免训练特性——无需任何模型修改即可获得显著加速。其核心洞察（句内注意力稳定性）揭示了 Transformer 推理中的冗余计算模式。对于搜索系统中使用 LLM 做实时 query 理解或文档摘要的场景，这种零成本加速方案可以直接部署到线上 serving 环境，是降低推理延迟的高性价比选择。

Xingyu Xie, Zhaochen Yu, Yue Liao, Tao Wang, Kim-Chuan Toh, Shuicheng Yan

NVIDIA Nemotron 3: Efficient and Open Intelligence

NVIDIA

NVIDIA 发布 Nemotron 3 系列开源模型（Nano/Super/Ultra），采用 MoE 混合 Mamba-Transformer 架构。Super 模型总参数 120.6B、活跃参数仅 12.7B，引入 LatentMoE（4 倍 expert 调用零额外推理成本）和 MTP（多 token 预测加速生成）等创新。支持 1M token 上下文窗口，使用 NVFP4 训练和多环境 RL 后训练。Super 于 2026 年 3 月 11 日 GTC 正式发布。

INSIGHTNemotron 3 是 NVIDIA 在开源模型领域的重磅布局，其架构创新值得关注：LatentMoE 通过压缩 token 表征后再路由，实现了「用同样推理成本调用 4 倍 expert」的效果；Mamba-Transformer 混合架构在长序列场景下提供 4 倍内存和计算效率提升。对于搜索基础设施团队，该模型的 NVFP4 量化训练方案和 MTP 推理加速设计可直接借鉴，且开放权重和训练配方大幅降低了复现门槛。

IndexCache: Accelerating Sparse Attention via Cross-Layer Index Reuse

Tsinghua University

针对长上下文 LLM 推理中稀疏注意力的索引计算冗余问题，提出 IndexCache 方法。核心思路是将层分为 Full 层（执行完整索引）和 Shared 层（复用 Full 层索引），提供免训练贪心策略和基于蒸馏的训练方案两种模式。在 30B 模型上实现 1.82 倍 prefill 加速和 1.48 倍 decode 加速，消除约 75% 索引计算，精度损失极小。

INSIGHT稀疏注意力是长上下文 LLM 推理的关键优化方向，但现有方法忽视了跨层索引计算的冗余。IndexCache 揭示了一个重要现象：相邻层的注意力索引模式高度相似，可以安全复用。这一发现对于在搜索场景中使用长上下文模型（如处理长文档、多轮对话历史）的团队具有直接价值，且免训练方案可立即部署。

Yushi Bai, Qian Dong, Ting Jiang, Xin Lv, Zhengxiao Du, Aohan Zeng, Jie Tang, Juanzi Li

AutoScout: Structured Optimization for Automating ML System Configuration

UIUC

将 ML 系统配置优化建模为带层次依赖的混合离散/连续优化问题，提出 AutoScout 框架。通过自适应特征优先级排序和多精度模拟器组合，减少昂贵的 GPU profiling 开销。在多种模型、硬件和部署场景下实现 2.7-3.0 倍训练加速，显著超越人工专家调优的配置。

INSIGHTML 系统配置调优（并行策略、通信方式、运行时参数等）是工程实践中的核心痛点，通常依赖经验丰富的工程师反复试验。AutoScout 将这一过程自动化，关键创新在于利用多精度模拟器层次结构大幅降低搜索成本。对于维护多个模型训练/推理任务的 ML 平台团队，该工具可以显著缩短新模型上线的配置调优周期。

MuxTune: Efficient Multi-Task LLM Fine-Tuning in Multi-Tenant Datacenters via Spatial-Temporal Backbone Multiplexing

Shanghai Jiao Tong University

解决多租户数据中心中 LLM 参数高效微调（PEFT）的资源浪费问题，提出 MuxTune 系统。核心方法是在空间和时间两个维度复用 backbone，通过层次化协同调度（任务级、算子级、数据级）和 chunk 对齐机制消除任务间无效 token。实验表明相比三个 SOTA 基线，实现 2.33 倍吞吐提升和 5.29 倍内存节省。

INSIGHT在实际生产环境中，多个团队通常需要在同一集群上并发微调不同任务的 LLM，而现有 PEFT 框架对多租户场景的支持非常有限。MuxTune 的 backbone 复用机制避免了每个任务独占一份模型权重的内存开销，5.29 倍内存节省意味着同样的 GPU 资源可以服务更多并发微调任务。对于搜索/推荐团队需要频繁针对不同场景微调模型的工作流，该方案具有很高的实用价值。

Chunyu Xue, Yi Pan, Weihao Cui, Quan Chen, Shulai Zhang, Bingsheng He, Minyi Guo

Speculative Decoding Scaling Laws (SDSL): Throughput Optimization Made Simple

Meta

提出 Speculative Decoding 的 Scaling Law 理论框架 SDSL，首次从解析角度建立预训练 LLM 超参数与投机解码推理系统吞吐效率之间的定量关系。该框架使研究者能在预训练之前就预测推理系统的最优超参数配置，避免了代价高昂的实验搜索过程。

INSIGHT投机解码是 LLM 推理加速的核心技术之一，但其最优配置（draft 模型大小、推测步数等）此前只能通过大量实验试错确定。SDSL 提供的解析框架将这一过程理论化，使得在模型预训练阶段就能规划配套的推理优化方案。虽然目前更偏理论导向，但对于长期投入 LLM 推理基础设施建设的团队，这一 scaling law 视角提供了重要的系统设计指导。

HAKES: Scalable Vector Database for Embedding Search Service

National University of Singapore

提出 HAKES 分布式向量数据库，采用两阶段索引设计：快速过滤阶段使用高度压缩向量，精炼阶段确保召回率。引入 ML 驱动的参数调优、提前终止检查和解耦写入管理等创新。分布式部署下相比 SOTA 基线实现高达 16 倍吞吐提升。论文发表于 PVLDB 2025。

INSIGHT向量数据库是搜索系统语义召回的核心基础设施。HAKES 的两阶段索引设计（压缩向量粗筛 + 精确向量精排）与搜索系统的召回-精排架构天然对齐，且其 ML 自动调参机制解决了 ANN 索引参数调优的工程痛点。16 倍吞吐提升和解耦写入设计对于需要支持高 QPS 实时写入（如 UGC 内容发布）的社区搜索场景具有直接应用价值。

Guoyu Hu, Shaofeng Cai, Tien Tuan Anh Dinh, Zhongle Xie, Cong Yue, Gang Chen, Beng Chin Ooi
