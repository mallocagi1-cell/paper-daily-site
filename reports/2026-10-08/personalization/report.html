Beyond Successor Accuracy: State Retention for Recursive Self-Improvement in Recommendation

论文研究推荐模型递归更新后应保留哪些状态，以跨代与同代模型配对的公平对照衡量互补收益，并用无需相关性标签的排名分离度选择保留方案。覆盖四个数据集、三种序列编码器，所选模型族在 34/36 条测试轨迹中优于直接后继模型，NDCG@20 平均相对增加 10.6%；跨代组合并非对所有架构始终有效。

Beyond Successor Accuracy：递归推荐更新中的状态保留

正文依据：https://arxiv.org/html/2610.07105 。以下实验数字来自论文第 3、4 节，工业建议属于本报告的迁移分析。

1. 问题与动机

推荐系统递归自改进会把当前模型生成的交互或监督信号用于训练下一代。通常的判断方式是比较新旧模型的 Recall 与 NDCG，然后用新模型替换旧模型。作者指出，这些总量指标没有说明哪些正确推荐被保留：两个平均准确率相近的模型，可以在不同用户上命中不同物品；新模型总体变好，也可能遗失旧模型独有的正确决策。

论文的实证动机非常具体。直接后继模型 A 在原始留出测试中只在 26/36 条轨迹优于父模型 P，而选择适当配对族后，组合在 34/36 条轨迹优于 A。作者把更新边界两侧保留的互补性称为分布式进展。它不是分布式计算，而是进步未必全部浓缩到单个后继网络中。研究问题因此变成：一个更新结束后，应保留单个模型、同代组合，还是跨代组合？

这与社区 UGC 搜索的排序迭代有直接关系。总体 nDCG 上升，仍可能覆盖不了旧模型擅长的口语、长尾内容或特定用户群。论文提供一个分析框架来区分“后继变强”和“更新制造了可利用的互补性”，而非直接提出更大、更复杂的主干模型。

2. 方法详解

每条轨迹训练四个模型：P、B 是独立的更新前运行；P 生成用于后续训练的交互；A、A′ 使用相同的增强数据与配置，只改变随机种子。跨代族 C 包含 P-A、P-A′、B-A、B-A′ 四个组合；同代族 W 包含 P-B 和 A-A′ 两个组合。这里既包含父子配对，也包含非父子配对，避免把某条特定继承边的收益误当作整个更新的性质。

两模型的融合规则固定：给每个物品的分数等于两个全目录概率的对数加权和，β 固定为 0.5，即各占一半，再按这个分数排序。跨代优势 CGA 定义为四个跨代组合的平均效用，减去两个同代组合的平均效用。两侧给 P、B、A、A′ 的边际总权重都是 0.5，推理时都调用两个模型。如果配对效用可以分解成模型本身的主效应与交互项，模型主效应就会相消，剩下更接近跨更新边界的互补作用。作者并未声称它单独辨识某种因果机制：校准、分数尺度与顶部排序决策都可能影响结果。

实际保留方案由排名分离度选择。先计算两模型 top-k 集合交集大小除以 k，并对用户取平均；再用同代重叠度均值减去跨代重叠度均值，得到 Sep_k。Sep_20 大于零，表示跨代的顶部决策分歧比同代种子分歧更大，选择跨代族；否则选择同代族。这个计算在选择时不需要相关性标签，但训练模型和最终测量效用当然仍需要交互数据。

实现细节相当充分。四个数据集为 Amazon Toys、Beauty、Sports 和 Yelp，评估用户数分别为 9,011、10,980、17,297 和 17,168。每个数据集与编码器组合有三条独立种子轨迹，每个模型训练 10,000 次更新。生成过程每个拟合历史产生五个续接，排名保真阈值为 20。每个用户最后三个事件分别形成检查点选择、诊断和确认窗口，早期事件才作为拟合前缀；原始验证和测试留待最终评估。

所有模型使用 64 维物品嵌入。GRU4Rec 为两层循环网络、隐藏宽度 256、dropout 0.2；SASRec 为两层注意力、两个头、隐藏宽度 128、dropout 0.5；FMLP 为两层滤波模块、dropout 0.5。优化器 Adam，学习率 0.001，batch 256，采样负例 256，最大序列长 50，每 500 次更新评估一次；全目录评测屏蔽 padding 与已观察物品。正文没有明确提供硬件型号，不能据此承诺某种 GPU 的训练时间。

3. 核心技术贡献

第一项贡献是把更新边界的互补性变成可检验的对照量。通常比较父子模型与单模型时，额外推理成本或强模型的边际优势会混入结论。CGA 对照的是相同双模型成本下的跨代与同代族，并匹配四个模型的边际使用率，因而更有利于解释更新本身产生的结构性差异。

第二项贡献是区分“获得进展”和“成功压缩进展”。作者用五条转移路线检查生成数据、概率、排名、互补目标以及参数能否被单网络继承。硬生成数据重训的收益随领域改变符号；全目录 KL、top-50 列表蒸馏和互补目标分别只在 1/4、2/4、1/4 个设置胜过相应对照；线性参数插值在十条轨迹中均未超过更强端点。最好的列表蒸馏仍留下残余收益。

第三项贡献是用顶部边界信号进行选择。开发数据上，CGA 与 top-20 分离度相关系数为 0.850，与独有命中优势为 0.870；全目录 Jensen–Shannon 与总变差对应只有 0.500、0.270。结果提示，真正需要观察的是曝光列表附近的变化，而不仅是整个概率分布的差异。这个发现比“模型不同所以组合有效”更具体，也更适合排序回归诊断。

5. 局限与未来方向

论文没有单列通用“局限”章节，但正文明确限制了排名分离度的解释范围：跨轨迹相关系数为 0.814，按架构中心化后降至 0.205。因此主要关系来自不同架构的更新响应，不是同架构不同随机种子的可靠优选信号。报告不能把 12/12 的设置正确率扩大解释为任何模型副本都能无标签精准选择。

作者也明确指出，固定融合下的交互项可能包含校准与分数尺度，不能归因到唯一机制；第二轮 FMLP 的表现更进一步说明该信号并非无条件稳定。五种转移未能一致重现双模型收益，是仍待解决的状态压缩问题。结论将关系状态保留定位为自改进推荐系统的设计问题，而不是声称已有普适闭环。

本报告额外指出：证据只覆盖四个离线数据集、三类相对小的编码器和两轮更新，没有真实社区搜索在线 A/B、延迟曲线或大型工业排序模型结果。这些属于可见的外推边界，并非作者报告的线上失败案例。

6. 工业实践意义

在 UGC 社区排序中，可先把这套方法作为模型更新诊断：保留上一版本与新版本的独立种子运行，固定融合方式、候选集及推理成本，测量跨代与同代组合的 nDCG 差异。再按用户活跃度、历史长度、内容冷启动程度审计独有命中与回归，判断总体增长是否掩盖特定用户损失。这里的分层审计是业务建议，论文并未直接验证这些人群。

可借鉴的工程路径是离线先算 Sep_20，再在独立窗口验证 CGA，最后用原始留出测试或真实 A/B 确认。前期计算无需新标注并不意味着可以省略最终相关性或点击验证。选择、诊断、确认三个窗口和未参与调参的 Sports 数据集值得复用，以减少信号在同一验证集上反复挑选造成的乐观偏差。

部署代价很清楚：相比单模型，多保存一份模型，并增加一次前向计算。应先并行化两个编码器并实测 P95 延迟、吞吐、显存与特征读取成本，再判断 0.002 级别的离线增益是否足够。若在线预算无法承担，可把 top-50 列表蒸馏作为压缩实验起点，但必须接受论文中仍存在残余损失这一事实。没有线上 A/B 数字可以直接用于收益预算；CTR 改善需要在本场景另行验证。

Personal-Agent Mediated Recommendation with Cross-Platform User History

MetaUCSD📖 有深读 · 12 分钟

论文将跨平台用户历史用于已有推荐列表的选择性调整，提出 MediateRec 基准和 PAMO 训练方法，通过遮蔽跨平台记录评估推理对个人信息的依赖，并保留平台相对价值下限。真实 OpenPlay 的 645 名用户测试中，PAMO 将 HR@10 从平台的 40.8% 提升到 47.9%，NDCG@10 从 0.241 提升到 0.284，有害覆盖率为 6.0%。

INSIGHT核心问题是跨平台用户建模带来的补救收益与错误改写之间的平衡，因此本次归入个性化。社区搜索可以借鉴强平台排序加用户授权历史的选择性调整，并分别监控补救、误伤和干预强度。结果来自固定 50 候选的重排测试，目标项始终被插入候选集；迁移到实际 nDCG 和 CTR 时还需验证召回、时延及历史可用性。

Personal-Agent Mediated Recommendation：跨平台用户历史的选择性介入

正文依据：https://arxiv.org/html/2610.07588 。方法和实验来自正文及附录 A、B，面向 UGC 社区的建议为本报告分析。

1. 问题与动机

平台推荐模型拥有大量群体协同信号，但只看到用户在本平台的行为；个人代理可能拥有用户授权的跨平台历史，却不知道平台内部训练数据、模型状态和原始分数。这形成双向信息不对称。把平台排序完全交给个人代理重做，很容易损失平台已捕捉的有效信息；完全不调整，则无法利用跨平台记录透露的具体兴趣。

作者将任务定义为 Personal-Agent Mediated Recommendation：平台先返回完整候选排序，个人代理输出最终 top-K。重点不是从空白目录生成推荐，而是在强默认排序之上决定哪些项目值得改写。评价中明确拆出“平台未命中但代理找回”的补救，以及“平台本来命中却被代理删掉”的有害覆盖。HR@K 的净改善等于补救概率减去有害覆盖概率，这让个人化收益和破坏已有正确决策的成本处于同一个尺度。

实证动机同样具体。真实 OpenPlay 平台基线 HR@10 为 40.8%，未适配的 Qwen3-4B-Instruct 只有 38.9%；获得额外历史并不自动带来更好的个性化。论文据此提出 PAMO，训练代理既利用个人记录，又保留平台证据。虽然采用 LLM 代理，核心评价仍是用户历史建模和个性化排序的净收益，因此本次单轨将其纳入 personalization。

2. 方法详解

平台提案 B 包含候选集合、完整平台排序和候选元数据。代理输入还包括本平台历史 H_within 和跨平台历史 H_cross，并先生成可见理由 R，再给出有序列表 S。平台内部得分与群体交互不向代理暴露。最终列表只可从现有候选中选择，保持平台 top-K 本身是合法动作。

MediateRec 用 Amazon Reviews 2023 的四个品类模拟不同平台：Movies、Toys 为见过的目标平台，Grocery、Beauty 用于未见平台迁移。同一用户在其他品类的先前交互作为跨平台记录，没有额外 k-core 过滤。Movie 和 Toy 各有 5,000 训练、1,000 验证和 2,000 测试；Grocery 与 Beauty 各有 2,000 仅测试样本。真实外部测试用 OpenPlay 链接 Steam、Nintendo、Xbox 的匿名同人记录，共 645 名用户，Steam 是唯一目标平台。这些用户不进入代理训练、超参数选择或检查点选择。

每次评测固定 50 个候选：真实目标加 49 个按流行度采样、此前未交互的物品，目标项明确被插入。这是候选条件排序测试，不是端到端召回评测。平台先用仅在本平台训练的 SASRec 排序，再由 Claude Sonnet 4.6 在仅含本平台历史的条件下重排，最后冻结提案。SASRec 为 64 维嵌入、最大长度 50、两层注意力、单头、dropout 0.5，以 256 个负例的交叉熵训练；Adam 学习率 0.001，batch 256。

PAMO 每个提示采样八个理由和列表。个人介入支持度是同一个理由在完整历史条件与遮蔽跨平台历史条件下的对数似然比，再除以理由长度。完整条件概率已由 rollout 保存，所以只需额外执行一次遮蔽历史的 teacher-forcing。作者刻意只计 FINAL 标记之前的理由，不计最终 ID 段：固定理由前缀后，ID 对遮蔽历史的敏感性可能很弱。支持度只说明模型的理由依赖那些记录，不保证记录正确，也不保证决策有价值。

接下来把单目标 NDCG 拆成 top-1 到 top-K 的嵌套命中指标，权重取相邻折扣差。这使从第八位升到第三位的收益只分配给跨越的第三至第七个边界。PAMO 在平台相关的变化上重新分配组内优势，倾向更有个人历史支持的回复，但同时保留平均平台相对 NDCG 的价值下限，避免奖励“理由特别依赖个人信息但排序更差”的输出。κ=0 时退化为标准组相对优势；主实验 κ 为 0.5，支持度不反向传播。

代理用 Qwen3-4B-Instruct 初始化。先用 2,000 条 Sonnet 示范做格式 SFT，Movie、Toy 各一千，不按推荐结果过滤；三轮训练，batch 64，最大长度 8,192，学习率 0.00001。RL 每次更新 64 提示、每提示八次采样，温度和 top-p 均为 1.0，学习率 0.000001，PPO minibatch 32、clip 0.2，无 KL 惩罚，理由回答最长 2,048 token。总计 400 次更新，每 50 次验证并存检查点；框架 VeRL，rollout 用 vLLM。正文没有明确列出可确认的 GPU 型号与训练墙钟时间。

3. 核心技术贡献

第一，定义强平台提案下的个人化介入任务。固定候选、平台排序和用户，并把补救、有害覆盖、替换数量分开，让用户信息的作用与“修正一个很弱的默认列表”区别开。平台基线已经包含协同过滤和 LLM 重排，代理胜出才更能说明附加信息与训练策略有效。

第二，用遮蔽历史的反事实评分评估理由对个人记录的依赖。它比按理由中有没有出现某个词更有结构：同一回复、同一提案、本平台历史不变，只移除跨平台部分。按长度归一化也避免长理由天然得到更大累计差值。作者同时明确，这个指标是模型相对的支持度，而不是人类可验证的因果归因或正确性证明。

第三，把推荐价值约束加入优势重分配。普通 outcome-only GRPO 会奖励正确结果，却不区分它是否受跨平台信息支持；只按支持度奖励则可能放大错误干预。PAMO 在嵌套排序边界上调整优势，并保留价值下限。理论部分证明其在保持相应质量质量约束的局部一阶重分配中具有最优性质；这不等于整个训练过程对任何数据分布都全局最优。

第四，提供代理平台和真实跨服务测试的组合。Amazon 能提供规模和受控信息边界，OpenPlay 则检查真实服务之间是否迁移。真实测试上，PAMO 的 NDCG@10 比匹配训练的 GRPO 从 0.267 提升到 0.284；HR@3 从 22.2% 提高到 26.2%，说明收益更明显地集中在榜首，而不只是第十位边缘命中。

作者还分析了 900 个平台漏掉、PAMO 找回的样本理由，用 Sonnet 标注其主要依据：72% 的补救主要来自跨平台用户语境，其中兴趣与粉丝偏好占 28%，家庭场景 19%，生活方式、饮食与健康 14%。这些是理由的模型标注，不是人工审计后的因果比例。例子中，跨平台 Led Zeppelin 记录帮助把 Robert Plant 音乐影片从第 37 位升到第 1 位；弱或无关记录则支持保持已有 Zelda 商品首位。

5. 局限与未来方向

作者在附录 A.5 明确说明三个范围限制。目标总被插入 50 个候选，因此结果不覆盖召回遗漏；Amazon 的品类边界只是代理平台，不是真实独立服务；Amazon 候选目录和流行度统计是静态全体数据，没有逐目标事件限制到当时可用物品。尽管历史严格在目标事件之前，目录可用性仍不是严格的时间因果部署协议。

真实外部测试也有明确边界：只有 Steam 作为目标，Xbox 信息只到类型级别，移动游戏记录因身份不可用被排除。645 名链接用户证明一种受控的跨服务迁移，不能直接代表所有用户、内容社区或长尾的新用户。作者对支持度的定义也强调，它测量模型理由依赖，不是记录真实性或对用户的真实有用性。

本报告另外指出：论文没有报告真实点击 A/B、在线隐私授权流完成率或重排的时延分布。Sonnet 被用于构造平台提案、示范以及理由标注，后者存在模型评估偏差的可能；这属于外推时应核验的事项，而非作者已经观察到的线上失败。可进一步在真实候选召回、多目标排序和时间严格目录中检验方法。

6. 工业实践意义

对社区搜索，最可借鉴的是保留强默认排序，再让用户历史产生具体且可审计的局部纠正。社区内历史、用户主动授权的其他来源记录和当前 query 意图应保持来源边界，避免把所有信号无差别混合。先固定同一召回集合做重排对照，区分哪些目标被找回、哪些原有正确结果被误删，以及实际替换多少条；再扩展到真实搜索 nDCG 和 CTR。

训练上可以先实现完整历史与遮蔽历史的成对评分，检验个性化理由是否真的利用记录。它每个 rollout 额外增加一次 teacher-forcing，而不是又生成一遍答案；这一成本与完整 RL 的采样预算需分别估计。400 次更新乘以每步 64 提示和八次采样形成较大的训练工作量，复现时不能只按一个 4B 模型的部署显存估算总成本。

服务侧正文采用每样本一次生成，从 50 候选中返回 top-10，并解析 FINAL 标记、去重 ID。建议增加非法 ID、列表不完整和超时的回退到平台提案，并先在小流量验证；这些回退是本报告的工程建议，并非论文已上线证明的机制。查询相关性强的搜索场景尤其应避免个人历史覆盖明确 query 约束。

最终收益判断要同时看用户分层 nDCG、CTR、误伤率、延迟、授权历史覆盖率和内容时效。论文证明的是离线候选条件排序更有效，不能直接宣称上线 CTR 增长 7.1%。更适合先作为用户建模与选择性干预的研究原型，在独立窗口和实际业务 A/B 中验证后再决定投入。
