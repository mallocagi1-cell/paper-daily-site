SCOUT: Active Information Foraging for Long-Text Understanding with Decoupled Epistemic States

针对百万 token 级长文本理解任务，论文指出端到端 long-context LLM 存在 token 消耗过高、注意力稀释问题，而传统专用 LTU 智能体（如图构建、索引）又会因任务无关的抽象牺牲精度。作者提出 SCOUT，一种从被动处理转向主动信息觅食（active information foraging）的新范式：把文档视为可探索环境，由「状态级 gap 诊断」驱动，自适应地在粗粒度浏览与细粒度精读间切换，从一个紧凑的、带可追溯证据的 epistemic state 中作答。该范式在长文本 QA 任务上同时提升了推理保真度与计算效率。

1. 问题与动机

百万 token 级长文本理解（LTU）面临作者称为"LTU 三难困境"的张力：极致可扩展性、高保真信息保留与推理效率三者难以同时实现。前沿长上下文模型如 Gemini-3-Pro、GPT-5.1 端到端处理百万 token 时遭遇注意力稀释和计算量二次增长，token 成本随上下文长度呈数量级上升；而 GraphReader、ReadAgent、MemAgent 等专用长文本智能体则通过任务无关的预索引（图构建、记忆压缩）牺牲了保真度，在结构构建过程中丢失答案关键细节；传统 RAG 的 chunking 策略破坏全局连贯与长程依赖。

作者提出关键洞察：对给定 query，回答所需信息通常是文档中一个稀疏的「query-sufficient subset」。因此高效系统不应被动地处理整个上下文，而应主动「觅食」该最小子集。这一信息稀疏假设直接挑战了"上下文越长越好"的工业默认范式，并为 LTU 提供了新设计原则。

2. 方法详解

SCOUT 的核心架构创新是「状态解耦」：把 ReAct 风格的交互历史拆为两部分：

Procedural Trace ℋₜ：记录 Agent 在哪里探索（动作序列）。
Epistemic State ℰₜ：仅维护已被确立为 query 相关的知识。

硬性约束（公式 4）：最终答案的生成只能访问 ℰₜ，而不能访问完整的交互历史 ℋₜ。这一设计阻止了探索噪音污染推理过程，也使最终回答的「证据集」是审计闭包。

Epistemic State 表示：ℰₜ = {e₁, …, eₘₜ}，每个元素 eⱼ 是二元组 ⟨cⱼ, αⱼ⟩。cⱼ 是蒸馏后的原子陈述，αⱼ 是溯源锚点（指向文档具体位置）。这种 provenance-anchored 设计保证了任何用于推理的陈述都能追溯到源文本。

动作空间分为两类：

  • 觅食动作 𝒜forage：Grep/Scan（词法级粗定位）、Read（局部精读，支持预算）。
  • 状态管理动作 𝒜state：Update（提交 provenance-anchored 单元）、Evaluate（执行状态级 gap 诊断）、View（查看当前 ℰₜ）。

Gap Diagnosis 机制是 SCOUT 的"灵魂"：Evaluate 不是简单的"是否终止"启发式，而是在状态层面分析「为可靠回答 q 还缺什么」，输出明确的下一轮觅食目标。这驱动了迭代式的 diagnose-acquire-commit 循环直至 query 满足。

算法 1 推理流程：(a) 初始化空 ℋ 和 ℰ；(b) 在步数预算内：从策略 πθ(a|q, ℋₜ, ℰₜ) 采样动作；若是觅食动作则在文档上执行，ℰₜ 不变；若是状态管理动作则更新 ℰ 或诊断 gap；将动作及结果追加到 ℋ；(c) 当 gap 关闭或步数耗尽，仅基于 ℰₜ 生成答案。

训练设置：开源权重实验在 Qwen2.5-72B-Instruct 上做 60M optimization tokens 预算的 SFT，并对比 DAPO（policy gradient）变体；统一评估时所有对比方法（包括前沿大模型与现有 LTU agent）都用 Claude-Sonnet-4.5 作为统一 backbone 以保证公平。

3. 核心技术贡献

(1) 状态解耦的 LTU 范式：把"探索轨迹"与"已确认知识"显式分离，是首次把 LTU 形式化为「带可读 epistemic state 的 POMDP」式问题。比单纯的 ReAct（动作历史不区分价值）更结构化，比 GraphRAG（先建索引再查）更动态。机制本质：阻断噪声反向通道，让最终生成只面对一个干净、紧凑、可审计的证据集。

(2) Provenance-Anchored 知识单元：每个 epistemic 单元都带溯源锚 αⱼ，使下游推理具备可解释性与可校验性，是工业可部署的关键 — 在线诊断时可直接定位"哪个片段支撑了这个回答"。

(3) State-Level Gap Diagnosis：把"下一步去哪儿觅食"从动作级（动作选择即决策）抽离到状态级（先诊断缺什么、再决定如何获取），相比 ReAct 的隐式 reasoning，更易做离线 reward 设计与监督蒸馏。

(4) 训练-时-架构协同：开源 SFT 大幅超过 LLM-only SFT（LooGLE-v2 上 +27.1% vs +1.2%），表明 LTU 瓶颈不是参数化知识而是长程交互与状态控制能力，这是 RL/SFT 时代的新发现。

Scaling 鲁棒性（Figure 3）：把上下文从 64K 拉到 1M+，前沿单体模型在 256K 之后准确率骤降（"long-horizon breakdown"），token 成本指数级增长；SCOUT 的准确率与 token 成本几乎保持平稳。

  • 去觅食动作（只剩 epistemic 操作）：17.7%（-60.5%）— 觅食是不可或缺的"输入"
  • 去文件工具：74.2%（-4.0%）
  • 去 grounding（去除 αⱼ）：75.5%（-2.7%）— 溯源带来稳定增益

最关键的消融是「去 ℰₜ」与「去 grounding」：它们共同证明 SCOUT 的两层设计（解耦状态 + 溯源锚）都是有贡献的，单独砍掉任一部分都会显著下降。

开源训练增益（Table 3）：在 Qwen2.5-72B-Instruct 上 60M token 预算下 SFT，LLM-only 几乎不动（LooGLE-v2 +1.2%、∞Bench -0.7%），而 SCOUT-SFT 分别 +27.1% / +25.1%。这是非常强的证据，说明同样训练预算下，SCOUT 提供的结构化交互范式才是开源模型 LTU 能力的关键瓶颈。

5. 局限与未来方向

作者明确承认三点：

(1) 单 query wall-clock latency 较高：SCOUT 多步交互比单次端到端推理在 wall-clock 上更慢（虽然 token cost 更低）；并行觅食优化是未来工作。这对线上低延迟场景（如社区搜索 P99 <500ms）是硬约束。

(2) 跨 query 复用缺失：每个 query 独立处理同一文档，没有摊销预处理。对于"同一长文档被多个 query 反复访问"的场景（如客服 FAQ、产品手册问答），SCOUT 不如索引式方法经济。

(3) 评测局限：仅在文本、信息稀疏的长文档上验证；信息密集（如代码评审、密集表格）和多模态长文档（图文交错）的场景未覆盖。

显见但未点出的局限：策略 πθ 在工业部署时仍依赖 SOTA 闭源大模型作 backbone，开源 72B 虽然能 SFT 到接近，但训练 60M token 的成本依然不低；线上"主动觅食"还可能因外部检索 API 延迟波动而方差较大。

6. 工业实践意义

对搜索/推荐 Agent 团队的具体启示：

(1) 长帖子/长问答 RAG 的范式重塑：社区平台普遍存在长帖、专栏、专业问答这类 5K-50K token 的内容。直接全文喂给 LLM 不仅贵且容易稀释。SCOUT 的「主动觅食 + epistemic state」范式可以直接照搬：让搜索 Agent 用 Grep/Read/Update/Evaluate 这套动作集围绕用户 query 在长帖中觅食，输出带溯源的精炼证据集。落地路径上，可从 Claude/Qwen 这类支持 tool-use 的模型起步，先用 prompt-engineering 实现 SCOUT 风格 ReAct 循环，验证后再做 SFT。

(2) Epistemic State 作为可审计原语：把"模型已知什么"显式化为带溯源的结构化状态，对线上诊断与 reward 设计是关键改进。建议搜索 Agent 在每步显式输出 ⟨陈述, 文档锚点⟩ 二元组，便于线下评估"哪个证据导致回答正确/错误"，也便于做 process reward。

(3) 不必用最大上下文模型：实验显示 SCOUT 在 Claude-Sonnet-4.5 上即可达成 SOTA，且 token 成本下降 8 倍。对于成本敏感的搜索场景（社区每日 query 数千万级），这个换算下来是巨大的推理预算节省。

(4) 对开源 backbone 的启示：72B 模型 LLM-only SFT 几乎没收益，而 SCOUT-SFT +27.1%。这意味着对于自研搜索 LLM 的团队，「先把 Agent 框架定好、再用 SFT/RL 让模型适应该框架」比「单纯增大数据量做指令微调」更有效。

(5) 部署考虑：多步交互意味着 P99 latency 高于单次推理，这对在线场景需要并行化（多步骤同时尝试不同动作）或离线预计算（针对热门长文档先 forage 出常见 query 的 ℰₜ）。后者实际上是把 SCOUT 与索引式方法结合的混合范式，可能是下一步工程价值最高的方向。

GEM: Graph-Enhanced Mixture-of-Experts with ReAct Agents for Dialogue State Tracking

针对多领域对话状态追踪（DST），作者提出 GEM 框架：一个智能 router 在 GNN（捕捉对话结构和 turn 间依赖）与 finetuned T5-Small 编码-解码器（序列建模）之间动态路由，对复杂槽位生成任务则集成 ReAct Agent 进行结构化推理。在 MultiWOZ 2.2 上实现 65.19% Joint Goal Accuracy，相对端到端 LLM 方法的最佳 38.43% 大幅提升，并超越当前 SOTA。

INSIGHTGEM 给出了「轻量专家 + ReAct Agent」分工的工程化模板：对结构性强的子任务用专用小模型（GNN/T5），仅在复杂、需要外部知识或多步推理的子任务上才升级到 LLM Agent。这种「按需调用 ReAct」的路由策略在社区搜索中也很关键——大多数 query 用召回+排序的传统流水线已足够，只有长尾、模糊或多意图 query 才走 Agent 路径，能在保持 P99 延迟的同时获得 LLM 的推理红利。MoE-router 框架同样可推广到搜索 Agent 中做「工具选择」。

ProMMSearchAgent: A Generalizable Multimodal Search Agent Trained with Process-Oriented Rewards

ProMMSearchAgent 提出了一种 introspective Process-Oriented Reward 机制，用以解决多模态 Agent 训练中「奖励-动作不匹配」的关键问题。系统训练了一个可泛化的多模态搜索智能体，能够进行复杂的多步推理、证据验证以及在视觉与文本模态间的主动搜索。

INSIGHTProcess-Oriented Reward 把「过程可解释性」当作 reward 信号——这是一种比 outcome reward 更稳定的训练范式，对长视觉/文本搜索链路尤为关键。社区搜索的图文检索（帖子常含图片+正文）可直接借鉴：将「是否点击有效图文片段」、「是否调用了正确的多模态检索工具」作为过程奖励，构造从外部 RM 过来的稀疏 reward 之外的稠密信号，让 RL 训练更稳。同时 introspective 信号也能在线上线下评估时复用。

Free Energy-Driven Reinforcement Learning with Adaptive Advantage Shaping for Unsupervised Reasoning in LLMs

针对无监督 RL 训练 LLM 时奖励信号无法适应模型不断进化的推理能力的问题，作者提出 FREIA 算法，由两个核心创新组成：(1) Free Energy-Driven Reward (FER) 基于自由能原理在共识与探索之间动态平衡奖励；(2) Adaptive Advantage Shaping (AAS) 根据采样奖励的统计特征自适应调整学习信号。在 9 个数据集、3 类推理任务上的实验显示 FREIA 显著超越其他无监督 RL 基线，尤其在数学推理上表现突出。

INSIGHTFREIA 把贝叶斯/自由能原理引入 RL reward 设计，是「无 ground truth 时如何继续 RL」的一个值得关注的解法。对搜索 Agent 训练特别有用：线上社区 query 大多没有标准答案，无法靠 RLHF/RLVR；用 FER 风格的「模型-自由能」作为奖励，可以让搜索 Agent 在没有人工标注的真实流量上做 self-play 式自我提升。AAS 的统计自适应也能缓解搜索 RL 中常见的「reward 方差爆炸」问题，是工业 RL Pipeline 可借鉴的稳定化技巧。

Adapt to Thrive! Adaptive Power-Mean Policy Optimization for Improved LLM Reasoning

针对 RLVR（Reinforcement Learning with Verifiable Rewards）中静态策略优化目标与模型推理能力进化不匹配的问题，作者提出 APMPO，包含两项创新：Power-Mean Policy Optimization (PMPO) 通过广义 Power-Mean 目标使模型自适应地从「信号放大」的算术均值行为过渡到「一致性强化」的几何均值行为；Feedback-Adaptive Clipping (FAC) 基于实时奖励统计自适应调整 clipping 边界，克服静态机制的局限。两者结合显著改善了 RLVR 训练动态与推理表现。

INSIGHTPMPO 的「Power-Mean 一族目标可在算术-几何之间连续插值」是 RL 调参的实用洞察：训练前期重信号放大（探索），后期重一致性（利用），这恰好对应搜索 Agent 在线学习的不同阶段。FAC 的「实时统计驱动的 clipping」对工业级 RL 也很关键——线上 query 流量分布漂移会让静态 PPO clip 失效，FAC 思路可直接迁移。两者都是无需额外标注、可复用现有 reward 信号的「软」创新，部署成本低，是 RL Pipeline 可叠加的稳定化模块。

RLearner-LLM: Balancing Logical Grounding and Fluency in LLMs via Hybrid DPO

传统 DPO 依赖人类或 LLM-judge 提供偏好信号，但二者都偏向流畅而非逻辑正确，导致 SFT 模型 NLI 蕴含分仅 0.05–0.22。作者提出 RLearner-LLM with Hybrid-DPO：用 DeBERTa-v3 NLI 信号 + verifier LLM 评分融合作自动偏好流水线，免人工标注且克服单信号优化的「alignment tax」。在 5 个学术领域 × 3 种基座（LLaMA-2-13B / Qwen3-8B / Gemma 4 E4B-it）下，最高带来 6× NLI 提升、15 个评测格中 11 个 NLI 改善并伴随 answer-coverage 增益。Hybrid-DPO 在 4.5B Gemma 上效果尤为突出。

INSIGHTHybrid-DPO 的核心思想——用一个细粒度的「事实/逻辑判别器」（NLI 模型）+ 一个粗粒度的「verifier LLM」组合监督，本质是把 reward model 拆为「硬判别 + 软评分」。这一思路非常契合搜索 RAG 场景：可以用 query-doc NLI 模型当硬判别（doc 是否真支持答案），LLM-judge 当软评分（回答是否流畅可读），从而在 RAG Agent 训练时同时纠正幻觉与提升可读性。该方案完全去除人工标注成本，是工业搜索团队可立即试点的对齐路线。

Distilling Bayesian Belief States into Language Models for Auditable Negotiation

针对端到端 LLM 谈判 Agent 的「对手信念隐式、不可审计」问题，作者提出 BOND（Bayesian Opponent-belief Negotiation Distillation）：由一个 LLM-based Bayesian Teacher 对 6 种对手优先级排序进行评分、维护后验分布并基于后验做菜单决策；再蒸馏到 8B 学生模型，让学生输出谈判动作的同时以 tagged text 形式输出归一化后验信念。在 CaSiNo 谈判数据集上 BOND 超越 SOTA，对手优先级后验的 Brier 分数为 0.085，蒸馏后的小学生在很大程度上保留了信念表达能力。

INSIGHTBOND 的「贝叶斯信念以可读文本形式输出」是 Agent 可审计性的关键设计：模型不仅给出动作，还给出「我认为对方在乎什么」的概率分布。对搜索 Agent 同样可迁移——例如让 RAG Agent 在每一步显式输出「我目前对 query 意图的信念分布 + 缺失证据」，便于线上诊断和 reward 设计。蒸馏到 8B 表明这一显式信念表达对部署友好的小模型也能保留，工业落地不需依赖巨型 teacher。
