1. HiPRAG: Hierarchical Process Rewards for Efficient Agentic Retrieval Augmented Generation
4.90
Relevance 5 | Novelty 5 | Practical 5 | Evidence 4 | Timely 4

Summary: 针对 Agentic RAG 中普遍存在的过度检索（检索已知信息）和不足检索（遗漏必要检索）问题，提出 HiPRAG 方法。该方法在 RL 训练中引入层级化过程奖励（Hierarchical Process Reward），将 agent 的推理轨迹分解为可解析的离散步骤，在每步检索决策点评估其必要性，从而实现细粒度的搜索行为优化。实验表明 HiPRAG 在多个 QA 基准上显著降低冗余检索次数的同时提升回答准确率。

Key insight: 核心创新在于将 agentic RAG 的检索决策建模为可学习的过程奖励问题，而非仅依赖结果奖励。层级化奖励函数能区分「有价值的检索」和「冗余检索」，为搜索系统中的 agent 自主检索策略提供了可控的训练信号。对搜索/推荐系统的启示：可借鉴该方法优化多轮检索 agent 的检索时机判断，减少不必要的召回调用，提升推理效率和质量。

2. Do We Still Need GraphRAG? Benchmarking RAG and GraphRAG for Agentic Search Systems
4.65
Relevance 5 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: 提出 RAGSearch 统一基准，系统性评估稠密 RAG 与 GraphRAG 在 agentic search 系统下的表现差异。核心发现：当引入动态多轮检索和序列决策的 agentic 搜索能力后，标准 RAG 的性能大幅提升，GraphRAG 所带来的显式图结构优势被显著削弱。这一结论对搜索架构选型有重要参考价值，表明在多数场景下无需承担构建 GraphRAG 管线的高昂成本。

Key insight: 关键洞察：agentic search 的多轮动态检索能力能通过交互隐式捕获文档间的结构关系，从而补偿显式图结构的缺失。这意味着搜索系统在引入 agent 循环后，可优先采用更轻量的 RAG 方案。对实践的启示：在资源有限时，投入 agentic 检索策略（多轮推理+动态决策）的 ROI 可能优于构建知识图谱管线。

3. HTAA: Enhancing LLM Planning via Hybrid Toolset Agentization & Adaptation
4.65
Relevance 5 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: 针对 LLM agent 大规模工具调用中的效率和错误累积问题，提出 HTAA 层级化工具使用框架。核心思路是将高频共现工具封装为专门的 agent 工具（Toolset Agentization），缩小 planner 的动作空间；并通过非对称 planner 适配（Asymmetric Planner Adaptation）实现高层 planner 与 agent 工具的对齐。在高德地图（中国最大在线地图服务）的 POI 验证工作流上验证，处理数百个工具的实际场景。

4. Self-Correcting RAG: Enhancing Faithfulness via MMKP Context Selection and NLI-Guided MCTS
4.60
Relevance 4 | Novelty 5 | Practical 4 | Evidence 4 | Timely 5

Summary: 提出 Self-Correcting RAG 框架，将 RAG 的检索和生成重新建模为约束优化与路径规划。输入端首次将上下文选择形式化为多维多选背包问题（MMKP），在严格 token 预算下最大化信息密度并消除冗余；输出端引入自然语言推理（NLI）引导的蒙特卡洛树搜索（MCTS），在推理时动态探索推理轨迹并验证答案忠实度。在 6 个基准上的实验表明该方法显著提升了 RAG 的准确性和忠实度。

Key insight: 核心贡献在于将两个经典优化框架（MMKP 和 MCTS）引入 RAG 系统：MMKP 解决了上下文窗口中信息冗余的定量优化问题，MCTS 则为生成过程提供了可验证的搜索树策略。对搜索系统的启示：上下文选择的 MMKP 建模可直接应用于多路召回结果的融合排序，通过 token 预算约束优化上下文质量；MCTS 的推理时计算扩展策略对需要高忠实度回答的搜索场景具有参考价值。

5. AgentWebBench: Benchmarking Multi-Agent Coordination in Agentic Web
4.40
Relevance 5 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 提出 AgentWebBench 基准，评估 Agentic Web 新范式下的多 agent 协调能力。在该范式中，内容提供方部署自己的 agent 管理数据并通过受控接口提供服务，信息获取从集中式检索转向去中心化协调。覆盖四类任务：网页搜索、网页推荐、问答和深度研究。在 7 个先进 LLM 和 3 种协调策略上的评估表明，多 agent 协调整体落后于集中式检索，但差距随模型规模缩小，部分场景甚至可以超越集中式方案。

Key insight: Agentic Web 代表了搜索架构的范式转移：从搜索引擎直接索引内容，转向 user agent 与 content agent 之间的协调对话。这一范式对搜索/推荐系统的架构影响深远——未来的搜索系统可能需要同时扮演 user agent（理解用户意图并协调多方信息）和 content agent（管理自有内容并通过 API 提供结构化服务）。关键发现是模型规模对协调能力的提升效果显著，暗示大模型是 agentic web 落地的基础。

6. Agentic Aggregation for Parallel Scaling of Long-Horizon Agentic Tasks
4.35
Relevance 4 | Novelty 5 | Practical 4 | Evidence 4 | Timely 5

Summary: 研究 agentic search 和 deep research 等长周期 agent 任务的并行测试时扩展（parallel test-time scaling）问题。提出 AggAgent 聚合 agent，将多条并行 agent 轨迹视为可探索的环境，配备轻量级工具（检查候选方案、跨轨迹搜索）按需导航和综合信息。在 6 个基准和 3 个模型家族（GLM-4.7, Qwen3.5, MiniMax-M2.5）上，AggAgent 超越所有现有聚合方法。

Key insight: 核心洞察在于 agentic 任务的并行扩展面临独特挑战：轨迹长、多轮交互、工具增强，且输出开放式，简单的答案聚合或轨迹拼接均不可行。AggAgent 的 agent-as-aggregator 方案提供了新思路——用另一个 agent 来整合多个 agent 的探索结果。对搜索系统的启示：可用于多路 deep research agent 的结果融合，以及多候选排序结果的智能聚合，通过并行化提升推理质量和效率。

7. Deep-Reporter: Deep Research for Grounded Multimodal Long-Form Generation

Summary: 提出 Deep-Reporter，首个面向多模态长文本生成的 agentic deep research 框架。包含三个核心模块：(i) Agentic Multimodal Search and Filtering，检索和过滤文本段落及信息密集的视觉内容；(ii) Checklist-Guided Incremental Synthesis，确保图文融合和引用放置的连贯性；(iii) Recurrent Context Management，平衡长距离一致性和局部流畅性。构建了 8K 高质量 agentic traces 用于模型优化，并引入 M2LongBench 测试集。

8. Controllable and Verifiable Tool-Use Data Synthesis for Agentic Reinforcement Learning
4.35
Relevance 4 | Novelty 5 | Practical 4 | Evidence 4 | Timely 5

Summary: 提出 COVERT 两阶段管线，解决工具使用 agent 的 RL 训练缺乏可执行环境的痛点。第一阶段通过自演化合成生成可靠的基础工具使用轨迹，结合多层验证；第二阶段应用保留 oracle 的增强策略，系统性增加环境复杂度（干扰工具、模糊查询、噪声/多格式工具输出），同时严格保留 oracle 工具调用和最终答案作为 ground truth。在 Qwen2.5-Instruct-14B 上的实验证明该方法有效提升工具调用策略。

Key insight: 解决了 agentic RL 训练的关键瓶颈：现有工具使用数据集仅面向 SFT，缺乏支持在线 rollout 和奖励验证的可执行环境。COVERT 的 oracle-preserving augmentation 策略巧妙地在增加训练复杂度的同时保留了自动奖励计算能力。对搜索 agent 训练的启示：可用该方法构建搜索工具使用的 RL 训练环境，模拟嘈杂搜索结果、模糊查询等真实场景，提升搜索 agent 的鲁棒性。

9. How You Ask Matters! Adaptive RAG Robustness to Query Variations
4.35
Relevance 5 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: 首次大规模评估 Adaptive RAG 对查询表述变化的鲁棒性。构建了包含人工和模型生成的语义等价查询变体基准，从三个维度系统评估：回答质量、计算成本和检索决策。核心发现：查询表面形式的微小变化会剧烈改变 Adaptive RAG 的检索行为和准确率，暴露出严重的鲁棒性缺口。即使模型规模增大，虽性能提升但鲁棒性并未相应改善。

Key insight: 揭示了 Adaptive RAG（agent 自主决定是否检索）中的关键脆弱性：语义相同但表述不同的查询导致截然不同的检索决策。这对搜索系统的启示极为直接——在部署基于 LLM 的 adaptive 检索策略时，必须进行充分的查询变体鲁棒性测试。可借鉴该研究的评估框架，对自身搜索 agent 的检索决策一致性进行审计，并探索查询规范化或 ensemble 策略来缓解该问题。
