深度解读：The Generative Recommender Behind Shopify's Commerce Engine

问题与动机

Shopify 面对的核心挑战是：如何在超大规模电商场景下，利用买家完整的行为序列来预测其下一步可能感兴趣的商品？

传统推荐系统通常将用户行为简化为静态特征（如用户画像、历史偏好标签），丢失了行为序列中蕴含的丰富信息——搜索、浏览、加购、收藏、购买的顺序、时间间隔和上下文变化。例如，一个用户 6 月份浏览 T 恤和 12 月份浏览 T 恤，其购买意图可能截然不同，但传统方法难以区分。

这个问题之所以重要，有三个层面：

  1. 规模层面：Shopify 在 BFCM 2025 期间处理了 2.2 万亿次边缘请求，超过 8100 万消费者完成了购买。这种规模既意味着海量的学习信号，也意味着严苛的实时服务约束。
  2. 商业价值层面：推荐质量直接影响转化率和订单量，在电商场景中每 0.1% 的提升都意味着巨大的商业价值。
  3. 方法论层面：将推荐问题重新定义为序列预测问题（而非传统的协同过滤或特征工程问题），可以让模型自动学习意图变化、长期偏好和季节性行为等复杂模式，减少对人工特征工程的依赖。

方法概述

Shopify 构建了一个基础生成式推荐系统（Foundational Generative Recommender），核心思路是将推荐问题建模为自回归的下一商品预测任务。

整体框架：

  • 输入：买家的原始事件序列（搜索、浏览、加购、收藏、购买等），跨 Shop App 和各个商户店铺
  • 建模方式：使用自回归模型 + 因果掩码（causal mask） 预测序列中的下一个 token（即商品）
  • 基础架构：基于 Meta 提出的 HSTU（Hierarchical Sequential Transduction Unit） 架构，这是一种专为序列推荐设计的生成式架构

系统沿三个维度演进：

  1. 数据：融合 Shop App 内行为和跨店铺行为，更完整地表示买家旅程
  2. 模型：引入创新的时间编码和改进的负采样策略
  3. 计算：实现优化的 CUDA kernel，满足内存和延迟约束

核心技术贡献

1. 时间感知注意力机制（Time-aware Attention）

Shopify 将时间作为一等公民（first-class signal） 编码进注意力机制中：

  • 采用 RoPE 启发的旋转编码来表示事件的绝对时间
  • 结合相对注意力偏置（relative attention bias） 来建模时间间隔和近因性
  • 关键创新：在推理时可以注入当前会话的时间戳，使模型能自适应地感知季节性变化，而不需要手工规则

与现有方法的区别：大多数序列推荐模型要么忽略时间信息，要么仅用简单的位置编码。Shopify 的方案将"绝对时间"和"相对时间差"统一进注意力计算，使模型从一个通用序列预测器转变为一个理解时间上下文的商业模型。

2. 负采样作为核心扩展轴（Negative Sampling as a Scaling Axis）

在百万级商品目录上训练下一商品预测模型需要使用 sampled softmax。Shopify 发现负样本的数量和质量是模型质量最重要的杠杆之一：

  • 共享负样本（Shared Negatives）：在 batch 内共享负样本池，在不爆内存的前提下有效扩大负样本覆盖范围
  • 正例感知的困难负样本（Positive-aware Hard Negatives）：困难负样本（near miss）最有价值，但必须仔细筛选以避免将用户未曾见过的潜在正例错误标记为负例（false negative 问题）

核心洞察：负采样不是一个训练细节，而是一个扩展维度——随着负样本数量和质量的提升，模型质量持续改善。但这需要将系统效率作为建模问题的一部分来解决。

3. Boosting 式增量训练策略

这是本文最具工业价值的贡献。在生产环境中，推荐系统通常是一个集成体（ensemble）——多路召回 + 精排 + 聚合层。一个单独模型即使离线指标很强，如果它找到的结果与其他模型高度重叠，对整体系统的增量价值可能很小。

Shopify 采用了 boosting 启发的训练策略：

  • 增加对集成系统薄弱区域的训练压力
  • 将其他模型的预测结果作为困难负样本
  • 目标不是追求新颖性本身，而是在真正需要的地方提升覆盖率，使集成系统整体变强而非只是变大

关键区别：传统做法是优化单个模型的独立指标（如 Recall@K），而 Shopify 优化的是模型对整体系统的增量贡献（incremental recall），这是一种系统级思维。

4. 训练效率优化

通过优化 CUDA kernel 和训练流水线，实现了相对于基线实现最高 7.3x 的训练加速。这不仅是工程优化，更直接转化为迭代速度——更快的训练意味着可以更积极地探索模型容量、批大小和上下文长度。

实验结果分析

在 2025 年 8 月版本模型的在线 A/B 测试中，Shopify 报告了以下关键指标的提升：

指标相对提升
Shop 订单量+0.94%
高质量点击率（导向收藏/加购/购买的点击）+5.0%
转化率+0.71%
最终服务的商品 Recall@2+4.8%

结果分析：

  1. 订单量 +0.94% 在 Shopify 的规模下极具商业价值。对于日交易额数十亿美元的平台，不到 1% 的订单量提升意味着显著的收入增长。
  2. 高质量 CTR +5% 是最显著的提升，说明模型不仅在找到相关商品，更在找到能驱动深层用户行为（收藏、加购、购买）的商品，而非仅仅吸引点击。
  3. Recall@2 +4.8% 验证了增量召回策略的有效性——模型确实在找到其他模型遗漏的真正正例。
  4. 离线召回质量与线上指标的正相关性得到验证，这对"离线指标能否代表线上效果"这一老问题提供了正面证据。

值得注意的是，文章强调这些提升不是来自单一改变，而是时间编码、负采样、boosting 训练和系统优化等多项技术协同作用的结果。

局限与未来方向

当前局限

  1. 商品 ID 空间问题：当前系统将每个商品建模为独立的 ID embedding，这导致：

- 超大规模的 embedding 表，内存开销巨大
- 冷启动问题——新商品没有充分训练的 embedding
- 难以融合更丰富的信号（如文本查询、对话式交互）

  1. 序列长度受限：虽然文章提到优化了 CUDA kernel，但长序列的计算成本仍然是实际限制。对于行为极其丰富的活跃用户，可能需要截断序列。
  1. 跨域泛化：当前模型依赖 Shopify 生态内的行为数据，对于新入驻商户或新品类的推荐可能存在冷启动瓶颈。
  1. 文章信息有限：作为工程博客而非学术论文，缺少消融实验（ablation study）的详细数据，难以精确评估每项技术的独立贡献。

未来方向

文章明确提出的方向是 Semantic IDs（语义 ID）：

  • 将商品从 product ID 空间映射到 token 空间，用更小的词汇表中的 token 序列来表示商品
  • 进而训练能同时处理语义 ID token 和文本 token 的统一模型
  • 最终实现基于 prompt 的任务适配，同时保持在 Shopify 商业上下文中的 grounding

这个方向与学术界的 TIGER（Google）、LC-Rec 等工作高度呼应，但 Shopify 更强调工程可行性和服务成本的可预测性。

工业实践意义

对搜索/推荐系统的借鉴

  1. "增量价值"思维比"独立最优"更重要：这是本文最核心的工业洞察。在多路召回的生产系统中，新模型的价值不在于它自己有多强，而在于它能为现有系统补充多少。Boosting 式训练策略提供了一个优雅的解决方案——让新模型专注于现有集成的盲区。这个思路对任何拥有多路召回的推荐系统都直接可用。
  1. 负采样是一个被低估的扩展维度：工业界常把注意力放在模型架构和特征工程上，而 Shopify 的经验表明，在足够大的商品空间下，负采样策略的改进可能比换模型架构更有效。特别是"共享负样本"和"正例感知的困难负样本"两个技巧，实现成本低但效果显著。
  1. 时间编码的工程化路径：RoPE + 相对注意力偏置的时间编码方案，给出了一种将时间信息融入 Transformer 推荐模型的实用方案，尤其是在推理时注入当前时间来处理季节性的做法，避免了传统基于规则的季节性调整。
  1. 系统效率即模型质量：7.3x 的训练加速不是锦上添花，而是使更多实验成为可能的基础设施。这提醒我们，在工业推荐系统中，迭代速度本身就是竞争优势。

对广告系统的启示

文章提到模型也用于推荐广告（"recommend the next products, and in some contexts the next ads"），这意味着该框架具有统一推荐和广告的潜力。将广告也视为买家旅程中的一个自然环节进行序列建模，可能比传统的分离式广告系统更能平衡用户体验和商业化目标。

关键 Takeaway

生成式推荐在工业界真正可行的关键，不仅在于选对了模型架构（HSTU），更在于围绕"系统级增量价值"这一目标，重新设计了训练策略（boosting 式负采样）、时间建模和计算效率的整套方案。 这是一个从"模型好不好"到"系统好不好"的思维范式转变。

PROMISE: Process Reward Models Unlock Test-Time Scaling Laws in Generative Recommendations — 深度解读

1. 问题与动机

本文瞄准的核心问题是生成式推荐中的"语义漂移"（Semantic Drift）。

在当前主流的生成式推荐范式中，物品被编码为多层的 Semantic ID（通常通过 RQ-VAE 或 Residual K-means 量化得到），推荐模型像语言模型一样，自回归地逐层生成这些 token。问题在于：早期高层 token 一旦生成错误，后续所有 token 都会被不可逆地带入错误的语义子空间——就像 Chain-of-Thought 推理中第一步逻辑错了，后面所有推导都跑偏了。

这一问题的根源是经典的 Exposure Bias：模型在训练时使用 teacher forcing（每步看到正确输入），但推理时要依赖自身上一步的预测，一旦犯错便缺乏纠错机制。传统的 beam search 仅依据模型自身的 likelihood 打分，无法有效识别和修剪偏离正确语义空间的候选路径。

为什么这个问题重要？ 在工业级推荐系统中（如快手，日活 4 亿+，物品库 1 亿+），语义漂移直接导致召回率大幅下降。论文实验表明，在没有 PRM 的情况下，第三层生成的 HRecall@3@1000 仅 22.96%，意味着超过 3/4 的候选在生成过程中已经偏离了正确的语义空间。

2. 方法概述

PROMISE 的核心思路可以用一句话概括：借鉴 LLM 推理中的 Process Reward Model (PRM) 思想，为生成式推荐的每一步中间生成结果提供密集的过程级反馈，通过 PRM 引导的 Beam Search 实现推理时扩展（Test-Time Scaling）。

整体框架包含两个关键组件：

(1) Path-Level PRM（路径级过程奖励模型）

一个轻量级的注意力模块，在 Semantic ID 生成的每一层（而非仅最终结果）对候选路径进行打分。具体结构为：

  • 使用 Cross-Attention 机制复用主编码器的输出（不需要重新编码用户序列）
  • F 层堆叠架构 + MLP 打分头
  • 使用 InfoNCE loss 在正样本（ground-truth 物品的 Semantic ID 前缀）和负样本（随机采样的有效路径）上进行对比学习训练

(2) PRM-Guided Beam Search

在推理时执行改进的 Beam Search：

  • 每一步先将候选集从 K 扩展到 K⁺ 个候选 token（K⁺ >> K）
  • 用 PRM 对 K⁺ 个候选打分，选出 Top-K′ 进入下一步（K′ = K，保持解码器计算量不变）
  • 关键洞察：扩大 K⁺ 只增加 PRM 的轻量计算，不增加主解码器的计算开销

3. 核心技术贡献

贡献一：首次建立"推理时扩展"在推荐系统中的理论联系

论文提出了一个重要的结构性类比：

LLM 推理生成式推荐
Token 序列Semantic ID 层级序列
Chain-of-Thought 步骤从粗粒度到细粒度的量化层
推理错误传播语义漂移
PRM 逐步验证逐层路径打分

这不是简单的方法迁移，而是揭示了两个看似不同领域之间的深层结构同构。

贡献二：PRM vs ORM 的关键区别

与仅在最终结果上给出监督信号的 Outcome Reward Model (ORM) 不同，PRM 提供密集的逐步反馈（dense, step-by-step feedback）。在 Semantic ID 的层级结构中，第一层编码粗粒度语义（如"运动鞋" vs "连衣裙"），后续层逐步精细化。PRM 可以在第一层就修剪掉偏离正确大类的候选，避免后续计算浪费在注定错误的分支上。

贡献三：计算-性能解耦的 Scaling 方案

传统提升推荐质量的方式是增大模型参数（training-time scaling），而 PROMISE 通过增加推理时的搜索宽度 K⁺ 实现性能提升（test-time scaling），且主解码器计算量保持不变。论文证明：在达到相同性能水平时，test-time scaling 比 parameter scaling 节省 30-40% 的 FLOPs。

贡献四：极轻量的工程设计

  • PRM 仅增加主模型 15% 的参数量
  • 使用主模型 1/4 的注意力头
  • 采用 Radix Top-K 优化加速 GPU 计算
  • 端到端推理延迟仅增加 10%

4. 实验结果分析

公开数据集（Amazon Review）

在 Sports/Outdoors 数据集上，相较 ActionPiece 基线：

  • Recall@5 提升 +42.41%
  • NDCG@5 提升 +44.39%

在 Beauty 数据集上提升相对温和（Recall@5 +4.90%），可能因为 Beauty 品类的语义空间更为紧凑，语义漂移问题不那么严重。

工业级数据集（快手）

在 1 亿+ 物品、500 亿日交互的规模上，相较 GRank 基线（K⁺=6000）：

  • Recall@100 提升 +59.31%（0.1609 vs 0.1010）
  • NDCG@100 提升 +40.47%（0.00663 vs 0.00472）
  • Recall@500 提升 +25.92%（0.3017 vs 0.2396）

工业数据集上的提升远大于公开数据集，说明语义漂移问题在大规模、高基数词表（M=8192 vs M=256）上更为严重，PRM 的价值也更大。

在线 A/B 实验

在快手主站和极速版上各分配 2000 万用户，运行 7 天：

  • 快手主站：总使用时长 +0.121%，人均观看时长 +0.440%
  • 快手极速版：总使用时长 +0.131%，人均观看时长 +0.296%

在快手这种体量的平台上，0.1%+ 的使用时长提升是非常显著的业务收益。

Test-Time Scaling 曲线

将 K⁺ 从 1000 增加到 6000 时：

  • HRecall@3@1000 从 22.98% 提升到 36.37%（+58.3%）
  • 主解码器计算量不变（K′ 固定在 1000）
  • 而传统 beam search 扩大搜索宽度（红色三角线）几乎无收益且计算开销线性增长

这条曲线是本文最核心的实验结论——清晰地验证了推荐系统中 test-time scaling law 的存在。

消融实验（语义漂移量化）

论文提出了新指标 HRecall@b@k（第 b 层生成的层级召回率）来量化语义漂移：

  • 无 PRM：HRecall@3@1000 = 22.96%
  • 仅第 1 层用 PRM：29.51%（+28.5%）
  • 全部 3 层用 PRM：33.58%（+46.3%）

证明第一层的 PRM 修正收益最大，符合"早期错误代价最高"的直觉。

5. 局限与未来方向

当前局限

  1. 对层级量化结构的依赖：PROMISE 的核心假设是 Semantic ID 具有从粗到细的层级结构（RQ-VAE / Residual K-means）。对于非层级的物品 ID 编码方案（如 flat hashing），方法不直接适用。
  1. 负样本采样策略较为简单：当前使用均匀随机采样构造负样本，没有利用 hard negative mining。对于语义空间中距离很近但实质不同的物品（如同品牌不同型号），PRM 的区分能力可能有限。
  1. 与 Scheduled Sampling 等训练时方法的对比缺失：论文未充分探讨训练阶段缓解 exposure bias 的经典方法（如 scheduled sampling、curriculum learning）是否能与 PRM 互补。
  1. Scaling Law 的边际递减：从实验曲线看，K⁺ 从 4000 到 6000 的收益明显放缓，更大的 K⁺ 可能面临收益饱和，且内存/延迟成本线性增长。

未来方向

  1. 自适应计算分配：不同用户/请求的语义漂移风险不同（如长尾用户 vs 活跃用户），可以动态调整 K⁺ 实现计算资源的最优分配，类似 LLM 中的 adaptive compute。
  1. 多步 PRM 的联合训练：当前 PRM 对每一层独立打分，未来可以建模层间的依赖关系，实现全局最优的路径规划。
  1. PRM 与强化学习的结合：将 PRM 的逐步反馈信号用于基础推荐模型的 RLHF/DPO 训练，可能同时提升训练质量和推理质量。
  1. 推广到更多生成式任务：如生成式广告创意、生成式查询改写等场景，同样存在层级生成中的漂移问题。

6. 工业实践意义

对推荐系统

  1. "小模型 + 多搜索" 的新范式：这可能是本文对工业界最大的启示。在推理成本受限的场景下，与其部署一个巨大的推荐模型，不如用一个较小的模型 + PRM 引导的更宽搜索——论文证明这种方案在相同 FLOPs 下性能更优。这为推荐系统的模型部署策略提供了全新的 trade-off 空间。
  1. 召回阶段的范式升级：PROMISE 直接作用于生成式召回（candidate generation），在快手的 A/B 实验中已验证端到端收益。对于正在从传统双塔/ANN 召回向生成式召回转型的团队，PRM 是一个值得优先探索的增强方向。
  1. 可插拔的架构设计：PRM 模块仅增加 15% 参数和 10% 延迟，且通过 cross-attention 复用主模型编码器输出，不需要重新训练基础模型。这种即插即用的特性极大降低了工业落地门槛。

对搜索系统

  1. 生成式检索的启示：生成式检索（如 DSI/GENRE/SEAL）同样使用层级 docid 进行自回归生成，面临完全相同的语义漂移问题。PROMISE 的 PRM 思路可以直接迁移到文档检索场景。

对广告系统

  1. 动态计算预算分配：广告系统对延迟极其敏感，但不同广告位的价值差异巨大。可以对高价值广告位分配更大的 K⁺（更多推理计算），对低价值广告位使用较小的 K⁺，实现ROI 最优的计算分配。

更宏观的视角

  1. 推荐系统的 "Inference-Time Compute" 时代：正如 OpenAI 的 o1/o3 系列证明了 LLM 领域 test-time scaling 的价值，PROMISE 为推荐系统开启了同样的范式——不再仅依赖更大的训练模型，而是通过更智能的推理时搜索策略来提升质量。这可能成为继 deep learning、预训练之后，推荐系统的又一个重要技术转折点。

总结：PROMISE 是一篇质量很高的工业论文，来自快手团队的真实系统验证。它不仅提出了一个有效的技术方案（PRM + 引导式 Beam Search），更重要的是建立了生成式推荐与 LLM 推理之间的理论桥梁，为推荐系统打开了 test-time scaling 这一全新的性能提升维度。15% 参数增量、10% 延迟增量换来 40-60% 的召回提升和显著的线上收益，性价比极高。
