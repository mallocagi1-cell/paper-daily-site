1. MAC-Attention: a Match-Amend-Complete Scheme for Fast and Accurate Attention Computation
4.20
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 长上下文解码中 LLM 需要反复读取不断增长的 KV 缓存，导致严重的 IO 瓶颈。现有加速方案要么通过压缩降低精度，要么通过选择/驱逐限制可访问范围。MAC-Attention 提出 Match-Amend-Complete 三阶段方案：先用低精度快速匹配关键 token，再修正误差，最后补全结果，在保持完整精度和可访问性的前提下显著降低 KV 缓存读取量，实现无损加速。该方法对延迟召回和长文本生成场景尤为友好。

Key insight: MAC-Attention 的核心创新在于将注意力计算分解为「粗筛-修正-补全」三步，避免了传统压缩方法的信息损失和选择方法的覆盖不足。这一设计思路可迁移至搜索系统中的多阶段召回-精排架构：先低成本粗筛候选，再精确修正关键结果。对需要处理长上下文的 RAG 场景（如 UGC 搜索中的多文档聚合），该方法可直接降低推理延迟而不牺牲质量。

2. HISA: Efficient Hierarchical Indexing for Fine-Grained Sparse Attention
4.20
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: Token 级稀疏注意力（如 DeepSeek Sparse Attention）通过轻量级索引器为每个 query 对所有历史 key 评分并选择子集来实现细粒度的 key 筛选。但索引器本身仍需扫描全部历史 key，成为性能瓶颈。HISA 提出层次化索引结构，将 key 组织为多层级索引，使索引器的计算复杂度从 O(n) 降低到 O(√n) 级别，在长序列场景下显著加速稀疏注意力的 key 选择过程。

Key insight: HISA 将信息检索中的层次化索引思想引入注意力机制，与搜索系统中的倒排索引分层检索高度类似。对搜索推荐系统而言，这种层次化稀疏注意力可直接用于长文档理解和大规模候选集的高效注意力计算。该方法解决了 DeepSeek Sparse Attention 等方案中索引器随序列长度线性增长的瓶颈，对需要处理长上下文的搜索场景具有直接的工程参考价值。

3. MF-QAT: Multi-Format Quantization-Aware Training for Elastic Inference
4.15
Relevance 3 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: 传统量化感知训练（QAT）针对单一数值格式训练，但实际部署中常需根据硬件支持或运行时约束在推理时选择不同精度。MF-QAT 研究多格式 QAT，使单个模型在多种量化格式下均保持鲁棒性。研究发现共享训练不同格式的量化参数可以相互增强，最终模型可弹性地在 INT8、INT4、FP8 等格式间切换部署，无需为每种格式单独训练。

Key insight: MF-QAT 解决了搜索推荐系统中模型部署的核心痛点：同一模型需要在不同硬件环境（GPU/CPU/边缘设备）上以不同精度运行。一次训练即可获得多种精度的部署能力，大幅降低了模型管理和部署成本。对于需要在 A100/H100/T4 等不同 GPU 上部署排序模型的团队，可直接采用该方法实现弹性推理，在延迟和质量间灵活权衡。

4. S0 Tuning: Zero-Overhead Adaptation of Hybrid Recurrent-Attention Models
4.15
Relevance 3 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: S0 Tuning 提出一种零推理开销的混合循环-注意力模型适配方法：仅优化每个循环层的初始状态矩阵，冻结所有模型权重。在 Qwen3.5-4B（GatedDeltaNet 混合架构）上，使用约 48 个 HumanEval 训练样本，S0 Tuning 在 HumanEval 上超越 LoRA +10.8 个百分点（p < 0.001），greedy pass@1 提升 +23.6 pp。该方法参数量极小，推理时无额外开销。

Key insight: S0 Tuning 的核心价值在于「零推理开销」——这对在线搜索排序服务至关重要，因为推理延迟是硬约束。与 LoRA 相比，S0 不引入任何额外的推理计算，仅通过改变循环层的初始状态来实现适配。这种方法特别适合混合架构模型（如 Mamba+Attention）的高效微调场景，为搜索推荐系统中的大模型轻量化适配提供了新思路。

5. Routing-Free Mixture-of-Experts
3.95
Relevance 3 | Novelty 5 | Practical 3 | Evidence 4 | Timely 5

Summary: 标准 MoE 模型依赖集中式路由机制（外部路由器、Softmax、Top-K、负载均衡），引入了刚性归纳偏置。Routing-Free MoE 完全消除所有硬编码的集中式设计，将所有激活功能封装在各个专家内部，由专家自主决定处理哪些 token。这种去中心化设计消除了路由瓶颈和负载不均衡问题，简化了 MoE 架构的训练和推理流程。

Key insight: Routing-Free MoE 是 MoE 架构的范式级创新——消除了路由器这一长期以来的性能和工程瓶颈。在搜索推荐系统中，MoE 架构越来越多地用于大规模排序模型和多任务学习。去掉路由器意味着：(1) 训练更稳定，无需复杂的负载均衡 loss；(2) 推理时无路由开销；(3) 更易于分布式部署。该设计对构建下一代大规模推荐模型有重要参考意义。

6. Spectral Compact Training: Pre-Training Large Language Models via Permanent Truncated SVD and Stiefel QR Retraction
3.90
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 内存墙是在消费级硬件上训练大语言模型的主要瓶颈。Spectral Compact Training（SCT）将稠密权重矩阵替换为永久截断 SVD 分解 W = U·diag(s)·V^T，在训练和推理过程中永远不实例化完整稠密矩阵。梯度通过 Stiefel QR 回缩在正交流形上流动，保持数值稳定性。该方法在不牺牲模型质量的前提下大幅降低了训练内存消耗。

Key insight: SCT 的核心思路是「永久低秩」——不同于 LoRA 等事后低秩近似，SCT 从训练开始就工作在低秩空间中，从根本上减少了内存占用。对于搜索推荐团队在有限 GPU 资源上预训练或微调大模型，这种方法可以直接降低显存需求。Stiefel 流形上的梯度优化保证了训练稳定性，是一种理论优雅且实用的内存优化方案。

7. ParetoBandit: Budget-Paced Adaptive Routing for Non-Stationary LLM Serving
3.90
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 生产环境的 LLM 服务通常依赖跨越约 530 倍成本范围的多模型组合，路由决策需在质量和成本间权衡。ParetoBandit 是一个开源的自适应路由框架，基于多臂老虎机算法处理非平稳的 LLM 服务场景：模型提供商调价、模型质量退化、新模型需无停机接入。系统自动维护 Pareto 前沿，在预算约束下动态选择最优模型。

Key insight: ParetoBandit 解决了 LLM 服务化的核心工程难题：如何在成本预算内自动选择最优模型。对于搜索系统中越来越多地使用 LLM（query 改写、文档理解、重排序等），这种自适应路由机制可以直接应用——根据 query 复杂度自动选择不同规模的模型，在保证质量的同时控制推理成本。开源实现降低了落地门槛。

8. Scheduling LLM Inference with Uncertainty-Aware Output Length Predictions
3.90
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: LLM 推理调度中，最短作业优先（SJF）原则通过优先处理短输出请求来避免队头阻塞（HOL blocking）。但现有方法仅预测单一输出长度（点估计），无法匹配推理输出的随机性。本文提出不确定性感知的输出长度预测方法，将输出长度建模为概率分布，基于此分布设计更鲁棒的调度策略，在高并发场景下显著降低尾延迟。

Key insight: 该工作将不确定性量化引入 LLM 推理调度，这是一个非常实用的工程优化。搜索系统中 LLM 推理请求的输出长度差异巨大（短答案 vs 长摘要），传统调度策略无法有效处理这种不确定性。概率化的输出长度预测+鲁棒调度策略的组合，可以直接应用于搜索服务中的 LLM 推理 serving，降低 P99 延迟。

9. Sequence-Aware Split Heuristic to Mitigate SM Underutilization in FlashAttention-3 Low-Head-Count Decoding
3.85
Relevance 3 | Novelty 3 | Practical 5 | Evidence 4 | Timely 5

Summary: 标准 FlashAttention-3 在低 head 数解码配置下存在 GPU 占用率瓶颈：它仅基于序列长度决定是否禁用序列分割，导致 Hopper GPU 的流式多处理器（SM）利用率不足。本文提出序列感知的分割策略，在低 head 数场景下允许序列级并行，充分利用 GPU 的 SM 资源，在 GQA/MQA 等现代注意力架构的解码阶段实现显著加速。

Key insight: 这是一个针对 FlashAttention-3 具体瓶颈的精准工程优化。随着 GQA（Grouped Query Attention）和 MQA（Multi-Query Attention）在主流模型中的广泛采用，低 head 数解码成为常态。该优化可直接集成到现有推理框架中，对使用 Hopper GPU 部署搜索/推荐模型的团队有立即可用的性能收益，无需修改模型架构。

10. Executing as You Generate: Hiding Execution Latency in LLM Code Generation
3.85
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 当前 LLM 编码 Agent 采用串行执行范式：先完整生成代码，再调用解释器执行。这种顺序工作流导致执行器在生成阶段空闲、生成器在执行阶段空闲，产生不必要的端到端延迟。本文提出「边生成边执行」的流水线方案，将代码生成和执行重叠进行，通过检测代码块边界实现增量执行，隐藏执行延迟，显著降低 Agent 的总响应时间。

Key insight: 「边生成边执行」的思路可广泛应用于搜索系统中的 LLM Agent 场景，如多步骤搜索 Agent、RAG pipeline 中的中间结果处理等。核心启发是：当 LLM 生成的输出可以分块独立处理时，不必等待完整输出再开始下游处理。这种流水线化思路对降低搜索 Agent 的端到端延迟有直接参考价值，尤其是在需要多次工具调用的复杂查询场景中。
