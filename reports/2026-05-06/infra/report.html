1. GhostServe: A Lightweight Checkpointing System in the Shadow for Fault-Tolerant LLM Serving
4.25
Relevance 4 | Novelty 5 | Practical 4 | Evidence 3 | Timely 5

Summary: 针对多 GPU/多节点 LLM 服务集群中单卡故障即可使整套推理服务中断的可靠性痛点，论文提出 GhostServe，一种以 "影子" 方式运行的轻量级 KV cache checkpoint 系统。GhostServe 在 host memory 上对正在串流生成的 KV cache 应用纠删码，仅保留少量 parity shard，发生故障时可在数百毫秒内重建丢失的 KV cache 并继续解码。实验显示稳态开销极低、故障恢复时间相比重新 prefill 缩短一个数量级。

Key insight: GhostServe 把存储系统的纠删码思想干净地迁移到 LLM serving 的容错场景，用 host memory 而非额外 GPU/网络资源换来 KV cache 的可恢复性，是一种适合搜索/排序在线服务的 "渐进式可靠性" 工程方案。社区搜索若已上线 LLM 重排或 RAG，可参考其 "主链路零侵入 + 影子链路兜底" 的思路，把容错从重新 prefill 升级为状态级恢复，避免单卡抖动击穿请求 SLA。

2. SAGA: Workflow-Atomic Scheduling for AI Agent Inference on GPU Clusters
4.10
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 面向 Agent / 复杂 RAG 场景，论文指出现有 GPU 调度器把每次 LLM 调用当作独立请求，丢弃跨步骤累积的 KV cache 与中间状态，导致端到端延迟膨胀 3–8×。SAGA 提出 workflow-atomic 调度：把整个 agent 程序作为最小调度单元，把依赖紧密的调用共置同一个 KV/显存域，并按程序结构复用 KV cache 与 prefix。实验在真实 agent 工作负载上同时显著降低尾延迟和提升集群吞吐。

Key insight: SAGA 揭示了一个被多数推理框架忽视的事实：调度粒度从 "单次 LLM 调用" 上升到 "整段 workflow" 后，KV cache 与 prefix 复用收益会成倍放大。社区搜索的 query 改写 → 多路召回 → 重排 → 摘要生成是典型多步链路，借鉴 SAGA 的 program-level 调度，可以把意图分类和重排共享 prefix，工程上一旦在 vLLM/SGLang 之上增加 workflow group 抽象，性价比远高于单 step 微优化。

3. SpecKV: Adaptive Speculative Decoding with Compression-Aware Gamma Selection
4.00
Relevance 4 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 现有 speculative decoding 把 "投机长度 γ" 当作离线超参，且与 KV cache 压缩相互独立调参。SpecKV 系统研究 KV 压缩比与最优 γ 的强耦合关系，提出基于每步置信信号的自适应 γ 选择器，并通过 "压缩感知 draft tree" 让 draft 模型与压缩后 target 模型对齐。在长上下文解码上，相比固定 γ 的 speculative + KV 压缩朴素拼装方案，SpecKV 取得稳定吞吐增益。

Key insight: 把 speculative decoding 与 KV 压缩当作正交优化是工程上常见的误区，SpecKV 证明二者最优解是耦合的：压缩越激进，target 接受率分布越漂移，固定 γ 会导致 draft 浪费或 mis-speculation。对社区搜索 RAG/重排在线服务来说，启示是把 γ 当作运行时信号驱动的可调参数，与 KV 量化/eviction 在调度器内联合决策；这与单纯加大 draft 模型相比，对 P95 延迟更友好。

6. LEAP: Layer-wise Exit-Aware Pretraining for Efficient Transformer Inference
3.55
Relevance 3 | Novelty 4 | Practical 3 | Evidence 4 | Timely 5

Summary: 传统 layer-wise 蒸馏会把中间层表征强行对齐到教师层，恰好抹掉 early-exit 所依赖的 "逐层收敛" 信号，导致蒸馏模型上 early-exit 几乎失效。LEAP 在预训练阶段加入一个轻量辅助约束，要求中间层在保持蒸馏目标的同时逼近最终层表征，从而在不改架构的前提下让早退机制重新可用。LEAP-MiniLM 在 NVIDIA L4 上 batch=1、阈值 θ=0.95 时取得 1.61× 实测墙钟加速，91.9% 样本在第 7 层退出，理论层数缩减 1.80×。

Key insight: LEAP 的价值不在 early-exit 算法本身，而在于把 "蒸馏" 与 "早退" 这两条历史上互相打架的优化路线统一到一个可联合训练的目标里。对社区搜索的 ranking/embedding 模型来说，这意味着一个模型即可在实时检索（早退）和精排（用满层）之间动态切换，省下双模型部署成本；落地路径是在自家 ranking 蒸馏 pipeline 里加入 LEAP 形式的中间层约束。

7. KV-CoRE: Benchmarking Data-Dependent Low-Rank Compressibility of KV-Caches in LLMs
3.55
Relevance 4 | Novelty 3 | Practical 4 | Evidence 4 | Timely 2

Summary: 长上下文 LLM 服务中 KV cache 已成为显存与带宽主要消耗，但工业落地缺乏一个共同的低秩可压缩性基线。KV-CoRE 系统测量了多个主流 LLM 各层 KV cache 的数据相关秩分布，给出按层、按头的可压缩 Pareto 前沿，并比较低秩压缩、量化、eviction 在不同 prompt 分布上的相对优势。结论是低秩压缩在中后层显著优于均匀量化，但前几层应避免高压缩比。

Key insight: 对社区搜索这种 RAG + 长 query 场景，KV-CoRE 给出可直接复用的 "分层压缩 budget" 经验：浅层保留高精度、深层用低秩压缩、对超长 context 用 eviction 兜底。工程上意义是把 KV 压缩从 "全模型一刀切" 升级为 per-layer policy，结合 vLLM/SGLang 的 KV manager，可在不损害召回相关性的前提下把单 GPU 服务并发提升一档。

8. Predicting LLM Output Length via Token-Wise Probabilistic Modeling
3.55
Relevance 4 | Novelty 3 | Practical 4 | Evidence 4 | Timely 2

Summary: vLLM/SGLang 等推理框架的调度器需要预知请求大致输出长度才能合理分配 KV slot 与做 head-of-line 控制。该 ICLR 2026 工作提出 token-wise 概率长度预测器，作为推理 side channel 训练，无需改动主模型；在常见长度回归基准上 MAE 低于 10%。把预测信号接入 vLLM-like 调度器后可优先放行短输出请求，端到端吞吐提升明显。

Key insight: 调度器质量长期被低估：很多在线 LLM 服务的尾延迟瓶颈不在模型本身，而在长短请求挤在同一 batch 互相阻塞。社区搜索摘要/复述类请求长度差异巨大，把该长度预测器接入推理网关用作分桶或抢占调度，是一种几乎零侵入的吞吐优化手段，配合上文 SAGA 的 workflow 调度有协同效果。

9. Mixture of Heterogeneous Grouped Experts for Language Modeling
3.35
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 4

Summary: 标准 MoE 架构假设所有专家形状一致，参数预算粒度受限。Mixture of Heterogeneous Grouped Experts (MoHGE) 把专家划分成多组、每组使用不同参数尺寸，路由器先选组再选专家，按 token 难度匹配相应容量。实验显示在相同激活参数预算下，MoHGE 在语言建模与下游任务上优于同构 MoE 基线，对长尾困难 token 的收益尤其明显。

Key insight: MoHGE 是过去两年 "专家结构" 维度上少见的真正变化：让 MoE 路由不仅决定 "用谁"，还决定 "用多大"。对推荐/搜索领域里的多任务排序、多场景 ranking 模型同样有启发——可以把 MoHGE 的 group 思想用于排序网络，让低活跃用户/高活跃用户走不同容量分支，比 "统一 expert + 输入门控" 更自然，落地时主要难点是 grouped GEMM 的 kernel 效率。

10. TildeOpen LLM: Leveraging Curriculum Learning to Achieve Equitable Language Representation
3.25
Relevance 3 | Novelty 3 | Practical 4 | Evidence 3 | Timely 3

Summary: TildeOpen 是一个 30B 参数、覆盖 34 种欧洲语言的开源多语 LLM。论文核心是用数据上采样 + 在 "均匀语种分布" 与 "自然分布" 之间交替的课程学习策略，专门提升小语种的表征质量。在保持总参数不增加的前提下，对 Baltic、Finno-Ugric、Slavic 语种取得显著优于基线的人工评估降错率（最高 10×），并完整开源模型权重与训练配方。

Key insight: TildeOpen 的工程价值在于一份完整可复现的 "中等规模多语 LLM 训练配方"：课程调度 + 数据上采样这一对组合在中文+方言/低资源场景同样可借鉴。对社区搜索而言，多语言/方言/UGC 混合的 query 是 query 理解模型的难点，TildeOpen 提供的 "如何在不增加预算的情况下平衡主语种与小语种" 的方法论，可直接迁移到自家多场景搜索 query encoder 训练曲线设计中。
