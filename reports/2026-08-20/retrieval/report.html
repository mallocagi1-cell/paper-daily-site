Polaris: Learning to Generate Table Descriptions from Retrieval Feedback

Polaris面向NL2SQL中的表检索，解决LLM生成表描述偏重流畅性、却未必提升可检索性的问题。它从查询—表相关性标注生成多个描述，用BM25效果排序构造偏好对，再以DPO训练描述生成器，并先扩展缩写的表名和列名以缓解词汇不匹配。多个表检索基准上，Polaris通常以显著幅度超过AutoDDG。

Sparse Coverage: Semantic Center Representations for Patent Prior-Art Retrieval

AALMAnaCHLLISNQatentSSTL

Sparse Coverage针对长文本和结构化文档中单向量压缩多个技术要点的问题，把局部span向量映射到由覆盖型k-center目标选出的稀疏语义中心。文档通过激活邻近中心形成稀疏表示，既保留局部语义证据，又能复用倒排索引。CLEF-IP 2013实验显示，该方法在多种配置下达到或超过强稠密专利编码器的文档级召回，并保持有竞争力的段落级检索效果。

INSIGHTUGC短文本同样存在“一个向量覆盖多个意图”的压缩损失，例如地点、时间、品牌和服务条件同时出现时，局部证据往往比整帖向量更稳。可以先在召回层试验span级语义中心与稀疏倒排的混合索引，再用nDCG和索引成本评估是否值得替换单向量召回；它也提供了可解释的中心命中信号。

CoAL-RAG: A Complexity-Aware Legal Retrieval-Augmented Generation Method

CoAL-RAG针对不同复杂度问题使用同一检索策略会导致简单问题过度推理、复杂问题证据不足的问题。方法以问题本质和检索一致性构造复杂度信号，再比较语义检索与关键词检索的差异，动态路由检索策略并过滤上下文。在SocialLawQA、LawBench、LexGLUE和CaseHold上均有验证；中文数据集BLEU提升42.5%，ROUGE-L达到知识图谱方法的3.6倍。

INSIGHT对社区UGC搜索，可把语义召回与词法召回的不一致视为查询难度信号：实体精确匹配稳定时走低延迟路径，语义和词法分歧大时扩大候选并启用重排或改写。这个路由策略比所有请求固定调用大模型更适合控制成本，也能把“短而简单”和“长而歧义”的查询分开优化。

Jin Su, Zhuofeng Zhao, Huanhuan Wang, Hao Chen

VisDocAgentBench: Benchmarking Agents for Visually Rich Document Retrieval

VisDocAgentBench评估视觉丰富文档在静态与代理式检索下的真实排序能力，构建了100份文档、2375页和120个目标查询，覆盖直接、单桥和双桥证据结构。强晚交互视觉检索器在直接查询上Recall@1为97.50%，双桥查询仅2.50%；最佳视觉路线为67.50%，OCR文本路线为37.50%。结果还显示迭代搜索、页面检查和完整支持上下文是关键能力。

INSIGHT社区搜索中的图片、布局、评论串和引用关系不能一律压成纯文本后再检索。该基准提醒我们把“直接命中”和“需要组合证据”分桶评估，并在低置信度结果上触发迭代检查或上下文补全；线上应分别监控Recall@1、桥接查询成功率、延迟和页面解析成本。

There is No Theoretical Curse of Multilinguality For Embedding Space Structure

论文从理论上研究多语言embedding空间是否存在不可避免的容量诅咒，形式化了“完美多语言性”的两个条件，并证明满足条件所需的最小维度只随语言数量对数增长。该结果说明，跨语言检索效果下降并非embedding几何结构的必然限制，更可能来自真实数据分布、训练覆盖和优化过程。

INSIGHT如果社区平台需要处理中英混杂、方言、拼音或低资源语言查询，不能把效果下降简单归因于“语言太多导致维度不够”。工程上应优先检查语料覆盖、对齐质量、负例构造和分语言校准，并用跨语言Recall、长尾查询nDCG和零样本迁移曲线定位问题；扩维不是唯一解。

Niyati Bafna, Neha Verma, Vil\'em Zouhar, Philipp Koehn, David Yarowsky

06 3.75

Towards Safer RAG: Only Agents Capable of System 2 Thinking may Access Untrusted Documents

Towards Safer RAG聚焦检索文档被投毒后对最终回答的影响：模型可能识别出文档错误，却仍被错误内容带偏。论文在严格隔离证据和效率之间提出折中原则，只允许具备审慎推理能力的代理访问不可信文档，并设计衡量“识别错误”和“实际受影响”差异的新指标。其价值在于把检索安全从文档分类扩展到下游影响评估。

INSIGHTUGC搜索不应只做内容安全分类，还要测量恶意或低质帖子进入候选集后是否改变排序、摘要和答案。可以在重排前加入可信度分层，在高风险查询上隔离原文、要求证据核验，并记录候选曝光到最终生成的因果链；安全指标应与nDCG、CTR一起按查询类型监控。

Mehrdad Ghassabi

MITRE-SAGE: A Multi-Agent Cybersecurity Question-Answering model

MITRE-SAGE面向网络安全问答，将查询理解、证据检索和答案合成拆成多代理流程，并同时利用语义知识与结构化安全知识，缓解领域知识不足、幻觉和实体关系难建模的问题。它的核心不是简单扩大召回，而是让复杂问题在不同阶段使用不同证据结构，提升结果的可解释性和可靠性。

INSIGHT对社区搜索中的专业垂类，可把“查询解析—候选检索—证据核验—结果解释”拆成可观测阶段，而不是让一个大模型端到端决定排序。落地时应保留低延迟默认路径，只对高风险、长尾或结构化实体查询启用额外代理，并用每阶段的召回、证据覆盖和失败类型做回归测试。

Ali Habibzadeh, Farid Feyzi, Reza Ebrahimi Atani

08 3.45

Agent Lightning v1.0: Towards Harnessed Agentic RL

Agent Lightning v1.0把代理运行时的harness纳入强化学习训练闭环：部署侧harness负责工具交互和环境循环，训练器观察LLM请求—响应序列，再处理重分词、样本合并、优势计算、损失归一化和后端调度。项目将该范式与传统训练引擎主导的agentic RL区分开，并已被多个代理训练框架采用。

INSIGHT对搜索代理，检索器、工具调用和停止策略的质量最终体现在完整轨迹，而不只是单次Recall。可以借鉴其harness可观测思路，把查询改写、召回、重排、点击和终止动作统一记录，再用离线轨迹训练成本敏感的策略；但要先限制探索空间，避免线上代理为了奖励反复搜索。

Zhiyuan He, Siwei Zhang, Zhiwen Zhou, Yuqing Yang, Yu Kang

How NVIDIA scales expertise with ChatGPT Work

OpenAINVIDIA

OpenAI分享NVIDIA使用ChatGPT Work连接外部信息与内部上下文的实践：工作流每周从25–40条外部AI更新中提炼5–8个可行动信号，并在GTC筹备周期每周节省约16小时。团队还把从想法到可用原型的时间从2–3周缩短到3–5天。它更像信息筛选和工作流编排案例，而非新的检索模型。

INSIGHT对搜索团队，这个案例说明检索价值不止是返回Top-K，还包括把快速变化的外部信息压缩成可执行信号。可以将查询聚类、来源可信度、摘要和人工反馈串成可复用工作流，但必须保留原始证据链接、更新时间和人工复核入口，避免把“信号提炼”误当成事实验证。

Evaluating AI Agent Skill Performance with NVIDIA SkillEvaluator

NVIDIA

NVIDIA SkillEvaluator工程文章强调，代理效果受上下文质量影响，即使模型能力和工具文档充分，代理仍可能花费额外步骤寻找所需信息。该实践把技能执行、上下文获取和结果质量放进统一评测视角，适合作为检索代理的补充工程信号；当前RSS摘要未给出可复核的离线指标或线上A/B数字。

INSIGHT检索系统应把“找到信息用了几步、花了多少token、是否重复搜索”纳入质量看板，而不是只看最终答案是否正确。对UGC场景可按查询难度统计首轮命中、补搜次数、上下文利用率和延迟，并用轨迹回放定位是召回不足、重排失误还是代理策略不稳定。
