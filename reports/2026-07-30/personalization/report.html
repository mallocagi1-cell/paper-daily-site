Memory Layer: Train the In-Model Cache for Recommendation Models

针对推荐早排中训练与服务使用不同物品表示的问题，论文把键值缓存做成可联合训练的 Memory Layer，使物品塔训练时写入、线上直接读取。Instagram Reels 部署后，预测覆盖率从 96% 升至 100%，新内容召回超过 2 倍，冷启动互动提升 5%–6%，训练发布成本下降 30%。

1. 问题与动机

这篇论文处理的不是一个单纯的模型精度问题，而是大规模推荐早排（Early-Stage Ranking, ESR）长期存在的训练—服务结构错位。Instagram Reels 的早排需要在双位数毫秒延迟内为每次请求约 \(O(1K)\) 个候选打分，因此通常先离线运行物品塔，把向量放入服务侧缓存；训练时却始终使用当前物品塔刚算出的新向量。作者把错位拆成三类：物品塔参数与缓存新鲜度不同、训练 Scribe 与候选池 Hive 表的特征来源不同、训练从不遇到缓存未命中而线上必须回退。实测这些差异使多个互动任务的训练与服务 Normalized Entropy（NE）相差 5%–12%，传统缓存总体预测覆盖率只有 96%，新发布 15 分钟内内容的命中率甚至只有 10%–20%。这正是新 UGC 冷启动的关键失败模式：模型可能知道新内容值得分发，但向量尚未进入缓存，早排直接给负分或跳过。

作者的核心判断是：缓存若只存在于服务系统，任何额外同步任务都只能缓解而不能消除错位；要解决问题，必须把缓存变成模型本身的可训练状态，让训练写入的向量就是服务读取的向量。该工作延续两塔召回、SilverTorch 内嵌缓存、TorchRec/FBGEMM 稀疏表等工业技术，但进一步把“只读服务制品”改造成训练和推理共享的单一事实源。

2. 方法详解

Memory Layer \(M\) 是以物品 ID 为键、以物品塔稠密向量为值的稀疏键值表。底层采用 Multi-Probe Zero-Collision Hashing（MPZCH）：身份张量把原始 ID 无碰撞地映射到行号，512 维向量表跨 GPU/CPU 分片存储，运行时元数据与向量共用行索引；容量有界，使用 LRU 淘汰。训练时物品塔 \(f_{\text{item}}\) 先产生目标向量 \(e_i\)，模型再从 \(M[i]\) 读出缓存向量 \(\hat e_i\)，排序损失实际使用缓存表示，因此训练看到的输入与线上一致。

作者比较了两种缓存学习方式。普通方式最小化 \(\|M[i]-\mathrm{sg}(e_i)\|_2^2\)，但需要调损失权重且渐进更新仍会短暂滞后。最终采用 Writeback：构造梯度 \(g_i^{wb}=\hat e_i-e_i\)，复用 TorchRec TBE 的 EXACT_SGD，令学习率 \(\eta=1\)，一次更新便得到 \(M[i]\leftarrow \hat e_i-(\hat e_i-e_i)=e_i\)。Writeback 梯度只更新缓存表，排名损失独立更新物品塔与其余参数，既实现精确赋值，又不需要新的 CUDA 内核或额外优化器状态；同一批次重复 ID 先去重，保证每行只执行一次精确写入。

缓存未命中由 Always-On Embeddings 兜底。大部分物品特征仍进入物品塔并被缓存；少量对新内容也有泛化能力的特征，如作者 ID、主题 ID 或内容理解特征，在线实时提取。命中时模型融合缓存向量与 always-on 向量，未命中时把缓存分支置零，只保留作者等通用信号，使所有候选都有可学习的分数，而不是固定负分。论文当前部署具体使用 always-on 作者 ID，命中后再加入媒体 ID 与 MPZCH 向量。

为覆盖没有自然互动日志的候选，Multi-Table Training 每步并行读取带标签的训练批次和无标签候选池批次，在 GPU 预处理阶段合并物品特征、只运行一次物品塔并统一 Writeback；排名损失只对训练批次计算，候选池批次只负责填充缓存。Raw Embedding Streaming（RES）则把新向量传播到预测器：每步利用 TBE 预取期间向量已在 HBM 的机会异步拷到 CPU，后台按 ID 去重、量化并合并分片，每 15 秒把向量、身份映射和元数据原子推送，P99 端到端传播约 21 秒且不阻塞 GPU 训练。

实验使用 Instagram Reels 的在线训练两塔早排，与 SilverTorch 缓存基线比较；共享表容量在中性服务算力下扩大 50%。论文明确给出在线数据源、表结构、流式间隔和服务架构，但没有披露训练批大小、优化器（排名模型部分）、学习率、GPU 型号或训练步数，这限制了外部团队对训练资源的精确复刻。MPZCH、Writeback 与 RES 的基础组件已通过 TorchRec/FBGEMM 开源，模型集成代码与内部数据未开放。

3. 核心技术贡献

第一，论文把训练—服务一致性从“同步流程治理”变成“模型结构保证”。同一 MPZCH 表在训练可写、在服务可读，消除了小时级锚点模型、Hive 回填和独立批量评估造成的表示分叉；pselect 的训练—服务 NE 差距由 12.11% 降至 1.64%，缩小 86%，reshare 差距由 5.24% 降至 3.42%，缩小 35%。

第二，Writeback 用 \(\eta=1\) 的稀疏 SGD 把反向传播基础设施复用为精确赋值算子。它比额外的 \(L_2\) 对齐损失更容易运维，因为没有损失权重、动量或收敛速度需要调节，同时保留分布式 TBE 的 all-to-all 路径。

第三，Always-On Embeddings 与多表训练把“缓存命中”从质量前提降为加分项。MPZCH 自身达到 99.5% 命中，剩余 0.5% 仍由作者 ID 等信号打分，最终预测覆盖率从 96% 提升到 100%；候选池无标签物品也能在训练循环中刷新，而不再依赖独立批处理集群。

第四，RES 把训练更新、缓存发布和模型发布收敛为一条链路。向量新鲜度从约 5 分钟改善到约 20 秒，训练与发布计算成本下降 30%，循环发布吞吐提高 3 倍；经过服务端优化后端到端吞吐提高 2.42 倍，使扩大缓存容量后仍保持与基线相同的服务算力。

一个值得注意的评测现象是：覆盖率从 96% 到 100% 后，实验组会额外打分原本被绕过的约 4% 新内容，处理组与对照组的内容分布不再完全相同；冷内容即时互动通常低，短周期 A/B 可能低估长期供给价值。作者因此结合相同媒体集合的受控服务评测与更长实验，而不是只看短期总体 CTR。这一处理对任何“提高新 UGC 覆盖”的实验都很重要。

5. 局限与未来方向

作者明确列出三类局限。其一，Writeback 仍是 write-behind：物品上次出现在训练步 \(t\) 时写入的是参数 \(\theta_t\) 生成的向量，服务到 \(t+k\) 时模型参数已更新，稀有物品仍会滞后；多表训练只能限制 \(k\)，不能达到逐请求运行物品塔的绝对实时。其二，训练时物品塔总能产生向量，因此缓存未命中的全零分支没有显式进入损失，模型只通过“新内容缓存信号较弱”间接学会融合；作者计划在训练中模拟未命中掩码、增加物品无关特征，并借鉴缺失模态鲁棒融合。其三，评测仅覆盖 Instagram Reels 一个内部生产面，数据、完整代码与基础设施不可公开，外部无法做精确复现或跨系统对比。

训练—服务差距也没有归零，残余来自服务端 int8 行量化、write-behind 读取和显式未命中分布与训练分布不同。作者未充分讨论的风险包括：LRU 淘汰可能进一步偏向高频内容；作者 ID 兜底会把创作者历史强势程度带入新内容冷启动，可能放大头部偏差；扩容 50% 与结构改造同时发生，使缓存容量对收益的独立贡献难以精确识别。

6. 工业实践意义

对社区搜索与推荐，最可迁移的设计是把“索引/缓存新鲜度”当作模型正确性的一部分，而不是独立数据工程 SLA。可先审计训练与线上使用的物品向量是否来自同一特征版本、同一物品塔和同一更新时间，再考虑模型扩容。若新帖子、评论或视频常在入库数分钟内错过首轮分发，可用可写稀疏表保存训练产生的内容向量，并用作者、主题、文本类别等 always-on 特征为未命中候选提供可学习兜底。

落地时不必一次复制 Meta 全套基础设施。最小试点可包含四项：共享缓存表、精确 Writeback、训练期缓存读回评测、未命中掩码与通用特征兜底；随后再加入候选池无标签灌入和秒级流式传播。验收指标除了 nDCG/CTR，还应包含缓存覆盖率、向量 Time-to-Serve、训练—服务 NE/AUC 差距、新内容首次曝光时间、5 分钟与 1 小时分桶召回、发布计算成本。论文证明这类模型—系统协同能在中性服务成本下同时提高质量、可靠性和冷启动，但内部数据不可复现，外部团队应通过逐组件灰度和相同候选集合的受控 A/B 确认因果。

NEXT: Reasoning-Driven Video Recommendation via a Vision-Language Model

Meta📖 有深读 · 11 分钟

NEXT 将视频推荐改写为 Item-to-Intent-to-Item：8B 视觉语言模型先理解刚看内容并推断下一意图，再生成查询检索具体视频。三阶段训练包含感知强化学习、分布对齐 SFT 与 GRPO；上线新增召回通路后，观看时长提升 0.53%，不同视频曝光提升 0.51%。

INSIGHT相比仅依赖共现或语义相似，显式生成“下一步想做什么”可补足剧集续看、教程进阶等有方向性的需求。社区 UGC 可把帖子内容转成可检索意图，再复用现有召回索引；8B 模型只承担意图推理而非全库打分，能控制在线成本并提升内容多样性。

1. 问题与动机

短视频推荐擅长从共看、点击和语义相似中拟合“用户可能还会看什么”，却不一定理解“看完这个以后逻辑上应该看什么”。论文列出三种直接影响体验的失败：流行度偏置使热门相似视频压过真正续集，推荐多样性下降，以及叙事连续性断裂，例如用户看完 Part 1 却收不到 Part 2，或看完谜题、实验、教程后得不到答案与后续步骤。传统 Item-to-Item 图通常近似对称，无法表达 A→B 的方向和因果式后续需求；纯生成推荐又难以承担全库检索和在线延迟。

NEXT 的动机是把推荐问题拆为“理解下一意图”和“在现有搜索栈中找到满足意图的内容”。模型不直接对全库逐项打分，而是将已观看视频转换成一个可检索的下一意图，再对搜索结果做逻辑验证，形成有方向的 NEXT Knowledge Graph（NKG）边。这样既利用视觉语言模型对 OCR、ASR、画面与事件关系的推理能力，又保留成熟搜索系统的规模化召回。论文进一步指出，离线 Precision/Recall/NDCG 会惩罚历史日志中没有出现但逻辑合理的新探索，因此最终必须依赖线上 A/B 验证。

2. 方法详解

NKG 中每条边是 \(\langle v_{\text{trigger}},v_{\text{next}}\rangle\)，只有多模态证据、用户行为信号和 NEXT-8B 验证共同支持“B 是 A 的合理后续”时才写入。候选来源有四类：显式续集、VLM 意图搜索、行为信号和方向性 Swing；这些来源只提出边，不直接决定最终排序。显式路径从 OCR、ASR、创作者元数据和 “part two”“to be continued” 等线索提取置信度，按 \(S_{\text{series}}=w_{\text{ocr}}C_{\text{ocr}}+w_{\text{asr}}C_{\text{asr}}\) 融合，超过阈值便优先写入 \(V_{\text{part}n}\rightarrow V_{\text{part}n+1}\)。

隐式路径让 NEXT-8B 根据采样帧、OCR、ASR、实体、布局和场景证据生成紧凑查询，例如谜题答案、挑战结果、被提及实体的详情或未完故事的后续；查询进入既有视频搜索栈，模型随后比较触发证据、意图与候选，只保留能“回答、延续或解决”需求的候选，拒绝仅主题相似或视觉接近的内容。行为路径使用 Watch→Search、Watch→Creator Profile→Watch、Watch→Comment 等短时间窗高置信模式，把搜索词或“part 2?”评论变成检索支点。

协同路径使用 Scene-Aware Reasoning Swing。它要求用户在会话窗口内先看 \(i\) 再看 \(j\)，候选共享 Semantic ID 前缀，并过滤低支持对；最终分数对有序共现用户对求和，以用户活跃度权重抑制重度用户，以时间衰减 \(\gamma^{|\Delta t|}\) 惩罚不一致转移，再由 NEXT-8B 验证。因此协同信号提供覆盖，VLM 保证方向和逻辑精度。

NEXT-8B 是标准 8B 视觉语言架构，创新集中在三阶段后训练。第一阶段 Perception-Enhanced RL 让多模态策略 \(\pi_\theta\) 生成与问题无关的视觉证据 \(e\)，冻结的纯文本验证器 \(\phi\) 看不到原图，只依据 \(e\) 回答多个问题，平均正确率成为奖励；每个样本采样 \(K\) 个证据，使用组内相对优势的 GRPO，并加裁剪与相对参考策略的 KL 正则。这样奖励改善只能来自更准确的 OCR、实体、空间关系与场景证据，而不是验证器偷看图片。

第二阶段 Distribution-Aligned SFT 混合 ChartQA、TableVQA、InfoVQA 等真实 DocVQA 数据与大 VLM 教师、多专家一致标注生成的稀有布局合成数据。自由问答有多个合法字符串时，从标签集合中选择与当前预测 Levenshtein 相似度最高的目标，降低格式差异对 ANLS 的干扰。第三阶段再次用 GRPO 做末端偏好对齐，奖励简洁格式、证据忠实性和“观察事实/推断意图”边界。

论文披露 DocVQA 含 12,767 张图像、超过 50,000 个问题，任务评测用 ANLS；推荐迁移评测采样 1,000 个视频。生产 A/B 运行数周、规模约 1 亿用户。论文未报告训练 batch size、优化器超参数、学习率、GPU 数量、训练步数、帧采样率或合成数据规模，因此读者能重建算法流程，却不能严格复现训练预算与数据配方。

3. 核心技术贡献

第一，NEXT 用 Item-to-Intent-to-Item 代替直接 Item-to-Item 相似匹配。显式下一意图把搜索作为生成模型与推荐系统之间的接口，使 VLM 负责“小而难”的推理与验证，搜索负责“大而快”的全库召回，避免让 8B 模型在线扫描候选库。

第二，NKG 是精度优先的有向知识图，而不是无约束共现图。显式续集、行为支点、方向 Swing 和多模态意图统一进入验证阶段，写入时保留来源、逻辑分与新鲜度；线上只需查图并插入，使昂贵推理移出请求关键路径。

第三，Perception-Enhanced RL 用冻结文本模型隔离视觉证据质量。验证器只能看到模型生成的证据，因此 8B VLM 必须学会保留小字、表格、人物和事件线索。完整训练把 DocVQA ANLS 从基座 96.10 提到 97.28，超过 235B MoE 的 Qwen3-VL 97.25，模型规模接近小 30 倍。

第四，论文给出从静态视觉基准、推荐边逻辑评测到线上指标的三级证据链。模型在 1,000 视频盲评中，高质量逻辑输出相对提升 3.3%，证据落地提升 4.0%，A→B 匹配提升 3.5%；真实系统最终取得观看时长 +0.53% 和不同视频曝光 +0.51%。

5. 局限与未来方向

作者明确指出，全库视频的 8B VLM 分析仍然昂贵。即使放到离线/近线，内容库快速增长时，转移挖掘吞吐仍是瓶颈；未来计划通过蒸馏、推测解码和更激进批处理提高新内容响应速度。当前只做单跳 \(v_1\rightarrow v_{1.a}\)，作者希望扩展多步转移；边离线生成、线上只在小集合内个性化，未来需把实时行为更紧密地纳入边质量优化。连续沿一条逻辑链推荐还可能收窄曝光，因此需要把 NEXT 与惊喜性候选交错重排。

论文没有把 LLM-as-a-judge 与人工评审相关性作为核心实验，1,000 视频评测也可能受评审模型偏好影响；线上增益虽然显著，却没有公布平台、国家、内容类型和用户分层。另一个未充分讨论的问题是“直接插入”对 feed 排序校准的影响：高精度 NKG 候选绕过完整候选竞争，若正反馈触发阈值或边新鲜度失准，可能造成过强的连播偏置。Semantic ID 前缀约束也可能错过跨主题但逻辑相关的后续内容。

6. 工业实践意义

NEXT 最适合以增量召回通路试点，而不是替换现有推荐系统。社区 UGC 可先挑三类高价值场景：系列帖/教程续篇、问题—答案与事件后续、用户看帖后立即搜索或访问作者主页。离线从标题、正文、图片 OCR、视频 ASR 与评论中提取证据，生成“下一步需求”查询，复用现有搜索召回，再由较小多模态模型验证是否真正回答或延续触发内容；把通过验证的边存入带来源、分数、时间戳和过期策略的有向图。

在线链路应保持极轻：检测完播、收藏、点赞等强正反馈，查询图；只有一条高置信边时插入，多条时复用现有个性化排序器，不新增专用在线 VLM。工程预算主要花在离线吞吐、边更新、证据审计和新鲜度，而不是请求延迟。验收除观看时长、CTR 外，还应看 distinct exposure、续集满足率、搜索后回流、负反馈、安全与延迟；同时做边来源分桶消融，防止无法归因。

对社区搜索业务，最值得借鉴的是“意图生成先于检索”。相比让大模型直接重排数千候选，先把未满足的信息缺口压成短查询，再交给现有索引，成本与可观测性都更好。上线时必须保留多样性配额和传统探索流量，避免有向链把用户困在单一叙事；对于新闻、健康等时效或风险内容，还应在 NKG 写入前增加事实、安全和过期检查。
