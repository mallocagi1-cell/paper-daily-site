1. Policy-Grounded Dynamic Facet Suggestions for Job Search
4.65
Relevance 5 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: 针对 LinkedIn 上超过 80% 的求职 query 仅含 3 个以内关键词、意图严重欠定义的问题，提出动态分面建议 (Dynamic Facet Suggestion, DFS)：在用户与 query 的联合上下文下实时推荐个性化语义属性，引导用户交互式澄清意图。框架是 policy-grounded、retrieval-augmented 的排序流水线，含离线 taxonomy 构建、embedding 召回 top-K 候选、蒸馏小模型 (SLM) 打分三段。线上服务用 pointwise 单 token 打分 + batching + prefix caching 实现实时延迟。离线评测显示分面相关性与意图覆盖显著优于基线。

Key insight: 短 query 意图澄清是社区/UGC 搜索的共性痛点，本文给出可落地范式：用 taxonomy 约束生成空间 (policy-grounded) 避免 LLM 自由发散，embedding 召回收窄候选，再用蒸馏 SLM 做单 token pointwise 打分压低延迟。社区搜索可借鉴这套「离线知识库 + 召回 + 小模型重排」三段式做查询补全/相关搜索词，prefix caching + batching 的工程手法对高 QPS 场景直接可用。

2. Improving BM25 Code Retrieval Under Fixed Generic Tokenization: Adaptive q-Log Odds as a Drop-In BM25 Fix
4.35
Relevance 4 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: 在分词器不可控 (frozen generic tokenization) 的检索系统里，BM25 的 log-RSJ-odds IDF 对区分函数名的「标识符长尾」分辨力不足，导致 RAG 编码场景相关文件频繁缺失。本文把 RSJ odds 外层的对数换成 q-对数：q=1 时由洛必达法则精确退化为标准 BM25，q<1 时等价于对 RSJ odds 做 λ=1−q 的 Box-Cox 变换。在 CoIR CodeSearchNet Go (182K 文档) 上，oracle 调参 NDCG@10 从 0.2575 提升到 0.4874 (绝对 +0.2299，相对 +89.3%；10000 次配对 bootstrap 零符号反转，p≤1e-4)，效果随 q 单调可控。

Key insight: 这是一个不需重训、不需改分词器的 drop-in 稀疏检索改进，对依赖既有 BM25 索引的社区短文本召回极具落地价值。核心洞察是标准 BM25 的对数 IDF 压扁了高区分度低频词 (UGC 中的实体名、口语词同理)，用 q-对数单参数即可重新拉开长尾词权重，且 q=1 可平滑回退保证安全上线。建议在短文本召回链路灰度一个 q 参数做 A/B，成本几乎为零。

3. IVF-TQ: Streaming-Robust Approximate Nearest Neighbor Search via a Codebook-Free Residual Layer
4.10
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 提出 IVF-TQ：在 IVF 索引上加一层无码本残差量化——固定随机旋转 + 仅依赖 (b,d) 的预计算 Lloyd-Max 标量量化，只训练 IVF 粗划分。基于 TurboQuant，针对训练码本类索引 (PQ/OPQ/ScaNN) 在流式写入下的 staleness 失效模式。实验 (3 seeds)：逐 batch 重训 PQ 在任何 bit 预算下都补不回流式差距 (paired-t p>0.28)；streaming Deep-10M 上 IVF-TQ 召回从 87.4% 仅降到 86.6% (Δ=−0.80pp)，而 IVF-PQ 降 −3.23pp；SIFT-1M 的 shuffled-iid 对照证实 PQ 的退化来自码本陈旧而非分布漂移。高 bit 预算 (约 1.5× 内存) 下 PQ 绝对召回更优，符合率失真预期。

Key insight: 社区 UGC 语料持续高速写入，向量召回索引最怕「码本随分布漂移而陈旧」。本文给出明确量化证据：训练码本类索引在流式场景天然劣化，而无码本残差量化用一次性随机旋转 + 标量量化换来流式稳定性，代价是同内存下绝对召回略低。对帖子/评论这类时效性强、增量大的语料，IVF-TQ 思路 (免码本训练、免逐 batch 重建) 能显著降低索引运维成本，值得在新内容召回链路评估。

arXiv2026-05-19Tarun Sharma
4. PIPER: Content-Based Table Search via profiling and LLM-Generated Pseudoqueries
3.70
Relevance 3 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 面向数据湖/开放数据门户中元数据缺失或低质的表格数据集检索，提出 PIPER：先对表格做 profile (schema + cell value 统计画像)，再用 LLM 为每张表生成伪查询 (pseudoqueries)，将伪查询嵌入用于 dense retrieval 的 ranking。区别于以往 LLM 表检索聚焦 Table QA (选一张表答问)，PIPER 面向检索并排序相关数据集。在弱元数据设定下，PIPER 同时优于纯元数据基线与已有 LLM 表检索方法。

Key insight: 「为内容生成伪查询再做 dense 召回」是应对元数据稀疏的通用招式，对社区 UGC 同样适用：很多帖子标题/标签信息量低，可离线用 LLM 为正文生成若干代表性 query 写入向量库，使召回侧能匹配用户多样化表达。表格 profile 的思路也提示：把结构化统计 (高频词、实体分布) 作为补充画像并入文档表示，可缓解短文本语义稀疏。

5. TIGER-FG: Text-Guided Implicit Fine-Grained Grounding for E-commerce Retrieval
3.45
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 电商图搜常以裁剪图为 query，候选则是整图 + 结构化文本，存在模态差 (视觉 query 匹配图文 item) 与粒度差 (裁剪图 vs 含背景干扰的整图) 两类不对称。检测式流水线靠显式定位处理粒度差但有额外开销与误差传播，CLIP 式编码器免检测却易被背景/无关物干扰。TIGER-FG 提出文本引导的隐式细粒度 grounding：用 item 文本作为语义引导，在不显式做目标检测的情况下隐式聚焦 query 相关区域，缓解两类不对称。

Key insight: 「用文本作为弱监督隐式引导视觉聚焦」避免了检测流水线的工程复杂度与误差累积，对图文混合 UGC 搜索 (社区帖子常含图) 有借鉴意义：当 item 侧有文本/标签时，可让文本指导多模态编码器抑制背景噪声，无需单独训练检测模块。对资源受限的社区搜索，免检测的隐式 grounding 是更轻量的多模态相关性方案。

6. Text-Video Retrieval With Global-Local Contrastive Consistency Learning
3.45
Relevance 3 | Novelty 3 | Practical 4 | Evidence 3 | Timely 5

Summary: 文本-视频检索中视频内容比文本更丰富，文本-视频对常只是部分相关。主流方法用语言-视频 attention 模块做细粒度对齐，效果好但带来巨大计算开销、检索效率低。本文提出 Global-Local Contrastive Consistency Learning (GLCCL)：通过全局与局部表示间的对比一致性约束实现对齐，无需逐对跨模态 attention，在保持相关性的同时大幅降低检索时计算量。

Key insight: 对社区视频/图文搜索，关键工程权衡是「细粒度跨模态 attention 的效果」vs「双塔式表示的检索效率」。GLCCL 的思路是把局部对齐信息蒸馏进可独立编码的全局/局部表示，用对比一致性替代在线 attention，从而保留双塔的离线建库 + 高效召回特性。这是高 QPS 检索系统在多模态相关性上常用的折中模板，值得在视频/图文召回侧评估。

arXiv2026-05-19Xiaolun Jing, Xinxing Yang, Genke Yang
7. LARGER: Lexically Anchored Repository Graph Exploration and Retrieval
3.45
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 仓库级编码 agent 必须先定位与任务相关的文件与符号，定位失败会级联污染补丁生成、测试编写、代码问答等下游目标。现有 agent 主要靠词法搜索导航，漏掉 import、调用链、类型层级、代码-测试链等结构关系；图检索能补回这些依赖但通常需要独立的图工具或遍历阶段，割裂 agent 交互回路。本文将仓库上下文定位形式化为 Lexically Anchored Structural Localization：把词法命中转成高精度的结构入口点，并暴露经置信度过滤的局部邻域，统一在一次检索调用内完成。

Key insight: 「词法锚点 + 结构图邻域」的混合检索范式对带结构的 UGC (问答的回答树、评论楼层、话题图谱) 有迁移价值：先用词法/向量召回锚点，再沿结构边扩展置信度过滤的邻域，比纯文本召回能补全上下文。把图扩展内联进单次检索调用、而非外挂遍历阶段，对延迟敏感的线上检索是更工程友好的设计选择。

8. Vector RAG vs LLM-Compiled Wiki: A Preregistered Comparison on a Small Multi-Domain Research Corpus
3.30
Relevance 3 | Novelty 3 | Practical 3 | Evidence 4 | Timely 5

Summary: 预注册对比两种让 LLM 回答小型语料问题的方式：单轮 Vector RAG vs LLM 预编译的 markdown wiki。同一生成模型在 24 篇论文上回答相同 13 个问题，由盲评 LLM 裁判打分。结论：wiki 在跨文档串联发现上明显更好，但答案组织优势经裁判校正后不显著；Vector RAG 在单事实查找上通过了预注册检验。查询侧成本意外反转——wiki 查询 token 远多于 RAG，无法靠更便宜的查询摊薄前期构建成本。claim 级引用核查的探索性分析进一步改变了对结果的解读。

Key insight: 对「是否要把语料预编译成结构化知识 (wiki/图谱) 再给 LLM」给出实证权衡：单事实召回 Vector RAG 足够且查询成本更低，跨文档综合才值得预编译，但预编译并不必然降低查询期成本。社区搜索若考虑用 LLM 预生成 FAQ/聚合页提升综合性问答，需用预注册式 A/B 量化构建成本与查询成本的真实账，而非默认「预编译更省」。

9. Trustworthiness in Retrieval-Augmented Generation Systems: A Survey
3.00
Relevance 3 | Novelty 2 | Practical 4 | Evidence 3 | Timely 3

Summary: 现有 RAG 研究多聚焦准确率与效率，对可信性 (trustworthiness) 探讨不足：不可靠检索或不当知识利用仍会导致不良输出。本文提出统一框架 Trust-RAG Compass，沿多个可信性维度系统评估 RAG 系统，综述各维度的现有方法与评测，并指出开放问题。属于综述 + 评估框架而非新方法。

Key insight: 当社区搜索引入 RAG 式问答/AI 摘要时，检索质量直接决定幻觉率与可信度。本文的价值是提供一份可信性维度清单与评估框架，可作为上线 RAG 答案前的 checklist：覆盖检索可靠性、知识利用正确性、可溯源/引用核查等。对实践者更像「质量门禁模板」而非算法创新，适合用于建立社区 AI 答案的评测体系。

10. Long Context Modeling with Ranked Memory-Augmented Retrieval
3.00
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 3

Summary: 面向长上下文的长期记忆管理，提出 Enhanced Ranked Memory Augmented Retrieval (ERMAR)：对记忆条目按相关性动态排序，引入新的相关性打分机制 + 针对 KV embedding 的 pointwise 重排模型，思路借鉴信息检索中的 learning-to-rank；结合历史使用模式与自适应检索，在标准长上下文 benchmark 上取得 SOTA。
