A Survey on Generative Recommendation: Data, Model, and Tasks

本文系统性梳理生成式推荐（Generative Recommendation, GR）范式，提出 Data-Model-Task 三维统一框架：在 Data 维度讨论 ID 形式（atomic ID、semantic ID、LLM token、向量量化 token）的设计哲学；在 Model 维度区分 LLM 驱动、扩散驱动、自回归 Transformer（HSTU/TIGER/SIGMA 系列）等不同实现路径；在 Task 维度覆盖召回、排序、序列推荐、多模态、对话式推荐与跨域推荐。综述汇总了 200+ 篇近三年代表工作，并指出 scaling law、可控生成、推理能力、低延迟 serving 等核心开放问题。

1. 问题与动机

推荐系统在过去十余年经历两次范式更迭：协同过滤/矩阵分解（机器学习时代）→ 深度神经网络（深度学习时代）。这两次更迭都共享同一个底层假设——把推荐建模为对固定候选集的判别式打分 (discriminative scoring)：学习评分函数 f(u,i)，再做 ranking。本文指出，这一假设正被新的浪潮打破：随着 LLM 和扩散模型的崛起，推荐被重新定义为'生成任务'，而不是'打分任务'。然而当前的工作呈碎片化状态——有的偏向用 LLM 直接做 token-level 推荐，有的偏向把 item ID 量化成 Semantic ID 进行自回归生成，有的偏向用扩散模型重构序列推荐，研究者很难判断这些路线的本质异同与适用边界。论文动机即是给生成式推荐这一新范式提供首份系统化分类。文中给出的核心数据是：判别式模型在大约 200B 参数量上停滞，而 Meta HSTU 在生成式架构下被推到 1.5T 量级仍持续受益（验证 scaling law）；Kuaishou OneRec 已在线上拿到 +1.68% 总观看时长，且推理成本仅是级联架构的 10.6%——这两个工业数据点是'判别式架构正在被取代'的最强论据，也是论文的现实动机。

2. 方法详解

综述提出 Data–Model–Task 三维统一框架来组织生成式推荐研究。

Data 维度（Section 3）：研究生成模型如何重塑'数据'本身，包含四类工作：(a) 内容增强 (ONCE, LLM-Rec, LRD, MSIT)，让 LLM 为 item 生成更丰富的自然语言描述；(b) 行为增强 (ColdLLM, LLM-FairRec)，针对冷启动和公平性生成虚拟交互序列；(c) 结构增强 (SBR, CORONA, LLM-KERec)，让 LLM 抽取物品-属性图谱；(d) 基于 Agent 的模拟 (Agent4Rec, AgentCF, STEAM)，用 LLM agent 当虚拟用户，用 multi-agent rollouts 生成可控的训练数据。

Model 维度（Section 4） 是综述的主体，区分三条技术路线：

  • LLM-Based：把 LLM 当主推理器。代表工作 TALLRec / LlamaRec / CoRAL / CLLM4Rec 用 prompt + 微调把推荐转成 next-token-prediction；TIGER 进一步引入 RQ-VAE 把 item 量化成层次化 Semantic ID，再用 T5 类 seq2seq 做自回归召回。
  • Large Recommendation Models：原生为推荐设计的大规模 Transformer。HSTU (Meta) 在自家流场景验证 scaling law，参数推到 1.5T；MTGR (Meituan) 引入 Group LayerNorm + 动态混合 mask 把交叉特征喂进生成式排序；OneRec/OneSug (Kuaishou) 用端到端生成替代召回-排序级联。
  • Diffusion-Based：DiffRec / DreamRec / DiffRIS / DDSR 把序列推荐建模为去噪生成过程，把噪声 → 用户兴趣或 next-item embedding。

Task 维度（Section 5）：研究 task-level 的新形态——会话式推荐（用 LLM 做多轮 dialogue，对 free-form 表达进行兴趣消歧）、可解释推荐（自然语言理由）、跨域推荐、可控推荐（用 prompt 控制生成偏置）。

配套训练栈也被讨论：包含 RLHF / RLVR / DPO 风格的偏好对齐，以及 SFT + Continued Pretraining 在 Semantic ID 上的训练流程。推理侧重点提及 AtSpeed 用 speculative decoding 实现 2.2–2.5× 加速。

3. 核心技术贡献

(1) 三维统一框架：把 Data / Model / Task 三个维度作为正交分类轴，避免现有综述按时间或单一方法分类时出现的重复与遗漏。例如 Agent4Rec 既属于 Data（生成训练数据）又能视为 Task（用户模拟），三维框架明确把它归到 Data 但提示了横向引用——这种归类对工程团队选型有清晰指导。

(2) 将 Semantic ID 与 LLM token 视为两种 item 表示哲学：综述明确指出 TIGER 系（Semantic ID + 自回归 seq2seq）与 TALLRec 系（直接 LLM token + 微调）在工程上的本质差异——前者推理快、词表小、易冷启动；后者天然能融入 prompt 信号但 vocabulary 爆炸。这对实际选型很关键。

(3) scaling law 验证：引用 HSTU 的 1.5T 与判别式 200B 停滞的对照，确立'生成式范式才能持续 scale'这一论点，为整个范式的存在合法性提供工业证据。

(4) task-level 创新分类：把会话推荐、可解释推荐、跨域、可控生成视为生成式范式独占的应用形态，相当于划定了'判别式做不到、必须靠生成'的最小价值边界。

4. 实验结果分析

作为综述，本文不做新模型实验，但对关键工业数据做了横向对比：

关键观察：(a) Meta、Kuaishou、Meituan 三家用三种不同的生成式架构都拿到了线上正向，说明范式收益是结构性的，不是某个 trick；(b) OneRec 的 10.6% 成本是颠覆性的——传统级联架构 vs. 端到端生成不仅效果更好，成本反而更低，这与一般人的直觉相反；(c) AtSpeed 的 speculative decoding 移植到推荐 serving 是一个被低估的工程方向，因为推荐输出长度短、batch 大，speculative 收益可能比通用 LLM 还高。

失败模式被简要提及：扩散类方法 (DiffRec 系) 在显式反馈数据集表现好，在稀疏的隐式反馈数据上仍弱于 LLM-based；冷启动场景下 Agent4Rec 类生成数据有 distribution mismatch 风险。

5. 局限与未来方向

作者明确列出三大开放挑战：

Data 层面：(1) 用 LLM 合成的训练数据存在分布偏置，长期 self-training 会导致 model collapse；(2) Semantic ID 的语义一致性如何与新增 item 持续对齐仍是开放问题；(3) 多模态生成数据的对齐（文本/图/音频）尚缺成熟方案。

Model 层面：(1) 鲁棒性——生成式架构对噪声 token、长尾 item 更敏感；(2) 效率——大模型推理延迟仍是 serving 瓶颈，speculative decoding 等加速方法刚刚起步；(3) 泛化性——跨域、跨场景的 transfer 能力没有充分验证。

Deployment 层面：(1) latency / scalability——端到端生成在 P99 上的稳定性仍需打磨；(2) 与传统判别式系统的混合部署策略缺乏 best practice；(3) AB 测试方法论需要重新设计，因为生成式系统的输出空间不再是固定候选集。

作者未提及的局限（评论者补充）：生成式推荐对'公平性 / 多样性 / 可解释性合规'的影响缺乏系统评估，这在国内监管环境下是个不能忽视的工程点。

6. 工业实践意义

对搜索/推荐团队的具体启示：

应该尽快做的事：(1) 为站内 item（UGC 帖子、商品、视频）建立 Semantic ID 体系（RQ-VAE 或 RQ-KMeans 量化），这是几乎所有生成式路线的共同底座，先把 ID 建好相当于占领高地；(2) 把 LLM-as-data-generator 当作冷启动和长尾增强的常规工具（参考 ColdLLM），ROI 高、风险低；(3) 在小流量场景试 TIGER 风格的端到端召回，对比当前 HNSW + DSSM 的两阶段架构。

应该试的事：HSTU 风格的大尺度生成式排序——参数 100M–1B 量级即可见效，不必直接奔 1T。Meituan MTGR 表明在'交叉特征 + 自回归生成'的组合下，判别式 DIN/SIM 系是可以被替代的，且 scaling 路径更通畅。

应该警惕的事：(1) 直接把 LLM 当推理器（TALLRec 系）在大流量短延迟场景仍很难落地，延迟与成本是硬约束；(2) Agent-based simulator 用作离线评估时要严防 distribution mismatch；(3) 不要被'端到端生成'迷惑——OneRec 的成本红利来自'去除级联中冗余打分阶段'，前提是召回侧足够强、Semantic ID 足够好。

部署考量：典型 serving 栈应包含：Semantic ID embedding 表（few GB）、生成式主模型（10B 内为佳）、speculative decoder（draft model 1B 内）、生成结果的多目标 rerank（保留小型判别式 head 做最后一公里融合）。这与 OneRec/AtSpeed 报告的'10.6% 成本 + 2.2–2.5× speedup'路径自洽。

综上，本综述的最大价值是把碎片化的生成式推荐工作整合成可执行的工程蓝图——读完即可决定团队下一年技术路线是 LLM-Based、Large Rec Model 还是 Diffusion 哪一条。对中国互联网搜推团队而言，Kuaishou/Meituan 的成功案例尤其值得逐字精读。

AgentGR: Semantic-aware Agentic Group Decision-Making Simulator for Group Recommendation

针对群组推荐传统方法将'群体偏好'简化为'个体偏好聚合'的局限，提出 AgentGR：用 LLM 驱动的 agent 扮演群组成员，让每个成员 agent 既携带协同信号（user/item embedding 检索得到）又携带语义偏好（profile prompt），通过多轮辩论模拟真实群体决策过程（角色扮演 + 共识达成）。在多个 group rec 公开数据集上 AgentGR 在 NDCG/Recall 上稳定超越基于注意力聚合的强基线，并在 ablation 中证明 LLM 多轮交互的增益。

NanoResearch: Co-Evolving Skills, Memory, and Policy for Personalized Research Automation

NanoResearch 提出'技能-记忆-策略'三层协同进化的多 agent 研究自动化框架：skill bank 把重复操作蒸馏成可复用过程性规则；memory module 跨会话保留用户特定经验；policy 通过 RL 内化用户隐式偏好。三层在每轮交互中互相更新（skill 提供原语、memory 提供上下文、policy 决定调用顺序），从而在不同资源/偏好/输出格式的用户场景下都能保持个性化产出。实验表明显著优于通用多 agent baseline。

INSIGHT把 Agent 的'记忆'拆成 skill / experience / policy 三层是一个值得借鉴的工程范式：现有 deep research agent 大多只有 chat history 记忆，无法跨会话沉淀 know-how。社区搜索的 agent 化（如 AI 助手帮用户找回历史发帖、组织主题答案）需要同样的多层记忆——skill 是 query 改写/检索原语，experience 是用户偏好/历史路径，policy 决定何时检索、何时直接回答。可以先做 skill bank（高频检索动作字典），再叠加 memory，回报较高。

Jinhang Xu, Qiyuan Zhu, Yujun Wu, Zirui Wang, Dongxu Zhang

ArchRAG: Attributed Community-based Hierarchical Retrieval-Augmented Generation

CUHK Shenzhen

ArchRAG 针对图 RAG 在'定位相关信息不准、在线检索 token 消耗大'的问题，提出基于属性社区的分层 RAG：先用 LLM 驱动的层次聚类对知识图谱构建属性社区索引，问答时先在社区层次结构上做粗筛、再在节点层做精检。论文给出新的层次索引数据结构与检索算法，在多个 QA benchmark 上相比 LightRAG/HippoRAG 等图 RAG 基线在准确率与 token 成本之间取得更优 Pareto。

INSIGHT图 RAG 的关键瓶颈是检索定位精度与 token 成本的 trade-off，分层社区检索是被反复验证有效的解法。对社区搜索的启发：UGC 内容天然带'话题/小组/标签'层次，可以直接用作社区粒度建立索引——粗层用话题/小组定位，细层在帖内匹配。比纯向量检索 + rerank 的两阶段架构，在长尾、跨主题问答场景会更稳健。落地路径可以先在站内问答场景试点。

Shu Wang, Yixiang Fang, Yingli Zhou, Xilin Liu, Yuchi Ma

Don't Retrieve, Generate: Prompting LLMs for Synthetic Training Data in Dense Retrieval

针对 dense retrieval 训练对全量语料挖掘 hard negative 的依赖，本文尝试用 4B–30B 的 Qwen3/LLaMA3/Phi4 直接从 query + positive 生成 synthetic hard negative，再用 DistilBERT 在 10 个 BEIR 数据集上评测。结论与预期相反：合成负样本 pipeline 一致弱于 BM25 / cross-encoder 等传统挖掘策略，且增大生成模型规模并不单调提升下游检索效果——14B 反而是甜区。

INSIGHT这是一篇有价值的'负结果'——生成式数据并不总是赢传统语料挖掘，尤其在 hard negative 这种需要语料分布信息的环节。对工业搜推团队的启示是：当资源允许时仍应坚持以语料为基础的 negative mining，LLM 合成更适合补充长尾 query 或冷启动域；而且'生成器越大越好'是错误直觉，14B 量级的甜区意味着用旗舰模型合成数据反而浪费成本。社区搜索可以将其作为补充策略而非替换。

Loom: Hybrid Retrieval-Scoring Outfit Recommendation with Semantic Material Compatibility and Occasion-Aware Embedding Priors

Loom 提出'神经召回 + 规则打分'混合的整套穿搭推荐系统：以某一锚定单品为起点，在 FashionCLIP embedding 空间用 slot-constrained ANN 召回互补单品，再用六维多目标打分（embedding 相似度、色彩协调、正式度一致性、场合契合、风格方向、套内多样性）选择最终搭配。两个新技术贡献是：(1) 用 CLIP embedding 几何推断面料重量以判断叠搭兼容性，无需人工面料分类；(2) 把场合描述 prose 嵌入到 CLIP 空间作为'vibe/anti-vibe'锚向量参与打分。

INSIGHT在垂类推荐里，'embedding 召回 + 多目标规则打分'仍然是工业落地的稳健架构，纯端到端神经方案在可控性上劣势明显。Loom 提供的可借鉴点是把'结构化领域知识（面料、场合、风格）'用 CLIP/LLM embedding 几何来表达，而不是写硬规则字典——这能避免冷启动新类目时知识库失配。对社区搜索的启示：UGC 帖子的'适合场景/适合人群/调性'标签也可以用 prompt embedding 锚点来软表达，比维护一个静态标签词典扩展性强。
