1. SkillGate: Training In-Policy Skill Selection in Long-Horizon Agents
4.50
Relevance 5 | Novelty 4 | Practical 4 | Evidence 5 | Timely 5

Summary: 论文指出长程 Agent 选择技能时存在“选择器信用饥饿”：候选技能名称只占少量 token，却被整条轨迹的结果奖励淹没。SkillGate 将执行 token 的结果信用与技能选择 token 的局部优势分成两条通道，在 16 个候选技能的设置下，把 9B 策略的试验成功率从 40.8% 提升到 53.2%，误导性候选暴露减少三分之二。

Key insight: 对社区搜索 Agent，技能路由不应与最终答案质量共用一条粗粒度奖励；应单独标注“选了哪个召回/查询理解技能”以及该选择是否正确。局部 credit 加上读取次数约束，可减少 Agent 反复加载无关工具，直接改善多轮检索成本和稳定性。

2. SPADE: Self-Play in Adaptive Synthetic Executable Environments
4.20
Relevance 4 | Novelty 5 | Practical 3 | Evidence 5 | Timely 5

Summary: SPADE 让同一个 LLM 同时担任环境设计者和推理 Agent：前者生成带 reset()/step()、状态转移、奖励与验证代码的长程环境，后者在其中学习工具调用。环境设计器依据“有无特权提示”的 regret 自适应制造接近能力边界的任务；在 30B 模型上，八个留出基准平均提升 5.3，BFCL-v4 多轮工具调用提升 5.7，ACEBench-Agent 提升 13.9。

Key insight: 这提供了搜索 Agent 自动生成难例的可行范式：用真实 UGC 查询、检索轨迹和验证器生成可执行多跳任务，再让环境难度随模型能力升级。落地时要保留确定性 verifier 与任务预算，避免把“会生成更难题”误当成线上 nDCG 或 CTR 的直接收益。

3. Can David Beat Goliath? On Multi-Hop Reasoning with Resource-Constrained Agents
4.10
Relevance 5 | Novelty 4 | Practical 4 | Evidence 4 | Timely 2

Summary: 论文针对低资源 RL 训练多跳搜索 Agent 时有效轨迹稀少的问题，提出 David-GRPO。方法把少量专家轨迹引入更新，并把部分成功轨迹转成证据覆盖分数来继续扩展；在最多 1.5B 参数、4 张 RTX 3090 的训练预算下，于 6 个多跳问答基准优于同预算 RL 基线，并学会增加检索深度与证据覆盖。

Key insight: UGC 搜索中的复杂问题通常需要 query 拆解、短文本召回和证据合并，适合把“覆盖了多少必要证据”作为轨迹级奖励，而不是只奖励单个文档相关性。专家 bootstrap 能降低冷启动成本，但应把检索深度、工具调用次数和最终相关性联合成预算感知目标。

4. FM-Bench: A Benchmark for Long-Horizon Management with Competing Agents
4.20
Relevance 4 | Novelty 4 | Practical 4 | Evidence 5 | Timely 5

Summary: FM-Bench 用确定性足球经营引擎评估 Agent 的长程决策：一个 Agent 要管理 20 个赛季、调用 26 个工具并经历约 340–400 个决策节点，最终由引擎累计得分而非 LLM 评审。基准覆盖 15 个前沿模型、单机与共享 Arena 两种赛制及 6 类行为能力；结果显示模型排序往往到长时域后期才稳定，规模、价格和厂商不能解释排名。

Key insight: 搜索 Agent 评测不能只看单轮答案 EM/F1，应增加几十轮检索、反思、改写和证据缓存后的最终任务完成率。FM-Bench 暴露的“记忆只增不减”与“计划每季重写”问题，可直接转化为搜索会话的上下文压缩、状态版本化和失败恢复测试。

5. SkillForge: Self-Distilling Agents for Project-Specific Issue Resolution
4.10
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: SkillForge 不等真实问题出现后才学习，而是从仓库中测试覆盖的核心功能合成项目特定问题，Agent 先解决这些问题，再把经验蒸馏为绑定实体的可复用技能。论文在开源与闭源模型上均报告相对强基线的持续改进，重点解决 Agent 缺少项目上下文以及逐问题探索成本过高的问题。

6. SemaPLC: A Project-Grounded, Verification-Gated Agent Harness for PLC Code Generation
3.90
Relevance 3 | Novelty 4 | Practical 4 | Evidence 5 | Timely 5

Summary: SemaPLC 用项目上下文和外部验证器约束代码 Agent，只有规格检查、编译检查和真实运行时行为检查全部通过才算完成。在 117 个独立 POU 任务、7 个模型上，严格验证通过率均值为 72.6%；在 65 个真实项目上下文任务中，动态行为分数达到 52.2，而基线为 22.4–31.4。

Key insight: 搜索 Agent 也应把“生成了答案”与“答案可验证”分开：对引用存在性、证据覆盖、时间有效性和 nDCG 代理指标设置门禁。动态验证比静态 LLM judge 更能发现错误，适合将离线 replay、检索日志和事实核验器接入 Agent 完成条件。

7. Co-RL: Unsupervised Reasoning Emerges from Diverse Cohort in Multi-agent RL
3.65
Relevance 3 | Novelty 4 | Practical 3 | Evidence 5 | Timely 5

Summary: Co-RL 让多个不共享参数的模型通过同伴奖励共同进行 RL，避免单模型自奖励造成偏差积累、行为同质化和训练崩溃。作者通过异构模型、模型规模和改写样本提高 cohort 多样性；在 7 个纯文本基准上平均提升 3.0–8.6%，在 4 个多模态基准上提升 2.3–7.2%，且不使用 ground-truth 标签。

Key insight: 在搜索 Agent 训练中，可让不同 query planner、retriever 和 verifier 互相提供弱反馈，减少单一模型偏好带来的召回盲点。关键不是简单堆多个 Agent，而是保持模型与样本的误差去相关，并监测多样性、重复查询率和奖励塌缩。

8. RAG 系统深度实战：从朴素检索到 Agentic RAG 的完整演进
3.55

Summary: 中文工程文章把 RAG 拆成解析、分块、Embedding、存储、Query 处理、检索、重排序和生成等阶段，并进一步比较 Self-RAG、Graph RAG 与 Agentic RAG。文章以一份约 10 万字中文技术文档对比 5 种分块策略，强调中文场景中分词边界、上下文完整性和检索延迟的共同影响。

10. Persona-Guided LLM Agents for Task-Oriented Dialogue
3.25
Relevance 3 | Novelty 3 | Practical 4 | Evidence 4 | Timely 2

Summary: 论文构建无需微调的双 Agent 任务对话框架：用户 Agent 表达目标人格，系统 Agent 在 Neutral、Try 和 Oracle 三种信息条件下完成任务。实验覆盖 GPT-4o、Qwen3-Next-80B、Gemini 2.0 Flash、SGD 酒店与餐厅对话及 Big Five 人格；人格适配提升约束满足、inform rate 和满意度，但会牺牲真实性，Try 条件的权衡最稳定。

Key insight: 如果社区搜索 Agent 需要适配用户表达风格，应把人格或偏好作为可撤销的检索策略信号，而非直接改写事实答案。Try 式从对话线索推断偏好比强行读取 Oracle 标签更稳妥，同时必须监控个性化带来的事实性下降。
