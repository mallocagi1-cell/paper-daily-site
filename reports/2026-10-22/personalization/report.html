ECHO: Efficient Cascade with Homogeneous Operators for Distillation-Guided 100K-Sequence Modeling

十万条历史行为让候选逐一匹配的成本过高，作者先筛选可复用的原始记录，再按候选查找证据。筛选器向完整历史教师学习，并让检索与聚合共享相关性参数。快手线上实验中，应用使用时长提高0.613%。

ECHO 是快手提出的三级漏斗：100K 条原始行为 → 用户侧学习式 top-K（不看候选，在请求链路外计算并按用户缓存）选出 10K 条 → 每个候选做 GSU 式检索取 100 条 → target attention 聚合进精排。用户侧选择器没有候选信息，所以用一个“看全历史 + 看候选”的 target attention 教师模型做知识蒸馏，再加一项边界损失，专门把“教师重视但没进 top-K”的行为推过门槛。检索和最终 attention 共用教师的相关性参数，这就是标题里的 Homogeneous Operators。按论文的解析估算，序列分支 FLOPs 比 STCA 低约 160 倍；KuaiRand 评论任务 GAUC 相对最强基线提升 1.520%，线上 7 天 A/B 使用时长 +0.613%。

1. 整体结构：三级漏斗各做什么

这一节回答：100K 条行为如何一步步缩到精排能处理的规模。

先定义四个贯穿全文的术语。

  • target attention：以待打分候选为 query、以历史行为为 key/value 的注意力。输出是“与这个候选相关的兴趣向量”。DIN 是代表。
  • GSU / ESU：SIM 提出的两阶段长序列建模。GSU（General Search Unit）用轻量打分从长历史里检索少量相关行为。ESU（Exact Search Unit）在这批行为上做完整的 target attention。
  • top-K：按分数保留最高的 K 个位置。
  • 知识蒸馏（KD）：让学生模型拟合教师模型输出的概率分布。

ECHO 的漏斗有三级，外加一个只在训练时存在的教师。

阶段模块输入 → 输出看候选？运行位置训练信号
① 用户侧压缩Distilled Selector（DS）100K → 10K 条原始记录否实时训练链路，写入中间存储KD + 边界损失
② 候选检索TFR，TWIN 式 GSU10K → 每候选 100 条是线上请求精排损失；打分参数来自教师
③ 兴趣聚合TWIN 式 ESU100 条 → 兴趣向量是线上请求精排多任务损失
教师全历史 target attention全部历史 + 训练候选是仅训练自身预测损失

TFR 是 Target-aware Fine-grained Retriever 的缩写，即第二级的候选检索器。

训练时有两张图同时跑。选择器图训练教师和 DS，DS 把每个用户的 top-K 记录写进中间存储。排序图从存储读这些记录，训练 TFR、聚合层和精排。

线上请求只读存储。它不运行 DS，也不碰 100K 全历史。

DS 保留的是原始记录：item ID、时间戳和侧特征。C-Former、SequenceO1 等方法把历史压成潜向量 token；ECHO 的每条保留记录都还能被候选单独匹配。

2. 走查：一次请求如何流过三级（示意数字）

这一节用一个例子把上面的表串起来。以下数字均为示意，非论文数据。

用户 A 有 80,000 条历史行为。凌晨实时训练时，DS 给这 80,000 条各打一个分，保留最高的 10,000 条，写进存储。其中有一条是 8 个月前看完的一个钓鱼视频。

上午 9 点，用户 A 刷新首页。精排要给 500 个候选打分，其中一个候选是新的钓鱼装备视频。

第一级已在请求前完成。精排直接读出用户 A 的 10,000 条记录，500 个候选共用这一份。

第二级：TFR 用钓鱼视频作为 query，给 10,000 条记录打相关性分，取最高的 100 条。8 个月前那条钓鱼视频分数很高，被取了出来。

第三级：target attention 在这 100 条上计算权重。钓鱼相关的行为拿到较大权重，聚合成兴趣向量，送进精排塔预测点击、点赞、评论等目标。

如果 DS 当初没保留那条钓鱼记录，第二级就找不到它。这正是 DS 需要教师监督的原因。

3. 标题关键词对应什么

这一节把标题里的每个词落到上面的模块上。

Cascade（级联）：100K → 10K → 100 → attention 三级预算。10K 决定能保住多宽的兴趣范围。100 决定每个候选的精细计算量。

Homogeneous Operators（同构算子）：TWIN 让 GSU 和 ESU 使用同一套相关性打分参数。ECHO 再往前推一步：教师学到的 query/key 相关性参数 Θrel​ 同时导出给 TFR 和最终 target attention。三处使用同一个打分算子，粗检索和精聚合对“相关”的定义一致。

Distillation-Guided（蒸馏引导）：DS 的训练信号来自教师，见第 4 节。

100K-Sequence Modeling：线上原始历史上限 100K 条。

4. DS 怎么训练：打分、蒸馏、边界损失

这一节解决第一级的核心难题：DS 看不到候选，却要提前选出对候选有用的行为。

4.1 DS 的打分

sjS​=Hs​1​h=1∑Hs​​⟨WQ,hS​e,WK,hS​zjS​⟩
符号：sjS​ 是学生（DS）给第 j 条历史行为的分数；e 是只由用户画像特征得到的用户向量；zjS​ 是第 j 条行为（特征加时间戳）的编码；WQ,hS​、WK,hS​ 是第 h 个头的 query/key 投影；Hs​ 是头数；⟨⋅,⋅⟩ 是内积。

直觉：这就是一个以“用户”为 query 的注意力打分。因为 query 里没有候选，同一用户的分数对所有候选通用，所以能提前算好并缓存。

打完分后保留最高的 K 个位置，记为集合 IK。生产中 K=10,000。

4.2 教师的打分

sv,jT​=Ht​1​h=1∑Ht​​⟨WQ,hT​fT​(c,xv​),WK,hT​zjT​⟩
符号：sv,jT​ 是教师在候选 v 下给第 j 条行为的分数；fT​(c,xv​) 把上下文特征 c 和候选特征 xv​ 编码成 query；zjT​ 是教师自己的行为编码（与学生不共享）；Ht​ 是教师头数。

直觉：教师是一个标准的全历史 target attention。它知道候选是什么，所以它的分数代表“对这个候选来说，哪些历史真正相关”。

4.3 蒸馏损失

LKD​=−∣B∣T2​b∈B∑​j=1∑Lb​​sg[pb,jT​]logpb,jS​
符号：B 是一个 batch，b 是其中一个“用户–候选”样本；Lb​ 是该用户的历史长度；pb,jT​ 和 pb,jS​ 分别是教师和学生分数在历史维度上做 softmax 后的概率，softmax 温度为 T；sg 表示 stop-gradient，学生损失不会更新教师。

直觉：这是标准的软标签交叉熵。同一用户有多个训练候选，每个候选给出一份教师分布。学生只有一份分数，只能去拟合这些分布的“共同部分”。结果是学生学会把对大多数候选都有用的行为排在前面。

4.4 边界损失

分布对齐之后，仍可能有个别教师很看重的行为排在学生 top-K 之外。边界损失专门处理这类行为。

做法分三步。第一步，用更低的温度 Tm​<T 算一份更尖锐的教师分布 p~​T。第二步，在学生 top-K 之外，找教师概率最高的 n 个位置，记为 j+（漏选的正例）；在 top-K 之内，找教师概率最低的 n 个位置，记为 j−（占位的负例）。第三步，按名次两两配对，计算：
ωb,i​=sg[max(p~​b,jb,i+​T​−p~​b,jb,i−​T​,0)]Laux​=∑b​∑i​ωb,i​+ϵ∑b​∑i​ωb,i​softplus((sb,jb,i−​S​−sb,jb,i+​S​+δ)/Trank​)​
符号：i 是第 i 个配对；ωb,i​ 是该配对的权重，等于教师对正例和负例的偏好差（小于 0 时取 0）；sS 是学生分数；δ 是希望正例领先负例的间隔；Trank​ 控制损失的尺度；ϵ 防止分母为 0。

直觉：这是一个带权的 pairwise 排序损失。它只作用在 top-K 的边界上，把“该进没进”的行为分数往上推，把“占了名额却不重要”的行为往下压。教师偏好差越大，推力越大。配对和权重都不求梯度，所以不需要对离散的 top-K 操作求导。

4.5 总目标

Lsel​=αLpred​+βLKD​+γLaux​
符号：Lpred​ 是教师的多任务预测损失（点击、点赞等标签）；α、β、γ 是权重。

直觉：Lpred​ 只更新教师，让教师持续学会“什么相关”；LKD​ 和 Laux​ 只更新 DS。教师和 DS 在同一条实时训练流里一起训练，教师不是冻结的预训练模型。排序图另用自己的多任务损失 Lrank​。

5. 部署：三处工程优化

这一节解决漏斗上线后的显存、存储和计算开销。

公共特征共享。 一个 batch 里同一用户的多个样本，只把长历史等用户侧特征加载进 GPU 一次。

紧凑记录编码。 生产 schema 每条记录 8 个字段。全用 int64 是 64 字节一条，10K 条就是 640 KB。ECHO 按每个字段的取值范围分配固定位宽，再紧密打包。

Key 投影挪到 query 侧。 常规 target attention 要给每条历史算一次 key 投影。线上要么每次重算，要么缓存投影结果，开销都随历史长度增长。ECHO 用一个内积恒等式：
⟨qWQ​,hWK​⟩=⟨(qWQ​)WK⊤​,h⟩
符号：q 是候选侧 query 向量；h 是一条历史行为向量；WQ​、WK​ 是 query/key 投影矩阵；WK⊤​ 是 WK​ 的转置。

直觉：先把 WK​ 乘到 query 上，每个请求只做一次。历史向量 h 直接参与内积，不再需要逐条投影，也不需要 key 缓存。

6. 实验

这一节回答三个问题：效果比基线好多少、DS 选得准不准、省了多少计算。

基线定义。 DIN：只用最近 100 条行为的 target attention。SIM：GSU/ESU 两阶段检索。TWIN：GSU 和 ESU 共用相关性参数的 SIM 改进版。STCA：堆叠 target-aware cross-attention 的端到端长序列模型，训练平均 2K、推理外推到 10K。TWIN V2：把最近 50K 行为聚类成约 10K 个单元再做 attention。SequenceO1：把历史压成 100 个 token 的固定 sketch。GAUC 是按用户分组计算 AUC 后加权平均。

结果数字含义
KuaiRand-1K 评论 GAUC0.6252 → 0.6347（+1.520%，最强基线 SequenceO1）公开数据上提升最大的任务；8 个任务全部最优
工业数据 评论 GAUC0.7824 → 0.7851（+0.345%，最强基线 TWIN V2）工业数据上提升 0.113%–0.345%
按历史长度（对比 TWIN）<10K 用户 +0.045%，>50K 用户 +1.279%历史越长，学习式选择越有用
教师 top-100 召回DS 99.976%，最近截断 57.905%，随机 49.443%DS 几乎没漏掉教师最看重的行为
选出的旧行为46.08% 不在最近 10K 条内DS 选的不是“最近的”，而是“相关的”

消融同时去掉了两项损失，边界损失单独的贡献论文没有拆开。

7. 局限

这一节说明漏斗第一级带来的代价。

100K → 10K 是硬截断。被 DS 丢掉的行为，第二级 TFR 无法再取回。作者指出，极长尾候选的相关行为可能因此丢失。

DS 随实时训练和存储刷新而更新。新兴趣要等下一次刷新才能进入保留集。

论文没有单独评估新用户、兴趣突变和新增候选类型下的保留质量。工业数据不公开。

8. 工业实践建议

这一节给已有长序列链路的团队几个可直接做的事。

在 GSU 前加一级用户侧 top-K。 已有 SIM/TWIN 链路时，同样存储预算下对比学习式选择、最近截断和随机。

监控保留集质量。 离线跟踪“教师 top-100 召回”和“教师 attention 质量覆盖率”。

复用现有模型做教师。 已有全历史或长窗口 target attention 模型，可以兼任教师，并把 query/key 参数导出给 GSU 和 ESU。

单独使用 key 投影技巧。 第 5 节的恒等式适用于任何线上 target attention。

定义刷新指标。 跟踪新行为进入 top-K 的延迟、模型版本与存储记录的兼容性，以及回滚方案。

KuaFu: Compressing Long User Behavior into Understanding at Billion Scale

Tencent📖 有深读 · 7 分钟

多个画像任务反复读取同一段长历史，造成大量重复计算。作者把物品内容预先压成可共享向量，再按时间拼回用户历史，配合分阶段训练减少信息损失。腾讯长期保留对照组的实验报告整体GMV提高1.37%。

INSIGHT复用的基本单位可以从用户换成物品。同一内容被不同用户消费时，只编码一次；动作和时序在用户侧保留。对多任务兴趣画像，缓存规模由物品数量决定，比重复运行整段历史更节省资源。

Jiahao Hui, Lin Zhu, Ben Tan, Yishen Hu, Jingdong Shu, Zetai Jiang, Xining Ran, Yeshou Cai, Gong Che...

同一件内容被很多用户看过，KuaFu就只压缩一次，再把这些压缩结果拼成各自的行为历史。这样，兴趣提取、职业画像和人生阶段识别可以复用物品侧计算。腾讯的目标是让十亿级用户的长历史画像更便宜，也更快更新。

1. 问题与动机：重复发生在用户与任务之间

传统画像往往按任务独立建设。内容兴趣读一遍用户历史，电商兴趣再读一遍，职业识别还要重新读取。即使这些任务都用大模型，同一物品的文字仍然被不同用户、不同任务反复编码。

直接压缩整段用户历史也有代价。历史变长或新增行为后，可能需要重新生成摘要；少量向量还可能丢掉罕见兴趣和时间关系。论文记录了编造、遗漏、日期归错和推理断裂几类错误，说明压缩是否成功不能只看最后的推荐指标。

KuaFu把共享计算的位置前移到物品侧。公共内容负责共享，动作和时间顺序在用户侧重建。它是一套离线理解与画像更新系统，不是要求每次线上排序都调用大模型。

2. 方法：物品压缩、紧凑缓存、按时间解读

压缩器先读取单件物品的文本，在末尾追加可学习的记忆标记。模型把文本信息写入这些位置的隐藏状态。这里的记忆标记是训练得到的连续向量，不是给物品分配的离散商品编号。

紧接着，投影器同时压缩两种维度。一种减少向量个数，另一种降低每个向量的宽度。论文给出的例子，是把8个记忆向量减为2个，把宽度从2560减到128。缓存只保存压缩核心，需要解读时再用轻量投影恢复到解码器可接收的宽度。

训练初期还有一条池化残差，帮助优化稳定。它逐渐衰减，前一阶段训练结束后不再依赖完整隐藏状态。这个细节很关键：若服务时还必须读取原始宽向量，低维缓存省下的空间就不能真正兑现。

解码器接收按时间拼接的物品表示，以及普通指令、动作等文本信息。它可以回答用户兴趣问题，也可以生成结构化画像。物品表征共享，并不意味着不同用户最终拿到相同的画像；用户消费了哪些物品、以什么顺序和动作消费，仍然决定输入。

训练分四阶段推进。先让冻结的解码器从记忆中重建原文，训练压缩器保留基本信息；再加入问答任务和投影器，让记忆保留用户理解需要的证据。随后联合更新压缩与解码两端，使接口彼此适应。

最后用强化学习减少幻觉。此时冻结压缩器和投影器，只更新解码器。奖励既惩罚几种具体错误，也奖励回答完整度，防止模型靠少说话来规避错误。奖励判断仍会对照原始文字，而非只在压缩结果内部自我检查。

长序列训练还按难度逐步增加物品数量。消融显示，把所有长度一开始混在一起，会让优化停滞；不同阶段继承参数，也有助于避免训练损失下降而验证误差上升。学习如何压缩与学习如何读压缩输入，需要同步安排。

3. 核心贡献：缓存能否共享，取决于表示依赖什么

KuaFu的共享收益来自物品表示不依赖具体用户和目标任务。物品变了才需要更新物品缓存，用户新增互动则主要改变拼装后的序列。这让表示库随物品规模增长，而不是为每个用户、每个任务各存一套长历史表示。

论文强调的另一点是直接检查保真。它除了看画像准确率，还测试压缩后能否找回藏在长历史中的事件，以及能否避免把事件日期和结论弄错。这些中间指标比等待完整线上实验更快暴露压缩损伤。

不同“压缩倍数”对应不同对象。按向量元素数计算，上述投影前后为8×2560和2×128，两者比值是80。与原始文本输入相比，解码器看到的序列缩短又是另一种口径。存储、文本长度和整条服务成本不能混在一个倍数里。

下面选取四个生产指标。F1衡量兴趣提取的查准与查全，分类准确率用于相对稳定的画像属性；它们不是同一个任务的统一分数。

内容兴趣任务的单卡吞吐从每分钟40个请求升到180个。按(180−40)/40计算，增加350%；也就是原来的4.5倍，而非3.5倍。论文报告多个任务合计节约190张解码侧GPU，不能把单一任务的倍数套到全部硬件。

公开推荐评测里，压缩后的4B模型超过同规模骨干，说明收益不只来自增大模型。但在CDs子集它也出现退步，这提示压缩优势会随领域变化。通用阅读理解和私有画像任务各有自己的协议，不能把不同评测的提升数字拼成一个统一效果。

强化学习评测中，编造率从33.5%降到4.5%。完整回答程度基本维持，支持奖励不只是把模型训练成少答。评分依赖模型裁判，论文另给人工评审与第二裁判的一致性分析；这比只用训练奖励报告成功更有说服力，但仍不等于所有生产错误都被覆盖。

线上按独立访客随机分组，并保持相同资源预算。实验组用压缩省下的资源把历史覆盖拉长、画像更新加快；整体GMV提高1.37%，置信区间为正。对照组仍是较短历史、较慢刷新，因此这个结果支持整套画像升级，无法单独归因于投影器或某一个训练阶段。

5. 局限：共享表示也会固化取舍

作者指出，目前不同任务族使用固定压缩比例，内容差异很大时未必最合适。信息密集的物品可能需要更多记忆空间；极短内容则可能不值得分配同样预算。自适应压缩仍是未来工作。

工业日志和生产训练数据不能公开，外部只能复核公开基准及已披露的实现细节。部分私有任务用大模型打分，也会继承裁判的偏差。数字看起来覆盖多个任务，并不意味着它们都是独立人工标注的客观真值。

工程上还要考虑缓存版本。物品内容更新、压缩器升级或解码器接口改变后，旧向量是否仍兼容，需要明确策略。跨用户复用降低重复计算，也放大了单个物品缓存错误的影响范围。这是从架构推导出的部署注意点，不是论文报告的线上故障。

6. 工业实践意义：从重复编码最严重的地方切入

对社区帖子、商品和视频，如果同一内容频繁出现在不同用户历史里，可以统计重复文本编码占比。以物品为键复用表征是否划算，取决于真实共享率、内容更新频率和向量存储成本，不能只看用户数巨大。

评估时可并列检查兴趣标签、时间归属和证据找回。一个表示也许足够判断职业，却不足以回答最近为何点击某类帖子。任务粒度的保真测试能决定哪些画像适合共享压缩，哪些仍需读取原始证据。

上线实验应把表征、历史覆盖与刷新周期作为清楚的变量。先固定其中两项观察第三项，再考虑组合升级，才能解释节约的资源究竟通过什么路径改善结果。KuaFu提供了把算力节省转成更新能力的实例，也提醒我们将效率指标与业务因果归因分开。
