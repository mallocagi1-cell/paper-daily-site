ECHO: Efficient Cascade with Homogeneous Operators for Distillation-Guided 100K-Sequence Modeling

十万条历史行为让候选逐一匹配的成本过高，作者先筛选可复用的原始记录，再按候选查找证据。筛选器向完整历史教师学习，并让检索与聚合共享相关性参数。快手线上实验中，应用使用时长提高0.613%。

ECHO 是快手提出的三级漏斗：100K 条原始行为 → 用户侧学习式 top-K（不看候选，在请求链路外计算并按用户缓存）选出 10K 条 → 每个候选做 GSU 式检索取 100 条 → target attention 聚合进精排。用户侧选择器没有候选信息，所以用一个“看全历史 + 看候选”的 target attention 教师模型做知识蒸馏，再加一项边界损失，专门把“教师重视但没进 top-K”的行为推过门槛。检索和最终 attention 共用教师的相关性参数，这就是标题里的 Homogeneous Operators。按论文的解析估算，序列分支 FLOPs 比 STCA 低约 160 倍；KuaiRand 评论任务 GAUC 相对最强基线提升 1.520%，线上 7 天 A/B 使用时长 +0.613%。

1. 整体结构：漏斗、规模与在线/离线分工

先定义几个贯穿全文的术语：

  • target attention：以待打分候选（target）为 query、以历史行为为 key/value 的注意力，输出“与该候选相关的兴趣表示”，DIN 是代表。
  • GSU / ESU：SIM 提出的两阶段长序列建模。GSU（General Search Unit）用轻量打分从长历史中检索与候选相关的少量行为；ESU（Exact Search Unit）在这批行为上做精细的 target attention。
  • top-K：按分数取最高的 K 个位置。
  • 知识蒸馏（KD）：让学生模型拟合教师模型输出的软分布，而不仅是硬标签。

ECHO 的生产配置（论文附录 A.2）与各阶段属性如下：

阶段模块输入 → 输出是否看候选运行位置监督信号
① 用户侧压缩Distilled Selector（DS）100K → 10K 条原始记录否实时训练链路，结果写入中间存储，按用户复用KD + 边界损失（来自教师）
② 候选侧检索Target-aware Fine-grained Retriever（TFR），TWIN 式 GSU10K → 每个候选 100 条是线上请求精排预测损失；打分参数来自教师
③ 兴趣聚合Candidate-aware Interest Aggregation，TWIN 式 ESU100 条 → 兴趣向量是线上请求精排多任务预测损失
教师全历史 target attention全部历史 × 训练样本候选是仅训练自身的多任务预测损失

训练分两张图并行跑：选择器图训练教师和 DS，DS 把 top-K 记录写入中间存储；排序图读取这些记录，训练 TFR、聚合和精排。线上请求只读存储，不运行 DS，也不扫描 100K 全历史。离线实验用 50K 原始历史 → 10K → 100。

保留下来的是原始事件记录（item ID、时间戳、侧特征），区别于 C-Former、SequenceO1 等把历史压成潜向量 token 的方法：被保留的每条行为仍能被候选逐条匹配。

2. 标题关键词与机制的对应

  • Cascade（级联）：上表的 100K → 10K → 100 → attention 三级预算。10K 决定能保住多宽的兴趣范围，100 决定每个候选的精细计算量。
  • Homogeneous Operators（同构算子）：TWIN 让 GSU 和 ESU 使用同一套相关性打分参数；ECHO 把这一做法扩展到教师——教师学到的 query/key 相关性参数 Θ_rel 导出给 TFR 检索和最终 target attention。教师、检索器、聚合器因此用同一种打分算子，粗检索和精排序的“相关”定义一致。DS 的事件编码器与教师相互独立，两者之间只通过蒸馏传递知识。
  • Distillation-Guided：DS 的训练信号来自教师的分布（KD）和边界损失，下一节给出公式。
  • 100K-Sequence Modeling：线上原始历史长度上限 100K。

3. 方法：DS 打分、蒸馏与边界损失

DS 打分。 用户画像特征编码为 e，第 j 条历史事件编码为 z_j，H_s 个头取内积均值，再取 top-K：

s^S_j = \frac{1}{H_s}\sum_{h=1}^{H_s}\langle W^S_{Q,h} e,\; W^S_{K,h} z^S_j\rangle,\qquad
\mathcal{I}^K = \mathrm{TopK}_{j\in[1,L]}\, s^S_j

e 只含用户特征，所以同一用户的分数和 top-K 对所有候选通用。

教师打分。 教师是一路全历史 target attention，query 来自上下文和候选 v：

s^T_{v,j} = \frac{1}{H_t}\sum_{h=1}^{H_t}\langle W^T_{Q,h} f_T(c, x_v),\; W^T_{K,h} z^T_j\rangle

KD 损失。 教师和学生分数各自在历史维度上做温度为 T 的 softmax，用交叉熵对齐（sg 为 stop-gradient，教师不被学生损失更新）：

\mathcal{L}_{KD} = -\frac{T^2}{|\mathcal{B}|}\sum_{b}\sum_{j=1}^{L_b}\mathrm{sg}[p^T_{b,j}]\,\log p^S_{b,j},\quad
p_{b,j} = \mathrm{softmax}_j(s_{b,j}/T)

同一用户的多个训练候选各自给出一份教师分布，学生用一份与候选无关的分数去拟合它们，学到的是“对这个用户的大多数候选都有用”的行为排序。

边界损失（boundary-targeted auxiliary loss）。 只对齐分布，教师重视的行为仍可能落在学生 top-K 之外。做法：用更低温度 T_m < T 得到更尖锐的教师分布 p̃；在学生 top-K 之外取教师质量最高的 n 个位置 j⁺（漏选的正例），在 top-K 之内取教师质量最低的 n 个位置 j⁻（占位的负例），按名次配对，做带权 pairwise softplus：

\omega_{b,i} = \mathrm{sg}\big[\max(\tilde p^T_{b,j^+_{b,i}} - \tilde p^T_{b,j^-_{b,i}},\,0)\big]

\mathcal{L}_{aux} = \frac{\sum_b\sum_i \omega_{b,i}\,\mathrm{softplus}\big((s^S_{b,j^-_{b,i}} - s^S_{b,j^+_{b,i}} + \delta)/T_{rank}\big)}{\sum_b\sum_i \omega_{b,i} + \epsilon}

效果是把 j⁺ 的学生分数推到比 j⁻ 高出间隔 δ，权重 ω 按教师偏好差加权；挖掘和权重都 detach，不需要对离散 top-K 求导。

总目标。 选择器图：

\mathcal{L}_{sel} = \alpha\,\mathcal{L}_{pred} + \beta\,\mathcal{L}_{KD} + \gamma\,\mathcal{L}_{aux}

其中 L_pred 只更新教师，L_KD 和 L_aux 只更新 DS；教师是在线一起训练的预测分支，不是预训练后冻结的模型。排序图只用自己的多任务预测损失 L_rank。

4. 部署优化：三处工程技巧

  1. 公共特征共享：batch 内同一用户的多个样本只把长历史等用户侧特征加载进 GPU 一次。
  2. 紧凑记录编码：生产 schema 有 8 个字段，全用 int64 是 64 字节/条，10K 条 640 KB；按每个字段的取值范围分配固定位宽后紧密打包存储。
  3. Key 投影吸收到 query 侧：target attention 常规要给每个历史位置算 key 投影 W_K h，线上要么每次重算（随长度增长），要么缓存投影后的 key（存储随长度增长）。利用内积恒等式把投影挪到 query 侧，每个请求只做一次：
\langle q W_Q,\; h W_K\rangle = \langle (q W_Q) W_K^{\top},\; h\rangle

5. 实验：离线、选择质量、成本与线上

基线：DIN（只用最近 100 条行为的 target attention）；SIM（GSU/ESU 两阶段检索）；TWIN（GSU/ESU 共用相关性参数的 SIM 改进版）；STCA（堆叠 target-aware cross-attention 的端到端长序列模型，训练平均 2K、推理外推到 10K）；TWIN V2（把最近 50K 行为聚类成约 10K 个单元再做 attention）；SequenceO1（把历史压成 100 个 token 的固定 sketch 并复用缓存）。GAUC 是按用户分组计算再加权平均的 AUC。

KuaiRand-1K 评论0.6252（SequenceO1）0.6347+1.520%

1.520% 是相对值：(0.6347 − 0.6252) / 0.6252 ≈ 1.52%，绝对差 0.0095。ECHO 在全部 8 个任务上都最好，KuaiRand 相对提升 0.227%–1.520%，工业数据 0.113%–0.345%。

按历史长度分组：相对 TWIN（最近 10K），历史 < 10K 的用户提升 0.045%，> 50K 的用户提升 1.279%，历史越长收益越大。

选择质量（以教师为参照）：教师 top-100 行为在 DS 的 10K 保留集中召回率 99.976%，最近截断 57.905%，随机 49.443%；DS 保留了教师 98.509% 的相关性质量。以教师 top-10K 为参照，保留预算 100 / 1K / 10K 时 DS 覆盖 70.84% / 91.65% / 99.38% 的 attention 质量，最近截断只有 0.43% / 5.14% / 55.93%。DS 选中的行为有 46.08% 不在最近 10K 条里，最长历史组为 75.09%。

计算成本：L = 100K、K = 10K 时，每个候选的序列分支解析 FLOPs，训练 STCA 14.26 vs ECHO 0.089 GFLOPs（160.3×），推理 1.346 vs 0.0085 GFLOPs（159.2×）。这是对序列分支的解析估算，与 STCA 比较；端到端服务延迟论文没有报告。L 超过 10K 后，下游 attention 成本固定，每多一条历史只增加 DS 刷新的少量开销。精度上，STCA 在 50K 时 GAUC 0.6645，ECHO 0.6630，长历史下全量建模仍略占优，ECHO 用约 1/160 的序列计算拿到了大部分收益。

消融：去掉 L_KD 和 L_aux、只用预测损失训练学生，KuaiRand 四个任务分别下降，ECHO 相对该变体提升 +0.272% / +0.925% / +2.371% / +0.317%（点击/点赞/评论/长播），评论最明显（0.6200 → 0.6347）。论文同时移除两项损失，所以边界损失单独的贡献无法从中读出。

线上 A/B：快手最大的短视频场景（日活 4 亿+），5% 流量，7 天；对照组已有 TWIN 检索和类 C-Former / SequenceO1 的序列压缩。总使用时长 +0.613%，人均使用时长 +0.640%。

6. 局限

100K → 10K 的压缩是硬截断：被 DS 排除的行为，下游 TFR 无法再取回，作者明确指出极长尾候选的相关行为可能因此丢失。DS 随实时训练和存储刷新更新，新兴趣进入保留集存在延迟；新用户、兴趣突变和新增候选类型下的保留质量论文没有单独评估。工业数据不公开，生产链路无法完整复现。

7. 工业实践建议

  • 已有 SIM/TWIN 链路：在 GSU 前加一个用户侧学习式 top-K，同样存储预算下对比最近截断与随机；用“教师 top-100 召回”和“教师 attention 质量覆盖率”作为离线监控指标，在线指标之外直接观察保留集质量。
  • 复用参数：若已有全历史或长窗口 target attention 模型，可让它兼任教师，并把 query/key 参数导出给 GSU 和 ESU，保持三处打分一致。
  • Key 投影吸收是独立可用的技巧，任何线上 target attention 都可以用它省掉逐位置的 key 投影和缓存。
  • 刷新指标：为保留集定义刷新延迟（新行为多久进入 top-K）、模型版本与存储记录的兼容性和回滚策略。

KuaFu: Compressing Long User Behavior into Understanding at Billion Scale

Tencent📖 有深读 · 7 分钟

多个画像任务反复读取同一段长历史，造成大量重复计算。作者把物品内容预先压成可共享向量，再按时间拼回用户历史，配合分阶段训练减少信息损失。腾讯长期保留对照组的实验报告整体GMV提高1.37%。

INSIGHT复用的基本单位可以从用户换成物品。同一内容被不同用户消费时，只编码一次；动作和时序在用户侧保留。对多任务兴趣画像，缓存规模由物品数量决定，比重复运行整段历史更节省资源。

同一件内容被很多用户看过，KuaFu就只压缩一次，再把这些压缩结果拼成各自的行为历史。这样，兴趣提取、职业画像和人生阶段识别可以复用物品侧计算。腾讯的目标是让十亿级用户的长历史画像更便宜，也更快更新。

1. 问题与动机：重复发生在用户与任务之间

传统画像往往按任务独立建设。内容兴趣读一遍用户历史，电商兴趣再读一遍，职业识别还要重新读取。即使这些任务都用大模型，同一物品的文字仍然被不同用户、不同任务反复编码。

直接压缩整段用户历史也有代价。历史变长或新增行为后，可能需要重新生成摘要；少量向量还可能丢掉罕见兴趣和时间关系。论文记录了编造、遗漏、日期归错和推理断裂几类错误，说明压缩是否成功不能只看最后的推荐指标。

KuaFu把共享计算的位置前移到物品侧。公共内容负责共享，动作和时间顺序在用户侧重建。它是一套离线理解与画像更新系统，不是要求每次线上排序都调用大模型。

2. 方法：物品压缩、紧凑缓存、按时间解读

压缩器先读取单件物品的文本，在末尾追加可学习的记忆标记。模型把文本信息写入这些位置的隐藏状态。这里的记忆标记是训练得到的连续向量，不是给物品分配的离散商品编号。

紧接着，投影器同时压缩两种维度。一种减少向量个数，另一种降低每个向量的宽度。论文给出的例子，是把8个记忆向量减为2个，把宽度从2560减到128。缓存只保存压缩核心，需要解读时再用轻量投影恢复到解码器可接收的宽度。

训练初期还有一条池化残差，帮助优化稳定。它逐渐衰减，前一阶段训练结束后不再依赖完整隐藏状态。这个细节很关键：若服务时还必须读取原始宽向量，低维缓存省下的空间就不能真正兑现。

解码器接收按时间拼接的物品表示，以及普通指令、动作等文本信息。它可以回答用户兴趣问题，也可以生成结构化画像。物品表征共享，并不意味着不同用户最终拿到相同的画像；用户消费了哪些物品、以什么顺序和动作消费，仍然决定输入。

训练分四阶段推进。先让冻结的解码器从记忆中重建原文，训练压缩器保留基本信息；再加入问答任务和投影器，让记忆保留用户理解需要的证据。随后联合更新压缩与解码两端，使接口彼此适应。

最后用强化学习减少幻觉。此时冻结压缩器和投影器，只更新解码器。奖励既惩罚几种具体错误，也奖励回答完整度，防止模型靠少说话来规避错误。奖励判断仍会对照原始文字，而非只在压缩结果内部自我检查。

长序列训练还按难度逐步增加物品数量。消融显示，把所有长度一开始混在一起，会让优化停滞；不同阶段继承参数，也有助于避免训练损失下降而验证误差上升。学习如何压缩与学习如何读压缩输入，需要同步安排。

3. 核心贡献：缓存能否共享，取决于表示依赖什么

KuaFu的共享收益来自物品表示不依赖具体用户和目标任务。物品变了才需要更新物品缓存，用户新增互动则主要改变拼装后的序列。这让表示库随物品规模增长，而不是为每个用户、每个任务各存一套长历史表示。

论文强调的另一点是直接检查保真。它除了看画像准确率，还测试压缩后能否找回藏在长历史中的事件，以及能否避免把事件日期和结论弄错。这些中间指标比等待完整线上实验更快暴露压缩损伤。

不同“压缩倍数”对应不同对象。按向量元素数计算，上述投影前后为8×2560和2×128，两者比值是80。与原始文本输入相比，解码器看到的序列缩短又是另一种口径。存储、文本长度和整条服务成本不能混在一个倍数里。

4. 实验：效率如何转化为更新质量

下面选取四个生产指标。F1衡量兴趣提取的查准与查全，分类准确率用于相对稳定的画像属性；它们不是同一个任务的统一分数。

内容兴趣任务的单卡吞吐从每分钟40个请求升到180个。按(180−40)/40计算，增加350%；也就是原来的4.5倍，而非3.5倍。论文报告多个任务合计节约190张解码侧GPU，不能把单一任务的倍数套到全部硬件。

公开推荐评测里，压缩后的4B模型超过同规模骨干，说明收益不只来自增大模型。但在CDs子集它也出现退步，这提示压缩优势会随领域变化。通用阅读理解和私有画像任务各有自己的协议，不能把不同评测的提升数字拼成一个统一效果。

强化学习评测中，编造率从33.5%降到4.5%。完整回答程度基本维持，支持奖励不只是把模型训练成少答。评分依赖模型裁判，论文另给人工评审与第二裁判的一致性分析；这比只用训练奖励报告成功更有说服力，但仍不等于所有生产错误都被覆盖。

线上按独立访客随机分组，并保持相同资源预算。实验组用压缩省下的资源把历史覆盖拉长、画像更新加快；整体GMV提高1.37%，置信区间为正。对照组仍是较短历史、较慢刷新，因此这个结果支持整套画像升级，无法单独归因于投影器或某一个训练阶段。

5. 局限：共享表示也会固化取舍

作者指出，目前不同任务族使用固定压缩比例，内容差异很大时未必最合适。信息密集的物品可能需要更多记忆空间；极短内容则可能不值得分配同样预算。自适应压缩仍是未来工作。

工业日志和生产训练数据不能公开，外部只能复核公开基准及已披露的实现细节。部分私有任务用大模型打分，也会继承裁判的偏差。数字看起来覆盖多个任务，并不意味着它们都是独立人工标注的客观真值。

工程上还要考虑缓存版本。物品内容更新、压缩器升级或解码器接口改变后，旧向量是否仍兼容，需要明确策略。跨用户复用降低重复计算，也放大了单个物品缓存错误的影响范围。这是从架构推导出的部署注意点，不是论文报告的线上故障。

6. 工业实践意义：从重复编码最严重的地方切入

对社区帖子、商品和视频，如果同一内容频繁出现在不同用户历史里，可以统计重复文本编码占比。以物品为键复用表征是否划算，取决于真实共享率、内容更新频率和向量存储成本，不能只看用户数巨大。

评估时可并列检查兴趣标签、时间归属和证据找回。一个表示也许足够判断职业，却不足以回答最近为何点击某类帖子。任务粒度的保真测试能决定哪些画像适合共享压缩，哪些仍需读取原始证据。

上线实验应把表征、历史覆盖与刷新周期作为清楚的变量。先固定其中两项观察第三项，再考虑组合升级，才能解释节约的资源究竟通过什么路径改善结果。KuaFu提供了把算力节省转成更新能力的实例，也提醒我们将效率指标与业务因果归因分开。
