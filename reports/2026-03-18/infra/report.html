1. SageSched: Efficient LLM Scheduling Confronting Demand Uncertainty and Hybridity
4.10
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: SageSched 针对 LLM 推理调度面临的两大核心挑战——输出长度不确定性（unpredictable output lengths）和计算/内存资源异质性（resource hybridity）——提出了一套高效调度框架。系统通过提示词内容和历史数据预测输出长度分布，构建同时考虑计算与内存资源的服务成本模型，并实施不确定性感知的调度策略。在多种配置的测试床评测中，SageSched 相比现有调度器实现了超过 28.7% 的效率提升。

Key insight: SageSched 的核心创新在于将输出长度预测与资源感知调度紧密耦合，解决了现有调度器（如 vLLM 的 FCFS、Orca 的迭代批处理）将计算和内存资源割裂处理的缺陷。对于搜索/推荐系统中的 LLM 推理服务，该方法可直接降低 P99 延迟、提升 GPU 利用率，尤其适合请求长度差异大的场景（如 query 改写、长文档摘要混合部署）。实践建议：将输出长度预测器作为调度层插件集成到现有 serving 框架。

2. Leech Lattice Vector Quantization for Efficient LLM Compression
4.10
Relevance 4 | Novelty 5 | Practical 3 | Evidence 4 | Timely 5

Summary: LLVQ 利用 Leech 格（24 维空间中已知最优球填充格）对 LLM 权重进行向量量化压缩，突破了标量量化在极低比特率下的性能天花板。方法通过扩展搜索算法支持 Leech 格的索引和角度搜索，并提出全并行化的去量化内核，无需显式存储码本。在压缩质量上全面优于 Quip#、QTIP 和 PVQ 等当前最先进方法，提供了更强的理论保证。

Key insight: Leech 格向量量化的关键优势在于利用 24 维空间最优球填充的几何性质实现信息密度最大化——这是目前已知的数学最优构型。对于搜索/推荐系统中的大模型边缘部署或成本敏感场景，该方法可在维持模型质量的前提下大幅降低权重存储量和传输带宽。工程落地的关键下一步是将并行去量化内核集成到 vLLM/SGLang 等主流推理框架，使其能直接受益于 Leech 格编码的权重。

4. ICaRus: Identical Cache Reuse for Efficient Multi Model Inference
4.00
Relevance 4 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 在多智能体 AI 系统中，多个 LLM 需对相同提示词（如系统提示、共享上下文）独立计算并存储 KV cache，造成严重的显存冗余。ICaRus 通过识别跨模型的相同 KV cache 片段并实现跨模型复用，从根本上消除这一冗余。该方案在 multi-agent 推理场景下显著降低显存占用，使同等硬件能支撑更多并发模型实例或更大 batch size。

Key insight: ICaRus 揭示了多模型推理中 KV cache 跨模型复用的可行性，这对于搜索/推荐系统中的多阶段 LLM pipeline 具有直接价值——例如 query 理解、候选生成、重排序各使用独立模型但共享系统提示的场景。核心工程考量是如何在动态 batching 场景下高效管理跨模型 cache 的共享与失效，以及处理不同模型 attention head 维度不一致的兼容性问题。

5. RelayCaching: Accelerating LLM Collaboration via Decoding KV Cache Reuse
4.00
Relevance 4 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 多智能体 LLM 协作架构中，不同 LLM 之间存在大量冗余 prefill 计算——多个模型反复处理相同或高度相关的上下文。RelayCaching 提出在 LLM 协作时直接复用上游模型的解码 KV cache，通过「接力」（relay）方式将 cache 传递给下游模型，跳过重复的 prefill 计算。该方案有效降低多智能体系统的端到端延迟和计算成本。

Key insight: RelayCaching 的接力 cache 复用思路为搜索/推荐系统中多阶段 LLM pipeline 的延迟优化提供了新路径，尤其适合 RAG 场景中检索器和生成器之间传递长上下文的情形。实践中需重点关注不同模型间 KV cache 格式的兼容性（特别是 GQA vs MHA 的 head 维度差异），以及如何在模型版本迭代时维护 cache 有效性。

6. SemantiCache: Efficient KV Cache Compression via Semantic Chunking and Clustered Merging
4.00
Relevance 4 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 现有 KV cache 压缩方法普遍在 token 或任意 chunk 粒度上操作，破坏语言单元的语义连贯性，导致不可逆的信息损失。SemantiCache 首先对文本进行语义分块（semantic chunking），确保每个 chunk 是语义完整的单元，然后通过聚类合并（clustered merging）对相似 KV 进行压缩合并。该方法在维持语义完整性的同时实现有效压缩，尤其适合长上下文 LLM 推理场景。

Key insight: SemantiCache 的语义感知压缩思路揭示：KV cache 的压缩粒度应与语言的自然语义边界对齐，而非任意切割。对于搜索系统中的长文档理解和 RAG 场景，该方法在降低显存压力的同时更好保留关键语义信息；与 vLLM prefix caching 机制结合时，可实现 prefill 复用 + decode 压缩的双重优化。建议在文档摘要、多轮对话等长上下文任务中优先评测。

7. Self-Indexing KVCache: Predicting Sparse Attention from Compressed Keys
4.00
Relevance 4 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 在长上下文和大 batch LLM 推理中，KV cache 成为主要内存瓶颈。现有稀疏注意力方法将稀疏性预测和压缩作为独立模块，依赖辅助索引结构，引入额外内存和计算开销。Self-Indexing KVCache 将两者统一：压缩后的 key 直接用于预测注意力稀疏模式，消除了独立辅助索引的需求，以更简洁的架构实现高效的长上下文推理。

Key insight: 将稀疏注意力预测与 key 压缩统一为单一模块的设计大幅降低工程复杂度，其核心洞察是：压缩后的 key 保留了足够的结构信息来预测注意力稀疏模式，无需单独的索引结构。对于希望在搜索/推荐系统中部署支持长上下文的 LLM 的团队，该方法提供了更轻量的稀疏推理路径；建议与 FlashAttention 的稀疏变体结合评估端到端加速效果。

9. PAT: Accelerating LLM Decoding via Prefix-Aware Attention with Resource Efficient Multi-Tile Kernel
3.90
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 3

Summary: LLM serving 中 decode 阶段因每步需从全局显存加载全部 KV cache 而受到内存带宽严重制约。PAT 发现实际工作负载中存在大量层次化共享前缀（系统提示、few-shot 示例等），提出前缀感知注意力机制和资源高效的 multi-tile CUDA kernel，通过复用共享前缀的 KV 数据减少重复显存访问，有效提升 decode 吞吐量。

Key insight: PAT 的前缀感知 decode kernel 与主流 serving 框架的 prefix caching 机制天然协同：prefix cache 消除了 prefill 重复计算，PAT 则进一步优化 decode 阶段对共享前缀 KV 的访问模式，形成完整的前缀优化链路。对于搜索/推荐系统中大量请求共享相同系统提示的场景（如统一的 query 改写指令），PAT 可在不修改模型的前提下显著降低 decode 延迟；multi-tile kernel 设计也为其他 kernel 级优化提供了参考架构。

10. Justitia: Fair and Efficient Scheduling of Task-parallel LLM Agents with Selective Pampering
3.55
Relevance 4 | Novelty 3 | Practical 4 | Evidence 3 | Timely 3

Summary: 在共享 GPU 环境中服务任务并行 LLM 智能体时，调度器需同时满足快速完成和用户公平性两个看似矛盾的目标。Justitia 提出选择性偏爱（selective pampering）策略：识别关键路径上的并行子任务并优先分配 GPU 资源，在不牺牲整体调度公平性的前提下加速智能体的端到端完成时间。

Key insight: Justitia 的选择性偏爱思路对于搜索/推荐系统中混合优先级的 LLM 服务具有参考价值：在共享推理集群中优先保障关键路径任务（如实时搜索请求）的 GPU 资源，同时避免低优先级任务（如离线评估、批量标注）被无限期饥饿。该策略可作为 vLLM 等框架调度层的补充机制，特别适合同时托管在线推理和离线批处理的混合集群。
