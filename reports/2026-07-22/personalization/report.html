Uncertainty as Remedy: Mitigating Satisfaction Label Bias in Short Video Multi-Objective Ensemble Ranking

针对短视频多目标排序中点击、时长、点赞等代理标签互相冲突并偏离真实满意度的问题，快手提出 UAME：把满意度分数建模为高斯变量，以均值预测排序分、方差刻画冲突不确定性，再用概率成对损失和样本级自适应加权直接修正训练偏差。离线实验中，相对 EASQ 的 pCTR GAUC 从 0.672 提至 0.734，问卷满意度 NDCG@5 提升 8.71%。

深度解读：UAME

1. 问题与动机

短视频推荐真正想优化的是用户的综合满意度，但这个变量无法直接观测。工业系统通常先用多任务模型估计点击、观看时长、长播、完播、点赞、关注、评论、分享等多个 pxtr，再把这些分数融合成最终排序分。问题在于这些行为只覆盖满意度的不同侧面，且经常给出互相矛盾的顺序：某视频可能更容易被点开，却不一定带来长播或正向互动。EMER、Pantheon、HarmonRank 等端到端融合方法虽然去掉了手工公式，训练时仍默认每个样本对、每个代理标签同样可信；一致样本容易主导梯度，真正决定满意度边界的高冲突样本反而学习不足。已有不确定性推荐方法大多在推理后以置信上界或分数校正做探索，没有把不确定性用于修正训练标签偏差。论文因此把核心问题改写为：能否从多目标冲突中学习样本级不确定性，并用它重新分配训练注意力，使代理风险更接近真实满意度风险？作者还利用问卷满意度作为近似真值，验证这种不确定性并非任意噪声：在 300 万样本上，它与代理标签偏差的 Pearson、Spearman 相关系数分别为 0.65 和 0.67。

2. 方法详解

UAME 接收用户、上下文、物料特征以及预训练 MTL 产生的多维 pxtr。任意 EMER 或 EASQ 主干先生成共享表示，顶部接两个轻量两层 MLP：均值分支输出满意度分数 μ，方差分支输出 log σ²，再通过指数函数保证 σ² 非负。于是每个候选不再是确定标量，而是高斯随机变量 N(μ,σ²)。对候选 i、j，假设二者条件独立，则分差仍为高斯；“i 排在 j 前”的概率等于标准高斯 CDF 作用于 (μ_i-μ_j)/sqrt(σ_i²+σ_j²)。论文对每一个 pxtr 构造二元成对标签，以该概率计算交叉熵式 probabilistic pairwise ranking loss。预测顺序正确时，优化会拉大均值差并缩小方差；标签冲突时，模型可增加方差表达不确定，而不是被迫输出折中分数。

单靠概率损失存在把所有方差无限放大的捷径，因此作者加入方差正则项。为让方差明确对应多目标冲突，又按某物料在不同 pxtr 排名中的标准差构造不确定性辅助成对标签，以 logistic loss 约束高冲突物料应有更大方差。随后把一对物料的综合不确定性定义为 σ_i+σ_j，在当前候选集合内做 min-max 归一化，并以缩放因子 γ 放大高不确定样本对的权重。最终损失由加权的多 pxtr 概率排序损失、方差正则和辅助约束共同组成。实现中用户/物料 embedding 为 32 维，pxtr embedding 为 8 维，Adagrad 学习率 0.001；正则系数 α=0.02、辅助损失系数 β=0.1、权重缩放 γ=2。线上服务只用 μ 排序，σ 分支及所有成对计算仅在训练期存在，因此不改变原在线排序链路，也不增加排序阶段推理延迟。

3. 核心技术贡献

第一，论文把多目标冲突从“要消除的噪声”转化为可学习信号：方差不是泛化意义上的模型置信度，而是同一用户—物料在多个行为代理下排序冲突的量化。第二，它推导出解析的高斯成对胜率，把均值排序与不确定性联合训练；相较 RankDist、EBRank 只在推理阶段调分，UAME 直接作用于优化过程。第三，样本级自适应权重专门强调高冲突物料对，区别于 ANSL 按损失大小衡量一般“困难样本”，理论上通过代理风险分解把这种权重与真实满意度偏差联系起来。第四，方法是主干无关的插件：在 EMER 与 EASQ 两种结构上均取得增益，且上线时裁掉方差支路，实现训练复杂、服务简单。相对 EMER，关注预测 GAUC 从 0.684 提至 0.724，最高相对增益 5.8%；相对 EASQ，长播 GAUC 从 0.668 提至 0.763，增益 14.2%，点击 GAUC 从 0.672 提至 0.734，增益 9.2%。

5. 局限与未来方向

论文没有独立的 Limitations 章节，也没有在结论中系统陈述限制。正文可以确认的边界包括：实验只来自单一大型短视频平台；数据规模、样本构成、特征集合及问卷采样策略未公开；训练硬件、batch size、训练时长也未给出，因此外部团队无法完整复现。理论分析依赖“pxtr 冲突与预测不确定性正相关”的经验假设，虽然 300 万样本的相关性提供支持，但相关并不证明方差只由满意度偏差造成，曝光偏差、分布漂移与偶发行为也可能贡献方差。线上长期指标提升远小于互动指标，尚不能证明该方法会改善数周或数月留存。未来应在不同内容形态、不同代理标签数量和跨域冷启动下验证，并比较问卷、主动负反馈、重复消费等多种满意度真值。

6. 工业实践意义

对社区搜索与推荐，最值得采用的是“冲突诊断—训练加权—服务裁枝”三段式。先统计点击、长停留、收藏、评论、关注等目标对同一候选对的排序冲突，再以双头模型学习均值与 log 方差；训练时用方差找出代理偏差最大的样本对，服务时仍输出单一排序分。这样能保留现有精排主干、特征平台和 serving 接口，工程风险低于重写多目标架构。上线前应建立三层验收：离线看各目标 GAUC 与问卷/人工满意度 NDCG，灰度看互动指标是否一致改善，长期看留存与内容生态是否被高互动目标透支。需要避免把方差直接当作“坏内容”惩罚，否则会再次退化为后处理调分；它在本文中的价值是告诉优化器哪些样本更值得学习。还应监控方差分布漂移、min-max 归一化的极值敏感性和成对样本数量带来的训练成本，并复用作者的 log-variance、分母小常数和训练期分支裁剪做数值与延迟保护。

深度解读：WHALE

1. 问题与动机

大规模推荐排序依赖两类互补信号：一类是用户、物料、上下文及显式交叉等非序列特征，另一类是数千到上万步的用户行为历史。Wukong 通过可堆叠的高阶交互模块扩展前一类信号，HSTU 则以序列注意力扩展后一类信号，但生产模型通常沿两条独立路线演进，或在末端做一次浅层拼接。浅耦合的缺陷是：静态交叉无法在每一层有针对性地从长历史中寻找证据，序列分支也不能持续接收当前候选和上下文形成的交互查询。单独加宽或加深任一主干还会快速增加 FLOPs、内存带宽与延迟，难以满足大流量排序的 QPS 预算。WHALE 的动机因此不是简单把两个强模型拼起来，而是在每个递归层保留 Wukong 和 HSTU 的完整能力，并让二者逐层交换信息。论文用 Meta 大型短视频平台的 800 亿训练样本和 40 亿评测样本验证：在同等复杂度下，统一架构优于单一路线；线上主指标超过 0.03% 即被视为显著，而 WHALE 达到 0.113%。

2. 方法详解

每个 WHALE 层包含 Wukong 模块、HSTU 模块和注意力融合模块。Wukong 接收用户、物料、上下文与交叉字段，产生高阶 interaction representation；HSTU 对长行为序列建模，产生逐位置的 behavior representation。融合时，Wukong 表征经线性投影成为 query，HSTU 表征成为 key/value，点积注意力让当前候选—上下文交互主动检索历史中最相关的细粒度行为证据。注意力输出再经过 fusion MLP 与 SwiGLU FFN，回注到下一层，因此第 ℓ 层的交叉特征会影响后续序列证据选择，而不是只在顶部进行一次信息混合。作者以 2、4、6、8 层，64、128、256、512 宽度，以及 3k、6k、10k、15k 序列长度分别做 scaling，证明三个方向在测试范围内均持续带来 NE 改善。

系统侧针对注意力中的不规则长度和高吞吐矩阵运算编写 Triton kernel，并沿 query 维切分反向计算，减少中间张量与同步。SwiGLU 原本上投影、门控投影和下投影需要三次主要矩阵乘；WHALE 共享门控相关投影，将其从三次降到两次，即减少 33%。密集主干与 FFN 使用 BF16，损失与任务头等数值敏感部分保留 FP32；再用 torch.compile/TorchInductor 做算子融合、内存规划与图级优化。训练使用 NVIDIA B200、全局 batch 与优化器配置在各基线间保持一致，每个模型训练一轮。论文没有给出优化器名称、确切 batch size 或 B200 数量，这些并非摘要遗漏，而是正文也未披露的复现边界。

3. 核心技术贡献

第一，WHALE 提出逐层 progressive fusion：Wukong 的候选交互表征不是被动拼接，而是作为 query 重复检索 HSTU 的长历史，使静态高阶交叉与动态行为证据形成闭环。第二，论文证明“统一两个 scaling 轴”比只扩大一个轴更有效；在 8、14、32 GFLOPs 三档，WHALE 的 NE 增益分别为 0.40%、0.83%、1.39%，而匹配复杂度的 HSTU 仅为 0%、0.04%、0.06%。第三，模型—系统协同把研究结构变成可上线系统：定制内核、共享门控、混合精度和编译优化共同使训练吞吐提升 30%，并把额外 serving 成本压到 5% QPS。第四，消融把收益定位到具体结构：浅层混合相对完整 WHALE 回退 0.25% NE，平均池化替代注意力回退 0.23%，移除 fusion MLP 和 SwiGLU 分别回退 0.11% 和 0.08%，说明候选条件检索与融合后的非线性变换都不可省略。

5. 局限与未来方向

论文没有专门的局限章节。作者明确给出的实验范围是单一大型短视频社交平台、单一主 engagement 预测任务和受匿名化约束的线上指标；因此跨电商、搜索或长内容场景的外推尚未验证。正文未披露数据字段、正负样本比例、优化器、batch size、硬件规模及线上流量比例，外部复现只能重建结构，不能复刻训练经济性。Scaling 曲线在 15k 序列、8 层、512 宽度处仍上升，但这不等于继续扩大一定划算，因为 FLOPs 从序列基线的 9 增至 38、宽度实验最高达 141 GFLOPs。论文也没有比较更简单的 late-fusion 加蒸馏、缓存或多阶段路由在相同 QPS 下的收益。未来应报告质量—延迟—成本 Pareto 曲线，公开至少一个可复现实验配置，并研究对新用户、稀疏历史和分布漂移的分组效果。

6. 工业实践意义

对于 UGC 搜索/推荐，WHALE 最直接的启示是让“当前 query/候选/场景交叉”成为读取长行为历史的查询，而不是对所有历史先做固定池化。可以从低风险版本开始：保留现有 DCN/Wukong 类精排分支和序列 Transformer，只增加一到两层候选条件 cross-attention，离线比较 nDCG、CTR 校准与 NE，再逐步增加层数和历史长度。系统侧应同步建立 FLOPs、显存、训练 QPS、推理 QPS、P99 延迟五维预算；若仅复制模型结构而忽视定制 kernel，5% QPS 回退可能被放大到不可上线。共享门控、BF16/FP32 分区及编译图融合属于相对通用的优化，可先于完整模型落地。还应复现四个消融：浅融合、平均池化、去 MLP、去 SwiGLU，以确认本业务的收益究竟来自候选条件检索还是单纯增参。对于搜索场景，query 表征还可与候选帖子交叉后共同查询用户历史，从而把“这个用户过去喜欢什么”收紧为“这个用户在当前 query 下的哪些历史行为最有证据价值”。
