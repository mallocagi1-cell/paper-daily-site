1. Observation, Not Prediction: Conversation-Level Disaggregated Scheduling for Agentic Serving
4.10
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 4

Summary: 这篇论文研究 Agent 服务中的多轮推理调度：现有系统以单轮 turn 为调度单位，必须预测 decode 长度、工具行为和 KV 增长，导致调度误差。作者提出 ConServe，把调度单位提升到 conversation，利用可观测的一轮输入长度和 decoder KV 占用来完成 placement：首轮 prefill 送到高吞吐 prefiller，KV cache 只迁移一次，后续长尾固定在同一 decoder。实验中，相比逐轮预测基线，ConServe 将 p95 time-to-first-effective-token 降低 51.08%，能效提升 7.51%，异构 GPU 分层映射后能效再提升 22.75%。

Key insight: 这篇工作的启发是：对多轮搜索 Agent 或复杂 RAG 工作流，关键不是更准地预测每一轮，而是换一个更稳定的调度边界。把会话作为资源分配单元，可以减少 KV 迁移次数并稳定长尾 decode 资源，对需要保障首响和多轮上下文连续性的搜索问答系统很实用。

2. FlexNPU: Transparent NPU Virtualization for Dynamic LLM Prefill-Decode Co-location
4.08
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 4

Summary: 这篇论文面向国产 NPU 上的大模型服务，指出直接暴露物理 NPU 会限制运行时调度，尤其难以处理 prefill 计算密集、decode 受内存带宽和 KV-cache 约束的阶段差异。作者提出 FlexNPU，在用户态拦截 AscendCL API，将 NPU 操作路由到设备守护进程，从而在不改模型代码、框架或驱动的情况下实现透明虚拟化和动态 PD 共置。实验显示，在 384 卡 Ascend 910C 部署 DeepSeek-R1 时，相比静态 PD 解耦吞吐提升 5.15% 和 26.33%；在 Qwen2.5-7B 上，TTFT 降低超过 92%。

Key insight: 核心价值在于把 NPU 从“裸设备”抽象为可调度资源，让推理系统能按 prefill/decode 阶段动态调整共置策略。对社区搜索和 RAG 服务来说，这类虚拟化层可以降低首 token 延迟，同时保留既有模型与框架栈，是国产算力集群上做多模型、多租户推理服务时值得借鉴的系统设计。

3. Omni-Flow: A Unified Workflow Orchestration and Distributed KV Cache Sharing Framework for Multimodal Inference
3.98
Relevance 4 | Novelty 4 | Practical 4 | Evidence 3 | Timely 4

Summary: Omni-Flow 面向从纯文本 LLM 扩展到多模态推理后的服务复杂度：不同计算单元存在依赖关系，中间张量需要跨进程/跨节点高速传输，KV cache 和模型权重也容易重复占用 GPU 显存。论文提出三层抽象：Control Flow 用 Python DSL 描述静态 DAG 和动态路由；Data Flow 提供跨 GPU/CPU/SSD 的分布式 KV cache 与零拷贝传输；Compute Flow 通过统一 SGLang 接口接管 KV 复用和采样逻辑。作者展示其可支撑 LongCat-Next 全模态对话和 HunyuanImage-3 图像生成流水线。

4. CacheFlow: Efficient LLM Serving with 3D-Parallel KV Cache Restoration
3.88
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 2

Summary: CacheFlow 针对长上下文 LLM 服务中的 KV cache 恢复瓶颈，指出现有方案常在“重算”和“从外部存储加载”之间按请求做局部权衡，忽略 token、layer 和 GPU 之间的并行结构，也没有充分考虑批处理服务中的资源竞争。作者提出 3D parallel KV cache restoration，把恢复任务拆到 token、layer、GPU 三个维度，并用 batch-aware two-pointer scheduler 按边际重算成本收益分配计算与 I/O。实验表明，在多种模型、工作负载和硬件下，CacheFlow 相比已有方法将 TTFT 降低 10%-62%。

Key insight: 对 RAG、多轮对话和 Agent 搜索而言，KV cache 恢复已经是首响延迟的核心瓶颈。CacheFlow 的启示是把缓存恢复当成可并行调度的系统任务，而不是简单的存取策略；当业务侧上下文越来越长时，调度器需要同时看层级依赖、GPU 拓扑和批内请求收益。

5. Joint Structural Pruning and Mixed-Precision Quantization for LLM Compression
3.81
Relevance 4 | Novelty 4 | Practical 3 | Evidence 4 | Timely 4

Summary: 这篇论文针对 LLM 部署中的压缩问题，指出传统 PTQ 常按层独立优化量化误差，忽略误差在全模型中的传播；剪枝和量化顺序执行也会造成次优解。作者提出联合结构化剪枝与混合精度量化框架，在统一搜索空间内同时学习剪枝决策和量化策略，并直接最小化全局误差传播。实验显示，在 1-3 bit 超低精度下，相比权重-激活量化 SOTA，WikiText perplexity 最多降低 21%；相比权重量化方法，在 WikiText 和 C4 上 perplexity 分别最多降低 59% 和 85%。

Key insight: 对于成本敏感的搜索排序、Embedding 生成和在线 RAG 服务，单独做剪枝或量化很容易把误差推到下游层放大。该方法提示工程团队应把压缩策略作为全局优化问题处理，尤其在 1-3 bit 这类激进部署目标上，联合搜索比流水线式压缩更可能保住推理质量。

6. dMX: Differentiable Mixed-Precision Assignment for Low-Precision Floating-Point Formats
3.81
Relevance 4 | Novelty 4 | Practical 3 | Evidence 4 | Timely 4

Summary: dMX 关注低精度浮点格式下的逐层混合精度分配，认为统一 bit-width 会在性能和精度之间产生次优折中。作者把 OCP MXFP 系列格式的层级选择转成连续优化问题，用一个可学习 offset 表示每层浮点格式，并通过温度退火逐步离散化，最终映射到硬件兼容格式；同时用目标感知正则约束平均 bit-width。论文在 Llama、Qwen3 和 SmolLM2 上评估 WikiText-2 perplexity 与 4 个 zero-shot reasoning benchmark，结果显示 dMX 相比 KL 散度层选择启发式能得到更优的质量-位宽 Pareto 前沿。

Key insight: 这篇论文适合指导“按成本预算部署模型”的推理平台：不要只用固定 8-bit/4-bit 配置，而应让不同层承担不同精度预算。对社区搜索中的在线召回、重排或摘要模型，dMX 这类可学习分配方法能把压缩目标和硬件格式对齐，减少人工试错。

7. EvalStop: Using World Feedback to Detect and Correct Reward Overoptimization in Multi-Tenant RLHF Platforms
3.74
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 4

Summary: EvalStop 面向多租户 RLHF 微调平台，问题是 reward model 在持续优化下会偏离真实下游评测，现有调度器却只优化 JCT 或训练损失，无法及时停止奖励黑客化作业。作者提出可组合的调度原语：当 eval score 连续 k 次下降时终止作业、释放 GPU、保留最佳 checkpoint，并可接入任意基础调度器。在 80% RLHF、64 GPU 的模拟工作负载上，EvalStop 达到 98% precision、99% recall、1.5% FPR，同时 JCT 改善 9%，浪费计算降低 22%；在不同基础调度器上 JCT 收益为 9-25%。

Key insight: 这篇工作的重点不是新的 RLHF 算法，而是把质量信号纳入训练平台调度。对需要频繁微调搜索理解、排序或 Agent 策略模型的团队，平台层面应把 eval 退化视为资源回收信号，而不是只看 loss 或队列时间，否则 GPU 会被已经“越训越坏”的任务长期占用。
