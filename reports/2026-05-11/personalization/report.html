UniVA: Unified Value Alignment for Generative Recommendation in Industrial Advertising

UniVA 是腾讯视频号广告团队提出的生成式推荐框架，统一建模用户兴趣对齐与商业价值对齐两条目标。框架包含三个核心模块：把广告价值属性嵌入语义 ID 的 value-aware tokenizer；通过强化学习联合训练生成与排序的 decoder；以及面向在线服务的个性化 beam search。在腾讯视频号场景上，UniVA 离线 Hit Rate@100 提升 37.04%，线上 A/B 测试 GMV +1.5%。

UniVA：腾讯视频号广告生成式推荐的统一价值对齐

1. 问题与动机

UniVA 直面工业广告场景下生成式推荐 (Generative Recommendation, GR) 的"价值不一致"问题。作者明确指出三个具体缺陷：(a) 价值不敏感的 SID tokenizer——语义相似的广告可能拥有截然不同的商业价值 (eCPM、ROI)，但现有 RQ-VAE / RQ-Kmeans tokenizer 只对齐内容语义，把高价/低价广告合并到同一 codebook 分支；(b) 语义主导的 SID 解码——自回归生成只看上下文语义相关性，对商业价值毫无感知；(c) 价值无知的在线服务——beam search 按生成概率展开，最终再用一个独立的 ranker 排序，重排会冲淡 GR 的分布优势。

论文以 Tencent WeChat Channels 广告系统为基线，引用 GPR (Zhang et al., 2025) 等先前生成式广告方法。基线生成式推荐离线 HR@100 与基线持平，但 wNDCG@100 落后近 26.2%——量化证据表明：纯语义 SID 的生成式范式不能直接迁移到商业广告。这一观察构成本文的核心动机：必须把"商业价值"作为一等公民贯穿 tokenizer→decoder→serving 三阶段。

2. 方法详解

UniVA 的统一价值对齐框架包含三个组件：

(1) Commercial SID Tokenization：分层 SID 设计：(s¹,...,s^{L-1}) 由 RQ-Kmeans+ 语义编码生成，最后一层 s^L 专门承载商业属性。属性压缩把稀疏的优化目标、ROI、行业、出价压缩成有限类别（25 类 OptGoal、8 类 ROI、10 类 industry）；再用"分类后分箱" (Classify-then-Bin) 策略：先按 (OptGoal', ROI', Industry') 分组，组内按出价做等频分箱，并通过加权熵 H = Σ_k w_k H_k 优化分箱粒度，受全局词表预算 Σ_k n_k ≤ V 约束。最终 ψ(k_i, x_i^b) 将"组键-分箱"对映射到全局 token id。

(2) Generation-as-Ranking 双头解码器：以 HSTU 共享 encoder 编码 User/Organic/Environment/Item 上下文 h = Enc(U,O,E,I)。decoder 引入两条扩展轴提升容量：Mixture-of-Experts (64 专家 top-16) 和 Mixture-of-Recursions (递归共享 mid block)。每个 decoding step 产出双头：生成头 o_gen = f_gen(z) 与价值头 o_value = f_value(z)，最终分布 π̃_θ = Softmax(Fuse(o_gen, o_value))，融合采用 element-wise 求和。

(3) SL + RL 联合训练：监督损失 ℒ_SL = -Σ log p_θ(s_{T+1}^l | s_{T+1}^{<l}, h) 训练生成头预测下一 SID。RL 阶段把 eCPM 作为奖励信号，用模拟器从生产快照采样轨迹（替换固定 5% 采样为基于学习难度的自适应采样）；轨迹由 beam search 和 MCTS-PPO 并集 𝒴(h) = 𝒴_beam ∪ 𝒴_{mcts-ppo} 收集；reward 按上下文做 z-score 归一化 R̄ = (R_eCPM - μ_R(h))/(σ_R(h)+ε)。损失为 PPO + value head ℒ_RL = ℒ_PPO + λ_v ℒ_value，与 SL 批次交替训练。

(4) Value-Guided Personalized Beam Search：在线服务时，构造全局合法 SID 路径 trie 𝒯，每个请求按用户/定向规则裁剪得到 𝒯_u；beam search 评分直接复用 fused logits：Score(s_{≤l}) = Σ Fuse(o_gen^t, o_value^t)[s_t]。

训练配置：SID decoder 参数量 3M (base) → 80M (full)，FLOPs 4.1G→23.2G；3 层 SID (2 语义+1 商业 2048)；MoE 64 总专家 top-16；Adam lr=1e-3；batch=16；seq=2048。

3. 核心技术贡献

(a) 价值感知 SID 设计：把商业价值从下游 loss 下沉到 token 级别。这一改动零参数代价就带来 HR@100 +5.78%，本质是把"出价相近的广告塌缩到同一 SID 子树"，让自回归解码直接受益于商业聚类先验。

(b) Generation-as-Ranking 双头融合：传统两阶段范式中，生成阶段输出 top-K 候选再喂给独立 ranker，会稀释 GR 的分布。UniVA 把价值预测下沉到每个 token decoding step，并通过共享 logits 让在线 beam 直接复用，消除了独立 ranker 模块。在线 A/B 实验里，这一改动单独贡献 +0.47% GMV 提升。

(c) eCPM-aware RL with MCTS-PPO：把 beam 和 MCTS 联合做采样，能在 beam search 高似然区之外探索"高价值但低概率"轨迹，并以 z-score reward normalization 稳定训练。

(d) 个性化 trie 约束 beam search：解决了"生成路径不可投放"问题——300 beam width 在无 trie 时只能恢复 48 条合法路径，加 trie 后恢复全部 300 条。

4. 实验结果分析

离线主表 (Table 1，HR@100 相对提升)：GPR+SID Decoder 基线 0%；+ Commercial SID +5.78%；+ Layer2-4 深度 +6.10%；+ MoR +13.56%；+ Sparse MoE +18.40%；UniVA Full +37.04%。可以看到容量扩展（MoE+MoR）贡献了 +18.4%，RL 联合优化在容量基础上又叠加 +18.64pp，说明价值对齐与容量扩展是正交的提升。

价值指标 (Figure 2/3)：2×2048 SID + CSID 配置最佳，ValueHR@100=0.0677，wNDCG@100=0.0554（相比纯语义基线 +26.2%）。同一 SID 路径内出价标准差、P75、P99 都下降约一个数量级——量化证明 CSID 把出价相近的广告聚到一起。

Codebook 尺寸 (Table 2)：2×2048+CSID 在 HR@1 上 +55.56% 提升；2×8192+CSID 反而下降——说明语义 codebook 必须与商业 codebook 容量匹配，否则商业 token 被语义稀释。

线上 A/B (5% 流量, 3 月 7-11 日)：v1 (无 Generation-as-Ranking) GMV +1.03%，v2 (含 GaR) GMV +1.50%，GMV(normal) +1.42%。GaR 单独贡献 +0.47%——这是把"重排融入生成"的关键证据。

值得注意：HR@100 与 GMV 提升比例 (37% vs 1.5%) 差异巨大，是工业 GR 论文的典型现象——离线相对指标天花板高但线上有诸多约束（库存、定向、风控）削减真实增益。

5. 局限与未来方向

论文未单独写局限性章节，可推断的限制包括：(1) RL 依赖离线 simulator 保真度，若与线上分布差异大则 RL 增益会被高估；(2) 商业 SID 的 attribute compression 依赖手工类别划分（OptGoal 25 类、ROI 8 类），换平台需重做；(3) Personalized trie 在用户定向极窄时会塌缩到极少候选，影响多样性；(4) 方法围绕 eCPM/GMV 目标设计，非广告场景（如内容推荐的 dwell time、互动率）的迁移需要重设 reward。

6. 工业实践意义

对社区/UGC 平台的搜索推荐团队，UniVA 提供四个可借鉴 pattern：

(1) 多目标融入 token 级别：与其在排序阶段加多目标 loss，不如把目标（如互动率、停留时长、内容质量分）作为 SID 的额外维度，让生成阶段就感知到——这与"商业 token"是同一思路的不同侧面。

(2) Generation-as-Ranking 替代两阶段：当 GR 已经能产 top-K 候选，再串一个独立 ranker 反而稀释分布。把 ranking 信号下沉到 decoder 共享 logits，可省一整个排序模块且效果更好。

(3) Trie-constrained beam search：UGC 内容也有大量"不可投放/不合规"约束（敏感、未审核、已删除），用 per-request trie 约束 beam 展开，比生成后过滤更高效。

(4) MCTS-PPO 增强 RL 探索：beam search 倾向高似然区，对长尾高价值内容覆盖不足，加入 MCTS 探索是工程上可落地的方案。

部署考虑：UniVA 80M decoder 与 256-dim embedding 的规模在工业上是温和的；论文未给出延迟数字，但 beam width 300 + trie 约束属于可承受范围；离线 simulator 的搭建是工程门槛，需要从线上日志重建可回放的反事实环境。

EKTM: Effective Knowledge Transfer for Multi-Task Recommendation Models

Huawei📖 有深读 · 8 分钟

EKTM 针对 CVR 预估在多任务排序框架中的数据稀疏问题，提出有效跨任务知识迁移方法。引入 router 模块按任务相关性分发共享表示，并通过 transmitter 模块做任务特定的特征变换后再融入目标任务，避免硬共享带来的负迁移。在线上 A/B 测试中带来 3.93% 的 eCPM 提升，已在某商业广告平台的两个主流量场景部署。

INSIGHTEKTM 揭示了多任务推荐里被忽视的细节：CVR 样本极少时，单纯共享底层 embedding 会让强势任务的梯度淹没弱势任务。router+transmitter 的双层路由相当于在 MMoE 之上加了一层任务特定的'整形'，比直接共享专家更安全。对社区 UGC 平台多目标排序（点击、停留、互动、转化）有直接借鉴价值：先用 router 做知识分发，再用 transmitter 做任务自适应变换，是缓解长尾任务负迁移的实用 pattern。

EKTM：多任务推荐的有效知识迁移

1. 问题与动机

EKTM 直击工业推荐多任务学习 (MTL) 中 CVR 任务的"双重数据稀疏"问题：作者在 AliExpress 数据集量化了 CTR vs CVR 的不平衡——CTR 任务的正样本率 1.5-3.63%，而 CVR 仅 0.035-0.088%，相差约 50 倍。这一稀疏性使得 CVR 塔难以学到稳定表征，是工业广告/电商场景中转化预估长期未解的难题。

更关键的是作者指出现有 MTL 方法（MMoE、PLE、ESMM、STEM）的共同局限：它们做的知识共享主要在共享底层 (Shared-Bottom) 或专家层 (Expert)，而越靠近输出层信息越丰富——"representations closer to the output layer contain richer information"。但直接共享靠近输出的高级表征又会带来三重风险：(a) 强势任务（CTR）的梯度淹没 CVR 任务；(b) 不同任务输出尺度差异巨大（CTR vs 时长预估），共享标量输出无意义；(c) 负迁移——任务相关性不足时硬共享反而损害目标任务。

EKTM 的目标是在共享高级表征的同时控制负迁移，让 CVR 任务能"挑选性地"利用其他任务的高级语义。

2. 方法详解

EKTM 在已有 MTL 框架（MMoE/PLE/STEM/Shared-Bottom）顶部插入两个新模块：

(1) Router 模块：负责"知识聚合"。对目标任务 i (CVR)，先计算它与每个辅助任务 t 的归一化余弦相似度 ŝ_{i,t} = softmax_t(cos(f_cvr^i, f_cvr^t))，再做加权聚合 F_i = mean(f_ctr, ŝ_{i,1}·f_cvr^1, ..., ŝ_{i,T}·f_cvr^T)。直觉：相似度高的任务表征获得更高权重，避免"无差别共享"。f_ctr 永远以 mean 中无加权权重出现，是因为 CTR 是 CVR 的天然前置信号（ESMM 思路）。

(2) Transmitter 模块：负责"知识过滤"。聚合后的 F_i 需要再做任务自适应整形才能注入到 CVR 塔——直接相加会引入辅助任务的偏置。Transmitter 用多头交叉注意力 (MHCA)：query/key 来自 F_i，value 来自当前任务的 CVR 主表征 f_ctr；输出经 LSTM-style 门控 g = σ(MHCA(F_i)^T w_f + b_f)，再与 f_ctr 逐元素相乘。门控让模型自动决定每一维的迁移强度，避免硬注入。

(3) Calibration Loss：核心损失设计是关键防负迁移机制：

ℒ = ℒ_ctr + Σ_i [(1-α) ℒ_o^(i) + α · max(0, ℒ_t^(i) - ℒ_o^(i))]

其中 ℒ_o 是不用 EKTM 的原始 CVR 损失，ℒ_t 是经 EKTM 转换后的损失。max 算子保证：只有当 EKTM 转换降低 loss 时才参与训练；若升高 loss 则梯度为 0。这相当于一个"安全护栏"，从理论上排除了 EKTM 比 baseline 更差的可能。α 是混合系数，超参搜索范围 [0.01, 0.1, 1.0]。

训练配置：batch=12,000，lr=1e-3，50 epochs；与已有 MTL 框架 (MMoE/PLE/STEM) 即插即用，不修改 backbone。

3. 核心技术贡献

(a) 靠近输出层的知识共享：以往 MMoE/PLE 在 expert 层共享专家，PLE 才显式区分共享/独立专家。EKTM 进一步把共享下沉到任务塔输出附近，能利用更高层语义。

(b) Router 用任务相似度做软聚合：相似度是数据驱动的（cosine sim），不需要手工指定任务关系图。比 PLE 的固定专家分配更灵活。

(c) Transmitter 用 cross-attention + 门控防过冲：多头注意力天然支持选择性融合；LSTM 门控提供二次过滤。两层选择性保证迁移精准。

(d) Calibration Loss 的 max 安全护栏：是工业落地最关键的设计——它把"迁移失败时不损害目标任务"做成数学约束，免除了 MTL 调参中的负迁移风险。

每个贡献都对应了与 prior work 的具体改进：相比 MMOE baseline 在 AliExpress US 数据上 CTR AUC 从 0.7092 提到 0.7139 (+0.66%)，CTCVR 0.8717→0.8738 (+0.24%)。

4. 实验结果分析

公开数据集 (AliExpress)：在 4 个国家 (US/NL/FR/ES) × 2 任务 (CTR/CTCVR) × 4 个 backbone (Shared-Bottom/MMoE/PLE/STEM) 共 32 个 setting 上，EKTM 几乎全部带来提升。MMOE+EKTM (US): CTR 0.7139 (vs MMOE 0.7092)；PLE+EKTM (NL CTCVR): 0.8653 (vs PLE 0.8639)。

公开数据集 (KuaiVideo)：3 个任务 (Follow/Like/Click)，EKTM 在 Follow 任务 STEM baseline 上从 0.7803 提到 0.7910 (+1.37% AUC)——比 CTR 任务更大，因为 Follow 是稀疏任务，正是 EKTM 设计针对的场景。

消融研究：线性投影 baseline AUC 0.7017；加 Transmitter 0.7102 (+1.21%)；加 Calibration loss 0.7139 (+0.53%)——两个模块都有独立贡献，且互补。

线上 A/B：在某商业平台两个主流量场景灰度发布，5%→20%→50%→100% 渐进放量，最终全量 eCPM +3.93%。

关键观察：(1) EKTM 在 STEM/PLE 等已经做了任务区分的 backbone 上仍能带来增益，说明它捕获了 prior MTL 未利用的信号；(2) 稀疏任务（CVR、Follow）的增益显著大于稠密任务，与设计目标一致；(3) 没有任何 setting 出现负向——印证 Calibration loss 的安全性设计。

5. 局限与未来方向

论文未明写局限。可推断：

(1) 任务相关性假设：Router 默认所有辅助任务都对目标任务有用，只调权重。若辅助任务与目标完全不相关（例如点击 vs 退订），软聚合可能引入噪声——calibration loss 能屏蔽损害但不能消除计算开销。

(2) 多头注意力延迟成本：每个任务 i 都要做一次 MHCA，对 T 个任务复杂度 O(T·d²)。论文未给出 serving 延迟数字，工业大规模部署需要量化。

(3) 超参敏感性：α ∈ [0.01, 0.1, 1.0] 的搜索粒度粗，不同场景可能需要重调；缺少 α 与任务稀疏度的关系分析。

(4) CVR 长链路问题：EKTM 把 CTR 作为前置信号（mean 中无加权），但工业场景下 CTR→CVR 链路还有曝光、加购等中间步骤，纯 CTR 信号未必最优。

6. 工业实践意义

EKTM 对社区/UGC 平台多目标排序的启示：

(a) 即插即用替换 MMoE/PLE 顶层：EKTM 不改 backbone，只在任务塔输出之前插入 Router+Transmitter。社区平台典型的多目标（点击、停留、点赞、收藏、转发、关注）排序如果当前用 MMoE/PLE，可以直接试 EKTM 而不需要重训 backbone。预期对长尾任务（关注、转发）提升更明显。

(b) Calibration loss 是低风险高 ROI 改造：max(0, ℒ_t - ℒ_o) 保证最坏情况不退步，是 MTL 模型迭代里少见的"零风险"改造。建议作为 MTL baseline 的标配引入。

(c) Router 的相似度计算可复用：cosine sim 计算的任务相似度矩阵本身就是宝贵的诊断信号——可以离线观察各任务间相似度变化，判断什么时候新增/废弃任务。

(d) 部署考虑：论文报告 batch=12,000、lr=1e-3、50 epochs 训完；线上灰度 5%→20%→50%→100% 渐进放量是稳妥范式；MHCA 计算成本需要在 GPU/CPU 集群上量化，必要时可降为单头注意力做 trade-off。

Latte: Expressiveness Limits of Autoregressive Semantic ID Generation in Generative Recommendation

UCSDSnap

Latte 系统性分析了生成式推荐中自回归语义 ID 解码的表达力上限：当 item 共享语义 ID 前缀时，模型产出的概率会与 RQ-VAE 树结构强相关，导致同分支下的 item 概率被人为拉平，与真实用户偏好无关。作者提出在语义 ID 序列前插入一段可学习的 latent token，重塑解码空间，使 item 概率脱离树状偏置；在多个公开基准上 NDCG@10 平均提升约 3.45%。

INSIGHT这是对 TIGER/HSTU 系列生成式推荐范式的一个关键理论补丁：之前大家把 RQ-VAE 量化误差当作工程问题，Latte 指出真正的瓶颈是自回归解码的'树状归纳偏置'。在 ID 序列前加 latent prefix 等价于让模型在第一步先输出一个用户/上下文 embedding，再展开 ID 路径，可大幅缓解'同分支同概率'问题。对生成式召回的工程化启示：要么改 codebook 结构，要么在 prefix 上注入丰富的上下文，二选一是必须的。

Light-FMP: Lightweight Feature and Model Pruning for Enhanced Deep Recommender Systems

Hesitator: Decision-aware User Simulation Agent for Evaluating Conversational Recommender Systems

NTU

Hesitator 是一个面向对话式推荐系统 (CRS) 评估的决策感知用户模拟 agent。已有 LLM-based 模拟器普遍存在'用户太爽快'的问题，会无脑接受推荐导致评估失真。Hesitator 把用户决策拆成模块化的 Decision Module：基于效用的 item 选择与基于'选择过载'的承诺决策分离，复现心理-经济学文献中的犹豫、回避、回退等行为模式。

INSIGHT对话式推荐评估的核心问题不是 LLM 模拟器'不像人'，而是它们'决策过快'——少了真实用户面对长候选列表时的认知负担。Hesitator 把效用打分与承诺判断显式拆开，本质上是为模拟器加了一个 'choice-overload prior'。社区平台做 CRS / agentic search 评估时可以借鉴：不要直接用 LLM 当用户，而要先注入决策心理模型再让 LLM 执行，能更准确预测真实场景的承诺率与流失率。
