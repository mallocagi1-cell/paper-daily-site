1. FlashRT: Agent Harness for Guiding Agents to Deploy Real-Time Multimodal Applications
4.25
Relevance 4 | Novelty 5 | Practical 4 | Evidence 4 | Timely 3

Summary: FlashRT 面向实时多模态应用的部署优化，把开发者参考实现转成中间表示，再由编码代理提出、验证并基准测试多 GPU 变换。论文在 NVIDIA B200 上报告最高约 70 倍延迟下降和 2.8 倍吞吐提升；在 AMD MI355X 上，Qwen3-Omni 文本转音频相对专家 vLLM-Omni 实现延迟下降 65%。

Key insight: 它的关键不是让模型“自动写代码”，而是把优化限制在可解释的 IR、静态分析和测量门控闭环内。社区搜索可借鉴这一模式，为 embedding、reranker 或多模态召回建立硬延迟与质量门槛，让自动 kernel/并行化探索只提交经过 nDCG、CTR、P99 延迟验证的变更。

2. SMetric: Rethink LLM Scheduling for Serving Agents with Balanced Session-centric Scheduling
4.00
Relevance 4 | Novelty 4 | Practical 4 | Evidence 5 | Timely 2

Summary: SMetric 面向 Agent 连续发起请求的 LLM 服务，指出纯粹按 KV 命中路由会让少数实例过载；BAILIAN 生产轨迹的跨轮 KV 复用超过 80%，聊天流量约为 54%–62%。它把会话首请求用于负载均衡、后续请求采用缓存感知路由，在 prefill-decode 共置下集群 TPS 提升 10%–16%，解耦部署的 prefill TPS 提升 2%–34%。

Key insight: 多轮 query 改写、RAG 和搜索 Agent 都会产生强会话局部性，不应把“缓存命中”当成每个请求的唯一目标。可先用无状态的会话轮次信号分散首请求，再让后续请求复用本地 KV，并同时监控全局 KV 迁移成本、TPS、P99 和缓存命中率。

3. MetaInfer: A Knowledge Only LLM Inference Engine Generator SKILL Toolbox
3.85
Relevance 4 | Novelty 5 | Practical 3 | Evidence 3 | Timely 3

Summary: MetaInfer 将推理引擎生成视为“LLM-as-Compiler”问题：用户提供运行约束，LLM 多智能体协作系统结合契约知识库，生成并验证面向模型、硬件、量化和并行策略的紧凑引擎。论文从源码参考、零参考运行行为、知识库演化 3 个角度评估，代码已公开，但摘要未给出统一吞吐或延迟数字。

Key insight: 对社区搜索而言，价值在于把硬件适配和 serving glue code 变成可验证的知识资产，而不是直接替代成熟引擎。落地时应把 CUDA/算子、显存、P99 延迟和相关性回归写成契约，要求生成结果通过 replay、压力和质量三重测试后才进入线上。

4. ModeSwitch-LLM: A Lightweight Phase-Aware Controller for Cross-Mode LLM Inference on a Single GPU
3.63
Relevance 4 | Novelty 3 | Practical 4 | Evidence 4 | Timely 2

Summary: ModeSwitch-LLM 在请求边界根据轻量 workload 特征选择 FP16、量化、投机解码或混合模式，避免所有请求使用同一 serving 配置。以 Meta-Llama-3.1-8B-Instruct 和单张 NVIDIA A100 评估，平均延迟相对 FP16 加速 2.10 倍、每 token 能耗降至 0.48 倍，质量门控的平均变化为 +0.17 个百分点。

Key insight: 短文本搜索的查询长度、输出长度和缓存状态差异很大，单一精度或批处理策略会浪费资源。可以先以规则路由做低风险试点：短 query 走低延迟模式、长上下文走 KV/量化模式，并把 nDCG、CTR、P99、能耗和显存约束作为切换条件，再评估是否需要学习型路由器。
