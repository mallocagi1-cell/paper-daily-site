From Inference Routing to Agent Orchestration: Declarative Policy Compilation with Cross-Layer Verification

针对 LLM 推理服务中请求级路由策略难以管理和验证的问题，提出 Semantic Router DSL——一种非图灵完备的声明式策略语言，已在生产环境中部署。系统将内容信号（embedding 相似度、PII 检测、越狱评分）输入加权投影和优先级决策树，实现模型选择、隐私策略执行和结构化审计追踪。通过跨层编译验证确保策略的一致性和安全性，从推理路由扩展到 Agent 编排场景。

Rethinking Attention Output Projection: Structured Hadamard Transforms for Efficient Transformers

Multi-Head Attention 的稠密输出投影层参数量随模型维度二次增长，显著占据参数总量、内存和推理成本。本文提出用固定的无参数 Walsh-Hadamard 变换 (WHT) 加对角仿射变换替代该投影，消除了 O(d²) 的参数矩阵，将投影操作降为 O(d log d) 复杂度。实验表明该方法在保持模型性能的同时大幅减少参数量和推理延迟。

INSIGHT用结构化 Hadamard 变换替代 Attention 输出投影是一种范式级效率优化，核心洞察在于输出投影的信息混合功能可由确定性正交变换近似完成，无需可学习参数。这对搜索/推荐系统中的 Transformer 排序模型有直接启示：在不显著损失效果的前提下，可将模型参数量和推理 FLOPs 降低 10-20%，特别适合对延迟敏感的在线 serving 场景。

Shubham Aggarwal, Lokendra Kumar

Kernel-Smith: A Unified Recipe for Evolutionary Kernel Optimization

MetaNVIDIA

提出 Kernel-Smith 框架，结合稳定的评估驱动进化 Agent 和面向进化的后训练方案，实现高性能 GPU kernel 和算子的自动生成。Agent 维护可执行候选种群，利用历史最优和语义多样的 archive 进行迭代改进。后训练阶段通过进化感知的微调增强 LLM 的 kernel 代码生成能力。在多个 GPU kernel benchmark 上超越手写 CUDA kernel 和 Triton 编译器输出。

INSIGHT自动化 GPU kernel 优化是 ML 基础设施领域的重要方向，Kernel-Smith 证明了 LLM 驱动的进化搜索可以生成超越人工编写的高性能 kernel。对于搜索/推荐系统的 serving 优化，这意味着可以针对特定硬件和 workload 自动生成定制化 kernel（如 attention、embedding lookup、特征交叉），减少对 CUDA 专家的依赖。该框架的进化搜索+后训练范式也适用于其他代码生成优化任务。

ScoutAttention: Efficient KV Cache Offloading via Layer-Ahead CPU Pre-computation for LLM Inference

针对长上下文 LLM 推理中 KV cache 导致 GPU 内存不足的问题，提出 ScoutAttention——通过层间 CPU 预计算实现高效 KV cache 卸载。不同于现有方案需要频繁 GPU-CPU 数据传输或大量 CPU 计算，ScoutAttention 利用当前层推理时 CPU 提前计算下一层所需的 attention 元数据（如重要性分数），实现 GPU-CPU 流水线并行，最大化隐藏卸载延迟。

INSIGHT层间预计算（layer-ahead pre-computation）是 KV cache 卸载的关键创新——利用 Transformer 逐层推理的特性，在 GPU 执行当前层时 CPU 已完成下一层的辅助计算，消除了传统卸载方案的阻塞等待。对于需要处理长 query 或长文档的搜索系统，该技术可以在不增加 GPU 的情况下支持更长的上下文窗口，直接降低 LLM-based ranking 的硬件成本。

Qiuyang Zhang, Kai Zhou, Ding Tang, Kai Lu, Cheng Li, Zhenyu Yang, Peng Xu, Jiguang Wan

TAPS: Task Aware Proposal Distributions for Speculative Sampling

KAUST

在推测解码（speculative decoding）中，draft model 通常在通用语料上训练，与目标任务分布不匹配导致接受率下降。TAPS 提出任务感知的提案分布方法，让 draft model 的 token 提案更贴近目标模型在特定任务上的分布。通过在 draft model 训练中引入任务特定信号，显著提升了推测解码的 token 接受率和整体推理吞吐。

INSIGHT推测解码的效率瓶颈不在于 draft model 的大小，而在于其提案分布与目标模型的对齐程度。TAPS 的核心启示是：为特定下游任务（如搜索排序、query 改写）定制 draft model 的训练数据和目标，可以比通用 draft model 获得更高的加速比。对于搜索系统的 LLM 推理加速，建议针对搜索 query 分布训练专用 draft model，而非使用通用小模型。

Mohamad Zbib, Mohamad Bazzi, Ammar Mohanna, Hasan Abed Al Kader Hammoud, Bernard Ghanem

06 4.15

KVSculpt: KV Cache Compression as Distillation

将 KV cache 压缩重新定义为知识蒸馏问题：将完整 KV cache 视为教师，压缩后的 KV cache 视为学生，通过最小化二者输出分布差异来指导 KV pair 的选择和合并。不同于现有的纯淘汰式（eviction）方法，KVSculpt 同时考虑量化、低秩分解（降低 per-pair 存储）和序列长度缩减（减少 pair 数量），在两个正交方向上协同优化 KV cache。

INSIGHT将 KV cache 压缩统一到蒸馏框架下是一个优雅的理论贡献——纯淘汰方法只按重要性丢弃 KV pair，但无法保证压缩后的 cache 在输出层面最优。蒸馏视角让压缩直接对齐最终输出质量，适合对答案准确性要求高的搜索场景。实践上，建议在 KV cache 压缩中同时使用量化（降低 bit-width）和选择性保留（减少 pair 数），而非仅用单一策略。

Bo Jiang, Sian Jin

RSR-core: A High-Performance Engine for Low-Bit Matrix-Vector Multiplication

UUIC

矩阵-向量乘法是神经网络推理、向量数据库和 LLM serving 的核心运算。RSR-core 针对低比特权重量化场景设计了高性能计算引擎，通过优化内存访问模式、SIMD 指令利用和数据布局，在低比特（如 2-bit、4-bit）矩阵与全精度向量的乘法中实现显著加速，直接提升量化模型的推理效率。

INSIGHT低比特矩阵-向量乘法的性能瓶颈不在计算而在内存带宽——RSR-core 的关键优化是重新设计数据布局以最大化 cache line 利用率和 SIMD 通道占用率。对于搜索/推荐系统，该引擎可直接加速两个关键环节：(1) 量化后的排序模型推理，(2) 向量数据库中的 ANN 检索（低比特乘积量化）。当部署 4-bit 量化 LLM 进行 query 理解时，使用优化的低比特 MVM 引擎可进一步降低推理延迟。

Mohsen Dehghankar, Abolfazl Asudeh

WVA: A Global Optimization Control Plane for llmd

随着 vLLM、SGLang 等推理框架快速迭代，chunked prefill、speculative decoding 等新功能不断改变系统瓶颈，使得固定的扩缩容策略迅速过时。WVA 提出全局优化控制平面，动态感知推理引擎的特性变化，自动调整资源分配、批处理策略和扩缩容决策，避免运维团队在每次引擎升级后手动重新调优。

INSIGHTLLM 推理引擎的快速演进是一个被低估的运维挑战——WVA 的核心贡献是将控制平面从具体引擎实现中解耦。对于运营搜索/推荐 LLM 服务的团队，这意味着不必在 vLLM 和 SGLang 之间做非此即彼的选择，而是通过统一的控制平面管理异构推理后端。当推理引擎升级引入新优化时，控制平面自动适配，减少因版本升级导致的性能回退风险。

ParoQuant: Efficient Post-Training Quantization for Reasoning LLMs

发表于 ICLR 2026 的训练后量化方法，专门面向具备推理能力的 LLM（如 o1、DeepSeek-R1 等 reasoning model）。传统 PTQ 方法在量化 reasoning LLM 时性能下降显著，因为推理链中的中间 token 对量化误差更敏感。ParoQuant 通过自适应校准策略，在保持推理能力的同时实现高压缩比，开销极低，适合大规模部署。

INSIGHTReasoning LLM 的量化难度高于普通 LLM——长链推理过程中量化误差会逐步累积，导致推理链断裂或结论错误。ParoQuant 的经验对搜索系统有直接意义：当使用 reasoning model 进行复杂 query 理解或多步检索推理时，选择量化方法必须考虑推理链长度的影响。建议对 reasoning 型 LLM 使用 ParoQuant 等推理感知量化方法，而非通用 PTQ。

Understanding Efficiency: Quantization, Batching, and Serving Strategies in LLM Energy Use

NVIDIA

在 NVIDIA H100 GPU 上对 LLM 推理的能耗和延迟进行系统性实证分析，覆盖量化精度（FP16/INT8/INT4）、批处理大小和 serving 配置（continuous batching、chunked prefill）三个维度。提供了量化-延迟-能耗三角权衡的详细实测数据，揭示了不同配置组合下的非线性交互效应，为生产环境的 serving 配置决策提供量化依据。

INSIGHT该研究最有价值的发现是量化和批处理的交互效应不是简单叠加——某些量化精度在特定批处理大小下反而增加能耗。对于搜索系统的 LLM serving 配置，不能孤立地调优单个参数，而应在目标硬件上进行组合测试。建议团队基于该研究的框架，在自己的 workload 上复现关键实验，找到最优配置点，而非直接照搬通用建议。
