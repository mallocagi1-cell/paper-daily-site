BitNet Text Embeddings

针对 LLM 文本嵌入部署贵的两个痛点——大 backbone 拖慢 embedding 推理、全精度高维向量给大规模索引带来存储与带宽压力——提出 BITEMBED 极低比特框架。做法是把预训练 LLM backbone 转成 BitNet 式编码器：三值 (ternary) 权重、量化激活、轻量归一化修正，再经过持续对比预训练，最后用相似度分布蒸馏 + 注意力关系蒸馏从全精度 teacher 上做有监督对比微调。框架同时压缩 backbone 权重和输出向量两端。

Boost Inference Performance up to 15x on NVIDIA Blackwell Using DFlash Speculative Decoding

NVIDIA

DFlash 是一个开源 block-diffusion 草稿模型：草稿器用一次前向就生成一整块候选 token（而非逐 token），target 模型并行验证。三个关键技术——并行 block-diffusion 草稿、来自大模型的 target hidden-state 条件、KV 注入维持接受率。在 8 卡 NVIDIA DGX B300 上跑 gpt-oss-120b、高交互场景 (每用户 500–600 tokens/sec) 时，相比标准自回归解码吞吐提升最高 15x，比 EAGLE-3 投机解码高 1.5x；较小模型增益温和：Gemma 4 31B 提升 5.8x、Qwen3 8B 提升 5.1x。

INSIGHT投机解码的瓶颈在草稿阶段仍是串行；DFlash 用 block-diffusion 把草稿也并行化，正好吃满 Blackwell 双 die、640 Tensor Core 暴露出来的并行算力。如果社区搜索用大 LLM 做 query 理解或重排，DFlash 这类把'起草+验证'都并行的方案能把解码瓶颈搬走，且开源、跑在 TensorRT 栈上，迁移门槛低。注意 15x 是 120B 大模型高并发下的极值，8B 量级只有约 5x，选型要按自己的模型规模估收益。

03 3.80

Dustin: Draft-Augmented Sparse Verification for Efficient Long-Context Generation with Speculative Decoding

投机解码在多 batch 长上下文 LLM 上常被验证阶段卡住——KV cache 加载主导了延迟。已有压缩方法在这个场景都失效：静态驱逐因 saliency shift 掉精度，动态选择又在验证路径上引入过高计算开销。Dustin 是面向长上下文投机解码的稀疏验证框架：融合 draft 模型的 lookahead 信号与 target 模型的历史注意力，在多步验证窗口内高保真地定位关键 token；再用稀疏估计方案，把重要性打分限制到极少数注意力头上以降低重算延迟。在 PG-19、LongBench 上用 Qwen2.5-72B 评测。

INSIGHT投机解码社区一直盯着草稿端，Dustin 指出长上下文下真正的瓶颈是验证端的 KV 加载，并把'草稿 lookahead + target 历史注意力'联合起来选 token，比纯静态/纯动态都更稳。把重要性打分压到少数 attention head 是个务实的省算技巧。对需要长 query/长文档拼接做重排的搜索 LLM，这类稀疏验证能在不重训模型的前提下压低长上下文解码延迟。

04 3.80

Scaling AI Inference Across Multiple GPUs Using NVIDIA TensorRT with Multi-Device Inference Support

NVIDIA

TensorRT 11.0 引入原生多设备推理：基于 NVIDIA NCCL，通过 IDistCollectiveLayer 原语支持 AllReduce、AllGather、AlltoAll 等分布式集合操作，把单模型推理切到多卡。测试聚焦生成式媒体——Cosmos 3 视频生成、FLUX.1-dev 文生图，两者注意力都要处理每 block 数万 token。在单节点 8 卡上，Cosmos 3 用 DeepSpeed Ulysses 上下文并行从 1 卡到 8 卡拿到约 7–8x 加速；FLUX.1 上 Ulysses 延迟最低，Ring Attention 在 4 卡内也有强 scaling。

INSIGHT当单个模型（长序列注意力、大图/视频生成）放不进一张卡时，过去要自己拼张量并行/序列并行，现在 TensorRT 把上下文并行做成内置原语，保留 kernel fusion 与量化等生产优化。对搜索侧需要多卡部署超大 embedding/重排模型或长序列 attention 的团队，这是个开箱即用的 scaling 路径；7–8x 是上下文并行在 attention 主导负载上的典型收益，纯解码负载未必同等受益。

05 3.80

Run DiffusionGemma on NVIDIA for Developer-Ready, High-Throughput Text Generation

GoogleNVIDIA

DiffusionGemma 是 Google DeepMind 的 25.2B 文本扩散模型，基于 Gemma 4 26B A4B MoE（激活 3.8B），支持 256K 上下文。与自回归逐 token 不同，它用扩散去噪每步并行生成 256 个 token，从根本上拉高吞吐：单张 H100 上最高 1,000 tokens/sec、DGX Spark 上 150 tokens/sec、DGX Station 上 2,000 tokens/sec。部署覆盖 HF Transformers（原型）、vLLM（高并发）、NVIDIA NIM（容器化、OpenAI 兼容 API）、NeMo AutoModel（微调），支持 BF16 与 NVFP4 精度。

INSIGHT扩散 LM 把'每步并行出多 token'当卖点，正好对治自回归的逐 token 串行瓶颈，是 DFlash 之外另一条非自回归提速路线（这次是完整模型而非草稿器）。1,000 tokens/sec/H100 对实时 chat/copilot 类负载有吸引力。但博客没给与自回归模型的质量对比基准，扩散 LM 在短文本搜索的相关性/事实性上是否够用还需自测；可作为高吞吐文本生成场景的候选，先在离线任务上验证质量再上线。

Maximize AI Factory Energy Efficiency Through Full-Stack Inference and Training Optimizations

NVIDIA

把 AI factory 的能效当成可优化目标（电力可占运营开支 40%）。全栈手段横跨硬件（GB200 NVL72 + 液冷）、精度（NVFP4 比 FP8 吞吐更高）、软件（TensorRT-LLM、Dynamo）。训练侧提出协同 GPU 调频——非关键路径 GPU 主动降频、关键路径 GPU 满速跑，配合 ML.ENERGY、落到 Megatron-LM，借细粒度 kernel 级 profiling 削减 GPU 空转，做到训练时间不增的前提下省最高 25% 能耗。整机层面用 45°C 液冷改善 PUE、NVIDIA DSX 动态功率再分配、机架内功率平滑；优化后的 AI factory 比未优化基线多产出 2.6x tokens/sec/MW，并称六代架构累计实现每兆瓦推理吞吐 1,000,000x 提升。

INSIGHT当推理是营收关键负载时，perf-per-watt 直接换算成 token 成本。这篇把能效拆成硬件/精度/软件/调度多层，最实用的是'按关键路径差异化 GPU 调频'——不改模型、不增训练时长就省 25% 能耗，对自建训练集群可借鉴。NVFP4 替 FP8 提吞吐也是值得评估的精度选项。2.6x tokens/sec/MW 是端到端整机口径，单点优化别直接套用。

07 3.55

Optimizing cloud economics with linear elastic caching

Google

把缓存驱逐建模成 ski-rental 问题：每个数据项在'继续租内存（持续成本）'与'买下 miss 代价（被驱逐后重取）'之间权衡。用轻量 ML（浅层决策树）按访问模式与 miss 成本给缓存页分配 TTL，从而动态调缓存大小，而不是按峰值静态配。在 Google Spanner 生产环境实测：内存降 15.5%、miss 多 5.5%、总成本省 5%，且多出来的 miss 集中在'重取便宜'的数据上。公开 cache trace 上，弹性策略在不同负载与成本比下的 miss 率持续显著低于固定大小基线。

INSIGHT搜索系统里向量索引缓存、特征缓存、KV 缓存都吃内存，这篇给出按'重取成本'差异化 TTL 的成本感知思路：贵的数据多留、便宜的先放掉，用浅决策树就能学。Spanner 上 15.5% 内存换 5% 成本是真实生产数字，方法轻、可迁移到自建缓存层。前提是云厂按内存粒度计费时收益才明显，自有机房需自己折算内存机会成本。

08 3.25

Improved Large Language Diffusion Models

RUCAAnt Group

iLLaDA 是一个从零训练的 8B masked diffusion 语言模型，全双向注意力。整个预训练 + SFT 都保持掩码扩散目标，预训练扩到 12T token，指令微调用 25B token 语料跑 12 个 epoch；并用变长生成提效、用基于置信度的打分做选择题评测。相比 LLaDA 在通用、数学、代码 benchmark 上普遍提升：iLLaDA-Base 在 BBH +21.6、ARC-Challenge +14.9；iLLaDA-Instruct 在 MATH +14.5、HumanEval +16.5；尽管是非自回归训练，仍在多个 benchmark 上与 Qwen2.5 7B 竞争。

INSIGHT扩散 LM 这条非自回归路线在 8B 量级、12T token 规模上把与自回归 SOTA 的差距收窄到可比，是值得跟踪的范式信号（双向注意力 + 掩码扩散目标贯穿预训练到 SFT）。变长生成与置信度打分是让扩散 LM 实用化的工程点。对搜索而言短期更多是观察价值：双向注意力天然适合做整体语义表征/重排，但当前还缺针对检索任务的直接证据，建议先关注其是否开源权重再评估。
