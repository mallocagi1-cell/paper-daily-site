Discovery to Execution: Scaling Agents with Toolboxes and Routines in Microsoft Foundry

Microsoft Foundry 将工具发现从静态塞入系统提示词改成运行时检索：Agent 先根据任务从工具箱召回相关工具，再调用确定性 Skill 或函数完成执行。文章明确区分 Skill、Tool 与 Agent 三层，并指出按需加载可减少 token、提升精度和降低延迟；但它没有披露统一公开基准的绝对分数，属于工程实践而非论文实验。

GRASP: 粒度感知的智能体检索增强生成搜索策略

GRASP 将多步推理中的检索工具选择建模为强化学习策略，按证据粒度在语义搜索、段落阅读和关键词检索之间切换。公开介绍称它在多跳问答上优于单步检索、提示式 Agentic RAG 与强化学习基线，并通过消融观察到“广泛探索—局部验证—实体取证”三类行为；页面未给出可复核的绝对指标。

INSIGHT它提示搜索系统不要把向量召回、倒排检索和文档阅读硬编码成固定流水线，而应让策略根据当前证据缺口选择工具。落地时可先用规则定义检索预算与停止条件，再用离线轨迹训练路由策略，并按每轮新增证据、答案覆盖率和调用成本联合奖励，避免 Agent 通过无效重复搜索“刷”最终得分。

03 3.25

MARS-RL: Enhancing Multi-Agent RAG Systems for Multi-Modal Documents via Strategic Reasoning with Reinforcement Learning

MARS-RL 面向多模态文档上的多 Agent RAG，把“下一步检索什么、由哪个 Agent 处理、何时结束”纳入强化学习驱动的策略推理。论文聚焦复杂多轮证据收集中的 Agent 协作，而不是单一向量库或单轮生成；CVPR 2026 Findings 页面确认了题目与发表信息，但当前公开摘要未提供完整的模型对比数字。

INSIGHT对于含图片、表格和文本的社区内容，先将证据分工和跨模态验证拆成可观测轨迹，再优化策略，比直接堆叠多个 Agent 更可控。工程上应记录每个子 Agent 的检索命中、证据引用和失败回退，优先做单 Agent 多工具基线；只有在任务确实需要并行证据搜集时，才引入多 Agent 以控制延迟和编排成本。

Zhongyu Wang, Pengbo Liu

Learning to Reason by Analogy via Retrieval-Augmented Reinforcement Fine-Tuning

Meta

Meta 的工作把检索增强放进强化微调循环：模型在推理时获取与当前问题相似的已解示例，并将这些类比证据作为策略改进的外部支撑，而不是只在生成前拼接固定上下文。Meta 页面将其归入检索增强与强化学习方向，发布日期为 2026-07-17；当前检索到的公开条目未给出完整 benchmark 表格，因此证据质量保守计分。

INSIGHT这条路线适合研究社区搜索中的复杂意图和长链路问答：历史高质量会话可作为“可检索策略案例”，帮助 Agent 选择查询改写、过滤或引用动作。上线前应做用户与内容隔离、近邻案例去重和反事实评估，防止把旧答案或流行模板当成事实证据，并把检索示例带来的收益与额外上下文成本分开测量。

Zilin Xiao, Qi Ma, Jason Chen, Xintao Chen, Avinash Atreya, Hanjie Chen, Vicente Ordonez

05 3.15

RAISE: RAG Design as an Architecture Search Problem

RAISE 将 RAG 设计形式化为架构搜索问题：系统不再固定采用“向量召回—重排—生成”链路，而是在检索、推理和生成组件及其连接方式中搜索更适合任务的组合。arXiv 条目确认其核心问题是自动选择 RAG 架构；当前可用摘要没有披露统一数据集上的绝对提升，因此未把缺失数字补写成实验结论。

INSIGHT对 UGC 短文本搜索，架构搜索可用于比较“关键词+向量”“多路召回+重排”“查询分解+多跳检索”等候选链路，但必须把 nDCG、CTR、P95 延迟、token 成本和失败率纳入同一目标。建议先限定安全的组件库和预算，再离线搜索少量候选，最终通过小流量 A/B 验证，避免让自动搜索生成不可解释、难运维的组合。
