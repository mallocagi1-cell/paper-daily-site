1. Discovery to Execution: Scaling Agents with Toolboxes and Routines in Microsoft Foundry
3.70
Relevance 4 | Novelty 3 | Practical 5 | Evidence 3 | Timely 2

Summary: Microsoft Foundry 将工具发现从静态塞入系统提示词改成运行时检索：Agent 先根据任务从工具箱召回相关工具，再调用确定性 Skill 或函数完成执行。文章明确区分 Skill、Tool 与 Agent 三层，并指出按需加载可减少 token、提升精度和降低延迟；但它没有披露统一公开基准的绝对分数，属于工程实践而非论文实验。

Key insight: 对社区搜索的 Agent 化改造，最值得借鉴的是把“检索内容”和“检索工具”同时做动态路由：简单短查询走固定召回，复杂任务才加载多跳搜索、计算或结构化查询 Skill。这样可以把昂贵的规划调用限制在必要位置，并用工具 schema、权限和确定性校验约束模型，降低错误工具调用对 CTR 与用户信任的影响。

2. GRASP: 粒度感知的智能体检索增强生成搜索策略
3.45
Relevance 4 | Novelty 4 | Practical 3 | Evidence 3 | Timely 2

Summary: GRASP 将多步推理中的检索工具选择建模为强化学习策略，按证据粒度在语义搜索、段落阅读和关键词检索之间切换。公开介绍称它在多跳问答上优于单步检索、提示式 Agentic RAG 与强化学习基线，并通过消融观察到“广泛探索—局部验证—实体取证”三类行为；页面未给出可复核的绝对指标。

Key insight: 它提示搜索系统不要把向量召回、倒排检索和文档阅读硬编码成固定流水线，而应让策略根据当前证据缺口选择工具。落地时可先用规则定义检索预算与停止条件，再用离线轨迹训练路由策略，并按每轮新增证据、答案覆盖率和调用成本联合奖励，避免 Agent 通过无效重复搜索“刷”最终得分。

3. MARS-RL: Enhancing Multi-Agent RAG Systems for Multi-Modal Documents via Strategic Reasoning with Reinforcement Learning
3.25
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 2

Summary: MARS-RL 面向多模态文档上的多 Agent RAG，把“下一步检索什么、由哪个 Agent 处理、何时结束”纳入强化学习驱动的策略推理。论文聚焦复杂多轮证据收集中的 Agent 协作，而不是单一向量库或单轮生成；CVPR 2026 Findings 页面确认了题目与发表信息，但当前公开摘要未提供完整的模型对比数字。

Key insight: 对于含图片、表格和文本的社区内容，先将证据分工和跨模态验证拆成可观测轨迹，再优化策略，比直接堆叠多个 Agent 更可控。工程上应记录每个子 Agent 的检索命中、证据引用和失败回退，优先做单 Agent 多工具基线；只有在任务确实需要并行证据搜集时，才引入多 Agent 以控制延迟和编排成本。

5. RAISE: RAG Design as an Architecture Search Problem
3.15
Relevance 4 | Novelty 4 | Practical 3 | Evidence 2 | Timely 2

Summary: RAISE 将 RAG 设计形式化为架构搜索问题：系统不再固定采用“向量召回—重排—生成”链路，而是在检索、推理和生成组件及其连接方式中搜索更适合任务的组合。arXiv 条目确认其核心问题是自动选择 RAG 架构；当前可用摘要没有披露统一数据集上的绝对提升，因此未把缺失数字补写成实验结论。

Key insight: 对 UGC 短文本搜索，架构搜索可用于比较“关键词+向量”“多路召回+重排”“查询分解+多跳检索”等候选链路，但必须把 nDCG、CTR、P95 延迟、token 成本和失败率纳入同一目标。建议先限定安全的组件库和预算，再离线搜索少量候选，最终通过小流量 A/B 验证，避免让自动搜索生成不可解释、难运维的组合。
