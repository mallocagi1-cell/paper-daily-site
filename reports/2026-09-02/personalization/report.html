SetMIR: Multi-Interest Retrieval as Set Prediction

工业推荐中的单一用户向量难以覆盖多兴趣，而固定多路召回又会产生兴趣坍缩和无效 ANN 查询。SetMIR 用 Transformer 与 K 个可学习查询把兴趣建模为集合，以匈牙利匹配保证一对一分工，并用 presence 分数和查询级 NMS 动态发起召回；在 Snap DPA 中减少 33% ANN 查询，整体 CVR 提升 3.1%。

SetMIR：把多兴趣召回当成“集合预测”，顺便决定每次请求该发几路 ANN

我的判断：做召回的团队值得认真读，尤其是已经在用多兴趣召回、又苦于几个兴趣向量越学越像的团队。它的改动很小，一个训练时的匹配方式和一个输出头，却同时处理了训练和线上两个老问题。来自 Snap 的动态商品广告（DPA，Dynamic Product Ads）团队，已在线上作为新召回源上线。核心思想一句话：用 K 个可学习的兴趣 query 去“预测一个兴趣集合”，没分到真实目标的 query 学会说“这次不存在”，线上据此决定实际发几路 ANN 检索。做法借自目标检测里的 DETR（用一组可学习 query 直接预测目标框集合的检测模型）：训练时用匈牙利匹配把真实目标一对一分给 query。几个数字：把匹配方式从常见的 argmax 换成匈牙利匹配，R@10 差距达 36.5%（argmax 版本只有完整版的 63.5%）；线上平均每次请求只发 6.70 路 ANN，比固定发 10 路少 33%；作为新召回源上线后整体 CVR +3.11%。

它到底在解决什么问题？

先看一个示意场景。一个用户这周看了衬衫、裤子、连衣裙、凉鞋和耳饰。单向量双塔会把这些平均成一个向量，结果往往偏向点得最多的那个品类。论文图 3 的真实案例就是如此：单向量召回的前 10 个全是裤子。

多兴趣召回（MIND、ComiRec 一类）给每个用户输出 K 个向量，每个向量各发一路 ANN 检索再合并。但它们有两个毛病。

第一个叫兴趣坍缩（interest collapse）。常见训练方式是让每个目标商品去找和它最近的那个兴趣向量（argmax），只更新那一个。看一个示意的相似度表：

兴趣 query目标 1：衬衫目标 2：连衣裙
q10.80.6
q20.30.5
q30.10.2

按 argmax，两个目标都选 q1（0.8 和 0.6 都是各自那一列的最大值），q2、q3 收不到任何梯度。训下去 q1 什么都管，其他 query 要么不动，要么漂移，最后有效兴趣只剩一两个。论文的消融里，argmax 训练的模型平均只有 2.16 个 query 被判为“存在”。

第二个叫静态派发（static dispatch）。线上不管用户今天有几个兴趣，都固定发 K 路 ANN，每路分 N/K 个候选名额。如果 10 个向量里有 4 个几乎重复，就有 4 路检索在重复取回同一批商品，白白占了候选预算和调用成本。

SetMIR 的出发点是：用户的兴趣是一个大小不定的集合，模型应该预测这个集合，而不是硬造 K 个互相独立的向量。

先看全景

阶段做什么为什么需要
输入最近 40 个行为，每个商品用冻结的内容向量，加位置和行为类型商品塔冻结，线上直接复用现成的单向量 ANN 索引
编码2 层 transformer 读历史得到上下文化的历史表征

输出每个 query 一个归一化召回向量和一个存在分数存在分数决定线上这路检索发不发

模型很小，隐藏维 128，可学习参数约 3M。监督信号来自未来 3 天窗口里的高意向行为：购买、加购和上划（swipe-up，Snap 广告里点进商品落地页的动作）。目标按商品去重，同一商品保留最强的行为，最多保留 15 个；窗口之前的最近 40 个行为作为输入。

拆开看：训练时怎么分配目标

匈牙利匹配是什么，为什么能防坍缩？ 匈牙利匹配是一种经典算法：给定一张“query × 目标”的代价表，找出一种一对一的配对，使总代价最小，任何 query、任何目标都不能被用两次。SetMIR 的代价是“负相似度”加一项“负的存在置信度”：
Γk,w​=−λemb​ek⊤​tˉw​−λcls​logσ(ℓk​)
两项权重分别取 1 和 0.5，第二项在前 10% 的训练步里线性升温，让早期的匹配主要由向量几何决定。

回到上面的示意表，先只看相似度。可选的一对一配对里，q1→衬衫、q2→连衣裙 的总相似度是 0.8+0.5=1.3；q1→连衣裙、q2→衬衫 是 0.6+0.3=0.9；q1→衬衫、q3→连衣裙 是 0.8+0.2=1.0。最优是第一种。于是 q2 被迫负责连衣裙，拿到梯度往连衣裙方向走；q3 没分到目标，得到一个“存在 = 0”的标签。这说明匈牙利匹配从训练目标上就保证了“一个兴趣只由一个 query 负责”，不需要额外的正则去硬拉开 query。

分到之后怎么学？ 每对（query，目标）用 InfoNCE 训练：正样本是分到的目标，负样本是同一个 batch 里跨 GPU 收集到的所有目标向量，温度 0.05。没分到的 query 不参与 InfoNCE，不会被拉向任何方向。

存在分数怎么学，为什么需要？ 每个 query 的存在头输出 p_k，标签就是“这次有没有被匹配上”，用二分类交叉熵训练。这是 argmax 训练缺的那块：argmax 下没被选中的 query 什么信号都没有，在 SetMIR 里它会被明确告知“这次不存在”。要注意论文自己的说明：没匹配上只代表未来 3 天窗口里没有更多高意向目标，不代表用户永远没有这个兴趣，所以存在分数是“这次请求要不要发”的调度信号，不是用户画像标签。

多样性损失做什么？ 只对存在分数大于 0.5 的 query 两两计算余弦相似度，超过 0.3 的部分才罚。示意：两个活跃 query 余弦 0.5，罚 0.5−0.3=0.2；余弦 0.2，不罚。已经分开的 query 不受影响。三项损失权重分别是 1.0、0.5、0.1。

拆开看：线上怎么决定发几路

线上只做一次前向，得到 10 组（e_k, p_k），然后三步：

  1. 存在门控：只保留 p_k > 0.3 的 query；一个都不过就保留分数最高的那个。
  2. query 去重：按 p_k 从高到低排，如果某个 query 和排在它前面、已保留的 query 余弦超过 0.9，就去掉。这一步论文叫 query 级 NMS（非极大值抑制，目标检测里去掉重复框的做法）。
  3. 每个剩下的 query 各检索 ⌈N/K̃⌉ 个商品，K̃ 是剩下的路数；同一商品被多路召回时取最高分，再取前 N 个。

手算一个示意例子：5 个 query 的存在分数是 0.95、0.90、0.70、0.25、0.10。门控后剩前 3 个。第 2 个和第 1 个余弦 0.93，超过 0.9，被去掉。最后 K̃=2，假设候选预算 N=1000，每路取 500 个。这说明总召回深度基本不变，省下的是 ANN 调用次数，以及重复检索浪费掉的名额。

这套方案真的更好吗？

离线数据是 Snap DPA 的用户-商品行为日志，商品库数亿，测试集约 100 万用户、530 万个目标商品。按 Snap 的规定只报相对值，下表每列都以 SetMIR 为 100%。所有方法共用同一套冻结商品向量、K=10、同样的优化器和召回预算：

最强的基线 ComiRec-SA 在 R@100 上几乎追平（99.9%），但 R@1 只有 67.4%、MRR 80.0%。这说明它能捞回差不多的候选池，排序却差得多，而下游精排最看重的正是靠前的那部分。最有说服力的一行是 SetMIR（argmax）：结构完全一样，只把匈牙利匹配换成 argmax，R@10 就掉到 63.5%，活跃 query 从 6.70 个降到 2.16 个。KuaiFormer 结构和 SetMIR 最接近，也是 transformer 加可学习 query，R@10 只有 52.0%。这说明差距主要来自 query 怎么被监督，而不是网络结构。

单项消融里，去掉存在损失后 R@10 降到 91.4%，门控还放进了 8.23 路而不是 6.70 路。这说明没有监督的存在分数不携带“该不该发”的信息，结果是发得更多、召回反而更差。去掉多样性损失后 R@10 降到 93.2%，query 之间更相似了。三者中匹配方式的影响最大。

K 的扫描也很有信息量：以 K=1 为 100%，K=3 时 R@10 已到 137.5%，K=10 到 155.0%，K=15 是 155.1%，基本饱和。更有意思的是活跃路数：K=15 时平均也只有 7.59 路被判为存在。这说明有效兴趣的个数是由数据决定的，给更多 query 模型也不会全用。

我认为它的局限

第一，离线对比对基线不太公平。SetMIR 用冻结商品塔，而 MIND、DCM（用可微聚类构造兴趣向量的多兴趣模型）等本来是和商品塔联合训练的；DCM 和 KuaiFormer 没有公开代码，是作者按论文复现的；训练步数也不同，基线在 6 万到 10 万步收敛，SetMIR 训到 16 万步。作者自己也说 MIND、DCM 的数字只能看作“在冻结商品空间下这些机制的表现”。所以表里 37.4%、52.9% 这类大差距不宜直接当作方法优劣。

第二，线上证据不完整。论文不报流量比例、样本量和显著性；整体 CTR 只 +0.21%，CVR 却 +3.11%，两者差了 15 倍，论文没有解释。44% 和 51% 这组数是实验组内部按召回源归因得来的，不是随机对照，会受精排偏好和召回源之间相互挤占的影响。

第三，存在标签依赖监督窗口。“没匹配上”只表示未来 3 天没有高意向行为，所以窗口一改，存在分数的含义就跟着变。另外目标最多保留 15 个，而 query 只有 10 个，意味着目标多于 10 个的用户一定有目标分不到 query。论文没有做窗口长度或目标上限的敏感性实验。

一个推荐/搜索团队可以怎么试

  1. 如果已有多兴趣召回，先离线统计 K 个兴趣向量两两的平均余弦，以及每个 query 平均分到多少目标。分布很偏（一两个 query 包揽大部分目标），就说明有坍缩，值得试。
  2. 最小改动是只换训练时的分配方式：argmax 换成匈牙利匹配，K=10 时每个用户只是一个 10×W 的小问题，算法开销可以忽略。看 R@10 和 MRR 的变化。
  3. 再加存在头，线上先不改派发，离线按论文的阈值 0.3 和去重阈值 0.9 回放，算 ANN 调用能省多少、召回损失多少。
  4. 线上 A/B 时，优先看实验组和对照组的整体指标；按召回源归因的指标只作参考，避免把挤占效应当成增益。
  5. 换监督窗口长度（例如 1 天、3 天、7 天）各训一版，看存在分数和活跃路数是否稳定，确认它适合自己的业务节奏。

一句话结论

多兴趣召回的问题不全在模型结构，更在训练时 query 怎么分目标；SetMIR 用一对一匹配加一个“这次存不存在”的分数，把防坍缩和按请求动态派发合成了一件事，改动小，离线消融和线上效果都支持它。

维度评价
问题重要性高。兴趣坍缩和固定派发是多兴趣召回的普遍问题
方法创新性中高。DETR 式集合预测在推荐召回里的直接迁移，存在头用于派发是新用法

CAMIE: Co-Engagement-Aware Multimodal Item Embeddings for Snap Dynamic Product Ads Retrieval

Snap📖 有深读 · 13 分钟

CAMIE 面向 Snap 动态商品广告的 I2I 召回，把图像与商品元数据送入同一 LLM/MLLM 原生多模态接口，再用用户旅程挖掘的共参与商品对和对称式 in-batch InfoNCE 对齐转化行为。线上替换两个内容编码器后，相对多模态对照 CTR +0.390%、CVR +10.832%，整体 DPA 流量 CTR +0.211%、CVR +1.911%。

INSIGHT关键不是继续堆独立视觉/文本塔，而是让统一内容空间接受真实共参与信号监督，使相似性直接靠近转化目标。该方案可作为现有 I2I 向量源的低风险替换：保持 ANN 基础设施不变，以统一 checkpoint 支持多模态和纯文本召回，并通过离线 Recall@10 与线上 CTR/CVR 双重把关。

CAMIE：商品向量的大部分收益来自“用户一起互动过”的监督，而不是换成多模态大模型

我的判断：做 I2I 召回或商品向量的团队值得读，主要因为它回答了一个大家常在争的问题：把商品编码器换成多模态大模型（MLLM），收益到底来自模型本身，还是来自训练用的监督信号。CAMIE（Co-Engagement-Aware Multimodal Item Embeddings，意思是“考虑共同互动的多模态商品向量”）来自 Snap 动态商品广告（DPA）团队，已上线替换了两套旧编码器。核心思想一句话：用 Qwen3-VL-Embedding 2B 把商品图片和文字一起编码成一个向量，再用从用户浏览路径里挖出的“共同互动商品对”做对比学习微调，同一个模型同时服务多模态和纯文本两条召回线。几个关键数字：同一个底座，微调后 R@10 比微调前高 37.7%；而在完全相同的训练配方下，换不同底座（MLLM、SigLIP2、CLIP）的多模态 R@10 最多只差 5.8%；线上替换旧的多模态 I2I 编码器后，这条召回线的 CVR +10.832%。

它到底在解决什么问题？

I2I 召回的输入是一个种子商品，输出是“相关”的商品。线上通常离线把整个商品库编码好、建 ANN 索引，请求来了只查一次，延迟低，冷启动商品也能覆盖。

问题一：相似不等于会一起买。用一个示意例子看：

示意种子：白色亚麻衬衫内容相似度会召回用户实际会一起看、一起买
商品 A–另一件白色衬衫（长得像）同店的亚麻长裤
商品 B–白色 T 恤（颜色、品类像）同系列的另一个颜色
商品 C–白色床单（材质词相同）搭配的草编凉鞋

CLIP/SigLIP 这类模型学的是“图文是否匹配”，把它直接用来做 I2I，召回的是长得像、写得像的商品，而广告关心的是用户接下来会点、会买的商品。

问题二：模态割裂。线上往往同时维护纯文本、纯图片和多模态三套编码器，各有各的微调、刷新流程和 ANN 索引。论文要的是一个模型、一套训练，同时能服务这几条线。

这篇论文真正想回答的是一个归因问题：效果提升有多少来自更强的 MLLM 底座，有多少来自“共同互动”这种行为监督。它用一个对照实验把两者拆开了，这是它比同类工作（例如小红书的 NoteLLM）多走的一步。

先看全景

步骤做什么为什么需要
1. 挖商品对从 30 天的用户路径里找同一用户在一小段时间内互动过的两个商品这是“会一起看、一起买”的直接证据
2. 渲染输入把图片和“Title: … Brand: … Description: … Category: …”拼成一条记录换模态时只改拼哪些字段，模型不变
3. 编码冻结的 Qwen3-VL-Embedding 2B 加 LoRA，取最后一个 token，过投影头底座自带多模态接口，不用另做融合模块
4. 训练对称 InfoNCE，负样本是 batch 内和跨卡收集到的其他商品把“一起互动”的商品拉近
5. 上线商品库刷新时离线编码，写进 ANN 索引；请求时查一次在线链路和旧的内容 I2I 一样，延迟形态不变

拆开看：商品对怎么挖、损失怎么算

商品对按什么规则挖？ 对每个用户 30 天内的路径按商品去重，每个用户最多采 2 对。保留浏览、点击、加购、购买四种行为，不只用高意向行为。然后过一组过滤：归因必须是论文所说的“精确匹配”类型（字面意思是这次互动能精确归到具体的广告商品，论文没有给出更细的定义），标题和图片都不能为空，两个商品属于同一个广告主，一级类目一致，时间衰减权重至少 0.5。时间衰减用 7 天半衰期，权重是 0.5 的（间隔天数 / 7）次方。

手算一下这条规则的含义：两次互动隔 3 天，权重 0.5^(3/7) ≈ 0.74，保留；隔 7 天正好是 0.5，刚好卡在线上；隔 10 天约 0.37，被过滤掉。所以“权重至少 0.5”等价于只保留一周内的共同互动。为什么要“同一广告主”？论文的通用规则要求两个商品属于同一个“服务范围”，也就是线上允许互相召回的商品集合；在 DPA 的实验里，这一条落成了“同一个广告主”。范围外的商品对，线上本来就召回不到，学了也用不上。离线实验用 1000 万训练对、10 万测试对；上线模型用同一流程挖的 1 亿对。

对称 InfoNCE 怎么算？ 一个 batch 有 N 个商品对。对第 n 对，把 i_n 当查询，j_n 是正样本，其余 N−1 个 j 是负样本，算一次 softmax 交叉熵；再反过来把 j_n 当查询、i 们当候选算一次，两者平均。

示意：batch 里 3 对，i_1 和三个 j 的余弦是 0.8、0.2、0.1，温度取 0.5。除以温度后是 1.6、0.4、0.2，取指数约 4.95、1.49、1.22，正样本的概率是 4.95/7.66 ≈ 0.65，这一项损失 −ln 0.65 ≈ 0.44。为什么要对称？因为“一起互动”没有方向，衬衫→长裤和长裤→衬衫是同一种关系，两个方向都要学。论文实际用可学习温度，初值 0.07。

换模态为什么不用重训？ 服务纯文本线时，只是不把图片拼进输入；服务纯图片线时，只拼图片。底座和投影头完全不变。这就是“一个 checkpoint 多条线”的含义。

这张表能读出三点。第一，同一个底座，微调带来 37.7% 的 R@10 提升，说明行为监督本身就是大头。第二，没微调时，加图片反而不如只用文字（纯文本 111.1% 对多模态 100%）；微调后图片才开始有用（137.7% 对 122.5%），所以图片的价值要靠行为监督才能释放出来。第三，CAMIE 在 R@10 上比最强的商用模型 Gemini Embedding 2 高约 6%，向量还小得多（512 维对 3072 维），但在 R@1 上 Gemini 仍略好。

一个模型能不能顶替纯文本编码器？ 多模态训练的模型只喂文字时，R@10 是多模态的 87.9%，专门用纯文本训练的模型是 89.0%，只差 1.1 个百分点。这说明纯文本线可以直接合并到同一个模型上。纯图片输入只有 67.0%，专门训的纯图片版也只有 68.8%，说明问题不在“合并”，而在这个底座本身不擅长只看图。

收益到底来自底座还是监督？ 这是全文最关键的实验。作者用完全相同的配方训了两个非大模型的双塔：SigLIP2-large 和 CLIP ViT-L/14。商品对、损失、负样本数、输出维度、LoRA 设置、学习率和步数都一样，唯一的差别是底座。

这说明行为监督是收益的大头：三个底座用同样的商品对训完，多模态 R@10 最多差 5.8%，而微调本身带来 37.7%。MLLM 的优势在两处：多模态上比 SigLIP2 高 4.3 个百分点，作者做了配对 bootstrap 和置换检验，p<0.001；纯文本上优势大得多。纯图片则应该交给专门的视觉塔。作者还给了一个训练曲线：在一个 epoch 的 40% 处，两个双塔就基本饱和了，MLLM 一直涨到最后，和 SigLIP2 的差距从 20% 处的 2.3 个百分点拉大到最后的 4.3 个百分点。

还有一个数据量和纯度的对比：只用加购和购买对，数量约为全量的三分之一；以“从全行为对里随机采三分之一”为基准：同样三分之一的规模，只用高意向对 R@10 只高 1.6%；用全量的全行为对，R@10 高 8.9%。这说明对这个任务，多保留数据比只挑高意向行为更划算。

我认为它的局限

第一，离线测试集本身偏向这种训练方式。测试对和训练对用同一个流程从共同互动里挖出来，所以任何用这个信号训过的模型都占便宜，未微调的底座和商用 API 天然吃亏。作者自己也承认离线集“无法公平衡量”监督方式的差异。所以 37.7% 和“超过 Gemini 6%”更多说明“对齐到自己的行为分布有用”，不能当作通用向量质量的比较。

第二，匹配对照对双塔可能不利。有效 batch 只有 32 到 64，因为 2B 的 MLLM 在 40GB 显卡上放不下更大的 batch，作者就把所有底座的负样本数都固定在 MLLM 能承受的上限。CLIP/SigLIP 这类对比学习模型通常很依赖大 batch 的负样本，固定在这么小的 batch 上，它们 5% 左右的差距里可能有一部分来自这个限制。论文说这样“算力和负样本对齐、不偏向 CAMIE”，但没有给双塔用大 batch 的对照。

第三，线上和离线用的不是同一个模型。离线表里的模型用 1000 万对训练、输出 512 维；上线模型用 1 亿对训练，而且为了让索引和旧的一样大，只取向量的前 128 维。论文没说训练时有没有针对截断做处理，也没有报 128 维的离线数字，所以离线表并不能直接说明上线模型的质量。纯文本线的旧编码器也没有离线评估，它的 +18.958% CTR 缺少离线对照。

一个推荐/搜索团队可以怎么试

  1. 先不换底座。拿现在线上的内容向量模型（例如 CLIP 或 SigLIP 系列），用同一用户一周内共同互动过的商品对做对比学习微调，按论文的过滤规则去噪。按论文的结论，这一步就能拿到大部分收益。
  2. 测试集要两套：一套用同样方式挖的共同互动对，一套和训练信号无关的人工相关性标注，避免第一套测试集偏向行为监督。
  3. 如果同时维护多模态和纯文本两套编码器，再试一个多模态大模型底座，用“拼不拼图片”的方式同时服务两条线，比较纯文本线和专用文本模型的差距。纯图片线保留专门的视觉塔。
  4. 挖商品对时比较“只用高意向行为”和“全行为、更多数据”，在相同规模和不同规模下各看一次，确认自己数据上数据量和纯度哪个更重要。
  5. 上线前先离线测好截断维度后的效果，再决定索引维度。

一句话结论

商品向量要对齐的是用户的行为，而不是内容本身；CAMIE 用一个干净的对照实验说明，行为监督带来了绝大部分收益，多模态大模型的价值主要在于让一个模型同时撑起多模态和纯文本两条召回线。

INSIGHT方法说明个性化策略不应只推荐“什么”，还要联合决定强度、顺序和约束，并把跳过等弱负反馈纳入状态更新。对内容推荐可类比为同时优化内容、展现频次和探索强度；但合成用户证据有限，实际采用前需要离线日志回放、保守策略约束和小流量实验来防止奖励模型偏差。
