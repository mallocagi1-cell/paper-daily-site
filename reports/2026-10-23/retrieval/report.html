pplx-embed-v2-late Technical Report

Perplexity 发布 0.6B 和 9B 两个多向量检索模型，能编码文本、图片和文档截图：文档每个 token 存一个 128 维向量，查询的每个向量取它和文档向量内积的最大值再求和打分。两个模型都去逐 token 拟合同一个 18B 教师的输出向量，因此向量空间相同，可以用 9B 离线建文档索引、线上用 0.6B 编码查询。在 72 个领域检索任务上，9B 平均 nDCG@10 为 81.3%，比 nemotron-3-embed-8b 高 1.6 个百分点；0.6B 查询配 9B 索引得到 79.6%，高于两端都用 0.6B 的 78.0%。BrowseComp+ 上 9B 让智能体答对 64.0%，搜索次数也最少。

Perplexity 发布了两个多向量检索模型 pplx-embed-v2-late，参数量分别是 0.6B 和 9B，能编码文本、图片和文档页面截图。它们属于"后期交互"检索：文档里每个 token 都存一个 128 维向量，查询的每个 token 也各算一个向量，打分时每个查询向量找文档里内积最大的那个向量，再把这些最大值加起来（MaxSim）。两个模型不是各自用对比学习训出来的，而是都去逐 token 模仿同一个 18B 教师模型输出的向量，所以两者落在同一个向量空间：文档库可以离线用 9B 建索引，线上查询用 0.6B 编码，直接拿来打分。在作者整理的 72 个领域检索任务上，9B 平均 nDCG@10 为 81.3%，比次优的 nemotron-3-embed-8b 高 1.6 个百分点；0.6B 查询配 9B 文档索引得到 79.6%，比两端都用 0.6B 高 1.6 个百分点，查询端成本不变。这是一份技术报告，篇幅不长，主要结果的可信度要分开看：领域基准的任务清单不公开，两个线上基准的标注又部分来自 Perplexity 自己的线上系统，只有 ViDoRe-V3 和 BrowseComp+ 可以独立复现。

1. 为什么做后期交互，为什么要蒸馏

检索模型通常在两种方案之间取舍。单向量模型把整段文档压成一个向量，用近似最近邻搜索很快，但细节信息会丢。交叉编码器把查询和文档拼在一起过一遍模型，效果好，但每个候选都要单独算一次，只能用于重排。后期交互介于两者之间：文档 token 向量离线算好存下来，查询时只算查询的向量，再做 MaxSim。代价是存储大，所以这篇把每个 token 的向量压到 128 维。

作者的另一个判断是：小模型直接做对比学习效果不够，让它去拟合大模型给出的 token 向量更好，尤其是小尺寸模型。这样做还带来一个副产品，同一个教师蒸馏出的不同尺寸学生可以互换使用。不过报告正文没有给出"蒸馏 vs 直接对比学习"的对比数字，这个判断目前只能当作作者的经验。

2. 训练流程

2.1 18B 教师：两阶段对比学习

教师从 Qwen3.5-27B 剪掉最后 20 层得到 18B，并把注意力层的因果遮罩去掉，让每个 token 能看到前后文。训练分两步。

第一步用查询-文档对。数据来自 28 个数据集，按语言和领域再切成 981 个子集，共 1.86 亿对，其中文本-文本 88.3%、文本-图片 8.3%、文本-文档截图 3.4%，文本对里有 1,400 万对是从 PDF 段落反向生成查询合成的。训练时调整采样权重，把三类比例改成 56.5%、30.9%、12.6%，图片和截图被大幅上采样。每个批次只从一个子集里取样，这样同一批里的其他文档（作为负例）和正例更相近，更难区分。为了让各子集按目标比例、并且均匀地间隔出现，作者没有每步独立随机抽，而是这样排：把 0 到 1 切成 981 段，每段长度等于对应子集的采样比例，同一来源的子集挨在一起；第 n 步取"随机起点 +n×0.618…"的小数部分（0.618 是黄金比例的倒数），落在哪一段就从哪个子集取这一批。这串点在 0 到 1 上铺得很均匀，每段被命中的次数接近它的长度，命中时刻也均匀错开；同一来源的子集连成一大段，所以"按比例、间隔均匀"在来源这一层也成立。对比批大小为 16,384 对，用 LoRA（秩 128）训练。和正例 MaxSim 分数相差不到 0.2 的批内文档不算负例，用来减少假负例。MaxSim 写成了 Triton 算子，避免显式存储 token 级相似度矩阵。

第二步合并 LoRA 后加一个秩 32 的新适配器，冻结视觉部分，只用文本三元组训练：每个查询配一个正例和最多 4 个难负例。部分难负例是把高度模板化文档里的关键信息改掉合成的，比如同一格式的财报只改一个数字，逼模型看细节。

2.2 学生：逐 token 拟合教师向量

学生的损失很直接：对查询和文档的每个有效 token，算学生向量和教师向量（都做 L2 归一化）之间的欧氏距离，查询部分和文档部分分别取平均再相加。教师不更新。
L=∣Q∣1​(i,t)∈Q∑​∥qitS​−qitT​∥2​+∣D∣1​(i,t)∈D∑​∥ditS​−ditT​∥2​
因为这个损失不依赖批内负例，一个批次里可以混合多个子集，梯度更稳。9B 学生基于 Qwen3.5-9B，作者发现只用 LoRA 拟合不到位，推测是逐 token 对齐对整个向量空间的约束太强，于是把文本部分最后 8 层全量微调，其余用 LoRA。0.6B 学生从 Qwen3.5-0.8B 剪枝而来，每个块里 3 个线性注意力（Gated DeltaNet）层剪掉 2 个，最后总参数 594M，其中 254M 是词表嵌入、100M 是图像编码，处理文本时实际参与计算的约 240M，并做全参数微调，因为在文档截图任务上全参数微调明显好于只训适配器。

第二列把 Perplexity 线上检索系统排得靠前的文档当作相关，天然偏向"排序方式和线上系统相似"的模型，pplx 模型在这一列领先 nemotron 最多（7.1 个百分点）。作者因此主推合并标注，说它能减少这种偏差。但第一列"智能体引用的文档"也是从线上系统的检索结果里来的，同样带有这种偏向，所以三列都不能算完全中立。即便如此，0.6B 在三列上都超过 8B 的 nemotron，说明优势不全是标注偏差造成的。

图片侧它不是全面领先。ViDoRe-V3 上，专门为图像检索训练的 EVIE（纯视觉多向量模型）8B 和 4.5B 两个版本更高，分别是 66.4% 和 65.9%，但它们每个 token 存 4,096 和 2,048 维，而 pplx-embed-v2-late 只存 128 维，所以这个差距要和存储成本一起看。

3.3 小模型查询 + 大模型索引

用 9B 给文档建索引，再分别用 9B 和 0.6B 编码查询。0.6B 查询配 9B 文档在六个领域都高于两端都用 0.6B，平均从 78.0% 升到 79.6%，两端都用 9B 是 81.3%。也就是说，9B 相对 0.6B 的 3.3 个百分点优势里，换文档侧能拿回将近一半，查询编码成本和纯 0.6B 一样，文档索引的成本在整个索引生命周期里摊销。报告只在领域基准上做了这组实验，没有在 Q2D-Web 和图片任务上验证。

3.4 给搜索智能体当检索器

BrowseComp+ 让 GPT-OSS-120B 作为智能体，用被测检索模型在固定语料里反复搜索并回答复杂问题，再由另一个大模型判分。9B 准确率 64.0%，比另一个后期交互模型 Reason-ModernColBERT 高 4.9 个百分点，比单向量模型里最好的 voyage-4-large 高 8.7 个百分点，平均搜索次数也比所有基线少，召回率同样最高。检索器更准，智能体就少搜几轮，这对按调用次数计费的搜索智能体来说是直接的成本收益。

4. 局限

报告没有给出存储和延迟数据，而这是后期交互方案的主要代价。按训练时的截断长度粗算，一篇 1,000 个 token 的文档要存 128,000 个数，用半精度约 256 KB；一个 1,024 维的单向量用半精度只要 2 KB，相差约 128 倍。实际系统通常会对 token 向量做量化或聚类压缩，报告没说 Perplexity 怎么做，也没给 MaxSim 在 1.9 亿网页上的检索延迟。另外，领域基准的任务清单不公开，无法复现；两个线上基准的标注带有线上系统的偏向；"蒸馏优于直接对比学习"缺少对比数字；图片检索上，专用视觉模型和 gemini-embedding-2 在部分基准上仍更好。

5. 实践意义

对检索团队，最直接能用的是"大模型建索引、小模型查"的部署方式：文档侧算力只花一次，查询侧延迟按 0.6B 算，效果比纯小模型好 1.6 个百分点。前提是两端模型由同一个教师蒸馏，换成独立训练的两个模型不能这样混用。0.6B 版本文本侧只有约 240M 活跃参数，作者认为可以部署到端侧。如果正在评估多向量检索，建议先在自家语料上测存储开销和检索延迟，并优先参考 ViDoRe-V3 这类公开基准的结果，这些是报告没有回答或无法核实的部分。

Directional Posterior Feedback Fusion for Query Reformulation in Dense Retrieval

TsinghuaRenmin University📖 有深读 · 12 分钟

用第一轮检索文档或大模型写的假想答案（HyDE）来改写查询向量时，常见做法是把反馈向量取平均再和原查询插值。DIFF 认为一条反馈只支持查询往某个方向修正，其他方向不该被它拉回：它先减掉每条反馈与原查询平行的部分，得到这条反馈要求的转动方向和幅度，只约束修正量在这个方向上的投影，再按反馈与查询的相似度和整组方向是否一致加权，解一个 K×K 的线性方程得到修正，不训练任何模型。BEIR 14 个子集上，bge-base 配 HyDE 反馈的平均 NDCG@10 从原查询的 0.5492 升到 0.5717；用检索文档做反馈时，向量平均会掉到 0.5045，DIFF 是 0.5522。

Yiteng Tu, Qingyi Pan, Weihang Su, Jiaxin Mao, Yiqun Liu, Qingyao Ai

向量检索里，短查询常常表达不全。常见的补救办法是先拿到一些"反馈"文本，比如第一轮检索排在前面的文档，或者让大模型写一段假想答案（HyDE），再用它们修改查询向量。现有做法大多把反馈向量取平均，或者和原查询线性插值，相当于把每条反馈都当成"新查询应该长成的样子"，把查询往它整体拉过去。清华这篇论文提出的 DIFF（方向式后验反馈融合）认为这样会互相干扰：一条反馈往往只支持查询在某一个方向上的修正，其他方向它没给信息，却也被它往回拉。DIFF 先算出每条反馈相对原查询多出来的方向，只要求修正后的查询在这个方向上和反馈一致，其他方向不管；再按反馈质量给每条约束加权，并用"别离原查询太远"的约束兜底。整个过程有闭式解，不训练任何模型。在 BEIR 14 个子集、3 个检索模型、4 种反馈来源上，DIFF 的平均 NDCG@10 在 12 组设置里都是最高，但用第一轮检索文档做反馈时，它相对不加反馈的原查询基本没有提升；用大模型生成的反馈时，它领先最强基线 AnchorQE 的幅度又和超参数选择带来的波动差不多大。所以这篇论文更可靠的贡献是"不被噪声反馈拖垮"，而不是"显著提高检索效果"。

1. 问题：把反馈当目标点会丢掉互补信息

设原查询向量为 q，第 i 条反馈相对 q 提出的修正是 ei​=ℓi​ui​，其中 ui​ 是方向（单位向量），ℓi​ 是幅度。逐点拟合的目标是让修正 δ 接近 ei​，即最小化 ∥δ−ℓi​ui​∥2。作者把它拆成两项：
∥δ−ℓi​ui​∥2=(ui⊤​δ−ℓi​)2+∥(I−ui​ui⊤​)δ∥2
第一项要求 δ 在 ui​ 方向上的分量等于 ℓi​，这是想要的。第二项惩罚 δ 在所有其他方向上的分量，而这些方向可能正是别的反馈支持的修正。举个例子：查询是"苹果 发布会"，一条反馈文档讲新手机，另一条讲新电脑，逐点拟合会把查询拉到两者中间，两个方向都只走了一半。

作者在附录里证明：权重相同时，方向约束得到的修正幅度总是不小于逐点拟合，只有所有反馈方向共线时两者相等。反馈方向两两正交时差别最明显，方向约束下第 j 个方向的修正量是 τj​ℓj​/(λ+τj​)，逐点拟合下分母还要再加上其他所有反馈的权重之和，也就是被其他反馈稀释了。这个证明说明了方向约束"走得更远"，但走得远不等于走得对，后者要靠实验检验。

2. 方法：四步

第一步是算出每条反馈的新增方向。所有向量都做 L2 归一化，位于单位球面上。对反馈向量 fi​，先算它和查询的相似度 si​=q⊤fi​，再减掉和查询平行的部分，得到 ri​=fi​−si​q。ri​ 的方向 ui​ 就是这条反馈想把查询往哪边转，长度 ℓi​ 等于两者夹角的正弦值，衡量这条反馈带来了多少原查询里没有的东西。作者特意把"新增多少"（ℓi​）和"是否可信"（由 si​ 决定）分开，避免把"和查询差得多"误当成"信息量大、值得信"。

第二步给每条反馈打可信度。可信度 τi​=g⋅ai​ 由两层组成。单条质量 ai​：把同一查询下所有反馈的 si​ 用中位数和中位数绝对偏差标准化，再过 sigmoid，所以和查询更接近的反馈权重更大，而且不依赖不同模型相似度的绝对数值。整组可信度 g：先算所有修正向量的平均 μ，记 S=∥μ∥2 为平均方向的强度，V 为各条修正向量到 μ 的距离平方的平均（离散程度），几何可信度 ggeo​=S/(S+V/K)，K 是反馈条数，取值在 0 到 1 之间；反馈方向一致时 g 高，各说各话时 g 低，最后再乘上整组的平均单条质量，因为一组都很弱的反馈也可能彼此一致。

第三步联合求修正量，目标函数只保留每条反馈在自己方向上的约束，外加一项惩罚修正幅度：
δ∗=argδmin​ 2λ​∥δ∥2+21​i∑​τi​(ui⊤​δ−ℓi​)2
这个问题有闭式解，只需要解一个 K×K 的线性方程组（K 是反馈条数，主实验取 5），计算量是 O(K2D+K3)，D 是向量维度。

第四步把修正转回球面：最终旋转角度取 ∥δ∗∥ 和"g × 最大允许角度 θup​"中较小的一个，然后 q′=cosϕq+sinϕδ∗/∥δ∗∥。整组反馈不可信时 g 小，查询几乎不动。

3. 实验

设置：BEIR 的 14 个子集（包括论辩检索 ArguAna、事实核查 FEVER（事实抽取与核验）、多跳问答 HotpotQA、MSMARCO、谷歌搜索问答 NQ（自然问题集）、科学论断核查 SciFact、新冠文献检索 TREC-COVID 等），三个检索模型 bge-base-en-v1.5、e5-base-v2、Qwen3-Embedding-0.6B。反馈有两类：第一轮检索的前 K 篇文档（PRF），以及 Qwen3.8-27B 生成的三种文本（HyDE 假想文档、Q2D 查询扩写、CoT 推理过程）。所有方法共用同一个编码器、同一份反馈和同一个索引，只比较融合方式。对比方法包括向量平均（VPRF）、拼接后重新编码（Concat-P/L）、只取正交分量的 OR-PRF、按维度加权的 DIME（逐维挑选重要维度）和它的改进版 Eclipse，以及需要额外检索来估权重的 AnchorQE。

这张图解释了 PRF 下平均分为什么几乎不动。VPRF 让大量查询明显变差，有一批查询掉了 0.4 到 0.6。DIFF 让绝大多数查询基本不变，变好和变差的数量差不多。原因是检索回来的文档方向分散，整组可信度 g 很低，第四步把旋转角度压得很小。换句话说，DIFF 在噪声反馈下的做法接近于"不动"，这是稳健，但也意味着它没能从检索文档里挑出有用的那几条。作者说在 HyDE 反馈下，DIFF 变好的查询明显多于变差的，同时仍有大量查询保持不变。

3.5 超参数和效率

DIFF 有两个超参数：拉回原查询的强度 λ 和最大旋转角 θup​，作者在 3×3 的网格里搜索。PRF 下 9 组结果在 0.5452 到 0.5522 之间，只有 5 组高于原查询，最佳设置是很小的旋转角 π/12，这再次说明检索反馈下最好的策略是少动。HyDE 下 9 组在 0.5631 到 0.5717 之间，只有 2 组超过 AnchorQE 的 0.5700。论文没有说明网格搜索用的是哪部分数据，如果是直接在测试集上选，那么 DIFF 对 AnchorQE 的领先在这个波动范围之内。

效率方面，在 10 个查询上计时，DIFF 耗时 0.258 秒，和向量平均的 0.247 秒相当，AnchorQE 因为要额外检索，耗时是 DIFF 的 3.67 倍。不过 10 个查询的样本很小，只能看出数量级。

4. 局限

最主要的一点在主表和分布图里：用第一轮检索文档做反馈时，DIFF 相对原查询几乎没有收益，它的价值是"不被噪声拖垮"。其次，用生成反馈时对 AnchorQE 的领先很小，又可能受超参数选择影响，论文没有报告多次运行的方差。此外，实验只在 BEIR 上做，检索模型最大 0.6B，没有在生产规模的语料和更大的向量模型上验证。生成反馈也只用了一个大模型。

5. 实践意义

如果系统里已经在用 HyDE 或查询扩写，并把生成文本编码后和原查询取平均，可以考虑换成 DIFF：只依赖向量本身，不训练、不额外检索，每个查询多解一个 5×5 的线性方程组，就能在不增加检索次数的情况下拿到和 AnchorQE 相当的效果。上线前应按自己的查询类型分开评估，因为像 Quora 这样"找相似问题"的任务，假想答案本身就和目标不对路。如果反馈来自第一轮检索结果，这篇的结果提示收益有限，DIFF 可以作为"防止平均做法把指标拉低"的保险，而不要指望它带来提升。
