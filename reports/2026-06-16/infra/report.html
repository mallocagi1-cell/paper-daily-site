1. Boosting MoE Training Throughput with Advanced Fusion Kernels
4.05
Relevance 3 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: NVIDIA 针对 MoE 训练的三个瓶颈——激活函数访存受限、路由专家带来的 CPU 同步开销、以及量化未打满 Tensor Core——提出用 CuTe DSL 编写的融合算子，把 GroupGEMM 与 SwiGLU/GeGLU/sReLU 激活、以及 MXFP8/NVFP4 量化折叠进单个 kernel，实现 sync-free 的 MoE 执行并配合整轮 CUDA Graph。kernel 级加速 1.3–2.1 倍，端到端在 DeepSeek-V3 预训练上提升 8%、在 GPT-OSS 上提升 93%。算子已集成进 Transformer Engine、cuDNN Frontend 与 Megatron-Core。

Key insight: MoE 训练的开销大量来自小算子之间的访存与 host 侧同步，而非纯矩阵乘。把激活和量化折叠进 GroupGEMM、用 CUDA Graph 消除每步的 CPU launch/同步，是把稀疏专家训练吞吐做上去的关键。自建训练栈的团队直接复用 Transformer Engine / Megatron-Core 这套融合 kernel 比手写更划算；FP8/FP4 量化要落地必须同时解决 Tensor Core 利用率，否则低精度的理论收益会被算子边界吃掉。

2. Multi-Segment Attention: Enabling Efficient KV-Cache Management for Faster Large Language Model Serving
3.80
Relevance 4 | Novelty 4 | Practical 4 | Evidence 3 | Timely 3

Summary: 现代 LLM serving 中前缀共享、部分复用与 agent 工作流会产生大量非连续的 KV 上下文，而现有引擎要求 KV 物理连续、需重排或重算。论文提出 AsymCache，核心是 Multi-Segment Attention：让 attention 直接在多段非连续 KV 上计算，无需把分散的 KV 物化成连续缓存。相比基线，TTFT 降低最多 1.90–2.03 倍，TPOT 提升 1.62–1.71 倍，agent serving 场景平均作业时延下降最多 18.1%。

Key insight: KV cache 复用是 RAG/多轮/agent 检索场景降本的核心，但真实负载里复用片段几乎总是非连续的，传统“要求连续 KV”的设计逼着引擎做拷贝或重算。直接支持分段 attention、把 KV 当作可寻址的段集合是这类场景的关键。对做 LLM 搜索（query 改写、文档重排、RAG）的团队，前缀缓存命中率和非连续复用能力直接决定线上 TTFT，值得在 serving 层评估这类多段 attention 方案。

3. SPEAR: A System for Post-Quantization Error-Adaptive Recovery Enabling Efficient Low-Bit LLM Serving
3.55
Relevance 4 | Novelty 4 | Practical 3 | Evidence 3 | Timely 3

Summary: 论文发现低比特量化的误差高度依赖输入、在不同 token 间差异很大，而现有后量化补偿方法是静态的、对所有输入施加相同修正。SPEAR 在诊断分析定位出的“误差敏感层”上插入轻量级 Error Compensator，用 per-token 门控按 token 自适应补偿，再配合 kernel 融合与调度优化落地。结果在仅增加不到 1% 模型显存的前提下，恢复了 W4 与 FP16 之间 56–75% 的困惑度差距，且时延与标准 4-bit serving 相当。

Key insight: 4-bit 量化对小模型/难 token 的质量损失，根源在于误差随输入变化而静态补偿一刀切。按 token 门控、只在少数敏感层补偿，是用极小开销换回大部分精度的思路。对要把 LLM 低成本部署到搜索（query 理解、相关性打分）的团队，这套“先量化、再自适应纠错”的范式可在不牺牲吞吐的情况下逼近 FP16 质量，比直接上更高比特更省显存。

4. Heterogeneous Parallelism for Multimodal Large Language Model Training
3.50
Relevance 3 | Novelty 4 | Practical 4 | Evidence 3 | Timely 3

Summary: 多模态大模型训练里，视觉编码器与 LLM 主干的计算/显存特征差异很大，对所有模块套用统一并行切分并不最优。论文提出一种抽象，允许不同模块使用各自独立的并行 layout，并通过 boundary communicator 在模块边界做前向/反向的 layout 变换、保持边界张量语义一致。实验显示 colocated 配置吞吐最多提升 49.3%，non-colocated 最多提升 13.0%。系统以 Megatron-LM 扩展形式发布。

Key insight: 把“全模型统一并行”拆成“按模块异构并行”，是多模态训练扩展性的关键；难点不在切分本身，而在模块边界的张量如何在不同 layout 间正确通信。对要训练图文/多模态搜索模型的团队，视觉塔和文本塔分别选最优并行度能显著省卡；boundary communicator 这种边界变换抽象值得借鉴到自研训练框架里。

5. Cross-Epoch Adaptive Rollout Optimization for RL Post-Training
3.25
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 3

Summary: LLM 的 RL 后训练通常对每个 prompt 采样固定数量 rollout，但不同 prompt 提供的训练信号差异很大，固定预算造成浪费。CERO 把“全局固定预算下的自适应 rollout 分配”建模为带 prompt 级边际递减的在线资源分配：对每个 prompt 的成功概率维护 Beta 后验，用后验期望的 Bernoulli 方差作为“再多采一条 rollout 的价值”的贝叶斯估计，构造凹的饱和效用，并经 Fenchel 对偶 + 投影在线梯度下降同时更新 prompt 级与预算级对偶变量。理论给出 O(√K) 后悔界，实验在多个开源 LLM 的数学推理任务上稳定优于 GRPO。

Key insight: RL 后训练的算力大量浪费在“已学会或完全学不会”的 prompt 上，按成功概率的不确定性动态分配 rollout 预算能直接提升样本效率。把它当成在线资源分配问题、用后验方差度量信息价值，比 GRPO 固定采样更聪明。对用 GRPO/RLHF 训练搜索排序或 query 改写模型的团队，这类自适应 rollout 预算可在相同算力下拿到更好的收敛。

6. Breaking the Ice: Analyzing Cold Start Latency in vLLM
3.00
Relevance 3 | Novelty 2 | Practical 4 | Evidence 3 | Timely 3

Summary: 随着推理服务普遍走向弹性伸缩与 serverless，推理引擎的冷启动时延成为关键。论文首次对 vLLM 启动时延做细致刻画，把启动过程拆解为模型加载、权重传输、CUDA Graph 捕获等六个基础步骤，指出其主要是 CPU-bound；进而构建一个轻量解析模型，能根据硬件配置较准确地预测 vLLM 启动时延，用于指导扩容与冷启动优化。

Key insight: 在线搜索流量有明显波峰波谷，弹性扩容时“新副本多久能服务第一个请求”直接决定突发流量下的可用性，而这块此前几乎没被量化。把冷启动拆成可度量的步骤、发现瓶颈在 CPU（加载/图捕获）而非 GPU，是优化方向的前提。对用 vLLM 做搜索 LLM 弹性服务的团队，这套刻画和预测模型可用来设定预热策略、副本数与扩容触发阈值。

7. Fine-Tuning Biological Foundation Models with LoRA Using NVIDIA BioNeMo Recipes
3.00
Relevance 2 | Novelty 2 | Practical 4 | Evidence 4 | Timely 5

Summary: NVIDIA BioNeMo Recipes 提供基于 PyTorch / Hugging Face / Megatron-Bridge 的训练配方，用 LoRA 对大型生物基础模型做参数高效微调：冻结预训练权重、只训练约占 1% 参数的低秩 adapter，并集成 Transformer Engine 加速与序列打包（THD 格式），相比 padding 方案吞吐提升 5.5 倍。ESM2-3B 在蛋白质二级结构预测达到 84.80% Q3 准确率、Evo2-1B 在 DNA 剪接位点分类达到 96.6%，均可在单张 RTX 6000 Blackwell GPU 上 1 小时内端到端跑完。

Key insight: 论文本身面向蛋白质/DNA 基础模型，但其工程手段对搜索/推荐团队同样可迁移：LoRA + Transformer Engine + 序列打包（THD）这套组合，是把大模型微调成本压到单卡可承受的标准配方，其中序列打包带来的 5.5 倍吞吐尤其值得在变长文本（UGC 短文本）微调中复用，避免 padding 浪费算力。
