1. ADORE: Iterative Query Expansion with Retrieval-Grounded Relevance Feedback
4.30
Relevance 5 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 多数 LLM query 扩展只生成不验证，产出看似合理的伪文档却不检查目标语料的真实响应，容易引入检索漂移、放大误导词或漏掉区分相关/不相关文档的关键词。ADORE（ADapt, Observe, Relevance Evaluate）把检索结果变成下一轮扩展的反馈：每轮由 LLM 生成伪段落、检索器暴露语料响应、相关性评估器对照原始 query 判定检索到的文档，据此决定强化什么、补什么、抑制什么。在 TREC Deep Learning 等基准上验证。

Key insight: 检索式反馈（retrieval-grounded feedback）优于单轮生成或无验证的迭代——让语料的真实响应来纠偏，避免伪文档把召回带偏。对短文本召回，可在 query 扩展环节按'生成→检索→相关性评估→再扩展'逐轮迭代，用相关性评估器显式识别欠覆盖词与误导词，比纯 LLM 一次性生成扩展更稳健。

2. ScoreGate: Adaptive Chunk Selection for Retrieval-Augmented Generation via Dual-Score Statistical Fusion
4.00
Relevance 4 | Novelty 3 | Practical 5 | Evidence 3 | Timely 5

Summary: 固定 top-K 检索对窄问题过检索、对组合问题欠检索。ScoreGate 在推理时复用流水线已有的两个分数——bi-encoder 相似度 s_i 与 cross-encoder 重排分 r_i——做轻量的分数空间决策来动态控制检索条数，不增加任何模型推理调用。核心观察是 cross-encoder 的确认能救回那些因词汇不匹配被 bi-encoder 排低、但语义相关的 chunk。在 MS MARCO（200 条 dev query）上 MRR@10=0.401，且保留 chunk 比 Standard Top-K 少 35%；内部基准（n=300，Fleiss κ=0.87）下零误报。

Key insight: 复用已有的双塔分与交叉编码分做自适应截断，几乎零额外成本就能缓解'词汇不匹配导致 bi-encoder 漏召'的老问题。对社区搜索的多级检索，可把这套双分数门控直接套在现有召回+重排之上，按 query 复杂度动态决定送入下游的条数：窄 query 省算力，组合型 query 提召回。

3. Succeeding at Scale: Enterprise Retrieval Benchmark Construction and Index-Preserving Query Adaptation for Multi-Tenant Search
3.80
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 2

Summary: 大规模多租户检索系统有海量 query 日志却缺相关性标注（'dark data'未被利用），而联合微调 query 与 document 编码器要全量重建索引，在数千个隔离索引的多租户场景不现实。论文提出 DevRev-Search——面向技术客服的段落检索基准，用稀疏+稠密多路检索融合生成候选、再用 LLM-as-a-Judge 做一致性过滤与相关性打标；并系统评估'只微调 query 编码器、保持文档索引不变'的 index-preserving 适配策略。在 DevRev-Search、SciFact、FiQA-2018 上验证。

Key insight: 只微调 query 端、冻结文档索引，能在不重建索引的前提下做域适配，对维护大量索引、更新成本高的搜索系统价值很大。用多路检索融合加 LLM 打标，从无标注日志里自动构造相关性标签，是把'dark data'转成训练信号的可落地路径；社区搜索同样积累大量未标注 query 日志，可照此造数据。

4. Rank4Gen: RAG-Preference-Aligned Document Set Selection and Ranking
3.45
Relevance 4 | Novelty 4 | Practical 3 | Evidence 3 | Timely 2

Summary: RAG 中文档排序决定下游生成器能看到的证据。论文通过受控分析指出两个被忽视的现象：下游回答质量不仅取决于相关性，还取决于所选文档的组合与排序；且不同生成器的偏好系统性不同。为此构建 PRISM 双语偏好对齐数据集，用四阶段流水线把'子集+排序'的组合空间压缩约四个数量级，并基于 7 个下游生成器产出回答质量偏好监督；在 PRISM 的 13k query 子集上训练 generator-aware 的 Rank4Gen，联合做文档集选择与排序。

Key insight: 排序训练不该只用 query-文档相关性——文档集的组合、顺序以及'面向哪个生成器'都会影响最终回答质量。对 RAG 与搜索排序，可借鉴其用回答质量偏好（而非纯相关性标签）训练 set-level 排序器的思路，尤其当下游生成器固定时，按生成器偏好对齐排序能拿到额外收益。

5. Knowledge Graph Enhanced Memory-Augmented Retrieval for Long Context Modeling
3.45
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 长上下文建模不只是扩窗口，还要在数千 token 间维持实体状态与关系的一致理解，仅靠语义相似度做不到。KGERMAR 在推理时从输入文本动态构建上下文相关的知识图谱，做实时实体/关系抽取，再把图结构 embedding 与文本语义通过多组件记忆架构融合：维护 contextual、semantic、structural 三个记忆库，用可学习权重融合各路检索信号。在 SlimPajama（8.47 万训练样本）与 WikiText-103 上评估。

Key insight: 把'显式实体关系'与'语义相似度'两路检索信号用可学习权重融合，能补足纯向量相似在实体一致性上的短板。对需要跨长文档保持实体/关系的检索场景（如社区长帖、多轮问答串联），三记忆库加动态 KG 提供了把结构化信号引入稠密检索的思路，代价是推理期实时抽取实体关系的额外开销。

6. Verbatim Chunks Beat Extracted Artifacts: A Controlled Ablation of Memory Representations for Long LLM Conversations
3.25
Relevance 3 | Novelty 3 | Practical 4 | Evidence 4 | Timely 2

Summary: 一类对话记忆系统把历史压缩成结构化产物（抽取的事实/决策/事件），假设蒸馏后的结构比原文更好检索。论文用受控消融检验这一前提：在固定的'检索-重排-推理'流水线里只替换存储表征——LLM 抽取的类型化产物 vs 逐字对话 chunk，保持模型、检索器、重排器、judge 不变。结果逐字 chunk 在 LoCoMo 上高 15.9 分（43.9% vs 28.0%）、LongMemEval-S 上高 22.0 分（67.4% vs 45.4%）；加 1-hop 语义图也补不回差距，5 项混淆控制复现该效应。机制是有损蒸馏：抽取丢掉了 chunk 免费保留的逐字细节。

Key insight: '存结构化产物比存原文更好检索'在受控实验下不成立——抽取式蒸馏是有损的，抽取产物流水线甚至从未超过朴素 RAG。对构建检索/记忆库的从业者，直接存逐字 chunk 往往是更强的基线；在上结构化抽取前，应先用同一条流水线做 A/B，避免为'结构化'付出准确率代价。

7. Hybrid Neural Retrieval with Generative Query Refinement for Quranic Passage Retrieval
3.20
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 5

Summary: 古兰经段落检索的难点在于日常 query 用现代标准阿拉伯语（MSA）、经文是古典阿拉伯语（CA），语义鸿沟使常规检索失效。论文提出四阶段神经架构：用 AraColBERT 稠密索引 + BM25 稀疏检索做混合候选召回，再用 CAMeLBERTmix cross-encoder 做语义重排，接着用置信门控过滤零答案 query，最后用基于 AraT5 的精化模块做多段聚合。在扩展版 Quran QA 2022 数据集上较基线有提升。

Key insight: 一套标准的混合检索范式——稠密(ColBERT)+稀疏(BM25)召回、cross-encoder 重排、置信门控过滤无答案 query、生成式 query 精化——在跨语体的语义鸿沟下依然奏效。对社区搜索里口语 query 与正式文档的用词鸿沟，可借鉴其'混合召回+交叉重排+零答案门控'的分层设计；该工作领域局限于宗教文本，迁移时需替换领域编码器。
