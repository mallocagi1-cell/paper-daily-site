Knowledge-Geometry Decoupling: Refreshable Pretrained Transfer for Streaming Recommendation

工业推荐在行为分布持续漂移时，传统 next-token 预训练会把跨兴趣会话的相邻物品当成依赖，迁移后还会与 CTR/排序目标争抢同一参数。KGD 用 BMTP 只预测协同或语义相关的未来物品，并以可刷新编码器、只读交叉注意力和正交 ACR 分离知识与任务几何。在 8 个公开基准上较强基线提升 4%–12%，Shopee 90 天流式验证保持优势，首页搜索 A/B 的人均 GMV +1.75%、广告收入 +1.53%。

1. 问题与动机

这篇论文解决的是流式推荐里一个容易被静态离线实验掩盖的问题：预训练行为知识、下游任务的判别几何和线上数据分布变化同时存在，而且三者的更新节奏并不一致。常见做法要么把序列行为预训练一次后冻结，要么把预训练模型和点击/转化任务放在同一套参数里继续训练。前一种做法会随着用户兴趣、商品供给和流量结构漂移而变旧；后一种做法虽然能刷新参数，却会让预训练目标和任务目标互相覆盖。论文用生产流中的梯度余弦相似度说明两类目标从负相关到近似正交，因而共享参数并不是天然合理的折中。

作者进一步指出，行为序列中的相邻商品不等于存在稳定依赖。用户可能在一次会话里跳转、比较、误触或被曝光策略引导，直接把下一个 item 当成唯一正例会把瞬时噪声写进预训练表示。KGD（Knowledge–Geometry Decoupling）因此把问题拆成两个明确的所有权：可刷新 encoder 负责“行为知识”，task learner 负责“任务几何”。目标不是让一个更大的 backbone 同时承担所有工作，而是让知识可以按天更新，同时不摧毁已经适配点击、转化或检索任务的表示空间。

论文的验证路径也比较完整。公开实验覆盖 8 个 Amazon 类 benchmark；工业离线数据包含约 130 亿样本、十亿级 item、千万级 user，基础 28 天流量再延长 62 天形成 90 天稳定性研究；最终在 Shopee Homepage Search 的线上 A/B 中部署。这个链路使它特别适合推荐/搜索团队评估：核心贡献不只是某个 loss，而是持续学习时哪些参数可以刷新、哪些参数应该隔离，以及这套隔离是否带来可观的业务收益。

2. 方法详解

第一部分是 BMTP（Behavioral Multi-Token Prediction）。作者没有把原始序列中的每个后续 item 都拿来预测，而是沿两个轴筛选监督：协同轴使用 item 图/共现关系判断未来 item 是否与当前 item 有稳定协同关系；语义轴使用 item 内容或语义表示判断未来 item 是否足够相近。只有通过相应阈值的 future item 才保留为正例，并且每个轴只监督最近的一个 qualifying item。这样做的直觉是：最近的相关转移已经携带最强依赖信号，继续把所有远期正例塞进 softmax 会让生产训练成本随正例数扩大，也会重新把偶然会话路径当成知识。工业实现中协同阈值为 0.5，语义阈值与具体数据一起校准。

BMTP 预训练出一个可刷新 encoder。它的参数拥有经过去噪的行为几何，并不是下游任务的最终排序空间。训练流每天到来时，encoder 可以用最新行为重新估计协同/语义转移；由于 task gradient 不会回传到 encoder，这个刷新不会直接覆盖 task learner 已经学到的判别方向。论文的关键思想是把刷新视为知识更新，而不是对整个推荐模型做无差别的 continual fine-tuning。

第二部分是 ACR（Anchored Calibration Residual）。对于第 k 个下游任务，任务侧表征写成 e_tilde = s_k × stop_gradient(e_pre) + Delta e_k。其中 s_k = 1 + ReLU(s_tilde_k) 保证沿预训练方向至少保留一个非负的缩放，Delta e_k 由低秩因子产生，并通过正交约束让它落在 e_pre 的正交补空间。这样任务可以增加点击或转化所需的判别维度，却不能通过旋转/反向更新把预训练知识抵消掉。低秩结构还把任务特定的写入成本限制在相对小的参数量内；不同 task 可以拥有不同 residual，而不是强迫 CTR、CVR、检索共享同一个校准方向。

第三部分是只读 cross-attention。仅在 item embedding 上叠加 residual 还不够，因为用户意图位于预训练序列 encoder 的中间 hidden states 中。KGD 为 task learner 配置独立的 transformer，以 task-side reader token 产生 query，并从 encoder 的 hidden states 产生 key/value；key 和 value 都 stop-gradient。形式上 Q = W_Q rho，K = W_K stop_gradient(H_tilde)，V = W_V stop_gradient(H_tilde)。这是一条单向接口：task learner 能选择并重新投影上下文表示，task loss 只更新 task transformer 与 ACR，不能改动行为 encoder。因而它同时得到“读到预训练上下文”和“拥有自己的判别几何”两种能力。

训练/部署上，KGD 叠加在两类 backbone 上：公开实验使用 ManCAR 以保持可复现，工业 ranking 使用生产 OneRank。论文报告工业训练每天约 2 小时、在 A100 上进行，并采用交替训练：encoder 侧按流刷新，task 侧在固定接口上更新。线上 A/B 前离线交替训练约 1.5 个月，正式实验按 user-ID hash 分桶，control 和 treatment 各占 10%，每桶超过 1,000 万用户，另设 A/A 桶检查实验系统。

3. 核心技术贡献

  1. 把“刷新知识”和“写入任务几何”变成两个所有权。 这比泛化地说“多任务学习”更具体：encoder 只拥有可迁移行为结构，task learner 只拥有排序所需的判别结构，二者通过读接口耦合，而不是共享同一组会被不同梯度争夺的参数。
  1. BMTP 针对流式序列的监督噪声。 协同过滤器保护高活跃用户中可靠的共现关系，语义过滤器为稀疏尾部用户补充语义相似性。论文的工业消融显示，移除协同过滤时 head user（活跃度前 30%）click AUC 损失约 0.5%，移除语义过滤时 tail user（后 30%）损失约 1%，说明两个过滤器不是重复特征。
  1. ACR 用正交低秩残差保护预训练方向。 它不是简单加 adapter，也不是把预训练向量冻结后直接拿给任务头，而是明确规定任务写入发生在预训练几何的补空间。只读 cross-attention 则把这一原则从 item-level 扩展到 contextual hidden-state level。
  1. 用长窗口验证持续刷新。 90 天曲线比单个时间切片更能识别“短期有效、长期过时”的 transfer 方法。论文在 8 个公开 benchmark 上报告相对强基线约 4%–12% 的提升，并在 Shopee 搜索上给出可观业务实验。

4. 实验结果分析

公开数据与工业数据的结果应分开理解。公开 benchmark 主要验证方法是否能学习可迁移结构；工业流则验证结构漂移、稀疏转化和持续刷新。公开 benchmark 的 8 个数据集包括 Software、Video Games、Office、CDs、Arts、Phones、Toys、Beauty，规模从 14 万到约 590 万 interactions 不等。工业 28 天训练集约 13B 样本，click 正例率约 7.5%，order 正例率约 0.41%；随后追加 62 天得到约 42B 样本的 90-day study。

这些数字给出三个清晰结论。第一，ACR 不是装饰：去掉后工业 click AUC 从 0.7867 降到 0.7829，order AUC 从 0.9015 降到 0.8950；只保留 ACR 但共享参数仍明显不如完整解耦。第二，增加同等数量参数并不能解释收益，“参数量对齐但共享 backbone”在 Office 的 N@50 只有 0.0267，低于 KGD 的 0.0352，说明收益来自 ownership，而不是简单扩大容量。第三，BMTP 两个过滤器互补：语义过滤器对 tail 用户更重要，协同过滤器对 head 用户更有帮助；工业 click AUC 也分别下降到 0.7859 与 0.7854。

工业 schedule 的对照进一步说明刷新必须建立在隔离上。相同的持续更新安排下，KGD 达到 click AUC 0.7867；移除 ACR 和只读 encoder 接口后，结果坍缩到 0.7785，甚至低于 Scratch 的 0.7806。共享参数的 TA&FT 从一次预训练后冻结的 0.7852 在每日刷新后降到 0.7837，TA&FE 也只有 0.7841；buffer replay 为 0.7732，IncCTR 为 0.7810，LoRA 为 0.7818。这些结果把“刷新会不会有用”改写成“谁拥有刷新后的参数”：刷新共享参数会反复覆盖几何，历史 replay 又会记住不再复现的 stale pattern。

在线实验放在 Shopee Homepage Search 的 ranking stage。两周 A/B 结果是 GMV per user +1.75%、advertising revenue per user +1.53%；论文还把 CTR、CVR 与人工评估的 per-query irrelevant-item rate 作为护栏指标。这个结果很重要，因为它证明了提升不仅是离线 AUC 的数值差异，而且穿过了真实搜索流量、广告收益和相关性安全检查。与此同时，线上实验是 10%/10% 的大流量分桶，不能简单理解为小样本探索。

对结果的限制也要看清。工业数据经过下采样和负采样，13B 不是完整生产流量的原始统计，作者也承认它不能完全反映线上分布；因此 90-day 曲线更适合比较方法的相对衰减/稳定性，而不适合直接估算绝对转化率。公开数据与 Shopee 的 item、用户和时间结构差异很大，4%–12% 的公开提升不能机械外推到社区搜索。线上 GMV uplift 还可能受到同时期供给、曝光和实验策略影响，部署团队应复核分层结果。

5. 局限与未来方向

论文最大的边界是工业数据和实验细节无法完全公开。用户词表是千万级、item 词表接近十亿级，但精确规模受业务要求不能披露；训练数据经过强下采样/负采样，外部读者无法复现真实流量。公开 benchmark 虽有 8 个，但它们缺少真实用户-ID 漂移、可靠时间戳或可用语义特征中的一部分，不能单独证明 streaming refresh 在所有场景成立。

方法上，BMTP 依赖协同图、语义表示和阈值，阈值如何随类目、语言、冷启动 item 与流行度校准没有一个普适答案。ACR 的正交约束保护了预训练方向，但也可能限制真正需要重写语义空间的任务；低秩 residual 的 rank、正则强度与每个任务的容量如何分配，需要在不同延迟预算下验证。多任务之间也可能共享读出的上下文资源，论文主要验证 ownership 原则，未充分讨论任务数大幅增加后的参数和服务成本。

未来可做三类工作：一是把 encoder 刷新频率从每天扩展到小时级或事件触发，并衡量新鲜度和训练成本；二是让 BMTP 对新商品、长尾用户、跨域迁移和多模态内容使用更稳健的正例筛选；三是探索把 task learner 蒸馏到更小的在线模型，同时保留只读接口带来的稳定性。对生产系统，还应加入漂移告警、回滚版本、分群 A/B、隐私审计和新旧 item 的公平曝光检查。

6. 工业实践意义

对社区搜索和推荐团队，最值得复用的是架构边界，而非直接复制 Shopee 的 backbone。可以先将“用户行为知识 encoder”与“搜索相关性/CTR/CVR task learner”拆开：encoder 用较长窗口吸收 query、帖子、作者和互动之间的稳定转移；task learner 读取 encoder 的隐藏状态，单独写入相关性排序所需的几何。这样当社区热点、流行词和内容供给快速变化时，刷新语义/行为侧不会把已经校准的排序目标一起抹掉。

BMTP 的思想也适合 UGC。一次会话中的相邻帖子、评论或搜索 query 不能全部当作依赖；可以用作者/主题共现作为协同轴，用文本或多模态语义相似作为语义轴，分别筛掉跳转噪声。对 tail user，语义过滤比协同过滤更关键，这与论文中 tail click AUC 下降约 1% 的消融一致。对负反馈稀疏的转化任务，还应将“曝光但未点击”“点击但未深读”“深读但未关注”按任务拆开，避免一个 shared head 逼迫不同目标竞争。

落地时建议分三阶段。第一阶段只做离线复现：固定已有召回/排序 backbone，对比 shared fine-tune、freeze、LoRA、buffer replay 与 decoupled reader，按用户活跃度、内容新鲜度、query 长度和冷启动 item 分桶。第二阶段上线小流量：同时监控 nDCG/GAUC、CTR、CVR、GMV/用户、无关结果率、P95/P99、每日训练时长和 embedding 漂移；至少保留 A/A 桶与可回滚 encoder/task 版本。第三阶段再优化容量：分别扩大 encoder 和 task learner，避免用一个更大的共享模型掩盖“知识容量”和“任务几何容量”哪个真正有效。

最终判断是：KGD 的产业价值在于提供了一种可操作的持续学习合同。什么时候可以刷新、刷新哪个参数、哪些梯度必须被截断、怎样保证任务仍能写入新几何，都被写成了明确接口。对于有日级训练、短生命周期内容和多个排序目标的系统，这一合同比单次榜单提升更有长期价值；但上线前必须用自己的流量验证阈值、训练成本和漂移节奏，不能把论文的 +1.75% GMV/用户直接当作可复制的业务承诺。

1. 问题与动机

这篇工业案例研究关注推荐系统里一个常见但经常被平均指标掩盖的矛盾：同一个统一 feed 同时服务网页文章、长视频、短视频、UGC 等异质内容，而用户对不同内容类型的消费意愿、停留机制和曝光位置并不相同。如果用一个共享的 MLP/多任务模型在总体样本上优化，micro-AUC 可能上涨，但模型对某一内容类型的判断会被另一类型的样本主导，最终表现为跨类型不公平、用户兴趣被单一媒介吞没，或者多样性下降。

Google Discover 的实际场景把这个问题放大了。它要在一个 feed 中混合多个内容类型，排序系统还要同时预测点击/兴趣与不感兴趣等多个目标。论文将“异质性”从一个离线分析维度提升为模型输入和训练目标：HA-MoE（Heterogeneity-Adaptive Mixture-of-Experts）让 gating 读取内容类型与其他 heterogeneity context，并让 expert representation 也感知这种差异；LENS 则提供线上可观察性，以便定位哪种类型、哪类用户和哪个目标受到影响。论文的贡献不是宣称 MoE 普遍优于 MLP，而是展示在统一 feed 中如何把跨类型 xAUC、模型可解释性和线上多样性放在同一套工程闭环里。

研究的业务目标因此有两层。模型层要提高兴趣/不感兴趣预测并缩小 web、video 等类型之间的 xAUC gap；产品层要确保 DAU、Viewed Impressions、Scroll Depth 等消费指标上涨的同时，Diverse Feed Rate 和 Diverse Engagement Rate 不恶化。这个目标组合比单看点击率更适合资讯流：如果模型只是把最容易点击的一种视频推到所有位置，短期 CTR 可能好看，但用户体验与内容生态会变差。

2. 方法详解

基线是生产中的 shared MLP，多任务输出 11 个 task heads。所有内容类型共享底层表示，任务权重使用固定的多目标损失组合。对照方法包括标准 MMoE 以及两个删减版本：HA-MoE without HA-Gating、HA-MoE without HDLM。完整 HA-MoE 在 dense MMoE 结构中设置 N=4 个 experts，并在 gate 中注入 heterogeneity context；作者比较了 2、4、8、16 个 expert，选择 4 个作为效果、容量和工程成本之间的折中。

HA-Gating 的直觉是让同一个用户/上下文下，不同 content type 看到不同的专家混合权重，而不是所有样本沿用一个平均路由。gate 既接收基础用户与场景特征，也接收内容类型等异质性信号；每个 expert 的输出再经过与 heterogeneity 相关的表示处理，使差异不仅停留在最后的路由层。这样 web article、long video、short video 与 UGC 可以共享通用模式，同时保留各自的消费与兴趣结构。HDLM 是论文中与 heterogeneity-aware representation 相关的组件；移除它可以检验“只改变 gate”是否足够。

训练目标使用 DL-AUC（Diversity-aware/heterogeneity-aware loss 的 AUC 形式），把总体 micro-AUC 和跨类型 Macro-xAUC 组合起来：DL-AUC = lambda × Micro-AUC + (1-lambda) × Macro-xAUC，线上实验取 lambda = 0.8。Micro-AUC 保持主业务目标，Macro-xAUC 则对不同正/负类型组合的区分能力施加约束。论文报告的一个核心例子是 web+ 与 video-、video+ 与 web- 的 xAUC；两者差距越大，说明模型偏向某一内容类型的交互反馈，无法把用户对不同类型的偏好放进可比较的尺度。

LENS 是观测层而不是另一个 ranking tower。它将模型预测、content type、用户分层和 cross-type 指标关联起来，让离线表与线上变化可以追溯到具体类型对。工程上这一点很重要：平均 DAU 提升可能来自某一个强势类型，只有把 xAUC gap、Diverse Feed Rate、Diverse Engagement Rate 一并看，才能判断模型是否真的改善了统一 feed 的异质性。

实现方面，作者采用 Adam-family optimizer、11 个任务权重和 dense MMoE；expert 数量从 2/4/8/16 做搜索，最终 4 experts。模型在约 1,000 万条样本的 7-day holdout 上做离线评估，再进入多个 7-day、1% live traffic 的在线 A/B。模型增量控制得很紧：参数量增加低于 5%，训练速度与基线相当，线上 p50/p95 latency 增加低于 0.5%。这让论文更接近工业升级方案，而不是只适用于宽松计算预算的实验模型。

3. 核心技术贡献

  1. 把内容异质性写进 gating 和 representation。 标准 MMoE 只提供多个专家，但不保证专家分工与内容类型有关；HA-MoE 显式让 gate 和 expert representation 读取 heterogeneity context，减少共享表示对某一强势类型的偏置。
  1. 用 Macro-xAUC 补充总体 micro-AUC。 统一 feed 的质量不应只由总体样本排序衡量。跨类型的正/负比较能够暴露 web+ 对 video-、video+ 对 web- 等组合的差异，DL-AUC 通过 lambda=0.8 保留业务主目标，又不会把跨类型一致性完全牺牲掉。
  1. 把模型改动和可观测性绑定。 LENS 使跨类型指标、用户分群、流量实验与多样性指标在同一诊断框架中可追踪；这有助于发现“主指标涨、内容生态变窄”的回归。
  1. 证明效果并非依赖大幅扩容。 完整方案参数量增加不到 5%，p50/p95 延迟增加不到 0.5%，说明在已经存在的多任务排序系统中，异质性建模可以在接近原服务预算内完成。

效率结果对工业迁移很有价值。与 Shared MLP 比，HA-MoE 的模型 size 增量小于 5%，训练速度 comparable；serving p50/p95 latency 增量小于 0.5%。因此它更像对现有 dense ranking tower 的受控替换，而不是需要重新建设特征或 serving 平台的项目。不过 dense MMoE 的计算仍随 expert 数量增长，4 experts 是论文场景的选择，不能假设在所有 QPS、batching 和硬件上都保持同样的尾延迟。

实验仍有三点需要谨慎。第一，离线 holdout 约 10M，线上只有 1% 流量；论文报告的是多次 7-day 实验的汇总，无法从摘要判断各实验的样本量、显著性校正和每种 content type 的置信区间。第二，pInterest/pDisinterest 是模型指标，不等同于用户长期价值；推荐系统还需观察 hide、负反馈、留存、创作者供给和广告收益。第三，xAUC gap 的改善可能部分来自重新分配不同类型的曝光，必须结合 feed position、库存与用户人群分层，才能确认是表示变好而不是流量结构变化。

5. 局限与未来方向

论文是一个 Google Discover 的案例研究，数据、特征、11 个 task heads、content type taxonomy 和在线实验细节都不能完全公开，因此外部团队无法直接复现实验。它也没有证明同样的 HA-Gating/HDLM 配置在类型更多、内容更短、中文 UGC 或强实时热点场景中一定有效。异质性上下文的定义依赖产品形态：把 long video、short video、article、UGC 设成四类只是当前 feed 的建模选择。

目标函数中的 lambda=0.8 是一个业务权衡，不是理论上最优的常数。lambda 太大时仍可能回到 micro-AUC 主导，太小时可能为多样性牺牲核心 engagement；论文没有展开不同 lambda、不同 expert 数量和不同内容分布下的完整敏感性曲线。离线 xAUC 也不直接处理曝光偏置、位置偏置、内容供应量不足和用户主动选择不同入口的问题。

未来可以沿三条线推进：把 heterogeneity context 从离散 type 扩展为主题、时长、意图和用户阶段的组合；让 expert routing 随时间漂移并提供版本化/回滚；把多样性与长期价值、创作者生态和用户满意度纳入统一的因果或多目标实验。对于在线 serving，还应研究稀疏/条件计算、expert cache 与类型级别的延迟预算，避免模型效果随着 content type 数量增长而线性消耗资源。

6. 工业实践意义

对社区搜索和推荐，这篇论文最可复制的是“类型分层 + 跨类型评估 + 受控升级”的方法。社区 feed 可以把原创帖子、问答、评论、短视频、外链和广告视为异质内容；同一个 query 下，不同类型并不是可以互换的候选。排序模型应显式接收 content type、长度、作者关系、时效、媒体形态和用户当前 session intent，让 gate 学到“当前用户/场景应该组合哪些专家”，而不是把全部类型混成一个平均 embedding。

离线评估不要只报总体 AUC、nDCG 或 CTR 代理指标。应建立 content-type confusion/偏置矩阵，例如 query+ 对帖子-、视频+ 对帖子- 的 cross-type xAUC，并跟踪 Macro-xAUC 的均值和最差类型对。与论文中 0.141 降到 0.060 的 gap 类似，团队可以把“类型间最差差距”设为护栏；若总体 nDCG 上涨但某一类型 gap 扩大，应暂停发布。对于社区搜索，还要按 query 长短、是否实体查询、用户新老、帖子新旧、作者是否关注和内容语言分桶。

模型落地可从标准 MMoE 的小规模对照开始：固定四个 expert，比较 Shared MLP、Standard MMoE、只做 type-aware gating、只做 heterogeneity-aware representation 和完整方案。记录参数量、GPU/CPU 利用率、p50/p95/p99、训练吞吐和索引/缓存成本。论文的 <5% 参数增量、<0.5% 延迟增量可以作为工程目标，不应当当作承诺；必须在自有线上 batch size、QPS 和热 key 分布下重新压测。

上线实验建议同时观察五组指标：核心消费（CTR、长停留、播放完成、Scroll Depth）、搜索相关性（nDCG、无关结果率、query reformulation）、跨类型公平（Macro-xAUC、Diverse Feed/Engagement Rate）、生态安全（负反馈、作者覆盖、新内容曝光）和系统成本（训练时长、GPU、P95/P99、错误率）。采用 1% 小流量、多次 7-day 实验、A/A 桶和 user-level hash 分桶，能够减少类型与用户组成变化带来的误判。对于热榜或重大事件，还应单独检查 gate 是否把某种媒介过度放大。

最终判断是：HA-MoE 的收益来自把“异质内容不是噪声，而是条件”写进模型和评估。对于一个统一 feed 或统一搜索结果页，这种思路比单纯扩大 MLP 更值得优先验证；但成功关键在于 content type 定义、跨类型标签质量、lambda 权衡和多样性护栏。若团队只有一种内容形态或数据量不足以支持专家分工，复杂 MoE 可能只是额外成本；若产品同时服务多媒介内容并长期遇到“总体指标好、某类内容被压制”的问题，则这篇案例提供了很清晰的实验起点。

CILER 关注推荐在时间、地域或特征分布变化下的偏好漂移，先把潜在环境建模为用户条件指数族，再用特征索引多项式描述环境如何改变偏好，最后对环境分布边际化得到预测。论文给出可识别性与部署风险界，并在 3 个数据集、特征/时间/地理三类 OOD 设置上，让 12 个排序指标全部提升。

INSIGHT当社区用户兴趣受季节、地域或事件影响时，简单把环境变量拼入特征并不能保证可迁移。CILER 的价值在于把“环境—偏好”关系显式化并给出风险边界；工程上可先用时间切片和地域切片验证 latent environment，再将其作为风险感知重排或校准模块，而不是直接替换线上模型。
