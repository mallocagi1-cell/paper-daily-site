1. A Matryoshka Hierarchical RAG for Efficient Multi-Hop Question Answering
4.00
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 4

Summary: 多跳问答的索引构建与迭代检索都可能增加成本。MatRAG 将文档组织为多粒度 DAG，用套娃向量维度匹配层级，并以实体线索控制搜索跳数；无需知识图谱构建或大模型摘要。在 MuSiQue 上，Recall@2 和 Recall@5 相对最强基线分别提升 14.48% 和 13.37%，评测覆盖三个问答数据集。

Key insight: 可将社区帖子按主题形成层级索引，让搜索 Agent 先用低维表征定位话题，再扩展到细粒度证据，避免每一步都扫描全部语料。迁移时需要比较多跳证据覆盖、nDCG 和端到端成本；论文中候选数从 5 增至 10 会显著提高上下文 token，说明召回收益仍须配合预算控制。

2. Continuous Process-Level Evaluation for Evolving Enterprise AI Agent Skills
3.75
Relevance 4 | Novelty 3 | Practical 4 | Evidence 4 | Timely 4

Summary: 企业 Agent 的最终数字正确仍可能掩盖工具调用与数据库行为漂移。论文用独立真值、可复用模板和过程检查评估 240 次运行；175 次通过最终数值检查的运行中，162 次仍有其他偏差，占 92.6%。依赖归因将每次运行平均 6.34 个失败检查归并为 2.65 个根因。

Key insight: 社区搜索 Agent 的验收应覆盖查询参数、检索顺序、证据可见性与工具结果使用，而不能只看最终答案是否像正确答案。可用历史搜索请求构建回归模板，并将上游检索失败与下游生成失败关联，避免重复计数。论文评估的是受控企业任务，尚未证明实际 API 长期演化中的稳定效果。

3. Causal Memory Policy: Making Memory Utility Identifiable by Intervening on Retrieval
3.75
Relevance 4 | Novelty 4 | Practical 3 | Evidence 4 | Timely 4

Summary: 记忆价值评估只观察被检索的记忆，可能把未曝光误认为无用。CMP 为随机记忆预留上下文位置，以已知采样概率和逆倾向加权恢复效用可识别性。LongMemEval 与 LoCoMo 分别有 54% 和 67% 的必要记忆缺乏识别条件；CMP 将必要记忆判别 AUC 从 0.542 提高至 0.664。

Key insight: 社区搜索 Agent 若按历史使用次数删除用户偏好，容易持续忽略低曝光信息。可以先在离线回放中随机曝光一小部分记忆，区分检索失败与记忆无效；同时保留按查询分析的效用。论文发现当前查询上的价值难以预测未见查询，因此不宜把一次检索贡献直接变成永久保留或删除规则。

5. Agents Are Systems, Not Models: Rethinking Agentic Evaluation
3.70
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 4

Summary: 论文把 Agent 视为可配置系统，在四个科学任务上改变任务信息、推理、自检、预算与模型。相同配置重复运行贡献约 54% 的结果方差，任务信息的影响大于时间预算和模型大小；作者公开超过 18,000 条轨迹。专用验证工具比仅要求模型自检更能改变实际验证行为。

Key insight: 比较社区搜索 Agent 时，应固定索引、工具接口与检索预算，并多次运行同一请求，报告均值和波动，避免把偶然成功归因于模型升级。把证据验证做成可调用工具比单纯增加提示词更值得试验；时间预算与任务信息存在交互，因此延长推理不一定提高 nDCG 或答案可靠性。

7. Not All Experience Belongs in the Weights: Component Routing for Self-Improving GUI Agents
3.45
Relevance 3 | Novelty 4 | Practical 3 | Evidence 4 | Timely 4

Summary: 自改进 GUI Agent 将整段轨迹送入权重或上下文，容易混合不同性质的经验。论文拆分定位线索、过程、状态事实和教训，并依据重复性与状态条件性选择去向。在三类模型、两个环境和三个随机种子的比较中，规则预测命中留出模型的 24/24 个单元，路由平均比各模型较优单一去向高 3.5 点。

Key insight: 这一结果可作为搜索 Agent 经验管理的迁移假设：检索流程与当前状态进入可更新上下文，稳定且反复使用的模式再考虑训练入权重。应使用社区查询回放分别验证不同经验类型，而不能直接把 GUI 成功率当作搜索收益。作者表示代码与数据将发布，复现条件尚需等待，工程评分因此有所保留。

8. Mingbird: A Local-First Agent Harness Enabling Small Open Models to Complete Real Tasks
3.35
Relevance 3 | Novelty 3 | Practical 4 | Evidence 3 | Timely 4

Summary: Mingbird 为小型开放模型设计工具预算、完成门槛与循环检测，减少上下文溢出和虚假完成。固定设备、模型与预算的 LRAB 比较覆盖 288 个单元，其总分为 0.886，goose 为 0.631；在 278 个任务的 τ²-bench 上得分 0.856。单机、自建基准与单次评分限制了结论的外推。

10. Introducing Agentic Search for Code and Context
3.15

Summary: Entire 将代码精确搜索与提交、会话记录的语义搜索结合，帮助 Agent 检索工程决策及其原因。官方测试包含九个真实工程历史问题，每题重复十次；正确次数由基线 70/90 增至 81/90，token 与步骤数均少于基线一半。这是产品团队报告的小规模结果，尚无独立复现证据。
