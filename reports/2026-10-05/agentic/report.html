A Matryoshka Hierarchical RAG for Efficient Multi-Hop Question Answering

多跳问答的索引构建与迭代检索都可能增加成本。MatRAG 将文档组织为多粒度 DAG，用套娃向量维度匹配层级，并以实体线索控制搜索跳数；无需知识图谱构建或大模型摘要。在 MuSiQue 上，Recall@2 和 Recall@5 相对最强基线分别提升 14.48% 和 13.37%，评测覆盖三个问答数据集。

Continuous Process-Level Evaluation for Evolving Enterprise AI Agent Skills

IBMGeorgia Tech

企业 Agent 的最终数字正确仍可能掩盖工具调用与数据库行为漂移。论文用独立真值、可复用模板和过程检查评估 240 次运行；175 次通过最终数值检查的运行中，162 次仍有其他偏差，占 92.6%。依赖归因将每次运行平均 6.34 个失败检查归并为 2.65 个根因。

INSIGHT社区搜索 Agent 的验收应覆盖查询参数、检索顺序、证据可见性与工具结果使用，而不能只看最终答案是否像正确答案。可用历史搜索请求构建回归模板，并将上游检索失败与下游生成失败关联，避免重复计数。论文评估的是受控企业任务，尚未证明实际 API 长期演化中的稳定效果。

Causal Memory Policy: Making Memory Utility Identifiable by Intervening on Retrieval

Illinois Institute of Technology

记忆价值评估只观察被检索的记忆，可能把未曝光误认为无用。CMP 为随机记忆预留上下文位置，以已知采样概率和逆倾向加权恢复效用可识别性。LongMemEval 与 LoCoMo 分别有 54% 和 67% 的必要记忆缺乏识别条件；CMP 将必要记忆判别 AUC 从 0.542 提高至 0.664。

INSIGHT社区搜索 Agent 若按历史使用次数删除用户偏好，容易持续忽略低曝光信息。可以先在离线回放中随机曝光一小部分记忆，区分检索失败与记忆无效；同时保留按查询分析的效用。论文发现当前查询上的价值难以预测未见查询，因此不宜把一次检索贡献直接变成永久保留或删除规则。

Nankai UniversityAlibabaTsinghua University

PoS 为长程 Agent 维护当前世界状态与未解决需求组成的显式信念，并检测状态矛盾、循环和停滞后执行针对性恢复。在 RCA-100 上，Qwen3.7-Plus 的联合准确率从 24.27% 增至 38.83%；但总 token 消耗增至 5.06 倍，质量收益并不等于成本节约。

Agents Are Systems, Not Models: Rethinking Agentic Evaluation

TUMHelmholtz MunichInriaEENSCNRSPPSL

论文把 Agent 视为可配置系统，在四个科学任务上改变任务信息、推理、自检、预算与模型。相同配置重复运行贡献约 54% 的结果方差，任务信息的影响大于时间预算和模型大小；作者公开超过 18,000 条轨迹。专用验证工具比仅要求模型自检更能改变实际验证行为。

INSIGHT比较社区搜索 Agent 时，应固定索引、工具接口与检索预算，并多次运行同一请求，报告均值和波动，避免把偶然成功归因于模型升级。把证据验证做成可调用工具比单纯增加提示词更值得试验；时间预算与任务信息存在交互，因此延长推理不一定提高 nDCG 或答案可靠性。

Wiedmann, Luis, Girrbach, Leander, Schmid, Cordelia, Akata, Zeynep

A model guide for the GPT-6 family

OpenAI

这篇官方工程指南讨论模型选择、推理预算、提示与技能一致性，以及长程工作流的状态管理。文中给出缓存输入成本最多降低 95% 的条件性说明，并要求通过代表性任务衡量成功率、延迟和成功任务成本。它提供工具编排与生产优化建议，没有报告社区搜索 nDCG 或 CTR 的实验证据。

INSIGHT社区搜索 Agent 可把稳定的工具定义与索引说明放在共享上下文前部，对不同请求复杂度设置推理预算，再用成本与质量曲线选择配置。缓存折扣只是输入计费条件，不能当作端到端成本下降 95%。对长程搜索，应明确完成标准并保留关键证据，避免压缩上下文时丢失约束和来源。

Not All Experience Belongs in the Weights: Component Routing for Self-Improving GUI Agents

自改进 GUI Agent 将整段轨迹送入权重或上下文，容易混合不同性质的经验。论文拆分定位线索、过程、状态事实和教训，并依据重复性与状态条件性选择去向。在三类模型、两个环境和三个随机种子的比较中，规则预测命中留出模型的 24/24 个单元，路由平均比各模型较优单一去向高 3.5 点。

INSIGHT这一结果可作为搜索 Agent 经验管理的迁移假设：检索流程与当前状态进入可更新上下文，稳定且反复使用的模式再考虑训练入权重。应使用社区查询回放分别验证不同经验类型，而不能直接把 GUI 成功率当作搜索收益。作者表示代码与数据将发布，复现条件尚需等待，工程评分因此有所保留。

Mingbird: A Local-First Agent Harness Enabling Small Open Models to Complete Real Tasks

UUSTBHonor

Mingbird 为小型开放模型设计工具预算、完成门槛与循环检测，减少上下文溢出和虚假完成。固定设备、模型与预算的 LRAB 比较覆盖 288 个单元，其总分为 0.886，goose 为 0.631；在 278 个任务的 τ²-bench 上得分 0.856。单机、自建基准与单次评分限制了结论的外推。

INSIGHT部署低成本社区搜索 Agent 时，可先减少静态工具清单，并用查询目标重读和重复调用签名检测控制无效迭代。应保留索引覆盖与候选质量评估，防止工具裁剪隐藏必要能力；将完成门槛与单纯增加模型规模分别比较。论文的机制消融受重复运行波动影响，不能把每项设计都视为已独立证实。

Mapping the RAG Landscape: A Four Axis Taxonomy of Efficiency, Defense, Interactivity, and Reasoning

这篇综述把 RAG 研究整理为效率、防御、交互和推理四条轴线，涵盖稠密与稀疏检索、融合策略、强化学习检索策略及模块化架构。它将用户驱动工作流与多步推理纳入统一分类，便于比较 Agentic RAG 的设计选择。四轴是分类结构，文中并未给出新方法的量化性能提升。

INSIGHT社区搜索团队可以按四条轴线梳理现有 Agentic RAG：检索成本、证据可靠性、用户交互与多步推理分别建立验收指标。它更适合作为方案评审清单，而非性能依据；任何具体架构仍应以社区 UGC 查询集测试 nDCG、CTR 代理指标与引用质量，避免用综述覆盖面替代可复现实验。

Introducing Agentic Search for Code and Context

EEntire

Entire 将代码精确搜索与提交、会话记录的语义搜索结合，帮助 Agent 检索工程决策及其原因。官方测试包含九个真实工程历史问题，每题重复十次；正确次数由基线 70/90 增至 81/90，token 与步骤数均少于基线一半。这是产品团队报告的小规模结果，尚无独立复现证据。

INSIGHT社区搜索可以借鉴双通道证据组织：精确匹配定位原始帖子，语义检索补充讨论上下文与观点形成过程，再由 Agent 汇总出处。工程历史问答的结果不能直接推导 UGC nDCG 或 CTR 收益；试验应检查来源一致性、引用可追溯性和多轮成本，并保留强词法基线作为对照。
