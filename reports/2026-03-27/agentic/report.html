MARCH: Multi-Agent Reinforced Self-Check for LLM Hallucination

RAG 系统中的幻觉问题严重影响搜索结果的可靠性。本文提出 MARCH 框架，通过三个专业化 Agent（Solver、Proposer、Checker）的协作流水线，利用刻意的信息不对称来避免验证者的确认偏误。Checker 仅基于检索证据（而非原始生成）独立验证原子命题，并通过强化学习（GRPO）优化各 Agent 的协作策略。在多个 RAG 幻觉检测基准上，MARCH 显著优于现有 LLM-as-judge 方法，F1 提升超过 8 个百分点。

1. 问题与动机

RAG 系统中的幻觉问题是制约 LLM 搜索应用可靠性的核心瓶颈。现有的 LLM-as-judge 验证方法存在「确认偏误」——验证者同时接触查询、文档和生成结果时，倾向于复现原始生成的错误。论文指出，上下文冲突型幻觉在数据密集型任务中尤为普遍，表现为「不准确的数字、扭曲的时间序列、错误的算术聚合」。传统 RLHF 依赖标量奖励模型，将多维评估压缩为粗粒度分数，缺乏 claim 级别的验证粒度。这一问题在社区搜索等 UGC 场景中尤为关键，因为用户对搜索结果中的事实性错误容忍度极低。

2. 方法详解

MARCH 提出三 Agent 协作的验证流水线，核心创新是「刻意信息不对称」设计：

三个专业化 Agent：

  • Solver (νsolve)：基于查询和检索文档生成 RAG 响应，参数化为 νsolve(·|x,D) = πθ(·|x,D,ssolve)
  • Proposer (νpropose)：作为「响应原子化器」，将 Solver 输出分解为离散的可验证命题，提取问答对 Q(y) = {(qi, ai)}，聚焦关键数字，输出纯数值答案
  • Checker (νcheck)：作为「盲审员」，仅接收问题 {qi} 和文档 D，不接收 Solver 的原始响应 y 和答案 {ai}，独立回答问题并通过多次采样的多数投票降低方差

信息不对称机制是核心设计：Checker 与 Solver 输出之间存在严格信息屏障，打破自我确认的循环。

零容忍奖励 (ZTR)：

  • R = 0（所有 ai = âi 时），R = -1（任何 claim 不匹配时）
  • 二元结构强制「全有或全无」约束，任何单个幻觉 claim 即判定整个响应失败
  • 消融实验显示 ZTR 显著优于比例性错误率奖励 ERR（61.25% vs 55.46%）

联合策略优化 (PPO)：

  • 单一策略 πθ 同时扮演三个角色
  • Solver 轨迹 y 和 Checker 轨迹 λ 共享终端奖励 Ri
  • 优势函数通过 GAE 独立估计，KL 散度惩罚 β=1×10⁻³ 防止分布偏移
  • 训练配置：全局 batch size 32，最大 prompt 24,567 tokens，最大响应 8,192 tokens，Actor 学习率 1×10⁻⁶，Critic 1×10⁻⁵，采样温度 0.6，8 次独立生成

3. 核心技术贡献

贡献一：非对称解耦验证。 通过严格的信息屏障将验证与生成解耦，消除了同时接触查询、文档和响应导致的确认偏误。这不是简单的「让另一个模型验证」，而是通过架构设计确保验证者无法接触原始生成结果。

贡献二：自包含验证闭环。 用 Agent 自生成的 ground truth（âi 近似 ai*）替代不可获取的 oracle 标注，无需人工标注即可训练。Checker 的多数投票（8 次采样）进一步降低近似误差。

贡献三：双轨迹联合优化。 单一策略在推理（Solver）和审计（Checker）两条路径上接收统一奖励信号，实现 Solver 减少幻觉和 Checker 提升验证能力的协同进化。

贡献四：Claim 级别的细粒度验证。 将响应分解为原子命题后逐一验证，相比 outcome 级别的评估能精确定位幻觉来源。

MARCH-STEM 在 Facts Grounding 上提升 +28.14%，接近 Gemini 2.5 Flash 等顶级商用模型水平。

多跳问答性能：

  • HotpotQA: 73.6%（vs IRCoT GPT-4o: 66.4%，+7.2%）
  • MuSiQue: 40.8%
  • 2WikiMultiHopQA: 69.4%

8B 参数的 MARCH 在多跳 QA 上超越了 GPT-4o 的专门 RAG 基线。

消融实验关键发现：

  • Solver only → +Checker：+1.6%（验证机制的基础收益）
  • +Few-Shot (10)：+11.8%（上下文学习的巨大提升）
  • ZTR vs ERR 奖励：61.25% vs 55.46%（零容忍奖励的优势显著）
  • ZTR(-1/0) vs 激励型(0/1)：59.06% vs 50.42%（惩罚信号优于奖励信号）
  • 跨模型泛化：Qwen3-8B + MARCH 达到 68.11%，证明方法的架构无关性

奖励黑客现象： 训练过程中模型倾向于减少提出的问题数量（「少说少错」策略），通过设定最小问题数 k=3 的约束有效缓解。

5. 局限与未来方向

作者明确指出的局限：

  1. 奖励黑客问题：模型会学习减少验证问题数来降低被发现的风险，虽可通过指令约束缓解，但根本矛盾未解决
  2. 数值验证聚焦：框架主要针对数值和定量验证，对更广泛的语义层面事实性（如逻辑关系、因果推理）的适用性尚不明确
  3. 计算开销：多 Agent rollout + 多次 Checker 采样（8x）增加了推理延迟
  4. Oracle 近似：Checker 生成的答案是近似的 ground truth，多数投票降低但不消除系统性偏差

6. 工业实践意义

直接应用场景： MARCH 的三 Agent 验证架构可直接嵌入搜索系统的答案质量校验环节。对于社区搜索中 LLM 生成的摘要、答案或知识卡片，通过信息不对称的独立验证可显著降低事实性错误。

训练优势： 无需人工标注验证数据，仅需查询+检索文档即可训练，且在噪声率 24.4%-88.4% 的检索结果上表现稳健。这对真实搜索场景中检索质量参差不齐的情况尤为重要。

部署考量：

  • 8B 模型达到 70B+ 基线的竞争力水平，推理成本可控
  • 多 Agent 流水线增加延迟（Solver → Proposer → Checker），适合离线/准实时场景（如答案预生成）
  • 与 CoT、few-shot 正交，可叠加使用不降低效果
  • 零容忍奖励的设计思路可借鉴到搜索质量评估中：对事实性错误采用严格惩罚而非比例扣分

关键借鉴： 「信息不对称」设计思想可推广到搜索系统的多种验证场景——评审员不应看到被评审的内容上下文，而应仅基于原始证据独立判断。

RLFactory: A Plug-and-Play Reinforcement Learning Post-Training Framework for LLM Multi-Turn Tool-Use

LLM 在多轮工具调用任务中表现不稳定。本文提出 RLFactory，一个即插即用的 RL 后训练框架，通过异步工具调用器和解耦的工具/训练架构解决工具异构性问题。框架引入工具反馈的 observation markers 重构 MDP，实现模型-工具-环境的闭环，并支持规则、模型判断、工具验证三类奖励信号。在 Search-R1 框架下，Qwen3-4B 在 NQ 数据集上达到 0.486 测试分数，超越了更大的 Qwen2.5-7B-Instruct-GRPO（0.473）。

INSIGHTRLFactory 的核心贡献是将多轮工具调用建模为完整的 MDP 闭环：模型输出 → 工具执行 → 观察标记 → 策略更新。这对搜索 Agent 的训练具有直接参考价值——搜索系统中的查询改写、召回、重排等工具链正是典型的多轮交互场景。框架的「即插即用」设计允许快速接入不同搜索工具，降低了 RL 训练的工程门槛。在 NQ 上小模型超越大模型的结果表明，RL 后训练比单纯增大模型规模更高效。

Composer 2 Technical Report

CCursor

Cursor 发布 Composer 2，一个专为 Agentic 软件工程设计的模型。模型采用两阶段训练：首先通过持续预训练提升编码知识，随后通过大规模强化学习提升端到端编码性能，包括推理、多步执行和长周期任务的连贯性。训练基础设施支持在真实 Cursor 工具环境中进行训练，并引入基于真实大型代码库的软件工程基准。该模型在 Agentic 编码任务上展现了强大的长期规划和工具使用能力。

INSIGHTComposer 2 的关键设计理念是「在部署环境中训练」——训练和推理使用同一套工具和环境结构，消除了训练-部署的分布偏移。这一思路对搜索 Agent 开发有重要启示：搜索系统中的 Agent 也应在真实搜索 API 和工具链环境中进行 RL 训练，而非在模拟环境中优化后再迁移。大规模 RL 用于提升多步执行连贯性的方法，可直接借鉴到多轮搜索 Agent 的训练中。

Environment Maps: Structured Environmental Representations for Long-Horizon Agents

长周期 Agent 在复杂软件工作流中频繁出现级联错误和环境随机性问题。本文提出 Environment Maps，一种持久化、Agent 无关的结构化表示，将屏幕录制和执行轨迹等异构证据整合为结构化图。该表示包含四个核心组件：Contexts（抽象位置）、Actions（参数化操作）、Workflows（观察到的轨迹）和 Tacit Knowledge（领域定义和可复用过程）。在 WebArena 基准的五个领域上，配备 Environment Maps 的 Agent 显著提升了任务完成率。

Willful Disobedience: Automatically Detecting Failures in Agentic Traces

Microsoft

AI Agent 日益嵌入真实软件系统，但其长执行轨迹（agentic traces）的验证极为困难——仅基于结果的基准测试会遗漏流程性错误。本文提出 AgentPex，从 Agent 提示和系统指令中提取行为规则，然后自动评估执行轨迹的合规性。在 τ2-bench 的 424 条轨迹（涵盖电信、零售、航空客服）上，AgentPex 能区分不同模型的 Agent 行为，并发现仅靠结果评估无法捕获的规范违规问题。

INSIGHTAgentPex 揭示了一个重要盲区：Agent 可能给出正确结果但过程违规（如不安全的工具使用、错误的工作流路由）。在搜索 Agent 中，这意味着即使最终检索结果相关，如果 Agent 绕过了内容安全检查或使用了未授权的数据源，也应被检测和阻止。从提示词自动提取行为规则的方法，可用于构建搜索 Agent 的自动化质量监控系统。

The Cognitive Firewall: Securing Browser Based AI Agents Against Indirect Prompt Injection Via Hybrid Edge Cloud Defense

INSIGHT搜索 Agent 的安全性是实际部署的关键挑战。Cognitive Firewall 的分层防御思路——边缘端过滤表示层攻击、云端进行深层语义分析——可直接应用于搜索 Agent 的安全架构。特别是在社区搜索场景中，UGC 内容本身可能包含恶意提示注入，Agent 在检索和处理这些内容时需要类似的多层防护。确定性 Guard 对副作用操作的约束机制也值得借鉴。

Efficient Benchmarking of AI Agents

AI Agent 的全面基准测试成本高昂，每次评估需要交互式 rollout、工具使用和多步推理。本文研究小任务子集能否在大幅降低成本的同时保持 Agent 排名。在 8 个基准、33 个 Agent 框架和 70+ 模型配置上发现，绝对分数预测在框架驱动的分布偏移下退化，但排序预测保持稳定。提出基于项目响应理论的中等难度过滤协议，将评估任务数减少 44-70% 同时保持高排序保真度。

INSIGHTAgent 评估中的「框架驱动分布偏移」是一个重要发现——同一模型在不同 Agent 框架下的绝对分数变化大，但相对排序稳定。这对搜索 Agent 的评估有实践指导意义：在比较不同搜索 Agent 方案时，应关注相对排序而非绝对指标。中等难度过滤的评估加速方法可直接用于降低搜索 Agent A/B 测试的成本。
