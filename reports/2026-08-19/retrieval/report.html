Dense Expands, Sparse Anchors: Channel-Asymmetric Query Expansion for Hybrid Retrieval

论文研究混合检索中查询扩展与融合截断深度相互耦合的问题，提出 DESA：让 LLM 生成互补参考段落，用正交残差扩展稠密查询，同时用得分乘积把词法线索锚定到稀疏通道。作者在 7 个 BEIR 数据集上使 nDCG@10 提升 3.82%、Recall@20 提升 2.38%，稠密和稀疏访问深度分别下降 36.90% 和 36.56%。

Static Pruning Across Sparse Retrieval Regimes: What Transfers, What Breaks, and What Still Helps

论文跨 3 个检索引擎、2 个基准、SPLADE 与 V3-GTE 两类查询密度，完成 1,140 组静态剪枝实验，并用 TREC DL 2019/2020 深度判断复核。索引侧剪枝稳定带来 1.2–6.6 倍延迟下降和 18–82% 索引缩减；在 BMP 上结合文档与查询剪枝可获得 2.5 倍加速，同时 nDCG@10 与精确基线相差不超过 0.003。

INSIGHT这项研究给短文本召回提供了清晰的工程顺序：优先压缩倒排索引和 posting list，再谨慎评估查询剪枝，避免把现代引擎已内置的动态剪枝重复做一遍。可以把 nDCG 饱和而 Recall@10 仍约 85–95% 的区间作为压缩拐点，并用线上缓存命中和 P99 延迟验证迁移效果。

Zirui Song, Yuye Zhu, Yang Yang

RCEM: Embedder Equipped with Query Rewriting Skill for Robust Conversational Search in Distributional Shift

RCEM 将 LLM 的查询改写能力蒸馏进对话式稠密检索器，通过让会话查询向改写后的独立查询对齐，减少对高质量 query-document 标注的依赖。作者在 QReCC、TopiOCQA 和 TREC CAsT 上验证了分布偏移鲁棒性，Recall@10 最高提升 20%，且无需重建原有文档索引即可兼容独立查询。

INSIGHT社区搜索中的短 query、上下文省略和口语化表达可以复用这一思路：把改写能力放进 query encoder，避免每次请求都调用大模型。落地时应把会话查询和独立查询混合评估，并重点检查改写造成的实体漂移、敏感词扩展和长尾 query 召回变化。

Kilho Son, Paul Hsu, Cha Zhang, Dinei Florencio

04 3.95

Coverage Is Not Redundancy: Maintenance Cost and Exposure of Query-Aware Admission Indexes in Vector Databases Under Workload Drift

论文分析向量库中的 retrieval hub：单个文档被异常多的查询命中并垄断某一主题证据的问题，提出基于 sentinel query 的入库准入检查。实验覆盖 HNSW、IVF-Flat、IVF-PQ 和 880 万向量 MS MARCO；当索引召回率低于约 0.5 时约束失效，而 recall-aware witness probe 可在固定 O(|S|d) 成本下恢复 containment，PostgreSQL/pgvector 实现的写入开销为 0.33%。

INSIGHTUGC 内容持续写入时，相关性不只取决于单次 top-K，还取决于某些热门或模板化帖子是否长期霸占召回曝光。可以把 hub 暴露率、主题覆盖率和写入开销纳入索引监控；对 IVF-PQ 等压缩索引，应先做工作负载漂移压测，再决定 sentinel 数量和准入阈值。

Prashant Kumar Pathak

05 3.80

NeuRoute: Logit-Guided Neural Routing for Billion-Scale Vector Search with Sub-Hour Index Construction

NeuRoute 用轻量神经编码器学习均衡二进制地址，将向量按桶组织并在桶内聚类；查询时根据 logit 偏离阈值的程度优先探测不确定 bit，再以候选簇质量提前停止低价值探测。BigANN-1B 上达到 Recall@10 90.3%、2,414 QPS，在相近精度下比 OPQ+IVF-PQ 快 1.7 倍，并把训练加建索引控制在 1 小时内。

INSIGHT当社区内容规模增长到十亿级时，索引构建时间会直接影响新内容可搜索的时效性；NeuRoute 的不确定性探测提供了比固定 nprobe 更灵活的预算分配方式。短期可借鉴其查询自适应 probing 和早停思想，先在离线重建与增量更新链路中验证 P99、Recall@K 和索引新鲜度。

Xingqiao Wang, Zi Wang, Xiaowei Xu

06 3.80

Skill2Query: Exploiting Skill Structure to Generate Pseudo-Queries for Agent Skill Retrieval

Skill2Query 把技能文档解析成 Skill Knowledge Graph，再经过风格模仿、查询模板生成和参数填充三阶段生成伪查询，用于索引扩充、在线改写和检索器训练。实验覆盖 TheoremQA、LogicBench、ToolQA、CHAMP，约 3 万个技能生成 70 万条伪查询，在稀疏、稠密和路由检索设置下平均提升 Recall@1 6.70 个百分点。

INSIGHT对社区搜索，可将帖子实体、主题、时间、地点和用户意图视为结构化字段，按字段关系生成训练 query，而不是只做同义词扩写。该方法尤其适合解决长尾 UGC 的监督稀疏问题，但必须校验伪查询中的实体和属性一致性，防止扩大错误标注。

FROG: Efficient Range-Filtering Approximate Nearest Neighbor Search on GPUs

FROG 面向带数值范围过滤的 GPU 近似近邻搜索，采用全局感知、以顶点为中心的索引结构组织扩展邻居，并为建索引和查询分别设计 GPU 算法，减少局部子图导致的冗余距离计算。六个数据集上的混合选择性查询显示，相比 44 核 CPU 基线吞吐提升 14.7–37.7 倍，相比最强 GPU 基线提升 4.5–7.6 倍，建索引加速 2.4–14.8 倍。

INSIGHT社区搜索常需同时满足语义相似与时间、地域、内容状态等过滤条件，单纯把过滤放在 ANN 之后会浪费大量候选计算。FROG 的启示是把属性过滤纳入索引和 GPU 扩展过程；实际接入前要按过滤选择性分桶测量吞吐、召回和显存，而不是只看无过滤向量检索成绩。

Xiaokun Cui, Pengbo Liu, Jiadong Xie, Yingfan Liu, Hui Li, Jeffrey Xu Yu, Jiangtao Cui

Run Massive-Scale UMAP in Minutes Using Multiple GPUs—Without Losing Accuracy

NVIDIA

NVIDIA 工程博客介绍使用多 GPU 扩展 UMAP，以分钟级处理大规模向量的降维和特征提取任务，并强调在速度提升的同时保持嵌入空间结构。它不是新的召回模型，而是一项与 embedding 分布可视化、聚类分析和索引诊断相关的工程实践，适合辅助定位向量空间中的孤立簇、热点簇和漂移。

INSIGHT对于 UGC 搜索，UMAP 更适合做离线诊断而不是在线召回：可按时间、语言、主题和命中率切片观察 embedding 漂移，再反哺 hard negative、分桶和索引参数。上线前应把降维图与真实 nDCG/CTR 关联起来，避免把二维视觉聚类误当作相关性证据。

Can Retrievers Find the Same Paper from Different Aspects? A Multi-Aspect Full-Paper Scientific Retrieval Benchmark

MAPLE 构建了面向论文背景、方法和实验等不同检索侧面的全论文评测集，包含 2,095 个专家验证 query，并用 MAPLE-Synth 结合 OpenReview 讨论和人工示例生成真实查询。跨词法、科学领域、通用文本和多模态检索器的实验显示，最强模型 AnyAspect@20 为 98.1%，但 AllAspect@20 仅 15.7%，实验/结果和表格引用查询最难。

INSIGHT社区 UGC 的相关性也常按事实、观点、步骤和结果等侧面变化，单一 query-doc 命中率可能高估真实体验。可以借鉴多侧面 query 集与 AllAspect 指标，把同一帖子在不同意图下是否都能被找到纳入评测，并用多 chunk 聚合验证短文本与长帖的差异。

Yiyang Wei, Fang Guo, Qiji Zhou, Zhizhang Fu, Mengru Ding, Kai Yang, Yue Zhang

10 3.05

An Empirical Analysis of Pruning Techniques: Performance, Retrievability and Bias.

这篇 CIKM 2017 论文研究倒排索引静态剪枝如何同时影响检索效率、可检索性和偏差，在 TREC GOV2 的 2,500 万文档、3,900 万唯一词项集合上比较 4 种剪枝方法。结果表明，剪枝初期偏差变化很小或略降，但超过拐点后偏差显著上升，并伴随 NDCG@10 和 MAP 的明显下降。

INSIGHT它提醒搜索团队不要把索引压缩只当作延迟优化：对短文本和长尾主题，剪枝可能让部分内容系统性不可见。实践上应同时监控 nDCG、MAP、query 覆盖率与文档 retrievability，在每个压缩档位保留长尾 query 和低曝光内容的回归集。

Ruey-Cheng Chen, Leif Azzopardi, Falk Scholer
