Coverage Is Not Containment: A Fundamental Limit of Admission-Time Defenses Against Coordinated Poisoning of Vector Retrieval

论文研究向量检索系统面临的协同投毒风险：攻击者只需注入少量单独看似正常的文档，就能共同包围目标查询并夺取 top-k。实验在 BGE-large、BEIR、HNSW 和 Qwen2.5-7B 链路上显示，10 个文档可在离线索引中占满 10/10 结果，在真实 HNSW 中达到 9.9/10，并使生成器在 88% 的目标上输出攻击者植入的说法。

OGX: An Open-Source, Vendor-Neutral Generative AI Application Server

OGX 提出开源、厂商中立的生成式 AI 应用服务器，以统一 API 隔离应用代码与模型和部署选择。系统兼容 OpenAI、Anthropic、Google 等接口，支持超过 20 个推理提供方、13 个向量存储后端，并提供 Kubernetes Operator，覆盖 RAG、多轮 Agent 与工具调用等服务形态。

INSIGHT社区搜索可以把 query 理解、向量召回、重排和生成服务放在统一的可替换接口后面，降低模型升级和供应商迁移成本。落地时应把接口兼容性、向量库适配、灰度路由和观测指标作为平台能力，同时保留对 nDCG、CTR、P99 延迟和 token 成本的端到端追踪。

面向分布式推理的大模型键值缓存分发网络

中中国移动中国科学院

文章面向分布式大模型推理中的 KV 缓存跨节点传输问题，讨论缓存分发网络的架构、节点协同与服务实现。其核心是把 KV 缓存从单机推理栈中的隐含状态提升为可调度的基础设施资源，服务于 Prefill-Decode 分离、跨节点复用和大规模在线推理。

INSIGHT对短文本搜索，query 编码和重排请求通常具有突发流量，KV 池化可以减少重复 Prefill 并改善 GPU 利用率。工程上应先定义缓存命中率、跨节点带宽、P99 TTFT、失效回收和租户隔离指标，再决定缓存分发协议；缓存内容还要绑定权限与版本，避免旧上下文泄露或模型切换后误复用。

Demystifying the Design Space and Best Practices for Heterogeneous LLM Inference and Serving

论文系统分析异构硬件、软件栈与工作负载共同作用下的大模型服务设计空间，重点讨论 KV 缓存驻留、传输、精度和生命周期，以及 vLLM 中的服务交接路径。作者总结 9 项设计实践，并报告在特定配置下优化 KV 精度可将可持续请求率从 0.1 请求/秒提升到 1.0 请求/秒。

INSIGHT推理优化不应只比较单卡 tokens/s，而要把硬件类型、并行方式、KV 精度、请求长度和调度策略作为联动变量。社区搜索可以先按 query 长度和请求优先级分层，再用小规模压测寻找吞吐、P99 延迟、显存和质量之间的 Pareto 点，避免将单一 benchmark 的结论直接迁移到生产。

Ventor-QTest: Threat-Model-Driven Verification of Vendor-Hosted LLM APIs

Ventor-QTest 将托管大模型 API 的质量审计形式化为随机路由过程，提出不依赖目标 API 概率信息的黑盒测试。方法通过重复请求冻结上下文估计平均保真损失 AFL，并用长序列独立运行测量极端保真损失 EFL，针对供应商路由、输出稳定性和长上下文退化建立可比较的观测指标。

INSIGHT当社区搜索把 query 改写、重排或摘要交给外部模型时，平台不能只监控 HTTP 成功率和平均延迟。应把同一输入的输出分布漂移、长上下文质量、供应商切换和模型版本变化纳入回归门禁，并按搜索意图分桶观察 nDCG、CTR 与生成质量是否同步退化。

pico-type: A 1.5M-Parameter Byte-Level Multi-Head Content Classifier

pico-type 用约 1.5M 参数的字节级模型在一次前向计算中同时预测 7 类内容属性，包括类型、模态、语言、MIME 和风险标记。架构由字节嵌入、3 个不同感受野的卷积块、2 层双向注意力、统计池化和 7 个 Matryoshka 分类头组成，并提供 16 到 576 维的分层表示与 ONNX 导出路径。

INSIGHTUGC 搜索的内容路由、风险过滤和索引分层不必都依赖大模型；小模型、多头输出和可裁剪表示适合放在召回前的高并发路径。建议以字节级输入覆盖混合语言和脏文本，优先测量 CPU/GPU 成本、P99 延迟、风险召回率及误杀对 CTR 的影响，再决定是否接入大模型复核。

Gautam Kishore

Efficient Privacy-Preserving Range Filtered Approximate Nearest Neighbor Search

论文研究外包向量数据库中的隐私保护范围过滤近似最近邻搜索，目标是同时隐藏向量、属性和查询。方法把范围定位放在授权用户侧的 N 叉属性树上，服务器只在对应的加密邻近图子索引中检索，再用 filter-and-refine 流程减少昂贵的密文比较，形成从范围过滤到向量搜索的分工。

INSIGHT社区平台的 UGC 向量可能包含用户属性、地理范围或敏感主题，托管向量库时不能只考虑召回率和成本。可以借鉴客户端范围定位与服务端加密检索的拆分，先按租户和访问策略缩小候选分区，再用密文近邻检索；上线前要验证加密开销、泄露面、索引更新和 nDCG 的共同变化。

Haoyu Wang, Yandi Zhang, Jiadong Xie, Yingfan Liu, Hui Li, Jeffrey Xu Yu, Jiangtao Cui

ConceptFormer: Learning Adaptive Latent Concepts for Query-Document Alignment in Visual Document Retrieval

ConceptFormer 面向视觉文档检索中的 query-document 对齐，把查询相关证据表示为连续、查询条件化的潜在概念，用来连接文本、版式、图表等分散的视觉证据。方法不依赖文本中间描述，也不直接依赖原始视觉标注，针对多模态 RAG 中证据跨页面和跨模态分布的问题提供了新的 embedding 建模路径。

INSIGHT如果社区内容逐步包含图片、截图和图文混排，单一文本 embedding 会遗漏版式和局部证据。可以把查询条件化潜在概念作为第二路向量表示，与现有文本召回并行，再用轻量重排融合；上线前需单独评估图文混排样本的 Recall、nDCG、索引体积和多模态编码延迟。

Peng Chunyi, Xu Zhipeng, Yan Yukun et al.

Domain-Specific Text Embedding Models for Entity Resolution

论文考察通用文本向量模型在实体解析和重复记录检索中的局限，提出用带 margin 的 triplet 微调让 embedding 学会区分身份保持的文本变体与高度相似但不相同的记录。作者构造业务和人物记录的合成数据，并比较 2 个通用 embedding 模型微调前后的相似度分离能力，结果显示领域微调能明显改善匹配边界。

INSIGHT短文本搜索中的同义表达与实体混淆可以用领域 triplet 数据改善，但不能把实体匹配收益直接等同于相关性收益。工程上应保留通用 embedding 与领域 embedding 的双塔或级联路径，在 hard negative、长尾实体、中文别名和新词冷启动上分别评估 Recall、nDCG、误合并率与索引重建成本。

腾讯云边缘推理：开源模型在线服务部署实践

腾讯

腾讯云文档给出将 1 个示例开源模型 Llama-3.2-3B-Instruct 部署为边缘在线推理服务的流程，覆盖容器镜像、服务凭证、API 调用和故障排查 4 个环节。该实践把模型从镜像构建到边缘节点上线的基础设施链路具体化，适合低延迟搜索或近端内容处理场景参考。

INSIGHT对社区搜索，边缘推理的价值在于缩短请求到模型的网络路径，并把模型服务的凭证、镜像和故障处理标准化。落地时应先以 query 改写、轻量重排等低延迟任务做灰度，记录端到端 P99、冷启动、GPU 利用率和 nDCG/CTR 变化，再决定是否把更大模型下沉到边缘。
