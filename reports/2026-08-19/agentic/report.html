When Deep Research Agents Stagnate: Enhancing Reasoning with Retrieval-Aware Agent Control

论文分析深度研究智能体的推理轨迹，发现大量迭代几乎不带来新信息，提出结合搜索新颖度与信息覆盖度的 Retrieval-Aware Agent Controller（RAAC）。在 BrowseComp-Plus 及多类深度研究智能体上，RAAC 平均减少 14 次搜索调用，准确率平均提升 3%，最高提升 10%。

The Commercial Tax: Rent-vs-Own Blind Spots in Multi-Hop Retrieval Benchmarks

论文审计多跳检索基准中常被忽略的商业许可和构建成本，并在统一 MuSiQue 测试框架中比较 8 家厂商的 13 个 embedding 模型。此前商用模型在 Recall@5 上落后 2.31 个百分点；2026 年 7 月发布的 Nemotron-3-Embed-8B 已缩小差距至 +0.24，差异不显著。

INSIGHTAgentic RAG 选型不能只看论文榜单，还要把许可证、显存、索引构建和可替换性纳入验收。企业落地应固定同一多跳任务集，记录 Recall@5、成本和置信区间，避免把不可商用的 SOTA 直接当作线上方案。

Luis M. Sanchez, Kosrow Dehnad

The Recall Trap: A Recall-Maximizing Retriever Configuration Reduces Issue Resolution in Fixed-Budget Code Context

论文在 SWE-bench Verified 中研究固定 12 槽上下文预算下的检索配置，发现提高 Recall@K 不一定提高任务成功率。关闭按文件去重后，gpt-5.6-sol 单次修复率从 39.2% 升到 46.8%（+7.6 个百分点），Qwen3.6-27B 复现提升 3.6 个百分点。

INSIGHT对搜索 Agent，检索指标必须和最终任务指标绑定；固定上下文预算下，更多文件覆盖可能挤掉同一文件内的关键证据。社区 UGC 场景也应 A/B 测试上下文打包、证据深度和回答/点击结果，而不是只优化 Recall@K。

Alexander Adkins, Teimuraz Trapaidze

Plan Before Search: Search Agents Need Plan

Plan 让搜索 Agent 在第一次检索前先把问题拆成有序子问题，使每步搜索锚定既定目标，减少被部分相关文档带偏。作者在 3B–14B 的三个模型家族上发现相同奖励会产生不同 RL 失败模式，并用小模型筛选轨迹自举，在多跳问答基准上稳定超过基线。

INSIGHT复杂搜索适合先规划证据依赖，再逐步检索，而不是让每轮结果决定下一轮方向。对短文本社区搜索，可把‘实体确认—属性补齐—交叉验证’建成轻量子问题链，并按 query 难度选择是否启用，避免简单 query 被过度推理拖慢。

When Tool-Backed Skill Retrieval Fails: Source-Style Collapse in Executable Capability Retrieval

论文发现工具检索器会因训练来源风格变化而失效，即使工具库本身不变；作者将这种现象称为 source-style collapse，并用查询侧 TF-IDF 指纹检测风格错配。ToolScout 在 4,996 条混合查询上把覆盖率从 22.3% 提升到 86.1%，五个坍缩来源的 top-1 代理指标从 1.3% 提升到 53.9%。

INSIGHTAgent 的工具调用质量首先受工具检索闸门影响，语义相似度高不代表能找到可执行能力。线上可增加来源风格监控和路由守门，按工具描述、参数格式和调用示例做分布漂移检测，再决定是否切换检索器或补充少量示例。

Yiqi Liu, Joseph James, Yang Wang, Chenghao Xiao, Chenghua Lin

Cost Scales with Change, Not Corpus Size: Incrementally Maintaining an Evolving Semantic Substrate

论文把语料语义关系在入库时编译成可查询的低秩语义基底，并研究语料持续变化时的增量维护。合成实验将语料从 3,000 扩到 9,000 篇、经历 50 次更新；增量更新单次便宜 33.7 倍、累计便宜 23.8 倍，Recall@10 保持 1.0，仅重嵌入约 10% 文档即可达到 0.95 平均余弦相似度。

INSIGHTAgentic RAG 的成本不应随每次问题重复解释整个语料。对持续增长的 UGC，可把主题、实体和语义邻接关系做成增量维护层，只对变化内容更新；同时保留全量重建作为周期校准，监控 Recall@10 和语义漂移。

Yusuke Takahashi, Kyle Wild, Asako Uraki

When Is Complex Chunking Worth It? A Multi-Objective Evaluation of Chunking Methods at Scale

论文在两个可扩展语料、三种 embedding 模型和多种规模上比较八类 chunking 方法，同时测量检索效果、索引吞吐、查询延迟和内存。结果显示，复杂且昂贵的切分很少稳定超过简单方法；即使效果相近，运行成本也可能差异很大，最佳方案取决于模型、数据集和目标指标。

INSIGHTAgentic RAG 的上下文质量先受切分粒度约束，不能只凭离线 Recall 选择复杂 chunker。社区内容应按帖子长度、结构和 query 类型做多目标评估，把索引时间、P99、内存与 nDCG/回答正确率放在同一张决策表里。

ClawGym II: Exploring Black-Box RL on Agent Harness

ClawGym II 提出面向复杂 Agent Harness 的黑盒强化学习框架：用沙箱并发 rollout、服务代理捕获模型调用，再用前缀树重建多轮轨迹，适配 PPO 和 GRPO，并进行混合 Harness 训练。Qwen3-30A3B 在 ClawGym-Bench 上通过 OpenClaw 和 Claude Code 分别提升 Pass@1 9.98 和 14.81 个百分点，200–400 步训练仍保持稳定。

INSIGHT当 Agent 行为由外部搜索、浏览器或代码 Harness 决定时，直接拿最终分数做 RL 会丢失中间轨迹。可借鉴其‘边界代理捕获调用—前缀树复用—多 Harness 联训’设计，但生产接入前应隔离工具副作用，并把搜索成本、失败恢复和安全约束纳入奖励。

Huatong Song, Fei Bai, Ming Yang, Renyuan Li, Jia Deng

Think Inside the Chunk: RegulaRAG for Regulation-Compliant Scenario Generation using LLMs: A Case Study of UN Regulation No. 152

RegulaRAG 面向长篇层级法规，结合 SmartChunking、图遍历增强段落与表格的引用关系，以及 Smart Retrieve & Rerank 生成合规测试场景。针对 UN Regulation No. 152 的人工整理数据集，它在五个基线中取得最高 Meta-Score 82.99，较 NoRAG 的 57.94 高 43%，每个 query 使用 14k–25k tokens，而图式基线最高消耗 500k。

INSIGHT这项工作说明复杂 Agent 检索的关键是保留跨 chunk 的引用和证据关系，而不是盲目扩大上下文。对社区问答可把帖子、评论、引用和时间线连接成轻量证据图，再用重排控制上下文预算，优先保证可追溯性和冲突检测。

Vahid Zolfaghari, Nenad Petrovic, Andr\'E Schamschurko, Alois Knoll

How AI Coding Agents Can Unlock Materials Simulation with NVIDIA ALCHEMI Toolkit

NVIDIA

NVIDIA 工程博客展示 AI Coding Agent 如何调用 ALCHEMI Toolkit，把材料科学知识、计算高效的原子模拟实现和可访问的工具接口连接起来。该实践将 Agent 从文本生成推进到可执行科学工作流，重点是通过工具调用完成模拟配置、运行和结果解释。

INSIGHT对 Agent 搜索系统，工具检索和工具接口同样是能力边界：模型必须找到正确工具、填对参数并处理执行结果。社区搜索可借鉴这种分层设计，把检索、结构化参数校验和结果回写拆开观测，并为失败调用保留可复现轨迹。
