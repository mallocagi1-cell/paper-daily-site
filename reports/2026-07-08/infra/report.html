Towards Load-Aware Prefill Deflection for Disaggregated LLM Serving

这篇论文针对分离式 LLM serving 中 prefill 节点排队、decode 节点空闲的结构性浪费，提出在 decode 节点上按块执行部分 prefill 的 load-aware deflection 调度器。作者在 2P2D A100 生产式集群和 DeepSeek-V2-Lite trace 上发现，prefill 执行本身只占 P95 TTFT 的 2%–23%，瓶颈主要来自排队和跨节点 KV 传输；实现到 vLLM 后，P95 TTFT 最高降低 81%，SLO 达成率最高提升 79%。

Lynx: Progressive Speculative Quantization for accelerating KV Transfer in Long-Context Inference

Lynx 解决分离式长上下文推理中 KV cache 跨网络传输阻塞 decode 的问题。它把 KV cache 拆成高优先级 Anchor 流和低优先级 Residual 流，先传最重要的高位信息让 decode 投机开始，同时并发传输剩余精度并做验证；在多模型与 serving workload 上，TTFT 接近激进 4-bit KV 量化，同时保持 BF16 级精度，相比标准 8-bit KV 量化 TTFT 最高提升 1.43 倍，准确率相比 SOTA 最高提升 5.1%。

INSIGHT这篇工作的关键不是“再压低 bit 数”，而是把 KV 传输从一次性阻塞路径改成可渐进消费的数据流。对长上下文搜索、RAG 和 Agent 工作负载，Anchor/Residual 分流意味着可以在网络传输尚未完全结束时启动生成，并通过验证避免低精度带来的不可控质量损失，适合与分离式推理、KV 远端缓存和跨机房 serving 结合。

Wenchen Han, Gingfung Matthew Yeung, Marco Barletta, William Toner, Amory Hoste, Adam Barker

KVpop -- Key-Value Cache Compression with Predictive Online Pruning

KVpop 面向自回归解码中 KV cache 随上下文线性增长导致的显存和带宽瓶颈，学习一个固定预算的在线 KV 淘汰策略，而不是依赖静态 heuristic 或 proxy score。它用 future-attention target 直接监督 keep/drop 决策，并加入延迟记忆 scorer 利用近未来上下文；在 AIME 和 HMMT 数学推理上，Qwen3-4B 在 75% KV 压缩下保持 full-attention 98% 性能，在 88% 压缩下保持 97%，Qwen3-8B 接近 teacher 表现。

INSIGHTKVpop 的价值在于把 KV eviction 从“当前 token 的局部重要性估计”改成“预测未来 attention 是否还会用到”。搜索和推荐中的长会话、多轮 query refinement、Agentic RAG 都会产生长上下文，这种未来注意力监督能在压缩率很高时保持推理质量，适合作为 vLLM/SGLang KV 管理策略的候选插件。

Lukas Hauzenberger, Niklas Schmidinger, Anamaria-Roberta Hartl, David Stap, Thomas Schmied, Sebastia...

Tropical: Enhancing SLO Attainment in Disaggregated LLM Serving via SLO-Aware Multiplexing

Tropical 分析了非分离式和分离式 LLM serving 的互补缺陷：前者排队时间低但 prefill/decode 互相干扰，后者干扰低但队列时间高。论文提出 SLO-aware multiplexing，在 TTFT 与 TPOT 约束下动态平衡排队和干扰；真实数据集评估显示，在 90% SLO 达成目标下可处理最多 2.09 倍请求，相比纯分离式系统 P90 TTFT 提升 9 倍，仅牺牲 15% P90 TPOT，相比非分离式系统 P90 TPOT 提升 2.8 倍。

INSIGHT这篇工作说明 serving 架构不应被固定为“分离式一定更优”或“合并式更简单”，而应围绕业务 SLO 动态切换复用方式。对搜索场景，TTFT 影响首屏体验，TPOT 影响长答案流畅度；Tropical 这类双指标调度可以把 query 类、摘要类和多轮 Agent 类请求放在同一集群内差异化治理。

Energy-Aware Scheduling for Serverless LLM Serving on Shared GPUs

Festina 针对 serverless LLM serving 中多模型共享 GPU 的能耗优化问题，提出 profiling-guided、power-aware 控制面。系统用全局调度器基于离线 profile 和 GPU 状态做常数时间 placement，本地调度器按 prefill/decode 阶段调整 batching 与 SM 资源，并通过 SLO-aware migration 做负载整合；与 4 个 SOTA LLM serving 系统和 1 个 DVFS 增强系统相比，能耗最高降低 56%，SLO 达成率保持在 2% 以内。

INSIGHT当 LLM 推理成为常态化云工作负载后，GPU 利用率不再是唯一目标，单位 token 能耗和静态功耗同样影响成本。Festina 的工程启示是把 request placement、SM partition、GPU operating point 和迁移放到一个控制面联合决策，特别适合多租户搜推平台在低峰时段做节能整合，而不牺牲 TTFT/TBT 约束。

Tianyu Wang, Gourav Rattihalli, Aditya Dhakal, Longfei Shangguan, Dejan Milojicic

Enhancing Goodput in Large-Scale LLM Training with Nonuniform Tensor Parallelism

NVIDIA

NVIDIA 这篇工程博客讨论大规模 LLM 训练的 Goodput，而不是只看原始硬件吞吐。文章聚焦数千 GPU、长时间训练任务中常见的资源波动和设备不可用问题，介绍 nonuniform tensor parallelism 如何让训练作业在可用 GPU 数变化时弹性调整并继续产生有效训练进展；相关资料指出，在高 TP degree 场景下，0.1% GPU 失效就可能造成接近 10% 的吞吐损失，而 NTP 目标是把损失压到更接近实际失效比例。

INSIGHT对训练基础设施团队来说，真正要优化的是“完成有效训练 token 的速度”，不是瞬时 TFLOPS。NTP 的实践价值在于降低单卡或小批量 GPU 异常对整个 tensor-parallel domain 的放大效应，适合用于搜推大模型预训练、后训练和 embedding/reranker 大规模训练集群的容错设计。

整合软硬一体化智算底座与大模型全链路落地实践

Tencent

这篇腾讯云工程文章梳理软硬一体化智算底座与大模型全链路落地方案，覆盖第五代 AMD EPYC、HCC 与星脉 RDMA 网络、TCCL 通信库、TurboCFS 训练存储、TACO 训推加速套件、INT4/FP8 量化和 ES 混合搜索/RAG。文章给出多项工程指标：单集群万卡规模、3.2 Tbps RDMA 网络、AllReduce 负载率 90% 以上、TurboCFS 千万级 IOPS 与 100GB/s 吞吐，并声称服务器整合比例 7:1、TCO 降低约 67%。

INSIGHT这不是单点算法论文，但对 infra 赛道很有参考价值：大模型搜推平台的瓶颈横跨算、存、网、量化、推理和检索组件，局部替换框架很难获得端到端收益。对企业内部平台建设，文章提示要把训练 checkpoint 存储、AllReduce 通信、量化推理和 ES/向量混合检索作为一条链路设计，并用 TCO、功耗、吞吐和故障定位时间共同验收。

Accuracy Is Speed: Towards Long-Context-Aware Routing for Distributed LLM Serving

这篇论文研究分布式 LLM serving 中的长上下文路由问题。现有系统常用 load-aware、session-affinity 或 cache-affinity 策略，但长上下文请求会让错误路由直接放大 TTFT、KV cache 搬运和队列等待；作者提出 long-context-aware routing，把路由准确性视为速度优化的一部分，而不是简单的负载均衡或亲和性规则。论文发表于 2026-04-17，虽不如本周论文新，但仍在 90 天窗口内。

INSIGHT对搜索/RAG 服务，长上下文请求通常来自多文档召回、历史会话和 Agent 轨迹，路由层如果不了解上下文长度与 KV 状态，就会把负载均衡做成延迟放大器。该工作提示平台应在入口层记录 prompt 长度、KV 复用可能性和 session 状态，把它们纳入 routing feature，而不是只看 GPU 当前队列长度。

Takeshi Yoshimura, Valentijn Dymphnus van de Beek, Tatsuhiro Chiba

Runtime-Certified Bounded-Error Quantized Attention

这篇论文关注 KV cache 量化在长上下文推理中的可靠性，而不是单纯追求速度。它提出分层 KV cache：INT8 key 和 INT4 value 存在 GPU 显存中，FP16 原始值保留在系统内存，并用两项误差分解为每个 head、每一步计算 attention 分布失真和 value 重构误差；在 PG-19、NIAH、RULER 上用 LLaMA 3.1-8B、最长 128K 上下文验证，语言建模和检索任务质量接近 FP16，并能恢复朴素 INT8/INT4 的灾难性失败。

INSIGHT量化 KV cache 的真实风险是线上长输出逐步偏离，平均 benchmark 不一定暴露。runtime-certified attention 给了一个可落地的安全阀：默认走低精度，误差边界触发时回退到 FP16。对搜索问答、代码生成和工具调用场景，这种“可证明或可恢复”的压缩比盲目追求极限压缩更适合生产上线。

Dean Calver

NVIDIA Vera CPU Boosts AI Factory Throughput to Accelerate Agentic Workloads

NVIDIA

NVIDIA Vera CPU 文章把 Agentic AI 的瓶颈从 GPU 推理扩展到 CPU 执行环节：工具调用、沙箱代码、检索、数据处理和环境交互都会成为模型下一步推理的上下文来源。公开资料显示 Vera 采用 88 个 Olympus core，面向 AI factory 中的训练、推理和 agentic execution，相关报道提到机架级方案可提供最高 6 倍 CPU throughput，并支持约 22,500 个并发 CPU 环境。

INSIGHTAgent 与深度搜索系统不只是“模型在 GPU 上跑得快”，还依赖 CPU 侧工具执行、检索管道、沙箱和数据搬运的吞吐。Vera 这类面向 AI factory 的 CPU 设计提醒平台团队要把 CPU 调度、隔离、多租户 sandbox 和 GPU 生成链路一起压测，否则 GPU 利用率提升后，Agent workflow 会很快暴露新的 CPU 侧瓶颈。
