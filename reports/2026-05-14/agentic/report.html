1. ReVision: Scaling Computer-Use Agents via Temporal Visual Redundancy Reduction
4.10
Relevance 4 | Novelty 5 | Practical 4 | Evidence 4 | Timely 5

Summary: 论文针对计算机使用 Agent (CUA) 在长 trajectory 下视觉 token 爆炸的问题，提出 ReVision：训练一个 patch selector，在保持空间结构的前提下比较相邻屏幕截图的 patch 表示，剔除时序冗余 patch。基于 Qwen2.5-VL-7B 在 OSWorld、WebTailBench、AgentNetBench 上验证，平均 token 用量降低 46%，5 张历史截图的设置下成功率比无裁剪 baseline 提升约 3 个百分点。论文还观察到：当冗余被消除后，更多历史观察可以持续带来收益，说明此前视觉历史饱和并非信息有限，而是 token 表示低效。

Key insight: 对搜索/推荐场景里的多模态 Agent 应用 (例如 GUI 自动化、视觉商品检索 Agent) 极具借鉴价值：视觉 trajectory 的核心瓶颈是时序冗余而非信息量本身。可借鉴的设计是把 patch 级别冗余剔除作为通用预处理模块，与多模态 LLM 解耦——这意味着可以在不改主模型的情况下显著扩大上下文容量。对线上 Agent 服务而言，46% 的 token 削减直接对应推理成本和延迟的同比例下降，是工业化部署的关键杠杆。

2. The Bicameral Model: Bidirectional Hidden-State Coupling Between Parallel Language Models
3.85
Relevance 3 | Novelty 5 | Practical 3 | Evidence 4 | Timely 5

Summary: 论文提出 Bicameral Model：两个冻结的 LLM 通过可训练的翻译网络和门控（约总参数 1%）以隐状态形式双向耦合，跳过文本 token 化以协同完成任务。实验中：耦合两个 0.5B 模型并接入计算器后，算术任务准确率从 36% 提升至 96%；耦合两个 0.6B 模型并接入 Z3 求解器，在 ZebraLogic 上达到 baseline 的 1.7×；辅助模型甚至能仅凭隐状态信号生成可执行的 Python 求解代码，而无需看到原始问题文本。

Key insight: 对多 Agent 协同范式提出根本性挑战：以文本 token 作为 Agent 间通信介质会丢失大量上下文信息，可训练的连续隐状态通道效率显著更高。对搜索/推荐工业系统的启示是 —— 当多个 LLM 子模块需要协作 (例如 query 改写 Agent + 排序 Agent，或 RAG 中的多个工具调用模块)，未来可探索用 adapter 级别的隐状态耦合替代纯文本协议，潜在带来推理成本与质量双优。短期落地难点是需要联合训练，与目前主流的 frozen-LLM + Prompt 工程范式不兼容。

3. VERDI: Single-Call Confidence Estimation for Verification-Based LLM Judges via Decomposed Inference
3.70
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 论文解决 LLM-as-Judge 在生产环境中缺乏可信置信度信号的问题。VERDI 把验证式评测分解为 step-verdict 对齐、claim-level margin 和 evidence grounding 三个结构化信号，使用 Platt scaling 进行 logistic 回归融合，单次调用即可输出置信度。结果：在 GPT-4.1-mini 上 AUROC 达 0.72–0.91，GPT-5.4-mini 上 0.66–0.80；Qwen 3.5 (4B/9B/27B) 上 AUROC 从 baseline 的 0.32–0.49 提升至 0.56–0.70。生产八条 rubric 上 AUROC 0.73–0.88，跨模型迁移仍可达 0.66–0.69。

Key insight: 对搜索/推荐里大量使用 LLM-as-Judge 评估相关性、CTR 标签质量、Agent 输出正确性的团队是直接生产力增益：终于有了不依赖 token logprob 的低成本置信度信号 (商用 API 通常不暴露 logprob，且 logprob 在结构化输出下饱和)。可借鉴的工程设计是把 "reasoning trace" 视为机器可解析的结构化对象，而不仅是文本——分解出验证步骤、证据接地度等子信号后再融合，泛化性显著优于直接 prompt 模型自评。可作为 Agent 输出的在线质量监控信号，用于触发降级路由或人工复核。

4. Building a safe, effective sandbox to enable Codex on Windows
3.55
Relevance 3 | Novelty 3 | Practical 5 | Evidence 3 | Timely 5

Summary: OpenAI 介绍了在 Windows 平台为 Codex 编码 Agent 构建安全沙箱的工程实践：通过受控的文件访问、网络限制等机制，把 Agent 可执行的操作约束在受信任的执行环境中，使代码 Agent 既能高效完成编辑、测试、运行任务，又不会对宿主机或外部资源造成不可控影响。这是 Codex 跨平台扩展的关键基础设施工作。

Key insight: 对工业级 Agent 落地的工程团队具有直接借鉴价值：当 Agent 需要执行任意命令、修改文件、访问网络时，宿主机沙箱的设计是安全与能力的核心 trade-off。搜索/推荐场景里类似问题出现在 "代码 Agent 自动生成召回策略"、"分析 Agent 自动执行 SQL" 等流程，借鉴 OpenAI 的设计——通过 OS 级权限隔离 + 显式 capability 白名单 + 网络出口策略——可以避免自研轮子，把工程精力放在业务策略上。Windows 沙箱方案的开源/文档化也降低了非 Linux 工程团队拥抱 Agent 的门槛。

5. Overview of the MedHopQA track at BioCreative IX: track description, participation and evaluation of systems for multi-hop medical question answering
3.40
Relevance 4 | Novelty 3 | Practical 4 | Evidence 4 | Timely 4

Summary: BioCreative IX 的 MedHopQA 任务发布了 1000 条覆盖罕见病、基因和化学物的 2-hop 医学问答数据集，要求系统跨多个 Wikipedia 源整合信息回答复杂问题。共 13 个团队提交 48 个系统。最优系统 F1 达到 89.30% (MedCPT)、EM 87.30%，相比 zero-shot baseline (F1 67.40%, EM 60.20%) 高出 21.9 个 F1 点。组织方明确指出：RAG 及相关 retrieval-based 策略是取得强表现的关键。

Key insight: 对 Agentic RAG 与多步检索系统的落地是非常 grounded 的参考。21.9 个 F1 点的差距说明在多跳问答里 "是否引入检索" 仍然是决定性变量，强于模型本体的差异。对社区搜索/UGC 问答场景，关键启示是：当用户问题需要跨多帖整合证据时 (例如比较两家店铺、串联多个回答)，无 retrieval 的 LLM 直接生成会塌缩到通用知识；应优先把多跳分解 + 显式证据回引作为 baseline 框架。该 benchmark 也提供了一套结合 surface F1 与概念级 MedCPT 的双重评估范式，可借鉴用于 UGC 长尾问答的离线评估。

7. Reflect then Learn: Active Prompting for Information Extraction Guided by Introspective Confusion
3.30
Relevance 4 | Novelty 3 | Practical 4 | Evidence 3 | Timely 4

Summary: 论文针对 few-shot 信息抽取中 LLM 对 in-context 示例选择极度敏感的问题，提出 APIE (Active Prompting for Information Extraction)。核心是一个双重不确定性指标：(1) 格式不确定性，衡量 LLM 生成 schema 化结构的难度；(2) 内容不确定性，衡量语义抽取的不一致性。基于 "内省式困惑" 对未标注样本排序，挑选最具信息量的样本作为 few-shot 示例。在四个 IE benchmark 上一致优于强 baseline，抽取准确率与鲁棒性均显著提升。AAAI 2026 录用。

Key insight: 对 Agent 中 "自我反思 / 自我评估再学习" 这一类范式做出了实证：把模型生成困难度分解为 "格式难" 与 "语义难" 两个正交维度，比单一 token-prob 信号更鲁棒。对搜索/推荐的可借鉴设计：1) 在 query 理解 Agent 里把 schema 抽取 (槽位填充) 和语义判断分别度量，能更精细地诊断 Agent 失败模式；2) Active prompting 思路可以迁移到 "线上召回低置信样本反向收集成 few-shot 样例" 的闭环，自动补齐长尾。注意论文未公开具体数字提升幅度，需在自有数据上复测。

8. Question Difficulty Estimation for Large Language Models via Answer Plausibility Scoring
3.20
Relevance 4 | Novelty 3 | Practical 4 | Evidence 3 | Timely 4

Summary: Q-DAPS 把问题难度建模为模型对多个候选答案 plausibility 分布的熵：候选答案分布越尖锐说明问题对模型越容易，越平坦说明越难。论文在 TriviaQA、NQ、MuSiQue、QASC 四个 QA benchmark 上一致优于既有 baseline (基于可读性公式、检索信号或流行度)，对模型规模、超参数与现实场景表现出强鲁棒性；人工评估亦确认与人类难度判断高度一致。ACL 2026 录用。

Key insight: 对搜索/推荐 Agent 系统的实践意义在于 routing：实时给问题打 "难度分" 可以用于动态选择是直接生成、走 RAG、还是路由到更大模型。对 Q-DAPS 的可借鉴设计是 —— 无需 ground-truth 答案，仅靠候选答案分布的熵就能近似难度，从而支持线上无监督部署。社区 UGC 搜索可类比 ——根据 query 触发的候选答案熵决定走 "直接召回" 还是 "Agentic 多跳召回"，避免对所有 query 一刀切。MuSiQue (多跳 QA) 上的稳定表现说明对复杂查询同样适用。

9. How finance teams use Codex
3.10

Summary: OpenAI 学院发布了金融团队使用 Codex Agent 的实操指南：从月度业务回顾 (MBR)、报表汇编 (reporting packs)、差异分析 (variance bridges)、模型核对 (model checks) 到情景规划，Codex 都可直接以业务工作产出为输入完成任务。展示了非工程领域用户用编码 Agent 解决结构化数据/分析问题的范式。

10. BatchBench: Toward a Workload-Aware Benchmark for Autoscaling Policies in Big Data Batch Processing
3.00
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 4

Summary: BatchBench 是一个面向大数据批处理自动伸缩策略的标准化 benchmark 框架，覆盖六大 batch 工作负载类型，参数化生成器经 Kolmogorov-Smirnov 与 EMD 验证。评估五个维度：成本、SLA 达成率、伸缩响应性、伸缩抖动和决策可解释性。统一 agent 接口支持规则、学习型和 LLM-based 三类自动伸缩器。这是 position paper，无实验数字。

Key insight: 对搜索/推荐离线训练与索引构建的资源调度提出了一个标准化评估视角。值得借鉴的是 BatchBench 把 "基于 LLM 的 Agent 调度器" 列为与规则、学习型 baseline 并列的第三类，反映了产业判断：LLM Agent 正在向系统级调度决策渗透。对搜索召回 batch、推荐特征工程 batch 等周期任务的团队，可考虑用统一接口对接 LLM Agent 调度器，至少为 SLA 异常工况提供解释性兜底。Position paper 阶段尚无落地数据，需等待实证补充。
