MTFM：美团统一推荐基座大模型在外卖多业务场景的落地实践

美团面向外卖多业务精排，提出统一推荐基座 MTFM，以异构 Tokenizer、动态掩码和混合注意力共享用户行为建模，保留业务独立任务塔。官方实践报告显示，多业务订单量提升 2.06%–6.68%，推理成本下降 24%；Target 与 Full Attention 按 3:1 堆叠时，样本吞吐达到全注意力架构的 2.9 倍。

1. 问题与动机

美团这项工作的直接问题是外卖多个业务各自维护精排模型：用户相同，行为却被分散存储和训练；业务特征结构不同，强行套一张统一特征表又容易损失信息。官方文章明确把挑战分为模型规模扩展、场景接入和计算效率三个方面。其任务仍是 CTR、CTCVR 等目标预测，因此本日报归入个性化排序。判断依据是最终任务与模型接口，而不是文中使用了“生成式”或“基座模型”的名称。

此前 MTGR 已在单场景验证大模型的收益，但多个业务独立扩容会重复消耗长序列计算。MTFM 的目标是让用户行为形成公共表示，再由各业务保留目标特征与预测头。它继承 HSTU 类骨干、MTGR 的交叉特征和掩码设计，也吸收多域推荐中共享参数与业务参数分离的思想。相较只把知识蒸馏给不同专家模型，该方案把多业务学习放进一张训练图，直接检验统一模型是否能够服务不同流量规模的业务。

这里也存在可量化的工程动机：模型单样本计算达到 192 GFLOPs，传统逐曝光计算很难承受；而多业务训练初期的随机实验 AUC 波动超过 0.4 个百分点，足以掩盖不少常规排序优化。文章的价值在于同时交代模型表示、样本组织和训练稳定性，便于判断线上收益来自哪些配套条件。

2. 方法详解

输入按三类 token 组织。H 表示全业务共享的历史商家、商品行为；R 表示按时间排列的近实时点击和加购等行为；T 表示待预估目标，包含用户上下文、物品和交叉特征。H、R 由相应序列的独立 tokenizer 编码；T 使用业务独立 tokenizer。编码后维度统一，送入共享骨干，因此业务不需要在原始特征字段上逐项对齐。这不代表上游数据不需要治理：共享行为的实体、时间戳和语义仍必须可靠。

动态掩码约束可见关系。历史 token 作为公共上下文，实时序列内部遵守因果次序，每个曝光目标只能读取曝光发生之前的实时行为；目标之间不能互相感知。用户级样本把一天多个曝光合在一起后，这个约束尤其关键，否则后一次点击会泄漏给前一次曝光标签。落地时应把掩码视为样本协议的一部分，与离线特征回放一起检查。

V1 用 16 层混合注意力，分成 4 个 block，每块包括 1 层 Full Attention 与 3 层 Target Attention。前者更新全局依赖，后者主要让目标从用户序列读取信息，并结合 GQA 控制开销。V2 进一步缓解目标特征压缩：经 AutoSplit 把一个目标映射成 4 个 token，各自使用独立 Q 投影和 SwiGLU FFN；目标侧与自注意力侧参数分开。目标 token 再通过 RankMixer 式混合交换信息，以免面对同一组用户 KV 时学成相似向量。最终的业务目标表示经过 MMoE 和独立任务塔完成预测。

训练以用户为单位合并当天跨业务曝光，多目标共享长序列计算；推理则以当前业务请求聚合候选，只导出共享基座和当前业务所需塔。损失从“每个业务先平均，再相加”改成全 batch 的有效曝光统一归一化，避免极少样本业务的梯度被过度放大。没有对应业务样本时，对相关参数跳过零梯度下的权重衰减，并采用 2 步梯度累积。部分 HSTU 投影矩阵改用 Muon，其他参数不能据此推断全部切换；文章强调只覆盖 UQKV 与输出投影的组合更合适。

初始化按网络深度缩放残差输出投影的标准差，以限制残差逐层累积。公开文章给出了结构层数、token 数、相对吞吐与若干优化器细节，但没有完整公开训练样本总量、GPU 型号数量、学习率、绝对 batch size 或训练步数；因此这些参数不能从行业惯例补写成作者配置。

3. 核心技术贡献

第一，异构输入与共享计算分开设计。业务特征可以保持独立编码，而跨业务行为进入统一序列；这把“特征模板相同”从多场景联合训练的前提中移除。较小业务能够获得其他业务的行为信号，文中报告小流量业务离线指标提高 0.60–0.93 个百分点，中流量业务提高 0.25 个百分点，大流量业务基本持平且略有正向变化。该分层结果比单一平均增益更能说明共享信息的价值。

第二，把计算预算偏向目标相关交互。Full Attention 负责必要的全序列整合，Target Attention 承担大部分层数；V2 又增加目标表示容量。这不是只增加模型参数，而是在特征密度不对称时重新分配 token 和计算。3:1 配比相对全注意力结构达到 2.9 倍样本吞吐，batch size 可提高 1.7 倍，但两项数字不能脱离共同的显存节省条件独立相乘。

第三，联合训练对小业务的影响被纳入优化器实现。统一损失归一化降低稀疏业务噪声；没有有效梯度时停止对应参数衰减，防止业务专属参数在缺席 batch 中持续退化。这些改动可迁移到社区搜索的帖子、问答、评论多任务，即使不采用完整 Transformer 骨干也值得单独验证。

第四，算子优化围绕真实矩阵形状。作者发现针对大矩阵的 Muon 优化在这里反而被启动成本抵消，改用同形状小矩阵批处理后，NS 阶段加速 241%，端到端训练吞吐增加 19%。这说明系统收益需要用业务模型中的形状分布验证，不能直接复制其他大模型的加速结论。

4. 实验结果分析

以下整理的是官方技术文章给出的比较口径，不把不同优化阶段叠加成一个新的总收益。

比较对象或阶段指标原文报告
MTFM 对原有业务基线多业务订单量相对提升 2.06%–6.68%
整体部署推理成本降低 24%
3:1 混合注意力对全注意力样本吞吐2.9 倍
初始化与优化器改进随机实验 train AUC 波动0.4pp 降至 0.1pp
动态掩码构造耗时22ms 降至 1ms
推理查表合并显存占用22GB 降至 5.9GB
特征精简训练吞吐提升 6%，GAUC 无损

随机稳定性结果来自 5–10 组重复实验。波动变小使后续模型对比更可信，但它不是平均 AUC 提高 0.3 个百分点。类似地，掩码生成的 22ms 到 1ms 只属于该算子阶段，不能当作整个在线请求的时延变化。

跨业务迁移对小流量业务更明显，符合共享数据补足稀疏信号的机制；大业务接近持平也提醒读者统一架构的收益可能主要来自整体成本和小业务增长。作者还在 token 维度 192–768、序列长度 400–2000 的范围观察到扩展趋势。这支持在已测范围内增加容量，但文章没有给出可直接外推到任意参数规模的普适指数。

Target Scale-Up 与混合注意力的讨论分别对应模型能力和效率，不应把 V2 的离线结论全部写成已经全量的线上收益。文章明确描述全量落地的是 V1。线上订单提升也包含样本、特征、训练和系统协同的综合效果，无法据此计算单独替换某个 tokenizer 对社区 CTR 的因果贡献。

有意义的负面经验是 flash-muon 风格优化对偏小矩阵可能变慢，以及深层联合训练可能产生局部梯度衰减。二者都说明“规模更大”本身不能保证收益，必须同时监控随机种子方差、梯度动态和设备利用率。

5. 局限与未来方向

文章是工业技术总结，没有单独的学术局限章节。作者明确提出的后续方向包括算法与基础设施协同扩大参数规模、继续验证参数和序列长度的扩展规律，以及通过联合训练、蒸馏构建 MTFM-Lite，向更多场景推广。这些属于计划，不能写成已完成的实验。

公开证据的边界包括未披露完整数据集、端到端复现配置及 A/B 样本量和置信区间；部分分业务结果以图展示，本解读没有猜测图中未读取的具体数值。订单是外卖业务指标，其变化不等于社区搜索相关性提升。以上是本次阅读对披露范围的判断，区别于作者正式声称的局限。

6. 工业实践意义

对社区 UGC 搜索，较可行的迁移起点是共享用户近期点击和长期阅读序列，帖子、问答、评论各自保留目标编码器与预测头。先验证联合建模是否改善小场景 CTR 和分场景 nDCG，再决定是否扩大共享骨干，避免把特征统一工程一次性扩展到全业务。

实验需要按曝光时间构造因果掩码，并按用户分组核查同一天多个样本之间的信息可见性。线上预算评估同时记录候选数、历史长度、特征处理耗时、显存和请求分位延迟；作者的相对吞吐数字不能代替本地服务容量测算。复用用户侧计算对一个请求包含较多候选时尤其有价值，但如果请求候选很少，共享计算的摊销收益也会改变。

可以分三步验证：先改样本组织与时间掩码，保持现有评分头；再测试混合注意力和目标侧多 token；最后针对已确认的瓶颈开发定制算子。多业务低流量任务应额外监控空梯度、权重衰减和损失归一化。成功标准同时包含业务增益、训练方差和成本，而不只是更大的模型参数量。

When LLM-Based User Profiling Adds Value in Production Streaming Recommendation

ComcastDePaul University📖 有深读 · 10 分钟

论文在真实流媒体数据上比较聚合向量与 LLM 画像，并交叉测试长短期兴趣拆分，共评估 4 种策略、1 万名用户和约 24 万个内容。全体用户中，长短期聚合向量使 NDCG@10 相对提升 4.7%；LLM 整体画像在探索型用户中提升 31.5%，但在总体上下降 26.9%，收益明显依赖人群。

INSIGHT社区搜索可先用历史点击内容的语义均值作用户特征，再检验 LLM 画像是否只对兴趣变化人群有效。论文中的探索型标签利用未来测试行为，不能直接作为线上路由；还需评估目录覆盖与新颖性，避免个体列表更丰富、全站内容曝光却更集中的现象。

1. 问题与动机

这篇 Comcast 与 DePaul 的工作研究一个具体决策：内容推荐的用户画像是否值得从物品向量平均升级为 LLM 生成的自然语言画像。LLM 可以从历史中提炼主题，但多一次生成带来计算、刷新和运维成本，离线学术数据上的优势也未必能迁移到真实平台。作者使用实际流媒体数据，覆盖电影、电视剧和体育内容，比较在相同候选编码与评分头下，画像构造本身带来的差异。

问题的关键是用户行为不均匀。一些用户持续消费类似内容，此时保留物品级语义可能已经足够；另一些用户未来消费偏离既有历史，主题级抽象可能更有用。论文同时关注准确率与内容生态：单个推荐列表语义更分散，不代表整个系统覆盖了更多内容。这使研究对社区搜索个性化有直接参考价值，因为点击偏好、新内容发现和长尾曝光往往需要共同考虑。

作者没有声称提出全新的推荐骨干，而是把两类画像表示与两种时间处理方式交叉成四组，用真实平台全库排序隔离变量。其主要贡献是说明收益发生在哪些用户上，以及准确率以外的代价；不能把论文标题中的“production”误读为已完成线上 A/B 实验。

2. 方法详解

全部方法共用冻结的 SBERT 物品编码器，将标题与描述编码成向量并预计算缓存。用户画像向量与候选物品向量拼接，送入同一结构的两层 ReLU MLP，输出相关性分数。训练采用二元交叉熵，每条正交互配均匀采样的负物品，优化器是 Adam。这样评分头、物品编码和训练协议保持一致，主要变量是如何从历史生成用户向量。

Centroid 把完整历史物品向量做算术平均，是成本较低的基线。TemporalCentroid 另取最近一定比例历史，分别计算近期均值与完整历史均值，再由可学习的单层注意力给两者分配权重。需要特别注意，长期集合是完整历史，并不是去掉近期行为之后的剩余部分；近期交互会同时出现在两个分支。这种定义保持长期画像包含所有持续兴趣，复现时不能自行改成互斥切分。

Narrative 将完整观看历史交给 LLM，要求总结稳定主题与反复出现的兴趣，再用同一个 SBERT 把生成文本编码成用户向量。TemporalNarrative 对近期与完整历史各生成一次总结，分别强调近期变化和长期主题，然后使用与 TemporalCentroid 一致的注意力融合。简化公式可以写为：用户向量等于近期画像乘以权重，加上完整历史画像乘以剩余权重；两个分支的区别在于输入是物品向量均值，还是总结文本向量。

数据随机抽取 10,000 名用户，筛选有足够英文标题描述的内容后，候选库约为 240,000 个物品。每名用户按时间顺序划分 80% 训练、10% 验证、10% 测试，评价时对完整过滤后目录排序。作者有意不加入 SASRec、BERT4Rec 等协同序列方法，目的是固定内容信号来源，避免把协同信息增益混入画像比较。因此结论只涉及这组内容画像策略的相对效果。

近期窗口扫描历史的 15%、20%、25%、30%，主结果使用 25%。论文披露 Adam、BCE、冻结编码和共享 MLP，但不足以从正文恢复完整训练配置：未在读取正文中给出可直接照抄的 LLM 具体型号、硬件、绝对 batch size、学习率和训练总步数。本解读保留这些缺口，不根据常见设置补全。实践复现可以先落实这套控制变量结构，再独立调参并记录所用模型版本。

3. 核心技术贡献

第一，二维实验设计把“使用 LLM”与“区分长短期兴趣”分开。很多方案同时改变表示、时间建模和评分网络，无法解释收益来源；这里四组方法只在画像构造不同。总体人群中，TemporalCentroid 的 NDCG@10 比 Centroid 高 4.7%，而 Narrative 低 26.9%，说明更复杂的自然语言画像并非全体用户的可靠替换。

第二，作者用事后行为划分解释结果反转。若测试历史中没有物品出现在训练历史里，就标为 Explorer；本样本有 1,761 人，其余为 Non-Explorer。这是物品是否重合的操作性定义，不是严格的语义新颖度，也不是人格分类。Narrative 对 Explorer 的 NDCG@10 相对增加 31.5%，对 Non-Explorer 则减少 27.8%。同一平均指标背后存在方向相反的效应，分层分析改变了工程决策。

第三，把列表内多样性、全库覆盖率与新颖性分开。多样性用列表物品向量的平均余弦差异，覆盖率统计全体用户推荐内容占目录的比例，新颖性使用训练用户中的物品流行度负对数。LLM 画像可以增加列表内多样性，却使推荐集中到更少、更热门的内容。这三类指标不能互相替代，尤其在社区搜索中，优质长尾帖是否被曝光与单张结果页是否看起来多样是两个问题。

第四，论文给出路由方向的初步可行性检查，但明确没有完成生产路由器。历史长度与 Explorer 标签的点二列相关为 -0.30，历史语义多样性为 +0.11，两者 p 值小于 0.001。它们说明训练期特征可能携带信号，但相关性不等于预测准确率，更不等于最终线上收益。

这些结果首先说明时间分解不是统一有效的增强。对习惯型用户，长短期均值融合改善排序；对探索型用户，TemporalCentroid 在两个截断位置没有优势。Narrative 在 Explorer 上比 TemporalNarrative 的 NDCG@10 更好，说明额外拆成两段自然语言总结也未必提高效能。作者讨论认为，探索行为本身可能不适合被强制组织为稳定的长短期差异，这属于机制解释，不能当作已被独立因果实验验证。

统计检验采用每用户指标的 Wilcoxon 符号秩检验，显著性阈值为 0.05。论文提示 Explorer 样本较少，K=10 的证据并不是每项指标都显著；Narrative 的 NDCG@10 有显著标记，但 Recall@10 的 +18.7% 没有。K=100 上分人群模式更稳定。Coverage 是系统级指标，不适合套用每用户检验，因此作者没有给出同样的逐用户显著性判断。

全体 TemporalCentroid 的 Coverage@10 相对下降 5.8%，即便它在 NDCG 上胜出，也没有做到所有指标共同改善。对 LLM 画像，论文报告更明显的热门集中现象。解释可能来自生成模型与编码器都更熟悉热门内容：总结向量向语义空间中热门区域移动，使同一个人的列表看起来更丰富，但不同人的列表更相似。作者没有分别隔离生成步骤和编码步骤，不能确定二者各占多少贡献。

窗口分析扫描四档比例，用每个模型在 25% 窗口下的自身结果归一化，和主表相对于 Centroid 的归一化口径不同。阅读图表时必须区分这两个分母，不能把窗口曲线上的相对变化误当成对基线模型的增益。文章为保密只给相对准确率，也意味着无法从表格恢复绝对命中数量或真实业务价值。

5. 局限与未来方向

作者明确提出两项边界：研究来自单一流媒体平台、特定内容领域，是否适用于其他平台、用户分布或 LLM 与编码器组合仍需复现；实验是离线分析，线上反馈和系统动态可能改变结论。LLM 成本部分也仅给出定性判断，没有披露完整价格、算力摊销或延迟测试，不能据此承诺节省某个固定比例的总成本。

作者承认用户路由只是部署方向：Explorer 标签依赖未来测试行为，不能在线直接获得。训练期相关性分析是前期观察，还需要特征工程、阈值校准和线上验证。若信号不足，默认采用聚合画像是论文建议的保守选择。额外的阅读判断是，内容基线内部的优势不足以证明它优于成熟协同排序系统；论文主动限制了比较范围，应保留这个范围。

6. 工业实践意义

社区短文本搜索可先把用户历史点击的帖子、问答与评论编码成语义向量，用全历史均值及近期均值作为轻量个性化特征。再在固定 query、候选集和排序网络的条件下，比较 LLM 主题画像是否为兴趣迁移较快的用户提供增益。不能直接用未来行为形成线上路由标签，否则实验会偷看答案。

一个可执行的验证方案是按时间切分训练路由器，仅使用当时可见的历史长度、主题跨度和近期行为变化；在之后的时间窗评价推荐结果，并保留无法确定的人群走普通向量画像。路由器本身也要与全体统一策略比较，避免离线分组收益在真实分类误差下消失。作者样本探索型约占 18%，这一比例只能描述该数据，不能直接用于估计社区算力预算。

指标同时记录 nDCG、CTR、目录覆盖、长尾曝光和画像刷新成本。点击率上升而覆盖显著下降时，需要判断是否牺牲了社区内容发现。在线请求可以消费离线生成的画像向量，因此不必假设每次搜索都调用 LLM，但画像生成频率、用户删除历史后的刷新和编码版本一致性仍会增加工程复杂度。这些是迁移建议，不是论文已经测出的在线结果。
