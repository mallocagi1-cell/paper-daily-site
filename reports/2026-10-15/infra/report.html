FlashVector: Agent for Hierarchical Model Serving Stack Optimization

推荐系统的服务成本来自内核、计算图、模型服务器和在线特征处理多个层级，单点调优难以覆盖整体瓶颈。FlashVector 用可扩展智能体框架统一优化异构技术栈。在 Unity 广告平台部署后，模型服务器吞吐最高提升至 2 倍、延迟加速最高 1.98 倍，特征存储吞吐最高提升至 1.6 倍。

Deploying RDMA for Distributed Inference and Training At Scale

ByteExpress 针对字节跳动参数服务器式训练与推理，将 RDMA 缓冲分配、零拷贝、连接复用、接收信用和软件发送窗口结合，并在传输层之上实现故障恢复。生产推理中，参数拉取平均延迟及 P99 分别下降 35.7% 和 43.7%，CPU 总使用下降 10.69%；训练参数推送 P99 最高下降 74.0%。

INSIGHT对社区搜索的大规模稀疏参数、排序模型和特征服务，网络卸载必须与缓冲生命周期、并发连接及恢复协议一起设计。可先定位参数拉取在请求耗时中的占比，再评估 RDMA 投入；这些收益来自参数服务器架构，不能直接等同于单机向量检索或普通 HTTP 服务的提升。

RadixFlow: Filling Execution Bubbles in Prefix-Cached Hybrid LLM Serving

混合注意力模型中，命中共享前缀并不代表循环状态已经就绪，队首阻塞会留下无法执行的批处理空槽。RadixFlow 将前缀匹配与状态就绪解耦，只局部等待受阻分支，让独立请求继续填充批次。在 5 个混合模型上，平均延迟降低 3%—24%，执行轮次减少 11%—44%，前缀复用率基本不变。

INSIGHT社区搜索中的共享提示词和文档前缀可提高缓存命中率，但调度器还必须检查状态依赖是否满足。可借鉴就绪感知遍历，避免单个未就绪分支拖住其他请求；论文在全注意力对照模型上收益很小，实际部署应先确认模型结构，并同时监测批次大小、轮次和真实延迟。

FastEEP: Fast Intra-Instance Elastic Scaling for Expert-Parallel MoE Serving

FastEEP 解决 MoE 推理实例内部专家并行组扩缩容需要销毁并重建实例的问题。系统将可复用的执行结构与当前并行配置激活的资源分离，在工作进程、GPU 显存和通信层保留昂贵状态，再协调资源回收和重配置。跨模型实验显示，相比基于 vLLM 的现有方式，扩缩容速度提高 4.5—11.7 倍。

INSIGHT社区搜索若用 MoE 承担查询理解或答案生成，流量峰谷下的扩容成本会影响容量规划。部分复用提供了比整实例重启更细的弹性路径，但扩容加速并不等于请求吞吐同比增长；落地应检查专家迁移、通信组重建和显存回收是否影响在途请求，并单独测试故障恢复。

SAFE-KV: Causal Suffix Repair for Behavior-Preserving Non-Prefix KV Cache Reuse in RAG

非前缀文档 KV 缓存带有原先上下文和位置条件，直接拼接容易改变 RAG 答案。SAFE-KV 从选定文档起重新编码因果后缀。在 Qwen2.5-7B 上，直接组合仅保留 HotpotQA-500/2Wiki-500 的 47.2%/37.8% 基准答案，实际后缀转发修复后达到 100.0%/98.4%；单请求 L40S 实验最终仍选择完整预填充。

INSIGHT社区 UGC 搜索会重复使用热门帖子，但复用文档文字与复用其内部状态是两回事。应以完全相同提示词的完整预填充作为正确性参考，验证答案一致率后再谈加速；该研究显示忠实修复可能重算大部分上下文，因此不应把高缓存复用率直接当成端到端收益。

Stable Token-level Scheduling for Serverless LLM Inference

无服务器推理接纳新请求时，计算密集的预填充会干扰带宽受限的解码。Token Window Pacing 利用运行时的 token 间延迟、排队深度和负载特征，闭环调整 token 窗口，并配合分块预填充。在真实感无服务器负载上，相比 ServerlessLLM 吞吐最高提高 45%，相比传统调度器最高提高 58%，同时改善延迟波动。

INSIGHT社区搜索的流式答案既要快出首字，也要保持后续输出平稳，可将 token 间延迟作为准入反馈信号。分块预填充有助于隔离新请求对解码的冲击，但应在真实短查询、长文档混合流量下调参，并同时验证 TTFT、P99 和排队时间，避免只优化吞吐而增加等待。

FidelityQ: Preserving Predictive Fidelity in Ultra-Low-Bit Language Model Quantization

FidelityQ 用随机 Hadamard 混合与四级最小失真标量编码压缩权重，再按教师与学生分歧的重尾程度选择校准样本，只更新量化级别和尺度。在 LLaMA-2-7B 上，W2A16 的 WikiText2 困惑度为 6.62；W2A4KV4 从此前 8.31 改善至 6.96，线性层权重显存相对 FP16 减少 8 倍。

INSIGHT社区搜索的查询理解与生成模型可借鉴其低位宽编码和困难样本校准方法，优先覆盖口语、长尾实体及高置信错误。权重显存降低不代表整个服务显存或延迟等比例下降；部署前需验证算子支持、KV 开销，以及量化是否改变相关性判断和答案质量。

Lightweight Scheduling Policies for Continuously Batched LLM Serving Across GPU Architectures

研究以真实 HuggingFace 模型执行构建连续批处理测试台，在 ShareGPT 派生流量、6 个 Qwen/Gemma/Mistral 模型和 L40S/A100/H100 上比较 8 种轻量调度策略，共完成 1,152 组运行。老化最短提示词优先在多个 L40S 和混合负载条件下表现突出；即使知道剩余输出长度，也不能消除批处理和硬件差异。

INSIGHT社区搜索请求长度差异明显，调度策略应针对短查询与长上下文混合流量选择。可将带老化机制的短提示词优先作为低成本基线，同时检查长请求是否饥饿；该研究提供跨硬件实验规模和策略结论，摘要未给统一加速比，因此不能宣称所有 GPU 都会获得固定收益。

The COUNT: Counting N-grams Unlocks Scaling on Host Memory and Training-Free Adaptation

COUNT 将离线统计的 n-gram 频次存放在主机内存，再对语言模型已有的输出嵌入按后继词频加权，构造无需新增可学习参数的输入表征。在固定计算预算的 1B 模型预训练中，其验证损失收益可比增加 57% 计算量的模型；推理时还能替换领域计数表，在不训练的情况下适配新任务。

INSIGHT对社区帖子这种领域词汇持续变化的数据，可探索把频次知识放到廉价主机内存，减少 GPU 显存竞争。它提供了模型参数之外的适配通道，但不是开箱即用的召回模型；需要测量主机查表传输开销、计数表更新成本，以及社区长尾词变化是否改善搜索任务。

LatentLoop: Scaling Looped MoE Models with Asymmetric Compute Allocation

LatentLoop 利用共享模块第一次循环与第二次循环贡献不对称的现象，压缩第一次的序列、保留第二次完整分辨率，并用节省的计算扩大隐藏维度。在 1.3B—7B 的 15 种配置中均降低验证负对数似然；拟合到 NLL 1.988 时，预测计算量相对普通 MoE 和循环基线分别节省 19.0% 和 7.9%。

INSIGHT对需要自训小型社区语言模型的团队，计算预算应按不同循环的实际贡献分配，而非机械地重复相同计算。可借鉴先测残差贡献、再调整序列分辨率的流程；文中的节省来自拟合曲线，不能当成线上延迟实测，推理端还需验证序列压缩与注意力实现成本。

Zefeng He, Yunkai Chai, Xiaoyang Chen, Tong Zhu, Zongliang Wu
