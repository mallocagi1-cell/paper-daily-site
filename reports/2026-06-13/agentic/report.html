1. GraphER: An Efficient Graph-Based Enrichment and Reranking Method for Retrieval-Augmented Generation
3.70
Relevance 4 | Novelty 4 | Practical 4 | Evidence 3 | Timely 2

Summary: 针对 RAG 在多源、复杂查询下语义检索难以召回完整证据的问题，提出 GraphER：在查询时依据数据的组织结构与邻近关系临时构建图，再用图排序挑选 top 文档。方法不需要额外的图数据库基建，可直接接入现有向量库，引入的查询延迟开销很小。在表格检索、多跳检索、长文档三类基准上检索完整性持续提升。

Key insight: GraphER 把图结构放在查询时临时构建而非预先建库，绕开了知识图谱 RAG 落地最重的图基建成本，对已有向量检索栈是低侵入的增量改造。对社区搜索的启示：当用户意图分散在多条短文本 UGC、单条命中不足以覆盖时，可用文档间的邻近/结构关系做查询时图重排来补全证据链，而不必重做召回层。

2. Agent-Orchestrated Adaptive RAG: A Comparative Study on Structured and Multi-Hop Retrieval
3.65
Relevance 4 | Novelty 3 | Practical 4 | Evidence 3 | Timely 4

Summary: 系统对比了把 agentic 能力（动态查询拆解、迭代检索、带上限的自反思评估环）加到 RAG 上的实际收益。在 DevOps 知识库与 MuSiQue 多跳基准上发现：查询拆解在结构化领域提升明显（DevOps 总分 +0.04、MRR +0.17），却会拉低多跳任务的排序精度；自反思提升了引用准确率但带来显著延迟。作者结论是 agentic 增强并非普遍有益，应按查询特征做成本敏感的选择性启用。

Key insight: 这篇给“是否要上 agentic RAG”提供了反例证据：拆解和反思都有明确代价，盲目叠加会在多跳排序上反伤精度。对社区搜索的启示：把 agentic 改写/反思当作按 query 类型触发的旁路而非默认链路——对结构化、实体明确的 query 才开拆解，对模糊宽泛 query 谨慎使用，并为反思环节设延迟预算上限。

3. Need to Know: Contextual-Integrity-Grounded Query Rewriting for Privacy-Conscious LLM Delegation
3.35
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 4

Summary: 把隐私保护的查询改写放到情境完整性（Contextual Integrity）框架下：只有当某段信息对完成任务必要时才转发给云端 LLM。作者构建了 DelegateCI-Bench（3,167 条样本、覆盖 11 类任务、含合成与真实用户 query），并用强化学习训练模型区分必要与非必要的敏感内容。相比端侧基线，平均效用最高 +10.1，取得更好的隐私-效用折中。

Key insight: 该工作把查询改写从“提升召回”重新定义为“按任务必要性做信息最小化转发”，给 LLM 委托场景引入可训练的必要性判别。对社区搜索的启示：当 UGC 查询含用户敏感信息又要调用云端大模型时，可借鉴必要性判别做改写脱敏；其 +10.1 的效用增益说明信息最小化不必以牺牲检索效果为代价。

4. Agentic Transformers Provably Learn to Search via Reinforcement Learning
3.25
Relevance 3 | Novelty 5 | Practical 2 | Evidence 2 | Timely 4

Summary: 理论分析 transformer 智能体如何通过强化学习学会“搜索”。作者构造了一个双头 transformer 实现随机化深度优先搜索（一个头追踪历史动作、另一个检测失败以触发回溯），并证明该搜索机制能在随机 k 叉树环境下、仅凭稀疏奖励、无需专家示范地自发涌现。学到的策略具备深度泛化（仅在浅树训练即可在更深的树上成功）；在目标分布不均、回报折扣的设定下，会发展出优先高概率分支的有序 DFS。

Key insight: 这篇从可证明的角度回答了“RL 智能体为何能学会回溯式搜索”：搜索与回溯不是被显式编程，而是稀疏奖励下的涌现行为。对搜索 agent 设计的启示：多步检索 agent 的“回溯/换查询”能力可由结果奖励驱动习得，深度泛化意味着可在短轨迹上训练再迁移到更长检索链；理论虽在合成树上，但为 Search-R1 类方法的有效性提供了机理解释。

5. NVIDIA Achieves Leading Agentic Coding Performance on First Agentic AI Benchmark (AA-AgentPerf)
3.30
Relevance 3 | Novelty 3 | Practical 3 | Evidence 4 | Timely 5

Summary: NVIDIA 在业界首个多厂商 agentic 编码基准 AA-AgentPerf（Artificial Analysis）上给出系统级结果。该基准用贴近真实 AI agent 编码任务的轨迹，衡量在满足性能 SLO 的前提下推理系统能并发支撑多少 agent。通过 WideEP/DeepEP 分散 MoE 执行、DeepGEMM 低精度核以及跨 72 GPU 的 NVLink 协同，GB300 NVL72 在 SLO #1 档位下达到每兆瓦 61.4K 并发 agent，约为上一代 H200（2.6K）的 20 倍。

Key insight: 这条评测把“agent 服务”的核心指标从单请求延迟转到“每兆瓦可并发 agent 数”，揭示长轨迹、多轮工具调用的 agent 负载对推理系统的压力点在 MoE 调度与互联带宽。对搜索 agent 工程的启示：上线多步检索 agent 要按并发 agent 吞吐而非单 query 延迟做容量规划；MoE 专家并行与高带宽互联是支撑大规模 agent 并发的关键。

6. IntentScore: Intent-Conditioned Action Evaluation for Computer-Use Agents
3.25
Relevance 3 | Novelty 4 | Practical 3 | Evidence 4 | Timely 2

Summary: 针对 GUI/计算机操作 agent 无法在执行前评估动作质量、易产生不可逆级联错误的问题，提出 IntentScore 奖励模型。它在跨三种操作系统的 39.8 万条离线交互步上训练，用对比对齐学习状态-动作相关性、用 margin ranking 学习动作正确性，并把规划意图编码进动作表示，以区分“看似相同但意图不同”的动作。作为重排器部署到 OSWorld 后显著提升任务成功率，并能泛化到未见过的 agent 与任务分布。

Key insight: IntentScore 的核心是“意图条件化的动作打分”——同一动作在不同规划意图下价值不同，这与搜索中“同一文档对不同 query 意图相关性不同”高度同构。对社区搜索的启示：其用 margin ranking + 对比对齐训练重排器的范式，可迁移到把用户意图显式编码进 query-doc 打分做意图条件化重排；39.8 万步离线数据训练也说明结果级奖励模型可由日志规模化构建。

7. Co-Evolution of Policy and Internal Reward for Language Agents
3.15
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 2

Summary: 针对长程 LLM agent 训练中奖励稀疏、延迟的问题，提出 Self-Guide：让 agent 自己生成内部引导信号。该信号双向使用——推理时引导动作选择，训练时作为步级奖励用于策略优化，形成“策略变强→引导更好→策略再变强”的协同演化环。结合 GRPO 后，在三个 agent 基准上相比仅用环境奖励的基线提升 8%。

Key insight: Self-Guide 把过程奖励从外部标注或独立奖励模型改成由策略自身派生，省去单独训练 PRM 的成本。对搜索 agent 训练的启示：多步检索任务通常只有最终答案的稀疏奖励，可让 agent 在每步生成自评作为步级奖励来稠密化信号；其与 GRPO 结合的 +8% 增益给“自生成中间反馈”提供了可复用的训练配方。
