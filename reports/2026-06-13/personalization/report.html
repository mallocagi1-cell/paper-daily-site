LLM-Based User Personas for Recommendations at Scale

针对十亿用户规模的工业级视频推荐平台，提出在 serving 阶段实时生成 LLM 自然语言用户兴趣 persona 的框架。方法把「已有兴趣摘要」与「新主题探索」结合，直接在线上缓解 exploitation-exploration 权衡；为应对十亿用户在线 LLM 推理的算力瓶颈，设计了知识蒸馏、异步推理、以及基于语义聚类视频表征的输入压缩三件套。离线评测、用户研究与线上 A/B 均显示 viewer value 显著提升。

LLM-Based User Personas for Recommendations at Scale — 深度解读

1. 问题与动机

现有 LLM 推荐方法多依赖结构化 ID 或离线/近线处理，牺牲了语义丰富度、实时适应性与对用户的可解释性。论文给出具体证据：此前工业界工作（Wang et al. 2024–2025）仅用用户「最近两个观看视频」的聚类标签，无法捕捉长期兴趣；现有方法几乎只在离线/近线运行，对即时意图响应迟钝；还把 LLM 输出限制在「几百个预定义聚类」的小词表里。这些限制让推荐既无法表达细粒度语义，也无法向用户解释「为什么推这个」。在十亿用户视频平台上，作者希望用自然语言 persona 一次性解决三件事：长期兴趣建模、实时性、可解释性，并且全程要在严格延迟/成本预算内服务。

2. 方法详解

核心是「单次 LLM 推理完成双目标任务」：(a) Summarized Interests —— 把用户观看历史综合成简洁可读的兴趣标签；(b) Exploration Interests —— 对每个 summarized interest 生成语义相关但新颖的主题，从而在一次推理内完成 exploitation-exploration 平衡。
用户表征三个关键发现：① 视频标题比描述/salient terms 信噪比更高，效果最好；② 先用「Infinite Concept Personalized Clustering」算法（按 salient term 相似度，salient term 是带 salience 权重的 unigram/bigram）把视频聚成语义簇再拼 prompt，显著提升语义丰富度，并剔除观看极少的簇；③ 模型越大越好，但到 Gemini Pro 与 Ultra 之间出现饱和。
知识蒸馏：teacher 用 Gemini 1.5 Pro（配 Chain-of-Thought 多步推理）生成高质量训练数据，随机采样「数万」合格用户，只保留兴趣数量符合指令的回复，按 80%/20% 切分；student 是 Gemini Flash 与 Gemini Nano，并对 student 做量化。
异步推理架构：在线请求先查缓存里是否有「最新的 persona」，若过期/缺失则触发异步后台 job 重算，当前请求不等待生成完成；生产中选用 Nano（而非 Flash）以满足严格延迟/成本。
召回侧两种方案：传统双塔（cosine 相似度）或 sequential transformer 上做「constrained nearest neighbor search」，把检索限制在语义相关 item。线上策略：每次请求随机采样一个 summarized + 一个 exploration interest，强制统一探索策略、保证 session 内发现多样性，缓解生产系统严重的 recency bias。输出端加安全分类器，命中敏感兴趣则回退到此前安全 persona。

3. 核心技术贡献

① 首个在十亿用户规模、serving 阶段实时生成自然语言 LLM persona 且满足延迟约束的系统——把「用户长期兴趣」从离线 ID 升级为在线可读文本。② 用统一 prompt 在一次推理内同时产出「已有兴趣」与「新颖探索主题」，把 exploitation-exploration 内化进生成，而非靠额外探索模块。③ 工业级低成本架构：异步后台生成 + student 量化 + 语义聚类输入压缩，三者叠加把在线 LLM 推理成本压到可服务范围。④ 语义聚类输入（标题 + 语义簇）相比 sequential ID 序列显著提升 persona 质量，BLEURT 上语义簇优于 embedding 簇。蒸馏证据尤其有力：Nano/Flash 的指令遵循率（IFR）从 epoch 0 的 0.07%/1.82% 提升到 epoch 26.2 的 99.08%/99.68%，说明若要服务小模型，蒸馏是必需的。

4. 实验结果分析

离线（用户表征）：BLEURT 上「标题 + 语义簇」显著优于 sequential 表征，语义簇优于 embedding 簇，模型规模 Pro/Ultra 明显优于 Flash。定性例子：sequential 只能给出「bengali tv shows」，聚类输入能给出具体剧名「mon ditey chai / icche putul / bojhena se bojhena」。
离线（蒸馏）：IFR 从 0.07%(Nano)/1.82%(Flash) → 99.08%/99.68%（epoch 26.2）；摘要 BLEURT 在 epoch 26.2 为 0.328(Nano)/0.345(Flash)，Nano 蒸馏后接近大模型初始水平；但 creativity（探索）分上 Flash 持续提升、Nano 始终吃力，说明 Nano 参数容量不足以做创造性探索。
用户调研（美国数千用户）：超 80% 认为 LLM 标签「非常/极其贴近」其观看历史；71% 表示强烈想看生成主题的更多视频；与知识图谱基线对比，57% 严格更偏好 LLM persona，另有 20% 认为等价。
线上 A/B（>30 天，十亿用户）：watch time +0.04%、活跃用户数 +0.03%、engaged topics +0.04%、有多个持续兴趣主题的用户 +0.03%（均 p<0.05）。用户分层显示提升主要来自 casual 用户——LLM persona 更擅长从稀疏数据推断偏好。探索 vs 摘要的拆解很有意思：探索兴趣召回的 item 曝光少 40.91%，但被观看概率高 13.6%，且看过 persona 推荐视频的用户后续访问更多，呈现更长的 viewer value。

5. 局限与未来方向

作者明确列出 persona 的失败模式：① 漏掉用户的部分主要兴趣；② 在零散活动上过度推断；③ 提到已过时的兴趣；④ 生成重复的兴趣标签。作者把「持续 refine persona、解决上述具体问题」列为重要未来方向。需要补充的是：线上 watch time/活跃用户的绝对增益较小（+0.04%/+0.03%），虽统计显著，但要在十亿级体量上才有意义，迁移到中小平台的收益需重新评估；此外探索兴趣靠均匀采样注入，尚未做更精细的探索预算分配，这是隐含的改进空间。

6. 工业实践意义

对搜推从业者：① 可读 persona 是把 LLM 接入推荐的高性价比切口——既服务召回探索，又能直接拿来给用户做推荐解释，一举两得。② 落地三件套值得照搬：异步后台生成（在线请求不等 LLM）、student 量化（生产选 Nano 而非 Flash）、语义聚类压缩输入（用标题 + salient-term 簇而非全量序列），这套组合是把在线 LLM 推理塞进延迟/成本预算的关键。③ 探索 item「曝光少、点击率高 13.6%」的现象提示：探索 item 不该和摘要 item 抢同一份曝光配额，可单独留探索坑位。④ 务必加输出安全分类器 + 回退机制，避免 LLM 生成敏感兴趣文本。⑤ casual/低活用户是 LLM persona 收益最大的人群，冷启动/低频用户场景应优先试。部署上注意：persona 更新频率与历史窗口都应可配置，按平台 recency bias 调参。

DiffCold: A Diffusion-based Generative Model for Cold-Start Item Recommendation

SJTU

冷启动 item 推荐因缺乏交互历史长期受困于「跷跷板困境」：提升冷 item 往往牺牲热 item。作者指出根因是分布差异——热 item embedding 处于交互信号塑造的「行为流形」，冷 item 只能落在内容衍生的「语义流形」，强行映射会损伤热表征精度。DiffCold 用条件扩散从内容重建热 item embedding、保持流形结构不退化，并设计 Retrieval-enhanced Aggregator（用相似热 item 初始化生成、跳过低效噪声）与 Simulation-based Representation Alignment（对比学习对齐生成与真实分布）。三个 benchmark 上全指标超过 SOTA。

INSIGHT把冷启动建模成「从语义流形向行为流形的生成式迁移」，用扩散替代 GAN/VAE 来保持流形结构，是缓解冷热跷跷板的新思路。「相似热 item 初始化 + 分布对齐」两个模块可直接迁到自有冷启动召回/排序，尤其适合 UGC 新内容持续涌入的社区场景。

Kangning Zhang, Yingjie Qin, Weinan Zhang, Yong Yu, Jianghao Lin

One Polluted Page Is Enough: Evaluating Web Content Pollution in Generative Recommenders

检索增强 LLM 越来越多地中介日常消费推荐，带来新风险：生成式推荐器可能消费被污染的网页内容（假评论、推广页）而误导推荐。作者提出 FORGE 基准，在检索结果上局部把真实商品改写成虚假商品来模拟污染，覆盖 15 类目 225 个真实商品、5 个消费场景。在 12 个商用/开源 LLM 上，单个污染页就能让被骗率达 27%，污染 top-3 全部时升至 73.8%；reasoning 不仅不能缓解，反而常编造「社会证明」为虚假推荐背书。三种防御（怀疑式 prompt、基于模型先验或跨文档证据的共识过滤）各有副作用。代码已开源。

INSIGHT当推荐从「模型内知识」转向「实时检索网页」，内容污染就成了可被攻击的新面。对接入搜索/RAG 的推荐链路，需要把「召回内容可信度」纳入排序与防御，单纯加 reasoning 反而放大风险；FORGE 这类对抗基准值得在上线前做污染鲁棒性评测。

Minghao Luo, Liang Chen

Efficient and Robust Online Learning to Rank in Decentralized Systems

EPFLTU Delft

在线学习排序（OLTR）从实时用户交互训练排序模型，但通常依赖可信中心服务器，运营方可借此引入与用户利益冲突的偏置。RankGuard 是去中心化 OLTR 框架，用户直接交换模型更新协同训练；防投毒的核心是用本地私有点击历史（经位置偏置校正）来评估传入模型——只有当传入模型比本地模型更好地解释用户历史交互时才聚合，使恶意节点难以构造既能通过校验又不真正帮助用户的更新。论文给出去中心化 OLTR 的首个形式化收敛证明，在 4 种投毒攻击、4 个基准、3 种点击模型上优于基线，且比最接近的竞品快至多 62 倍。

INSIGHT「用用户自己的点击历史当作模型更新的验真锚点」是个朴素但有效的防投毒思路：任何聚合都必须先证明它更好地解释了本地行为。即便不做完全去中心化，这种「以私有交互校验外来更新」的机制也能用于联邦/多方排序训练的安全聚合。

Marcel Gregoriadis, Martijn de Vos, Sayan Biswas, Anne-Marie Kermarrec, Johan Pouwelse

CFALR: Collaborative Filtering-Augmented Large Language Model for Personalized Fashion Outfit Recommendation

PolyUNUS

个性化穿搭推荐需兼顾用户偏好与美学兼容性，传统协同过滤在数据稀疏和复杂「用户-单品-搭配」关系下表现不佳，模板方法又受限于刚性结构。CFALR 把用户-搭配交互用自然语言描述并交给 LLM 捕捉时尚语义，同时用 CF 增强的 embedding 桥接语义空间与协同交互空间；贡献包括首个面向个性化穿搭的 LLM 架构、CF 增强的生成机制（高效遍历庞大单品组合空间）、以及可训练投影层融合关系与内容特征。在 Polyvore、IQON 上的个性化填空与搭配生成任务超过传统 CF 与 LLM 方法。

INSIGHT用自然语言描述交互、再用 CF embedding 把协同信号注入 LLM，是把协同过滤与大模型语义对齐的一种轻量做法；「可训练投影层对齐两个空间」的设计，对任何想在 LLM 推荐里保留协同信号的团队都有参考价值。

Yujuan Ding, Junrong Liao, Yunshan Ma, Yi Bin, Wenqi Fan, Tat-Seng Chua, Qing Li
