Power-aware Deep Learning Model Serving with μ-Serve

μ-Serve 面向多模型 GPU 集群联合优化模型切分、放置、请求调度与动态频率缩放，在满足延迟或吞吐 SLO 的前提下降低能耗。系统使用算子敏感度指导细粒度供给，用预测输出长度的调度器缓解生成模型的不确定性，并在 8 节点、16 GPU 集群及生产负载上验证，报告 1.2–2.6 倍节能且不违反 SLO。

Compiler Optimization via LLM Reasoning for Efficient Model Serving

论文把模型服务中的编译器调优建模为上下文相关的序列决策问题：LLM 根据当前程序状态和历史性能反馈提出硬件感知变换，再由结构化蒙特卡洛树搜索平衡探索与利用。作者强调无需重新训练 LLM，即可在神经网络编译优化中提升样本效率，并以更少的候选评估获得与领先神经编译器相当或更好的加速效果。

INSIGHT对推理基建团队而言，LLM 更适合做离线编译搜索器，而不是进入在线请求路径。可将 kernel 融合、布局变换、并行策略等优化封装成可验证动作，用 MCTS 保留搜索多样性，再把最优配置固化进运行时；上线前必须复测不同模型、输入长度和硬件，避免把一次性的编译收益误当成稳定服务收益。

Annabelle Sujun Tang, Christopher Priebe, R. Mahapatra, Lianhui Qin, Hadi Esmaeilzadeh

03 4.15

Cracks in the Foundation: Seemingly Minor Architectural Choices Impact Long Context Extension

论文系统考察长上下文扩展中的四类看似细小的 Transformer 架构选择，发现它们会产生叠加性的负面影响。单个选择的损失可能不明显，但三个或更多选择组合时，下游长上下文表现最多下降 47%，而短上下文 loss 和验证集无法提前暴露问题；作者还指出，在预训练早期进行上下文扩展即可较早识别差异。

INSIGHT长上下文服务的瓶颈不只来自 KV Cache 和显存，模型架构本身会决定扩展上限。部署或继续预训练前，应把长上下文能力纳入早期架构验收，建立跨长度、跨任务的回归集；对搜索中的长帖、评论串和检索拼接上下文，不能用短上下文验证结果替代真实窗口压测。

Amanda Bertsch, Luca Soldaini, Matthew R. Gormley, Graham Neubig, Hannaneh Hajishirzi, Kyle Lo, Dirk...

04 4.10

The Multilingual Quantization Tax: Structural Collapse and Typological Fragility in Edge SLMs

论文评估 Gemma 4 与 Qwen 3.5 在八种类型学差异明显的语言上进行 4-bit 权重量化后的性能变化，关注边缘设备部署中的 quantization tax。结果显示，低资源语言和非拉丁文字可能出现结构性表示坍塌，跨语言路由和多步任务比部分联想记忆更脆弱；量化损伤并不能由英语基准结果可靠预测。

INSIGHT中文社区搜索的量化验收不能只看英文通用集或平均准确率。应按语言、脚本、query 长度、低资源实体和混合语种切片，分别监控 nDCG、召回率、拒答与非法输出；部署 INT4/边缘 SLM 前先做代表性 query 的精度—显存—延迟三维回归，并保留高风险语言的 FP8/FP16 回退。

05 3.90

How to Choose Full-Stack Observability for NVIDIA AI Factories

NVIDIA

NVIDIA 的工程文章把 AI 基础设施可观测性拆成计算、网络、存储、编排、运行时和应用多个层级，重点讨论性能退化时如何定位瓶颈。它强调从单一 GPU 指标扩展到端到端链路，包括请求路由、队列、显存/KV Cache、通信和模型服务质量，适合作为推理平台监控面的设计参考。

INSIGHT搜推平台应把模型质量与系统信号放进同一观测闭环：除了 nDCG/CTR，还要关联 TTFT、TPOT、GPU 利用率、显存碎片、队列等待、缓存命中、网络传输和实例级错误。先建立 query/request trace，再按 prefill、decode、向量检索、重排和回源阶段分解 SLO，才能判断指标下滑来自模型还是基础设施。

06 3.75

SkillZip: Evaluation-Free Skill Compression for Self-Evolving Agents by Discovering Reusable Structure

SkillZip 针对自演化 Agent 长期积累的技能文本冗余，提出无需评测 rollout 的结构化压缩方法。它把技能视为由触发条件、工作流、工具与输出契约、例外规则组成的结构，而不是普通段落，目标是发现可复用结构并让重复规则只保留一份，从而降低注入成本并改善维护性。

INSIGHT基础设施层可借鉴“契约感知压缩”：对搜索 Agent 的工具说明、检索策略和回退规则，压缩时必须保留触发条件、参数约束和异常分支，不能只按 token 数删文。上线前可用 schema、静态检查和少量黄金任务做安全门禁，再把压缩后的技能按版本缓存，控制上下文长度与回归风险。

Xiaofan Bai, Hongqiang Lin, Chao Liu, Yantao Zhang, Xuan Jin

07 3.60

Locally Deployable Small Language Models for Emergency Department Decision Support: A Systematic Benchmark of Fine-Tuning Strategies

论文以 2,083 个 MIMIC-IV-ED 案例为基准，比较八个开源小语言模型在零样本、Prefix Tuning、LoRA 和全量微调下的本地部署效果，并与 Claude Haiku 4.5、Claude Sonnet 4.5 对照。LoRA 微调的开源 SLM 在分诊和专科转诊任务上超过商业基线，但诊断预测仍然困难，说明本地化并不等于所有任务都可替代大模型。

INSIGHT它提供了“隐私约束下的小模型服务”评测模板：固定数据、任务、微调方式和商业基线，分别测准确率、显存、延迟与故障回退。对 UGC 搜索可迁移为本地 query 理解、敏感内容分类或轻量重排模型，先把 LoRA 和量化作为低成本路径，再按难例路由到更强模型。

Qingfeng Zhang, Yuanxiong Guo, Yanmin Gong

Reference-Free Post-Training of Open Large Language Models for Multilingual Machine Translation

该工作研究开放大模型的 reference-free 后训练，使用两个无参考质量估计模型构造平均奖励，并通过语言识别门控避免跨语言信号混淆；随后线性插值 SFT 与强化学习检查点得到新模型。实验覆盖 46 种语言，报告相对 SFT 持续提升，并在多个开放模型与专有系统对照中取得竞争性质量。

INSIGHT对模型平台，后训练流水线应把奖励模型、语言门控、检查点合并和离线评估做成可复用组件。中文 UGC 场景尤其要分语言和领域统计奖励偏差，避免把通用质量估计器直接当排序监督；上线前应同时检查模型质量、显存占用、吞吐和回退版本，保证训练收益可部署。

Chris Han, Pengzhi Gao, Pei Fu, Jian Luan

Proceedings of the 1st Workshop on Small and Efficient Large Language Models for Knowledge Extraction (SmaLLEXT 2025) co-located with CIKM 2025, Seoul, Korea, November 14, 2025.

SmaLLEXT 是围绕小型与高效大型语言模型知识抽取的专题论文集，聚焦在有限算力、较小模型和知识抽取任务之间的工程取舍。当前候选元数据主要提供专题范围和作者信息，未给出单篇论文的统一摘要或可直接比较的实验数字，因此本条更适合作为方向性技术雷达，而不是单项方案结论。

INSIGHT专题价值在于提醒平台团队把“高质量模型”与“可服务模型”分开评估：参数规模、量化、蒸馏、上下文长度和抽取准确率需要共同纳入成本模型。若要落地，应从其中挑选有代码和完整实验的单篇工作，先在短文本实体/标签抽取链路做小流量试验，再决定是否替换现有大模型。

Daybreak models are now available on AWS

OpenAIAWS

OpenAI 宣布 Daybreak 模型能力通过 Amazon Bedrock 提供，案例聚焦企业安全工作流。对基础设施团队而言，价值不在新算法，而在模型通过托管云服务进入现有企业平台后的部署形态：统一 API、权限与治理、供应商侧弹性，以及把模型能力接入既有安全和运维流程。

INSIGHT模型接入层应把供应商路由、权限、审计、成本和质量回退抽象为平台能力，不要让业务代码绑定单一模型。对于社区搜索，可将云端强模型用于低频难例或离线标注，常规 query 理解和重排继续走本地服务，并以数据边界、延迟、单请求成本和可替换性作为选型门槛。
