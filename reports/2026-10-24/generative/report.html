UniRec: A Unified Expressive-Aligned Generative Recommendation Framework for E-commerce

已录用 RecSys 2026

Shopee 的作者统计了标准 RQ-KMeans 生成的三层语义 ID（SID），发现最常曝光的前 10% 编码拿走了近九成曝光，生成式推荐模型的概率因此集中在少数热门编码上。UniRec 让模型先生成商品的二级和三级类目，再生成三层 SID，并在构建 SID 时给每个编码设一个按曝光加权的容量上限。离线 HR@50 比 OneRec-V2 相对高 22.6%，线上和原来的多阶段链路相比，GMV 提高 5.60%。先生成类目，后面每一层 SID 只需要在这个类目里挑。

生成式推荐把每个商品编码成几层离散的语义 ID（SID），模型逐层生成这些 ID 来完成召回和排序。Shopee 的这篇论文指出它和判别式排序模型之间的一个差距：判别模型给候选打分时能直接看到商品的类目、店铺、品牌这些特征，和用户特征做交叉；生成模型在生成第一层 SID 之前，没有看到任何商品侧信息。UniRec 的核心做法叫 Chain-of-Attribute（CoA）：先让模型生成商品的类目，再在已知类目的条件下生成 SID，相当于在解码路径里补回判别模型能用的商品特征。配套的还有按曝光量限制码本负载的 SID 构造、给解码过程注入场景和组合特征的 CDC，以及 RFT 加 DPO 的业务对齐。离线 HR@50 比最强基线 OneRec-V2 相对高 22.6%；在 Shopee 主 feed 和落地页上线，订单 +4.76%，GMV +5.60%，端到端延迟 110ms，原多阶段链路是 266ms。

论文在 arXiv 上的标题是 “UniRec: Bridging the Expressive Gap between Generative and Discriminative Recommendation via Chain-of-Attribute”，本文按 arXiv 全文解读。

1. 生成式推荐差在哪里

判别式排序模型估计 p(y∣f,u)，也就是给定用户 u 和商品特征 f，用户产生互动 y 的概率，商品特征在打分时全部可见。生成式模型按 ∏l​p(sl​∣s<l​,u) 逐层生成 SID，生成第一层时只看用户，不看任何商品特征。

作者用贝叶斯公式说明这个差距从哪里来：
p(y∣f,u)∝p(f∣y,u)p(y∣u),p(f∣y,u)=k=1∏n​p(fk​∣f<k​,y,u)
p(y∣u) 不随商品变化，所以按判别分排序等价于按 p(f∣y,u) 排序，而后者按链式法则展开正好是逐个生成商品特征。结论是：如果生成模型逐个生成商品的全部特征，它和判别模型的排序能力一样。实际系统做不到逐个生成全部特征，延迟太高，所以用几层 SID 压缩商品语义。类目、店铺、品牌这些判别模型直接拿来交叉的结构化属性，在压缩时被揉进了 SID，解码时不再显式出现，差距就出在这里。

2. 方法

2.1 Chain-of-Attribute：先生成类目，再生成 SID

CoA 在 SID 序列前面加 m 个属性 token a，生成顺序变成先属性、后 SID：
p(s∣u)=p(a∣u)⋅l=0∏L−1​p(sl​∣a,s<l​,u)
线上配置里，属性是商品的二级类目和三级类目（类目分 L1、L2、L3 三级，越往下越细），所以一个商品的解码路径是“二级类目 → 三级类目 → s0​ → s1​ → s2​”，比原来多两步。

先生成类目为什么有用：同类目的商品在 SID 空间里挨得近，知道类目以后，下一层 SID 的候选范围变小。作者把这一点写成条件熵的减少量 ΔHl​=H(sl​∣s<l​,u)−H(sl​∣a,s<l​,u)，它等于属性和该层 SID 之间的条件互信息，只要两者相关就大于 0。每层出错的概率降下来，整条路径全对的概率就提高，beam search 也更稳。

2.2 带容量约束的 SID：按曝光量而不是商品数平衡码本

已有的平衡量化（如 OneRec 用的 RQ-KMeans）让每个码字分到的商品数接近，但商品热度是长尾的，商品数平均不代表曝光量平均。作者在 Shopee 线上数据上统计了曝光集中度。只看第一层，曝光最多的 10% 码字拿走三分之一的曝光，还算温和；到前两层的组合，前 10% 就拿走了近九成曝光（87.90%）。这意味着越往深层，码字分配越不均衡，少数热门组合几乎包揽了全部流量。

训练数据里高曝光的 token 路径出现得多，模型在 beam search 时就反复生成这几条路径，作者称之为逐层继承的马太效应。容量约束 SID 的做法是在每一层残差聚类里加一条约束：每个簇里商品的曝光权重之和 Vk​ 不能超过平均负载的 τ 倍。
{zi​},{μk​}min​i=1∑N​∥xi​−μzi​​∥22​s.t.Vk​=i:zi​=k∑​wi​≤τCcap​
xi​ 是第 i 个商品在当前层的残差向量，zi​ 是它被分到的簇，μk​ 是簇中心，wi​ 是它的历史曝光次数，Ccap​ 是总曝光除以簇数，线上 τ=1.05。精确求解是 NP 难，实际用两步贪心：先把每个商品分到最近的簇，再把超载簇里的商品挪到最近的未满簇，重复到重构误差不再变化。

2.3 CDC：告诉模型当前是什么任务，再补上组合特征

一个生成模型要同时服务点击、购买、加购、跨境等目标，以及主 feed、搜索、相似推荐、秒杀等场景。Task-Conditioned BOS 把固定的起始 token 换成按“目标 × 场景”查表得到的可学习向量，从第一步开始就把解码引向该场景的分布。

Content Summary 处理 token 之间的组合含义：同一个 s1​ 跟在不同类目后面，代表的商品可能完全不同。直接给每对 token 组合建一个 embedding，两个 4000 词表的层就有约 1600 万个组合。CDC 改用 3 个哈希函数（$x+y$、x⋅y、p1​x+p2​y，p1​、p2​ 为质数）把（二级类目, s0​）、（三级类目, s1​）、（s0​, s1​）等组合映射到一张共享的哈希 embedding 表，拼成每一步的组合特征 ct​。

2.4 解码器和业务对齐

解码侧序列是 [BOS, 属性 token, SID token]，作为 Q；用户最近 200 条点击行为的商品向量，再接上 100 个由多层 SID embedding 融合成的多模态向量，一起作为 K、V，经过 3 层带可学习门控系数的交叉注意力和 MMoE-FFN。每一步有一个独立的 Rank Head，把注意力输出、已生成前缀的 embedding、ct​ 和用户聚合表示拼起来，经 SENet 和 MaskNet 输出该步的 token 分布。

下一 token 预测只拟合曝光分布，不直接优化 GMV。RFT 给每条样本算一个业务奖励，在 batch 内减均值、除以均方根、截断后得到 A~i​，把样本的损失权重乘上 (1+λA~i​)。DPO 按同一请求下的曝光商品构造偏好对，购买 > 点击 > 仅曝光，并且只对最后一层 SID 回传梯度，前面各层的预测保持不动，免得对齐过程打乱前缀。两者合起来训练：
L=LRFT​+λDPO​LDPO​
线上 RFT 和 DPO 的损失权重比是 20:3，DPO 的 β=0.1。

4. 局限

论文没有单独的局限讨论。从实验设置看有两点需要注意。一是所有离线对比都在 Shopee 内部数据上做，基线也都限制在 0.05B 参数，没有公开数据集上的结果。二是线上对照组是整套判别式多阶段系统，A/B 的提升包含了生成式架构、CoA、容量约束 SID、CDC 和对齐的全部作用，论文没有给出各组件在线上的单独贡献。

5. 实践意义

  • 如果你的生成式召回第一层 SID 命中率低，可以先试 CoA：在 SID 前加一到两级类目 token，只多两步解码，表 2 里第一层 Top-3 命中率从 0.314 升到 0.682。
  • 做 SID 时检查曝光集中度，不只看商品数是否平均。商品数均衡的码本仍可能让少数热门组合吃掉近九成曝光，beam search 会反复走这几条路径，按曝光量加容量约束只改聚类的分配步骤，成本不高。

OneLatent: Latent Reasoning for Efficient Foundation Recommendation Models

Kuaishou📖 有深读 · 11 分钟

用大模型做推荐底座时，先生成一段自然语言推理再输出物品的语义 ID（SID），推理文本很长，吞吐随之下降。快手的 OneLatent 在用户上下文和目标 SID 之间插入 3 个可学习的特殊 token。训练时，模型先在这些 token 之后复现教师大模型写的推理文本，再改成直接预测 SID，上线时就不再生成推理文字。它的吞吐是显式推理的 17.49 倍。不过和用同样的教师推理数据训练、直接作答的最强对照相比，它只高 1.58%，说明大部分提升来自教师推理数据。推理位置固定为几个 token，解码时间就不再随推理长度增长。

把大语言模型当作推荐底座时，一种做法是让模型先写一段自然语言推理（CoT），再输出下一个物品的语义编码（SID，把物品映射成三层离散编码的标识）。推理文本比三层 SID 长得多，解码时间和吞吐都被它拖住；而且此前的 OneReason 工作已经报告，同一个模型先推理再作答，并不稳定地好于直接作答。快手这篇 OneLatent 的做法是在用户上下文后面接 3 个固定的特殊 token，训练分几步：先让模型在这 3 个 token 之后复现教师大模型写的推理文本，再改成在它们之后直接输出目标 SID；上线时只接这 3 个 token，不生成任何推理文字。在快手本地生活工业数据上，OneLatent 的 SID@64 是 0.1993，比先写推理再作答的 OneReason-CoT 高 17.44%，推理吞吐是显式推理的 17.49 倍，和不推理的直接预测基本相同。和用同样教师推理数据训练、直接作答的最强对照相比，3 个潜在 token 在工业数据上只多出 1.58%，说明大部分提升来自教师推理数据本身。5% 流量的线上 A/B 测试估算收入提升 9.6%，目前已全量上线。

1. 显式推理为什么在推荐里不好用

推荐底座模型（FRM）的输入是用户画像 Pu​、按时间排列的交互历史 Hu​ 和请求时的上下文 Cu​（时间、地点、搜索词等），输出是下一个交互物品的 SID。让模型先写推理有两个问题。一是成本：每个请求都要逐个解码整段推理文字。二是准确率不一定涨：推理文字和 SID 之间多了一段生成路径，推理写偏一步，后面的 SID 就跟着偏。论文的 Table 2 里，OneReason-CoT 的先推理模式在工业数据上 SID@64 是 0.1697，低于同一检查点直接作答的 0.1823。

作者的思路是把教师写的推理只当训练信号，推理过程留在模型内部的隐状态里，推理时不输出文字。

2. 方法

2.1 潜在 token 是什么

作者在词表里加了 3 个特殊 token ⟨L1​⟩⟨L2​⟩⟨L3​⟩，所有样本共用这同一组 token ID。Transformer 处理到这 3 个位置时会产生随上下文变化的隐状态，后面的 SID token 通过普通的因果注意力读取这些隐状态。这里没有额外的编码器、投影层或解码器，推理时多出来的计算就是固定的 3 个 token。作者也明确说，后面的 token 仍然能直接看到原始上下文，所以不能保证推理信息全部压在这 3 个位置里。

2.2 教师推理：三个视角，长度随难度调整

教师模型是 Qwen3-235B-A22B-Instruct-2507，从三个视角为每个样本写推理：

  • 探索：只给用户画像和历史，让教师推测用户可能的消费意图，输出推理和意图列表。
  • 评估：额外告诉教师用户真实交互的物品，让它判断这个物品和用户证据的匹配程度，输出推理和 1–5 分。
  • 归因：告诉教师这个物品是正样本，让它解释是哪些历史信号导致了这次交互。

评估和归因视角用到了真实物品，但这个信息只给教师，不进学生模型的输入，所以不会泄露答案。提示词还要求教师先判断证据的复杂程度：信号明确的样本快速收敛，信号冲突的样本做多维比较。这样生成的推理平均长度降到原来的 65%（把不做自适应时的平均长度记为 100），在最长的一成样本上，两种推理的语义相似度约 0.92。

2.3 三阶段对齐和后训练

学生模型从 Qwen3.5-0.8B 初始化，先做推荐领域预训练，让 SID 和物品文字描述能互相生成：
Lsem​=−logpϕ​(Sv​∣Cv​)−logpϕ​(Cv​∣Sv​)
其中 Sv​ 是物品 v 的三层 SID，Cv​ 是它的文字描述。之后分三个阶段训练潜在 token：

  • 阶段一：输入是“画像、历史、视角标记、3 个潜在 token”，目标是复现一个视角的教师推理。
  • 阶段二：同样的输入，目标换成该样本的所有视角推理。每条推理内部按 token 数取平均，避免长推理在损失里占更大比重。
  • 阶段三：输入加上请求上下文，目标从推理文本换成下一个物品的 SID。

后训练先按用户活跃度从高到低做课程式微调，然后把“接潜在 token 再预测 SID”和“不接潜在 token 直接预测 SID”两种样本按 1:1 混合训练，保证两种模式都能用。

这组实验检验三视角推理是否比原有推理更好。作者请 GPT-5.5 从事实性、证据使用、因果逻辑等九个维度，给每种推理各 100 条样本打 1–5 分。三个新视角都在 4 分以上，评估视角最高（4.33），而 OneReason 的原推理只有 3.14，说明新推理的质量确实更高（论文 Table 4）。质量高也带来了推荐效果：用不同推理数据训练 OneLatent，公开数据上的 SID@64 从原推理的 0.0092 升到三视角合并后的 0.0239，只用评估视角就已经有 0.0233，所以收益大部分来自评估视角（论文 Table 5）。

为了看潜在 token 里存了什么，作者把画像、视角标记和 3 个潜在 token 输入训练好的模型，故意去掉交互历史，让它生成推理文字，再和教师推理比较语义相似度，三个视角的余弦相似度在 0.79 到 0.80 之间（论文 Table 8）。作者自己说明，画像仍然可见，这个相似度只能说明有关联，不能证明推理信息都存在潜在 token 里。

3.4 上线方式和 A/B 测试

即便没有推理文字，对每个请求同步调用底座模型仍然超出延迟和吞吐预算。所以 OneLatent 作为一路独立召回部署：用户有新行为时触发异步推理，按用户价值和行为强度决定刷新优先级，生成的候选写入 Redis，在线请求从缓存取候选，和原有召回结果一起进入精排竞争。A/B 测试在快手本地生活广告的一个子场景进行，实验组和对照组各占 5% 流量，时间是 2026 年 9 月 3 日到 10 日。实验组曝光量提升 2.566%，广告消耗提升 5.157%，后验估计收入提升 9.6%。

4. 局限

论文没有单独的局限章节，作者在正文里承认两点：潜在 token 不是严格的信息瓶颈，推理信息可能分散在整个模型里；Table 6 的提升来自完整的训练流程，不能单独归因于潜在 token。

另外两点需要注意。第一，工业数据上 OneLatent 比用同样教师数据训练的直接作答模型只高 1.58%，论文没有报告多次运行的方差，这个差距是否稳定无法判断。第二，线上采用异步缓存，候选是在用户上次行为之后生成的，A/B 的收益里有多少来自潜在推理、有多少来自新增一路召回，论文没有拆开。

5. 实践意义

一是想给推荐模型加推理能力，可以先把教师推理当作训练数据用，而不是要求模型在线上生成推理。论文里同一份三视角推理数据，用作训练信号时工业 SID@64 达到 0.1993，要求模型先写出来再作答只有 0.1505。

二是评估“潜在推理”类方法时，要把用同样教师数据训练的直接作答模型作为对照。本文工业数据上大部分提升在这个对照里已经出现，只和显式推理对比会高估潜在 token 本身的作用。

GenPage: Towards End-to-End Generative Homepage Construction at Netflix

已录用 RecSys 2026Netflix📖 有深读 · 12 分钟

Netflix 首页由多行组成，每行有一个主题和若干影片，过去由行模型、影片模型等多个阶段拼出来。GenPage 把用户的观看历史、设备和时段编码成 token 作为 prompt，用一个约 2 亿参数的 decoder-only Transformer，按从左到右、从上到下的顺序逐个生成行和影片。每行和每部影片只占一个 token，所以业务规则可以直接写成每一步的候选掩码。线上 A/B 测试中，核心指标提升 0.24%，端到端延迟降低 20%。把整页当成一个序列来生成，业务规则就能在每一步直接约束候选。

Lequn Wang, Jiangwei Pan, Linas Baltrunas

Netflix 首页由多行组成，每行是一个主题（比如“韩国电视剧”），行内横排若干部影片。原来的首页由多阶段推荐系统拼出来：先召回候选行和候选影片，再分别排序，最后组页。GenPage 用一个 decoder-only Transformer 直接生成整页：用户历史、账号属性和请求信息编码成 prompt，模型按从左到右、从上到下的顺序逐个生成行 token 和影片 token，每行、每部影片都只占一个 token。训练照搬大模型的流程，先在线上获得正反馈的首页上做下一 token 预测预训练，再用加权二分类（WBC）或强化学习做后训练。约 2 亿参数的 WBC 版本在 14 天 A/B 中把 Netflix 上线决策用的核心互动指标提升 0.24%，端到端延迟降低 20%；强化学习版本还没有上线。

1. 为什么要整页生成

多阶段系统里，召回、排序、组页各有各的模型和目标，特征工程也分散在各阶段。整页生成想解决三件事。第一，一个模型从原始输入直接出页面，要维护的模型少，各阶段目标不一致的问题也随之消失。第二，逐个生成的页面可以用强化学习按整页奖励优化，把行与行之间的相互影响算进去。比如“继续观看”行放在顶部时，用户多半直接续看已经开始的剧，不再往下浏览。论文把这种吸住注意力、让用户停止浏览的能力叫 stopping power。第三，模型质量可以靠加数据、加参数继续提高，不必反复改系统结构。

落到线上有四个约束：首页要实时生成，延迟是第一位的；片库每天都有新片，要处理冷启动；用户兴趣和热点在变，模型要保持新鲜；页面还要满足大量业务规则。

2. 数据怎么变成 token

每条训练样本对应一次首页曝光，包含三部分：上下文（用户历史、账号属性、请求信息）、页面（按版面顺序排列的行和影片）、反馈（播放、点赞、放弃等）。只有上下文和页面被 token 化作为模型的输入输出，反馈经过奖励系统转成监督信号。

团队没有用现成的文本分词器，而是为首页数据定制了 token。“用户 30 天前看了 50 分钟《女子监狱》”这件事，GPT-5 的分词器要 16 个 token，GenPage 只要 4 个：影片 ID、行为类型、行为时间分桶、观看时长分桶。一个影片、一行各对应一个 token，序列更短、推理更便宜，业务规则也能直接写成对某些 token 的屏蔽。行和影片的词表每天更新。

首页通常分几次请求、每次生成几行。每次翻页前，已经生成的行和用户在这些行上的最新行为会追加到 prompt 里，下一批推荐就能同时用上长期偏好和本次会话的行为。

3. 奖励与模型

奖励来自 Netflix 已有的奖励系统，它经过线上 A/B 调校，和用户的长期满意度对齐。系统给页面上每个曝光的影片一个标量奖励：一晚上刷完的剧奖励高，只看了 10 分钟的电影奖励低，曝光后用户放弃的影片得负奖励。整页奖励是所有曝光影片的奖励之和。

模型是标准 decoder-only Transformer，只有一处改动：输入 embedding 和输出投影不共享权重。预训练优化整个词表上的 softmax，WBC 后训练优化每个 token 各自的 sigmoid，两者需要的 logit 数值范围差别很大，拆开权重让模型能同时适应两种目标。线上 A/B 用的是约 2 亿参数的模型，为的是守住延迟预算。

4. 训练

4.1 预训练：模仿线上系统

预训练用线上获得正反馈的首页曝光，给定上下文和已生成的前几个页面 token，预测下一个页面 token。模型从零开始训，不从现成的大模型初始化。这一步让模型学会生成和线上系统相似的页面，但它只是模仿，不直接优化奖励大小；GenPage 上线后，如果反复用自己生成的页面再训练，模型还有退化的风险。

4.2 WBC 后训练：把生成变成逐 token 估值

WBC 让模型在给定上下文和已生成前缀时，估计生成每一个候选行或影片的价值。每个曝光影片的标签取奖励的正负（正向互动为 1，放弃为 0），权重取奖励的绝对值，行的奖励由行内影片奖励汇总得到。按论文的描述，损失写成：
LWBC​=−t∑​∣rt​∣[yt​logσ(zt​)+(1−yt​)log(1−σ(zt​))],yt​=1[rt​>0]
t 是页面上一个曝光的行或影片，rt​ 是它的奖励，zt​ 是模型在该位置给这个 token 的 logit，σ 是 sigmoid。每个曝光目标之外，还随机抽一些 token 当负样本。很少被曝光的影片作为随机负样本被抽中的次数远多于作为正样本出现的次数，于是模型给冷门影片的估值天然偏低，这相当于一个热度先验，避免模型因为少量噪声样本把冷门影片排得很高。

生成时，模型在每一步对所有候选 token 算 logit，贪心选最大的那个，追加到前缀，再生成下一个。在线上排序模型的标准离线评估集上，WBC 模型在加权 AUC 等影片级指标上超过了线上排序模型。

4.3 强化学习后训练：按整页奖励优化

WBC 优化的是单个影片，强化学习优化整页。做法参照大模型的 RLHF：先训一个奖励模型，输入任意一页生成结果，预测这一页的整页奖励（监督目标是奖励系统给出的影片奖励之和），再用 Dr. GRPO（GRPO 的一个修正目标偏差的变体）优化生成策略，训练框架是 verl，推理引擎是 vLLM。策略、参考模型和奖励模型都从预训练 checkpoint 初始化。奖励模型的训练数据来自线上策略，只在和线上相似的页面上可靠，所以策略用 KL 惩罚约束在参考模型附近，防止策略生成那些奖励模型会误判为高分的页面。另有规则奖励，比如页面必须是一行一行的结构，业务上关键的行不能排得太靠下。

5. 上线要解决的工程问题

冷启动有两个办法。一是把新片或直播等时效内容的元数据直接写进上下文 token。二是语义 embedding 融合：每部影片的输入 embedding 由 ID embedding 和基于简介、演员、字幕、类型、视频内容的内容 embedding 融合而成，新片即使交互很少也有可用的表示。

保持新鲜靠多节奏增量训练：隔一段时间在较长的历史窗口上完整做一遍预训练和后训练；两次之间每天从前一天的 checkpoint 继续后训练，数据是最近一天加一部分抽样的历史数据，既跟上新片和热点，又不忘掉旧知识。新行、新影片先用对应类型的兜底 token 初始化，训练时还随机把一小部分已知 token 换成兜底 token，让模型学会处理没见过的 token。

业务规则用约束解码保证：每一步按适用的规则算出可选 token 的掩码，乘到输出 logit 上，只允许合规的 token 被生成。比如要把“热门游戏”行固定在第 2 行，就在第 2 行的位置屏蔽其他所有行 token。规则因请求而异，所以掩码要按请求、按位置动态构造，团队为此改了推理引擎。

每行只自回归生成前几部影片，因为前几部最受注意、最能决定这一行给人的印象；剩下的位置在这个前缀条件下做一次前向，按 logit 取分数最高的合规影片，这叫混合行解码，用来减少解码步数。

6.1 预训练有没有用

这组实验要说明预训练能给 WBC 后训练提供更好的起点。做法是对比先预训练再做 WBC，和直接做 WBC。

Entity AUC 从 0.91 到 0.92 看起来很小，作者换了一种说法：不考虑样本加权时，随机抽一对曝光影片（一个正样本、一个负样本），模型排错的概率从 9% 降到 8%。在成熟的线上系统上，单个改动很少能带来这么大的提升。

6.2 加参数还是加上下文

这组实验要比较两种提升方式的收益：模型从约 1.2 亿参数扩到 9 亿参数，以及模型大小不变、逐步丰富 prompt 的内容和 token 化方式。

模型扩大约 7.5 倍，WBC 损失只降约 1.3%；丰富上下文累计降约 6.9%，好几次单独一项上下文改进的收益就超过整个参数扩大的收益。作者的判断是，当前阶段个性化质量先受限于模型能拿到的信息和表示方式，然后才受限于容量。两组实验的轴不同，上下文的每一步也是在不同数据快照上测相对上一步的改进再连乘出来的，只能做相对比较。

6.3 强化学习是不是在优化整页

这组实验要说明强化学习学到的是整页层面的策略，而不是逐个 token 贪心。奖励在训练中稳步上升，但这是用策略正在优化的同一个奖励模型算的，只能算验证。更有说服力的是多样性：用页面上影片两两之间的 embedding 距离衡量，它不在训练目标里，却也随训练上升。

6.4 线上 A/B

线上对照组是现有的多阶段首页推荐系统，实验组是约 2 亿参数的 WBC 模型。为了沿用资格审核等业务规则，GenPage 在现有系统给出的候选行和候选影片集合里解码。共 5 个实验组，区别在随机负样本的数量和训练时纳入哪些线上曝光。

5 个配置的提升接近，说明收益不依赖某个特定的训练数据设置。作者称这是近几年最大的算法驱动提升之一。延迟下降是因为一个 Transformer 直接吃 token 化的原始输入，替换了多个排序阶段和大量特征计算，定制 token 和混合行解码又减少了解码步数，而且可用的优化还没有用完。

上线后还观察到两件事。一是会话内的最新行为会很快影响后续推荐，一两天后回落到长期偏好，说明模型确实在使用行为时间戳，原系统做到这一点要靠大量手工特征。二是曝光内容的构成发生了意料之外的变化，比如新片和老片、剧集和电影、高质量和低质量互动的比例都变了。作者推测这是因为 GenPage 的个性化更精准，暴露出从原系统继承来的奖励系统等组件和生成式范式还没对齐，后续会调这些组件。

7. 局限

作者列出的未完成部分有三项：强化学习后训练还没有上线；长上下文仍然靠手工设计的摘要；文本、多模态和推理能力还没有接入。强化学习还有两个开放问题：离线评估依赖策略正在优化的奖励模型，结论是循环的；WBC 完全按影片拆分、整页强化学习完全不拆，两者之间如何利用部分结构还没有答案。

另外，线上实验是在原系统给出的候选集合上解码，召回阶段并没有被替换，所以这次 A/B 验证的是排序和组页，不是完全端到端的生成。

8. 实践意义

  • 如果你在做生成式推荐，可以先检查 token 化方式：一个物品、一个版面单元对应一个 token，序列短，业务规则也能直接写成 logit 掩码，不需要在多 token 的文本词表上维护复杂的约束。
  • 在加大模型之前先丰富上下文。Netflix 的数据里，上下文改进累计带来的损失下降约为 7.5 倍参数扩大的 5 倍。
04 4.20

Coarse-to-Fine Long-term Interest Modeling for Generative Recommendation

已录用 RecSys 2026📖 有深读 · 11 分钟

生成式推荐的注意力计算量随序列长度平方增长，所以通常只用短行为序列。快手和清华的 GLASS 在两个地方使用长期历史。生成第一层 SID 之前，它按长期历史里各物品和每个一级编码中心的相似度分档计数，压成一个兴趣 token 送进编码器。第一层 SID 生成后，它再从长期历史里取出第一层编码相同的物品，用门控融合辅助生成后两层。在快手短视频为期两周的 A/B 测试中，人均使用时长提高 0.052%。第一层编码定下大类，后两层要在大类里区分具体物品，所以需要同类的历史。

生成式推荐把物品编码成几层语义 ID（SID），再用 Transformer 一个码一个码地生成下一个物品。注意力计算量随序列长度平方增长，所以这类模型通常只吃最近几十条行为。论文用的两个数据集里，用户平均历史长度是 987（TAOBAO-MM）和 884（KuaiRec），模型输入却只截最近 50 条。作者还观察到一个现象：普通生成式召回在第一层码生成之后，真实物品在 beam 里的排名不升反降，第二层平均名次变差 1.25。论文提出的方法 GLASS 按 SID 的层级分开用长期历史。生成第一层码之前，它把整段长期历史压成一个兴趣 token 送进编码器；第一层码生成之后，拿它当检索键，从长期历史里取出同一大类的物品，辅助生成后两层码。在 TAOBAO-MM 上，R@1 比最强基线 DualGR 高 21.57%；短视频平台两周 A/B 中，人均使用时长 +0.052%，召回率绝对提升 3 个百分点。

1. 问题：长历史怎么进生成式召回

排序阶段处理长序列有成熟做法，就是 SIM 的两段式：先用 GSU（General Search Unit）按目标物品从长历史里检索相关子序列，再交给 ESU（Exact Search Unit）做精细的 target attention。召回阶段没有目标物品，GSU 不知道该拿什么去检索。OneRec、OneSearch 用 Q-Former 把长期行为压成固定长度的向量，粒度停在兴趣簇一级。DualGR 已经把 SID 当检索键用在生成式召回里，但它对所有层级的码一视同仁。

作者的出发点是 SID 本身的结构。第一层码决定物品属于哪个大类，后两层码在这个大类里定位具体物品。生成第一层码时还没有任何路径，模型需要的是用户在各个大类上的整体偏好；生成后两层码时大类已经定了，需要的是用户在这个大类里具体点过什么。两层需要的长期信息粒度不同，所以分两处注入。

2. 整体结构

主干是 TIGER 式的编码器-解码器。物品的多模态向量经 RQ-VAE 量化成三层码，公开数据集上码本大小是 [64,128,128]，嵌入维度 96，编码器和解码器各 4 层。用户历史按时间排序后切成两段：最近 50 条是短期序列，更早的全部算长期序列。

3. 第一层码：SID-Tier 把长期历史压成一个 token

这一步解决“第一层码生成时没有任何线索”的问题。直接对长期历史做注意力太贵，作者利用了一级码本很小这一点：一级码只有几十到一百多个，用户历史和每个码之间的交叉特征可以全部算出来。

先给每个一级码 k 一个原型向量 h~k​，取所有第一层码为 k 的物品向量的平均。然后把余弦相似度区间 $[-1,1]$ 等分成 N 档，对每个一级码统计长期历史里落在每一档的物品数：
tk​[j]=v∈Hlongid​∑​I(bin(Cos(h~k​,hv​))=j)
hv​ 是历史物品 v 的多模态向量，bin(⋅) 把相似度映射到档位，I 是指示函数。直觉上，tk​ 描述的是“用户历史里有多少物品和大类 k 很像、有多少一般像、有多少不像”。把所有一级码的直方图拼起来，长度是 K0​⋅N，过一个 MLP（隐层 256）压成一个 d 维向量 etier​，拼在短期序列嵌入后面一起送进编码器。

这个 token 只依赖用户历史和码本，和要生成的物品无关，可以离线提前算好。它其实就是排序模型里常见的“用户对类目的历史偏好统计特征”，换成了在 SID 一级码上算。

4. 后两层码：用生成的第一层码去长期历史里检索

第一层码 c^0​ 生成之后，模型从长期历史里取出第一层码相同的所有物品：
Hret​={c(vi​)∣vi​∈Hlongid​, c0​(vi​)=c^0​(vn+1​)}
这相当于 SIM 的硬检索，检索键从“目标物品的类目”换成了“刚生成的第一层码”。解码器每层先做自注意力，再并行做两路 cross attention：一路以编码器输出为 key/value，得到 Zshort​；一路以检索回来的物品嵌入为 key/value，得到 Zret​。两路用门控合并：
g=σ([Zshort​;Zret​]Wg​),Zcontext​=(1−g)⊙Zshort​+g⊙Zret​
Wg​ 是 2d×d 的投影矩阵，σ 是 sigmoid。g 大，结果偏向检索到的长期物品；g 小，偏向短期序列。训练目标是三层码的标准自回归交叉熵。

5. 检索回来的物品太少怎么办

硬检索有个直接的问题。按论文的例子，历史长度 1000、一级码本 128 时，每个一级码平均只能取回约 7.8 个物品，信息太少，噪声占比又高。作者给了两种补法：

  • 语义邻居补充：预先算出一级码之间的余弦相似度，给每个码记下 top-k 个最近邻。检索结果少于阈值 τ 时，把邻居码对应的历史物品也并进来。
  • 缩小一级码本：训练时就把一级码本调小，让每个一级码覆盖更多物品。第一层负责“多”，后两层负责“准”。

6. 实验

主实验要证明 GLASS 比 ID 类序列模型和 SID 类生成式模型都好。两个数据集都只保留正反馈：TAOBAO-MM 取点击，并从商品里均匀采样 1 万个、只留训练集中出现至少 5 次的；KuaiRec 取播放时长超过视频时长的样本。下表从论文表 2 摘了最强的 ID 模型 HSTU 和两个 SID 基线：TIGER 是标准生成式召回，DualGR 用长短期两路分支加路由。

KuaiRec 上的提升只有 3.81%–4.94%。作者的解释是 KuaiRec 的多模态向量来自简单的文本编码，SID 质量差，而 TAOBAO-MM 用的是对比学习训出来的多模态特征。

消融实验说明两个模块管的是不同的层：SID-Tier 主要帮第一层码，语义检索主要帮第二层码。作者看两个量：teacher forcing 下第 i 层码的训练准确率 acci​，以及前面各层都对时第 i 层码在 top-1 beam search 下也对的概率 Pi​。加上 SID-Tier 后，第一层的这两个量都有提升，Recall@5 也从 0.0702 升到 0.0842，说明第一层码更准直接带来了召回提升。再加语义检索，主要抬高的是 acc2​ 和 P2​。

作者还解释了正确答案的名次为什么会往下掉。他们定义了条件名次（CRP）：只看前 $d-1$ 层码都留在 beam 里的样本，算第 d 层正确码在 top-K 候选里的平均名次，越接近 1 越好。beam 大小为 20 时，普通生成式模型到第二层，正确码的名次平均变差 1.25 位，加上语义检索后只变差 0.98 位，第三层也有类似的改善。原因是普通模型生成后两层码时，条件上下文还是开头那一份，没有新信息去拉开正确答案和干扰项的概率差距；语义检索恰好补上了这份新信息。

门控是有用的。固定权重 0.5 在一级码本小的时候有提升，码本变细后反而变差，因为检索结果的长度波动很大，太短时噪声会直接进入 beam search 的累积概率。学习到的门控值随检索长度整体上升，检索到的物品越多，模型给长期分支的权重越高。

两种补救检索稀疏的办法里，缩小一级码本拿到了最高的 Recall@10。语义邻居补充只在不缩码本时有效；码本已经缩小时再加邻居，指标略降，作者认为是邻居带进来的物品模糊了不同兴趣之间的边界。

线上实验是在一个短视频平台上做的两周 A/B，实验组和对照组各占 3% 的用户，约 1200 万人。使用时长只涨了约 0.05%，但在这么大的流量上统计显著，召回率则绝对提升了 3 个百分点。

7. 局限和可以做的事

论文没有单独讨论局限，有两点事实要注意。一是公开数据集规模偏小：KuaiRec 只有 3790 个用户，TAOBAO-MM 的物品被采样到 1 万个，和工业级码本的规模差很远。二是效果对 SID 质量很敏感：在 SID 质量好的 TAOBAO-MM 上，各指标比最强基线高 14%–30%，到了 SID 质量差的 KuaiRec 上只高 4% 左右。

如果你在做生成式召回、又有长行为序列，有两件事可以直接试：

  • 把“用户对一级码的历史偏好直方图”当作一个额外 token 拼到编码器输入里，它可以离线算，线上几乎不增加开销。
  • 用生成出的第一层码做硬检索之前，先统计一下每个一级码在用户历史里平均能取回多少物品；太少就先考虑缩小一级码本，再考虑邻居补充。
