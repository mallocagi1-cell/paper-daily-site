1. RankUp: Towards High-rank Representations for Large Scale Advertising Recommender Systems

Relevance 5 | Novelty 4 | Practical 5 | Evidence 5 | Timely 5

Summary: 本文揭示了推荐系统 Scaling Law 中一个关键盲区：虽然 MetaFormer 架构在增加深度和维度后性能提升，但 token 表征的有效秩（effective rank）并未随参数增长而线性扩展，甚至在深层出现退化。作者提出 RankUp 架构，通过随机排列分裂稀疏特征、多嵌入范式、全局 token 集成、交叉预训练嵌入 token 和任务特定 token 解耦等五大机制缓解表征坍塌。RankUp 已全量部署于微信视频号、公众号和朋友圈广告系统，分别带来 3.41%、4.81% 和 2.21% 的 GMV 提升。

Key insight: 表征有效秩的阻尼振荡现象表明，单纯加深模型并不能持续提高表达能力——这对当前推荐系统 Scaling Law 的实践方式提出挑战。RankUp 的多嵌入范式和任务解耦设计可直接借鉴到搜索排序模型中：当我们增大模型规模时，应同时监控中间层表征的秩变化并引入结构性约束，避免参数浪费。微信三大产品线的 GMV 提升验证了该方法在工业级流量下的可靠性。

独立页面阅读 ↗

1. 问题与动机

推荐系统的 Scaling Law 近年来得到广泛验证——MetaFormer 类架构在增加模型深度、隐层维度和用户行为序列长度后性能持续提升。然而，一个关键问题尚未被充分探讨：表征能力是否随参数增长而线性扩展？

作者团队在 RankMixer 的实证分析中发现了一个令人担忧的现象：token 表征的有效秩（effective rank）在深层出现"阻尼振荡"轨迹，即有效秩不仅没有随深度增加而持续提升，反而在某些深层发生退化。这意味着即使模型从 10M 参数扩展到 100M，表征仍可能被困在低维子空间中，导致表征坍塌——学习到的表征集中在低维子空间，模型区分不同用户和物品的能力受限。

这一发现对工业界的推荐系统 Scaling 实践具有根本性影响：单纯堆叠参数量并不能保证推荐效果的线性提升，需要在架构层面引入结构性约束来维护表征的多样性和表达能力。

2. 方法详解

RankUp 提出五个核心架构组件来缓解表征坍塌：

（1）随机排列分裂（Randomized Permutation Splitting）：替代传统的语义分组策略。使用随机置换算子 σ 将稀疏特征索引随机打乱后分配到不同 token 中。核心原理是：语义分组会导致高度相关的特征聚集在同一 token 中，造成 token 间冗余度过高。通过随机分裂，高相关特征被分散到不同 token，扩展了初始表征的几何基底。互信息分析证实，该策略使 token 间的冗余度显著降低。

（2）多嵌入表征范式（Multi-Embedding Paradigm）：采用 K 个独立的 embedding table (ψ₁,...,ψₖ) 替代单一 embedding 函数。每个特征获得来自不同 table 的 embedding 元组，提供"多个几何视角"。这打破了单一 embedding 空间的表达瓶颈，使相同特征可以在不同子空间中被捕捉。

（3）全局 Token 集成（Global Token Integration）：引入聚合全局 token g = func(Pool({Embed(fᵢ)}))，捕获全局输入上下文信息。与局部 token 并行处理，使模型能在特征间建立全局交互，避免信息被局部分组割裂。

（4）交叉预训练嵌入（Cross Pre-trained Embedding Integration）：通过元素级乘积注入交互先验：e_cross = Proj(z_ue ⊙ z_ie)，将用户和物品的预训练嵌入组合后融入模型，显式暴露"交互感知的先验知识"，为深层网络提供更丰富的初始化信号。

（5）任务特定 Token 解耦（Task-Specific Token Decoupling）：引入 K 个可学习任务 token {x_task^(k)}，在 MetaFormer 骨架中独立处理。核心目标是缓解多任务监督下的表征坍塌——不同任务的梯度信号可能相互干扰，任务 token 解耦后各自维护独立的表征空间。

训练配置：2 层 MetaFormer 骨架，100M 参数（从 ~10M 基线扩展 10 倍）。输入包含 1200+ 稀疏类别 ID、稠密向量和序列表征。联合优化 32 个转化预测任务，使用 Pre-Layer Normalization 和 SwiGLU 激活函数保证深层训练的梯度稳定性。计算量约 70 GFLOPs/batch，模型 FLOPs 利用率 23%。

3. 核心技术贡献

贡献 1：揭示推荐模型的表征秩退化现象。 通过有效秩分析（erank(H^l) = exp(-Σpᵢ ln pᵢ)，其中 pᵢ 是归一化奇异值分布）量化了 MetaFormer 深层网络中表征多样性的退化轨迹。这是首次在推荐系统 Scaling 研究中系统性地分析了参数增长与表征质量的关系。

贡献 2：五组件协同架构提升表征秩。 随机分裂降低 token 间冗余、多嵌入提供多几何视角、全局 token 建立跨特征交互、交叉嵌入注入先验、任务解耦减少梯度干扰——五个组件各自解决表征坍塌的不同成因。消融实验显示各组件贡献互补。

贡献 3：微信三大产品线的全量部署验证。 RankUp 在微信视频号、公众号和朋友圈三个亿级流量场景中全量上线，提供了推荐系统 Scaling 研究中罕见的多场景生产级验证。

贡献 4：冷启动场景的显著增益。 新广告 GMV 提升分别达到 5.83%、9.67% 和 2.84%，说明高秩表征对冷启动物品的表达能力尤为关键。

5. 局限与未来方向

论文主要聚焦 MetaFormer 架构上的表征秩分析，尚未探讨：（1）更深层网络（10+ 层）中有效秩的行为模式是否与 2 层一致；（2）不同类型的稀疏特征（如文本 vs ID vs 数值）对表征秩的影响差异；（3）多嵌入范式 K 值的选择策略——论文未详细讨论 K 的敏感性分析。

此外，23% 的模型 FLOPs 利用率表明仍有较大的计算效率提升空间，如何在保持高秩表征的同时进一步优化推理效率是值得探索的方向。

6. 工业实践意义

对搜索排序模型的直接启示：在 Scaling 推荐/排序模型时，应建立有效秩监控机制——不仅关注 AUC/nDCG 等下游指标，更要追踪中间层表征质量。如果发现有效秩随深度增加而停滞或退化，应考虑引入类似 RankUp 的结构性约束。

工程实践要点：

  • 随机分裂：实现成本极低（仅需一个随机置换操作），可立即在现有模型中试验
  • 多嵌入：会增加 K 倍的 embedding table 存储，需在表达能力和资源消耗间权衡
  • 冷启动优势：对 UGC 平台尤为重要——新内容频繁产生，高秩表征有助于从有限信号中提取有效特征

部署指标参考：70 GFLOPs/batch 在微信广告场景下满足延迟约束，100M 参数量在工业级 GPU 集群上可支持全量推理。三个场景的一致性提升（GMV +2~5%）说明该方法具有良好的场景迁移性。据估计，全量部署带来年化数亿美元级收入增长。

2. Modular Representation Compression: Adapting LLMs for Efficient and Effective Recommendations

Relevance 5 | Novelty 4 | Practical 5 | Evidence 5 | Timely 5

Summary: 本文发现一个反直觉现象：LLM 中间层表征在推荐任务上优于最终层输出，说明 LLM 的深层语义压缩可能丢失了推荐所需的特征多样性。基于此洞察，作者提出 MARC（Modular Representation Compression），显式引入压缩和任务适配模块，利用信息约束解耦不同任务的表征需求。MARC 已被 SIGIR 2026 接收，在大规模商业搜索广告场景的在线 A/B 测试中取得 2.82% 的 eCPM 提升。

Key insight: "中间层优于最终层" 的发现对 LLM+推荐的工程实践有重要指导意义：直接使用 LLM 最后一层 embedding 做推荐可能并非最优，应该系统性地评估各层表征质量。MARC 的模块化设计使其可以作为即插即用组件集成到现有推荐 pipeline 中，降低 LLM 表征的存储和计算成本。2.82% eCPM 提升在搜索广告场景下是非常可观的收益，验证了 LLM 表征压缩在工业界的实用价值。

独立页面阅读 ↗

1. 问题与动机

随着 LLM 在推荐系统中的应用日益广泛，一个关键工程挑战浮现：LLM 生成的高维表征（如 Llama3-8B 的 4096 维）带来了巨大的存储和计算开销。以实际数据衡量，采用 LLM 表征相比 BERT 级别模型会导致 140 倍的存储增长和 20 倍的训练时间增加。

现有解决方案通常采用降维压缩（如 PCA）来缩减表征维度，但作者发现了一个反直觉现象——中间层表征优势（Mid-layer Representation Advantage, MRA）：LLM 中间层生成的表征在推荐任务上系统性地优于最终层输出。这意味着现有压缩方法在压缩已经退化的最终层表征，从根本上限制了压缩效果。

MRA 的发现动摇了"使用 LLM 最后一层 embedding"这一推荐系统工程中的默认实践，揭示了 LLM 内部在微调过程中会自发形成功能模块化——前中层负责通用表征学习，最终层被任务损失驯化为特定任务的适配器。

2. 方法详解

MARC（Modular Representation Compression）将 LLM 内部隐式的模块化重构为显式、可控的三模块设计：

模块 1：表征模块（Representation Module）

  • LLM 骨架生成原始表征 r_u, r_i ∈ ℝ^(d_o)（如 d_o=4096）
  • 关键设计决策：不对 LLM 输出施加直接的任务损失。任务监督信号仅通过外部模块的反向传播间接流入 LLM，防止最终层坍塌为任务特定预测器
  • 使用 LoRA 进行高效微调，冻结大部分 LLM 参数

模块 2：压缩模块（Compression Module）

  • 专用压缩网络 g(·)：c_i = g(r_i), c_u = g(r_u)
  • 将 d_o 维压缩到 d_c 维（如 4096→128，实现 32 倍压缩）
  • 核心约束——HSIC（Hilbert-Schmidt Independence Criterion）：

- L_HSIC = HSIC(X,Y) = 1/(n-1)² Tr(K_X J K_Y J)
- K_X, K_Y 是基于高斯核 k(x_i,x_j) = exp(-‖x_i-x_j‖²/2σ²) 的核矩阵
- J = I_n - 1/n·I_n·I_n^T 为中心化矩阵

  • HSIC 的优势在于能处理不同维度间的信息保持度度量，避免简单投影导致的信息扭曲
  • 压缩网络架构：MLP [256, 128]

模块 3：任务适配模块（Task Adaptation Module）

  • 输入：压缩后的表征 + 显式交互特征
  • 预测公式：ŷ = f(c_i, c_u, |c_i − c_u|, c_i ⊙ c_u)
  • 包含元素级差值和乘积的显式交互 + MLP 隐式交互
  • 交叉熵损失：L_match = −Σ[y·log(ŷ) + (1−y)·log(1−ŷ)]
  • 关键作用：吸收任务特定的优化压力，保护 LLM 骨架不被迫特化

总损失函数：L = L_match + α·L_HSIC（α=0.01）

训练细节：在完整训练集中随机采样 200,000 条数据进行训练；下游集成使用 MoE（2-5 个专家/任务）。

3. 核心技术贡献

贡献 1：首次发现并系统验证 MRA 现象。 通过跨模型（Qwen2-1.5B、Phi-2、Qwen2.5-3B、Qwen2-7B、Llama3-8B）和跨数据集（MovieLens-1M、MovieLens-25M、Yelp）的实验，证明中间层表征优势具有普遍性，而非个别模型的特例。该发现改变了"总是使用最后一层"的工程默认实践。

贡献 2：基于功能模块化理论的解释框架。 将 MRA 归因于 LLM 在微调过程中自发形成的功能分工：前中层形成通用表征学习模块，最终层演化为任务适配模块。这一理论框架不仅解释了 MRA，还指导了 MARC 的架构设计。

贡献 3：HSIC 约束的信息保持压缩。 与传统降维方法（PCA、MRL）不同，HSIC 在不同维度空间间度量信息依赖性，避免了强制线性映射导致的信息扭曲。消融实验显示 HSIC 是 MARC 中最关键的组件。

贡献 4：工业级搜索广告场景的在线验证。 2.82% 的 eCPM 提升在竞争激烈的搜索广告场景中属于显著收益，且推理延迟与现有系统相当。

重排序任务：MARC-C 在 MAP@5 和 NDCG@5 上均显著优于 MRL（p<0.05），MAP@5 从 0.7395 提升至 0.7445。

  • HSIC 约束影响最大——移除后性能大幅下降
  • 显式交互特征对压缩表征尤为重要（对原始高维表征影响有限）
  • 模块化结构本身即可缓解 MRA，不依赖特定损失函数

维度敏感性：在 16-512 维范围测试中，128 维为最佳点。256 维以上性能反而下降，表明存在信息饱和效应。

在线 A/B 测试：在大规模商业搜索广告场景（千万级用户和广告）中，7 天 10% 用户分流实验取得 2.82% eCPM 提升，推理延迟与现有系统持平。

5. 局限与未来方向

作者隐含承认的局限：（1）MRA 现象目前仅在推荐微调场景中验证，是否推广到其他领域未知；（2）HSIC 的计算复杂度为 O(n²)（n 为 batch size），虽然训练数据采样至 200K 控制了成本，但在更大规模数据上可能成为瓶颈；（3）最优层选择策略（哪一个中间层最优）未被深入探讨——论文展示了层级性能曲线但未提出自适应选择机制。

未涉及但值得关注的方向：（4）LoRA rank 与 HSIC 效果的交互关系；（5）压缩模型在增量更新（新用户/新物品到达）场景下的表现；（6）α 超参数的自适应选择（当前固定为 0.01）。

6. 工业实践意义

对搜索广告系统的直接价值：MARC 解决了 LLM 表征在在线推理中的核心瓶颈——存储和延迟。32 倍压缩（4096→128）意味着 embedding cache 的内存需求降低一个数量级，使 LLM 增强的推荐系统在延迟敏感的在线服务中变得可行。

工程落地建议：

  • 立即可行：对现有 LLM+推荐 pipeline 进行层级表征质量评估，确认是否存在 MRA 现象——若存在，切换到中间层表征可获得"免费"的性能提升
  • 中期规划：部署 MARC 的三模块架构，重点是 HSIC 约束的实现（核矩阵计算可用 GPU 高效并行化）
  • 注意事项：128 维可能并非所有场景的最优维度，需根据具体业务数据量和特征空间大小进行调优
