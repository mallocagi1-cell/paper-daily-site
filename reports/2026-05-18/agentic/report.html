Summary: 针对纯关键词检索可靠但召回受限、而前沿 LLM 直接生成检索结果昂贵且幻觉率高（实测幻觉率 37.79%）的矛盾，提出 PaSaMaster：把文献检索拆成「意图分析 → 检索 → 排序」的可迭代闭环，并坚持用排序而非生成来产出结果以杜绝来源幻觉，同时把规划与检索分离以控成本。在覆盖 38 个学科的 PaSaMaster Benchmark 上，F1 较传统关键词检索提升 15.6 倍，较 GPT-5.2 提升 30% 而仅用其 1% 算力，且来源幻觉为零。

PaSaMaster: Towards Self-Evolving Agentic Literature Retrieval — 深度解读

1. 问题与动机

论文针对文献检索中一个被作者明确表述的「双重矛盾」: 既要保证来源真实性，又要深度理解复杂的学术检索意图。两类现有方案各占一极却都不及格:

  • 关键词检索（Google Scholar 类）: 来源 100% 真实（幻觉率 0），但完全无法理解复杂多约束意图——在论文构建的 PaSaMaster-Bench 上 F1@20 仅 1.39%，NDCG@20 仅 2.07%。
  • 前沿生成式 LLM 直接生成文献: 能理解复杂意图，却产生严重的来源幻觉。作者实测各模型「编造/不可核实论文」的比例: MiniMax-M2.7 37.79%、Kimi-K2.5 35.67%、Gemini-3.1 32.41%、GLM-5 29.07%、DeepSeek-v3.2 20.57%，即便最好的 GPT-5.2 也有 11.80%，且单 query 成本高达 \$6.06。Table 3 进一步拆解出幻觉发生在 title/author/date/link 各字段。
  • 固定流水线 agent（Google Scholar Labs 类）: 不能用「已排序的证据」反过来迭代修正意图理解，导致对复杂研究需求的理解被一次性查询锁死，F1@20 仅 18.87%。

动机由此清晰: 检索结果必须来自可核实语料（杜绝幻觉），同时意图理解必须能基于检索到的证据迭代自我进化，而不是一次性查询匹配。该问题当下重要，因为 LLM 检索 agent 正被大量用于科研/知识工作，而幻觉来源与高成本是其无法进入严肃工作流的两大硬伤。

2. 方法详解

PaSaMaster 是一个「Navigator + Librarian Swarm + 三层 agent 原生语料」的三组件系统，核心创新是把检索重构为可自进化的闭环。

(a) Navigator Agent (πNav): 负责理解复杂意图，产出两样东西——检索策略 S（搜什么）与 query 专属的验证清单 C = [c₁,...,cₘ]（如何判定相关）。这把「模糊意图」显式分解为可逐条核验的客观标准。

(b) Librarian Swarm ({πLib}): N 个并行 librarian 执行检索、证据核验、意图-论文打分、按清单重排。

(c) 三层科学语料 𝒟 = {𝒟^meta, 𝒟^abs, 𝒟^chunk}: 覆盖 1.6 亿篇论文，分别是结构化元数据、摘要级语义表示、全文 passage 级证据块。粗粒度先过滤、细粒度再定位证据。

核心检索流程（Eq.1–4）: ⟨S,C⟩=Plan(q,πNav) → 𝒫init=Retrieve(S) → 𝒫scored=Verify(𝒫init,C) → 𝒫=Rerank(𝒫scored)。

自进化迭代（关键公式）: 第 t 轮后，⟨S^(t+1), C^(t+1)⟩ = Reflect(q, S^(t), C^(t), 𝒫^(t)_scored)。Navigator 检视已排序结果，识别覆盖缺口、模糊约束、欠探索方向，再生成下一轮策略与清单——这是把「固定查询解释」变成「渐进改进」的闭环。

反幻觉的证据绑定: 对候选论文 p 与清单项 cⱼ，从该论文的 chunk 库取 top-k 支撑证据 𝓔_p(cⱼ)=argtop-k cos(φ(cⱼ),φ(e))，φ 为共享文本编码器。即每条相关性判断都必须绑定到论文原文证据，而非模型臆断。打分由训练好的 Scorer 输出 sⱼ∈{1..5}，criterion 级取均值 s̄(p)=Σsⱼ/m，最终相关性 𝒮(p)=(s̄(p)+ρ)/6，ρ 为校准置信度。

规划-检索分离（控成本关键）: 工具集 𝒯=𝒯^ret∪𝒯^read。检索工具有三种——语义直检、引文网络扩展、Web→库映射核验——构造广候选池 𝒞init=∪Retrieve_o(S,𝒟)；阅读工具只做廉价元数据/摘要读取，避免昂贵全文处理。前沿 LLM 只承担低频高价值的意图分析，大规模检索/打分交给经知识蒸馏训练的轻量 Scorer（教师模型对 query-paper 对标注 checklist 级分数与证据 rationale，蒸馏到部署侧）。

3. 核心技术贡献

  1. 自进化检索（self-evolving retrieval）: 把一次性 query-doc 匹配改成「用已排序证据反推意图缺口→修正策略与清单」的迭代过程。它有效是因为复杂学术意图往往无法一次表达完整，只有看到初轮结果才知道哪些约束被误解；闭环 Reflect 让系统逐轮逼近真实意图，相对固定流水线 Google Scholar Labs 的 F1 从 18.87→21.69（+14.9%）。
  1. 排序而非生成（ranking not generation）: 所有论文都从可核实语料检索得到，相关性绑定到原文证据。机制上彻底切断了参数化幻觉路径——实验中所有检索类系统幻觉率均为 0%，而生成式 LLM 为 11.80–37.79%。这对「来源可信」是结构性保证而非概率性缓解。
  1. 规划-检索分离: 前沿 LLM 只做高价值意图理解，海量检索/打分下沉到轻量模型+专用语料。它有效是因为成本主要花在高频检索而非低频规划，分离后 F1 比 GPT-5.2 高 30.0% 而成本仅其 1%（\$0.05 vs \$6.06）。

5. 局限与未来方向

作者未设独立 limitations 章节（这是论文的一个缺陷）。从方法与实验可推出的隐含局限: (1) 强依赖定制化 1.6 亿篇科学语料与三层索引基建，迁移到无此语料的垂直域（如 UGC 社区）需重建；(2) 评测仅 244 query，且 ground-truth 与 checklist 由专家构造，存在标注者偏置；(3) 轻量 Scorer 依赖更强教师模型蒸馏，教师能力上限会传导为系统上限；(4) Recall@20 仅 31.84% 表明复杂意图的召回天花板仍低，迭代轮数与召回的权衡未充分讨论。

6. 工业实践意义

对社区搜索（UGC 短文本、强调 nDCG/CTR 与结果可信）从业者，有三条可直接借鉴:

  1. 「检索结果只能来自被排序的真实内容，绝不由 LLM 生成」应作为硬约束: 该论文用结构性手段（证据绑定 + 排序）把幻觉压到 0%，对 UGC 搜索做 LLM 改造时，应坚持「LLM 只做意图理解与重排，候选只能来自真实倒排/向量索引」，避免 RAG/agent 改写阶段引入伪结果。
  1. 规划-检索分离是 agentic 搜索控成本的可落地范式: 把昂贵前沿模型限制在低频意图分析、把高频召回/打分蒸馏成轻量模型，实测 1% 成本达到更优效果。社区搜索 QPS 极高，这种分层（贵模型做 query 理解、廉价模型做大规模打分）直接决定能否上线。
  1. 把「意图→可核验 checklist」显式化: 将模糊 query 分解为逐条客观标准并绑定证据打分 s̄(p)=Σsⱼ/m，比端到端黑盒相关性更可解释、可调试、可做 badcase 归因——对需要持续优化 nDCG 的搜索团队是高价值工程设计。落地注意: checklist 生成与多轮 Reflect 会增加延迟，需对延迟敏感的在线检索做轮数预算与缓存。无在线 A/B（仅离线 benchmark），上线前需自建在线实验验证 CTR/nDCG 收益。

Summary: 针对 RL 训练多轮 agent 时轨迹级奖励监督过于稀疏、而直接叠加 On-Policy Self-Distillation (OPSD) 会因多轮不稳定而崩溃的问题，提出 SDAR：把 OPSD 当作一个「门控辅助目标」，RL (GRPO) 仍是主干优化；将脱离梯度的 token 级信号映射为 sigmoid 门，对 teacher 认可的正差距 token 加强蒸馏、对 teacher 否定项软性衰减。在 Qwen2.5/Qwen3 上、ALFWorld/WebShop/Search-QA 三个任务，相比 GRPO 分别提升 +9.4%、+10.2%（WebShop-Acc）、+7.0%（Search-QA），且避免了朴素 GRPO+OPSD 的训练不稳定。

4. EvolveMem: Self-Evolving Memory Architecture via AutoResearch for LLM Agents

Summary: 现有 agent 记忆系统只让存储内容演化，而打分函数、融合策略、答案生成策略在部署后被冻结。EvolveMem 主张存储知识与检索机制必须协同演化：把完整检索配置暴露成一个结构化动作空间，由 LLM 诊断模块读取每题失败日志、定位根因、提出针对性配置调整；一个带「回退-止损」与「停滞-探索」保护的 meta-analyzer 应用这些调整，形成对自身架构做迭代研究的 AutoResearch 闭环。从极简 baseline 起步可自主收敛，并发现原动作空间外的全新配置维度。LoCoMo 相对最强 baseline +25.7%，MemBench +18.9%。

9. PREPING: Building Agent Memory without Tasks

Summary: 无论 agent 记忆来自离线示范还是线上交互，初到新环境时都面临无任务经验的冷启动缺口。本文研究「任务前记忆构造」：能否在观察到任何目标任务前，仅靠自生成的合成练习构建程序性记忆。直接合成不够——不控制练什么/存什么会让合成任务冗余、不可行、无信息量。提出 Preping：核心是 proposer memory（塑造未来练习的结构化控制状态），Proposer 据此生成合成任务、Solver 执行、Validator 判定哪些轨迹可入库并反馈以指导后续提议。在 AppWorld/BFCL v3/MCP-Universe 上大幅超越无记忆基线、与离线/线上经验构建的强 playbook 方法相当，且部署成本在 AppWorld 低 2.99 倍、BFCL v3 低 2.23 倍。
