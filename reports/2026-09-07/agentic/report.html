Making Every Tool Call Count: Necessary Tool-Evidence Path Rewards for Agentic Vision-Language Models

为减少视觉搜索 Agent 的无效调用，论文以必要工具证据路径标注每个问题，分别奖励调用前的证据目标对齐、调用后的信息获取，并惩罚重复目标。NTEP-8B 在统一三工具框架下的七个评测切分平均准确率为 70.34，比复现的 SenseNova-MARS 高 2.03 点；搜索类任务平均调用次数由 2.54 降至 1.89。

When Users Don't Ask: Benchmarking Context-Driven Memory Retrieval in Conversational Agents

NTU

LoCoMo-Conv 将记忆问答改写成对话、隐式、反事实和组合四类请求，分别评估五种记忆系统的检索与回答。AnchorMem 的隐式查询 recall@10 为 0.368，多角度改写加 RRF 后升至 0.524；组合查询从 0.279 升至 0.432。摘要型记忆并未稳定受益，说明显式问答成绩难以代表真实对话。

INSIGHT社区用户常通过上下文表达需求，可将“帮我找之前提到的做法”等隐式请求加入搜索 Agent 的离线集，同时检查多步证据召回和回答质量。原始帖子记忆适合尝试多角度改写，压缩后的记忆需要单独验证；不要把召回改善直接记作回答质量或 CTR 收益，还要检查反事实请求是否得到纠正。

Chang, Wen-Yu, Chen, Yun-Nung

DRACO: Fine-Grained Credit Assignment with Dynamic Rubrics for Long-Horizon Agent Training

CMUIBM

DRACO 面向缺少成功判定器的长程 Agent，用动态生成的细则评价完整轨迹，再将得分分配给承担对应细则的步骤，形成 GRPO 的分步优势。在 Qwen3.6-27B 上，AppWorld 常规测试任务成功率从 69.4% 升至 85.3%，比稀疏真实奖励训练高 5.3 点；三次均成功指标从 47.6% 升至 72.8%。

INSIGHT社区复杂搜索往往难以用一个答案判定器覆盖质量，可围绕意图澄清、证据补齐、引用核验制定可检查的细则，再把奖励分配到具体检索决策。实施前要审计自动细则和裁判偏差，并用独立的人工相关性标注验证，避免把高裁判分误认作 nDCG、CTR 或事实正确率的改善。

Gandhi, Shubham, Goyal, Saurabh, Kate, Kiran, Rizk, Yara

Agentic Search. More accurate and efficient results from your AI systems.

Mistral

Mistral 在已有索引上开放 search、open、navigate、read、grep 五种工具，让模型按证据缺口迭代查找和核实。官方评测中，FinanceBench 准确率由 26.7% 升至 86%，OfficeQA Pro 从 6.3% 升至 51.9%；加入定点导航后，FinanceBench 的 p90 延迟由 255 秒降至 154 秒。

INSIGHT社区搜索可为长帖、楼层和引用提供稳定定位，把反复宽泛搜索改成“召回帖子—定位段落—核查证据”的循环。原文结果来自长文档和表格问答，不能直接外推至短文本排序；适合先在跨帖比较与复杂问答小流量试验，并同时记录答案依据、调用次数、nDCG 和尾延迟。

Building a Memory-Driven Agent with NVIDIA NemoClaw

NVIDIA

NVIDIA 的记忆型 Agent 用 Markdown 维护人物、项目和优先级，用 SQLite 保存判断、修正与审计记录，任务执行时只读取有限相关上下文。在 186 道题上，整体准确率由 Agentic RAG 的 82.8% 升至 90.9%，31 道难题由 67.7% 升至 87.1%；单跳查询则由 86.7% 降至 83.3%。

INSIGHT对社区多轮搜索，可把原帖证据、推导记忆与当前检索计划分开保存，并让用户纠正后续持续生效。结构化记忆有助于跨时间汇总，但单跳查询退步提示应按问题类型路由；原文涉及变化事实的子集仅 5 题，宜扩充本地评测，分别测实体消歧、引用覆盖和过期信息污染。

Fresh Memory, Stale Plans: Dependency-Scoped Validation for Distributed LLM-Agent Memory

PlanFence 针对“已收到新事实却继续执行旧计划”的失效，要求计划记录所依赖的具体版本，并在行动前仅校验相关依赖。30 个受控实时流程中，单纯检查最新状态的方法全部沿用旧计划，PlanFence 无无效行动；高更新回放中它在 330 次行动上同样为零，协调等待为每次 230.8 毫秒。

INSIGHT社区搜索 Agent 若跨轮缓存证据和查询计划，应将计划绑定到帖子版本、删除状态与用户约束，在输出或下一次工具调用前重验受影响依赖。该方法提供可追溯的失效条件，但论文刻意构造了计划后修订，不能把零失效率当成通用质量保证；低更新率场景也需比较主动同步成本。

Chen, Evan, Wang, Shiqiang, Brinton, Christopher G.

KC-Bench: A Dynamic Interactive Benchmark for Evaluating Knowledge Conflicts in LLM Agents

Shanghai AI LabHKUXiamen University MalaysiaBUPT

KC-Bench 将事实错误、输入身份不一致和多源时序冲突注入可交互环境，形成 238 个任务，并结合状态断言与人工核验评估九种模型。GLM-5.2 的人工核验成功率在三个域分别为 53.52%、61.96% 和 65.75%，没有模型在全部场景中稳定解决冲突，展示了工具调用前核对证据的缺口。

INSIGHT社区帖子会同时包含旧结论、更正和相互矛盾的描述，可借鉴该基准把“识别冲突后是否继续错误调用”纳入 Agent 搜索评测。构造题目时保留可达证据和唯一冲突点，并分别统计检测、澄清与最终回答；论文测的是固定提示和模拟环境下的模型行为，不代表完整产品的可靠性。

Speculative Macro Commit for Faster Tool-Using Agents

SMC 让小模型在隔离环境快照上预执行动作链，用轨迹挖掘出的宏匹配候选，主模型确认首步后复用后续结果。在电信工具任务中，平均延迟由 27.60 秒降至 22.47 秒，准确率保持 99.52%；AppWorld 延迟下降 44.93%，任务完成数则从 70/168 降至 68/168。

INSIGHT社区搜索可以先在只读、可重放的检索链上试验推测执行，关注用户请求中重复出现的查帖与取证模式。必须验证候选链与当前状态一致，不能仅凭模板命中直接复用；论文推测配置用了三张 GPU、串行基线为一张，采购或上线前应同时计算总算力成本和成功率。

Terminal-Universe: Turning Agent Trajectories into Scalable Terminal Environments

AlibabaTsinghua

Terminal-Universe 从 Agent 历史文件操作反推初始工作区，再补全依赖，重建原任务并生成跨工作区、多轮新任务。框架得到 3.73 万个可用环境；以 3.2 万条筛选轨迹微调 Qwen3.5-27B 后，Terminal-Bench 2.1 从 46.2% 升至 58.1%，多轮 MT@4 从 6.3% 升至 20.1%。

INSIGHT对社区搜索可迁移的是把静态工具日志恢复成可重放环境，再生成追问、证据变更与跨帖任务，而非直接套用终端任务分数。优先固定索引快照、工具版本和检验规则，对比原始轨迹模仿与重求解训练；工作区重建和教师轨迹生成有成本，短文本召回本身仍需独立评测。

Research acceleration: The view inside OpenAI

OpenAI

OpenAI 报告其研究团队使用编程 Agent 的内部观察，并按决策、设计、构建、运行、分析和沟通六类活动分析变化。截至八月中旬，每个人类工作日对应 3.1 个 Agent 工作日；按 API 价格折算，中位研究人员每日使用超过 600 美元推理，90 分位超过 7000 美元。实验量增加与采用率相关，但算力也在增长。

INSIGHT社区搜索团队可据此将 Agent 提效评估拆成数据准备、实验执行和结果分析，分别衡量完成质量、等待时间及推理成本，再观察有效搜索实验的产出。原文是团队内部的描述性数据，Token 用量、代码量和实验数不能证明业务价值；是否改善 nDCG 或 CTR，仍应由受控实验决定。
