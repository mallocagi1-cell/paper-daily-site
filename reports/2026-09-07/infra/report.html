Fast Embeddings on GPUs

Perplexity 将嵌入服务拆为 Rust 网关 Ivy、调度层 Tulip 和推理引擎 ROSE，复用 LLM 内核并用整模型 CUDA Graph 与 LazyTensor 重叠主机和设备工作。原文观察到十亿参数以下模型约 512 token 即可饱和 GPU，并在 BF16、vLLM 0.22.0 对照中验证余弦相似度偏差不超过 0.1%。

AInfer-PD: Communication-Safe In-Place Prefill-Decode Multiplexing for Distributed MoE Rollouts

AAnt Group

AInfer-PD 面向分布式 MoE 强化学习 rollout，把预填充与解码留在同一设备并共享权重和 KV。系统协调跨 rank 集体通信顺序，隔离 DeepEP 两条路径的协议状态；相对 SGLang，固定负载完成时间在单节点降低 24.8%–32.9%，双节点降低 18.3%–31.8%。

INSIGHT社区搜索若使用强化学习训练查询处理模型，多轮生成期间会反复出现预填充与解码混跑，通信顺序和协议状态需要一并设计。原地复用可避免另建资源池及 KV 迁移，但论文主要验证一至两节点 H20-3E；更大集群应先验证通信正确性、尾延迟和吞吐，不能直接外推加速幅度。

FlowTT: Exploiting Computation Flow Reuse in Irregular Tensor-Train Embedding

Hanyang University

FlowTT 针对张量列车压缩嵌入查表中的重复计算与片外搬运，按索引共享前缀组织计算流，并结合融合内核、片上中间结果保留、任务窃取和 L2 复用。在 Meta 的三组合成推荐基准上，批量 32768 时相对 EcoRec 的推理与训练延迟最多分别降低 42.2% 和 49.2%。

INSIGHT对社区搜索排序中的大规模稀疏特征表，压缩率之外还应衡量解压查表的执行成本。可借鉴按共享前缀成组和动态调度的设计，评估热点特征分布下的复用收益；这些结果来自合成推荐数据和较大批量，迁移前需用真实 UGC 请求分布验证小批量延迟、排序精度与显存开销。

MeanField Surrogate Modeling for Scalable Runtime Scheduling of Concurrent Heterogeneous AI Inference on Shared GPUs

Seoul National University

MeanField 用单模型配置和聚合 GPU 状态预测混部性能，避免枚举所有模型组合，实验预测 R² 约 0.96。结合遗传算法后，在五模型、78732 种可行配置中，调度结果距穷举不超过 0.10%，八类动态负载无 SLA 违约，决策耗时中位数为 26 毫秒。

INSIGHT社区搜索的嵌入、重排和内容理解服务共享 GPU 时，可用聚合资源状态降低混部性能建模成本。适合先建立离线画像并在资源控制层试验，26 毫秒调度耗时未必适合逐请求调用；论文测试平台为单张 RTX 3090，换到生产 GPU、模型组合或突发流量后需要重新校准。

RT-HiSS: Ray Tracing Accelerated High Dimensional Vector Similarity Searches

Northern Arizona University

RT-HiSS 将高维固定半径精确相似性搜索拆为 RT 核候选过滤和 CUDA 核精确校验，并通过两遍搜索估计结果规模以安排显存内批处理。在六个真实数据集上，相对有竞争力的 GPU 算法最高加速 8.37 倍；实验使用具有 16 GiB 显存的 Quadro RTX 5000。

INSIGHT社区 UGC 的近重复内容检测或阈值邻域构建可以探索这类硬件协同过滤。论文研究的是固定半径精确检索，迁移到语义 Top-K 召回需要另外验证算法和数据分布；部署也要求具备 RT 核，不能默认沿用现有训练卡。应同时测量建索引、候选校验、结果传输及真实向量维度下的性能。

该系统根据工作流依赖预测激活时机、显存和模型加载成本，再联合选择节点融合、模型生命周期及异构 GPU 放置方案。在三种工作流场景中，相比已有调度器，突发到达负载的总完成时间和整体 p95 延迟最多降低 36.8% 与 25.9%，每次会话最多节省 24.63 GPU 秒。

INSIGHT社区搜索若串联查询理解、检索后推理和答案检查，可把整条计算图及模型驻留需求提供给资源调度器，而不只处理独立请求。实践中先记录各阶段耗时与峰值显存，再试验提前加载和节点融合；收益依赖预测准确性及异构设备状态，需要在真实请求突发和模型切换条件下复测。

Rice University

Einsummable 把 AI 算子表示为张量关系上的连接与聚合，自动搜索跨 GPU 分解方案，并生成拓扑感知的通信程序。正文实验中，八张 A100 上 LLaMA Transformer 块的几何平均运行时间为 8.97 毫秒，手工 PyTorch 与 vLLM 基线分别为 13.65 和 14.87 毫秒。

INSIGHT社区搜索的大模型训练和推理可借鉴以通信成本统一选择算子切分的思路，减少逐层手写并行策略的负担。该系统仍是原型，结果针对 Transformer 块，不能等同于完整搜索服务加速；摘要页基线写作 13.80 和 15.90 毫秒，与正文不一致，本报告采用正文实验数值。

mzCache: On-Device LLM Memory Management under Multitasking

Seoul National UniversityUC Berkeley

mzCache 针对手机多任务引起的 LLM 权重和 KV 缓存驱逐，把内存拆成细粒度共享缓冲区，让 GPU 推理与 CPU 恢复并行，并采用混合交换和逆序驱逐策略。系统基于 llama.cpp 实现并部署为 Android 应用，相对存储支撑的部分卸载方案，首 token 等待时间改善 2.1–5.5 倍。

INSIGHT若社区产品尝试端侧查询理解或隐私搜索，用户切换应用后的恢复时间可能比连续生成速度更影响体验。可借鉴面向恢复顺序管理权重及 KV 的设计，测试内存压力下的首 token 延迟和能耗；目前证据来自手机统一内存环境，迁移到云端独立显存服务需要重新设计共享缓冲与恢复机制。

CREDIT: Cost-guided Reduction-reuse with Efficient DSMEM Inter-CTA Tiling

UUniversity of Wisconsin–Madison

CREDIT 为 NVIDIA 分布式共享内存建立收益成本模型，识别适合跨线程块归约复用的工作负载，并据此改写内核。实验对是否值得采用 DSMEM 的预测准确率达 91.7%；六种负载上，相对所选基线的几何平均加速在 RTX 5090 和 H100 上分别为 1.466 与 1.318 倍。

INSIGHT社区搜索若已把嵌入或重排瓶颈定位到归约类 GPU 算子，可先按共享复用量、远程访问和同步成本筛选优化机会。开源实现提供了清晰起点，但不应把内核平均加速当成整条检索链路收益；建议保留原内核，在实际形状、并发和目标 GPU 上逐项测量后再切换。

NVIDIA

NVIDIA 给出 Jetson 上结合 NVFP4 量化与推测解码的部署方案，对 Nemotron 3.5 Lightning 选用 DSpark，对 Qwen3.8-27B 选用 DFlash2。相对 BF16，解码吞吐最高提高 6.28 倍；四类 SpeedBench 负载下，两者分别达到 123.01–138.02 和 27.69–34.44 token/s。

INSIGHT社区搜索若探索边缘端答案生成，可先复用公开量化模型、草稿模型及 vLLM 配置，再用真实 UGC 问题测量质量和速度。不同架构的最佳草稿方案并不一致，文章也要求检查草稿接受率；6.28 倍是特定平台配置的最高值，不能直接作为服务器成本预算或搜索相关性提升预期。
