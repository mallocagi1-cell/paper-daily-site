提出面向 SLO 的长上下文 LLM 推理系统，通过 ILP 求解器动态管理 KV Cache 在 GPU/CPU 间的精细放置。

Attn-QAT: 4-Bit Attention With Quantization-Aware Training

首次系统研究 4-bit (FP4) 注意力机制的量化感知训练，解决新一代 FP4 GPU 的端到端低精度推理瓶颈。

INSIGHTFP4 注意力量化的两个关键原则：反向传播中使用低精度重计算匹配前向，以及修正 Flash Attention 梯度中的精度假设。无需显式 outlier 缓解即可恢复质量。

业务关联随着 RTX 5090 等新 GPU 支持 FP4 计算，搜索排序模型（如 cross-encoder reranker）可利用此技术实现端到端 FP4 推理，大幅降低 serving 成本。

证据在 RTX 5090 上实现 1.5x 推理加速；在 diffusion 和语言模型上均验证有效；提供了 Triton 融合算子实现训练和 FP4 推理。

Peiyuan Zhang, Matthew Noto, Wenxuan Tan, Chengquan Jiang, Will Lin, Wei Zhou, Hao Zhang

03 4.35

DeepSeek-V3.2: Pushing the Frontier of Open Large Language Models

DeepSeek 发布 V3.2 开源大模型，引入 DeepSeek Sparse Attention (DSA) 高效注意力机制和可扩展 RL 框架。

INSIGHTDSA 基于 MLA 架构的 MQA 模式，通过共享 latent vector 大幅降低注意力计算复杂度。三大核心创新：DSA 高效注意力、可扩展强化学习框架、大规模 Agent 任务合成管线。

业务关联作为当前最强开源模型之一，DeepSeek-V3.2 可直接用于搜索场景的 LLM 能力升级（query 理解、摘要生成等），其 DSA 注意力机制也为自研模型的效率优化提供参考。

证据标准版性能与 GPT-5 相当；高算力版 V3.2-Speciale 超过 GPT-5 并在推理能力上接近 Gemini-3.0-Pro；完全开源可商用。

FLYING SERVING: On-the-Fly Parallelism Switching for Large Language Model Serving

基于 vLLM 实现 LLM 推理服务的运行时并行策略动态切换（DP↔TP），无需重启引擎即可适应流量变化。

INSIGHT生产环境中 LLM 请求的负载和上下文长度分布随时变化，固定 DP/TP 配置无法同时满足高吞吐、低延迟和长上下文需求。FLYING SERVING 通过零拷贝权重管理和 KV Cache 适配器实现无缝切换。

业务关联社区搜索的 LLM 推理服务面临流量波动（高峰期需高吞吐 DP，低延迟请求需 TP），该技术可直接集成到现有 vLLM serving 系统中实现自适应资源利用。

证据高负载场景 4.79x 性能提升，低负载场景 3.47x 提升；在 3 个主流 LLM 上验证；支持延迟驱动和内存驱动的混合请求。已被 ICS 2026 录用。

Shouwei Gao, Junqi Yin, Feiyi Wang, Wenqian Dong

05 4.25

The Llama 4 Herd: Architecture, Training, Evaluation, and Deployment Notes

Meta 发布 Llama 4 系列，采用原生多模态 MoE 架构（Scout 16 专家、Maverick 128 专家），仅 17B 活跃参数。

INSIGHTMoE 架构使 Llama 4 在仅 17B 活跃参数下拥有远超同规模模型的能力（Maverick 从 288B 蒸馏而来）。Scout 支持业界领先的 1000 万 token 上下文窗口，Dense 和 MoE 层交替排列实现计算效率最大化。

业务关联Llama 4 的 MoE 架构为搜索/推荐团队提供了高性价比的开源大模型选择：17B 活跃参数意味着更低的推理成本，超长上下文能力适用于长文档理解和多轮搜索场景。

证据Scout 支持 1000 万 token 上下文窗口；Maverick 128 专家从 288B 参数基座蒸馏至 17B 活跃参数；原生支持文本、图像和短视频多模态输入。完全开源。

Learning to Draft: Adaptive Speculative Decoding with Reinforcement Learning

提出用强化学习训练自适应投机解码策略，直接优化每轮 draft-verify 循环的实际吞吐量而非代理指标。

INSIGHT现有投机解码方法依赖静态时间分配或优化接受长度等代理指标，而非真实吞吐。LTD 将问题建模为 RL 环境，通过协同自适应策略动态协调 draft 和 verify 阶段。

业务关联搜索系统中 LLM 在线推理（如生成式 query 改写、答案生成）对延迟极为敏感，LTD 的自适应投机解码可根据请求特征动态调整 draft 策略，直接降低 P50/P99 延迟。

证据在 5 个 LLM、4 个任务上实现 2.24x-4.32x 加速比；比当前 SOTA Eagle3 最高提升 36.4%。

Out of the Memory Barrier: A Highly Memory Efficient Training System for LLMs with Million-Token Contexts

提出 OOMB 训练系统，通过 chunk-recurrent 框架和按需激活重计算实现 O(1) 激活内存开销，单卡训练百万 token 上下文。

INSIGHT长上下文 LLM 训练的真正瓶颈不是计算时间而是 GPU 显存——激活值内存随序列长度线性增长。OOMB 通过分页内存管理和异步 CPU offloading 将激活值内存降至常量级。

业务关联搜索/推荐场景中长文档理解和长上下文模型训练需要大量 GPU 资源，OOMB 使单卡即可完成百万 token 训练，大幅降低训练基础设施成本。

证据Qwen2.5-7B 每额外 10K token 仅增加 10MB 显存；单张 H200 可训练 400 万 token 上下文（原本需要大型集群 context parallelism）；代码已开源。

Quantization-Aware Distillation for NVFP4 Inference Accuracy Recovery

NVIDIA 提出 QAD（量化感知蒸馏）方法，通过全精度教师蒸馏到 NVFP4 量化学生模型，恢复接近 BF16 的推理精度。

INSIGHT相比传统 QAT 在多阶段后训练流程中的工程复杂性和训练不稳定性，QAD 通过 KL 散度损失的蒸馏方式更稳定、更适配现代 LLM 多阶段训练管线（SFT→RL→Model Merging）。

业务关联搜索排序模型部署在 NVIDIA GPU 上可利用 NVFP4 格式实现 4x 内存节省和推理加速，QAD 提供了恢复量化精度损失的实用方案，适合现有 SFT+RLHF 训练管线。

证据在 AceReason Nemotron、Nemotron 3 Nano 等多个模型上验证，一致恢复至接近 BF16 精度；对不完美训练数据具有鲁棒性。

Meng Xin, Sweta Priyadarshi, Jingyu Xin, Bilal Kartal, Aditya Vavre, et al.

MoE Parallel Folding: Heterogeneous Parallelism Mappings for Efficient Large-Scale MoE Model Training with Megatron Core

NVIDIA 提出 MoE Parallel Folding，在 Megatron-Core 中实现五维混合并行（TP/EP/CP/DP/PP）解耦注意力层和 MoE 层的并行策略。

INSIGHTMoE 模型中注意力层和专家层的最优并行策略不同，传统统一并行映射导致效率损失。Parallel Folding 允许每层独立选择最优并行维度组合，突破千卡训练的扩展性瓶颈。

业务关联训练大规模搜索排序 MoE 模型需要高效的分布式训练框架，该方案已集成至 Megatron-Core 开源，可直接用于团队的大规模模型训练基础设施。

证据Mixtral 8x22B 达到 49.3% MFU，Qwen2-57B-A14B 达到 39.0% MFU（H100）；高效扩展至 1024 GPU，支持 128K 序列长度训练。

Dennis Liu, Zijie Yan, Xin Yao, Tong Liu, Vijay Korthikanti, Evan Wu, Shiqing Fan, et al.

Google, ByteDance and Red Hat improve AI on Kubernetes: Optimizing LLM Inference on K8s

INSIGHT大规模 LLM serving 从专有基础设施逐步向 K8s 云原生架构迁移，关键挑战在于 GPU 资源的精细调度、请求级负载均衡和推理服务的弹性扩缩。三家公司联合解决了这些生产级问题。

业务关联搜索/推荐系统的 LLM serving 通常部署在 K8s 集群上，Google 和字节跳动在此方面的联合工程实践可直接参考：自动扩缩策略、高效请求路由和 GPU 资源管理。

证据Google Cloud、字节跳动和 Red Hat 三方联合发布；涵盖 LLM 推理的自动扩缩、负载均衡和模型服务器性能优化；基于大规模生产环境验证。
