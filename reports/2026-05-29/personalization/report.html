Context Features Are Cheap: Rank-Aware Decomposition for Efficient Feature Interaction 深度解读

1. 问题与动机

现代工业推荐排序对同一次请求里的 N 个候选，复用同一份用户/上下文特征逐一打分。主流实现（DLRM、DeepFM、DCNv2）在前向早期就把上下文特征广播开来，使 context-only 运算每请求重复 N 次。作者给出量化浪费：对 K 个上下文字段、M 个目标字段、嵌入维 D，仅 context-context 的 FM 交互每请求就白白消耗 (N−1)·C(K,2)·D FLOPs，且随上下文特征数 K 平方增长。随着系统引入更长用户历史、会话、页面特征，K 越来越大，这笔浪费随之扩大。对每天服务数十亿请求的生产系统（Taboola 的 CPU 推理基建），这直接换算成机器规模与成本。

2. 方法详解

核心是一条代数原理：任何作用在"按 rank 划分输入"上的线性/双线性运算，都存在精确块分解，可把 context-only 计算从 per-candidate（rank 3，[B,N,D]）下放到 per-request（rank 2，[B,D]），且与原模型输出逐位等价。

  • 线性层（FC、attention 投影）：Wx = W_c·x_c + W_t·x_t，上下文项 W_c·x_c 算一次再广播，目标项按候选算。RankSplitDense 把首个 FC 层这样拆，节省 ΔFC=(N−1)·|x_c|·U；当上游 FM_ctx 输出（大小 C(K,2)）喂进来时，节省进一步变成 (N−1)·C(K,2)·U，对 K 平方、跨阶段叠加。
  • 双线性（FM 内积、attention 打分）：x^T·W·y 拆成 cc/ct/tc/tt 四块，只有 context-context 块算一次；FM 拆成 FM_ctx（一次）与 FM_tgt（按候选）。
  • DCNv2 cross 层：x_{l+1}=x_0⊙(W_l·x_l+b_l)+x_l，第 0 层的 W_cc·x_0^c、W_tc·x_0^c 是 rank 2 可预计算，节省比例 d_c²/(d_c+d_t)²。
  • self-attention：Q/K/V 投影按线性拆；注意力矩阵 Q_c·K_c^T 块是 rank 2，softmax 的混合用 block-wise log-sum-exp 把预计算的上下文部分与按候选的目标部分以 O(1) 合并。

为何只在首层成立：cross network 与 attention 每层输出都会"混 rank"（如 cross 的上下文输出行含 W_ct·x_l^t，把目标耦合进本该是上下文的维度），经非线性后上下文与目标在每个神经元混合，后续层在纯目标依赖张量 [N,U] 上运算，秩分离被破坏。

3. 核心技术贡献

(1) 把"上下文特征冗余计算"形式化为 rank-partitioned 输入上的精确块分解，统一覆盖 FM/DCNv2/self-attention/FC 四类主流交互算子，且数学上恒等等价——不改预测、不需重训。
(2) 闭式分析证明节省随上下文特征数平方增长，并用受控实验验证。
(3) 提出 rDCN 架构变体：把 context×target 交互只加载到 target 流，context 流仅靠 context×context 演化（结构性删去 W_ct 块），从而跨深度保持秩纪律。target 流 T_{l+1}=T_0⊙(W_l^ct·c_l + W_l^t·T_l + b_l^t)+T_l 把一次性的上下文交叉项广播给按候选的目标项；rDCN 消去 baseline 中的 N·D_c² 项，使上下文驱动的扩展从平方降为线性（N·D_c·D_t），每层省 D_c·D_t 参数。

4. 实验结果分析

生产部署（DLRM 排序器，Table 4）：仅 FM rank-aware 即 +25% RPS/pod、p50 −17%、p99 −26%；FM+FC 组合达 +87.5% RPS/pod、p50 −30%、p99 −33%，峰值 pod 数减少 47%，且预测逐位不变。FM 与 FC 收益相互叠加，说明 FC 拆解并非可有可无。
合成 DLRM 吞吐刻画：固定 M=4 变 K，vanilla RPS 从 K=8 的 1.00 退化到 K=24 的 0.34，rank-aware 从 1.13 退到 0.69，优势从 +13%(K=8) 扩大到 +105%(K=24)，印证平方级 scaling；固定 K=8 变 M，两条曲线同步退化，rank-aware 优势稳定在 +7~+21%，说明节省以上下文为中心、对目标数不敏感。
精度（Table 3）：DLRM(K=27,M=4) vanilla LogLoss 0.3875，FM 与 FM+FC rank-aware 均 0.3875（恒等等价，±0.0001 内），FM+FC 省 73% 总 FLOPs；DCN(K=26,M=16) DCNv2 0.3876，rDCN 0.3877（+0.05%）省 67% 总 FLOPs（交互层省 72%）。消融：rDCN 去掉并行 context 流后 LogLoss 退化约 0.001（到 0.3886），比恒等分解的扰动大一个量级，证明并行 context 流对捕捉高阶 ctx×ctx 动态必要。

5. 局限与未来方向

作者明确：(1) 恒等分解在 cross network 与 attention 只在首层成立，跨深度不叠加，须靠 rDCN 这类架构改动；(2) target-attention 模型（DIN、ETA、TWIN）用户表征按设计依赖目标，没有 context-only 路径，无法套用；TransAct 的 target-token 注入在第 0 层即破坏秩纪律；(3) 如何扩展到通过共享 self-attention 把目标早融到用户侧表征的架构，列为开放问题；(4) rDCN 牺牲严格恒等等价换取跨深度叠加节省，离线精度损失在训练噪声内；(5) rDCN 仅离线验证、尚未上线，因生产中 DLRM 的 FM+FC 变体已能以更低算力达到同等离线精度。

6. 工业实践意义

最直接的价值：这是"零精度损失、零重训、可直接替换"的推理优化，对推荐/搜索精排服务（一次请求打分成百上千候选）几乎是免费的吞吐红利。落地建议：(1) 先在 FM 与首个 FC 层套恒等分解，按 Taboola 经验单 pod 吞吐可近翻倍、峰值机器数砍掉约一半；(2) 上下文特征越多（长历史、会话、页面特征）收益越大，正契合特征不断膨胀的趋势；(3) 若用 DCNv2 且想跨深度获益，可评估 rDCN，但它非恒等等价、需离线验证精度；(4) 注意适用边界——DIN/TWIN 这类 target-attention 模型、以及把目标早融到用户侧的架构无法直接套用。部署上 Taboola 在 CPU(Intel Xeon Sapphire Rapids)+K8s 自动扩缩+TF Serving oneDNN 环境验证，说明对 CPU 推理同样有效。

Joint Optimization of Relevance and Engagement in Multi-Task Ranking 深度解读

1. 问题与动机

工业搜索排序若只用参与度信号（CTR / ATCR 加购率 / CVR）优化，会引入系统性偏差：因热门、价格锚定或词面重叠而获得点击的商品会被上排，即便语义上并不满足用户意图。难点在于高质量语义相关性监督在生产规模下稀缺——人工标注昂贵、缓慢，且对含数百万商品与长尾 query 的动态目录难以维护。于是形成根本张力：行为信号丰富但有偏，人工相关性判断可靠但稀疏。DoorDash 的目标是把语义相关性提升为首要优化目标，同时可控地平衡参与度。

2. 方法详解

三大件：序数相关性头 + 统一 value model + LLM 大规模产标。

  • Ordinal relevance head：不做二分类或 softmax，而是预测两个累积概率 p(r≥1)、p(r≥2)（相关性分级 0 不相关 / 1 中等 / 2 高度相关），标量相关性分 ŝ_rel = p̂(r≥1)+p̂(r≥2) 即期望相关性等级（式 3），天然保序。
  • 统一 value model 打分（式 1）：S(q,i)=α·ŷ_CTR+β·ŷ_ATCR+γ·ŷ_CVR+(1−α−β−γ)·ŝ_rel，α/β/γ∈[0,1] 可调，显式控制相关性-参与度权衡。
  • LLM 大规模产标流水线：①收集约 60 万人工标注作基线；②审计步骤——对"人工标 irrelevant 但参与度排进前 50%"的样本，用 GPT-4o 或 o3 配更细粒度 prompt 复评；③用 Query-to-Taxonomy(Q2T) transformer 预测相关类目做"标签调和"：类目命中则取人工/审计 LLM 的较高分，否则取较低分；④在审计后标签上微调 gpt-4o-mini，再推到 1 亿+ query-item 对。微调 LLM 在 10.5 万 hold-out 上三分类准确率 89%、within-1 准确率（|人工−LLM|≤1）98%。
  • 多任务架构：共享底层处理 query / item / consumer / interaction（BM25、历史率、字符串相似度）/ user-item / user-taxonomy 等特征，任务塔分别预测 CTR/ATCR/CVR 与序数相关性头；因共享底层与特征复用，加相关性头几乎不增计算成本。

3. 核心技术贡献

(1) 把 LLM 从"外部裁判"升级为"一等训练信号"：用多阶段审计 + Q2T 调和 + 微调小模型，把可靠相关性标签从 60 万人工扩到 1 亿级，解决相关性监督稀缺的根因，且 within-1 98% 的标注质量足以支撑训练。
(2) 序数累积概率头：相比 softmax 多分类或 MSE 回归，更契合相关性"有序等级"语义，并可直接转成能加进 value model 的标量分。
(3) 统一 value model 用可调权重显式建模相关性-参与度权衡，给出可操作的 trade-off 前沿，而非隐式融合。

4. 实验结果分析

离线（Table 1，200 万 query-item 对）：参与度-only 基线用 CTR 当相关性代理，Relevance NDCG@10 仅 0.812；本文序数法把 Relevance NDCG@10 提到 0.962（+0.150），同时 Click/ATCR/CVR 的 AUC（0.838/0.851/0.855）与基线持平。softmax(0.961)、regression(0.959) 也能拉高相关性 NDCG，但 trade-off 前沿（图 2）显示序数法在相同转化 NDCG 下相关性 NDCG 更高，且"适度的相关性权重即可大幅提升相关性、几乎不损参与度"。
在线 A/B（Table 2，三周）：ATCR +1.16%(p=0.01)、CVR +1.10%(p=0.01)、GOV 总订单额 +0.50%(p=0.03)，均显著。关键发现：提升语义相关性不仅没牺牲参与度，反而拉高了参与度与成交。
消融：仅把序数头当辅助任务、不把相关性并入最终打分（Auxiliary Only），相关性 NDCG 仅比基线微升——证明把相关性整合进统一 value model（式 1）才是收益关键，而非单纯多一个监督任务。

5. 局限与未来方向

作者未单列局限，但指向：探索更丰富语义信号（query 意图分解、属性级相关性）；用 query 自适应权重替代全局 value model 权重；纳入长期用户满意度指标。隐含局限：序数仅取 0/1/2 三级以平衡，未试更细粒度；微调 gpt-4o-mini 受标签分布敏感性约束，且未量化推理成本/延迟；在线实验仅三周，对低方差指标统计功效有限。

6. 工业实践意义

这篇与"社区搜索（相关性 nDCG + CTR 双目标）"场景几乎逐项对口，落地启示：(1) 别让 LLM 在线打分，而把它当离线/近线的相关性标注器，用"人工种子→审计可疑样本→类目调和→微调小模型批量推全量"的流水线，把相关性监督扩到亿级，within-1 98% 质量即可用；(2) 相关性头用序数累积概率而非多分类，保序且能转标量；(3) 用统一 value model 的可调权重显式做相关性-参与度权衡，并据 trade-off 前沿选"适度相关性权重"——可能同时涨相关性和 CTR/转化；(4) 关键是把相关性分真正并入线上排序打分，仅当辅助任务收益甚微。DoorDash 三周 A/B 的 ATCR/CVR/GOV 同向正收益，是双目标可兼得的有力证据。

Fine-Tuned LLM as a Complementary Predictor Improving Ads System

LRanker: LLM Ranker for Massive Candidates

LLM 排序受上下文长度与算力限制，难以应对百万级候选池。LRanker 面向大候选排序：candidate aggregation encoder 用 K-means 聚类显式建模全局候选信息；graph-based test-time scaling 把候选切分为子集、生成多个 query embedding 并通过集成融合。RBench 7 任务/3 场景评测：RBench-Small >30% 提升，RBench-Large MRR +3~9%，RBench-Ultra（>680 万候选）仍保持 20~30% 提升，消融验证各组件有效。

INSIGHT关键是“聚合多个 query embedding 而非依赖单一表征”以提升鲁棒性与表达力，并用 K-means 全局建模+图划分把 LLM 排序扩展到百万级。test-time scaling 走推理期增算力换效果，落地需权衡延迟成本，更适合离线或对延迟不敏感的粗排环节。

Ocean4Rec: Offline LLM-Derived OCEAN Profiles for Request-Time VOD Reranking

SSamsung

工业 VOD 推荐需要更丰富的内容理解，但 LLM-as-reranker 每请求都要重复 prompt 构造、token 生成、模型调用、解析与兜底，在高并发低延迟服务里难做吞吐规划与尾延迟控制。Ocean4Rec 只在离线用 LLM 把物品内容元数据物化成 OCEAN（开放/尽责/外向/宜人/神经质）五维画像；用户画像由近期点击/深度访问物品在同一五维空间做时间衰减聚合。请求时只 join 预计算画像+基础打分+目录新鲜度做数值重排，不调 LLM。Samsung Smart TV VOD 日志上，相对更强的 Base+Recency 基线，NDCG@20 在 NCF 生成器 +7.6%、LightGCN +61.5%；HR@20 在 NCF 不确定、LightGCN +67.3%。
