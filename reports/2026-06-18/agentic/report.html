1. Scaling Enterprise Agent Routing: Degradation, Diagnosis, and Recovery
4.10
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 研究生产环境中 LLM 助手把用户请求路由到工具库的准确率如何随目录规模下降。在一个已部署的企业办公助手上（110 个 agent、584 个工具），三款前沿模型从 10 个 agent 扩到 110 个时，欠规约请求的路由 F1 下降 16–23 个百分点。作者用 oracle 分析把退化拆成“检索缺口”（模型找不到正确工具）与“混淆缺口”（即便检索完美，oracle 上限仍降 10pp）。基于 embedding 的候选预筛在满规模下把 F1 拉回 +10–11pp，并用 1435 条人工标注的真实流量验证了 +10–17pp 的回升。

Key insight: 工具/agent 路由本质是大规模检索加排序问题：工具目录越大，召回正确工具的难度和工具间语义混淆都会拖垮路由准确率。把退化拆成检索缺口与混淆缺口的诊断方法，对社区搜索里“意图→召回通道/类目”的路由同样适用——embedding 预筛只补检索缺口，混淆缺口要靠工具描述消歧或重排来解决。论文用真实流量标注复核离线结论，是难得可信的工业证据。

arXiv2026-06-17Kellen Gillespie, Robyn Perry
2. Benchmarking LLM Agents on Meta-Analysis Articles from Nature Portfolio
3.75
Relevance 4 | Novelty 4 | Practical 3 | Evidence 4 | Timely 4

Summary: 针对系统性科学推理，作者构建 MetaSyn——442 篇来自 Nature 子刊、专家整理的 meta 分析数据集，每条含研究问题、PI/ECO 筛选标准、14 万篇 PubMed 检索语料、已核验的正例研究，以及主题相近但不符合 PI/ECO 的难负例。在 12 种流水线（9 种 RAG 变体加一个协议驱动 agent）上评测发现：检索召回上限可达 90.9%（K=200），但没有任何系统能恢复超过 52.7% 的真实正例，瓶颈卡在筛选环节，不在检索。

Key insight: 该基准把“检索-筛选-综合”全链路拆开评测，定位出 agent 在多步检索任务里的真实短板是筛选判断：召回能到 90.9%，可用筛选只剩 52.7%。对社区搜索的启示是，用 LLM agent 做多轮取证式搜索时光堆召回收益有限，把算力投到候选的相关性判别（区分难负例）才是收益点。其难负例构造方式（主题相似但标准不符）也值得搬到搜索相关性评测集的建设上。

3. OPD-Evolver: Cultivating Holistic Agent Evolver via On-Policy Distillation
3.70
Relevance 3 | Novelty 5 | Practical 3 | Evidence 3 | Timely 5

Summary: 自进化 agent 普遍把记忆当作存储底座，但“存下经验”不等于“学会如何利用经验进化”。作者提出 OPD-Evolver，一个慢-快协同进化框架，通过 on-policy 自蒸馏培养 agent 的进化能力：快循环中 agent 与四级记忆层级交互，读取、使用、写入、维护经验以支持测试时快速进化；慢循环用结果校准的记忆归因与特权后见之明，把这四种能力蒸馏进可部署策略。多领域基准上 OPD-Evolver 比 ReasoningBank 等记忆系统最高领先 11.5%。

Key insight: 该工作把 agent 记忆从被动检索升级为主动学会怎么用记忆，区分了“选取有用经验/写可复用知识/维护知识库”等能力并分别蒸馏。对搜索推荐里的会话与长期用户记忆有借鉴：与其无脑存全部历史，不如训练模型判断哪些交互值得写入、如何把效果归因回去。on-policy 自蒸馏用自身轨迹而不是外部 teacher，规避了离线 teacher 的分布漂移，是落地记忆型 agent 时可参考的训练范式。

4. From Trainee to Trainer: LLM-Designed Training Environment for RL with Multi-Agent Reasoning
3.45
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: LLM 的 RL 训练流水线常需在阶段间手工重设环境，靠经验猜哪种配置最能提升当前策略。作者提出 LLM-as-Environment-Engineer 框架：让当前策略模型分析失败轨迹与上下文，自动提出下一阶段训练环境的配置修改；并构建 MAPF-FrozenLake 可控测试台，其生成器暴露多维环境配置以便研究环境重设计。以 Qwen3-4B 为骨干，环境工程师基于策略行为、失败案例与环境统计的结构化摘要产出下一阶段配置。

Key insight: 把课程/环境设计这件原本靠人工调的事交给 LLM 依据失败轨迹来做，本质是自动化的 curriculum learning。对搜索推荐里的 RL（排序策略、agentic 检索）有启发：可以让模型分析自己 rollout 的失败模式，自动调整训练任务的难度分布，而不固定课程。MAPF-FrozenLake 这种暴露多维可控配置的测试台，也为评估“环境自适应”能力提供了范式。目前仅在 4B 模型与合成环境验证，工业规模仍待检验。

5. Environment-Grounded Automated Prompt Optimization for LLM Game Agents
3.45
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 交互环境中的 LLM agent 对 prompt 极度敏感，但 prompt 工程仍是人工、任务专用的过程。作者提出自动 prompt 优化框架：把“观察→动作”流水线拆成目标条件的描述器 agent 和动作选择 agent，通过环境回报引导的 LLM 进化循环迭代优化各模块 prompt；并引入行为分析器把回合结果归因到具体 prompt 组件，用变异器提出针对性修改，再经环境 rollout 验证后保留。

Key insight: 该框架价值在于把 prompt 优化变成带信用分配的进化搜索：行为分析器先定位是哪段 prompt 导致失败，再定向变异，比无差别改写更高效。对搜索推荐里大量依赖 prompt 的 LLM 模块（query 改写、相关性判别、agentic 检索规划）有直接借鉴——用线上或离线指标当环境回报自动迭代 prompt，能省掉人工调 prompt 的成本。把流水线拆成描述器加动作选择两个 agent 的模块化设计，也便于分别归因与优化。

6. MemSlides: A Hierarchical Memory Driven Agent Framework for Personalized Slide Generation with Multi-turn Local Revision
3.45
Relevance 3 | Novelty 3 | Practical 4 | Evidence 3 | Timely 5

Summary: 个性化幻灯片生成要求 agent 跨任务保留稳定用户偏好、在多轮修订中记住新引入的偏好与约束、并可靠地做局部编辑。作者提出 MemSlides 分层记忆框架：把长期记忆与工作记忆分离，长期记忆再分为用户画像记忆（存意图条件化画像，用于第 0 轮个性化）和工具记忆（存可复用执行经验以支持可靠局部编辑），工作记忆承载跨修订轮的活跃偏好与会话约束。框架配合 slide-local 局部修订，使定向更新只作用于最小受影响区域，避免整篇重生成。

Key insight: MemSlides 的三分记忆设计（用户画像/工具/工作记忆）对多轮个性化场景很有参考价值：把长期稳定偏好与本次会话的临时约束分开存储，避免会话噪声污染长期画像。其局部修订机制（只改最小受影响区域）对推荐/搜索的增量更新也有启发——多轮交互式推荐中，用户的局部反馈不该触发全量重排。三类记忆的边界划分是可直接迁移到对话式搜索 agent 的核心思路。

7. PromptMN: Pseudo Prompting Language
3.35
Relevance 3 | Novelty 3 | Practical 4 | Evidence 2 | Timely 5

Summary: prompt 已成为人与生成式 AI 的主要接口，但自然语言 prompt 常很脆弱：角色、目标、约束、期望输出往往埋在散文里或留作隐含。在 agentic 与软件开发工作流中，第一个交接点的误读会沿每一步传播，作者指出相当一部分 agent 失败源于上下文歧义，而不是模型能力不足。为此提出 PromptMN，一种伪 prompt 领域特定语言，用紧凑的 %- 前缀类型化指令标注自然语言，覆盖角色、目标、要求、优先级、约束等。

Key insight: PromptMN 把“把意图写清楚”这件事结构化成轻量 DSL，针对的是多步 agent 里因上下文歧义而级联放大的失败。对搜索推荐的 agent 编排有现实意义：当检索 agent 把任务交给下游排序/生成模块时，用类型化指令标明哪些是硬约束、优先级如何，能减少误读。这类方案的好处是低成本、可增量加在现有 prompt 上；局限是论文证据偏弱，缺少在大规模 agent 任务上失败率下降的量化。

8. GameCraft-Bench: Can Agents Build Playable Games End-to-End in a Real Game Engine?
3.15
Relevance 2 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 游戏生成是编码 agent 的新兴应用，要求模型把自然语言规格转成可玩的交互系统，且需在游戏引擎内让脚本、场景、资产、渲染与运行时交互共同产出连贯玩法。作者把端到端游戏生成形式化为“通过目标环境中可观察的玩家-游戏交互来实现规格的完整游戏产物”，提出引擎接地、产物完整性、交互式验证三项准则，据此构建 GameCraft-Bench——140 个 Godot 任务、覆盖 15 个游戏家族，用回放演示和 rubric 引导的多模态评判来评估可执行玩法。

Key insight: GameCraft-Bench 的方法论亮点是交互式验证：不只看代码静态正确性，而是回放真实玩家-游戏交互、用多模态评判看是否真能玩，比传统单测式代码评测更贴近 agent 真实能力。对搜索推荐里评测生成式/agentic 系统有启发——与其只看离线指标，不如构造可执行、可回放的端到端交互评测。引擎接地加产物完整性的拆解也提示，评测 agent 产物要同时看“能跑”和“完整满足规格”。该基准与搜推业务本身距离较远，价值主要在评测范式。
