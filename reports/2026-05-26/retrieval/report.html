1. HARNESS-LM: A Three-Phase Training Recipe for Harnessing SLMs in Sponsored Search Retrieval
4.40
Relevance 5 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 针对赞助搜索 (sponsored search) 中检索质量与生产延迟难以兼顾的问题，HARNESS-LM 提出三阶段训练 recipe 把大规模 SLM 检索器的能力迁移到小模型：(1) 微调十亿参数级 SLM (如 Qwen3-Embedding-4B/8B) 得到高性能 teacher 检索器；(2) 用 L2 目标对齐 query 表示，把知识蒸馏进一个 sub-600M 的 student encoder；(3) 再做一轮对比学习精炼。论文还系统对比了各关键设计选择对检索效果的影响。

Key insight: 把『大检索模型当 teacher、小 encoder 当线上 student』的两段式蒸馏拆成『L2 表示对齐 + 对比精炼』两步，是延迟敏感的短文本召回场景值得借鉴的工程范式——既拿到 4B/8B SLM 的语义上限，又把线上模型压到 600M 以内。query 侧表示对齐 (而非直接蒸 logits) 对召回任务更稳定，社区搜索的双塔召回可以直接套用这套 teacher-student 流程。

2. Query-Adaptive Semantic Chunking for Retrieval-Augmented Generation: A Dynamic Strategy with Contextual Window Expansion
3.90
Relevance 4 | Novelty 3 | Practical 4 | Evidence 3 | Timely 5

Summary: 固定切块按统一粒度切文档，无视语义和用户意图，导致 precision-recall 难以两全。QASC 把 query 引入切块阶段，通过三个机制动态构造 chunk：(1) 句子与 query embedding 的 cosine 相似度打分定位种子句；(2) 围绕种子句做上下文窗口扩展以保持连贯；(3) chunk 级分数聚合保证整体相关。在 100 篇技术文档、200 条覆盖四种类型的 query 上，与五种粒度的固定切块、递归切块等基线对比。

Key insight: 把分块从『检索前的静态预处理』改成『随 query 自适应』，本质是把 query-content 对齐提前到召回链路最上游。对社区搜索这类短文本场景启发在于：长帖/长问答的切分不必固定窗口，可按 query 语义动态聚合句子。预算敏感时该思路也能减少下游冗余上下文 (preference_bonus 来自 RAG 主题匹配)。

3. LFRAG: Layout-oriented Fine-grained Retrieval-Augmented Generation on Multimodal Document Understanding
3.60
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 现有多模态 RAG 多依赖粗粒度的 page-level 检索，无法捕捉视觉富文档里的细粒度语义和布局结构，既损失检索精度又给下游带来冗余上下文。LFRAG 把多模态 RAG 从 page-level 推进到 block-level：先做布局分割构造语义连贯的细粒度检索单元，再用 semantic-layout fusion encoder 通过 cross-attention 把局部语义与全局上下文融合，最后以 block-level late interaction (ColBERT 式后期交互) 完成 query-内容精确对齐。

Key insight: late interaction + 布局感知的细粒度单元，是把『检索单元粒度』作为可调维度的代表做法。对搜索系统的启示：当文档结构信息 (标题、分区、版式) 有判别力时，与其整页编码，不如切到 block 级并保留布局上下文做后期交互打分。preference_bonus 来自 retrieval-augmented generation 主题匹配。

4. Vector Retrieval with Similarity and Diversity: How Hard Is It?
3.55
Relevance 4 | Novelty 4 | Practical 3 | Evidence 3 | Timely 3

Summary: 稠密向量检索是语义搜索、RAG、知识密集推理的基础模块，但很多应用不只要『单条与 query 相似』，还要结果集合多样、互补、整体信息量大。业界广用的 MMR (Maximal Marginal Relevance) 依赖手工调的权衡参数，导致优化波动、结果不可预测。本文给出相似性与多样性联合优化的理论刻画，分析二者在稠密向量空间中如何相互作用，并提出比 MMR 更稳定、理论可解释的优化方式。

Key insight: 把『相似性 + 多样性』从启发式 MMR 升级为有理论保证的联合优化问题，对搜索结果去同质化有直接参考价值。社区搜索结果页常被高度相似的帖子刷屏，该工作提示用统一目标 (而非外挂一个 λ 调参) 来控制相似与多样的权衡，减少线上结果抖动。

5. Knowledge Distillation for Low-Resource Open-source Text-to-SQL Model
3.45
Relevance 3 | Novelty 3 | Practical 4 | Evidence 3 | Timely 5

Summary: Text-to-SQL 把自然语言问题转成可执行 SQL，让非技术用户也能查库做分析。真实场景常受限于低资源：高质量 <问题,SQL> 标注稀缺，尤其领域库；schema 定义不透明、有缩写和隐式业务逻辑。现有数据合成与 prompting 能扩覆盖但难产出与数据库约束对齐、语义扎实的样本。本文用知识蒸馏把大模型能力迁移到低资源开源小模型，缓解标注稀缺与领域适配问题。

Key insight: Text-to-SQL 属于 query 理解 (自然语言→结构化查询) 的一类，其『低资源 + 蒸馏到开源小模型』思路对社区搜索的 query 改写/结构化解析有迁移价值：当领域标注少、schema/标签体系复杂时，先用大模型造对齐约束的样本再蒸馏到可部署小模型，是务实的落地路径。

6. The Efficiency Frontier: A Unified Framework for Cost-Performance Optimization in LLM Context Management
3.30
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 5

Summary: LLM 越来越依赖长上下文，但扩窗带来显著的算力与成本开销。现有上下文缩减方法 (检索、记忆压缩等) 通常把性能与效率分开评估，难以系统对比、也不利于部署决策。本文提出 The Efficiency Frontier 统一框架，把上下文策略选择建模成『部署感知』的优化问题，联合考虑任务性能、token 成本与预处理复用，给出在成本-性能权衡上的最优前沿。

Key insight: 把『检索 vs 记忆压缩 vs 长上下文』放进同一成本-性能坐标系，对 RAG/检索系统的部署选型有参考意义。社区搜索接 LLM 时，检索召回多少、压缩到什么粒度、是否复用预处理结果，应当按 token 成本与效果一起算账，而不是只看单一指标。

7. Is Dimensionality a Barrier for Retrieval Models?
3.25
Relevance 3 | Novelty 4 | Practical 2 | Evidence 3 | Timely 5

Summary: 为什么 embedding 检索模型的表示维度通常只有 d≈1000，却能扩展到数十亿甚至万亿级数据点？本文用 max-margin embedding 在经典检索模型 (查询-文档相关矩阵 A) 下研究最大间隔 m^rd(d,A)，分析在给定维度 d 下能容纳多少 query/document 仍保持正负样本内积有正间隔。间隔是表示质量的关键代理，控制鲁棒性与可分性。结论从理论上解释了低维 embedding 不构成扩展的根本瓶颈。

Key insight: 回答了一个工程上反复纠结的问题：embedding 维度到底是不是召回容量的天花板。结论偏理论但有指导性——盲目堆高维度未必换来召回增益，间隔 (margin) 比维度更能刻画表示质量。对社区搜索的双塔召回选维有参考：在大规模库下，d≈1000 量级通常够用，优化重点应放在间隔/对比目标而非单纯加维。

8. Synthetic Sources?: Auditing Generative Search Engine Citations for Evidence of AI-Generated Sources
3.20
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 5

Summary: 生成式搜索引擎 (能从网络抓取、综合并引用信息来回答用户问题的对话式接口) 简化了信息获取，但随着 AI 生成内容在网上泛滥，这些引擎能否可靠地『不引用合成来源 (AI 生成的来源)』并不清楚。若做不到，用户会把生成式搜索综合进答案的 AI 生成来源当成权威/官方信息，带来误导风险。本文对生成式搜索引擎的引用做审计，检验其引用中 AI 生成来源的占比与证据。

9. RAS: Reflection-Augmented Scaling with In-Context Learning for Executable Cypher Query Generation
3.15
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 5

Summary: 推理时扩展 (inference-time scaling) 能减少结构化查询生成的错误，但如何分配查询代码生成的算力仍少有研究。本文研究 Text2Cypher——让模型生成可在属性图数据库执行的 Cypher 查询。不可执行查询是区别于语义错误的语法失败：语法错会触发数据库返回错误信息，而这些信息在推理时通常被丢弃而非通过 ICL 利用。论文对比 Independent Scaling (无记忆重采样) 与 Reflection-Augmented Scaling (把数据库错误信息反馈给模型做 ICL 反思)。

Key insight: 把『数据库执行返回的错误信息』作为 ICL 反思信号，是结构化查询生成里被忽视的免费监督。对社区搜索的结构化检索/标签查询有借鉴：当 query 被解析成可执行的结构化表达 (DSL/过滤条件) 时，用执行反馈做迭代修正比盲目重采样更省算力、更易拿到可执行结果。

10. PLACE: Prompt Learning for Attributed Community Search in Large Graphs
3.00
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 3

Summary: PLACE 是面向属性社区搜索 (Attributed Community Search, ACS) 的图 prompt learning 框架。受 NLP 中 prompt-tuning 启发 (插入可学习 prompt token 来语境化查询)，PLACE 把结构化与可学习的 prompt token 注入图中作为依赖 query 的精炼机制，形成 prompt-augmented graph；这些 prompt token 充当桥梁，强化与 query 相关的节点连接，让 GNN 更有效识别结构内聚性与属性相似性。采用交替训练联合优化 prompt 参数与 GNN，并用分治策略支持百万级图。

Key insight: 把 NLP 的 prompt-tuning 思路迁移到图上的『社区搜索』，对以关系/社群为核心的检索场景有借鉴：用 query 依赖的可学习 prompt token 改造图结构，而非为每个 query 重训模型。对社区平台 (用户-内容-话题图) 的相关社群/相关用户召回是可迁移的范式，分治策略也给出了百万级图上的扩展路径。
