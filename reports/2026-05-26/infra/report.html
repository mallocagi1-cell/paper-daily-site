1. PALS: Power-Aware LLM Serving for Mixture-of-Experts Models
4.25
Relevance 3 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: 针对 MoE 大模型推理的能耗问题，PALS 把 GPU 功率上限 (power cap) 当作和 batch size 同级的可调控制量来联合优化，而不是固定功率后只调软件参数。它用轻量级离线功耗-性能模型加上反馈式在线控制器，在满足吞吐目标的前提下挑选能效最高的配置，并以插件方式接入 vLLM，不需要重训模型或改 API。在多 GPU、稠密与 MoE 两类模型上，能效最高提升 26.3%，在功率受限场景下 QoS 违约次数下降 4-7 倍，并能跟随动态功率预算调整。

Key insight: 对于把 LLM 接入搜索召回/query 改写/重排的团队，PALS 给出一个被长期忽视的调优维度：在固定 SLA 下，功率上限和 batch size 一起搜才能逼近能效最优，单调软件参数会留下 26% 的能效空间。它无需改模型、直接挂在 vLLM 上的特性意味着接入成本低；反馈式控制器跟踪动态功率预算的设计，适合电力受限或潮汐流量的在线 serving。MoE 由于专家激活不均、瞬时功率波动大，从功率角度调度的收益尤其明显。

2. Charon: A Unified and Fine-Grained Simulator for Large-Scale LLM Training and Inference
3.95
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: Charon 是一个统一、模块化、细粒度的大规模 LLM 训练与推理模拟器，把并行策略、系统优化和硬件配置组成的庞大设计空间显式建模，让团队在真正起集群之前就能预测某套部署方案的性能。论文报告整体预测误差低于 5.35%，在大规模 GPU 集群训练场景下误差低于 3.74%，并用它找到了一个比工程团队手工调优更优的推理部署配置。该工作已被 MLSys 2026 接收。

Key insight: 搜索/推荐团队上线 LLM 服务时，并行切分、KV 配置、硬件选型的组合爆炸常靠经验拍板，试错代价是几天的算力。Charon 把这步前置为可模拟、可比较的预测问题，5% 量级的误差足以用于方案排序和容量规划。它能跑出比手工调优更好的推理配置这一点，说明细粒度模拟不只是验证工具，还能主动发现被人忽略的配置。对自建训练/推理平台、需要频繁评估新卡新拓扑的团队价值较高。

3. The Efficiency Frontier: A Unified Framework for Cost-Performance Optimization in LLM Context Management
3.70
Relevance 4 | Novelty 3 | Practical 3 | Evidence 3 | Timely 5

Summary: 长上下文 LLM 带来高昂的算力与费用，而现有上下文裁剪方法（检索、记忆压缩等）通常把性能和效率两个指标分开评估，难以横向比较、也难以做面向部署的取舍。The Efficiency Frontier 提出一个统一的成本-性能优化框架，把上下文策略选择建模为面向部署的优化问题，用摊销成本 (amortized cost) 同时考虑任务表现、token 成本和预处理结果的复用，从而把不同方法放到同一条效率前沿上做决策导向的分析。

Key insight: 在社区搜索里用 LLM 做 RAG、query 理解或长文档重排时，'要不要压上下文、压到什么程度'往往凭感觉。这篇把它变成可量化的成本-性能权衡：关键是引入摊销成本，把可复用的预处理（如缓存的压缩结果、共享前缀）分摊到多次调用上，这正是高 QPS 搜索场景区别于一次性问答的地方。框架本身偏方法论，落地需要自己接评测，但它提供的'效率前沿'视角有助于在检索增强与记忆压缩等方案间做有依据的选型。

4. Is Dimensionality a Barrier for Retrieval Models?
3.60
Relevance 4 | Novelty 4 | Practical 2 | Evidence 3 | Timely 5

Summary: 论文追问一个反直觉的现象：为什么约 1000 维的低维表示，没有阻止 embedding 检索模型扩展到十亿乃至万亿规模的数据。作者在通信复杂度经典模型框架下研究最大间隔 (maximal-margin) embedding，用一个 0/1 的 query-文档相关性矩阵 A 定义可实现的最大间隔，分析在固定维度 d 下能稳定区分相关/不相关对所需的几何条件，给出维度与可分性、规模之间关系的理论刻画。

Key insight: 对短文本语义召回团队，这篇从理论上回答了一个实际问题：盲目堆 embedding 维度未必有收益，可分性更取决于相关性矩阵的结构而非单纯的维度。它解释了为何 768/1024 维向量仍能服务超大规模库——只要相关关系的'秩'结构友好。实践意义在于：选维度、做向量压缩 (PQ/降维) 时，可以参考相关性结构而非一味追求高维，这对控制向量检索的内存和延迟成本有指导价值。偏理论、不能直接落地，但能纠正工程直觉。

5. Multi-Layer Scheduling for MoE-Based LLM Reasoning
3.55
Relevance 3 | Novelty 3 | Practical 4 | Evidence 4 | Timely 4

Summary: Gimbal 为 MoE 推理 serving 设计了三层调度框架。请求层用最短作业优先 (SJF) 加优先级老化 (priority-aging) 提升吞吐、降低排队延迟；引擎层做负载感知派发，综合考虑前缀 token 负载、KV cache 占用和用户粘性把请求分到合适实例；专家层缓解专家热点、并合理安排跨层专家依赖以均衡负载。在 100 多组不同负载分布的实验中，相比 vLLM 基线，首 token 延迟 (TTFT) 最多降低 17.8%，单 token 输出延迟 (TPOT) 降低 13.3%。

Key insight: 把 LLM 推理服务用于搜索在线链路时，调度通常停留在 FIFO + 轮询。Gimbal 的价值在于把调度拆到请求/引擎/专家三个粒度分别优化：引擎层利用前缀负载和用户粘性做亲和派发，对有大量共享 prompt 前缀的搜索场景（统一 system prompt、相似 query 模板）能提高 KV 复用率；专家层的热点均衡则直击 MoE 负载不均的痛点。17.8%/13.3% 的延迟收益对延迟敏感的搜索请求是实打实的，且策略可在 vLLM 上实现。

6. BlossomRec: Block-level Fused Sparse Attention Mechanism for Sequential Recommendations
3.45
Relevance 3 | Novelty 3 | Practical 4 | Evidence 3 | Timely 4

Summary: 随着用户行为序列变长，序列推荐 (SRS) 里标准注意力的算力和显存开销线性甚至平方增长，而已有的高效注意力或 SSM 方法在长序列建模力不足、短序列上又表现不稳。BlossomRec 设计了一种块级融合的稀疏注意力：把用户兴趣显式拆成长期和短期两类，用两套不同的稀疏注意力分别计算，并在块级做融合，从而在长短不一的序列上都保持稳定表现，同时降低注意力的计算与访存成本。

Key insight: 社区场景里用户行为序列长度差异极大（重度用户上千条、新用户寥寥几条），统一注意力很难两头兼顾。BlossomRec 的思路对召回/排序的序列建模有借鉴：长短期兴趣分流 + 块级稀疏，是在不牺牲短序列稳定性的前提下压低长序列成本的可行路径。块级融合稀疏注意力本质是工程友好的 kernel 级优化，便于在现有 Transformer 排序模型上替换。需关注其在公开数据外、真实短文本行为上的稳定性。

7. Vector Retrieval with Similarity and Diversity: How Hard Is It?
3.40
Relevance 4 | Novelty 3 | Practical 3 | Evidence 3 | Timely 3

Summary: 稠密向量检索是语义搜索、RAG 和知识密集推理的基础组件，很多应用不只要求结果单个相似，还要整体多样、互补、信息覆盖全。如何稳定且有理论保证地平衡相似性与多样性长期是难题。广泛使用的最大边际相关 (MMR) 依赖手工调的权衡参数，导致优化波动、检索结果不可预测。该论文 (v4) 从理论上分析相似性与多样性联合优化的难度，并给出比 MMR 更有理论依据的求解视角。

Key insight: 社区搜索结果若全是高度相似的帖子，体验和点击都会受损，多样性是真实需求。这篇的价值在于指出 MMR 的核心问题是那个手调的 λ 参数带来的不稳定，并把'相似+多样'的检索抽象成有理论保证的优化问题。对工程实践的启示：与其线上反复调 MMR 的权衡系数，不如采用有理论支撑的多样性求解方法以获得更可预测的结果。该工作偏理论分析，落地需要把结论转化为可用的重排算法。
