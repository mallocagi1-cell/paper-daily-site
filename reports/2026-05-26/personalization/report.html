TubiFM: Unified Item, Carousel, and Search Ranking for Streaming Discovery

针对流媒体平台为 item 排序、carousel 排序、搜索分别训练独立模型的割裂现状，提出 user story 表示：把用户跨场景历史（属性、session、带 surface/carousel 上下文的观看事件、搜索事件）串成单一 token 序列，并把预训练语言 token 与领域事件 token 交错。TubiFM 基于 Llama 3.2 1B 在 user story 上训练，用 prompt 把异构的推荐与搜索任务统一表达为 next-token 预测，单模型同时服务三类排序任务。

1. 问题与动机

流媒体发现系统通常为 item 排序、carousel(横滑卡片) 排序、搜索分别训练独立模型，无法共享同一用户旅程中的互补信号。作者指出三类信号天然互补：观看行为塑造 carousel 与 item 排序；搜索 query 即使没命中目录也暴露用户意图；观看历史帮助把一次搜索解读为重看(rewatching)、续看(continuation) 还是新发现(new discovery)。数据规模为约 2000 万观众、约 8 亿次观看、约 6600 万次搜索，覆盖 Home/Search/Browse/Autoplay 四个主要 surface。多模型并存导致跨任务信号割裂、维护成本高、且无法把搜索意图与观看历史互相印证，这是统一建模的动机。

2. 方法详解

核心是 user story 序列化：把单个用户在观察窗口内的行为写成有序的 session+event 序列，分三层：(1) 用户属性层——粗粒度国家、设备上下文、类别/数值字段，按普通文本序列化；(2) session 结构层——以 >1 小时不活跃切分 session（最长 12 小时），每个 session 用 <|session|> token 加 elapsed time 与星期标注；(3) 事件数据层——watch 事件记录 item id、观看时长、surface、carousel 名、时间戳，search 事件记录 query 文本与时间戳（含失败搜索，as-you-type 中间 query 单独记录）。词表把 Llama 预训练 BPE subword 与领域原子 token（<|watch|>、<|search|>、字段、surface、carousel、item id）交错。一个关键取舍是 item 用单个原子 token 表示（而非多 token 语义 ID），从而一次前向就能用 logits 直接对全目录打分，比自回归语义 ID 解码便宜得多。

模型基于 Llama 3.2 1B 公开 checkpoint。训练语料约 2000 万 user story（平均 560 token，约 110 亿 serialized token），辅以目录文本映射语料（如 <|id|> has title {title}）按 1:20 混入；序列长截到 1024。训练 120k macro-step，8×H100，per-device batch 4、梯度累积 4，约 22 小时，bf16，梯度裁剪 1.0，weight decay 0.033，Adam，lr 1e-5（1000 步 warmup）。训练时做两种 masking：surface/carousel 对以 0.1 概率替换为 <|carousel(MASK)|>（教模型学容器无关打分），content id 以 0.001 概率替换为 unknown token（应对目录刷新间的变化）。任务通过 prompt 后缀表达：item 排序追加 watch-event head（masked carousel 做容器无关排序，或具体 surface/carousel 做上下文排序）；carousel 排序追加 surface 上下文预测下一个 carousel token；search 排序追加 query token + search-surface watch head，预测从结果中被选中的 item。损失为标准自回归 next-token 预测，无定制 loss——靠 prompt 上下文决定预测 item id、carousel 还是 search 结果。

3. 核心技术贡献

(1) 分层 prompting 框架：单一生产模型经 user story 共享接口同时服务 item/carousel/search 三类排序，复用预训练 LLM 的语言 token + 领域事件 token，仅靠改 prompt 后缀切换任务（同一 story 改 prompt 即产出不同排序列表）。(2) 把稀疏文本与时间特征纳入生成式推荐，user story schema 可扩展接入更多有序用户事件信号。(3) item 用原子单 token、一次前向对全目录打分，省去独立召回阶段——这是相对语义 ID 自回归解码的关键工程取舍，直接决定了线上延迟可控。

4. 实验结果分析

离线 (Table 2)：item 排序 TubiFM unified HR@8 0.5817，相对 HSTU(0.4121) +41.2%、NDCG@8 +48.1%；carousel HR@8 0.8343 vs HSTU 0.7724 +8.0%；search HR@8 0.5673 vs BM25 0.4637 +22.3%、HR@50 +47.0%（语义向量基线 Qwen3-4B Emb、Sentence-Transformer 在搜索任务上远低于 BM25）。unified 模型还优于 task-specific TubiFM：item +16.9%、carousel +2.5%、search +12.1% (HR@8)，说明跨任务联合训练存在正迁移。消融：随机初始化使 item HR@8 0.5817→0.5670（Llama 预训练有用）；去掉用户属性仅微降(0.5817→0.5773，属性是弱先验，去掉位置有时还略升)；去掉 session 切分与时间字段明显掉点(item→0.5569、search→0.5410)，说明 session 结构提供有用的时间上下文。在线 A/B (Table 6)：search TVT +3.9%（长尾/长 query 高达 +20%），carousel +0.30%，item +0.14%(不显著)；三个 surface p99 延迟从 ~500ms 降到 ~200ms。item 中性被作者定位为系统性胜利——以更简架构匹配成熟生产基线。

5. 局限与未来方向

作者明确三点：(1) 离线标签仅来自隐式互动、并非穷尽的相关性判断，继承了曝光偏置与正反馈-only 的偏差；(2) 在线对照是专有生产系统（含内部召回/过滤/排序组件），只报相对提升而非原始流量或完整 serving 细节；(3) user story 虽设计为通用 schema，但本文只在流媒体视频域做了实验验证，跨域泛化未证。

6. 工业实践意义

对搜推统一架构有直接借鉴：用一个 1B 小 LLM + prompt 服务多场景排序，item 排序端到端替代了生产中「十几个召回器 + transformer-DCN 排序器」，搜索/carousel 也同样压平多阶段流水线，p99 延迟 500→200ms（部署在 L40S GPU + 动态 batching）。item 用原子单 token、全目录一次前向打分，是规避语义 ID 自回归解码延迟的可落地方案。收益最大处在搜索长尾 query（行为上下文补偿了词面证据稀疏），非常契合社区搜索这类短文本、意图模糊、长尾多的场景：query 与点击/浏览行为可统一进同一用户序列建模。部署节奏可参考：模型每日重训跟踪行为漂移、目录 token 每月刷新、新 item 先映射到保留 UNK token。落地需注意离线指标受正反馈偏置影响，需自建在线评测来判断真实收益。

Expand More, Shrink Less: Shaping Effective-Rank Dynamics for Dense Scaling in Recommendation

TencentHKUST📖 有深读 · 8 分钟

推荐模型 dense scaling 的代表方案 RankMixer（统一 token 表示 + token mixing 与 per-token FFN 交替）存在 embedding collapse：表示有效秩偏低、表达力受限、扩展出的表示空间被浪费。论文经实证与理论分析指出刚性 token mixing 与 P-FFN 共同诱发跨层有效秩的「阻尼振荡」轨迹，提出 RankElastor：用 parameterized full mixing 等组件产生谱稳健（spectrum-robust）表示，并给出可证明的 collapse 缓解。

INSIGHT把推荐大模型的扩展瓶颈归因到表示有效秩坍缩，并用有效秩动力学这一可量化视角诊断 token mixing 架构，是对 RankMixer 一类「推荐 Scaling Law」工作的直接改进。对做排序模型放大的团队有用：扩参数前先看表示有效秩是否坍缩，否则增容会被低秩瓶颈吃掉；提供了一个判断 dense scaling 是否真正生效的诊断指标。

Guoming Li, Shangyu Zhang, Junwei Pan, Wentao Ning, Jin Chen, et al.

1. 问题与动机

推荐大模型扩容遇到 embedding collapse：学到的表示集中在低秩子空间，限制表达多样性、浪费扩出的容量。RankMixer 虽比 DCNv2、xDeepFM、AutoInt 等传统模型好，但提升不足。作者用 effective rank（erank = ||X||_F² / ||X||_2²，超越代数秩刻画表示容量）逐层度量：Criteo 上 RankMixer 末层 erank 仅略高于原始 embedding（提升「modest」未能阻止坍缩）；Avazu 上 P-FFN 的收缩占主导、collapse 重现。关键现象被概括为「阻尼振荡轨迹(damped oscillatory trajectory)」——token mixing 抬高 erank、P-FFN 压低 erank，逐层交替收缩却始终未能消除坍缩。实验在 Criteo 与 Avazu 两个各 3300 万+ 训练样本的工业级 CTR 基准上进行，坍缩问题在这种规模下尤为现实。

2. 方法详解

RankMixer 三件套：tokenization 把异构 embedding 投到统一 D 维 token 矩阵；token mixing 是无参的 block-transpose（成对置换 token）；P-FFN 是 per-token GELU FFN。理论诊断：block-transpose 的秩扩张有界 erank(M) ≤ 2(k+μ)（k、μ 为原矩阵与转置矩阵的有效秩）；带正齐次激活的标准 FFN 以概率收缩 erank（Theorem 2.1/2.2）。RankElastor 以「Expand More, Shrink Less」为目标提出两组件：

(1) 参数化全 token mixing：把无参 block-transpose 换成可学习稠密变换 vec(M⊤)=LN((W+I)vec(X⊤))，其中 W∈ℝ^(TD×TD) 为可学习混合矩阵，(W+I) 的残差形式保证初始接近恒等，把 block 粒度从 d>1 降到 d=1（细粒度），实现比 Kronecker 约束的 block mixing 更丰富的坐标交互；Theorem 3.1 证明 d=1 情形严格扩张表达力。

(2) GLU 改进的 P-FFN：把 GELU 换成门控形式 Z_t=(GELU(M_tW₁)⊙(M_tW₂))W₃+M_tW_r（⊙ 为逐元素乘），遵循 GLU 原则用乘性特征交互防止秩收缩；Theorem 3.2 证明乘性项引入 degree-2 交互，代数秩至少抬升 k(k+1)/2，并保证 effective rank 增量 δ>0。

复杂度：token mixing 从 RankMixer 的 O(TD)、零参数升到 O(T²D²) 计算与参数（主要开销来源）；P-FFN 加常数因子（扩展比 3r+1 vs r）；净结果是训练时间增加 10-15%，显存影响可忽略。

3. 核心技术贡献

(1) 首次系统刻画 RankMixer 的 collapse：把经验 effective-rank 动力学与理论(Theorem 2.1-2.2)结合，解释为何 RankMixer 的提升不彻底。(2) RankElastor 架构：参数化全混合 + GLU P-FFN，给出可证明的 collapse 缓解与「谱稳健(spectrum-robust)表示」理论保证（Theorem 3.1-3.2）。(3) 工业规模验证：在 CTR 与行为序列建模上都取得一致增益、表示多样性提升与更优的参数 scaling 行为，并开源代码。

4. 实验结果分析

CTR (Table 2)：Criteo AUC RankElastor 0.81482 vs RankMixer 0.81375、DCNv2 0.81365、MLP 0.81307；Avazu 0.79323 vs RankMixer 0.79270、DCNv2 0.79258。约 0.001 AUC 增益，在工业级基准属「统计显著」（CTR 领域 0.001 AUC 常对应可观线上收益）。collapse 缓解 (Fig 6)：RankElastor 跨层维持持续更高的平均 erank，Avazu 上保持稳定的 erank 增长，而 RankMixer 呈阻尼振荡且扩张有限；分布偏移(Fig 5)显示参数化全混合相对 block-transpose 带来明显更大的 erank 增益。scaling (Fig 7-8)：宽度、深度、深+宽联合扩展三种方式下，RankElastor 都比 RankMixer 有更大 AUC 提升与更低 LogLoss，且联合扩展收益大于单维扩展，与 LLM 的 scaling 规律一致——这点对「推荐 Scaling Law」尤为关键，说明先解决 collapse 才能让加参数真正兑现。消融 (Table 3)：去掉 full mixing→Criteo 0.81413、换 ReLU FFN→0.81326、换 GELU FFN→0.81349，两组件协同——只把 GLU 加到原始 RankMixer 仅 0.81393(对比 0.81375)，说明需先增强 token mixing 才有协同效应。泛化 (Table 4)：行为序列建模 KuaiVideo gAUC 0.6731 vs 0.6691、AUC 0.7514 vs 0.7482；TaobaoAd gAUC 0.5778 vs 0.5763、AUC 0.6522 vs 0.6508，证明方法不局限于 CTR 估计。效率 (Fig 4)：10-15% 运行时增加、GPU 显存相当，作者称对大规模推荐「practically negligible」。

5. 局限与未来方向

作者明确：(1) 有效秩动力学与理论分析专门针对 token-transformation 类(RankMixer 式)架构，结论未必推广到根本不同的设计范式；(2) 理论框架适用面较窄，RankMixer 类仍有大量探索空间；(3) 分析假设了特定初始化与 incoherence 条件，现实偏离未被完全刻画。此外论文未给在线 A/B，也未讨论稠密 (TD×TD) 混合矩阵在 serving 规模下的推理延迟、量化/蒸馏等服务优化策略，以及 T×D 远大于实验设置时的可扩展性。

6. 工业实践意义

对做排序模型放大的团队最有用的一点：扩参数前先量化表示的 effective rank，若已坍缩则单纯增容会被低秩瓶颈吃掉——erank 是判断 dense scaling 是否真正生效的可量化诊断指标，可作为放大实验的前置体检项。RankElastor 的两点改造（可学习全混合替代无参 block-transpose、GLU 替代 GELU FFN）可直接嫁接到 RankMixer 类统一 token 排序模型，10-15% 训练开销换来更好的 scaling 与跨场景泛化(CTR 与行为序列双验证)。但 O(T²D²) 的 token mixing 是 serving 隐患，落地需评估推理延迟、可能配合量化/蒸馏，建议增量上线并密切监控服务侧性能。代码已开源(Zenodo DOI 10.5281/zenodo.20252036)。对社区搜索/推荐排序而言，若已在用统一 token 排序骨干，这是低成本提升表示表达力与放大效率的可借鉴改造。

Discrimination Is Generation: Unifying Ranking and Retrieval from a Tokenizer Perspective

生成式推荐的 Semantic ID (SID) 决定了个性化上限，但现有 tokenizer 用检索目标独立训练，使个性化信号与 SID 构建完全解耦，导致生成式检索持续落后于判别式排序。论文提出洞见：排序是在 item 空间求 argmax、检索是在 token 空间求 argmax，本质同一问题不同粒度。据此提出 DIG，把 tokenizer 嵌入判别式排序模型做端到端训练，排序器自然变成检索模型，一次训练得到排序与检索两个模型；在 3 个公开基准 + 2 个工业数据集上同时提升排序、检索及统一检索-排序质量。

INSIGHT用 feature assignment taxonomy 把 SID 构建与排序目标端到端绑定，破解「tokenizer 与个性化解耦」这一生成式检索的结构性短板。对搜推统一架构的启示：检索（召回）与排序不必是两套独立模型与目标，可由同一 tokenizer 端到端导出，一次训练产出两阶段模型，降低离线-在线不一致与维护成本。

From Head to Tail: Asymmetric Knowledge Transfer in Long-tail Recommendation with Generative Semantic IDs

Alibaba

电商长尾推荐受困于数据严重不均衡，且头尾 ID 间存在知识迁移的非对称性——尾部 ID 的噪声会损害头部 ID 的表示学习。AKT-Rec 用多模态 LLM (MLLM) 经 SFT 对齐内容表示与协同信息，生成 item/user 语义表示，再用 RQ-VAE 离散化为语义 ID 形成相似实体的语义簇；含 Cluster-Guided Adaptive Embedding 等组件做非对称知识迁移。Tmall 在线 A/B 取得 CTR +2.76%、GMV +3.47%，离线 AUC +0.35%、GAUC +1.53%。

INSIGHT明确建模头尾知识迁移的非对称性（防止尾部噪声污染头部表示），是对「语义 ID + 协同信号」融合范式在长尾/冷启动场景的精细化改进。对社区 UGC（天然长尾、冷启动多）的启示：用 MLLM 生成语义 ID 把内容多模态信息引入协同表示，并以语义簇为粒度做自适应迁移，是缓解新内容冷启动的可借鉴路线，且已有真实电商 A/B 收益佐证。

BlossomRec: Block-level Fused Sparse Attention Mechanism for Sequential Recommendations

序列推荐 (SRS) 中 Transformer 标准注意力随用户交互历史变长导致算力与显存激增，而已有高效注意力/SSM 方法对长序列建模不足、在短序列上表现不稳。BlossomRec 设计 block-level 融合稀疏注意力：把用户兴趣分为长期与短期，用两种不同的稀疏注意力模式分别计算，再经可学习门控融合输出，从而在不同长度序列上保持稳定性能；在 4 个公开数据集上取得相当或更优效果并显著降低显存。

INSIGHT用「长期/短期兴趣分而治之 + 门控融合」的稀疏注意力，兼顾长序列效率与短序列稳定性，回避了单一稀疏模式在短序列上掉点的通病。对需要建模长行为序列的推荐/搜索排序有参考价值：稀疏注意力不必全局统一，可按兴趣时间尺度设计不同稀疏模式，在工业级长序列建模中平衡效果与成本。

Building a privacy-preserving Federated Recommender system for mobile devices

移动端个性化传统上需把敏感用户数据汇聚到中心服务器，与隐私法规冲突。论文提出两阶段联邦推荐流水线：第一阶段在云端用非敏感 app 上下文数据跑协同过滤生成候选 shortlist；第二阶段在端侧用敏感移动上下文信号对候选重排，仅模型更新/梯度离开设备。在 MovieLens、UCI HAR 及自有 pilot 数据集上验证，并交付可部署到 Android/iOS 的 Kotlin Multiplatform 生产级库。

INSIGHT以「非敏感数据云端召回 + 敏感数据端侧重排」的职责切分，把隐私边界落到具体两阶段架构，而非泛泛的联邦学习口号。对受隐私合规约束的推荐场景的启示：召回与重排可按数据敏感度分层部署，端侧只做轻量重排、只回传梯度，是在不集中敏感数据前提下保留个性化能力的工程化方案。

Controlled Personalization in Legacy Media Online Services: A Case Study in News Recommendation

传统新闻媒体在个性化上谨慎，常将编辑精选内容与算法选择内容混合，论文称之为 controlled personalization（受控个性化）。作者在一家挪威主流传统新闻机构网站上做 A/B 测试评估其效果，发现即便是适度个性化也带来显著收益：被推送个性化内容的用户点击率更高、导航成本更低，同时提升内容多样性与目录覆盖、降低流行度偏置。

INSIGHT用真实 A/B 证明「编辑精选 + 算法推荐」的混合受控个性化在保守内容平台同样有效，且适度个性化即可见收益。对社区内容平台的启示：个性化不必一步到位全量算法接管，可在保留人工/编辑信号的前提下渐进引入算法推荐，兼顾 CTR/导航效率提升与多样性、流行度偏置控制，降低上线风险。
