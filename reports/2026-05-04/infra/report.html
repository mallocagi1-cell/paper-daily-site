Unifying Sparse Attention with Hierarchical Memory for Scalable Long-Context LLM Serving

针对长上下文 LLM 推理在 KV 缓存膨胀下成为成本和延迟瓶颈的问题，论文提出 SPIN 框架，将多种稀疏注意力算法与分层 KV 存储进行系统级协同设计。SPIN 包含三大组件：统一的稀疏分区抽象（兼容 token 级、block 级、cluster 级稀疏度）、面向 GPU 的局部性感知 KV 缓存管理器，以及两层级元数据布局来减少元数据访存开销。在多种长上下文工作负载上，SPIN 相对 vLLM 实现 9× TTFT 降幅，请求率越高优势越明显。

KEY INSIGHT · 对业务意味着什么稀疏注意力与分层存储原本是两条独立优化路线，SPIN 将二者统一为执行流水线的一等公民，是面向长 query 召回与多文档 LLM rerank 的关键参考。社区搜索若将多帖串联给 LLM 判官打分，长上下文 KV 是首要成本项；统一抽象意味着不必为不同稀疏算法重写调度，能直接复用 vLLM/SGLang 的部署形态。可借鉴的是其元数据两层布局——把热数据元数据驻留在 GPU、冷数据元数据下沉到 CPU，避免元数据本身成为新瓶颈。

Scalable Inference Architectures for Compound AI Systems: A Production Deployment Study

Salesforce

Salesforce 系统披露其 Agentforce 与 ApexGuru 等复合 AI 系统的生产部署架构：把多模型扇出、检索器、工具调用编排到自适应推理平台上，处理峰值 1.4M req/天、2,250 RPS、21 个全球区域。相对前一代单 GPU 端点的部署，新架构 P95 延迟降低 50%+，吞吐提升 3.9×，成本下降 30-40%。论文系统性总结了多模型 fan-out 开销、级联冷启动、SLO 路由等真实工程痛点和对应缓解策略。

INSIGHT这是 2026 年少见的把复合 AI 系统生产指标和坑位完整披露的案例。社区搜索若开始把召回-排序-LLM rerank-LLM 解释串成 pipeline，多模型 fan-out 与冷启动成本会很快成为主要矛盾。可借鉴：按 SLO 类别分池调度、预热模型常驻 + 长尾按需弹起、以及把 P95 而非 P50 作为容量规划锚点。文中提出的 30-40% 成本节约更多来自架构层而非单模型优化，对决策投资策略很有启发。

Srikanta Prasad S V, Utkarsh Arora

ZipCCL: Efficient Lossless Data Compression of Communication Collectives for Accelerating LLM Training

HKUST(GZ)HIT-Shenzhen

ZipCCL 是一个在 Megatron-LM 与 TorchTitan 之上即插即用的无损通信压缩库，针对分布式 LLM 训练中 AllReduce/AllGather 占比高的问题。三大创新：基于 LLM 张量近高斯分布特性提出有理论支撑的指数编码、设计访存友好的 GPU 压缩/解压 kernel、根据负载动态切换集合通信策略。在多个工业规模训练任务上把通信时间最多降 1.35×，端到端训练加速 1.18×，且不影响模型质量。

INSIGHT通信压缩此前多用有损量化，常常牺牲收敛性；ZipCCL 把无损压缩做到 1.35× 增益是工程突破。其指数编码的洞察——LLM 梯度/权重张量大体上服从高斯——意味着压缩比可以从张量统计直接预估，不需要经验调参。对自研训练栈的团队，相比直接换硬件 NIC 升级带宽，软件层的无损通信压缩可以零迁移成本拿到 18% 训练吞吐。社区搜索的 reranker pretraining 若上千卡量级，这个收益足以覆盖一次集群扩容。

Wenxiang Lin, Xinglin Pan, Ruibo Fan, Shaohuai Shi, Xiaowen Chu

04 3.80

AMPD: Efficient Multi-round LLM Inference over Disaggregated Serving

Peking UniversityOceanBaseCambridge

AMPD 把 prefill-decode 解耦的思路扩展到多轮对话/Agent 场景：核心是按实时负载自适应地决定 prefill 在何处执行、如何调度，并配套资源分配规划算法满足 SLO goodput。基于 NVIDIA Dynamo 与 NIXL（RDMA P2P 传输库）实现，在多轮 Agent 工作负载下相对静态 PD 解耦显著提升 SLO goodput。

INSIGHTPD 解耦是 LLM serving 标配，但多轮场景下 KV cache 跨 prefill 节点搬迁的成本成为新瓶颈，AMPD 的实时调度恰好解决这个问题。社区搜索的 LLM 阅读理解/对话式问答属典型多轮场景，且后续轮次的 KV 大量复用前轮，AMPD 的思路（前轮 prefill 节点动态切换 + RDMA 直传 KV）非常契合。可借鉴的工程点：把 NIXL 这类 RDMA 传输库纳入 serving 栈底座，比走以太网拉 KV 能把跨节点延迟从毫秒级降到亚毫秒级。

Wenhao He, Youhe Jiang, Penghao Zhao, Quanqing Xu, Eiko Yoneki, Bin Cui, Fangcheng Fu

DUAL-BLADE: Dual-Path NVMe-Direct KV-Cache Offloading for Edge LLM Inference

Sogang UniversityFSU

DUAL-BLADE 提出双路径 KV 驻留框架：动态把 KV tensor 分配到 page-cache 路径或 NVMe 直访路径。NVMe 直访绕过文件系统，配合应用层批写/批读和 SSD 内部并行度，把 KV offload 的开销从硬件层根治。对边缘端低显存设备，端到端延迟最多降 42.4%，SSD 利用率提升 2.2×。被 IEEE ICDCS 2026 接收。

INSIGHT传统 KV offload 走文件系统，syscall 与 page cache 抖动都吃延迟；DUAL-BLADE 把 KV 视作裸块设备读写，是从存储栈层级而非显存层级思考的少见尝试。对中端 GPU + 大 NVMe 的部署形态（社区搜索的中等流量、对长尾延迟敏感的检索-排序混部场景）有直接借鉴价值。配合 io_uring 与 SPDK 这套异步 I/O 栈，可以做到 KV 加载与解码计算重叠，避免长尾抖动击穿 SLO。

Bodon Jeong, Hongsu Byun, Youngjae Kim, Weikuan Yu, Kyungkeun Lee, Jihoon Yang, Sungyong Park

Meituan LongCat-Next: 原生多模态大模型与训练/推理框架协同优化

Meituan

美团技术团队介绍 LongCat-Next 原生多模态模型的工程实践：训练侧基于扩展的 DORA 框架做大规模多环境强化学习，推理侧与 SGLang 团队合作完成模型路径优化（前缀缓存、推测解码、MoE 路由对齐），并把图像/语音/文本端到端离散分词器与模型一并开源，让外部团队能复现整套部署形态。

INSIGHT国内大厂里美团把训练/推理协同优化讲得最透的一篇案例。两个亮点：一是开源离散分词器配合开源模型，让多模态推理的部署门槛骤降；二是 LongCat 团队和 SGLang 做的路由对齐——让 MoE 的专家选择策略与前缀缓存命中率联动，避免缓存失效导致 TTFT 抖动。社区搜索若引入 LongCat-Lite（68.5B / 激活 2.9-4.5B）做 query 改写或多模态搜索的 backbone，能直接吃到这些工程红利，无需自己改 SGLang。

Meituan LongCat Team

LLM-Guided Runtime Parameter Optimization for Energy-Efficient Model Inference

Virginia Tech

论文提出一种 LLM 辅助的 human-in-the-loop 推理参数调优流程：增强的提示模板让聊天 LLM 迭代建议 batch size、并发度、量化精度等运行时参数。相对 baseline 提示，增强模板平均 3.4 次提示就能收敛（baseline 5.2 次），单 token 能耗持续低于 baseline，并击败传统 Sobol 采样基线。

INSIGHT把 LLM 当作启发式搜索器去调推理超参是个轻量化思路，比 Sobol/网格搜索更省，比强化学习更易上线。社区搜索的多模型 serving 集群里，每个模型/卡型/上下文长度组合都需要单独调参，LLM 辅助流可以把 SRE 从重复调参中解放出来。但实际落地需要把 LLM 的搜索结果与可观测性指标（GPU 利用率、KV 缓存命中率、TTFT 分布）反馈闭环，否则容易停留在 demo。

Katelyn Crumpacker, Dimitrios Nikolopoulos

Multi-Head LatentMoE and Head Parallel: Communication-Efficient and Deterministic MoE Parallelism

ASU

Multi-Head LatentMoE 把 MoE 模块和注意力的 head 维度耦合：每个 head 拥有独立的 router 与 expert 集合，构成完全独立的 MoE 模块。配合 Head Parallel 并行策略，得到 O(1) 通信复杂度（与 top-k 无关）、完全均衡的 expert 流量、确定性通信。端到端训练相对标准 MoE 提速最多 1.61×，模型质量持平。

INSIGHT此前 MoE 训练的 top-k all-to-all 通信是负载不均衡 + tail latency 来源，论文用架构-并行联合设计绕开这个问题——用 head 维度天然均衡 + 确定性路由。社区搜索若计划自研 MoE rerank 模型，head 级独立 MoE 是相对 expert-only MoE 更可调度的选项；缺点是参数总量上升，需要权衡 head 数与 expert 数。文中确定性通信意味着 profiler 数据可以直接复用，工程价值不可低估。

Chenwei Cui, Rockwell Jackson, Benjamin Joseph Herrera, Ana Maria Tarano, Hannah Kerner

LAER-MoE: Load-Adaptive Expert Re-layout for Efficient Mixture-of-Experts Training

Peking UniversityByteDance

LAER-MoE 提出 Fully Sharded Expert Parallel 范式：允许在每个 iteration 都按当前负载重新分配 expert 到设备的 layout。把 re-layout 与 FSDP 的参数预取、梯度 reduce-scatter 融合到同一通信窗口，使重排不引入额外内存。在 A100 集群上相对现有 MoE 训练系统加速最多 1.69×，且不依赖额外 token 重路由。

INSIGHTMoE 训练负载不均衡是工业级痛点，常规做法是冻结一段 layout 再算 token reroute；LAER-MoE 选择更激进的方向——layout 本身按 iteration 重排，但通过通信复用避免代价。来自 PKU + 字节，意味着工程合理性较高。社区搜索若用 MoE 做 query intent 分类或多场景 reranker，按数据集流分布动态 re-layout 能避免特定 expert 长期空闲；但配套需要稳定的负载预测器，否则 layout 抖动会反过来吃通信吞吐。

Xinyi Liu, Yujie Wang, Fangcheng Fu, Xuefeng Xiao, Huixia Li, Jiashi Li, Bin Cui
