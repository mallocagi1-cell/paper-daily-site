1. PBSD: Privileged Bayesian Self-Distillation for Long-Horizon Credit Assignment
3.85
Relevance 4 | Novelty 4 | Practical 3 | Evidence 4 | Timely 5

Summary: 针对多轮搜索 agent 的长程信用分配难题——轨迹级奖励只验证最终答案对错，无法判断中间哪一步推理或工具调用真正有贡献（成功轨迹里可能混入误导动作，失败轨迹里可能藏着有价值的取证步骤）。PBSD 用“特权贝叶斯自蒸馏”把答案侧难估计的后验/先验概率比，经贝叶斯公式转成标准 student 模型与“已知答案”的特权 teacher 模型之间可计算的似然比，再按自回归分解得到每一轮的信用信号。在 Qwen3-30B-A3B MoE、最长 300 轮交互的设置下，BrowseComp 相比 GRPO 提升 +3.50（hard 子集 +4.75），域内验证 +2.62。

Key insight: 把稀疏的 outcome 奖励重写成 turn-level 的贝叶斯校准信用，且完全兼容标准 policy optimization，不改训练框架就能插进现有 RL pipeline。对做 agentic search / deep research 的团队，关键启示是“短上下文训练→长上下文推理”的迁移有效（64K 训练、256K 评测），不必在超长轨迹上直接训也能拿到收益；turn-level reweighting 思路也可迁到多轮检索改写、工具选择的奖励塑形上。

2. Hardening Agent Benchmarks with Adversarial Hacker-Fixer Loops
3.80
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: agent benchmark 普遍用人工编写的 outcome verifier 打分，脆弱且容易被 reward hacking。作者审计了 5 个 terminal-agent benchmark 的 1968 个任务，发现 323 个（16%）仅凭任务描述就能被前沿模型钻空子，污染排行榜与 RL 训练信号。提出 hacker–fixer–solver 三 agent 交替的循环：hacker 试图不解题就骗过 verifier，fixer 打补丁堵每个漏洞，solver 确认补丁后合法解仍能通过。在 KernelBench 上把已公开 exploit 的攻击成功率从 62% 压到 0%；Terminal Bench（77 任务）从 39% 降到 17%。

Key insight: 最反直觉的发现是“弱模型能防住强模型”——用 Gemini 3 Flash 跑 loop，就能把更强的 Gemini 3.1 Pro、Claude Opus 4.7 的攻击成功率打到 0%。对自建 RL 奖励/相关性评估体系的搜索团队，这套自动化加固 verifier 的范式直接可用：与其每个 case 人工打补丁，不如让 hacker agent 持续挖洞、fixer 持续收紧奖励边界，防止线上 reward model 被刷分。

3. Reasoning Arena: Trace Tournaments When Verifiable Rewards Fall Short
3.55
Relevance 3 | Novelty 4 | Practical 3 | Evidence 4 | Timely 5

Summary: RLVR（可验证奖励强化学习）常在 group 层面失效——同一 prompt 采样的所有轨迹拿到相同奖励时，group-relative advantage 没有梯度，即便这些轨迹推理质量差别很大。Reasoning Arena 把这类“零优势”组路由给 judge 做 trace tournament：每条新轨迹只与动态维护的少量 anchor 轨迹两两对比，再用 Bradley-Terry 模型在不完全对比图上拟合排序，避免 O(n²) 比较。在竞赛数学与代码 benchmark 上平均超过 RLVR 基线 +7.6%（AIME 2026 +12.9 分），训练加速 27%–41%，省下近 50% 生成算力。

Key insight: 把原本被丢弃的 zero-advantage 样本（约 43%–47% 的组）变成有用梯度，是 RLVR 训练效率的实在杠杆。对训练搜索/推理 agent 的团队，启示是奖励稀疏不等于无信息——可用轻量 pairwise judge + Bradley-Terry 从“看似一样好/一样差”的轨迹里榨出相对偏好；anchor pool + 增量比较的设计让 judge 成本可控，适合接入大规模 RL。

4. Experience Makes Skillful: Enabling Generalizable Medical Agent Reasoning via Self-Evolving Skill Memory
3.55
Relevance 3 | Novelty 4 | Practical 3 | Evidence 4 | Timely 5

Summary: 医疗 agent 要在连续病例中复用经验，但现有 memory 多保留冗余、嘈杂的原始 trace，且分不清哪些记忆对未来推理真正有用。SkeMex 是部署后自进化框架，不更新模型权重，把有信息量的交互轨迹蒸馏成结构化“技能”（可复用的程序性知识），按 general / task-specific / action-level 组织成多分支仓库；用环境反馈估计 context-dependent utility 做 value-aware 检索与仓库治理，并以“读—写—评—治理”的生命周期持续演化。在 9 个临床 benchmark 上，DeepSeek-V3.2 平均比 ReAct +7.88 分（48.20%→56.08%），Qwen 上 +10.59 分，OOD 泛化 +13.78 分。

Key insight: 关键设计是给记忆打“效用分”并据此 promote/删除，而不是无脑堆历史，缓解了 agent memory 越用越脏的通病。对做对话搜索、客服/导购 agent 的团队，可借鉴“把成功轨迹蒸馏成技能而非存原文”的思路：技能可跨 backbone 迁移、在线持续更新（epoch@1→epoch@3 稳定上涨），且无需重训模型，落地成本低。

5. VisualLeakBench: Reproducible Action-Boundary Propagation Failures in Vision-Language Agents
3.55
Relevance 3 | Novelty 3 | Practical 4 | Evidence 4 | Timely 5

Summary: 视觉-语言 agent 在写入 memory、发消息、调工具前会先“看”截图、文档、UI，由此产生一类具体失效：action-boundary propagation——图像里的敏感/不安全文本被原样复制进下游工具参数。作者构建 VisualLeakBench（500 张图，覆盖 UI/聊天/文档/表单/仪表盘 5 类场景），在 4 个生产级 VLM 系统、note capture 与 external handoff 两种工作流下评测。基线下 PII 文本有 78.8% 被传进工具参数，渲染的不安全文本达 85.5%；加防御性 system prompt 后 PII 降到 2.0%，但不安全文本仍有 52.6%，且主要靠“抑制工具调用”而非保住可用性。

Key insight: 防御提示词对 PII 有效却几乎压不住渲染型不安全文本，说明“提示词补丁”不是安全边界。泄漏率还与工具类型相关——search-like 工具能抑制 PII 传播，但不安全文本仍会越界。对要上线多模态搜索/导购 agent 的团队，这是个现成的红队 benchmark：在 agent 把视觉内容写入工具调用的“边界”处做过滤，比在响应端兜底更有效。

6. Decoy-Calibrated Failure Audits for Language Models
3.45
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 模型审计不仅要知道失败率，更要定位失败集中在哪——但审计者会试很多候选解释（长输入、间接提问、干扰证据……），最大效应可能只是“试得多了碰上的最优”，存在 selection 偏差。Janus 给每个 descriptor（误差解释）算 error-rate lift，再与频率相同但随机分配的 decoy 对比：只有在发现集上击败 decoy floor、且在独立 held-out 数据上复现，才确认为真发现。多表查找的受控审计里 Janus 准确定位了植入失效（LLM 常在查找链中途停下）；在 MuSiQue 与 LongBench v2 上，固定阈值报 20 个高误差点，decoy floor 只留 1 个，holdout 检验把最后那个也否掉（lift 从 0.36 缩到 0.05）。

Key insight: 这是把统计显著性纪律引入 LLM 失效归因的方法——“提出解释”和“上报解释”要分开。对用 LLM 做相关性评估、bad case 归因的搜索团队很实用：很多看似显著的“模型在 X 类 query 上更差”的结论，可能经不起 decoy + holdout 双重检验。MuSiQue/LongBench 这类多跳检索场景正是 RAG 失效分析的常见对象，方法可直接迁移。

7. Evaluating Advanced Prompting on Gemini Flash for Multi-Hop Biomedical QA
3.20
Relevance 3 | Novelty 2 | Practical 4 | Evidence 3 | Timely 5

Summary: 围绕 MedHopQA 多跳生物医学问答，作者对 Google Gemini 2.0 Flash 做纯 API 评测，考察 prompt engineering 的影响。为 Gemini 2.0 Flash 设计了组合 role-playing、显式 multi-shot CoT 样例、详细格式规则的复杂 prompt，最佳运行的 Concept Level Score 达 0.720，显著超过基线。

8. Detection and Interpretability Analysis of Quotation Errors by Large Language Models
3.10
Relevance 3 | Novelty 3 | Practical 3 | Evidence 2 | Timely 5

Summary: 引文错误指引用信息与原始来源不一致，人工核验费时低效。论文提出“引文错误自动检测”任务，用 LLM 微调来做，并在数据集构建上引入被引文献全文，对比三种全文整合方式找最优方案；再用 TokenSHAP 做可解释性分析。结果显示微调 LLM 能提升检测性能，全文整合里“用来源摘要”的方案效果最好。

Key insight: “把来源摘要而非全文塞进上下文效果最好”这个发现对 RAG 的证据组织有直接参考——更多原文不等于更好，精炼的来源摘要可能让校验更准。对做带引用/出处的搜索答案（如社区问答 RAG）的团队，可借鉴这套“检测引用与来源是否一致”的思路做答案可信度校验；不足是摘要未给出具体指标数字，证据偏薄。

9. OmniGameArena: A Unified UE5 Benchmark for VLM Game Agents with Improvement Dynamics
3.00
Relevance 2 | Novelty 3 | Practical 3 | Evidence 4 | Timely 5

Summary: VLM agent 在交互式游戏里的评测通常只报单次首发分、只测 Solo、且不同 agent 类别无统一协议。OmniGameArena 用 12 款新建 UE5 游戏（Solo 7、PvP 3、Coop 2）+ 统一动作接口，并提出 Improvement Dynamics Curve（IDC）：一个 tool-using reflector LLM 在多轮里自主精炼有界的技能 prompt。除冷启动分外，IDC 还暴露两个观测量——分数随反思轮次的演化、以及学到的技能在 held-out 变体上的表现。在 12 个 VLM agent 冷启动 + 4 个 top agent 的 IDC 评测中，反思带来 +130%~+437% 的生存任务提升。

Key insight: 最有价值的发现是“origin-task 提升与 held-out 迁移会背离”——一个 agent 在原任务 +201% 却在所有变体上负迁移，另一个仅 +130% 却全部正迁移，说明技能的“风格”比提升幅度更重要，且峰值常出现在反思中段而非最后一轮。对评测搜索/推荐 agent 自我改进能力的团队，IDC 这种“看改进曲线和迁移性而非单点分数”的协议值得借鉴；业务相关性偏低（游戏域），主要作方法论参考。
