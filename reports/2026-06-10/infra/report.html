End-to-End Context Compression at Scale

长上下文 LLM 推理的瓶颈是 KV cache 随上下文长度线性膨胀。论文重新审视 encoder-decoder 压缩路线：先做架构搜索、从零预训练多个变体确定最优设计，再持续预训练一族 0.6B encoder + 4B decoder 模型（每个用 350B+ token），支持 1:4、1:8、1:16 三档压缩比。提出的 Latent Context Language Models (LCLMs) 把长 token 序列映射为更短的 latent embedding 序列交给 decoder 消费，在通用任务性能、压缩速度、峰值显存三个维度上推进 Pareto 前沿，并能作为 long-horizon agent 的高效 backbone——先略读压缩上下文、再按需展开相关片段。

KEY INSIGHT · 对业务意味着什么相比逐 query 压缩 KV cache 的主流做法，encoder-decoder 把压缩成本前置到预训练，推理时直接吃 latent embedding，因此天然兼容现有生产推理引擎、且不受目标模型上下文窗口限制——这正是过去 encoder-decoder 压缩难落地的两个硬伤。对社区搜索里用 LLM 做长文档 RAG / query 改写的场景，1:8~1:16 压缩比意味着同样显存能塞下更长的检索上下文；'略读+按需展开'的 agent 用法也契合多轮检索式问答。代价是要从零预训练专门的压缩模型，自研门槛高，更现实的是等其放出 checkpoint 直接用。

FlashMemory-DeepSeek-V4: Lightning Index Ultra-Long Context via Lookahead Sparse Attention

常规 LLM 解码时把完整 KV cache 常驻显存，超长上下文 serving 时显存成为硬瓶颈。论文提出 Lookahead Sparse Attention (LSA)：基于 DeepSeek-V4 架构构建一个 Neural Memory Indexer，主动预测未来会用到的上下文、只把 query-critical 的 KV chunk 保留在显存。关键是 backbone-free 解耦训练——把 indexer 建成标准 dual-encoder，用常规检索训练框架独立训练，全程不把巨大的 backbone 载入显存。最终把平均物理 KV cache 占用压到全量基线的 13.5%，在 500K 上下文下 KV 抑制超过 90%，同时在 LongBench-v2、LongMemEval、RULER 上平均精度还 +0.6%。

INSIGHT把'该看哪些历史 token'建模成一个可独立训练的检索问题，是这篇的关键拆解：indexer 不依赖 backbone 前向、用 dual-encoder + 标准 retrieval loss 训练，训练成本和主模型彻底脱钩。对搜索团队的启示是 KV 稀疏化可以直接套用我们熟悉的召回/双塔范式来做，而不必改动主模型本身。13.5% 的 KV 占用、500K 下 >90% 抑制说明长上下文 serving 的显存账可以显著重算。局限是方案绑定 DeepSeek-V4 架构，迁移到其它模型需要重训 indexer。

Yan Wang, Qifan Zhang, Jiachen Yu, Tian Liang, Dongyang Ma

Model Quantization: Turn FP8 Checkpoints into High-Performance Inference Engines with NVIDIA TensorRT

NVIDIA

NVIDIA 这篇工程博客讲怎么把一个 FP8 量化 checkpoint 落地成高性能 TensorRT 推理引擎，五步流程：PyTorch 模型 → ModelOpt 量化 → 导出 ONNX(opset 20+) → trtexec 构建 engine → 部署推理。ModelOpt 导出时把权重侧 quantize-dequantize 对折叠成 FP8 存储的 DQ-only 链，text encoder 的 ONNX 体积缩 34%、image encoder 缩 50%。构建 engine 必须加 --stronglyTyped 强制 FP8 执行，但要先手动把 attention scaling 里的 FP32 initializer/Cast 改回 FP16 才能兼容。在 RTX 6000 Ada 上相对 FP16 基线推理延迟降 1.39~1.45×，GEMM 因 FP8 Tensor Core 提速 >2×。

INSIGHT这是一份可直接照搬的 FP8 部署 checklist，对要在 GPU 上压低 serving 成本的搜索/排序模型很实用：关键坑是 --stronglyTyped 与 ModelOpt 的 FP32 attention scaling 冲突，需手动回退到 FP16，否则 FP8 执行不会生效。硬约束也要记牢——FP8 矩阵乘只在 Ada 及更新架构（compute capability ≥8.9）上支持，老卡白搭。1.39~1.45× 的端到端加速 + 34~50% 的体积下降，是把 FP8 checkpoint 真正变成线上引擎能拿到的量级，可作为评估 LLM/encoder 量化上线收益的基准参考。

Accelerating Federated Learning Research with AI Agents and NVIDIA FLARE Auto-FL

NVIDIA

FLARE Auto-FL 让 AI agent 在受约束的框架内自动探索联邦学习策略。它用 program.md 作为 control plane 定义研究边界，agent 只能改被许可的参数——学习率、optimizer、聚合规则(FedAvg/FedProx/SCAFFOLD)、架构选择——同时保持 FL 协议契约不变；每个候选在固定训练预算下同条件运行，结果写入 results.tsv ledger；当进展停滞时 agent 转去查文献、提出契约安全的新候选。实验上 CIFAR-10 有可量化提升，医疗 VLM(Qwen3-VL LoRA) 三个联邦站点把 FedAvg 基线的 token 级 F1 从 0.580 提到 0.589，增益集中在更难的 OOD 数据集上。

INSIGHT对搜索/推荐团队真正可借鉴的不是联邦学习本身（社区搜索一般用不到），而是这套'带护栏的 agent 自动调参实验'范式：用一份 program.md 把 agent 能改的搜索面收窄到安全集合、所有 run 落到统一 ledger、停滞时用文献而非盲目 sweep 来扩展候选。这套结构可以迁移到排序/召回模型的自动超参与结构搜索上，比无约束的 agent 调参更可控、可复现。局限是当前效果增益很小(F1 +0.009)，更多是流程框架的价值而非指标突破。
