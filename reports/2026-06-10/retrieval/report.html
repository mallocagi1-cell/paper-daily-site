1. End-to-End Context Compression at Scale
3.80
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 针对长上下文推理中 KV cache 随长度线性膨胀、现有 KV 压缩要么大幅掉点要么压一条长 prompt 太慢的问题，提出 Latent Context Language Model (LCLM)：用 Qwen3-Embedding-0.6B 作 encoder 把长 token 序列映射成更短的 latent 向量，再交给 Qwen3-4B-Instruct decoder 消费，每个压缩比各从头预训练 350B token。在 4×/8×/16× 压缩比下，16× 时 RULER 4K/8K/16K 分别为 75.06%/70.23%/65.91%，在精度-延迟-显存三维上超过 SnapKV、KVzip、Expected Attention 等 KV 压缩基线、构成新的 Pareto frontier；单卡 H200 上 TTFT 明显快于 KV 压缩，16× 时峰值显存在 128K–512K 区间趋于平稳。

Key insight: encoder-decoder 压缩此前被认为打不过 KV cache 压缩，这篇靠从头预训练做架构搜索把差距补平，给"把召回到的长文档高效喂给 LLM"提供了一条与生产推理引擎兼容的路线。对社区搜索里用 LLM 做相关性判断或答案生成的链路，用一个 0.6B 的 embedding 模型把召回长文压成 latent、再交给 4B decoder，能在 16× 压缩下把多数任务掉点压在个位数，值得在 RAG 排序/生成环节做对照实验。

2. FlashMemory-DeepSeek-V4: Lightning Index Ultra-Long Context via Lookahead Sparse Attention
3.55
Relevance 3 | Novelty 4 | Practical 3 | Evidence 4 | Timely 5

Summary: 针对超长上下文解码时全量 KV cache 常驻显存的瓶颈，提出 Lookahead Sparse Attention (LSA)：在 DeepSeek-V4 上构建 Neural Memory Indexer，预测后续 token 的上下文需求、只在显存里保留 query 关键的 KV chunk。关键做法是把 indexer 设计成标准 dual-encoder 检索结构、用现成检索训练框架独立训练（backbone-free 解耦训练，单张 H20 GPU 一小时收敛、一周可做约 500 次训练）。在 LongBench-v2、LongMemEval、RULER（最长 512K）上平均 KV 用量降到基线的 13.5%（省 86.5%，500K 时省约 90%），平均精度 77.5% 对基线 76.9%，LongBench-v2-L(493K) 70.0% 对 68.1%，RULER-512K 89.6% 对 88.3%。

Key insight: 把 KV 选择直接当成稠密检索问题、用 dual-encoder + 检索训练栈来做记忆索引，是把搜索/检索技术迁移到 LLM 推理侧的典型案例——indexer 不必加载巨型 backbone 就能独立训练，工程上极轻。但作者也报告局限：在 MRCR 这类需要密集全局记忆的任务上精度从 76.0% 掉到 48.0%，且长度泛化只到训练上下文的 2 倍。对做 embedding/召回的团队，这说明检索式稀疏注意力适合"长尾稀疏命中"、不适合"全局密集召回"。

3. RACT: Retrieval Augmented Column-Table Learning and Prediction for Multi-Table Schema Matching
3.20
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 5

Summary: 多表 schema matching 中，语义相近的列常分布在上下文迥异的表里，纯相似度方法不够用。RACT 提出自监督的 Retrieval Augmented Column-Table 学习：先对 source 列做候选表的概率检索，用 top-t 表约束相关列的候选空间，再做列匹配。实验显示这种"先检索候选表、再约束列搜索空间"的做法相比相似度基线，把平均匹配精度和完整度最高提升 +70%。

Key insight: 可借鉴点是"用检索把候选空间收窄、再做精细匹配"——这与搜索系统多阶段召回-精排里"先粗筛候选、再约束精排范围"的结构同构。把列匹配建成 retrieval-augmented 任务、用 referential context（表间引用关系）作检索信号，对需要跨结构化来源做语义对齐的场景（如 UGC 里表格/结构化字段的归一）有参考价值。

4. Driving Video Retrieval for Complex Queries with Structured Grounding
3.20
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 5

Summary: 自动驾驶数据检索要找的不只是场景、还有 cut-in、急刹等动态事件，纯 vision-language 或关键词检索常因运动信息没被文本描述而漏召，规则检索又脆弱。STRIVE-D 用弱标注的域内视频估计某条 query 规则何时可靠、对不匹配的规则做自适应，再把校准后的规则分与 vision-language、关键词检索信号融合。在含 DrivingDojo 新人工标注事件数据的三个驾驶 benchmark 上，top-1 准确率相对 SOTA 最高提升 84%。

Key insight: 可借鉴的是"对规则信号做可靠性校准、再与语义/词面信号加权融合"的混合检索框架。社区搜索同样有词面匹配、语义向量、人工规则/运营策略三类信号，STRIVE-D 用数据估计每条规则的可信度、而不是硬上规则，给"规则+模型"混排提供了一种数据驱动的权重分配范式。

5. PulseBench-Tab: A Multilingual Benchmark for Table Extraction with Graph-Based Evaluation
3.00
Relevance 2 | Novelty 3 | Practical 3 | Evidence 4 | Timely 5

Summary: 面向文档图像的表格抽取评测，PulseBench-Tab 收录 1,820 张人工标注表格，覆盖 9 种语言、4 种文字系统（含 CJK），取自 380 份金融申报、政府报告等真实文档，单表 2–1,183 个单元格、48.1% 含合并/跨行列单元格。同时提出 T-LAG 评测指标：把表格建成单元格邻接的有向图，用最优二部图匹配在单一分数里同时刻画结构与内容保真度。基于此评测了 9 个商用/开源表格抽取系统并给出分语言结果。

Key insight: 对做多语言/CJK 文档理解的搜索团队，T-LAG 这种"把结构正确性和内容正确性统一进一个图匹配分"的评测思路，比只看 cell-level 准确率更能反映下游可用性。含合并单元格的真实多语言评测集也提醒：在含表格/结构化片段的 UGC 内容上，现成抽取系统的跨语言表现差异不小，召回前的结构化解析不能想当然。
