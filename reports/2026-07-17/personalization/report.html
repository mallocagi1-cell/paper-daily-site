TMallGS: Scaling Unified Feature and Sequence Modeling for Generative E-commerce Search

针对工业 CTR 排序把异构特征一律 token 化后出现的信号稀释问题，TmallGS 组合分布校准投影、字段自适应门控 Transformer、FiLM 晚融合、偏差解耦与渐进训练。在 5 亿级天猫搜索样本上，离线 AUC、GAUC 分别提升 1.12%、1.26%；30 天线上实验使 UCTCVR 提升 1.38%、GMV 提升 1.52%。

1. 问题与动机

天猫搜索精排正在从传统 DLRM 转向计算密集型 Transformer，但直接照搬 LLM 的“全部 token 化”并不适合工业排序。搜索输入同时包含 query、候选商品、用户超长行为序列、统计特征、显式匹配分和位置等偏差特征，它们的分布、维度和更新频率差异很大。OneTrans 一类统一骨干把这些信号塞进同一个注意力流后，高频且强判别的显式交叉信号容易被深层注意力的低通效应稀释；传统 DLRM 又受稀疏 embedding 随机访存限制，现代 GPU Tensor Core 利用率低，继续加宽 MLP 很快遇到 scaling ceiling。论文因此提出一个更具体的问题：能否在保留异构特征归纳偏置的前提下，把精排主干改造成可预测扩展、能高效吃算力且满足线上延迟约束的 Transformer。

实验数据也体现了这一难点：天猫搜索日志覆盖连续 31 天、约 5 亿样本、1300 万用户和 7400 万商品，用户序列平均长度为 1500，显著高于常见工业设置的 200 以内。前 30 天共 4.84 亿样本用于训练，第 31 天 1600 万样本用于测试，严格按时间切分。模型既要在超长行为中抽取兴趣，又不能损伤同一 query 会话内候选的相对次序，这也是论文将 GAUC 作为主要离线指标的原因。

2. 方法详解

TmallGS 的第一步是“分层分布校准 token 化”。对第 i 个字段的序列矩阵，先做 Field-wise Saliency Reweighting：池化字段得到摘要，经一个轻量 squeeze/excitation 式网络产生字段内显著性权重，再逐元素重标定原特征；随后 Distribution-Calibrated Projection 不使用重型 SwiGLU，而是按字段统计分布投影到统一维度。该组合相对 SwiGLU-FFN 将投影 FLOPs 降低约 33%，性能差距小于 0.03%。不同字段仍保留独立投影，不会因统一维度而丢失来源信息。

第二步构造异构序列，将 query、上下文、候选商品和用户行为按字段组装。候选商品同时评分时使用 Context-Dominant Visibility Mask：公共上下文可以被所有候选读取，候选之间则隔离，避免同一 batch 内的信息泄漏。主干的每层采用 Per-Field Q/K/V 投影，让不同字段学习各自的语义变换；Noise-Adaptive Gated Attention 再根据 token 内容控制注意力输出，抑制长行为序列中的噪声和 attention sink。移除门控后 GAUC 下降 0.16%，说明它不是装饰性模块。

第三步是 Decoupled FiLM Late Fusion。显式交叉、匹配分等高频信号不穿过所有 Transformer 层，而是在主干产生语义表示后，以缩放和偏移的方式调制表示。与简单拼接相比，FiLM 的乘性调制更能恢复精排所需的强交互；去掉 FiLM 时 GAUC 下降 0.32%，改为加法拼接也下降 0.24%。Context-Aware Bias Net 则单独用全局上下文估计系统性偏差，使位置、曝光等偏差信号与真实用户意图解耦。

训练采用 Error-Aware Progressive Training：根据层级预测误差动态加权困难样本，并联合 pointwise 与会话内 pairwise 排序目标。消融中去掉 pairwise loss，GAUC 下降 0.87%，但全局 AUC 基本稳定，清楚说明会话内排序目标不可替代。为继承历史稀疏 embedding，论文先冻结稀疏表、对齐新稠密主干，再端到端联合微调；两阶段 warm-up 相比直接加载带来 AUC +1.42%、GAUC +1.09%。训练运行在 16 张高性能 NVIDIA GPU 上，全局 batch size 4096，学习率 2e-4；稀疏参数用 Adam，稠密 Transformer 与 MLP 用 AdamW，以适应两类参数不同的收敛与正则需求。

线上模型没有盲目追求十亿参数。Scaling-law 分析后，作者优先增加序列长度而非层数，最终配置为 4 层、hidden size 1024、8 个头、序列长度 1500，稠密主干约 0.05B 参数。这个“浅而宽、长上下文”的形态能提高 GPU 并行度，并将新增平均延迟控制在 6ms。

3. 核心技术贡献

第一，论文把“统一架构”重新定义为共享计算骨干而非抹平所有字段。字段独立 QKV、分布校准投影和显式信号晚融合共同保留异构性，使 Transformer 既能做全局交互又不会吞掉排序领域的强先验；相对生产基线，离线 AUC 与 GAUC 分别提升 1.12% 和 1.26%。

第二，方法将扩展效率与排序正确性一起设计。FSR+DCP 降低约 33% 投影 FLOPs，Context-Dominant Mask 防止多候选泄漏，门控注意力抑制长序列噪声，解决了只扩模型但 MFU 和精排质量不同步的问题。

第三，两阶段 warm-up 与拆分优化器为旧 DLRM 迁移到计算密集主干提供了可执行路径。它不是从零训练一个孤立模型，而是显式处理海量历史 embedding 与新主干的流形错位，因此更适合已有生产系统渐进替换。

第四，论文用 30 天线上实验验证架构收益，而非只报告离线 AUC。最终 GMV +1.52%、UCTCVR +1.38%，说明 scaling-law 导向的主干在严格 SLA 下能够转化成商业指标。

最关键的结果不是某一个离线百分点，而是各项消融与设计动机一致。FiLM 的降幅最大之一，证明统一 Transformer 确实会稀释显式匹配；pairwise loss 对 GAUC 的影响远大于 AUC，说明全局点击预测好不等于同一搜索会话内排得好。FSR+DCP 在性能几乎不变时减少约三分之一投影计算，也说明效率优化没有靠牺牲精度换取。

5. 局限与未来方向

作者没有单列正式 limitations 章节，但在部署与结论中明确承认：高 QPS、低延迟搜索目前不适合直接部署十亿参数 LLM，因此线上只使用约 0.05B 的浅宽模型；公开数据集也缺少同时包含超长行为和 query-item 显式匹配的数据，实验只能在天猫私有日志上进行。论文计划继续探索十亿参数级扩展和多模态生成能力，但这会重新带来延迟、成本及在线稳定性问题。

论文未充分讨论的限制包括：所有结果来自单一电商平台，UGC、短视频或新闻推荐中的特征分布可能不同；30 天实验能证明短中期收益，尚不能回答长期兴趣固化、流行度偏差和生态多样性；Context-Aware Bias Net 的因果可识别性也未被验证，所谓“偏差解耦”更接近预测性正则而非严格因果校正。

6. 工业实践意义

对搜索/推荐团队，最值得采用的不是完整复制五个模块，而是三条迁移原则。第一，先按字段盘点信号：query 与内容语义适合深交互，位置、统计分和强交叉适合旁路晚融合，稀疏 ID 与稠密主干应使用不同优化器。第二，在扩深度前先扩有效历史长度；TmallGS 的线上选择是 4 层、1024 维、1500 序列，而不是更深模型，说明对行为建模，覆盖更长时间跨度可能比增加层数更划算。第三，离线必须同时看 AUC 与按会话分组的 GAUC，并保留 pairwise 目标，否则模型可能提高全局点击预测却破坏单次 query 下的候选次序。

对社区 UGC 搜索，可将帖子文本、作者、话题、互动统计和用户历史分别建字段；文本与历史进入门控 Transformer，BM25/语义匹配分、作者关系和时效分通过 FiLM 晚融合。上线应从 4 层级别的小主干开始，记录 MFU、P95/P99 延迟、GAUC、CTR 与停留时长，并按序列长度做 scaling sweep。需要避免两种做法：把所有特征无差别 token 化，以及只用全局 AUC 判断精排收益。若已有大型 embedding 表，优先复用论文的“冻结稀疏表对齐主干—联合微调”两阶段迁移，可显著降低替换旧模型的风险。

1. 问题与动机

增量视频搜索在用户每输入一个字符后都要刷新结果，1–3 字符前缀通常同时对应大量候选，纯词法相关性无法确定真实意图。传统个性化搜索依赖用户长期画像，但流媒体目录还面临新内容冷启动、行为稀疏、共享账号和曝光偏差：只用协同 ID 向量无法覆盖新片，只用文本向量又捕捉不到“文本看似不同但被同一群体共同观看”的关系。论文聚焦 Apple TV 搜索的这个低词法信息区间，提出一个务实问题：能否在不重建既有多阶段召回与 XGBoost 精排栈的前提下，用互补的语义和协同信号改善每次按键后的排序。

结果验证了问题选择：有历史用户的总体 NDCG@10 提升 2.99%、MRR@10 提升 3.30%，但 1–3 字符前缀的 NDCG@10 增益达到 8.63%，长查询仅 1.46%。也就是说，个性化不是所有 query 都应同等增强，而应在当前文本不足以区分候选时补足信息。

2. 方法详解

系统离线训练两个共享维度的 item embedding。TextEmb 是 Siamese 多语言文本编码器：标题、类型、演员/创作者、实体类别等字段分别定长 token 化，经同一个多语言 Transformer 编码，再拼接字段表示，通过 BatchNorm—Linear—ReLU—BatchNorm—Linear 投影头并 L2 归一化。编码器在训练中保持可更新，使通用语义表征适应媒体搜索。IdEmb 则完全不使用文本，以 item ID 查表得到高维向量，再经小型 MLP 投影到相同空间，专门学习共同观看和受众亲和关系。

两种模型使用相同的搜索日志训练样本。若两个内容在同一用户的搜索驱动互动历史中、指定时间窗内连续被观看或转化，就构成正样本；负样本来自当前 mini-batch。作者刻意不使用规模更大的通用播放日志，因为首页推荐和曝光会引入更强噪声。核心损失是 pairwise hinge loss：L=max(0, m-cos(phi(anchor),phi(positive))+cos(phi(anchor),phi(negative)))，要求正样本相似度至少比负样本高 margin m。TextEmb 使用多 GPU 混合精度训练多个 epoch，batch size 与学习率计划在验证集调优；论文未披露具体数值，这是复现上的信息缺口。

在线侧将两类 item embedding 离线计算并写入两个位置：按 item ID 索引的低延迟 KV 存储，以及搜索索引的文档元数据。用户历史也保存在定期刷新 KV 中，只保留长时间窗内有限数量的最近播放，剧集映射到母剧，重复内容只保留最近一次。查询时分别对历史内容的 TextEmb 和 IdEmb 做均值池化，形成两个用户向量，再计算用户—候选的两个余弦相似度。它们作为新增特征，与词法和行为特征一起输入现有 XGBoost rank:pairwise 排序器；无历史或退出个性化的用户把特征置为 missing，模型结构无需分叉。

混合设计同时承担覆盖与精度。TextEmb 对 session 和用户覆盖均为 100%；IdEmb 因未见 item 无法查表，session 覆盖 87.70%、用户覆盖 86.65%。约 12%–13% 的缺口由文本向量兜底。作者还构建了一个仅用于评估的 LLM 标注语料：从不同流行度分位均匀抽 anchor，根据标题、类型、演员等元数据判断内容相似性，以减少点击和曝光偏差；线上训练和服务均不调用 LLM。

3. 核心技术贡献

第一，论文把语义覆盖与协同精度做成并行信号，而非二选一。TextEmb 对新内容和长尾稳健，IdEmb 对头部、中腰部以及跨类型受众关系更准；最终精排而不是单一 embedding 指标决定是否部署两者。

第二，它提供了低侵入工业集成方式：用户向量只需均值池化，item 向量预计算并随索引返回，在线增加两项余弦特征即可继续使用成熟的 pairwise XGBoost。相较端到端重训大型序列模型，工程风险和延迟成本更低。

第三，论文系统展示了个性化收益的条件性。短前缀 NDCG 增益 8.63%，长 query 仅 1.46%；历史 1–5 条用户增益 2.13%，历史 51–100 条用户达 4.37%。这些切片比单一总体指标更能指导何时开启和增强个性化。

第四，三周用户级随机 A/B 证明离线增益能转化成业务指标：tap-through rate +1.14%，conversion rate +1.23%，转化内容平均排名改善 2.91%，两项主指标校正后 p<0.001。

用户历史切片也很重要。NDCG 增益从 1–5 条历史的 2.13% 单调增至 51–100 条的 4.37%，MRR 增益从 1.59% 增至 2.98%；与此同时长历史组的基线 NDCG 从 0.733 降到 0.680，说明个性化恰好在默认排序较弱的人群上贡献更大。三周 A/B 采用用户级等流量分组、单一区域、多主要客户端；点击率增益 1.14% 的 95% CI 为 [0.95%,1.32%]，转化率增益 1.23% 的区间为 [0.97%,1.50%]，均完全高于零。

5. 局限与未来方向

作者明确列出五点限制：线上实验只在一个区域进行，跨地区泛化尚未验证；离线数据仍受曝光偏差影响；稀疏历史用户收益小于丰富历史用户；均值池化无法建模时间动态和当前 session 意图；训练/服务偏移与 embedding 新鲜度会削弱离线到线上的一致性，因为在线历史更新和离线快照并不同步。IdEmb 对未见 item 没有表示也是结构性限制，虽然 TextEmb 提供兜底，但混合模型对纯冷启动 item 的高精度协同信号仍不存在。

未来工作包括序列化、query-aware 用户模型，多模态 item embedding，以及显式探索机制。论文未讨论的现实问题还包括共享账号会混合家庭成员偏好、LLM 标注语料本身可能继承模型偏差，以及均值池化在超长历史中会稀释近期兴趣。更复杂的用户模型应与额外延迟、状态更新频率和隐私成本一起评估。

6. 工业实践意义

这篇论文适合已有检索/排序栈、希望低风险加入个性化的团队。第一阶段可离线训练文本与 ID 两套 item 向量，把它们写入索引和 KV；用户向量先用最近历史均值即可，不必一开始就上大型序列 Transformer。第二阶段只向现有 GBDT/LambdaMART 增加两项余弦相似度，并保留 missing 值路径，保证无历史、隐私退出和冷启动用户仍走相关性优先的基础排序。第三阶段按 query 长度、历史条数和内容流行度做切片，而不是只看总体 NDCG。

对社区 UGC 搜索，TextEmb 可由帖子标题、正文、话题、作者简介等构建，IdEmb 从共同点击、收藏、评论或关注序列学习。短 query、歧义 query 和内容型探索 query 可提高个性化特征权重；导航型、明确实体 query 应让词法/语义相关性占主导，避免“越个性化越偏题”。上线指标至少包含 NDCG/MRR、点击率、转化或深度互动、首个有效结果位置，并监控新内容覆盖和历史新鲜度。最值得避免的是只比较两套 embedding 的单一离线准确率：论文证明语义标注会偏向 TextEmb，session 标签会偏向 IdEmb，真正的选择标准应是下游排序与在线实验。

POEM: Partial-Order Enhanced Real-Time Sequential Modeling for Recommendation 深度解读

1. 问题与动机

POEM 解决的是工业推荐中一个很具体的错位：序列推荐模型通常只看用户已经点击或观看过的静态时间序列，而真实的线上推荐系统每次请求都会由召回、粗排、精排产生大量实时排序信号，例如 pCTR、pCVR、观看时长预估和其他业务目标分。这些信号本质上表达了系统对用户当前偏好的“偏序判断”，但传统 SASRec、BERT4Rec、DIN/DIEN/MIMN 等模型只把新点击当作更新触发器。论文指出这会带来两个问题：第一，系统内部的多目标排序知识没有被召回模型使用；第二，用户兴趣在没有新点击时也会因候选池、上下文和排序策略变化而漂移，静态序列会滞后。作者把核心命题改成：用上一刷请求中 top-ranked candidate 的多目标分数来构造当前请求的输入序列，使用户向量每次请求都被重新评估。这个问题在短视频流和 UGC 信息流里尤其重要，因为内容池变化快、隐式反馈延迟明显，单靠历史点击序列会错过当前候选环境中的细粒度偏好。

2. 方法详解

POEM 的系统由双序列编码、动态偏序序列构造、多目标分数融合、层次化学习目标和实时 serving 闭环组成。训练和 serving 都使用两条序列：一条是用户最近行为构成的 historical interaction sequence，另一条是由上一刷请求的 top-ranked items 及其排序分构成的 dynamic partial-order sequence。对上一刷候选集合中的每个 item，系统拿到多个实时排序分，例如 CTR、CVR、watch time 等。由于不同目标量纲不同，作者没有直接平均，而是先对每个目标内部按分数排序，把名次转换成 inverse-rank utility，再按目标权重融合得到 fused score。候选按 fused score 排序后，被切成若干连续 group，并从每个 group 内随机采样，形成长度为 64 的偏序序列。这样既保留全局偏序，又避免完全确定排序导致的多样性不足。

序列表示上，每个偏序 item 被编码成 quintuple，其中包含 item id 与多目标相关连续特征；连续特征经线性投影，item id 查 embedding 表，然后送入 Transformer encoder。历史行为序列也由独立 Transformer encoder 编码，两边都追加 special token 聚合序列级信息。两个 encoder 不共享参数，最终把两个 special token 输出 concat 后过两层 MLP，得到最终用户向量，用于 ANN 召回。训练目标是 hierarchical objective：正样本既包括真实用户反馈正样本，例如长播视频，也包括系统偏好的 top-ranked item；负样本除 in-batch negatives 外，还从离线 Swing item-item 图中围绕正样本动态挖 hard negatives。损失由带采样偏差校正的 cross-entropy 和 margin-based pairwise loss 组成，让模型同时对齐真实满意度和下游排序器偏好。

Serving 设计强调因果性和低延迟。当前请求只读取用户历史序列和“上一刷”的 top-ranked item 及分数，这些信息存 Redis 等低延迟缓存；模型生成实时用户向量后做 ANN retrieval；当前请求经过下游排序后，再把结果和分数写回缓存，供下一刷使用。这个一请求周期的反馈闭环避免了使用未来信息，同时让用户向量在没有新点击时也会随候选池和排序信号变化而变化。

3. 核心技术贡献

第一，POEM 把排序信号从“监督目标”提升为“输入构造的结构先验”。以往使用 ranker 信号常见于蒸馏、listwise loss 或采样偏差校正，仍然是在训练目标层面对齐；POEM 直接用 ranker 产生的偏序来重写召回阶段的用户序列，使召回向量具有 cascade awareness。

第二，多目标融合采用 rank-weight 而非 raw score average，解决 CTR、CVR、watch time 等分数尺度不一致的问题。消融显示 Multi-Avg 的 HR@50 只有 0.5224，甚至低于 Single-WT 的 0.5820；Multi-Rank 达到 0.6661，说明排序名次归一化比简单均值更适合多目标系统信号。

第三，层次化正样本同时纳入 user-feedback positive 和 system-preferred positive。只用用户反馈会受曝光和延迟影响，只用系统偏好又可能只模仿 ranker；Dual-Pos 在 HR@50、NDCG@50、online gain 和 delivery rate 上都优于单一路径。第四，图挖 hard negative 让模型在相似 item 间学习细粒度边界，而不是只靠容易的随机负样本。

4. 实验结果分析

论文使用快手大规模工业数据，覆盖 1.08 亿用户、4200 万 item、27 亿训练样本、1300 万 1-hour test 样本和 4.57 亿 1-day test 样本。所有模型用 TensorFlow，在相同软硬件环境训练；AdamW 初始学习率 0.001，cosine annealing，batch size 1024；POEM Transformer 为 4 层、hidden dimension 128、1 个 attention head，偏序序列长度 64。

主表中，1-hour test 上 DSSM 的 HR@50/NDCG@50 为 0.4703/0.1778，SASRec 为 0.5267/0.2092，CAIN variant 为 0.5749/0.2371，POEM 达到 0.6661/0.3080；相对第二强 CAIN，HR@50 提升 15.9%，NDCG@50 提升 29.9%。在 1-day test 上，POEM HR@50/NDCG@50 为 0.4879/0.2100，相对 CAIN 的 0.4700/0.1923 提升 3.81% 和 9.19%。时间间隔分析显示，POEM 对实时性最敏感：[1h,2h) 的 HR@50 是 0.6661，对 CAIN 0.5749 提升 15.9%；到 [12h,24h) 时 POEM 0.4801、CAIN 0.4694，提升缩小到 2.29%。这证明上一刷偏序信号越新，价值越高。

线上 A/B 是 7 天实验，实验组和对照组各 5% 流量，对照为生产模型 Kuaiformer。KS Single Page 上 Total App Usage Time +0.254%、Usage Time per User +0.249%、Video Watch Time +0.237%；KS Lite Page 上分别为 +0.158%、+0.213%、+0.335%，且论文称均有统计显著性。消融方面，Hist-Only HR@50/NDCG@50 为 0.5808/0.2531，RankSig-Only 为 0.6511/0.3238，完整 POEM 为 0.6661/0.3079。RankSig-Only 的 NDCG 更高，说明它更像下游 ranker；完整 POEM 的 HR 更高，说明融合历史行为能扩大召回覆盖。正样本消融中，Only-FB HR@50 0.5661、online gain +0.161%、delivery rate 1.052%；Only-Sys HR@50 0.5966、online gain +0.132%、delivery rate 1.472%；Dual-Pos HR@50 0.6661、online gain +0.254%、delivery rate 1.845%。案例分析中，即便连续两刷之间没有新点击，偏序输入序列 diff ratio 达 96.8%，最终召回结果差异 86.2%，显示模型确实能随系统当前理解变化。

5. 局限与未来方向

论文没有单独的 limitations section，但从正文可以归纳出几类明确限制。第一，POEM 强依赖上一刷排序结果和多目标分数缓存，如果用户请求间隔过长或排序策略快速变化，偏序信号会过时；时间间隔实验中增益从 15.9% 降到 2.29% 已经说明这种衰减。第二，方法依赖完整的工业级排序级联与 Redis 类低延迟缓存，对只有简单召回/排序链路的小团队部署成本较高。第三，论文公开了大量指标，但没有开放数据和实现，外部复现难度大。第四，偏序序列来自已有 ranker，可能继承 ranker 的偏差；虽然历史序列能缓和纯模仿问题，但如何避免把旧 ranker 的流量分配偏差固化到召回阶段，仍需要额外探索。

6. 工业实践意义

对搜索/推荐从业者，POEM 最直接的启发是：召回模型可以消费排序链路已经产生的实时知识，而不必等用户产生下一次点击。UGC 社区搜索/推荐中，每次请求的候选集、query/session 上下文和内容新鲜度都在变，上一刷的 pCTR、完播、互动、质量分可以构造偏序序列，辅助生成更贴近当前会话的用户向量。落地时不必一次复刻 POEM 全部组件，可以先做三个小试验：一是缓存上一刷 top candidates 及多目标 rank；二是用 rank-normalized fusion 替代 raw score average；三是在召回训练中加入 system-preferred positive，看 delivery rate 和 downstream ranker 接受率是否提升。

部署上需要关注延迟、缓存一致性和目标漂移。POEM 的 serving 只用上一刷结果，工程上合理，但要求每次请求都能稳定写入和读取上一刷候选及分数；如果用户跨设备、跨场景行为混杂，还要设计场景隔离和过期策略。对业务指标而言，论文的线上增益看似小于 0.3%，但在 4 亿 DAU 级平台上已经很有价值；对中小规模系统，应该同时观察 CTR/nDCG、时长、内容多样性和长尾曝光，避免只优化 ranker 一致性而牺牲探索。
