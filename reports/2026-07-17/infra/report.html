OvisOCR2 Technical Report

OvisOCR2 是 0.8B 端到端文档解析模型，可按自然阅读顺序生成包含文本、公式、表格和视觉区域的 Markdown。训练流程先在 4B 分支进行监督微调与强化学习，再在线蒸馏到 0.8B；OmniDocBench v1.6 总分达 96.58，PureDocBench Avg3 达 75.06。

INSIGHT该工作表明“小模型部署、较大分支探索”的训练架构能兼顾推理成本与复杂文档质量。社区搜索若需摄取截图、长图或扫描 UGC，可把 0.8B 解析器作为离线内容理解前置层；真实落地应重点复测表格、公式和混排页面的失败率。

Shiyin Lu, Yinglun Li, Yu Xia, Yuhui Chen, An-Yang Ji

Scaling laws meet model architecture: Toward inference-efficient LLMs

Amazon

论文把隐藏维度、MLP/Attention 参数比例和 GQA 等架构变量加入 Chinchilla 条件 scaling law，并训练超过 200 个模型，覆盖 80M–3B 参数和 8B–100B token。相同训练预算下，搜索所得架构相对 LLaMA-3.2 准确率最高提升 2.1%，推理吞吐提升 42%。

INSIGHT与训练完成后再做量化相比，先用条件 scaling law 选择“准确率—吞吐”更优的骨干架构，能从源头降低长期服务成本。对 UGC 搜索中的生成式 query 理解或重排模型，可先用小规模模型族拟合曲线，再决定隐藏宽度、GQA 和 MLP 配比，避免只按参数量扩张。

Song Bian, Tao Yu, Shivaram Venkataraman, Youngsuk Park

Policy-Conditioned Constrained Decoding for Column-Level Access Control in Text-to-SQL

PCC-SQL 将列级策略细分为输出、过滤条件和聚合参数三种语义角色，并把角色约束对齐到解码器跟踪的语法产生式，通过逐 token logits mask 在单次解码中确定性阻断违规 SQL。3 个基准、3 个开源模型上泄漏率为 0%，Spider-CU 覆盖率最高 88.7%，token 开销低于 10%。

INSIGHT相比生成后审计，解码期掩码能把权限约束变成不可越过的生成边界，尤其适合运营检索、数据分析 Agent 等跨信任域服务。社区搜索内部若开放自然语言取数，可复用“语义角色—语法规则”映射；但支持的 SQL 子集、联表和嵌套查询必须单独做安全验证。

Ryoto Miyamoto, Xin Fan, Hayato Yamana

Reason Only When Needed: Efficient Generative Reward Modeling via Model-Internal Uncertainty

TencentUNSW

腾讯混元与 UNSW 提出 E-GRM，将奖励模型内部不确定性直接作为算力调度信号：低不确定样本走短路径输出，高不确定样本才启用完整思维链。该设计把“一律推理”改成逐样本动态路由，面向 ACL 2026 的奖励模型服务场景减少无效推理计算。

INSIGHT同一思路可迁移到搜索 query 理解和重排：先用轻量路径估计置信度，仅把歧义 query 或高价值请求升级到重推理模型。真正上线时要联合校准不确定性阈值、P95 延迟和 nDCG/CTR，而不能只看平均算力；当前二手解读未披露完整数值，应回到论文复核。

Tencent Hunyuan, UNSW

GigaWorld-Policy-0.5: A Faster and Stronger WAM Empowered by AutoResearch

GigaWorld-Policy-0.5 针对世界动作模型在推理时显式生成未来视频、难以实时闭环的问题，改为训练阶段联合建模未来视觉动态，部署阶段只解码动作。预训练混合 Action-Conditioned World Modeling 与 WAM 目标，以增强视觉动力学和动作表征耦合。

INSIGHT它体现了一条重要系统原则：昂贵辅助目标可留在训练期，在线路径只保留业务必需输出。虽然机器人任务与社区搜索距离较远，但生成式排序也可探索“训练时重建丰富上下文、服务时仅输出 item/query 决策”的非对称结构，降低在线解码负担。

Hybrid Serving Architecture with Cost-Benefit Routing for LLM-Based Recommendation Systems

该工业技术披露提出混合在线推荐架构，仅在后排序阶段对预期收益高于推理成本的请求调用 LLM，其余请求沿用传统模型路径。方案发表于 2026 年 6 月 30 日，核心是用成本—收益路由控制大模型调用范围，而非让所有候选都进入昂贵推理。

INSIGHT社区搜索可把该模式用于高商业价值、低置信度或强意图 query：传统召回和粗排维持全量吞吐，LLM 只处理少量候选。落地关键是建立可在线校准的收益预测器，并把 token 成本、P99 延迟与 nDCG/CTR 增益放入同一决策函数；该披露缺少公开实验数字。

Hallo4D: Multi-Modal Hallucination Mitigation for Consistent Spatio-Temporal Generation

Hallo4D 面向 3D/4D 生成中的结构复制、几何错位、抖动和身份闪烁，提出“生成—检测—修正”三阶段、模型无关框架。多模态大模型从多视角与多帧渲染中识别时空不一致，再由共识驱动的图像空间优化和候选选择器执行修正。

INSIGHT其可借鉴点不是具体 4D 模型，而是把大模型用于发现结构化失败，再由受约束优化器执行修复，避免端到端生成器独自承担一致性。对多模态 UGC 索引，可采用相似的检测—修正旁路检查跨帧标签和实体一致性；当前摘要未给出定量增益，部署成熟度有限。

Hongbo Wang, Huaibo Huang, Jie Cao, Jin Liu, Haoyang Tong
