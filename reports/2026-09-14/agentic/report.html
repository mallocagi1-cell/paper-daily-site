VikingRAG: Accurate and Token-efficient Retrieval-augmented Generation over Structured Documents

VikingRAG 针对结构化文档问答的多轮检索成本，将目录、摘要与文本块统一为可寻址对象，并按证据缺口调用检索工具。系统把历史检索路径保存为经验边，再按证据充分性决定是否升级多轮搜索。在六个数据集上，基础版仅消耗高准确率基线的11.6%–51.9% Token，增强版降至5.1%–32.5%，保持相近准确率。

VikingRAG 深度解读

原文：https://arxiv.org/html/2609.11390 。本解读依据正文第2至6节、表2至表7；数值保留论文口径，业务建议单独标明。论文评估的是结构化文档问答，不是社区搜索线上实验。

1. 问题与动机

结构化文档的答案经常分散在不同章节，单次向量召回未必能找到所有前提。已有方法利用目录、章节树和知识图谱补齐证据，但把完整目录交给模型会消耗大量上下文；从根节点逐层下钻也可能绕远路。VikingRAG希望同时保留多轮查证能力和低查询成本，把文档结构从提示词里的长文本，变成能按地址访问的外部状态。

作者具体比较了不同系统的访问方式：KohakuRAG有层级分块与索引，却没有把层级统一为可寻址对象；MoDora依赖从根开始的导航；DeepRead让代理自由导航，但先将候选文档完整目录放进提示词。VikingRAG用语义检索直接定位任意层级的入口，再只展开与当前证据缺口相关的局部区域。因此，节省的主要是没有必要提前暴露的结构信息，而非简单截短正文。

另一个动机是重复查询。相近问题经常需要走相似的跨章节查证路径，重新运行完整代理会重复支付决策、工具说明和历史交互的Token成本。作者将这些已走通的路径物化为经验边，再增加是否需要多轮查询的判断，分别处理“多轮怎么更省”和“这次是否需要多轮”两个问题。

2. 方法详解

系统首先将Markdown标题转成目录树；PDF和DOCX经转换后使用同一结构处理流程。每个文本块属于最细的结构节点，块大小受上限L约束。叶节点摘要由所属文本块生成，内部节点摘要由子节点摘要逐层汇总。目录节点、摘要和原始块都有唯一URI，URI路径前缀保留父子包含关系。向量索引同时收录摘要和文本块，并记录URI、对象类型、层级和预览。摘要承担导航功能，原始块仍是主要证据来源。

代理有四种互补访问工具：Search按语义返回候选及地址；List列举某个目录的内容；Grep在指定目录下做词法匹配；Read读取具体对象。工具共用URI，因此一次向量命中能成为结构导航入口，而目录地址也可以反过来限制下一次语义或词法搜索的范围。每轮状态包括用户问题、指令、模型先前输出、工具调用与返回结果；代理判断证据是否充足，不足则继续调用工具，达到预算后结束。这一设计不需要预先把完整目录塞入上下文。

基础版之上，VikingRAG-E从一次多轮检索轨迹中记录起始命中URI与实际支持答案的URI之间的联系，同时保存历史查询上下文和紧凑路径信息。新问题先做普通Top-K搜索，再从这些种子URI沿经验边扩展。论文公式25用新旧查询向量的余弦相似度决定是否激活边，默认阈值为0.8。扩展维护已访问集合和前沿，避免循环及重复访问。边是有方向的；系统额外保存反向记录，在删除节点时可以局部清除入边与出边。

VikingRAG-E+先执行单轮经验增强检索，然后运行证据充分性检查。检查提示要求先识别实体、时间、范围等关键约束，再选取直接证据逐项核对。只要信息不完整或含混就升级为多轮检索，而非仅根据语义相似度判定已经足够。这个检查是控制遗漏风险的关键：能够找到相关段落，并不意味着能回答问题中的全部条件。

本文没有提出需要重训主模型的损失函数、优化器或训练步数，主要贡献是检索系统和推理控制。默认实验使用通过API调用的DeepSeek-V4-Pro Preview，并以GPT-5.5、Seed-2.0和GLM-4.7重复关键实验。参数为K=10、分块上限L=1000、最大轮数B=15；这些是论文默认值，不应视为对所有UGC场景都最优。实验每个语料库还生成1000条独立历史问题预热经验边；正式测试问题、答案、元数据及改写不参与该构建过程。

3. 核心技术贡献

第一，语义入口与结构地址共用命名空间。它让代理从任意相关章节进入，再按局部需要读取邻近区域，避免完整目录预加载。正文表3显示基础版在六类数据上相对两种高准确率基线的Token占比为11.6%至51.9%。这是比较对象和数据集共同形成的范围，并不是每个数据集都节省同样比例，也不是相对所有RAG系统的统一优势。

第二，经验边保存的是历史使用路径，而非文档中的静态语义关系。知识图谱通常在入库时抽取实体关系，经验边则在查询后记录“从哪里开始、最终哪里提供了证据”。其激活还受当前查询条件约束，防止把过去有效的连接无差别用于所有请求。与基础版相比，仅加入经验边后，Token为原来的67.3%至88.1%，延迟为72.3%至91.5%。

第三，证据充分性门控将已积累的经验转成单轮回答机会。加入门控后，E+的Token进一步降至E版的49.8%至81.1%，延迟为73.1%至89.8%。这里的比较基准是E版，不能与上一段百分比直接相加。系统节省的不只是检索块长度，还有每次代理决策产生的交互历史成本。

4. 实验结果分析

正文使用六个结构化文档数据集，最大语料为FinanceBench的8.78M Token。VersionQA包含34份文档与100个问答；SyllabusQA有63份文档和4358个问答；QASPER有281份文档和945个问答；HotpotQA子集有991份文档和100个问答。LegalBench-cuad为462份文档与1000个问答，FinanceBench为84份文档与150个问答。特别需要注意，文中的HotpotQA评估是这个子集，不是整个公开基准。

答案正确性采用LLM判分并经专家核验，要求保留参考答案关键事实且不引入矛盾。该度量与nDCG、CTR不同。论文图3报告各方法端到端表现；此处不从图像猜测未读出的准确率小数，数值分析以明确可读的正文和表格为准。部分知识图谱基线未能在24小时内完成某些语料的入库，作者记为N/A；不能把这些缺失视为准确率为零。

充分性检查的消融提供了比总成本更关键的风险信息。表7中，VersionQA的错误不升级率由朴素提示的13%降到5%；QASPER由29.7%降到14.4%；FinanceBench由22.7%降到6.7%。HotpotQA从8%降到3%，对应正确判断率从90%升到93%。这些差异支持逐条件检查的价值，同时也显示QASPER还有明显遗漏风险。作者指出，错误不升级并不等比例转成最终准确率下降，因为其中一些问题即使升级也无法找到足够证据。这解释了整体准确率接近，却仍存在停止判断错误的现象。

经验边构建开销在六个数据集上每个历史查询约1.5至3.7秒。1000个历史问题生成的边数从12764到38540不等；测试问题与历史问题语义相似的比例约26.48%至60%。这些数字表明收益依赖工作负载重复性，不能只看热身后的平均性能。参数分析还发现，K=1不一定最省：由于单次证据过少，代理需要更多轮搜索，反而可能比K=10花更多Token。K过大、块过大或轮数预算过宽，同样会增加成本；碎片化过度也会导致额外检索。

5. 局限与未来方向

作者在实验讨论中承认，多数数据集的错误不升级率仍高于5%，充分性判断尚未完全可靠。文档插入阶段，VikingRAG需要生成对象预览，因此比DeepRead和MoDora消耗更多Token；其经济性建立在文档入库相对低频、查询反复发生的假设上。作者也说明，报告评估了经验边构建与存储开销，但不计生成或回答历史预热问题的成本，理由是部署时历史请求自然存在。对新上线且流量不足的产品，这个成本边界应重新计算。

以下是业务迁移推断：实验只评估文档文本问答，不能证明图片、视频评论或高度口语化短帖同样受益。UGC内容更新和删除频率高，过期经验边、权限变化及跨用户信息隔离需要额外验证。尽管URI删除维护有机制，论文没有给出社区高频编辑负载下的线上收益。冷启动、热门查询和长尾新查询应分别评估，避免总体均值掩盖体验退化。

6. 工业实践意义

对社区搜索，可先在“帖子—回答—评论串”或专题知识库建立稳定地址，把摘要用于导航、原文用于引用核查。第一阶段仅接入四类检索工具并记录轨迹，比较固定单轮与按证据缺口多轮的效果；第二阶段从确实被答案引用、人工抽检正确的路径构建经验边；第三阶段再加入逐约束充分性检查。这样的顺序有利于把结构寻址、经验复用和停止策略的贡献分开测量。这是基于论文机制提出的试验设计，并非作者报告的生产部署步骤。

试验指标应包括查询级证据覆盖、引用正确率、错误不升级率、P50/P95延迟和Token成本，同时用现有搜索评测集观察nDCG，并通过合适的线上实验测CTR。复杂咨询可能需要回答质量或任务完成率作为补充，不能用点击增加代替证据正确。论文没有公开UGC线上A/B结果，所以报告中不承诺点击或留存收益。

部署成本需要把入库摘要生成、向量索引、经验边记录与失效清理一起计算。对频繁删除的内容，利用反向记录及时撤销路径，并在Read前重新检查可见性；对新问题保留正常多轮检索回退。模型API可能带来网络与尾延迟，即使Token节省明显，也应实际测量响应时间。最值得先验证的设计，是让已验证的证据路径减少重复探索，同时对每个新问题重新检查其约束是否被满足。

AREX: Towards a Recursively Self-Improving Agent for Deep Research

BAAI

AREX 将深度研究拆成内层证据搜集与外层逐约束核验，并用自主上下文更新保存已证实事实和待解决约束。论文结合关键步骤监督与长程强化学习，提供4B和122B-A10B模型。正文消融中，自主上下文更新使 BrowseComp 单轮准确率从59.6升至71.4；完整训练设置为82.5，改用随机步骤监督后降至74.1。

CIVI: A Framework for Diagnosing Search Agent Failures in Civic Information

CIVI 研究搜索代理为何在公共事务问答中给出错误指引，构建覆盖跨国家、跨行政层级的评测框架。作者用来源注入消融形成 ARISE，将失败拆成四类，并比较搜索调用、无搜索回答和官方来源引用情况。评测的10个前沿搜索代理均未达到认真作答的人类基线，72.1%的失败被归为检索受限。

INSIGHT社区搜索可以借用来源注入消融：对失败问题直接提供正确帖子或权威证据，再观察答案是否恢复，从而区分找不到资料与读不懂资料。这个诊断比只看最终回答分数更利于定位召回、工具使用和证据利用问题；公共事务任务的72.1%比例不能迁移为 UGC 业务结论，仍需自建样本并联看 nDCG、CTR。

《Agent 评测白皮书》系列01：Agent 评测全览

Meituan

美团以商家经营分析 Agent 为例，梳理从冷启动到扩量、自进化的评测体系，将其概括为4个模块、3种能力、2条迭代回路和1套资产。线上异常样本经归因分别进入评测标准修订或 Agent 修复，再通过回归与线上实验验证。本文是工业方法论指南，未披露可复核的准确率或线上收益数字，证据质量据此保守评分。
