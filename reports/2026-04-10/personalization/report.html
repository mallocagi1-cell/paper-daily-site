The Unreasonable Effectiveness of Data for Recommender Systems

本文系统研究了推荐系统中训练数据量与离线推荐性能之间的关系。作者使用 LensKit 和 RecBole 两大工具包，在 11 个超过 700 万交互的公开数据集上评估了 10 种算法组合，训练数据量从 10 万扩展到 1 亿交互。实验结果表明 NDCG@10 随数据量增加持续提升，未观察到明显的饱和点——最大样本量下约 75% 的实验点同时达到了组内最优性能。这一发现对推荐系统的数据投资决策具有直接指导意义。

1. 问题与动机

推荐系统的数据采集、存储和处理成本持续攀升，但业界缺乏关于「数据量增加到何时会停止带来显著收益」的系统性实证研究。已有工作结论矛盾：部分数据剪枝研究报告了 3% 的性能提升，而另一些则建议不要剪枝。深度学习在大数据集上的能耗约为传统 ML 的 8 倍，但性能优势并未得到充分验证。这一知识空白直接影响推荐系统团队的数据投资决策——在环境成本（平均研究消耗约 6,854 kWh 电力）和人力成本日益增加的背景下，理解数据 scaling 行为至关重要。

2. 方法详解

数据集选择：11 个大型公开数据集，均包含 700 万以上交互记录，涵盖 MovieLens-25M（3200 万交互）、Netflix（1 亿+）、Last.fm、Alibaba-iFashion、Amazon 等。数据预处理统一移除时间戳、确保 user-item 对唯一性，存储为 Parquet 格式。

采样策略：提供四种采样方法（随机、用户分层、物品分层、混合分层），最终选用绝对分层用户采样（Absolute Stratified User Sampling），确保采样保持用户比例。样本量设定 9 个级别：从 10 万到 1 亿交互。

算法评估：使用 LensKit 2025.2.0 和 RecBole 1.2.1 两大工具包，共 10 种算法组合——LensKit 端包括 PopScorer、ItemKNN、ImplicitMF、BiasedMF、BiasedSVD；RecBole 端包括 Pop、ItemKNN、BPR、NeuMF、SimpleX。10 算法 × 11 数据集 = 110 个实验组。

评估指标：NDCG@10（Top-10 推荐的归一化折扣累积增益），纯离线评估。所有实验在 University of Siegen OMNI HPC 集群上执行，使用 GPU 节点。

分析方法：三层递进分析——(1) 原始 NDCG 随样本量变化趋势；(2) 组内 min-max 归一化后的分布分析；(3) 最后 10-30% 数据段的斜率分析（Late-Stage Slope Analysis）。

3. 核心技术贡献

贡献一：首个大规模系统性 data scaling 实证。覆盖 10^5 到 10^8 交互区间的 110 个实验组，规模远超此前零散的数据剪枝研究。可复现的 Python 评估流程（含代码）为后续研究提供了标准化基线。

贡献二：「无饱和点」的强实证。在测试范围内，NDCG@10 未观察到明显的饱和拐点。最大样本量下约 75% 的实验点同时达到组内最优，min-max 归一化后数据点密集聚集在 (1.0, 1.0) 附近。

贡献三：弱 scaling 行为的归因。明确指出弱 scaling 仅集中在非典型数据集（Last.fm、Alibaba-iFashion）和个别算法异常（RecBole BPR 因运行时配置限制表现异常），而非普遍现象。

Late-Stage Slope 分析：中位斜率约 1.0（正向），四分位范围 [0.0, ~1.5] 完全非负，仅 8 个实验点斜率为零。下须线约 -2.25（极少数回退），上须线约 3.5。

归一化分析的核心发现：当组内归一化后，最大样本量处的数据点绝大多数位于 (1.0, 1.0) 附近，表明「更多数据 → 更好性能」在绝大多数 group 中成立。

异常值分析：RecBole BPR 表现异常归因于运行时配置约束；Last.fm 和 Alibaba-iFashion 的弱 scaling 可能反映数据集特有特征（极度稀疏、交互模式不同）而非普遍规律。

5. 局限与未来方向

作者明确提出以下局限：(1) 仅离线评估——NDCG@10 不直接等同于线上用户行为或 A/B 测试结果；(2) 超参未充分调优——优先保证运行可行性而非峰值性能；(3) 探索范围有限——未测试 1 亿以上交互的区间，长期饱和行为未知；(4) 未覆盖深度推荐模型——SimpleX/NeuMF 是相对轻量的深度模型，GPT/Transformer-based 推荐模型的 scaling 行为可能不同。

此外，论文指出 GUI 变化可带来 6% CTR 提升，暗示小数据集上的性能波动可能受非数据因素干扰。

6. 工业实践意义

数据策略指导：对于采用传统推荐算法（协同过滤、矩阵分解、浅层深度模型）的团队，本文提供了「持续增加数据量仍有价值」的量化证据。这直接影响数据采集/存储预算决策——在 1 亿交互量级内，不应因假设饱和而削减数据投入。

算法选择参考：ItemKNN 类算法在多数据集上表现出最强的 data scaling 行为，而 BPR 在配置约束下表现不稳定，提示团队在资源受限时优先选择 scaling 行为稳健的算法。

环境成本意识：研究报告了约 6,854 kWh 的能耗数据，提醒团队在追求数据 scaling 收益时需权衡计算成本。建议先在子采样上评估 scaling 趋势再决定是否投入更大规模训练。

可复现框架：论文开源的评估流程可直接用于其他推荐场景的 data scaling 预评估，避免盲目扩大数据量。

CASE: Cadence-Aware Set Encoding for Large-Scale Next Basket Repurchase Recommendation

Walmart📖 有深读 · 7 分钟

Walmart 提出 CASE，一种面向大规模零售场景的复购推荐模型。CASE 的核心创新在于将商品级别的复购节奏（cadence）学习与跨商品交互解耦：用日历时间信号表示每个商品的购买历史，通过共享多尺度时间卷积捕捉周期性复购节奏，再用 induced set attention 以亚二次复杂度建模跨商品依赖。在三个公开基准和 Walmart 千万级用户生产数据上，CASE 的 Top-5 Precision 提升 8.6%、Recall 提升 9.9%。

INSIGHTCASE 最大的实践启示在于将「时间」从序列位置编码中解放出来——用真实日历时间而非访问顺序建模复购节奏。这种 cadence-aware 设计在电商、社区等有周期性消费/浏览行为的场景中可直接借鉴。此外，induced set attention 的亚二次复杂度设计使模型可在千万级用户规模下批量推理，证明了精细化时间建模与生产可用性可以兼得。Walmart 的大规模 A/B 结果增强了该方法的可信度。

1. 问题与动机

复购行为是零售推荐中的核心信号——大量用户的下一个购物篮中包含此前购买过的商品，且复购时间遵循稳定的商品特定节奏（如牛奶每周、洗衣液每月）。然而，现有 Next Basket Repurchase Recommendation（NBRR）模型将购买历史表示为按访问顺序索引的离散篮子序列，存在根本性缺陷：(1) 在第 1、8、36 天购买的商品与第 1、2、3 天购买的商品获得相同表示；(2) 两次购买间隔期内推荐无法动态更新；(3) 无法区分已逾期和尚未到期的商品。

现有方法的具体不足：KNN 方法（如 TIFUKNN）需要在推理时计算用户间相似度，在千万级用户规模下计算开销不可接受（O(|U|·d) per query）；先前的日历时间方法依赖用户级别的卷积滤波器和二次复杂度的物品交互模块，限制了生产环境的可扩展性。

2. 方法详解

日历时间历史表示：对每个商品 i，构建 T 天滚动窗口内的二值购买指示向量 h_i ∈ {0,1}^T，h_{i,t}=1 表示第 t 天购买了商品 i。这保留了精确的购买间隔信息。

多尺度时间 CNN：使用共享 Conv1d 滤波器在五个预设核尺寸上处理 h_i——7 天（周频）、14 天（双周频）、28 天（月频）、91 天（季度频）、182 天（半年/趋势）。每个尺度使用非重叠步长 stride=w，⌊T/w⌋ 个激活值在所有尺度上拼接后经两层 FC+ReLU 投影为 cadence embedding c_i ∈ R^{d_c}，d_c=128。

Induced Set Attention (ISAB)：将 cadence embedding 和物品 embedding e_i ∈ R^{d_e}（d_e=128）拼接为组合表示 x_i = [c_i || e_i]，输入 Set Transformer 编码器。使用两层 ISAB，K=32 个 induced points，H=4 注意力头。ISAB 将 O(n²) 的成对注意力降至 O(nK)，n 为用户候选商品数。

评分与训练：每个表示 z_i ∈ R^{d_h}（d_h=256）经两层 MLP 产生标量分数 s_i，按 s_i 排序推荐。训练使用 BCE 损失，下一个篮子中的复购商品为正样本。训练 30 个 epoch，Adam 优化器（lr=10^{-3}，weight decay=10^{-5}），batch size=64，ISAB 和 MLP 后 dropout=0.1。

关键设计选择：(1) 时间卷积滤波器跨所有用户共享（非用户级），大幅减少参数量；(2) 使用 induced points 而非完整 self-attention，使复杂度与候选集大小线性相关而非二次；(3) 解耦 cadence 学习与跨商品交互——CNN 独立捕捉每个商品的时间节奏，ISAB 处理商品间的互补/替代关系。

3. 核心技术贡献

贡献一：日历时间 vs 序列索引的问题重构。论文明确指出 basket-index 公式化是阻碍生产部署的结构性限制，提倡以日历时间节奏作为更优的建模基础。这一重构使模型能在两次购买之间动态刷新推荐。

贡献二：可扩展的 cadence 学习架构。通过共享多尺度 CNN + induced set attention 的组合，实现了显式日历时间建模与生产级可扩展性的兼得。推理复杂度 O(n(T+K))，与用户总数无关。

贡献三：嵌入依赖降低。消融实验表明移除物品 embedding 仅导致 1.75% 的 Precision 下降，说明 cadence 信号本身已携带大量信息，减少了对频繁刷新的大规模 embedding 表的依赖。

贡献四：首个 NBRR 的生产级评估。在千万级用户规模上的评估表明 CASE 在工业环境中可行，而非仅限于学术基准。

5. 局限与未来方向

作者指出以下局限：(1) 依赖历史日历时间戳，缺失时间戳时需重建相对日期，可能引入噪声；(2) 在数据密集的场景（如 Instacart）上增益相对较小，暗示当历史信息足够丰富时 cadence 的边际收益递减；(3) 尚未进行在线 A/B 测试——论文明确提到「online A/B test is planned to validate offline gains on user-facing metrics」。

此外，模型仅处理复购推荐场景，对全新商品（无历史购买）的推荐需要与其他冷启动方法结合。

6. 工业实践意义

直接可借鉴的设计：多尺度时间卷积的思路不限于购物篮推荐——任何有周期性行为模式的场景（社区平台的周期性浏览、视频平台的观看节奏、音乐平台的收听习惯）都可套用。核心思想是「用真实时间间隔而非事件序号建模行为节奏」。

生产部署友好：推理复杂度 O(n(T+K)) 与用户总数无关，这对千万级 DAU 平台至关重要。共享权重设计避免了用户级参数爆炸。

减少 embedding 依赖：消融显示 cadence 信号本身携带大量信息，这启示团队在 embedding 基础设施受限时可以优先投入时间建模。

Walmart 的工业验证：在千万级用户上 +8.6% Precision / +9.9% Recall 的提升具有显著业务价值，表明 cadence-aware 设计在真实工业环境中可行且高效。但需注意该评估为离线指标，在线效果有待 A/B 验证。

Leveraging LLMs and Heterogeneous Knowledge Graphs for Persona-Driven Session-Based Recommendation

NestPipe: Large-Scale Recommendation Training on 1,500+ Accelerators via Nested Pipelining

Huawei

NestPipe 是面向万亿参数推荐模型的大规模去中心化嵌入训练框架，解决了 1500+ 加速器集群上训练推荐模型时的数据移动瓶颈。框架通过嵌套流水线设计利用两层稀疏并行机会：批间层面用 Dual-Buffer Pipelining 构建无 staleness 的五阶段流水线缓解 lookup 瓶颈；批内层面基于 embedding freezing 现象设计 Frozen-Window Pipelining 重叠通信与计算。在保持同步训练语义的同时大幅提升吞吐量。

INSIGHTNestPipe 的核心发现——embedding freezing 现象（训练过程中嵌入参数逐渐趋于稳定）——具有独立的学术价值，为推荐模型的训练优化提供了新视角。对于大型推荐系统团队，NestPipe 的分层流水线思想可借鉴：在不同粒度上分别优化数据移动瓶颈，避免吞吐量与训练一致性的 trade-off。该工作在华为 Ascend 集群上验证，展示了 NPU 在推荐训练场景的适用性。

Leveraging Artist Catalogs for Cold-Start Music Recommendation

本文将冷启动音乐推荐重新定义为「半冷启动」问题——大多数新曲目来自有历史交互的艺术家，因此可利用艺术家级别的协同过滤信号。作者发现 artist-aware 方法可将 Recall 提升超过 2 倍。核心方法是学习从艺术家目录特征到协同过滤潜空间的映射，利用艺术家与曲目之间的层次结构，而非简单地将艺术家信息当作普通输入模态。实验在多个公开数据集上验证了这一思路的有效性。

INSIGHT「半冷启动」这一问题框架值得推广到其他推荐场景——在 UGC 社区中，新帖子往往来自有历史的作者，可直接套用相同思路：利用作者级别的协同信号缓解内容冷启动。艺术家-曲目的层次建模方法可推广为创作者-内容的层次建模。该工作 2 倍以上的 Recall 提升表明，充分利用已有的层次关系是低成本高收益的冷启动解法。

EviSnap: Faithful Evidence-Cited Explanations for Cold-Start Cross-Domain Recommendation

EviSnap 是一个轻量级跨域推荐框架，其预测结果自带忠实且可审计的证据引用解释。核心方法包括：(1) 离线用 LLM 将噪声评论蒸馏为紧凑的 facet cards，每个 facet 配对原始支撑句子；(2) 通过聚类 facet embeddings 构建跨域共享的概念库；(3) 用证据加权池化计算用户正/负偏好和物品概念激活。整个推荐仅需单层线性分类器，实现了解释性与效率的统一。

INSIGHTEviSnap 的亮点在于将可解释性作为系统设计约束而非事后附加——通过 concept bank 将推荐理由内嵌于模型结构中，避免了 post-hoc 解释与实际决策不一致的问题。对搜索推荐系统的启示：在跨域推荐或冷启动场景，利用 LLM 离线蒸馏用户评论为结构化 facets，既可缓解冷启动又提供可审计的推荐理由。线性分类器的选择也意味着极低的线上推理成本。

TREASURE: The Visa Payment Foundation Model for High-Volume Transaction Understanding

Visa

Visa 推出 TREASURE，首个面向高频交易数据的多用途 Transformer 基础模型。模型同时捕捉消费者行为信号和支付网络信号（响应码、系统标志），支持异常检测、个性化推荐等多种下游任务。架构设计包括静态属性和动态属性的专用子模块，通过预训练获得通用的交易表示。在 Visa 工业级数据集上验证了模型在多任务场景下的有效性。

INSIGHTTREASURE 展示了 Transformer 基础模型在非传统推荐数据（交易流水）上的应用范式，核心设计思想可迁移到搜索推荐领域：(1) 将静态特征和动态行为序列分别建模再融合的架构设计适用于任何有用户画像+行为序列的场景；(2) 多任务预训练策略（同时捕捉用户行为和系统信号）可作为构建社区内容理解基础模型的参考。Visa 的工业部署经验也表明这类基础模型在实际业务中是可行的。
