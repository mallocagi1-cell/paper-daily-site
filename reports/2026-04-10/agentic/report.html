1. Multi-Turn Reinforcement Learning for Tool-Calling Agents with Iterative Reward Calibration
4.25
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 针对多轮工具调用 agent 训练中奖励稀疏和信用分配困难的问题，本文首次将 MT-GRPO（多轮 Group Relative Policy Optimization）与 GTPO（Generalized Token-level Policy Optimization）结合用于训练工具调用 agent。核心创新是提出 Iterative Reward Calibration（迭代奖励校准）方法论，通过对 rollout 数据的系统性分析，发现朴素设计的逐轮密集奖励会因奖励区分度与优势方向的错位导致性能下降高达 14 个百分点。实验在真实客服任务上验证，MT-GRPO V3 搭配稀疏��励提升 +10pp，叠加迭代奖励校准后达到 69.5%（+11.5pp）。

Key insight: 该工作揭示了多轮 agent 训练中一个违反直觉的发现：逐轮密集奖励反而比稀疏奖励更差，根本原因在于奖励信号的区分度方向与策略优势方向不一致。Iterative Reward Calibration 通过经验性判别分析消除了这一错位，为搜索/推荐系统中的对话式 agent（如多轮检索、问答引导）提供了可直接复用的奖励设计范式。实践中应先用稀疏奖励建立基线，再谨慎引入密集奖励并校验其区分方向。

2. Beyond Stochastic Exploration: What Makes Training Data Valuable for Agentic Search
4.15
Relevance 4 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 当前基于 RL 的搜索 agent 依赖随机探索和精心设计的结果奖励进行训练，导致推理轨迹低效、训练不稳定。本文提出 HiExp（Hierarchical Experience）框架，从训练数据质量而非策略探索角度优化 agentic search 的 RL 训练。核心思路是构建层次化的经验库，分层管理不同粒度的搜索经验，让 agent 从高价值轨迹中学习而非随机采样。该框架显著提升了搜索 agent 在复杂推理任务上的训练效率和最终性能。

Key insight: 本文将 agentic search 训练的瓶颈从「策略优化」转移到「训练数据筛选」，指出不是所有搜索轨迹都有学习价值。HiExp 的层次化经验管理思路对搜索系统的 LLM agent 训练具有直接借鉴意义：在构建搜索 agent 时，与其投入大量算力做随机探索，不如先投资于高质量��索轨迹的收集和分层策略。这一发现改变了 agentic search 训练的优先级排序，值得搜索团队关注。

4. SubSearch: Intermediate Rewards for Unsupervised Guided Reasoning in Complex Retrieval
3.90
Relevance 4 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 面向复杂查询需要多步推理但无预定推理路径的检索场景，提出 SubSearch 方法，通过中间奖励引导 LLM 在无监督条件下进行复杂检索推理。核心思路是在强化学习框架中引入检索中间步骤的奖励信号，而非仅依赖最终检索结果的稀疏奖励，从而指导模型学习有效的多步检索策略。该方法无需预标注推理路径，适用于推理结构未知的开放式检索任务。

Key insight: SubSearch 解决的核心痛点是「无监督条件下的复杂检索推理」，对搜索系统极具实践价值。在 UGC 搜索中，用户的复杂查询常需要多步推理（如先理解意图、再分解子查询、再综合结果），但标注推理路径成本极高。SubSearch 的中间奖励机制提供了一种无需人工标注即可训练多步检索 agent 的思路，尤其适合查询意图模糊、需要渐进式检索的社区搜索场景。

5. Tool Retrieval Bridge: Aligning Vague Instructions with Retriever Preferences via Bridge Model
3.85
Relevance 4 | Novelty 3 | Practical 4 | Evidence 3 | Timely 5

Summary: 当前工具检索方法基于学术基准中过度详细的指令（如具体 API 名称和参数），但真实场景的用户指令更加模糊。本文提出 Bridge Model（桥接模型），对齐模糊用户指令与检索器偏好之间的语义鸿沟。桥接模型将模糊的自然语言指令转化为检索器更易匹配的结构化查询表示，无需修改底层检索模型即可适配真实场景。实验表明该方法显著提升了模糊指令下的工具检索准确率。

Key insight: 该工作揭示了工具检索中「学术基准与真实场景」的巨大鸿沟：现有方法在详细指令上表现良好，但在模糊指令上急剧退化。Bridge Model 的架构设计（指令增强而非检索器重训）对搜索系统有直接启发——在 UGC 搜索中，用户查询同样模糊且非结构化，可借鉴「桥接层」思路在查询理解和工具/API 调用之间增加语义对齐模块，提升 agent 对模糊查询的处理能力。

Key insight: 该基准揭示了 LLM 工具调用从「实验室」到「真实场景」的三大差距：组合编排、隐式意图和��令过渡。对于搜索 agent 的开发者，最有价值的发现是「隐式意图推断」——真实用户很少给出完整的工具调用指令，agent 需要从对话上下文中推断需要调用哪些工具以及调用顺序。这与 UGC 搜索中用户查询意图模糊的痛点高度一致，为搜索 agent 的评测设计提供了清晰的维度框架。

7. SEARL: Joint Optimization of Policy and Tool Graph Memory for Self-Evolving Agents

Summary: 针对自演化 agent 学习中策略优化与工具记忆脱节的问题，提出 SEARL 框架，联合优化策略模型和工具图记忆（Tool Graph Memory）。核心思路是将工具使用经验组织为图结构记忆，agent 在 RL 训练过程中同步更新策略网络和工具图，实现策略与工具知识的协同进化。相比依赖大规模 LLM 或多 agent 框架的现有方法，SEARL 更适合在资源受限条件下部署。

8. Reason in Chains, Learn in Trees: Self-Rectification and Grafting for Multi-turn Agent Policy Optimization
3.60
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 针对多步推理任务中 RL 训练受稀疏奖励制约的问题，提出 T-STAR（Tree-structured Self-Taught Agent Reasoning）算法。现有方法如 GRPO 将采样轨迹视为独立链，对所有步骤分配均匀信用，忽略了对推理结果影响不成比例的关键步骤。T-STAR 将轨迹组织为树结构，通过自纠正和嫁接操作在关键分叉点探索替代路径，实现步骤级的信用分配和策略优化。

Key insight: T-STAR 的树结构轨迹探索理念对多步搜索 agent 有重要启示。在多轮检索任务中（如复杂 query 的分步检索），某些中间步骤（如关键 query 改写决策）对最终结果影响远大于其他步骤。T-STAR 的「嫁接」机制——在关键步骤复用已有成功经验、在非关键步骤进行新探索——可为搜索 agent 的训练提供更高效的样本利用策略，避免在低影响步骤上浪费探索预算。

9. Act Wisely: Cultivating Meta-Cognitive Tool Use in Agentic Multimodal Models
3.60
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 当前 agentic 多模态模型存在深层「元认知缺陷」：无法判断何时应依赖内部知识、何时需要调用外部工具，导致盲目调用工具（即使查询可直接从原始上下文中回答）。这种病理行为引发严重的延迟放大和准确率下降。本文提出培养 agent 元认知能力的方法，使其学会在内部知识和外部工具之间做出合理的策略性裁决。

Key insight: 「盲目工具调用」是当前搜索/检索 agent 的普遍问题——许多查询本可通过模型内部知识直接回答，但 agent 仍会触发检索或工具调用，造成不必要的延迟。该工作提出的「元认知」能力培养对搜索 agent 设计有直接启发：在 UGC 搜索场景中，agent 应学会区分「需要检索的查询」和「可直接回答的查询」，从而优化整体响应时间和系统资源利用率。

10. How Much LLM Does a Self-Revising Agent Actually Need?
3.55
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 当前 LLM agent 将世界建模、规划和反思全部放入单一语言模型循环中，难以区分 agent 能力中哪些来自 LLM 本身、哪些来自外部结构化设计。本文通过系统性实证研究，将 agent 能力分解为 LLM 内在能力和外部架构贡献，量化评估自修正 agent 中 LLM 组件的实际必要程度，揭示过度依赖 LLM 的浪费以及外部结构可替代的能力边界。

Key insight: 该研究挑战了「越大越好」的 agent 设计范式，为搜索 agent 的架构选择提供了实证依据。研究表明，agent 的很多能力来自外部结构（如检索策略、工具编排框架）而非 LLM 自身。对于搜索系统，这意味着在构建搜索 agent 时不应盲目使用最大的 LLM，而应投资于更好的检索架构和工具编排设计——用较小的 LLM 配合精心设计的搜索流程，可能比用巨型 LLM 做端到端搜索更高效。
