AdaWidth: Query-Adaptive Embedding Width for Dense Retrieval

AdaWidth 针对高维稠密向量检索的计算与存储开销，提出按查询自适应选择参与计算的 embedding 前缀宽度。它用共享的正交旋转把判别信息集中到前缀，再由轻量路由器根据当前排序的统计量决定是否扩展维度；在 6 个检索任务、5 个冻结编码器上，NDCG@10 与现有降维方法相当，同时每个查询少用 55%–84% 的维度。

Hybrid Semantic Tool Discovery for Enterprise MCP Gateway: Architecture and Implementation

PayPal

SCOUT 把企业 MCP 网关中的工具暴露问题重构为检索问题：面对 200+ 个服务器、2,000+ 个工具，不再把全部 schema 塞进上下文，而是通过 tool_search 用 BM25 与稠密向量做 RRF 混合召回。PayPal 生产数据表明，工具 token 消耗从 140.2k 降至 1.3k，占上下文比例由 70.1% 降至 0.8%，减少约 99%。

INSIGHT虽然对象从帖子变成工具 schema，但它对搜索基础设施的启示很直接：词法信号负责精确匹配参数名和权限词，语义信号负责自然语言意图，RRF 负责降低单一路径失效。社区搜索可复用这种“检索即上下文治理”设计，为 query 理解、字段过滤和结果解释设置统一的检索门面。

Olympia Saha, Amy Wang, Srinivasan Manoharan

SQLite is Enough. Lexical, Semantic, and Hybrid Search with scrydb

scrydb 将三种能力放进一个 Python/SQLite 组件：用 FTS5 做词法搜索，用 sqlite-vec 做向量检索，再用结果融合与重排组合两路候选。论文在多个信息检索基准上评估关键词匹配、语义相似度和 rank fusion，并同步讨论查询延迟与效果的取舍；软件以 MIT 许可证发布，适合快速验证轻量检索链路。

INSIGHT对中小规模 UGC 搜索或离线评测集，先用单库承载倒排、向量和融合，可以显著降低索引同步与实验编排成本。它不替代线上分布式引擎，但很适合作为可复现基线：固定 FTS5、向量 Top-K、融合公式和 reranker，再逐项测 nDCG、召回率、P95 延迟与内存，而不是只比较模型分数。

DPR-FL: A Dual-Path Retrieval Method with Fusion-Based Filtering and LLM Feedback

DPR-FL 采用双路径检索，把稀疏召回的精确词面覆盖与稠密召回的语义覆盖合并，再使用融合过滤和 LLM 语义反馈压制高冗余候选。其关键特征是纯推理式设计：通过 ANN 获取候选，不更新模型参数，并在复杂查询中对候选进行语义筛选，以更稳定地识别关键文档。

INSIGHT它适合被当作现有召回—重排链路的增量模块，而不是全量替换。实践上可将 LLM 反馈限制在低置信度或高重复度 query，结合 BM25、dense 和去重特征做门控；同时必须单独测空结果率、错误过滤率和 P99 延迟，避免语义反馈改善离线排序却伤害长尾召回。

Wontopos Tablet 2: Measuring Multilingual and Multimodal Memory Retrieval Without Lexical Matching

论文评测不含词法匹配和关键词打分的生产级长期记忆检索引擎 tablet-2。它在 500 个问题的 LongMemEval-S 上达到 95.7%，在包含 2.21M 条记忆、700 个问题的 BEAM-1M 上达到 67.5%；跨模态实验中，captionless 图片的平均 Recall@5 为 95.2%，而 BM25 仅 19.0%，并报告了重试预算可造成 8.9 个百分点的差异。

INSIGHT这项工作最重要的不是单一高分，而是把 reader、重试预算和检索阶段作为独立变量控制。社区搜索的离线评估也应记录 query 改写次数、候选池大小和 reader 版本，否则很容易把后处理能力误算成召回能力；对图片、表情和无文本 UGC，则应准备跨模态或 caption-free 的专项评测。

Optimizing Efficiency in Multi-Stage Semantic Re-ranking Architectures

本文针对交叉编码器重排序精度高但延迟高的问题，研究多阶段 semantic funnel 架构，在文档到文档检索中逐步缩小候选集合，再把更昂贵的语义模型留给末端候选。受控实验同时比较效果、计算开销和可解释性，为资源受限的语义检索提供一套可迁移的工程基线。

INSIGHT对短文本社区搜索，可把重排预算变成显式的漏斗策略：第一层用词法与向量取宽候选，第二层用轻量交互模型过滤，最后只对低 margin 或高价值 query 运行 cross-encoder。上线评估应按 query 难度分桶，报告每层的召回损失、P95/P99 延迟和单位请求成本。

Mitigating Database Leakage in RAG Systems with Keyword-Grounded Fact Substitution

KFS-RAG 面向 RAG 中的提示注入与数据库泄漏风险，提出三步防护：先用 attention rollout 与因果扰动找出少量关键字，再让辅助 LLM 从检索段落生成关键词约束的事实，最后用这些净化事实替换原始上下文。这样生成器接收的是结构化、压缩后的证据，而不是未经处理的原始检索文本。

INSIGHT检索结果不应天然等于可交给生成器的上下文。对含权限信息、用户评论或可能被注入的 UGC，可在重排后增加“证据净化”层，并保留原文到事实的可追溯映射；但要把它作为安全门控而非默认摘要器，分别监控事实遗漏、误改写、拒答率和额外 LLM 成本。

Ziliang Zhang, Yubo Zhu, Wei Tong, Jingyu Hua, Zijian Wang, Yuan Zhang, Sheng Zhong

PARTAB: Partition-Aware Reasoning with Structured Evidence for Scalable Table Understanding

PARTAB 解决大表格进入 LLM 后上下文冗余、证据定位困难的问题，把查询相关内容组织成语义连贯且保留行关联的区域，并按列组与行分区进行层级选择。论文在问答、事实核验、数值推理 3 类表格任务上评估该结构化证据接口，目标是用更小的上下文保持关键行列关系。

INSIGHT它提示 UGC 搜索中的结构化内容也可以先做“证据分区”再重排：例如把帖子正文、评论、时间、作者和实体字段分成可检索区域，先按 query 选择字段组，再对局部片段做语义匹配。这样比把整帖拼成长文本更容易控制 token、解释命中原因，并降低无关评论干扰。

Md Mahadi Hasan Nahid, Davood Rafiei

PlaceSeek: Human-Centered Geospatial Retrieval of Urban Outdoor Places via Semantic Grounding and Affective Alignment

PlaceSeek 研究开放式、带情绪与活动意图的地理检索，将自然语言 query 拆成功能子意图和情感子意图。Semantic Grounding Module 先验证街景候选是否真的包含活动所需的物理证据，Affective Alignment Module 再用 LoRA 适配的视觉语言模型重排；实验覆盖米兰 31,956 个街景位置，强调从 POI 元数据走向可验证语义匹配。

INSIGHT对社区短文本搜索，相关性不只由文本相似度决定，还可能取决于“是否具备用户描述的属性”。可以借鉴先做硬证据过滤、再做软偏好重排的两层结构，把帖子实体、图片和用户意图分别建模；工程上应明确证据缺失时的降级路径，避免视觉模型把风格相似误判成事实满足。

Ziqi Cui, Shangyu Lou

前沿重器：聊聊搜索系统5——召回、检索、粗排、多路召回

字节跳动

火山引擎文章从搜索系统的召回、检索、粗排和多路融合出发，讨论语义向量、用户与物料表征、内容质量和话题信号如何共同进入候选生成。文章强调向量不只承载文本语义，也可以表达行为与内容侧特征，为搜索推荐链路设计多路召回与下游排序协同提供工程化梳理。

INSIGHT它更适合作为落地检查清单而非新模型论文：社区搜索可以并行保留词法、语义、行为和实体召回，再用统一候选协议进入粗排。每一路都应有独立覆盖率、增量命中率和延迟预算，最后用 query 分桶确认新增语义信号带来的是有效 nDCG/CTR，还是仅仅增加重复候选。
