1. Structurally-bounded Agentic Graph Exploration for Evidence-Grounded Scholarly DeepSearch
4.40
Relevance 5 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: Crase 为深度研究 Agent 提供有界且可检查的搜索流程：先调用一次搜索引擎获得种子论文，再沿 1.5 跳引用图扩展，删除缺乏蕴含支持的边，最后用考虑时效性的随机游走排序。它在 50 万篇规模的 arXiv 语料和 LitSearch 等基准上，相比专有模型驱动的深度研究 Agent 将 Recall@50 提升最高 3 倍，同时成本约降至三分之一。

Key insight: 社区 UGC 搜索不必把所有查询都交给无限循环的 Agent；可以先用固定的候选扩展预算和可解释的图剪枝控制成本，再让模型做有限重排。该设计把候选集、停止条件和保留理由显式化，适合在高并发场景中用预算约束换取稳定延迟，也便于定位召回图上的错误路径。

2. When "Must" Becomes "Maybe": Constraint Weakening in LLM Agent Workflows
4.10
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 论文研究 Agent 工作流在摘要、计划、工单和交接记录中传递约束时的语义退化：原本表示“执行前必须满足”的安全阻塞条件，可能被改写成“可以参考”的普通信息。作者在 1,296 个受控合成回合中比较直接交接与多种变换，发现约束保真度会随中间语言产物的改写而下降，并将问题形式化为行动绑定状态保存。

Key insight: 搜索 Agent 的 query 改写、检索摘要和多轮 handoff 都可能把硬过滤条件弱化，导致违规内容进入排序或答案阶段。线上应把时间、地域、内容安全和权限条件编码为结构化字段，由确定性校验器在每次工具调用前复核；自然语言摘要只承载解释，不应成为唯一的约束载体。

3. Contextual Information Policy Optimization for Search Agents
3.85
Relevance 5 | Novelty 4 | Practical 3 | Evidence 3 | Timely 3

Summary: CIPO 面向搜索 Agent 的确认偏差问题设计证据导向的强化学习框架，把推理轨迹与检索到的证据对齐，并提供回合级信用分配。该方法不依赖额外奖励模型或人工标注，目标是在 Agent 逐步检索时奖励真正由证据支持的判断，而不是只奖励与模型先验一致的最终答案；候选资料将其定位为近期搜索 Agent 训练方法。

Key insight: 社区问答中，热门帖子和模型先验容易形成“看起来合理”的错误闭环，单一答案奖励会放大这种偏差。CIPO 的可借鉴点是把证据是否参与决策纳入轨迹奖励；落地前应先在离线 query 集上检查证据覆盖、拒答率和成本，并补充人工抽样，因为公开资料目前缺少完整的线上指标。

3.80
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: Recuris 将长程 Agent 的记忆拆为记录当前进度的工作记忆、可复用经验记忆和技能记忆，并让固定 Meta-Agent 根据执行证据做局部、带验证门控的更新。作者在 4 个长程基准、10 个模型上报告，37 个已完成的模型—基准组合中有 35 个成功率提升；在 tau-bench 上，GPT-5.6 Sol 提升 17.8 个百分点，Claude Opus 提升 15.6 个百分点。

8. Forgotten in Weights, Recovered by Tools: Agentic Tool Unlearning for LLM Agents
3.45
Relevance 3 | Novelty 4 | Practical 3 | Evidence 4 | Timely 4

Summary: 论文指出，传统模型遗忘只压制参数记忆，但 Agent 仍可能通过网页搜索、检索或数据库把被遗忘内容找回来，形成 tool-mediated recovery。ATU 采用两阶段设计：先做参数知识遗忘，再在模拟工具环境中用轨迹级强化学习惩罚目标搜索和答案泄露；在 RWKU、MUSE 及不同架构模型上，报告了更好的目标遗忘与保留能力折中。

Key insight: 社区内容删除、隐私合规和版权撤回不能只测模型是否直接背出文本，还要测它是否会通过召回链路重新构造目标内容。落地时应把索引删除、缓存清理、工具权限和最终答案泄露放进同一套回归集，并用轨迹级指标检查 Agent 是否主动绕过过滤器；这会增加评测和检索侧维护成本。

10. Beyond Two Bytes per Letter: Tokenization Overhead in Cyrillic AI Systems
3.25
Relevance 3 | Novelty 3 | Practical 4 | Evidence 4 | Timely 5

Summary: 论文量化多语言 tokenizer 对西里尔文字的额外开销，覆盖 9 个生产 tokenizer、5 种语言和 837 万个词形；乌克兰语在现代 tokenizer 上产生 68%–121% 的 token overhead，在旧版 cl100k 上达到 220%。在包含 1,536 个商品和 145 个查询的电商 RAG 基准上，LLMLingua-2 将输入长度压缩 47%–49%，为受限上下文的 Agent 检索提供了可测的成本优化路径。

Key insight: 如果社区 UGC 含有多语言、方言或混合文字，token 成本和上下文容量会直接影响 Agent 能否完成多轮检索。上线前应按语言分桶测 token fertility、召回质量和压缩后的实体丢失率，优先在 query 改写与历史轨迹摘要处做压缩；不要只依据英文 benchmark 估算服务成本。
