MARS: Multi-rate Aggregation of Recency Signals for Sequential Recommendation across Sparse and Dense Regimes

序列推荐里，Transformer 用位置自注意力、State-Space Model（如 Mamba）用单一隐式衰减来加权历史行为，二者都没把真实用户行为的多尺度时间结构显式建模。MARS 提出一个与编码器无关的聚合算子：直接消费真实时间戳，产出 K 个强调不同 recency 尺度的摘要，再用上下文自适应门控融合。它最多只增加 6% 参数、时间复杂度 O(LdK)，并按训练集平均序列长度自动在稀疏数据用 MARS-T（Transformer）、稠密数据用 MARS-M（Mamba）间切换。在 5 个公开 benchmark、对比 10 个 Transformer/Mamba 基线（统一 RecBole 协议）下，MARS 在每个 benchmark 上都拿到最佳 HR@10，平均相对提升 +19.7%。

MARS 深度解读

1. 问题与动机

序列推荐的核心是给历史行为加权，但现有两类骨干各有盲区：Transformer（SASRec 类）用位置自注意力，把"加权"交给可学习的位置/内容注意力，没有时间先验；State-Space Model（Mamba4Rec、SIGMA 类）用单一隐式指数衰减，强加了一条固定的"越近越重"曲线。作者点出关键 gap：序列混合（sequence mixing）的最优架构，未必等于多尺度时间加权（multi-scale temporal weighting）的最优参数化——这两件事被现有模型耦合在了一起。真实用户行为天然有多个时间尺度：分钟级的冲动点击、天级的短期兴趣、月级的长期偏好，单一衰减无法同时拟合。量化证据上，论文显示在稀疏数据上 MARS 相对最强 content-only Transformer 基线平均 +19.7% HR@10（Games 上达 +36.2%），在稠密 ML-1M 上以 42% 更少的 MFLOPs 取得 +3.2% HR@10 / +0.9% NDCG（对比 SIGMA），说明显式多尺度建模既涨点又省算力。

2. 方法详解

MARS 是一个与编码器无关的聚合算子，挂在任意骨干输出的 token 表征 h 之上，分三步：

(a) Per-Head 衰减加权：先把相邻交互的真实间隔时间 Δt 做对数压缩 Δ̃tᵢ = log(1 + Δtᵢ/τ₀)，τ₀=1 小时。设 K 个衰减 head，每个 head 有可学习基础衰减率 λₖ=softplus(λ̃ₖ) 和温度 τₖ=softplus(τ̃ₖ)+0.1。

(b) 用户条件化调制：用序列最后一个表征 hₗₐₛₜ 过 MLP 调制每个 head 的衰减率：λₖ(u)=λₖ·exp(σ·tanh(Wλ·hₗₐₛₜ)ₖ)，σ=0.5。这样每个用户有自己的衰减曲线，但不引入 per-user 参数。

(c) 聚合：第 k 个 head 的权重为 softmax 归一化的衰减 logit：wₖ,ᵢ(u)=exp(−λₖ(u)Δ̃tᵢ/τₖ)·mᵢ / Σⱼ(...)，得到 K 个摘要 Zₖ(u)=Σᵢ wₖ,ᵢ(u)hᵢ。理论上（Proposition 1）K 个指数衰减的混合是单调衰减核的通用逼近器。

上下文自适应融合门：用上下文向量 c=[时间编码; 最后物料 embedding; hₗₐₛₜ] 对 K 个摘要做门控：gₖ=vᵀtanh(Wg[Zₖ(u);c])，α=softmax(g/τα)，最终 hᵤ=hₗₐₛₜ+Σₖ αₖZₖ(u)。残差连接保留编码器原信号，避免退化。

损失：L=L_CE + η_div·L_div + η_bal·L_bal。多样性损失 L_div=−Σ JSD(wₖ‖wₖ') 防止 K 个 head 塌缩到同一衰减率；负载均衡损失 L_bal=K·Σ ᾱₖ²（MoE 风格）防止门只走单个 head。默认 η_div=η_bal=1e-2。

骨干自动选择：按训练集平均序列长度 L̄ 切换——L̄<50 用 MARS-T（Transformer），L̄≥50 用 MARS-M（Mamba）。复杂度 O(LdK)，仅增 ~6% 参数。

训练配置：d=64，2 层 block，dropout（稀疏 0.5 / 稠密 0.2），Adam lr=1e-3，batch 2048，K（稀疏 4 / ML-1M 8）。

3. 核心技术贡献

(1) 解耦"序列混合"与"时间加权"：这是最核心的观念贡献。把时间衰减从骨干中剥离成独立、可即插即用的算子，使得"用什么架构混合序列"和"如何按时间加权"可以各自最优。这比 TiSASRec 把时间嵌入硬塞进注意力更模块化。

(2) 多速率衰减 + 用户调制：用 K 个可学习指数核覆盖不同时间尺度，再用用户表征调制——既有多尺度表达力，又不爆 per-user 参数。消融显示去掉真实 Δt（用位置序号替代）在 Beauty 上掉 2.5%，是单个最重要组件。

(3) 防塌缩正则：多样性损失保证 K 个 head 真的学到不同尺度（Proposition 3：在 Hawkes 过程数据下可恢复真实衰减率），负载均衡保证门不退化。在稠密 ML-1M 上去掉负载均衡掉 3.0%。

4. 实验结果分析

主结果（HR@10）：Beauty 8.84（SASRec 8.04，+9.95%）、Sports 5.22（+13.5%）、Games 12.07（SASRec 8.86，+36.2%）、Yelp 6.45（+19.2%）、ML-1M 用 MARS-M 32.80（SASRec 29.62，+10.7%，对比 SIGMA +3.2%）。效率上 MARS-T 仅增 ~2% 参数、1% MFLOPs；MARS-M 比 SIGMA 省 40-42% MFLOPs。

消融最有信息量：稀疏数据上 backbone-only（去掉 MARS）掉 4.0-6.3%；K=1 单 head 在 Beauty 已达最优 K=8 的 96.2%，说明稀疏场景少量 head 就够；稠密 ML-1M 上 K 敏感得多（K=16 时 +6.4% HR@10 摆动），负载均衡损失变成最关键组件。

按历史长度分组分析揭示一个反直觉点：稀疏 benchmark 上增益随序列变长而增大（Yelp 从短序列 +21.8% 到超长 +29.7%）；但 ML-1M 上 MARS-T 在超长桶（76% 测试用户）反而 −2.9%——因为注意力本就已在长序列上聚焦——而 MARS-M 在所有桶稳定 +5.7%~+9.0%。这正是骨干自动选择规则的实验依据。

5. 局限与未来方向

作者明确列出：(1) 骨干选择是手工设定的数据集级阈值（L̄=50），在 20× 密度差内稳健但未在更连续的密度谱上验证，且非学习得到；(2) 可辨识性（Proposition 3）依赖 Hawkes 过程假设，分布无关版本仍开放；(3) TiSASRec 在 Beauty/Games 的 NDCG/MRR 上仍略胜 MARS-T（1.1-7.1%），作者用 40× 内存优势换取这一让步；(4) 评估仅限五个公开集的离线 next-item 预测。隐含未提的局限：未做线上 A/B，工业超长行为序列（千级）下 K 个核是否够用未知。

6. 工业实践意义

对搜推团队最直接的可借鉴点：MARS 是低成本即插即用算子（+6% 参数、O(LdK)），可直接挂在现有 SASRec / Mamba 召回塔输出上，不动主干。对社区推荐尤其契合——用户行为兼有秒级刷信息流的冲动和长期话题偏好，单一时间衰减拟合不了，多速率核能同时建模。三条工程结论：(1) 务必喂真实时间戳而非位置序号（去掉真实 Δt 是最大掉点项）；(2) 稀疏行为场景 K=4 足矣，不必堆 head，省算力；(3) 行为密度差异大时用骨干自动选择思路——短序列用注意力、长序列用 Mamba。门控融合多尺度摘要的设计也能迁移到 query-行为时序特征构造。部署上 MARS-M 比 SIGMA 省 40% FLOPs，对延迟敏感的精排友好。需注意：超长行为用户（注意力已聚焦）上 Transformer 变体可能无增益甚至掉点，上线前要按行为长度分桶评估。

Taiji: Pareto Optimal Policy Optimization with Semantics-IDs Trade-off for Industrial LLM-Enhanced Recommendation

Kuaishou📖 有深读 · 7 分钟

快手团队（Kun Gai、Peng Jiang）针对工业级 LLM4Rec 的两大瓶颈：SFT 阶段开放域推荐里 CoT 质量难衡量、难提升；RL 对齐阶段 LLM 语义奖励与推荐偏好奖励之间的 trade-off 被忽视。Taiji 是 LLM-as-Enhancer 框架：SFT 端用「逆向工程推理 + 开放式拒绝采样」生成高质量领域 CoT 数据；RL 端提出 Pareto Optimal Policy Optimization (POPO)，自适应调节语义奖励与推荐偏好奖励的交叉权重，在二者间逼近帕累托最优，从而把 LLM 的语义空间与推荐器的 ID 空间对齐。

INSIGHT工业 LLM4Rec 落地的真问题不是「能不能用 LLM」，而是 LLM 语义奖励和推荐 CTR/偏好奖励经常互相打架。Taiji 把它显式建成多目标帕累托优化（POPO），而非简单加权求和，这对做多目标排序的团队很有启发：reward 冲突应该用帕累托前沿来调，而不是手调权重。SFT 用拒绝采样自产领域 CoT 数据的做法，也为缺乏推荐场 CoT 标注的团队提供了冷启动数据生产范式。

Taiji 深度解读

1. 问题与动机

用 LLM "增强"工业推荐（LLM-as-Enhancer）已成趋势，但把 LLM 的语义空间与推荐器的 ID 空间对齐（通过 SFT/RL 后训练）一直很难。Taiji 来自快手（Kun Gai、Peng Jiang 团队），直指两个被忽视的瓶颈：(1) SFT 阶段——开放域推荐里"缺乏合理、系统的指标来准确衡量推荐专用 CoT 的质量"，导致没法判断生成的推理链好不好、怎么提升；(2) RL 阶段——现有方法"没有考虑两类异质信息之间的动态平衡"，即 LLM 的语义理解奖励与推荐偏好（CTCVR）奖励经常互相打架，固定权重加和会让一方压倒另一方。这个问题在工业场景尤其尖锐：语义对了但 CTR 没涨，或 CTR 涨了但模型只学会复读热门 ID、丢了泛化。论文要解决的是"如何让 LLM 既懂语义又服从线上偏好信号"。

2. 方法详解

Taiji 是 LLM-as-Enhancer 框架，四阶段流水线：数据构造（从快手平台采集用户画像和行为序列）→ 推理激活（SFT 注入高质量 CoT）→ LLM-推荐协同（POPO 平衡奖励）→ 在线排序（把 LLM 输出编码成特征喂给广告排序模型）。

SFT 端——逆向工程 CoT 数据生产：

  • RUPR（Reverse-Engineered User Preference Reasoning）：用"用户真实下一个购买物料"作为 ground-truth 条件，喂给 QwQ-32B 反向蒸馏出推理链——即已知答案再让大模型补出"为什么是这个"的推理，保证 CoT 与真实偏好一致。
  • ORFT（Open-Ended Rejection Sampling Fine-Tuning）：用 ground-truth 答案的困惑度（PPL）过滤 CoT 样本，只保留 PPL < R（中位数阈值 4.6）的样本，在 DeepSeek-R1-7B 上做 SFT。损失是标准自回归 NLL：L_ORFT=−(1/N)ΣΣ log P(tⱼ|qᵢ,t_<ⱼ)。

RL 端——Pareto Optimal Policy Optimization (POPO)：
两个奖励：语义奖励 r_s（预测物料与真实物料 embedding 的余弦相似度）、ID 协同奖励 r_id（来自生产排序模型的 CTCVR，即点击∧转化概率）。核心是动态权重调整（Eq.5）：w̃^(t)=w̃^(t-1)⊙exp(η^(t)·I^(t)/μ)，再归一化，其中 I^(t) 是梯度对齐指示器，衡量单个目标梯度与聚合目标梯度的协调度——哪个目标"拖后腿"就动态加权。还提供 POPO-light，用奖励统计量替代梯度计算，几乎零开销。组合奖励 r̃ᵢ=w_s^(t)·r_s + w_id^(t)·r_id，套进 GRPO 损失：L_POPO=E[min(ρA, clip(ρ,1−ε,1+ε)A) − β·D_KL]。

训练配置：快手 111 万用户记录（100 万 SFT / 10 万 RL / 1 万测试），base model DeepSeek-R1-7B，3 节点 × 8 张 A800；SFT 1 epoch lr=1e-7 batch 32；RL 1 epoch lr=2e-5 batch 16，rollout group G=4，最大 13K prompt / 2048 completion token。

3. 核心技术贡献

(1) 把奖励冲突显式建成帕累托优化：这是最有启发的贡献。语义奖励和 CTCVR 奖励异质且常冲突，传统做法手调固定权重加和，必然牺牲一方。POPO 用梯度对齐指示器在线动态调权，逼近帕累托前沿。消融显示 POPO 比固定权重 GRPO 在 Category L1 上 +11.61%、L3 上 +29%。

(2) 逆向工程 CoT 数据生产：开放域推荐没有现成 CoT 标注，RUPR 用"已知答案反推理由"绕开了这个冷启动难题。消融显示 RUPR 比直接蒸馏在 Category L1 准确率上 +19.83%。

(3) PPL 拒绝采样做质量过滤：用 ground-truth 答案困惑度作为 CoT 质量的可量化代理指标，解决了"CoT 质量无法衡量"的痛点，且阈值（中位数 4.6）可解释。

4. 实验结果分析

离线（1 万测试集）：Category L1 准确率 0.2433 vs backbone 0.1560（+55.96%）；Title Hit-Rate@50 0.0567 vs 0.0496（+14.31%）；CTCVR 0.003816 vs 0.003417（+11.68%）。POPO 在 6 个指标中 5 个超过固定权重 GRPO；POPO-light 以可忽略开销取得几乎相同效果。

在线 A/B（10% 流量，1 周）：整体 ADVV +2.83%、Revenue +3.30%；长尾用户 ADVV +5.26%、Revenue +5.32%——长尾收益明显高于大盘，说明 LLM 语义增强对数据稀疏的长尾用户帮助更大，这正是 LLM4Rec 最该发力的地方。

消融：RUPR 对 Category L1 贡献 +19.83%（vs 直接蒸馏）；POPO 对 Category L1 贡献 +11.61%、L3 +29%（vs 固定权重）。两个核心组件都被验证有效。

部署规模：自 2026 年 5 月起已在快手全量上线，服务 4 亿+ 日活。这是少有的给出真实线上规模和 A/B 数字的工业 LLM4Rec 论文。

5. 局限与未来方向

论文未设独立局限章节。隐含约束有几条：(1) 强依赖 teacher 模型 QwQ-32B 的质量，蒸馏天花板受限于教师；(2) ID 协同奖励需要生产排序模型实时提供 CTCVR，没有成熟排序基建的团队无法复现；(3) 对 PPL 拒绝采样阈值（中位数 4.6）敏感，阈值选择缺乏自适应机制；(4) 整套是 LLM-as-Enhancer 离线/近线产特征喂给排序模型，并非端到端在线生成，LLM 推理仍在离线侧，线上时延问题被规避而非解决。

6. 工业实践意义

对做多目标排序的搜推团队，Taiji 给出三条可直接落地的经验：(1) reward 冲突要用帕累托前沿调，别手调权重——语义目标和业务目标（CTR/CVR）几乎必然冲突，POPO 的"梯度对齐指示器动态调权"思路可迁移到任意多目标排序/多任务学习场景，且 POPO-light 几乎零成本。(2) 缺 CoT 标注就用逆向工程——RUPR"已知 label 反推 CoT"的范式，为推荐、搜索相关性等没有现成推理标注的场景提供了冷启动数据生产模板，再用 PPL 过滤质量。(3) LLM 增强优先打长尾——线上长尾用户收益（+5.3%）显著高于大盘（+3.3%），资源有限时应把 LLM 语义增强投向数据稀疏的长尾流量。部署上 Taiji 走的是 LLM-as-Enhancer 离线产特征路线（DeepSeek-R1-7B，3×8 A800），把计算密集部分推到离线、线上只查表，这与业界主流"LLM 不直接端到端在线推理"的工程共识一致，是当前可落地性最高的范式。对社区搜索，可借鉴其"语义 reward + 业务 reward 帕累托对齐"来平衡相关性与点击。

03 3.55

BAHSD: Bridging the Long-tail Gap via Adaptive Distillation in Black-box Sequential Recommendation

CAS

序列推荐常以黑盒 API 部署，催生了「模型抽取」把能力本地复刻的需求。但长尾分布带来严重信号异质性：稠密 head 序列会固化 teacher 偏好、把抽取偏向局部模式；稀疏 tail 序列预测平坦且噪声大。现有一刀切抽取忽视这种差异，导致噪声过拟合。BAHSD 提出黑盒自适应蒸馏：用多尺度一致性探测机制隐式量化信号可靠性，再设计分层目标——高置信信号用动态温度 KL 散度缓解偏好固化，tail 用排序一致性与 InfoNCE 对比约束抑制噪声。
