Generative Long-term User Interest Modeling for Click-Through Rate Prediction

针对超长用户行为序列下 CTR 预估的两阶段框架 (GSU 检索 top-k 行为 + ESU 注意力建模) 的两个痛点——以目标 item 为中心的 GSU 会漏掉其它潜在兴趣、且基于 pairwise 相似度的匹配检索随行为增长而耗时，论文提出生成式长期兴趣模型 GenLI。GenLI 由兴趣生成模块 IGM、行为检索模块 BRM、兴趣融合模块 IFM 组成：IGM 生成多个目标无关的兴趣分布、显式编码行为间交互信息以保证兴趣完整多样；BRM 用一次 lookup 选取相关行为，把逐行为加权的时间复杂度降到 O(1)；IFM 用门控机制生成最终兴趣特征。整体在精度与在线服务效率间取得更好平衡。

KEY INSIGHT · 对业务意味着什么把 GSU 的「目标-行为匹配检索」范式改造为「目标无关的兴趣分布生成 + O(1) 行为查表」，是对工业界 SIM/ETA/TWIN 系列长序列建模的一次范式级简化：既绕开了在线 pairwise 打分随序列膨胀的延迟瓶颈，又通过多兴趣分布缓解了 target-centered 检索的兴趣偏置。对社区 feed/搜索排序中长行为建模的启示是——兴趣表征可前置生成、与目标解耦，从而把昂贵的检索退化为可缓存的查表操作。

1. 问题与动机

GenLI 针对工业级 CTR 预估中超长用户行为序列建模的两阶段范式 (GSU 检索 top-k 行为 → ESU 注意力建模) 提出三个具体失效模式。第一，target-centered 的 GSU 只检索与目标 item 相关的行为，"ignore other latent user interests"，导致兴趣特征不完整且有偏。第二，基于 pairwise 相似度的匹配检索需要把目标 item 与每条历史行为逐一打分，随着行为序列增长 (工业数据集序列长达 1000) 在线服务计算开销不可承受。第三，pairwise 架构"overlook the interaction information among user behaviors"，丢失行为间交互信号。论文用 Meituan 广告系统的生产规模佐证问题严重性：240M 用户、1.1B 样本、序列长度达 1000，TWIN 这类 SOTA 在该规模下检索延迟成为瓶颈。这使得"如何在不牺牲精度的前提下把长序列检索复杂度降下来"成为亟待解决的工业问题。

2. 方法详解

GenLI 由三个模块组成。兴趣生成模块 IGM：从近期行为 (l=10~100) 生成三个目标无关的兴趣分布。显式兴趣 p^E 直接拟合用户点击，损失 ℒ_explicit = -∑ 𝕀_{y=1} log s(t_i, p^E)；隐式兴趣 p^I 建模平台曝光但无反馈的 item，损失 ℒ_implicit = -∑ log s(t_i, p^I)；相对兴趣 p^R = softmax(p^E − p^I) 编码点击与曝光的差异、刻画决策动态。生成过程用多头注意力 h = MHA(Q_G, K_G, V_G)，其中 Q_G=[e_1, e_q] (当前行为 + 可学习 query)，K_G=V_G 为近期行为序列，再 p = softmax(MLP(h))，输出维度 N=4096。行为检索模块 BRM：用一次查表实现 O(1) 打分，s(b_i, p) = LOOKUP(b_i, p) = p_{ID(b_i) % N}，对每个分布取 top-20，三分布共 K=60 条行为 (与基线对齐)。兴趣融合模块 IFM：对每类兴趣分别用 MHA 聚合 z^I = MHA_F(e_t, 选中行为, 选中行为)，再门控融合 g=σ(MLP(z^F))，x_l=(g⊗z^F)W^g，z^F=concat(z^I,z^E,z^R)。端到端训练 ℒ = ℒ_ctr + α·ℒ_implicit + β·ℒ_explicit (α=β=1.0)，Adam lr=0.001，batch 256，正负 1:1，整体复杂度 O(L + (l+K)d_h) ≈ O(L)。

3. 核心技术贡献

(1) 首个把生成式方法引入 CTR 长期兴趣建模的工作——用"生成目标无关兴趣分布"替代"目标-行为匹配检索"，从范式上消除了在线 pairwise 打分。(2) 把逐行为打分复杂度从 O(d_h) 降到 O(1)：BRM 的模哈希查表把昂贵的相似度计算退化为可缓存的索引操作，这是延迟收益的根本来源。(3) 三类兴趣分布 (显式/隐式/相对) 显式建模"点击 vs 曝光"差异，缓解 target-centered 检索的兴趣偏置，消融显示移除 p^E 在 Amazon 掉 2.17%、TaoBao 掉 1.88%，是贡献最大的分布。(4) 可插拔设计：x_l 与短期特征、side info、目标 embedding 拼接进下游 MLP，无需重训下游即可替换现有 GSU/ESU。

4. 实验结果分析

三数据集：Amazon (75K 用户/100 序列)、TaoBao (988K/500)、Industrial (240M/1000)。离线 AUC：GenLI 在 Amazon 0.7564 (vs TWIN 0.7503，+0.61%)、TaoBao 0.9552 (vs 0.9449，+1.03%)、工业集 0.7463 (vs TWIN 0.7441，+0.22%)。消融：移除 p^E 影响最大 (−2.17%/−1.88%)，p^I 次之 (−1.31%/−1.46%)，p^R 最小 (−0.42%/−0.27%)，验证三分布层级贡献。检索数 K 敏感性揭示关键现象——K=15 时 GenLI 比 TWIN +1.65%，K=75 时仅 +0.88%，说明 GenLI 在检索预算受限时优势最大 (恰是在线场景)。推理效率：每 8192 样本 GenLI 4.6ms，TWIN 7.9ms，SIM-soft 6.8ms，比 TWIN 快 41%。在线 A/B (6 天、30% 流量) CTR +0.776%、RPM +1.567%，带来显著营收增长。

5. 局限与未来方向

作者明确承认的局限：(1) 开放数据集 (Amazon/TaoBao) 缺曝光日志，用"序列中采样一个相近 item"近似曝光 item 来训练 p^I，是 p^I 训练的噪声源。(2) 分布维度 N=4096 是碰撞概率与计算开销的折中，超过该值性能饱和。(3) IGM 依赖近期行为 (l=10~100) 生成分布，超过 ~100 条收益边际、成本上升。(4) 三类兴趣是领域特定设计，迁移到其它场景需重新设计。(5) 模哈希 (ID % N) 缺乏哈希碰撞对检索质量影响的形式化分析——这是最值得后续补强的理论缺口。

6. 工业实践意义

对搜推从业者最直接的可借鉴点：把"目标-行为匹配检索"重构为"目标无关兴趣分布生成 + O(1) 查表"，在序列长达千级时把检索延迟降 41%，且越是在线检索预算受限 (K 小) 收益越大——这正契合社区 feed/搜索排序的长行为建模痛点。已在 Meituan 广告系统生产部署 (240M 用户、1.1B 日样本)，模块可插拔、不需重训下游，落地复杂度低。在线 RPM +1.567% 对 CPC 计费模型直接转化为广告营收，CTR +0.776% 可迁移到内容点击场景。需注意的部署权衡：O(1) 查表牺牲了哈希碰撞的可解释性换取延迟，生产系统中可接受；隐式兴趣 p^I 依赖曝光日志，若平台无完整曝光埋点需先补数据基建。建议先在离线/长尾场景验证三分布设计，再灰度替换现有 SIM/TWIN 检索链路。

Fortress: A Case Study in Stabilizing Search Recommendations via Temporal Data Augmentation and Feature Pruning

📖 有深读 · 6 分钟

搜索与推荐的预测模型常因部分输入特征带来分数波动而出现「时间维度不稳定」，在多阶段系统中会因上下游分数不一致而损害可靠性与体验。论文提出通用框架 Fortress，通过定位并裁剪导致分数随时间不一致的特征来提升模型稳定性与精度，遵循四步流程：(1) 采集历史快照、按时间切分数据集以捕获同一实体跨周期的分数波动；(2) 识别预测不稳定的样本；(3) 隔离并移除引发不稳定的特征；(4) 仅用稳定特征重训模型。论文还指出来自 LLM/BERT 的语义特征虽利于泛化但可能引入不稳定，需要纳入该裁剪流程评估。

INSIGHT把「特征稳定性」当成一个可量化、可裁剪的工程目标，而非泛泛追求精度——这对多阶段搜索/推荐链路（召回→粗排→精排）尤其关键，因为上游分数抖动会被下游放大。可直接借鉴的设计是用时间切分的历史快照构造「同实体跨周期分数波动」数据集来定位不稳定特征，并对引入语义噪声的 LLM/BERT 特征保持警惕：泛化收益与线上稳定性需要联合权衡。

1. 问题与动机

Fortress 针对搜索与推荐预测模型的"时间维度不稳定"问题：同一 query-app 对在不同时间得到差异显著的相关性分数，导致结果在"可见/不可见"间反复横跳 (flip-flop)，在多阶段系统中上游分数抖动会被下游放大、损害可靠性与体验。论文用 app 应用市场场景给出量化证据：全特征模型 PR-AUC 达 0.9572，但分数的变异系数 (CV) 高达 0.5462——精度高却极不稳定。权衡被明确点出：基于用户互动 (engagement) 的特征能提升精度但"tend to introduce temporal instability"；来自 LLM/DistilBERT 的语义特征更稳定但覆盖率仅 ~80%。如何在保留 engagement 预测力的同时压制其波动，是多阶段检索/排序系统的真实工程痛点。

2. 方法详解

Fortress 是一个四步通用框架。第一步 采集历史快照：按时间把数据切成连续区间 (daily snapshot)，对被多次打分的同一实体评估预测一致性。第二步 识别不稳定样本：取跨快照 CV 处于 75 分位 (最高变异) 的 query-app 对作为不稳定样本。第三步 隔离引发不稳定的特征：对高方差样本逐特征单独计算 CV，CV 最高的特征作为裁剪候选。第四步 仅用稳定特征重训：移除候选特征后重训。关键设计是贪心搜索 + 显著性门控——只有当移除某特征后在验证集上 PR-AUC 相对基线"statistically significant improved"才真正裁掉该特征，避免误删有预测力的特征。不稳定度量为 CV = 跨时间快照预测分数的标准差 ÷ 均值。数据结构：70/15/15 切分，~40% 样本标 BAD，其余 60% 均分 ACCEPTABLE/GOOD/EXCELLENT，daily 快照粒度。模型选 XGBoost (因其速度与抗噪)。

3. 核心技术贡献

(1) 框架可泛化：不限于本案例，适用于任何"同一实体被多次打分"的场景。(2) 时间稳定性分析视角：揭示"单快照有益的特征可能跨时间退化"，多快照视角暴露此前隐藏的不稳定性——这是方法论层面的核心洞见。(3) 实用权衡求解：engagement 信号有预测力但波动、语义特征稳定但覆盖不全，Fortress 在抑制波动的同时保留预测价值。(4) 系统级收益：不止模型指标，还带来下游推荐一致性的真实改善 (flip-flop 率下降)，证明特征稳定性是可量化、可裁剪的工程目标。

4. 实验结果分析

数据集为某大型商业应用市场的 query-to-app 相关性分类，含 ~25 个每日多次刷新的 engagement 特征 + LLM/DistilBERT 语义特征。四方法对比 (Table I)：仅语义特征 (SR) PR-AUC 0.9367 / CV 0.4744；全特征 0.9572 / 0.5462；多快照全特征 0.9593 / 0.5283；Fortress 0.9595 / 0.5274。即 Fortress 相对多快照基线再降 CV 3.44%、PR-AUC 绝对 +0.24%——在不牺牲 (甚至略升) 精度下显著降波动。系统级 (Table II flip-flop 率下降)：Region 1 降 14.7%、Region 4 降 49.6%、全局降 25.8%，区域差异大说明效果与地域/数据分布相关。值得注意：仅用 SR 特征虽 CV 最低 (0.4744) 但 PR-AUC 最低 (0.9367)，印证"稳定但覆盖不全"，Fortress 在两者间取得更优折中。

5. 局限与未来方向

作者未显式列举局限，但隐含承认：(1) 语义特征覆盖率仅 ~80%，存在覆盖缺口。(2) flip-flop 改善区域差异巨大 (14.7%~49.6%)，方法有效性可能依赖地域/数据分布。(3) 结论来自单一领域 ~25 个 engagement 特征，跨特征集/跨领域泛化未验证。此外论文未讨论延迟开销，多快照重训需历史数据采集与时间切分，更偏批处理而非实时特征工程——这是落地需补充评估的部分。

6. 工业实践意义

对搜推从业者最可直接借鉴的是把"特征稳定性"当成可量化、可裁剪的工程目标，而非泛泛追求精度。具体做法：用 daily 时间快照构造"同实体跨周期分数波动"数据集，按 CV 定位不稳定特征，并用"移除后验证集 PR-AUC 显著提升"作为裁剪门控，避免误删有效特征。这在召回→粗排→精排的级联架构中尤其关键——论文明确指出"in multistage retrieval and ranking systems, volatility in production scores can lead to undesirable shifts in system dynamics"，上游抖动会向下游传播。对引入 LLM/BERT 语义特征要警惕：泛化收益与线上稳定性需联合权衡，覆盖率不足时不宜全量替换 engagement 特征。部署上 XGBoost 因速度与抗噪被选用，多快照重训属离线批处理，适合作为定期特征体检流程嵌入模型迭代。社区搜索场景可直接套用：对 query-内容相关性模型做特征稳定性审计，裁掉抖动大的实时互动特征，换取结果排序的跨时间一致性、减少用户感知的"结果忽隐忽现"。

LLM-EDT: Large Language Model Enhanced Cross-domain Sequential Recommendation with Dual-phase Training

跨域序列推荐 (CDSR) 面临两大问题：不平衡问题（某一域交互主导整条行为序列，难以学到弱域的域特异特征）与迁移问题（混合序列中难以刻画用户跨域偏好，导致特定域 next-item 预测差）。论文提出 LLM-EDT：用「可迁移 item 增强器」自适应生成用户可能的跨域行为以缓解不平衡、同时控制无关噪声；用「双阶段训练」让域特异线程获得域共享背景以缓解迁移问题；用「域感知画像模块」对各域偏好做摘要并自适应聚合成完整用户画像以解决粗粒度画像问题。在三个公开数据集上验证有效性。

INSIGHT把 LLM 同时当作「跨域行为生成器」和「域感知画像器」，并用双阶段训练显式解耦域共享与域特异表征，给社区多场景（搜索/推荐/问答）共用用户表征提供了思路：与其在混合序列里隐式学跨场景偏好，不如让 LLM 显式做带噪声控制的行为补全 + 分场景画像摘要再聚合。其「先补域间行为、再分域画像、最后聚合」的三步设计可迁移到多频道 UGC 个性化。

Agent4POI: Agentic Context-Conditioned Affordance Reasoning for Multimodal Point-of-Interest Recommendation

现有多模态 POI 推荐把每个 POI 编码为与上下文无关的静态 embedding，无法解释「同一家咖啡馆为何周一适合独自办公、周五晚上适合聚会庆祝」。论文首先形式化证明：在标准双线性打分下，任何预计算编码器都无法满足上下文敏感的排序，从而论证必须在推理时生成 item 侧表征。Agent4POI 反转计算顺序：给定情境上下文，四阶段 LLM agent 先生成上下文相关的 affordance 查询 (Phase 1)，再对图像/评论/元数据证据执行五步跨模态思维链 (Phase 2)，产出带不确定性、植根于 Gibson affordance 理论的上下文相关表征用于排序。

INSIGHT「静态 item embedding 在双线性打分下无法做上下文敏感排序」的不可能性证明，是对推荐系统双塔/向量检索范式的一次理论敲打：当排序强依赖情境（时间、场合、同行人）时，item 表征必须随上下文在推理时动态生成，而非离线固化。对社区内容推荐的启示是——高价值场景可考虑推理时 item 侧重表征；但四阶段 agent + 五步 CoT 的在线开销极高，落地需做表征缓存/蒸馏，短期更适合离线重排或长尾场景。

Logging Policy Design for Off-Policy Evaluation

离线策略评估 (OPE) 用某个 logging policy 收集的数据来估计目标策略（如推荐系统）的价值，使高风险实验无需上线即可进行，但估计精度高度依赖 logging policy 的设计。论文研究「如何设计 logging policy 使给定目标策略的 OPE 误差最小」，刻画了一个根本的 reward-coverage 权衡：把概率质量集中在高回报动作上能降方差，但会漏掉目标策略可能采取动作的信号。论文给出统一的 logging policy 设计框架，并在目标策略与回报分布 (i) 已知、(ii) 未知、(iii) 通过先验/带噪估计部分已知 三种典型信息状态下推导最优 logging policy。

INSIGHT把「探索日志怎么打」从经验直觉提升为可优化问题：reward-coverage 权衡说明纯按线上模型分数采样的日志会系统性低估那些当前模型很少曝光、但新模型会偏好的动作——这正是推荐/搜索离线评估常年偏乐观的根因之一。可借鉴的是按「目标策略信息已知程度」分档设计采样策略：信息越少越应向覆盖倾斜，为后续模型迭代保留可评估的信号。

On the Factual Consistency of Text-based Explainable Recommendation Models

基于文本的可解释推荐用自然语言解释来佐证推荐项以提升用户信任与系统透明度，但「这些 LLM 生成的解释是否与可用证据事实一致」长期未被充分研究。论文提出一套评估文本可解释推荐事实一致性的完整框架：用基于 prompt 的流水线让 LLM 从评论中抽取原子级解释性陈述，构造聚焦事实内容的 ground truth；在 Amazon Reviews 数据集的五个品类上构建增强基准做细粒度评估；并提出结合 LLM 与 NLI 的陈述级对齐指标，同时衡量事实一致性与解释质量。

INSIGHT可解释推荐的「流畅 ≠ 事实正确」是 LLM 生成解释落地的核心风险——论文把评估从整体打分细化到「原子陈述级 + LLM/NLI 双重对齐」，提供了可复用的评测方法学。对社区场景（如给 UGC 推荐/搜索结果附 LLM 理由）的直接启示是：上线 LLM 解释前必须建陈述级事实一致性基准，否则会以「看起来可信」的幻觉解释损害用户信任。
