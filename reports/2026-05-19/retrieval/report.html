Ascend-RaBitQ: Heterogeneous NPU-CPU Acceleration of Billion-Scale Similarity Search with 1-bit Quantization

针对十亿级向量相似检索在纯 CPU 实现下算力与内存带宽受限的瓶颈，论文提出 Ascend-RaBitQ——首个面向 IVF-RaBitQ 的 NPU-CPU 异构 1-bit 量化检索系统。核心做法是把粗排与精排解耦到不同硬件：在 AI Core 上对 1-bit 量化向量做加速粗排，在端侧 AI CPU 上做 Top-k 处理，再由 host CPU 做精排重排，构成三级异构流水线，从而绕开既有 CPU/GPU 实现无法直接移植到 NPU 的硬件适配问题。实验报告索引构建较 CPU 基线快 3.0×–62.8×，吞吐最高提升 4.6×，端到端相对等价 CPU 基线整体加速超过 100×。

Fairness-Aware Retrieval Optimization for Retrieval-Augmented Generation

RAG 中检索环节引入的偏置会随 top-k 文档共同传播到生成结果，论文提出一个面向公平性的检索优化框架来建模并控制这一偏置。方法包含三部分：通过重排做受控的偏置注入、一个位置感知（position-aware）的偏置传播模型、以及一个在相关性与公平性之间做权衡的优化形式；并进一步给出可扩展解法 FARO（Quadratic Fairness via Dual Hyperplane Approximation），通过问题分解实现高效求解。实验表明该方法能在保持相关性的同时有效缓解生成端偏置（cs.DB/cs.IR，摘要未给出具体数据集与数值）。

INSIGHT把“检索结果的位置”显式建进偏置传播模型，是这篇论文区别于一般公平重排的点：top-k 里文档的排位会影响其对生成的影响力，因此公平约束要在重排阶段、按位置加权地施加。对社区搜索的启示是，作者/内容维度的曝光公平可建模为带位置权重的二次优化，用对偶超平面近似（FARO）做问题分解后可在重排层在线求解，与相关性目标做可调权衡。证据偏弱（摘要未披露数据集与指标），落地前需自建评测验证相关性损失。

Yingqi Zhao, Vasilis Efthymiou, Jyrki Nummenmaa, Kostas Stefanidis

03 3.20

X-SYNTH: Beyond Retrieval -- Enterprise Context Synthesis from Observed Human Attention

企业场景里 Agent 任务所需的上下文散落在记录系统、静态文档与沟通渠道中，而“被存储下来的”只是工作过程的有损快照。论文指出主流“按请求内容匹配已存储内容”的检索范式在复杂任务上失效（True Lead Rate 低、False Lead Rate 高且无自我改进机制），提出 X-SYNTH：以可数字化观测的“人的注意力交互痕迹”为基准，将每个工作者建模为 Digital Twin Signatures，并用 7 种注意力过滤机制筛出与任务相关的行为模式来合成上下文。在销售线索识别任务上，True Lead Rate 从 9.5% 提升到 61.9%（约 6.5×），False Lead Rate 从 90.5% 降到 18.8%。

INSIGHT核心论点对搜索排序有迁移价值：很多“相关性”信息存在于用户行为/注意力模式里，而检索索引本身并不编码这部分信号——把上下文合成当作“以行为为 ground truth 的相关性问题”来做。对社区搜索的启示是，点击/停留/交互序列等行为痕迹可作为相关性监督的一等公民，而非仅做事后排序特征；7 类注意力过滤可类比为多种行为信号的去噪/聚合算子。局限是高度依赖可观测的逐用户交互签名与企业内部数据，社区场景需替换为可获得的隐式反馈，且评测仅单一任务。

Guruprasad Raghavan, George Nychis, Rohan Narayana Murthy

04 3.02

Retrieval-Augmented Large Language Models for Schema-Constrained Clinical Information Extraction

面向护患对话转写的结构化抽取（MEDIQA-SYNUR：把叙述按预定义 schema 与取值类型约束归一化），论文提出一个模块化 RAG 流水线：用训练集作为示例语料做检索增强，结合 schema 约束提示（完整 schema 对比裁剪后的候选 schema）、基于 schema 的确定性后处理，以及第二遍审计（second-pass audit），底座对比 Llama-4-Scout-17B-16E-Instruct 与 GPT-5.2 及对应 embedding 模型。最佳配置（GPT-5.2 + 完整 schema + RAG + 二次审计）取得 F1 80.36%；结论是 RAG 稳定带来增益，schema 约束的最优强度依模型而定，二次审计带来小幅额外提升。

INSIGHT可借鉴的是这套“训练集即示例语料的检索增强 + schema 约束提示 + 确定性后处理 + 二次审计”流水线模板：在结构化抽取/槽位填充类任务（如 query 理解中的意图与属性抽取）上，用历史标注样本做 RAG 召回示例，比纯 prompt 更稳。两点工程结论可直接用——RAG 召回示例几乎总正向；schema 约束强度不要固定，需按所用 LLM 调优（强约束未必对所有模型最优）。局限在于任务/领域偏临床且仅单一 shared-task 数据集，业务相关性偏低，主要价值是 pipeline 设计参考而非方法创新。

A H M Rezaul Karim, Ozlem Uzuner
