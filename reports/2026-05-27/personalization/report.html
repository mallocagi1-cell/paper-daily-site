Equip Pre-ranking with Target Attention by Residual Quantization (TARQ)

工业级推荐系统中粗排（pre-ranking）阶段长期受限于向量内积模型，无法承担精排常用的 Target Attention (TA) 这类高算力交互模块。TARQ 提出用 Residual Quantization（残差量化）把目标 item 的注意力计算近似为查表式离散化运算，将 TA 的建模能力首次引入粗排，重建了精度-延迟权衡曲线。淘宝大规模线下实验与线上 A/B 均验证 TARQ 在保持粗排延迟约束的前提下显著提升上层精排候选质量，已开源相关组件以便集成。

Memento: Personalized RAG-Style Long-Retention Data Scaling for META Ads Recommendation

Meta📖 深度解读 · 8 分钟 →

Meta 提出 Memento：把广告推荐场景的超长用户历史当作“文档库”，把当前广告请求当作 query，用 Maximal Marginal Relevance (MMR) 检索出相关历史交互注入模型。两个互补应用：Representation Memento 检索历史 embedding 做特征增强，Data Memento 检索历史训练样本做多轮训练。通过时序分块、INT8 量化和异步 serving 协同设计，相比线性扩展达到 5–10× 资源效率，日处理请求亚 10ms 延迟，在 baselines 上获得 0.25–0.3% Normalized Entropy 增益。

INSIGHTMemento 把“长序列建模”从“一次性塞进 transformer”改写成“RAG 风格的按需检索”，绕开了 attention 稀释、catastrophic forgetting 与系统效率三座大山。两层应用（Repr / Data）分别覆盖在线服务和离线训练两条主线，是当前“RAG 思路反哺推荐”最完整的工业范例。对社区搜索来说，用户的长期 query/点击历史完全可以套用 MMR 检索来做个性化重排，比起直接 SFT 一个 50k-token 历史窗口的 LLM 更现实。

SIREN: Unified Multi-Granularity Semantic Interaction for Multi-Modal Lifelong User Interest Modeling

SIREN 针对多模态终身用户兴趣建模中“多模态序列与协同行为序列错位”的核心难题，提出统一多粒度语义交互框架。在 General Search Unit (GSU) 阶段提供两条检索策略：基于多模态相似度的软检索（效果优先）与基于 Semantic ID 的硬检索（工业 serving 效率优先）；在 Exact Search Unit (ESU) 阶段做多粒度 token-level 与 sequence-level 交互。在公开数据集与工业数据上均验证了多模态终身兴趣建模相对纯 ID 序列建模的显著提升。

INSIGHT工业终身行为建模的瓶颈正在从“序列长度”转向“多模态对齐”——纯 ID 序列已经无法承载短视频/图文场景的语义信号。SIREN 的“soft 检索 + hard SemID 检索”双路设计很务实：线上链路用 SemID 走索引、线下评估用多模态向量做天花板，是非常容易落地到现有 SIM/ETA 类终身兴趣框架的增量改造。对社区搜索同样适用：UGC 的标题/正文/图片可以通过 SemID 进入 GSU 检索，避免单纯靠 itemId 召回错过新发帖。

From Item-Only to Query-Item: Query-Conditioned Generative Search with QGS in Quark

Alibaba📖 深度解读 · 11 分钟 →

生成式序列模型在推荐里已有成熟方案，但搜索是 query-driven 的——每次切换 query 都会引入剧烈话题跳变。现有方法把 query 与 item 拍平到单一 token 序列，无法区分 query 边界，导致监督信号被噪声污染。Quark 团队提出 QGS：把每次交互编码为 (query, item) 配对 token，用 query-conditioned next-item 目标训练，使预测目标从有噪声的 P(item_{t+1}|context) 变成清洁的 P(item_{t+1}|context, query_{t+1})；同时引入压缩注意力机制处理长交互历史。

INSIGHT把“生成式推荐”照搬到搜索的最大坑是 query 切换引起的话题断裂，QGS 用 (query,item) pair token + query-conditioned 监督直接消除了这种语义不连续。这套范式对社区搜索的 session 级建模非常有借鉴价值——同一个用户在“健身”、“电影”、“地推”之间频繁切换 query 时，引入显式的 query 条件能避免“健身偏好”污染“电影排序”。可以作为 LLM-based 生成式重排在社区场景的最小可行落地起点。

LENS: A Staged Design for Interaction Granularity in Sequential CTR Prediction

Sequential CTR 预估的核心设计问题是“target 与行为序列在什么粒度交互”：raw-item 路线（DIN 类）让 target 直接打分每个历史 item，依赖优质 item embedding，遇到稀疏 item 容易脆化；latent-query 路线（HyFormer / MixFormer / OneTrans）通过组合 target 与上下文构造 query 表示，对 item 稀疏度更鲁棒但 target-specific 控制被稀释。LENS 用 Target-Conditioned Query Gate (TCQG) 做 query 激活、Target-Conditioned Position Bias (TCPB) 做历史检索，再加一个 Query-Specific Position Bias (QueryPos) 作为静态位置参考，在粗 bottleneck 内恢复 target-specific 控制。

INSIGHTDIN-vs-Transformer 之争实际是“raw-item 精细但脆”与“latent-query 鲁棒但糊”的取舍。LENS 用两个 target-conditioned 模块在 latent 路线里重新注入 target 信号，是“鱼和熊掌兼得”的工程化设计模板。这种“在抽象层后再加 target gating”的思路也适用于社区搜索的排序：当 LLM-based 表征替代 itemId embedding 后，可以用 target-conditioned gate 防止稀疏 query 失控。

DeGRe: Dense-supervised Generative Reranking for Recommendation

多阶段推荐里的 reranking 通过捕捉 list 内上下文依赖优化整体效用，难点在指数级排列空间的最优序列探索。现有 end-to-end 生成式框架靠 list-wise reward 或偏好对齐训练 generator，但存在两大问题：(1) heuristic label bias——把“点击 item 上移”这类简单规则当成训练目标，忽略 list 内的因果依赖；(2) credit assignment——稀疏的 list-level posterior reward 无法直接指导生成的中间步骤。DeGRe 用 dense supervision 解决这两点：将 list-level reward 沿生成路径分解到每一步，并消除启发式标签偏置。

INSIGHT生成式重排的瓶颈不在“能否生成”而在“怎么打分每一步”：list-level reward 太稀疏、点击启发式又有 bias。DeGRe 的 dense supervision 思路把 list-wise 信号分解成 step-wise 信号，等价于把 RLHF 的 reward shaping 经验迁回 reranking。对社区搜索的页面级混排（帖子 + 视频 + 用户）很有借鉴价值——这类场景天然有 list 上下文，但点击转化是延迟稀疏信号，需要 dense 信号才能学到合理混排策略。

How Reliable Are Semantic-ID Tokenizer Comparisons in Generative Recommendation?

📖 深度解读 · 16 分钟 →

在 Semantic-ID (SID) based 生成式推荐里，每个 item 表示为一串离散 code，自回归模型生成下一个 item 的 SID 序列，Top-K 性能通过“目标 item 的 SID 是否出现在生成序列中”衡量。这个评测协议默认 SID 与 item 一一对应，但本文发现：4 个数据集、5 种主流 tokenizer 上，平均 30.5% 的 item 与他人共享 SID，匹配 SID 实际只是命中“碰撞组”而非具体 item，导致现有 SID-level 指标系统性高估。论文提供修正后的评测协议。

INSIGHT这是给“生成式推荐 hype”的及时降温——HSTU/TIGER 类范式赖以立足的 Recall@K 指标，可能有约 30% 的水分来自 SID 碰撞。研究和工程引入生成式推荐前必须先做 collision 审计，并采用 item-level 评测。对计划上线生成式重排/召回的团队，这意味着 offline 提升要再打折，否则线上 A/B 大概率不达预期。

Selective Test-Time Compute Scaling for CTR Prediction via Uncertainty-Triggered Feature Path Exploration (UTTSI)

test-time compute scaling 在 LLM 上已被验证，但在工业 CTR 几乎未被探索。CTR 模型存在结构性不对称：训练充分的特征组合给出自信预测，稀疏组合输出不可靠。训练期解法（adaptive gating）会被同样的稀疏性束缚。UTTSI 是 training-free、model-agnostic 框架：用 logit 置信度 + 数据级频率先验组成 dual-signal 不确定性估计器（区分 epistemic 与 aleatoric），按 per-instance 不确定性自适应扩展推理深度——每个实例先做特征过滤，再触发 feature path exploration。

INSIGHT把“test-time compute scaling”从 LLM 平移到 CTR 是个未被充分挖掘的方向，关键洞察是：CTR 99% 流量是高频组合不需要花更多算力，只有 1% 长尾该多花算力做特征路径搜索。这种“按 instance 不确定性动态分配 inference 算力”的思路对成本敏感的工业推荐非常香。对社区搜索来说，长尾低频 query 的相关性预估恰好对应高 epistemic 不确定性，引入 UTTSI 类机制可以只对长尾 query 加重 LLM 推理，整体边际成本可控。

HeteGenCTR: Self-Balancing Gradient Allocation for Heterogeneity-Aware Feature Generation in CTR Prediction

用离散扩散做生成式预训练能给 CTR 提供 dense 重建监督，缓解数据稀疏导致的表征坍塌。但既有生成式 CTR 方法把所有特征字段平权对待，忽略高基数 ID、稀疏类别、数值、行为序列等字段的重建难度差异，导致简单字段主导梯度、最难且最关键的字段长期欠拟合——作者称之为“生成难度不平衡”。HeteGenCTR 通过 per-field 可学习难度参数与 denoising 网络联合训练，自动平衡各字段的梯度分配，避免重建监督被 easy field 吞掉。

INSIGHT“离散扩散生成式预训练 + CTR”这条线最大障碍就是字段异构性，HeteGenCTR 的 per-field difficulty 参数是非常简洁的解法：等价于自动温度退火 + 难例挖掘。这套思路对任何“用 MLM/denoise 预训练做 CTR 表征”的工业团队都有借鉴意义——尤其是同时含 itemId/类目/数值统计的复杂特征体系，无须人工分组就能让训练梯度自适应。

Rethinking Contrastive Learning for Graph Collaborative Filtering: Limitations and a Simple Remedy

在图协同过滤 (GCF) 中，Sampled Softmax (SSM) 等对比学习目标被广泛使用，但其与 GCF 预测机制的相互作用并不清晰。作者展开 GCF 的预测机制，发现 user-item 预测分数实际上是对“user 与 item 多跳邻居形成的大量邻居对”加权聚合的结果。这暗示有效优化关键在“训练中哪些邻居对被 up-weight”。实验显示仅 up-weight 一小部分“与 target user/item 结构相似”的邻居对就能实现有效推荐，且不同邻居对类型的 up-weight 效果差异显著。

INSIGHT这篇把图对比学习的“神秘有效性”拆解到了邻居对级别——核心机制不是“拉近正样本/拉远负样本”，而是隐含的 structure-aware 邻居加权。对工业 GCF 实践者意义在于：可以显式做邻居对采样而非依赖 SSM 的随机隐式加权，既降低训练开销又更可解释。社区搜索中 query-doc 的二部图召回同样适用这套分析框架。
