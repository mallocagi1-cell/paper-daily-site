DynaTree: Dynamic Agentic Retrieval Tree for Time-Sensitive News Retrieval

针对 agentic RAG 把语义扩展与检索决策耦合在短视推理循环里、导致时效性新闻检索推理成本高的问题，提出 DynaTree 两阶段框架。离线阶段用多个协同 agent 构建一棵可复用的检索树，把某个 query 主题的语义空间一次性物化；在线阶段只在时间局部化的评估代理上做轻量的子树选择，不再做 agentic 推理、不改树、也不重训。在多天 Syft 新闻基准和多个 BEIR 数据集上验证了检索效果与效率的折中。

On the impact of retrieved content representations in RAG Pipelines

University of Queensland

多数 RAG 流水线沿用为「人类读者」设计的检索组件，但当下游消费者是 LLM 而非人时，检索内容应如何表示并不清楚。论文做了一项控制实验：固定检索结果，只改变文档表示，把原始基线与覆盖筛选 (selection)、摘要 (summarisation)、改写 (reformulation) 三类共 13 种变换做对比，并区分 query 相关与 query 无关两种设定，系统性地考察哪种表示特征对生成最关键。

INSIGHT价值在于把「喂给 LLM 的文档该长什么样」从零散的单点改造，变成一个可控的、13 种变换横向对照的实证结论，明确了 selection/summarisation/reformulation 哪类更影响下游生成。对社区搜索的启示：在 LLM 重排或问答场景中，召回后对 UGC 文本做面向 LLM 消费的表示改造（裁剪冗余、按 query 重组），可能比单纯堆召回量更划算，且这是低成本即可上线的工程改造点。

Jonathan J Ross, Bevan Koopman, Anton van der Vegt, Guido Zuccon

03 3.55

Fighting Numerical Hallucinations via Data-centric Compilation for Online Financial QA

Tencent

在线金融问答 (FinQA) 中 LLM 易出现数值推理幻觉，而标准 RAG 引入三大顽疾：噪声敏感、计算脆弱、可审计性危机。已有 model-centric 方法只孤立地优化检索器或生成器，难以整体解决。论文提出 data-centric 范式与 Data-centric Reasoning Compiler (DCRC) 框架，把推理过程当作可编译/可审计的数据对象来处理，以抑制数值幻觉并提升结果可追溯性。

INSIGHT思路转变是关键：不再只调模型，而是把「检索-推理-计算」的链路当成可编译的数据流水线来治理噪声与计算脆弱性，并天然带来可审计性。对社区搜索/问答的启示：当 UGC 问答涉及结构化事实或数值（如商品参数、评分统计）时，可借鉴 data-centric compilation 把易错的数值推理从自由生成中剥离、做成可校验步骤，降低高风险场景的幻觉率。来自腾讯团队，偏工业落地视角。

Hao Chen, Xing Tang, Qirui Liu, Weijie Shi, Shiwei Li, Fuyuan Lyu, Weihong Luo, Xiku Du, Xiuqiang He

04 3.50

Evaluating Factual Density in Multi-Source RAG: A Study in Medical AI Accuracy

传统检索靠关键词匹配与主题接近度排序，衡量的是内容「听起来多像 query」，却没衡量内容实际包含多少经核实的事实，导致标准 RAG 把高事实密度的证据埋没在词面占优的文本之下（称为 Expert Blindness Effect）。论文提出 Factual Density (FD*) 这一检索优化信号，度量「经核实的原子事实数 / 总 token 数」的比例，用 Ghost Audit 预处理管线对原文做事实特异性打分，并在医疗 AI 准确性场景中验证。

INSIGHT核心是给检索排序引入一个与语义相似度正交的信号——单位长度内的可核实事实密度，用来对抗「词面占优但信息稀薄」的内容。对社区搜索的启示：UGC 普遍存在「口水多、干货少」的长帖，可借鉴 FD* 思路在排序中加入事实/信息密度特征，把高信息密度的优质回答提到前面，缓解相关性高但内容空泛的问题。

Michael R. DeMarco

05 3.55

Exploring Autonomous Agentic Data Engineering for Model Specialization

Zhejiang University

LLM 在通用任务上强，但缺少高质量领域数据时难以适配垂直领域；已有 LLM 数据治理方法多依赖人工设计的工作流，尚未检验 LLM 能否自主跑完端到端的数据工程。论文形式化「Autonomous Agentic Data Engineering」新任务，把训练数据当作可优化组件，让 agent 在多个领域上以「后训练性能提升」为目标，自主完成规划、生成、迭代优化数据。实验显示自主数据工程 agent 带来显著的领域适配收益。

INSIGHT把「造数据」本身变成一个以下游模型指标为奖励的闭合优化任务，让 agent 自主决定造什么、怎么造、何时停。对搜索/推荐的启示：相关性标注、query 改写样本、难负例挖掘等都极依赖数据工程，可借鉴「以后训练指标为反馈的 agentic 数据生成」来自动化构造领域训练集，尤其适合社区垂类冷启动时缺标注数据的场景。

06 3.55

Beyond Static Dialogues: Benchmarking Realistic, Heterogeneous, and Evolving Long-Term Memory

Microsoft

现有 LLM 记忆基准的对话缺乏长期语义一致性、人设扁平且静态，且现实交互还涉及文档、邮件等异构数据流，限制了评测的真实性。论文提出 RHELM 基准：由精心构造的用户画像驱动，配合 LOOP（pLan-rOllout-evOlve-Prune）模块，构造出跨多种场景、具有动态时间演化与长期连贯性的对话，并深度融入异构数据，从而更真实地评测长期记忆能力。来自微软团队。

INSIGHT亮点是用 plan-rollout-evolve-prune 的生成式流程造出「会随时间演化、跨异构数据源」的长期记忆评测，逼近真实助手场景。对社区搜索/对话式推荐的启示：当产品演进到带记忆的搜索助手时，需要这种异构、可演化的记忆评测来衡量个性化记忆质量；其 evolve/prune 思路也可借鉴用于用户长期兴趣记忆的更新与遗忘机制设计。

07 3.30

Evaluating using Mock Tool Calls to Quarantine Untrusted Prompt Inputs

FAR AI

LLM 经常要处理不可信输入（如评判另一模型的答案、做垃圾/有害分类），这些输入常被直接字符串拼进 prompt 模板，易被操纵。各家 spec 按 Instruction Hierarchy 区分可信度（System 最高、Tool Results 最低），一种直觉缓解是把不可信内容包进 mock tool call 做隔离。作者用跨 7 个模型、3 个 LLM-as-Judge 任务的自动化红队搜索静态攻击串来检验该假设，结果与直觉相反：tool-wrapping 并未普遍提升鲁棒性，在 GSM8K 评分这类二分类任务上甚至更差。

INSIGHT这是一个有价值的负面结果：把不可信文本「包成工具调用」并不能可靠地抵御 prompt 注入，提醒不要依赖指令层级标签做安全边界。对搜索的启示：当用 LLM 做 UGC 相关性打分/内容审核时，被检索到的用户文本本身就是不可信输入，单纯靠 prompt 结构隔离不可靠，需要更强的输入消毒或专门的防注入机制，尤其在 LLM-as-Judge 用于线上相关性评估时。

David Gros, Adam Gleave

08 3.20

CanLegalRAGBench: Evaluating Retrieval-Augmented Generation on Canadian Case Law

UUBC

法律 RAG 助手日益流行但幻觉问题严重，且多数已有基准用合成 query 而非真实法律场景，加拿大法律也在评测中代表性不足。论文提出 CanLegalRAGBench：基于真实 query、由专家标注答案并锚定到判例法的加拿大法律 QA 基准。评测发现：检索性能对设计选择高度敏感，开源 embedding 模型与闭源模型竞争力相当；同时自动评测会因系统检索到「其它同样相关的文档」而误罚，暴露了自动评估的局限。

INSIGHT两个可迁移结论：一是开源 embedding 在垂直检索上已可与闭源抗衡，二是自动评测会因「正确但非标准答案」的相关文档而系统性误判检索质量。对社区搜索的启示：UGC 检索同样存在「多条等价相关结果」，沿用单一 golden 的离线指标会低估真实相关性；评测应允许多正例，且选型上不必迷信闭源 embedding。

Ethan Zhao, Maksym Taranukhin, Wei Cui, Moira Aikenhead, Vered Shwartz
