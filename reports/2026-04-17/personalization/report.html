深度解读：On the Practice of Deep Hierarchical Ensemble Network for Ad Conversion Rate Prediction

1. 问题与动机

广告转化率（CVR）预测与 CTR 预测有本质不同：CVR 标签极度稀疏（用户从点击到实际购买/注册的转化率远低于点击率）、标签收集延迟长（站外转化可能延迟数天才回传）、标签质量嘈杂。Pinterest 的转化广告系统需要预测用户在第三方网站/App 上的站外行为（购买、加购、注册等），面临的核心挑战是：预训练用户嵌入擅长通用个性化，但未针对转化概率预测进行优化。DHEN（Deep Hierarchical Ensemble Network）此前已在 CTR 预测中取得成功，但其在 CVR 场景的实践方案尚不明确。本文系统攻克了 DHEN 在 CVR 预测中的工程实践问题。

2. 方法详解

问题建模：转化概率分解为 P(conv;U,P) = P(ctr) × P(conv|ctr)，将 CVR 建模为点击后的条件转化概率。

多任务学习框架：以 DHEN 为统一 backbone，合并所有转化动作（购买、加购、注册等）到单次前向推理中。训练时额外包含 CTR 预测头（serving 时不使用），利用 CTR 的海量标签作为辅助信号增强 CVR 学习——CTR 标签量级比 CVR 高数个数量级。损失函数采用加权二元交叉熵，跨头联合优化。

五类行为序列特征：(1) S_search：用户在平台的搜索 query 序列；(2) S_org：有机内容互动序列（非广告）；(3) S_ads：广告互动历史；(4) S_match：匹配转化对（用户ID + 广告主ID + 动作类型）；(5) S_conv：归因转化序列（广告到站外转化的链接）。各序列独立编码而非合并，保持架构灵活性。

DHEN 架构：两层集成结构。第一层包含 MLP + Transformer 模块，第二层包含 MLP + MaskNet 模块。输入处理包括连续特征 min-max 归一化到 [0,1]、预训练嵌入的 Batch Normalization、时间戳对数变换、类别嵌入映射，统一投影到 R^(B×L×D) 维度。最终 MLP 为三层 [128,128,128] + sigmoid。总参数量 340M，部署在 8× NVIDIA A100 GPU 上。

自监督辅助损失：为解决 CVR 标签稀疏问题，加入未来动作预测的自监督目标：L(S) = -Σ log P(P_t | P_{t'<t})，通过 INFO-NCE 对比损失近似：L(S) = -Σ log(e^(x^T x_t) / (e^(x^T x_t) + Σ e^(x^T x_-)))，正样本 90 个、负样本 20 个为最优配置。

ParetoNet 参数搜索：不做穷举调参，而是随机采样配置在 60 天数据上训练，构建预测模型映射参数到 AUC/吞吐量，识别 Pareto 最优配置。

3. 核心技术贡献

(1) DHEN 统一多任务 CVR 预测：证明两层异构 DHEN（不同层使用不同模块组合）优于精心调优的单一 Transformer，关键在于不同特征交叉模块捕捉不同类型的特征交互模式。三层架构出现边际递减（+0.30% vs 两层的 +0.31%），且同质堆叠（每层相同模块）仅提升 +0.08%。

(2) 端到端行为序列建模：序列特征的影响力是预训练嵌入的 2 倍（图 6 消融实验）。这验证了在 CVR 场景中，端到端序列学习比静态预训练特征更重要——预训练嵌入虽有用，但不可替代序列特征。

(3) 自监督未来动作预测：NAL（Next Action Loss）比 MLM（Masked Language Modeling）效果更好（+2.18% vs +1.68% AUC），且最优负正样本比为 1:20，这与预训练场景需要更高比例不同。

(4) ParetoNet 高效参数搜索：通过构建参数-性能预测模型，在 AUC 和推理吞吐量之间找到 Pareto 最优，避免了穷举搜索的高昂成本。

5. 局限与未来方向

作者明确提出四个方向：(1) 全空间优化：CVR 和 CTR 正交运作，联合优化参与度信号（CTR、观看、收藏）和 CVR 可能进一步提升；(2) 高级序列建模：探索更长序列、生成式 AI 方法、更丰富的逐 item 特征；(3) 延迟标签反馈：站外转化测量固有延迟，造成训练信号滞后；(4) 隐私保护 ML：行业趋向差分隐私和数据洁净室，减少标签数量和质量。

6. 工业实践意义

直接可采纳：(1) 多任务 DHEN 框架——用一个模型预测多种转化类型，比独立模型更高效且效果更好；(2) 自监督序列预测损失——在标签稀疏的搜索/推荐场景中，通过预测用户未来行为增强模型泛化，即插即用；(3) 五类行为序列的分离编码策略——搜索序列、浏览序列、交互序列分开处理比混合更好。

关键数字：序列特征 > 预训练嵌入（2x 影响力）；两层异构 DHEN > 单一 Transformer（+0.31%）；NAL 自监督 +2.18% AUC；线上 CPA -2.15%，转化量 +1.62%。

部署考量：340M 参数模型部署在 8× A100 上，年增 $1.2M 基础设施成本。对于中小规模系统，可从两层 MLP+Transformer 的简化 DHEN 开始，逐步引入 MaskNet 层和自监督损失。

TokenFormer: Unify the Multi-Field and Sequential Recommendation Worlds

Tencent📖 深度解读 · 7 分钟 →

推荐系统长期存在两个独立范式：多域特征交互模型（建模类别特征相关性）和序列模型（捕捉用户行为动态）。本文揭示了朴素统一两者会导致“序列坍塌传播（SCP）”——非序列域的维度不匹配导致序列特征的维度坍塌。为此提出 TokenFormer，通过统一的 token 化表示和专门的注意力机制，在单一架构中有效融合多域特征交互与序列建模，避免 SCP 问题。在腾讯广告平台的实验中验证了该方法的有效性。

INSIGHTSCP（序列坍塌传播）是工业推荐系统中一个被忽视但普遍存在的问题：当多域特征和序列特征简单拼接送入共享 backbone 时，维度不匹配的非序列特征会“污染”序列表征。TokenFormer 的 token 化统一策略为解决该问题提供了实用方案。对于社区搜索的排序模型，如果同时使用 query/用户画像等类别特征和用户行为序列，应特别关注特征维度对齐，避免序列建模能力退化。

深度解读：TokenFormer: Unify the Multi-Field and Sequential Recommendation Worlds

1. 问题与动机

推荐系统长期沿两条独立路线发展：特征交互模型（DCN、DeepFM 等）建模多域类别特征的相关性，序列模型（SASRec、HSTU 等）捕捉用户行为动态。工业界越来越需要在单一模型中统一两者。然而，本文通过实验揭示了一个被忽视的失败模式——序列坍塌传播（Sequential Collapse Propagation, SCP）：当多域静态特征和序列特征通过共享注意力算子交互时，低维静态特征的维度不匹配会导致序列表征的维度坍塌。具体表现为：联合建模虽然提升了互信息（表征可区分性），但引发了更陡峭的谱衰减（维度坍塌）。图 1 清晰展示了这一 trade-off。这意味着朴素的特征拼接+共享 Transformer 方案在工业场景中可能适得其反。

2. 方法详解

统一 Token 流：TokenFormer 将所有输入表示为扁平 token 序列，包括：非序列域 tokens（F，如用户画像、商品属性）、序列行为 tokens（T，用户历史交互）、目标特征 tokens（V）。统一实体集 E = F ∪ T ∪ V。位置编码采用类型感知索引：静态域映射到位置 0，行为 tokens 按时间顺序编码，目标特征映射到 SL+1。

Bottom-Full-Top-Sliding (BFTS) 注意力：核心创新。分层注意力设计：

  • 浅层（l ≤ l_f）：全因果注意力，允许 tokens 在整个序列上交互，实现跨域信息融合
  • 深层（l > l_f）：递缩滑动窗口注意力，窗口大小递减 w_{ls} < w_{ls-1} < ... < w_1，迫使逐层精细化

关键设计：浅层全注意力结束后，完全丢弃非序列 token（公式 15），防止静态特征在深层"冗余回访"并污染序列表征。最优配置为 2F2S（2 层 full + 2 层 sliding），w=[32,16]。

非线性交互表征 (NLIR)：通过 sigmoid 门控引入高阶非线性：G^(l) = X^(l) W_g^(l)，然后 Ĩ^(l) = σ(G^(l)) ⊙ A^(l)（逐元素乘法）。这种乘法调制增强了特征可区分性，同时保持了表征秩（防止维度坍塌）。

FFN 设计：采用 SwiGLU 架构 + RMSNorm 归一化：(Swish(Ĩ W₁) ⊙ (Ĩ W₂)) W₃。

训练目标：支持两种设置——用户中心（对整个统一序列做密集自回归监督）和新曝光仅（仅对新曝光候选 tokens 计算交叉熵损失）。

3. 核心技术贡献

(1) 发现并解决 SCP 问题：首次系统揭示多域特征与序列特征统一建模时的维度坍塌传播机制。通过有效秩（effective rank）分析定量证明：vanilla 联合建模的谱衰减显著快于纯序列 Transformer。BFTS 和 NLIR 分别从注意力模式和特征变换两个维度独立缓解坍塌。

(2) BFTS 分层注意力："浅层广交互、深层精细化"的设计原则。浅层 full attention 的平均感受野为 52.7（vs vanilla 的 40.0），深层完全屏蔽静态 tokens 后展现出"显著的窗口内稀疏性"，动态关注最相关的邻近 tokens。2F2S 配置在 AUC 提升 +0.85‰ 的同时减少 20.1% GFLOPs。反向配置 2S2F 导致灾难性的 -6.18‰ AUC 下降，证明"先全局后局部"的顺序不可逆。

(3) NLIR 门控机制：sigmoid 门控乘法作为"维度坍塌的有效安全阀"，通过非线性乘法交互促进特征去相关，保持"整个网络中的表征多样性"。单独贡献 +4.87‰ AUC。

(4) 残差连接的几何分析：注意力残差恢复注意力中丢失的维度（erank 提升），FFN 残差正则化过度的秩扩展（erank 回调到中间范围），形成平衡恢复机制。

5. 局限与未来方向

作者隐含指出的局限：(1) 数据规模依赖：在小数据集上 scaling 效果有限，需要数据充裕的工业场景才能发挥全部潜力；(2) 窗口大小调参：BFTS 效果依赖合理的窗口配置，w=[32,16] 为经验最优，但不同场景可能需要重新搜索；(3) 架构特异性：静态 token 丢弃、RoPE 位置编码等设计需要与场景仔细对齐。未来方向包括自动注意力模式搜索、其他乘法交互方案探索、扩展到广告/信息流之外的推荐场景。

6. 工业实践意义

直接可采纳：(1) SCP 诊断——如果你的排序模型同时使用画像类别特征和用户行为序列，务必检查序列表征的有效秩是否因静态特征而坍塌，方法是计算注意力输出的奇异值谱；(2) BFTS 注意力——"先全局后局部"的分层注意力设计在保持效果的同时减少 20% 计算量，是工业模型提效的实用手段；(3) 深层丢弃静态 tokens——简单但有效的操作。

关键数字：GMV +4.03%（微信视频号）；AUC +0.22%（腾讯广告）；GFLOPs -20.1%（BFTS vs full attention）。

部署考量：TokenFormer 的参数量从 0.48M（Tiny）到 10.14M（Large），工业部署选择 TokenFormer-S（3.77M，3.5G FLOPs）是效果/效率的良好平衡点。BFTS 的滑动窗口注意力支持高效的增量推理。对于社区搜索的排序模型，如果同时使用 query 特征、用户画像和行为序列，建议先检查是否存在 SCP 问题，再考虑采用 BFTS 架构。

03 3.95

DUET: Joint Exploration of User Item Profiles in Recommendation System

传统推荐系统用稠密向量表征用户和物品，新兴的 LLM 推荐器则使用自然语言表征。本文研究如何构建有效的用户-物品文本画像并对齐它们用于推荐。核心难点在于最优画像格式未知——手工模板脆弱且可能与任务目标不对齐，且独立生成的用户/物品画像可能语义不一致。DUET 提出联合优化用户和物品画像的框架，通过迭代探索找到推荐效果最优的画像表述方式，实现文本空间中用户-物品的高效匹配。
