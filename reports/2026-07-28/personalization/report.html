PinEqualizer: Full Funnel Content Exploration and Debiasing System at Pinterest

论文针对工业级搜索与推荐中的内容冷启动，把探索与去偏从单点策略扩展到召回、排序等完整漏斗，并同时适配搜索和推荐场景。Pinterest 已连续两年迭代并部署该系统，通过可扩展评测框架连接短期实验与长期影响，显著改善新内容探索、整体互动和内容生态健康；摘要未披露具体提升数值。

深度解读：PinEqualizer 如何在完整漏斗中解决内容冷启动

1. 问题与动机

Pinterest 面向超过 5 亿用户、数千亿条 Pin，Homefeed、Related Pins 与 Search 三个主要入口合计承担 92% 的内容曝光。平台原有 Pin-Board 图随机游走、PinSage/ItemSage 图优化向量和用户行为序列模型都高度依赖历史连接与互动；随着越来越多新内容不再天然接入用户生成的 Pin-Board 图，新内容会在构图、召回、排序各层同时吃亏，形成老内容与成熟创作者越强、新进入者越难获得反馈的循环。论文把问题明确为漏斗级偏差，而不是在最终结果里机械插入一定比例新品。

此前工业方案常用专用冷启动双塔、Neural Thompson Sampling 或 user-corpus 共分流实验，但 Pinterest 发现三处现实障碍：跨三大入口、多个图片/视频/商品语料做全局 corpus 分桶成本过高；只在 x% 语料上实验无法准确度量完整用户体验；缩小语料本身会伤害用户指标并限制并行实验数。PinEqualizer 的目标因此包含三部分：逐层找到新内容的真实瓶颈，减少模型对老内容的系统性偏置以降低强探索的短期代价，并用可快速迭代的代理指标连接长期留存和创作者生态。

2. 方法详解

系统先建立三层度量框架。第一层是长期 fresh-content holdout：实验组只能使用实验开始前的旧内容，生产组可使用新内容，同时按 content ID 哈希从生产组随机移除等量内容，排除候选池变大带来的天然优势，最终差异才代表新内容的增量价值。第二层是 content graduation：新内容在 Y 天内累积 X 次正向互动后，互动率方差显著下降，即从高不确定的探索阶段毕业到可预测的利用阶段；若充分探索后互动率上置信界仍低于阈值 Z，则归入低潜内容。第三层是用户 A/B 可快速观测的 under-explored content engagement volume，它只统计尚未毕业、也未判低潜内容获得的正向互动，与毕业量强相关，并且比曝光量更能约束相关性。

语料选择阶段维护独立探索池。初版使用 Thompson Sampling，对每个 item 从 Beta(α+e, n-e) 后验采样，e 是正互动、n 是曝光、α 来自内容提供者整体表现；同时加入创作者多样性约束。后续用内容与站外特征预测先验互动率 α，并用 r̂=(αN+e)/(N+n) 融合先验与观测，N 控制先验强度。每次刷新取后验 Top-K，达到毕业阈值或互动率上置信界低于门槛的 item 被退出，用新候选替换，避免把探索流量浪费在低潜供给上。

特征层重点不是继续堆历史统计，而是降低新内容缺失协同信号的惩罚。系统加入纯内容 Unified Visual Embedding、基于大视觉语言模型与 CLIP 对齐的 PinCLIP、Semantic ID；重型内容向量尚未产出时，每个维度从全库经验正态分布独立采样完成插补，避免统一零向量成为“新内容”泄漏标签。训练时对 item 历史互动计数与比率做 dropout，单个特征独立 dropout 优于整组同时丢弃；用户侧历史互动不做 dropout，以保留个性化。随后用 DCNv2 显式交叉内容年龄、内容特征和历史互动，让模型对新 item 更依赖语义，对成熟 item 更依赖行为。商家历史交易等站外信号提供先验，Flink 准实时管道则在探索早期快速更新互动率，老内容继续走低成本批处理。

召回层按 token、图和向量三种通道分别治理。Token Retrieval 为探索语料建立独立倒排索引，保证后续阶段始终收到一定数量新品；Pin-Board 图随机游走把连接到未充分探索 Pin 的边加权，抵消高连接老内容优势；ANN 既可用 PinCLIP 做专用探索索引，也可训练去掉互动特征的专用双塔。考虑长期运维成本，团队最终更偏好统一 learned retrieval，通过前述特征和去偏同时服务新老内容。Related Pins 的 query tower 还把内容与互动特征分开编码，到末层才融合，防止作为 query 的老 Pin 把偏差传给候选。

排序与 utility 层先做 content-type-aware calibration，把 fresh、old 等关键 cohort 作为校准类别，避免全局校准掩盖分组误差；再用分数正则让语义相近的新老内容分布对齐，并生成混合特征空间训练样本。该正则在 Related Pins 有效，但移植到 Search 时过强会显著损伤 query relevance，所以搜索入口必须更保守。显式探索采用 UCB_i=α/sqrt(1+β·impressions_i)，α 控制强度、β 控制随曝光衰减速度；放在 utility 层比直接改模型 logit 更易独立调参。更复杂的 Neural Linear UCB 使用主模型末层 φ(x)，以 φ(x)^TΣφ(x) 的平方根估计不确定性，并用二阶段无偏小样本校准更新协方差；为消除校准 batch 大小带来的探索幅度漂移，α 按 sqrt(N/N0) 缩放。搜索还设置最低相关性门槛，并把探索奖励改成 relevance_i^γ·UCB_i，避免不相关新品靠高不确定性上位。

论文没有披露主排序模型的优化器、学习率、batch size、训练步数、GPU 数量和绝对延迟，因此不能从正文补推这些参数。它的可复现部分主要是完整漏斗结构、指标定义、后验与 UCB 公式、特征/召回/校准设计及大量线上组件实验。

3. 核心技术贡献

第一项贡献是把冷启动从末端探索改写为漏斗生存问题。团队对每层记录新旧内容的输入占比和 Top-k 存活率：Related Pins 曾经上游供给充足却在最终排序大量跌出 k，Search 同期则在召回层流失；通过过召回新品再跑相关性模型，确认搜索语料实际有足够相关供给，瓶颈确实在 retrieval。这种诊断避免所有团队同时优化同一层，也解释了为何单独增强排序有时没有线上收益。

第二项贡献是以“减偏”降低“强探索”成本。纯内容向量、缺失特征插补、item 互动 dropout、年龄交叉、分 cohort 校准和查询塔晚融合共同提升新老内容预测可比性，显式 UCB 只负责剩余不确定性。与只给新品额外流量相比，这一组合能减少无关或低潜内容占位，并让训练反馈本身更干净。

第三项贡献是三层测量闭环。长期 holdout 给出北极星因果增量，28 天毕业量反映语料是否从探索走向稳定，under-explored 正向互动让普通用户分流实验快速判断组件。论文还明确承认共享语料会导致 treatment 帮助 control、从而低估代理指标，但观察到毕业后次日即退出统计且低流量实验两组用户看到的内容差异较大，泄漏在实践中有限。

第四项贡献是跨 Homefeed、Related 与 Search 的两年工业部署证据，而非单一公开集离线实验。论文给出各组件、入口、用户会话、购物与创作者生态的量化结果，使团队可以比较基础探索、模型去偏与更复杂 bandit 的边际价值。

4. 实验结果分析

整体结果来自 2024 年下半年以来逐步上线和长期 A/B holdout 的累计影响。最直观的站点级指标是新内容曝光累计增长 350%。三层指标链也同时改善：28 天内毕业内容库同比增长 41%，成功内容提供者数量同比增长 99%；北美与国际市场的成功会话增量分别提升 24% 和 49%，购物会话分别提升 63% 和 29%。三个入口的 under-explored 内容互动量累计提升为 Homefeed 37%、Search 13%、Related 27%。

Neural Linear UCB 比启发式 UCB 再提升 5.83%/5.32%，但团队没有在所有位置一律部署复杂方案：早期轻量 ranker 仍使用曝光数启发式，只在最终重排序使用 NLB。这是重要的工程消融——最高离线/线上增益并不自动意味着全链路最优，透明度、调参独立性和维护成本会决定放置位置。Search 上强正则导致 query relevance 明显下降，也是论文报告的失败案例；最终通过更保守的正则、最低相关性门槛和 relevance 缩放 UCB 保住语义相关性。

长期结果强在覆盖多入口与生态指标，但仍有解释边界。站点表使用 2025 对 2024 的同比相对增幅，且系统由多次上线共同贡献，无法从公开数据重建每个组件的独立因果份额。绝对会话量、实验流量、置信区间、显著性水平、P99 延迟和成本没有披露；350% 新内容曝光也必须和成功会话、毕业率与低潜内容淘汰一起看，不能单独当质量指标。

5. 局限与未来方向

作者在结论中明确提出，下一步会继续改进各漏斗组件，并把探索产生的长期创作者价值等更复杂目标纳入系统。正文还暴露了若干明确限制：user-corpus 共分流在多入口多语料上成本过高；普通用户 A/B 的共享语料仍会产生 treatment leakage，使代理指标低估真实收益；不同入口的最优技术并不完全可迁移，Related Pins 的强分数正则在 Search 会伤害相关性。

论文没有报告训练超参、模型规模、硬件、流量占比、绝对延迟和单位增量成本；因此外部团队可以复现原则，却无法按文中配置复刻容量规划。主要结果是多年度、多组件累计提升，而非单次随机实验，季节性、语料增长与产品变化可能混入同比指标。成功创作者以站点互动份额超过某阈值定义，但阈值、集中度和小创作者长期留存未披露。

作者未充分讨论的边界包括内容质量模型对新创作者可能再次形成先验歧视，站外商家数据会让有外部规模的供给获得优势，Semantic ID 与 VLM 可能把视觉风格偏见带入探索。按经验正态分布插补向量虽然优于固定零值，但会产生不一定对应真实内容的伪特征；需要监控插补样本的校准和错误曝光。探索还必须受内容安全、版权、地域政策和用户敏感偏好约束，不能只靠 engagement 上置信界。

6. 工业实践意义

对搜索/推荐团队，第一步不是上线 bandit，而是建立 full-funnel 生存看板：按内容年龄、互动量和创作者成熟度分 cohort，记录每层输入占比、Top-k 存活率、最终正向互动与毕业速度。用过召回加高精度相关性模型验证“库里是否存在合格新品”，再决定优化语料、召回还是排序。社区 UGC 可把毕业定义为帖子在限定天数内达到足够多的高质量互动，使互动率或相关性估计进入稳定区间；低潜退出则结合负反馈、内容质量和上置信界。

第二步优先做低风险去偏：引入只依赖文本/图像的内容向量，对尚未生成的重型特征显式插补并增加 missing indicator；只 dropout item 历史热度，不破坏用户兴趣；用内容年龄×语义×互动的 DCNv2 或门控模块动态切换信号；对新老内容分别校准。搜索场景必须把 query relevance 设为硬护栏，任何探索奖励都应经过最低相关性过滤和相关性幂次缩放。

第三步再配置探索通道。倒排、图和 ANN 各保留可观测的新内容配额，但不要绕过主排序；使用后验 Top-K 和毕业/低潜淘汰控制探索池容量。UCB 建议先从实时曝光数启发式开始，参数可在 utility 层独立调节；只有当末排模型已提供稳定表征、无偏校准集和协方差更新能力时，再引入 Neural Linear UCB。批大小变化需要像论文一样归一化探索强度，防止同一参数随训练样本规模漂移。

评测至少保留三种时间尺度：小时/天级看未探索内容正向互动与总体 CTR 护栏，28 天级看毕业量和低潜淘汰率，季度级用新内容 holdout 看成功会话、留存和创作者多样性。还应补充绝对曝光、投诉率、内容安全命中、创作者集中度、P95/P99 延迟与每千次探索成本。PinEqualizer 最值得借鉴的不是某个 UCB 公式，而是把诊断、去偏、探索和长期生态测量连成一条可逐层回滚的生产链路。

深度解读：Long-History User Transformers 的离线—在线长序列拆分

1. 问题与动机

在线广告 CTR 排序必须在几百毫秒内完成候选打分，而长行为序列 Transformer 的计算随序列增长，若为每次请求重算数千事件，无法进入竞价关键路径。已有 HSTU 展示了 8000 行为生成式建模，LLaTTE 讨论多阶段序列缩放，TransAct 则聚焦实时近期行为；但工业系统仍缺少一个明确答案：能否保留长历史的大部分质量，同时让在线只承担固定、可控的小窗口成本。

论文还指出长历史不是单一广告日志。Yandex 用户的真实意图分散在自然搜索 query、自然点击、Search Ads、Yandex Advertising Network（YAN）和 Product Gallery。只看目标广告面会丢掉大量先于广告点击出现的意图信号；但把所有表面拼接后简单多任务训练又会产生梯度干扰和位置偏差。作者因此把研究问题拆成六个可检验部分：拆分架构能恢复多少完整模型收益、数据与训练配方有多重要、缓存向量能容忍多陈旧、能否跨广告表面迁移、历史长度是否真的决定收益，以及线上增益是否在不增加延迟的条件下成立。

2. 方法详解

数据层构建统一跨表面时间线。每个事件包含时间、surface/交互类型、banner ID、文本向量和点击标签。自然 query 与自然点击各占一个 token；广告事件把 context 作为一个 token，再把 banner embedding 与 action embedding 相加形成第二个 token，因此一个广告事件占两个位置。系统区分 NoAware、ContextAware 和 TargetAware：NoAware 只编码历史、可完全离线；ContextAware 还看当前页面/设备等请求上下文但不看具体候选，一次前向可服务多个广告；TargetAware 把候选写入序列、每个候选重跑模型，成本随候选数增长。生产选择 ContextAware，兼顾上下文质量和多候选吞吐。

预训练使用带 causal mask 和 ALiBi 的统一 Transformer，在一年约 10 亿事件上训练。Search query 占事件 40%、自然点击 30%，Search Ads 与 YAN 各约 13%–14%，Product Gallery 3%。三个广告面同时承担二元 CTR 交叉熵与 next-event retrieval 目标；自然 query/点击没有 CTR 标签，但通过 sampled-softmax 预测下一次自然事件，所以每个 token 都贡献监督。统一预训练让底层同时学到行为反馈和下一事件语义，之后从同一个 checkpoint 初始化离线与在线编码器。

部署模型约 2 亿参数。离线 Transformer 输入维度 64、hidden size 1024、10 层、ALiBi、全因果注意力，最多处理 8192 token；线上 Transformer 同为 1024 hidden，但仅 5 层、无显式位置编码，每层窗口 20，总感受野 100 个事件，生产最多可输入 200 个事件但最终选择 100 作为延迟折中。两塔输出维度为 128。在线编码器复制预训练模型的前 5 层初始化，比随机初始化的 CTR fine-tuning loss 更低；短窗口本身提供强局部顺序约束，因此实验中无需额外位置编码。

离线模型取完整历史最后一个 hidden state 作为固定用户向量。训练时故意模拟生产陈旧：对曝光时刻 t，只给离线塔输入 t 两天以前的事件，因为真实管道约需一天摄取去重、另一天合并历史、GPU 批推并写入特征库。线上读取当前缓存，不人为截断；每次广告点击触发重算，低活用户每周全量刷新。在线塔始终取最新固定数量事件，因此活跃用户主要看到两天内新信号；若两天内无活动，窗口会与离线前缀重叠，但不会产生历史空洞。

融合时把预训练联合 head 换成可部署的双塔。离线向量和在线最后 hidden state 拼接，经 DCNv2 与 MLP 投影为用户侧 128 维向量；候选 banner embedding 经过同结构 DCNv2+MLP 映射到同一空间，最终内积得到 CTR 分数。候选向量可预计算缓存，线上 Transformer 每请求只跑一次，不随候选数量线性重复。运行时模型采用 windowed causal attention，单层复杂度由全注意力的 O(L²) 限制为 O(LW)；离线 8192 全注意力在专用 GPU 异步运行，不进入请求关键路径。

训练使用 Adam，无 warmup、无 weight decay，并关闭 dropout；学习率按约每 1/5 epoch 衰减 3 次，HTML 版本未显示初始数值。预训练 1 epoch，64 张 NVIDIA A800，每张卡 pack 5 万 token，约两天完成；随后在目标广告面端到端 fine-tune 3 epoch，同时更新两编码器和预测 head。位置去偏时，历史事件始终保留真实展示位置；训练候选用真实位置，推理候选位置固定为 1，迫使模型预测“若位于首位”的内在点击概率，削弱位置对 CTR 的混杂。

3. 核心技术贡献

第一项贡献是把长历史质量与请求成本真正解耦。离线塔吸收 8192 token 的全局信号，在线塔只负责 100 个近期事件和当前上下文，两者不是简单蒸馏，而是在 CTR fine-tuning 中联合训练为互补表示。离线向量相对仅在线模型额外贡献 5.3 个百分点的归一化 log-loss 增益，说明缓存不是冗余摘要。

第二项贡献是跨表面、异构 token 的双目标预训练。自然搜索行为没有广告点击标签，却通过 next-event retrieval 成为主动监督；广告事件同时学 CTR 与检索。加入自然点击使收益从 +8.5% 增至 +11.0%，表明用户意图数据的覆盖度与架构宽度同等重要。最终再做单表面 fine-tuning，解决共享预训练中的梯度干扰。

第三项贡献是面向真实管道训练“陈旧分布”。作者没有在训练时使用完美新鲜的离线向量再到线上接受两天延迟，而是直接用两天 cutoff 构造样本；随后通过 5 天 embedding lag 与 6 个月 checkpoint age 实验区分“表示陈旧”和“模型陈旧”，据此设计点击触发加每周批刷，而非盲目每事件更新。

第四项贡献是完整线上闭环：模型分数只作为现有 CatBoost CTR ranker 的新增特征，隔离了长序列信号的增量；在线 Transformer 与既有特征管道并行执行，计算被现有延迟预算吸收。Search Ads 和 YAN 两个结构不同的表面均获得显著业务收益且辅助指标无回退。

4. 实验结果分析

离线主指标不是 AUC，而是给生产 CatBoost 加入 Transformer 特征前后的归一化 log-loss 差。广告排序的预测会进入竞价、预算节奏和收入计算，校准与顺序同样重要，因此 log-loss 比只看排序的 AUC 更贴近业务。完整在线 8k 模型作为不可部署上界，收益 +16.2%；只用在线 Transformer 时，200/100 事件分别为 +7.29%/+6.30%，半尺寸模型为 +7.01%/+5.75%。加入离线 8k 后，半尺寸在线 200/100 事件达到 +12.3%/+11.7%，分别恢复完整上界的大部分收益。

感受野比宽度更重要：在 200 事件下，全尺寸与半尺寸只有 7.29% 对 7.01% 的差距；把在线窗口从 100 增至 200 带来温和提升，但生产仍选择 100，因为 +11.7% 已接近 200 事件的 +12.3%，而注意力预算更紧。跨表面上，Search Ads 有显式 query，完整模型上界更高；YAN 只有页面上下文与历史，绝对增益较小，但拆分保留率反而达到 80%，说明离线表示学到的是可迁移用户模式而非单表面技巧。

训练配方消融同样关键。三表面多任务 baseline 为 +7.5%；只在目标 Search Ads fine-tune 后 +8.5%，表明共享目标存在梯度干扰；加入自然搜索点击后 +11.0%；候选位置去偏加更高学习率后 +15.0%，最后一步贡献 +4.0 个百分点，为最大单项。这个结果提醒实践者：长序列模型效果不应全部归因于参数规模，跨表面行为、目标适配和位置因果混杂往往是一级因素。

陈旧度实验中，缓存 embedding 延迟 5 天只损失 0.38 个百分点，变化是渐进的；6 个月旧 checkpoint 却损失 3.40 点，约高一个数量级。历史完全不看当前请求的 NoAware 模式仍有 +2.81%，说明即使搜索广告强依赖 query，长期广告互动也包含独立信号。注册用户 PUID 平均历史 1200 条，增益 +18.22%；匿名设备 UniqID 平均 550 条，增益 +13.32%，历史长度与收益方向一致，也揭示了持久身份用户受益更大。

线上 A/B 中，Search Ads/YAN 的主 acceptance 指标分别 +2.77%/+2.10%，点击 +2.87%/+2.59%，收入 +2.26%/+0.43%，均具统计显著性。YAN 点击增长快于收入，但广告主侧 post-click conversion 同步改善，作者认为这是更高广告主价值的点击，而非低 CPM 流量稀释。所有辅助指标改善或中性，服务延迟没有增加；Search Ads 收益主要集中在移动端，因为原移动 baseline 使用的长历史信号较少。

5. 局限与未来方向

作者在结论中明确提出三条未来路线：为缓存表示加入内容对比学习、转化和复访等长期辅助目标；依据用户会话新鲜度动态分配在线感受野，而不是所有人固定 100；系统研究模型深度、序列长度和特征丰富度的 scaling law，辅助容量规划。论文也明确指出实现依赖 Yandex 的异步 GPU、特征库和现有 CTR 并行管道，跨公司可迁移的是拆分模式，不是原样系统配置。

实验主要来自 Search Ads 和 YAN，Product Gallery 只参与预训练且占 3%，没有给出独立线上结论。绝对训练样本/用户分群细节、初始学习率、batch 的样本数、GPU 利用率、特征库容量、离线刷新成本及在线 P99 延迟均未披露。离线上界用完整 8k 在线模型测得，但它本身不可生产，未比较蒸馏、长序列检索压缩或线性注意力等其他成本方案。

作者未充分讨论的风险包括：PUID 跨设备长历史比匿名用户丰富，收益差距可能扩大个性化体验不平等；广告点击触发刷新让高活用户更及时，低活用户只每周更新，可能进一步强化活跃度偏差。跨表面时间线涉及隐私、目的限制和特征保留期限，特别是自然搜索行为用于广告建模，需要严格权限、脱敏和用户控制。缓存向量与模型版本必须成对管理，否则新 checkpoint 读取旧空间向量会产生兼容性故障。

6. 工业实践意义

社区搜索或推荐团队可以先做低风险验证：不替换现有排序器，只把长序列模型分数作为 GBDT/深度 ranker 的一项新增特征，按归一化 log-loss、校准、NDCG、CTR 与负反馈评估净增量。事件时间线应覆盖 query、点击、收藏、关注、作者互动和内容消费，但每种事件明确 token 化与监督任务；无点击标签的 query/浏览可做下一事件或对比目标，而不是被动上下文。

架构上可从 7 天或更长历史的离线用户向量加最近 50–100 事件在线塔开始。训练时按真实数据 SLA 截断离线前缀，若生产需要两天才能产出向量，训练就必须模拟两天 lag。候选侧尽量预计算，用户侧融合使用轻量 DCNv2/MLP；在线塔和其他特征 RPC 并行，而非串在召回之后。先做窗口长度与网络宽度消融，论文结果提示扩感受野可能比加宽更划算。

刷新策略应由陈旧曲线决定。分别测 embedding lag 1/3/5/7 天和 checkpoint age 1/3/6 个月，若表示缓慢退化，可用高价值行为触发更新、低活用户周期批刷；但模型重训频率不能因缓存稳定而放松。需要建立 embedding_schema_version、model_version、生成时间和 TTL，支持双写、回滚与缺失时退回短序列模型。

位置去偏是可直接借鉴的训练细节：历史保留真实位置用于解释行为，待评分候选在推理时固定到同一标准位置，输出更接近内在相关性，再由下游 utility 决定最终展示。上线必须按注册/匿名、历史长度、设备、活跃度和隐私授权分层，防止只改善长历史用户。成本侧同时监控离线 GPU 小时、特征库字节/用户、点击触发刷新 QPS、在线 P95/P99 和缓存命中率。该论文的核心启示不是“所有请求跑 2 亿参数”，而是把昂贵的全历史理解移出关键路径，把在线算力集中在最新意图。

RankGraph-2 深度解读

1. 问题与动机

十亿节点图学习需要同时解决图构建、表征学习、实时服务三个相互耦合的问题，但已有工作各自孤立处理。论文明确指出在 Meta 的规模下：朴素地构建完整共现图不可行（原始约 100 万亿条边）；朴素地在图上训练需要昂贵的在线图基础设施；朴素地用在线 KNN 服务 embedding 需要数千台机器。量化的失败模式很直白——GAT+Deep Graph Infomax 在用户 embedding 上 Recall@5 仅 0.038，远低于 RankGraph-2 的 0.143（3.8 倍差距）；PyTorch-BigGraph 在 item 检索上 Recall@100 仅 0.374，约为 RankGraph-2（0.775）的一半。问题之所以紧迫，是因为三者需求互相牵制：服务侧若要避免在线 KNN，就必须把索引能力前置进训练；训练侧若要省掉在线图设施，就要求构建侧产出自包含数据并支持小时级刷新。

2. 方法详解

图构建：异构图含三类边，全部来自用户行为（不引入外部社交/知识图谱）。U-I 边按近 T 小时是否交互建立；U-U 边在两用户共同交互 ≥C_U 个 item 时建立，权重 w = ln(Σ w_{n_i,e}·w_{n_j,e})；I-I 边类似。对 I-I 边做流行度偏置校正 w' = w × (w_{ji}/Σ w_{jk})^α（α=0.3），压低热门 item 的边权。边子采样：原始约 100 万亿边，保留约 0.1B 优先用户节点（每日刷新）加全部 item，每节点按权重保留 top K_CAP 边，降到数千亿量级（三个数量级）。再用 personalized PageRank（随机游走蒙特卡洛、重启概率 0.15）为每节点预计算 K_IMP=50 个重要邻居，训练时每条边采样 K'_IMP=10 个。数据按边类型分区、自包含，训练不需访问在线图。

表征学习：节点表征 M(n_i)=AGG_t(f_t(自身特征), {f_U(用户邻居)}, {f_I(item 邻居)})，每节点固定 K 个预计算邻居；多头 embedding 用于负样本增强、推理时平均。负采样每条正边配 100 个同类型负例（in-batch + 跨 batch 滚动池 + 多头互为负例）。损失是 margin ranking loss（margin=0.1）与 InfoNCE（τ=0.06）的加权组合，再按四类边（U-U/U-I/I-U/I-I）用不确定性加权聚合。训练 batch=32768，稀疏参数用 AdaGrad（lr 0.02）、稠密用 AdamW（lr 0.004），embedding 维度 256。

共训练的残差量化聚类索引：两层 codebook（5000×50=25 万簇），残差量化 k_i=argmin||h_{i-1}-C_{i,j}||²、h_i=h_{i-1}-C_{i,k_i}，重构 h'=Σ C_{i,k_i}。把重构损失 ||h-h'||²、对重构 embedding 的链接预测损失、以及码字不均衡正则 L^reg 一并并入训练目标——这正是"把索引共训练进训练目标"的具体含义。为对抗持续训练下的 codebook 崩塌，用基于历史 1000 个 batch 码字分布 p̂ 的正则惩罚高频码字，并改用偏置码字选择 k_i=argmax p(h,C_i)[j]/p̂[j] 偏向冷门码字。

服务：U2U2I 把候选限定在近期活跃用户（如近 15 分钟）效果最好；每用户经残差量化得到簇码 (k1,k2)，每个簇维护其近期活跃成员产生的实时 item 队列，服务时只需查目标用户所在簇队列的最新 item，无需最近邻搜索，使基础设施成本降 83%。U2I2I 因 item embedding 更新慢，I2I KNN 离线预计算，本就便宜。整条链路从行为数据到刷新 embedding 约 2 小时，图每 3 小时全量重建、单次构建约 1 小时。

3. 核心技术贡献

1）生命周期联合设计：把构建—训练—服务当作互相约束的整体而非独立模块。机制上，服务对"避免在线 KNN"的需求把聚类索引推进训练目标；训练对"相似度检索可容忍预计算邻居"的观察消除了在线图设施；构建据此产出自包含数据并支持 3 小时刷新。
2）共训练的残差量化聚类索引：相比事后再对 embedding 聚类建索引，把 25 万簇码本与表征一起学，使簇本身对检索目标可用。消融显示带正则的重构 embedding Hitrate@1 为 0.846，去掉正则掉到 0.717（崩塌），码本利用率从 100% 显著下降，证明正则与偏置码字选择对持续训练下防崩塌是必要的。
3）PPR 多跳邻居 + 流行度校正：PPR 邻居相比随机邻居（Recall@5 0.045）和仅 1 跳 top-weight（0.098）提升到 0.143；流行度校正使 item Recall@100 从 0.620 升到 0.775。

4. 实验结果分析

离线（10 万采样用户，对次日行为算 Recall@K）：用户 embedding 上 RankGraph-2 Recall@5/10/50/100 = 0.143/0.209/0.399/0.482，对比 GAT-DGI 的 0.038/0.066/0.180/0.251 和 HSTU 基础模型的 0.013/0.024/0.085/0.135 全面领先，说明该任务上联合设计胜过更复杂架构与基础模型。item embedding（按天时序切分、1000 条 I-I 边）RankGraph-2 Recall@100=0.775，对 PyTorch-BigGraph 0.374（2.1 倍）、HSTU 0.434（1.8 倍）。索引质量上原始 embedding Hitrate@1=0.871，带正则重构 0.846（仅降 0.025），无正则 0.717。

消融：边类型上 U-I only Recall@5=0.052，加 I-I 到 0.089，加 U-U 到 0.115，三类齐全 0.143——U-U 带来发现能力、I-I 补长尾覆盖，收益叠加；邻居选择上 PPR 多跳明显优于随机和 1 跳。线上 14 天 A/B（p<0.05）：U2I2I 在 Surface 1 +0.96% CTR/+2.75% CVR、Surface 2 +0.33%/+0.76%；U2U2I Surface 1 +0.40% CTR/+1.01% CVR。共训练聚类索引在与在线 KNN 可比的 CTR/CVR 下把服务设施从数千台机器降 83%，已支撑 Meta 20+ 召回上线。一个值得注意的反直觉细节是：HSTU 这类基础模型在该相似度检索任务上反而不如专门设计的 RankGraph-2，提示"基础模型并非处处最优"。

5. 局限与未来方向

作者明确的局限有三：1）联合设计针对相似度检索（U2U2I/U2I2I）这类结构信号主导的场景，对直接的 user-to-item 检索，带实时行为特征的排序模型可能更有效；2）离线预计算邻居，无法支持需要 query 相关、动态邻居探索的任务；3）3 小时刷新对极端时效场景可能不够，U2U2I 通过近 15 分钟候选过滤来缓解。这些边界划得很诚实——它没有声称图召回能取代排序，而是定位在召回的相似度通路上。论文未展开但值得留意的是：0.1B 用户节点的每日筛选规则、流行度校正 α=0.3 与各类边权 β 的迁移性，换平台需重新调参。

6. 工业实践意义

对搜推从业者，最可直接借鉴的是"把索引当作可学习对象与表征一起训练"这一思路：传统做法是先训 embedding 再用 ANN/IVF 事后建索引，而这里把 25 万簇码本并入训练目标，使簇对检索目标本身可用，服务时退化为"查簇队列最新 item"，省掉在线最近邻搜索，设施成本降 83%——对自建召回、机器预算紧张的团队极有价值。其次，PPR 预计算多跳邻居加边权流行度校正（α=0.3）是低成本高回报的组合：前者把图结构信息固化进自包含训练样本、免去在线图设施，后者直接缓解热门物料挤占长尾。持续训练下的 codebook 崩塌问题及其正则/偏置选择解法，对任何用 VQ/RQ 做 semantic ID 或聚类索引的系统都有参考价值。部署上要注意：方法定位召回相似度通路，不替代排序；3 小时图重建加约 2 小时端到端 embedding 刷新的节奏，需配合 U2U2I 的近 15 分钟候选过滤来保时效。对社区 UGC 召回，U2U2I（找相似用户、取其近期内容）尤其契合"新内容快速分发"的诉求。
