Trust or Abstain? A Self-Aware RAG Approach

RAG 在外部证据 (CK) 与模型参数知识 (PK) 冲突或两者都不可靠时容易产生错误。作者基于五个冲突 QA 数据集，针对每个 LLM backbone 构造了约 69K 条 query-context 实例的 ground-truth-aligned 冲突基准，量化测得 PK-only 与 CK-conditioned 两条答案路径的可靠性。在此基础上提出 SABER：一个无需微调 LLM 的 Self-Aware Belief Estimator，将 self-prior 与 PK/CK 两侧条件概率组合后再决定是回答 (Trust) 还是拒答 (Abstain)，在 5 个数据集上拒答-准确率 Pareto 优于纯一致性投票与置信度阈值方法。

Trust or Abstain? A Self-Aware RAG Approach — 深度解读

1. 问题与动机

RAG 已成为缓解 LLM 幻觉的主流范式，但作者指出已有方法在面对 知识冲突 时只做了 "二选一" 的路由：要么相信模型的参数知识 (Parametric Knowledge, PK)，要么相信检索到的上下文知识 (Contextual Knowledge, CK)，几乎没有方法显式地问 "这两条路径都不可靠时该怎么办"。作者用 "考试 + 教科书" 的类比刻画该 gap：一个学生既有记忆 (PK) 又有可能错误的参考书 (CK)，理性策略是 "两者都不可靠时拒答"，而当前 RAG 系统经常被迫给出 confident hallucination（参数知识被高估、忽视纠正性证据）或 context over-reliance（被错误检索片段误导，丢弃正确内部知识）。

为量化这个问题，作者基于 5 个冲突 QA 数据集 (ConFiQA QA/MR/MC、ConflictQA-PopQA、ConflictBank、TriviaQA、Natural Questions) 在 4 个 backbone (Qwen-2.5-3B/7B-Instruct、Llama-3.2-3B、Llama-3.1-8B) 上构造了约 68,872 / backbone 的 PK 路径 vs. CK 路径 ground-truth-aligned 实例，发现在 ConflictBank 上当前最好的 inference-time 路由 TPC 的 Macro Faithfulness Score 仅 64.3%，远低于本文 SABER 的 92.5%——也就是说在两条路径冲突时，主流方法有近 1/3 的样本选错了知识源。

2. 方法详解

SABER 的核心是把 "Trust or Abstain" 建模为四象限决策：用 self-prior 表征模型对问题本身的把握，用 PK-条件 / CK-条件表征对每条答案路径的事后可靠度，再用两个轻量分类器输出 PK / CK 的可靠概率，最后落到四象限规则。

(a) Self-Prior 表征：只输入 query，不带任何检索内容，做一次前向，把第 ℓₚ 层 hidden state 抽出来作为 "考前直觉"，反映模型对问题本身是否有把握。

(b) PK-条件推理表征：让模型按 "假设我的参数知识正确" 生成 K = 3 条 chain-of-thought rollout（temperature = 0.9 采样保证多样性），对每条 rollout 再做一次 self-evaluation 前向，把第 ℓc 层 hidden state 抽出，对 3 条 trace 做 mean pooling 得到 PK 侧 robust 表征。

(c) CK-条件推理表征：同样的 K=3 rollout，但前缀里强制 "假设检索文档可靠并包含必要事实"，按同样方式抽 hidden state 并 mean pool。

(d) 信念分类器：把 self-prior 分别与 PK 侧、CK 侧条件表征拼接，喂给两个独立的小型 MLP (256→128，ReLU + dropout 0.2)，输出 p̂_pk 与 p̂_ck。训练只用 BCE 在 PK / CK 是否能给出正确答案的标签上，AdamW lr = 1e-3，weight decay 1e-4，batch 256，最多 50 epoch 在验证集 AUROC 上 early-stop，patience 8。注意 backbone 全程冻结，只训 MLP，所以单条样本的全部训练成本只是抽几次 hidden state 加 256-128 MLP。

(e) 四象限决策：阈值 τ = 0.5，把 (p̂_pk > τ, p̂_ck > τ) 划成 4 个 cell。两侧都可靠取置信度更高的；只一侧可靠就走那侧；都不可靠则 abstain (在部署模式下也可以走 fallback)。τ 可以离线扫 [0.05, 0.95] 调风险-覆盖，无需重训。

3. 核心技术贡献

贡献 1：知识冲突基准化。作者第一次把 "PK-only vs. CK-conditioned" 两条答案路径在 5 个冲突 QA 数据集上系统对齐，对每个 backbone 生成 ~69K 条标注实例，按 80/10/10 切分 (55,097 / 6,889 / 6,886)。这套基准本身就是后续做 self-aware RAG 工作的基础设施，比此前 ConFiQA 等单点评测覆盖更广。

贡献 2：Self-Prior + 条件 hidden state 的解耦表征。不同于 Implicit-SCR 等只读单一隐状态的方法，SABER 显式建模 "对问题本身的先验" 与 "走某条路径后的事后可靠度" 两类信号。消融显示只用 prior 会比完整 SABER 在 Acc 上低 3-5%，只用条件信号也有 +2.8% Acc / +13.4% MFS 的提升，验证了 "条件化 hidden state 比 prior 携带更多可靠性信息" 的判断。

贡献 3：多 trace mean pooling 的鲁棒性。K = 3 比 K = 1 在 Qwen-2.5-3B 上拿到 +3.2% MFS，对小模型增益最大；并且层扫描显示 mid-to-late layer 40%-70% 处都属于高准 plateau，超过 33% 网格点能进入 90 分位，方法对层选择不敏感。

贡献 4：无需 fine-tune 即可比肩 DPO。在 Llama-3.2-3B / Qwen-2.5-3B 上 SABER 与 CR-DPO 持平甚至领先，证明冻结 backbone + 轻量分类器可以替代代价更高的 RLHF / DPO 训练。

5. 局限与未来方向

作者在 Appendix G 自述三点局限：(1) backbone 局限于 Llama-3.x / Qwen-2.5，未在 mixture-of-experts、reasoning-distilled 模型 (DeepSeek-R1、QwQ) 上验证；(2) 检索侧只用 top-1 passage，多 passage 聚合与不同检索质量 (recall@k) 的影响未研究；(3) 冲突基准是 "静态构造" 的，真实 RAG 中的分布漂移 (时间敏感事实、对抗性投毒) 没有覆盖。

笔者补一条更隐性的：SABER 拒答标签 y_pk / y_ck 来自 "模型回答与 gold 一致"，对开放式生成（摘要、解释）天然不适用，泛化到开放生成需重设计标签。

6. 工业实践意义

对社区 UGC 搜索这种 "召回内容质量高度参差" 的场景，SABER 给出非常贴近上线的范式：

(1) 落地步骤。给现有 RAG 系统加 SABER 几乎不动 backbone：a. 选好层 ℓₚ / ℓc（中层 40-70% 即可，无需精调）；b. 离线在站内冲突 QA / 站内问答日志上构造 ~50K-100K PK / CK 标注样本；c. 训两个 MLP，单 GPU 跑数小时；d. 上线时只需 K=3 rollout + 2 次条件 self-evaluation 前向。

(2) 业务收益。最直接的是把 "自信胡说" 转化成 "安全拒答"，对应到产品就是 "展示原帖让用户自己判断" 的兜底逻辑，能显著降低 LLM 摘要在 UGC 噪声上的 risk-on-answered。Pareto 提升 19%-53% 的 risk 降幅意味着同样 coverage 下假阳显著减少。

(3) 部署成本。多 trace 在 7B 模型上单 query 需 ~6-8 次前向，是裸 RAG 的 2-3×，可以用 SGLang/vLLM 的 prefix sharing + speculative decoding (本日 Top-2 Graft 论文) 摊薄；阈值 τ 完全离线可调，所有 backbone 上 τ ∈ [0.40, 0.55] 范围内 MFS 波动 < 0.9%，业务方调 coverage 时不必担心翻车。

(4) 风险与配套。需要为 abstain 设计 fallback UX（例如："我们暂时没有把握给出答案，请查看以下相关帖子"），否则拒答率 > 20% 时用户体验下降明显；同时 self-prior 容易被 prompt 注入污染，K=3 rollout 内若出现 prompt injection 鼓励 "高自信"，建议把 self-prior 抽取限制在系统 prompt 之上的固定查询模板。

Draft Less, Retrieve More: Hybrid Tree Construction for Speculative Decoding

投机解码 (Speculative Decoding) 通过 draft-then-verify 加速 LLM 推理，但密集 draft tree 的 VRAM 带宽和算力开销吃掉了端到端 speedup；动态剪枝又会丢候选导致接受率下降。作者提出 Graft：把剪枝和检索耦合成互补操作，先 prune 释放预算，再用 retrieval 从 n-gram/缓存中补回被剪掉的高质量候选，形成 prune-then-retrieve 的 hybrid tree。实验显示在保持/超过 dense tree 接受长度的同时显著降低 draft 阶段算力，端到端 throughput 优于 EAGLE 等基线。

INSIGHT搜推线上 LLM 部署（搜索摘要、对话推荐）最痛的是 P95 时延，而投机解码已成为主流加速手段。Graft 的关键观察是 draft tree 不必都来自参数模型，可以引入轻量级 retrieval-based draft 来弥补剪枝后的覆盖损失，这与搜索系统已有的 query log/n-gram 资产天然契合。对于 UGC 搜索，可以把站内热门 query 的延续、热门评论模板做成 draft 检索源，几乎零额外训练成本就能拿到接受率收益。

LLM-based Conversational Recommendation Agents with Collaborative Verbalized Experience

NetflixUUVACornell

现有 LLM-based 会话推荐 (CRS) 要么 retrieve few-shot 示例，要么抽全局规则，难以利用 implicit、偏好导向的历史经验。作者提出 CRAVE：先让 CRS agent 在历史 query 上跑 rollout，再基于用户反馈反思 agent 行为，构造 "verbalized experience bank"；再训一个 collaborative retriever，用 content-parameterized multinomial likelihood 在 query-item 对上微调，将经验向量与协同信号绑定。最后用 debater-critic agent (DCA) 在生成阶段对候选回复做对抗式自审，多个数据集上 Recall@K、Coverage 优于 LLM4CRS 与检索增强基线。

INSIGHT面向社区内容的对话式发现/搜索场景，CRAVE 给出一条 "经验沉淀-协同检索-辩论审校" 的完整链路。可借鉴的工程设计：(1) 把 agent 历史轨迹 + 用户点击/停留反馈做成 verbalized experience，本质上是把行为日志翻译成 LLM 可读的偏好规则；(2) 协同检索器用 multinomial likelihood 同时学语义相似度和协同信号，避免冷启动；(3) DCA 双 agent 自审等价于把 ranker 的 listwise pairwise 思路搬到生成阶段。

Yaochen Zhu, Harald Steck, Dawen Liang, Yinhan He, Nathan Kallus

Stage-adaptive Token Selection for Efficient Omni-modal LLMs

Omni-modal LLM (om-LLM) 把视频和音频编码成时间对齐的非文本 token，在 LLM 前向中处理这些密集 token 计算开销巨大。作者先做 layer-wise token dependency 分析，发现视觉/音频依赖呈 block-wise 模式且随深度衰减——晚期层很多非文本 token 在跨模态融合后变得冗余。基于此提出 SEATS：免训练、按 stage 自适应剪 token，前段保留较多多模态 token，深层激进剪枝；在多个 om-LLM benchmark 上以 30%-50% token 预算保留 ≥97% 任务精度，吞吐 1.6-2.1×。

INSIGHT短视频/图文社区的多模态搜索如果上 om-LLM，最大瓶颈就是非文本 token 数量。SEATS 揭示一条免训练优化路径：跨模态依赖是分块且随深度衰减的，剪枝策略必须分阶段而非全局固定比例。可在自己业务上先做同样的 layer-wise dependency 探针实验，验证 "早保留-晚剪枝" 假设是否仍成立，再决定按层动态调整 token budget 的具体曲线。

Measuring Prosodic Richness in LLM-Generated Responses for Conversational Recommendation

现有会话推荐评估几乎只关注语义相关性和推荐准确率，对生成回复的风格化、表达力度量缺失。作者提出 Prosodic Richness Score (PRS)：从结构性停顿、强调词使用、节奏变化三个维度组合的复合指标。在 ReDial (任务型) 与 INSPIRED (社交化) 两个 CRS 数据集上，对 6 个主流 LLM 做句级和回合级 PRS 对比，发现人类与模型回复在 PRS 上有 p<0.01 的显著差异，模型整体偏单调；进一步分析展示 prosody 与用户接受度、对话长度的相关性。

INSIGHT社区平台的对话式推荐和客服话术评估，单纯靠 BLEU、Recall@K 无法暴露 "虽然推对但话风很 AI" 的体验缺陷。PRS 给出可量化的风格化评估方案，三个子指标都可以直接基于规则计算，几乎零成本接入离线评估流水线。落地时可把 PRS 作为 reward shaping 信号或拒答门槛之一，区分 "机器味推荐" 与 "自然推荐"。

Darshna Parmar, Pramit Mazumdar

CEPO: RLVR Self-Distillation using Contrastive Evidence Policy Optimization

RLVR 训练中所有 token 得到同样的稀疏 reward，无法区分决策性推理步与填充词。条件化在正确答案上做 teacher 蒸馏会泄漏标签或信号过弱。CEPO 改成对比式提问：每个 token 同时计算 "正确答案下的概率" 与 "错误答案下的概率"，只把两者方向相反 (前者高、后者低) 的 token 视作真正的推理步并赋予更强 policy gradient 权重。错误答案 teacher 由 rejected rollout 自蒸馏构造，整体保持纯 on-policy。在 GSM8K、MATH、AIME 等任务上 +2~4% 优于 vanilla RLVR 与 baseline self-distillation。

INSIGHT搜推中的 LLM ranker / 解释生成器越来越依赖 RL 二段训练，痛点正是 reward 太粗。CEPO 提供一种细粒度 token-level credit assignment 的通用模板：用正反 teacher 概率差来标定真正贡献的 token。可借鉴的关键工程点：拒答样本本身就是天然的反向 teacher，无需额外标注；reward 加权而不是 mask，能保留训练稳定性。

Ahmed Heakl, Abdelrahman M. Shaker, Youssef Mohamed, Rania Elbadry, Omar Fetouh

STAR: Semantic-Tuned and Tail-Adaptive Retriever for Graph-Augmented Generation

Sichuan UniversityNUS

现有 GraphRAG 轻量检索器在 KG 多跳问答时存在两类偏置：Semantic Shortcut Bias (依赖少量高频路径) 和 Long-Tail Path Bias (长尾路径召回差)。STAR 用两套学习范式联合缓解：(1) token-level interaction learning，用 cross-attention 配合 hard path mining 联合建模 query 与候选路径，避免 dual-encoder 的语义捷径；(2) path-weighted contrastive learning，根据路径在训练集中的稀有度加权对比损失，强化尾部路径表示。在 HotpotQA、2WikiMultiHopQA、MuSiQue 上 EM/F1 与下游 LLM 生成质量均显著优于 GAR、SubGraphRAG 等基线。

INSIGHT社区搜索若引入 GraphRAG（实体-话题-用户图），最容易踩坑的就是头部话题/热门实体反复出现而长尾兴趣检不到。STAR 的两个机制都可以独立借鉴：cross-attention 替代 bi-encoder 适合做精排级别的轻量重打分；path-weighted contrastive loss 等价于把长尾路径当作 hard negative 的反向操作，提升尾部召回。
