1. IterCOMP: Reasoning-aware Adaptive Prompt Compression for Multi-hop Question Answering
4.35
Relevance 5 | Novelty 4 | Practical 4 | Evidence 4 | Timely 3

Summary: IterCOMP 针对文档过长、噪声干扰推理问题，提出无需训练的迭代压缩框架：把文档切成证据片段，用 bge-m3 稠密语义相似度与加权词法匹配筛选，让 LLM 判断证据是否足够，不足时生成下一跳追问。在 MuSiQue、2WikiMultiHopQA、HotpotQA 上取得 16.67/27.36、27.39/39.69、37.65/51.78 的 EM/F1，上下文比例为 0.14–0.37。

Key insight: 对社区短文本搜索，重要启示不是盲目扩大 top-K，而是让“证据是否足够”成为检索控制信号。双路分数 S=λ语义+(1−λ)词法与百分位截断能同时保留实体词和语义改写；下一跳追问可用于复杂 query 分解。线上落地应设置最大迭代轮数和 token 预算，避免错误的不可回答判断触发噪声循环。

2. Enhancing Scientific Named Entity Recognition via Large Language Models: A Type-driven Multi-task Learning Approach
4.10
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 4

Summary: TdSciNER 面向科学文本实体识别中的类型空间过大问题，先用实体类型过滤器缩小候选类型，再以多任务实体类型分类增强上下文表示，并按句子相似度与实体类型多样性选择示例。论文在 3 个数据集上达到接近全监督模型的表现，并通过组件分析验证类型过滤、辅助任务和示例选择均有贡献。

Key insight: 对社区 UGC query understanding，先判定候选意图或实体类型，再做语义匹配，比把全部标签塞给大模型更稳。可把类型过滤器放在召回前，减少 query 改写与实体抽取的提示长度；再以相似度加类型多样性选 few-shot 样例，兼顾长尾表达和领域覆盖。

3. When Lexical Change Misleads: Rethinking Dynamic Topic Model Evaluation with Traditional and LLM-Based Metrics
3.95
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 论文研究动态主题在词汇变化下的评测偏差，比较 CoNTM、DLDA 在 NYT、DBLP、arXiv 的 120 个主题，由 3 名标注者按词汇变化程度评估。传统时间一致性与人工判断的相关系数从 −0.256 到 0.614；LLM 语义相似度在 CoNTM 上与人工语义判断的 ρ 达 0.609/0.721/0.502，说明词面变化会掩盖语义稳定性。

Key insight: 搜索相关性评估不能只看词法重合或单一 nDCG 切片，尤其 UGC 新词、别名和话题迁移会造成 lexical drift。实践中可把 LLM 或 embedding 语义一致性作为旁路诊断，与人工 judgments、点击和词法指标并报；但不同模型在 DLDA 上一致性较弱，不能把语义分数直接当唯一金标准。

4. BM25-Augmented Many-Shot Translation for Low-Resource North-Eastern Indian Languages
3.80
Relevance 3 | Novelty 3 | Practical 5 | Evidence 4 | Timely 4

Summary: 论文在 WMT26 低资源翻译中用 BM25 从语言专属训练库检索最多 80 个平行样例，交给 Gemini 2.5 Flash 翻译，无需微调；覆盖 11 种语言、22 个方向。测试中 Bodo 英译目标方向 BLEU/ChrF++ 为 14.61/48.21，最佳配置 (r=80,d=49) 在开发集达到 76.37 ChrF、72.14 ChrF++；结果显示领域匹配比语料数量更重要。

Key insight: 它提供了一个低成本检索基线：先用 BM25 做 lexical recall，再让生成模型消费少量示例。对社区搜索可迁移为 query–帖子示例库，按语言、主题或业务垂类建索引，并用 r/d 网格调节召回量与高质量示例数。关键不是盲目扩大库，论文在 22 个任务上观察到方向差异，去重后 18/22 个最优配置改变。

5. Does a Language Server Save Tokens for Coding Agents? A Measurement Methodology and Preliminary Study
3.70
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 3

Summary: 论文用 tokens-to-success 比较 grep 与 LSP 语义检索，设计五臂消融，并测试 Claude Opus 4.8、Sonnet 4.6、Haiku 4.5。符号定位中 LSP 令 Opus token +6%、Sonnet +118%、Haiku −26%；跨文件引用任务 F1 从 0.706 升至 0.778，但 token +19%，收益取决于任务噪声与模型能力。

Key insight: 对 UGC 搜索，可借鉴按 query 类型路由检索器，而不是默认 dense 或 semantic 全覆盖。论文显示噪声高时语义检索更值：hono 仓库 F1 提升 +0.245，干净的 remeda 为 +0.000；精确词命中任务则 grep 更快。工程上可用 query 或候选词噪声估计控制是否启用重排，并保留实体名、评论原文等 lexical fallback。
