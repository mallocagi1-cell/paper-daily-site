Benchmarking KV-Cache Optimizations across Task Quality and System Performance for Long-Context Serving

这篇论文把长上下文 LLM serving 中最棘手的 KV-cache 膨胀问题做成统一基准，覆盖 KIVI、TurboQuant、SnapKV、CaM 四类量化、剪枝和合并方案。实验使用 Llama-3.1-8B-Instruct 与 Mistral-7B-Instruct-v0.3，在多文档 QA、单文档 QA、few-shot 与摘要任务上同时度量质量、吞吐、TTFT 和实际压缩率。结论是压缩率不能单独预测端到端收益：KIVI4 质量最稳，SnapKV 长上下文吞吐最好，CaM 在部分 QA 场景收益大但波动明显。

The Silent Hyperparameter: Quantifying the Impact of Inference Backends on LLM Reproducibility

CISPA

这篇论文把推理后端本身定义为影响 LLM 评测和线上行为的“隐性超参”。作者先梳理 200 个推理引擎，并分析 35,000 篇机器学习论文，发现具体 inference stack 很少被报告；随后在固定模型权重、解码参数和硬件的条件下比较 vLLM、SGLang、llama.cpp 等 5 个常用后端。结果显示，仅更换后端就可能让基准分数移动最高 16.6 个百分点，并引入高比例输出分歧。

INSIGHT搜索/推荐团队把 LLM 或 reranker 接入生产后，不能只版本化模型权重和 prompt，还要版本化推理后端、CUDA kernel、量化精度与批处理策略。论文提醒我们，离线评测、灰度回放和线上 A/B 的后端必须一致，否则小幅 nDCG/CTR 提升可能只是 serving stack 造成的数值差异。实践上应把 vLLM/SGLang/TensorRT-LLM 配置写入实验元数据，并在升级后端时重跑关键评测集。

David Pape, Jonathan Evertz, Lea Schönherr

vLLM, SGLang, or TensorRT-LLM? Picking an LLM Serving Stack

JarvisLabs

这篇工程文章比较 vLLM、SGLang 与 TensorRT-LLM 三类主流 LLM serving stack，重点放在 PagedAttention、continuous batching、prefix/radix cache、TensorRT 编译以及部署复杂度。它不是新算法论文，但把不同框架的适用负载讲清楚：vLLM 更像通用 serving 默认项，SGLang 更适合复杂会话和结构化生成，TensorRT-LLM 更偏稳定高吞吐 NVIDIA 生产链路。

INSIGHT对基础设施选型来说，这类文章的实用性高于单点 benchmark，因为线上瓶颈通常来自调度、KV cache、模型兼容和运维成本的组合。社区搜索如果要承载 query rewrite、RAG answer generation 或 reranker-as-a-service，建议按真实流量分三组压测：短 prompt 高并发、长上下文召回增强、多轮会话复用。框架选择应跟 workload 绑定，而不是把 tokens/s 当唯一指标。

vLLM vs SGLang vs TensorRT-LLM

Inference Engineering

这篇生产指南从 2026 年部署成熟度角度比较 vLLM、SGLang 与 TensorRT-LLM，给出很明确的工程判断：多数团队先用 vLLM；高并发 MoE 或结构化生成可优先评估 SGLang；稳定、大批量、NVIDIA 环境且有编译维护能力时再考虑 TensorRT-LLM。文章强调要用真实 workload benchmark，而不是用合成吞吐结果替代业务压测。

INSIGHT它对搜推团队的启发是把 LLM serving 当容量规划问题，而不是模型 API 封装问题。UGC 搜索里的 query expansion、意图识别、摘要生成、答案生成有完全不同的 prefix 复用率、上下文长度和尾延迟要求；同一后端很难在所有场景最优。落地时可以建立统一压测模板，把 TTFT、TPOT、P95/P99、GPU 利用率和失败率一起纳入上线门槛。

Running Low-Latency Analytical Workloads with GPU-Accelerated Presto on NVIDIA GB200 NVL72

NVIDIA

NVIDIA 这篇工程博客讨论如何在 GB200 NVL72 上运行 GPU 加速的 Presto，以降低大规模交互式分析查询延迟。虽然它不是专门的搜索排序论文，但 Presto 这类分布式 SQL 引擎常用于特征分析、日志回放、训练样本构建和在线指标排障；文章强调 GPU 化后可面向 very large datasets 提供低延迟分析能力。

INSIGHT对搜索/推荐基础设施来说，离线特征和在线指标的分析链路经常决定模型迭代速度。GPU 加速 Presto 的实践意义在于把“模型训练算力”和“数据分析算力”合并到同一代 AI 基础设施上，减少超大日志查询和特征回溯的等待时间。适合优先在高频排障查询、召回/排序样本回放、embedding 质量诊断等读密集场景验证成本收益。

vLLM vs TensorRT-LLM: 2026 Production Benchmarks

Lyceum Technology

这篇文章把 vLLM 与 TensorRT-LLM 放到生产推理成本框架下比较，关注吞吐、延迟、基础设施经济性和每百万 token 成本。它的核心价值不是提出新后端，而是提醒团队：当并发用户数上升时，engine 选择会直接影响 tail latency、tokens/s 和 GPU 成本曲线。文章适合作为从 vLLM 默认栈迁移到编译型 TensorRT-LLM 前的评估清单。

INSIGHT搜索/推荐里的 LLM 功能通常从少量流量试点开始，但一旦进入 query rewrite、智能摘要或客服问答主路径，推理成本会迅速成为业务约束。该文建议先用 vLLM 获得工程灵活性，再在稳定高流量模型上评估 TensorRT-LLM 的编译和维护成本是否值得。实践中应按业务 SLO 计算“每次搜索附加 token 成本”，而不是只看单机峰值吞吐。

ResonatorLM: Causal Resonant Field Mixing for Efficient Long-Context Language Modelin

ResonatorLM 尝试用物理启发的 causal resonant field mixing 替代 Transformer self-attention，把 token 序列视为受驱动的一维潜在场，并用阻尼谐振器的因果函数替代 attention dot product。论文在 6M 参数 matched setting 上测试长上下文建模，报告训练和 prefill 加速随序列长度增加而扩大，在 32K tokens 解码速度达到优化 Transformer 的 6.47 倍，WikiText 准确率为 61.31%，高于 55.32% baseline。

INSIGHT这篇更偏前沿架构探索，短期不适合作为线上替换 Transformer 的方案，但对长上下文成本曲线有启发。搜推系统里的长会话、长文档 RAG 和用户历史建模都被 attention 复杂度限制，ResonatorLM 说明“非 attention 长上下文模块”仍值得跟踪。实践上可以把它放入研究雷达，而不是本季度落地清单：先关注开源实现、规模扩展和真实检索任务表现。

除了相似度搜索，2026 年的向量数据库还在卷什么？

这篇中文文章讨论 2026 年向量数据库从单纯相似度搜索扩展到多模态融合、分布式架构、存储计算分离和 AI 生态集成的趋势。它没有严格实验，但覆盖了中文工程社区正在关注的基础设施问题：向量检索不再只是 ANN 索引，还要处理多模态 embedding、混合检索、规模扩展、质量保障和上下游工具链。

INSIGHT对 UGC 搜索系统来说，向量库选型要从“查得快”升级为“能支撑完整检索平台”。如果未来要把帖子、图片、评论、用户行为和知识库统一检索，向量数据库需要同时支持多模态向量、标量过滤、冷热分层、在线更新和召回质量监控。该文适合作为中文团队的选型背景材料，但具体采购或改造仍需用自有 query 集压测召回率、P99 和写入延迟。

Introducing GPT-Live

OpenAI

OpenAI 发布 GPT-Live，称其为用于自然人机交互的新一代语音模型，并已驱动 ChatGPT Voice。候选摘要没有披露公开 benchmark，因此证据质量分较低；但它仍值得 infra track 关注，因为实时语音模型会把 serving 要求从离线文本生成推向低延迟、多模态流式推理，涉及音频输入、增量解码、会话状态和端到端延迟预算。

INSIGHT这类模型发布对搜索/推荐的启发在交互形态：社区搜索可能从输入框逐渐扩展到语音、实时追问和多轮任务。基础设施上要提前考虑流式模型网关、会话态缓存、音频转写质量监控和安全审计，而不是只复用文本 LLM serving。短期可把它作为趋势信号，长期关注低延迟多模态模型是否能承担语音搜索、问答导购和内容理解入口。
