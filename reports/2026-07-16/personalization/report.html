SlimPer: Make Personalization Model Slim and Smart

SlimPer 将个性化排序改写为对紧凑用户—物品知识库的逐层迭代精炼，每层按需查询多模态用户 token，并以固定中间表示实现 O(N) 复杂度。模型把深度与历史长度解耦，已部署于 Instagram Reels 和 Feed，可建模超过 1 万条细粒度历史事件；论文未公开具体线上提升值。

SlimPer 深度解读

1. 问题与动机

工业推荐系统正大量采用 Transformer/HSTU 一类长序列架构，但 SlimPer 指出，这些模型继承了语言模型并不适用于排序任务的计算前提。自回归语言模型需要在每个 token 位置输出预测，因此保留随序列长度增长的中间表示是合理的；精排模型最终只为一个“用户—候选物品”对输出若干个点击、点赞、评论等标量，没有逐 token 监督。照搬 Transformer 后，系统只能在两种坏选择间权衡：逐层压缩 token 会丢失原始细粒度行为，完整保留则使计算和显存随历史长度快速增长。

论文以 Instagram Reels 和 Feed 的末级排序为真实场景。生产输入通常有 10³–10⁴ 个用户侧 token，一个训练请求约含 5 个候选，而推理请求可含约 10² 个候选；若每个候选重复用户侧计算，浪费会被进一步放大。作者的核心判断是：推荐真正需要的是持续提炼“该用户与该候选为什么相关”的紧凑状态，而不是让所有用户 token 彼此反复交互。SlimPer 因此把模型容量从用户侧 token-to-token 计算转向用户—物品匹配，并要求每一层仍能直接读取完整原始证据，避免一次压缩后的不可逆信息损失。

2. 方法详解

输入由三类特征构成：高基数 ID 等稀疏特征、包含内容/行为类型/时间/上下文的用户事件序列，以及 CTR、物品质量、设备等稠密特征。各模态先被 token 化：稀疏特征用 embedding pooling；每条事件把内容 embedding、显式或隐式行为类型、位置与时间差编码、局部上下文编码相加；稠密特征归一化后经 MLP 投影。知识库由非用户侧（主要是候选物品及交叉侧）token 初始化，形状固定为 K×d。

每个 SlimPer 层执行 Select–Match–Refine 三步。第一步 Select：由当前知识库线性投影出 q 个 query。固定长度稀疏 token 使用 MLP 参数化注意力，变长事件序列使用缩放点积注意力，分别取回 q×d 的证据；稠密特征因规模较小，直接传到每层。query 来自融合后的知识库，因此一次序列检索已同时受候选物品、稀疏兴趣和其他模态影响。作者测试过额外的 key/value 投影，但没有收益，生产实现将其去掉。

第二步 Match：知识库再投影出 t 个“多面模板”，与两路取回证据做显式点积，形成 q×t 的相关性矩阵。第三步 Refine：对两路匹配矩阵做 RMSNorm，再与当前知识库投影和稠密特征拼接，经 MLP 产生残差更新。多任务场景可在每层输出任务 embedding，跨层求和后投影成各任务 logit。生产模型通常堆叠 5–10 层：低层广泛浏览历史，中层聚焦较近行为，高层把注意力收缩到最相关的约 400 条事件。

Request-Only Optimization（ROO）是工程关键。所有用户侧 token 每个请求只计算并保存一份，在同请求的全部候选间共享；候选相关状态只保留固定 K 个槽。每层计算为 O(Nq)，中间显存为 O(LK)，而完整自注意力基线为 O(LN²) 计算和 O(LN) 中间显存。典型设置 K=64、q=16、t=32、d=256；Feed 使用 5 层，Reels 使用 7 层。所有模型训练一个 epoch，采用 Shampoo 优化器、学习率 0.05。论文没有公开 batch size、GPU 型号、数据条数或训练步数，这是复现时必须自行补齐的部分。

3. 核心技术贡献

第一，论文提出推荐专用的固定槽迭代精炼范式。固定瓶颈没有切断原始输入，因为每一层都重新跨注意力访问全量 token；它限制的是中间显存，而非后续层可获得的证据。作者从信息容量角度说明，排序只需输出 τ 个标量，64×256 的知识库远高于目标熵需求。

第二，SlimPer 将计算明确分配给用户—物品交互。其每层交互容量为 O(NK)，比只让候选通过单一状态读取序列的 Transformer 式结构高 K 倍；即使把自注意力改成线性或滑窗注意力，后者仍传播 N 个中间 token，且大部分容量用于用户 token 互相混合，因此并不能获得相同的质量—显存优势。

第三，模型在统一骨干中兼容稀疏、稠密和行为序列，并把 ROO 从历史序列扩展到全部用户侧模态。这既替代原先 HSTU（序列）+ Wukong（固定特征）的后融合链路，也让大候选请求的用户计算可摊销。注意力天然连接候选与具体历史事件，还提供了可检查的预测归因路径。

4. 实验结果分析

论文在 Instagram Reels 与 Feed 末级排序的真实训练、评估数据上，以线上成熟的 HSTU+Wukong 后融合模型为基线。离线主指标是 Normalized Entropy（NE，越低越好），经验上约 0.03% 的变化已具有实际意义。

同为 2k 历史时，SlimPer 不仅质量更好，还把 QPS 提高 11%、显存降低 9.32%。扩到 6k 后，SlimPer 的 reshare NE 改善达 -0.86%，QPS 回退仍小于 20%；基线在相同扩展趋势中只改善 -0.13%，QPS 却下降 48%。FLOPs 也吻合结构分析：2k 时基线约 24 GFLOPs、SlimPer 约 3 GFLOPs，相差约 8 倍；4k 时约 74 对 5，相差约 16 倍；6k SlimPer 约 6 GFLOPs，仍只有基线 2k 成本的四分之一。

消融显示瓶颈容量和迭代深度都有效。K 从 64 降至 4 虽使 QPS 提高 23.2%、显存减少 9.53%，但 NE 恶化 1.2%；K=32 时只换来 4.25% QPS，NE 仍恶化 0.18%，说明 64 个槽是更稳妥的生产平衡。层数从 7 降至 3，QPS 提高 21% 但 NE 恶化 0.32%；增至 9 层又改善 0.12% NE，代价为 QPS -7.16%、显存 +4.92%。事件上下文带来约 -0.15% NE，其中行为类型贡献几乎全部收益，加入事件内容只再改善不足 0.02%，说明“用户做了什么动作”比局部内容共现更关键。

线上方面，Reels 5k 和 Feed 4k 模型已全流量发布，多项核心互动指标显著提升，综合 topline 影响约为典型显著发布的 10 倍；完整性、多样性、时效性等护栏无回退，训练与推理 GPU 容量大致中性。作者未披露逐项线上百分比，这限制了外部对业务收益的精确比较。

5. 局限与未来方向

作者明确列出两项局限。其一，实验只和内部最强的 HSTU+Wukong 混合基线直接比较，没有在同一条件下对比 OneTrans、HHFT、RankMixer 等近期统一架构；虽然作者称单独 HSTU 更弱，但外部仍无法验证 SlimPer 相对这些系统的优势。其二，全部数据来自 Instagram 内部，训练数据量、batch、硬件和任务标签分布未公开，精确复现不可能。

此外，论文的注意力归因说明“模型关注了什么”，并不等于因果解释；固定 K=64 是否适用于低流量、小特征或跨域场景也未验证。未来方向包括把无序的跨场景行为和上游候选证据接入知识库，将 ROO 扩展到粗排的大候选集，以及在保持 O(N) 与固定显存的前提下尝试比点积和轻量 MLP 更强的匹配、更新算子。

6. 工业实践意义

对搜推团队最直接的启示是：先检查模型的计算是否服务于最终判别目标。若线上只需少量任务分数，却在每层维护几千个用户 token 的完整状态，应优先验证“固定候选相关状态 + 每层回读原始证据”，而不是继续堆叠高效注意力变体。一个低风险试点可保留现有特征与损失，仅替换交互骨干，以 K=64、q=16、t=32 和 5–7 层为起点，并同时观察 NE/AUC、QPS、峰值显存与请求候选数。

工程部署需要把用户侧 token 化放到 request scope，确保同一请求的候选共享一份缓存；否则 SlimPer 的主要收益会被错误实现抵消。长历史应按 1k、2k、4k、6k 分档测质量—成本曲线，因为论文显示收益随长度持续扩大，但显存和 QPS拐点因场景不同。层数与 K 可作为两类预算旋钮：缩 K 更省吞吐但质量损失大，减层更适合延迟敏感流量；也可以按用户历史长度或请求价值路由不同深度。

在社区搜索/推荐中，事件 token 应显式编码点击、长停留、点赞、跳过、负反馈和时间差，而不是只编码内容 ID。论文的消融说明行为类型上下文比局部内容更有价值。上线前应保留完整性、多样性、时效性护栏，并用注意力热图检查模型是否从广泛长期兴趣逐层收敛到近期意图；若高层长期只盯最近事件，可能需要为长期兴趣设置独立槽或正则。最值得避免的是在没有 request-level 共享、没有与强生产基线同特征对比时，仅凭 O(N) 复杂度宣称成功。

Learning to Forget: Satiation-Aware Long-Sequence Transducers for Mitigating Post-Purchase Redundancy

Alibaba📖 有深读 · 9 分钟

SAM 针对购买后仍反复推荐同类商品的“兴趣退出”问题，用双路交叉注意力压制已满足意图、用时间敏感门控逐步唤醒补购需求，并通过下一次购买时间自监督任务学习商品生命周期。工业离线实验和线上 A/B 测试显示，购买后重复推荐率降低超过 60%。

INSIGHT购买并不总是更强的正反馈，它常常意味着当前需求已经终止。推荐系统应把行为类型与兴趣生命周期联合建模：短期抑制已完成意图，长期依据个体补购周期恢复权重；这一机制也可迁移到社区内容中的“看完即满足”主题，减少重复曝光。

SAM 深度解读

1. 问题与动机

主流序列推荐把点击、加购、购买等交互统一当作兴趣增强信号，但在电商里购买常意味着某个意图已经完成。用户刚买冰箱后继续看到冰箱，或刚补货纸巾后仍被同类商品轰炸，就是论文所称的 Action–Intent Asymmetry：模型看到的是强正反馈，用户状态却已经从“需要”切换为“满足”。DIN、HSTU、OneTrans 等模型越擅长捕捉长历史，越可能把购买事件反复放大，造成购买后重复推荐。

简单固定窗口过滤并不能解决问题，因为商品生命周期和个体节奏差异很大。冰箱的合理复购间隔可能超过 300 天，纸巾约 15–30 天；同一用户还会在预计补购前提前浏览。统一屏蔽窗口会误杀补购前的“lead-in”行为。论文在天猫日志上进一步展示，DIN+固定窗口虽把 PPRR 从 15.5% 降到 7.7%，但 GAUC 从 0.674 降到 0.670，线上 CTR -0.2%、GMV -0.3%。因此，系统不仅要知道“忘掉什么”，还要为每个用户—品类估计“忘多久、何时重新唤醒”。

2. 方法详解

SAM 是接在工业精排模型上的兴趣饱和模块。输入包括用户静态画像、最长 500 的点击/购买混合序列、只保留购买事件的长期序列，以及当前候选商品。它用双路交叉注意力分别解决意图定位和补购节奏估计，两路共享 query/key 投影，使“哪些历史点击属于本次购买意图”和“该品类多久会再买”处在同一语义空间。

意图定位路径把最近购买品类 embedding 作为 query，与历史每个节点的品类 embedding 做缩放点积，再过 Sigmoid 得到归因权重 a_j。这里刻意不用 Softmax：在长度 500 的序列中，一个购买可能同时结束多条同类探索行为，Softmax 会让它们竞争总概率而稀释抑制强度；逐点 Sigmoid 允许多个相关节点都接近 1。

节奏检索路径在长期购买序列上做 target-aware Softmax 注意力，value 是历史购买间隔的 embedding。加权结果经 MLP 和 Softplus 解码成正数周期 c（天）。随后 ASGU 生成软门控：m_ij = 1 - a_j·sigmoid(k·(α-Δt_ij/c))。购买刚发生时 Δt≈0，同意图节点 m 接近 0；随着时间逼近 αc，屏蔽逐渐解除；超过阈值后 m 接近 1。α 是提前量（示例 0.8），用于在真正复购周期前恢复浏览兴趣，k 控制曲线陡峭程度。

门控不是直接乘 embedding，而是以 log(clip(m, ε, 1)) 加到注意力 logit。这样 m→0 时对应注意力权重稳定趋近 0，同时避免直接相乘造成尺度漂移。周期 c 由 Time-to-Next-Purchase（TTNP）辅助任务监督：对同品类相邻购买间隔 Δt，最小化 log(c+1) 与 log(Δt+1) 的平方误差。只有一次购买的右删失样本，用 max(观测窗剩余时间, 该品类平台平均周期) 作为下界式插补。总损失为 CTR 损失加 λ 倍 TTNP 损失。

实验数据来自天猫 2025-06-07 至 2025-11-07 的线上日志，前五个月训练、最后一个月测试；只保留至少 20 次交互的活跃用户，序列截断为 500。训练集含 1152 万用户、782 万商品、1.9033 亿行为和 906 万购买；测试集含 613 万用户、465 万商品、5274 万行为和 322 万购买。论文未公开优化器、学习率、batch size、训练硬件或训练步数，这些是实现复现的主要缺口。

3. 核心技术贡献

第一，SAM 把购买从普通正反馈改写为兴趣生命周期的状态转换，并通过双路结构同时建模“意图簇”与“补购节奏”。这比在重排末端套固定过滤规则更强，因为抑制对象和持续时间都由行为数据学习，并能随用户与品类变化。

第二，逐点 Sigmoid 意图归因适配“一次购买结束多条探索行为”的多对一结构，解决长序列 Softmax 权重稀释；共享投影又保证意图定位与节奏检索对品类相似性的理解一致。消融中移除双路节奏检索后，GAUC 从 0.691 降到 0.682，PPRR 从 4.1% 激增到 12.9%，是影响最大的组件。

第三，ASGU 用连续可学习的饱和曲线取代硬屏蔽，并用 TTNP 让时间尺度具有物理意义。移除 TTNP 后 GAUC 变为 0.688、PPRR 8.4%；改用硬 mask 虽保持 4.0% PPRR，却把 GAUC 降到 0.685，证明提前恢复的 lead-in 阶段对捕捉补购前浏览至关重要。

结果揭示一个重要反常现象：更强的长序列模型提升 GAUC，却没有降低冗余。OneTrans 的 GAUC 达 0.689，但 PPRR 15.8%，甚至略高于 DIN；其“已购买”负反馈还增加 10.2%。SAM 的 GAUC 进一步升至 0.691，同时将 PPRR 降到 4.1%，相对 OneTrans 减少约 74%，并让 Bad-Case 下降 74.5%。CTR 与 OneTrans 同为 +1.1%，GMV 则从 +0.6% 提升到 +0.9%，说明释放重复曝光后，跨品类探索带来了额外交易价值。

消融排序为双路节奏检索 > TTNP > 自适应门控。无双路检索时 PPRR 回到 12.9%，说明历史购买间隔是决定停止时长的主信号；无 TTNP 时模型无法区分耐用品和高频消耗品；硬 mask 的 PPRR 甚至略低于完整 SAM，但 GAUC 明显变差，印证“冗余最低”并非最终目标，必须同时保护真实补购意图。论文还报告模型学到冰箱平均超过 300 天、纸巾约 15–30 天的周期，表明时间预测具有业务可解释性。

5. 局限与未来方向

论文没有独立的 Limitations 章节，结论主要强调工业有效性。正文可确认的限制包括：只在天猫单一平台、活跃用户（至少 20 次行为）和叶子品类层面评估，因此新用户、跨平台迁移以及同品类内替代/互补关系尚未验证；PPRR 的统计窗口依赖平台已有的品类复购周期表，评估本身并非完全无先验；右删失样本用全局品类均值插补，可能低估小众用户的超长周期。

作者在消融中间接指出，TTNP 和历史节奏检索对稀疏品类仍敏感。未来可采用生存分析或删失似然替代均值插补，引入价格、库存、季节、家庭共享购买等外生变量，并把“兴趣退出”扩展到服务完成、内容看完、事件结束等非购买动作。还应分别报告新用户、低频品类和不同价格带的公平性，避免模型只对高活跃主流用户学得准确周期。

6. 工业实践意义

SAM 最适合作为现有 DIN/HSTU/Transformer 精排的可插拔分支，而非重建整套推荐链路。团队可先构建三个输入：混合行为长序列、购买专用长序列、候选品类；再离线增加 PPRR 与“已经买过”负反馈率，避免只看 AUC/GAUC。首版可以用平台品类平均周期初始化 c，再逐步启用个体节奏检索和 TTNP。门控应注入 attention logit，并保留 clip ε，防止数值不稳定。

线上实验必须同时观察 CTR、GMV、跨品类覆盖、负反馈和复购召回。固定窗口过滤可作为对照，但不宜直接上线全量：论文已经显示它虽然减少冗余，却伤害 GAUC 和 GMV。更安全的发布顺序是先在耐用品、已知周期稳定的品类上使用软门控，以 1% 流量验证；再扩大到高频消耗品，并针对预计周期前的 lead-in 流量检查是否错误抑制。

对社区搜索/推荐，购买可映射为“意图完成”事件，例如用户完整看完教程、报名活动、解决问答或明确点选“不再推荐”。双路思想仍成立：一路找出属于同一已满足主题的历史点击，另一路估计该主题再次需要的时间。应避免把所有强互动都永久累加为兴趣，也不要把一次完成动作变成永久黑名单。真正可借鉴的是把兴趣表示从静态强度升级为带进入、满足、休眠、恢复阶段的状态机，并用可学习软门控在相关性与新颖性之间做连续权衡。
