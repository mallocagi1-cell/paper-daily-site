1. Token Reduction Is Not Cost Reduction
4.75
Relevance 5 | Novelty 4 | Practical 5 | Evidence 5 | Timely 5

Summary: 论文用 2,848 次可计费 Claude Code 配对运行检验上下文压缩的真实经济性，覆盖 103 个任务、7 个代码库和 3 个模型。删除 38% 工具输出 token 的方案反而使配对成本上升 6.8%；缓存流量占重建成本约 87%，说明 token 数并非账单成本的可靠代理。

Key insight: 推理基础设施应以“任务成功率校正后的实际账单成本”评估压缩、检索排序和代理层，而不能只看输入缩短比例。社区搜索 Agent 若压掉可执行证据，可能延长轨迹甚至降低完成率；应分别监控缓存创建、缓存读取、输入与输出四类成本，并保留关键原文锚点。

2. Scaling LLM Inference Beyond Amdahl's Limits via Eliminating Non-Scalable Overheads
4.45
Relevance 5 | Novelty 5 | Practical 4 | Evidence 5 | Timely 2

Summary: Albireo 针对张量并行受调度、I/O 和采样串行开销限制的问题，通过计算重叠与序列并行采样提高最优并行度，无需修改模型架构。相较 vLLM，其吞吐最高提升 1.9 倍、延迟降低 48%、GPU 利用率提升 28%、能耗降低 54%，生产环境吞吐最高提升 2 倍。

Key insight: 扩卡不是线性提速，最优 TP 度取决于通信、KV cache 压力和运行时串行部分的平衡。对搜索生成服务，应先用剖析确定经验最优并行度，再把调度与 I/O 隐藏到计算后面；这一系统级改造比盲目增加 GPU 更可能同时改善吞吐、尾延迟和能耗。

3. ELDR: Expert-Locality-Aware Decode Routing for PD-Disaggregated MoE Serving
4.45
Relevance 5 | Novelty 4 | Practical 5 | Evidence 4 | Timely 3

Summary: ELDR 从 prefill 阶段的专家激活构造签名，以平衡 K-means 划分解码 worker，并在同等局部性候选中选择负载最低者；签名缓存与 KV block 共索引。其 vLLM 实现在最多 40 张 GPU、3 个 MoE 模型和 2 类负载上，将中位 TPOT 降低 5.9%–13.9%，且输出保持不变。

Key insight: MoE 的解码路由不能只按请求数均衡，还要让同批请求复用相近专家权重，从而缓解显存带宽与权重加载瓶颈。现有 prefill/decode 分离集群可把专家签名作为低成本路由特征，并与 prefix/KV cache 生命周期绑定，在不改模型结果的前提下降低逐 token 延迟。

4. Formal schedulability analysis for LLM inference: TTFT and TBT deadline guarantees via response-time theory
3.95
Relevance 5 | Novelty 4 | Practical 3 | Evidence 4 | Timely 3

Summary: Chronos 把 LLM 请求建模为带 TTFT 截止期的 prefill 作业和受 TBT 约束的 decode 任务，推导最坏响应时间、容量条件与准入控制。基于 Azure 一周 4,400 万请求轨迹抽样 5 万次回放；在 10 倍负载下维持零违约并接纳 53.9% 请求，而无准入调度的 TTFT 违约率达 99.4%。

Key insight: 高峰期追求全部接纳会让尾延迟失控，形式化准入比经验优先级更适合有硬 SLO 的生成式搜索。工程上可先为单 GPU 服务估计 prefill/decode 最坏执行时间，再把 TTFT 与 TBT 分开做容量预算；代价是主动拒绝或降级部分流量，以换取已接纳请求的可证明保障。
