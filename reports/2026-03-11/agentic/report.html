SynPlanResearch-R1: Encouraging Tool Exploration for Deep Research with Synthetic Plans

针对深度研究 Agent 在使用 RLVR（可验证奖励强化学习）训练时常出现的提前终止和工具使用偏差等探索行为不足问题，提出 SynPlanResearch-R1 框架。核心思路是通过合成包含丰富工具使用轨迹的计划（synthetic plans），引导 Agent 学习多样化的工具探索策略，并将这些轨迹用于初始化 RL 训练。实验表明，该方法显著提升了 Agent 的工具调用多样性和任务完成质量，在多个深度研究基准上相比纯 RLVR 基线取得了明显提升。

问题与动机

深度研究 Agent（Research Agent）需要通过动态交织内部推理与外部工具使用来回答用户查询。理论上，强化学习（RLVR，基于可验证奖励的 RL）可以训练这种能力，但实践中 Agent 常表现出严重的探索行为不足：提前终止（过早结束搜索）和工具使用偏差（偏好某些工具模式）。这导致 RLVR 单独训练时效果有限。如何让 Agent 在训练早期就学会多样化地使用工具，是当前 RL 训练搜索 Agent 的核心挑战。

方法概述

SynPlanResearch-R1 提出了一个两阶段训练框架：

  1. 计划引导的数据合成（Plan-guided Synthesis）：用于冷启动阶段的 SFT 数据生成

- 工具计划构造：生成随机化的工具动作序列（web_search, crawl_webpage），长度从 [3,8] 采样
- 线索注入思维（Cue-injected Thoughts）：在推理步骤中插入动作特定的提示，引导模型行为但不硬性约束
- 过滤：仅保留答案正确且格式有效的轨迹
- 思维重写：使用 Claude 将合成线索改写为自然语言

  1. 强化学习：使用 GRPO（Group Relative Policy Optimization）进行 80 步训练

核心技术贡献

  1. 揭示了 RLVR 的探索瓶颈：系统性地证明了纯 RL 训练在搜索 Agent 场景下的探索不足问题，包括提前终止和工具偏差两种失败模式
  2. 合成计划引导机制：通过构造多样化的工具使用轨迹，将探索策略显式编码到 SFT 阶段，有效引导后续 RL 训练
  3. 线索注入思维：创新性地在 ReAct 框架中插入动作特定线索，将计划遵循率从 28.32% 提升至 76.96%
  4. 冷启动策略：提供了从合成数据到 RL 训练的完整冷启动路径

实验结果分析

实验设置：7 个基准（HotpotQA, 2WikiMultihopQA, MuSiQue, Bamboogle, GPQA, WebWalkerQA, GAIA），基座模型 Qwen3-8B 和 Qwen3-4B，合成使用 Qwen3-32B。

主要结果（F1 指标）：

  • Qwen3-8B：平均 F1 = 0.580，优于 SimpleDeepSearcher (0.547, +6.0%)、Search-R1 (0.512, +13.3%)、Rejection Sampling (0.464, +25.0%)
  • Qwen3-4B：平均 F1 = 0.529，优于 SimpleDeepSearcher (0.500, +5.8%)、Search-R1 (0.462, +14.5%)

消融实验：

  • 去掉探索采样：性能下降 0.058（最关键组件）
  • 去掉线索注入：性能下降 0.041
  • 减少 max_turns (8→6)：性能下降 0.026

工具使用分析：合成计划使平均工具调用次数从 1.40（vanilla ReAct）提升到 4.36，且在 RL 训练全程保持更高的策略熵。

局限与未来方向

  • 当前仅验证了 Qwen3 系列模型，对其他 LLM 架构的泛化性有待验证
  • 合成计划的质量依赖于 Qwen3-32B 教师模型的能力
  • 计划长度的采样范围 [3,8] 是手动设定的，可能需要根据任务复杂度自适应调整
  • 尚未在更大规模模型（如 70B+）上验证效果

工业实践意义

  1. 搜索 Agent 训练范式：为 RL 训练搜索 Agent 提供了明确的冷启动策略——先用合成轨迹初始化，再用 RL 优化。这比直接从零开始 RL 训练高效得多
  2. 工具探索设计：揭示了工具调用数量与性能正相关的规律，提示在搜索 Agent 设计中应鼓励更多的探索行为，而非追求最少步骤完成任务
  3. 数据效率：仅需 8k 合成 SFT 样本 + 约 10k RL 样本即可显著提升性能，训练成本可控
  4. 框架通用性：该框架不限于搜索场景，可推广到任何需要多步工具使用的 Agent 训练

DualSpec: Accelerating Deep Research Agents via Dual-Process Action Speculation

Microsoft📖 有深读 · 4 分钟

针对 LLM 深度研究 Agent 在长链信息检索任务中端到端延迟过高的问题，提出双进程动作推测（DualSpec）框架。受人类认知双进程理论启发，设计快速（System 1）和慢速（System 2）两种推测策略：快速策略处理常规动作模式，慢速策略应对需要深度推理的复杂动作。通过自适应选择推测策略并放宽严格动作匹配约束，实现推理与工具执行的有效重叠，显著降低了深度研究 Agent 的端到端响应时间。

INSIGHT深度研究 Agent 的主要瓶颈不在于单步推理能力，而在于多步推理和频繁工具调用累积的延迟。DualSpec 借鉴认知双进程理论，将动作推测分为快慢两个通道，这种设计思路可直接应用于搜索 Agent 的推理加速——对常见查询模式用轻量推测跳过等待，对复杂查询保留完整推理。该方法来自微软研究院，具有较强的工程落地参考价值。

问题与动机

基于 LLM 的深度研究 Agent 在处理长链信息检索任务时，由于大量推理步骤和频繁工具调用，端到端延迟极高。现有的推测执行框架（Speculative Execution）试图通过重叠动作执行与推理来降低延迟，但采用统一的推测策略和严格的动作匹配，限制了加速效果和鲁棒性。核心问题是：不同类型的 Agent 动作（如搜索查询 vs URL 访问）具有本质不同的推理需求，一刀切的推测策略无法充分利用这种差异。

方法概述

DualSpec 受认知科学双进程理论启发，将 Agent 动作分为两类并采用不同的推测策略：

  1. Search 动作（System 2）：需要深思熟虑的推理，使用小模型 + 显式推理链来生成推测草稿
  2. Visit 动作（System 1）：依赖模型的参数化知识，直接使用大模型无推理链快速生成推测草稿

两种草稿并行生成，根据动作类型选择合适的草稿。验证环节使用语义置信度而非严格的文本匹配：

验证分数 = log(p_accept) - log(p_reject)

超过阈值 τ 的草稿被接受，否则回退到完整推理。

核心技术贡献

  1. 动作异质性发现：通过熵分析发现 Search 动作不确定性高（需要推理），Visit 动作不确定性低（依赖模型知识），为差异化推测提供理论基础
  2. 异质推测策略：首次将双进程理论应用于 Agent 推测执行，为不同动作类型定制推测方式
  3. 语义验证器：用基于置信度的语义验证替代严格文本匹配，提高了推测接受率而不牺牲准确性
  4. 进度感知验证：验证 prompt 评估 Agent 是否在「取得新进展」，而非简单比较动作文本

实验结果分析

实验设置：模型组合（MiroThinker-72B+8B, MiroThinker-72B+30B-A3B, Qwen3-32B+4B），数据集（GAIA-Text-103, XBench-DeepSearch, Seal-0），基线（DSP, SPAgent）。

主要结果：

  • 最高加速：3.28× 端到端延迟降低（MiroThinker-72B + 8B 组合）
  • 准确率保持：异质推测与原始模型准确率一致（63.1% vs 63.1% on GAIA）
  • 对比统一策略：纯无推理策略虽快但准确率下降 3.9%（63.1%→59.2%），纯推理策略准确率下降 6.8%（63.1%→56.3%）

消融分析：

  • 干预率在 20-30% 时达到最佳平衡——准确率接近基线，效率显著提升
  • 准确率随干预率增加先升后稳定，超过 30% 后收益递减

局限与未来方向

  • 当前仅在特定模型组合上验证，对更多 LLM 架构的适配性需进一步研究
  • 语义验证器的阈值 τ 需要针对不同任务调优
  • 异质策略的分类（Search vs Visit）较为粗粒度，更复杂的动作类型可能需要更精细的策略划分
  • 未探索在分布式部署场景下的加速效果

工业实践意义

  1. 搜索 Agent 延迟优化：3.28× 的加速对实时搜索系统意义重大。在社区搜索场景中，用户期望秒级响应，DualSpec 可将深度研究 Agent 的响应时间从分钟级降至可接受范围
  2. 成本效率：通过小模型承担部分推测工作，降低了大模型的调用频率和计算成本。在大规模部署中可显著降低 GPU 消耗
  3. 动作分类思路：将 Agent 动作按推理需求分类的思路可推广到各类搜索 Agent——例如将简单的关键词搜索和复杂的语义查询构造区分处理
  4. 来自微软研究院：Qi Chen 和 Chuanjie Liu 是微软在搜索和 AI 系统领域的资深研究员，方法的工程可行性较高

SPD-RAG: Sub-Agent Per Document Retrieval-Augmented Generation

针对复杂查询需要从大规模文档语料库中综合分散事实的问题，提出 SPD-RAG 层次化多 Agent 框架。核心创新是沿文档轴分解问题：每个文档由一个专用文档级 Agent 处理，负责深入阅读和事实提取，上层协调 Agent 负责跨文档信息综合与推理。相比标准 RAG 管道的证据覆盖不全和长上下文 LLM 的推理不可靠问题，SPD-RAG 通过分治策略实现了更全面的证据覆盖。

INSIGHTSPD-RAG 提出的「每文档一个子 Agent」思路为搜索系统中的多文档综合问答提供了新的架构范式。在社区搜索场景中，当用户查询需要综合多个帖子/回答的信息时，可以为每个相关文档分配独立的理解 Agent，避免长上下文窗口中的注意力稀释问题。这种分治式架构也天然支持并行处理，有利于降低延迟。

Mind2Web 2: Evaluating Agentic Search with Agent-as-a-Judge

针对 Deep Research 等 Agentic Search 系统缺乏有效评估基准的问题，提出 Mind2Web 2 基准和 Agent-as-a-Judge 评估方法。该基准包含 130 个真实、高质量、长链任务，需要实时网页浏览和大规模信息综合，构建耗费超 1000 小时人工标注。提出的 Agent-as-a-Judge 评估方法解决了传统评估框架无法处理时变答案和开放式输出的问题，为评估 agentic search 系统提供了更真实的衡量标准。

INSIGHTMind2Web 2 填补了 agentic search 系统评估领域的重要空白。当前 Deep Research 类产品（如 OpenAI Deep Research、Gemini Deep Research）缺乏统一评估标准，该基准的 130 个长链任务设计和 Agent-as-a-Judge 方法为搜索 Agent 的质量评估提供了可操作的框架。对搜索系统开发者而言，可参考其任务设计思路构建内部评测集，尤其是其强调的真实性和时变性评估维度。

ARLArena: A Unified Framework for Stable Agentic Reinforcement Learning

UCLA

针对 Agentic Reinforcement Learning (ARL) 训练高度不稳定、频繁崩溃的问题，提出 ARLArena 统一框架。首先系统性定义了 ARL 的训练稳定性，然后提供一套稳定训练方案（stable training recipe），涵盖梯度裁剪、学习率调度、经验回放缓冲等关键设计选择。框架支持在多种环境和交互时长下系统性分析算法设计决策对训练稳定性的影响，为 ARL 研究提供了标准化的实验平台。

INSIGHTARL 训练不稳定是阻碍搜索 Agent 规模化部署的关键障碍。ARLArena 提供的稳定训练方案（包括具体的超参数配置和训练策略）对于想要用 RL 训练搜索/检索 Agent 的团队极具参考价值。特别是其关于训练崩溃诊断和预防的系统性分析，可以帮助团队在早期发现并避免常见的训练失败模式，降低 RL 训练搜索 Agent 的试错成本。

Scaling Agentic Capabilities, Not Context: Efficient Reinforcement Finetuning for Large Toolspaces

Microsoft

针对小型语言模型（SLM）在大规模工具生态中因上下文饱和和稀疏奖励导致的脆弱性问题，提出 ATLAS 强化微调框架。两大核心贡献：一是将上下文控制和执行结构作为可学习决策，结合迭代工具加载与程序化执行结构；二是通过高效的 RL 训练使 SLM 学会在庞大工具空间中按需获取上下文和执行动作，而非一次性加载所有工具描述。使 SLM 在大工具空间中接近前沿大模型的性能。

INSIGHT该工作来自微软研究院，核心洞察是「扩展 Agent 能力而非上下文」——在工具数量庞大时，SLM 不应贪婪加载所有工具描述，而应学会按需检索和使用工具。这对搜索系统有直接启示：当搜索 Agent 需要对接多种检索、排序、过滤工具时，可通过 RL 训练模型学会动态选择工具组合，而非在 prompt 中罗列所有可用工具。该方法显著降低了部署成本，使 SLM 也能胜任复杂 Agent 任务。

In-Context Reinforcement Learning for Tool Use in Large Language Models

针对 LLM 工具使用能力训练的冷启动问题，提出 In-Context RL 方法。不同于传统的先 SFT 再 RL 的两阶段训练范式，该方法通过在上下文中直接进行强化学习，让 LLM 从交互反馈中学习如何使用外部工具（如 Python 解释器、搜索引擎）。核心思路是利用上下文学习能力将工具使用经验编码为隐式策略，避免了构造高质量 SFT 数据的需求。

RAVine: Reality-Aligned Evaluation for Agentic Search

针对现有 agentic search 评估框架与真实用户场景脱节的三大问题（查询不真实、标注噪声大、仅评估最终答案），提出 RAVine 评估框架。核心创新在于三个对齐：一是查询与真实用户搜索场景对齐，二是端到端评估中降低标签噪声的精细化标注方案，三是不仅评估最终答案质量，还评估 Agent 的迭代搜索过程。为 agentic search 系统提供了更贴近现实的评测标准。

INSIGHTRAVine 强调的「过程评估」维度对搜索 Agent 开发至关重要。当前大多数评估仅关注最终答案是否正确，忽略了 Agent 的检索路径是否高效、是否存在冗余搜索。在实际搜索系统中，Agent 的搜索效率直接影响响应延迟和计算成本。该框架可作为搜索 Agent 质量监控的参考，帮助团队同时优化结果质量和搜索效率。
