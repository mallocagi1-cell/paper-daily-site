Scalable Training of Mixture-of-Experts Models with Megatron Core

本文针对 Mixture-of-Experts (MoE) 模型训练中的系统挑战，提出了跨内存、通信和计算的集成优化方案。由于 MoE 模型的稀疏性使参数量远超每 token 计算量，优化任一维度会将压力转移到其他维度，因此需要全栈协同设计。框架支持 Parallel Folding 灵活多维并行、FP8/NVFP4 低精度训练和高效长上下文训练。在 NVIDIA GB300 和 GB200 上，DeepSeek-V3-685B 模型达到 1,233/1,048 TFLOPS/GPU。

Megatron Core MoE 深度解读：万亿参数混合专家模型的可扩展训练系统

问题与动机

MoE 架构通过稀疏激活实现了参数量与计算量的解耦——以 DeepSeek-V3 为例，模型总参数量达 685B，但每个 token 仅激活 37B 参数，参数-计算比高达 18:1。这种稀疏性带来了三个紧密耦合的系统级挑战：

内存墙：所有专家的参数、梯度和优化器状态都必须驻留在内存中，即使每个 token 只激活少数专家。以 Llama-405B（BF16 + Adam）为参考，总内存需求约 12,865GB。

通信墙：专家并行（EP）依赖 all-to-all 集合通信分发和收集 token。未优化的 all-to-all 可占总训练时间的 60%。

计算效率墙：MoE 的稀疏激活产生大量小型矩阵乘法。在稠密模型中 GEMM 约占执行时间的 70%，而在细粒度 MoE 中不到 50%，路由和排列开销约占 MoE 层执行时间的 9%。

关键洞察：这三面墙不是独立的——优化一个维度往往将压力转移到另一个维度，因此需要跨整个系统栈的协同设计。

方法概述

围绕 MoE 的四阶段前向传播流程展开优化：Route（路由）→ Dispatch（分发）→ Compute（计算）→ Combine（聚合）。系统优化分层组织：并行策略（Parallel Folding）、通信优化（Flex Dispatcher + DeepEP/HybridEP）、内存优化（FSDP+EP、激活卸载）、计算优化（Grouped GEMM、CUDA Graphs）、精度优化（FP8/FP4）。

核心技术贡献

1. 并行折叠（Parallel Folding）

传统框架要求 EP 是 DP 的子集，导致 Attention 和 MoE 层被迫使用相同的 TP/CP 配置。并行折叠将两者的并行配置完全解耦：Attention 层可用 TP=4, CP=8 优化长序列大矩阵，MoE 层用 ETP=1, EP=16 优化稀疏专家分布。梯度同步也相应解耦，通过 ChainedOptimizer 防止不同副本数下的错误梯度平均。

2. 多后端 Token Dispatcher 与通信-计算重叠

提供三种通信抽象：AllGather Dispatcher（小规模）、All-to-All Dispatcher（NCCL 标准）和 Flex Dispatcher（统一抽象，支持 DeepEP 和 HybridEP 后端）。关键策略包括 EP 通信与专家计算并发执行，以及共享专家与路由专家的流水线并行。

3. 全栈低精度训练（FP8/FP4）

低精度是唯一能同时缓解三面墙的优化手段。支持 Per-Tensor FP8、Blockwise FP8（Hopper）、MXFP8（Blackwell）和 NVFP4（Blackwell）四种精度 recipe。针对 MoE 特有的动态形状对齐、分组量化和 FP8/FP4 主权重等挑战提出了专门的解决方案。

4. CUDA Graphs 与 Dropless MoE 兼容

通过 Sync-free kernels（无同步内核）、ECHO（弹性克隆热点专家）和 Paged stashing（分页暂存）三项技术实现全 CUDA Graphs 覆盖，结合 Grouped GEMM 将多个专家计算批处理为单次内核调用。

实验结果分析

在 NVIDIA GB300 上，DeepSeek-V3-685B 模型达到 1,233 TFLOPS/GPU，GB200 上达到 1,048 TFLOPS/GPU。Qwen3-235B 在 GB300/GB200 上分别达到 974/919 TFLOPS/GPU。

优化栈贡献拆解：无 Grouped GEMM 约 35% 效率损失；无通信-计算重叠约 20% 效率损失；无低精度训练约 15% 效率损失。框架已在实际生产中训练了从数十亿到万亿参数的 MoE 模型，集群规模扩展到数千个 GPU。

局限与未来方向

  1. CUDA Graphs 与动态路由的张力：dropless MoE 的完全覆盖仍需特殊处理
  2. 负载均衡的根本困境：辅助损失可能强制不自然的路由决策
  3. 跨平台可移植性有限：大量优化深度绑定 NVIDIA 硬件特性
  4. 未提供与其他 MoE 训练框架（DeepSpeed-MoE、Tutel）的直接对比
  5. 未来方向包括 MoE + RL 后训练、自适应专家分布策略、端到端编译优化

工业实践意义

  1. MoE 训练的核心矛盾不是模型太大，而是参数多但激活少带来的内存-通信-计算三维失衡。通信优化的 ROI 在 MoE 中高于计算优化
  2. 并行折叠应成为 MoE 训练框架的标准能力，解决 Attention 和 MoE 层最优并行配置不同的问题
  3. 低精度训练是 MoE 的万能钥匙：FP8/FP4 同时缓解三个瓶颈，多种精度 recipe 提供渐进式迁移路径
  4. 推荐系统天然适合 MoE 架构——不同用户群体/场景可以由不同专家处理。论文中的负载均衡、共享专家设计和 Grouped GEMM 优化可直接迁移
  5. 分布式检查点的并行无关重分片对于搜索/推荐训练场景的跨集群迁移极为实用

LycheeCluster: Efficient Long-Context Inference with Structure-Aware Chunking and Hierarchical KV Indexing

HIT📖 有深读 · 4 分钟

针对 LLM 长上下文推理中注意力机制的二次复杂度和 KV 缓存内存瓶颈，提出 LycheeCluster 方法。该方法通过边界感知分块（boundary-aware chunking）保持局部语义完整性，并构建基于三角不等式的递归层次索引，将缓存检索从线性扫描降低到对数时间复杂度。lazy update 策略支持高效流式生成。实验表明，LycheeCluster 实现最高 3.6 倍端到端推理加速，且模型性能几乎无损。

INSIGHT与传统固定大小分块的 KV 缓存管理不同，LycheeCluster 的结构感知分块保留了语义边界，层次化索引实现了对数级别的缓存检索。这种设计对搜索场景中的长文档理解和 RAG 任务尤为重要——3.6 倍的加速意味着可以在相同延迟预算下处理更长的上下文，直接提升搜索相关性判断的准确度。lazy update 策略还适合流式搜索结果生成。

问题与动机

长上下文 LLM 推理面临严峻的延迟和内存瓶颈。随着上下文窗口从 4K 扩展到 2M+ tokens，自回归解码阶段的注意力机制需要对每个生成 token 扫描完整的 Key-Value (KV) 缓存历史。KV 张量的加载消耗大量内存带宽，导致解码速度随序列增长严重退化。

现有方法存在根本性缺陷：基于页的方法（如 Quest）使用固定大小的页划分，会粗暴切断语义边界，破坏局部上下文的完整性；token 级聚类方法（如 ClusterKV）将局部连贯的 token 打散到不相交的聚类中。论文通过先导实验（StrucText-Eval）揭示了一个关键洞察：长上下文检索的瓶颈往往不是未能识别重要区域，而是这些区域的碎片化。仅将 Quest 的固定页替换为结构感知的变长分块，平均准确率就提升了 10.6%，JSON 提取任务提升 15.0%。

方法概述

LycheeCluster 采用预填充-解码两阶段架构：(1) 预填充阶段将输入上下文通过结构感知分块切分为变长语义块，然后对块表示进行球面 k-means 聚类，构建三层层次索引（粗粒度单元 → 细粒度聚类 → 语义块）；(2) 解码阶段对每个生成 token 的查询向量，利用三角不等式推导的注意力上界，自顶向下逐层剪枝，实现对数时间复杂度的缓存检索，同时采用惰性增量更新策略将新生成的 token 缓冲后分配到已有聚类中。

核心技术贡献

1. 结构感知变长分块

与固定大小分页不同，采用贪心策略累积 token，设定最小/最大长度阈值（默认 8-16 tokens），在达到最小长度后前探搜索自然分隔符。分隔符按优先级分为四级：段落分隔 > 句子终止符 > 短语标点 > 空白回退。消融实验表明固定大小分块准确率下降 3.03%。

2. 基于三角不等式的层次索引与剪枝

核心数学基础是注意力上界推导：对于查询 q_t 和聚类中的任意向量 v，有 q_t^T v ≤ q_t^T μ_u + ||q_t||_2 · r_u。基于此上界执行三层剪枝，将检索复杂度从线性 O(N) 降至亚线性 O(√N)。

3. 惰性增量更新机制

解码阶段新生成的 token 被缓冲（buffer size 128），当缓冲区满时打包为新块并分配到最近的已有聚类。质心通过移动平均更新，避免每步重建索引的开销（惰性更新成本 < 解码时间的 1%）。

实验结果分析

在 Llama-3.1-8B-Instruct 上，token 预算 1024 的条件下，LycheeCluster 总体准确率达到 30.8%，超过完整注意力的 30.02%。对比基线：RazorAttention 27.44%、ClusterKV 26.64%、Quest 仅 20.68%。在 MATH500 推理任务上仅损失 1.4% 准确率。端到端解码加速：32K 上下文 2.6x，64K 上下文 3.6x。索引额外内存开销仅 ~1%。

局限与未来方向

  1. 仅优化解码阶段，预填充的索引构建是额外开销
  2. 与 vLLM、SGLang 等主流推理框架的集成需要工程工作
  3. 分块阈值为固定超参数，未自适应调整
  4. 上下文窗口继续扩展至千万级别时可能需要自适应层级深度

工业实践意义

  1. 搜索场景长文档理解：结构感知分块天然适配有段落和标题结构的文档，3.6x 加速直接降低在线推理延迟
  2. RAG 系统 KV 缓存优化：层次索引可与检索阶段的文档分块对齐
  3. 对话式推荐长会话建模：惰性增量更新特别适合流式输入场景
  4. 成本优化：3.6x 加速意味着同等 QPS 下 GPU 需求降至约 1/3，内存开销仅增加 ~1%
  5. 四级分隔符优先级设计可直接复用于任何需要语义分块的场景

Deterministic Differentiable Structured Pruning for Large Language Models

AAnt GroupTsinghua

提出 Deterministic Differentiable Pruning (DDP) 方法，解决 LLM 结构化剪枝中随机松弛带来的训练-测试不匹配问题。与基于 hard-concrete 的随机方法不同，DDP 直接优化离散 L0 目标的确定性软替代函数，提供更强的表达能力、更小的训练-测试差异和更快的收敛速度。在 Qwen3-32B 和 Qwen3-30B-A3B 等 Dense 和 MoE 模型上验证有效性。

INSIGHT该方法的核心创新在于用确定性代理函数替代了传统的随机 hard-concrete 松弛，消除了剪枝mask离散化时的训练-测试不一致。对搜索推荐系统而言，结构化剪枝是降低在线推理成本的关键技术路径。DDP 在 Qwen3 系列模型上的验证表明，该方法已可直接应用于当前主流开源模型，为搜索排序模型的轻量化部署提供了新的工程选择。

FreeKV: Boosting KV Cache Retrieval for Efficient LLM Inference

SJTU

vLLM Hook v0: A Plug-in for Programming Model Internals on vLLM

IIBM Research

vLLM 是当前最主流的 LLM 推理引擎之一，但其实现限制了对模型内部状态的可编程性。本文提出 vLLM Hook，一个开源插件，通过配置文件指定需要捕获的内部状态，支持两种核心功能：被动编程（读取注意力模式、激活值等）和主动编程（基于激活值引导模型响应）。该工具使得在 vLLM 上实现对抗提示检测和 activation steering 等 test-time 对齐方法成为可能。

INSIGHTvLLM Hook 填补了生产级推理框架中模型内部可观测性的空白。对搜索系统而言，这意味着可以在不修改 vLLM 源码的情况下实现：(1) 基于注意力模式的查询意图检测；(2) 通过 activation steering 引导模型生成更符合搜索相关性的响应；(3) 运行时的对抗输入检测。作为即插即用的插件架构，实践落地成本极低。

DOPD: A Dynamic PD-Disaggregation Architecture for Maximizing Goodput in LLM Inference Serving

UU. of MacauUU. of Melbourne

针对 LLM 推理服务中 Prefill-Decoding (PD) 分离架构的负载不均衡问题，提出 DOPD 动态系统。DOPD 基于实时负载监控动态调整 Prefill/Decoding 实例的分配比例，结合请求调度策略有效解决两阶段实例间的不平衡，缓解高并发下混合长度请求导致的资源错配。实验表明，相比 vLLM（聚合架构）和 DistServe（静态分离），DOPD 显著提升了吞吐量和 SLO 达标率。

Scaling Embeddings Outperforms Scaling Experts in Language Models

研究表明在 MoE 语言模型中，扩展 Embedding 维度比增加专家数量能获得更好的性能。这一反直觉的发现挑战了当前通过不断增加专家数量来扩展 MoE 模型的主流趋势，为模型架构设计提供了新的 scaling 维度。

INSIGHT该发现对搜索推荐系统中大模型的架构选型有重要指导意义。当前业界倾向于通过增加 MoE 专家数来扩展模型容量，但如果扩展 Embedding 维度更高效，那么搜索 Embedding 模型和排序模型的架构设计可能需要重新权衡参数分配策略。这也暗示了 Embedding 的表征能力在 scaling 中被低估。

Advancing Model Refinement: Muon-Optimized Distillation and Quantization for LLM Deployment

提出集成 GPTQ 量化、LoRA 低秩适配和专用数据蒸馏的统一框架，用于 LLM 的高效部署。该流水线可实现 2 倍内存压缩（例如将 6GB 模型压缩至 3GB），同时保持或增强任务特定性能，面向专用任务的高效推理场景。

MoE Lens -- An Expert Is All You Need

通过领域特定路由模式和 early decoding 两个视角分析 MoE 模型的专家特化机制。对 DeepSeekMoE 的分析发现：尽管有 64 个路由专家（每层激活 6 个），系统实际主要依赖少数专家。最高权重专家的输出与完整集成的预测高度一致（余弦相似度达 0.95），单专家推理仅增加 5% 困惑度。这表明 MoE 存在显著的专家集中现象，为推理优化提供了剪枝空间。

INSIGHT该研究揭示了 MoE 模型中「专家冗余」的量化证据——少数专家承担了超过 50% 的路由决策。这为搜索推荐系统部署 MoE 模型提供了重要的优化方向：通过识别并保留关键专家，可以大幅降低推理时的内存和计算开销。5% 的困惑度增加换取的是显著的资源节省，在搜索实时性要求高的场景下，这是一个有价值的工程权衡。

Marmik Chaudhari, Idhant Gulati, Nishkal Hundia, Pranav Karra, Shivam Raval
