Semantic Retrieval for Product Search in E-Commerce

针对电商搜索中 query 短、口语化、噪声大且商品属性细粒度的问题，提出基于孪生 LLM 双塔编码器的两阶段语义召回方案。第一阶段用对比学习训练，并引入 false-negative margin mask 避免把近似重复商品当负样本惩罚；第二阶段提出 ROAR（Relative Odds Alignment for Retrieval）偏好优化目标，把 Bradley-Terry 扩展到可变长度的分级相关性分组，用相邻档位的 odds-ratio margin 做排序对齐。训练语料同步分级：Stage1 用替代品 query-商品对提供粗粒度语义监督，Stage2 用分级相关性标注驱动细粒度排序。

1. 问题与动机

论文处理的是电商语义召回里一个很实际的断层：通用文本 embedding 在长句和知识问答上很强，却未必理解只有两三个词、拼写不完整且强依赖商品属性的查询。传统词法检索能抓住品牌、型号等精确 token，但面对 comfortable shoes for office 这类意图表达会漏掉大量可替代商品；标准双塔虽然服务高效，训练时又常把同一查询下实际可购买的替代品当成 batch 负例。更进一步，生产相关性并非简单二元标签：完全匹配、可替代、弱相关和不相关之间有序，但 InfoNCE 只学习正负边界，普通 pairwise 偏好训练也很难处理每个查询候选数不同、标签档位不均的问题。

Flipkart 的目标因此不是单纯刷新离线榜单，而是在大规模商品库中保留双塔召回的索引效率，同时把短查询语义、假负例和分级偏好纳入同一训练流程。工作建立在大规模文本 embedding、对比学习和 Bradley–Terry 偏好建模之上，选择 Qwen3-Embedding-4B 作为预训练底座，再针对商业搜索做两阶段适配。论文的重要性来自端到端生产证据：离线不仅测语义相似度，还与既有线上模型比较；线上进一步报告 CTR、加购、订单、延迟、QPS 和显存，能判断模型增益是否真正穿过索引与服务链路。

2. 方法详解

系统采用共享参数的 Siamese 双编码器，查询和商品文本分别输入同一个 Qwen3-Embedding-4B，取最终表征后归一化，以余弦相似度作为召回分数。为了控制索引和在线计算，训练同时使用 Matryoshka Representation Learning，把部署向量截断到 256 维；主干通过 LoRA 适配，秩为 32、alpha 为 64、dropout 为 0.1，而不是全量更新 4B 参数。完整训练分为对比预训练和分级偏好对齐两步。

第一阶段使用约 700 万查询—商品对。正样本来自行为与相关性数据，batch 内其他商品作为负例，温度系数为 0.02。关键改动是假负例 margin mask：对于某个 query，如果 batch 中另一商品的相似度已经接近该 query 的正商品，且差值落在 0.1 的 margin 内，就不强迫模型把它当成负例。直观上，这是承认电商查询往往存在多个合理替代品；与把所有 batch 内样本塞进 softmax 分母相比，mask 能减少对潜在正例的排斥。阶段一学习率为 2e-5，warmup 占 10%。

第二阶段使用约 200 万组分级相关性样本。每组属于同一 query，包含 2–7 个商品及其有序标签。作者采用 ROAR，即 Relative Odds Alignment for Retrieval：先把 embedding 相似度转换成候选间的相对胜率，再用 Bradley–Terry 思路要求高标签商品的 odds 高于低标签商品。区别于只采一对 chosen/rejected，ROAR 在可变长度组内利用所有等级关系，并以参考模型约束更新，避免排序对齐破坏阶段一已学到的语义空间。其偏好强度 beta 为 0.1，辅助温度为 0.01，学习率降至 5e-7；这种小步对齐说明作者把阶段二视为对召回几何的校准，而不是重新学习表示。

训练使用 8 张 NVIDIA H200，每卡 batch size 1024，有效全局 batch 8192。离线测试集约 2.5 万查询，指标包括 MAP@8、nDCG@8 和区分相关/不相关样本的 AUC。服务侧将 256 维商品向量离线写入 ANN 索引，查询仅需一次编码后检索；论文给出的模型占用约 7.5GB。名义 200 QPS 下 P99 为 135ms，峰值 680 QPS 下为 236ms，说明较大 backbone 并未被包装成零成本方案，而是通过 LoRA、低维向量、离线商品编码和批处理控制在线预算。

3. 核心技术贡献

  1. 面向多正例电商查询的假负例抑制。 常规 in-batch contrastive learning 默认一条 query 只有一个正商品，margin mask 则根据当前相似度跳过可疑负例。它不需要额外人工重标整个 batch，却能保护替代品和同款不同规格等合理结果的语义邻近性，针对的是电商数据中普遍存在的弱监督噪声。
  1. 把分级标签直接写进双塔几何。 ROAR 将 Bradley–Terry 相对 odds 扩展到每个查询 2–7 个候选的分组数据，利用完整的等级次序，而不是把多档标签压成二元对。阶段一负责广义语义和可分性，阶段二以很小学习率调整局部次序，最终相对生产基线把 MAP@8 提高 5.57 个百分点、nDCG@8 提高 3.56 个百分点。
  1. 给出从 4B 底座到生产召回的完整折中。 论文没有让交叉编码器承担全库检索，而是坚持双塔；通过 LoRA、MRL 256 维索引和离线商品编码，把大模型知识压到常规 ANN 流程。AUC 相对生产基线提高 13.13 个百分点，同时 P99 在 200 QPS 下维持 135ms，说明表示增益和服务可行性被共同验证。
  1. 以线上漏斗证明召回收益不是离线幻觉。 A/B 测试同时观察点击、加购和订单，分别提升 2.39%、4.58% 和 2.62%。加购增幅高于点击，订单仍保持正向，表明改进不仅来自更吸睛的结果，也更可能提高商品与购买意图的匹配。

论文把新模型与 Flipkart 的生产语义召回基线比较，主要结果如下。离线表中的变化为绝对百分点，线上为相对业务增幅。

AUC 的增幅显著大于排序指标，说明通用底座经领域适配后首先增强了相关与不相关商品的整体可分性；MAP@8 和 nDCG@8 仍有可观提升，则表明 ROAR 没有只把容易样本推得更远，也改善了头部候选次序。线上加购提升 4.58% 是最强信号，超过 CTR 约 2.19 个百分点；如果提升只来自标题语义更接近但商品不可买，通常不会在更深漏斗继续放大。订单提升低于加购但仍为 2.62%，符合价格、库存、配送等召回模型不可控因素会在后续漏斗稀释增益的预期。

论文的两阶段结构本身构成关键消融逻辑：只做通用 embedding 无法适配短而噪声的商品查询；只做对比训练会浪费多档人工/行为标签；直接强偏好优化又可能破坏原表示。较大的阶段一数据与 2e-5 学习率负责领域迁移，较小的阶段二数据和 5e-7 学习率只校正等级顺序。margin mask 对多正例噪声、ROAR 对分级顺序分别解决不同问题，因而不是可互换的技巧。遗憾的是，论文没有在公开正文中完整列出移除 mask、移除 ROAR、不同向量维度和不同 base model 的逐项数字表，外部读者无法精确分摊 +5.57 MAP@8 中各组件贡献。

服务实验揭示另一组条件。7.5GB 模型在名义 200 QPS 下 P99 135ms，峰值 680 QPS 时升到 236ms，吞吐扩大 3.4 倍而尾延迟增加约 75%。这仍可能满足商品搜索预算，但对于已有几十毫秒 query encoder 的系统不是无成本升级。256 维 MRL 表征降低了 ANN 存储和带宽，不过论文未同时报告 256 维与完整维度的精度差、索引规模、召回深度及 ANN 参数，所以只能确认端到端配置有效，不能独立判断压缩损失。

5. 局限与未来方向

论文明确呈现的边界主要在数据和系统可复现性：训练与评测均来自单一大型电商平台，查询、商品、标签规则和流量分层不能公开；线上实验验证了整套两阶段方案，却不能把业务收益分别归因于 margin mask、ROAR、Qwen3 底座或 MRL 压缩。正文也没有公开完整消融数字、优化器细节、训练步数、墙钟时间、ANN 索引配置和绝对业务指标，因此外部团队难以复算每一点增益的 GPU 与服务成本。

论文较少讨论库存、价格、流行度和曝光偏置如何进入训练对；如果行为正例集中在已获得曝光的商品，模型仍可能强化头部。分级标签在不同类目是否一致、低频或多语言查询是否同样受益也缺少细分结果。未来值得验证公开电商数据上的可复现版本、跨语言/跨类目迁移、蒸馏到更小 query encoder，以及在保持 ROAR 排序关系时加入新商品公平曝光和时间衰减。

6. 工业实践意义

对社区搜索或 UGC 检索团队，最可复制的是数据与目标的分层，而不是直接照搬 4B 模型。第一步应把点击、长停留、收藏、关注和人工相关性整理成同一 query 下的多档标签；同一主题下的不同帖子常同时有效，训练双塔时不要把 batch 内所有其他内容视为硬负例。可以先用 margin mask 做最小改动，对比假负例率、Recall@K 和 nDCG，再决定是否引入完整 ROAR。

第二步可冻结已有 encoder 做小学习率偏好对齐。每组保留 2–7 条不同质量内容，建立完全匹配、补充信息、弱相关和不相关的顺序；离线除了 nDCG，还要按 query 频次、长度、实体/非实体、时效意图和多语言分桶。社区内容比商品变化快，商品侧离线编码的经验不能直接照搬：新帖、热点和删除内容需要增量索引旁路，偏好训练也应加入时间窗口，防止旧行为长期支配语义空间。

第三步才是模型与基础设施升级。MRL 256 维值得作为索引降本基线，但应同时测 128/256/512 维的 Recall、内存与延迟。若 4B query encoder 的 135ms P99 超出预算，可尝试离线教师生成偏好分数，再蒸馏到数亿参数学生，或只把大模型路由给低置信、长尾查询。峰值 680 QPS 时 236ms 的结果提示容量规划必须基于高峰尾延迟，并预留回退到轻量 encoder 或词法召回的开关。

线上实验建议沿漏斗观测 CTR、有效停留、收藏/加购、后续转化和结果多样性。Flipkart 的加购 +4.58% 高于 CTR +2.39%，说明更深目标能帮助识别真正的意图匹配；社区场景可对应为点击之后的长停留、评论或关注。总体上，这项工作证明了通用 embedding 底座只有经过领域对比学习、假负例治理和分级偏好对齐，才更可能转化为生产收益；而部署成功依赖训练目标、低维索引、峰值容量和业务漏斗共同设计。

Scaling Search Relevance: Augmenting App Store Ranking with LLM-Generated Judgments

Apple📖 有深读 · 13 分钟

商业搜索同时优化行为相关性（用户点击/下载）与文本相关性（语义匹配），但专家标注的文本相关性标签相对海量行为标签极度稀缺。论文系统评估多种 LLM 配置，发现经过专门微调的小模型在生成高相关性标签上显著优于规模大得多的预训练大模型；以该最优模型为「放大器」生成数百万条文本相关性标签，用于增强 App Store 生产排序器。结果显示注入 LLM 生成判断后线上排序相关性获得提升。

1. 问题与动机

这篇工作来自 Apple App Store 的大规模商业搜索。作者指出，线上搜索排序同时面对两个并不等价的目标：行为相关性，即用户是否点击或下载；文本相关性，即结果在语义上是否真正符合 query。行为日志量大、更新快，但它混合了位置、曝光、品牌认知、价格和 UI 等因素，不能单独代表语义匹配。人工标注的文本相关性更接近专家判断，却昂贵、覆盖有限，尤其难覆盖低频的 tail query。结果是生产 ranker 在头部 query 上有较强行为信号，在尾部 query 上既缺语义标签，也缺稳定行为样本。

作者的核心动机不是把 LLM 放到在线重排链路中，而是把它作为离线标注器，为已有搜索日志中的 query-app pair 生成可规模化的文本相关性标签。论文把这条路线明确放在两个已有方向之间：一类工作让 LLM 直接做 pointwise、pairwise 或 listwise 重排，面临推理时延和成本；另一类工作使用 LLM-as-a-Judge 辅助评测，但通常没有把生成标签直接用于生产 ranker。本文希望验证一个更工程化的问题：一个针对本业务 rubric 微调过的小模型，是否可以把少量人工判断扩展成数百万条训练监督，并且同时改善语义相关性与点击/下载表现。

论文的重要性在于它把标注瓶颈和排序目标放到了同一条生产链路中。作者不是只在公开数据集上展示离线增益，而是使用跨 storefront、跨语言的历史搜索日志生成标签，随后用独立的文本相关性验证集和全球线上流量检验信号是否可靠。这样能够回答社区 UGC 搜索最现实的问题：当短 query、长尾实体、口语表达缺少点击统计时，能否用离线语义监督补上相关性模型的盲区。

2. 方法详解

整体流程分为两个阶段。第一阶段训练并选择 LLM relevance judge，第二阶段把它生成的 pointwise 文本标签混入多目标 ranker 的训练集。对每个历史 query-app pair，模型看到 query、若干 app metadata，以及与人工标注一致的五档 relevance rubric，输出唯一的 label。论文给出的 few-shot prompt 例子要求模型只返回标签，不生成解释，从而使输出稳定、方便批量解析。作者同时比较 zero-shot 和 few-shot、字符串标签和数字标签等 prompt 配置。

标注器的实验设置很具体：三种模型分别是预训练 3B、预训练 30B，以及在人工 judgments 训练集上微调的 3B。人工标注数据被切成训练集和验证集，用于微调 FT-3B 以及评估模型能否复现 held-out human label；随后，最优配置在大规模历史 App Store session logs 上推理。日志数据包含按 query 聚合的 query-app 候选对，规模为 millions，记作 n×m 的候选关系。这样做的关键不是让模型理解所有 App Store 业务，而是让它内化本业务专家的 relevance 定义：同一个 app metadata 在不同 query 下应得到不同的 ordinal label。

第二阶段使用一个多目标 learning-to-rank 框架。行为相关性标签来自聚合后的 click 和 download 日志，文本相关性标签有两部分：人工 judgments 和 LLM-generated judgments。相同的 query-app feature vector 可以在训练数据中出现多次，但携带不同来源的监督：一行用于行为目标，另一行用于文本目标。作者采用 scalarization，把不同标签源按可控比例混合成 ranker 训练数据，相当于在 behavioral relevance 与 textual relevance 之间寻找一条 Pareto frontier。文中举例的混合比例包括 90–10、70–30 和 50–50；改变比例可以选择新的折中点，而不是把两个目标硬编码成一个不可解释的标签。

这种数据混合方式的工程含义是保留现有生产 ranker 的结构和特征，只扩展训练监督，不要求在线调用 LLM，也不必为 LLM 设计一套新的推理服务。训练阶段严格区分 label source，避免把文本判断和行为统计的梯度混在同一条样本语义里。文本相关性的离线验证使用与 LLM 微调和验证不重叠的人工判断集合；ranker 的 NDCG 也使用独立的人工文本判断，避免模型仅仅记住生成器的偏好。

3. 核心技术贡献

第一，论文把 LLM-as-a-Judge 从通用评测工具改造成生产数据生成器。与实时 LLM reranker 不同，LLM 只在离线阶段对日志候选打标签，因此可以把成本摊到索引和模型迭代周期，不改变在线 SLA。真正起作用的机制是把专家 rubric 作为模型输出空间，让生成监督和现有人工 label 可对齐。

第二，作者用实验说明领域微调比简单扩大模型尺寸更有价值。FT-3B 的验证 F1 达到 0.800，而 PT-30B 只有 0.382；前者参数量约为后者十分之一，却更接近人工判断。这不是单纯的压缩结论，而是说明 relevance judgment 的关键在于业务定义、示例和标签边界，通用语言能力不能替代任务对齐。

第三，LLM 标签不是独立优化语义指标，而是被放入多目标 ranker 的数据混合框架。这样得到的是 Pareto 改善：加入生成标签后，文本 NDCG 和行为 NDCG 在多个 cutoff 同时提升。相比只把 LLM 分数作为一个额外 feature，数据级混合能够显式控制文本与行为监督的比例，方便在不同业务阶段选择更保守或更语义化的模型。

第四，论文把离线指标和线上转化串起来。全球 A/B 测试中，llm-augmented ranker 的 conversion rate 显著提升 0.24%，并且在 89% 的 storefronts 中优于生产模型。更重要的是增益集中在 tail query，说明生成标签确实填补了行为数据稀疏的区域，而不是只在流量最大的 query 上重复已有信号。

实验分两层。第一层检验 LLM 是否能复现人工文本相关性；第二层检验这些标签是否能改善生产排序器。标注器验证集结果如下。

结果显示，预训练 30B 比预训练 3B 好，但规模提升十倍仍远低于业务微调的 3B。论文还报告 few-shot、字符串标签的 prompt 配置最佳；数字输出更便于解析，却没有字符串 rubric 那样充分地承载人工判断边界。作者没有把所有 prompt 组合的完整表格放出，因此不能据此断言某个具体模板在所有语言上都最优，但方向很清楚：先固定业务标签定义，再用少量高质量 judgments 微调。

数据混合比例实验体现了一个实用的消融结论：增加 LLM 标签会把 Pareto frontier 向外推，但继续改变 LLM 标签占比主要是在新 frontier 上移动，而不是无限制地继续抬高 frontier。也就是说，生成标签首先解决的是监督覆盖不足，达到一定覆盖后，业务需要根据文本相关性与行为相关性的权重选择工作点。这个结论支持把比例做成可配置训练旋钮，而不是把 LLM 监督一次性全量替换行为监督。

线上 A/B 测试比较全球真实流量的 prod 与 llm-augmented。conversion rate 定义为至少发生一次 app download 的搜索 session 比例；增强模型整体显著提升 +0.24%，并在 89% 的 storefronts 中胜出。按 query frequency 分桶后，低频尾部的曲线提升最大，高频头部相对有限。原因与方法假设一致：头部 query 已经有足够 click/download 信号，尾部 query 缺少可靠行为标签，LLM 生成的文本相关性提供了较稳的先验。

一个值得注意的边界是，论文主要报告 aggregate 指标和 storefront 分布，没有展开不同语言、query 意图、应用类别和错误类型的完整分桶，也没有披露生成 millions 标签的绝对推理成本、人工校验比例或线上延迟变化。因而可以确认方法具有工业可行性，但还不能直接推导在社区短文本、强噪声 UGC 或中文口语 query 上会获得同等幅度。

5. 局限与未来方向

作者明确提出的未来工作包括尝试更多微调模型，以及从 pointwise 标签扩展到 pairwise 和 listwise prompt，使 LLM 能直接表达两个候选之间的偏序，或对一个候选列表提供排序信号。这个方向可能让生成监督更贴合 LTR 的相对排序目标，但也会显著增加 prompt 复杂度、候选组合数和标签一致性问题。作者还指出，当前工作依赖已有人工 relevance judgments 来微调和验证 judge，因此完全没有人工标签的新市场仍不能直接套用。

从论文实验可见但未充分展开的限制包括：第一，LLM judge 与 ranker 共享同一业务 metadata，生成器和排序器可能形成闭环偏差；第二，五档 pointwise label 不一定能识别多样性、覆盖性和近重复内容，UGC 搜索还需要 pairwise、listwise 或 set-level 约束；第三，跨语言生成标签的质量需要单独校准，不能由英文或高流量 storefront 的验证结果外推；第四，线上 A/B 只证明总体转化提升，并不能替代对误召回、低质内容、敏感内容和长尾新帖的安全检查。

6. 工业实践意义

对社区 UGC 搜索，推荐采用离线 LLM 标注器而不是把大模型直接放在每次请求的重排路径上。第一步应整理 query—帖子或 query—评论的人工相关性 rubric，至少区分完全匹配、部分满足、主题相关但意图不符、无关和潜在误导等等级；然后用少量高质量人工 judgments 微调一个小型 judge，并在独立验证集上检查 precision、recall、F1，而不是只看模型生成的自洽性。本文的 FT-3B 对 PT-30B 的结果说明，业务对齐样本比盲目追求更大参数量更重要。

第二步是把生成标签作为增量监督，与 CTR、停留、收藏、关注、负反馈等行为标签分开管理。UGC 的点击往往受作者、标题党、发布时间和社交传播影响，不能把 click 直接当作语义相关；可用 90–10、70–30、50–50 等混合比例训练多个 ranker，在 nDCG、CTR、长尾 query 覆盖和低质召回率之间画出自己的 Pareto frontier。训练/验证必须按时间和用户切分，并确保用于 judge 微调的人工样本不出现在最终文本 NDCG 评估中。

第三步应优先在 tail query、冷启动帖子和新实体上做分桶实验。论文线上收益集中在低频 query，这正对应社区中口语、拼写变体、简称和新热点词的监督稀疏区。上线前可以用离线生成标签训练候选重排或粗排模型，线上只保留轻量模型；对 judge 的输出设置置信度阈值，低置信度、争议度高或涉及安全的样本回流人工审核。

最后要建立数据治理和偏差防线。不能让 LLM 生成标签完全替代人工；应抽样比较不同语言、内容类别、作者规模和 query 频次，检查是否系统性偏向长文本、热门作者或规范表达。对中文短文本，还应单独覆盖错别字、谐音、方言、缩写、emoji 和多意图 query。线上评估不应只看整体 CTR，应同时监控 nDCG、长尾覆盖、bad-case rate、用户负反馈与内容安全指标。论文给出的 +0.24% conversion lift 说明成熟系统的增益可以很小但有价值，社区系统应把统计显著性、效果稳定性和可回滚的训练版本一起纳入发布门槛。
