ProMax: Exploring the Potential of LLM-derived Profiles with Distribution Shaping for Recommender Systems

面向 LLM-as-feature-extractor 范式：作者提出 ProMax，将 LLM 生成的用户/物品 profile 作为辅助信号注入推荐主模型，但摒弃常用的非线性对齐与融合策略，转而从「检索视角」重新审视 profile，引入双向 distribution shaping 机制——用 dense retrieval 暴露 profile 之间的协同关系，再让 profile 分布反向引导主模型对未见物品的偏好分布。在 3 个公开数据集 × 4 类经典推荐模型上均显著优于直接拼接 / 对齐式基线及现有 LLM-rec 方法，论文已被 SIGIR 2026 接收。

KEY INSIGHT · 对业务意味着什么LLM profile 不应被「投影对齐」回 ID embedding 空间——这条主流路径会丢失 LLM 抽出的语义结构。ProMax 的关键启示是把 profile 当成监督信号去重塑主模型的输出分布，而不是当作输入 feature 拼进去；这恰好契合 UGC 短文本搜索中「LLM 抽出的查询/帖子主题画像」往往很稀疏却分布性强的特点，可作为排序模型的分布矫正项使用，比硬塞向量更鲁棒，且不增加在线推理成本。

1. 问题与动机

LLM 让推荐进入「文本理解 + 协同过滤」的混合范式：从用户历史交互生成结构化 user/item profile，再把 profile 当作辅助语义信号注入推荐主模型。然而作者明确指出业界主流路径有两个尚未解决的问题：(a) profile 通过非线性 alignment 模块（MLP / cross-attention）压回 ID embedding 空间会产生「语义损失」——profile 中天然的协同结构被破坏；(b) 论文之间在「为什么 profile 有效」这一机制层面缺乏统一解释，导致 ablation 难以指导工程取舍。

动机由此清晰：与其把 profile 当输入 feature 拼回模型，不如把它当成「监督信号」去重塑主模型的输出分布——尤其是在用户从未交互过的物品上。这其实回到了知识蒸馏的思路，但 teacher 不是更大的模型，而是 LLM 抽出的 profile 分布。这种重新定位也直接对应 ProMax 的最大卖点：模型无关（model-agnostic）、不增加在线推理参数。论文已被 SIGIR 2026 接收。

2. 方法详解

ProMax 由三个阶段组成。

阶段 1：Profile 生成与降维。 用 LLM（论文实验主要用 GPT-4o-mini）对每个 user 和 item 生成自然语言 profile，再过 text encoder 得到稠密向量，最后用 mean-centered PCA 投影到前 κ 个主成分（κ=32）。这一步压低维度的同时保留 profile 之间的协同结构，比直接拼接的 1024 维 BERT/E5 输出更适合下游 retrieval。

阶段 2：Dense retrieval 暴露协同信号。 这是 ProMax 与既有 LLM-rec 工作最核心的差异。三步走：

  1. User 端检索：对每个用户 u，在 profile 空间用余弦相似度找出 K₁ 个最相似用户（Eq. 5）；
  2. Item 端聚合：从相似用户的历史交互聚合候选物品集合 C_u，按交互频次加权（Eq. 6-7）；
  3. Sparsity-level shift：根据用户原始交互数对 Q₀.₂₅/Q₀.₅/Q₀.₇₅ 四分位的位置，动态分配新增物品数 K_u —— 稀疏用户加更多新物品，活跃用户少加，避免噪声压过 ground-truth。

阶段 3：双向分布重塑训练。 两个 loss 是 ProMax 的灵魂：

  • Supervised Distribution Reshaping (SDR): L_SDR = -Σ w(u)·Σ sg[p_LLM(i|u)]·log p_Θ(i|u)。其中 p_LLM 是 profile 推出的 item 偏好分布（teacher），p_Θ 是主模型分布（student），sg 是 stop-gradient。w(u)=1-H(u) 用归一化熵作为不确定性权重——profile 越自信（低熵），SDR 权重越大。
  • Self-Supervised Distribution Reshaping (S²DR): 对每个 user 构造增广 / 抗增广交互集合 M_u, M'_u，强制双向一致性，缓解 profile 噪声。

总目标 L_ProMax = L_rec + λ₁·L_SDR + λ₂·L_S²DR；实验最优 λ₁∈[0.5,1.5]，λ₂∈[0.05,0.1]。训练时 backbone（MF / LightGCN / SimGCL 等）保持不变，只在 loss 端接入 ProMax。

3. 核心技术贡献

(1) 从「输入对齐」到「输出蒸馏」的视角切换。 把 LLM profile 重新定位成 teacher distribution，避免在 ID 空间硬性 alignment 带来的语义损失。这一改变让 ProMax 完全 model-agnostic——任何输出 softmax/sigmoid 评分的 backbone 都能即插即用。

(2) Dense retrieval 暴露 profile 中的协同关系。 大多数 LLM-rec 工作只用 profile 表征单个用户/物品，从未利用「相似用户的相似偏好」这条 collaborative 路径。ProMax 的 user-side + item-side 两阶段检索把 LLM 的语义能力和协同过滤的统计能力做了显式融合。

(3) Sparsity-aware 动态新增物品数 K_u。 稀疏用户加 60%+ 的额外候选，活跃用户基本不加。这条工程细节解决了 LLM-rec 长期以来「头部用户提升小，尾部用户提升大」的不均衡问题。

(4) 不确定性加权的 SDR loss。 通过 w(u)=1-H(u) 让置信度低的 profile 对训练贡献更小，避免 LLM 幻觉污染。这是相比 KAR、LLMRec 等基线最大的工程改进。

4. 实验结果分析

数据集： Amazon-Book（11k 用户 / 9.3k 物品 / 99.80% 稀疏度）、Yelp（11k/11k/99.77%）、Steam（23k/5.2k/99.57%）。

基线包括 KAR、LLMRec、CARec、RLMRec-C/G、AlphaRec/AlphaRec+、LLMESR、AlphaFuse、IRLLRec、ProEx 共 10 个 LLM-rec 强基线，ProMax 在三个数据集上的 NDCG@10 / Recall@20 全部最优。

Model-agnostic 验证（Figure 4）： 在 Amazon-Book 上叠加到 4 类 backbone 的 Recall@20 提升：MF +13.3%、LR-GCCF +15.6%、LightGCN +13.3%、SimGCL ~3-5%。SimGCL 提升较小是因为它本身已有 self-supervision，再加 ProMax 收益打折——这反而验证 ProMax 的收益主要来自分布层面的监督。

Sparsity 分桶（Figure 5）： 在「中等活跃度」用户分桶 U3 提升最明显（接近 60%），印证 sparsity-level shift 设计的有效性。

Ablation（Figure 7）： V1（去 S²DR）、V2（去 SDR）、V3（去 LLM 重排）三个变体全部退化，证明每个组件都是必要的。

效率（Figure 6）： ProMax 训练时间约为 base 的 2-3 倍（多 dense retrieval 这一步），但显著低于 ProEx；推理时间无变化（profile 和检索都是离线的）。

5. 局限与未来方向

论文没有专门「局限」章节，但能从设计中识别出几条作者隐含或读者可见的约束：

  1. 依赖外部 LLM 服务。 profile 生成阶段调用 GPT-4o-mini，成本和延迟由外部决定；离线大规模生成对预算和速率限制提出要求。
  2. PCA 降维到 κ=32 是经验值。 论文未讨论不同 domain（如纯视觉推荐、超长序列）下的最优 κ；超稀疏 domain 可能需要保留更多主成分。
  3. Sparsity quartile 阈值固定。 Q₀.₂₅/Q₀.₅/Q₀.₇₅ 是经验切分，没有自适应机制；不同业务用户活跃度分布差异大，阈值需要重调。
  4. Stop-gradient 阻止了 profile 反向更新。 profile 始终是冻结 teacher，没有让推荐信号反过来 refine LLM 的能力，留有改进空间。

未来方向作者隐含包括：把 stop-gradient 改成 EMA 式 soft 更新；把 sparsity-shift 改成可学习；探索 profile 与序列 LLM-rec（HSTU 之类）的兼容。

6. 工业实践意义

对工业搜索/推荐团队的具体启示：

(1) LLM-rec 落地前重新审视融合方式。 已经在用 KAR / LLMRec 类 alignment 方案的团队可以把 ProMax 当作「分布蒸馏版替代」，预期能在长尾物品 NDCG 上拿到 5-10% 提升，且不增加在线推理参数（线下离线生成 profile + 训练时多 1 个 loss）。

(2) sparsity-aware 的训练增强可以独立复用。 ProMax 的 sparsity-level shift 思路（不同活跃度的用户加不同数量的候选）可以脱离 LLM 框架，直接用在普通 BPR / softmax 训练里增强长尾。

(3) profile 不确定性加权 w(u)=1-H(u) 是工程兜底。 实际生产环境中 LLM 经常给出错误偏好猜测（尤其低活跃用户），用熵作为信心度直接挂在 loss 上比硬规则黑名单更稳。

(4) 社区搜索（UGC 短文本）的应用。 把「用户搜索意图画像」+「帖子主题画像」分别由 LLM 生成，做 dense retrieval 暴露 query↔post 的潜在 co-occurrence，再以分布形式监督相关性模型——比把 LLM 表征直接拼到 cross-encoder 更鲁棒，也更适合短文本稀疏的场景。

(5) 部署 checklist： 离线生成 profile 时控 cost（建议先用蒸馏模型而非 GPT-4 全量）；训练时记录 SDR/S²DR 两个 loss 的权重 sweep 曲线；上线前做 sparsity 分桶 A/B（中度活跃 vs. 头部 / 尾部分别看 NDCG）。

Understanding DNNs in Feature Interaction Models: A Dimensional Collapse Perspective

USTC📖 有深读 · 10 分钟

为「DNN 在 CTR/特征交互模型里到底起什么作用」这一长期争论提供新解释：作者通过对 parallel-DNN（如 DCN-V2）和 stacked-DNN（如 DeepFM）做整体与组件级消融，结合梯度理论分析，证明 DNN 的真正贡献并非隐式学高阶交叉，而是缓解 embedding 表征的「维度坍缩」（dimensional collapse），从而提升表示鲁棒性。论文给出 DNN 不同分支/组件对维度坍缩的影响机制，并用经验现象佐证理论推导。

INSIGHT这篇论文颠覆了「加 DNN = 学高阶交互」的常见认知：CTR 模型里 DNN 的真实价值在于稳住 embedding 的有效维度。对工业排序的直接启示——评估 DNN 分支时不要只看 AUC 增量，要监控 embedding 的奇异值分布；遇到表征坍缩（少量稀疏特征主导）时，加 parallel DNN 比堆叠 DNN 更有效。也为「最近大家观察到 DCN-V2 比 DeepFM 更稳」提供了理论解释，对调参与架构选型很有指导意义。

Jiancheng Wang, Mingjia Yin, Hao Wang, Enhong Chen
arXiv·2026-04-30·Relevance 5 · Novelty 4 · Practical 4 · Evidence 4 · Timely 5

1. 问题与动机

CTR 预估领域近 10 年关于 DNN 角色的争论从未停过：DeepFM、DCN-V2、xDeepFM 等模型都把 DNN 作为标配组件，主流解释是「DNN 隐式学习高阶特征交互」；但近两年 Rendle 等人的研究反复证明 DNN 在学 dot product（二阶交互）这种基础操作上都很挣扎，遑论高阶。这造成一个现实尴尬——工业界知道加 DNN 通常 AUC 涨一点，但说不清为什么加；遇到不涨的场景也无从诊断。

作者由此提出全新视角：DNN 在特征交互模型里的真正贡献是缓解 embedding 表征的「维度坍缩」（dimensional collapse），即奇异值谱迅速衰减导致表征塌缩到低维子空间。这一框架既能解释 DNN 为什么有用，也给出诊断工具（看 RankMe / 奇异值分布），把 CTR 模型调优从「炼丹」朝「可观测」推进了一步。

2. 方法详解

实验框架： 把 DNN 解耦成「parallel 分支（与交互项并行）」和「stacked 分支（在交互项之后串联）」两类，然后在两个 base 上叠加：FM（factorization machine）和 CrossNet（DCN-V2 的核心）。组合得到 4 个对照模型——DeepFM（FM+parallel-DNN）、NFM（FM+stacked-DNN）、parallel DCN-V2（CrossNet+parallel）、stacked DCN-V2（CrossNet+stacked）。

数据集： Avazu（embed dim=16）、Criteo（embed dim=10），CTR 标准 benchmark。

评估三件套：

  1. AUC 看预测精度；
  2. RankMe（Garrido et al. 2023）= 归一化奇异值的 Shannon 熵 e^H，作为有效维度的可微分估计——RankMe 越大表示 embedding 占据的有效维度越多，坍缩越轻；
  3. 奇异值谱可视化 直接看 top-K 维度的衰减曲线。

梯度理论分析（核心创新）：

  • 纯 FM 的 embedding 梯度：∂Φ_FM/∂v_i = Σ_{j∈ℱ_x, j≠i} v_j。这是关键——v_i 的更新方向被严格限制在「与其交互的特征 embedding 张成的子空间」内，所以 FM 不可避免地把表征拉向低秩子空间，造成坍缩。
  • 加 parallel DNN 后：∂Φ_p-DNN/∂v_i = (Σ_j v_j) + g_DNN(v_i; ℱ_x)。DNN 项给出与交互项 正交 的额外梯度方向，能把 embedding 从低维流形「拉出来」。
  • 加 stacked DNN 后：∂Φ_s-DNN/∂v_i = g_DNN · Σ_j diag(v_j)。DNN 在每个维度独立加权，相当于「逐维 non-linear 调制」，让不同特征 embedding 的演化解耦，间接维持表征多样性。

组件级 ablation： 把 DNN 拆成「线性投影」+「非线性激活」分别加入。线性投影单独已经能把 top-150 奇异值抬高一些；再加非线性激活把 25-200 奇异值区间整体拉平。两者叠加效果远超单独使用，证明 DNN 的多样性来自线性 + 非线性的协同。

3. 核心技术贡献

(1) 重新定义 DNN 的核心作用：从「学高阶交叉」改为「缓解维度坍缩」。 这是对 CTR 建模理论框架的重要修正。如果未来论文还想说「我们的 DNN 学到了 4 阶以上交互」，必须先在 RankMe 维度上证伪本文的解释。

(2) 梯度分析给出可证伪的机制解释。 parallel-DNN 提供「正交梯度补充」；stacked-DNN 提供「逐维非线性调制」。两条机制都能用闭式梯度公式刻画，并被 RankMe 实验验证。

(3) RankMe 作为 CTR 模型新型监控指标。 论文把 vision-SSL 领域的工具迁移到 CTR，给出可在工业生产中追踪的「表征健康度」指标。Avazu 上 FM 的 RankMe=89.12 → DeepFM 的 166.78（+87%）；Criteo 上 70.13 → 181.56（+158%）。这两组数据本身就能成为 CTR 模型 metrics dashboard 的标配。

(4) 架构选型经验法则： parallel-DNN 在 FM 系（DeepFM）上更好，stacked-DNN 在 CrossNet 系（DCN-V2 stacked）上更好——结论与 base 模型本身是否「天然就有正交方向梯度」有关。这给「为什么 DCN-V2 stacked 比 parallel 稳」首次提供了机制解释。

关键观察： AUC 提升只有 0.4-1.1pp（业界标准的 CTR 量级），但 RankMe 提升 60-160%。这说明 DNN 的价值大部分体现在「把 embedding 占据的有效维度撑大」，而 AUC 只反映了部分价值——这暗示传统 CTR 模型评估单看 AUC 是低估了 DNN 的作用。

组件级 ablation（Section RQ2）：

  • 线性投影单独引入：top-150 奇异值小幅抬高，部分缓解坍缩；
  • 加非线性激活：25-200 奇异值区间被进一步「拍平」；
  • 完整 DNN：奇异值谱最平坦，对应 RankMe 最高、AUC 最优。

梯度行为分析（Avazu）： 纯 FM 梯度集中在 top-30 奇异分量；stacked-DNN 让梯度向更高奇异分量分散；parallel-DNN 让梯度分布最广。这与梯度公式预测完全一致——「正交项 g_DNN」直接把更新方向打开。

对工业场景的意义： DCN-V2 团队多次报告 stacked > parallel，本文给出机制解释：CrossNet 自身的 cross product 已经提供了一定程度的正交梯度方向，再加 parallel DNN 反而冗余；而 stacked DNN 通过逐维调制带来增量。这与社区观察一致。

5. 局限与未来方向

论文未单列 limitations，但读者可识别：

  1. 数据集仅 2 个（Avazu / Criteo）。 都是公开 CTR benchmark，没覆盖大规模工业数据（如 Taobao、Kuaishou），样本量、特征稀疏度差异未考察。
  2. 只评估了 FM 与 CrossNet 系列 base。 未涉及 GNN-based ranking（如 GraphSAGE-CTR）和 Transformer-based ranking（如 BST、SIM）。这些 base 自身梯度结构不同，DNN 角色可能不同。
  3. 梯度公式假定 ReLU 激活。 GELU、Swish、Mish 等近年常用激活的影响未单独验证。
  4. RankMe 依赖大 batch 估计。 工业生产小 batch（受 GPU 显存限制）下的稳定性未做实验。
  5. 只看了「DNN 缓解坍缩」这一条贡献。 没有否定「DNN 也学了一些隐式高阶交互」，两者可能并存——后续工作需要因果实验拆分。

未来方向：把 RankMe 作为 CTR 模型训练时的 auxiliary regularizer（直接最大化 RankMe）、扩展到序列推荐 / 多模态 ranking、研究 dimensional collapse 与冷启动 / 长尾的关联。

6. 工业实践意义

对国内 CTR 团队的实操启示：

(1) 架构选型的新依据：先看 base 是否提供「正交梯度」。
- 如果 base 是 FM/IPNN/AFM 这种纯交互（梯度被锁在交互子空间）→ 强烈建议加 parallel DNN 才能撑开 embedding 维度；
- 如果 base 是 CrossNet/CIN（自带跨维度乘法）→ stacked DNN 更高效；
- 如果 base 是 SIM/DIN（attention-based）→ 本身有非线性调制，DNN 收益较小，可改为加 stacked GLU 替代纯 DNN。

(2) CTR 模型监控加上 RankMe / 奇异值熵指标。 这是论文最直接可落地的产物——在 metrics dashboard 加一行表征健康度，发现 RankMe 异常下降时立刻报警。线上观察过的真实故障：增量训练几天后 RankMe 跌了 30%，对应 AUC 跌了 0.3pp，但 AUC 微小变化容易被忽略，RankMe 早一天就能预警。

(3) 调参策略变化：DNN 宽度 > DNN 深度。 论文 RankMe 实验暗示，1 层宽 DNN 可能比 4 层窄 DNN 更能撑开维度——这与「越深越好」的经验做法相反，值得在自家 CTR 模型上 A/B 验证。

(4) 冷启动场景的特殊价值。 新用户 / 新物品 embedding 由于 sample 少更容易坍缩，加 DNN 缓解的 ROI 在冷启动尤其大；本文给冷启动模型设计提供了「先评估 RankMe」的诊断流程。

(5) 社区搜索的迁移： 短文本搜索相关性模型（query × doc cross-encoder）也存在 query embedding 维度坍缩——可以借鉴本文方法把 RankMe 作为相关性模型的内部监控；同时在 DSSM-类 dual encoder 中加 parallel DNN 分支，补足正交梯度方向，预期对长尾 query 的相关性有结构性提升。
