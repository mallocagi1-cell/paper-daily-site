1. MDL: A Unified Multi-Distribution Learner in Large-scale Industrial Recommendation through Tokenization
4.75
Relevance 5 | Novelty 4 | Practical 5 | Evidence 4 | Timely 3

Summary: 针对工业推荐系统中多场景多任务学习的两大瓶颈——大规模参数未能充分与复杂特征模块交互、场景和任务信息难以在统一框架中联合建模——提出了 MDL 框架。核心思路借鉴 LLM 的 prompting 范式，将场景和任务信息转化为专用 token 而非辅助输入或门控信号。框架包含统一信息 token 化模块，以及特征 token 自注意力、领域-特征注意力和领域融合聚合三种机制。在抖音搜索平台上线 A/B 测试取得显著提升，现服务数亿日活用户。

Key insight: MDL 的核心创新在于将多场景多任务学习从「门控路由」范式转向「token 化 prompting」范式——场景和任务不再是辅助信号，而是与特征等价的一等 token，从而让大规模参数真正参与到不同场景/任务的建模中。对于社区搜索等多场景系统（如搜索 vs 推荐 vs 广告），这种统一 tokenization 方案可以用一个模型覆盖多个业务线，避免为每个场景独立维护排序模型，显著降低工程复杂度。

MDL: A Unified Multi-Distribution Learner — 深度阅读分析

1. 问题与动机

工业级推荐系统通常需要同时服务多个场景（Multi-Scenario Learning, MSL）和多个优化目标（Multi-Task Learning, MTL）。现有方法面临两个根本性挑战：

挑战一：规模利用不足 — 现有 MSL/MTL 方法（如 STAR、MMoE、PEPNet）将场景/任务的分布信号作为辅助输入，仅作用于模型浅层或中间层。在 0.1B+ 参数的大型工业模型中，深层参数无法受益于分布差异信息，无法充分利用 Scaling Law。

挑战二：统一建模困难 — 输入侧（场景差异）和输出侧（任务差异）的分布信号性质不同，传统 shared-specific 架构难以在统一框架中联合建模。

Douyin Search 需同时处理单列/双列/内嵌搜索三个场景和点击/点赞/收藏三个任务，形成 3×3 的分布组合。

2. 方法概述

MDL 的核心思想借鉴 LLM 的 prompt 范式：将场景信息和任务信息从「辅助输入」转变为「专用 token」，使其能与特征 token 在注意力机制中进行全层次交互。

整体架构分三步：

  1. 统一信息 Tokenization：将用户/物品/交叉/序列特征统一投影为特征 token；场景/任务 ID 通过 FFN 生成专用 token
  2. 域感知全 token 交互：特征自注意力 + 任务-特征交叉注意力 + 场景-特征交叉注意力
  3. 域融合聚合：实例级别场景 token 选择与均值池化，将场景信息注入任务 token

3. 核心技术贡献

贡献一：统一信息 Tokenization — 场景和任务不再是「条件控制信号」，而是与特征平等参与注意力计算的序列成员，能影响模型每一层。

贡献二：特征自注意力 — 特征 token 通过 Token Mixing 操作跨组融合，提升特征表达丰富度。

贡献三：域感知注意力 — 任务/场景 token 分别通过交叉注意力自适应地从特征 token 中提取信息。注意力可视化证实不同任务/场景 token 呈现截然不同的特征聚合模式。

贡献四：域融合聚合 — 通过实例级别的场景 token 选择与均值池化，确保场景上下文对最终任务预测的调制作用。

4. 实验结果分析

离线评估（QAUC）

与最强基线 RankMixer 相比，MDL 在所有 9 个场景×任务组合上均取得提升：

  • 单列点击 +0.31%，点赞 +0.23%，收藏 +0.42%
  • 双列点击 +0.27%，点赞 +0.63%，收藏 +0.77%
  • 内嵌搜索点击 +0.25%，点赞 +0.34%，收藏 +0.71%

稀疏场景提升更大（双列 > 单列），低频任务提升更大（收藏 > 点赞 > 点击），有效缓解多任务「跷跷板效应」。

消融实验

场景 token 的贡献（-0.17%）大于任务 token（-0.12%），说明场景分布差异对搜索推荐系统的影响更为根本。

线上 A/B 测试（1 个月，数亿用户）

  • LT30（30日用户留存）+0.0626%
  • 换词率 -0.3267%（用户修改查询频率降低，直接反映搜索满意度提升）

5. 局限与未来方向

  • 仅在 3 场景 × 3 任务上验证，场景数大幅增加时的 token 竞争问题未探讨
  • 未讨论新场景/新任务上线时的 token 初始化策略
  • 计算开销分析不透明，未报告与基线的推理延迟对比
  • 未涉及覆盖率、多样性、公平性等多维度评估

6. 工业实践意义

  • 架构启示：把「控制信号」升级为「序列成员」是大模型时代 MS-MTL 的关键进化方向
  • 重点关注：稀疏场景和低频任务是提升空间最大的地方（收藏 +0.77%）
  • 指标设计：换词率是搜索推荐中被低估的核心指标，应纳入多目标优化
  • 正则化：全局场景 token 能捕获跨场景共性知识，是防止场景过拟合的有效手段
  • 工程落地：MDL 已在数亿用户规模下成功落地，tokenization 的推理开销在可接受范围内

2. The Confidence Gate Theorem: When Should Ranked Decision Systems Abstain?
4.26
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 研究排序决策系统（推荐系统、广告竞价、医疗分诊队列）应在何时对排序输出进行干预、何时选择放弃干预（abstain）的问题。提出 Confidence Gate 定理，给出基于置信度的放弃机制单调改善决策质量的充要条件：rank-alignment（排序对齐）和 no inversion zones（无反转区）。区分了结构性不确定性（缺失数据，如冷启动）和上下文不确定性（缺失上下文，如时序漂移）。在 MovieLens 协同过滤、广告竞价和医疗分诊三个领域验证。

Key insight: 该定理揭示了排序系统「何时不该出手」理论边界，对推荐和搜索系统的实践启示是：在冷启动用户（结构性不确定性高）上强行出排序结果可能适得其反，此时放弃干预（fallback 到热门/探索策略）反而更优。对于社区搜索场景，可以用该框架识别哪些 query-user 组合下排序模型的置信度不足，对这些请求切换到备选策略，从而提高整体 CTR 和用户体验。

The Confidence Gate Theorem — 深度解读

1. 问题与动机

在推荐系统、广告竞价、临床分诊等排序决策系统中，基于置信度的弃权（abstain）是常见策略。核心问题：置信度分数在什么条件下，能保证随阈值提升而单调改善决策质量？盲目使用置信门控可能产生反效果——在时序漂移场景下 RMSE 反而恶化。

2. 方法概述

理论推导 + 多域实验验证：(1) 形式化选择性准确率问题；(2) 证明 Confidence Gate Theorem 的充要条件（C2: 无反转区间）和充分条件（C1: 秩-精度对齐）；(3) 区分结构性不确定性（冷启动）和情境性不确定性（时序漂移）；(4) 在协同过滤、电商意图识别和临床分诊三域验证。

3. 核心技术贡献

贡献一：Confidence Gate Theorem

SA(t) 关于阈值 t 单调非递减当且仅当 C2（无反转区间）成立。C1（秩-精度对齐）是更强的充分条件。C1 蕴含 C2，但 C2 不蕴含 C1。

贡献二：结构性 vs 情境性不确定性

  • 结构性不确定性（数据稀疏/冷启动）：计数型置信信号可靠，C1/C2 可靠成立
  • 情境性不确定性（时序漂移）：历史数据训练的置信信号无法捕捉分布偏移，C2 违反

贡献三：异常标签不稳定性

基于残差定义的异常集在时序偏移下不具有不变性。异常检测器 AUC 下降约 0.09-0.10，否定了「用残差训练异常检测器再弃权」的朴素方案。

贡献四：自适应重校准的负向结果

自适应重校准在时序漂移下不仅未改善，反而恶化（RMSE 1.027→1.042，违反次数 11→14）。根因：漂移破坏的是不确定性排序本身，而非仅仅是校准。

4. 实验结果分析

MovieLens 100K

  • 冷用户切分（结构性）：RMSE 1.057→1.015，单调改善，零违反
  • 时序切分（情境性）：RMSE 非单调（1.027→1.021→1.028→1.035），3次违反
  • 集成弃权（5个随机种子）：仅1次违反，RMSE 最优改善（1.024→1.001）

电商意图识别

  • RetailRocket：HIGH层 4.4% 购买率 / LOW层 0.0%，4.89× 提升，C1/C2 满足
  • Criteo：初步出现反转，替换为学习型逻辑回归后解决

MIMIC-IV 临床分诊

  • 5个置信区间准确率严格单调：23.1%→35.9%→64.8%→86.1%→93.9%
  • 40% 弃权时准确率从 34.8% 提升至 64.3%，零违反
  • Spearman ρ = 0.349（p < 10⁻²⁸⁰）

5. 局限与未来方向

  • 理论假设固定置信函数，未涉及在线学习场景
  • 纯离线实验，无线上 A/B 验证
  • 情境性失败证据主要来自单一场景（MovieLens 时序切分）
  • 与保形预测（Conformal Prediction）的关系未厘清
  • 阈值选择缺乏系统性方法

6. 工业实践意义

  • 弃权策略须先诊断：上线前在留出集验证 C2 是否成立（各置信区间桶准确率是否单调递增），成本极低但能避免翻车
  • 冷启动用计数信号，时序漂移用集成信号：冷用户/物品用交互次数等计数信号（零违反）；时序漂移改用集成方差（违反 3→1，RMSE 1.024→1.001）
  • 异常检测标签在分布偏移下不可信：需定期重训并监控 AUC
  • 自适应重校准不是银弹：换用对分布更鲁棒的置信信号（集成方差、近期行为特征）才是正解
  • 置信层级分离是可解释性工具：HIGH/MED/LOW 三级分层既做决策又做监控

3. TaoSR1: The Thinking Model for E-commerce Relevance Search
4.35
Relevance 4 | Novelty 4 | Practical 5 | Evidence 4 | Timely 3

Summary: 针对电商搜索中 query-商品相关性预测任务，提出直接部署 LLM 的框架 TaoSR1，解决三个关键挑战：Chain-of-Thought (CoT) 推理中的错误累积、判别式幻觉（discriminative hallucination）和部署可行性。框架分三阶段：(1) 监督微调建立推理基础；(2) 基于强化学习的 CoT 错误纠正机制；(3) 工程优化实现在线部署。该模型已在淘宝搜索系统上线，解决了 BERT 类模型擅长语义匹配但缺乏复杂推理能力的问题。

Key insight: TaoSR1 验证了 LLM「思考式」排序在工业电商搜索中的可行性路径：SFT→RL 纠偏→在线部署三步法。核心经验是 CoT 推理并非开箱即用，直接 fine-tune 会产生判别式幻觉（模型编造理由来合理化错误判断），需要 RL 阶段专门纠正这一问题。对于社区搜索中复杂 query（如长尾问题、含歧义的 UGC 搜索词），这种思考式相关性模型可能比传统 BERT 排序提供更好的语义理解。

TaoSR1: The Thinking Model for E-commerce Relevance Search — 深度解读

1. 问题与动机

电商搜索中的查询-商品相关性预测是核心任务。当前 BERT 类判别式模型能满足 80-90% 的搜索需求，但在长尾复杂查询上存在短板：否定查询（如「非棉质衬衫」）、替代品查询（如「Miumiu 平替」）、问答类查询、知识依赖查询。BERT 的双向注意力存在低秩问题，限制了参数规模扩展的收益。LLM 虽具备更强语义理解和推理能力，但直接部署面临延迟、错误传播和判别性幻觉三大挑战。

2. 方法概述

TaoSR1 是三阶段训练 + 部署优化的完整框架：

  1. Stage 1 — SFT with CoT：基于 RAG 合成思维链数据进行监督微调，采用 respond-then-think 格式
  2. Stage 2 — Pass@N DPO：多次采样构建偏好对，引入 DeepSeek-R1 作为 Oracle 指导硬样本
  3. Stage 3 — GRPO：在线采样强化学习，通过均衡标签分布解决判别性幻觉
  4. CumPT 部署模块：累积概率分层，单参数稳定转换为 Good/Mid/Bad 三档

3. 核心技术贡献

3.1 Respond-Then-Think：逆直觉的 CoT 格式

在判别任务中采用「先给出标签、再展开推理」格式，部署时只需提取标签 token 概率，推理过程可被截断，大幅降低延迟。SFT 阶段 Macro F1 从 57.63 提升到 60.01。

3.2 RAG-Augmented CoT 数据合成

设计五步 RAG 流水线（查询理解→商品理解→类目匹配→属性匹配→相关性判断），将业务规则分解为原子化组件并动态检索注入，解决 LLM 对领域业务规则的盲区。

3.3 Pass@N + Oracle 双轨 DPO

Pass@1 准确率 67.38% vs Pass@5 81.73%，多次采样揭示模型潜力。对可解样本用正确回答做 chosen，对硬样本引入 DeepSeek-R1 作为 Oracle。

3.4 标签分布均衡的 GRPO + CumPT

GRPO 中标签 CV 与性能呈强负相关，强制均衡分布后幻觉错误率降 30%。CumPT 将传统 4+ 阈值压缩为单参数，Macro F1 在 67.05-67.17 间稳定（传统方法 56.83-65.26 大幅波动）。

4. 实验结果分析

离线评测（~70,000 条人工标注）

  • BERT 基线: Macro F1 61.33
  • TaoSR1 (CoT + DPO + GRPO): Macro F1 67.12, Accuracy 76.86
  • 比 BERT 提升 5.79 pt Macro F1
  • 最难的 Class-3 (Related) F1 从 32.91 提升到 39.40

在线 A/B 测试（GSB 并排人工评估）

  • 替代品查询: GSB +34.43%, Query Goodrate +13.11pt
  • 问答类查询: GSB +16.62%, Query Goodrate +6.53pt
  • 知识依赖查询: GSB +18.45%
  • 否定类查询: GSB +10.92%

用户行为指标

  • UV +0.22%, 商品页面浏览量 +2.43%, 交易笔数 +0.82%, GMV -0.29%（置信区间内持平）

5. 局限与未来方向

  • respond-then-think 格式并未真正提升推理能力，改进主要来自更好地遵循业务规则
  • 完整 CoT 在线推理延迟无法承受，截断后无法利用深度推理
  • DPO 中依赖 DeepSeek-R1 作为 Oracle，且只覆盖约 50% 硬案例
  • 未来方向：Implicit CoT / Adaptive CoT（根据查询难度自适应展开 CoT）

6. 工业实践意义

  • 生成式判别范式可行性：提取第一个 token 概率作为相关性分数，无缝替换判别式模型
  • Pass@N 是诊断上界的廉价手段：先做 Pass@N 分析再决定标注策略
  • Oracle-Guided DPO 突破自我改进上限：引入外部更强模型为硬案例提供指导
  • 标签分布均衡对 RL 至关重要：强制均衡分布（即使总量减少）显著优于原始分布
  • CumPT 降低运维成本：单参数且不敏感，每次模型迭代无需重新校准阈值
  • GMV 中性是关键安全信号：提升体验不损害商业收益，为类似系统提供风险基准

4. Evoking User Memory: Personalizing LLM via Recollection-Familiarity Adaptive Retrieval
4.00
Relevance 4 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 针对个性化 LLM 中记忆检索的两大问题——将所有历史记忆塞入 prompt 成本高且不可扩展、单次相似度检索只能捕捉表面匹配——提出基于认知科学双过程理论的自适应检索框架。借鉴人类记忆的双过程机制：Familiarity（快速但粗略的识别）和 Recollection（深层链式重建），实现对用户历史偏好和上下文的精确召回。系统能根据 query 复杂度自适应选择快速检索或深度重建路径。

Key insight: 该工作的核心启示是：用户记忆检索不应是简单的 top-k 相似度匹配，而应区分「我认识这个」（快速模式匹配）和「让我想想之前的经历」（深层链式推理）两种模式。对于社区搜索的个性化排序，可以借鉴这种双通道设计：对频繁交互的 topic 使用轻量级匹配（familiarity），对长尾或新兴话题使用深度用户偏好推理（recollection），在个性化质量和推理成本间取得平衡。

Evoking User Memory (RF-Mem) — 深度解读

录用: ICLR 2026 | 作者: 大连理工大学、香港城市大学、华为

1. 问题与动机

个性化 LLM 需要从用户历史记忆中检索相关信息，但现有方法存在两个极端：(1) Full Context 将所有历史塞入 Prompt，128K 语料需 115,601 tokens，1M 时直接 OOC；(2) 单步 Dense Retrieval 只能捕捉表面语义匹配。借鉴认知科学双过程理论——Familiarity（快速粗粒度识别）和 Recollection（慢速精细链式重建），提出自适应检索框架。

2. 方法概述

提出 RF-Mem（Recollection-Familiarity Memory Retrieval），基于熟悉度不确定性引导的双路径检索：

  1. 探针检索计算熟悉度信号（均值分数+熵）
  2. 路由决策：高熟悉度→Familiarity 快速路径；低熟悉度→Recollection 迭代扩展路径
  3. Familiarity 路径：直接 Top-K，延迟 3-5ms
  4. Recollection 路径：迭代 retrieve-cluster-mix，通过 alpha-mix 将查询与聚类质心融合，纯 embedding 空间内实现链式推理

3. 核心技术贡献

熟悉度不确定性路由

温控 softmax 归一化后计算熵，三段式路由：均值分数高→Familiarity；低→Recollection；中间区域用熵消歧（低熵=置信高→Familiarity，高熵=不确定→Recollection）。

Recollection 迭代聚类扩展

每轮检索 N_r 条候选→KMeans 聚为 B 个簇→alpha-mix 生成新查询→重复 R 轮→最终 Top-K。在纯 embedding 空间实现类链式推理，无需 LLM 干预。

模块化兼容性

与 MemoryBank、HyDE、Search-o1 叠加均带来一致提升，证明其作为通用在线检索层的价值。

4. 实验结果分析

PersonaMem (主实验)

  • 32K 规模：RF-Mem 0.6350 vs Full Context 0.6129（+2.2%），仅用 3,567 tokens（Full Context 的 14.5%），延迟 5.09ms
  • 128K 规模：RF-Mem 0.5394 vs Dense Retrieval 0.5259（+1.35%）
  • 1M 规模：Full Context 完全 OOC，RF-Mem 0.4589 仍有效

PersonaBench (个性化检索)

  • Recall@5：RF-Mem 0.4788 vs Familiarity 0.4515（+2.7%），延迟 9.16ms vs Recollection 17.29ms

LongMemEval (长期记忆)

  • LME-S Recall@5：RF-Mem 0.8186 vs Familiarity 0.7924（+2.6%），延迟比 Always-Recollection 低 6.31ms

集成实验

  • 与 MemoryBank：RF-Mem 0.5314 vs Familiarity 0.4941（+3.7%）
  • 与 Search-o1：RF-Mem 0.6146 vs Familiarity 0.5823（+3.2%）

5. 局限与未来方向

  • 仅评估对话式文本记忆，未覆盖跨模态
  • 不确定性度量基于 list entropy，对语义歧义刻画有限
  • 静态 embedding 索引，无时序更新或会话间冲突建模
  • 隐私风险：提升历史可检索性可能无意重浮敏感信息
  • 未来：多模态扩展、更丰富不确定性估计、时序动态建模

6. 工业实践意义

  • 成本控制：以不足 4,000 tokens 的固定预算实现 Full Context 级别效果，显著降低推理成本
  • 低延迟：4-10ms 检索延迟满足实时搜索/推荐要求，比 Always-Recollection 快 30-50%
  • 即插即用：纯检索层工作，不需修改 LLM 或索引逻辑，工程接入成本极低
  • 差异化服务：自动区分简单查询（快路径）和复杂查询（慢路径），计算资源精细调度
  • 长期偏好建模：Recollection 路径通过迭代扩展聚合时间分散的行为信号，适合用户长期行为建模

Summary: 揭示了 Mixture-of-Experts (MoE) 模型在推理阶段的「双重惩罚」现象：第一，专家路由导致 microbatch 碎片化，降低权重复用率；第二，大量驻留的专家参数池挤占 HBM 空间，压缩 KV cache 容量。将这一现象形式化为 reuse fragmentation，并提出 $qs$ 不等式作为预测准则，判断何时 MoE 在推理阶段结构性地劣于 dense 模型，特别是在长上下文场景下。

Summary: 针对 LLM 生成式查询扩展往往过于聚焦单一语义、忽略多义和多面性的问题，提出 ThinkQE 框架。核心是两个组件：(1) thinking-based 扩展过程，通过深层思考鼓励更全面的语义探索；(2) corpus-interaction 策略，迭代地利用检索反馈来优化扩展方向，避免语义漂移。无需额外训练即可提升检索性能，具有良好的跨领域泛化能力。

9. What Do We Care About in Bandits with Noncompliance? BRACE: Bandits with Recommendations, Arms, Compliance, and Exploration

Summary: 研究推荐系统中的一个根本问题：当用户不完全遵循系统推荐时（noncompliance），系统应该优化什么目标？形式化了推荐福利（recommendation welfare）vs 治疗学习（treatment learning）两种目标可能冲突的问题。证明当用户完全遵循推荐时两个目标一致，但在存在不服从行为时，推荐福利可能严格超越所有基于治疗效果的策略。

10. Decoupling Reasoning and Confidence: Resurrecting Calibration in Reinforcement Learning from Verifiable Rewards
3.25
Relevance 2 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 揭示了 RLVR（基于可验证奖励的强化学习）在提升 LLM 推理能力的同时会严重破坏模型校准——模型对错误答案变得过度自信。理论分析表明推理目标和校准目标之间存在根本性梯度冲突。提出解耦方案：将推理能力和置信度估计分离优化，在推理 token 上优化 RL 奖励，在置信度 token 上独立优化校准损失，成功恢复校准性能而不损失推理准确率。
