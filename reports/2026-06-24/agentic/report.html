1. EvoEmbedding: Evolvable Representations for Long-Context Retrieval and Agentic Memory
4.30
Relevance 5 | Novelty 4 | Practical 4 | Evidence 4 | Timely 4

Summary: 针对现有 embedding 模型孤立编码每段文本、忽略上下文与时序的问题，提出 EvoEmbedding：在顺序处理输入时维护一个持续更新的 latent memory，将其与原文一起生成可演化（evolvable）的向量表示，使同一 query 能根据演化中的上下文检索到不同目标。作者构建 EvoTrain-180K 联合优化 latent memory 与检索，并用 memory queue 防止循环编码时的表征坍塌、用 segment-batching 把训练加速 3.8×。在多个长上下文检索 benchmark 上超过 Qwen3-Embedding-8B、KaLM-Embedding-Gemma3-12B 等更大模型，并能泛化到上下文比训练窗口长 10× 的下游任务（如个性化）；接入朴素 RAG 后效果超过专门的 agentic memory 系统。

Key insight: 把 embedding 从「静态孤立编码」改成「带状态的循环编码」，让向量随上下文演化，是对语义检索范式的实质修改。对社区搜索的启示：UGC 场景里同一 query 在不同会话/帖子流上下文中应召回不同内容，evolvable 表示天然契合这种「上下文相关召回」；用更小的模型 + latent memory 跑赢 8B/12B 专用 embedding，意味着可以在不堆参数的前提下提升长上下文短文本召回。memory queue 防坍塌、segment-batching 提速 3.8× 这两个工程细节对自研 embedding 训练有直接借鉴价值。

2. DailyReport: An Open-ended Benchmark for Evaluating Search Agents on Daily Search Tasks
3.90
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 3

Summary: 现有 search agent 评测多聚焦真实用户不会遇到的专门任务，且用粗粒度的 task 级 rubric 导致评测可解释性差。DailyReport 提出面向「日常搜索任务」的开放式 benchmark：150 个开放任务、3546 条关联 rubric，覆盖真实用户高频且有时效性的信息需求。每个任务拆成子任务，用级联（cascade）rubric 在解耦的维度上打分，再通过级联归因与用户中心聚合，得到每个维度的高可解释分数及一个用户偏好分。在 17 个 agentic 系统上的结果显示，当前系统仍达不到用户期待。数据与代码已开源。

Key insight: 把 search agent 评测从「最终答案对不对」改成「子任务 × 级联 rubric × 用户偏好聚合」，本质是给搜索 agent 建了一套可解释的过程评测。对社区搜索从业者：日常 UGC 搜索正是这种开放、时效、无标准答案的场景，DailyReport 的 rubric 拆解思路可直接迁移到自建搜索助手的离线评测，避免只看 nDCG/最终答案而漏掉中间检索质量。Meituan 出品、强调「真实用户日常需求」，与社区平台的搜索分布更接近，可作为选型与回归测试的参考基线。

3. PlanBench-XL: Evaluating Long-Horizon Planning of LLM Tool-Use Agents in Large-Scale Tool Ecosystems
3.80
Relevance 3 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 现有 agent benchmark 很少在「工具可见性受限」下评测规划能力。PlanBench-XL 构造了 327 个零售任务、1665 个工具的交互式 benchmark，要求 agent 迭代式检索可用工具、调用它们以获得中间证据再服务后续调用，直到完成最终目标；并加入可选的 blocking 机制（工具缺失、失败或干扰）模拟真实环境的不确定性，迫使 agent 在运行时识别被打断的路径并自适应。在 10 个主流 LLM 上的实验显示，海量工具规划仍很难：GPT-5.4 在无 blocking 时 51.90% 准确率，在最严重 blocking 下骤降到 11.36%。

Key insight: 把「从 1665 个工具里检索出正确工具」作为长程规划的前置环节，揭示了 tool retrieval 是 agent 落地的真实瓶颈——和搜索系统的召回问题同构。对从业者：当 agent 要在大规模工具/API 库中选择时，先做好工具检索（embedding/重排）比单纯增强规划更重要；blocking 机制下从 51.90% 跌到 11.36% 说明真实环境的工具失效是被严重低估的失败源，线上 agent 必须设计「检测路径中断 + 运行时重规划」的兜底。可作为评测自研 agent 工具调用鲁棒性的标尺。

4. Self-Compacting Language Model Agents
3.70
Relevance 3 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 长 agent 轨迹（思维链 + 工具调用）会累积过时内容，锚定后续生成并最终撑爆上下文窗口。现有 scaffold 用「固定 token 阈值触发」的定期 compaction，不顾轨迹结构，可能在推导或检索中途丢弃部分结果。论文提出 SelfCompact：让模型自己决定何时、如何 compact。它在推理时配两个元素——(i) 一个 compaction 工具供模型主动调用以总结已累积上下文；(ii) 一份轻量 rubric 规定触发时机（某子任务已解决、或轨迹达到自然断点）。由模型自身判断断点，避免在中间状态截断。

Key insight: 上下文压缩的触发权从「固定阈值」交还给模型本身，是长程 agent 工程的一个实用范式转变。对搜索 agent 的启示：多轮检索 agent 的上下文里塞满中间检索结果，按 token 数粗暴截断常把还没用上的召回证据丢掉；SelfCompact 用「子任务完成」作为压缩时机更安全。最大优势是纯推理时 scaffold、无需训练，可直接套在现有多轮 RAG/搜索 agent 上做工程验证，落地成本低。

5. Tmax: A simple recipe for terminal agents
3.50
Relevance 2 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 终端（terminal）agent 已成为 LLM 最热门的下游应用之一，但 RL 训练这类模型的学术工作很少，原因是 benchmark 难、数据缺、缺简单 baseline 配方。Tmax 给出目前最强的开源终端 agent RL 配方：用一套新的任务分类法生成数据，结合难度控制、persona 与 verifier 多样化。配方虽简单，但仅 9B 参数就在 Terminal-Bench 2.0 上达到 27%，超过此前工作中更大的模型，把开源数据配方推近前沿。

Key insight: 核心可借鉴点不是终端这个场景，而是它的「数据合成 + RL」配方：难度控制、persona 多样化、verifier 多样化三件套，对任何有可验证奖励的 agent 任务（包括搜索 agent 的多跳问答）都适用。9B 跑赢更大模型说明在 agent RL 里数据配方的质量比模型规模更关键——对算力有限的团队是利好信号。可作为自建 search-agent RL pipeline 的数据构造参考。

6. When Agents Commit Too Soon: Diagnosing Premature Commitment in LLM Agents
3.45
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 长程 LLM agent 会「悄悄失败」：早早锁定对证据的一种解读，然后把剩余步骤都用来为它辩护，作者称之为 premature commitment（过早承诺）。只看最终答案的评分发现不了这种失败，因为它看不到过程是否已坍塌到一条固定路径。论文把 representational commitment 定义为「在固定推理步上跨多次运行的 hidden-state 收敛」，用作轨迹一致性的早期诊断。在 Llama-3.1-70B 跑 ReAct/HotpotQA 上，第 4 步 hidden-state 相似度可预测下游行为一致性（r = -0.35，partial r = -0.45），且有局部化的时序与层级特征。

Key insight: 提出用「隐状态收敛」作为多轮检索 agent 是否「想死了」的早期信号，比看最终答案更早发现失败。对搜索 agent 实践：多跳检索里 agent 一旦在前几步锁死错误假设，后续召回都在自我印证，本文给出可量化的早停/重采样触发依据（如第 4 步隐状态过度收敛即重启探索）。HotpotQA 多跳 QA 设定与社区搜索的多轮信息聚合高度相关，可借鉴其诊断指标做线上 agent 的轨迹健康度监控。

7. Connect the Dots: Training LLMs for Long-Lifecycle Agents with Cross-Domain Generalization Via Reinforcement Learning
3.35
Relevance 3 | Novelty 4 | Practical 3 | Evidence 3 | Timely 4

Summary: 提出训练 LLM 具备「Connect the Dots（CoD）」这一长生命周期 agent 所需的元能力：agent 部署到某环境后，要在求解一长串任务的同时持续探索环境、从自身经验中学习、迭代地自更新对环境的上下文记忆，从而在后续任务上基于更新后的上下文取得递进式更好的表现。框架包含带细粒度信用分配（credit assignment）的强化学习算法、用于激发该能力的专门任务与环境，以及验证跨域泛化潜力的实证结果。实现已开源。

Key insight: 把 agent 的「持续学习 + 自更新上下文记忆」当作可被 RL 训练出来的元能力，而非靠外挂记忆库，是 long-lifecycle agent 的一条新路线。细粒度信用分配解决了长序列任务里「哪一步的探索带来后续收益」的归因难题。对搜索/推荐：常驻型搜索助手需要跨会话积累用户与领域知识，CoD 的跨域泛化结论提示这种记忆能力可迁移；阿里出品、代码开源，适合作为自研常驻 agent 记忆机制的实验起点。

8. Capable but Careless: Do Computer-Use Agents Follow Contextual Integrity?
3.15
Relevance 2 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: Computer-use agent（CUA）开始代表用户跨邮件、日历、待办等个人应用执行操作，这种跨应用访问带来一个被忽视的隐私风险：在一个上下文工作时把另一个上下文里不该出现的信息拉进来。论文提出 AgentCIBench，把该风险变成可执行、确定性打分的场景，针对三类常见失败：visual co-location（拉入 UI 上紧邻任务目标的违规项）、task-ambiguity overshare（任务模糊时倾倒大量个人信息），以及跨上下文泄露。用 contextual integrity（情境完整性）框架系统评测 CUA 的隐私合规性。

Key insight: 首次把「情境完整性」这一隐私理论变成 agent 的可执行评测，揭示能力强的 CUA 在跨应用时会无意识泄露信息。对搜索/推荐 agent：当 agent 能访问用户多源数据（历史、私信、画像）来增强检索时，同样存在「把 A 场景信息错误带入 B 场景」的越界风险；visual co-location 这类失败模式提醒在做 agent 上下文拼接/召回时要做信息边界隔离。可借鉴其确定性打分场景设计来做自家 agent 的隐私回归测试。

9. CLI-Universe: Towards Verifiable Task Synthesis Engine for Terminal Agents
3.15
Relevance 2 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 终端 agent 训练的核心瓶颈是缺高质量、可执行的训练数据。现有合成 pipeline 多靠把表层产物回填成任务，常产出含糊指令、浅执行路径和脆弱测试，学习信号弱。CLI-Universe 提出有原则的任务合成引擎：先在多维能力分类法（domain、skill type、capability、engineering pillar）上采样组合生成候选任务，再把每个候选 ground 到可执行环境并配可验证的测试，从而产出指令明确、执行路径深、测试稳健的高质量训练任务。

Key insight: 可借鉴的是「能力分类法采样 + 可执行 grounding + 可验证测试」这套任务合成方法论，而非终端这个具体场景。对要做 search-agent RL/SFT 的团队：高质量、带可验证奖励的训练数据是最大瓶颈，CLI-Universe 用「先按能力维度组合采样、再 ground 到可执行验证」的思路，可迁移到合成多跳搜索任务、工具调用任务。强调「深执行路径 + 稳健测试」对避免 reward hacking 有直接价值。

10. Training Open Models for Agentic Phone Use
3.15
Relevance 2 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 手机正成为通用 agent 的重要执行面，但训练开源模型可靠地操作手机很难：部署时真正重要的真机真 app 环境慢、有状态、有副作用、难重置与验证，而可扩展的 mock 环境只能近似真实行为。论文提出 PhoneBuddy：一套训练配方与开源模型，结合真 app 环境与 mock 环境 PhoneWorld（从真实 GUI 使用结构重建可运行的 mock app）。PhoneBuddy 先用两个环境收集的轨迹做共享 SFT 阶段，再在此基础上训练，兼顾真实性与可扩展性。

Key insight: 可借鉴点是「真实环境 + 从真实使用结构重建的 mock 环境」混合训练范式，用来解决 agent 训练里「真环境慢且不可重置、纯 mock 又失真」的两难。对做交互式搜索/推荐 agent 的团队：线上真实检索环境同样慢且有副作用，PhoneWorld 这种「从真实日志重建可运行 mock」的思路可迁移到搭建可大规模 RL 的搜索 agent 仿真环境。共享 SFT 再分化训练的两阶段设计也值得参考。
