1. ReasonRank: Empowering Passage Ranking with Strong Reasoning Ability
3.75
Relevance 4 | Novelty 4 | Practical 3 | Evidence 4 | Timely 3

Summary: 该论文聚焦 LLM 推理增强的列表式排序问题。现有 reranker 缺少推理密集型训练数据，在复杂排序场景表现不佳。作者提出自动化推理训练数据合成框架，利用 DeepSeek-R1 生成高质量标注；并设计两阶段训练策略（SFT 冷启动 + 强化学习），在 BEIR 等多个 benchmark 上显著提升 listwise ranking 性能。该方法将推理能力注入排序模型，推动 LLM-based ranking 从简单打分走向深度推理。

Key insight: 核心创新在于将大推理模型（LRM）的逐步推理能力迁移到通用排序场景：通过多领域推理训练数据合成框架解决数据稀缺问题，并用 RL 进一步强化排序推理。对搜索系统实践者而言，该工作表明在 reranking 阶段引入推理链可显著提升复杂 query 的排序质量，特别适合语义匹配困难的 UGC 短文本搜索场景。两阶段训练范式（SFT+RL）可直接借鉴到搜索排序模型的训练中。

2. SkillGraph: Graph Foundation Priors for LLM Agent Tool Sequence Recommendation
3.70
Relevance 3 | Novelty 4 | Practical 3 | Evidence 4 | Timely 5

Summary: 该论文解决 LLM Agent 从大规模 API 库中选择和排序工具的推荐问题。语义相似度无法捕捉工具间的数据依赖关系，导致排序失败（Kendall-τ 为负）。作者提出 SkillGraph，从 49,831 条成功执行轨迹中挖掘有向加权执行转移图作为图基础先验，并设计两阶段解耦框架：GS-Hybrid 混合检索 + 学习型 pairwise reranker。在 ToolBench 上 Set-F1=0.271，在 API-Bank 上 Kendall-τ 从 -0.433 提升至 +0.613。

Key insight: 核心贡献在于将推荐系统的图先验思想引入 LLM Agent 工具推荐：通过挖掘执行轨迹构建工具转移图，将语义检索与结构化排序解耦。这种「先检索候选、再基于图结构排序」的两阶段范式，与搜索推荐系统的召回-排序架构高度一致。对构建 LLM Agent 系统的团队具有直接参考价值，特别是在工具选择和 pipeline 编排场景中，图先验可大幅提升序列推荐的准确性。

3. LLaDA2.0-Uni: Unifying Multimodal Understanding and Generation with Diffusion Large Language Model
3.60
Relevance 2 | Novelty 5 | Practical 3 | Evidence 4 | Timely 5

Summary: LLaDA2.0-Uni 提出统一的离散扩散大语言模型（dLLM），原生支持多模态理解与生成。架构融合语义离散 tokenizer（SigLIP-VQ）、MoE-based dLLM backbone 和扩散解码器。通过块级 masked diffusion 统一处理文本和视觉 token，并结合 prefix-aware 优化和少步蒸馏提升推理效率。在多模态理解任务上匹配专用 VLM，同时在图像生成和编辑上表现出色，展示了扩散 LLM 作为统一生成-理解框架的可扩展性。

Key insight: 该工作验证了离散扩散模型作为统一生成范式的可行性：将理解和生成任务统一到同一 dLLM 框架中，消除了传统自回归 LLM 在生成任务上的局限。对生成式推荐研究者而言，dLLM 范式提供了一种替代自回归的生成方式——通过 masked diffusion 并行生成 token，可能在推荐序列生成中获得更好的延迟-质量权衡。MoE 架构的引入也为大规模推荐模型的稀疏化提供了参考路径。

6. Near-Future Policy Optimization
3.45
Relevance 2 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: RLVR（基于可验证奖励的强化学习）已成为 LLM 后训练的核心方法，但混合策略训练面临轨迹来源的两难：外部教师轨迹质量高但分布远，历史轨迹分布近但质量上限低。本文提出 Near-Future Policy Optimization（NPO），从模型自身「近未来」检查点获取辅助轨迹——同一训练过程中稍后的检查点天然满足「既强于当前策略、又比外部教师更近」的条件，最大化有效学习信号 S=Q/V。

Key insight: NPO 的核心洞察是：训练过程中稍后的自身检查点是最佳的 off-policy 轨迹来源。这一思路可直接应用于 LLM-based 推荐系统的 RLHF/RLVR 训练：不需要额外的教师模型，只需利用训练过程中的检查点作为辅助数据源。对搜索排序模型的在线学习和持续优化场景也有启发——自身近期版本既比当前版本更好（higher Q），又不会偏离太远（lower V），是天然的学习信号来源。

8. From Signal Degradation to Computation Collapse: Uncovering the Two Failure Modes of LLM Quantization
3.25
Relevance 2 | Novelty 4 | Practical 3 | Evidence 4 | Timely 5

Summary: 该论文系统分析了 LLM 量化的两种失败模式：Signal Degradation（计算模式完好但信息精度受累积误差影响）和 Computation Collapse（关键组件失效，阻止正确的信息处理，在早期层破坏信号）。4-bit 量化主要表现为 Signal Degradation，而 2-bit 触发 Computation Collapse 导致灾难性性能悬崖。作者设计了机制感知的干预方法，证明有针对性的 training-free 修复可缓解 Signal Degradation，但对 Computation Collapse 无效。

Key insight: 该工作对 LLM-based 推荐系统的部署具有重要实践意义：首次揭示了量化失效的两种本质不同的机制，为部署决策提供了理论依据。对于将 LLM 用于生成式推荐的团队，4-bit 量化是安全的（Signal Degradation 可修复），但 2-bit 量化需要特别警惕（Computation Collapse 不可修复）。这为推荐系统中大模型的成本-性能权衡提供了清晰的技术边界。

9. HaS: Accelerating RAG through Homology-Aware Speculative Retrieval
3.20
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 5

Summary: HaS 提出同源感知推测检索框架加速 RAG 系统。现有加速策略要么牺牲精度（近似检索），要么仅在严格相同 query 时复用结果。HaS 在受限范围内进行低延迟推测检索获取候选文档，然后验证候选文档是否包含所需知识。验证基于 query 间的同源关系，将其形式化为同源 query 重识别任务：一旦确认入射 query 是历史 query 的同源重现，即可绕过全库检索，直接使用缓存结果。

Key insight: HaS 的「同源 query 推测检索」思路对搜索推荐系统有直接价值：在高 QPS 场景下，大量 query 在语义上是已见 query 的变体，通过同源识别可大幅降低检索延迟。这与搜索系统中的 query 缓存策略思路一致，但 HaS 将其提升到语义层面——不要求 query 完全相同，只需语义同源即可复用。对 LLM-based 推荐的实时推理场景，这种推测执行策略可有效降低端到端延迟。

10. Avoiding Overthinking and Underthinking: Curriculum-Aware Budget Scheduling for LLMs
3.10
Relevance 2 | Novelty 3 | Practical 3 | Evidence 3 | Timely 5

Summary: 该论文解决 LLM 推理中 test-time compute 的效率问题。现有方法在固定或均匀采样的 token 预算下优化推理，忽略了问题难度与计算量的匹配。作者提出 Budget-Adaptive Curriculum Reasoning（BCAE），通过三个协同组件：1) 将 token 预算作为连续条件信号嵌入的统一策略；2) 根据问题难度自适应调整训练预算分布的课程调度器；3) 联合优化推理质量和 token 效率的训练目标。

Key insight: BCAE 的核心思想——根据任务难度自适应分配计算预算——与推荐系统的 scaling law 研究高度相关。在 LLM-based 推荐中，不同请求的复杂度差异巨大：简单的热门查询不需要深度推理，而复杂长尾 query 需要更多计算。BCAE 的课程调度策略可直接借鉴到推荐 LLM 的推理预算分配中，实现「简单请求快速响应、复杂请求深度推理」的差异化 serving 策略，优化整体计算成本。
