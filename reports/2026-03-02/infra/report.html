SideQuest: Model-Driven KV Cache Management for Long-Horizon Agentic Reasoning

让推理模型自主管理 KV Cache 压缩，通过并行辅助任务评估 token 相关性来减少内存占用。

INSIGHT与传统基于启发式的 KV Cache 压缩不同，SideQuest 让模型自身判断哪些 token 重要，仅需 215 个训练样本就能实现 65% 的 token 用量降低，这种自适应方案更适合复杂多轮场景。

业务关联社区搜索中使用 LLM 进行多轮 query 理解或文档摘要时，长上下文的 KV Cache 是部署瓶颈，SideQuest 的模型驱动压缩可显著降低内存需求和延迟。

证据在 agentic 工作流上实现约 65% 峰值 token 用量降低，准确率损失最小；仅需 215 个训练样本；优于传统启发式压缩方法。

Sanjay Kariyappa, G. Edward Suh

DualPath: Breaking the Storage Bandwidth Bottleneck in Agentic LLM Inference

通过双路径 RDMA 传输 KV-Cache，打破预填充-解码分离架构中的存储带宽瓶颈。

INSIGHT在 PD 分离架构中，prefill 引擎的存储网卡带宽饱和而 decode 引擎空闲，DualPath 利用 RDMA 让 KV-Cache 同时从两条路径加载，并做动态负载均衡——这种思路可推广到任何分离式部署场景。

业务关联社区搜索中若部署 LLM 用于实时排序或 query 理解，PD 分离架构是常见的生产方案，DualPath 直接解决其中最大的存储带宽瓶颈，可提升在线吞吐。

证据离线推理吞吐提升 1.87x，在线服务在不违反 SLO 的前提下吞吐提升 1.96x。

PrefillShare: A Shared Prefill Module for KV Reuse in Multi-LLM Disaggregated Serving

在多模型 agent 场景中，通过共享 prefill 阶段实现跨模型 KV 复用，大幅降低延迟和提升吞吐。

INSIGHT多 LLM agent 系统中各模型处理相同上下文会产生大量冗余计算，PrefillShare 将模型分解为 prefill 和 decode 组件，让多个模型共享 prefill 结果，这对搜索系统中的多模型 ensemble 有直接参考价值。

业务关联社区搜索中若同时部署多个模型（如召回模型 + 排序模型 + LLM 理解模型），PrefillShare 的共享 prefill 方案可减少重复计算，降低整体延迟和 GPU 开销。

证据多模型 agent 工作负载下 p95 延迟降低 4.5x，吞吐提升 3.9x，精度与全量微调持平。

FlowPrefill: Decoupling Preemption from Prefill Scheduling Granularity to Mitigate Head-of-Line Blocking in LLM Serving

将 LLM 推理的抢占粒度与调度频率解耦，通过算子级抢占消除队头阻塞问题。

INSIGHT传统 LLM serving 的 chunked-prefill 粒度和抢占粒度耦合，导致要么吞吐低要么延迟高；FlowPrefill 在算子级实现细粒度中断和事件驱动调度，无需 trade-off 两者。

业务关联社区搜索的在线 LLM 服务需同时保证低延迟和高吞吐，FlowPrefill 的调度优化可直接应用于 vLLM/SGLang 等推理引擎的生产部署。

证据与 SOTA 系统相比最大 goodput 提升 5.6x，同时满足多样化 SLO 要求。

Chia-chi Hsieh, Zan Zong, Xinyang Chen, Jianjiang Li, Jidong Zhai, Lijie Wen

SpecAttn: Co-Designing Sparse Attention with Self-Speculative Decoding

将稀疏注意力与自推测解码协同设计，利用验证阶段的副产品指导后续 token 的草稿生成。

INSIGHTSpecAttn 的核心创新在于利用 speculative decoding 验证阶段已有的 KV 条目重要性信息来指导下轮 draft 的稀疏注意力选择，将两个原本独立的优化技术协同起来，获得超线性加速。

业务关联对于社区搜索中的长文本理解（如长帖子摘要、多轮对话），SpecAttn 可在不增加硬件的前提下提升 LLM 推理吞吐 2.8x，直接降低 serving 成本。

证据吞吐比原生自回归解码提升 2.81x，比 SOTA 竞争方法提升 1.29x；同时提升了 draft token 接受率。

Yikang Yue, Yuqi Xue, Jian Huang

BiScale: Energy-Efficient Disaggregated LLM Serving via Phase-Aware Placement and DVFS

通过阶段感知的放置策略和动态频率调节（DVFS），实现 PD 分离式 LLM 推理的能效优化。

INSIGHTprefill 和 decode 阶段对 GPU 计算和内存带宽的需求差异极大，BiScale 利用预测性延迟和功耗模型，为每个阶段独立选择最优频率和放置策略，在满足 SLO 的同时大幅降低能耗。

业务关联对于大规模社区搜索平台，LLM 推理的电力成本是重要运营开销，BiScale 的节能方案可在不影响服务质量的前提下显著降低 GPU 集群电力消耗。

证据在 16 节点 H100 集群运行 Llama 3.3 70B 时，相比 DistServe 在 prefill 阶段节能 39%，decode 阶段节能 48%，同时严格满足延迟 SLO。

Omar Basit, Yunzhao Liu, Z. Jonny Kong, Y. Charlie Hu

Quantized Evolution Strategies: High-precision Fine-tuning of Quantized LLMs at Low-precision Cost

提出在量化参数空间中直接进行进化策略优化的方法，无需反向传播即可微调量化 LLM。

INSIGHTPTQ 后的模型通常无法再微调，QES 通过累计误差反馈和无状态种子重播，在量化空间中直接优化参数，打开了「先量化后适配」的新范式。

业务关联社区搜索部署量化 LLM 时常面临精度损失，QES 允许在量化状态下继续微调适配搜索场景，无需反量化-微调-再量化的复杂流程。

证据在算术推理任务上显著优于当前 SOTA 零阶微调方法；支持全程在量化参数空间内进行缩放。

Yinggan Xu, Risto Miikkulainen, Xin Qiu

09 3.25

POP: Prefill-Only Pruning for Efficient Large Model Inference

发现深层网络在 prefill 阶段冗余而在 decode 阶段必需，提出仅在 prefill 时剪枝深层以加速推理。

INSIGHTPOP 揭示了一个实用洞察：LLM 深层在处理上下文（prefill）时大量冗余，但在生成 token（decode）时不可或缺，因此可安全地仅在 prefill 阶段移除深层，获得免费加速。

业务关联社区搜索中 LLM 处理长 query 或文档的 prefill 是延迟主要来源，POP 可在不影响生成质量的前提下加速 prefill 阶段，降低首 token 延迟 (TTFT)。

证据在 Llama-3.1 和 Qwen3-VL 上 prefill 延迟加速 1.37x，性能损失最小；优于现有结构化剪枝方法。

Junhui He, Zhihui Fu, Jun Wang, Qingan Li

ISO-Bench: Can Coding Agents Optimize Real-World Inference Workloads?

从 vLLM 和 SGLang 中提取 54 个真实优化任务，构建评测编码 agent 推理优化能力的基准。

INSIGHTcoding agent 虽能准确定位性能瓶颈，但在实现可工作的优化补丁上仍有明显短板；且相同模型上不同 agent 设计的效果差异巨大——说明 agent 工程设计至少与模型能力同等重要。

业务关联对于搜索团队而言，ISO-Bench 提供了一种评估和选择 AI 编码工具辅助推理引擎优化的方法论，可帮助判断 agent 工具的实际价值。

证据基于 vLLM 和 SGLang 的 54 个真实优化任务；发现仅用执行指标（runtime）评估不够，需结合 LLM 评判；不同 agent 之间性能差异显著。

Ayush Nangia, Shikhar Mishra, Aman Gokrani, Paras Chopra
