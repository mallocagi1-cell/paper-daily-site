1. Layer-wise Token Compression for Efficient Document Reranking
4.70
Relevance 5 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: 针对 Transformer cross-encoder 重排序器推理成本高的问题，提出 Layer-wise Token Compression (LTC)，把自适应 token 池化放到中间层而非输入层。在 MS MARCO passage/document 排序上，中间层压缩在保持排序质量的同时把 QPS 最多提升 25%（passage）和 116%（document），并可直接扩展到 listwise LLM 重排，长上下文场景收益更大。

Key insight: 双塔检索常用的输入层 token 压缩对 cross-encoder 无效，把压缩挪到中间层是关键发现；更意外的是用短 passage 训练、压缩后的模型在长文档排序上反超未压缩版本，说明压缩起到了鼓励长度无关表征的正则作用。对线上重排降本与跨长度泛化都有借鉴价值。

独立页面阅读 ↗

1. 问题与动机

Transformer cross-encoder 重排序器是现代 IR 系统的核心组件，但要把 query 与 document 拼成长序列一起过 Transformer，推理成本高、QPS 受限。一个已知的提速思路是 token compression——在 embedding 层把相邻 token 聚合，减少有效 token 数。这一招在双塔（bi-encoder）检索器上被证明有效，但作者通过实验发现：直接搬到 cross-encoder 上会失效。证据很硬：沿用 Jasper 的 embedding 层压缩虽然带来 25% 的 QPS 提升，却让 nDCG@10 从基线 0.727 暴跌到 DL19 的 0.5832、DL20 从 0.665 跌到 0.4975，约 20% 的效果损失。

作者给出的根因假设是：cross-encoder 的相关性信号来自 query/document token 之间细粒度的交互，而这些交互从最早的 Transformer 层就开始发生；在 embedding 层就把 token 压掉，等于在交互发生之前抹掉了信号。双塔则是独立编码、只在向量层比相似度，所以对 token 压缩不敏感。这个观察直接引出本文的设计动机：压缩不能在交互之前做，而要等交互充分进行之后再做。

2. 方法详解

LTC（Layer-wise Token Compression）的核心是把 1D 自适应平均池化从 embedding 层挪到中间 Transformer 层。形式化为 H_compressed^(l) = C(H^(l), r)，输出 token 数 n' = ⌊n·r⌋，压缩比 r ∈ (0,1]。具体实现：在目标层 l∈{1,…,L} 之前的 1 到 l-1 层处理完整序列；从 l 层起，沿 token 维做自适应平均池化，把相邻 token 表征合并，同时更新 attention mask 与位置索引；l 到 L 层在压缩后的短序列上计算。池化用「相邻 token 平均」而非丢弃，尽量保留语义结构。

对 listwise reranker，作者额外引入 document mask M∈{0,1}^(n×k)，只允许文档内池化、禁止跨文档压缩，并保护 instruction prompt 与 query 不被压。

训练设置很关键：pointwise 用 Qwen3-0.6B-Base（28 层 decoder + 分类头），在 MS MARCO passage（约 880 万 passage、50 万训练 query，用 Tevatron 取 hard negative）上训练，损失为 1 正 + 5 hard negative 的交叉熵，3 epoch、batch 32、lr 1e-5、AdamW，且压缩在训练阶段就施加以让模型适应。listwise 用 Mistral-7B-Instruct-v0.3（取首生成 token 的 logits），RankZephyr/FIRST 数据（每 query 20 篇 GPT-4 排序文档），语言建模 + ListMLE 联合损失、LoRA rank 16。QPS 在单张 NVIDIA L40S 上测。

一个非常重要的非显然结论：压缩必须「compression-aware training」。把压缩只在推理时加到未经压缩训练的模型上会灾难性掉点——r=0.2、layer 2 时 nDCG@10 从 0.728 跌到 0.287（相对下降 60%），说明未经训练的中间层表征不具备对 token 缩减的鲁棒性。

3. 核心技术贡献

第一，定位并解释了「embedding 层压缩对 cross-encoder 失效」这一现象，给出 token 交互时机的机理解释，纠正了从双塔直接迁移的错误直觉。第二，提出中间层自适应池化 LTC，把压缩点作为可调超参 l* 与压缩比 r 的二维设计空间，实验找到 layer 8–14 的「甜区」：既保排序质量又显著提速。第三，把方法无缝扩展到 listwise LLM reranker，用 document mask 实现文档内压缩、保护 prompt/query，长上下文 listwise 收益更大（27–73% QPS）。第四，意外发现压缩在长文档泛化上起到正则作用——用短 passage 训练、压缩后的模型迁移到长文档排序时反超未压缩版本。

4. 实验结果分析

Pointwise passage（Qwen3-0.6B，TREC DL19/DL20）：基线 DL19 nDCG@10=0.727、QPS=5.35。最优 LTC（r=0.4、layer 8）DL19 nDCG@10=0.7274 与基线持平，QPS 5.35→6.69，提速 25%。消融揭示规律：早层压缩伤害大（layer 2、r=0.2 跌到 0.638，降 12.2%，p<0.001）；中层 8–14 中等压缩保质量且显著提速；后层 14–20 轻压缩（r=0.8）甚至略超基线（0.7314 vs 0.727，不显著），印证正则效应。

Pointwise document（512 token 截断）：r=0.4、layer 20 在 DL19 上 nDCG@10=0.663，反超基线 0.651——压缩鼓励长度无关表征。文档排序因序列更长，QPS 提升最高可达 116%。

BEIR 六数据集（NFCorpus、FiQA、ScIDocs、SciFact、TREC-COVID、ArguAna，BM25 top-100 重排）零样本：无压缩 avg nDCG@10=0.422；r=0.8/layer20 为 0.424（+9% QPS）；r=0.6/layer14 为 0.420（+18%）；r=0.4/layer8 为 0.416（+25%），最激进压缩也仅相对降 1.4%。Listwise（Mistral-7B）passage 在无显著掉点下获 27–73% QPS 提升，document 提速空间更大。

最值得警惕的反面结果是 zero-shot 压缩的崩盘（0.728→0.287），它把「必须压缩感知训练」这条工程红线划得很清楚。

5. 局限与未来方向

作者明确列出的局限：(1) 目标层 l* 与压缩比 r 目前靠人工 sweep，未来可用 NAS 自动选择以降低部署成本；(2) 基线对比偏窄，主要对 Jasper，缺与 MRL-Reranker、prompt compression、KV-cache 压缩、early-exit 等的系统比较；(3) 激进压缩依赖压缩感知微调，完全 training-free 的变体仍开放；(4) 正则化假设还需表征级分析（隐状态范数、attention 稀疏度随长度变化）与 runtime 拆解来确证。除作者所述，评测主要在 MS MARCO/BEIR 学术集，缺真实线上 A/B 与多语种、短文本 UGC 场景验证。

6. 工业实践意义

对搜索重排的直接启示：cross-encoder 想降本，不要在输入层砍 token，而应在中间层（经验上 8–14 层）做自适应池化，并务必在训练阶段就加入压缩。落地收益清晰——passage 重排 +25% QPS、长文档重排最高 +116% QPS，且质量基本无损；这对 query-document 序列偏长、重排算力吃紧的线上系统很有吸引力。压缩比 r 与压缩层 l* 构成「质量-时延」可调旋钮：要更激进提速就早压、要更稳就晚压且轻压。

值得借鉴的还有两点：其一，「压缩即正则」的现象提示，用短文本训练、压缩部署，可能换来对长文档/长 query 更好的泛化，适合 UGC 长短文混合的检索场景；其二，listwise LLM reranker 用 document mask 做文档内压缩、保护 instruction 与 query，是把 LLM 重排搬上线时控成本的实用模式。部署注意：必须重训（compression-aware），不能对存量模型推理期直接加压；层/比例需离线 sweep 选定，建议结合自身延迟预算与 nDCG 容忍度确定甜区。

2. DIVE: Embedding Compression via Self-Limiting Gradient Updates
4.15
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: LLM 高维 embedding 给向量检索带来存储与算力压力。已有压缩适配器（Matryoshka-Adaptor、Search-Adaptor、SMEC）在标注稀缺时严重过拟合，效果反低于冻结基线。DIVE 用自限制 hinge 三元组损失（满足 margin 后梯度归零，限制对预训练空间的扰动）加 head-wise NT-Xent 多视图对比损失，在 6 个 BEIR 数据集、所有压缩比上均超过三个基线适配器，实现仅 14M 参数且开源。

Key insight: 核心思路是“少改动”：自限制损失避免小数据上破坏预训练 embedding 分布，多视图对比损失补偿三元组信号稀疏。对需要给召回向量降维、又缺乏大量领域标注的搜索场景有直接价值——14M 适配器可挂在现成 embedding 上，无需重训基座。

3. Beyond Semantic Similarity: A Two-Phase Non-Parametric Retrieval Workflow for Corporate Credit Underwriting
3.90
Relevance 4 | Novelty 3 | Practical 4 | Evidence 3 | Timely 5

Summary: 标准 RAG 按语义相似度检索，常召回话题相关但对决策无用的段落（作者称为 similarity-utility gap）。提出两阶段非参数检索：第一阶段用词法加稠密多语检索构建高召回候选池；第二阶段用自适应检索控制器按 query 意图与文档结构过滤，再用 LLM-as-a-Judge 按“分析有用性”而非语义接近度排序。在 800 多名信贷分析师的生产部署中，文档审阅时间从数小时降到约 3 分钟。

Key insight: 把“相关”与“有用”拆成两个阶段、用 LLM-as-Judge 做 utility 重排，是对纯向量相似度排序的有益补充，尤其适合长文档、决策导向的检索。全程本地部署满足数据合规要求，对企业内搜索与 RAG 落地有参考意义。

4. Efficient Table QA via TableGrid Navigation and Progressive Inference Prompting
3.65
Relevance 3 | Novelty 3 | Practical 4 | Evidence 4 | Timely 5

Summary: 表格问答需要精确的单元格检索与多步结构化推理。提出免训练的两套结构化提示：TableGrid Navigation (TGN) 用三模块循环迭代遍历行列定位证据并修正答案；Progressive Inference Prompting (PIP) 强制按 query 先识别列再渐进选行。在 17 个 LLM、6 个基线上评测，TableBench 上 TGN 比最强基线高 3.8 分，FeTaQa 上 PIP 超过 ReAct 与 CoT 达到 SOTA。

7. SG-LegalCite: A Principle-Augmented Benchmark for Legal Citation Retrieval in Singapore Law
3.30
Relevance 3 | Novelty 3 | Practical 3 | Evidence 4 | Timely 5

Summary: 普通法系的法律引用不仅看事实相似，还取决于先例确立的“法律原则”，而现有 benchmark 多以案件事实或引用上下文为输入，原则常缺失或被上下文淹没，导致检索到事实相似但法理无关的先例。提出 principle-augmented 检索范式：用“案件事实加显式法律原则”作为 query 排序被引案例，并构建 SG-LegalCite（8523 份新加坡最高法院判决、100,890 对 case-principle），11 个基线验证显式原则提供强判别信号。

8. Stage-Audit: Auditable Source-Frontier Discovery for Cross-Wiki Tables
3.00

Summary: LLM 整理的表格可能“看似有出处”实则包含来自参数记忆、事后硬贴引用的无支撑行。Stage-Audit 针对 Seed2Frontier（从种子页发现互补维基页面以拼表）任务，用 curator-auditor 写权限分离、行级 source-citation 门控、以及覆盖 key/schema/角色/基数/范围的 12 项审计 taxonomy。在 51 实例、15 个领域的评测集上，source-frontier 精度从 0.356 提升到 0.505（相对 +42%），F1 从 0.334 到 0.451（+35%）。
