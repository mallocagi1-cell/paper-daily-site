Harrier-OSS-v1: Microsoft's Decoder-Only Multilingual Embedding Model Family

微软Bing团队开源Harrier系列embedding模型，采用decoder-only架构（与GPT-4、Llama同源），在多语言MTEB-v2基准上排名第一。提供三种规模（270M/0.6B/27B参数），旗舰27B模型得分74.3，超越Google Gemini Embedding 2。支持100+语言和32K上下文窗口，采用LLM-based re-ranker生成训练信号并进行知识蒸馏。MIT开源协议发布于HuggingFace。

SGLang v0.4+: RadixAttention and the Rise of RadixArk ($400M Startup)

SGLang推理框架的核心创新RadixAttention使用基数树数据结构实现自动细粒度KV缓存重用，当新请求包含相同系统提示或历史对话时直接复用已有计算结果。2026年1月项目孵化出商业公司RadixArk，由Accel领投，估值约4亿美元。在H100上吞吐达16,200 tok/s（比vLLM高29%），DeepSeek V3推理快3.1x。已在xAI、AMD、NVIDIA、LinkedIn、Cursor等超40万GPU上部署。

INSIGHTSGLang的RadixAttention为多轮对话和Agent场景提供了最优推理性能，这对搜索系统中越来越多的LLM-powered功能（如query理解、重排序、摘要生成）至关重要。其从学术项目到$400M商业化的路径也验证了推理框架赛道的商业价值。对于需要在搜索pipeline中频繁调用LLM的场景，SGLang的prefix caching能显著降低推理成本。

pgvectorscale: PostgreSQL Vector Search with StreamingDiskANN Outperforms Dedicated Vector DBs

pgvectorscale为PostgreSQL引入StreamingDiskANN索引（基于微软DiskANN研究）和Statistical Binary Quantization。在50M Cohere embedding（768维）基准测试中，以471 QPS对比Qdrant的41 QPS（99%召回率）实现11.4x性能优势。相比Pinecone s1索引，p95延迟降低28倍、吞吐提升16倍，自托管成本降低75%。支持基于标签的过滤向量搜索。

INSIGHTpgvectorscale让PostgreSQL成为向量检索的有力竞争者，对中小规模搜索系统而言意味着无需引入额外的专用向量数据库。StreamingDiskANN的磁盘索引方式特别适合数据量大但对延迟要求不极端的UGC搜索场景（如帖子/评论的语义检索）。75%的成本节省对团队预算控制意义重大。过滤向量搜索能力可直接用于按社区/话题等属性筛选的搜索需求。

Sentence Transformers v3: Multimodal Embedding and Reranker Training

Sentence Transformers v3发布，大幅降低多模态embedding和reranker模型的训练微调门槛。支持视觉+文本联合信息处理，开发者可用统一API创建自定义embedding和reranker模型。为RAG系统和搜索应用提供更灵活的模型训练pipeline，使得团队可以基于自有数据快速训练领域特定的检索模型。

INSIGHTSentence Transformers一直是搜索和推荐领域最广泛使用的embedding训练框架。v3的多模态支持意味着UGC搜索可以开始处理图文混合内容（如带图帖子）的语义检索。统一的训练API让团队可以用相同代码训练embedding和reranker，简化了从召回到精排的模型迭代流程。这对需要快速实验的搜索团队尤为实用。

LMCache: An Efficient KV Cache Layer for Enterprise-Scale LLM Inference

LMCache是首个开源KV缓存解决方案，可将vLLM和SGLang生成的KV缓存从GPU显存中提取并存储，实现跨引擎、跨查询的缓存共享。支持缓存卸载（prefix跨查询重用）和prefill-decode分离（跨引擎/GPU缓存传输）。在多轮问答和文档分析等工作负载上实现最高15倍吞吐提升。

INSIGHTLMCache解决了LLM serving中最关键的成本问题之一——KV缓存的高效管理。对于搜索系统中使用LLM进行query理解、文档摘要等场景，跨查询的prefix缓存重用可大幅降低推理成本（如系统提示的KV缓存只计算一次）。15x的吞吐提升意味着同样的GPU资源可以服务更多搜索请求。与vLLM和SGLang的原生集成降低了接入门槛。

llm-d: Kubernetes-Native Distributed LLM Inference Framework (CNCF Sandbox)

llm-d是Kubernetes原生的分布式LLM推理框架，2026年3月在KubeCon Europe被接纳为CNCF Sandbox项目。由IBM Research、Red Hat和Google Cloud联合捐赠，架构桥接KServe控制平面与vLLM推理引擎。核心特性包括prefill/decode分离、基于Gateway API Inference Extension的缓存感知路由、以及支持DeepSeek-R1等MoE模型的宽Expert并行。在B200 GPU上验证了~3.1k tok/s的decode性能和16x16拓扑下50k tok/s的输出吞吐。

INSIGHTllm-d的意义在于将LLM推理的最佳实践标准化为Kubernetes原生组件，获得NVIDIA、CoreWeave、AMD、HuggingFace等行业巨头背书。对使用K8s管理搜索/推荐serving的团队而言，这提供了一条标准化的LLM推理部署路径，无需自研调度和路由逻辑。prefill/decode分离架构可显著降低搜索系统中LLM请求的首token延迟(TTFT)。

ZeroQAT: End-to-End On-Device Quantization-Aware Training for LLMs at Inference Cost

ZeroQAT是首个支持低比特权重和激活值端侧量化的端到端QAT框架。采用零阶优化（仅前向传播的梯度估计）消除反向传播需求，相比LLM-QAT减少89-92%内存使用。可在单张8GB GPU上微调13B模型至2-4 bit，甚至可在OnePlus 12手机上微调6.7B模型。通过OpenReview同行评审。

INSIGHTZeroQAT的零阶优化方法为资源受限环境下的模型量化提供了突破性方案。虽然端侧量化训练与当前UGC搜索场景的直接关联不强，但其将量化训练内存需求降低89-92%的技术思路，对在有限GPU资源上优化搜索排序模型（如distilled reranker）具有参考价值。随着搜索系统逐步向边缘端扩展，这类技术将变得更加重要。

ExecuTorch 1.0: Meta's On-Device AI Inference Framework Reaches Production

ExecuTorch 1.0于2025年10月达到GA（正式发布）状态，是PyTorch官方端侧AI推理框架。支持12+硬件后端（Apple、Qualcomm、Arm、MediaTek、Vulkan），运行时仅50KB。已在Instagram、WhatsApp、Messenger、Facebook、Quest 3、Ray-Ban智能眼镜等Meta全系产品部署，服务数十亿用户。HuggingFace上80%以上热门Edge LLM开箱即用。

INSIGHTExecuTorch作为Meta大规模验证的端侧推理框架已成为行业标准。虽然UGC搜索主要是服务端场景，但随着搜索体验向端侧扩展（如离线搜索、隐私敏感的本地query理解），ExecuTorch提供了一条成熟的部署路径。其50KB极小运行时和12+硬件后端支持使得在各类终端设备上部署轻量级搜索模型成为可能。Meta的大规模生产验证确保了框架的可靠性。
