RecGPT-V3 Technical Report

RecGPT-V3 面向淘宝推荐中重复处理全量历史、文本标签到商品的信息损失和显式推理延迟三类瓶颈，引入持续演化的 Memory Hub、文本与语义 ID 混合推理及潜在意图 token。系统将用户建模计算降低 55.8%、输出 token 成本降低 200 倍；线上 A/B 中 CTR 提升 1.00%、GMV 提升 3.97%。

1. 问题与动机

RecGPT-V3 的出发点是阿里已经上线的 RecGPT-V1/V2 在规模化后暴露出的三个瓶颈，而不是实验室中的概念推荐。其一，无状态用户建模每次请求都重读完整行为历史；高活跃用户序列可达约 55K token，Global Planner 占意图分析计算的约 95%，且不能复用已经发现的复购周期、品牌偏好或季节变化。其二，V1/V2 先生成自然语言商品标签再召回物品，粗标签是损失信道，无法传递 ID 级协同证据。其三，显式思维链平均数千 token，在亿级用户和高 QPS 下不可承受。

论文把这三个问题分别映射到用户状态、意图表示和意图推理，目标是让 LLM 不仅能说出“用户想要什么”，还能以召回器可直接消费的形式表达这一意图，并且把每次显式重做的推理转为可累积的内存和紧凑潜在 token。这是从“LLM 作为一个临时插件”转向“LLM 作为工业推荐的有状态推理中枢”。

2. 方法详解

Memory Hub 先把全量行为压缩成一组结构化 memory unit。每个 unit 以数百种电商行为原型中的 pattern ID 和自然语言 preference summary 为核心，附带代表性行为索引、品牌、时间活跃轨迹和时间戳。初始压缩只做一次；之后每两个月用新行为 delta 做一次增量 curation。已有 unit 只在出现相关新证据时重写，没有证据则保留；未匹配行为如果形成一致新模式，就建立新 unit。同一次前向同时完成更新与新模式抽取。这个设计将原始序列 token 压缩 94.5%，同时保留指向原行为的 provenance，推理时只读取 memory 和近期 delta。

Hybrid-modal Foundation Model 以 Qwen3-14B 为底座，将自然语言和商品 Semantic ID（SID）编入统一词表。首先，用 CN-CLIP 编码商品文本、图像和转成文本的侧信息，再用 Q-Former 融合。正样本来自行为日志中高频共现且多模态相似的商品，batch 内其他商品为负样本，InfoNCE 同时约束融合表示、文本表示和图像表示，以避免后续量化 codebook collapse。然后用两层 RQ-VAE 量化，每层 codebook 为 32,768，向 LLM 词表新增共 65,536 个 token；一个商品由两个 code 表示，第一个给粗语义簇，第二个做簇内细分。

新 SID embedding 随机初始化，训练分两段。持续预训练将 SID 与标题、类目等文本对齐，同时混入约 10% 数学、代码、科学、医疗和指令数据防止灾难性遗忘。指令微调覆盖 SID↔文本双向翻译、纯 SID 序列推荐和通用任务；其中约 20% 为开放域指令，以保持 JSON 格式与多约束遵循。纯 SID 任务把用户点击按 3 天、2 天、1 天、12 小时、1 小时多粒度窗口组织，直接预测下一次点击 SID。

Latent Intent Reasoning 把约 2,700–2,840 个显式 CoT token 内化到 10 个专用 <cot> token。训练先使用 DeepSeek-V3.2 的显式推理轨迹 SFT，再通过单段、多段和全链重建任务把语义压入潜在 token，最后根据排序反馈做 RL。潜在 token 在默认服务中避免长解码，但需要审计时可通过重建 prompt 解码回可读理由。论文未披露预训练总 token 数、optimizer、batch size、训练步数和训练硬件，这些无法从正文复现。

下游召回同时接收 tag 和 SID，分别 embedding 后拼接投影，用 Target-Attention 给候选商品打分。训练排序为“已点击且相关 > 未点击但相关 > 未点击且不相关”，总损失是点击 softmax utility loss 与多级对比 relevance loss 的加权和，生产中权重为 1 和 0.5。

3. 核心技术贡献

  1. 可累积、可追溯的用户内存替代每次重算。 Memory Hub 不是普通摘要缓存；它以行为索引保留来源，以选择更新/保留/新建维持语义连续性。相对 V2，Planner 总成本降低 55.8%，使用户理解成为跨会话资产。
  2. 用语义 ID 打通意图推理与物品召回。 自然语言负责开放世界知识和广覆盖，SID 负责带协同信号的细粒度落地。它不是二选一：混合召回 HR@500 达 0.1571，高于单用 tag 的 0.1503 和单用 SID 的 0.1539。
  3. 把长推理压缩为可选解释的潜在步骤。 10 个 latent token 保持了与显式 CoT 接近的推荐质量，又可按需重建理由；进一步 RL 后 HR@30 从显式 CoT 的 0.3508 提高到 0.3693。这为“常态低延迟，审计时可解释”提供了可行分层。

4. 实验结果分析

线上实验在淘宝首页“猜你喜欢”进行，实验组与 RecGPT-V2 对照组各占平台总流量 1%，分开评估纯商品宫格和混合内容 feed。

商品场景的 GMV 与 TC 增幅远大于 CTR，说明提升不只是诱导点击，更可能是召回的商品更贴近购买意图。Feed 中还有 +0.56% DAU，表明作用不局限于少数高活跃人群。不过论文没有披露实验持续天数、置信区间和分群效果，对长期因果仍应保持谨慎。

Memory Hub 的人工审核包含 2,514 个 behavior pattern 标注和 21,268 个行为索引标注，准确率分别为 82.89% 和 95.27%。这一差距很关键：证据指针非常准，但对证据的高层模式概括仍有约 17% 误差。成本上，每次推理为 V2 的 33.43%，周期内存更新为 10.77%，合计 44.20%，即 Planner 节省 55.80%。

通用数据混合是最明显的消融之一。保留通用数据时，GSM8K 仅从 94.31% 降到 92.65%；完全移除后，GSM8K、MMLU、CMMLU、IFEval 分别崩到 4.70%、0.12%、0.01%、23.29%。同时，混入通用数据把类目 HR@30 从 0.2250 提升到 0.3050（论文报告相对提升 26.2%），说明通用能力不是与推荐无关的附加项，而会反哺语义意图理解。

后训练结果也有清晰分层：Qwen3-14B 原生推理只把 HR@30 从 0.2276 提到 0.2347；领域混合模型加显式 CoT 则从 0.3050 到 0.3508。把约 2,700 token 压成 10 个潜在 token 时，HR@30 为 0.3462、CTR 为 0.0649，质量基本保留；再加 RL 达到 0.3693 和 0.0679。在同硬件 1,000 样本测试中，平均输出从 2,840 token 降到 122，总时间从 1,020 秒降到 295 秒，端到端加速 3.46 倍。单个 expert 因 SID 与更长输入增加 15% 开销，但 Planner 成本约是 expert 的 20 倍，因此系统加权总资源仍节省 52.4%。

5. 局限与未来方向

论文没有独立局限性章节。作者在正文明确显示的约束包括：SID 和 latent reasoning 使单 expert 计算增加 15%，只因 Planner 在当前架构中大约贵 20 倍才得到系统净节省；Memory Hub 的 behavior-pattern 正确率为 82.89%，并非无损用户理解；量化和词表扩展若不混入通用数据会导致严重灾难性遗忘。论文还只在淘宝电商和自有生产链路上验证，数据、代码、训练规模和硬件不公开，外部团队难以完整复现。

作者未充分讨论的限制有三个。第一，两个月一次的 curation 对快速变化兴趣可能太慢，近期 delta 能否完全补偿未被报告。第二，潜在理由虽可重建，重建文本与真正影响输出的内部计算是否忠实对齐尚不确定。第三，线上只给了总体相对增幅，没有新用户、长尾商品、不同消费群体的分层结果，也没有长期生态指标。未来应研究自适应 curation 频率、SID 在新品和跨域中的稳定性，以及 latent explanation 的忠实性审计。

6. 工业实践意义

这篇论文最重要的工程启示是先找到系统中最贵的重复计算，再决定是否值得增加更复杂的表示。RecGPT-V3 的 expert 局部成本实际上上升 15%，但它通过消除 Planner 的重复全历史编码得到 52.4% 全局节省。因此不应孤立比较某个模块 FLOPs，而要按 QPS、调用频率和缓存周期计算加权端到端成本。

对搜索/推荐团队，可分三步借鉴。第一步先建立可追溯的结构化用户内存，保存兴趣摘要、时间轨迹和原始行为指针，将全量重算改为增量更新。第二步用现有商品/内容 embedding 构造两层语义 ID，但必须保留自然语言通道：论文数据表明 tag 类目广度 1.40、跨用户重叠 11.36%，SID 分别为 0.84 和 4.61%，前者管探索覆盖，后者管个人精度。第三步再将长推理蒸馏为短潜在 token，并保留按需重建通路用于质检。

在 UGC 社区中，SID 不必是商品 ID，可以是帖子、话题、作者和内容簇的层级代码。对比学习正对可由共点击、共收藏与语义相似双重过滤得到，避免纯共现把热度当语义。运维上应同时监控内存模式准确率、行为指针准确率、SID codebook 利用率与崩塌、通用 benchmark 遗忘、潜在 token 输出长度、混合召回增益和端到端 GPU 资源。最关键的避免项是：不要只为追求协同精度而去掉自然语言和通用训练数据，论文已经用近乎归零的 MMLU/CMMLU 消融结果证明了这种做法的风险。

RECAP: Feedback-Driven Streaming Semantic User Profiles for Short-Video Recommendation

KuaishouUSTC📖 有深读 · 9 分钟

RECAP 把短视频用户画像从开放环摘要改为由历史推荐反馈驱动的离线闭环优化：结构化有界记忆负责流式更新，LLM 过滤标签一致行为对，双塔评估器的匹配分作为 GRPO 奖励。快手数据上 uAUC 提升 0.0084、Recall@2000 提升约 4.9%，7 天线上实验的人均使用时长提升 0.139%。

INSIGHT语义画像不应只追求描述流畅，而应直接对后续排序收益负责；有界记忆还能把无限行为流压缩成稳定、可审计的用户状态。社区搜索可用点击、停留、收藏构造画像—内容反馈对，以排序器分数训练画像更新策略，同时用确定性容量和生命周期规则控制漂移与成本。

1. 问题与动机

RECAP 研究的不是“如何用 LLM 写一段更好的用户摘要”，而是更具体的工业问题：在短视频行为持续到达、用户兴趣不断漂移、画像容量有上限的情况下，如何让一个结构化画像在多轮更新后仍然可靠，并直接为后续推荐服务。过去的语义画像方法大多是开环的：它们能流畅地概括历史，却没有被直接优化为“更能匹配未来喜欢的内容”。LangPTune、LettinGo 开始使用下游信号优化文本画像，LIBER、HiT-LBM 改善长历史切分与兴趣提取，但它们没有把原始隐式反馈、流式状态更新和有界内存政策闭成一个环。

论文指出两个实质障碍。第一，LLM 擅长语义抽象，却不擅长在反复更新中维护 span、recency、strength 等数值状态，容易出现跨 chunk 状态跳转错误。第二，直接拿工业排序分数当奖励会混入 ID、热度、上下文和曝光机制；观看与跳过也不等于纯语义喜好。RECAP 因而把问题定义为“有界结构化语义状态的离线闭环优化”，而不是一次性摘要。

2. 方法详解

数据预处理中，每条短视频先由 Qwen3-VL-8B 生成结构化 caption，包含从 25 个闭集类别中选取的 tag 和自由文本描述。有效观看被定义为播放超过 7 秒或完播；每个用户最多保留最新 500 条有效观看，再按时间切成每块最多 50 条的 chunk。第 t 轮更新可写成 P_t=f(C_t,P_{t-1})：模型只看当前 chunk 和上一轮画像，不再重读全历史。

第一个组件是 Structured User Memory。画像是最多 L 个 slot 的集合，每个 slot 包含 topic、description 和不暴露给 LLM 的生命周期字段。LLM 每轮只输出最小 JSON diff：confirmed_interests 用来确认或细化旧兴趣，new_interests 用来提出新兴趣，两者都必须带支持视频索引。新 slot 至少要有 2 条视频支持才能进入内存。确定性状态机执行 Update、Add、Remove，负责衰减、稳定/近期标记、容量淘汰与重复控制。这一分工的核心是“LLM 管语义，规则管状态不变式”。

第二个组件是 Recommendation-Aligned Reward。用户画像文本和视频 caption 分别进入双塔；排序头用 BCE 预测有效观看，对比头用正例和分布式 batch 内负例学习语义间隔，总损失为 L_eval = w_bce L_bce + w_nce L_nce。为降低隐式标签噪声，Qwen3-30B-A3B-Instruct-2507 先对正负视频做随机次序的成对判断，先找高置信负例，再重估正例一致性，仅保留一致性分超过 0.45 的样本。

第三个组件是 GRPO。对每个 chunk 采样 K=8 个语义 diff，通过同一状态机得到候选画像。奖励等于画像—视频匹配奖励，减去非法 JSON、错误引用、过长描述等格式罚项，再减去支持视频高重叠的多样性罚项。组内奖励标准化后使用 clipped surrogate 和相对冻结参考策略的 KL 约束更新。基座是 Qwen3-4B-Instruct-2507；SFT 使用 8K 条 Claude Sonnet 4.5 生成示范；GRPO 训练 80 步，batch size 64，学习率 2.5e-5，LoRA rank 32，KL 系数 0.01。双塔使用 Qwen3-Embedding-0.6B，w_bce=1, w_nce=0.1。论文没有披露优化器和具体硬件型号。

3. 核心技术贡献

  1. 把用户画像重新定义为可执行的有界内存。 它不要求 LLM 重写全文，而是只生成语义 diff，再由状态机保证生命周期和容量正确。这直接针对长历史方法在多轮继承时的漂移与数值状态错误。
  2. 从工业隐式日志中构造画像专用语义反馈。 与直接复用生产排序分数不同，RECAP 用 LLM 成对裁判清洗标签，再训练仅依赖画像文本和内容语义的双塔，因此奖励更接近“画像是否解释了用户为什么看”。
  3. 将 SFT 和清洗反馈 GRPO 分工。 论文的诊断表明，SFT 主要改善历史覆盖与兴趣间去重，GRPO 则改变更新动作和抽象层级。原始反馈会让模型少修改旧兴趣、多产生无支持新兴趣；清洗奖励则促使其生成更有根据、更偏动机层的描述。

完整模型对 Base 的 clean uAUC 提升 0.0084，Recall@2000 从 0.0122 提到 0.0128，相对提升约 4.9%。值得注意的是，GRPO-raw 在 clean Recall 上反而从 0.0122 降到 0.0119，说明“有更多日志”不等于“有更好的奖励”。清洗反馈与 SFT 结合才同时获得最好 uAUC 和 Recall。

消融还给出三个重要结论。BCE 与 cosine-margin 联合奖励最好，因为前者管标签判别，后者管语义拉开；只用粗粒度评估指标的 chunk 奖励不稳定。画像容量越大性能越好却成本越高，L=8 是论文在训练、编码和服务预算下的折中。让 LLM 直接生成全量生命周期字段时，离线分数未必明显变差，但跨 chunk 的 span 错误频繁，证明工程可靠性不能只用排序指标衡量。

线上实验在快手海外短视频服务运行 7 天，实验组分配 10% 流量，对照组 20%。RECAP 画像经 Qwen3-Embedding-0.6B 编码后作为生产 U2I 召回的新特征，使人均 App 使用时长相对提升 0.139%，统计显著。提升幅度不大，但它是在不替换主排序器、仅增加语义画像特征的情况下获得，工业信号很强。

5. 局限与未来方向

作者没有设置独立 limitations 章节，因此不能把泛化局限当成论文自述。文中明确的边界包括：视频 caption 是由 Qwen3-VL-8B 离线生成并被当作已知输入，并未联合优化视觉理解；主要实验来自快手内部短视频数据，数据不公开；奖励依赖 LLM judge 和双塔代理模型，仍可能继承裁判器的偏差；画像容量与性能存在明确成本折中。作者也只报告 7 天线上实验和人均使用时长，未报告长期留存、内容多样性或创作者侧影响。

作者未充分讨论的风险是反馈回路：若画像参与召回后又用新日志强化自身，小的早期误判可能被稳定 slot 固化。未来应增加探索流量、反事实校正和画像置信度，并测试跨地区、跨内容品类迁移。

6. 工业实践意义

对推荐与社区搜索团队，最可操作的起点不是立即训练 GRPO，而是先建立可追溯的 slot 画像和确定性状态机。每个兴趣必须保留支持行为，新兴趣设最小证据数，对长期与近期兴趣分层，这些设计本身就能降低幻觉和无限增长。第二阶段再用现有点击、停留、收藏和跳过日志构造成对样本，但必须先做标签一致性清洗，否则策略很容易学会“不改”或产生会被规则删除的空更新。

部署时，RECAP 的路径很清晰：caption、LLM 画像更新和 judge 都放在离线；线上只读取最新有界画像，用小型 embedding 模型编码为 U2I 特征。这使它适合以旁路特征方式小流量接入，回滚只需移除该特征。需要额外监控的不只是 uAUC 和时长，还包括 slot 覆盖率、重复分配率、无支持兴趣数、更新率、画像 token 长度和兴趣漂移速度。对 UGC 搜索，可把视频 caption 替换为帖子标题、正文、话题与评论摘要，将画像 embedding 同时供给个性化召回和精排，但保留非个性化通路作为探索与安全垫底。
