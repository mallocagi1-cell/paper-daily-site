DeltaServe: Host-Agnostic Co-Serving of Inference and Fine-Tuning for LLMs

DeltaServe 把峰值负载下闲置的推理 GPU 转为 LoRA 微调资源，并通过 CUDA Graph 感知的延迟模型与 SLO-aware 调度器，只在推理有余量时接纳训练。接入 vLLM、SGLang 和 S-LoRA 后，生产 trace 上微调吞吐比 LLMStation 高 2.9 倍，推理 SLO 达到 100%（对照为 85%），比 vLLM+torchtune 高 39%。

GRAFT: Adaptive DLM-Based Draft Tree Construction with Target-Distilled Edge Scoring

GRAFT 面向扩散语言模型草稿器的树式推测解码，提出 TDES 目标模型蒸馏边打分，显式学习父子 token 兼容性；SABA 则按每轮状态在草稿收益与验证成本间动态分配树预算。多模型、多任务实验相对自回归解码取得 2.13–6.36 倍端到端加速，每轮额外开销低于 0.5 ms，约为验证延迟的 1.4%。

INSIGHT推测解码的关键不只是提高 draft 概率，而是让草稿树的父子关系与 target 分布一致，并随解码状态调整预算。对搜索重排或 RAG 生成服务，可把 TDES/SABA 迁移到多分支候选验证；上线时重点监控接受 token 数、验证 GPU 时间和尾延迟，而不是只报平均加速比。

Xuming Ye, Zeming Ma, Runjie Yu, Yuan Liu, Tianle Li, Shuhan Bai, Jian Zhou, Fei Wu

03 4.10

Self-Speculation for Faster Reasoning Models

SSR 是无需训练的自推测解码方法，把较小推理预算下的部分 CoT 分布当作 drafter，把完整 CoT 分布当作 verifier，并用 suffix decoding 回收非连续但高重合的答案片段。论文在结构化和长文本任务上测试 Qwen3.5、Gemma-4 等开源模型，报告总生成延迟最高降低 24.1%，说明推理轨迹结构也能成为服务优化信号。

INSIGHTSSR 提供了不训练 draft model 的低侵入优化路径，适合已有推理服务但无法追加训练资源的场景。对社区搜索的多步查询改写、摘要或答案生成，可按 partial/full CoT 的语义重合度决定是否启用 suffix cache；必须按短 query、长上下文和工具调用分别压测，避免把理论重合误认为稳定收益。

Ravisri Valluri, Tung Nguyen, Aditya Grover

Nemotron 3 Ultra: Open, Efficient Mixture

NVIDIA

Nemotron 3 Ultra 是 550B 总参数、55B 激活参数的混合 Mamba-Transformer MoE，采用 LatentMoE、MTP 和 NVFP4 预训练，并开放 Base、Post-Trained 与量化 checkpoint。8K 输入、64K 输出设置下，其推理吞吐分别达到 GLM-5.1、Kimi-K2.6、Qwen-3.5 的 5.9 倍、4.8 倍和 1.6 倍，同时支持最长 1M token 上下文。

INSIGHTNemotron 的价值在于把稀疏激活、MTP、NVFP4 和推理预算控制组合成完整部署配方，而不是单一模型结构替换。若用于社区搜索，可用小激活参数模型承载高并发 query 理解与重排，再将 1M 上下文能力限制在少量长文任务；部署前需用自己的中文短文本和 GPU 栈复核 throughput，而非直接照搬 NVIDIA 对比。

NVIDIA BlueField-4 Powers New Scale-In Network Infrastructure for Agentic AI Factories

NVIDIA

BlueField-4 以 DPU、DOCA 和 Spectrum-X 组成 Scale-In 基础设施，把安全策略、存储访问、租户隔离和遥测从主机 CPU 卸载到独立处理域。其网络接口最高 800 Gb/s，相比 BlueField-3 内存带宽提升 4 倍、网络带宽提升 2 倍；在 50 GB 文件传输测试中，协同存储路径最高达到通用以太网的 1.45 倍吞吐。

INSIGHT当检索集群的瓶颈从 GPU 算力转向数据、存储和安全路径时，DPU 卸载能减少主机 CPU 与租户工作负载的耦合。对社区 UGC 搜索，适合优先评估向量索引读写、对象存储和多租户隔离的网络开销；不要只看 1.45 倍文件吞吐，还要验证索引更新延迟、故障域和可观测性成本。

Ronil Prasad, Itay Ozery

Giga-Scale AI and the Ethernet Evolution: How Spectrum-X Ethernet Rewrites the Rules

NVIDIA

NVIDIA 将 Spectrum-X Ethernet 设计为面向大规模 AI collective 的多平面网络，组合交换机自适应路由、目标式拥塞控制和 SuperNIC 平面负载均衡。文章给出的架构规模为 512,000 张 Rubin GPU、每 GPU 1.6 Tb/s scale-out 带宽和 100 Tb/s 交换机；故障切换示例为 2.68 ms，相比传统以太网的 1.08 s。

INSIGHT大规模训练和推理网络应把 collective 的低熵流量当作专门工作负载，使用自适应路由与硬件拥塞控制降低热点和尾延迟。即使社区平台规模远小于 512,000 GPU，也可以借鉴多平面、快速故障切换和 NIC 侧负载均衡的分层设计，并用 NCCL/向量检索混合流量进行压测。

Scaling AI with 8 to 20x energy efficiency

Microsoft

Microsoft 的同行评审研究估计，大规模部署下典型 LLM 查询耗电为 0.16–0.60 Wh，中位数 0.31 Wh，比以往非生产估计低 4–20 倍。服务 10 亿次日查询的基线约 0.7 GWh，采用模型路由、服务编排和硬件优化后约 0.3 GWh；模型、服务与硬件改进的近期开合收益估计为 8–20 倍。

INSIGHT基础设施优化不能只看单请求 tokens/s，还要把模型路由、批处理、prefill/decode 分离、硬件功耗和请求长度分布放进单位 query 成本模型。社区搜索可先用小模型处理大多数短 query，把长文生成、复杂 RAG 与重排任务单独计费和限流；10% 长推理请求可能使总能耗翻倍，必须纳入容量规划。

Melanie Nakagawa, Juan Lavista Ferres

NVIDIA Vera Rubin and Blackwell Set a New Standard for Agentic AI Performance per Watt

NVIDIA

NVIDIA 用 AgentX 重放生产式 coding-agent 会话，评估长上下文 prefill、KV cache 复用、交互式 decode、工具调用间隙和 MoE 并发，而不是只看峰值 tokens/s。其披露的预览结果显示，在 160 tokens/s/用户的 DeepSeek V4-Pro 工作负载上，Vera Rubin NVL72 的每兆瓦吞吐最高为 GB300 NVL72 的 30 倍；该结果仍待 SemiAnalysis 审核。

INSIGHTAgentX 的设计提醒我们，真实服务基准应包含 KV cache 命中、长 prompt、工具调用空洞、动态并发和每瓦吞吐，而不是单轮短输入 benchmark。社区搜索可建立自己的 trace replay，将 nDCG/CTR、TTFT、端到端完成时间与 GPU 功耗绑定；NVIDIA 的 30 倍结果仍是厂商披露，需独立复测后再做硬件采购决策。

TriPLU: Bypassing the Gate with Direct Trilinear Product FFNs in Tiny Language Models

TriPLU 用三个投影流逐坐标相乘的三次乘积 FFN，替代 Tiny decoder-only 模型中的门控 FFN。TinyStories 1M-byte 字符级实验中，最佳验证损失为 1.0637，优于匹配的 SwiGLU 1.1017、四次乘积 1.0780 和二次乘积 1.1026；但作者明确指出尚未证明 FLOP 归一化效率或大模型扩展性。

INSIGHTTriPLU 适合被当作小模型结构探索，而不是直接替换生产 Transformer。其 1.0637 对 1.1017 的收益来自低计算量、低学习率的特定设置，且作者报告高学习率和最终 BPB 会退化；工程上可先在 query encoder 或轻量 reranker 做小规模消融，并同时测 FLOP、内存、P95 延迟和长尾泛化。

When Do LLMs Replace Fine-Tuned NLU? A Decision Framework for Intent Detection in Production Conversational Systems

论文比较微调 RoBERTa、TF-IDF、句向量 kNN 与 Claude Haiku 在生产意图识别中的边界，给出按标签规模、越界检测、噪声和动态 schema 选择模型的决策框架。ATIS 上 RoBERTa 以 95.9 对 84.1 击败零样本 LLM；CLINC150 上为 89.1 对 88.5，但 OOS 召回为 85.6 对 58.1，提示部署应把效果、延迟和成本一起评估。

INSIGHT论文的启示是模型路由应由意图空间和线上约束共同决定：标签稳定、数据充足时小模型更快更便宜；schema 高频变化、越界或噪声场景才值得调用 LLM。社区搜索可以把 query 理解拆成 OOS、噪声、动态类目三类 gate，并把 95.9/84.1 这类离线差异与真实 nDCG、CTR、P95 延迟一起做决策。

Carson Rodrigues, Oysturn Vas
