SORT: A Systematically Optimized Ranking Transformer for Industrial-scale Recommenders

SORT 将工业推荐排序重构为请求中心的 Transformer：把用户历史、画像和候选集合拼成一条序列，用局部注意力、query pruning、QKNorm、门控注意力和稀疏 MoE 处理高稀疏特征，再以生成式预训练缓解标签稀疏。在 0.6B 训练请求、9B 曝光的数据上，AliExpress 线上订单提升 7.47%、买家提升 6.67%、GMV 提升 8.65%，延迟下降 61%，吞吐提升 589%。

Chunqi Wang, Bingchao Wu, Taotian Pang, Jiahao Wang, Jie Yang, Jia Liu, Hao Zhang, Hai Zhu... · 2026-08-24 · arXiv

1. 问题与动机

SORT 的出发点不是“把一个语言模型缩小后用于推荐”，而是反过来问：为什么在 LLM 上表现出规模化优势的 Transformer，到了工业推荐排序场景却很难直接发挥作用。论文把差异归结为两个结构性问题。第一，推荐系统要处理用户、商品、店铺和上下文等大规模离散特征，商品词表可以达到十亿级，稀疏 embedding 表非常容易过拟合；第二，推荐标签密度很低，用户历史主要是输入而不是逐 token 的监督，真正有标签的通常只有候选商品的点击、加购或购买，而且非点击样本占绝大多数。也就是说，模型需要用极大的参数空间去拟合稀疏的二值反馈，长历史反而会带来计算浪费和噪声。

论文还指出，传统 DIN、DeepFM、DCN 等模型擅长手工特征交互，但主要依赖向量级操作和低维矩阵乘法，不能充分利用现代加速器的并行算力，也难以统一处理动态行为序列、用户画像和候选集合。HSTU 等生成式推荐模型已经证明“把排序看成序列预测”有扩展潜力，但工业排序仍然存在请求内候选重复计算、长历史注意力平方复杂度、稀疏 ID 训练不稳定等问题。SORT 因而选择在 Transformer 框架上系统重做样本组织、注意力、稀疏 embedding、预训练目标和训练基础设施，而不是只添加一个新模块。

这项工作的重要性在于它有完整的生产闭环：训练数据来自工业推荐日志，模型同时预测点击、加购和购买三类行为，实验既报告离线 AUC 和消融，也报告 AliExpress 多场景线上 A/B。论文最后说明 SORT 已经全量服务 AliExpress 用户，因此它关注的并非单一公开数据集上的百分点，而是模型容量、吞吐、时延和业务收益能否同时成立。

2. 方法详解

2.1 请求中心的数据组织

传统 impression-centric 样本会把同一个请求的用户历史和画像复制 N 次，分别与 N 个候选 item 组成样本。SORT 将一个请求 r 表示为 S=〈H,U,C〉：H 是按时间排列的用户行为序列，U 是静态用户属性与统计特征，C 是同一请求内的候选集合。每个候选还携带商品元数据、统计特征和 user-item 交叉特征。这样，用户侧上下文只编码一次，候选 token 共享同一个请求上下文，避免候选数量增长时重复处理用户历史。

2.2 Token、注意力与候选隔离

模型为用户历史中的每个行为 item 和候选 item 生成一个 token；用户画像映射为多个 token。原始离散特征先做 embedding lookup，拼接后经过线性投影和归一化映射到 Transformer 维度。输入序列为 [BOS; Tokenize(H); SEP; Tokenize(U); SEP; Tokenize(C)]。BOS 和两个 SEP 不只是分隔符，也作为位置边界和 attention sink，帮助模型识别历史、画像、候选三类区域。

候选 token 使用相同的位置 ID，并通过对角 mask 保证每个候选只看自己和之前的历史、画像 token，不直接看其他候选，避免候选间相互泄漏。注意力中加入 RoPE、QKNorm 和 attention gate：QKNorm 对 query/key 做 RMSNorm，降低注意力 logits 的波动；gate 在 scaled dot-product 后重新控制信息流。对长用户历史，绝大多数历史 token 使用局部注意力，窗口为 W 时复杂度从 O(L²) 降到 O(WL)。此外，query pruning 在每层删除远离候选的 query，到顶层最多保留 128 个非候选 token，既明显降算力，也形成了“越靠近候选越精细”的时间衰减归纳偏置。

2.3 多目标排序头、稀疏 MoE 与预训练

候选 token 经过一个带 ReLU 隐层的 FFN 和 sigmoid 输出层，分别预测 click、cart、purchase 三个概率，训练损失是三个二元交叉熵的加权和。FFN 使用 DeepSeek-style sparse MoE，每个 token 只激活少量专家，最终实验在总专家数的 1/8 激活比例上效果最好。相比 Switch-style MoE，DeepSeek-style 路由不需要额外调 auxiliary load-balancing loss，训练更容易稳定。

为缓解 item ID 的高稀疏性，SORT 不使用显式 user ID，而是用用户行为序列和画像描述用户；item embedding 则采用生成式预训练。先用 next-item 目标提升标签密度，再把预训练 sparse embedding 迁移到排序模型并冻结。论文对“只迁移”和“迁移+冻结”做了对比：只迁移会轻微退化，而冻结后可以多轮训练且不过拟合，说明稀疏表更适合作为稳定的语义/记忆底座，而不是和排序目标一起快速漂移。

2.4 训练和推理基础设施

系统构建在 RecIS 上，MoE 使用 Megablocks。稀疏模块的瓶颈是 I/O 和内存访问，作者设计 MPGC，在多个 process group 间调度 embedding 流量来隐藏通信延迟；密集模块的瓶颈是复杂 sparse mask 下的计算，作者实现 block-wise sparse attention operator，预加载 mask，跳过完全被 mask 的 block，并结合 BF16、梯度累积和算子融合。训练采用 AdamW，β=(0.9,0.99)，weight decay=0.01，小/基座/大模型学习率分别为 5e-4、2e-4、1e-4，batch size=12K，默认训练一 epoch、最长历史 1K，ranking head 和 MoE router 保持 FP32，其余使用 BF16。不同规模模型使用 4–32 张 A100，训练 1–10 天。

3. 核心技术贡献

第一，SORT 把推荐样本从“一个候选一个样本”变为请求中心的候选集合，避免重复编码用户侧信息。这一改变使 Transformer 的注意力真正面向一次请求的排序决策，而不是面对一堆相互独立的 impression。

第二，作者将局部注意力、候选隔离和 query pruning 组合起来解决长历史成本。局部窗口限制远端历史的全连接访问，候选 mask 确保每个候选独立打分，逐层剪枝将计算集中到和候选更相关的历史。实验中，基座序列长度 1K 时 local attention 将 FLOPs 从 43G 降到约 40G；更长序列时收益更明显，且剪枝有时比不剪枝更好，说明它不是单纯的近似，而是对行为时间衰减的结构化先验。

第三，生成式预训练和 sparse freeze 解决了低标签密度与稀疏 embedding 过拟合的组合问题。对基座 Transformer，CTR AUC 从 0.7175 提升到 0.7456，CVR AUC 从 0.8959 提升到 0.9093，AddCart AUC 从 0.8455 提升到 0.8663。这个结果说明“用 next-item 监督补充排序标签，再冻结稀疏表”比直接把预训练 embedding 放进排序训练更有效。

第四，模型结构与系统内核同步优化。MoE 增加容量但只执行少量专家，MPGC 和 sparse attention 让硬件真正吃到密集部分的算力；基座 MFU 从未优化时的 13% 提升到 22%，大模型达到 45%，推理相对未优化版本吞吐提升 29.4%、延迟下降 29.3%。

在 base scale 的对比中，标准 Transformer 的 CTR/CVR/AddCart AUC 是 0.7456/0.9093/0.8663；HSTU 为 0.7438/0.9070/0.8644，反而略低；OneTrans 为 0.7476/0.9103/0.8677。加入 special token 后，CTR AUC 进一步到 0.7489，说明看似简单的序列边界符对稀疏推荐 token 很有帮助。SORT 的优势不是某一个孤立数字，而是随着 small、base、large 三种规模扩大仍保持优势，同时大模型需要更少 FLOPs。

4.2 预训练与消融

稀疏预训练的消融最清楚地揭示了训练策略：scratch Transformer 的 CTR/CVR/AddCart 为 0.7175/0.8959/0.8455，只做 sparse transfer 下降至 0.7162/0.8943/0.8449；transfer+freeze 则达到 0.7456/0.9093/0.8663。也就是说，冻结不是实现细节，而是让预训练稀疏表免受排序任务稀疏标签牵引的关键机制。

结构消融显示，special token 让 CTR-AUC 增加 +0.33pt，query pruning 增加 +0.26pt；attention gate、QKNorm、local attention 和 MoE 均有收益。局部窗口在 64、128、256 中以 256 最佳，过小的窗口失去长期依赖，过大的窗口增加计算。MoE 激活比例比较 1/2、1/4、1/8，1/8 最优；稀疏并不等于盲目少算，而是要保留足够的专家容量与稳定路由。

4.3 线上解释与失败边界

线上业务结果非常强，但不能把全部收益简单归因于 Transformer。SORT 同时改变了数据组织、预训练、注意力和基础设施，因此 A/B 证明的是完整系统方案的业务价值。论文还显示大模型训练需要 1–10 天、4–32 张 A100，且依赖 RecIS、Megablocks、MPGC 和定制 sparse attention；这意味着小团队很难只复制模型代码就得到同等结果。另一个值得注意的结果是 local attention 在 1K 序列上只少约 3G FLOPs，却在更长序列中成为关键，说明短序列离线指标可能低估系统优化的长期价值。

5. 局限与未来方向

论文没有单列一个形式化的 Limitations 小节，但实验范围明确了几项限制。数据来自一个工业推荐系统，线上验证集中在 AliExpress 多场景；虽然作者报告了跨数据量、模型规模和序列长度的 scaling，但没有证明同一组结构在社区内容、广告或短文本搜索上无需重新调参。训练依赖 4–32 张 A100、RecIS/Megablocks 和定制通信、注意力算子，工程门槛明显高于普通 Transformer。模型还使用一个固定的一 epoch、最大 1K 历史和三类行为目标，如何处理更长、多模态、强延迟反馈或更多负向反馈，论文没有展开。

从论文呈现的范围看，未来应继续验证三点：第一，生成式预训练目标能否把 query、帖子、作者和主题等 UGC token 统一起来；第二，冻结稀疏表会不会在新内容、新用户和概念漂移下限制适应速度；第三，线上业务提升是否能在长期留存、内容多样性和作者生态指标上持续。对于社区产品，不能只追求订单式短期指标，还需要把 CTR、nDCG、作者覆盖和负反馈共同纳入多目标排序头。

6. 工业实践意义

第一步可以先做“请求中心样本”改造：把同一请求的用户历史、画像和候选批量组织起来，测量重复编码减少了多少，以及排序服务的 P50/P99 延迟如何变化。第二步再逐层引入 local attention、candidate mask 和 query pruning，先从历史序列的尾部做局部窗口，并用离线 AUC、nDCG 与线上延迟联合验收。第三步才考虑生成式预训练和 sparse freeze，因为它要求稳定的 item/token 体系、足够长的行为序列以及可复现的 next-item 训练集。

对于 UGC 短文本搜索，可把点击、停留、收藏、关注、负反馈分别作为多目标头，使用用户行为序列和帖子语义 token 组成请求级输入。内容 ID 不应完全依赖高基数 embedding，可以用主题、实体、作者和语义簇形成较稳定的中间 token；但精排输出仍需保留 exact post ID 和业务过滤。部署时要把 embedding I/O、跨卡通信、稀疏 attention kernel 和 KV cache 一起剖析，不能只看 FLOPs。

最值得避免的是直接把大语言模型的完整 dense attention 和单一 next-click 目标搬到生产排序。SORT 的证据表明，收益来自多个工程约束共同作用：标签密度增强、历史计算裁剪、候选隔离、稀疏容量扩展和硬件利用率提升。若没有大规模训练数据或定制算子，应先复现请求中心、冻结稀疏表和轻量局部注意力三个低风险组件，再决定是否投入 MoE 与专用加速器。

One Hierarchy, Two Systems: Semantic Product IDs for Discovery-Surface Ranking and Search-Page Query Reformulation

DoorDash📖 深度解读 · 13 分钟 →

DoorDash 用产品内容 embedding 学习三层 Semantic ID（每层 512 个码），再将 SID 前缀上的用户偏好、商品表现和序列特征接入个性化排序，同时把查询转成商品概念做层级改写。排序离线 MRR@5 相对生产基线提升 6.98%、NDCG@5 提升 6.76%；线上首位加购率提升 8%，搜索滚动深度下降 1.866%。

1. 问题与动机

这篇工作来自 DoorDash 的跨商家电商场景，核心问题是商品标识和搜索词都在碎片化行为证据。相同或相近的商品会因为商家不同而拥有不同 listing ID：用户在商家 A 买过某个商品，这条行为通常不能直接帮助商家 B 的等价商品排序。反过来，人工 taxonomy 虽然可解释，却常常过粗，不能表达品牌、规格、用途和细粒度偏好。结果是新商家或低频商品缺少可靠的个性化信号。

搜索改写有类似问题。传统方法在 query string 之间统计 session transition，同义词、拼写错误、缩写会被当作不同节点；同一个词在不同 business vertical 中又可能代表不同意图。高频 query 会淹没长尾意图，导致改写结果看似热门但不一定可购买或可推进用户任务。论文因此提出一个统一但不耦合的中间表示：从商品内容学出多层 Semantic ID，让商品、用户历史和 query 都能落到同一个细粒度概念层级上。

论文的关键立场是“共享表示，不共享决策模型”。同一个 Semantic ID 层级被排序和 query reformulation 使用，但两个应用各自组织行为数据、训练目标和 serving 逻辑。这样可以在跨商家合并证据的同时，保留发现流排序与搜索页改写各自的业务上下文。对社区搜索尤其有启发：帖子、作者、主题、实体可以共享一个语义层级，但召回、排序、改写和安全过滤仍需按任务分开。

2. 方法详解

2.1 三层 Semantic ID 的构造

论文先把商品名、品牌、规格等 catalog 字段串成文本 profile，用 gemini-embedding-001 编码为 3,072 维向量。然后采用三阶段 residual-quantization K-means，层数 L=3，每层 K=512 个 centroid。对商品 i，第一层把 embedding 分配到最近的 centroid，减去该 centroid 得到 residual；第二、三层对 residual 重复分配和相减，最终得到 SID s_i=[c_i0,c_i1,c_i2]。深度 1、2、3 分别称为 L1、L2、L3 前缀。

共享前缀的商品被视为同一层级概念，短前缀聚合更宽泛的语义，长前缀表达更具体的商品意图。内在分析显示，L1/L2/L3 的 Gini 分别为 0.472/0.508/0.467，DBI 为 3.934/2.065/0.976，held-out cosine 为 0.957/0.965/0.981。随着前缀变长，簇分离度提高、未见商品的语义一致性增强，而 code usage 的不平衡没有明显恶化。这给跨商家行为共享提供了一个介于精确 listing ID 和粗粒度 taxonomy 之间的中间层。

2.2 个性化发现流排序

发现流排序器是 multi-task、multi-label 神经网络，同时预测 CTR、ATCR（加购）和 CVR（购买）。SID 派生特征分为两类。第一类是 dense aggregate：在 L1、L2、L3 前缀上统计用户的购买频次、购买新近性、消费金额，以及子市场中的曝光、点击、加购、购买和对应率。浅层前缀提供跨商家的统计支持，深层前缀恢复商品意图的细节。

第二类是 sequence features。作者用 SentencePiece 把 SID 三个 code 映射为子词。输入符号表大小为 3×512=1,536；BPE 词表为 2×10^5，embedding 维度 64。候选商品使用自己的 SID token，用户侧取过去 180 天买过的商品，按订单数量排序、以新近性打破平局，再保留高频 token。商品与用户共用 embedding 表，因此排序器可以直接学习“候选 SID 子片段—用户历史语义片段”的交互。

这个设计把两种归纳偏置叠加起来：dense aggregate 直接提供统计证据，减少高基数概念必须从零学习的压力；sequence feature 保留 SID 的顺序和子片段，让模型能学习更复杂的用户—商品组合。精确 listing ID 与 taxonomy 没有被删除，而是与 SID 特征并存，分别负责身份、业务组织和可迁移语义。

2.3 基于 SID 的 query reformulation

query 先按 business vertical 与加购事件落到 SID 概念。一个 query–BV 对至少要有 5 个相关 ATC 事件；若某个 L2 前缀占证据至少 30%，就使用该 L2，否则退回 L1；两层都不满足时保留 raw query，避免无证据的强制映射。session 中相邻 query 不再直接作为字符串边，而是变成 SID 概念之间的 transition，分别在每个 BV 中统计，并用 NPMI 排序。保留边的条件是观测次数至少 5、独立假设下的期望次数至少 1、NPMI 至少 0.1。

同一 L2 前缀内的细粒度改写容易塌成 self-loop，因此作者增加 L2 到 L3 的 hierarchical refinement，用 query-specific ATC 证据或父级流行度挑选子概念。随后让语言模型只负责把内部 SID 概念渲染成用户可读 query，第二阶段删除不可用的 source-target pair，最后按 source query 与 rendered query 的 embedding 相似度排序。serving 端还会检查商家 active assortment，保证建议对应的商品确实可买。

3. 核心技术贡献

第一，论文把 Semantic ID 从生成式检索的 item code 扩展成跨发现任务的 reusable concept layer。它用一套三层语义层级在商家之间搬运行为证据，解决 listing ID 无法共享和 taxonomy 太粗的问题，但不强迫应用共享模型参数。

第二，排序和 query 改写使用不同的任务上下文。排序把前缀当作用户偏好和商品表现的统计 key，并拼进用户序列；改写把前缀当作 query grounding、transition、层级导航和库存过滤的结构节点。这种“共享语义、独立策略”比单一端到端模型更容易嵌入现有多阶段系统。

第三，作者同时用 dense 和 sequence 两类 SID 特征，使语义聚合既有显式统计支持，又有可学习的 token 交互。离线 FC-A 去掉 SID 特征后仍有部分收益，说明同期非 SID 特征也重要；完整 FC 的增益明显更大，证明 SID 派生特征贡献了完整候选的主要离线提升。

第四，论文明确了语义压缩的风险和补救办法。浅层前缀能提升覆盖却可能连接无关行为，深层前缀能恢复 specificity 却可能稀疏；因此排序使用多层特征，改写用 BV 条件、L3 证据和 assortment filter 恢复任务约束，而不是把 SID 当作完整意图表示。

4.3 改写质量与线上搜索效率

4.4 失败模式与实验解释

论文没有把线上 ranking treatment 的所有收益都归给 SID，因为 bundle 同时包含同期 non-SID 更新；作者借助 FC/FC-A 离线消融和事后分析推断 SID 贡献主要部分。定性分析还发现量化边界会把本来可互换的商品分到不同 code，过宽前缀会形成高连接度 hub，query grounding 可能捕捉最终加购概念而不是原始查询意图。这些问题解释了为什么需要多层聚合、BV 条件和库存过滤。

5. 局限与未来方向

作者在定性分析和实验解释中明确给出几类边界。首先，Semantic ID 是语义压缩，量化边界可能把相近替代品分开，同一前缀内部也可能混入对具体用户而言属性不同的商品。其次，过宽的 prefix 会成为高阶 hub，在 query transition 中传播不相关建议；商品 grounding 还可能把“用户最后买了什么”误当作“用户最初想找什么”。第三，线上 ranking 实验的 feature bundle 同时含有非 SID 更新，因此不能从线上结果单独识别 SID 的因果增益。第四，改写依赖商家 active assortment 和 BV 内足够的 ATC 事件，低流量、冷启动和无库存场景仍要回退 raw query 或其他策略。

论文还只展示了 DoorDash 自身的生产规模研究，并未证明三层、512 code、180 天历史等设置适合其他品类或内容社区。未来可以研究动态 SID 更新、对新 item 的增量量化、跨语言/跨市场语义层级，以及在隐私约束下共享用户兴趣而不暴露原始行为。对社区搜索，还需要验证作者、主题、实体和帖子生命周期的语义层级是否比商品内容更稳定。

6. 工业实践意义

在社区搜索或推荐中，可以先把帖子标题、正文短文本、作者、话题和实体编码成多层语义 ID，按“主题—子主题—实体/事件”形成粗到细的概念层级。第一阶段只将 SID 前缀作为离线聚合 key：统计用户在不同主题、实体、作者簇上的点击、停留、收藏和负反馈，观察跨内容类型合并行为后 nDCG@5、CTR 和冷启动覆盖是否改善。这样不需要重写整个 ranker，也能验证语义层级是否比现有 taxonomy 更能转移行为证据。

第二阶段可把 SID token 加入序列特征。对候选帖子和用户历史分别保留 exact ID 与 SID 子词，使用共享 embedding 学习“候选主题片段—用户兴趣片段”的交互；历史应使用多个时间窗口，类似论文的 180 天窗口，但社区内容需要额外加入新鲜度和事件衰减。第三阶段再接入 query reformulation：查询先落到主题/实体概念，再在 session 中统计概念跳转，最后由语言模型负责可读化，不让 LLM 自由生成没有库存、没有证据或违反安全规则的建议。

上线时必须保留任务特有的约束。排序需要用户、候选、作者质量、内容安全和时效性；改写需要查询意图、可检索内容、敏感词和当前库存。SID 应被视为可迁移先验，而不是唯一真值。监控面板至少要同时看 nDCG@5、CTR、首位/中腰部曝光、query reformulation success、滚动深度和负反馈；特别要关注热门前缀是否变成新的信息茧房。若线上 bundle 含有多个非 SID 改动，应同步保留 SID-only 的离线消融或分层实验，否则很难知道投入到底来自语义表示、排序特征还是其他策略。
