AutoSearch: Adaptive Search Depth for Efficient Agentic RAG via Reinforcement Learning

论文针对 Agentic RAG 反复搜索导致成本和延迟上升、固定搜索深度又会漏掉复杂证据的问题，提出 AutoSearch。方法用中间答案评估每一步是否已获得足够信息，并以达到最小充分深度给奖励、对过度搜索惩罚，再用强化学习训练搜索策略。作者在多个 agentic-search 基准上验证了更优的准确率—效率折中，同时保持复杂问题的回答质量。

Reinforcing Agentic Search Via Reward Density Optimization

论文把 Agentic Search 的训练瓶颈归因于奖励稀疏：长链路探索付出很大，却通常只在最终答案处得到反馈。InfoFlow 将奖励密度优化拆成三部分：用子目标脚手架分解长任务并提供过程奖励，用路径提示修正停滞轨迹，再用双 Agent 分担深度探索。作者在多个搜索基准上报告其超过强基线，并让轻量模型达到接近先进闭源模型的表现。

INSIGHT这套设计适合把搜索 Agent 的训练目标从“答对/答错”细化为查询改写、证据覆盖、冲突核验和停止决策等可观测子目标。对 UGC 搜索，可将错误点击、短停留和无结果回退变成过程级反馈，但要限制路径提示的偏置，并单独评估多 Agent 带来的调用成本。

jXBW: A Compressed Index Enabling Structure-Aware JSONL Retrieval for Structured RAG

jXBW 面向 JSONL 等已具备层级结构的语料，指出传统 RAG 每次查询都重建结构会带来额外开销。它把子结构搜索直接编译为压缩索引，通过合并树结构与紧凑编码，在对象集合上按模式检索，避免逐文档建索引和 XML 转换。论文围绕索引空间与查询时间增长进行评测，证明结构化检索适合为多步 Agent 提供可控、可复现的证据入口。

INSIGHT如果社区帖子、作者属性、话题标签和互动统计已落成 JSONL，Agent 不必把整条记录重新解释成文本再检索。工程上可把 jXBW 式子结构入口与语义召回并行：结构过滤保证约束可执行，向量检索补足口语表达，再把两路证据交给重排器，降低工具调用中的歧义。

04 3.95

MMSearch-R1: Incentivizing LMMs to Search

MMSearch-R1 研究多模态模型何时应该调用搜索、何时可以直接回答。方法用强化学习训练模型在真实网络环境中多轮调用图像和文本搜索工具，并加入搜索惩罚；训练数据同时包含必须搜索和无需搜索的样本。作者在知识密集型与信息寻求 VQA 任务上超过同规模 RAG 基线，达到更大 RAG 模型的表现，并将搜索调用次数降低 30% 以上。

INSIGHT对带图片、帖子和评论的社区搜索，可把“是否需要外部检索”作为显式策略，而不是默认每次都触发 Agent。训练集必须包含无需搜索的负例，并把搜索次数、上下文长度和用户等待时间纳入奖励；同时保留文本与图像检索两条工具链，避免单一模态误导意图判断。

How to Train a Real-World Silicon Concierge? Internalizing Complex Business Workflow to Only OneModel

OneModel 针对 Router、Retriever、Planner、Executor、Reviewer 等模块化 Agent 易形成补丁链、错误级联和高延迟的问题，把业务规则与 SOP 通过持续预训练和逻辑编译 SFT 内化到单一模型中。论文报告其已部署在全球金融服务系统，并在线 A/B 测试将端到端延迟从 18.7 秒降至 8 秒以上，降幅超过 50%。

INSIGHT它说明复杂 Agent 的收益可能来自减少跨模块状态传递，而不只是换更大的模型。社区搜索可以把稳定的 query 理解、改写和召回编排蒸馏进模型，但动态 UGC 知识仍应留在可更新索引中；上线时需保留检索证据、版本回滚和规则兜底，避免把易变事实固化进参数。

Auditable by Construction: An Ontology-Driven Framework for Trustworthy LLM Analytics in Enterprise Finance

KDAF 关注企业 RAG“答得像”但无法审计的问题，构建本体驱动知识系统，并用 CARP 在关系传播中检索证据，使每条事实携带关系类型、置信度和来源链路。论文在包含 145 道题的 FinanceBench 上比较零上下文、BM25、概念加权词法检索和无约束图遍历，强调准确率之外还要验证证据可追溯性。

INSIGHTAgentic 搜索进入社区平台后，答案和推荐理由都需要能回指帖子、评论和规则来源。可以借鉴“关系类型+置信度+lineage”的证据对象，把 query 改写、工具调用和最终引用串成可回放轨迹；评测不要只看答案相似度，还应加入来源覆盖、冲突检测和不可引用率。

Graph Engineering in the Era of LLM Agents: From Individual Intelligence to System Intelligence

论文认为长周期 Agent 任务的瓶颈已从单个 LLM 能力转向系统组织能力，提出 System Intelligence。它归纳 Prompt、Context、Harness、Loop 四类工程，并强调复杂任务需要专业 Agent 分工、并行执行、独立验证和持久状态。文章主要给出架构性分析，适合作为多 Agent 搜索编排的设计框架，但没有提供足够的线上或基准量化结果。

INSIGHT对搜索系统，最可借鉴的是把“检索、核验、总结、监控”拆成职责清晰的 Agent，并用共享状态连接，而不是让一个模型包办所有步骤。落地时应先固定可观测协议和失败转移，再增加并行 Agent；没有独立验证与超时预算，多 Agent 只会放大延迟和错误传播。

Structure for Reading, Prose for Writing: Asymmetric Structural Conditioning in Multi-Agent Document Authoring

论文提出面向正式文档的多 Agent 写作管线：阅读阶段保留表单和结构约束，写作阶段再生成自然语言，形成“结构读、 prose 写”的非对称条件。部署在投标响应系统的盲测中，55 个真实段落里有 40 个不低于人工答案、4 个更好、没有漏答，且仅发现 1 个无依据陈述；68% 的差距来自系统未提供的内容。

INSIGHT它提醒搜索 Agent 不应把结构化约束和自然语言答案混在同一上下文里。社区场景可先把时间、地域、内容类型等约束解析成结构字段，再用生成器组织帖子证据；验证器要分别检查约束满足、引用支撑和表达质量，避免流畅文字掩盖召回缺失。

WebAggregator: Enhancing Compositional Reasoning Capabilities of Deep Research Agent Foundation Models

WebAggregator 针对 Deep Research Agent 过度依赖检索、却缺少跨证据组合的问题，提出数据合成管线。Proactive Explorer 先收集相互关联的知识，Compositional Logic Proposer 再依据 12 条以上组合准则构造复杂问题，训练数据因此覆盖多跳证据聚合而非简单实体查找。论文将“会找到”推进到“会组合并解释”。

INSIGHT社区搜索里的高难问题往往要求把多个帖子、评论和事件串起来，单纯扩大召回不等于完成推理。可借鉴其先建关联证据图、再生成组合任务的离线流程，用多跳覆盖率、证据链完整度和冲突处理准确率评估 Agent，而不是只测最终文本相似度。

手把手教你构建Agentic RAG：一种基于多文档RAG应用的AI Agent智能体

字节跳动

火山引擎文章以多文档知识库为例，说明如何把一次性向量检索升级为由 Agent 规划、选择检索工具并综合多份证据的流程。内容聚焦企业场景中跨文档、复杂条件和结构化数据任务对检索规划的需求，并给出 Agentic RAG 的工程实践路径。它更像落地指南，未提供可与论文直接比较的统一基准数据。

INSIGHT这类工程实践适合作为社区搜索的最小可行架构：先判断问题类型，再路由到关键词、向量、结构化查询或网页工具，最后统一证据格式。生产上应为简单 query 保留单跳快速路径，并用轮数、Token、失败重试和证据命中率建立成本—质量看板，避免 Agent 默认走重流程。
