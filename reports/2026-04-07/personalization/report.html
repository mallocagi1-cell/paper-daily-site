1. MBGR: Multi-Business Prediction for Generative Recommendation at Meituan
4.40
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 针对工业级生成式推荐在多业务场景下面临的「跷跷板效应」（NTP 无法捕捉跨业务行为模式）和「表征混淆」（统一 SID 空间混淆不同业务语义）两大关键问题，提出 MBGR 框架。核心设计包括：(1) 业务感知语义 ID (BID) 模块通过领域感知 tokenization 保持语义完整性；(2) 多业务 token 预测框架捕捉跨业务行为依赖。该工作是首个面向多业务场景设计的生成式推荐框架，已在美团工业系统中部署验证。

Key insight: 生成式推荐从单业务向多业务扩展时，统一的语义 ID 空间会导致跨业务语义混淆，这是工业级 GR 落地的核心瓶颈。MBGR 的 BID 模块思路——通过领域感知的 tokenization 隔离不同业务的语义空间——为多业务推荐系统提供了可复用的设计模式。对于运营多条业务线的平台（如社区搜索同时覆盖帖子、问答、评论），该方法可有效避免跨内容类型的推荐质量互相干扰。

独立页面阅读 ↗

1. 问题与动机

生成式推荐（GR）近年来成为工业推荐的重要范式，通过语义 ID（SID）压缩编解码空间、利用 Next Token Prediction（NTP）框架探索 scaling law。然而，现有 GR 方法均面向单一业务设计，在美团这类多业务平台（外卖、到店、医疗等 4 条业务线）部署时暴露出两个核心缺陷：(1) 跷跷板效应——NTP 框架无法捕捉跨业务行为模式的复杂依赖关系，导致优化一个业务时另一个业务性能下降；(2) 表征混淆——统一的 SID 空间使不同业务的语义信息在梯度优化过程中发生耦合，无法区分跨业务差异。这两个问题在小业务线上尤为严重——占比仅 9.56% 的 B 业务在传统方法下的 Hit@10 仅为大业务的 46%。

2. 方法详解

MBGR 框架包含三个核心模块：

Business-aware Semantic ID (BID) 模块：通过编码器-解码器结构将业务上下文注入 token 表征。编码器将 token embedding \in \mathbb{R}^{K \cdot d_t}$ 与业务 embedding $ 拼接后经 FFN 和门控融合（ = \sigma( ext{FFN}_{gate}([e_i, b_i]))$， = e_i \odot g_i$），产生业务感知的 item 表征。解码器采用镜像结构还原 token embedding，通过重构损失 {recon} = rac{1}{K} \sum_k \|T_u^{(k)} - \hat{T}_u^{(k)}\|_2^2$ 确保语义信息最小损失。关键设计：业务 embedding 在编解码两端均参与拼接，确保业务上下文贯穿表征学习全过程。

Multi-Business Prediction (MBP) 模块：采用参数共享的 Mixture-of-Experts 架构。对每个 item 表征和业务 embedding 的拼接向量 ^b = [e, b]$，通过自适应门控 ^b = ext{SiLu}( ext{FFN}_{gate}(z^b)) \in \mathbb{R}^K$ 产生 K 个专家权重，最终输出 ^b = \sum_k g_k^b \cdot ext{FFN}_k^{exp}(z^b)$。所有业务共享 K=8 个 expert FFN，仅门控网络按业务特化，平衡知识共享与业务特异性。

Label Dynamic Routing (LDR) 模块：解决多业务场景下标签稀疏问题。对序列中每个位置 $ 和每个业务 $，将标签路由到该业务的下一次交互：{u,t+1}^{(k)} = i_{u,t'}$，其中 ' = \min\{t'' > t | b_{u,t''} = b_k\}$。将原本每个位置约 1 个有效标签扩展为最多 4 个（等于业务数），显著增强梯度信号。

训练使用 InfoNCE 损失（含业务权重 $ 和时间衰减 = \exp(-lpha \cdot (t_{last} - t))$）加重构损失。训练数据：3830 万用户、5490 万商户、1 年历史数据。架构：16 层 Transformer、8 头注意力、128 维 embedding、最大序列长度 1500。硬件：NVIDIA A100-80GB，优化器 Adam（lr=0.001），batch size 1024。

3. 核心技术贡献

贡献 1：业务感知语义 ID 与重构损失。BID 模块通过在编解码两端注入业务 embedding，将统一的 SID 空间分化为业务感知的表征空间。重构损失确保分化过程不丢失核心语义信息。消融实验显示去除 BID 后整体性能下降 18.3%，验证了表征混淆是多业务 GR 的真实瓶颈。

贡献 2：参数共享 MoE 实现单次前传多业务预测。与为每个业务部署独立模型不同，MBP 通过共享 expert + 业务特化 gate 在一次前传中完成所有业务的预测。去除 MBP 后性能下降 19.5%，其中 B 业务（最小）下降最为显著（-27.6%），说明跨业务知识共享对小业务的增益最大。

贡献 3：标签动态路由解决稀疏标签问题。LDR 是对整体性能贡献最大的模块——去除后性能下降 34.6%。小业务 B 的下降尤为剧烈（-43.7%），因为其本身交互数据稀疏，密集化标签带来的边际收益最大。这一发现揭示了多业务推荐的核心挑战不在于模型架构，而在于训练信号的稀疏性。

4. 实验结果分析

在生成式 Hit@10 指标上，HSTU-MBGR 相较 HSTU 基线提升 91.6%（0.0214 → 0.0410）。最显著的提升出现在小业务：B 业务从 0.0127 提升到 0.0554（+336%），C 业务从 0.0198 提升到 0.0398（+101%）。下游 CTCVR GAUC 上，MBGR 整体提升 3.8%（0.7748 → 0.8040），B 业务提升 8.7%。

消融实验揭示各模块贡献排序：LDR > MBP > BID（分别贡献 34.6%、19.5%、18.3%）。超参分析显示：(1) 时间衰减 α=0.05 最优，过大会丢失历史信号；(2) 业务权重需按业务规模反向调整（B 业务权重 1.5，A 业务权重 0.9）；(3) Expert 数 K=8 最优，更多 expert 边际收益递减。

在线 A/B 测试（30% 美团线上流量，1 周）：加权平均 CTCVR 提升 +3.98%，其中 B 业务 +7.5%、C 业务 +4.5%、D 业务 +5.2%、A 业务 +3.0%（p < 0.01）。

5. 局限与未来方向

论文未显式列出局限性，但存在以下隐含限制：(1) 损失函数中 $\lambda$ 超参（平衡预测与重构）的设置方法未说明；(2) 仅在 4 个业务上验证，业务数量进一步扩展时 MoE 的 expert 分配策略是否需要调整尚不清楚；(3) 缺少在线推理延迟和内存开销的定量分析；(4) 未与其他多业务方案（如 M3OE、PLE 等）进行对比。未来方向可能包括与 LLM 结合进行语义增强、跨业务冷启动优化等。

6. 工业实践意义

MBGR 的工业价值体现在三个层面：(1) 多业务平台的通用设计模式——BID + MBP + LDR 的组合为所有运营多条业务线的平台（电商多品类、社区多内容类型）提供了可复用的 GR 框架；(2) 小业务的差异化增益——B 业务 +7.5% CTCVR 的在线提升证明该框架能有效缓解「大业务挤压小业务」的马太效应；(3) 渐进式部署策略——美团选择将 MBGR 作为召回通道和排序特征增量接入（而非端到端替换），反映了工业界对 GR 系统稳定性风险的务实态度。

对于社区搜索场景，MBGR 的启发在于：当平台同时覆盖帖子、问答、评论等多种内容类型时，可以借鉴 BID 模块的思路——在共享的语义空间中引入内容类型感知的表征分化，避免不同内容类型的搜索排序模型互相干扰。LDR 的标签路由思路也可迁移到多场景联合训练中。

3. Jump Start or False Start? A Theoretical and Empirical Evaluation of LLM-initialized Bandits
4.30
Relevance 4 | Novelty 4 | Practical 4 | Evidence 4 | Timely 5

Summary: 系统性研究利用 LLM 生成的用户偏好数据对 contextual bandits 进行 warm-start 的效果与边界。实验发现：在偏好对齐的场景中，warm-start 在数据损坏率达 30% 时仍有效，40% 时优势消失，50% 以上时反而损害性能。当 LLM 偏好与真实用户存在系统性偏差时，即使无噪声注入，LLM 先验也会导致比冷启动更高的 regret。理论分析将随机噪声和系统性偏差的影响进行了分解量化。

Key insight: 该工作为「LLM 辅助冷启动」设定了清晰的适用边界：LLM 生成的用户偏好只有在与目标用户群大致对齐时才能加速 bandit 学习，否则反而有害。这对推荐系统的冷启动实践有直接指导意义——在部署 LLM warm-start 前，必须先验证 LLM 的偏好分布与目标人群的匹配度。30% 损坏率阈值为工程上设置数据质量 gate 提供了量化参考。

独立页面阅读 ↗

1. 问题与动机

利用 LLM 生成合成偏好数据来 warm-start contextual bandits（CBLI）近来备受关注。Alamdari et al. (2024) 的先驱工作显示 LLM warm-start 可降低 14-20% 的早期 regret。然而，这些结果建立在一个隐含假设之上：LLM 生成的偏好与真实用户偏好大致对齐。本文系统性地研究当这一假设被打破时会发生什么——当合成先验包含噪声或系统性偏差时，warm-start 的效果如何退化？先前关于 LLM 作为「硅基样本」的研究报告了混合的保真度结果，且对 prompt 设计高度敏感。真实世界的 LLM 输出呈现异方差、上下文相关的误差结构，远非简单的随机噪声。这使得部署前理解失败模式成为关键需求。

2. 方法详解

CBLI 流程包含三阶段：(1) LLM 预训练——通过 prompt 生成 N 个合成 context-reward 对，拟合 ridge 回归得到 warm-start 参数 {A₀, b₀}；(2) 微调——用 warm-start 参数初始化 LinUCB，在真实数据上运行 T 轮；(3) 对比基线——从冷启动（A₀=I, b₀=0）运行同等 T 轮 LinUCB。

噪声注入模型：作者设计了两种控制性损坏：(1) 随机替换（corruption rate p）——随机选择 p 比例的 LLM 标签，替换为随机 arm，模拟无信息的 LLM 错误；(2) 偏好翻转（corruption rate p）——随机选择 p 比例的合成记录，反转选择的 arm（K=2 时 A↔B），模拟系统性偏差。两种噪声在 p=0.0 到 p=0.7 范围内扫描。

理论框架：在线性 contextual bandit 设定下（$\mathbb{E}[r_t|x_{t,a}] = heta^{ op} x_{t,a}$），推导出 Prior-Centered Confidence Bound（定理 1）：$\|\hat{ heta}_t - heta^\|_{V_t} \leq eta_t(\delta) + B_0$，其中 = \| heta_0 - heta^\|_{A_0}$ 是先验误差标量，吸收了所有预训练效果。warm-start 有益的充分条件是 ^{warm} < B_0^{cold} = \| heta^\|_2$。

偏差-方差分解：将翻转噪声下的参数估计展开为 $ heta_0 = (1-2p)M heta^* + pA_0^{-1}X^ op 1 + A_0^{-1}X^ op arepsilon$，在高覆盖近似下得到偏差项 $pprox 4p^2\lambda_i$，表明翻转引起的偏差随 ^2$ 增长且在高覆盖方向放大。

3. 核心技术贡献

贡献 1：Prior-Centered Confidence Bound。将 warm-start 估计误差分解为先验误差 $ 和标准方差项 $eta_t$，证明预训练对 regret 的影响主要通过单一标量 $ 传导。这使得 warm-start 效益的评估从「试试看」变为可量化的诊断：只需估计 $\hat{B}_0$ 即可判断是否部署 warm-start。

贡献 2：翻转噪声与系统性偏差的解析刻画。证明在 well-covered 方向上，翻转噪声的偏差以 ^2$ 增长且被合成数据覆盖度放大——这解释了 30-40% 损坏率是 breakpoint 的原因。当存在系统性偏差 $\Delta = heta^_{syn} - heta^_{real}$ 时，即使 p=0 也会产生大 $，导致 negative transfer。

贡献 3：两类噪声的不对称性。实证发现随机替换噪声即使在 p=70% 时也几乎无害（$ 不在有害方向增长），而偏好翻转在 p>30% 时可靠地降低性能。这一不对称性有深刻的实践含义：LLM 的「不确定但不系统性错误」的输出可以容忍，但「自信但方向性错误」的输出极其危险。

贡献 4：跨模型/跨域的鲁棒性基准。在 3 个数据集（COVID-19 疫苗偏好、移民态度、休闲旅行）和 4 个 LLM（GPT-4o、GPT-3.5、Llama 3.1、Qwen 3）上建立了系统性基准，发现 $\hat{B}_0$ 与实际 regret 减少之间存在强相关，验证了理论框架的预测能力。

4. 实验结果分析

核心实验结果（COVID-19 疫苗数据集，GPT-4o，N=10k 合成数据）：偏好翻转噪声下，warm-start 在 p=0 时提供 11.52% 的 regret 减少，p=30% 时仍有 7.49% 收益，p=40% 时降至 2.98%，p=50% 时变为 -7.78%（warm-start 反而有害），p=70% 时恶化至 -32.37%。

与之形成鲜明对比，随机替换噪声在所有测试级别上几乎不产生负面影响——即使 p=70%，warm-start 仍略优于冷启动。这一不对称性在所有 3 个数据集和 4 个 LLM 上一致成立。

跨模型对比显示，GPT-4o 在 COVID-19 数据集上表现最佳（$\hat{B}_0 = 44.4$），而 Qwen 在旅行数据集上出现 p=0 时的 negative transfer（-1.44%），对应最高的 $\hat{B}_0 = 62.3$。$\hat{B}_0$ 的排序在每个数据集内与 regret 减少的排序一致，验证了先验误差作为核心诊断指标的有效性。

一个值得注意的发现：GPT-3.5 的早期快照（约 9 个月前）比当前版本展现出更好的对齐效果和更清晰的噪声阈值，揭示了 LLM 对齐的时间非平稳性——模型更新可能悄然改变合成先验的质量。

5. 局限与未来方向

作者明确列出的局限：(1) 评估使用固定 prompt，但 LLM 输出对 prompt 措辞、上下文和选项顺序高度敏感；(2) 注入噪声为 IID 模型，而真实 LLM 误差呈现异方差和上下文相关结构；(3) 高覆盖近似假设合成数据设计矩阵覆盖充分，在稀疏场景下偏差-方差权衡可能偏离二次 scaling；(4) LLM 的安全护栏和模型修订引入非平稳性，不同时间点的模型快照可能产生不同结果；(5) LLM 编码的人口统计和意识形态偏见可被 bandit 直接操作化到真实用户上，存在反馈循环放大歧视的风险。

6. 工业实践意义

对推荐系统冷启动的直接指导：(1) 部署 LLM warm-start 前必须估计 $\hat{B}_0$，以此作为 go/no-go 的定量决策依据——$\hat{B}_0 < 45$ 可以部署，$> 55$ 应回退到冷启动；(2) 随机误差可容忍但系统性偏差致命——在数据质量检查中应侧重检测方向性错误而非随机噪声；(3) 30% 损坏率阈值可作为工程实践中数据质量 gate 的量化参考。

对社区搜索的启发：在 UGC 搜索中引入 LLM 生成的用户偏好（如 query-document 相关性标注）进行模型 warm-start 时，必须首先验证 LLM 的标注与目标用户群的实际点击行为是否对齐。社区平台用户的搜索行为往往与通用 LLM 的「理性」偏好存在系统性偏差（如更偏好情感表达而非信息完整性），此时盲目使用 LLM warm-start 可能适得其反。建议实现 $\hat{B}_0$ 监控，定期验证 LLM 先验质量，并在模型更新后重新评估。
