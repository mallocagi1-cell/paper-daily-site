Meta Adaptive Ranking Model 深度解读

Meta 广告排序系统 Wukong Turbo：将万亿参数模型的推理成本曲线从线性弯曲为亚线性

1. 问题与动机

Meta 在广告排序领域面临一个核心的 "推理三难困境"（Inference Trilemma）：

  • 模型复杂度：广告排序效果的提升依赖于更大、更深的模型，业界已验证 LLM 级别的参数量（万亿量级）能带来显著的排序质量增益；
  • 延迟约束：广告系统要求亚秒级响应（O(100ms) 量级），这与 LLM 动辄数秒的推理延迟形成尖锐矛盾；
  • 成本效率：Meta 每天服务数十亿次广告请求，模型参数量线性增长若导致推理成本同步线性增长，则经济上不可持续。

为什么重要？ 传统广告排序模型（DLRM 系列）的 scaling 路线是"加参数 → 加机器 → 加成本"，呈线性关系。而 LLM 领域的 scaling law 研究证明更大模型有更好效果，广告排序领域同样适用。但广告系统的实时性和成本敏感性远超 LLM 应用场景——你不可能让用户等 2 秒看到一条广告。Meta 需要回答的问题是：能否在不突破延迟和成本约束的前提下，将排序模型扩展到 LLM 级别？

这本质上是一个 model-system co-design 问题，不能只看模型，也不能只看系统。

2. 方法概述

Wukong Turbo 的核心思路可以用一句话概括：将推理计算的粒度从"逐对 user-ad 打分"提升到"request 级别批处理"，从而将计算成本与候选集大小解耦。

架构建立在三大支柱之上：

支柱一：Request-Oriented 计算共享

传统排序模型对每个 (user, ad) pair 独立计算，如果一个 request 有 N 个候选广告，user 侧的特征（行为序列、画像等）会被重复计算 N 次。Wukong Turbo 将 user 信号的计算提取出来，一次计算、广播复用给所有候选广告：

  • In-Kernel Broadcast：在 GPU kernel 内部实现 embedding 的跨候选广播，避免数据搬运开销；
  • Request-Oriented Sequence Scaling：用户长行为序列只处理一次，结果分发给所有候选，大幅降低 serving 和存储开销。

支柱二：Model-System Co-design（Wukong Turbo 架构）

基于原有 Wukong 架构（分解机 + 序列学习 + cross-layer attention），做了三个针对推理效率的结构性调整：

  • No-Bias：移除不稳定的偏置项，在不增加 FLOPs 的前提下提升吞吐；
  • Parameter Delegation：将部分参数从 FSDP（全分片数据并行）迁移到 DDP（分布式数据并行），降低网络和内存开销；
  • Sparsity-based Simplification：裁剪冗余的线性层。

支柱三：GPU-native 全链路优化

将特征预处理从 CPU 端迁移到远端 GPU 主机，使用紧凑的 tuple-based 格式和 GPU 原生 kernel，消除 CPU 端的数据准备瓶颈（data starvation）。同时将 Top-K 排序的复杂度从 O(N log N) 降至 O(N)。

3. 核心技术贡献

贡献 1：推理成本曲线从线性到亚线性

这是本文最核心的贡献。传统模型的推理成本与候选集大小 N 呈线性关系：Cost = N × C_per_pair。Wukong Turbo 通过 request-oriented 计算共享，将成本拆解为：

Cost = C_user (一次性) + N × C_ad (仅候选侧)

其中 C_user 通常远大于 C_ad（用户侧特征更稠密、序列更长），因此当 N 增大时，总成本的增长远低于线性——推理 scaling 曲线被"弯曲"了。

贡献 2：选择性 FP8 量化

不是全模型 FP8，而是通过 micro-benchmark guided 选择机制，仅在精度损失容忍度高的层应用 FP8 量化。这样做的好处是：

  • 充分利用现代异构硬件（如 H100 的 FP8 Tensor Core）的算力；
  • 对推荐质量的影响可忽略不计；
  • 实测达到 35% Model FLOPs Utilization (MFU)，跨多种硬件类型一致。

35% MFU 在推荐系统领域是一个相当高的数字——传统 DLRM 类模型由于 embedding lookup 的 memory-bound 特性，MFU 通常在 10-20%。

贡献 3：万亿级 Embedding 的多卡分片

Embedding 表是推荐模型的参数大头，万亿级参数主要来自这里。解决思路：

  • 动态分配：根据特征稀疏度动态调整 embedding 维度；
  • Pruning：裁剪未使用的 embedding 行；
  • Unified Embeddings：多个特征共享 embedding 表；
  • 多卡分片：embedding 表切分后分布到 GPU 集群，且性能与单卡持平。

贡献 4：算子融合与 Grouped GEMM

  • 算子融合：减少 HBM 与 SRAM 之间的数据搬运次数；
  • Grouped General Matrix Multiply：将多个小矩阵运算合并为计算密集型 kernel，提升 GPU 利用率。

4. 实验结果分析

Wukong Turbo 于 2025 Q4 在 Instagram 上线，实测结果：

指标提升
广告转化率（Conversions）+3%
目标用户 CTR+5%
推理延迟O(100ms) 以内，亚秒级
Model FLOPs Utilization35%（跨多种硬件）
模型加载时间< 10 分钟（多流下载 + 远端缓存）

结果解读：

  • +3% 转化率 在 Meta 的广告体量下是一个非常显著的数字。Meta 2025 年广告收入约 1600 亿美元，3% 的转化率提升即使仅部分转化为收入增长，也意味着数十亿美元级的影响。
  • +5% CTR 说明模型不仅提升了深层转化，在浅层交互指标上也有增益，表明更大模型确实学到了更好的 user-ad 匹配信号。
  • 100ms 延迟的维持证明了亚线性 scaling 的实际效果——模型大了几个数量级，但延迟没有同步膨胀。
  • 35% MFU 意味着推理阶段 GPU 不再是"大部分时间在等数据"，计算效率得到了实质性提升。

5. 局限与未来方向

当前局限

  1. 信息披露有限：作为工程博客而非学术论文，缺少关键的消融实验（ablation study）——无法量化每个优化技术各贡献了多少增益。
  2. 硬件依赖性：选择性 FP8 量化和 Grouped GEMM 优化高度依赖特定 GPU 架构（如 H100），在异构硬件环境下的泛化性未知。
  3. 仅 Instagram 数据：目前仅报告了 Instagram 上的结果，不同广告形态（Feed、Stories、Reels、跨平台）的效果差异未披露。
  4. 模型鲜度问题：万亿级模型的更新/训练成本未讨论——模型越大，训练和更新越慢，在广告这种数据分布快速漂移的场景下，模型鲜度可能成为新瓶颈。

作者提出的未来方向

  1. Agentic 优化框架：用自主代理（agent）自动适配新硬件和模型架构，进一步加速 kernel 性能优化。
  2. 近实时模型更新：探索增量式、就地权重更新（incremental in-place weight updates），实现接近实时的模型适应。
  3. 极低精度量化：推进模型压缩和超低精度量化方法，以适配多样化的硬件集群。

我认为的额外方向

  1. 跨请求的计算复用：当前是 request 内复用 user 信号，但同一用户短时间内的多次请求之间，user 信号高度重叠，可以引入 跨请求缓存进一步降低计算量。
  2. 动态计算分配：不是所有候选广告都需要同等精度的打分，可以结合 early exit 或 cascading 策略，对高置信候选提前输出。

6. 工业实践意义

对广告系统

  • 验证了广告排序模型 scaling 到 LLM 级别的可行性和收益。这是业界首次公开披露万亿参数级广告排序模型的完整上线数据，对所有广告平台都是一个重要信号。
  • Request-oriented 批处理是最值得借鉴的设计模式。绝大多数推荐/广告系统仍在做 per-pair scoring，切换到 request-level 计算共享是一个架构级的优化机会，且与具体模型结构无关。

对搜索系统

  • 搜索排序同样适用 request-oriented 计算共享。搜索场景中 query 侧特征（query embedding、用户画像、session context）同样在所有候选文档间共享，完全可以复用这一思路。
  • 选择性量化策略对搜索排序模型同样适用——搜索模型中的语义匹配层通常对精度敏感，而特征交叉层则有较高的量化容忍度。

对推荐系统

  • Model-System Co-design 将成为标配。Wukong Turbo 最大的启示不是某个具体技术，而是一种思维方式：模型架构设计必须与推理系统联合优化。单独优化模型或单独优化系统都无法突破 scaling 瓶颈。
  • GPU 预处理替代 CPU 端数据准备是一个被低估的优化方向。很多推荐系统的延迟瓶颈不在模型推理本身，而在 CPU 端的特征拼接、序列化和数据传输——将这部分工作搬到 GPU 上可以消除"数据饥饿"问题。
  • Embedding 的多卡分片 + 动态裁剪为其他需要超大 embedding 表的系统（如召回模型、向量检索）提供了工程范式。

核心 Takeaway

排序模型的 scaling 瓶颈不在模型大小本身，而在 serving 效率。 通过 request-oriented 计算共享 + 选择性量化 + GPU-native 全链路优化，推理成本可以从与参数量的线性关系弯曲为亚线性关系。这意味着"更大的模型"不再等于"更贵的推理"——对所有受限于推理成本而无法扩大模型的工业系统来说，这是一个范式转换的信号。

Renmin UniversityAlibaba📖 有深读 · 10 分钟

本文首次系统探索了扩散语言模型（dLLMs）在文档重排序中的应用，提出 DiffuRank 框架，实现了三种重排序策略：(1) pointwise 方法利用 dLLMs 估计 query-document 对的相关性分数；(2) 基于 logit 的 listwise 方法联合评估多文档相关性并直接从模型 logit 导出排序列表；(3) 基于排列的 listwise 方法。实验表明 dLLMs 在文档重排序上性能可与同等规模的自回归 LLM 相媲美甚至超越，同时因并行解码带来效率优势。代码已开源。

DiffuRank: 扩散语言模型在文档重排序中的应用 — 深度解读

1. 问题与动机

当前基于 LLM 的文档重排序（reranking）主要依赖自回归语言模型（如 LLaMA、Qwen），但存在两个核心瓶颈：

  1. 高延迟：自回归模型逐 token 生成，在 listwise 重排序场景下需要依次输出每个文档的排名标识符，延迟随候选文档数线性增长。对于实时搜索系统，这是不可接受的。
  1. 错误传播：固定的从左到右生成顺序意味着早期的预测错误会向后传播。例如在 permutation-based 重排序中，如果第一个位置排错了，后续排名都会受影响——这在排序任务中尤为致命，因为排序本质上是一个全局优化问题，不应被局部生成顺序所约束。

为什么重要？ 重排序是现代搜索系统中精排阶段的核心模块。LLM-based reranker 已经展现出超越传统 cross-encoder 的能力，但其效率问题严重制约了工业部署。如果能找到一种既保持 LLM 级别语义理解能力、又具备并行推理效率的新范式，将对搜索系统的精排架构产生深远影响。

2. 方法概述

DiffuRank 提出将扩散语言模型（diffusion LLMs, dLLMs） 引入文档重排序，核心思路是利用 dLLMs 的两大特性：双向注意力（bidirectional attention）和并行解码（parallel decoding）。

框架包含三种重排序策略：

Pointwise 策略 (DiffuRank_Pointwise)

  • 独立评估每个 query-document 对
  • 在 prompt 末尾添加一个 mask token [M]，让模型预测该位置为 "1"（相关）或 "0"（不相关）的概率
  • 得分公式：s(q,di​)=p1​/(p0​+p1​)
  • 各文档得分独立计算后排序

Logit-based Listwise 策略 (DiffuRank_Logits-List)

  • 将多个文档放入同一个 prompt，每个文档对应一个 mask 位置
  • 一次前向传播同时获得所有文档的相关性得分
  • 文档间无序列依赖，所有得分并行计算
  • 对于长文档列表采用滑动窗口策略

Permutation-based Listwise 策略（两个变体）

Perm-Samp（采样式）：通过多步去噪迭代生成排列。采用约束采样算法——维护可行标识符集合，每步基于置信度贪心分配，避免重复。参数 K 控制采样步数（效率-效果权衡）。

Perm-Assign（分配式）：单次前向传播生成 N×N 概率矩阵，将排序建模为二部图匹配问题，用匈牙利算法求解最优分配，一步到位得到最终排列。

3. 核心技术贡献

3.1 首次系统验证 dLLMs 在 IR 任务上的可行性

这是第一篇将扩散语言模型用于文档重排序的工作，填补了 dLLMs 在信息检索领域的空白。

3.2 约束采样算法 (Constrained Sampling)

这是最具工程价值的贡献之一。实验表明，朴素的采样策略只能产生 16.54% 合法排列（存在大量重复标识符），而约束采样达到 100% 合法输出率，同时显著提升性能。具体做法是：

  • 维护可行标识符集合 Ut​
  • 每步根据置信度得分动态贪心分配
  • 同时保证位置唯一性和标识符唯一性约束

3.3 将排序建模为匹配问题

Perm-Assign 变体将重排序转化为最优分配问题：构造代价矩阵 Cij​=−logPij​，用匈牙利算法 O(N3) 求解。这完全绕过了自回归生成的顺序依赖，是一个优雅的范式转换。

3.4 结构感知的训练策略

  • DocID-aware masking：训练时只对文档标识符位置做 mask，而非随机 mask 所有 token。这让模型专注于学习排序信号而非语言建模。
  • RankNet loss 替代 Cross-Entropy：实验证明 RankNet 在排序任务上一致优于 CE loss（DL19 上 +2.5 NDCG@10）。
  • RoPE scaling 支持 16K 上下文长度，适应长文档列表。

4. 实验结果分析

评测设置

  • 数据集：TREC DL19、DL20 + BEIR（8个子集：Covid、NFCorpus、Touche、DBPedia、SciFact、Signal1M、News、Robust04）
  • 指标：NDCG@10
  • 候选集：BM25 top-100
  • 基线：LLaMA-3.1-8B、Qwen3-8B 等同等规模自回归模型

Zero-shot 结果

DiffuRank_Logits-List48.27
DiffuRank_Perm-Assign49.30
自回归 LLM 基线~48-49

关键发现：dLLMs 在零样本设置下已可媲美自回归 LLM，其中 Perm-Assign 表现最优。

Fine-tuned 结果（40K MS MARCO 样本，LoRA 微调）

DiffuRank_Perm-Samp55.10

微调后 DiffuRank 的 permutation 变体全面超越自回归基线，且展现出强跨域泛化能力（在 MS MARCO 上训练，在 BEIR 多领域数据集上测试）。

效率分析

最亮眼的结果：DiffuRank_Perm-Samp 在 K=2 步时，性能已超越两个自回归 LLM 基线，而延迟不到后者的三分之一。 Perm-Assign 更是单次前向传播即可完成排序。

行为分析

模型展现出粗到细（coarse-to-fine） 的排序策略：

  • 早期步骤：先确定最相关和最不相关的文档（解决排名两端）
  • 中间步骤：精细化中间区域的模糊排序
  • 最终步骤：确定性地完成剩余位置

这与人类的排序直觉高度吻合。

5. 局限与未来方向

当前局限

  1. 模型生态不成熟：dLLMs 目前的预训练模型选择远少于自回归 LLM（论文主要基于 DREAM 等少数模型），模型规模也相对有限，尚无 70B+ 级别的 dLLM。
  1. 上下文窗口受限：虽然用了 RoPE scaling 支持 16K，但在需要处理大量长文档的 listwise 重排序中，上下文容量仍是瓶颈。
  1. Pointwise 和 Logit-based 方法相对弱：实验中 permutation-based 方法明显优于前两种，说明简单的评分方式未能充分发挥 dLLMs 的优势。
  1. 训练数据依赖：微调需要 MS MARCO 等监督数据，零样本性能虽可用但仍有差距。

未来方向

  • 更大规模 dLLM 预训练：随着 dLLM 基础模型的进步（更大规模、更好的预训练），排序性能有望进一步提升。
  • 可微松弛（differentiable relaxations）：论文提到可探索连续松弛方法替代离散的匈牙利算法，实现端到端可微训练。
  • 更丰富的约束融合：将业务约束（如多样性、新鲜度、公平性）直接编码到扩散过程中。
  • 多阶段排序流水线整合：将 dLLM 与传统检索模型（如双塔、cross-encoder）更深度地集成。

6. 工业实践意义

6.1 精排延迟优化的新思路

对于搜索/推荐系统的精排阶段，延迟是核心约束。DiffuRank 的并行解码特性提供了一条从根本上降低 LLM-reranker 延迟的路径。特别是 Perm-Assign（单次前向传播 + 匈牙利算法）的范式，延迟接近单次模型推理，远优于逐 token 生成。

6.2 Logit-based Listwise 值得优先探索

在工业场景中，DiffuRank_Logits-List 策略最具落地潜力：

  • 一次前向传播为所有候选文档打分，计算图简单
  • 无需复杂的 prompt 工程来控制输出格式
  • 天然避免了自回归 listwise 方法中的位置偏差问题
  • 可直接替换现有的 cross-encoder 打分模块

6.3 排序建模范式的启示

将排序建模为二部图最优匹配（Perm-Assign）是一个值得深入研究的方向。这种思路可以扩展到：

  • 广告竞价排序：同时考虑广告主约束和用户体验
  • 推荐 re-ranking：在满足多样性、类目均衡等约束的同时优化排序
  • 搜索结果组织：结合分组展示等结构化展现需求

6.4 约束采样的工程价值

约束采样算法解决了一个实际问题：如何保证模型输出的排列合法性。这在工业系统中至关重要——线上系统不能容忍非法输出。该算法的思路（维护可行集 + 贪心分配）也可迁移到其他需要结构化输出的场景。

6.5 对模型选型的启示

这篇论文传递了一个信号：自回归不是 LLM 用于排序的唯一范式。随着 dLLM 生态的成熟（更多预训练模型、更好的推理框架），工业团队应该关注这一技术路线。尤其是在以下场景中 dLLM 可能优于自回归模型：

  • 需要同时评估大量候选（listwise）
  • 延迟约束严格
  • 需要结构化输出保证
  • 排序需要全局一致性（双向注意力的天然优势）

总结：DiffuRank 是一篇开创性的工作，首次系统验证了扩散语言模型在文档重排序中的可行性和优越性。其核心价值不在于当前绝对性能（虽然已经 competitive），而在于打开了一个新的技术范式空间——并行解码 + 双向注意力 + 结构化输出控制，这三者的组合恰好契合排序任务的本质需求。对于搜索/推荐领域的从业者而言，这是一篇值得认真跟踪的方向性工作。
