1. MinT: Managed Infrastructure for Training and Serving Millions of LLMs
4.30
Relevance 4 | Novelty 5 | Practical 5 | Evidence 3 | Timely 5

Summary: MinT 提出一套面向「百万级 LoRA 策略」训练与在线服务的托管基础设施：基座模型常驻、仅将 LoRA adapter revisions 在 rollout、更新、导出、评估、上线、回滚之间流转，将分布式训练、调度、数据移动隐藏在服务接口之后。系统沿 Scale Up（LoRA RL 扩到含 MLA/DSA 注意力的 1T+ 稠密与 MoE 基座）、Scale Down（仅传输 adapter 增量）、Scale Out（多租户共享基座）三轴扩展，覆盖从训练到服务的全生命周期。

Key insight: MinT 把「LoRA-as-a-service」提到平台级：基座驻留 + adapter 流转的模式天然贴合搜索/推荐线上需要并行迭代多个任务专家（rerank、相关性、query 改写）的场景，让团队可以用同一组 frontier 基座承载几百个业务方向的微调策略，显著降低显存与运维成本。在 UGC 搜索里，这种「统一服务 + 多 adapter」架构是把 LLM 引入排序与相关性的关键基建。

2. SOMA: Efficient Multi-turn LLM Serving via Small Language Model
4.10
Relevance 4 | Novelty 4 | Practical 5 | Evidence 3 | Timely 5

Summary: SOMA 针对多轮对话场景：标准做法是把整段历史每轮都拼给大模型，延迟与 API 成本都高。论文提出在会话早期用大模型回答几轮，估计该会话的「局部响应流形」，然后训练一个小模型软提示把它对齐到这一局部区域，后续轮次由小模型代答。这样把成本敏感的 long-context 推理转化为本地化的小模型推理，在多轮基准上以远低于纯大模型的开销保持质量。

Key insight: 对搜索/推荐里的 conversational search、多轮 query 澄清场景非常实用：把代价大头的全历史拼接替换成「会话本地小模型 + 早期大模型蒸馏」，意味着不必为每个用户每轮都打满 LLM。对部署的启示是把「会话级蒸馏」作为线上 LLM 服务的一等公民——按 session 维护轻量代理，是降本提速的明显方向。

3. HEBATRON: A Hebrew-Specialized Open-Weight Mixture-of-Experts Language Model
3.95
Relevance 3 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: Hebatron 基于 NVIDIA Nemotron-3 稀疏 MoE 架构构建希伯来语开源大模型：采用三阶段「由易到难」课程 + 持续抗遗忘锚定的预训练，再用 200 万条希—英双语样本做 SFT。课程序的顺序就贡献了 3 分综合基准提升；最终在希伯来推理任务上拿到 73.8%，超过 DictaLM-3.0-24B-Thinking (68.9%)，并与 Gemma-3-27B-IT 在 GSM8K-HE/Israeli Trivia 上持平，而每次前向只激活 30B 中的 3B 参数，吞吐约提升 9 倍。

Key insight: 对低/中资源语言场景下的「自有大模型」路径很有参考意义：开源 MoE 基座 + 课程式继续预训练 + 抗遗忘锚定，是一条性价比高的本地化方案。对 UGC 社区搜索来说，「小激活参数 + 大总参」的 MoE 推理特征意味着同等 latency 预算下可以塞下更大的语义匹配/排序模型；课程顺序贡献 3 分的实证也提醒我们 data curriculum 是被低估的训练手段。

4. ReAD: Reinforcement-Guided Capability Distillation for Large Language Models
3.65
Relevance 3 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: ReAD 研究「能力蒸馏」在固定 token 预算下的行为，观察到两条规律：蒸馏会带来系统性、与预算相关的跨能力迁移；预算加得过多反而对目标任务收益递减、还会损害其他能力。基于此提出 RL 引导的蒸馏策略，把不同 capability 当成耦合目标动态分配训练样本，避免一刀切的多目标蒸馏方案。

Key insight: 对搜索/推荐里「用小模型承担排序、改写、摘要」这类多能力工作负载有直接价值：盲目堆蒸馏 token 既贵又会让一个能力的提升偷走另一个能力的预算。把蒸馏看成多目标 RL 资源分配问题，是给在线服务用的轻量 LLM 提质降本的更稳健做法。

arXivVanderbiltFSU2026-05-14Xueqi Cheng, Xugui Zhou, Tyler Derr, Yushun Dong
5. FeatCal: Feature Calibration for Post-Merging Models
3.55
Relevance 3 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: Model merging 把多个 task expert 合并成一个模型可省去多模型部署，但合并后通常仍逊于专家。论文把「合并后差距」分解为「特征漂移」：上游传播 + 局部错配。在此理论下提出 FeatCal：用一个很小的校准集，按层在前向顺序里增量校准合并权重，既显著缩小特征漂移、又保留合并带来的部署收益，几乎不增加部署侧成本。

Key insight: 对搜索/推荐里常见的「一个排序模型同时服务多个垂类、多个意图」场景非常合用：与其养 N 个 expert 模型，不如先合并再用小校准集「补一刀」。FeatCal 把模型合并从「近似可用」推到「接近 expert」，是降低 serving 复杂度的同时维持效果的实用工程武器。

6. A Study on Hidden Layer Distillation for Large Language Model Pre-Training
3.45
Relevance 3 | Novelty 3 | Practical 4 | Evidence 4 | Timely 5

Summary: 在算力受控实验下系统对比 Hidden Layer Distillation (HLD) 与 logit-based KD：以 Gemma3 3.4B 为 teacher、123M/735M 学生在 C4 上训练高达 168B tokens。结果显示 HLD 在下游任务上未必持续优于标准 KD；但中间层表示在某些训练阶段确实能注入互补信号。提供了在 decoder-only 大规模预训练里使用 HLD 的实证证据与适用边界。

Key insight: 想给搜索/推荐做「小一号自有 LLM」的团队尤其有用：HLD 在论文层面被吹得很高，这篇做了 168B token 的对照实验，结论谨慎——不要直接拿 HLD 替换 logit KD，要按训练阶段、teacher/student 容量比来挑。预训练蒸馏的成本曲线很贵，知道边界才能避免无效消耗。

arXivGoogle2026-05-14Maxime Guigon, Lucas Dixon, Michaël E. Sander
7. Freeze Deep, Train Shallow: Interpretable Layer Allocation for Continued Pre-Training
3.40
Relevance 3 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 持续预训练里「冻哪层、训哪层」通常靠经验。论文提出 LayerTracer：一种架构无关的诊断框架，通过定位任务执行位置和量化层敏感度，揭示分层表示的演化与稳定性。实验显示深层是「任务执行关键区」且对扰动更稳定；据此对照三种 freeze-train 策略，结论是「冻深层、训浅层」在效率和效果之间提供更可解释的折中。

Key insight: 对在通用 LLM 上做「领域继续预训练」的搜索/推荐团队很有用：继续预训练动不动跑几百小时 GPU，不该靠盲调。LayerTracer 给出了一个可量化的诊断工具，告诉你哪些层是「业务知识承载层」。把这套诊断接进训练前的体检流程，是少花冤枉算力的明显操作。

8. Qwen-Image-VAE-2.0 Technical Report
3.30
Relevance 2 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: Qwen-Image-VAE-2.0 是一组高压缩比 VAE：采用 Global Skip Connections 与扩展潜空间通道，在数十亿图像上训练并加入合成渲染引擎以提升文字密集场景；用语义对齐策略改善高维潜空间的扩散收敛；编码-解码骨干刻意非对称且免注意力，以最小化编码计算。在重建保真度与「可扩散性」上同步显著超越前代，并开源权重。

Key insight: 对多模态社区搜索（含图文帖）有用：高压缩 VAE 是端到端多模态搜索/生成的基础设施，谁能把潜空间做得「既小又好扩散」，谁就能压缩多模态检索特征。Qwen 把「VAE 编码器不要 attention」做成默认选择，这种「为吞吐做减法」的工程取向值得 serving 团队关注。

9. AnyFlow: Any-Step Video Diffusion Model with On-Policy Flow Map Distillation
3.15
Relevance 2 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 针对「few-step 视频扩散」在加大采样步数时质量反而退化的问题，AnyFlow 提出基于 flow map 的 any-step 蒸馏框架：把蒸馏目标从端点一致性切到完整 ODE 采样轨迹，配 on-policy 采样让 student 沿教师轨迹自我探索。结果是单一 student 在 1 步到多步上都可用，扩展了视频扩散在测试期的算力-质量曲线。

Key insight: 对短视频/UGC 视频内容平台关注的「端侧/服务侧视频生成」有借鉴价值：把 few-step 蒸馏从「只为一个步数 optimize」做成「沿轨迹 optimize」，是把推理时 budget 当成可滑动旋钮的工程范式。一条 student 适配多套 latency 预算，对动态算力调度极友好。
