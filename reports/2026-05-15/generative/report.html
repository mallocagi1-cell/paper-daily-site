EcoGEO: Trajectory-Aware Evidence Ecosystems for Web-Enabled LLM Search Agents

本文提出 EcoGEO，将传统针对单页面的 Generative Engine Optimization 扩展到 web-enabled LLM 搜索 Agent 的多步浏览轨迹场景。作者设计 TRACE 框架，在给定推荐 query 与目标产品后，构建受控的 Evidence 生态系统，通过协同布置多个互链页面、调整证据出现位置与关联结构，影响 Agent 在多步 retrieve→follow→reformulate 过程中聚合的最终结论。实验在多种主流 LLM Agent 上显示，相比 page-level GEO，TRACE 显著提升了目标产品被 Agent 推荐的概率。

EcoGEO 深度解读

1. 问题与动机

随着 GPT-5.1 这类具备网页浏览能力的 LLM Agent 接管真实搜索场景，传统 SEO/GEO 的优化对象已经从「单个落地页」迁移为「Agent 在多步访问中的整条浏览轨迹」。已有 Generative Engine Optimization (GEO) 研究（如 C-SEO、E-GEO、AutoGEO）的核心假设依然是单页面：把目标内容塞进单文档里，希望它在 1 次召回里被采纳。但 Agent 实际上会做最多 5 次 search + 5 次 crawl 这样的多步交互——issuance、follow-link、reformulate、聚合证据——单页优化的 lever 与之并不匹配。论文用一个简单的对照实验定量描述这种 gap：在 E-GEO 数据集上，单页基线 final recommendation rate 仅 59.0%，且 internal-link crawl 几乎为 0，意味着 Agent 在浏览中根本「走不进来」单页系统设计的影响范围。

由此作者把 GEO 重写为 ecosystem-level influence 问题，研究 page content、page-to-page 结构、轨迹经过点位三者如何协同放大 Agent 端的被推荐概率，并构造受控环境严格验证这一新设定的可优化性。

2. 方法详解

作者提出 TRACE（Trajectory-Aware Coordinated Evidence Ecosystem），核心做法是为每个目标产品构造一张「证据图」：

  • 一个 navigation entry page v₀：表面伪装为「评估指南」/「选购对比」等中立 hub，而非赤裸宣传的产品页。它的关键作用是创造下一步动作的 affordance——给 Agent 一个明确的「下一跳」选择列表。
  • 一个由 6 个 role-specialized support pages 组成的 V_s 集合：official、review、expert、news、forum、social。每个角色对应一种 Agent 在多步检索中倾向消化的证据风格。

TRACE 的两层协调机制：(i) Attribute consistency——目标产品在所有 page 上保留一致的「身份属性」（型号、参数、关键卖点），让 Agent 在多源比对时认得是同一个对象、不会因细节漂移触发自我否定；(ii) Internal cross-referencing——review 引官方规格、expert 引行业数据、forum 引 review 评论，编织出 Agent 可沿链路展开的「证据网」。

测试环境是 "9+1" controlled exposure：合成的目标结果被插入到真实 Google Search API 9 条结果的第 5 位；对目标后的 follow-up 查询，TRACE 的 ecosystem 页面按语义相似度替换第 9 位。Agent 采用 GPT-5.1，预算最多 5 次 query + 5 次 crawl。基线包括纯单页、C-SEO、E-GEO、AutoGEO，所有方法共享同一搜索预算与暴露协议，保证「优化对象」是唯一变量。

3. 核心技术贡献

  1. 重新定义优化对象：从 page-level 的内容补写跨到 ecosystem-level 的轨迹环境构造。这一抽象使得「结构」和「连接」第一次成为一阶 lever；过往 GEO 几乎只动 page content。
  1. Navigation entry + role-specialized support 的双层设计：通过 ablation 证明 navigation page 贡献最大——在 SafeSearch 上 internal-link crawl 从 0% 提升到 29.7%。这说明 Agent 跳转行为是个稀缺资源，谁能提供更便利的 affordance 谁就能截走更多浏览。
  1. OPR-Bench 数据集：3,124 个 query-product pair (SafeSearch 64 + E-Commerce 121 + E-GEO 2,939)，用 fictional product 避免真实产品 leak 与伦理风险，是这类研究的方法论贡献——保证实验可复现、可对照。
  1. 可分离的指标体系：除了 final recommendation rate，还监控 Initial Target-Result Crawl、Target-Specific Second Search、Internal-Link Crawl 三项轨迹指标，允许把「为什么 TRACE 涨」拆解到具体行为层面。

4. 实验结果分析

最终推荐率（vs. 最强 page-level 基线）：

数据集TRACE最强基线绝对涨幅
SafeSearch67.2%35.9%+31.3
E-Commerce71.9%56.2%+15.7
E-GEO73.9%59.0%+14.9

轨迹指标（E-GEO）：

  • Initial Target-Result Crawl: 48.9% (TRACE) vs 27.0% (single-page)
  • Target-Specific Second Search: 21.9% vs 11.0%
  • Internal-Link Crawl: 20.4% (TRACE 独有，基线为 0)

Ablation（强制初次抓取，剥离暴露因素）：

  • Uncoordinated multi-page → coordinated：SafeSearch 75.0% → 82.8%；E-Commerce 81.8% → 87.6%。证明多页协调本身就能加分。
  • Coordinated → TRACE（加 navigation page）：SafeSearch 82.8% → 89.1%；E-Commerce 87.6% → 93.4%；同时 internal-link crawl 跃升至 29.7% / 25.6%。说明 navigation page 的影响主要来自「给 Agent 主动跳转的入口」，而不是单纯内容更多。

值得关注的反直觉点是：E-Commerce 在最强 page-level 基线下已能拿到 56.2%，TRACE 涨 15.7 个点；SafeSearch 单页基线只有 35.9%、TRACE 涨 31.3 点——越是难影响的高门槛 query，ecosystem-level lever 越突出。这暗示 page-level GEO 已临近天花板，未来增益空间几乎都在结构层。

5. 局限与未来方向

作者明确指出三类局限：

  1. 全部使用虚构产品 + 受控环境，没有覆盖真实排名波动、Organic discovery、时效衰减等动态因素；
  2. 仅研究了一类 evidence ecosystem 结构（navigation + 6 角色 support），support page 数量、多样性、链接密度的影响尚未系统消融；
  3. 出于伦理考虑没有在公开 web 部署，所有评测都在合成环境完成，方法的真实环境鲁棒性未知。

需要补充观察的是：实验 Agent 只用了 GPT-5.1，未横跨 reasoning/non-reasoning 模型，也没考察国内 Agent（如基于 Qwen、DeepSeek 的浏览 Agent）的行为差异；Agent 改预算（如 10+10）下 TRACE 的边际收益是否衰减也未做。

6. 工业实践意义

对搜索/推荐侧团队，本文最直接的两条 takeaway：

  1. 「Agent-friendly site structure」开始成为流量获取的新 surface：传统 SEO 关注关键词与单页可读性，未来 Agent 优化的核心是为 LLM Agent 的多步行为铺出可走的路——hub 页 + 角色化 support + 互相引用。对内容平台/电商/UGC 社区，这意味着内容运营从「单帖优化」迁移到「话题生态构建」。
  1. 召回/排序系统要重新定义"target"：当 Agent 是真正的消费者时，"被点击/被采纳"的最小单位不再是一条结果，而是一组互联的结果簇。对社区搜索来说，应当考虑把"同主题、互相引用"的多个帖子打包成一个 cluster 候选，rerank 阶段直接评估 cluster-level 的轨迹友好度，而不是 doc-level 的独立得分。

部署层面，TRACE 的方法不需要训练任何新模型（all training-free），只是改 site map + page template，但前提是站点本身允许批量改造页面与互链结构——对老旧 CMS 是工程量大于算法的事。另一个隐含成本是：navigation entry page 必须看起来"中立"，过度自我推销会触发 Agent 端的反垃圾/反 prompt-injection 启发式（GPT-5.1 已经具备），所以内容写作上是一门"避免被识破"的工艺，工业部署需配合 Agent-side 行为监控来动态调整。

最后注意：本文方法在伦理上接近 prompt injection / SEO grey-hat 边界，企业实际采用前需要法务与 trust&safety 评估，避免触发平台反作弊系统或合规问题。

Retrieval is Cheap, Show Me the Code: Executable Multi-Hop Reasoning for Retrieval-Augmented Generation

本文针对多跳 RAG 中自由文本推理状态不显式、retrieval query 漂移以及自我反思不可靠的问题，提出 PyRAG，把多跳 RAG 重写成程序合成与执行问题。模型生成一段 Python 程序，将 retrieval 调用、实体绑定、子问题串联固化为代码，由解释器逐步执行检索与计算并显式记录中间状态。在多跳 QA 基准上，PyRAG 在准确率与 retrieval 调用效率上相对自由形式 ReAct 类基线获得稳定提升，并自然引出可验证的执行轨迹。

INSIGHT将「reasoning over retrieval」从自由文本范式切换到「可执行程序」范式，是生成式搜索一个重要的工程化方向：中间状态、变量、检索意图全部显式可控，自然支持单步重试、debug、并行化。对社区搜索场景，可以用代码化的多跳意图（如「先按用户找帖子→再按帖子聚合评论→最后过滤时间窗」）来取代纯文本 query rewriting，让 LLM-as-orchestrator 在保证准确率的同时把单次大模型调用替换成大量便宜的 retrieve+小模型 step。

Granite Embedding Multilingual R2 Models

IBM

IBM 发布 Granite Embedding R2 多语言系列：基于 ModernBERT 架构、扩展多语言词表，支持 200+ 语种与代码，上下文窗口扩展到 32,768 token（相比 R1 提升 64x）。提供 311M 完整模型与 97M 压缩模型，后者通过模型剪枝与词表选择得到，在 100M 参数以下的开源多语言 embedding 中达到 SOTA。完整模型支持 Matryoshka 表示学习，可灵活调整嵌入维度。在多语言/跨语言文本搜索、代码检索、长文档搜索与 reasoning retrieval 等综合任务上获得领先。

INSIGHT对落地侧最实用的一项工作之一：32K 上下文+200 语种+Matryoshka 多维度切片+开源，几乎覆盖企业级 dense retrieval 的所有刚需。对社区搜索而言，<100M 的压缩版本可以替代当前线上 BERT 召回塔，在不显著加机器的前提下吃掉跨语种、长帖正文、代码片段三类边角流量；Matryoshka 维度切片对 ANN 索引规模也是直接的成本节省。是少见的「可以直接拿来上线评测」的研究侧 release。

ViDR: Grounding Multimodal Deep Research Reports in Source Visual Evidence

ViDR 是一个 multimodal deep research 框架，强调把源图作为可检索、可路由、可验证的证据对象，而不是 LLM 自己生成图表来「装饰」。系统会先构造 evidence-indexed outline 把声明与图文证据连接，再用 context-aware 过滤、outline-aware 重排和 VLM 视觉分析把网页图像精炼为「source figure evidence atoms」，并按 section 选择对应证据生成报告。论文还提出图引用是否落地的校验机制，避免生成阶段的图文错配。

INSIGHT对生成式搜索/Deep Research 系统而言，本文给出了多模态证据从「检索 → 重排 → 路由 → 校验」的完整 pipeline。社区场景里大量内容是图文混合（截图、表情包、产品图），通常的纯文本 RAG 会把图变成 alt text 弱信号；ViDR 的做法提示可以把贴子内图像建索引、与文本证据对齐，并在生成阶段为每段答案绑定显式 figure 引用，对解决 UGC 搜索结果可验证性、降低幻觉非常直接。

Utility-Oriented Visual Evidence Selection for Multimodal Retrieval-Augmented Generation

本文从信息论视角重新定义多模态 RAG 中的「视觉证据选择」：把证据效用定义为它对模型输出分布的信息增益，而不是与 query 的语义/表面相似度。为绕开 answer-space 优化的不可解性，作者引入隐变量「证据有用性」，理论上证明用其上的信息增益排序等价于 answer-space utility，再用轻量多模态模型代理估计该增益，得到一个 training-free 框架。在 MRAG-Bench 与 Visual-RAG 多个模型族上取得稳定提升。

INSIGHT把检索证据排序从「相似度」升级到「对生成结果的信息增益」，对社区搜索这种多模态 RAG 场景非常关键：在 UGC 中往往大量图片视觉接近 query，但对最终回答几乎无信息贡献。该范式给出了 training-free 的轻量化做法，可以叠加在现有图文召回之后做 utility-reranker，相比训一版重排模型成本极低；同时为「召回相关性 ≠ 生成有用性」这一长期工业痛点提供了可量化的中间指标。

Weiqing Luo, Zongye Hu, Xiao Wang, Zhiyuan Yu, Haofeng Zhang, Ziyi Huang

LeanSearch v2: Global Premise Retrieval for Lean 4 Theorem Proving

LeanSearch v2 提出「global premise retrieval」任务：为整条定理一次性返回所需的所有引理集合，而不是单步选一个或单 query 召回。系统包含两个模式：standard 模式用 hierarchy-informalized Mathlib 语料 + embedding-reranker，在单 query 上 nDCG@10 达到 0.62 (上一代 SOTA 0.53)；reasoning 模式以 standard 为底，通过 sketch→retrieve→reflect 多轮循环逼近完整 premise set。在 69 个研究级 Mathlib benchmark 上显著优于一阶检索基线。

INSIGHT这是一个干净的「生成式搜索 + 迭代检索」案例：把「找答案」拆为先粗草稿→检索→反思→再补检索的循环。对社区搜索/QA 系统的迁移价值在于：很多用户的复合意图（例如「找一组互相印证的帖子」）天然适合 sketch-retrieve-reflect 形式，而不是单 query/单结果。论文里 informalized 知识表示 + embedding+reranker 的两段式还示范了如何把符号化领域知识转写成检索语料，对垂类社区（医疗、法律、技术问答）有直接借鉴价值。

Guoxiong Gao, Zeming Sun, Jiedong Jiang, Yutong Wang, Jingda Xu, Peihao Wu, Bryan Dai, Bin Dong

Many-Shot CoT-ICL: Making In-Context Learning Truly Learn

本文系统研究 reasoning 任务下的 many-shot CoT-ICL，发现非 reasoning 任务的经验在 reasoning 场景并不成立。关键结论：(i) 增加 CoT demonstration 数量对非 reasoning LLM 不稳定，主要提升 reasoning-oriented LLM；(ii) 基于相似度的 example retrieval 在 reasoning 任务上反而失效，因为「语义相似」并不预示「过程上 (CoT) 兼容」；(iii) 存在 order-scaling 现象，demonstration 顺序对长上下文稳定性显著。

INSIGHT对生成式搜索的检索增强提示工程是一记警钟：检索召回 example 时常用的「语义相似」假设在涉及推理任务时会引入噪声，应改为「过程兼容性 / 解题模板相似」作为 reranker 信号。社区搜索里如复杂 query 的 query-rewriting、多步意图分解，从 1-shot 升级到 many-shot CoT 时需要重新设计 example 池与排序方式，否则越多 shot 性能反而下降，这一陷阱在文章里有直接实验证据。

Training Long-Context Vision-Language Models Effectively with Generalization Beyond 128K Context

本文系统研究 LVLM 的长上下文 continued pre-training，将一个 7B 模型从 32K 扩展到 128K。三条关键发现：(i) 长文 VQA 的训练效果显著优于 OCR 转写式任务；(ii) 序列长度分布上，均衡分布比集中在目标长度（如 128K）效果更好，说明长上下文能力本质上是「跨位置可泛化的关键信息检索」；(iii) 在多种数据 mixture 配比下，retrieval 仍是主要瓶颈。模型在 128K 以上仍保持泛化能力。

INSIGHT对生成式搜索 + 多模态 RAG 是非常实用的训练 recipe：长上下文不是堆 128K 数据就能涨，关键是构造跨长度、跨位置的「关键信息检索」型监督。把 retrieval 当作 long-context 任务底座这一点也直接呼应工业实践——所谓 long-context LVLM 其本质仍是「内部检索引擎」。社区搜索若需训自己的长帖/长评论理解模型，可以按文中均衡长度分布 + 长文 VQA 化目标的方式构造监督数据。

Context Training with Active Information Seeking

本文为 context optimization 加入主动信息获取能力：在不更新模型权重的前提下，让 LLM 通过 Wikipedia 检索与浏览器工具主动找新信息。作者发现简单地把工具拼到顺序 context optimization 流水线里反而降低效果；只有配合「保留并剪枝多个候选 context」的 search-based 训练流程，主动信息获取才能稳定带来增益。在低资源翻译 (Flores+)、健康场景等多领域得到一致提升。

INSIGHT这篇是「检索 + 生成」联合优化思路里很有工业味的一篇：得到的不是新模型，而是一组优化后的 context（包含主动收集到的外部知识）。对社区搜索的启示是，不必每个新词条/新热点都微调底层模型，可以走 context-bank + 主动 retrieve 的轻量路径，但必须配合多候选 + 剪枝的搜索式训练流程，否则会被工具噪声带偏。这给「插件化 / 业务知识注入」做了一种可复用的方法学。

MAP: A Map-then-Act Paradigm for Long-Horizon Interactive Agent Reasoning

MAP 针对当前交互式 LLM Agent「边走边猜环境」的 Delayed Environmental Perception 问题，提出先 Map 再 Act 的范式：(1) Global Exploration 获取环境通用先验；(2) Task-Specific Mapping 构建结构化认知地图；(3) Knowledge-Augmented Execution 在地图上下文中执行任务。该框架是插件式的、模型无关。在 ARC-AGI-3 上，MAP 让前沿模型在 25 个游戏环境中的 22 个超过此前接近零的基线表现。

INSIGHT「先建地图再行动」是对 ReAct 风格 Agent 一个干净的反转，对生成式搜索/Deep Research 场景尤其重要：搜索 Agent 在第一次访问站点时往往不停被结构骗到（无限滚动、广告、相关推荐），而真正高效的是先做一次站点结构与内容拓扑的 prior 提取，再针对当前 query 构造可执行 plan。对社区搜索 Agent，可对应到「先对当前社区的内容分布与互动结构构图，再在图上做用户 query 的 mapping → execution」，可大幅减少多步 trial-and-error。

Yuxin Liu, Ziang Ye, Yueqing Sun, Mingye Zhu, Jinwei Xiao
