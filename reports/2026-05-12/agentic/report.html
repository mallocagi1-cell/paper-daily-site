1. LLM-Based Agents for Competitive Landscape Mapping in Drug Asset Due Diligence
3.75
Relevance 4 | Novelty 3 | Practical 4 | Evidence 4 | Timely 4

Summary: 针对生物医药 VC 的竞品挖掘场景，文章构建并 benchmark 了一个 agentic 检索系统：给定适应症，agent 在 paywalled、碎片化、本体不一致、多别名的多源数据中召回所有竞争药物并抽取标准属性。作者用 5 年 VC 内部备忘录通过 LLM agent 生成结构化评测语料，给出召回率/属性正确率对照，证明现有 LLM agent 在长尾别名召回上存在系统性缺口。

Key insight: 对社区搜索的启示在于：当语料分布是 UGC、别名重、本体破碎时，单轮 LLM 检索远不够，应把 agent 设计成迭代召回 + 实体规范化 + 来源融合的多阶段流水线。论文把 LLM 既作为生产者（系统）又作为评估者（语料构造）的双重角色用法可复用到 query 同义改写与 hard-case 评测集自动构建上。

2. ScrapeGraphAI-100k: Dataset for Schema-Constrained LLM Generation
3.75
Relevance 4 | Novelty 3 | Practical 4 | Evidence 4 | Timely 4

Summary: 作者发布了 ScrapeGraphAI-100k，包含 93,695 条 schema-constrained 抽取事件（来自 9M 条原始日志去重平衡后），覆盖 18,000+ 唯一 schema、15 种语言（英文与繁体中文占 88%）。每条样本配齐 Markdown 页面、prompt、schema、LLM 回复以及 jsonschema-rs 结构合规标签，为工具调用、结构化抽取、KB 构建提供首个大规模真实评测语料。

Key insight: Schema-constrained 生成是 Agent 工具调用的基础能力。对搜索方向的可借鉴点：可仿照该数据构造方式，把社区站点的 query 解析、card 抽卡、属性面板的输出格式包装成 schema 约束任务，并通过结构合规率而非自由文本质量做线上 grading，让 LLM 在召回/重排链路里输出可消费 JSON。

arXivScrapeGraphAI2026-05-11William Brach, Francesco Zuppichini, Marco Vinciguerra, Lorenzo Padoan
3. Securing Computer-Use Agents: A Unified Architecture-Lifecycle Framework for Deployment-Grounded Reliability
3.70
Relevance 3 | Novelty 4 | Practical 4 | Evidence 3 | Timely 5

Summary: 面向已经进入真实软件环境的 Computer-Use Agent（CUA），论文提出统一的 architecture-lifecycle 框架。架构维度将 Perception/Decision/Execution 视作把观察转换为带权动作的耦合层；生命周期维度沿 capability formation → authority exposure → failure manifestation → control placement 串联可靠性问题，给出去过 benchmark 化、可部署可控的可靠性视图。

Key insight: 对社区平台越来越多的 agent 化检索/对话功能，论文给出的『权限暴露面 + 失败模式 + 控制点放置』分析法可直接用于搜索 agent 的安全审查。尤其是 perception drift（OCR/截图理解错位）与 planning drift（多轮搜索越走越偏）两个 failure mode，能映射到社区搜索 agent 设计时的护栏与回退策略。

4. MedExAgent: Training LLM Agents to Ask, Examine, and Diagnose in Noisy Clinical Environments
3.55
Relevance 3 | Novelty 4 | Practical 3 | Evidence 4 | Timely 5

Summary: 论文把临床诊断形式化为部分可观察 MDP，三类动作分别是『向患者提问 / 调用医学检查工具 / 给出诊断』。作者引入包含 7 种患者噪声的系统噪声模型，并训练 MedExAgent 在多轮、含噪、不完整信息下做出主动信息收集与工具调用决策，跑出明显优于单轮 QA 与无噪 baseline 的表现。

Key insight: 把『多轮检索 + 工具调用 + 输出最终答案』套到 POMDP 形式，是当下 search agent / deep research 的通用建模。社区搜索可以借鉴其『主动提问能力 + 噪声鲁棒训练』思路：把模糊 query 改写、追问澄清、调用 retrieval / KB / spam-filter 工具作为动作空间，并加入 UGC 噪声模型（拼写错误、表情、隐式上下文）做 RL 微调。

5. MIST: Multimodal Interactive Speech-based Tool-calling Conversational Assistants for Smart Homes
3.55
Relevance 3 | Novelty 3 | Practical 4 | Evidence 4 | Timely 5

Summary: MIST 是一个合成的多轮、语音驱动的 IoT 工具调用代码生成数据集，要求 LLM 在时空约束、动态状态、混合主动交互下输出可执行调度代码。开源与闭源多模态 LLM 在 MIST 上拉开明显 gap，即便最前沿的闭源模型仍有大幅 headroom，论文同时发布可扩展的数据生成框架。

6. A Comprehensive Survey on Agent Skills: Taxonomy, Techniques, and Applications
3.45
Relevance 3 | Novelty 3 | Practical 4 | Evidence 3 | Timely 5

Summary: 围绕 OpenClaw、Claude Code 这类系统兴起的『agent skills』，作者提出 skills 作为可复用的过程性 artifact，在 tool/memory/runtime context 之上做任务约束。综述给出从 reasoning-only 到 skill-driven 的演进、分类学（按可复用性、可编排性、安全边界）以及典型应用，把 agent 与 skill 视为高层规划 vs 操作层执行的互补结构。

Key insight: 对搜索/推荐工程团队的价值在于：与其每次都让 LLM 从头规划检索流程，不如把『相关性诊断 → query 改写 → 多 source 召回 → 重排』固化成 skill 包，agent 仅负责挑选 skill 与拼接，能显著降低 token 成本与 drift。论文的 skill 分类学给出了构建公司内 skill registry 的起手框架。

7. GSM-SEM: Benchmark and Framework for Generating Semantically Variant Augmentations
3.25
Relevance 2 | Novelty 4 | Practical 3 | Evidence 4 | Timely 5

Summary: 针对 GSM8K 等数学推理 benchmark 因测试集记忆导致排行榜虚高的问题，GSM-SEM 提出一种语义变体生成框架，通过修改实体/属性/关系扰动题面但保留原解法与答案，并支持每次运行生成新变体而无需重新人工标注。论文给出多家模型在 GSM-SEM 与原 benchmark 上的显著掉点，并量化各扰动维度对模型脆性的贡献。

Key insight: 对 search agent 的『可信评测』有直接借鉴：把社区搜索 agent 的 query 改写为语义变体，要求模型在变体上保持判断稳定性，可作为 agent 鲁棒性指标。这种『stochastic benchmark』思路相比静态评测更难被微调期间间接拟合，适合在 retrieval/重排模型迭代里加入 hard-case 自动扩样链路。

8. From Surface Learning to Deep Understanding: A Grounded AI Tutoring System for Moodle
3.20

9. Cognitive Agent Compilation for Explicit Problem Solver Modeling
3.15
Relevance 2 | Novelty 4 | Practical 3 | Evidence 3 | Timely 5

Summary: 受经典认知架构启发，作者提出 Cognitive Agent Compilation (CAC)：用强教师 LLM 把问题求解知识『编译』到一个显式的目标 agent，并把（i）知识表示、（ii）求解策略、（iii）验证与更新规则三者分离，得到可检视、可编辑的有边界求解器。早期 PoC 在小语言模型上跑通。

Key insight: 搜索/推荐里也有类似的『行为可解释 + 可编辑』需求，例如运营要能直接修改 query 改写逻辑或重排规则。CAC 的『知识 / 策略 / 校验』三段式蒸馏路径可作为把大模型经验逐步固化到可治理小模型的范式，比传统 prompt-only 落地更适合长期维护。

10. VDCook: DIY Video Data Cook Your MLLMs
3.10
Relevance 3 | Novelty 3 | Practical 3 | Evidence 3 | Timely 4

Summary: VDCook 是一个自演化的视频数据 OS：用户用自然语言下达数据需求（规模、检索-合成比例、质量阈值），系统并行执行真实视频召回与受控合成，最终输出带 provenance、metadata、可复现 Notebook 的数据包。底层基于 MCP（Model Context Protocol）做数据接入，使数据集从一次性产物变成持续演化的生态。
