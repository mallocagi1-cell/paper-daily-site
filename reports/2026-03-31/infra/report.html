Extending Puzzle for Mixture-of-Experts Reasoning Models with Application to GPT-OSS Acceleration

本文将 Puzzle（一种后训练神经架构搜索框架）扩展应用于 MoE 推理模型 gpt-oss-120B，生成部署优化版本 gpt-oss-puzzle-88B。方法融合了异构 MoE 专家剪枝、选择性窗口注意力替换全上下文注意力、FP8 KV-cache 量化（带校准缩放因子），以及后训练强化学习恢复精度。在 8×H100 节点上，长上下文场景实现 1.63× 吞吐提升，短上下文 1.22×；单卡 H100 上实现 2.82× 加速。该工作展示了系统化的 MoE 模型压缩与部署优化流水线。

SonicMoE: Accelerating MoE with IO and Tile-aware Optimizations

UC BerkeleyTTogether AIPPrinceton

本文针对 MoE 模型推理中的两大瓶颈——细粒度专家带来的激活显存膨胀与 IO 开销增大，以及稀疏专家导致 Grouped GEMM 中的 padding 浪费——提出 SonicMoE 优化方案。核心技术包括：(1) 内存高效的前向/反向计算算法，最小化激活缓存；(2) GPU 内核级 IO 与计算重叠优化，适用于所有 MoE 架构；(3) 新颖的 token rounding 策略减少 padding 浪费。该工作来自 FlashAttention 作者 Tri Dao 团队，具有很强的工程实践价值。

INSIGHTSonicMoE 的核心创新在于从 GPU 内核层面解决 MoE 的效率问题。当前 MoE 趋势是更多更小的专家（细粒度）和更高稀疏度，这虽然提升模型质量但严重降低硬件利用率。SonicMoE 通过 IO-computation overlap 内核设计和 tile-aware token rounding 直接在算子层面提升效率。对搜索/推荐系统部署 MoE 模型的启示：选择推理框架时应关注其 MoE 内核实现质量，细粒度 MoE 的性能瓶颈往往不在计算量而在 IO。

Wentao Guo, Mayank Mishra, Xinle Cheng, Ion Stoica, Tri Dao

Route Experts by Sequence, not by Token

MITYale

本文提出 SeqTopK，一种将 MoE 专家预算从 token 级别转移到序列级别的最小化修改方案。标准 TopK 路由为每个 token 分配固定数量的专家，忽略了 token 复杂度差异。SeqTopK 在序列中所有 T 个 token 上选择 top T×K 个专家，实现端到端学习的动态分配——为困难 token 分配更多专家，简单 token 分配更少。该方法仅需几行代码修改，额外开销不到 1%，且兼容预训练 MoE 模型。在数学、编程、法律、写作等任务上均有一致提升。

INSIGHTSeqTopK 的设计哲学极其简洁：不改变总计算预算，只改变分配粒度（从 token 级到 sequence 级）。这让模型自动学会把计算资源集中在真正需要的 token 上。对搜索/推荐系统的实践意义：(1) 已部署的 MoE 模型可零成本切换到 SeqTopK 路由，无需重训；(2) 在 query 理解等任务中，关键词往往只占少数 token，序列级路由能更好地分配计算资源；(3) 仅几行代码的修改降低了采用门槛。

KALAVAI: Predicting When Independent Specialist Fusion Works -- A Quantitative Model for Post-Hoc Cooperative LLM Training

本文提出 KALAVAI 协议，可预测独立训练的领域专家模型融合后的性能增益：gain = 0.82 × divergence - 2.72（R²=0.856）。在 410M 到 6.9B 参数规模下验证一致性（+6.5%~+7.7%），跨语言融合（Tamil/Yoruba/Welsh/Code）达到 +21.76%，Yoruba 困惑度从 41.9 降至 7.7。20 个贡献者联邦训练实现 +16.71%。该协议使用 DiLoCo 分布式合并，仅需 500 步轻量 MoE 路由训练。

INSIGHTKALAVAI 最大的实用价值在于提供了一个可预测的融合增益公式——在投入计算资源之前就能估算合作训练的收益。对搜索/推荐系统的启示：(1) 多个团队独立微调的领域模型可以低成本融合为统一模型；(2) 跨语言场景尤其受益，多语言搜索系统可通过独立训练各语言专家再融合来降低训练成本；(3) 3.3% 以下的 divergence 阈值提供了明确的 go/no-go 决策边界。

MemBoost: A Memory-Boosted Framework for Cost-Aware LLM Inference

本文提出 MemBoost，一个基于记忆增强的 LLM 服务框架，通过复用历史生成的答案和检索相关支持信息实现低成本推理，同时将困难或不确定的查询路由到更强的模型。与标准 RAG 不同，MemBoost 专为交互式场景设计，支持答案复用、持续记忆增长和成本感知路由。实验表明，该框架在保持与强模型基线相当的回答质量的同时，显著减少了对大模型的调用次数和整体推理成本。

INSIGHTMemBoost 的核心思路是将 LLM 服务从「每次都调用大模型」转变为「记忆驱动 + 按需升级」的架构。对搜索/推荐系统的实践启示：(1) 搜索场景中大量查询具有重复性，答案缓存+语义检索可大幅降低 LLM 调用成本；(2) 成本感知路由（简单问题用小模型，复杂问题用大模型）是落地 LLM 搜索服务的关键设计模式；(3) 持续记忆增长机制可逐步积累领域知识，提升服务效率。

Joris Köster, Zixuan Liu, Siavash Khajavi, Zizhan Zheng

Label-Free Cross-Task LoRA Merging with Null-Space Compression

KAIST

本文提出 Null-Space Compression (NSC) Merging，一种无需标注数据、不依赖输出类型的 LoRA 合并方法。核心发现是：LoRA 微调过程中，下投影矩阵 A 会压缩其零空间，且压缩程度与任务性能正相关。NSC 利用这一几何信号作为合并权重的优化目标，可泛化至分类、回归和序列生成等不同任务类型。该方法解决了现有方法在跨任务类型（如分类+回归）场景下失败的问题。

INSIGHTNSC Merging 的技术创新在于发现了 LoRA 适配器几何结构与任务性能之间的关联——零空间压缩程度可作为合并权重的代理指标。对搜索/推荐系统的实践意义：(1) 多个独立微调的 LoRA（如不同任务、不同场景的排序模型）可无需标注数据直接合并；(2) 支持跨任务类型合并（如排序+分类+生成），适合多任务搜索系统；(3) 无需推理评估即可确定最优合并权重，大幅降低合并成本。

Wonyoung Lee, Wooseong Jeong, Kuk-Jin Yoon

Syncopate: Efficient Multi-GPU AI Kernels via Automatic Chunk-Centric Compute-Communication Overlap

UCSDUUT Austin

本文提出 Syncopate，一个编译器和运行时系统，实现单个融合内核内的自动细粒度计算-通信重叠。现有分布式编译器仅在 stream 级别重叠整个计算和通信内核，粒度过粗，导致额外内核启动、设备级同步和通信尾延迟。Syncopate 引入通信 chunk 抽象，将通信粒度与内核结构解耦，允许基于 Triton 内核自动生成重叠优化代码。该方法兼容现有分布式编译器的 chunk 计划。

INSIGHTSyncopate 的核心贡献是将计算-通信重叠从粗粒度的 stream 级提升到细粒度的 chunk 级，在单个融合内核内完成。对搜索/推荐系统的基础设施启示：(1) 多 GPU 模型并行推理中，通信延迟是主要瓶颈，细粒度重叠可显著提升吞吐；(2) 基于 Triton 的编译器方法意味着可自动化应用优化，降低手写 CUDA 内核的工程负担；(3) chunk 抽象的设计使优化策略可移植到不同的分布式框架。

Xinwei Qiang, Yue Guan, Zhengding Hu, Yufei Ding, Adnan Aziz

Systematic Characterization of LLM Quantization: A Performance, Energy, and Quality Perspective

本文开发了自动化在线表征框架 qMeter，对 11 种后训练 LLM 量化方法在 4 种模型规模（7B–70B）和两种 GPU 架构（A100、H100）上进行系统评估。评估覆盖应用层、工作负载层、并行层和硬件层，在在线服务条件下揭示了高度任务依赖和方法依赖的性能-能耗-质量权衡关系。研究发现量化效果对工作负载特征高度敏感，不存在「一刀切」的最优方案。

INSIGHTqMeter 的实践价值在于提供了量化方法选择的系统性决策依据。对搜索/推荐系统的启示：(1) 量化方法的选择应基于具体工作负载特征（batch size、sequence length、并发度），而非单一 benchmark；(2) A100 和 H100 上的最优量化策略可能不同，升级硬件时需重新评估；(3) 在线服务场景的量化评估与离线 benchmark 结论可能存在显著差异，部署前需做在线 profiling。

Accelerating Mixture-of-Experts Inference by Hiding Offloading Latency with Speculative Decoding

本文提出 SpecMoEOff，利用推测解码技术加速 MoE 模型在 GPU 显存受限场景下的推理。核心思路是通过推测解码放大每个专家的工作负载，从而将专家从 CPU 内存卸载到 GPU 的延迟隐藏在计算过程中。系统设计了专用的 CPU 分块注意力验证内核，以适配卸载场景下的推测解码并最小化 draft 模型带来的额外开销。实验表明 SpecMoEOff 在吞吐量上比 DeepSpeed-ZeRO-Inference 高 11.3–27.5 倍。

INSIGHTSpecMoEOff 巧妙地将推测解码从「加速生成」的角色转变为「隐藏 offloading 延迟」的工具——draft 模型在 GPU 上快速生成多个 token，为 CPU→GPU 的专家权重传输争取时间。对搜索/推荐系统的启示：(1) 在显存受限但需部署大型 MoE 模型时（如混合部署场景），推测解码+卸载是可行方案；(2) 11.3–27.5× 的吞吐提升使得单卡部署百亿级 MoE 模型成为可能；(3) CPU 端的验证内核设计表明，推理优化不能只看 GPU，CPU 侧的计算效率同样重要。

Utility-Driven Speculative Decoding for Mixture-of-Experts

本文揭示了推测解码在 MoE 模型上的反直觉现象：draft token 会集体激活更多专家权重，导致数据移动量和验证时间增加 2–3 倍，当 token 吞吐增益无法弥补此开销时，推测解码反而造成最高 1.5 倍的减速。针对此问题，提出 Cascade 框架——一种效用驱动的方法，选择性启用推测解码以避免减速，并动态调整推测长度 K 来加速 MoE 推理服务。

INSIGHTCascade 的核心洞察打破了「推测解码总是有益」的认知——对 MoE 模型而言，推测解码可能适得其反。对搜索/推荐系统的实践启示：(1) 部署 MoE 模型时不应盲目启用推测解码，需根据实际工作负载评估效用；(2) 动态调整推测长度 K 的思路适用于搜索场景中不同长度查询的混合负载；(3) 该发现提醒我们，dense 模型上验证有效的优化技术在 MoE 架构上可能需要重新评估。
