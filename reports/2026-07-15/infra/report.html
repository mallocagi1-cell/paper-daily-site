1. Adaptive Model Compression (AMC): Saliency-Driven Resource Allocation for Ultra-Low-Power Transformer Inference
4.35
Relevance 4 | Novelty 5 | Practical 4 | Evidence 4 | Timely 5

Summary: 针对边缘设备上 Transformer 静态推理对所有 token 使用同等精度、导致能耗与内存浪费的问题，AMC 按 token 显著性动态分配计算资源：高显著信息保留全精度，低显著信息同时降低秩与位宽。45nm CMOS 实验显示，系统能耗下降 59.2%，吞吐提升 2.24 倍，准确率代价仅 3.6%。

Key insight: 真正可落地的端侧压缩不必把统一量化方案施加到整条序列，而可把显著性判断变成运行时资源调度信号。对社区搜索的端侧 query 编码或轻量重排，可先离线验证显著性估计的稳定性，再评估分层精度是否能在可控 nDCG 损失下换取电量、延迟和吞吐收益。

2. Post-Train NVIDIA Cosmos 3 in One Day Using Agent Skills
4.35
Relevance 4 | Novelty 4 | Practical 5 | Evidence 4 | Timely 5

Summary: NVIDIA 将 Cosmos 3 Nano 的 LoRA、评测、数据检查和 AutoML 搜索封装为 TAO Agent Skills，使编码代理可自动修补数据配置并启动训练容器。8 张 A100 上约 30 分钟把验证准确率从 54.41% 提升至 87.14%，43 组并行 AutoML 试验在 19.5 小时内进一步达到 93.35%，LoRA 所需 GPU 时约为全参 SFT 的七分之一。

Key insight: 这项实践的价值不只是“用 Agent 跑训练”，而是把训练配方、数据格式、基线评测、容器启动和部署约束固化成可复用技能。搜索团队可借鉴这种受控自动化：让代理负责可审计的配置生成与故障修复，同时强制先跑基线、保留实验记录，并把超参搜索与最终线上灰度分开。

3. Supercharging LLM inference on Google TPUs: Achieving 3X speedups with diffusion-style speculative decoding
4.30
Relevance 4 | Novelty 5 | Practical 5 | Evidence 4 | Timely 2

Summary: Google Cloud 与 UCSD 将 DFlash 块扩散式投机解码接入开源 vLLM TPU 栈，让草稿器以一次 O(1) 前向生成整块候选 token，消除传统自回归草稿的 K 次串行瓶颈。TPU v5p 上平均 tokens/s 提升 3.13 倍，复杂数学任务峰值接近 6 倍；端到端服务加速 2.29 倍，高于 EAGLE-3 的 1.30 倍。

Key insight: 投机解码的上限常由草稿阶段而非大模型验证阶段决定，因此优化重点应从“更小的自回归草稿器”转向与硬件并行单元匹配的块级提议。若搜索系统使用生成式 query 改写或答案生成，应按真实批量和接受长度测试 DFlash，并把草稿开销、验证吞吐与输出质量拆开监控。

4. Context by Distinct Information: An Auditable Dirichlet-Process Working Memory for Long, Redundant Context Streams
4.10
Relevance 4 | Novelty 5 | Practical 3 | Evidence 4 | Timely 5

Summary: 论文把长上下文的计量单位从 token 改为“不同信息”：新键仅在足够新颖时占用缓存槽，并按任务依赖将内容分别送入新颖性缓存、状态空间摘要或近期窗口。字符级对照中，新颖性门控仅关注约一半 token 即达到全注意力性能；在千事件医疗序列上，组合组件优于全注意力及固定预算淘汰策略。

Key insight: UGC 搜索会反复出现模板化帖子、重复评论和近似行为事件，按 token 扩展 KV 缓存会为冗余内容持续付费。可审计的新颖性缓存提供了另一条路径：保留可回溯的代表模板，把统计性历史交给摘要状态，把局部依赖留给滑窗；但作者也表明短而局部的序列仍更适合普通滑窗。

6. GIGP+: A CPU-GPU Co-Processing Engine for Multi-Vector Retrieval.
3.65
Relevance 4 | Novelty 4 | Practical 3 | Evidence 2 | Timely 5

Summary: GIGP+ 面向 ColBERTv2 等多向量检索，把 CPU 方案 IGP 的低候选开销与 GPU 大规模并行结合，设计并行候选生成内核、降低同步成本的分数重排及批处理调度。SIGIR 2026 摘要报告，相比 PLAID-GPU，QPS 提升 11.0 倍、延迟降低 7.6 倍且精度相当；相对先进 CPU 方案，每美元查询量提升 2.3 倍。
