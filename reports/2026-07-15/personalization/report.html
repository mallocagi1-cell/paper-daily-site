1. CMSL: Constructive Multi-Sequence Learning for Recommendation Systems
4.75
Relevance 5 | Novelty 4 | Practical 5 | Evidence 5 | Timely 5

Summary: 针对单一行为序列中多兴趣相互争抢注意力、形成上下文污染的问题，Meta 提出 CMSL，在隐空间主动构造多条主题序列并分别建模。模型以 300亿至500亿条样本、128 张 H100 训练；四个线上场景的排序 NE 改善 0.06%至0.13%，召回 A/B 指标提升 0.092%至0.171%。

Key insight: 推荐序列不是语言句子，先按当前上下文拆成多条意图流，再做注意力，比盲目拉长单序列更有效。对社区内容流可把浏览、搜索、互动等行为构造成主题流，并用异步用户模型输出低延迟表征；其 0.03% 即显著的 NE 门槛也说明工业精排应重视稳定的小幅增益。

CMSL 深度解读

1. 问题与动机

论文质疑了把用户行为历史直接类比为自然语言句子的主流做法。语言通常具有连续的句法和语义结构，但真实用户轨迹往往是点击、点赞、评论、搜索等行为的混合，其中还夹杂探索性点击、偶发行为和互不相关的兴趣。把这些事件塞进一条长序列，会让编程教程、烹饪视频等不同意图争抢同一注意力预算，作者把这种现象称为上下文污染。现有 HSTU、OneTrans、InterFormer 等工作主要增强单序列注意力、拉长上下文或加强序列与非序列特征交互，却没有先解决输入历史本身缺乏语义统一性的问题。论文的核心判断是：推荐系统不应只学习如何读取历史，更应学习如何为当前预测主动构造上下文。

2. 方法详解

CMSL 的输入同时包含非序列特征和多类行为序列。连续特征如年龄、价格、观看时长先归一化，再通过线性投影映射到 d 维；国家、语言、品类等稀疏特征使用各自 embedding table，多值特征用 embedding 求和。点击、点赞、评论等行为序列先经过共享 item embedding。若同一产品表面有多条相关序列，模型为每类行为配置一个 MLP，经 sigmoid 得到逐 token 门值，再对各序列加权求和，先压成一条输入序列，避免后续计算随行为类型数膨胀。

核心由 N 个 CMSL Block 堆叠，每层包含四步。第一步是多序列构造：当前非序列上下文经 K 个投影头分解成 K 组意图条件，并分别生成 key/value；原始行为序列生成 query，通过 cross-attention 得到 K 条上下文相关的潜序列。第二步在每条潜序列内部独立做 self-attention，使不同意图不再直接互相干扰。为控制 K 倍开销，作者近似 Meta 推荐系统常用的 HSTU 注意力。HSTU 计算 SiLU(M⊙QKᵀ)V；CMSL 用 SiLU 的二阶多项式核 φ(x) 近似大部分项，把主体改写为 φ(Q)φ(K)ᵀV，并另用稀疏 kernel 捕捉 QKᵀ 中的大值，因此随序列长度近似线性扩展。

第三步用 PMA（Pooling by Multi-head Attention）汇总每条潜序列：以当前上下文 S(l,k) 为 query，以序列表示为 key/value，提取与当前用户状态最相关的固定长度向量 h(l,k)，并把这些摘要传给下一层非序列特征。第四步把 K 条潜序列沿通道拼接，再用 MLP 压回一条序列，防止每层序列数乘 K。最后一层的 K 个摘要拼接后进入多任务头，输出 CTR、CVR 等预测。

训练完全基于 Meta 内部生产流量，每个实验使用 300亿至500亿条样本，在 128 张 NVIDIA H100 上以混合精度训练，并配有定制 kernel 优化显存和吞吐。论文没有披露优化器、学习率、batch size、K/N 的具体取值和训练步数；这意味着方法结构可复现，但完整生产配方不可复现。

3. 核心技术贡献

第一，论文把序列推荐的瓶颈从模型容量重新定义为上下文构造：不是继续让更深的单序列 Transformer 自己过滤噪声，而是先用当前上下文将同一历史拆成 K 条意图流，使注意力只在语义更一致的事件之间发生。

第二，多序列构造不是人工按行为类型硬切分。K 个上下文投影头与 cross-attention 会在潜空间中动态分配历史事件，因此同一条点击记录可在不同当前场景下贡献给不同意图。它比固定的点击流、点赞流拆分更适应兴趣重叠。

第三，作者把 HSTU 的无行归一化 SiLU 注意力近似成多项式核线性项与稀疏大值修正项，从而抵消 K 条序列带来的主要复杂度。第四，PMA 摘要与逐层序列压缩让信息可以跨层传递，同时保持每层输入序列数恒定。相比仅提升长上下文长度，这套设计同时处理了语义干扰和工程成本。

4. 实验结果分析

论文在四个大规模产品表面评估排序，在第五个表面直接进行 U2U 召回线上 A/B。排序使用 Normalized Entropy，数值越低越好；作者说明在其系统中 NE 改善超过 0.03% 即具有统计显著性。表面 1 直接将 CMSL 用作互动预测模型；表面 2至4 为降低主排序链路时延，把长上下文 CMSL 放到异步上游用户模型，只把用户 embedding 输入线上排序器。

5. 局限与未来方向

论文没有独立的 Limitations 或 Future Work 章节，结论也没有明确列出作者承认的限制。正文能够直接观察到的公开性限制包括：全部结果来自 Meta 内部数据，指标被匿名化；缺少公开数据集复现、标准消融、训练超参数、服务延迟和资源成本；U2U 召回四个线上指标未命名。这些信息缺口使外部团队难以估计收益是否来自具体模块、数据规模还是基础设施。另一个作者未讨论的风险是潜序列可能学成冗余或流行度驱动的通道，K 的选择也可能随用户历史长度和场景变化。

6. 工业实践意义

对搜索推荐团队，最直接的做法不是一次性替换主排序器，而是先验证上下文污染是否存在：把同一用户历史按主题或行为弱监督拆分，比较单序列与多序列的 NE、AUC、nDCG 和线上互动。若有效，再用可学习构造器代替人工规则。社区 UGC 可把搜索点击、首页浏览、收藏、评论等行为作为原始流，当前 query、入口、时间和内容类别作为 K 个意图头的条件。

部署上可复制论文的两阶段策略：长序列 CMSL 在异步用户塔中运行，线上精排只消费固定长度 embedding，避免把 128 张 H100 级训练复杂度带入请求链路。线性注意力和序列压缩应作为必需的成本控制，而不是事后优化。团队还应补充论文未报告的监控：潜流之间的相似度、各流负载、长尾用户覆盖、embedding 新鲜度、线上 P99 时延，以及多目标之间是否出现此消彼长。若业务只有很短历史或单一意图，CMSL 的 K 路构造开销可能不划算，应保留单序列基线和按请求降级路径。

2. Prompt Generation Technical Report
4.75
Relevance 5 | Novelty 4 | Practical 5 | Evidence 5 | Timely 5

Summary: 论文把生成式搜推的特征处理从模型代码中解耦，以两份声明式 JSON 统一离线训练和在线服务，并用四类特征、三种可组合组件完成组装与压缩。该框架已部署于淘宝搜索，线上 A/B 实验使成交笔数提升 0.47%、GMV 提升 0.51%，并复用于多个搜索推荐团队。

Key insight: 最值得借鉴的不是某个网络结构，而是把特征契约设为训练与服务的唯一事实源，从根源上减少特征不一致和场景定制代码。社区搜索若采用生成式召回，可先统一行为、内容、数值与向量特征的配置式 token 化，再在同一标准接口上做序列压缩和推理优化。

Prompt Generation Technical Report 深度解读

1. 问题与动机

生成式检索把 query、用户行为和候选信息编码进 LLM，并直接生成文档或商品标识。但工业系统真正拖慢迭代的常常不是模型，而是异构特征工程：原始文本、预计算 embedding、组合特征和时间行为序列各有不同的数据处理与 token 组装逻辑；每次增删特征都可能同时修改数据加载、训练、服务和推理优化代码。更严重的是离线与在线若采用不同实现，会产生 training-serving skew。淘宝团队观察到特征集合和组合方式的变化频率远高于模型主干，因此提出 Prompt Generation（PG），目标是把特征处理从模型代码中抽离，使同一份配置成为训练和服务的事实源。

2. 方法详解

PG 由两份声明式 JSON 驱动。prompt_feature.json 描述 feature_name、feature_type、数据 expression，以及预处理器、投影器、合并器和空值策略；prompt_template.json 负责最终 prompt 结构和占位符。系统只保留四类特征：text、embedding、combo、sequence。text 进入 LLM tokenizer；embedding 以 [N,D] 形式绕过 tokenizer，可经 MLP 对齐到模型 hidden size；combo 把多个子特征聚合；sequence 表示时间行为，并支持长度控制和压缩。

所有变换分成三条正交轴。Preprocessor 在 token 化前做映射和分桶，例如年龄按 18、25、35、45、60 划分；Projector 用 MLP 等结构调整 embedding 维度，示例将 256 维向量经 512、896 隐层映射，并支持 ReLU、bias 和 dropout；Merger 负责 mean、sum 或 concat-MLP 聚合，同时明确 output_token_len。mean/sum 无参数且固定输出 1 个 token；concat-MLP 更灵活，但输入必须先投影到相同维度。Merger 因而不仅融合特征，还直接控制 prompt token 预算。

离线侧由数据处理 pipeline 解析同一配置，生成模型输入；训练框架用 wrapper 在 forward 前执行 PG，使模型结构无需知道每个业务特征。在线侧采用两层架构：通用 PG 引擎负责特征解析、投影和合并，模型服务消费统一请求协议。事件追踪会记录线上原始源特征，离线可重放同一请求，借此排查并消除离在线偏差。新场景只需遵循 schema 与通用 pipeline 对接，不再复制场景专用处理代码。

论文未给出统一优化器或 batch size，因为 PG 是框架而非单一模型。实验覆盖淘宝搜索、淘宝推荐与 S1-tiny、RecIF、Amazon Reviews 三个公开基准；训练与推理优化包括并行化特征处理、合并小 kernel、缓存静态项、减少 host-device 传输和按场景控制 token 数。作者强调配置抽象必须保持窄：每增加一种 feature type，都要在离线与在线同时实现和验证，类型膨胀会重新制造维护成本。

3. 核心技术贡献

第一，PG 将 prompt 特征工程变成可版本化的声明式协议。两份 JSON 同时驱动训练和服务，配合线上事件重放，直接针对生成式搜推最危险的离在线不一致，而不只是提供方便的配置文件。

第二，四类特征与三类组件形成小而完整的组合空间：特征类型回答数据是什么，preprocessor/projector/merger 回答如何变换、对齐和压缩。这个分解允许团队按特征选择策略，而不是对所有信号使用一种统一融合器。

第三，Merger 把信息融合与 token 成本放在同一接口中。实验发现参数免费的 mean-pool 在固定 prompt 预算下常常不输 MLP 或 attention；SID 等关键标识若与文本、embedding 一起压成单 token，性能反而会崩塌。这提供了可操作的工程原则：先保护高辨识度 token，再压缩冗余文本。

第四，配置化让自动研究代理只编辑安全、局部的 schema，而无需修改训练代码。内部 autoresearch 在20轮配置实验后将 hitrate@20 提升3.05%，展示了框架对自动特征探索的放大作用。

4. 实验结果分析

论文报告五类离线场景都能仅通过配置适配获得增益，并给出多项生产结果。最关键的定性结论是不存在通用特征配方：item SID 加辅助信号通常有效，但最佳组合随淘宝搜索、推荐和公开数据集变化；不同信号需要不同处理。文本可大幅 mean-pool 而损失较小，SID 若与其他特征过度合并则会显著掉点。

一个值得注意的反直觉结果是 learned merger 并非总优。输入已被强压缩时，可学习参数的剩余表达空间很小，mean-pool 的稳定性和零参数成本反而占优。失败模式同样明确：把 SID、文本和 embedding 粗暴压成一个 combo token 会破坏标识信号。论文没有报告显著负向的线上实验，但通过这一现象说明配置自由度需要约束和自动验证。

5. 局限与未来方向

作者在结论中明确承认，当前评估只覆盖电商，向内容推荐和广告的泛化仍待验证；现有 merger 库也有限，mean/sum 完全忽略交互，concat-MLP 只能做固定前馈融合。计划中的方向包括把图像加入第五类特征：将视觉编码器 patch embedding 视作 embedding 序列并复用 projector/merger 压缩；增加 attention 或低秩跨特征 merger；让 autoresearch 同时探索特征组合、merger 和序列长度。论文未充分讨论的限制包括 schema 演进与向后兼容、配置错误的权限边界、线上事件记录的隐私与存储成本，以及自动代理可能对离线指标过拟合。

6. 工业实践意义

PG 最适合作为生成式搜推平台层，而不是单个模型技巧。落地可先定义最小 schema：文本、数值/稠密 embedding、组合特征、行为序列四类；每类只开放少量可审计 preprocessor、projector、merger；训练和服务必须共享解析器与版本号。随后加入线上源特征采样和离线重放，建立逐字段一致性检查，再允许业务团队通过配置迭代。

对社区搜索，可把 query、帖子文本、作者与社区属性、内容 embedding、用户短长行为序列分别声明，避免把所有信息拼成不可控的自然语言。token 预算应成为配置的一等约束：保留 query、内容 ID 或关键 SID 的独立 token，对冗长画像和历史用 mean-pool 或可学习压缩。评估除 nDCG、CTR 外，还应记录 PG 解析耗时、投影与 merger 耗时、最终 token 数、P99 推理延迟及离在线字段差异率。

自动研究应在这套安全边界内运行：代理只能修改 JSON，配置需通过类型、维度、token 上限和敏感特征校验，实验必须有预算与回滚。论文的淘宝结果表明，即使线上提升只有0.47%至0.51%，统一特征契约带来的长期价值还包括减少场景专用代码、缩短部署路径和让多个团队复用优化；但在非电商业务复制前，应先用一到两个真实场景验证 schema 是否覆盖内容供给、社交关系和强时效特征。

3. ZoRRO: A Zero-Weight Personalized Recommender System for Scalable News Recommendation
4.75
