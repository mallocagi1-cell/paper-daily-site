Beyond Positive Signals: Unlocking Implicit Negative Behaviors for Enhanced Sequential User Modeling

现代 CTR 预估普遍只用正向行为（点击、购买、完播）构建用户行为序列，而数量更庞大的隐式负反馈（划过、跳过、低完播）被忽视。论文提出按时间戳把正负行为混合成单一序列，并设计 Target-Aware Polarity Fusion (TAPF) 门控：对每个候选做 target-aware 交互、内容自适应 sigmoid 门控，再按极性符号做带符号残差融合，把正向 token 推向目标、负向 token 推离目标。在 KuaiRec、KuaiRand、腾讯广告 TAAC-2025 三个数据集、DIN/Transformer/OneTrans/HyFormer/MixFormer 五种架构上，相对 AUC 提升 +1.9%~+9.6%，且额外计算开销可忽略。

1. 问题与动机

现代 CTR 预估的用户行为序列建模这几年都在卷“怎么编码序列”——从 DIN 的 target-aware attention、DIEN 的兴趣演化，到 SIM/TWIN 的超长序列两阶段检索，再到 OneTrans 这类统一架构。但论文指出一个更根本却被忽视的问题：序列里到底该放什么？ 当前实践只用正向交互（点击、购买、完播）构建序列，而数量远超正向的隐式负反馈（划过、快速滑走、低完播）几乎没被用。

论文给了量化证据：正向行为占比在 KuaiRec 仅 7.4%、KuaiRand 37.9%、TAAC 6.3%，正向序列本身受真实参与率上限约束；继续加长正向序列收益递减——KuaiRec 上 AUC 在 L≈50~100 后趋平，OneTrans 从 L=100 到 L=500 只涨 +0.0010。而混合极性序列的 scaling 斜率约为正向序列的 2 倍。动机即：当“加长正向序列”这条路走到头，应该换一种思路——把海量隐式负反馈纳入序列，这与架构改进正交、互补。

2. 方法详解

序列构造：给定固定长度 L 和正向比例 r∈[0,1]，取最近 ⌊rL⌋ 个正向交互和 ⌊(1−r)L⌋ 个负向交互，按时间戳合并成单一时序序列；总长仍为 L，即负向行为“替换”部分正向而非追加（保证序列长度与算力不变）。默认 r=0.5。

TAPF（Target-Aware Polarity Fusion）三步：

  1. Target-aware interaction：对每个序列 token h_k 与候选 embedding e_v 做逐元素交互 e_k = ReLU(W_int(h_k ⊙ e_v))，刻画历史行为与当前候选的相关性；
  2. Content-adaptive gating：g_k = σ(W_g[h_k ‖ e_k ‖ b_pk])，门控向量拼接原 token、交互特征、可学习的极性 embedding b_pk，输出每维 (0,1) 的控制门；
  3. Signed residual fusion：h'_k = h_k + p_k·(2g_k − 1) ⊙ e_k，极性符号 p_k∈{+1,−1} 直接乘到 (2g_k−1)——正向 token 把表征推向目标、负向 token 推离目标，实现“同一套门控、按极性反向调制”。

训练设置：embedding 维度 d=64，序列长度 L=100（KuaiRec/KuaiRand）或 50（TAAC），batch 2048，Adam lr=1e-3，训 1 epoch。隐式负反馈定义为“曝光但表现出脱离”（划过、快速滑走、低完播）；KuaiRec 用 watch-ratio≥2.0 作为正样本阈值。方法可挂到 DIN、Transformer（两阶段）与 OneTrans、HyFormer、MixFormer（统一块）五种 backbone 上，复杂度线性、开销可忽略。

3. 核心技术贡献

  1. 范式重定义：把问题从“how to encode”转向“what to encode”，论证混合极性序列与架构改进正交互补——这是最核心、最可迁移的贡献。即便不用 TAPF，仅把负反馈混进序列（配简单极性偏置 PBE）就能拿到 70~80% 的增益。
  2. 带符号门控融合：用同一套 target-aware 门控、靠极性符号 p_k 决定 push/pull 方向，避免为正负行为各训一套参数；相比 PBE（每种极性一个统一偏移），TAPF 通过 target-conditioned 门控按“候选相关性”区分负样本，额外再加 +0.3~0.8% AUC。
  3. 等长替换的序列构造：负向替换正向而非追加，序列长度/算力不变即可获益，工程上几乎零成本接入现有 pipeline。

4. 实验结果分析

主结果（Mix Seq + TAPF 相对 AUC 提升）跨五架构一致：KuaiRec +4.2%~+5.5%，KuaiRand +6.7%~+9.6%，TAAC +1.9%~+2.5%。

  • KuaiRand 增益最大（最高 +9.6%，Transformer），因为它是随机曝光日志，负反馈信号更“干净”、信息量更高；TAAC（腾讯广告）最小（+1.9%~2.5%），作者归因于广告域的特定因素。
  • PBE vs TAPF：简单极性偏置已拿 70~80% 增益，说明“把负反馈纳入序列”这个数据范式本身是主因；TAPF 的 target-conditioned 门控在此之上再加 +0.3~0.8%，价值在于按目标相关性细分负样本。
  • 正向比例 r 敏感性：各数据集都是倒 U 曲线，峰值 r*∈[0.2,0.7]，平台较宽；r=0.5 是稳健默认值，无需精调即可拿大部分增益。
  • Scaling：混合序列 AUC-长度斜率约为正向序列 2 倍，正向序列在 L=100→500 几乎不涨（OneTrans +0.0010），印证“加长正向已到头”。

5. 局限与未来方向

论文未单列 limitations，但承认：(a) 增益随数据集差异明显（TAAC 明显低于 Kuai 系），暗示存在域特定因素未解释；(b) 隐式负反馈语义上比显式反馈更模糊（划过可能因不喜欢、也可能已看过/误触）；(c) TAPF 引入线性但非零的额外开销。隐含未来方向：扩展到显式负反馈、解释 TAAC 增益偏低、适配 10K+ 超长序列。补充一点作者没强调的局限：负反馈定义（划过/低完播阈值）依赖埋点口径，跨平台迁移需重新标定；且 r 的最优值与负反馈质量耦合，随机曝光多的场景收益更大。

6. 工业实践意义

对搜推从业者，这是“低成本高 ROI”的典型：

  • 该做：在现有 CTR/排序模型里，把曝光未点击、快速划走、低完播等隐式负反馈按时间戳混入用户序列（等长替换部分正向），默认 r≈0.5，先上简单极性偏置就能拿大部分收益，再考虑 TAPF 门控做精细化。改造架构无关、算力不变，DIN 到 OneTrans 都能挂。
  • 该试：在随机曝光/探索流量上收集更干净的负反馈（这里增益最大）；长序列团队与其继续堆正向长度（已递减），不如把预算投到负反馈混合。
  • 该避：别把所有负反馈一视同仁——TAPF 的价值正是按候选相关性区分负样本；也别迷信复杂门控，先验证“加负反馈”这个数据范式在自己业务的增益盘子有多大。
  • 社区短文本搜索映射：UGC 搜索里“曝光未点击/秒退/无互动”就是天然负极性信号，可作为 query 感知用户序列的一部分；TAPF 的“按极性 push/pull 候选”也适用于把“用户历史快速划走的帖子类型”作为负向约束注入排序。

PIANO: Personalized Reranking via Information Aggregation Node for Music Search Optimization

NetEase📖 有深读 · 7 分钟

音乐搜索重排需同时对齐用户当前 query 与长期偏好，并联合优化 CTR 与 CVR，但已有序列方法只用 item 交互历史、无法用历史 query 判断哪些偏好匹配当前意图，且多数 listwise 模型只优化单目标。论文提出 PIANO：Query-Driven Interest Refiner (QDIR) 用当前 query 对历史 query 序列做 cross-attention 筛选相关历史交互、融合长短期兴趣；Information Aggregation Node (IAN) 用一个 [CLS] 式可学习 token 在列表级聚合并预测 CTR/CVR，配合 list-level + item-level 联合损失。工业音乐数据集 NDCG@5 0.8606 优于 PEAR 0.8586；网易云音乐线上 4 周 A/B，CTR 相对 +0.62%、CVR 相对 +4.45%（p<0.05）。

INSIGHT两个设计值得借鉴：一是用历史 query 序列而非仅 item 序列刻画“搜索意图下的长期偏好”，解决了序列推荐在搜索场景下意图错配的问题；二是用列表级 [CLS] token 把多目标（点击/转化）的权衡放到整列粒度而非单 item 粒度优化（消融显示去掉 QDIR 掉 ~1.9% NDCG@5、去掉 IAN 掉 ~1.2%）。对社区搜索而言，QDIR 的“query 感知历史筛选”可直接迁移到 UGC 搜索重排，把用户历史搜索词作为意图锚点对齐当前 query，同时用列表级损失协调相关性与点击/互动多目标。

1. 问题与动机

音乐搜索重排与短视频不同：音乐曲目生命周期长、价值持久，重排既要对齐用户当前 query，又要兼顾长期偏好，还要同时优化 CTR 与 CVR。论文指出已有方法两个缺陷：(1) 序列方法只用 item 交互历史，无法利用历史 query 判断“哪些过去偏好匹配当前搜索意图”——比如用户此刻搜“安静的钢琴曲”，纯 item 序列分不清历史里哪些交互与当前意图相关；(2) 多数 listwise 模型只优化单目标（如只优化 CTR），而传统多目标方法在 item 粒度平衡点击与转化，忽略了整条排序列表层面 trade-off 如何展开。动机即：把“历史 query 感知的长期偏好对齐”与“列表级多目标优化”结合进个性化重排。

2. 方法详解

PIANO = QDIR + IAN + 联合损失。

QDIR（Query-Driven Interest Refiner），对齐长短期兴趣：

  • 当前意图表征：用音乐专用 embedding 模型 Qwen3-Embedding-0.6B 编码当前 query，投影 r_short = W^E · q_cur；
  • 历史 query 感知的偏好精炼：以当前 query 为 Query、历史 query 序列为 Key、历史交互 item 为 Value 做 cross-attention，r_long = softmax(QK^T/√d)V——用“当前 query 与哪些历史 query 相似”来筛选相关历史交互；
  • 长短期融合：r_user = LayerNorm(W_f·[r_long ‖ r_short ‖ user_profile] + b)。

IAN（Information Aggregation Node），列表级聚合：

  • 一个 [CLS] 式可学习 token 前置到候选列表，初始化 h_0 = MLP_init(g)（g 为 QDIR 输出）；
  • IAN 用固定位置编码、item 用顺序位置编码，送入 2 层 pre-norm Transformer encoder 处理 [h_0, h_1,…,h_M]；
  • 双预测头：列表级 p_list = Sigmoid(MLP(h_0'))，item 级 p_j = Sigmoid(MLP(h_j'))。

多目标优化：问题形式化为 π* = argmax_π [λ·U_clk + (1−λ)·U_conv]，列表级损失对每条列表的 CTR/CVR 率做 BCE（标签 y_clk = 列表内点击 item 数/列表长度，y_conv 同理），item 级损失对单 item 做 BCE，联合目标 L = α·L_list + (1−α)·L_item，α 平衡两种监督粒度（最优 α=0.5）。

3. 核心技术贡献

  1. 用历史 query 序列刻画搜索意图下的长期偏好：QDIR 的 cross-attention 以“当前 query↔历史 query 相似度”为桥筛选相关历史交互，直击序列推荐在搜索场景的“意图错配”痛点。消融显示去掉 QDIR 掉 ~1.9% NDCG@5（工业集），是贡献最大的模块。
  2. 列表级 [CLS] token（IAN）做整列粒度多目标：传统多目标在 item 级平衡点击/转化，PIANO 用 h_0 聚合整条列表、在列表层面预测 CTR/CVR 率，配合列表级+item 级联合损失显式建模“整列 trade-off”。去掉 IAN 掉 ~1.2% NDCG@5。
  3. 长短期 + 多粒度监督的统一重排框架，且在公开（Yahoo Letor）与工业（音乐搜索）双数据集 + 线上 A/B 三重验证。

4. 实验结果分析

数据集：Yahoo Letor（公开，29,921 记录 / 709,877 item）+ 工业音乐搜索（3133.7 万记录、448.9 万用户、23.6 万 query、64.2 万 item）。

离线主结果：

  • 工业集 NDCG@3 0.8296、NDCG@5 0.8606、MAP 0.8100，优于次优 PEAR（0.8277/0.8586/0.8081）与 PRM（0.8098/0.8433/0.7868）；
  • Yahoo Letor NDCG@5 0.6700 vs PRM 0.6676、MAP 0.6516 vs PRM 0.6494。

消融（工业集）：full（QDIR+IAN）0.8606 → 去 QDIR 0.8442（−1.9%）→ 去 IAN 0.8507（−1.2%）→ 都去 0.8437，两模块均有效、QDIR 贡献更大。超参 α（list vs item 损失权重）：0→0.25→0.5→0.75 呈倒 U，α=0.5 最优。历史序列长度：从 5 到 30 单调提升，越长越好（长期偏好越充分）。

线上 A/B（网易云音乐，4 周）：CTR 绝对 +0.17pp / 相对 +0.62%，CVR 绝对 +0.005pp / 相对 +4.45%，均 p<0.05，工作日/周末、主要 query 类目均稳定。CVR 相对提升（+4.45%）远高于 CTR（+0.62%），说明列表级多目标优化对“转化”这类更稀疏目标帮助更大。

5. 局限与未来方向

论文无专门 limitations，但隐含：(a) Yahoo Letor 上必须关掉 QDIR 的 query 序列分支（公开集无用户行为序列），QDIR 核心能力只在工业集完整验证；(b) 没量化在线推理延迟/算力开销，仅提到部署有延迟要求；(c) 引入 λ、α、β 多个平衡超参，只系统分析了 α，交互未充分研究；(d) 公开集用合成位置偏置（P_exam∝1/pos^η），非真实交互；(e) 无失败案例分析。补充：QDIR 依赖 Qwen3-Embedding 编码 query，embedding 模型质量与音乐域适配直接影响意图对齐，跨域迁移需重训 embedding。

6. 工业实践意义

对搜索/推荐重排从业者：

  • 直接可借鉴：QDIR 的“query 感知历史筛选”——把用户历史搜索词作为意图锚点，用当前 query 对历史 query 做 attention 挑选相关历史交互，几乎可平移到任何“搜索场景下的个性化重排”，社区 UGC 搜索尤其契合（用户历史搜过的话题/帖子类型就是长期意图信号）。
  • 列表级多目标：IAN 的 [CLS] token + 列表级 CTR/CVR 率损失，给“既要相关性又要点击/互动/转化”的多目标重排提供了 item 级之外的整列视角；线上 CVR 相对 +4.45% 说明对稀疏转化目标增益显著，值得在付费/收藏等稀疏转化业务上试。
  • 部署考量：2 层 Transformer encoder 处理候选列表，推理成本可控；但 QDIR 用了 0.6B 的 query embedding 模型，需评估在线 query 编码延迟（可离线缓存历史 query embedding、仅在线编码当前 query）。
  • 该避：别只在 item 级做多目标平衡而忽略整列 trade-off；历史序列越长越好（5→30 单调提升），但要权衡存储与延迟。

OneRank: Unified Transformer-Native Ranking Architecture for Multi-Task Recommendation

RUCNTUShopee

工业排序已从 DNN 转向 Transformer，但仍把 Transformer 当作任务无关编码器、与多任务预测头解耦，导致信息瓶颈、梯度干扰（跷跷板）和“动态注意力表征→静态前馈预测”的数据流割裂。论文提出 OneRank：为每个候选配 K 个任务私有 token，用结构化注意力掩码实现任务条件信息选择、候选感知上下文化与可控跨任务交互（前向传递知识）；反向用 cross-task gradient detachment 只放行对角梯度、阻断跨任务梯度（隔离优化）；并用动态内积匹配打分替代静态 MLP。Shopee 数据集（3300 万用户、266 亿曝光）上 C-AUC 0.7910 优于 PLE 0.7770，参数更少（4.9M vs 6.1M）；线上 7 天 A/B，GMV/UU +1.01%、付费 GMV/UU +1.17%、坏 query 率 -2.29%。
