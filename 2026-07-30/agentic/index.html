SearchArt: Training Long-Horizon Search Agent with Scalable Synthetic and Verified Task

针对搜索智能体缺少可扩展长链任务与过程监督的问题，SearchArt 从网页和自动生成的证据图合成问答及搜索轨迹，再以问答一致性、轨迹质量和证据相关性三重验证过滤数据，最后结合 SFT 与强化学习优化策略。仅用 Qwen3.5-27B，BrowseComp-ZH、BrowseComp 和 DeepResearch-Bench 分别达到 74.39、70.06 和 52.55。

S2G-RAG: Structured Sufficiency and Gap Judging for Iterative Retrieval-Augmented QA

Soochow University

S2G-RAG 用独立 S2G-Judge 判断证据是否足够；若不足则输出结构化信息缺口并生成下一轮查询，同时保留句子级 Evidence Context 抑制噪声。Llama3-8B+BM25 在 HotpotQA 上 F1 达 56.5，较 SIM-RAG 的 43.3 高 13.2；搭配 E5 时，2WikiMultiHopQA F1 为 45.3，较 RAG-Critic 高 11.3。

INSIGHT多轮检索最关键的不是“再搜一次”，而是把“还缺什么”和“何时停止”变成可审计的结构化状态。对社区复杂 query，可将帖子级证据压缩为句子级记忆，并把缺口直接映射成下一轮召回条件；这一轻量控制器无需更换搜索引擎或重训生成器，适合先在现有 RAG 链路旁路试验。

Minghan Li, Junjie Zou, Xinxuan Lv, Chao Zhang, Guodong Zhou

From Naive RAG to Deep Agentic Retrieval: An Evolving Context Engineering Pipeline for Regulatory Compliance

OOntario Power GenerationDalhousie University

论文复盘 Ontario Power Generation 监管检索系统从朴素 RAG、混合召回与重排、函数调用检索到深度多 Agent 的四阶段演进，并提出 PEA-CAE：先用低成本高精度检索，只有预期证据增益足够时才升级到全文读取。文章提供生产运行轨迹与架构取舍，但没有报告统一离线指标或线上 A/B 提升。

INSIGHTAgentic Retrieval 的工程价值来自成本感知的逐级升级，而不是默认让 Agent 无限搜索。社区搜索可把 BM25/向量召回、重排、全文读取和子 Agent 总结设计为分层动作，并以证据覆盖、剩余预算和边际增益决定升级；这能避免长上下文“稀释”关键信息，同时保留可追溯证据链。

Mishca de Costa, Muhammad Saleh Anwar, Dave Mercier, Issam Hammad

Agent Retrieval Bench: Evaluating Repository Context Retrieval for Coding Agents

NUSPeking University

该基准把编码 Agent 的上游“找对文件”独立出来，覆盖 25 个仓库、427 个样本、392,000 个文件和 790 万个 chunk，并设置 code2test、trace2code 等四类正例与自然无答案/错仓库对照。Qwen3-Embedding-4B 的加权 MRR 最佳，但真实 Agent 轨迹仍有 27%–35% 的样本从未触达任何 gold 文件。

INSIGHT端到端补丁成功率会掩盖检索失败，Agent 评测应单独记录首次命中步骤、文件级召回、上下文预算与无答案校准。对搜索 Agent 同理：除了最终回答，还应测证据首次出现轮次、每轮新增有效证据和错误库/错误域拒答；“更大的 embedding”也无法统一赢下所有任务，路由策略必须按任务类型选择。

Bowen Qin, Yi Xie

HiEviDR-Bench: A Benchmark for Hierarchical Evidence Aggregation in Deep Research

UUniversity of Chinese Academy of SciencesNortheastern UniversityTsinghua UniversityShanghai Jiao Tong University

HiEviDR-Bench 用显式证据图描述“证据选择—跨源连接—中间主张—最终结论”的层级聚合过程，覆盖开放域/学术域、纯文本/多模态，共含 2,000 个人工验证问题。它从报告质量、证据可追溯、引用准确、主张验证和答案正确五维评测 16 个代表性模型，发现表面报告质量高并不等于证据链可靠。

INSIGHTDeep Research 的质量门控应沿证据图逐层验收，不能只用一个 LLM Judge 打最终报告分。社区搜索可把每条结论绑定到帖子、评论或外链证据，并分别测召回、跨源关联、主张成立和引用正确；渐进式 gate 能定位故障发生在“没找到、没连上、推错了”中的哪一层，便于针对性修复。

When Thinking Before Retrieval Hurts: TraceBound Diagnostics for Adaptive Knowledge-Graph Retrieval

ETH Zurich

TraceBound 在不改变图数据、工具和评测指标的前提下，为 ARK 式控制器加入查询画像、失败提示与轨迹计数，检验“检索前思考”是否真能改善排名。Qwen3-14B 在 12 步预算下平均 MRR 从未条件化的 0.4087 降至 0.3141；Qwen3-30B-A3B 在 MAG 上从 0.7711 降至 0.4974，重复调用和零结果调用是主要负向信号。

INSIGHT把更多思考文本塞进 prompt 可能让 Agent 更忙，却不一定让检索更准；轨迹状态必须进入经过校准的动作策略，而非无条件上下文。线上应监控重复 query、零结果、无效邻域扩展和单位预算的排名增益，并让策略学习何时宽搜、局部扩展、回退或停止；单纯收紧轮数只降成本，不能修复错误动作选择。

Partha Sarathi Purkayastha

Aethel: A Reproducible Graph-Retrieval Framework for Multi-Hop Financial Diligence

DDartmouth College

Aethel 结合实体—段落二部图、Personalized PageRank、共指传送与专家 Agent。封闭池中 2WikiMultiHopQA、MuSiQue 的 HR@5 分别为 100.0%、88.5%；但在 4,123 个金融 chunk 的开放语料上，图检索 HR@5 为 0.600，仍低于 BM25 的 0.700，融合 MRR 0.479 对 0.468 也未显著胜出。

INSIGHTGraphRAG 的优势高度依赖语料规模和实体索引质量，不能把小候选池收益直接外推到生产开放库。对 UGC 社区，图检索更适合补充跨帖实体关系和可解释路径，而 BM25 仍应保留为强基线；上线前必须在真实全量索引上比较召回、首位精度与成本，并验证融合增益是否统计显著。

Krish Sapru

VLD-RAG: Agentic Vision-Language Retrieval-Augmented Generation for Long, Visually-Rich Multi-Page Documents

MMazelone

VLD-RAG 按页保存结构化文本、元数据与视觉向量，混合稀疏/稠密检索后由 Retrieval、Answer、Validation 三个 Agent 迭代补证校验。MMLongBench-Doc、LongDocURL 的 Recall@5 分别为 77.96%、81.16%，NDCG@5 为 71.82%、73.57，明显高于 MoLoRAG 的 57.29%、61.30%。

INSIGHT当 UGC 搜索包含截图、长图或多页附件时，纯 OCR 会丢失布局与图表语义，页面级视觉索引和结构化文本索引应并行保留。实践上可先用混合召回取候选页，再让验证 Agent 检查缺失证据和引用；需要注意该方法牺牲部分 Precision@K 换取更高证据覆盖，必须结合生成阶段的上下文预算评估。

A new benchmark for evaluating patient-facing health AI agents

Amazon

Amazon 的 PatientAgentBench 动态生成合成病历、临床情景和患者 Agent，让被测系统在有状态工具环境中完成多轮问诊与任务。LLM jury 按临床安全、分诊、流程准确、任务完成、帮助性和对话质量六维、100 多条临床审核标准评分；对数千段共享对话的测试显示，强模型仍会遗漏危机资源或声称执行了实际未执行的动作。

INSIGHTAgent 评测需要同时覆盖状态、工具执行和隐性高风险场景，静态问答无法暴露“说已完成但工具未执行”这类故障。搜索产品可借鉴动态场景生成与可复用 rubric：用合成用户画像和长尾意图驱动多轮检索，并把检索正确、动作落地、风险升级和对话体验分开评分；安全维度宜采用偏保守的自动判定并抽样人工复核。

Korosh Vatanparvar, Ashutosh Joshi

Scientific computing in the age of agentic AI

OpenAI

OpenAI 汇总 8 个生命科学为主的 Agent 辅助计算项目，其中 5 个只用 Codex，3 个结合 Codex 与 Claude Code，任务涵盖维护、性能优化、语言迁移和 GPU 原生重构。案例一致表明 Agent 能快速给出初版，但科学有效性、边界差异和最后一公里仍依赖人工验证；该报告为探索性复盘，未给出统一速度或质量提升比例。

INSIGHT工业落地的瓶颈正在从“能否生成实现”转向“如何定义验收标准并长期维护”。搜索/推荐团队使用 Agent 改造召回、特征或评测代码时，应先建立结果等价、统计行为和回归测试等外部 oracle，把大任务拆成可测迭代，并明确代码所有者；否则低成本生成会制造更多分叉实现和维护债务。
