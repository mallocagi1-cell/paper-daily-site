TideCache: Efficient Hybrid LLM Serving with Transparent Cache Management and Layer-Wise Streaming

混合架构大模型里，全局注意力缓存随并发和上下文一起增长，有界状态缓存只随并发增长，固定切分显存容易一边闲置、一边排队。像 HiCache 这类分层缓存把历史前缀拉回后全程常驻显存，decode 期间高速 CPU 与 GPU 互联几乎空转。TideCache 在 SGLang 中保留各缓存子池的固定虚拟地址，按需重映射物理页，不改缓存布局和注意力后端就能在子池间挪动容量。

Supercharging XLA-based inference: Announcing the launch of XLA Serving Engine

Google

很多团队用 Python 训练模型，但部分线上推理环境不允许部署 Python，还要承受解释器和全局解释器锁的开销，Google 为此开源了面向 OpenXLA 生态的 XLA Serving Engine。它把 JAX 模型导出为以 StableHLO 存计算图、以 Orbax 存权重的 XLA SavedModel，再在原生 C++ 运行时里直接调用 PJRT 并经 XLA 编译执行，支持单机和多机部署，并保留训练时的算子优化。在 Google 的短请求测试中，它的吞吐量达到其团队能做出的最优 Python 服务的 2 到 5 倍，内存降至四分之一。目前它已在 Google 内部承载每秒超过 600 万次请求，支撑 YouTube Shorts、Google Ads、Search 和部分 Gemini Omni 推理链路。它定位为轻量级单次推理引擎，通常面向非 LLM 模型，对于长上下文的大型自回归语言模型，官方仍建议使用 vLLM 或 SGLang，而通过 TorchTPU 支持 PyTorch 导出仍在规划中。

Oleg Shaldybin, Monica Song

E2E: Efficient Filtered AKNN Search via Adaptive Termination

已录用 KDD 2026HKUST

带属性过滤的向量近邻检索里，HNSW 等图索引常对所有 query 用固定终止条件，让简单请求多搜大量节点。普通检索的早停模型只看距离，放到过滤场景就会失灵，因为属性与向量距离错位时，附近点再近也可能不满足条件。E2E 在必经的早期探测阶段顺手统计已访问节点和候选队列里的过滤通过比例。它把这两个比例和距离特征交给轻量 LightGBM 预测计算预算，让简单请求早停，困难请求多搜。高召回区间下，它比朴素 HNSW 在 Tripclick 上提速最高 2.6 倍，在 YoutubeAudio 上把距离计算量最多降至三分之一，适配过滤索引 ACORN 后效率也提升最高 1.5 倍。它不改底层图索引，用历史 query 日志离线训练即可减少简单过滤请求的冗余遍历。

Wenxuan Xia, Mingyu Yang, Wentao Li, Wei Wang

RoCoKV: Accelerating LLM Inference Serving through Uncertainty and Redundancy Aware KV Cache Compression

Georgia TechIntel

推理大模型生成长思维链时，decode 阶段的 KV cache 压缩很挑时机。在 AIME25 上，近似注意力选 token 的误差在输出概率集中时影响很小，但在概率分散的不确定步骤里，下一步最可能 token 的翻转率高达 65%。过长生成里的重复推理也更容易答错。RoCoKV 用上一步输出分布的熵动态调预算，不确定时多留上下文，确定时加强剪枝，无需额外前向计算。它还用近期上下文摘要压低重复 token 的选中分数，避开全缓存两两比对。工程上它作为插件接入 vLLM，用三阶段融合 CUDA kernel 保留分页 KV cache 和 CUDA 图执行，把稀疏压缩变成端到端加速。在两个推理模型和三个数学基准上，紧预算下的准确率高于所测压缩基线。在 vLLM 中用 DeepSeek-R1-Distill-Llama-8B 测 AIME25，比 Full-KV 提速 1.27 倍、吞吐提高 38%。

Berth: SLO-Preserving GPU Sharing Without New Preemption

USC

在线推理 GPU 平时大量闲置，但混跑训练等后台任务常会导致毫秒级 SLO 难以达标，现有方案要么几乎停掉后台，要么得改写 kernel 或改驱动。这篇论文指出，商用 GPU 自带的时间片调度器本来就能在不到一毫秒内抢占运行中的 kernel，它缺的是优先级，而优先级完全可以在用户态制造。免特权用户态系统 Berth 不改应用、框架、闭源库或驱动，在请求期间暂停放行后台 kernel，空闲时限制排队量，并缩短后台时间片以压住长算子开销。在多类 MLPerf 场景中，它平均 SLO 达标率达 95.8%，接近单跑的 97.9%，并保住 48% 的后台单跑吞吐，超过最接近基线的两倍半。面对持续批处理 LLM 服务，它按每步剩余裕度放行后台任务，几乎满足全部逐 token 目标并让训练持续运行。

Mohammadali Khodabandehlou, Mahdi Alizadeh, Lei Gao, Murali Annavaram, Bhaskar Krishnamachari

TripleKV: Predict, Prefetch, Protect -- KV Cache Management for AI Agents

UIUCNNTUAIBM

多 agent 并发调用工具时，空闲上下文的 KV cache 容易被挤出显存和内存，恢复推理再从 SSD 临时读回往往卡上几秒。直接把 KV 块钉在或预取回显存，又会挤占推理空间并拉长排队。TripleKV 抓住下一轮复用前缀已知、只有工具耗时未知的特点，结合工具类型、输入参数和实时输出线索预测结束时间，提前把 KV cache 从 SSD 预取到主机 DRAM。同时它在 DRAM 用分级队列防 LRU 过早淘汰预取块，并去掉与显存重复的副本。预取到主机 DRAM 而非稀缺显存，既藏住慢速 SSD 读取，又不抢线上推理显存。 在四个 agent 基准上，它将关键路径读 SSD 的请求占比从最高 76% 压到 10% 以下，相比带 DRAM 和 SSD 层的 vLLM 将 P95 TTFT 最高降了 49%，尾延迟和吞吐也优于近期显存固定与预取方案。

Twindex: Index Cache Offloading with Coarse-to-Fine Selection for Long-Context Sparse-Attention Serving

UIUCIBM

稀疏注意力模型在百万 token 解码时，哪怕主 KV cache 已卸载到主机内存，留在显存里的索引缓存仍会卡住并发，在所测的 Qwen、DeepSeek 和 GLM 三款模型上最高占单请求 HBM 的 90%。索引器每步都要扫全历史，直接卸载过 PCIe 太慢，单纯低精度压缩又会丢召回。Twindex 先离线拟合跨输入共享的位置成分并只压缩残差，只在 HBM 留短索引和热缓存，把原始索引放到主机内存。每步先扫短索引圈出大候选集，再读原始索引由原索引器复算选出 top-k，不改模型权重，也能跑进 CUDA 图。在主机内存不限批次、Qwen 与 GLM 共享前缀主 KV 时，三款模型的解码吞吐达到优化后主 KV 卸载基线的 1.25 到 2.54 倍，评测均分相对基线最多低 3.1%。索引压小后，主机内存可能就会成为下一道并发瓶颈。

Yuxuan Xia, Jiakun Fan, Han Meng, Hao Mark Chen, Shenji Wan, Dongsheng Yang

Accelerating Mixture of Block Attention via Dynamic Routing, KV-Centric Execution and Runtime Pipelining

长上下文块稀疏注意力如果给每个 query 固定选块预算，分数集中时会多算无关块，分散时又会漏掉相关块。按 query 区间分配 GPU 任务，还会让多个计算单元重复加载同一 KV 块。LightningMoBA 保留 MoBA 的均值池化打分与 softmax 计算，改用相对分数阈值动态选块。执行上它以 KV 块为中心，把被大量 query 选中的块拆成行数受限的子任务，并在 Hopper GPU 上用流水线重叠 KV 读取、不规则 query 聚合与矩阵计算。在五个模型的 RULER 评测中，它在匹配 Top-16 预算下比 FlashMoBA 将端到端生成提速 1.20 到 1.60 倍。平均分从 74.42 升到 75.28，但 64K 下变量追踪任务普遍掉点。同后端对照表明，小预算提速主要靠执行优化，到 Top-64 时，动态路由在评测模型上的速度与精度收益才同步显现。

Yingqi Shi, Junru Lu, Yun Liu, Di Yin, Xing Sun

Announcing distributed KV caching for self-hosted LLMs with Amazon ElastiCache

Amazon

自建 LLM 推理跑长上下文多轮对话或文档问答时，单机显存和内存的 KV cache 容量有限且无法跨机，请求切到别的服务器、会话隔久回来或节点故障都要重算 prefill。Amazon 在 ElastiCache 的 Valkey 服务推出全托管分布式 KV cache，在同可用区为 GPU 集群提供共享缓存层。vLLM、SGLang 和 TensorRT-LLM 经开源 LMCache 改配置即可接入，热块留 DRAM、冷块沉 NVMe，经 EFA 的 RDMA 直传宿主机。缓存跨机共享后，请求不必再绑在单台机器上，新扩节点和故障接管都能直接复用。共享文档问答测试中，单机每秒请求数翻倍，扣除缓存费用后每百万输出 token 成本降 40%。跨八款模型实测，命中缓存可把 TTFT 降低 55% 到 93%。长上下文复用及共享系统提示的零售广告场景最受益，部署前可用开源 KVTrace 离线估算收益。

Meet Bhagdev, Chaitanya Nuthalapati, Kevin McGehee

ECHO-2: A Large-Scale Distributed Rollout Framework for Cost-Efficient Reinforcement Learning

大模型做 RL 后训练时，rollout 占了大部分时间，却常和更新挤在昂贵的数据中心 GPU 上，还常让训练节点空转。ECHO-2 把集中训练留在少量数据中心 GPU，把 rollout 卸载到广域网上更便宜的异构推理节点。它把策略滞后步数当作可控预算，让采样、权重分发和训练重叠，按单位吞吐成本从低到高启用刚好够用的节点。下发权重时，节点组成并行转发链逐块接力，装完就切到新版本采样，绕开训练机上行瓶颈。在 Qwen3-8B 的 GRPO 数学后训练中，它在广域网下达到同等 AIME 精度，累计成本比集中式基线低 33.3% 到 36.3%，滞后不超过 6 步时效果接近同步基线。用有界滞后和链式接力消化广域网延迟，便宜的分布式推理就能接手 rollout 而不拖慢训练。
