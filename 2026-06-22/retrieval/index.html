Stellar: Scalable Multimodal Document Retrieval for Natural Language Queries

Stellar 针对多模态文档检索中 late interaction（多向量 token 级表示）内存开销过大、难以规模化的问题，提出把 token 级文档 embedding 存到磁盘、检索时只把候选 token embedding 调入内存。两个核心组件：LRF（Lexical Representation-based Filtering）把 MLLM 微调成稀疏编码器产出词项表示先做粗筛缩小候选集；DLI（Efficient Disk-backed Late Interaction）用平衡聚类设计磁盘上的 token embedding 存储布局，再按成本模型动态只加载必要 token。在四个真实基准外加一个新的大规模数据集上验证了效果与可扩展性。

ELVA: Exploring Ranking-Driven Universal Multimodal Retrieval

ELVA 面向通用多模态检索（UMR），指出对比学习把样本简单当正/负二分类会导致 grain blindness——模型忽略 query 里的粒度信息、处理复杂 query 时失效。它提出一个基于规则的 RL 框架：把 RLVR（Reinforcement Learning with Verifiable Rewards）从生成任务扩展到检索，无需 reward model、也无需显式 ranking 标签，用 rule-based reward 按负样本与正样本的相似度差异做差异化排序，同时拉大正负相似度间隔。

INSIGHT把对比学习的二元正负换成按相似度分级的排序信号是这篇的关键——负样本不该一视同仁，离正样本越近越要细分。用 RLVR 替代 reward model 来训练检索/embedding 模型是个值得关注的新范式：当 query 带细粒度意图时，纯 InfoNCE 容易丢信息，引入 ranking-aware 的 reward 可能比单纯堆负样本更有效，对训练社区搜索的语义匹配模型有直接启发。

Yuhan Liu, Pei Fu, Hang Li, Yukun Qi, Chao Jiang, Jingwen Fu, Zhen Liu, Bin Qin

Closing the Calibration Gap in Semantic Caching

论文针对语义缓存（semantic caching，给语义相似 query 直接返回缓存结果以省 LLM 推理成本）的评估问题，指出业界常用的 PR-AUC 只衡量打分排序好坏、不管在固定阈值下是否可用，导致 PR-AUC 最高的模型上线后反而最差。提出两个 cache-aware 指标 P-CHR（Precision-Cache Hit Ratio）AUC 和 CRR（Calibration Retention Rate），并把离线-线上质量差拆成可恢复的校准分量和由数据集正例率决定的不可约结构分量。实验显示校准差距主要由训练目标决定、与数据规模关系不大，post-hoc 校准只能部分弥补。

INSIGHT论文的判断是：语义缓存的模型选型本质是校准问题，PR-AUC/AUC 这类排序指标会系统性误导固定阈值场景的上线决策。这点对社区搜索同样成立——相关性匹配模型最终要在某个分数阈值上做召回/不召回、缓存/不缓存的硬决策，光看 AUC 选模型会踩坑，应改用 P-CHR 这类带阈值利用率的指标，并把校准当作训练目标的一部分而非事后补救。

Aditeya Baral, Radoslav Ralev, Iliya Sotirov Zhechev, Srijith Rajamohan, Jen Agarwal

Query-aware Routing for Filtered Approximate Nearest Neighbors Search

论文系统评测了主流类别过滤 ANN（向量相似度 + 属性谓词）方法，发现在多数据集、三种谓词下没有单一方法占优，甚至同一数据集同种谓词内最优方法也随 query 而变。于是提出 query-aware 路由框架：用轻量 ML 模型预测每个候选方法在该 query 上的 recall，再查离线 benchmark 表（每个方法+参数到实测 recall/QPS 的映射）选 recall-QPS 权衡最好的方法。消融把 22 个候选特征收敛到 3 个，并用回归而非分类作为预测目标。在 6 个训练数据集训练、5 个未见验证集上取得 SOTA 的 recall-QPS 平衡，路由开销可忽略。

INSIGHT没有一个过滤 ANN 方法通吃、连同库同谓词都因 query 而异，这个实测结论本身就值得记——别迷信单一索引方案。query-aware 路由把方法选择变成一个三特征的轻量回归预测问题，对带属性过滤的社区搜索（按时间/板块/标签过滤再做向量召回）很实用：可以在线根据 query 特征动态切换召回策略而非固定一条；回归优于分类作为路由目标这点也能直接复用。

Qianqian Xiong, Mengxuan Zhang

When Global Gating Is Enough: Admission-Time Hubness Control in Anisotropic Vector Retrieval Systems

论文研究向量 hubness（少数点成为大量 query 的最近邻）带来的 RAG 投毒风险——一个注入文档可能影响无关请求。现有防御靠周期性 reverse-kNN 扫描，存在暴露窗口且要反复全库计算。论文提出 admission-time 控制：在文档入库前用 sentinel queries 给候选打分、隔离类 hub 文档。在两个 10 万文档语料、五种编码器、攻防 query 不相交的设置下，全局 gate 在 embedding 空间关键点达到 recall 1.0、HotFlip 攻击下 0.91±0.07、通用文档 1% 误报；per-topic gate 无可靠收益。HNSW 上入库延迟仅增约 3.1%，打分到 10^6 向量仍平坦。

INSIGHT把 hubness 防御从周期性全库扫描前移到入库准入打分是关键设计，省掉暴露窗口和重复全库计算；各向异性导致 per-topic gate 没用、全局 gate 就够这个发现也反直觉。对运行 RAG/向量召回的社区搜索系统，这套 admission-time gating 给出了低开销（+3.1% 入库延迟）的鲁棒性方案，可借鉴用于 UGC 内容入库时过滤异常 hub 文档，防止个别内容污染大量无关 query 的召回结果。

Prashant Kumar Pathak, Tarun Kumar Sharma

MonaVec: A Training-Free Embedded Vector Search Kernel for Edge and Offline AI Systems

MonaVec 是面向边缘/离线 AI 的确定性嵌入式向量检索内核——目标场景没有服务器、网络、训练数据，部署形态对标 SQLite（单文件、单函数调用）。其量化核心默认免训练且数据无关：用 Randomized Hadamard Transform（RHDH）把任意输入分布调向 N(0,1)，再用预计算的 Lloyd-Max 表量化到 4 bit（8x 压缩），无需学习码本、无需数据扫描。索引落成单个 .mvec 文件，内嵌 ChaCha20 旋转种子保证跨架构可复现、同构建字节级一致。在 AG News（45K×1024 维 BGE-M3，cosine）上 4-bit BruteForce 达 0.960 Recall@10、仅 27MB，召回超过 float32 FAISS-IVF 和 8-bit usearch；可选 IvfFlat/HNSW 后端支撑百万级语料，纯 Rust 实现带 Python 绑定。

INSIGHT免训练、数据无关的 4-bit 量化（RHDH 把分布调成高斯 + 固定 Lloyd-Max 表）是这篇最可借鉴的技术点——不用过库训练码本就拿到 8x 压缩且 0.960 Recall@10，比需要数据 pass 的方案省事。虽主打边缘/离线场景，但先 Hadamard 旋转再固定表量化的思路，对服务端向量检索的低成本压缩同样有参考价值；字节级确定性复现对需要可审计/可回归的检索系统也是个加分项。
