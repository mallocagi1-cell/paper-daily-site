UniRec: A Unified Expressive-Aligned Generative Recommendation Framework for E-commerce

已录用 RecSys 2026

生成式推荐逐层生成商品的 Semantic ID，在生成第一层之前看不到任何商品侧信息，这是它和判别式排序模型之间的差距：判别模型给候选打分时能直接看到商品的类目、店铺、品牌这些特征，和用户特征做交叉。UniRec 先让模型生成商品的类目，再在已知类目的条件下生成 Semantic ID，相当于在解码路径里补回判别模型能用的商品特征。上线后订单提高 4.76%，GMV 提高 5.60%。

OneLatent: Latent Reasoning for Efficient Foundation Recommendation Models

Kuaishou📖 深度解读 · 12 分钟 →

把大语言模型当作推荐底座时，让模型先写一段自然语言推理再输出下一个物品的语义编码，推理文本比语义编码长得多，解码时间和吞吐都被它拖住。OneLatent 的做法是在用户上下文后面接 3 个固定的特殊 token，训练分几步：先让模型在这些 token 之后复现教师大模型写的推理文本，再改成在它们之后直接输出目标语义编码；上线时只接这些 token，不生成任何推理文字。在工业数据上，OneLatent 前 64 个候选的语义编码命中率比先写推理再作答高 17.44%，推理吞吐是显式推理的 17.49 倍。

GenPage: Towards End-to-End Generative Homepage Construction at Netflix

已录用 RecSys 2026Netflix📖 深度解读 · 12 分钟 →

Netflix 首页原来由多阶段推荐系统拼出来，先召回候选行和候选影片、再分别排序、最后组页，GenPage 改用一个 decoder-only Transformer 直接生成整页。首页由多行组成，每行是一个主题。用户历史、账号属性和请求信息编码成 prompt，模型按从左到右、从上到下的顺序逐个生成行 token 和影片 token。训练照搬大模型的流程，先在线上获得正反馈的首页上做下一 token 预测预训练，再用加权二分类或强化学习做后训练：前者给每个曝光的行或影片按用户反馈的正负定标签、按奖励大小定权重，后者按整页曝光影片的奖励之和来优化。它在 14 天 A/B 中把 Netflix 用来决定新算法能否上线的核心用户互动指标提升 0.24%，端到端延迟降低 20%。

Coarse-to-Fine Long-term Interest Modeling for Generative Recommendation

已录用 RecSys 2026📖 深度解读 · 11 分钟 →

生成式推荐一个码一个码地生成下一个物品的 Semantic ID，注意力计算量随序列长度平方增长，所以这类模型通常只吃最近几十条行为，用不上长期历史。GLASS 按 Semantic ID 的层级分开用长期历史。生成第一层码之前，它给每个一级码取该类物品向量的平均当原型。再把余弦相似度区间等分成若干档，统计长期历史里和原型的相似度落在每一档的物品数，所有一级码的计数拼起来经一个小网络压成一个兴趣 token 送进编码器；第一层码生成之后，拿它当检索键，从长期历史里取出同一大类的物品，辅助生成后两层码。在 TAOBAO-MM 上，R@1 比最强基线高 21.57%；短视频平台两周 A/B 中，召回率绝对提升 3 个百分点。

CSG4Rec: Collaborative-Similarity Guided Semantic IDs Tokenization for Generative Sequential Recommendation

生成式推荐把每件商品编成一串 Semantic ID，这项工作发现，把用户行为上的相似关系直接放进编 ID 的空间里学，比事后再去对齐效果更好，在三个常用数据集上都超过了已有的强基线。现有做法先按商品内容编好 ID，再拿 ID 的向量去对齐协同过滤学到的 embedding，但两种向量不在同一个空间里，硬对齐效果有限，也学不到哪些商品常被同一批用户购买。它改为先用协同过滤给每件商品找出行为上相近和不相近的商品，再让前者的 ID 向量靠近、后者远离。它还把用户交互过的商品的文本向量合起来，同样编成用户的 Semantic ID，和商品 ID 一起输入生成模型。商品 ID 不光要反映内容，也要反映哪些人会一起买它。

Wei Liu, Bo Yang, Qianyang Zhu, Ruijie Xiao, Sirui Huang, Qing Li

Evaluating LLM-based conversational recommenders with semantic and genre-aware metrics

让大模型陪用户聊天、给他推荐电影时，常用的 Recall@K 和 BLEU 只看推荐的是不是数据集里用户最后选的那一部，可很多没对上的推荐其实也合他的口味。在 ReDial 和 INSPIRED 两个电影推荐对话数据集上，这项研究统计到，标准答案只有 39% 的时候出现在前 10 个推荐里，而在推荐出的所有电影中，有 53% 至少和标准答案属于同一类型。他们据此加了按电影类型计分的指标，前 10 个推荐里只要有和标准答案同类型的电影，就算推荐对了，再用同一套流程比较了六个指令微调过的大模型。结果是模型越大不一定推荐得越好，是否接入知识图谱、给多少上下文影响更大。评测对话推荐，要看推荐是否对上用户的偏好，而不只看有没有猜中唯一答案。

Darshna Parmar, Dhruv Shah, Pramit Mazumdar, Saurav Mallik

Integrating implicit desire fusion for proactive conversational recommendation systems with LLMs

对话推荐时，先从用户零散的几句话里推断他真正想要什么，再决定追问还是推荐，成功率会高得多。在 LastFM 音乐推荐上，让 GPT-3.5-Turbo 和模拟用户对话，加上这一步后，15 轮内推荐成功的比例从 0.327 提高到 0.583。比如用户先说想听点安静的音乐，又补一句不要快节奏，过去常听爵士和氛围音乐。DESIRE 让大模型把这些话、他的收听记录、检索到的歌曲信息，比如某首爵士乐节奏很慢，和他刚拒绝过的歌放在一起，推断他真正的需求。之后大模型判断这些信息够不够推荐，不够就追问，比如直接问或让用户在两个选项里比较，够了就推荐，并用摆证据或打感情牌这类方式说服，回复里提到的歌曲属性以检索到的信息为依据。

Sitong Yan, Shengli Song, Chengen Lai, Jingyang Li, Guangneng Hu
