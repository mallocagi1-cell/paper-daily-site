ULME: Predictive Coupling for Mutually Reinforcing Embedding and Language Modeling

Yang Liu, Zhiqiang Yuan, Shu-Dong Huang, Jiancheng Lv, Liwei Yang, Qiwei Yan, Kailin Lv, Jinchao Zhang
25 minread4.30score

In RAG, in-context example selection and agent memory, the same query is usually processed twice: an embedder first encodes it into a vector for retrieval, and a generator then reads it again to answer. The two models are trained separately and their representations of the same query never interact. The authors, from WeChat AI at Tencent and Sichuan University, argue that a generative model, on its way to a coherent answer, already encodes an "answer-relevant reading of the query" in its hidden states, which is largely what a good embedding should be. They propose ULME, a post-training framework that inserts a chain of learnable slots into a causal decoder and uses a stop-gradient "predictive coupling" loss so that generation shapes the embedding. Across Qwen2.5 and Qwen3 at 8 scales from 0.5B to 8B, a single ULME checkpoint beats the strongest same-backbone open baseline on MTEB by 3.3–4.1 points, while matching or beating a generation-only fine-tune on MMLU, GSM8K, MMLU-Pro and HumanEval.

1. The problem: existing "unified models" only unify parameters

Another line of work turns an LLM into a pure embedder: E5-Mistral and NV-Embed fine-tune causal LLMs contrastively and pool the last token, while LLM2Vec removes the causal mask to obtain a bidirectional encoder. They show decoder hidden states are enough for strong embeddings, but the fine-tuned model is no longer usable as a generator.

Putting retrieval and generation into one model is not new. GritLM trains one LLM with both a contrastive embedding loss and a language-modeling loss, and GEM injects embedding ability into a generative LLM through extra tokens and self-supervised contrast. The authors see these as only "partially unified", with two gaps.

Mechanism. GritLM switches to bidirectional attention for embedding and back to causal attention for generation, so its embedding readout and generative hidden states do not lie on the same causal trajectory.

Objective. The two losses are optimized in parallel over shared parameters but never supervise each other: generation does not depend on the learned embedding, and the embedding receives no direct signal from generation-side representations. Parameter sharing alone establishes no interface between them.

The concrete conflict is the readout position. Causal LLM embedders normally pool the query's last token, but in a unified model that position must also predict the first answer token. The authors call this a representational collision: retrieval needs a sequence-level state that is globally comparable under inner product, language modeling needs a position-dependent state that supports the LM head, and one hidden state is asked to play both roles.

2. Method: a slot chain and three losses

Slot chain. Following latent chain-of-thought ideas such as Coconut and pause tokens, ULME inserts N learnable slots between query q and answer a, so a training example reads q∥⟨\textscemb⟩1:N​∥a and a document is encoded as d∥⟨\textscemb⟩. The slots are ordinary positions in the causal forward pass: each attends back to the query and earlier slots, and every answer token attends to all slots. No mask is changed and no side branch is added; attention is causal throughout, and one forward pass yields both embedding and answer. Slot 0 is the semantic embedding and slot $N-1$ the reasoning embedding.

Semantic retrieval loss. A symmetric InfoNCE between the slot-0 query representation and the document representation, with temperature τ and cross-rank in-batch negatives.

Answer generation loss. Standard next-token cross-entropy over the answer span only; slots carry no token loss, but because the slot chain sits on the causal path that produces the answer, the language-modeling gradient reaches them through the answer's attention.

The authors note that these two losses alone are the "parallel objectives" of prior unified models: the semantic loss pins slot 0 to document space but says nothing about the answer, and the generation loss conditions on the slots but never asks any slot to represent anything specific.

Predictive coupling. The third loss aligns the query-side terminal slot hq(N−1)​ with a pooled summary rqa​ of the answer-side hidden states from the same forward pass (by default their mean), via a one-sided in-batch InfoNCE with stop-gradient sg(⋅) on the answer side:
Lpred​=−log∑k​exp(⟨hq(N−1)​,sg(rqa,k​)⟩/τ)exp(⟨hq(N−1)​,sg(rqa​)⟩/τ)​
The stop-gradient is deliberate: rqa​ sees both q and a and is more informed than hq(N−1)​, which sees only the query and slots, so a well-posed objective lets the less-informed side reach toward the more-informed one; letting gradient flow into rqa​ would push the answer side toward whatever is easy to contrast in a batch, distorting the hidden states the generation loss must supervise. It amounts to one-sided distillation from the answer-side representation into a query-only latent available at inference. The total loss is a weighted sum with λsem​=λgen​=1.0, λpred​=0.3, and defaults $N=4$, τ=0.05.

Illustration: for the query "how do I deduplicate a Python list while keeping order", the training answer is code using dict.fromkeys plus an explanation. The semantic loss pulls slot 0 toward the matching document's embedding; predictive coupling pulls slot 3 toward the mean of that answer's hidden states. At inference no answer is generated: running the query plus 4 slots reads out the embedding.

3. Embedding results

Training uses LLM2Vec-format E5 contrastive data (embedding side) and OpenThoughts-114k (generation side), AdamW at 1×10−5. Every number comes from the final checkpoint of a single run per configuration, with no capability toggled off and no head fine-tuned in isolation. Baseline numbers are those reported by LLM2VEC-GEN on the same backbone.

On Qwen3-8B ULME reaches 66.0, 9.2 points above LLM2Vec and 4.1 above LLM2VEC-GEN; gains over LLM2Vec are +7.1, +7.3, +9.2 across the three scales, and over LLM2VEC-GEN +3.3, +3.5, +4.1. On 8B against LLM2Vec, Retrieval gains +9.6, PairClassification +9.0, Summarization +9.0, STS +9.6 and Clustering +9.4. The authors note the largest lifts, Retrieval and Summarization, are on tasks whose target is itself a produced text. Against LLM2VEC-GEN, though, Clustering and Classification are slightly lower at 1.7B and 4B (−1.5, −0.6), and Classification is 0.5 lower at 8B, so the gain is not everywhere. By category, ULME's edge over LLM2VEC-GEN comes mainly from Retrieval (+8.2 to +8.9), Summarization (+7.0 to +8.6) and PairClassification (+5.3 to +5.7), with Reranking and STS gaining 1.5–2.5 points.

Reasoning-intensive retrieval. On BRIGHT (nDCG@10) ULME is 0.7, 0.8 and 1.2 points above LLM2VEC-GEN (1.7B/4B/8B), reaching 21.4 at 8B; on AdvBench-IR (lower is better) it cuts the score relative to LLM2Vec by 25.3% at 1.7B and 20.3% at 8B, another 1.3–1.8 points below LLM2VEC-GEN. Both directions improving rules out trading one property for another.

4. Generation results

Against a generation-only fine-tune (Gen-only FT) on the same OpenThoughts-114k data: on knowledge and math (MMLU, GSM8K, MMLU-Pro), ULME matches or exceeds it everywhere except a −0.1 on Qwen3-8B MMLU, with MMLU-Pro gains of +1.0, +2.0, +1.7 and GSM8K at 8B of 89.5 vs 78.6, 10.8 points higher. On code it is ahead at every scale, by 2.4–4.9 points on HumanEval and 3.0–4.9 on HumanEval+, with 67.7 vs 62.8 on HumanEval+ at 8B. The authors' explanation is that making the query slot summarize what the model will generate is especially informative for structured, functionally verified outputs. Both ULME and Gen-only FT sometimes trail the original backbone, which the authors attribute to distribution shift from continued training on OpenThoughts-114k rather than to the joint objective.

5. Ablations: the three losses really interlock

Ablations use Qwen2.5-7B-Instruct, with the 10-task MTEB-lite for embedding and MMLU and GSM8K for generation.

Number of slots. With no slots ($N=0$, pooling the query's last token) MTEB-lite is 58.6, 5.2 points below the 63.8 of $N=4$, and MMLU is 2.0 lower, confirming the readout collision is a real cost. One slot recovers most of the gap, $N=4$ is best, and $N=8$ dips slightly, which the authors attribute to a longer chain diluting gradient per slot.

Loss decomposition. Removing the semantic loss collapses MTEB-lite from 63.8 to 31.2 with generation untouched; removing the generation loss drops MMLU by 14.7 and GSM8K by 15.8, while embedding falls only to 61.0. More telling are cases where a score moves although its own loss is untouched: without the generation loss embedding still loses 2.8 points, showing that answer-side states shaped by language modeling feed signal to the query slot; without predictive coupling generation is flat but embedding loses 3.6 points, the cleanest measure of what the coupling contributes, i.e. the cost of reverting to the "parallel losses" regime.

Predictive target. Mean pooling over the answer scores 63.8, a length-weighted mean 62.7, and the last answer token 61.9. The last answer token is also pulled by next-token prediction, so using it as the target imports local generation pressure. Generation barely changes under any choice, showing the two capabilities are supervised through distinct channels of the shared computation.

The two slots do different jobs. Slot 0 leads most on tasks where relevance is mostly lexical or entity overlap (SprintDup +4.84, CQAGaming +3.09, Touche2020 +2.85, HotpotQA +2.60); slot $N-1$ leads most where one must understand what a document claims, summarizes or expresses (ClimateFEVER +3.60, SummEval +2.29, StackExchangeP2P +1.83).

6. Limitations and industry relevance

The paper has no dedicated limitations section; the following are read from the setup. The main tables show only three Qwen3 scales, with the other five backbones in the supplement; all ablations use one backbone (Qwen2.5-7B) and a 10-task subset; each configuration is a single run with no variance reported; baseline numbers are cited from LLM2VEC-GEN rather than reproduced, and backbones it does not report are omitted; unified models such as GritLM and GEM are not compared in the same table; and neither the inference overhead of the slots nor end-to-end gains in a real RAG or agent system are reported.

For industry, the significance is the deployment shape. RAG and agent-memory systems commonly run an embedder and a generator side by side, each with its own memory footprint and maintenance. ULME offers a workable path: one checkpoint, causal attention throughout, no mode switching, with neither embedding nor generation behind dedicated models, and embedding needs only the query plus 4 slots, not a generated answer. Two engineering details are worth borrowing: give the embedding readout its own positions instead of overloading the next-token position, and use stop-gradient to distil the side that "knows the answer" into a query representation usable at inference. Whether it really removes a separate embedding service depends on recall on your own corpus and the latency the slots add.
