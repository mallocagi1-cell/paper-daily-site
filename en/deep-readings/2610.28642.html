Controllable Generative Recommendation via Guided Token Refinement

Haichao Zhang, Zhixuan Liang, Chong Zhang, Zixi Chen, Wen Wang, Jia Wang
19 minread4.10score

ReGen performs three online operations: generate item codes in parallel, refine them under a diversity objective, and decode valid catalog paths. Offline, it trains a semantic tokenizer and a masked predictor. Inference-time control keeps their parameters fixed. On the Instruments dataset, the controlled configuration produces 99.97% valid IDs. Validity measures whether a code maps to a real item; relevance requires separate evaluation.

1. Problem and motivation: change the candidate pool as intent changes

This work addresses how a generative recommender can explore different categories when the user’s immediate goal changes. A Semantic ID is a short sequence of discrete item codes. Earlier positions represent coarse semantics; later positions add detail. Left-to-right generation commits to an early prefix that constrains subsequent choices.

Reranking can rearrange only items already retrieved. ReGen instead changes the semantics explored during candidate generation and then repairs the details. In its title, “Controllable” refers to inference-time steering, “Guided” to frequency-based penalties on coarse codes, and “Token Refinement” to repeatedly predicting uncertain positions.

RQ-VAE, a residual-quantization variational autoencoder, approximates item embeddings with multiple codebooks. A trie organizes catalog IDs into valid paths.

2. Method: steer coarse semantics and repair the details

The online generator must keep fine-grained codes consistent after a coarse decision changes. Each item uses four code levels, with 256 entries per codebook. A bidirectional Transformer reads user history and partially specified target codes, predicting masked positions together.

During training, coarse positions have lower masking probabilities. This teaches the model to complete details from known coarse semantics. Online decoding starts fully masked, preserves reliable positions, and predicts uncertain ones again. Parallel prediction happens within each round; inference still uses multiple rounds.

For a controlled code level, the guidance rule is:
z~l​(v)=zl​(v)−λlog(1+nl​(v)).
Here, l is the code level, v a candidate code value, zl​(v) its original logit, nl​(v) its frequency in the user’s history, λ the guidance strength, and z~l​(v) the adjusted logit. Frequently visited coarse regions receive larger penalties, giving other regions more probability.

The predictor then estimates confidence as the largest predicted probability at each position. Positions below the round’s threshold are masked and predicted again. This lets fine details adapt to the guided coarse choice.

Trie constraints remove code values that cannot complete a valid catalog ID given the fixed positions. Beam search keeps multiple promising paths rather than one prediction. The default beam width is 50; results stabilize at about four refinement rounds.

After decoding, the system maps IDs to items, removes history items and duplicates, and selects the final list with an additional reward for category coverage. Reported diversity therefore involves generation-time guidance and list construction. Ablations hold the latter fixed to isolate individual components.

A concrete request

The following codes and numbers are illustrative. A user has browsed guitar accessories nine times and now wants a broader mix of instruments. A practice drum pad has hypothetical ID $(12,8,31,6)$.

Suppose the guitar-accessory coarse code has logit 5 and history count 9, while a percussion-practice code has logit 4 and count 0. With λ=1, the first becomes 5−log(10)≈2.70, while the second stays at 4. The percussion region can now enter the beam.

Some existing fine codes may conflict with this new coarse choice. The model masks low-confidence positions and predicts them again using history and retained codes. Trie constraints remove nonexistent combinations. A valid drum-pad ID becomes an item candidate, after which list selection checks whether it adds a category.

History-frequency guidance and list-level category gain operate on different sets: past interactions and the current output list, respectively.

3. Contributions: separate steering, consistency, and validity

Each component solves a distinct generation problem. Coarse guidance shifts the distribution; confidence-based refinement restores consistency; the trie restricts outputs to catalog items.

Removing refinement can increase diversity while sharply lowering recall. Removing the trie yields many codes that cannot map to items. Category coverage alone therefore misses important failure modes.

The experimental design also distinguishes accuracy-oriented and control-oriented configurations. Control should be judged at comparable diversity levels rather than by combining unrelated best-case numbers.

4. Experiments: compare recall at matched diversity

The study uses the Instruments, Industrial & Scientific, and Video Games subsets of Amazon 2023. Interactions are ordered chronologically, with the final item held out for testing and the preceding item for validation.

Recall@10 checks whether the held-out next item appears in the top ten. NDCG@10 also rewards a higher position. Diversity@10 measures category coverage. TIGER-MMR combines the Semantic-ID generator TIGER with maximum marginal relevance reranking. ComiRec models multiple user interests. Paragon generates task-specific parameters for controllable recommendation.

ReGen trails strong accuracy baselines on Video Games. The evidence supports adjustable exploration with controlled relevance loss, rather than universal accuracy leadership.

5. Limitations: category diversity is the evaluated objective

The authors leave systematic fairness, exposure-balance, and freshness evaluation to future work. The motivation figure illustrates more objectives than the experiments test.

Control also depends on the semantic hierarchy learned by the tokenizer. If coarse codes align poorly with item semantics, their history counts become a weaker steering signal. Tokenizer-agnostic control is an explicit future direction.

Offline category coverage does not establish whether users prefer the newly explored categories. A deployment evaluation should record usable candidate count, relevance, diversity, and latency together.

6. Practical implications: make control observable

For an existing Semantic-ID retrieval system, compare generation-time guidance with current reranking while holding list length and downstream ranking fixed. Measure which additional categories also produce relevant candidates.

Track ID validity as a serving metric. Catalog updates, trie updates, and ID-to-item mappings must stay consistent so controlled decoding produces enough usable candidates.

Vary guidance strength and refinement rounds independently. Plot coverage, recall, and latency together. Four rounds is a useful offline starting point from this paper; the local catalog and response budget determine the operating setting.
