Think Harder Where It Matters: Item-Level Adaptive Recursion for Sequential Recommendation

Zhanshuo Cao, Jiakai Tang, Yuqi Zhou, Sunhao Dai, Jun Xu
13 minread4.10score

LoopRec assigns computation depth to individual items in a user’s history. Every position receives an initial shared encoding pass, then binary gates decide which positions continue through the same block. Training uses next-item prediction, routing regularization, and a warm-up stage. On Software, it improves SASRec NDCG@20 by 5.68% relative.

1. Problem and motivation

Sequential recommendation predicts a user’s next item from ordered interactions. Fixed-depth encoders process every historical item equally. LoopRec asks whether some positions are already useful after shallow processing while others benefit from more context integration.

The authors first freeze a trained three-layer SASRec, a self-attention sequential recommender, and stop individual positions early. Saturation depth is the earliest stopping depth that preserves the final recommendation set. A second diagnostic searches depth assignments for the last five items using the true target. This target-aware oracle is a diagnostic upper-bound tool, not the deployed router.

2. Method

The model recursively reuses one backbone block. L2R3, for example, means a two-layer shared block applied at most three times. Sharing keeps parameter growth limited and gives different exit depths a common transformation family.

After the full initial pass, a router reads each active position’s current hidden state and a recursion-index embedding:
pi(r)​=σ(g(hi(r)​,er​)).
i indexes a historical position, r is the recursion index, h is its state, e is a depth embedding, g is the router, and sigma is the logistic function. Positions whose exit probability reaches the threshold stop; the others continue. Remaining positions stop at the maximum recursion budget.

Only continuing positions enter the next recursion. Their original order is preserved under a causal mask, while stopped states remain unchanged. A depth-specific readout combines the selected state with the original input. Hard forward routing is coupled with differentiable readout weights so recommendation gradients can train the router.

Training addresses two failure modes. A balancing term discourages concentration at a narrow set of depths. A router z-loss discourages excessively confident gates before useful representations have formed. The combined objective is:
L=Lrec​+λb​Lbal​+λz​Lz​.
Lrec is next-item cross-entropy, Lbal regularizes depth usage, and Lz stabilizes gate scores. The lambda coefficients control the two regularizers. They add routing constraints without adding item-prediction labels.

Warm-up forces every valid position to maximum depth and disables routing regularizers. The router is enabled after the backbone has started to learn. Shared-block depth, recursion budget, and warm-up length are consequential structural choices.

For an illustrative history A–E and candidate F, the first pass contextualizes all five items. A and B might stop immediately, C after another pass, and D and E at the recursion cap. Readout combines the selected states to score F. These letters and exit choices are illustrative; inference never observes the true next item to choose depths.

3. Main contribution

Computation allocation becomes part of recommendation modeling. The router makes its decision after seeing the latest context, rather than assigning all depths before encoding. The learned allocation tends to spend more computation on recent and low-frequency items.

The framework also works beyond attention. The paper tests causal-convolution and linear-recurrent backbones alongside attention models. Shared recursion provides the common interface.

4. Results

Experiments use three Amazon Reviews 2023 categories with chronological leave-one-out splits. Validation NDCG@20 selects checkpoints. NDCG measures position-discounted ranking quality; MRR averages reciprocal target rank. Main-table metrics are means over five runs.

Backbone and datasetNDCG@20: fixed → LoopRec
SASRec / Software0.0944 → 0.0998
SASRec / Office0.0582 → 0.0595
NextItNet / Patio0.0192 → 0.0263
LRURec / Software0.0958 → 0.1001

NextItNet uses causal convolution; LRURec uses linear recurrence. The fourth family, BSARec, adds a frequency-domain bias to attention. Published relative gains use unrounded results, while the absolute table values are rounded.

Encoder-only timing on one A6000 GPU shows L2R4 taking 79.273 ms against 91.230 ms for a fixed model with the same maximum effective depth. L2R2 has nearly unchanged latency despite reduced selected computation. Dynamic indexing and smaller operations absorb some theoretical savings.

5. Limitations

The reported speed tests cover the encoder, not end-to-end candidate scoring. The authors explicitly distinguish selected computation savings from wall-clock gains. All three main datasets come from the same source, and conditioning histories are trimmed to warm-start items.

Production batching must preserve user identity and position order while compacting active sequences. Ultra-long histories and industrial feature interactions were not directly tested.

6. Practical implications

Log chosen depth by recency and item frequency to see where additional computation goes. Compare latency against a fixed model with matched maximum effective depth, and measure the complete request separately from its encoder. Ablations should also separate weight sharing from adaptive stopping to identify which mechanism supplies the gain.
