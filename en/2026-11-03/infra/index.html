5. Flide: Accelerating Decision Inference with Exact State Forking

Inference engines built for generation handle the decision models used in agent systems badly. These models do not generate long text: they attach many short questions to one shared context, and each question outputs a single category. Existing engines either recompute the shared context for every question, or pack the questions together so they interfere and the output probabilities drift. Flide packs the shared context and all questions into one token sequence computed in a single pass. Indices kept on the GPU record which shared context each question belongs to. Attention layers use them so a question sees only the shared context and itself, and recurrent layers such as Gated DeltaNet restart every question from the state at the end of the shared context. The result matches a separate computation exactly, and queries are answered up to 9.5 times faster than with vLLM and SGLang.

6. Trainable Vector Quantization for Large Language Models

Vector quantization can compress an LLM to about 2 bits per weight, but the harder it compresses, the more quality it loses. It splits weights into small groups and replaces each group with the closest vector in a codebook, a shared table of representative vectors. Picking the vector is a discrete choice that gradients cannot fix directly, so existing methods only make each layer's quantized output match the original, one layer at a time. TVQ keeps trainable continuous weights behind the quantized ones: in the forward pass each group of continuous weights looks up its closest codebook vector and computes with it, and the backward pass sends the gradient straight to the continuous weights. The lookup is redone after every update, so once the continuous weights move far enough, a different codebook vector is chosen. That lets the quantized model be optimized for any training objective; the paper uses block-wise knowledge distillation. LLaMA2-70B at 2 bits loses only 1% accuracy on common question-answering benchmarks.

7. ACCT: Asymmetric Cross-LLM Context Transfer

When models of different sizes from the same family are mixed, switching models means prefilling the same context again. ACCT lets the target model use a KV cache another model has already computed: a small model reads a long context, and a large model answers without rereading the text. A small scoring module reads the source model's hidden states and scores each context token for each attention head, trained on how much deleting that token would hurt the answer. How many tokens each head keeps is a learned parameter, the counts across heads stay within one total budget, and each head keeps its highest-scoring tokens. It then uses a trained conversion module to turn the selected tokens' representations into keys and values for the matching target layers and heads. With KV cut by 75%, the target model matches or beats its original quality; on contexts of about 19K tokens, the conversion is 6.5 to 21.2 times faster than the target's own prefill.

8. Prune Gradually, Adapt Sparsely: Efficient Pruning of Large Language Models at Extreme Sparsity

When an LLM is pruned so that 90% of its weights are zero, one-shot pruning degrades sharply, and the strongest method, ELSA, needs optimizer state as large as the model. ETAPS tightens sparsity over several stages, pruning a little more each time, while training weight increments to make up the loss. The increments sit on a fixed, small number of positions; when one is pruned, its slot goes to a surviving weight with the largest accumulated gradient. After each stage it scores weights as the patched weight's absolute value times that position's accumulated gradient, and the next stage prunes the lowest. Across six models it beats ELSA's perplexity at every sparsity tested. Pruning LLaMA2-7B to 90% sparsity takes one H200 instead of ELSA's four.

9. ARK: Avoiding Routing Collisions for KV Cache Transfer in Disaggregated LLM Inference

When prefill and decode run on separate GPU pools, the KV cache must move from one pool to the other, and each transfer lasts hundreds of milliseconds to seconds, making it a huge flow on the network. Switches pick paths with ECMP by hashing packet headers, so two such flows that hash onto the same uplink share it for seconds while neighboring links sit idle. ARK uses the fact that these flows last long: senders tell each other in advance and choose source ports so that concurrent large flows hash onto different spine switches, with no switch changes and no reordering at the receiver. In packet-level RDMA simulation under moderate load, mean flow completion time drops by up to 27.3% and mean TTFT by up to 12.9%.

10. Making Kubernetes AI-Ready for NVIDIA Vera Rubin on Day One

NVIDIA

Getting a new generation of GPU racks running on Kubernetes right away is hard: if the driver, kernel, NICs or scheduling plugins are mismatched in any one place, jobs fail to start or run below capacity. This NVIDIA blog post shows how its AI Cluster Runtime (AICR) handles this for Vera Rubin NVL72. It captures validated settings for the driver, kernel, resource-allocation plugin and more as reusable recipes, generates deployment bundles, and then checks deployment, conformance and cross-node NCCL bandwidth on the running cluster. Validation on early hardware already caught an architecture-detection bug that kept crashing the resource-allocation plugin, and the fix has shipped in the official release. Teams upgrading from GB200 can use this list to plan ahead.
