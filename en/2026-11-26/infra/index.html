Today's infrastructure papers ask how training and serving can use less GPU memory and less waiting without quietly changing answers, and how large models can also run on smaller local devices. One framework treats five common parallelisms as one generalized tensor scheme, and trains trillion-parameter models at tens of exaFLOP per second on more than ten thousand GPUs. Another lets idle inference instances sleep and lends the cards out, but only if wake-up takes seconds. The KV cache can be compressed losslessly from GPU memory onto host DRAM and SSD, and long-context parallelism for linear recurrent models cuts the cost of boundary states. Speculative decoding, scheduling for compressed MoE experts, and native integer quantization each squeeze throughput from drafting, residency, or number formats. A smaller document parser keeps up with much larger general models, and a direct sparse solver speeds up factorization and triangular solves in engineering simulation.

1. Generalized Tensor Parallelism: Powering Trillion-Parameter LLM Training at 10+ EFLOP/s

NVIDIA

Pretraining trillion-parameter language models usually forces a tradeoff between per-GPU memory and throughput. Data parallelism replicates parameters, tensor parallelism and FSDP add communication on every microbatch, and pipeline parallelism leaves GPUs idle while the pipeline fills and drains. For linear layers, these five common schemes are special cases of one framework, generalized tensor parallelism, in which parameters and activations are partitioned and can be gathered back just before use. A parameter gather becomes an optional step before each matrix multiplication, rather than a prelude to a whole Transformer block, so communication can start early without holding memory for too long. On 12,288 GB300 GPUs, an internal two-trillion-parameter MoE model reaches 13.0 exaFLOP per second. Weak-scaling efficiency is 98% from 4,096 GPUs to that scale. The implementation ships in Megatron-Core and can also run million-token sequences on a few hundred GPUs.

2. ModelLess: A Serverless System for Multi-Tier LLM Inference on Shared GPUs

AAnt Group

LLM inference platforms often pin GPUs to a product, so cards sit idle between bursts while other work waits. ModelLess makes inference serverless: idle instances scale to zero and sleep with their weights in host memory, releasing and waking in seconds, whereas a cold start often takes more than four minutes. Freed GPUs can be lent to lower-priority tiers, each with explicit rules for what it may lose if preempted. Preemption stops admission, durably re-enqueues a request, and only then releases memory. Replaying a week of traces from 1,100 H20 cards that served long-tail online models shows that about 38% of GPU-time could be lent under a coarse latency target and one fixed idle threshold, but only as an idealized upper bound when recovery takes seconds. If a cold start takes 240 seconds, even per-service thresholds leave only 8%.

3. LoomKV: Lossless KV Cache Compression from GPU Memory to SSD for LLM Serving

ECNUZZTE

Serving engines offload the KV cache from GPU memory to host DRAM and SSD so multi-turn and agent requests can reuse prefixes, but tight capacity limits concurrency, and lossy compression can change the outputs. LoomKV adds lossless compression without modifying the engine. A calibrated per-head two-level three-bit code stores BF16 KV at 0.71 of its raw size across nine models. Writes leave the original eviction and prefetch path unchanged, and loads decompress straight into scattered GPU pages. On AgentX, when LMCache's LRU policy is at the eviction cliff, tier mode delivers 2.7 times to 3.6 times the goodput of an uncompressed cache. Where raw capacity already holds the working set, compression costs at most 2.2% of throughput, and tier-mode outputs match the uncompressed ones bit for bit. In pool mode, a fused decode kernel reads smaller pages in place, and when the working set already fits it keeps queueing and goodput close to the uncompressed pool.

4. FlashQLA: Efficient Context Parallelism for Gated DeltaNet

Zhejiang UniversityAlibaba

Gated DeltaNet makes the compute linear through recurrent state updates, but chunks still depend on one another in sequence. For long contexts, small batches, or limited head parallelism on a GPU, context parallelism is hard to exploit, and preparing boundary states is especially costly, sometimes taking more than half of the forward time. FlashQLA cuts that preprocessing with decay-aware preparation, shares summary computation across parallelism levels with Dual CP, and picks a configuration from the workload. On a single GPU, it speeds up the forward pass by 1.7 times to 3.1 times over Flash Linear Attention. The backward pass is up to 4.4 times faster. On eight GPUs with context lengths up to a million tokens, Dual CP reaches up to 4.8 times the forward speed of FLA KCP. The automatic choice lands near the best setting on the great majority of inference and training workloads. In real models, most attention heads often have decay windows shorter than eight thousand tokens, which is why decay-aware preparation helps.

5. Wavefront: Low-Rank Drafting with Parallel Causal Refinement for Speculative Decoding

University of OregonAmazon

Speculative decoding lets a cheap drafter propose tokens that the target model verifies in parallel. Parallel block drafters can propose a whole block in one pass, but they drop the dependence among tokens inside the block. A sequential correction head can restore some of that dependence, yet it often overrides most slots, so the expensive full output layer mainly supplies a seed. Wavefront replaces that full layer with a learned low-rank base, lets the correction head see the whole drafted prefix inside the block, and resolves it with a few parallel Jacobi passes. The pass count is fixed, so the draft step can be captured as one CUDA graph in vLLM with fused kernels. On Qwen3-8B, average throughput across math, code, chat, and agent benchmarks is 23.6% higher than DFlash and 10.7% higher than DSpark. The edge over DFlash reaches 28.9% on long-context prompts, and the gains remain as serving concurrency rises.

6. RankServe: Rank-Aware CPU-GPU Scheduling for Memory-Constrained MoE Serving

Stevens Institute of TechnologyNortheastern University

Low-rank compression shrinks the expert pool of an MoE model, but experts kept at different ranks have unequal storage, transfer, and compute costs. Popularity and transfer cost alone cannot decide which experts are worth keeping on a memory-tight GPU. RankServe compares the value of keeping an expert on the GPU with the cheaper nonresident path, either CPU execution or a transfer followed by GPU execution, under that expert's rank and token load, then ranks experts by savings per byte. It updates residency from recent routing and can run a miss temporarily on the GPU without admitting the weights into the cache. A variable-rank runtime executes heterogeneous factors through grouped matrix multiplies, without padding them to a common rank. On a single CPU-GPU platform, against six serving systems, per-model geometric-mean TTFT is 1.69 times to 2.29 times that of the fastest baseline for each configuration. In the same comparison, TPOT is 1.71 times to 2.48 times faster.

7. Shifter Quantization: Compact Representations for Native Integer Computation

Columbia University

Groupwise quantization can preserve accuracy at low bit widths, but grouping weights often stops standard integer matrix multiplies from covering the full dot product, so GPU inference cannot run at full efficiency. Shifter Quantization rebuilds native-width integer operands by appending and shifting shared bits, and a variant, SHI, can use INT4 kernels. On a prefill of about four thousand tokens, the two-bit SQ2 and SHI2 formats reach 2.71 times to 3.77 times the throughput of a llama.cpp Q2_K checkpoint. They also cut WikiText-2 KL divergence by 6.6% to 7.8%. Quality is measured by projection error and KL, and speed is measured in both decoding and prefill. At four-bit and eight-bit settings, prefill throughput and error also improve on the corresponding groupwise-integer and online FP8 baselines. The formats keep quality at low bit widths and let integer matrix multiplies cover the full dot product, instead of being split by grouping.

8. VenusOCR2.0: Towards Efficient and Effective Document Parsing

Tencent

Document parsing has to read text, tables, and formulas accurately and still run fast, and very large general-purpose vision-language models do not always win. VenusOCR2.0 is a compact recognizer of about one billion parameters that uses a dynamic-resolution encoder, spatial token merging, and compact table tokens to shorten sequences and cut structural errors. To ease the autoregressive decoding bottleneck, it adds a parallel draft module, PTPv2, with about sixty-seven million parameters, and keeps token-for-token equivalence with standard decoding. A bounded recursive data engine has the model only probe weaknesses, while external multi-expert consensus and visual verification supply the supervision. On OmniDocBenchv1.6, the overall score is 96.45 and formula CDM is 98.57, ahead of the much larger Gemini-3-Pro at 92.91. Deployed in vLLM on a single H20 GPU, PTPv2 raises single-request speed by 2.96 times. Batched throughput also rises, without changing the tokens of standard decoding.

9. How to Run NVIDIA Cosmos 3 on Local AI Devices Using Hugging Face Diffusers

NVIDIA

Running video generation models locally is hard when weights and intermediates exceed GPU memory. NVIDIA Cosmos 3 Nano generates video from text, images, and other inputs to support physical AI development. This tutorial uses Hugging Face Diffusers to keep most weights in system RAM and move them to the GPU as needed, so generation can run on a consumer card with only 12 GB of VRAM, and you can also try sound and other input types. The tradeoff is higher system-RAM use and more PCIe transfers; the path is not interactive, and it does not stream weights from disk during inference. On an RTX 5070, a 720p text-to-video run in BF16 took 2,624.9 seconds, with peak GPU memory of 9.94 GiB. An FP8 checkpoint can reduce the memory requirement further. Cards with more memory run faster in the tests, but these are single-run measurements, not a formal ranking of GPUs.

10. Accelerating Direct Sparse Solvers for Computational Engineering with NVIDIA cuDSS 1.0

NVIDIA

Structural mechanics, fluid flow, and circuit simulation all depend on solving sparse linear systems. As problems grow and accuracy tightens, solvers need GPU speed without giving up the robustness that production simulations require. NVIDIA cuDSS 1.0 is now a production-ready GPU library for direct sparse solves. On real semiconductor and mechanical-modeling matrices, geometric-mean speedups compared with Intel MKL are 2.5 times for analysis, 5.9 times for numerical factorization, and 151 times for the triangular solve. A hybrid memory mode stages data across GPU memory and CPU DRAM, cutting minimum device memory by about 30% on large VLSI cases, and can let a single GPU finish problems that previously needed several cards. It also offers more stable pivoting for symmetric indefinite systems and moves symbolic factorization onto the GPU. Software vendors can now put the library into commercial simulation products.
