1. From Item Scores to Semantic Tokens: Test-Time Collaborative Adaptation for Generative Recommendation

In generative recommendation with semantic IDs, the model writes an item's code one token at a time, and beam search keeps only the highest-scoring prefixes at each step. Once a prefix is pruned, every item beneath it can never be generated. The problem is sharpest when a user has just developed a new interest that shows up in only one or two recent interactions. This paper proposes TCBSA (test-time collaborative beam search adaptation), which turns a scoring model's item scores into bonuses on code prefixes before every pruning step. The scoring model scores the whole catalog and keeps the top few hundred items; each item's margin above the cutoff is spread over every step of its code. Before each beam search ranking step, these bonuses are added to the path's cumulative score. Neither model is retrained. Added to TIGER, it raises NDCG@10 by a relative 4.9% to 30.4%, depending on the public dataset. With a narrower beam, it is also more accurate and faster than TIGER with a wider beam.

2. MPQ: A Message-Passing View of Post-Training Quantization

When an LLM is quantized after training to very low bit widths, common solvers such as GPTQ decide block by block which codebook value each group of weights takes. Once a block is fixed it never changes, and near-tied alternatives are dropped. This paper proposes MPQ (message-passing quantization), which keeps probabilities over each block's candidate values and commits only at the end. It alternates between two steps. One uses the layer's output error to estimate each block's weights as continuous values along with how reliable that estimate is. The other gives each candidate a probability: candidates closer to the estimate score higher, and the less reliable the estimate, the more even the probabilities. After a few rounds each block takes its most probable value, and blockwise coordinate descent polishes the result. On Llama, Qwen and Mistral models it improves perplexity and zero-shot accuracy, with larger gains at lower bit widths. With Llama-3-8B at 2 bits, its perplexity is about 11.6, against 12.76 for the baseline.

1. SynRec: Synergistic multi-domain recommendation with frequency-guided expert specialization

When several businesses each run their own recommender and share no users, knowledge cannot be transferred between them through shared user IDs. This paper proposes SynRec, which lets several domains share one Transformer recommender and shares only domain-agnostic behavior patterns, such as the fast and slow rhythms of behavior sequences over time. It replaces the feed-forward layer with a domain-aware mixture of experts (MoE): some experts serve all domains and learn shared patterns, while others serve only one domain and learn its differences, which limits domains dragging each other down. Across 6 domains with no shared users, it beats the single-domain models in every domain and is the best of the evaluated multi-domain methods in 5 of them.

1. Semantically Rich, Metrically Affect-Blind: A Geometric Blind Spot in Modern Text Embedders

Search a vector index for what users dislike about a product, and the reviews you get back are usually on topic but a mix of praise and complaints. This paper measures why. Across 11 text embedding models, sentiment is present in the vectors and a simple linear classifier can read it, yet the cosine similarity that retrieval actually uses barely registers it. A small projection head on the frozen embedder, trained in seconds on a CPU, repairs this. It is trained contrastively on a few thousand sentiment-labeled sentences, pulling same-sentiment sentences together and pushing opposite ones apart. When a review sentence is used to find similar sentences, more of those with the same sentiment rank near the top, and the MAP measuring this rises by up to 26 points. The cost is a lower score on the general semantic similarity benchmark STS-B, but after concatenating the head's output with the original vector, it is only 2.4 to 12 points below the original vector.

2. What the Query Remembers: Query Abstraction Governs Lexical and Dense Retrieval of Classical Arabic Poetry

When searching a classical Arabic poetry archive, which works better: keyword search with BM25 or an embedding model? This paper finds that the answer depends mainly on how much of the original wording the user still remembers. When users half-remember a few lines, BM25 beats all nine embedding models. When users can only describe what the poem is about, BM25 drops to 8th of 10 systems. By rewriting the same queries, the authors show that the ranking is driven by whether the query contains original wording. Adding half a verse of the original to a query raises BM25 recall by 37.8 points.

1. KVStream: Adaptive Parallel Storage Management for KV Caching in Large-Scale LLM Serving

Long-context inference keeps reusing the same prefixes: system prompts, whole documents, code repositories and multi-turn session histories. Their KV cache no longer fits in GPU memory or host memory, so it has to live on disk and be read back on the next hit, which puts disk reads on the critical path of every inference step. Existing systems read only from the node-local NVMe, while the parallel file system that every cluster already mounts sits almost idle. This paper builds KVStream: every KV chunk is written to both the local disk and the shared storage. At read time both tiers read at once, and whichever finishes first claims the next batch. Plugged into LMCache, it reaches up to 1.49x LMCache's offline throughput and up to 6.1x lower mean TTFT under bursty traffic.

2. Advancing Generative Recommendation Inference: our collaboration with NVIDIA on TensorRT LLM

SpotifyNVIDIA

By moving generative podcast recommendation off two separate inference engines and onto TensorRT-LLM together with NVIDIA, Spotify cut beam search cost by up to 54% and scoring cost by up to 7% on Qwen3-1.7B. Spotify recommends with semantic IDs, and a single online request needs three kinds of inference: beam search to generate candidates, scoring a given batch of candidates, and inserting the user vector into the prompt as one extra token. These used to be split across two inference engines, vLLM and SGLang, and vLLM's beam search could not saturate the GPU, so Spotify fell back to lower-tier cards. The two companies added the missing features to TensorRT-LLM and unified all three in one engine.
