LEAD STORY · Alibaba

1. PailitaoMMSearch2.0 Technical Report: Scaling Generative Retrieval to Unified End-to-End Multimodal Search

Alibaba

In Taobao's Pailitao, a user may photograph a shirt and ask for shorts to match it, which calls for a complementary item rather than a duplicate. The usual pipeline classifies intent first and routes to separate retrieval channels, so one wrong step breaks everything after it. Alibaba's report lets a 2B vision-language model read the raw image and instruction and generate product Semantic IDs directly, with no intent labels. On matching requests the excellent rate rises from 44.2% for the multi-channel pipeline to 74.3%, and online GMV grew 8.94% at full rollout.

2. Latent Residual Reasoning for Ranking in Generative Recommendation

CIKM 2026MeituanUSTCRUCPolyUAAcademy of Cyber

Generative ranking models usually score every candidate in one forward pass. Refiner, from Meituan and the University of Science and Technology of China, adds a few more steps. Each candidate gets a reasoning token, and each step predicts only a correction added to the original score. The base model stays frozen; only LoRA and a new output layer are trained. On Steam it lifts MTGR's AUC from 0.7698 to 0.7872, and a 7-day online A/B behind production MTGR raised CTR by 0.75%. Because it learns only residuals, the extra steps refine the ranking instead of overturning it.

1. Exploratory creative pre-ranking: Hierarchical empirical-Bayes Thompson sampling for real-time creative optimization

AI-generated content makes it easy for advertisers to produce many creatives, but each gets very few impressions. This Roblox paper adds a creative pre-ranking layer between recall and ad ranking. The historical play rate μ of a new creative's campaign, game and target audience serves as the prior mean, and the prior strength κ is computed in closed form from the variance of true differences among sibling creatives: the smaller the differences, the larger κ. Adding the creative's own plays and non-plays gives a Beta posterior, and one random score drawn from it is used for ranking. Borrowed experience dominates while data is scarce and gives way to the creative's own record as data grows. On replayed live traffic, it lifts the ranker's predicted play-through rate by 8.14%, against 2.80% for a random shortlist of the same size, the pipeline gets only 0.2% slower, and it now serves production.

2. Rethinking Positional Encoding and Interaction Granularity for CTR Prediction

In unified Transformer CTR models like OneTrans, the authors tried six positional encodings on Kuaishou's KuaiRand data, and none beat using no positional encoding at all. Building on this, the Wuhan University and Tencent paper proposes TRIP (the authors' name for the whole method). Each behavior encodes both its rank in the sequence and how long before this prediction it happened. Behaviors are then grouped by that time distance: the seconds before this prediction are put on a base-2 log scale and rounded, so each group spans twice the time of the previous one. Behaviors in the same group see each other, while across groups a behavior sees only earlier groups. For the same history, change the impression time and every behavior's distance from now changes, something language-model positional encodings never had to handle. On four public datasets AUC improves over the strongest baseline by 1.47% relative on average, and by up to 4.45% on the Tencent ad dataset TAAC (a public Tencent ad-click sequence dataset).

LEAD STORY · Google

1. EmbeddingGemma 2: Unified and Efficient Multimodal Representations

Google

To search text, images, video and audio with one embedding model, the usual route is to transcribe audio and caption images first, then hand everything to a text model. That costs extra compute and throws away tone of voice and visual detail. Google's EmbeddingGemma 2 is a 744M-parameter model that maps these inputs directly into one vector space, and each modality encoder can be loaded only when needed. Finding text passages from a spoken question shows the difference best: the same model transcribing speech to text first reaches an MRR@10 of 57.59, while reading the audio directly reaches 69.54. A small multimodal model need not give up text and code; its code retrieval score is almost ten points above its predecessor's.

2. Natural Hard-Negative Mining from Positives for Instruction-Following Retrieval

Instruction-following retrieval asks one query to rank documents differently under different instructions: once an instruction adds a requirement, the original positive should drop if it fails that requirement. Training data for this is scarce, and existing methods keep the positive fixed and have an LLM invent a negative passage that violates the instruction. This paper does the reverse. It picks an existing negative that meets some extra condition, writes a short instruction that makes it the positive, and the original positive naturally becomes the hardest negative under that instruction. InstructIR gives each query several user instructions and scores the worst top-ten nDCG among them. With only 6,716 such examples built from MS MARCO, the small Qwen3-Embedding's score rises from 49.29 to 67.06, beating Promptriever, a model more than ten times larger.

1. Let the Gate Decide: Per-Lookup Precision for Quantized Conditional Memory in LLMs

When you quantize a language model's n-gram memory tables to low bits, keeping the most frequently accessed rows precise does worse than picking rows at random. The reason is the gate. In conditional memory layers such as DeepSeek's Engram, each fetched vector is scaled by a gate; common function words get small gates, rare entity names get large ones, and quantization error is scaled by the gate. GateRQ stores each row as a few levels of 1-bit residual codes and reads level 1 to compute the gate. It then ranks lookups within the batch by gate-based importance: the top few read to level 3, the next ones to level 2, and the rest stop at level 1. The share at each level is fixed by a preset budget of average bits read per lookup. Without retraining, it cuts DeepSeek-V4.1-Flash's table memory from 23.6 GiB to 3.0 GiB per GPU, and the freed memory clearly raises long-context throughput over FP8 tables.

2. WAKMan: Workload Aware KVCache Manager

Which eviction policy vLLM's prefix cache should use depends on the traffic arriving right now. Agent requests come back within seconds with the same history, so the default LRU fits. Popular system prompts and long chat histories return much later, and only S3FIFO, which protects blocks used repeatedly, keeps them. Across 20 request mixes, each policy wins some. WAKMan replays the traffic of the last 15 minutes on two simulated caches and uses whichever had the higher hit rate for the next window, gaining 5 points of hit rate over LRU alone on average.

1. OpenJaws: An Open Hardware UMI Framework with Stereo Localization for Generalist Manipulation

Collecting robot demonstrations in the wild with a handheld gripper (UMI) is now common, but how good the action labels are depends on one step: recovering the gripper trajectory from the wrist-camera video. The original UMI uses a monocular camera plus an IMU (inertial measurement unit); a single camera cannot see true scale, so it also needs a pre-built map and a fiducial marker to stay stable. OpenJaws swaps in a stereo camera that costs about a hundred dollars. The distance between the two lenses is calibrated, so triangulation gives true scale directly. On a new benchmark with ground truth, comparing only segments both methods can track, the stereo trajectory error is about 2.9 mm versus 18.4 mm for the original pipeline, which also tracks only 37% of frames on average. The whole gripper costs about $400, and all hardware and software are open source.

2. Pushing Dexterity and Safety for In-Hand Object Pose Reaching That Works Remarkably Well

Skills learned by multi-fingered hands mostly stop at simple grasps or spinning an object in place. For harder in-hand moves the most common failure is dropping the object, yet earlier work rarely counts drops. This paper has a LEAP hand move a held object to almost any position and orientation, with random wrist orientations, through one goal after another. The main policy is trained entirely in simulation and transfers directly to the real hand. On the real hand it accurately reaches 95.2% of unseen goals. The authors then stack a small network on the frozen main policy. Seeing only the hand and object state, it learns with reinforcement learning to add a small correction to each action, rewarded for keeping the object and for keeping corrections small. The penalty weight on corrections can be set at run time, and a larger weight keeps actions closer to the original. Drops fall by 75% while 91.5% of goals are still reached.
