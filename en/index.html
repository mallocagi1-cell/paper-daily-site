LEAD STORY · Alibaba

1. Progressive Learning from Content to Relevance to Personalization for CTR Prediction

Alibaba

Taobao search CTR models mainly remember historical clicks through item IDs, so the same item with a different main image is almost indistinguishable to the model. FineSID turns each item image into 30 discrete codes across four VAR tokenizer scales from 1×1 to 4×4, tokenizes titles and OCR text by field, and looks them all up like ordinary ID features; the shared network is first trained on query–item relevance labels from a Qwen3.5 teacher, then fine-tuned with a click head on click logs. Offline AUC is 0.25 points above the HiFormer baseline and 0.38 points higher on cold items; a seven-day Taobao main-search A/B test raised GMV by 0.85%.

2. Generative Recommenders Forget the Long Tail: Restoring Memorization in Retrieval and Ranking

USTC

Generative recommenders use beam search to emit item-ID tokens one by one, and tail items have low generation probability and are often pruned in the first one or two steps: on Amazon Industrial & Scientific, MiniOneRec's 50 candidates cover only 11.94% of tail targets. CAPE does not retrain the model; at inference it counts which items co-occurred with the user's history in the training data, retrieves 25 extra tail candidates by that count, and adds the count into the ranking score. On LastFM, TIGER's top-10 hit rate on tail targets rises from 3.94% to 17.19%, with 11–16% extra latency per request.

LEAD STORY · XXJTLU / University of Liverpool / PolyU

1. Controllable Generative Recommendation via Guided Token Refinement

XXJTLUUniversity of LiverpoolPolyU

Generative recommenders emit item-ID tokens left to right, so temporary diversity at inference can only rewrite one position mid-decode and often produces IDs that do not exist in the catalog. ReGen uses a bidirectional Transformer to predict all 4 ID tokens at once, subtracts a score only on the coarsest positions for token values common in the user history, remasks low-confidence positions and repredicts, and uses a prefix tree of all legal IDs to drop token values that cannot complete a real item—without changing model parameters. On Amazon Instruments, top-10 category coverage rises from 0.41 to 0.59 while Recall@10 falls only from 0.0427 to 0.0394 (TIGER-MMR falls from 0.0433 to 0.0319 in the same range); without the prefix tree only 27.63% of IDs map to real items.

2. From Habits to Discovery: Deploying LLMs for Personalized Generative Recommendations at Spotify

Spotify

Spotify wants the home feed to surface podcasts the user has not yet formed a habit around (under 10 minutes on a show in the past 28 days). GLIDE, based on Llama 3.2 1B, first learns to translate between episode semantic IDs and text, then reads recent episode semantic IDs, region and other text fields, a soft-prompt token projected from a collaborative-filtering user vector, and an instruction to push familiar versus unseen content, and directly generates 30 episode candidates. Offline Recall@30 is 29.9% above a semantic-ID-only variant; online A/B tests show up to +5.4% non-habitual listening and +14.3% new-show discovery while meeting latency SLOs.

LEAD STORY · Perplexity

1. pplx-embed-v2-late Technical Report

Perplexity

Perplexity releases 0.6B and 9B multi-vector retrievers that encode text, images, and document screenshots: each document token stores a 128-d vector, and scoring sums MaxSim of each query vector against document vectors. Both models distill token-by-token from the same 18B teacher, so they share one vector space and a 9B offline document index can be queried by a 0.6B online encoder. On 72 domain retrieval tasks the 9B model averages nDCG@10 81.3%, 1.6 points above nemotron-3-embed-8b; a 0.6B query with a 9B index scores 79.6%, above 78.0% when both ends use 0.6B. On BrowseComp+ the 9B model lets an agent answer 64.0% correctly with the fewest searches.

2. Directional Posterior Feedback Fusion for Query Reformulation in Dense Retrieval

TsinghuaRenmin University

When rewriting a query vector with first-round retrieved documents or an LLM-written hypothetical answer (HyDE), the usual approach averages feedback vectors and interpolates with the original query. DIFF argues that each piece of feedback only supports correcting the query along one direction, so other directions should not be pulled back by it: it subtracts the component parallel to the original query to get each feedback's rotation direction and magnitude, constrains only the projection of the correction onto that direction, weights by query–feedback similarity and group agreement, and solves a K×K linear system—without training any model. On 14 BEIR subsets, bge-base with HyDE rises from 0.5492 to 0.5717 mean NDCG@10; with retrieved-document feedback, vector averaging falls to 0.5045 while DIFF scores 0.5522.

LEAD STORY · KAIST / Korea University

1. Let Agents Design How They Search: Automatic Interface Optimization for Agentic Search

KAISTKorea University

Korea University and KAIST have Claude Code (Claude Opus 5.5) design retrieval tools for a search agent: it reads each question's execution log and score, jointly edits pre-generated index files, executable search scripts, and usage instructions, and after 10 rounds keeps the best version on the optimization set. With GPT-5.4-nano as the search agent, BrowseComp-Plus accuracy rises from DCI's 71.6% to 78.4%, and mean nDCG@10 on four BRIGHT subsets from 45.7 to 55.0. Prompt-only optimization reaches 75.6% and 52.0, so the rest of the gain comes from the generated index files and search scripts; handing the interface unchanged to Gemini 3.5 Flash-Lite still beats DCI (73.9% vs 60.9%).

2. MAPS: Macro-Adaptive Parallel Reasoning for Regulating Search Momentum in Retrieval-Augmented Generation

Northeastern UniversityTsinghua

Northeastern University and Tsinghua find that in retrieve-while-reasoning RAG, later sub-queries keep drifting away from the original question along the direction earlier sub-queries already moved, and the effect grows with step count. MAPS therefore makes two changes: each round only passes distilled knowledge and a compressed reasoning summary to the model, never historical sub-queries; before writing sub-queries it lists several complementary directions, writes one sub-query per direction, retrieves in parallel, and merges. On Qwen3-32B, mean Cover-EM over six QA sets is 56.0 versus 49.2 for ParallelSearch and 43.9 for Search-o1; removing any of the three components hurts.

1. Is 2:4 Sparsity Still Worth It? Semi-Structured Sparsity versus Quantization in LLM Inference

An independent researcher compares "add 2:4 sparsity" versus "drop one precision tier" on Llama-3.1-8B-Instruct and Qwen3-8B under matched storage bits (including sparse indices) and matched nominal compute tiers, with measurements on L40S, H100, and RTX PRO 6000. As long as a lower precision is still available, adding 2:4 is both less accurate and slower: 2:4 + INT8 costs the same storage as INT5. At the FP8 floor, a retrained 2:4 model served by vLLM on H100 raises prefill throughput 27% over dense FP8 with matched GSM8K; but during retraining perplexity recovers first while reasoning accuracy recovers much more slowly.

2. SGLang Low-Latency Mode: Kernels and Runtime

SSGLangAMDNVIDIA

SGLang, NVIDIA, and AMD use a plugin framework to plug specialized fused kernels into SGLang, cutting inter-kernel waits and cross-GPU communication at low concurrency. On AgentX replays of DeepSeek-V4.1-Flash + DSpark, per-user P90 generation rises from 671.2 to 928.4 token/s on 4×GB300 with 1 session, and from 331.6 to 516.0 token/s on 4×MI355X with 4 sessions. On NVIDIA, median time for one decode layer falls from 96.8 µs to 68.4 µs with almost the same kernel count; the speedup mainly comes from less waiting between kernels and overlapping work.
