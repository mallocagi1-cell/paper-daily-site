1. PinRec: Unified Generative Retrieval Model for Pinterest Recommender Systems

Pinterest

Recommender systems usually run a separate retrieval model for the home feed, search and related items, because each surface wants something different: saves on the home feed, outbound clicks to buy on search, and continued browsing on related items. This Pinterest KDD 2026 paper replaces all three with one generative retrieval model, PinRec. It is pretrained on site-wide behavior, fine-tuned on each surface's logs, and told at generation time which action to aim for. Conditioning on the target action matters far more than unifying the model. Removing that condition cuts offline recall on the three surfaces by 7.5% to 12.6%. Added to search as one retrieval source online, it raised saves by 3.88%.

2. Unifying Behavior Modeling and Semantic Generation for Generative Recommendation

Generative recommenders that write the next item's Semantic ID code by code have a systematic bias. This KDD 2026 paper from South China University of Technology finds that the fewer items in a user's history share the target's category, the worse they do against classic behavior-only sequential models; in the worst group, TIGER's NDCG@10 trails SASRec by 30%. The cause: the encoder learns which item comes next, while the decoder must write its code. OMG inserts a two-layer network between them; each step adds the previous state to the encoder's final state and runs it through the network again. Each step predicts both the next item and the first code, with the latter weighted more each step, and all intermediate states go to the decoder. That one part lifts metrics by 14.5% on average while adding only 0.16% compute.

1. Hierarchical GTV Estimation: Bridging the Gap between Container-Level Ranking and Item-Level Conversion

RecSys 2026Meituan

Local-services and live-commerce ads are ranked and billed per store or livestream room, but users actually buy one voucher or one product inside it, so directly predicting how much a click will sell gives a noisy label that is hard to learn. This Meituan paper splits a store's expected sales into parts: first whether the user orders at all, then each voucher's purchase probability and quantity, multiplied by its price and summed. A store-level regression tower covers samples whose voucher-level signal is too sparse. Each sub-task gets a far more stable label. In a 13-day online A/B test, ad revenue per search rose 1.42%, and the method is fully deployed.

2. iFusion: Integrating Dynamic Interest Streams via Diffusion Model for Click-Through Rate Prediction

CTR models usually encode long-term and short-term behavior separately, then concatenate or gate them into one interest vector, so one-off noise in recent behavior, such as stocking up during a sale or buying for someone else, gets written straight into long-term preference. This JD.com ICLR 2026 paper treats long-term interest as a draft: it adds noise, then denoises step by step conditioned on the latest sessions to produce the fused interest vector. Each session splits in two: averaging keeps repeated preferences, attention catches sudden interests, and the stable path gets about twice the weight. In a 7-day online A/B test, CTR rose 2.44% while serving latency grew only about 0.3%.

1. System One models Are Not Better Rerankers

Using the new decision models to rerank search results does not beat a purpose-tuned reranker, concludes this University of Passau paper. Decision models, also called System One models, answer a question with a calibrated probability of yes instead of text, and within weeks of release they were used for reranking. The paper compares two fine-tunes of the same backbone: decision fine-tuning trains on all kinds of yes-or-no questions to give accurate probabilities, while reranker fine-tuning trains only on MS MARCO queries and passages to judge relevance. Across six Qwen backbones of different sizes and ten TREC DL and BEIR collections, reranker fine-tuning wins on every small and mid-sized backbone, by 5 to 29 points nDCG@10 up to 9B, and the two tie at 27B. Below that size, decision fine-tuning is no better than asking the untuned model. The authors' advice is blunt: if you need a reranker, fine-tune a reranker.

2. LightRetriever: A LLM-based Text Retrieval Architecture with Extremely Faster Query Inference

In LLM-based text retrieval, documents can be encoded offline, but queries arrive in real time, so every query runs the full LLM, which keeps throughput low and serving costly. LightRetriever breaks the symmetry: documents still go through the full LLM, while the query side is reduced to a table lookup. During training, a shared prompt plus a single token is fed through the LLM to get that token's vector, and a query vector is the average of its token vectors. Every vocabulary token's vector can be precomputed into one table, so at serving time a query is just lookups and an average. Versus running a full LLM on an A800 GPU, query encoding is over 1000 times faster and end-to-end retrieval throughput rises more than tenfold, while keeping about 95% of the full LLM retriever's retrieval scores on average across benchmarks.

1. Where Rounding Happens Matters: Rounding-Location Alignment Stabilizes LLM Reinforcement Learning

LLM reinforcement learning usually generates answers with one inference engine and trains with another framework. Even with identical weights and BF16 on both sides, the numbers differ slightly, so an update meant to be on-policy quietly becomes off-policy and training can suddenly collapse. This paper from ByteDance Seed and Peking University finds that the two systems need not be aligned wholesale. It is enough to round at the same place on both sides in three spots, RoPE, SwiGLU and residual RMSNorm, keeping those intermediates in FP32 until their BF16 outputs. With all three aligned, four Qwen-family models no longer collapse, and aligning RoPE alone also suffices. The inference engine, matmul and attention kernels, and the training objective stay unchanged.

2. C 2 KV: Compressed and Composable KV Cache Reuse for Efficient LLM Inference

Retrieval-augmented generation stitches several retrieved documents into the context, and recomputing their KV caches from scratch every time is expensive, so some methods store each document's KV cache and concatenate them on use. But long documents have huge KV caches, so storing and loading them becomes the bottleneck, and naively compressing them before concatenation hurts accuracy badly. This paper from Shanghai Jiao Tong University and Alibaba proposes C2KV: a light extractor beside the frozen model reads each document followed by a few learnable compression tokens and keeps only those tokens' KV as the document's cache. Caches are stored without positions, which are re-applied at concatenation time, so they combine like building blocks. On long contexts, inference is up to 17 times faster with generation quality largely preserved.
