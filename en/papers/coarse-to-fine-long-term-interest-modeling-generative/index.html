Coarse-to-Fine Long-term Interest Modeling for Generative Recommendation

RecSys 2026
Shiteng Cao, Junda She, Ji Liu, Bin Zeng, Chengcheng Guo, Kuo Cai, Qiang Luo, Ruiming Tang, Han Li, Kun Gai, Zhiheng Li, Cheng Yang
28 minread4.20scoreNo. 410-24 Generative issue
Original paper ↗

Generative recommendation encodes each item as a few levels of semantic IDs (SIDs) and uses a Transformer to generate the next item one code at a time. Attention cost grows quadratically with sequence length, so these models usually take only the most recent few dozen behaviors. In the paper's two datasets, the average user history length is 987 (TAOBAO-MM) and 884 (KuaiRec), yet the model input keeps only the last 50. The authors also observe a pattern: in plain generative retrieval, after the first-level code is generated, the true item's rank in the beam gets worse rather than better, with the average rank dropping by 1.25 at the second level. The paper's method GLASS uses the long-term history differently for each SID level. Before generating the first-level code, it compresses the whole long-term history into one interest token fed to the encoder. After the first-level code is generated, it uses that code as a retrieval key to pull items of the same broad category from the long-term history, which help generate the last two codes. On TAOBAO-MM, R@1 is 21.57% higher than the strongest baseline, DualGR; in a two-week A/B test on a short-video platform, app usage time per user rose 0.052% and recall rose 3 percentage points in absolute terms.

1. The problem: getting long histories into generative retrieval

The ranking stage has a mature recipe for long sequences, SIM's two-stage design: a GSU (General Search Unit) first uses the target item to retrieve a relevant sub-sequence from the long history, then an ESU (Exact Search Unit) runs fine-grained target attention over it. The retrieval stage has no target item, so the GSU has nothing to search with. OneRec and OneSearch use a Q-Former to compress long-term behavior into fixed-length vectors, which stops at the granularity of interest clusters. DualGR already uses SIDs as retrieval keys in generative retrieval, but it treats codes at every level the same way.

The authors start from the structure of SIDs themselves. The first-level code decides which broad category an item belongs to, and the last two codes locate the specific item inside that category. When the first-level code is generated there is no path yet, so the model needs the user's overall preference across categories; when the last two codes are generated the category is fixed, so the model needs what the user actually engaged with inside that category. The two levels need long-term information at different granularity, so it is injected in two places.

2. Overall structure

The backbone is a TIGER-style encoder-decoder. Each item's multimodal vector is quantized by RQ-VAE into three levels of codes; on the public datasets the codebook sizes are [64,128,128], the embedding dimension is 96, and the encoder and decoder each have 4 layers. The user history is sorted by time and split in two: the most recent 50 behaviors are the short-term sequence, and everything earlier is the long-term sequence.

3. First-level code: SID-Tier compresses the long-term history into one token

This step addresses the fact that the first-level code is generated with no clue at all. Running attention directly over the long-term history is too expensive, so the authors exploit the small size of the first-level codebook: there are only tens to a little over a hundred first-level codes, so cross features between the user history and every code can all be computed.

Each first-level code k first gets a prototype vector h~k​, the mean of the vectors of all items whose first-level code is k. The cosine-similarity range $[-1,1]$ is then split evenly into N bins, and for each first-level code the model counts how many long-term history items fall into each bin:
tk​[j]=v∈Hlongid​∑​I(bin(Cos(h~k​,hv​))=j)
hv​ is the multimodal vector of history item v, bin(⋅) maps a similarity to its bin, and I is the indicator function. Intuitively, tk​ describes how many items in the user's history are very similar to category k, how many are somewhat similar, and how many are not. The histograms of all first-level codes are concatenated into a vector of length K0​⋅N, compressed by an MLP (hidden size 256) into one d-dimensional vector etier​, and appended after the short-term sequence embedding before entering the encoder.

This token depends only on the user history and the codebook, not on the item being generated, so it can be precomputed offline. It is really the familiar "user's historical preference statistics per category" feature from ranking models, computed over first-level SID codes instead.

4. The last two codes: retrieve from the long-term history with the generated first-level code

After the first-level code c^0​ is generated, the model takes every item in the long-term history with the same first-level code:
Hret​={c(vi​)∣vi​∈Hlongid​, c0​(vi​)=c^0​(vn+1​)}
This is SIM's hard search with the key changed from "the target item's category" to "the first-level code just generated". Each decoder layer runs self-attention and then two cross-attention paths in parallel: one with the encoder output as key/value, giving Zshort​; one with the retrieved item embeddings as key/value, giving Zret​. A gate merges the two:
g=σ([Zshort​;Zret​]Wg​),Zcontext​=(1−g)⊙Zshort​+g⊙Zret​
Wg​ is a 2d×d projection and σ is the sigmoid. A large g tilts the result toward the retrieved long-term items; a small g tilts it toward the short-term sequence. The training objective is the standard autoregressive cross-entropy over the three codes.

5. What if too few items come back

Hard search has an obvious problem. In the paper's example, with a history of 1000 and a first-level codebook of 128, each first-level code retrieves only about 7.8 items on average: too little information, with a high share of noise. The authors offer two fixes:

  • Semantic neighbor augmentation: precompute cosine similarities between first-level codes and record each code's top-k nearest neighbors. When fewer items than a threshold τ come back, the history items under the neighbor codes are merged in as well.
  • Shrinking the first-level codebook: make the first-level codebook smaller during training so that each first-level code covers more items. The first level is responsible for volume, the last two for precision.

6. Experiments

The main experiment aims to show that GLASS beats both ID-based sequential models and SID-based generative models. Both datasets keep only positive feedback: TAOBAO-MM keeps clicks, uniformly samples 10,000 items and keeps those that appear at least 5 times in the training set; KuaiRec keeps samples whose play time exceeds the video length. On KuaiRec the gain is only 3.81%–4.94%. The authors attribute this to KuaiRec's multimodal vectors coming from a simple text encoding, which gives poorer SIDs, whereas TAOBAO-MM uses multimodal features trained with contrastive learning.

The ablation shows that the two modules help different levels: SID-Tier mainly helps the first-level code, and semantic search mainly helps the second. The authors track two quantities: acci​, the training accuracy of the level-i code under teacher forcing, and Pi​, the probability that the level-i code is also correct under top-1 beam search given all earlier levels are correct. Adding SID-Tier raises both quantities at the first level, and Recall@5 rises from 0.0702 to 0.0842, which shows a more accurate first-level code translates directly into better recall. Adding semantic search on top mainly lifts acc2​ and P2​.

The authors also explain why the correct answer's rank drops. They define Conditional Rank Progression (CRP): over samples whose first $d-1$ codes all stayed in the beam, the average position of the correct length-d prefix among the beam's top-K candidates at step d; closer to 1 is better. The beam is ordered by cumulative path probability, as beam search normally is; the paper does not say how a correct prefix that falls out of the top K is counted. With beam size 20, the plain generative model's correct code worsens by 1.25 places on average at the second level, and only by 0.98 with semantic search, with a similar improvement at the third level. The cause is that when a plain model generates the last two codes, its conditioning context is still the original one, with no new information to widen the probability gap between the right answer and the distractors; semantic search supplies exactly that new information.

The gate does matter. A fixed weight of 0.5 helps when the first-level codebook is small but hurts once the codebook gets finer, because retrieved-sequence length varies a lot, and when it is too short the noise flows straight into beam search's cumulative probabilities. The learned gate value rises overall with retrieval length: the more items are retrieved, the more weight the model puts on the long-term branch.

Of the two fixes for sparse retrieval, shrinking the first-level codebook gave the best Recall@10. Semantic neighbor augmentation helps only without codebook shrinking; adding neighbors on top of a shrunken codebook lowers the metrics slightly, which the authors attribute to neighbor items blurring the boundaries between different interests.

The online experiment was a two-week A/B test on a short-video platform, with 3% of users, about 12 million, in each of the treatment and control groups. Usage time rose only about 0.05%, but that is statistically significant on this much traffic, and recall rose 3 percentage points in absolute terms (the paper does not say what online recall uses as ground truth or over how large a retrieved set it is computed, so treat it only as a directional signal).

7. Limitations and what to try

The paper has no separate limitations discussion; two facts are worth keeping in mind. First, the public datasets are small: KuaiRec has only 3790 users and TAOBAO-MM's items are sampled down to 10,000, far from industrial codebook scale. Second, results are very sensitive to SID quality: on TAOBAO-MM, where SIDs are good, each metric is 14%–30% above the strongest baseline, while on KuaiRec, where SIDs are poor, the gain is only about 4%.

If you work on generative retrieval and have long behavior sequences, two things are worth trying directly:

  • Append the "user's historical preference histogram over first-level codes" as an extra token to the encoder input; it can be computed offline and adds almost no online cost.
  • Before doing hard search with the generated first-level code, measure how many items each first-level code retrieves from user histories on average; if too few, try shrinking the first-level codebook first and neighbor augmentation second.
