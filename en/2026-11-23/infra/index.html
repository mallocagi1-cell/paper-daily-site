In hybrid LLMs, global-attention KV cache grows with both concurrency and context length, while bounded-state cache scales only with concurrency, so fixed GPU memory partitions can leave one pool underused while the other blocks requests. Hierarchical caching like HiCache keeps restored prefixes resident in GPU memory during decode, leaving the high-bandwidth CPU-GPU interconnect largely idle.

2. Supercharging XLA-based inference: Announcing the launch of XLA Serving Engine

Google

Many teams train models in Python, yet some production environments disallow Python and face interpreter and global interpreter lock overhead, so Google has open-sourced XLA Serving Engine for the OpenXLA ecosystem. It exports JAX models to an XLA SavedModel storing StableHLO computations and Orbax weights, then runs them in a native C++ runtime wrapping PJRT and the XLA compiler, supporting single-host and multi-host serving while preserving training kernel optimizations. In Google's short-request studies, it achieves 2 to 5 times the throughput of the best Python server they could build using a quarter of the memory. Internally, it already serves over 6 million queries per second across YouTube Shorts, Google Ads, Search, and parts of Gemini Omni. It is built as a lightweight one-shot inference engine typically for non-LLM models, while the authors recommend vLLM or SGLang for large autoregressive language models with long contexts, and PyTorch export via TorchTPU is planned.

3. E2E: Efficient Filtered AKNN Search via Adaptive Termination

KDD 2026HKUST

In filtered approximate nearest neighbor search, graph indexes such as HNSW typically apply a fixed termination rule to every query, causing easy queries to explore far too many nodes. Early-termination models built for plain vector search look only at traversal distances and break down under filters, because when attributes and vector distances misalign, nearby nodes may still fail the filter. During the mandatory early probing phase of graph search, E2E records the filter-matching ratios of visited nodes and queued candidates. It feeds both ratios and distance features into a lightweight LightGBM model to predict each query's computation budget, stopping easy queries early while letting hard ones search longer. In the high-recall regime, compared with Naive HNSW, it runs up to 2.6× faster on Tripclick and reduces distance computations by up to three times on YoutubeAudio, while improving efficiency by up to 1.5× when adapted to the filter-aware index ACORN. Without altering the underlying graph index, offline training on historical query logs cuts redundant traversal on easy filtered queries.

4. RoCoKV: Accelerating LLM Inference Serving through Uncertainty and Redundancy Aware KV Cache Compression

Georgia TechIntel

When large reasoning models generate long chains of thought, decode-stage KV cache compression depends heavily on timing. On AIME25, approximate attention token selection has little effect when output probabilities are concentrated, yet in uncertain steps with spread-out probabilities the flip rate of the most likely next token reaches 65%. Overly long generations with repetitive reasoning are also more likely to end in wrong answers. RoCoKV uses the entropy of the previous step's output distribution to adapt its budget without an extra forward pass, keeping more context during uncertain steps and pruning harder during confident ones. It also uses a compact summary of recent context to down-weight repetitive tokens, avoiding full-cache pairwise comparisons. On the systems side, it plugs into vLLM with fused three-phase CUDA kernels that preserve paged KV cache management and CUDA graph execution, turning sparse compression into end-to-end speedups. Across two reasoning models and three math benchmarks, it achieves higher accuracy than the evaluated compression baselines under tight budgets. Serving DeepSeek-R1-Distill-Llama-8B on AIME25 in vLLM, it delivers a 1.27x speedup and 38% higher throughput than Full-KV.

5. Berth: SLO-Preserving GPU Sharing Without New Preemption

USC

Online inference GPUs sit largely idle off-peak, yet co-locating best-effort work such as training often breaks millisecond SLOs, and existing fixes either nearly halt the background job or rewrite kernels and patch drivers. This work shows that the stock time-slicer on commodity GPUs already preempts running kernels in under a millisecond; what it lacks is priority, which can be created in user space. Berth is an unprivileged user-space system that leaves applications, frameworks, closed libraries, and drivers untouched. It holds best-effort kernel launches while a request is in flight, caps queued work during idle gaps, and shortens only the best-effort time slice to bound long kernels. Across MLPerf scenarios, Berth reaches 95.8% average SLO attainment, close to 97.9% alone, while keeping 48% of solo best-effort throughput, more than two and a half times what the closest baselines retain. For continuous-batching LLM serving, Berth feeds background work within each step's remaining slack, meeting per-token targets for nearly every request while training keeps running.

6. TripleKV: Predict, Prefetch, Protect -- KV Cache Management for AI Agents

UIUCNNTUAIBM

When multiple LLM agents run tool calls concurrently, idle KV cache blocks are quickly evicted from GPU memory and host DRAM, stalling returning requests for seconds on SSD reads. Pinning idle blocks in GPU memory or prefetching them straight to the GPU instead consumes scarce GPU capacity and lengthens queues. Because an agent's reused prefix is already known and only tool duration is uncertain, TripleKV predicts tool completion from tool type, input arguments, and live output cues, then prefetches the needed KV blocks from SSD into host DRAM. In DRAM, a multi-queue policy protects prefetched blocks from premature LRU eviction and removes duplicates of GPU-resident blocks. Prefetching into host DRAM instead of scarce GPU memory hides slow SSD reads without competing with active inference. Across four agentic benchmarks, it cuts requests needing critical-path SSD reads from up to 76% to under 10%, lowers P95 TTFT by up to 49% over vLLM with DRAM and SSD tiers, and outperforms recent GPU-pinning and GPU-prefetching systems on tail latency and throughput.

7. Twindex: Index Cache Offloading with Coarse-to-Fine Selection for Long-Context Sparse-Attention Serving

UIUCIBM

During million-token decoding in sparse-attention models, even after offloading the main KV cache to host memory, the indexer cache left in GPU memory still caps concurrency, taking up to 90% of per-request HBM across the three tested Qwen, DeepSeek, and GLM models. Because the indexer scans every past entry at each step, direct PCIe offloading is too slow, while plain low-precision compression hurts recall. Twindex fits a shared cross-input position component offline and compresses only the residual, keeping compact keys and a hot buffer in HBM while storing full native rows in host memory. Each step screens a larger candidate set with compact keys, then rescores native rows with the original indexer for top-k, without changing model weights and inside CUDA graphs. When host memory does not limit batch size and Qwen and GLM share prefix main KV, decode throughput across the three models reaches 1.25 to 2.54 times an optimized main-KV-offloading baseline, with mean benchmark scores at most 3.1% below baseline. Once the index shrinks, host memory can become the next concurrency bottleneck.

8. Accelerating Mixture of Block Attention via Dynamic Routing, KV-Centric Execution and Runtime Pipelining

In long-context block-sparse attention, giving every query a fixed block budget wastes work on weakly related blocks when scores are concentrated and drops relevant blocks when scores are diffuse. Assigning GPU work by query range also forces multiple thread blocks to reload the same KV block repeatedly. LightningMoBA keeps MoBA's mean-pooled block scoring and softmax computation, switching block selection to a per-query relative score threshold. It organizes execution around KV blocks, splits heavily selected blocks into row-capped subtasks, and uses Hopper GPU pipelining to overlap KV transfers, irregular query gathers, and matrix computation. Across five checkpoints on RULER at a matched Top-16 budget, it accelerates end-to-end generation by 1.20 to 1.60× over FlashMoBA. Mean RULER score rises from 74.42 to 75.28, though variable tracking drops across all five models at 64K context. Same-backend comparisons show execution optimizations drive most small-budget speedups, while at Top-64 dynamic routing yields simultaneous speed and accuracy gains on the evaluated models.

9. Announcing distributed KV caching for self-hosted LLMs with Amazon ElastiCache

Amazon

When self-hosted LLM inference serves long-context multi-turn chats or document Q&A, single-server GPU and host memory KV caches are capacity-limited and local to one host, forcing prefill recomputation when requests route elsewhere, sessions return later, or a node fails. Amazon has launched fully managed distributed KV caching on ElastiCache for Valkey, adding a shared cache tier across GPUs in the same Availability Zone. Engines including vLLM, SGLang, and TensorRT-LLM connect via the open-source LMCache connector with only a configuration change, keeping hot blocks in DRAM, tiering colder blocks to local NVMe, and transferring KV state to GPU hosts via RDMA over EFA. Sharing KV state across servers frees fleets from pinning requests to one host and lets scaled-out or surviving servers reuse cached prefixes. In shared-document Q&A tests, per-server requests per second doubled and cost per million output tokens dropped 40% after paying for the cache node. Across eight models, cache hits cut TTFT by 55% to 93%. Long-context reuse and retail or ads workloads with shared system prompts gain the most, and teams can run open-source KVTrace offline to estimate savings first.

10. ECHO-2: A Large-Scale Distributed Rollout Framework for Cost-Efficient Reinforcement Learning

During LLM RL post-training, rollout generation takes up most of the time, yet it usually shares expensive data-center GPUs with updates and often leaves the learner idle. ECHO-2 keeps centralized training on a small set of data-center GPUs and offloads rollouts to cheaper heterogeneous inference workers over a wide-area network. It treats policy staleness as a controllable budget so rollout generation, weight broadcast, and training overlap, activating the lowest-cost workers per unit throughput needed to saturate the learner. During broadcasts, workers form parallel peer-forwarding chains that relay chunks and switch to the new snapshot once installed, relieving the learner uplink bottleneck. In GRPO math post-training on Qwen3-8B over a wide-area network, it cuts cumulative cost by 33.3% to 36.3% over centralized baselines at matched AIME accuracy, with quality staying close to the synchronous baseline up to 6 steps of staleness. With bounded staleness and peer-forwarded broadcasts absorbing wide-area latency, cheaper distributed inference can take over rollout workloads without stalling training.
