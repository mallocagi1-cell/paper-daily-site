1. Push-Based KV Transfer to Improve TTFT and TPOT for Disaggregated Inference in vLLM

AmazonMistral

A push-based NIXL connector overlaps destination allocation with prefill and moves transfer setup off the decode loop. In the specified Qwen3-32B 1P1D test on EC2 P5en with EFA, TTFT improves by up to about 3× over pull mode.

Key insight: Transfer ownership and setup placement matter alongside bandwidth. Overlap preparation with prefill and keep coordination off the token-generation critical path.

2. Improve TTFT for Multi-Turn Agentic Workloads with Bi-Directional KV Transfer in vLLM

Amazon

Bidirectional KV transfer lets prefill nodes reuse state produced on decode nodes in earlier turns. In the specified GLM-5-FP8 1P1D multi-turn benchmark, TTFT improves by up to 3.3×.

Key insight: Output-side cache becomes input-side state on the next turn. Session routing, retention and recompute controls determine whether that reuse survives in a deployed service.

3. Adaptive Verification Without a Confidence Head

IInferact

An online logistic estimator gives existing draft checkpoints acceptance probabilities without retraining a confidence head. For DeepSeek-V4-Flash with DSpark, the reported acceptance-classification AUC is 0.8336.

Key insight: Use verification feedback already available during serving, but choose features that preserve the target sampling distribution. Conditioning trimming on the sampled token itself can introduce bias.

4. Taking vLLM Apart: A Practical Guide to Disaggregated Serving

IBM

The guide separates prefill, decode and CPU text processing, then measures transfer costs. In its two-GPU test at 0.4 requests per second, p99 inter-token latency falls from 169 ms to 29 ms.

Key insight: Disaggregation helps only when avoided interference outweighs transfer overhead. The slow-interconnect counterexample makes this a useful benchmark design guide.

5. DeepSeek-V4.1-Flash on vLLM: 5x Agentic Throughput Since Day 0

IInferact

vLLM combines compressed global state with bounded replay of recent sliding-window state and kernel fusion. The post reports 5× AgentX throughput compared with its day-zero implementation.

Key insight: Decide what to cache by state type and recomputation cost. Bounded replay is approximate, so its quality checks belong with the performance result.

7. Reducing vLLM startup time with one uv flag

Precompiling Python bytecode during image construction avoids repeated runtime compilation. H100 benchmarks with images and models already local save about 18 seconds per startup.

Key insight: Move repeatable preparation into the build. Account separately for image-size growth, first-pull cost and startup time on a node with cached layers.

vllm-metal brings continuous batching and paged KV management to Apple Silicon. In the reported mixed-length prompt test, batch wall time changes by only about 1% relative to the balanced-prompt batch.

10. Hyper Optimizing Kimi K3 in vLLM: Moving Fast and Responsibly

NVIDIA

Kimi K3 decode kernels fuse attention, expert execution and communication, with paths tuned to batch size. On sixteen GB300 GPUs at batch one, the reported controlled DSpark test delivers 1.73× the baseline decode throughput at the same synthetic acceptance length.

Key insight: Optimize gaps between operators as well as individual kernels. The useful engineering lesson is to validate synchronization and long-context numerical behavior alongside latency.
