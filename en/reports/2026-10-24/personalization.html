1. A Framework for Value-Aligned Modeling and Robust Experimentation

RecSys 2026

Carousel ads on Google Discover often get several clicks from one view, and each extra click can bring value to the advertiser. The old click model predicted only whether a view would get at least one click, and predicting the expected number of clicks instead raised the value delivered to advertisers online by 1.2%. Yet the existing offline metrics barely showed that the change helped. This paper tackles exactly that mismatch between offline metrics and the online goal. The authors weight prediction errors by what advertisers are willing to pay for a conversion, so an expensive purchase counts more than an ordinary page view. Weighting by business value raised delivered value on Discover ads by 4.7% and lifted the correlation between offline and low-traffic online results from about 0.1 to 0.65. Offline metrics must be weighted by business value to show in advance which changes really help online.

2. scikit-rec: A Unified, Extensible Recommendation Library with scikit-rec-agent, a Conversational Interface

RecSys 2026Intuit

Intuit's internal recommendation library has been in production for more than 3 years, serving 15 use cases across TurboTax and QuickBooks with real-time responses under 100 milliseconds. scikit-rec is its refactored open-source release. In one use case, QuickBooks picks the next action and contact channel for each customer, with XGBoost models predicting conversion probability and expected revenue. The team replaced one model per product with a single global model that uses item features by swapping only the scoring component, leaving the recommendation logic, model training and evaluation harness untouched. The library's offline policy evaluators match the reference implementations in Open Bandit Pipeline on ZOZOTOWN logs, differing only at the level of floating-point error. It also ships a conversational interface in which an LLM calls tools to prepare data, train and evaluate, while conventional models still produce the recommendations. Splitting selection, scoring and training into swappable components means changing a model does not require rebuilding the pipeline.

3. Generalized Position-Based Model: Rethinking Position Weights in Ranking Off-Policy Evaluation

RecSys 2026

The authors simulate clicks on Yahoo Webscope search results from expert labels, with only 5 logged rankings per query, and want to use logs from a weaker policy to estimate how many clicks a stronger one would get. One existing method uses a click only when the item holds the same position in the old and new lists, which leaves little data and high variance. Another converts clicks from every position with an assumed curve of how likely each position is to be seen, which is biased whenever the curve is wrong. INTERPOL converts with the curve within a band around each position and uses only same-position clicks outside it, with the band width set by hand. The authors write each new position's click estimate as a weighted sum of clicks at logged positions, choosing the weights to minimize an upper bound on the error. The bound covers random variation plus the bias from a wrong curve, with the curve's maximum error given by hand. When the assumed curve is too high, their mean squared error is more than 6 times smaller than INTERPOL's even with its band width tuned after the fact. When evaluating rankings offline, learn the position weights from data instead of trusting an examination curve that may be wrong.
