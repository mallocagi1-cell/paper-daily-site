AI Search — Paper Daily, 2026-10-24

Today's 10 papers cover several stages of a question-answering pipeline. On retrieval, one paper analyzes the queries where hybrid search does worse than vector search alone, Lean Finder V2 uses reinforcement learning to generate short queries for training theorem search, and SurveyGraph retrieves papers for surveys along a graph of method relations. In the RAG pipeline, one paper measures how many chunk embeddings must be recomputed after a knowledge base is revised, and CANOPY trims multimodal results to the granularity needed. Another paper replaces sequential decoding in hierarchical RAG with one forward pass, and GBOR-RAG pulls evidence subgraphs from a gene graph. On the answering side, JCA has the model check each condition in the question. On the industry side come Alibaba Cloud's full-stack AI Search optimization and Tencent Cloud TokenHub's web search API.

1. The Fusion Tax: A Diagnostic Analysis of When Hybrid Retrieval Hurts

Semantic Retrieval

Hybrid retrieval fuses BM25 and vector search results into one ranking, and most search engines and RAG frameworks default to reciprocal rank fusion (RRF). Tracking every query on 7 BEIR datasets, the authors find that the best fusion method beats vector-only retrieval on average nDCG@10 on every dataset, yet still ranks 8% to 21% of queries worse. These losses concentrate on queries where only one retriever finds relevant documents; the other one then adds only noise, and fusion pushes already well-ranked relevant documents down. A larger vector encoder does not remove these losses. Choose the fusion method from the measured gap between the two retrievers on your corpus.

2. Chunk Recomputation under Real Document Revisions: Measuring Update Cost and Retrieval Quality of Fixed, Recursive, and Content-Defined Chunking

RAG Pipeline

RAG chunking schemes are usually compared on a static corpus, but knowledge bases keep changing. Each chunk is embedded on its own, so when a document is edited the chunk boundaries move and unchanged text must be re-embedded too. The authors measure this on consecutive versions of Chinese and English Wikipedia articles, reusing an old vector only when a chunk's input is byte-for-byte identical. Fixed-length chunking must recompute more than half of the new version, two schemes that split by paragraph or by text fingerprints recompute somewhat less, and the three differ by under 2 points in retrieval recall. Inserting a little text at the top forces fixed-length chunking to recompute everything, because every window after the insertion shifts. For frequently edited knowledge bases, report a chunking scheme's recompute rate alongside its retrieval quality.

3. Lean Finder V2: Semantic Search for Mathlib That Disambiguates User Queries

Query Understanding & Rewriting

Mathlib is the mathematics library of the Lean proof assistant. When people and coding agents search it, the median query is only about 15 tokens long, while the theorem paraphrases used to train earlier retrievers are several times longer. Lean Finder V2 uses reinforcement learning to train a query generator that writes, for each theorem, short queries the current retriever ranks poorly. Queries whose target theorem already ranks near the top get no reward, and an LLM must first confirm that the query says the same thing as the theorem. On MathlibQR, a set of human-written short queries, Recall@10 rises from 0.780 for the best previous system to 0.893. Rewarding difficulty without checking consistency backfires, because a query may be hard only because it is off target.

4. CANOPY: Adaptive-Granularity Evidence Compression for Multimodal RAG

RAG Pipeline

In the text, tables and video that multimodal RAG retrieves, answering often needs only a sentence or two, one table row or one clip. CANOPY splits each retrieved item into a hierarchy, with text down to sentences, tables down to rows and video down to 30-second clips. A fine-tuned encoder then walks down from the root: if a child is at least as similar to the query as its parent, it goes deeper, otherwise it keeps the whole parent. When evidence is insufficient, a critic module writes a follow-up query and retrieves again. Across 5 QA sets, average accuracy rises from 32.9 with plain RAG to 39.4. Ablations show the accuracy gain comes mainly from follow-up retrieval, while compression just saves input.

5. From VDBBench to the Top of MMEB: Full-Stack Optimization of Alibaba Cloud AI Search, from Engine to Model

Multimodal MatchingAlibaba

This Alibaba Cloud developer community article describes full-stack optimization of AI Search, from the retrieval engine to the embedding model. The author's premise is that once agents reach production, search must keep feeding models high-quality context, through model understanding, vector and full-text recall, hybrid retrieval, fusion reranking and engine execution. The article claims breakthroughs on leaderboards for vector search, classic search and multimodal document retrieval, built on FalconSeek, an in-house Elasticsearch engine, and a multimodal embedding model. The summary gives no scores, so teams should check the leaderboards themselves. Its value is in breaking an AI search pipeline into stages that can each be optimized.

6. Web Search on TokenHub, Tencent Cloud's Model Serving Platform

QA & Deep ResearchTencent

This is the web search API documentation for TokenHub, Tencent Cloud's model service platform. With web search on, the model decides while answering whether to search and with which keywords, then answers from the results. There are two ways to integrate: the Responses API declares a web_search tool in its tool list, and the Chat Completions API turns search on with a separate parameter, and both return cited sources in structured form with the answer. It currently supports the Hy3 and DeepSeek V4 model families and is only available in the Guangzhou region. Search is packaged as a tool the model calls itself, with sources returned alongside the answer, and in-house RAG services can mirror these fields to make switching easier later.

7. Joint Constraint Aggregation for Qualifier-Sensitive Retrieval-Augmented QA

QA & Deep ResearchCMU

In retrieval-augmented QA, the model can pick the wrong answer even when the right one is in the retrieved results, because another candidate meets only part of the question's conditions but appears more often in the documents. For example, the question asks about the original Broadway cast, but the distractor is from the film. Simply raising the share of passages that support the distractor makes the model pick it noticeably more often. JCA first breaks the question into atomic conditions, then checks with the retrieved evidence which conditions each candidate meets, and finally compares all candidates' reports side by side. On the hard subset where distractors are mentioned more, it beats the strongest chain-of-thought baseline by 6.1 to 15.5 points. Comparing the same check results side by side is more accurate than counting how many conditions each candidate meets.

8. Compiling Autoregressive LLM Control into Policy-Exact Parallel Inference for Hierarchical RAG

RAG Pipeline

In hierarchical RAG, an LLM picks three of up to twenty sections at each level of a document's table of contents to read further. Doing this with grammar-constrained decoding takes one sequential forward pass for every output token. The authors enumerate every selection prefix reachable within three steps as a shallow tree and pack it into one sequence that needs only one more forward pass. A tree-shaped causal mask makes each prefix see only the prompt and its own ancestors, with positions numbered as in sequential decoding. Each prefix sees exactly the input it would see in sequential decoding, so with exact arithmetic the probabilities are identical. In practice selection latency drops by 35% to 47%, and the few mismatches are all near-ties under low precision. If every prefix sees the same input, one parallel pass gives the same result as step-by-step decoding.

9. SurveyGraph: Generating Academic Surveys via Methods-Entity Knowledge Graphs

EMNLP 2026Semantic Retrieval

Most automatic survey writers retrieve papers as independent documents and cannot see which paper builds on which method. SurveyGraph first extracts relations between methods, such as extending, improving or moving to a new task, using rules, citation context, shared entities and LLM reasoning, builds a method-entity graph, and then retrieves papers for each survey section along graph neighbors. When the target is the core papers the graph itself selected, graph retrieval has clearly higher recall than flat retrieval. But when the target is the papers the real survey cites, with 5 per section, its recall is only 0.153, below flat retrieval's 0.252. The first target set was chosen by the graph itself, so its higher recall does not prove better retrieval, and the authors accordingly narrow their claim to retrieval that can be audited.

10. Automated Enrichment Analysis with GraphRAG: Efficient Multi-Database ORA Extraction and Biological Interpretation

RAG Pipeline

Gene expression studies often use over-representation analysis (ORA), which tests whether a predefined gene set contains more differentially expressed genes than chance would predict. Results are spread across databases such as GO and KEGG, each giving its own ranked table, and readers must find the links between them. GBOR-RAG builds a bipartite graph of terms and genes from seven databases, runs the same hypergeometric test directly on the graph, and then extracts a compact evidence subgraph connected through shared genes for an LLM to interpret. Its p-values almost exactly match standard ORA, and median query time is 37 times faster. Across 42 queries, 90% of its claims are backed by evidence, against 71% for GeneAgent. Every term in the subgraph links to concrete genes, so each generated claim can be checked against evidence.
