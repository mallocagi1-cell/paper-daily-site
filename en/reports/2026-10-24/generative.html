Community search over short user-generated posts, questions, answers and comments. Key metrics are search relevance (nDCG) and CTR. Focus: semantic matching, query understanding, short-text retrieval, ranking models, and LLM applications in search.

3.95

1. CSG4Rec: Collaborative-Similarity Guided Semantic IDs Tokenization for Generative Sequential Recommendation

The semantic IDs used in generative sequential recommendation are usually produced by quantizing item text embeddings layer by layer, so items with similar text get similar codes; collaborative information such as "often bought by the same users" never enters the codes. CSG4Rec adds a contrastive loss when training the tokenizer: the quantized vectors of two items with similar collaborative behavior are pulled together and those of dissimilar items are pushed apart, so that items with similar codes are similar in both text and user behavior. It also aggregates the embeddings of each user's historically interacted items and quantizes them into a user semantic ID, which is fed into the generative model together with the item semantic IDs. The authors report gains over existing baselines on three benchmark datasets.

3.90

2. Topology-Aware Tokenization for Generative Recommendation

Generative recommenders first use RQ-VAE to quantize each item's semantic embedding layer by layer into a code sequence (a semantic ID), but quantization scrambles neighbor relations between items: of an item's top-20 neighbors in the original embedding space, only 63% are still in the top 20 after layer-1 codes, and only 27% by layer 3. TopoTok adds a KL loss at each layer when training the tokenizer so that neighbor rankings after quantization match those of the original embeddings: layer 1 aligns distances between code groups (items sharing the same layer-1 code), layer 2 aligns distances among items in the same layer-1 group, and layer 3 aligns distances among all items. Constraints go from coarse to fine by layer because early RQ-VAE layers only separate broad categories and later layers separate individual items. On TIGER (a generative recommender that uses T5 to generate semantic IDs token by token), Recall@5 on Amazon Scientific rises from 0.0275 to 0.0302; the losses are computed only in training and add no inference cost.

3. Evaluating LLM-based conversational recommenders with semantic and genre-aware metrics

In conversational recommendation, Recall@K and BLEU count an LLM's movie suggestion as wrong whenever it is not the exact labeled answer, even if both are action comedies. The authors find that the labeled answer appears in the top 10 recommendations only 39% of the time, while another 53% of recommendations share at least a genre with the answer. They build one unified pipeline: a prompt extracts titles, genres and actors from the user's words, these are used to filter candidate movies from a knowledge graph, and an LLM generates the reply; six instruction-tuned models are compared on two movie dialogue datasets, ReDial and INSPIRED. Two new metrics, GHR@10 and SoftGHR@10, score whether the top 10 recommendations overlap the answer in genre, with SoftGHR also crediting partial overlap. The authors conclude that recommendation quality and fabrication depend on the knowledge graph and dialogue context, not on model size.

4. Integrating implicit desire fusion for proactive conversational recommendation systems with LLMs

In conversational recommendation, users often cannot say what they want, and asking about attributes turn after turn drags the dialogue out. DESIRE trains no model; it uses LLMs such as GPT-3.5-Turbo with prompts to handle each turn: it first summarizes the dialogue context, the user's historical preferences, attributes retrieved from the item database and this turn's accept or reject feedback into a needs description, then decides whether to keep asking or to recommend; when asking it picks one of five question types, when recommending it picks one of six persuasion strategies such as presenting evidence or social proof, and item attributes in the reply may only come from retrieval results. Evaluation uses an LLM-simulated user. On LastFM the success rate within 15 turns (SR@15) is 0.583, versus 0.544 for the multi-agent baseline MACRS; removing the needs-summary step drops it to 0.327, showing that the success rate mainly comes from summarizing multiple signals first and then deciding whether to ask or recommend.

5. Unleashing the Native Recommendation Potential: LLM-Based Generative Recommendation via Structured Term Identifiers

When LLMs do generative recommendation, item IDs usually take one of two forms: generating titles directly, whose huge output space makes it easy to invent nonexistent items, or numeric semantic IDs from quantization, which require adding new tokens to the vocabulary plus extra alignment training. Kuaishou's GRLM instead uses 5 standardized keywords as the item ID (e.g., "Cell-Phone | iPhone 17 Pro | 120Hz | Apple AI"). When generating the keywords, the information of the items with the most similar embeddings is put into the prompt as well, so that similar items use the same wording and each item's differences are also written into its keywords. Qwen3-4B is fully fine-tuned on two tasks at once: writing keywords from item information, and predicting the next item's keywords from user history. At inference, items are first matched by exact string; if none matches, keywords are compared one by one, with earlier keywords weighted more. On Amazon Sports, Recall@5 is 0.0375, 30.21% above OneRec-Think, which needs vocabulary expansion; over 98.9% of generated IDs map to real items in the catalog.

3.55

6. HARPO: Hierarchical Agentic Reasoning for User-Aligned Conversational Recommendation

Conversational recommenders are usually evaluated with Recall@K and BLEU, and the authors argue that high scores on these metrics do not mean the recommendations fit what users want. HARPO applies LoRA fine-tuning to DeepSeek-R1-Distill-Qwen-7B; before each reply it expands several candidate reasoning paths (beam width 3, depth 3), a value network scores each path on four dimensions—relevance, diversity, satisfaction and engagement—and the highest-scoring path generates the reply. The four reward heads are first trained on preference pairs made of one better and one worse reply, the value network then learns from the reward heads' scores, and the dimension weights change with the dialogue context. On ReDial, Recall@10 is 29.8%, versus 25.1% for the strongest baseline DCRS and 21.6% for supervised fine-tuning alone on the same backbone. Satisfaction and engagement are scored by the same reward model HARPO optimizes during training, so comparing methods with it favors HARPO; the authors add a human evaluation of 200 samples per dataset.
