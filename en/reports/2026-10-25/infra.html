Today's infrastructure theme is the cost of training and inference. Amazon has a coding agent edit training recipes directly, and uGDS moves the control path of GPU direct storage into user space. Several other papers cut the cost of long-context and agent workloads by compressing attention dimensions, using stratified sparse attention and managing the lifecycle of the KV cache.

1. ATTUNE: Agentic Throughput Tuning for LLM Training

Amazon

LLM training throughput depends on a whole recipe of model sharding, memory-compute trade-offs and overlap of communication with compute, and it has to be retuned for every new model, accelerator or framework. Existing auto-tuners search a fixed grid of knobs and only check that the job runs, so they miss gains outside the grid and can silently change training results. Amazon's ATTUNE is a coding agent that edits the training recipe code on its own within a GPU-hour budget, with a correctness check that keeps training semantics unchanged. On H100, H200 and B200 it raises throughput 1.7 times on average. Throughput gains often lie outside the preset knobs, so letting an agent edit the recipe works better than grid search.

2. uGDS: A User-Space Development Kit for High-Performance GPU Direct Storage

NVIDIA's GPU Direct Storage (GDS) moves data from NVMe drives straight to the GPU. But the control operations of every read and write still go through the kernel, requests in one stream must run in strict order, and the user-space engine is closed source and hard to debug. The authors measure that GDS submission calls can take up to 99.6% of the time. uGDS is a user-space development kit that moves the whole control path into user space and drops unnecessary strict ordering. On a Samsung 990 PRO drive, its batched read bandwidth reaches up to 12 times that of GDS. The bottleneck of GPU direct storage is often the control path and ordering rules, not data transfer bandwidth.

3. RACE: RoPE-Aligned Attention Compression Based on Query-Key Activation Energies

One way to compress the KV cache is to shrink the head dimension, but many such methods restore the full dimension at inference time, so decoding ends up doing more compute. RACE uses a small calibration set to rewrite a pretrained model's attention in a natively low-dimensional form: queries and keys share a projection, RoPE positions stay aligned, and the dimensions to keep are chosen by query-key activation strength, so storage and compute shrink together. Keeping half of the KV at a 256K context, total inference compute drops by 47.8% and throughput rises 1.79 times. Compressed heads must compute in the low dimension directly, or the memory saved turns into extra decoding compute.

4. Cache Engineering for Agents

In long agent tasks, reading, writing and storing the KV cache is the main cost; in API bills the authors find that KV reads make up 82.4%. Rewriting earlier conversation history invalidates everything cached after it and forces a new prefill. So this paper stops compressing history by summarization and instead manages the cache lifecycle and eviction policy. A simple policy that drops the outputs of simple tool calls cuts average cost by 27.7% compared with the usual threshold-triggered summarization, while the benchmark score even rises slightly. Agents save money by not invalidating the cache, not by summarizing history more tightly.

5. Stratified Sparse Attention: Reducing the Sparse-to-Dense Gap at Extreme Sparsity

Long-context inference is slowed down by attention over an ever-growing KV cache. Sparse attention computes only some positions, but keeping only the top-scoring ones loses the attention on the rest, random sampling is unstable, and mixing the two still falls clearly short of full attention. Stratified Sparse Attention (SSA) splits positions into strata and allocates the compute budget within each stratum, using a little compute to recover the attention that would otherwise be dropped. When only one in fifty positions is computed, it recovers 85% of full-attention quality at a 128K context, and decodes million-token contexts up to 2.96 times faster than FlashInfer. At extreme sparsity, recover the attention on dropped positions instead of only picking the top scores.

6. Scaling NVIDIA TensorRT Performance Optimization Beyond a Single Build Route with the Global Performance Tuner, Part 2

NVIDIA

TensorRT 11.1 adds the Global Performance Tuner, which tunes a model end to end automatically while meeting accuracy requirements, finding a suitable optimization path for each model. Part 2 of this NVIDIA blog builds on the concepts from Part 1 to explain the tuner's algorithm and architecture, and gives practical advice, including when global tuning is worth turning on and how to weigh accuracy against performance across several builds. Compiler optimization is not picking the fastest kernel but a global search across many decisions under an accuracy constraint.

7. When PTQ Calibration Helps or Hurts: Dose-Driven Collapse and Validation-Gated Abstention in Quantized Text Embedders

When text embedding models get post-training quantization (PTQ), calibration is commonly used to reduce accuracy loss, but how much calibration changes the model is rarely separated from whether to calibrate at all. The authors apply 4-bit weight quantization to three embedding models over more than a hundred calibration runs, and the same pipeline ranges from small gains to catastrophic drops. What decides the outcome is how much calibration changes the model's outputs, which the authors call the dose. With too large a dose, in-domain NDCG@10 falls by as much as 71.53 points. They therefore propose a validation gate: a calibrated model that misses the bar on a validation set is not shipped. Check how much a calibration changes the model first, and skip it when the change is too large.

8. Gandalf: Flash Shall Not Die! Increasing Flash Storage Lifetime for KV Cache Offloading in LLM Serving

In multi-turn chat and agent workloads, putting the KV cache on SSDs expands capacity, but the write volume far exceeds what the drives can endure, shortening flash lifetime from years to months. Gandalf first decides which KV is worth writing, giving priority to the KV of full-attention layers, then merges writes and places data in tiers to reduce write amplification. Flash lifetime grows 7.3 times, while the serving gains from the larger capacity are kept. When the KV cache goes to SSD, controlling writes to protect lifetime comes first and bandwidth second.

9. Lychee: Certified Screening of Inverted Lists for High-Recall Vector Search

Face watchlists, fraud matching and medical image comparison need nearest-neighbor recall of 0.999 or more, yet approximate indexes cannot tell which queries missed a true neighbor. Probing more lists of an inverted index raises recall, but every probed vector then needs a full-precision score, which is expensive. Lychee adds certified screening to the inverted index: cheap computation first rules out candidates that provably cannot reach the top results, accelerated with Tensor Cores. With recall guaranteed, it is 9.7 to 117 times faster than IVF-Flat. High-recall vector search pays off by provably skipping vectors, not by probing more lists.

10. Scaling NVIDIA TensorRT Performance Optimization Beyond a Single Build Route with the Global Performance Tuner, Part 1

NVIDIA

Deploying a neural network is more than mapping each operator to a GPU kernel. When TensorRT builds an inference engine, it makes interdependent decisions about graph transformations, fusion, implementation choice, memory placement and quantization, and the number of valid combinations is huge. Part 1 of this NVIDIA blog places the Global Performance Tuner within this compilation problem and explains why searching along a single build route is not enough and global tuning is needed. Building an inference engine is a constrained compilation scheduling problem, and a single-route search misses the global optimum.
