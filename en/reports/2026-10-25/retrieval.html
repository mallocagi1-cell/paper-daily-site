AI Search — Paper Daily, 2026-10-25

Today's AI search theme is a fresh look at evaluation. Adobe shows that in agent assistants the model reads retrieval results first, so click-based attribution breaks; AutoSim tests whether simulated users can replace real ones in evaluation; and Cohere's RCP replaces sparse human labels with calibrated LLM judgments. In addition, LMVU picks evidence by which viewpoints are still missing, and ULME has one model do both retrieval and generation well.

1. When Agentic Retrieval Fails Silently: Framework and Production Evidence from a Creative AI Assistant

Adobe

Retrieval metrics such as CTR and MRR assume users see and click the ranked results, but in an agent assistant the generator reads the results first and users see the generated answer. Adobe points out that attribution then breaks in three places: who saw the results, when the user acted, and whether the outcome came from retrieval or from the model's own knowledge. They propose LARA, which measures retrieval quality, user engagement and downstream outcomes in three layers, and specifies four kinds of fields that logs must record. In one production assistant, only 0.31% of prompts actually triggered retrieval. Evaluating agent retrieval can no longer assume users clicked the results; attribution has to be traced layer by layer.

2. AutoSim: A Self-Improving User Simulator for Conversational Search Evaluation

Conversational search wants to replace real users with simulated ones for large-scale evaluation, which only works if the simulator's judgments can be trusted. The system rankings AutoSim produces agree closely with NIST's human assessments in three years of TREC iKAT, but it talks very differently from real people. The authors measure improvement against real conversations held out from training. Tuning only the prompt cannot push the AUC of a classifier that tells humans from the simulator below 0.85, while fine-tuning the model weights brings it down to 0.45, where the simulator can no longer be told apart. Sounding human also changes evaluation results, because a prompt-only simulator is too optimistic about cases where real users struggle to find what they need. A simulator must also talk like real users for its conclusions to hold; ranking systems correctly is not enough.

3. Learning Marginal Viewpoint Utility for Budgeted Evidence Selection in RAG

Some questions are only fully answered with several viewpoints; a question about election participation should cover people who voted, people who did not, and people who were not eligible. RAG selects evidence by relevance and often fills the context budget with passages that support the same view. LMVU is a linear ranker with only 18 coefficients that, at each step, estimates how many still-uncovered viewpoints each candidate would add and puts the best one into the context until the budget runs out. It is trained with viewpoint labels from a development set and needs no labels at inference. On four benchmarks with viewpoint labels, its average viewpoint coverage beats all 16 compared methods, including neural rerankers that cost orders of magnitude more to train. Choose evidence by which viewpoints are still missing, not only by how relevant each passage is.

4. ULME: Predictive Coupling for Mutually Reinforcing Embedding and Language Modeling

In RAG and agent systems the same query usually passes through two models: an embedding model encodes it for retrieval, then a generator reads it again to answer, and the two are trained separately with nothing shared. Unified models such as GritLM share parameters, but their two training objectives still work independently. ULME inserts a sequence of learnable slots between the query and the answer and reads the embedding from two of them. An extra loss makes one slot predict the overall representation of the answer, so information from generation shapes the embedding in turn. Across several sizes of Qwen2.5 and Qwen3, one model scores 3.3 to 4.1 points higher on MTEB than the strongest open baseline, while matching generation-only fine-tuning on generation. Sharing parameters is not enough; the generation objective must supervise the embedding directly for both abilities to improve.

5. Rubric-Calibrated Preferences: Cross-Query Calibration of LLM Judgments via Item Response Theory

CCohere

The closer two rerankers are, the less nDCG can tell them apart, because human relevance labels are sparse and have only a few grades; on NanoBEIR, nDCG cannot separate rerankers on nearly half of the queries. LLM pairwise comparisons can separate very similar documents, but their scores have no common scale across queries, and asking the LLM for absolute grades is too coarse. Cohere's RCP combines the two: an LLM first ranks the documents of each query by listwise comparison, then a set of yes-or-no rubric questions and item response theory (IRT) put the scores of all queries on one scale, replacing the discrete labels inside nDCG. Judged by blind ratings from external annotators, the probability that it ranks a useful document above a useless one (AUC) reaches 0.910, against 0.651 for the original human labels. Calibrated to one scale, relative LLM judgments become finer relevance labels than human grades.

6. Self-Assessment Reinforcement Learning for Search-State Awareness in Retrieval-Augmented Large Language Models

Search agents often do not know what they have already found and what is still missing, so they start reasoning and make things up before the information is complete, or stop searching too early. SARL has the model assess its own search progress during reinforcement learning, with a reward that considers two things: whether each self-assessment corrected the later search, and whether the model leans on assessment too much. After training, no extra assessment step is needed at inference. It improves 24.3% over the strongest baseline in relative terms, and training stays stable as search horizons get longer. A model that learns in training what information is missing knows whether to keep searching or answer.

7. Graph Topology Meets Energy-Driven Pathfinding: Preserving Contextual Consistency in Retrieval-Augmented Generation

EMNLP 2026

Knowledge-graph RAG for multi-hop questions usually breaks text into discrete entities and relations, which loses context, and fragmented graph structures look very different from the continuous text LLMs were pretrained on. ThreadRAG keeps whole text passages as graph nodes, links them by narrative, semantic and lexical relations, finds the subgraph relevant to the question by energy diffusion, and lays it out in order as a coherent passage of textual evidence for the model. On HotpotQA, its exact match (EM) is 14.4% higher than text-centric methods, while it uses only 23.3% of the tokens of the strongest baseline. Graph RAG should keep the original context and turn evidence back into coherent text for the model to read.

8. ERCLIP: Small-Data Adaptation of CLIP for Free-Length Image-Text Retrieval

CLIP's text encoder reads at most 77 tokens, so longer image captions get cut off. ERCLIP adapts CLIP with a small amount of data: during training it encodes a long caption sentence by sentence, fuses the results, and adds a sentence-level contrastive loss. At inference it keeps the original dual encoder, and test captions are still truncated. Its image-text retrieval R@1 is 6.5 to 11.2 points higher than the original CLIP, closing more than 60 percent of the gap to Long-CLIP. Long captions do not require changing the inference encoder; adding sentence-level signals in training is enough.

9. FlexVDR: Learning to Allocate Matryoshka Representation Budgets for Visual Document Retrieval

Visual document retrieval relies on fine-grained multi-vector representations of each page, which are expensive to encode and match. Existing compression and elastic representation methods offer configurations of several sizes, but do not say which one each query should use. FlexVDR combines encoder depth, embedding width and token count into several compute routes inside one retriever. Its budget allocator predicts each route's retrieval value from early query features and, together with an adjustable resource preference, picks one route per query. In experiments it chooses smaller routes for individual queries while keeping most of the original model's retrieval quality. Elastic representations need a per-query budget choice; offering several configurations is not enough.

10. Unbalanced Optimal Transport for Efficient Visual Document Retrieval

ECCV 2026

OCR-free visual document retrieval with vision-language models produces many tokens per page, which makes retrieval hard to scale. Existing compression methods rely on separate rules of thumb and struggle to balance token importance, semantic redundancy and coverage of the page at the same time. This paper casts visual token compression as an unbalanced optimal transport problem and handles all three goals in one alternating optimization. The authors also prove that a lower transport cost bounds the retrieval scoring error more tightly, which keeps the ranking stable. Visual token compression should weigh importance, redundancy and coverage within one optimization problem.
