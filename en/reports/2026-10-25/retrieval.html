Today's AI search theme is a fresh look at evaluation. 1. When Agentic Retrieval Fails Silently: Framework and Production Evidence from a Creative AI Assistant

Adobe

Retrieval metrics such as CTR and MRR assume users see and click the ranked results, but in an agent assistant the generator reads the results first and users see the generated answer. Adobe points out that attribution then breaks in three places, namely who saw the results, when the user acted, and whether the outcome came from retrieval or from the model's own knowledge. They propose LARA, which separately measures whether retrieval ranked well, whether the returned assets were used, and whether the user finished the task. Each retrieval logs an ID and its list of returned assets, and when the user uses an asset, the log records that asset and the retrieval it came from, which links later actions back to that retrieval. In one production assistant, only 0.31% of prompts triggered retrieval. Evaluating agent retrieval can no longer assume users clicked the results; attribution has to be traced layer by layer

2. AutoSim: A Self-Improving User Simulator for Conversational Search Evaluation

Conversational search wants to replace real users with simulated ones for large-scale evaluation, which only works if the simulator's judgments can be trusted. The system rankings AutoSim produces agree closely with NIST's human assessments in three years of TREC iKAT, but it talks very differently from real people. The authors measure improvement against real conversations held out from training. Tuning only the prompt cannot push the AUC of a classifier that tells humans from the simulator below 0.85, while fine-tuning the model weights brings it down to 0.45, where the simulator can no longer be told apart. Sounding human also changes evaluation results, because a prompt-only simulator is too optimistic about cases where real users struggle to find what they need. A simulator must also talk like real users for its conclusions to hold; ranking systems correctly is not enough.

3. Learning Marginal Viewpoint Utility for Budgeted Evidence Selection in RAG

Some questions are only fully answered with several viewpoints; a question about election participation should cover people who voted, people who did not, and people who were not eligible. RAG selects evidence by relevance and often fills the context budget with passages that support the same view. LMVU is a linear ranker that scores the remaining candidates at each step and adds the top one to the context until the budget runs out. It does not identify viewpoints directly. Its 18 features can be computed at run time, covering the candidate itself and how similar it is in embedding space to passages already selected. In training, viewpoint labels from a development set show which candidates added a new viewpoint, and it learns the feature weights from them. On four benchmarks with viewpoint labels, its average viewpoint coverage beats all compared methods. Choose evidence by which viewpoints are still missing, not only by how relevant each passage is

4. ULME: Predictive Coupling for Mutually Reinforcing Embedding and Language Modeling

In RAG and agent systems the same query usually passes through two models: an embedding model encodes it for retrieval, then a generator reads it again to answer, and the two are trained separately. Unified models such as GritLM share parameters, but their two training objectives still work independently. ULME inserts a few learnable slot tokens between the query and the answer and uses the model's hidden vectors at these positions as embeddings. The first slot's vector is used for retrieval and is aligned with document representations in training; another slot's vector must predict the average of the answer's hidden states, so information from generation shapes the embedding in turn. Across several sizes of Qwen2.5 and Qwen3, MTEB scores are 3.3 to 4.1 points above the strongest open baseline, while generation matches generation-only fine-tuning. The generation objective must supervise the embedding directly for both abilities to improve

5. Rubric-Calibrated Preferences: Cross-Query Calibration of LLM Judgments via Item Response Theory

CCohere

The closer two rerankers are, the less nDCG can tell them apart, because human relevance labels are sparse and have only a few grades. Cohere's RCP first has an LLM compare each query's documents listwise and turns the result into a score per document. The LLM then answers five yes-or-no questions about every document, each stricter than the last: whether it is on topic, has useful information, discusses the specific things the query names, answers the query directly, and goes in depth. Item response theory (IRT) treats the five questions as exam items with fixed difficulty shared by all queries, and learns a shift and scale per query so that adjusted scores explain which items each document passed, making scores comparable across queries. Judged by blind ratings from external annotators, the probability that it ranks a useful document above a useless one (AUC) is 0.910, against 0.651 for the original human labels. Calibrated to one scale, relative LLM judgments become finer relevance labels

6. Self-Assessment Reinforcement Learning for Search-State Awareness in Retrieval-Augmented Large Language Models

Search agents often do not know what they have already found and what is still missing, so they start reasoning and make things up before the information is complete, or stop searching too early. In reinforcement learning, SARL has the model assess at the end of each search whether its information is complete, and keep searching to revise if not. If the revision turns a wrong answer into a right one, that assessment is rewarded; the more assessments it makes, the more the final-answer reward is discounted, so the model does not lean on them. After training, no extra assessment step is needed at inference. Across ten QA and deep-research benchmarks, its average score is 24.3% higher than the strongest baseline in relative terms, and training stays stable as search horizons get longer. A model that learns in training what information is missing knows whether to keep searching or answer

7. Graph Topology Meets Energy-Driven Pathfinding: Preserving Contextual Consistency in Retrieval-Augmented Generation

EMNLP 2026

Knowledge-graph RAG for multi-hop questions usually breaks text into discrete entities and relations, which loses context, and fragmented graph structures look very different from the continuous text LLMs were pretrained on. ThreadRAG keeps whole text passages as graph nodes, links passages that are adjacent in the original text, and also links passages with similar meaning or shared wording. For a question, it picks the most relevant passages, gives them initial scores in proportion to relevance, and lets the scores spread along edges (personalized PageRank). Passages with high scores afterwards form the relevant subgraph, which is laid out roughly in the original text order as one passage for the model. On HotpotQA, its exact match (EM) is 14.4% higher than text-centric methods. Graph RAG should keep the original context and turn evidence back into coherent text

8. ERCLIP: Small-Data Adaptation of CLIP for Free-Length Image-Text Retrieval

CLIP's text encoder reads at most 77 tokens, so longer image captions get cut off. ERCLIP adapts CLIP with a small amount of data. In training, a long caption is split into sentences that are encoded one by one, then averaged or combined by a small network into one long-caption vector. This vector and its image form a positive pair, with the other images in the batch as negatives, in contrastive learning. Since the sentences pass through the original text encoder, this signal improves the encoder itself. At inference it keeps the original dual encoder, and test captions are still truncated. Its long-caption image-text retrieval R@1 is 6.5 to 11.2 points higher than the original CLIP. Long captions do not require changing the inference encoder; adding sentence-level signals in training is enough

9. FlexVDR: Learning to Allocate Matryoshka Representation Budgets for Visual Document Retrieval

Visual document retrieval relies on fine-grained multi-vector representations of each page, which are expensive to encode and match. Existing compression and elastic representation methods offer configurations of several sizes, but do not say which one each query should use. FlexVDR combines encoder depth, embedding width and token count into several compute routes inside one retriever. Early in query encoding, its budget allocator uses features from the first layers to predict each route's retrieval value, then picks a route under an adjustable resource preference, where a stronger preference favors smaller routes. The same retriever can thus change its compute without retraining. In experiments it chooses smaller routes for individual queries while keeping most of the original model's retrieval quality. Elastic representations need a per-query budget choice; offering several configurations is not enough

10. Unbalanced Optimal Transport for Efficient Visual Document Retrieval

ECCV 2026

OCR-free visual document retrieval with vision-language models produces many tokens per page, which makes retrieval hard to scale. Existing compression methods rely on separate rules of thumb and struggle to balance token importance, semantic redundancy and coverage of the page at once. This paper treats compression as assigning each page's original tokens to a few representative tokens. Tokens that receive more attention carry more weight, and semantically closer tokens tend to merge into the same representative. Each representative takes roughly equal weight so the page stays covered, which makes this an unbalanced optimal transport problem. It alternates two steps, first fixing the representatives and solving the assignment, then updating the representatives from the assignment. The authors also prove that a lower transport cost tightens the bound on retrieval scoring error. Importance, redundancy and coverage should be weighed within one optimization problem
