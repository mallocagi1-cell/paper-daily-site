Today's recommendation and ads track has two threads. The first is where training signals come from: Meta uses auxiliary signals such as pre-click viewing time and add-to-cart events to fill in rare conversion labels, and another paper uses behavior patterns learned from popular items to correct the content embeddings of long-tail items. The second is the details around launch. How to encode numerical features has to be re-tested on your own data, and whether a click opens a website or an app is worth deciding click by click. Headline rewrites by LLMs that push up rankings now also have a defense with no added latency.

5. Dynamic Click Destinations: Personalizing Post Ad-Click Landing Experiences

A user taps an offsite ad: should it open the advertiser's website, or jump straight into the advertiser's app already installed on the phone? Switching the default from web to app for everyone actually lowers overall advertiser value (value-weighted conversions) by 1.05%, with a small gain only on ads optimizing for purchases. In other words, which destination is better depends on each click. This paper from Meta picks the destination for each click separately, and the model went through three generations. The last one directly predicts which of the two destinations is better, with training labels taken from the difference between a larger model's conversion scores for the two destinations. In online A/B tests, this generation raises advertiser value by 0.54% over always opening the website. Where a click sends the user is an often overlooked lever for optimization.

6. Efficient Conformal Calibration for Paired Recommendation Decisions

A post-processing rule on a trained recommender, such as swapping a few items or reordering, may improve the average result but hurt some users. The usual safeguard is conformal risk control: use held-out data to set a threshold that keeps the expected loss within a budget. But it is often too conservative and blocks useful changes too. This paper finds the problem is wasted information during calibration. One existing method only records whether each user got worse, so a slight drop counts the same as a severe one. The paper's calibration method (ACRC) charges the budget by the actual size of each loss, so a slight drop uses only a little budget, and more changes get through under the same risk guarantee. On 6 datasets, changing only this calibration step gives higher net utility than the existing calibration methods.

7. Yielding Fairness: Coupled Learning and Fairness for Value-Weighted Ranking

Risk screening and recommendation systems often decide whether to pass or block an account, and an account brings both value and loss. If the value lost by blocking has a cap, the best ranking orders accounts by how much value each unit of expected loss carries, blocking the lowest ratio first until the value budget is used up. Another common criterion blocks by expected loss (or loss minus value), from largest to smallest. Under the same budget, the ratio rule may block an account this criterion would pass, and the paper counts this as a contestable block. When training the ranking score, the paper adds a penalty for accounts that would trigger such a block, and the heavier the penalty, the more the account is pushed toward the pass side. Using different penalty multipliers for different groups traces a trade-off curve between how much loss is caught and the gap in complaints between groups. On public recommendation, insurance and credit data, group-specific penalties narrowed the gap in some groups, but on average they were not significantly better than group-blind penalties.

8. PACERec: Progressive Adaptation of LLM Item Embeddings with Collaborative Evidence for Recommendation

Sequential recommenders often use LLM item embeddings to help long-tail items, but these embeddings only capture whether item contents are similar, not what users tend to view right after what. Long-tail items have too little behavior data to correct their embeddings on their own. PACERec first computes a behavioral target for each item: it takes the items users viewed just before choosing it and computes a weighted average of their content embeddings, with more recent items weighted higher. The model then learns one correction pattern shared by all items: given where a vector is now, it computes which direction to move next and by how much, moving the content embedding step by step toward the behavioral target. This pattern is learned mainly from popular items, whose behavioral targets are reliable. A long-tail item only needs its content embedding to use it directly. On three datasets and three sequential models, tail-item NDCG@10 is on average 33.31% higher than the strongest baseline in each setting.

9. RecRSI: Mechanism-Guided Discovery of Recommendation Algorithms

When an LLM agent tries to improve recommendation algorithms automatically, the hard part is that one experiment's result rarely tells it what to change next. RecRSI attaches a mechanism hypothesis to every change: which component to modify, which existing design it draws on, why it should work, and what result to expect. After the experiment, the result and its design context are passed on to later research and used to decide which mechanisms to develop, revise or combine next. Across several initial recommenders and datasets, it raises NDCG@5 by 8.48% on average relative to the initial algorithms, and by 2.60% over the strongest competing method in each setting. This shows that automated algorithm work keeps improving only when each experiment leaves a reusable conclusion.

10. F3 Lightning: How Meta Accelerates Ads ML Features to Production at Scale

Meta

The more than twenty thousand features used in Meta ads ranking used to be released together, so a single broken feature definition stopped every feature from shipping. They were tied together because they were compiled into one merged computation graph, which let shared computation run only once. F3 Lightning turns each feature into a unit that can be compiled, validated, deployed and rolled back on its own, while keeping the shared computation. It does this by giving each shared step a stable identifier, and all features share one execution plan and one block of memory. As a result, comparable features reach production about 3.6 times faster, with no increase in compute cost. Faster feature releases mean more model iterations in the same amount of time.
