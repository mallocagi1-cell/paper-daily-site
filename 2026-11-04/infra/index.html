Rethinking KV Cache Eviction for Agentic LLM Serving

KV cache 放不下时，vLLM 和 SGLang 都从缓存序列的末尾开始删，为的是保住开头那段能被很多请求共用的前缀。但 agent 每一轮都会把很长的历史重新发回来，而越靠后的 token 重算越贵，因为它要和前面所有 token 算注意力。Penelope 反过来做：共享前缀照样保留，剩下的历史从靠前的部分开始删，留住靠后的部分。请求回来时，只重算缺掉的那一段。在 SGLang 上用真实 agent 请求记录测，只用 GPU 缓存时平均首 token 延迟最多降 60%，再加上 CPU 内存做第二层缓存时最多降 76%。该删哪一段，要看重算它要花多少，而不只看它被多少请求共用。

Jiakun Fan, Han Meng, Yuxuan Xia, Hao Mark Chen, Dong Li, Dimitrios S. Nikolopoulos

Scute: Exact Batched Serving for PEFT Adapters Beyond LoRA

vLLM 和 SGLang 能把许多 LoRA 适配器的请求拼成一批，但 DoRA、VeRA、OFT 这类其他微调方法的适配器直接被拒，没法和它们混在一批里跑，转成 LoRA 又要多占显存、可能掉精度。多租户平台常给每个客户叠一个自己的小适配器，这个限制很碍事。Scute 在 LoRA 的计算里留出几个可填的位置：基础权重那条路上，输入先乘一个变换矩阵，输出再按列缩放、加一个偏移；低秩那一项的中间和输出也各乘一个向量。不用的位置就是乘 1 或加 0。比如 OFT 先旋转输入再走原来的层，它的旋转矩阵就填进输入变换。这样五种方法能在一个批次里精确混跑，decode 时间只比同样数量的 LoRA 多 5% 到 17%。与其把各种适配器都转成 LoRA，不如让 LoRA 的批处理核函数认识它们。

Faster and Cheaper Search With Qdrant 1.20

Qdrant

向量库里最贵的往往是存向量本身：冷数据占磁盘，热数据占内存。Qdrant 1.20 新加了两种低位存储类型 turbo8 和 turbo16。它们不是把 float32 直接截成低精度，而是先把向量旋转一下再量化，尽量保住检索需要的信息。在官方测试的一组向量上，turbo8 只占 float32 四分之一的空间，召回还略高一点，服务端延迟比 float32 多出不到 10%。延迟涨得少，是因为查询向量只做旋转、不做量化。先旋转再量化，能在省空间的同时基本不丢召回。

XLA from the Trenches: Correctness on TPU Workloads at Scale

编译器里的一个错误可能不报任何错，只是悄悄让数值算偏，几周后让一次昂贵的训练发散，或者让线上推理质量变差。Google 介绍了他们怎样在大规模上排查 TPU 上 XLA 编译器的这类问题。一方面，用随机生成的程序和真实生产里的计算图做模糊测试，并让一群 AI agent 自动写压力测试、复现失败、起草修复。另一方面，定位时把出错的大计算图层层二分，一直缩小到融合核函数里出错的那一个算子。这套流程上线后已经推动修复了超过 142 个编译器缺陷，另有 103 个发现还在核实。编译器正确性要靠持续的生产级测试，只跑回归用例远远不够。

Keep Distributed Training Running with Automated Workload Recovery

NVIDIA

分布式训练规模越大，某个训练进程卡住、某个节点失联、某台机器拖慢全局这类中断就越频繁。每次都要有人看日志、找出坏节点、从 checkpoint 重启，期间 GPU 在空转。NVIDIA 开源的 NVIDIA Recovery 把这件事自动化：从应用日志、GPU 指标和调度器信号里发现异常，判断是哪台机器的问题，把它隔离，再按策略重启或停掉任务。新部署默认只给建议、不动手，方便运维先确认信号可靠。在一个每天约 200 个任务的训练集群上跑了三个月，平均 69 秒发现异常，94 秒采取恢复动作。先只给建议、再放开自动处理，让这类系统上线的风险小得多。

Reduce LLM latency with prefix-aware routing on Amazon SageMaker Inference

Amazon

很多 LLM 应用的提示都以一大段固定内容开头，比如几千 token 的客服规则，后面才是用户的一句话。单台机器上的前缀缓存能省掉这段重算，但多台机器时请求被随机分出去，每台都很少重复见到同一个开头，缓存基本用不上。Amazon SageMaker 新加的前缀感知路由会把开头相同的请求固定发到同一台机器。那台机器满载时，请求转给空闲的机器；扩缩容时，也只挪动一小部分流量。在官方测试里，缓存命中率从约 25% 升到 80% 以上，中位首 token 延迟最多降 77%。多实例部署时，前缀缓存省不省得下来，取决于路由。
