Diverse-Teacher On-Policy Distillation for Generative Recommendation

让学生模型自己生成、老师逐位给出完整概率的蒸馏（OPD）能让生成式推荐训得更快，但学生会越来越偏向热门商品。原因有两头：老师的概率本来就偏爱热门商品的 SID，学生自己生成时也很少走到冷门商品的 SID，这些路径几乎拿不到监督。

Beyond Uniform Token Training: A Multi-Target Framework for Learning Token-Weighted Objectives in Generative Recommenders

已录用 CIKM 2026CMUNTUNNTHUAAcademia Sinica

生成式推荐训练时给 SID 每一位 token 同样的损失权重，这篇论文发现按位置和罕见程度给不同权重，推荐效果会稳定变好。原因是 SID 的前几位决定商品大类，后几位只做细分，而且有些 token 出现得特别少。这篇论文给 token 加两种权重：一种看位置，某一位确定以后能排除的候选商品越多，这一位的权重越大，所以靠前的位权重更大。另一种看频次，token 在训练数据里出现得越少，权重越大。训练时把这两种加权损失和普通似然损失放在一起优化。相对基础的 TIGER，Hit@5 平均提升 6.11%，热门商品和长尾商品都有改善。它只改损失权重，不动模型结构，接入成本很低。

Wei-Ning Chiu, Song-Duo Ma, H. Shu, Chuan‐Ju Wang, Pu‐Jen Cheng

Search-Aware On-Policy Self-Distillation with Sibling Alignment for Generative Recommendation

生成式推荐靠束搜索出结果，前缀一旦被剪掉就找不回来，可常见的自蒸馏训练并不关心哪些前缀快被剪掉。自蒸馏的老师是同一个模型的冻结副本，训练时额外看到目标商品的标题，它在学生生成的每个状态上一视同仁地给监督。SA-OPSD 只在学生自己 束搜索 走过的状态上蒸馏，优先挑那些分数离束搜索保留线最近、差一点就会被剪掉的状态；它在一个工业数据集和两个公开数据集上更好，训练成本也低于全量 KL 蒸馏，推理流程不变。

HiGenTrans: Hierarchical LLM Knowledge Transfer for Generative Recommendation

生成式推荐只靠交互数据训练，大模型里现成的语义知识用得很少；束搜索 的似然排的是 token 序列，也不直接等于商品和用户的相关性。HiGenTrans 在三处引入大模型知识：生成前，把大模型算出的用户表示加到序列开头；中间层，让生成模型每一层的表示去贴近大模型里相对深度相同的那一层；最后用一个小的 MoE 打分器，把每个候选的语义相关度和生成置信度等信号合成一个分数，按这个分数对 束搜索 的结果重排。所有语义特征只用用户已有的交互计算，可以离线缓存。在三个公开数据集上，NDCG@10 最多提升 33.7%，而且每个数据集上 NDCG 涨得都比 Recall 多，收益主要来自把对的商品排得更靠前。

Zhuohang Jiang, Yuxin Chen, Haohao Qu, ZeFei luo, Yunlong Wang, Xu Yuan, Haojie Ding, Boheng Zhang 等 16 人

Neutralizing Popularity Bias in LLM-based Recommendation via Counterfactual Reasoning Guidelines

已录用 CIKM 2026Nanjing University

让大模型做推荐，它常顺着预训练学到的流行度走，推的是热门而不一定是用户喜欢的。这种偏差藏在参数里，很难直接去掉。NPRec 不改参数。它先根据用户的交互记录生成几条候选的文字准则，描述这个用户可能的偏好。接着训练一个小模型，预测某条准则是否适用于某个用户和商品。每条准则算两次适用概率：一次输入真实的用户和商品；一次把用户和商品的输入都换成全零向量，只留商品热度。用真实用户和商品时概率明显更高的准则才保留；只靠热度就适用的，讲的其实是随大流。推理时把准则放进提示词，让大模型照着推荐。换成人工写的准则，MovieLens 上的首位命中率比基础提示高 95.6%，准则写得好不好才是关键。

Guanrong Li, Haolin Yang, Xinyu Liu, Zhen Wu, Rui Xia
