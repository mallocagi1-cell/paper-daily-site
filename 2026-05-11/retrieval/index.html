Superintelligent Retrieval Agent: The Next Frontier of Information Retrieval

论文提出 SIRA (SuperIntelligent Retrieval Agent)，把多轮探索式检索压缩为一次具有语料判别力的检索动作。系统在文档侧用 LLM 离线扩充补充检索词、在 query 侧用 LLM 预测被忽略的证据词，再用文档频率统计过滤无效扩展项，最终以一次加权 BM25 调用完成检索。在 BEIR 十个基准与下游 QA 任务上均超过密集检索器与多轮 agentic 基线，且无需训练、保持可解释性、计算开销远低于多轮 search。

AgenticRAG: Agentic Retrieval for Enterprise Knowledge Bases

AgenticRAG 给推理型 LLM 配备 search/find/open/summarize 四类工具，让模型迭代式地探索企业知识库再回答，取代传统单步检索。在 BRIGHT 上 recall@1 达到 49.6%，比 embedding 基线高 21.8 个百分点；WixQA 事实一致性 0.96，FinanceBench 答案正确率 92%。消融实验显示从 single-shot 升级到 agentic 检索带来 5.9 倍提升，多 query 搜索与文档内导航各自再叠加增益。

INSIGHT把检索从一次性向量召回升级为带工具的多步交互，对长尾、隐式 query 提升尤其显著。对社区搜索可借鉴的工程路径：先用现有双塔召回作为 search tool 的一种，再让 LLM agent 控制 reformulate / open / summarize 的流程；先在长尾低 CTR query 集合落地，避免主流量延迟敏感场景一刀切。

Susheel Suresh, Hazel Mak, Shangpo Chou, Fred Kroon, Sahil Bhatnagar

Beyond Semantic Similarity: Rethinking Retrieval for Agentic Search via Direct Corpus Interaction

传统检索把访问压缩为单步 top-k，难以处理精确约束、稀疏线索与多步细化。论文提出 Direct Corpus Interaction (DCI)：让 agent 用 grep、shell 等通用工具直接在原始语料上搜索，无需 embedding 模型与向量索引，从而免去离线索引并适配频繁更新的数据。在 BRIGHT、BEIR 两个高难数据集上明显超过稀疏、密集与重排基线，并在 BrowseComp-Plus 与多跳 QA 上保持强势。

INSIGHT作者把核心论断概括为：检索质量不仅取决于推理能力，更取决于模型访问信息的接口分辨率。对于 UGC 平台上线索稀疏、长尾约束密集的 query，可以引入 LLM 直接执行结构化搜索（如 ES DSL、ClickHouse SQL）作为补召回通道，把 ES/向量库当作 LLM 的工具，而不是只把它输出当作上下文。

A Case-Driven Multi-Agent Framework for E-Commerce Search Relevance

面向电商搜索相关性，论文提出由多个 agent 替代用户、产品经理、标注员、工程师、评估员的 case-driven 多智能体框架。核心组件包括 Annotator Agent 多轮标注、Optimizer Agent 分析与解决坏 case、User Agent 主动发现问题，再加上一个统一的 retrieval-and-ranking 相关性模型、一个指令遵循的实时 case 解决模型、以及降低信息不对称的 Global Memory。系统作为坏 case → 解决方案的 pipeline 落地，人工评测显示在标注准确率与坏 case 修复时效上均有提升。

INSIGHT把 LLM agent 接入相关性运营全链路（采集、定标、归因、修复、回灌）是工业界落地 LLM-for-search 最务实的形态：不是用 LLM 取代排序，而是让 LLM 取代相关性优化的”人力流水线”。社区搜索同样存在大量长尾坏 case 跨 PM/标注/算法的协同瓶颈，可以先在标注 agent 与坏 case 优化 agent 落地，配合统一相关性模型共享上下文。

Global E-Commerce Search Relevance Team (Junfeng Hu et al.)

OBLIQ-Bench: Exposing Overlooked Bottlenecks in Modern Retrievers with Latent and Implicit Queries

MITStanford

论文定义”oblique”查询为指向潜在模式的查询：例如表达隐式立场的推文、显示失败模式的聊天日志、匹配抽象场景的会议记录。作者刻画了三种 obliqueness 产生机制并构建 OBLIQ-Bench——五个基于真实长尾语料的 oblique 检索任务。实验揭示一个关键缺口：reasoning LLM 几乎总能从候选中识别出隐式相关性，但即使最先进的检索 pipeline 也常常召不出真正相关的文档；瓶颈在召回端而不是判别端。

INSIGHT这正是社区搜索 UGC 内容的核心难题：query 描述的是抽象场景或情绪，文档表达却隐式。论文给出”reasoner OK + retriever miss”的明确诊断，意味着投入应优先放在召回侧的语义扩展（query 改写、文档侧 enrichment、隐式标签生成），而不是堆叠重排端 LLM。可以借鉴 OBLIQ-Bench 的难度构造方法，在内部相关性评测集中加入 oblique 切片，避免被高 saturation 的传统 benchmark 误导。

Diane Tchuindjo, Devavrat Shah, Omar Khattab

AdaGATE: Adaptive Gap-Aware Token-Efficient Evidence Assembly for Multi-Hop Retrieval-Augmented Generation

针对多跳 RAG 在冗余/噪声语境下的脆弱性，论文提出无需训练的证据选择控制器 AdaGATE，把证据选择形式化为受 token 预算约束的”修复”问题，结合实体级 gap 跟踪、micro-query 生成与基于效用的证据筛选。实验在干净 HotpotQA 上 evidence F1 达 62.3%，在注入冗余的设置下 71.2%，并比 Adaptive-k 基线少消耗 2.6 倍输入 token。

INSIGHT把”证据组装”从黑盒交给 LLM 改造成可控的修复流程，对延迟与成本敏感的线上 RAG 链路非常有价值。社区搜索的多模块结果（帖子、问答、评论）天然适合”先 gap 再 micro-query”的渐进检索：先看一轮初始结果，识别仍未覆盖的实体/约束，再发起第二轮局部召回，用 token 预算控制总体成本。

Yilin Guo, Yinshan Wang, Yixuan Wang

Towards Dependable Retrieval-Augmented Generation Using Factual Confidence Prediction

论文目标是判断 RAG 召回的上下文是否真正支撑生成答案。方法两阶段：第一阶段用 conformal prediction 过滤召回 chunk，部分数据集上回答质量提升最高 6%，但统计保证依赖检索器假设；第二阶段用 attention-based factuality classifier 衡量答案与上下文一致性，检测不一致的准确率 77%。整体目标是把 RAG 推向”可认证”的工业可用形态。

INSIGHT对 UGC 搜索的”问答型”卡片或社区智能助手而言，事实一致性比单纯相关性更关键。两段式（先 chunk 过滤、再 attention 一致性分类）可作为线上 hallucination 兜底链路；conformal prediction 的”可校准置信”思路也可以借鉴到相关性置信度上，对低置信 query 改走多样性策略而非 top-1 直出。

Florian Geissler, Francesco Carella, Laura Fieback, Jakob Spiegelberg

Text-Graph Synergy: A Bidirectional Verification and Completion Framework for RAG

TGS-RAG 针对纯文本 RAG 检出无关证据、纯图 RAG 在剪枝时丢失有效推理路径的痛点，引入双向增强：Graph-to-Text 通道用 Global Voting 精炼文本证据，Text-to-Graph 通道用 Memory-based Orphan Entity Bridging 恢复被丢弃的推理路径。多跳推理 benchmark 上稳定优于 SOTA。

INSIGHT社区内容天然带有半结构化关系（用户、话题、商品、评论），完全文本化召回会损失关系信号。TGS-RAG 的双向校正给出一个工程范式：用图 voting 过滤文本噪声、用文本记忆恢复被截断的图路径，可在话题聚合搜索、商品评价聚合等场景带来更稳健的多文档相关性。

Jiarui Zhong, Hong Cai Chen

EnterpriseRAG-Bench: A RAG Benchmark for Company Internal Knowledge

论文构建面向企业内网知识 RAG 的评测集：约 50 万文档、覆盖 9 类企业数据源（Slack、Gmail、Linear、Google Drive、HubSpot、Fireflies、GitHub、Jira、Confluence），共 500 道题，涵盖单文档检索到多文档推理、约束检索、冲突解决等 10 个类别，并刻意保留错放文档与冲突信息等真实噪声。配套生成框架可按行业与规模二次定制。

INSIGHT对内部知识搜索（员工搜索、客服 RAG）这是稀缺的”接近真实环境”评测集——同时包含跨数据源覆盖、多文档冲突与噪声噪文档。社区/电商场景可以参照其题目分类法（单跳/多跳/约束/冲突）重构评测体系，避免线上 RAG 在长尾困难分布上裸奔。

Yuhong Sun, Joachim Rahmfeld, Chris Weaver, Roshan Desai, Wenxi Huang, Mark H. Butler
