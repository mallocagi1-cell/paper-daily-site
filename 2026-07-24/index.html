SilverTorch: Index as Model — A New Retrieval Paradigm for Recommendation Systems

Meta 将推荐检索中的索引、过滤、重排和多任务打分统一为一个 PyTorch 模型，把索引本身变成模型张量，并在不足 100 毫秒内完成全链路。面向 8000 万物品的评测中，SilverTorch 吞吐提升 23.7 倍，估算算力成本效率提升 20.9 倍。

Towards Generalizable and Efficient Large-Scale Generative Recommenders

Netflix📖 深度解读 · 8 分钟 →

论文把生成式推荐骨干从 200 万参数扩展到 10 亿参数，并用带偏移项的 Scaling Law 判断不同下游任务是否接近收益上限。作者结合多 Token 预测、采样 Softmax、投影解码头及语义冷启动塔，在 100 万用户的一周生产影子实验中让 10 亿模型在全部任务上取得更高 MRR。

INSIGHT推荐模型扩容不能只看统一损失曲线，应分别估计每个任务的剩余容量，再把训练成本、在线缓存陈旧和新内容冷启动纳入同一决策。对社区搜索可按内容类型拟合独立 Scaling Law，优先扩容仍有 headroom 的任务，并用语义塔承接新帖冷启动。

Qiuling Xu, Ko-Jen Hsiao, Moumita Bhattacharya

ReList: A Multi-objective Reasoning Framework for Diversified Listwise Query Recommendation

ReList 将相关搜索词推荐改写为带推理的 Listwise 生成任务：先把多样查询列表反向构造成思维链数据，再交替执行门控多目标奖励的强化学习与纠错式 SFT。论文在真实搜索基准和线上 A/B 中同时改善查询多样性与用户参与度；候选摘要未披露具体提升幅度。

INSIGHT点式 Beam Search 容易产生语义重复，单一 CTR 奖励也无法约束列表覆盖面；ReList 用列表级推理和多目标门控把相关性、多样性与互动统一起来。社区搜索可把“同义改写、主题扩展、意图澄清”设为不同奖励维度，并用纠错 SFT 专门回收难例。

Shuxian Bi, Chenxu Wang, Wenjie Wang, Yueqi Mou, Fuli Feng, Tang Biao, Peng Yan

Faster than Light: Optimizing Generative Recommender Training Efficiency at LinkedIn

LinkedIn

LinkedIn 将最长 360 天的异构行为序列输入约 11 亿参数生成式推荐模型，并针对变长序列、巨型 Embedding 与数据 I/O 优化数据管道、计算和训练生命周期。组合方案在生产训练中最多减少 65% GPU 小时，线上 Feed A/B 的会话时长提升 2.10%。

INSIGHT生成式推荐的落地瓶颈常在数据搬运和变长批处理，而不只在 Transformer 算子。社区平台可先统一行为 Token 流并测量 I/O、Padding 与 Embedding 热点，再逐项复用流水线优化；若离线质量不降，应以 GPU 小时和会话指标共同决定扩容。

Chen Zhu, Tommy Li, Tao Huang, Yang Pei, Jaideep Ray, Yitong Zhou

Beyond Relevance-Centric Retrieval: Rubric-Oriented Document Set Selection and Ranking

论文指出面向 LLM 生成的检索不能只逐文档计算 nDCG，而要评估集合内冗余、冲突与互补。SetwiseEvalKit 提供三级、九维、约 2.8 万条评判标准；对 12 个重排器的评测显示最佳覆盖率也不超过 45%，训练免费方法 Rubric4Setwise 用更少文档和搜索轮次取得最佳下游生成效果。

INSIGHT当搜索结果供生成模型消费时，单篇相关并不等于集合最优，重复帖子会浪费上下文并放大单一观点。社区搜索可把信息互补、证据冲突、来源覆盖加入 Setwise 重排，在不重训主模型的前提下先用规则化 Rubric 做候选集选择。

From Local Indices to Global Identifiers: Generative Reranking for Recommender Systems via Global Action Space

📖 深度解读 · 10 分钟 →

GloRank 用稳定的全局 Semantic ID 取代随样本变化的局部位置索引，把 Listwise 重排改成受前缀树约束的 Token 生成。模型先用高质量示范做监督预训练，再以强化学习直接优化列表效用；作者在 2 个公开基准、1 个工业数据集及线上 A/B 上验证有效性，摘要未给出增幅。

INSIGHT局部序号让同一输出神经元在不同请求中代表不同物品，难以沉淀跨请求的物品知识；全局 ID 能稳定动作空间并改善冷启动。社区搜索可为帖子构建 Semantic ID，再用约束解码保证输出仍来自本次候选集，从而兼顾生成式建模与线上安全。

Fidelity Before Structure: Verbatim Chunks Beat Lossy Artifact Extraction in Long-Conversation LLM Memory

论文在固定检索—重排—推理流水线中只替换记忆表示，比较 LLM 抽取的结构化事实与原文分块。原文块在 LoCoMo 上得分 43.9% 对 28.0%，在 LongMemEval-S 上为 67.4% 对 45.4%，分别领先 15.9 和 22.0 个点，六组混杂控制仍复现该结论。

INSIGHT对话记忆的首要目标是保真，过早抽取事实会丢掉语气、条件与时间关系，后加一跳语义图也补不回来。面向会话式搜索或推荐，应先保留可追溯原文块，再把结构化摘要作为辅助索引，并监控抽取后仍保留的源文本比例。

Expressiveness Limits of Autoregressive Semantic ID Generation in Generative Recommendation

SnapUCSD

论文从理论和实验上说明，自回归 Semantic ID 会形成固定解码树，使树上相近物品对任意用户都得到相似概率，连部分协同过滤模式也无法表达。Latte 在每个 Semantic ID 前插入潜变量，把单树改成多棵条件树，平均带来 3.45% 的 NDCG@10 相对提升。

INSIGHTSemantic ID 的树结构不仅影响检索效率，也会给用户偏好施加隐性概率耦合；仅扩大模型可能无法突破这一表达上限。团队应把树距离与用户区分度加入诊断，并尝试多路径或潜变量条件解码，而不是只调整码本大小。

Yupeng Hou, Haven Kim, Clark Mingxuan Ju, Eduardo Escoto, Neil Shah, Julian McAuley

Implicit Reasoning for Large Language Model-based Generative Recommendation

Snap📖 深度解读 · 7 分钟 →

论文拆解显式推理式生成推荐，发现世界知识表述削弱、Semantic ID 与自然语言 embedding 错位、推理文本质量敏感是三类主要问题。PauseRec 改用隐空间额外计算，较显式 CoT 最高提升 6.22%，训练 GPU 小时最多减少 65%，推理速度最高提升 71.3%。

INSIGHT推荐任务需要的推理未必适合输出成长思维链；隐式停顿既避免昂贵的轨迹采集，也降低不稳定文本监督的影响。若社区搜推已用 LLM 生成物品 ID，可优先在隐藏状态增加少量计算步，并以端到端 nDCG、延迟和 GPU 成本验证收益。

Yinhan He, Liam Collins, Bhuvesh Kumar, Jundong Li, Neil Shah, Donald Loveland

ACL 2026美团论文精选：从能力评测到推理优化，构建生成新范式

Meituan

美团技术团队解读 6 篇 ACL 2026 工作，其中 FLR 将单一隐向量拆成多个语义解耦偏好因子，并用轻量多因子注意力完成隐式推荐推理。配套 FLR-GRPO 以噪声注入和组内对比稳定对齐，在 Amazon 数据集平均超过 LatentR3 3.2%，Games 子集提升 10.26%。

INSIGHT单一用户向量会把多兴趣压成一条轴，分因子隐式推理更适合社区用户同时存在的主题、时效和内容形态偏好。落地时可先控制因子数量与注意力开销，再用组内对比约束因子解耦，并重点观察长尾主题与跨兴趣会话的增益。
