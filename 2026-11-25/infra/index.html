Fast 4-bit KV-Cache Decoding on Hopper GPUs: Why Existing Kernels Are Slow and How to Fix Them

把 KV cache 压到四比特，读写量大约只有 FP8 的一半，但 Hopper 没有 FP4 硬件，现有内核还得靠软件解码。在 H200 上，vLLM 的 NVFP4 路径最多比 FP8 慢 1.7 倍，带宽利用率也很低。新的解码内核让取数和计算重叠，并在写入时排好布局，使解码结果能从寄存器进入张量核心。接入 vLLM 后，在中等规模的 Llama 3.1 上，中等批量每步解码可比 FlashInfer 的 FP8 路径快 1.12 到 1.64 倍，同一块缓存也能多放下不少 token。在五个中等规模模型上，反复测试与 BF16 KV 没有显著精度差异。

Jian Zhang

Design Once, Deploy at Scale: Building a Template-Driven ML Ecosystem

Meta

大型排序和召回舰队里，每个模型都单独试新方法，工程时间会堆在重复劳动上。Meta 用少量覆盖主要排序和召回模式的模板，把成熟改动一次设计后批量套到不同规模的模型上。过去两年，单模型工程时间因此减少了 92%，离线质量在不增加在线容量的前提下平均提高 0.63%，累计线上收益 0.86%。模板也把可复用的改进留给后续模型，而不是让每个模型从零开始。

Zarc: Exact Nearest Neighbors over a Billion Vectors in Seconds

University of Washington

精确最近邻往往要么扫完整库，要么退回近似结果；已有的半精度证明又能跳过大部分向量，却通常要求整库都放在一块 GPU 上。新系统只把短证明行放在 GPU 内存，其余完整向量按需从主机内存取回，因而能在更新下回答欧氏、余弦、内积和带过滤的精确查询。四张 H100 上，它在 1.1 秒内完成十亿向量上的一万次精确查询，穷举则要五分钟。在多个开源大模型上，取精确 top-10 注意力键比穷举快 2.2 到 13.1 倍。

Dongfang Zhao

Exact on Paper: Which LLM Serving Shortcuts Flip Graded Answers, Measured Against the Noise of Reordering the Same Requests

服务端常在确认基准准确率不变后打开前缀缓存、分块预填充或推测解码，因为文档把它们写成精确特性。准确率是汇总指标，特性仍可能改写哪些请求答对。作者用同一个中小指令模型，在约三千条请求上比较九种单特性配置。默认内核下，七个所谓精确特性会改写 1.47% 到 1.78% 请求的对错，都不超过把同样请求换个顺序带来的 1.72% 底线。FP8 KV cache 则会改写 3.36%。换上批不变内核后，这七个特性能逐字复现对照，FP8 KV 仍会改写结果。

Sharven Rane

IndexerStage: Staging Indexer-K across Memory Tiers for Sparse-Attention LLM Serving

长上下文稀疏注意力把注意力数据卸到别处后，用来选 token 的 Indexer-K 仍可能把 GPU 内存撑满。新运行时把已完成页暂存到共享缓冲区，本层新条目先留在本地，并在扩批前检查存储和传输预算，同时保留原来的打分、top-k 和注意力内核。在十六张模型服务 GPU 和十六张后备 H800 上，相对主机内存版 HiSparse，批量可增加 12.28% 到 23.08%。解码吞吐达到 1.08 到 1.14 倍。混长动态服务里，平均在生成批量和服务吞吐也一并提高。

Grammar-as-a-Draft: More Tokens per Speculative Decoding Step on Grammar-Constrained Structured Outputs

结构化输出时，推测解码的起草模型看不见语法约束，会反复提出不合法的键名、分隔符和缩进。新方法把语法当成第二个起草器，在校验前把强制 token 和起草提案并成一行，语法已确定的位置不必再算 logits，也不用在关键路径上加新内核。在 TPU 上的 JSON 角色设定基准里，MTP 搭配较小的 Qwen3.5 时，平均接受长度从 2.06 提到 5.43。单请求时解码快 2.66 到 2.81 倍，大批量时加速会收窄。

Look Back, Draft Ahead: Corrective Prefix Attention for Parallel Speculative Decoding

Huawei

并行推测解码会一次提出整块 token，前面一个不一致，后面整段都可能被目标模型否掉。新方法让块内候选项能看到更早的选择，并把交互预计算成查表，推理时不必反复跑网络，训练时再用自回归损失在干净前缀上监督共享主干。在八个数学、代码和对话基准上，用中小规模的 Qwen3 作目标时，每轮确认接受的 token 比 DSpark 多 13% 到 15%。贪心解码的平均加速达到 3.35 倍和 3.37 倍。更多接受并不自动等于更快，还要看这一轮的计算开销。

Mohammad Mahdi Moradi, Ali Pourranjbar, Zongzuo Wang, Mingming Zhu, Ben Feng, Boxing Chen

Training Transformers for KV-Cache Compressibility

已录用 NeurIPS 2026

事后压缩 KV cache 的效果，取决于模型内部表示本身好不好压，而不是只取决于这段上下文。理论结果表明，几乎任意的序列到向量函数，都可以既有很好压的 Transformer 实现，也有几乎压不动的实现。新的继续预训练会在训练时遮蔽部分 KV 槽位，逼模型用更少槽位，从而学到更适合事后压缩的表示。用在开源基座模型上之后，同样预算下后缀困惑度保持最多可提高到 3.21 倍，检索准确率最多提高 68%，长上下文问答最多提高 39%。

PatchKV: Weight Space Compensation of KV Cache

已录用 NeurIPS 2026

长上下文推理时，KV cache 会随前缀线性变长，现有压缩到很狠的预算时效果会明显变差。新方法不必额外训练：在装入上下文时一次性算出一块权重补丁，把被压缩掉的部分上下文补进模型权重，随后同一上下文上的多次查询前向图和单次开销都不变。它在 SCBench、SQuAD、NIAH 和 GSM8K 以及三种模型架构上，都能提升现成的缓存压缩方法，尤其是在缓存预算降到两成以下时，能补回被压掉的相当一部分准确率。

Chanryeol Lee, Chanhyuk Lee, Yeonwoo Choi, Donggyun Kim, Seunghoon Hong
