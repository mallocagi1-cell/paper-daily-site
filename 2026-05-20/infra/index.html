OSCAR: Offline Spectral Covariance-Aware Rotation for 2-bit KV Cache Quantization

针对长上下文 LLM serving 中 INT2 KV cache 量化既要精度又要可部署的难题，论文提出 OSCAR。它在离线阶段估计「注意力感知」的协方差结构，据此推导出固定的旋转矩阵和裁剪阈值，使 KV 量化方向与注意力实际消费的协方差结构对齐——而非沿用 Hadamard 等与下游注意力无关的通用旋转（后者在 INT2 下会明显掉点）。论文不仅给出理论依据，还实现了一套完整可部署系统：自定义 INT2 attention kernel，兼容 paged KV-cache 与 fused kernel pipeline，可直接接入 SGLang 等现代 serving 框架。

Post-Trained MoE Can Skip Half Experts via Self-Distillation

MoE 通过稀疏专家激活提升 LLM 效率，动态 MoE 进一步按输入调整激活专家数，但现有动态 MoE 大多需要从头预训练或针对任务适配，已训练好的静态 MoE 如何低成本转成动态形态一直缺乏方案。论文提出 ZEDA (Zero-Expert Self-Distillation Adaptation)：在每个 MoE 层注入「无参数的零输出专家」，再用两阶段自蒸馏（以原始 MoE 作教师）适配增广后的模型，使简单 token 在 serving 时可跳过不必要的专家。论文报告可跳过约一半专家以直接削减推理成本。

INSIGHT「零输出专家 + 自蒸馏」把静态 MoE 转动态的成本压到很低，不必重训：注入参数为零的占位专家让路由可以学会「对简单 token 少激活」，两阶段自蒸馏稳定这一架构改造。对自建 MoE 推理栈的团队，这是一条不改主模型权重、仅做轻量适配就能省一半专家算力的路径，适合搜索场景中 query 难度差异大、长尾简单 query 占多数的流量结构。可关注其路由稳定性与精度损失的权衡曲线。

SNLP: Layer-Parallel Inference via Structured Newton Corrections

自回归 LLM 顺序执行 Transformer 各层，形成一条 tensor/pipeline 并行都消不掉的延迟瓶颈。论文把跨层 hidden-state 轨迹视为一个非线性残差方程的解，用并行 Newton 式更新去求解，从而放松层间依赖。由于精确 Newton 修正需要昂贵的 Jacobian-vector product、朴素不动点迭代在已训练 Transformer 上又不稳定，论文提出 SNLP (Structured Newton Layer Parallelism)：用架构诱导的廉价替代动力学代替精确层 Jacobian——残差 Transformer 下退化为类前缀和的 Identity Newton (IDN)，mHC 类架构下为 HC Newton (HCN)。

INSIGHT把「层间顺序依赖」重新表述为「非线性残差方程并行求解」是少见的视角，给出了绕开层深度延迟的新自由度。对在线 LLM 推理延迟敏感的搜索应用（如生成式 query 改写、实时摘要），这类层并行思路若成熟可在不增加显存的前提下降低尾延迟。当前更偏研究阶段、需训练与推理框架配合，建议作为前沿跟踪而非短期落地：重点关注 IDN 的前缀和近似在深层网络上的精度衰减边界。

Symmetry-Compatible Principle for Optimizer Design: Embeddings, LM Heads, SwiGLU MLPs, and MoE Routers

现代网络结构天然具有对称性与等变性，但 Adam 等主流优化器逐坐标更新，无法尊重参数空间的等变结构，论文称之为长期存在的几何错位。论文提出「对称兼容」优化器设计原则：梯度更新规则应在作用于对应权重块的对称群下保持等变。基于此先统一解释了一般矩阵层的双正交等变更新（涵盖 stochastic spectral descent、Muon、Scion、polar gradient），再从正交群推广到置换与共享平移对称，针对 embedding、LM head、SwiGLU MLP、MoE router 推导出对称兼容的更新形式。

INSIGHT用「更新规则需在权重块对称群下等变」这一原则统一了 Muon/Scion 等一系列谱方法，并把它扩展到 embedding、router 这类置换/平移对称的特殊层。对训练大规模 embedding/排序模型的团队有直接参考价值：embedding 表与 MoE router 正是搜索/推荐里参数量最大、对优化器最敏感的部分，按对称性定制更新有望改善收敛与稳定性。属于训练基建层面的方法升级，需在自有训练框架做实证验证后再决定是否替换默认优化器。

LongLive-2.0: An NVFP4 Parallel Infrastructure for Long Video Generation

LongLive-2.0 是一套贯穿长视频生成全流程（训练 + 推理）的 NVFP4 并行基础设施，针对速度与显存瓶颈。训练侧提出序列并行自回归训练 Balanced SP：在每个 rank 上配对 clean-history 与 noisy-target 时间块，使 teacher-forcing 掩码与 SP 执行协同，并配合 SP 感知的分块 VAE 编码。结合 NVFP4 精度，降低 GPU 显存并加速 GEMM（视频越长，GEMM 占比越高，收益越大），且作者指出高质量基建与数据可让训练 pipeline 显著简化，无需 Self-Forcing 系列的 ODE 初始化与分布匹配蒸馏。

INSIGHTNVFP4 + Balanced SP 的「精度与序列并行协同设计」是值得借鉴的工程范式：4-bit 浮点不是孤立的量化技巧，而是与并行布局、teacher-forcing 掩码一起做协同设计才能既省显存又不掉质量。虽然落点是视频生成、与 UGC 文本搜索业务关联弱，但其 sequence-parallel 自回归训练与 FP4 GEMM 加速思路对长序列推荐/生成式检索模型的训练基建有迁移价值，可作为 FP4 训练落地的参考实现。

Lance: Unified Multimodal Modeling by Multi-Task Synergy

Lance 是一个轻量原生统一模型，支持图像与视频的多模态理解、生成与编辑。它不靠堆模型容量或文图主导设计，而是探索通过协同多任务训练实现统一多模态建模，基于两条原则：统一上下文建模与解耦能力通路。具体上 Lance 从零训练，在共享的交错多模态序列上采用双流 MoE 架构，既做联合上下文学习又解耦理解与生成的通路，并引入模态感知旋转位置编码 (modality-aware RoPE) 缓解异构视觉 token 间干扰，训练上采用分阶段多任务范式。

INSIGHT「统一上下文建模 + 解耦能力通路」配合双流 MoE 与模态感知 RoPE，是处理异构 token 干扰的可借鉴架构设计——这一点对多模态社区内容（图文帖子）的统一表征/检索有潜在迁移价值。当前业务关联偏弱（落点是图像/视频生成与编辑），建议作为统一多模态架构的参考样本跟踪，重点看其双流 MoE 在「理解」侧任务上的精度是否被「生成」侧训练拖累。

A Reference Model and Patterns for Production Event Data Enrichment

组织在跨系统执行流程时产生大量异构数据，整合后可支撑流程性能监控与分析，但相关信息通常在数据预处理/工程阶段以临时、耗时、人工密集的方式抽取。论文提出一个参考模型与一组模式 (patterns) 来规范化「生产事件数据 enrichment」：参考模型给出存储与抽取生产事件数据的标准方式，patterns 描述常见信息抽取任务及其实现方法，使数据工程阶段从 ad-hoc 走向可复用的标准流程。

INSIGHT把事件数据 enrichment 沉淀成「参考模型 + 复用模式」对搜索/推荐的日志与特征管线有直接借鉴意义：曝光、点击、行为序列等事件数据的清洗与拼接往往正是临时脚本堆叠、最难维护的一环，用统一参考模型描述存储与抽取契约可显著降低特征管线的维护成本。本身技术新颖度与时效性一般（replace 版本），价值在于工程实践的标准化方法论，可作为特征/数据平台规范化的参照。

Position: LLM Serving Needs Mathematical Optimization and Algorithmic Foundations, Not Just Heuristics

这篇立场论文主张 LLM 推理 serving 已超出通用启发式的能力边界，需要数学优化与算法基础支撑。尽管 vLLM、SGLang 等系统快速演进，其算法内核仍沿用经典分布式计算：请求路由用 join-shortest-queue 或 round-robin，调度默认 FIFO，KV cache 淘汰用 LRU。这些通用策略忽视了 LLM 推理的独特结构——动态增长的 KV cache 显存、prefill/decode 阶段不对称、输出长度未知、连续 batching 约束。作者主张应建立刻画这些特性的数学模型，设计在多样负载下有可证明性能保证的算法，并指出运筹学与 ML 系统交叉的新工作已能在提供理论保证的同时匹配或超过启发式。

INSIGHT核心提醒是：当前 serving 框架的瓶颈不在 kernel 而在调度/路由/淘汰的算法内核仍是 FIFO+LRU+JSQ 这类与 LLM 负载结构无关的通用策略。对自建或调优 LLM serving 的搜索团队，值得据此审视自家网关：按 prefill/decode 不对称、输出长度未知做调度与 KV 淘汰的定制化，可能比继续堆 kernel 优化收益更大。本身是立场论文、无方法与实验，价值在于研究/优化方向的指引而非可直接落地的方案。

Zijie Zhou
