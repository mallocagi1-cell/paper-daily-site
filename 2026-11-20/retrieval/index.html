Can Programs Replace LLM Judges? Executable Program Judges for Scalable and Efficient Relevance Labeling

用大模型给检索结果打相关性标签，每篇文档都要调用一次前沿模型，既贵又难解释、也难复现。一个办法是让大模型按主题写出一段可读的程序，之后用程序给整个结果池打分。程序只依赖词面匹配、常规自然语言处理库和结果池统计；若有少量人工标签，还可以据此再把规则调一遍。在七个 TREC 集合上，无标签版本与 NIST 评估员的一致程度，达到 Claude Sonnet 5.5 裁判在连续几届深度学习检索任务上的水平。用这些标签给官方参赛系统排序，Kendall 的 τ 在 0.87 到 0.94 之间，写程序只需一次性花费，之后给再多文档打分都不必再调接口。对要给深层结果池标注的人来说，可检查、可复现的程序，有时可以代替逐篇调用大模型裁判。

Doubling Query Embedding Throughput with Dynamic Batching in Vespa Cloud

Vespa

查询量上去以后，每条查询都要过一遍 embedding 模型，单独推理会让 GPU 效率上不去，高峰时吞吐和延迟一起恶化。开源系统和此前的云服务都把每条 embedding 请求当成一次独立推理，并发一高，启动开销和显存占用就会叠上去。云上的新推理运行时在容器节点上做动态批处理，把同时到达的请求合成一批，并限制并行调用的数量。在 NVIDIA L4 上，EmbeddingGemma 2 的查询吞吐从大约每秒 300 条升到大约每秒 600 条，中位延迟仍是 15 毫秒。动态批处理让同一台 GPU 在中位延迟基本不变时吃下大约两倍的查询负载，因此同样的查询速率可以少用一些 GPU 节点。这项能力已经在 Vespa Cloud 的容器节点上可用。

Evidence-Based Credit Assignment for Search-Augmented Language Models

Tencent

搜索增强的语言模型常用最终答案对整条轨迹做强化学习，但只要答案错了，路径里有用的检索和没用的检索会拿到同一份信用；一组采样全部失败时，优势函数还会塌成零。一种基于证据的信用分配只在训练时加一项辅助信号：把问题和迄今去重后的文档单独拿给当前策略的冻结副本，看它们能把参考答案的似然提高多少。在七个搜索问答基准上，保留整段证据增益的写法相对只看最终对错的 GRPO，把严格宏平均精确匹配在三十亿参数模型上提高 1.03 个百分点，在七十亿参数模型上提高 4.80 个百分点。在全部失败的采样组里，它也能在绝大多数组中恢复出非零的学习信号。答案错了，并不等于这次检索没有提供有用证据。

Know Before You Fetch: When Does Confidence-Based Retrieval-Budget Allocation Pay Off?

按闭卷置信度决定要不要检索、检索多深，通常被拿去和每条查询都取很多段落比较，这把更便宜的固定深度或随机混合排除在外了。这篇工作在相同的平均段落预算下，把它和最好的简单策略比较，策略只能分配零段、一段或五段。在全部七种设定里，当预算只有每条查询半段时，自适应策略的准确率比最好的简单策略高出 0.010 到 0.075。预算到一段以上时，收益几乎只出现在维基百科检索上，因为段落会改写模型已经知道的答案。置信度擅长判断要不要给第一段，却几乎不能判断该读一段还是五段。把探测延迟也算进去后，收益往往只在大量跳过检索时还站得住。按置信度分配预算，主要值当段落很少，或检索可能毁掉已知答案。

MIRAGE: A Framework for Multi-hop Reasoning under Dynamic Knowledge Injection

多跳问答一旦要同时消化互相冲突的知识更新和全新事实，错误常常出在每一步信错了来源：参数记忆过时了还死守，遇到全新事实又答不出来。一份新基准专门覆盖冲突知识和增量知识；一套无需训练的框架在每一步用模型对自己答案为真的概率来选择知识路径，再用轻量模板修正残留的结构偏差。在该基准上，GPT-4o 面对单条编辑时，准确率从对照方法的 52.15% 提高到 73.65%。在另一份已编辑的多跳集合上，该方法还能恢复到未编辑参考准确率的约 96%。对要在知识不断注入时做多跳推理的人来说，先判断这一跳该信哪一路知识，往往比只把新文档检索进来更关键。

VIBRA: Backward-Compatible Cross-Modal Retrieval with Consensus Barycenters

升级跨模态检索模型时，如果新编码器不能直接查旧模型已经编好的图库，就得把海量条目重新编码一遍。现有兼容方法要么贴近旧模型的精度，要么每条查询同时跑新旧两个编码器。一种新方法在旧图库上对齐相关性，并用多个视角的重心在旧空间里形成一条查询来纠正单模型错误，再让新编码器继承这种共识，于是部署时不在场的模型仍能影响每条查询。在五个基准、六种主干之间的全部升级设定上，它都是最好的兼容方法，Recall@1 最多比最强基线高 5.6 个百分点，比旧模型高 18.0 个百分点，却只给新编码器增加不到 1 毫秒延迟。兼容升级不必在精度和每个查询跑两个编码器之间二选一。

Shubing Yang, Xutong Liu, Dongfang Zhao

Frustratingly Simple Retrieval Improves Challenging, Reasoning-Intensive Benchmarks

人们常觉得，最小的检索增强生成对需要推理的基准帮助不大，甚至会帮倒忙。缺的往往不是更复杂的智能体流程，而是一个用得上的、覆盖面接近预训练语料的网络规模存储。一套紧凑的高质量存储先滤掉大部分网页，再用内存里的近似近邻检索加磁盘上的精确检索，在单机上做到亚秒延迟。接上一条最小检索增强流水线后，各个规模的模型在所有测试基准上都有稳定提升，其中在 MMLU Pro 上相对提高 33%，在 MATH 上相对提高 19%。没有任何单一数据源单独够用。这个自建存储在全部基准上达到或超过 Google 搜索，也比得上近来更复杂的智能体检索系统，同时保持简单、可复现和自包含。

LazyAttention: Efficient Retrieval-Augmented Generation with Deferred Positional Encoding

KV 缓存能加速长上下文推理，但常规做法把位置信息写进缓存，同一段文档换个位置就很难再直接复用。检索增强生成里，热门文档会在不同请求、不同排列中反复出现，却因为位置不同而无法共享缓存。已有办法要么只复用前缀，要么为了改位置编码再把缓存物化一遍，代价很高。一套推迟位置编码的注意力机制在核里当场调整位置，一份物理上的 KV 就可以在任意位置服务多条逻辑请求。在文档访问偏斜的检索增强场景里，相对目前最强的 Block-Attention，它把 TTFT 缩短 1.37 倍，并把推理吞吐提高到 1.40 倍，输出质量仍相当。位置不必先写进缓存，检索到的文档才更容易在请求之间共享。

Haocheng Xia, Mihir Pamnani, Hanxi Fang, Supawit Chockchowwat, Yongjoo Park

Rankify: A Comprehensive Python Toolkit for Retrieval, Re-Ranking, and Retrieval-Augmented Generation

搭建检索增强生成系统时，检索、重排和生成常常要拼多套工具，数据格式、评测和部署流程对不上，系统比较也很难做。一套开源 Python 工具把这三段收进同一套模块化框架，提供带预检索文档和现成索引的数十个基准、十多种检索器和二十多种重排模型，并支持多种生成策略和推理后端。作者用它跑了两百多种配置，覆盖问答以及 BEIR、TREC 基准。在这些配置里，加上重排后，下游精确匹配会提高 5 到 15 个百分点，而且不取决于用的是哪一种检索器或生成器；上下文精确度最多还能再提高 8.5 分。对要比较检索栈的人来说，统一的接口本身就能把重排到底有没有用测量清楚。

Automated Formalization via Conceptual Retrieval-Augmented LLMs

把自然语言数学定理自动写成形式化代码时，模型常会发明库里不存在的谓词、用错符号，或把同一概念在不同领域里的定义搞混。一套概念驱动的检索增强框架从 Lean 的标准数学库自动构建概念到形式定义的知识库，收录两万六千多条形式定义和一千多个核心概念。它再用带领域与应用信息的查询扩展和双通道混合检索，把核心概念的形式定义取回来，给生成提供上下文，并可以直接接到现有的大模型自动形式化流程上。在常用基准和新的高难度集合上，翻译准确率相对提升最高达到 62.1%，平均为 29.9%。先把概念在形式库里的正确定义找准，才能减少幻觉和跨领域的定义混淆。
