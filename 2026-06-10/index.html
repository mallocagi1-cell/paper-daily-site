OneFeed: A Unified Generative Framework for Feed Content Enhancement and Query Generation

feed 推荐靠浏览行为捕捉隐式兴趣、搜索靠显式 query 匹配意图，二者通常各用一套架构，用户理解被割裂。OneFeed 用一个共享行为编码器编码异构用户行为序列，再挂两个生成头：Feed Semantic ID Generator 自回归生成推荐召回用的层级 Semantic ID，Intent Query Generator 生成搜索候选扩展用的自然语言 query；并用 SID-Query 对比对齐目标(in-batch 负采样)把 Semantic ID 与 query 表示拉到同一空间，加候选一致性损失把 query 质量与 feed 增强挂钩。关键提醒：论文本质是方法论提案，公开数据集(KuaiRec/Amazon/MovieLens-1M)的表格是“预期值”(基线标 †、OneFeed 行用 >> 只示方向)，唯一真正跑通的是合成数据最小原型(Recall@20 0.4389 vs feed-only 0.3167)，全程无真实训练与线上 A/B。

KEY INSIGHT · 对业务意味着什么把“推荐生成内容 Semantic ID”和“搜索生成 query”塞进同一个生成模型、再用对比对齐共享语义空间，正对社区搜索这种 feed 与搜索强耦合的场景：feed 行为可反哺 query 生成、生成的 query 又能扩展 feed 召回，对冷启动/长尾尤其友好。最值得借鉴的是 Semantic ID 与自然语言 query 的对齐设计，以及用伪 query(标题/类目/标签/高频评论词)在缺真实搜索日志时构造监督。但要清醒：本文没有真实实验结果，方法可行性仅靠合成原型证明，价值在“范式与 loss 设计”而非可复现的指标，落地需自建 Semantic ID 体系并自行验证。
