HyperTool: Beyond Step-Wise Tool Calls for Tool-Augmented Agents

工具增强型 LLM agent 普遍用 step-wise 原子工具调用，每次调用、观测、取值都暴露在主推理轨迹里，造成执行粒度错配：本可确定性执行的工具子流程被展开成大量模型可见的低层决策，挤占上下文。HyperTool 提出统一的可执行 MCP 风格工具接口——模型用一段代码块按工具原始 schema 调用、处理返回值、在本地传递中间结果，把确定性子流程折叠进一次外层调用。在 MCP-Universe 上 Qwen3-32B 平均准确率从 15.69% 提升到 35.29%，Qwen3-8B 从 9.93% 提升到 33.33%，超过 GPT-OSS 与 Kimi-k2.5。

KEY INSIGHT · 对业务意味着什么关键不是调更多工具，而是改变模型可见的工具执行单元：把确定性的工具编排沉到代码执行层、只把高层意图留在推理轨迹，既省 token 又减少模型管理低层 dataflow 的出错机会。对搜索/RAG agent 有直接借鉴——多跳检索、过滤、重排这类固定子流程可封装成一次 HyperTool 调用，主 agent 只决策检索什么。训练数据由跨工具组合任务合成并在真实 MCP 环境验证，落地路径清晰。

SENTINEL: Failure-Driven Reinforcement Learning for Training Tool-Using Language Model Agents

AmazonNNortheastern

用 RL 训练多轮工具调用 agent 时，训练任务分布在训练前就固定，会与策略不断演化的能力错配，大量 rollout 浪费在无信息量的任务上。SENTINEL 是 failure-driven RL 框架，把 Solver 的 rollout 失败转化为针对性训练任务，采用 Controller-Proposer-Solver 流程：Controller 分析失败轨迹归纳反复出现的错误模式，Proposer 生成专门压这些弱点的可执行任务，Solver 在这些任务上训练。在 Tau2-Bench Retail 用 Qwen3-4B-Thinking-2507，Pass@1 从 66.4 提升到 74.9，并在 Pass@k 各档优于在通用合成任务上做 RL。

INSIGHT模型自身的失败是高质量、可扩展的训练信号来源——与其预先固定任务集，不如让课程随策略弱点动态生成。Controller-Proposer-Solver 的诊断-出题-训练循环可迁移到搜索 agent 的 RL：从线上失败 query 与检索轨迹中归纳错误模式，自动生成针对性训练样本，比静态数据集更贴合当前模型瓶颈，也更省 rollout。

Effective Reinforcement Learning for Agentic Search by Recycling Zero-Variance Queries During Training

CMU

GRPO 类算法训练 LLM 搜索 agent 时，只有 rollout 组同时含成功和失败的 query 才贡献梯度；全对(太易)和全错(太难)的零方差组白白消耗 rollout。作者发现 query 会随策略演化在零方差与有信号之间反复翻转，提出 query recycling：把零方差组放回可变池等待后续重采样，让有效训练分布随策略共同演化。一个 1.7B 模型在合成数据上训练，7 个多跳 QA 基准平均 Pass@1 达到 66.0，追平甚至超过用基准衍生监督训练的 7B 系统；训练后期回收 query 约占有效 batch 的 3/4。

INSIGHT零方差不是 query 的静态属性而是随策略变化的动态状态，丢弃或预过滤太易太难样本其实扔掉了后期会重新变有用的训练信号。对训练搜索 agent 的启示：维护动态难度池、按当前策略能力重采样，比固定课程更省算力，且 1.7B 小模型即可逼近 7B，对资源受限团队友好。

SearchSwarm: Towards Delegation Intelligence in Agentic LLMs for Long-Horizon Deep Research

AAnt Group

长程任务的上下文需求可无界增长，但模型上下文窗口有限。SearchSwarm 针对 deep research 提出委派智能：主 agent 分解任务、把子任务派给子 agent，子 agent 执行后只回传摘要结果，节省主 agent 的上下文预算。难点在何时委派、委派什么、如何整合返回结果——这类数据在自然文本里稀缺。作者设计 harness 引导模型做高质量任务分解与委派、并约束子 agent 规范回传；harness 引导的轨迹天然编码正确委派决策，用作 SFT 数据把委派能力内化进权重。SearchSwarm-30B-A3B 在 BrowseComp 达 68.1、BrowseComp-ZH 达 73.3，为同规模最佳，并开源 harness、权重与数据。

INSIGHT多 agent deep research 的瓶颈不在能不能调子 agent，而在主 agent 的委派智能——靠 harness 把好的分解/委派轨迹蒸馏成 SFT 数据，是一条不依赖 RL 即可获得委派能力的可行路径。对构建中文深度搜索/研究产品尤其有参考价值（BrowseComp-ZH 73.3），且开源了完整训练栈，可直接复现。

DuMate-DeepResearch: An Auditable Multi-Agent System with Recursive Search and Rubric-Grounded Reasoning

Baidu

Deep Research 需要系统迭代地界定问题、获取证据、核验来源并合成长报告，但现有系统受限于欠定范围下的长程规划、单 agent 调度瓶颈、长文合成幻觉、过程不可审计四个问题。DuMate-DeepResearch 是基于百度千帆 Agent Foundry 的多 agent 框架，把负责理解/规划/调度的 Agent Core 与可扩展工具生态解耦，使每个决策和工具调用可追溯。它引入三机制：图式动态规划(由粗到细，通过反思/重规划/回溯/并行分支持续修正)、递归两层执行(把复杂子任务交给内层 Search Agent 自跑规划循环以隔离噪声检索)、基于 rubric 的测试时优化(动态生成任务专属质量标准作为证据合成与自适应停止依据)。在两个基准取得 SOTA：DeepResearch Bench 58.03%、DeepResearch Bench II 61.95%，信息召回与分析项排名第一。

INSIGHT工业级 deep research 的可落地要点是可审计与递归隔离——把噪声检索下沉到内层 Search Agent、主 agent 只看摘要，能稳定长程执行；rubric 测试时优化提供了自适应停止这一实用机制，避免无谓过度检索。对搭建企业级研究/搜索助手的团队，这套解耦+全程可追溯架构有直接参考价值。

Lingyong Yan, Can Xu, Yukun Zhao, Shuaiqiang Wang, Jianmin Wu, Dawei Yin, et al.

SlimSearcher: Training Efficiency-Aware Web Agents via Adaptive Reward Gating

AAnt Group

Deep research agent 在准确率导向训练下普遍采用蛮力策略——盲目依赖工具、生成冗长轨迹，造成大量无谓工具调用和 token 消耗。SlimSearcher 在 SFT 与 RL 两阶段推动准确率-成本的帕累托前沿：SFT 阶段用 Pareto-efficient 过滤蒸馏既成功又经济的轨迹；RL 阶段引入 Adaptive Reward Gating，在采样 cohort 内评估相对的工具/token 效率，并与严格的正确性 gate 级联，从而避开绝对惩罚带来的过短偏置并抑制 reward hacking。在 GAIA、BrowseComp、XBenchDeepSearch 等长程基准上，平均工具调用轮数减少 17%-58%，同时维持或提升准确率。

INSIGHT搜索 agent 的成本不是只能靠砍长度硬压——用组内相对效率奖励而非绝对惩罚，能在不牺牲准确率前提下减少 17%-58% 的工具调用。对线上 deep search 服务，这意味着同等效果下推理成本和延迟显著下降；Pareto 过滤 + 相对奖励 gating 的设计可直接用于约束自家搜索 agent 的检索轮数。

Zequn Xie, Junjie Wang, Dan Yang, Jie Feng, Yue Shen, Jian Wang, Jinjie Gu

LoHoSearch: Benchmarking Long-Horizon Search Agents Beyond the Human Difficulty Ceiling

Meituan

BrowseComp 等搜索 agent 基准在过去一年迅速饱和(最强模型超 90%)，因为人工出题者缺乏对实体统计的全局视角，难以系统性扩大搜索空间与结构复杂度，形成难度天花板。LoHoSearch 含 544 道人工验证、覆盖 11 个领域的题目，由一条自动化流水线在覆盖 700 万+ 维基百科实体的知识图谱上构建——选取搜索空间大的关系、组装成结构复杂且 KG 可验证唯一答案的问题。评测显示最强模型仅 34.74% 准确率，现有上下文管理策略收益(最高 +6.8%)远小于在旧基准上的提升。

INSIGHT用知识图谱自动合成超越人类出题上限的长程搜索题，是解决基准饱和的可扩展思路。34.74% 的低分说明长程推理与上下文管理仍是搜索 agent 的真实短板，现有 context 管理技巧在更难题上几乎失效。对自建搜索 agent 评测体系的团队，KG 驱动的难度可控合成方法值得借鉴，可避免被刷榜假象误导。

Jiarui Zhao, Rongzhi Zhang, Lingchuan Liu, Hao Yang, Xunliang Cai, Xi Su

EvoBrowseComp: Benchmarking Search Agents on Evolving Knowledge

Tencent

静态搜索 agent 基准(如 BrowseComp)易受测试集污染和参数化记忆影响，模型可能靠事实背诵而非真实检索拿高分。EvoBrowseComp 是会进化的基准，含 400 道英文 + 400 道中文无污染复杂题，通过实时网络爬取合成，采用三 agent 协作框架：QA 合成 agent 从实时网络检索新知识合成问答对、信息过滤 agent 按可信度与流行度过滤以阻断参数化捷径、高层引导 agent 把问题形式化成推理图以减少逻辑冗余和捷径。全自动合成使其可定期更新，防止数据污染并保持时效。

INSIGHT对抗刷榜靠背诵的根本办法是让基准持续进化——用实时网络 + 过滤 agent 主动剔除模型可凭记忆走的捷径。这套合成-过滤-图式约束的三 agent 流水线可复用于构建任意领域的抗污染评测集。对搜索/RAG 团队，启示是离线指标要警惕参数化泄漏，评测应优先考查真实检索能力而非记忆。

Yunhan Wang, Jiaan Wang, Lianzhe Huang, Xianfeng Zeng, Fandong Meng

The Illusion of Multi-Agent Advantage

SalesforceNTU

主流观点认为多 agent 系统(MAS)凭上下文隔离、并行处理、分布式决策优于单 agent，但支撑证据多来自孤立推理任务的基准。作者针对自动生成的 MAS 做系统评测，与 Chain-of-Thought + Self-Consistency(CoT-SC)对比：在传统推理数据集和交互式多步工作流(如 BrowseComp-Plus)上，自动 MAS 始终不如 CoT-SC，却贵达 10 倍。为排除任务结构干扰，作者构造带显式任务分解、上下文隔离、并行潜力的诊断合成数据集，结果显示专家手工设计的 MAS 在性能和成本效率上都稳超自动生成架构；对自动 MAS 的解构发现其堆砌的是表面复杂度，并不转化为功能效用。

INSIGHT多 agent 一定更好是个需要警惕的错觉——自动生成的 MAS 常是架构臃肿，10 倍成本换不来真实收益，现有评测因忽视边际算力成本而掩盖了这点。对搜索/推荐工程团队的实践启示：上多 agent 前先与 CoT-SC 等强单 agent 基线做成本-效果对比，任务确实具备可分解可并行结构时再用，且优先专家设计而非全自动编排。

Reward Modeling for Multi-Agent Orchestration

RRutgersSalesforce

LLM 多 agent 系统需要有效编排来协调各专长 agent，但训练编排器受限于监督稀缺和高算力成本。OrchRM(Orchestration Reward Modeling)是自监督框架，利用多 agent 执行的中间产物构造胜负对来训练 Bradley-Terry 奖励模型，直接在编排层操作而非依赖昂贵的子 agent rollout。OrchRM 把训练的 token 效率提升最高 10 倍，同时把 MAS 测试时扩展性能最高提升 8% 准确率，且收益可跨数学推理、网页问答、多跳推理多个领域迁移。

INSIGHT评估编排质量不必每次都把子 agent 跑完——用执行中间产物构造偏好对、在编排层训练奖励模型，能以低成本指导编排器并支撑测试时扩展。对需要协调多检索/工具模块的搜索系统，这提供了一条低成本评估并优化调度策略的思路，10 倍 token 效率对大规模在线编排尤其有意义。
