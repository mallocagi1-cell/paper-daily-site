Beyond Query-Item Matching: Personalized Behavioral Relevance Modeling for E-commerce Search via Rubric-Guided Reinforcement Learning

电商搜索通常先由相关性模型按 query 和商品的文字匹配把候选分成几档，再交给 CTR 模型排序，于是用户明明偏爱的商品，可能因为被分到低档而很少露出。阿里 1688 的这篇工作把一部分个性化挪到相关性这一步：让大模型读用户当天、近期和长期的搜索与购买记录，判断这件商品有没有行为证据支持，有就在相关性分档里提一级。

PCG-RAG: Progressive Compositional Grounding for Retrieval-Augmented Generation in Complex Web Question Answering

📖 深度解读 · 17 分钟 →

复杂网页问答常常要先从几条线索里认出说的是谁，再去查它的某个属性，而常见的错法是只对上一条线索就把名字当成定论。论文里的例子是一座改建成美术馆的伦敦发电厂，系统只凭伦敦和发电厂就认定是 Battersea，接着查到的建筑师其实属于另一座楼。PCG-RAG 把这种只对上部分线索的名字当作搜索线索，用它去补查还没对上的条件，确认之后才让后续问题依赖它。

HiddenPathQA: A Benchmark for Knowledge Graph Question Answering When Questions Hide Their Paths

用户提问时并不知道知识图谱的结构。问「Andrew 可能因为家族史得什么病」，背后其实是父亲、父亲的父亲、病症、遗传病这样一条多跳路径，可问题里一个关系名都没出现。现有 KGQA 测试集的问题几乎把路径写在字面上，所以逐跳挑关系、先规划再检索、按向量相似度召回这三类方法很少被这种情况考过。作者造了上千道这样的题，还把实体名换成无意义的代号，排除模型靠记忆答题：不查图的大模型在代号版上掉了约 40 分，和瞎猜差不多。他们的做法是把实体周围所有候选关系链一次性列给大模型整条比较，中途不剪枝。这种做法比六个基线高 8.8 到 17.9 分。逐跳打分的问题在于中途一步选错就回不来。

Sumin Jo, Edward Choi

SNAPRAG: Cost-Efficient Knowledge Extraction Attack on RAG Systems via Adversarial Perturbations

RAG 系统背后的私有知识库可以被一条条问出来：攻击者在 query 后面附一句指令，让模型原样吐出检索到的文档，再用吐出的内容造下一批 query。已有攻击要么靠攻击者自己再跑一个大模型来写 query，要么要问很多次。SNAPRAG 不用大模型，直接替换已偷到文本里的若干 token，让新 query 在攻击者本地的 embedding 空间里离已见过的内容足够远，从而撞到知识库里还没被检索过的部分。要偷走一半知识库，已有方法需要的 query 数最多是它的 6.77 倍。在同样的提问预算内，它最多能拿走 96.9% 的文档。目标系统加上输入输出审核后，五个目标里它仍在四个上领先。只靠内容审核，拦不住这种一点点往外抽的攻击。

Melih Coşğun, Mehmet Emre Gürsoy, Alptekin Küpçü, Sinem Sav

MMGraph-Agent: Agentic Multimodal RAG via Cache-Inspired Multimodal Knowledge HyperGraphs

已录用 NeurIPS 2026

多模态 RAG 有两笔现实开销，一是建知识图谱要花钱调大模型抽实体，二是多轮检索会把上下文越撑越长。MMGraph-Agent 的建图很朴素：用本地的命名实体识别工具，把每个句子里出现的几个实体连成一条超边，也就是一条可以同时连多个实体的边。图片直接用 CLIP 编码入库，整个过程不调用付费 API，几个 CPU 小时就能建完。检索时它模仿 CPU 的两级缓存，每轮检到的证据先压成摘要放进小缓存，后面几轮优先复用。在 23 个多模态问答数据集上，它平均比每个数据集上第二好的方法高 11.6 个 F1 点，缓存让 token 用量少了 67%。建图这一步换成便宜的规则抽取，效果并没有变差。

DeepResearch RewardBench: Evaluating Reward Models for Deep Research Report

已录用 EMNLP 2026

深度研究 agent 写出的长报告，人工评审太贵，大家只好用奖励模型或大模型来打分，但很少有人系统检验过它们靠不靠谱。作者从多个 agent 收集报告，按原数据集的专家评分细则排出优劣，组成两篇、三篇、四篇一组的比较题。常规奖励模型在这里明显吃力，让大模型直接当裁判效果最好。把几篇放在一起让裁判比，比给每篇单独打分准得多，四篇排序时平均高出 28.4 个点。单独打分时，模型总爱给 80 或 85 分，好坏拉不开。人工分析错例发现，裁判最常见的错，是自己挑了评分细则以外的维度来评，比如更看重引用新不新、表格多不多。评报告难在裁判看的维度和细则对不上。

Dhara: Evidence-Oriented Retrieval for Indian Knowledge Systems

在印度古典典籍里找证据，难点是答案常散在偈颂、译文和注释的不同位置，提问者还经常只记得半句诗。Dhara 在常规混合检索之外加了两条路。一条先为每章、每本书里出现的人物和概念写好说明笔记，查到笔记再顺着链接回到原文段落。另一条专门把问题里的残句抽出来做模糊匹配。残句匹配让偈颂类问题的 nDCG@10 提高约 20 个百分点。单向量检索和多向量的 ColBERTv2 效果相近，平均检索耗时却是 0.108 秒对 0.962 秒，磁盘占用也更小。换更强的 reranker 在每类题上都更好，代价是整体计算时间多出好几倍。多段证据的问题，要看能不能一次找全，不只看第一条准不准。

Cascading Circle Loss: Order-Preserving Contrastive Learning for Graded Legal Retrieval

法律检索不只要找出直接作答的那条条款，相关的定义、责任上限、不可抗力条款也要按相关程度排在后面，而常用的 InfoNCE 只分相关和不相关，不管正例之间的先后。CasCL 把这两件事拆开，InfoNCE 只拿最相关的那条和负例比，负责划开相关与不相关。另一项损失把各档相关的段落按分数串成一条链，链尾接最难的负例，要求每一档都比下一档离 query 近出一段与分差成正比的距离。相邻两档排对了，整条顺序也就对了。在作者公司六种语言的合同条款数据上，它的 NDCG@10 比 Circle Loss 高 2.94 分，去掉 InfoNCE 后 Recall@1 从 41.14 掉到 28.56。两项损失各管一件事，少了哪项都不行。中间几档相关度由三个大模型投票标出，没和人工标注比对过。

Rayane Kimouche, Ahmed Touila

VisProve: Learning Typed Visual Provenance for Scientific Document Question Answering

给科学论文问答加引用，现在大多只框出答案出自哪一块，却不说明这块内容是怎么被用上的，是原样照读、压缩概括，还是要推理才得出结论。作者建了近四千道整篇论文上的问答，每条证据都标了页、章节、区域框和这三种用法之一。VisProve 在模型生成每个 token 时，先预测要看的区域并读取那里的视觉特征，再估计这块证据属于哪种用法，把两者作为一个有上限的小修正叠加回生成过程。和同一底座直接做监督微调相比，章节定位的 F1 从 45.99 升到 53.24，页级定位几乎没变。连区域和用法都要对上的 F1 也只有 5.48。模型大多能找对页，但说清哪块证据怎样支撑答案还差得很远。

Jingxuan Wei, Zhengyang Wang, Zheng Guo, Xiaoming Wu, Fuqiang Wang, Xin Wang, Bihui Yu, Yining Wang 等 9 人

ARMOR: Adaptive Curriculum Meta-Learning for Noise-Robust RAG Reasoning

检索回来的文档总夹着无关甚至误导的内容，RAG 模型要扛住噪声，得同时会三件事，判断自己知不知道、挑出有用的文档、在噪声里推出答案。把三件事放在一起做强化学习，奖励会互相干扰。ARMOR 每轮只练一项，由一个调度器看哪一项最近成绩变化最大，就优先练哪一项。它还改了 GRPO 的优势计算，因为子任务的输出空间很小，同一道题的多次采样往往非常相似，组内比不出高低，于是改成在整个 batch 里一起归一化。作者往五篇检索结果里人为掺噪声，即使 80% 是噪声，它的正确率仍有 69%。按固定顺序依次训练三项，反而会把前面学会的忘掉。训练顺序跟着模型的进度走，比事先排好更稳。

Yan Wang, Yuxin Zhang, Shenyu Zhang, Yongrui Chen, Sheng Bi, Guilin Qi
