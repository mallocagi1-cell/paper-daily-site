Diagnosing and Mitigating Retrieval Bottlenecks in LLM-Based Cold-Start Recommendation

论文检验“LLM 语义理解能解决冷启动推荐”的常见假设，构建五领域基准，把候选召回覆盖率与重排质量拆开评估。结果显示，在 gold item 已注入候选池时，校准后的 LLM reranker 仍不能稳定超过协同过滤和内容基线；在真实召回场景中，单一 retriever 只能把 gold item 放入 200 个候选的 4.6%–22.9% 案例里，且 32%–91% 冷启动目标是没有训练交互的新物品。作者提出 LHF 多召回融合层，在五个领域均超过单一召回器，并在内容丰富领域恢复 17%–61% 的 oracle 覆盖上限。

KEY INSIGHT · 对业务意味着什么对 UGC 社区搜索/推荐最直接的启示是：LLM 不是先验替代召回质量的捷径，冷启动链路首先要把候选池做“可达”。可以把 LHF 这类验证集训练的 hybrid fusion 作为召回侧基线，再让 LLM 只处理文本丰富、候选已覆盖的长尾样本；否则 prompt 级 LLM rerank 可能消耗算力却恶化融合候选池。该论文还提供 benchmark、split、prompt 和评测工具，适合用来压测现有短文本召回与 rerank 链路。

Do Recommendation Algorithms Work When Users Are LLM Agents? A Case Study on Moltbook

论文研究当平台用户变成 LLM Agent 时，传统推荐算法是否仍然有效。作者在 Moltbook 这一由 OpenClaw 自主智能体组成的社交平台上，把任务定义为预测 agent 下一步会参与哪个论坛，并评估 8 类方法，覆盖 popularity 规则、矩阵分解、ItemKNN、图方法和序列模型。实验发现，简单流行度规则或利用共现结构与 vote count 的 item-side 协同过滤，反而超过显式学习用户表征的方法；静态 agent persona 描述也未能提升参与预测。

INSIGHT这篇论文不是传统 LLM4Rec 的生成模型，但它指出了 AI-agent 用户的推荐行为可能从“个性化偏好建模”退化为“结构模式匹配”。对未来社区平台很实用：如果 UGC 搜索/推荐中出现大量代理用户、自动运营账号或 AI 创作助手，先用共现、热度、上下文结构做强基线，再谨慎引入 persona 或长序列用户画像。它也提示离线评测要把人类用户与 agent 用户分层，否则模型提升可能只是适配了非人类流量模式。

Daming Li, Simeng Han, Jialu Zhang

Rethinking Fairness in LLM-Based Recommender Systems: A Survey

论文系统梳理 LLM-based recommender systems 中的公平性问题，覆盖语义化、生成式和交互式推荐管线引入的新偏差来源。作者用“bias mechanism × fairness target”的二维视角组织已有研究，并总结评测景观与缓解策略，同时把公平性与可解释性、隐私、鲁棒性、可控性等可信推荐议题连接起来。由于它是 survey，主要贡献是框架化整理而非新的在线或离线实验。

INSIGHT对生成式推荐落地来说，这篇 survey 的价值在于提醒团队不要只看 CTR/Recall，也要把 prompt、生成解释、解码策略和反馈循环纳入风险面。社区搜索场景常有敏感内容、创作者曝光和长尾分发问题，LLM rerank 或 conversational recommendation 会放大预训练偏见与交互反馈偏差；实践上可把论文的偏差来源分类转成审核 checklist，用于上线前的分层评测和监控。

Song-Duo Ma, Chu-Yun Chen, Bang-An Li, Pin-Yu Chen, Shau-Yung Hsu, Yun-Nung Chen
