Prism: Cost-Efficient Multi-LLM Serving via GPU Memory Ballooning

Prism 面向多模型推理服务商的资源浪费问题：大量低频但必须在线的模型会占住 GPU 显存，传统空分/时分共享很难同时保证 SLO 和利用率。论文基于生产 trace 发现模型请求呈动态 bursty-group 模式，提出以 GPU memory ballooning 统一回收和再分配跨模型显存；其 kvcached balloon driver 已开源，并在 10K+ GPU 的生产环境部署，证据强度明显高于普通离线系统论文。

WarmServe: Enabling One-for-Many GPU Prewarming for Multi-LLM Serving

WarmServe 解决共享 GPU 集群中多 LLM 服务的冷启动和 TTFT 抖动问题。它利用真实工作负载的周期性和可预测性做 one-for-many GPU prewarming，并结合模型放置、空闲 KV cache 预留和 GPU tensor memory switching 三个机制提前装载多模型权重。真实数据集评测显示，相比 autoscaling 系统，尾部 TTFT 最高降低 50.8x，相比 GPU-sharing 系统吞吐最高提升 2.5x。

INSIGHT这篇论文把“预测未来请求”变成推理平台的一等能力，适合搜索推荐中的早晚高峰、活动流量和批量离线回灌场景。工程上可以先从模型热度预测、KV 空洞复用、预热干扰控制三块拆分落地；如果 UGC 搜索同时服务 query rewrite、embedding、rerank 和摘要模型，WarmServe 能显著降低长尾首 token 延迟。

Chiheng Lou, Sheng Qi, Rui Kang, Yong Zhang, Chen Sun, Pengcheng Wang, Xuanzhe Liu, Xin Jin

ExpertFlow: Optimized Expert Activation and Token Allocation for Efficient Mixture-of-Experts Inference

A*STARHKUSTHKBUNTU

ExpertFlow 针对 MoE 推理中 GPU 显存不足和专家 CPU/GPU 频繁换入换出的瓶颈，提出 routing-path predictor、expert cache engine 和 dynamic token scheduling。它把专家是否会被激活转成轻量预测任务，提前调度专家并在不同 batch 间重排 token，减少每批激活专家数量。公开摘要和论文页显示，实验覆盖 Mixtral-8x7B 与 Switch-32/64/128，报告最高 93.72% GPU 显存节省、2-10x 推理加速。

INSIGHT这篇工作虽然较旧，但对 infra 仍有复用价值：MoE 服务的关键不是只做量化，而是同时管理路由预测、专家缓存和 token 编排。若社区搜索后续引入 LongCat、DeepSeek、GLM 等 MoE 模型，可把 ExpertFlow 的“预测-预取-纠错”链路作为单卡或小集群部署的设计参考，尤其适合显存预算紧张但模型切换频繁的场景。

Xin He, Shunkang Zhang, Yuxin Wang, Haiyan Yin, Zihao Zeng, Shaohuai Shi, Zhenheng Tang, Xiaowen Chu 等 10 人

SoftMoE: Soft Differentiable Routing for Mixture-of-Experts in LLMs

SoftMoE 聚焦稀疏 MoE LLM 的路由效率：传统 top-k routing 不可微，通常固定每层激活专家数，导致不同 token 和层之间的计算预算无法细粒度分配。论文用 truncated soft top-k LapSum relaxation 替代离散路由，并在全局预算约束下学习每层平均激活专家数。作者报告其在语言建模和下游任务上达到不弱于稀疏 MoE 的效果，同时激活显著更少的专家，且后层专家分配更密集。

INSIGHTSoftMoE 的价值在于把 MoE 推理成本从“固定 top-k”改成“可学习预算分配”。对需要低延迟的搜索排序或 query 理解模型，类似思路可用于按层、按请求复杂度调整专家激活，避免简单剪枝带来的质量损失；但它仍偏模型训练/结构改造，短期落地成本高于纯 serving runtime 优化。

Mikolaj Zasada, Lukasz Struski, Jacek Tabor, Marcin Kurdziel

A Tabular Schedule Abstraction for Communication-Aware Evaluation of Pipeline-Parallel LLM Training

这篇论文研究 LLM 分布式训练中的 pipeline parallel schedule 评估问题。作者提出 tabular schedule abstraction，把公式分析、理想调度表和通信感知执行模拟串起来，对 GPipe、1F1B、Chimera、Hanayo 等策略做多配置比较。结果显示 schedule 排名并不在不同抽象层保持一致：通信开销会抵消 bubble analysis 中的结构优势；在其假设下 GPipe 与 1F1B runtime 等价，但 1F1B 的 activation-memory peak 更低。

INSIGHT对训练平台团队而言，这篇论文提醒不要只用 bubble ratio 选择 pipeline 策略，必须把网络瓶颈、microbatch 数和激活内存峰值纳入同一个评估框架。社区搜索团队如果做领域模型继续训练或多模态基础模型训练，这套抽象可用于在真实硬件实验前筛掉不适合当前网络拓扑的 schedule，减少昂贵试错。

Daniel Barley, Jonathan Leis, Benjamin Klenk, Holger Froning

2026中国AI大模型平台发展洞察与算力挑战解析

Baidu

百度开发者中心文章从产业视角总结 2026 年国内大模型平台的算力压力。文中称智能体任务占 AI 算力消耗比例从 2025 年的 12% 升至 2026 Q1 的 47%，头部 5% 高复杂度任务消耗超过 60% 总算力；传统架构执行多步骤推理时利用率低 40%-60%，万卡集群通信开销超过 35%。文章给出液冷、DVFS、FP16/FP8、梯度检查点、模型压缩和蒸馏等全栈优化方向。

INSIGHT这不是严格论文，但补足了工业实践覆盖：Agent 化搜索、复杂工单和多工具 RAG 会把 token 与算力需求推到长尾分布，平台必须从资源池化、异构调度和能效优化一起治理。对 UGC 搜索平台，最可借鉴的是按任务复杂度拆分推理资源，并用量化/蒸馏把常见请求下沉到低成本模型，把高复杂度任务留给大模型。
