AgentIR: A Workload-Adaptive Cascade Retrieval Substrate for Long-Term Conversational Memory

针对长程对话记忆这一动态、查询类型漂移、sub-10ms 延迟的检索负载，提出 AgentIR：把融合策略（BM25 / Dense / RRF / agent-aware RRF）作为每条 query 的决策，再用一个仅看 BM25 top-k margin 的置信度阈值级联路由器，决定是否还要跑约 52ms 的 dense 通道。LongMemEval (n=500) 上在 LLM-as-judge 同等准确率下跳过 63% 的 query，端到端加速 2.67×（paired bootstrap p≥0.88），分 qtype 阈值下 5-fold 交叉验证加速 5.76×。

KEY INSIGHT · 对业务意味着什么对 RAG / Agent 长期记忆场景而言，Lucene 类引擎把索引当静态、把查询当无状态的假设并不成立，AgentIR 把融合方式当作 per-query 决策 + 用 BM25 边际作为是否唤起 dense 通道的廉价信号，是工业 Agent 记忆模块降本提速的范例：不必重训模型也不必上更大 embedding，仅靠廉价信号路由就拿到 2.67–5.76× 提速。搜推团队的对话历史检索、Memory Bank 选择召回链路可直接借鉴这种 confidence-triggered cascade 结构。

Anticipate and Learn: Unleashing Idle-Time Compute in Proactive Agents

SJTUHuawei

现有 Agent 是被动响应——只有在用户显式 prompt 之后才计算。ProAct 提出主动式 Agent 架构：在对话间的空闲时间，结合演化中的对话历史与持久记忆，预测用户下一步可能需要的信息，并迭代采集证据。论文同时发布 ProActEval 基准，覆盖 40 个领域、200 个场景，含可预测的 need chain 与多样的用户认知画像。在 ProActEval 上 ProAct 相对被动基线显著提升预测准确性与证据覆盖率。

INSIGHT把 Agent 的 idle-time compute 当作可调度的资源，是当前 Agent 系统设计中被严重低估的杠杆——对推荐 / 搜索场景，这等价于把会话间隙变成离线召回 + 候选预热的窗口。ProAct 的 need prediction + iterative retrieval 框架，可以直接迁移到对话推荐、客服 Copilot、个性化 deep research 场景：会话静默期预拉数据，用户开口时直接返回，等同于把首响应延迟摊到了无人感知的空闲槽位。

Agent Learning via Early Experience

MetaOOSU

面向缺少可验证奖励（如网站操作）或 rollout 过长（多轮工具调用）导致 RL 训练困难的 Agent 任务，提出 early experience 范式：用 Agent 自身动作产生的交互数据，把后续状态作为监督信号——介于专家 SFT 和 RL 之间的中间态。论文系统地研究了 implicit world modeling、self-reflection 两类 early experience 训练目标，在 8 个跨网页 / 工具 / 多轮对话的基准上稳定优于 SFT 基线，且能作为 RL 的更好初始化。

INSIGHTAgent 训练数据的真正瓶颈不是奖励信号，而是有效环境多样性——专家数据只覆盖窄分布。早期经验范式给出的核心 takeaway 是：用 Agent 自己走出的轨迹、把未来状态当 free supervision，可以以零 reward 成本获得显著优于 SFT 的泛化能力。对工业 Agent 系统的意义在于：上线初期 RLVR 跑不起来时，先做 early experience 蒸馏即可拿到大部分增益，且能直接为后续 RL 提供更优 warm start。

Kai Zhang, Xiangchao Chen, Bo Liu et al. (Meta, Jason Weston, Yu Su 等)

Agent-Facing Information Design in LLM Tool Registries

把 LLM 工具注册表当作“无监管广告平台”研究：服务商写自由文本，Agent 据此选工具，但缺乏 viewability、quality score、outcome audit。在 5 个 LLM × 10 个领域 × 17,700+ 试次上系统测量发现：合法的吹嘘语（主观最高级、利益框架）就吃下了 100% 的优化收益，编造性陈述带来的偏置增量为 0——这意味着 FTC 反虚假广告条款对真正起作用的机制无效；system-prompt 告警在 4/5 模型上完全无效。最强单一特征是 superlatives（SBC = +0.35）。

INSIGHT对搜推团队建设 Agent 平台 / 工具市场（如 plugin store、tool registry）有直接警示价值：用户撰写的工具描述会被 Agent 检索 + LLM 选择机制系统性地偏向“吹得响”的而非“做得好”的，且系统提示防护无效。可行的工程对策不是依赖描述合规审核，而是引入 registry 层归一化（去主观词、统一模板）、行为产出审计、第三方质量分。值得 search-as-tool-platform 团队在前端注入阶段就引入这套 information design。

Haochuan Kevin Wang

How Many Tools Should an LLM Agent See? A Chance-Corrected Answer

Agent 调用工具前，工具检索系统要先决定给模型看多少候选工具。论文把 shortlist 长度本身作为评估对象，引入 Bits-over-Random (BoR)：相对于该深度随机抽样的成功率，模型多赚了多少比特的信息。在三个工具选择 benchmark、多种打分器、工具规模 20–3251 的设置上验证 BoR，并把它直接当作 RL 奖励，让 Agent 学会按 query 决定 shortlist 深度——一个刻意简化的 RL Agent 主要用来探针式验证该指标。

INSIGHT把“召回返回多少候选给下游 LLM”作为可学习决策、而不是一个静态超参，是 RAG / 工具检索系统设计的关键升级。BoR 这个 chance-corrected 度量对推荐和搜索同样适用——在 reranker 输入长度、LLM-rerank top-N 选择、Agent 工具 shortlist 等场景，都能用 BoR 替代“固定 top-K + recall@K”的传统指标，并用其作为 RL 奖励训练自适应深度选择策略。

Vyzantinos Repantis, Ameya Gawde, Harshvardhan Singh, Joey Blackwell II

RAG-Match: Retrieval-Augmented Knowledge Injection and Hierarchical Reasoning for Calibrated Semantic Relevance

📖 深度解读 · 10 分钟 →

针对知识密集型搜索相关性场景——需要语义匹配 + 背景知识接地 + 多步推理 + 决策边界校准——提出 RAG-Match 三阶段框架：知识增强预训练（强化 query-centered 语义接地）、层次化推理对齐（结构化相关性推理）、偏好驱动的决策校准（修复难样本的边界不一致）。在真实搜索相关性数据上 NDCG/相关性准确率优于直接监督和浅层语义相似基线。

INSIGHT工业搜索相关性团队长期被两类失败困扰：知识盲点（同义但不同表面形式）和决策边界不稳定（难样本上 label-judge 一致性差）。RAG-Match 给出的解法是把这两类问题拆分到不同训练阶段——pretrain 注入知识、SFT 学层次化推理、preference 对齐校准边界，而不是塞进一个统一 loss 里。对美团/京东/小红书这类 query-doc 相关性任务，这种分阶段流水线天然对齐线上日志的 label 噪声特征，可直接落地试点。

CUA-Gym: Scaling Verifiable Training Environments and Tasks for Computer-Use Agents

RLVR 在数学、工具调用、软件工程已成型，但向计算机使用 Agent (CUA) 扩展卡在“任务指令 + 可执行环境 + 可验证奖励”三元组的稀缺。CUA-Gym 设计可扩展流水线协同生成三元组：Generator agent 构造 init / golden 环境状态，Discriminator agent 从任务规约写出奖励函数，由 orchestrator 多轮迭代驱动两者；生成结果经 LLM 多数投票 + 执行通过率联合过滤。可在不需要人工 curation 的前提下扩大可验证 CUA 训练任务规模。

INSIGHTComputer-use Agent 的真正瓶颈在数据合成而非算法。CUA-Gym 把“任务、环境、奖励”统一交给 Agent 协作生成，再用执行可验证性做硬过滤，本质上是把 RLVR 的“verifiable reward”门槛从问题域降到了数据合成域。对要把 Agent 落到生产场景（如电商客服自动执行、办公助手）的团队而言，这个 Generator-Discriminator-Orchestrator 三件套是一个可复用的数据飞轮——比标注外包要好上一个数量级。

Bowen Wang, Dunjie Lu, Junli Wang, Tianyi Bai, Shixuan Liu

DVAO: Dynamic Variance-adaptive Advantage Optimization for Multi-reward Reinforcement Learning

把 GRPO 扩展到多奖励真实场景：Reward Combination 容易产出过大平方幅度的 advantage 导致训练不稳；Advantage Combination 用静态超参且忽略跨目标相关性。DVAO 按 rollout group 内每个目标的经验奖励方差动态调权——给学习信号强（高方差）的目标加权，压制噪声目标。在多奖励对齐基准上比 RC/AC 基线训练稳定性与最终对齐质量均更优。

INSIGHT多奖励 RLHF / RLVR 在搜推 LLM 应用里几乎是默认设置——相关性、安全、风格、长度同时优化。DVAO 给出的 takeaway：奖励权重应当是 rollout-time 自适应而不是 grid-search 调出来的静态值，且 advantage 而非 reward 端做组合更稳。对搜索摘要、对话推荐、客服 Agent 这类多目标 RL 任务而言，DVAO 类组件可以作为 GRPO 训练框架的即插即用替换。

Guochao Jiang, Jingyi Song, Guofeng Quan, Chuzhan Hao, Guohua Liu

Claw-Anything: Benchmarking Always-On Personal Assistants with Broader Access to User's Digital World

现有 LLM Agent 作为“常驻个人助手”只能访问用户数字世界的窄切片（单一 App / 单一文档来源），限制了上下文敏感推理与长程任务执行。Claw-Anything 提出一个 benchmark，系统评估 always-on 个人助手在更广访问范围（跨应用日历、文档、消息、浏览历史）下的任务完成度，覆盖跨域信息综合、隐私敏感操作、长尾偏好理解等维度。

INSIGHT搜推团队做“超级 App 内 Copilot”时最大的产品落差不是模型能力，而是 Agent 能看到的用户上下文范围。Claw-Anything 的评估维度（跨应用上下文、隐私敏感动作、长尾偏好）给出了未来端侧 Agent 的产品边界图——值得在做对话推荐 / Copilot 时把这些维度纳入产品验收 checklist，而不是只看回答正确率。

Yusong Lin, Xinyuan Liang, Haiyang Wang, Qipeng Gu, Siqi Cheng

Diverse reasoning traces teach LLMs to make better decisions

Amazon

Amazon Science 介绍如何用控制 token 引导 LLM 生成多样化、准确的推理路径——为每种推理策略分配一个独特的控制 token，训练时让模型学会按 token 切换思维风格（演绎 / 类比 / 反事实 / 分解）。在多个决策类任务上，diverse reasoning trace 训练相对单一 CoT 蒸馏取得更好的最终决策准确率与解释多样性。

INSIGHTAgent 决策质量的瓶颈不在“是否会推理”而在“是否会切换推理风格”。Amazon 的做法——用控制 token 强制模型在训练时见到多种推理策略——是相对低成本的工程手段，可与搜推领域的多目标排序训练范式直接结合：例如在 query 改写、Agent action 选择、推荐解释生成中，用 task-control token 控制不同决策风格，比单一 SFT 更鲁棒。
