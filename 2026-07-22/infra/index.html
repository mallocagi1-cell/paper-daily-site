C$^2$KV: Compressed and Composable KV Cache Reuse for Efficient LLM Inference

针对长上下文推理中非前缀 KV 复用仍受存储与传输成本制约的问题，C²KV 联合学习位置无关、可拼接的压缩缓存表示。其侧挂 Extractor 以可学习压缩 token 和结构化注意力抽取缓存，并用压缩—拼接协同训练对齐复用行为；在多种长上下文基准与模型上最高实现 17 倍推理加速，同时保持生成质量。

KEY INSIGHT · 对业务意味着什么缓存复用与缓存压缩不能作为两个独立开关：朴素组合会因位置错配导致精度显著下降。对搜索/RAG 服务，更可行的路线是把文档片段缓存训练成位置无关的模块，再按请求动态拼接；这能同时压低 prefill、显存驻留和跨节点传输成本，尤其适合高复用知识库与多文档问答。

SpecLA: Efficient Speculative Decoding for Linear-Attention Models

SpecLA 面向具有循环状态的线性注意力模型重做投机解码运行时，解决 Transformer KV 缓存方案无法正确处理链式依赖、分支验证与接受路径状态更新的问题。系统采用拓扑感知核函数、紧凑因子状态恢复、置信度剪枝和目标对齐的 EAGLE 式草稿器；在 H100 与公开 GDN-1.3B 模型上端到端最高加速 1.70 倍。

INSIGHT线性注意力减少了 KV 缓存，却把状态一致性变成投机解码的新瓶颈。工程上不能直接移植 Transformer 的验证核，而应把候选树拓扑、接受轨迹恢复和草稿质量联合设计；若搜索生成链路采用线性注意力模型，这套运行时思路可在不改模型语义的前提下提升解码吞吐。

Zhibin Wang, Xuying Han, Zhaohua Yang, Fuliang Liu, Xue Li, Rong Gu, Sheng Zhong, Chen Tian

VDAR-Router: Adaptive LLMs Routing via Verbalized Query Difficulty Analysis Retrieval

NNational Yang Ming Chiao Tung University

VDAR-Router 不再只按查询表面语义或 embedding 相似度选模型，而是先让模型显式描述查询难度，再检索难度画像相近的历史样本，最后以兼顾效果与成本的奖励函数完成路由。论文在三个数据集上均取得优于既有基线的成本—性能折中，且无需训练专用路由器；案例分析显示难度描述能召回更可靠的决策参照。

INSIGHT模型路由真正需要匹配的是“解题难度”，不是“主题相似度”。社区搜索可把 query 歧义、时效性、证据跨度和推理深度 verbalize 成稳定画像，再在历史线上样本中检索相似案例，用于选择小模型、强模型或检索增强链路；这种训练免费方案适合先做灰度实验并持续积累路由日志。

Yu-Chien Tang, Jun-Chen Hung, Wen-Chih Peng, An-Zi Yen

04 3.90

Setting a World Record for MoE Pre-Training on NVIDIA GB300 NVL72

NVIDIA

NVIDIA 展示 GB300 NVL72 上预训练 DeepSeek-V3 671B 的系统级优化，单卡达到 1,648 TFLOPs；模型每 token 仅激活约 37B 参数。平台用第五代 NVLink 提供单卡 1.8 TB/s、机架 130 TB/s 无阻塞全互联，并以 Megatron Core、TorchTitan 和 JAX 联合优化；从 256 扩到 1,024 GPU 时单卡吞吐保持 97% 以上。

INSIGHT大规模 MoE 的主瓶颈正在从算力转为每层 all-to-all 通信，单纯增加 GPU 会迅速遇到扩展墙。训练平台应把机架内低延迟 scale-up、跨机架可预测 scale-out、专家并行和软件通信重叠作为一个系统共同调优；97% 以上的扩展保持率说明硬件互联拓扑必须进入并行策略设计。

Kirthi Devleker, Farshad Ghodsian, Syed Ahmed, Sukru Burc Eryilmaz

Inside NVIDIA Rubin GPU Architecture: Powering the Era of Agentic AI

NVIDIA

NVIDIA Rubin GPU 面向长上下文与 Agent 持续推理设计，集成 3360 亿晶体管、224 个 SM、896 个 Tensor Core 和 288 GB HBM4，内存带宽达 22 TB/s。第三代 Transformer Engine 提供最高 50 PFLOPS 稀疏 NVFP4 性能，NVLink 6 单卡 scale-up 带宽达 3.6 TB/s；官方内部 2T MoE 工作负载显示单位能耗 Agent 吞吐最高为 Blackwell 的 10 倍。

INSIGHTAgent 推理的关键不再是一次请求的峰值 FLOPS，而是长时间 decode、KV 容量、细粒度核函数衔接与机架级功耗的共同约束。Rubin 把 HBM4、稀疏注意力、依赖核触发和 NVLink 通信协同设计；服务团队评估下一代硬件时，应以 tokens/瓦、并发长上下文与整机架可用吞吐替代单卡峰值指标。

Eduardo Alvarez, Vishal Mehta

06 3.90

Automated Tensor Scheduling for Hybrid CPU-GPU LLM Inference on Consumer Devices

ATSInfer 针对消费级设备显存不足时传统按层或按专家卸载过于粗糙的问题，把 CPU—GPU 混合推理调度细化到 tensor 粒度。系统结合静态放置、负载感知动态迁移与异步计算传输协调，并在稠密及 MoE 模型上验证；相较既有系统，prefill 吞吐最高提升 1.94 倍，decode 吞吐最高提升 3.29 倍。

INSIGHT混合推理的收益来自“单位显存带来的加速”而非固定层边界，同一层中的不同 tensor 应根据 GPU 收益、PCIe 成本和实时负载分别安置。该设计适合边缘搜索、私有化部署和开发机推理，但论文尚未公开实现；落地前应重点复现实测平台上的动态迁移开销与热降频适应性。

Yangyijian Liu, Hongyi Ye, Mingyang Li, Wu-jun Li

OpenLanguageModel: Readable and Composable Small-Language-Model Pretraining for Education and Research

OpenLanguageModel 是强调可读与可组合的小语言模型预训练库，以普通 PyTorch 模块配合 Block、Residual、Repeat、Parallel 描述网络连线，并覆盖 tokenizer、流式数据、混合精度、检查点和 CPU/单卡/单机多卡执行。项目提供九类模型的 27 个预设；348M 参数任务在四卡弱扩展中达到 90.6% 效率，并与独立参考实现保持接近。

INSIGHT研究框架的价值不只在极致吞吐，还在于让架构改动、训练脚本和消融实验共享同一套可读抽象。对于搜索团队的小模型预训练、蒸馏与结构实验，OLM 可降低从教学原型到完整训练的迁移成本；不过当前只覆盖单节点多卡，多节点规模化仍需接入成熟分布式栈。

Tavish Mankash, Vardhaman Kalloli, Keshava Prasad, Deepan Muthirayan

SWE-Pruner Pro: The Coder LLM Already Knows What to Prune

ByteDance

SWE-Pruner Pro 利用代码 Agent 自身隐藏表示判断工具输出中每一行是否保留，无需外挂代码分类器；轻量预测头结合按输出行数编码的长度 embedding 完成裁剪。论文在两个开源骨干和四个多轮基准上最多节省 39% 的提示与生成 token；在 MiMo-V2-Flash 上，SWE-Bench Verified 解题率提升 3.8%，Oolong 长上下文准确率提升 2.2 点。

INSIGHT上下文裁剪可以复用主模型已经形成的相关性信号，避免额外分类器带来的模型漂移和部署复杂度。该方法虽面向代码 Agent，但同样启发搜索链路：可从 LLM 隐状态学习帖子、评论或工具结果的行级保留门，在质量不降的前提下降低长上下文 token 成本，并用任务指标共同训练裁剪阈值。

Agent 时代下大模型推理系统的架构优化和工程实践

Baidu

百度智能云总结 Agent 负载对推理系统的结构性冲击：线上平均上下文已从 4K 输入、1K 输出增长到 40K—60K，部分达到 100K。百舸围绕 DeepSeek-R1 的 MLA、MoE 和原生 MTP 适配，建设大规模 Prefill—Decode 分离系统，并用通信优化与冗余均衡缓解专家并行开销；在 4K/1K 场景达到不逊于 DeepSeek 官方实现的性能。

INSIGHTAgent 会把推理瓶颈从短请求吞吐推向长上下文 KV 管理、PD 分离网络和 MoE 通信，旧有容量模型需要按真实长度分布重算。对带搜索工具调用的社区 Agent，平台应分别观测 prefill 与 decode SLO、缓存命中和跨节点流量，并为 MLA、MTP 等模型结构建立专用执行路径，而不是只依赖通用框架默认配置。

Multi-level context Modeling for consistent expert selection in Mixture-of-Experts

MCF-MOE 将 MoE 路由不稳定归因于上下文信息不完整：传统路由器只看浅层或孤立 token 表示，导致不同层的专家选择语义不一致。方法融合跨层语义聚合与局部 token 交互，构造更完整的路由表示；语言建模和理解基准显示，它相对强 MoE 基线持续改善路由一致性与下游表现，代码已提供匿名公开实现。

INSIGHT专家路由并非只需更复杂的负载均衡损失，输入表示是否含有跨层语义和局部上下文同样决定专家能否稳定专门化。对于面向多领域 UGC 的 MoE 模型，可重点监控相邻层路由漂移和语义簇稳定性；但论文未在摘要披露具体增益与大规模部署成本，适合作为研究性消融而非直接替换线上路由器。

Shuhan Huang, Naifan Zhang, Yuanbo Tang, Yang Li, Wai Kin Victor Chan
