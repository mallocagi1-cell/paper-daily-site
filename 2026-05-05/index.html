Exploring LLM biases to manipulate AI search overview

针对 LLM Overview 类生成式搜索结果（搜索结果上方的 AI 总结），论文研究 LLM 在源选择阶段的偏差，并训练一个小模型用 RL 重写搜索 snippet 以提升被 LLM Overview 选中的概率。实验通过限制策略只能改写 snippet，证明 LLM Overview 的源选择对 token 级扰动高度敏感，重写后小语言模型生成的 snippet 命中率显著提升。

A Survey of Reasoning-Intensive Retrieval: Progress and Challenges

综述 Reasoning-Intensive Retrieval（RIR）：当 query 与候选证据之间的相关性需要靠潜在推理而非语义相似来桥接时，传统稠密检索失效。论文按知识领域和模态系统化整理 RIR benchmark，并提出按'推理在 pipeline 哪个阶段、以何种方式注入'的方法分类——包括查询端 reasoning rewriting、retriever 端 LLM 驱动召回、reranker 端推理重排。同时分析各方案的算力/延迟/质量权衡。

INSIGHT对社区搜索来说，UGC 长文本里大量'问题→答案在帖子中段'的隐式相关，正是 RIR 关注的场景。这篇 survey 给出可借鉴的工程路线：先用 LLM rewriting 把 query 中的隐含意图显式化，再走稠密召回；reranker 阶段插入轻量 reasoning 模块比直接用 LLM 重排更划算。值得在搜索相关性评测中引入 RIR 风格的 hard subset，识别现有系统的能力短板。

03 3.55

Hierarchical Abstract Tree for Cross-Document Retrieval-Augmented Generation

Ψ-RAG 针对跨文档多跳问答场景，指出现有 Tree-RAG 三大缺陷：k-means 聚类对分布敏感、树索引缺乏跨文档连接、抽象粒度过粗。方案包含两个组件：通过迭代'merge & collapse'构建无先验假设的层次抽象树索引，以及多粒度检索 agent 智能交互不同层级——既能拉粗粒度摘要，也能下钻到细节。论文在多跳 QA benchmark 上证明端到端答案质量优于 RAPTOR 等 baseline。

INSIGHT对长文 UGC 搜索的启示：把社区帖子按'楼主主帖→评论树→片段'三层抽象建索引，让检索 agent 自动选择粒度，比单层 chunk 更符合用户多跳查询。Ψ-RAG 的 merge-collapse 构建过程可以离线增量化，适合每日新增帖子的工业流；agent 端则需控制 LLM 调用次数，避免 latency 失控。

Structure-Aware Chunking for Tabular Data in Retrieval-Augmented Generation

STC 提出针对 CSV/Excel 的结构感知 chunking 框架：以行为单元构建层次 Row Tree，每行编码为 key-value block，按结构边界做 token 受限分割，再用无重叠贪心合并形成稠密 chunk。在 MAUD 数据集上相比标准 recursive 与 key-value chunking baseline，chunk 数减少 40%-56%，token 利用率提升、片段化降低，下游 RAG 答题准确率上涨。

INSIGHT社区里大量'表格化'内容（评分卡、配料表、参数对比贴）以纯文本方式贴出，传统 chunker 会把行打散导致信息丢失。STC 的 Row-Tree 思路可以迁移到结构化 UGC 抽取后建索引：先解析为 row-level KV 单元再按 token 预算合并，能在不改 LLM 的前提下显著提升 RAG 在比较类 query 上的召回质量。

Retrieval-Augmented Reasoning for Chartered Accountancy

CA-ThinkFlow 针对印度 CA 考试这类需要法规知识 + 多步数值推理的领域，构建参数高效 RAG 框架：使用 14B-DeepSeek-R1 的 4-bit 量化推理模型 + Docling 版面感知抽取系统保留文档结构。把检索片段直接注入 prompt，依赖模型的 CoT 能力生成解答；在受限算力下相比纯 LLM 显著提升正确率，尤其多步法规题。

INSIGHT工业落地角度的代表案例：用 DeepSeek-R1 14B + 量化代替闭源大模型，配合 Docling 保留版面，证明在垂域 RAG 中开源 reasoning 模型已经可用。社区搜索的法律/医疗/政策类问题本质相似——靠开源 14B 推理模型 + 结构化抽取就能搭出可控可部署的智能问答，无需 70B 级 API 调用。

Making Every Verified Token Count: Adaptive Verification for MoE Speculative Decoding (EVICT)

EVICT 是面向 MoE 模型 speculative decoding 的训练-免参数自适应验证算法。指出树状 speculative decoding 在 MoE 上失效：候选树扩张让被激活专家集合膨胀、target 验证成本反升。EVICT 在 target 验证前先按 drafter 信号 + 离线 profile 的验证成本截断 draft 树，只保留性价比高的前缀，与 SGLang 高性能 serving 完全兼容。多种 MoE backbone 上端到端加速最高 2x 以上、无损质量。

INSIGHT生成式搜索/推荐如果用 MoE 大模型在线生成（如 OneRec、AI Overview），speculative decoding 是降本关键。EVICT 给出的核心结论：MoE 下树状 spec decoding 不能盲目扩，应该用 drafter 概率与专家激活成本动态剪枝。可以直接接入 SGLang 部署，是社区搜索 LLM 摘要服务的现成优化点。

07 3.55

Escaping Mode Collapse in LLM Generation via Geometric Regulation

论文用动力系统视角重新解释 LLM 生成中的 mode collapse：模型内部轨迹被困在表征空间的低维子区域（geometric collapse），表现为循环、多样性丢失、提前收敛。提出 RMR (Reinforced Mode Regulation)：在 Transformer value cache 里对主导自激励方向做低秩阻尼，作为在线状态空间干预。多模型实验显示能显著降低 mode collapse 而不损推理能力，且无需重训。

INSIGHT对生成式搜索摘要场景，重复或趋同回答是 LLM Overview 的典型故障。传统温度/惩罚类 decoding 改不动 geometric collapse。RMR 的 low-rank value-cache damping 思路可以作为推理期插件接入 vLLM/SGLang，社区搜索如果上 LLM 摘要，可以用类似的几何正则避免不同 query 输出趋同的'AI 模板感'问题。

08 3.40

Agent Capsules: Quality-Gated Granularity Control for Multi-Agent LLM Pipelines

Agent Capsules 把多 agent 流水线执行视作带经验质量约束的优化问题：测量每组 agent 的协调开销、评分组合机会、在三种 compound 执行策略中选择，并以滚动均值输出质量做 gate。一个反向实验证明往合并调用里塞更多 context 反而加剧压缩损伤；框架的逐步降级阶梯（标准→两阶段→分散）通过向 per-agent dispatch 回退恢复质量，而非改写 prompt。LLM-judged 质量上控制器实现 token 节省同时保持质量。

INSIGHT对搜索/推荐场景的 agentic pipeline，朴素地把多个 agent prompt 合并节约 token 会伤效果。Agent Capsules 给出的核心准则是'用质量监控 + 阶梯降级替代盲目压缩'，这一框架可以直接套用到社区搜索的多步 agent（query 改写→召回→重排→摘要），用 rolling-mean 质量门控自动决定在哪一步合并，在哪一步分开。
