Intelligent Elastic Feature Fading: Enabling Model Retrain-Free Feature Efficiency Rollouts at Scale

工业大规模排序系统依赖数千个跨多时间窗口的用户行为特征，特征效率上线常需重训模型，导致 3–6 个月迭代周期与可观 GPU 消耗。本文提出 IEFF（Intelligent Elastic Feature Fading）这一生产级基础设施，能在 serving 端弹性控制特征覆盖与分布，配合周期性重训完成增量适配，无须显式触发重训。系统内置严格安全护栏、可逆机制与全链路监控以保障稳定性，实测在多条线上链路上把效率类上线提速 5×、消除重训型 GPU 开销，并提升 rollout 吞吐。

DynamicPO: Dynamic Preference Optimization for Recommendation

USTCMeituan📖 深度解读 · 9 分钟 →

在 LLM-based 推荐里，DPO 通常借助多负样本目标函数从隐式反馈中放大偏好边界。但作者发现一个反直觉的“偏好优化坍塌”现象：训练损失持续下降，但增加负样本反而带来性能退化。理论分析显示，易判别的简单负样本会主导梯度，把真正定义偏好边界的“边界负样本”信号压制住。基于此，论文提出 DynamicPO，通过动态加权机制识别并放大 boundary-critical 负样本的梯度贡献，是一个轻量、即插即用的 DPO 改造，实验显示能在多个推荐基准上稳定改善对齐效果。

INSIGHT把 DPO 的“多负样本”看成排序里的“困难负样本挖掘”问题，是 LLM-Rec 训练范式与传统 ranking 训练经验对齐的关键洞察。社区搜索的相关性精排、CTR 预估与对齐微调都可以照此思路：识别每个 batch 中真正贴近决策边界的负样本，给予动态权重，避免简单负样本“偷走”梯度。这个改造代价低、无需新数据，是最容易迁移到现有 LLM-Rec 与 reranker 训练管线的优化点。

Time-Interval-Aware Disentangled Expert Modeling for Next-Basket Recommendation

Next-Basket Recommendation (NBR) 受两类用户意图驱动：习惯性复购与探索性发现。现有方法常把两者揉进单一表征，导致习惯压制发现，且依赖离散序列建模，忽略连续时间间隔与物品自身周期性。作者提出 TIDE：(1) Hawkes-enhanced Fourier Time Encoding 捕捉物品级周期与衰减；(2) 引入两套解耦专家分别建模习惯与探索意图，并通过门控融合输出。论文在标准 NBR 基准上对照多个基线，验证 TIDE 在召回与命中率指标上的提升。

INSIGHT意图解耦 + 连续时间感知是改造序列推荐的两个杠杆。社区搜索/推荐场景同样存在“日常需求 vs 新鲜内容探索”的冲突——比如关注流刷帖与发现频道；TIDE 的双专家分支与 Hawkes-Fourier 时间编码可被借鉴到我们的 sequential ranker：用时间间隔信号取代离散 position embedding，并用门控让模型对不同 query/场景动态调权“惯性”与“探索”专家。

MemRouter: Memory-as-Embedding Routing for Long-Term Conversational Agents

长程对话 Agent 必须为每一轮决定是否写入外部记忆；现有方法逐轮调用 LLM 自回归生成决策，开销大且延迟高。MemRouter 把“记忆准入”从答题主干解耦：以 frozen LLM 作 backbone 给当前轮和近期上下文做 embedding，再接轻量分类头判断该轮是否进库，仅训练 12M 参数。在 LoCoMo 基准上，与 LLM-based memory manager 比对（同一 retrieval、prompt、QA 主干 Qwen2.5-7B），MemRouter 整体 F1 52.0 vs 45.6（95% CI 不重叠），同时把记忆管理 p50 延迟显著下降。

INSIGHT把“是否写入记忆”看成一个轻量分类问题，而不是让大模型每轮“想一遍”，是把对话 Agent 推理路径“瘦身”的高 ROI 改造。对社区搜索/推荐场景的对话产品（搜索助手、个性化 chatbot）有直接借鉴：用户长程偏好的存储决策可由 12M 量级路由器承担，让大模型只负责回答；这样既降本又规避了 LLM 决策不稳定带来的记忆爆炸/丢失风险。

Tianyu Hu, Weikai Lin, Weizhi Zhang, Jing Ma, Song Wang

Robust Multimodal Recommendation via Graph Retrieval-Enhanced Modality Completion

NUS

Web 推荐系统常依赖图像/文本多模态信号，但实际数据因传感失效、标注稀疏、隐私约束常出现模态缺失，显著拖累模型效果。已有补全方法多依赖节点自身或一阶邻居推断缺失模态，忽略图中语义相关、却非简单邻接的上下文线索。作者提出基于图检索增强的模态补全：对缺失节点先在图上检索语义最相关的子图样本，再用该上下文重建缺失模态特征，再喂给下游推荐模型；论文在多模态推荐基准上验证补全质量与下游召回/排序指标的提升。

INSIGHT把“缺失模态补全”从“对邻居取平均”升级为“在全图上做语义检索 + 重建”，把 RAG 的思想引入图侧多模态推荐，是个轻量但通用的预处理改造。社区搜索/推荐里 UGC 帖子常有缺图、缺标题、缺描述场景，可在 item embedding 入库前加一道“graph retrieval-completion”，提升冷启动与稀疏模态物品的召回质量；这条思路也方便与现有多模态特征 pipeline 拼接，无须改动主排序模型。

Yuan Li, Jun Hu, Jiaxin Jiang, Bryan Hooi, Bingsheng He

ReLay: Personalized LLM-Generated Plain-Language Summaries for Better Understanding, but at What Cost?

NIHUniversity of Washington

Plain Language Summary (PLS) 通常是“一刀切”风格，忽略读者背景与信息需求差异，在医学等高风险场景里可能误导决策。作者构建 ReLay 数据集：50 名 lay 受试、300 对 participant–PLS 配对，覆盖静态专家撰写与交互式 LLM 个性化两种模式，并采集用户特征、信息需求、检索行为、理解结果与互动日志。论文在 ReLay 上评估 5 个 LLM 在两种个性化策略下的效果，分析了个性化是否真的提升理解、安全与个性化之间的张力，以及哪些用户特征最值得用于条件生成。

INSIGHTReLay 给出了一个少见、可复用的“用户特征 → LLM 个性化输出 → 理解效果 + 风险”的端到端评估范式。社区搜索结果摘要（query-focused summary）个性化是同样的问题：用什么用户信号去条件、如何避免幻觉与误导、如何衡量“是否真的更好懂”。论文的数据采集模板（信息需求 + 行为日志 + 主观评分 + 客观理解题）可直接借鉴用于自家 A/B 实验。

MemoryBench: A Benchmark for Memory and Continual Learning in LLM Systems

Tsinghua

数据/参数/算力 Scaling 接近瓶颈后，给 LLM 系统加“记忆 + 持续学习”成为新主线。但现有 LLM 记忆 benchmark 多停留在长文本阅读理解，难以衡量“在 serving 中持续从用户反馈学习”的能力。作者提出一个用户反馈仿真框架与 MemoryBench：覆盖多领域、多语种、多任务类型，用模拟用户的反馈信号驱动 LLM 系统的记忆与持续学习评估，统一对比当下主流记忆架构在累积反馈中的提升曲线，识别它们在不同领域、不同反馈密度下的失败模式。

INSIGHT把“用户反馈在线学习”作为推荐/搜索 LLM 系统的一类核心能力来评测，而不是只看一次性回答质量，是 RecSys 与 LLMSys 融合的方向。我们做社区搜索的 LLM 改写、个性化摘要时，可以把这套“用户反馈仿真 + 长期能力曲线”的评估框架引入离线评测：除了点击/相关性，还衡量“模型从过往同用户反馈学到了多少”，作为长期 retention 与个性化深度的代理指标。

Qingyao Ai, Yichen Tang, Changyue Wang, Jianming Long, Weihang Su, Yiqun Liu

GNN Explainers 2.0: User-centric and Data-driven Insights

NTUZhejiang UniversityCCase WesternCCENTAI

WSDM 2026 教程“GNN Explainers 2.0”系统梳理图神经网络可解释性研究的第二代进展：从仅给出 saliency 子图升级为面向用户问题、数据特性的可解释框架，覆盖节点级/边级/子图级解释、对比解释、反事实解释，以及基于 LLM 的语言化解释。教程总结了在推荐系统、社交图、知识图、欺诈检测等场景下，2.0 一代解释器在保真度、稳定性、用户可读性、与下游决策一致性等维度的权衡，并系统给出评测协议与开源工具链。

INSIGHT推荐排序模型从黑盒迈向“用户中心可解释”是 2026 年的明确趋势。社区搜索/推荐里同样面临“为什么这条帖子排在前面”的解释需求；GNN Explainers 2.0 提供的反事实+语言化解释模板，可结合 LLM 把图模型给出的子图解释翻译成用户可读的理由（“因为你关注了 A，且 B 与 A 有强协同信号”），既支撑面向用户的“为什么推荐”功能，也为内部调参与算法 review 提供可视化抓手。

Constructing Commonsense Knowledge Graph for Persona Consistency

对话/个性化系统中 persona 一致性是核心痛点：模型既要记住用户既定身份与偏好，又要在多轮交互中不前后矛盾。论文提出基于常识知识图（Commonsense Knowledge Graph）的 persona 建模方案：把用户陈述抽取为 (subject, relation, object) 形式的三元组，叠加常识边形成 persona-CKG，并在生成阶段用图检索约束模型回答必须与 persona-CKG 中事实兼容；在 PersonaChat 等数据集上验证 persona 一致性、回答相关性同步提升。

INSIGHT把用户长期偏好/事实结构化成可校验的小图，是降低个性化 LLM “幻觉式翻车”的有效路径。社区搜索的对话式个性化（“帮我找上次聊过的那家店”、“按我之前的口味推荐”)可借鉴 persona-CKG：把用户长期偏好事实化、可索引、可推理，让生成模型在每次回答前必须先与该图对齐，再结合检索增强；这比单纯把历史消息 token 拼到 prompt 更稳、更省 token、也更易做归因。

Lei Xia, Yuyan Chen, Xiangqin Chen, Jixiang Fan, Weinan Dai
