Control How Your GPU Shares Work with Green Contexts

CUDA Green Contexts 让同一进程显式划分 SM 与工作队列，降低吞吐任务对关键 kernel 的干扰。148 SM 的 Blackwell 微基准中，8 SM 留给关键任务、140 SM 给批量任务，关键延迟为 0.007 ms；仅设高优先级为 0.140 ms，同优先级为 3.727 ms。CUDA 13.1 已提供 Runtime API。

StagQ: Constraint-Driven Multi-Precision Weight Quantization for LLMs

StagQ 用 2-bit 分组仿射基础码加若干 1-bit 精化平面，让同一权重流的前缀支持不同精度，并以稀疏旁路保存难量化权重。2-bit 下在 Llama-3.1-8B、Phi-4、OLMo-2-7B 上较最强多精度基线提升 3.1–7.0 个 MMLU 点；A100 合成权重矩阵向量测试多数配置更快。

INSIGHT同一份权重支持多档精度，适合社区搜索按流量、显存和 query 难度配置推理资源，可减少多副本存储与分发。应同时核算旁路记录和共享元数据的真实容量，并复测短文本相关性；文中的 kernel 结果来自 batch-one 合成权重，尚不足以承诺生产服务吞吐收益。

Tailoring the Quantization Space for 1-Bit KV Cache Compression

TaSQ 针对 1-bit KV 向量量化误差过大的问题，联合查询引导通道加权、跨头归一化与协方差分组，重塑量化空间。变换兼容 RoPE，可并入投影权重和码本；单张 RTX 6000 Ada 上的 SGLang 实现相对 BF16 支持最高 14 倍 batch，峰值吞吐达到 1.87 倍。

INSIGHT优化量化空间比单纯扩大码本更有价值，尤其适合社区搜索中长上下文 query 理解与生成服务的显存约束。可在相同模型与 SLO 下比较并发容量、首 token 延迟及尾延迟，再验证长尾短文本匹配是否退化；14 倍 batch 容量与 1.87 倍吞吐是不同指标，不能互换。

Minsoo Cheong, Donghyun Son, Sungjoo Yoo

Crossflow: Prefill-Decode Elasticity for Agentic LLM Serving

Crossflow 针对预填充与解码静态分池无法响应负载变化的问题，让解码节点发布短时可撤销租约，限制本地预填充计算、KV 容量及传输负担。公开与内部轨迹上，相对静态 P/D 的吞吐几何均值提升 16.2%–17.4%，高负载下最高提升 43.4%，所有测试点的平均 TTFT 均下降。

INSIGHT社区搜索的突发流量和不同 query 长度容易改变输入输出比例，静态分池可能导致部分 GPU 空闲、另一部分排队。短时租约提供无需重分配节点角色的弹性路径，可先在 query 改写和生成服务回放流量；需把租约撤销、缓存压力和业务 P99 联合纳入准入条件，而不只优化平均吞吐。

Yi Xu, Ehsan K. Ardestani, Wenyin Fu, Martin Schatz, Krishna Malladi, Zhan Shu, Adnan Aziz 等 10 人

Closing the Context Gap: Activation Alignment for Tabular In-Context Learning

论文用无标签合成查询训练轻量线性变换，把小上下文学生的中间激活对齐到全上下文教师，降低表格基础模型每次处理全部样本的代价。TabArena 的 38 个分类数据集、TabPFN-3 与 TabFM 两种模型验证了改善；低数据条件恢复近一半教师优势，对齐训练无需 GPU，耗时秒至分钟。

INSIGHT这是一种保留冻结模型、只校准中间表征的低成本推理适配，值得在社区搜索的结构化特征分类或快速离线试验中比较。关键是用完整上下文提供监督而非直接删样本，在线只增加一次矩阵乘法；论文验证的是表格分类，迁移到文本相关性排序仍需独立评测，不能视作已有 CTR 提升。

How DOCA GPUNetIO Unifies GPU-Initiated Networking Across the NVIDIA Software Stack

NVIDIA

DOCA GPUNetIO 将 GPU 发起 RDMA 的公共实现整合到 NCCL、NVSHMEM、UCX/NIXL 等通信栈，CPU 负责初始化而 CUDA kernel 驱动数据路径。NCCL 2.27 与 NVSHMEM 3.7 已接入；IGX Thor、ConnectX-7 与 FPGA 的专门回环测试报告最低 2.6 微秒、中央値 2.7 微秒往返延迟。

INSIGHT搜推多卡训练和推理可借鉴公共传输层设计，减少每套框架重复维护队列、doorbell 和完成轮询逻辑。应先确认 GPU-NIC 拓扑与实际通信瓶颈，再选开放 Verbs 子集或完整 SDK；2.6 微秒来自特定回环测量，不能当作分布式搜索端到端延迟，且 CPU 辅助 doorbell 路径仍可能保留代理成本。

Differentiable Bit-Widths: Co-optimizing Pruning and Quantization via SVD for Ultra-Efficient LLM Compression

论文针对先剪枝再量化的两阶段压缩无法协调资源分配的问题，以 SVD 分量为单位学习可微比特宽；不重要分量获得 0-bit 后被移除。作者在平均 1.61-bit 的极低精度设置下优于两阶段基线，并公开代码；摘要未给出端到端服务吞吐增幅。

INSIGHT可借鉴的是把删除分量与降低精度放进同一个预算优化问题，减少人工依次调参。社区搜索的 query 理解模型可先用此方案压缩离线教师或批量标注模型，再检查短文本语义判断与 nDCG 的变化；压缩率尚不能替代实测延迟，部署前要核对矩阵布局和算子支持。

Capability Scaling-Down Laws for LLM Compression

研究比较剪枝、量化和蒸馏造成的能力损失，建立连接模型状态、压缩配置与训练曝光的简洁预测关系。共享剪枝密度响应将拟合所需测量量减半；在 Pythia、预注册 OLMo-2 状态及 Wanda 设置下，数学与代码预测和完整测量回归的差异不超过每 token 0.020 nats。

INSIGHT对社区搜索模型压缩，可先用少量测量缩小候选配置，再针对语义匹配和 query 理解补齐业务验证。论文明确各设置需要重新拟合系数，且固定方法优先级在部分问答实验中同样达到相近遗憾；因此应把预测器当作试验成本控制工具，不能直接外推成 nDCG 或 CTR 的缩放规律。

AICR v1.0: Open, stable, and verifiable GPU cluster configuration

NVIDIA

AICR v1.0 用版本锁定 recipe 管理 GPU Kubernetes 组件兼容性，并以 Snapshot、Recipe、Bundle、Validation 四项独立能力记录状态、生成配置及验证运行集群。文章报告超过 100 位贡献者、近半来自 NVIDIA 外部；提供签名验证证据和稳定接口契约，但未报告吞吐或故障率收益。

INSIGHT社区搜索 GPU 集群可把驱动、网络、调度器和框架组合固化为可复用配方，再通过现有 Helm、Argo CD、Flux 或 Helmfile 部署。价值在于将安装完成与能力验证分开，并保留硬件对应的签名证据；上线应选择匹配机器和负载的配方，自行验证 embedding 服务与训练任务的 SLO。

MAPS: Memory-Aware Predictive Scheduling Framework for Large Language Model Serving

MAPS 面向预填充/解码分离服务，将端侧推测输出长度与云端预填充重叠，并用不确定性校准得到目标覆盖率下的长度上界。全局与本地两级调度据此缓解解码节点间拥塞和队首阻塞；两个真实负载、两个 LLM 的实验中，平均端到端延迟降低 42.6%，尾延迟最高降低 84.8%。

INSIGHT对社区搜索在线推理，可借鉴以保守输出长度上界而非单点预测进行显存和队列准入，避免少数长回答拖慢多数短 query。完整方案依赖端侧预测与云端协同，上线成本高于纯服务端调度；应先回放真实请求分布，核对覆盖率失准时的显存峰值、超时和 P99，而非直接套用论文降幅。

Tiancheng Zhang, Yulin Chen, Yunfeng Zhao, Shaoyuan Huang, Cheng Zhang, Xiaofei Wang
